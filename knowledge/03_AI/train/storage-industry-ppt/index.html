2.1KV Cache 是第一性需求：128K 上下文 KV 已吃掉 H200 近 30% 容量，decode 带宽远超 CXL/SSD

KV 公式（第一性原理，70B GQA 8:1 FP16）：KV = batch × seq × 2 × L × D_eff × dtype = 320KB/token；128K→41.9GB、1M→320GB。

对整机硬件的诉求量化
HBM 容量仍不足141→288 GB/卡，KV 必然溢出
分层迁移带宽DDR 450GB/s / CXL 64GB/s / SSD 14GB/s
SSD 小随机读512B 粒度，4K 优化盘 8× 读放大
host DRAM 容量≥ 8× GPU HBM（P0 结论）
decode 全量读 838 GB/s
仅 HBM/DRAM 可撑

    5.1机会一 G3.5：共享闪存层不是「更多容量」而是「语义迁移」——14 条需求 P0 五条缺一不可

    维度G3.5 规格对比
    时延50-200 μs介于本地闪存(10-100μs)与远端共享(1-10ms)
    带宽25-50 GB/s/链路；200-800 GB/s/pod网络直连 + 控制面卸载
    容量100s TB · pod 共享填补容量断层

    5.4机会四 KV 四层命运分层——KV 放置决策器 + 带宽预算管理是整机软件核心资产

    L0
    HBM (hot)
    decode 期间 KV 必须在此
    →
    L1
    CPU DRAM (staging)
    DDR→HBM 0.7s 可在线预热
    →
    L2
    persistent (CXL/SSD)
    cross-req reuse；SSD→HBM 23s 只适合离线
    →
    L3
    checkpoint
    训练恢复/容灾
  • KV 放置决策器：按访问热度/生命周期在四层间迁移（场景 A 容量驱动 → 分层为主）
  • 带宽预算管理：decode 全量读不可能 → 注意力稀疏性感知的 KV 子集读取（128K:2K = 64:1 稀疏性）
  • 主导权切换点 T_cross = W/k：模型越小上下文越长 KV 越关键（8B@131K / 70B@452K / V3@10.3M）
  • KV 层 SSD 新三围：512B IOPS + 有效 DWPD + FDP 流数（不再是顺序带宽）
  • 实证：HiSparse 合入 SGLang（200K 4.7×、每请求 KV ~30× 缩减、B=2k 稳健默认）；OasisKV（arXiv:2608.08097）

    5.5机会五 NCCL 假存活案证明「链路 UP ≠ 可用」——I/O 层监控成为软件可靠性标配 P0 行动点

    NCCL 假存活案（marin#7344）分诊/根因
    死锁 GPU 100% util + 功耗冻结到小数点两位 + SM 时钟钉死 1950MHzpower.draw 双采样 5 判据合取
    根因：NCCL 2.28.9 aarch64 proxy-op slot 泄漏（弱 CAS 重试旧值）国产 ARM 芯片 NCCL 移植必须 ISA 级验证

    ⚠️「假存活」陷阱（GDS 直通形态最危险）：数据面硬件全存活、链路 UP，但控制面在 CPU——CPU 挂起后任何新 I/O 无法发起。仅看链路状态会误判"存储可用"。

  • 监控 I/O 层而非链路层：命令完成率/队列深度/超时计数；告警阈值=完成率 <95% 持续 10s
  • watchdog 分层：应用级 > 框架级 > 系统级
  • NHA 全息健康评估（ODCC2505002）：多源异构融合（SMART/遥测/事件），1-5 分/24h IO 延时+块大小
  • BMC Agent 化（R8）：故障响应提速 400%、准确率 ≥90%
  • "验证实际加载物"：/proc/self/maps 而非包元数据
    • ✅来源：CPU 故障网络可靠性设计（NCCL 假存活案 marin#7344）· ODCC NHA 标准 ODCC2505002

    📦相关产品领域影响
