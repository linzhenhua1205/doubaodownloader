§6.2 方法一：模式提取法 (meth-006)

知识库搭建设计模式 (36种, 6类): P- 管道模式 (3) — 数据流转路径 E- 执行引擎 (6) — Skills/Scripts 职责 A- AI 任务处理 (8) — Token 优化/质量门禁 G- 知识治理 (8) — 目录/SSOT/索引 C- 变更管理 (5) — 版本/迁移/同步 Q- 质量保障 (6) — 审计/验证/健康检查 操作步骤: Step 1: 扫描知识库 → 识别高频任务 Step 2: 归类 → 同类任务聚合 Step 3: 提取通用流程 → 参数化 Step 4: 验证 → 用全新场景测试

方法二：两阶段生产法 (meth-009)

Phase 1: 自由生成 (聚焦质量) ✅ MECE/数据出处/安全红线/可验证 ❌ 不管索引/日志/冲突/位置 Phase 2: 集中维护 (脚本批量) check-description-conflict.py check-skill-format.py fix-index-skill.py

## 编码规范 1. 🔴 寄存器操作有 bit-field 注释 2. 🔴 敏感配置项校验范围 3. ⚠️ 硬件抽象层有 Mock 测试 ## 安全红线 1. 🔴 禁止直接操作生产设备 2. 🔴 固件刷写前校验 checksum 3. 🔴 电压/时序修改经硬件团队审核

§7.4 Pipeline 注入法

借鉴 AI Production Pipeline (6阶段编排): 阶段 1 — 需求分析 → 注入 hardware-rules.md → 输出: 需求文档 阶段 2 — 架构设计 → 注入 + architecture-design-rules.md → 输出: 架构图 + 接口定义 阶段 3 — 编码实现 → 注入 + bmc-rules.md → 输出: 代码 + 测试 阶段 4 — 审查 → 注入 + review-rules.md → 输出: 审查报告

用户话术: "现在进入架构设计阶段，请加载 .trae/rules/architecture-design-rules.md 规则"

§7.5 开源封装法

4 步将 GitHub 硬件项目封装为 Trae 规则: Step 1: 找项目 → cluster-smi (84⭐) GPU 集群状态查询 Step 2: 提取使用模式 → cluster-smi → 全集群 GPU 状态一览 Step 3: 封装为 .trae/rules/ → gpu-cluster-check.md Step 4: 加触发条件+输出格式 → 用户说"检查GPU集群"→自动触发 → 输出: JSON 健康报告
用户说: "检查 GPU 集群状态" → 加载 .trae/rules/gpu-cluster-check.md → 运行: cluster-smi → 输出: {total:256, healthy:254, degraded:1, offline:1}

§7.6 Trae 质量门禁

级别含义适用

L3 💡最佳实践，建议遵守文档/命名

§8.5 GPU 集群健康检查

name: gpu-cluster-health-check description: "GPU 集群健康检查 — DCGM/cluster-smi/nvidia-smi Use when: (1) 例行集群巡检, (2) 训练前预检, (3) 排查 GPU 异常(ECC/Power/NVLink), (4) 生成集群健康报告。 Do NOT use: 单 GPU 诊断、应用层性能分析。" 检查清单: 1. 全集群 GPU 状态 (nvidia-smi -L / cluster-smi) 2. ECC 错误计数 (nvidia-smi -q -d ECC) 3. NVLink 健康 (nvidia-smi nvlink --status) 4. GPU 温度/功耗 (nvidia-smi -q -d TEMPERATURE) 5. DCGM 诊断 (dcgmi diag -r 1-3) 输出: { "total_gpus": 256, "healthy": 254, "degraded": 1, "offline": 1, "details": [{"node":"gpu-12","status":"Degraded","cause":"ECC"}] }

§8.7 训练 Hang 排查

name: training-hang-diagnosis description: "分布式训练 Hang/超慢 — NCCL timeout/通信 hang Use when: (1) 进程 hang, (2) NCCL timeout, (3) 训练速度突降, (4) 多机卡在某步。" 排查流程: L1: 进程状态 ps aux | grep train nvidia-smi (GPU 利用率是否为 0%) echo $NCCL_DEBUG (环境变量) L2: 网络状态 ibstat / ibstatus (IB 链路) rdma link show (RDMA 链路) netstat -s | grep retransmit (TCP 重传) L3: 存储状态 iostat -x 1 (IO 是否 hang) nfsstat (NFS 状态) L4: 系统日志 dmesg -T | tail -50 (内核错误) /var/log/messages (系统日志) L5: NCCL Debug 复盘 NCCL_DEBUG=INFO 重新运行

§8.8 功耗建模

name: server-power-modeling description: "功耗建模与 PUE 估算 — 基于组件规格 Use when: (1) 整机功耗估算, (2) 散热方案对比, (3) Power Capping 策略, (4) 数据中心 PUE。" 计算模型: P_total = Σ(GPU × N) + CPU + Memory + NIC + Disk + Misc GPU 功耗: TDP × 利用率 × GPU 数 CPU 功耗: TDP × 负载系数 Memory 功耗: 8W/DIMM × DIMM 数 NIC 功耗: 25W/400G 口 × 端口数 PUE ≈ P_total_input / P_total_it Power Capping 建议: P_total × 1.2 (余量)
