## 核心概念

### 向量嵌入（Vector Embeddings）

通过神经网络模型将原始数据映射到 $d$ 维实数空间 $\mathbb{R}^d$ 中的连续向量：

$$\text{embed}(x) \in \mathbb{R}^d, \quad d \in \{128, 256, 384, 768, 1024, 1536, \dots\}$$

核心特性：

- **语义编码**：向量空间中的距离 ≈ 语义相似度
- **稠密表示**：每个维度都是浮点数（通常 float32），几乎没有零值
- **维度灾难**：高维空间（d > 100）中距离分布趋于均匀，是 ANN 算法的核心挑战

| 模型 | 输出维度 | 用途 |
|:----|:-------:|:----|
| OpenAI text-embedding-3-small | 1536 | 通用文本嵌入 |
| OpenAI text-embedding-3-large | 3072 | 高精度文本嵌入 |
| BERT-base (CLS) | 768 | 语义搜索/分类 |
| Sentence-T5 (XXL) | 768 | 句子相似度 |
| CLIP (ViT-L) | 768 | 图文跨模态检索 |
| ResNet-50 (pool5) | 2048 | 图像特征向量 |

### 距离度量（Distance Metrics）

给定查询向量 $q$ 和库向量 $v$，常用度量：

| 度量 | 公式 | 特点 | 适用场景 |
|:----|:----|:----|:---------|
| **余弦相似度** (Cosine) | $\cos(q,v) = \frac{q \cdot v}{\|q\|\|v\|}$ | 关注方向，忽略幅值 | 文本嵌入（常态） |
| **欧氏距离** (L2) | $\|q - v\|_2 = \sqrt{\sum(q_i - v_i)^2}$ | 关注绝对差异 | 视觉/图像嵌入 |
| **内积** (IP/Dot) | $q \cdot v = \sum q_i v_i$ | 不归一化，有偏 | 推荐系统 |
| **曼哈顿距离** (L1) | $\|q - v\|_1 = \sum\|q_i - v_i\|$ | 鲁棒到异常值 | 生物信息学 |

**重要关系**：对归一化向量（$\|v\|=1$），$\|q-v\|_2^2 = 2(1 - \cos(q,v))$，余弦和 L2 等价。

### 精确搜索 vs 近似搜索

| | **k-NN** (精确) | **ANN** (近似) |
|:--|:--------------:|:-------------:|
| **复杂度** | $O(nd)$ — 遍历全部 | $O(\log n)$ 至 $O(\sqrt{n})$ |
| **精度** | 100% recall | 通常 95-99% recall |
| **内存** | 完整向量 | 压缩索引（通常 10-30% 原始） |
| **适用规模** | $n < 10^5$ | $n > 10^5$，可到 $10^9+$ |

## 一、基于量化的索引 —— Product Quantization (PQ)

> **核心思想**：把高维向量切碎、聚类、压缩为短编码，用查表替代全距离计算。

### 算法流程

```text
原始向量 v ∈ ℝ^d            PQ 编码
+----------------+         +----+----+----+----+
| 0.3  0.9  ...  |  -> m段  | ID₁| ID₂| ID₃| ID₄|  <- 4 × 8bits
| 0.1 -0.2  ...  |  切分   | 0x3| 0xA| 0x7| 0x1|
| ...            |         +----+----+----+----+
+----------------+
  高维密集浮点                 超低比特率编码
  128×32=4096 bits             4×8=32 bits (压缩~128x)
```

**步骤**：

1. **分割 (Split)**：将 $d$ 维向量均匀分为 $m$ 个子向量，每段 $d^* = d/m$ 维
2. **子量化 (Sub-quantization)**：对每个子空间独立运行 k-means，得到 $k^*$ 个质心（典型 $k^*=256$，用 8-bit 编码）
3. **编码 (Encode)**：每个子向量映射到最近质心的 ID，得到一个 $m$ 元组 `(ID₁, ID₂, ..., IDₘ)`

### 距离计算 —— SDC 与 ADC

- **SDC**（Symmetric Distance Computation）：查询向量也做 PQ 编码，用编码间的距离近似。更快但精度低。
- **ADC**（Asymmetric Distance Computation）：查询向量保持完整精度，仅库向量用 PQ 编码。用查找表计算非对称距离——更精确，是主流选择。

### 关键参数

| 参数 | 影响 | 典型值 |
|:----|:----|:------|
| $m$ (子向量数) | 越大压缩率越高但精度下降 | 8, 16, 32 |
| $k^*$ (每空间质心数) | 越大精度越高但内存和训练开销大 | 256 ($2^8$) |
| $n_{\text{bits}}$ | 编码位宽，通常 8 | 8 |

### 内存对比（d=128, n=1M）

| 索引类型 | 内存占用 | 压缩比 |
|:--------|:-------:|:-----:|
| Flat (原始 float32) | 512 MB | 1x |
| PQ (m=8, nbits=8) | ~4 MB | 97.4% |
| PQ (m=16, nbits=8) | ~2 MB | 99.6% |
| PQ (m=32, nbits=8) | ~1 MB | 99.8% |

### 优缺点

- **✅ 优点**：极高的压缩率（可压缩 97%+），极低内存需求
- **❌ 缺点**：recall 上限受限（通常 50-60%），不适合高精确度场景

## 二、基于图的索引 —— HNSW (Hierarchical Navigable Small World)

> **核心思想**：构建多层可导航小世界图，顶层长跳（全局搜索）、底层短链接（局部精搜），搜索时从顶层贪婪下降。

### 分层结构

```text
层 2 (顶层)     o <- 入口点（最长链接）
                |
         +------+
         |      |
层 1      o-----o----o
          |     |    |
    +-----+     |    |
    |     |     |    |
层 0  o---o---o-o---o-o----o  <- 完整数据集，最短链接
   (底层)
```

- **顶层**：仅包含少数高连接度的 hub 节点，链接跨越长距离
- **底层**：所有节点都在，链接仅连接近邻节点
- **搜索策略**：从顶层进入 → 每层贪心遍历到局部最优 → 下降到下一层 → 重复 → 底层返回 k 个最近邻

### 关键参数

| 参数 | 描述 | 影响 | 典型值 |
|:----|:----|:----|:------|
| $M$ | 每个节点每层的最大出边数 | 越高 recall 越高但建图/搜索越慢 | 16-64 |
| $M_{\max}$ | 非底层的最大出边数 = $M$ | 同 $M$ | 16-64 |
| $M_{\max 0}$ | 底层最大出边数 = $M \times 2$ | 底层更密集连接 | 32-128 |
| $efConstruction$ | 建图时的动态候选集大小 | 越大图质量越高但建图越慢 | 100-500 |
| $efSearch$ | 搜索时的动态候选集大小 | 越大 recall 越高但越慢 | 50-500 |
| $m_L = 1/\ln(M)$ | 层归一化因子 | 控制元素分配到高层的概率 | 0.25-0.36 |

### 概率跳表（Probability Skip List）继承

HNSW 继承了 Pugh (1990) 的概率跳表思想：

```text
插入概率：P(level=i) = e^{-i/m_L} · (1 - e^{-1/m_L})

对 M=32: P(level=0) = 0.969, P(level=1) = 0.030, P(level=2) = 0.001
```

这样确保了 95%+ 的向量仅在底层，顶层非常稀疏。

### 复杂度

| 操作 | 复杂度 | 说明 |
|:----|:-----|:----|
| 搜索 | $O(\log n)$ | 对数复杂度，几乎最好的 ANN 理论下界 |
| 建图 | $O(n \log n)$ | 每次插入需在多层路由 |
| 内存 | $O(n \cdot M)$ | 每节点存 $M$ 个链接（其中 $M$ 可达 32-64） |

### 优缺点

- **✅ 优点**：recall 极高（可到 99%+），搜索速度极快（对数复杂度），无训练阶段
- **❌ 缺点**：内存占用大（每个节点存邻接表，d=128,m=32 时 ~4-8x 原始数据大小），建图慢

## 三、基于哈希的索引 —— LSH (Locality Sensitive Hashing)

> **核心思想**：设计哈希函数，使相似的向量以高概率碰撞到同一桶，不相似的向量以高概率分到不同桶。

### 核心性质

对于距离度量 $d(\cdot,\cdot)$，哈希函数族 $\mathcal{H}$ 满足：

- 如果 $d(q, v) \leq r_1$，则 $P[h(q) = h(v)] \geq p_1$
- 如果 $d(q, v) \geq r_2$，则 $P[h(q) = h(v)] \leq p_2$

其中 $r_1 < r_2$，$p_1 > p_2$。

### 随机投影 LSH (Random Projection)

对余弦相似度，用随机超平面划分空间：

$$h(v) = \text{sign}(r \cdot v), \quad r \sim \mathcal{N}(0, I)^{×d}$$

- $r$ 是随机单位向量
- $h(v) \in \{-1, +1\}$ —— 一个 bit
- 串联 $k$ 个独立哈希函数得到 $k$-bit 指纹

### 多表策略

单表 recall 不足，用 $L$ 个独立哈希表：

```text
表 1:  h₁(v) -> [桶 A₁, 桶 A₂, ... ]
表 2:  h₂(v) -> [桶 B₁, 桶 B₂, ... ]
...
表 L:  hₗ(v) -> [桶 L₁, 桶 L₂, ... ]

搜索：对 q 计算 L 个哈希值 -> 到 L 个桶中取并集
```

参数权衡（$(k, L)$ 空间）：

- $k$ 越大 → 每个桶越小（选择性高）→ 但 recall 降低
- $L$ 越大 → recall 提升 → 但搜索时间和内存增加

### Cross-Polytope LSH

将向量投影到标准单纯形顶点，取最近顶点作为哈希值：

$$h(v) = \arg\max_i (A v)_i, \quad A \in \mathbb{R}^{d' \times d}$$

- $d'$ 是目标维度（典型 $d'=d$ 或 $2d$）
- 比随机投影精度更高

### 优缺点

- **✅ 优点**：理论保证强（有界概率），适合洗数据/去重
- **❌ 缺点**：需要多表（内存开销大），低 recall 下比 HNSW 慢，不适合高精度搜索

## 四、基于树的索引

> **核心思想**：用空间分割树将向量空间递归划分，搜索时剪枝大幅减少候选。

| 算法 | 分割策略 | 复杂度 | 弱点 |
|:----|:--------|:-----|:-----|
| **KD-Tree** | 轮流按各维度中位数切分 | 最好 $O(\log n)$，最差 $O(n)$ | 高维灾难严重 |
| **Ball Tree** | 超球面分割 | $O(d \cdot n \log n)$ 建树 | 高维球体体积爆炸 |
| **VP-Tree** | 按到枢轴点的距离分割 | $O(\log n)$ 搜索 | 构建开销大 |
| **R-Tree** | 最小包围矩形 (MBR) 层次嵌套 | $O(\log n)$ | 高维 MBR 重叠严重 |

**高维灾难**：当 $d > 20$ 时，基于树的索引性能急剧下降，几乎所有节点都需要访问。在 $d=128$ 或更高维的向量搜索中，纯树索引不实用。

## 五、复合索引 —— IVF + PQ

> **核心思想**：两级策略——IVF 做粗粒度剪枝 + PQ 做细粒度压缩和加速。

### 结构

```text
                      IVF 倒排
              +--------------------+
              | Voronoi 单元格索引  |
              | (nlist 个聚类中心)  |
              +--------------------+
                    |       |
           +--------+       +--------+
           v                         v
     +----------+              +----------+
     | 单元 1    |              | 单元 k    |
     | PQ 编码向量|    ...      | PQ 编码向量|
     | (m×8bits) |              | (m×8bits) |
     +----------+              +----------+
```

### 搜索过程

1. **粗排**：用 IVF 将查询映射到最近的 `nprobe` 个 Voronoi 单元
2. **精排**：在这些单元的 PQ 编码向量上用 ADC 做完整距离排序
3. **返回**：Top-k 最近邻

### 关键参数

| 参数 | 描述 | 典型值 |
|:----|:----|:------|
| `nlist` | Voronoi 单元数 | 4096, 8192, 16384 |
| `nprobe` | 搜索时探访的单元数 | 1-256 |
| `m` | PQ 子向量数 | 8, 16, 32 |
| `nbits` | PQ 编码位宽 | 8 |

### 性能数据

在 Sift1M 数据集（d=128, n=1M）上：

| 索引 | Recall@1 | 搜索时间 | 内存 |
|:----|:-------:|:-------:|:---:|
| Flat (Brute-force) | 100% | 8.26 ms | 512 MB |
| PQ (m=8) | 50% | 1.49 ms | 6.5 MB |
| IVFPQ (nlist=2048, nprobe=48) | 52% | 0.09 ms | 9.2 MB |
| HNSW (M=32) | 99%+ | 0.15 ms | ~2 GB |

**IVFPQ** 是压缩 + 速度 Recall 三者的最佳权衡：0.09ms 搜索（比 Flat 快 **92x**），9.2MB 内存（比 Flat 少 **56x**），~52% recall。适合超大规模但容忍中等 recall 的场景。

## 六、索引选择决策树

```text
你的数据集有多大？
|
+- n < 10K ---------> 用 Flat (暴力搜索)。简单，100% recall。
|
+- 10K < n < 1M ----> 看精度要求
|   |
|   +- recall > 99% ---> HNSW (M=16-32, efSearch=100-300)
|   +- recall ~ 95% ---> IVFPQ (nlist=4096, m=8)
|
+- 1M < n < 100M ----> 看场景
|   |
|   +- 高精度 ------> HNSW (但内存成本高，需分布式)
|   +- 中精度/低内存 --> IVFPQ (m=16, nbits=8)
|   +- 极低内存 ----> PQ only (但 recall 受限)
|
+- n > 100M ----------> 必须用分布式
    +- DiskANN ----> 基于 SSD 的 Vamana 图
    +- IVF+PQ 分片 --> 多节点 + 分片构建
    +- SPANN -----> 分层内存+SSD 索引
```

## 九、工程实践要点

### 1. 维度选择

- 128-256 维：最佳性价比（搜索快、recall 高）
- 768 维：BERT 级别，IVFPQ 或 HNSW 必须用
- 1536+/3072+ (OpenAI)：推荐先降维（如 PCA 压缩到 256-512 维），否则搜索性能大幅下降

### 2. 归一化

- 始终将向量归一化到单位长度（L2 归一化）
- 归一化后余弦 ≈ L2，可互换度量而无需重建索引
- PQ 在归一化数据上表现更稳定

### 3. 量化类型权衡

```text
                        高
                         ^  HNSW (图)
                         |
                   Recall |  IVF+PQ
                         |
                         |  PQ only
                         |  LSH
                         v
                         低
  <------------------------------------>
  慢                        快     搜索速度
  <------------------------------------>
  大                        小     内存占用
```

### 4. 召回率-延迟调试

调优的策略路线（以 HNSW 为例）：

1. 先设 `efSearch=100`，看 recall
2. recall 不够？→ 增大 `efSearch`
3. 搜索太慢？→ 减少 `efSearch` 或减少 `M`
4. 内存太高？→ 不能减少 HNSW 内存（那是图本身的开销），换 PQ/IVFPQ

对于 IVFPQ：

1. 增大 `nprobe` 可线性提升 recall，但搜索时间线性增长
2. 增大 `m` 减少内存但降低 recall
3. 先定 `m` 满足内存约束，再定 `nprobe` 满足 recall 约束

### 5. 混合搜索（Hybrid Search）

现代系统（如 Elasticsearch、Milvus）通常需要：

```text
最终得分 = α × 向量相似度 + (1-α) × 关键词BM25分数

filter-first:  先按元数据过滤缩小候选集 -> 再向量搜索
search-first:  先向量搜索得候选 -> 再过滤 -> 重排
```

## 十一、前沿方向

| 方向 | 描述 | 代表 |
|:----|:----|:----|
| **Learned Index** | 用 ML 模型学习索引结构 | Google Recursive Model Index |
| **Product Quantization 改进** | 残差量化、LOOC (局部优化量化码本) | OPQ, AQ, RaBitQ |
| **图索引加速** | GPU HNSW 构建/搜索 | CAGRA (RAPIDS), cuVS |
| **硬件加速** | 利用 SIMD/VPU/TPU 加速距离计算 | FAISS 的 IVF 已用 SIMD |
| **Disk-based ANN** | 用 SSD 存储索引，内存仅 cache | DiskANN, SPANN |
| **流式/动态索引** | 实时插入/删除不影响查询 | HNSW 原生支持动态，PQ 需重训练 |
| **内存-精度权衡** | 混合精度 PQ + 重排 | IVFPQ + 重排序（Faiss 的 IVFPQFS） |

## 总结

> **向量相似度搜索的选择本质上是三个维度的平衡：Recall × 延迟 × 内存。** 没有银弹。
>
> - **HNSW**：通用冠军，99%+ recall，但内存贵
> - **IVFPQ**：性价比之王，52% recall + 92x 加速 + 97% 压缩
> - **PQ only**：极致压缩，但 recall 天花板低
> - **LSH**：有理论保障，适合特定场景（去重、大规模粗排）
>
> 工程上的关键是：**理解你的数据、你的延迟预算、你的召回率目标。** 先跑 ann-benchmarks，再调参，再上生产。
