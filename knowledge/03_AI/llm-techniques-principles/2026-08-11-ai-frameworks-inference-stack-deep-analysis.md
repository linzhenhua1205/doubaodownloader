## 2. GraceKV：KV 压缩的全局资源分配

### 2.1 问题定义：固定规则的三大死穴

现有 KV 压缩方法分两派——**token eviction**（驱逐）与 **merging**（合并），但都有共同缺陷：

1. **规则固定**：压缩策略在层/头/槽维度上预设（如"保留前 N 个 token"），无法按实际信息量流动
2. **资源不可流动**：缓存预算不能跨层、跨头、跨上下文槽自由分配——某层某头信息密集却拿不到预算，另一处信息冗余却占着预算
3. **分辨率 vs 覆盖不可权衡**：局部分辨率（保留单 token 细节）与信息覆盖（保留更多不同区域的粗粒度信息）此消彼长，固定规则无法动态平衡

### 2.2 技术框架：全局资源分配问题

**核心建模**——把压缩形式化为**固定预算下的全局资源分配问题**：

- **原子单元**：每个 (层, KV 头, 上下文槽) 组合是一个原子单元，是资源分配的最小单位
- **原型树（Prototype Tree）**：每个原子单元内部构建一棵树——
  - **叶节点** = token 级 KV 条目（原始信息）
  - **内部节点** = 用**单个原型向量**压缩其子节点覆盖的 KV 空间（类似向量量化/层次聚类）
- **树的两种操作 = 资源的两条消耗路径**：
  - **加新树根**（Add root）→ 扩大信息覆盖（把新区域的 token 纳入缓存）
  - **分裂选中节点**（Split）→ 提升局部分辨率（把粗原型细化为多个子原型）
- **全局竞争**：所有候选操作（所有原子单元的 add/split）**共享同一个缓存预算池**，按信息增益/成本比全局竞争
- **最终结果**：所有树中保留的节点构成压缩后的 KV 缓存

### 2.3 原理细节：为什么是树 + 原型

- **原型 = 损失压缩的原子**：一个内部节点用单向量代表其子树全部 token 的 KV，本质是层次化向量量化——与 `K-means`/`RVQ` 同源，但**树结构使分辨率可分级**（从 1 个原型到全部叶节点，任意粒度）
- **Add vs Split 的经济学**：Add 新树是**扩展型**动作（覆盖新信息，代价=1 节点）；Split 是**细化型**动作（把 1 节点替换为 k 子节点，代价=+k-1 节点）——两者在预算竞争时天然形成「分辨率-覆盖」帕累托前沿
- **无需训练**：整个分配过程在 GPU 上运行，不引入额外训练阶段（对比需训练的门控/学习型压缩）
- **全局性**：不同于逐层独立压缩，GraceKV 让信息密度高的层/头自动获得更多预算——**这是「全局优化 vs 局部贪心」的典型对比**

### 2.4 结果与边界

- **24/32 设置排名第一**（跨长上下文任务 × 压缩率）
- **128× 压缩率仍鲁棒**——极高压缩下的优雅降级是实用性的关键（对比固定规则在 >32× 时急剧崩溃的常见现象）
- **局限**（待验证）：原型树构建的计算开销、动态场景（流式生成中树增量更新）的复杂度未披露

### 2.5 知识库互证

- **KV 四层命运论**：GraceKV 优化的是 **L1（CPU DRAM 事实丢失）层的空间冗余**——通过压缩让更多 KV 留在 L0/L1，推迟落入 L2/L3（落盘/checkpoint）——与「长上下文=落盘+检索」原则互补：**先压缩再落盘，落盘带宽需求同步下降**
- **四类冗余-空间**：GraceKV 是对空间冗余的定点消除，且**不牺牲（甚至提升）时间**——压缩后的 KV 读取带宽下降 → 时间冗余同步缓解

## 3. AoH：冻结 QK 几何的数据无关稀疏注意力

### 3.1 问题定义：头诊断的输入依赖困境

稀疏注意力与 KV 压缩的既有方法，判断"哪些 token/头该保留"依赖：
- **运行时注意力分数**（runtime attention scores）——需实际推理才能知道，且随输入变化
- **观察窗口/校准提示**（observation windows/calibration prompts）——需收集数据
- **学习门控**（learned gates）——需训练

→ 共同问题：**头功能诊断是输入依赖的、部署成本高**。

### 3.2 技术框架：权重空间的 QK 几何

**核心洞察**：头是 retrieval（检索）还是 streaming（流式），可以从**查询-键投影矩阵的谱几何**直接读出——**不需要任何输入数据**。

- **定义核注意力算子**：`M_h = W_K^(h)^T · W_Q^(h)`（d_head × d_head 矩阵，完全由冻结权重决定）
- **有效秩（effective rank）** = 谱集中度的度量：
  - **谱集中（低有效秩）**：少数主导的 query-key 匹配方向 → **retrieval 头**（精确匹配特定键）
  - **谱弥散（高有效秩）**：无主导全局匹配方向 → **streaming 头**（信息搬运/复制到后续位置，如 positional/induction 类功能）
- **高效计算**：推导出 `d_head` 维计算，避免构造完整的 `d_model × d_model` 矩阵（d_model 通常 4096-8192，而 d_head 仅 64-128，计算量降 3-4 个数量级）

### 3.3 原理细节：为什么 QK 谱能反映头功能

- **注意力匹配的线性代数本质**：attention logit = `q^T k`，其中 `q = x W_Q`、`k = x W_K`。投影到同一空间后，匹配强度由 `W_Q W_K^T`（或等价的 `M_h`）的谱决定
- **retrieval 头**：需要"少数精确方向"完成精确匹配（如"找到文中出现过的实体名"）→ 谱集中在少数方向
- **streaming 头**：功能是"把当前 token 的信息传播到远处"（如复制 token、保持位置信息）→ 不需要单一强方向，谱弥散
- **数据无关性**：以上完全由权重决定，**一次计算、所有序列复用**——部署成本 = 一次离线扫描
- **稀疏策略**：retrieval 头保留全 KV（信息密度高），streaming 头按策略稀疏化（丢弃部分 token/降低存储）——与 GraceKV 的"按信息量分配"哲学一致，但**判据来自权重而非运行时**

### 3.4 结果与边界

- **50% 稀疏度保留 96.5% 全注意力性能**（平均）
- **prefill 延迟最高 -41.4%、decode 延迟最高 -66.0%**（稀疏注意力直接省计算）
- **256K tokens 时 KV 内存 -50%**
- **局限**：①只识别两类头（retrieval/streaming）的二分法是否覆盖全部功能类型；②稀疏度-性能曲线是否随上下文长度漂移；③与 KV 压缩（而非稀疏）的协同未展开

### 3.5 知识库互证

- **与 GraceKV 构成两极**：AoH = **静态结构**判据（权重谱，数据无关，一次计算）；GraceKV = **动态预算**判据（运行时全局竞争）——合起来覆盖"稀疏谁 + 压缩多少"两个正交问题
- **数据无关的价值**：对齐 `08-10 三层证据标注` 精神——判据可复现、可审计，不依赖运行时观测
- **与 KV 四层命运**：AoH 让 streaming 头 KV 减半 → 更多 KV 留在 L0/L1，延迟确定性提升（agent 场景关键）

## 4. HeteroPanacea：Agentic 推理解聚仿真框架

### 4.1 问题定义：异构解聚的"该不该拆"缺乏决策工具

Agentic 推理（多轮工具调用）下，prefill 与 decode 计算/带宽需求显著不同（prefill 计算密集、decode 访存密集），单一同构 GPU 系统难以两全 → 产业转向**异构+解聚**（如 Vera-Rubin 平台 GPU+Groq LPU）。但**每个组件的最优硬件形态是什么？**——缺乏系统级评估工具。

### 4.2 技术框架：三轴仿真

**HeteroPanacea** = 解聚服务的系统级仿真框架，三个维度：

1. **解聚量化**（Disaggregated Quantization）：prefill/decode 各自可用不同量化精度（如 prefill 用高精度、decode 用低精度）——解聚使量化策略也可分离
2. **自动化并行调度**（Automated intra/inter-device parallelization）：设备内（tensor/pipeline 并行切分）与设备间（哪些阶段放哪些设备）的自动搜索
3. **PDAF 架构异构**（Prefill-Decode-Attention-FFN NPU heterogeneity）：把模型执行拆成 **4 种工作负载类型**——prefill、decode、attention、FFN——每种可映射到不同 NPU 微架构

### 4.3 原理细节：为什么拆 4 路比拆 2 路更稳

- **2 路解聚（prefill/decode）的收益来源**：prefill 是 compute-bound（批量矩阵乘），decode 是 memory-bound（逐 token 访存）→ 分离后各自可极致调优（GPU 高并行 vs LPU 高带宽低延迟）
- **4 路解聚（PDAF）的额外维度**：attention 与 FFN 在 prefill/decode 内的**访存模式也不同**——attention 需 KV 随机访问，FFN 是规则大矩阵乘 → 专用 NPU 可分别优化（如 attention 用高带宽 SRAM、FFN 用大算力阵列）
- **仿真价值**：不实际造硬件即可回答——"哪种解聚粒度、哪种异构组合、在什么量化下，吞吐最优"
- **关键结论**：**4 路 PDAF 解聚是跨模型最一致的吞吐提升方案**（假设自定义 NPU）——即异构粒度的天花板在"工作负载类型"，而非仅"阶段"

### 4.4 结果与边界

- **PD 解聚：吞吐最高 +75%**（对比传统同构服务）
- **局限**：①仿真依赖 NPU 微架构假设的准确性；②未披露具体模型集的多样性（是否含 MoE）；③"4 路最稳"结论在真实硬件（非仿真）上的验证待补

### 4.5 知识库互证

- **与 Rubin 异构路线互证**：Vera-Rubin = GPU（prefill 主战场）+ Groq LPU（decode 主战场）——产业已经在走 2 路解聚，PDAF 4 路是学术侧的前瞻推演
- **与 08-10 推理调度三级升级**（排队器→编排器→HorizonServe）：解聚改变的是**资源拓扑**，调度器解决的是**拓扑上的分配**——两者是上下游
- **与 Glimmer 边界**：dense 单卡（确定性）vs MoE 数据中心（规模化）——HeteroPanacea 的 PDAF 解聚恰好是**数据中心侧的异构答案**

## 5. Agora：Agentic 工作负载架构刻画

### 5.1 问题定义：Agentic 负载的架构影响未知

Agentic AI 进入数据中心，但**其架构影响未探索**。Agora 给出首个**架构刻画**——Azure 生产研究 + 开源框架受控研究。

### 5.2 技术框架：分类法 + 三大架构错配

**核心观察**：Agentic 执行是**碎片化、异构的**——请求展开为工作流（LLM 推理 × 工具调用 × 编排决策），**反复跨越 CPU-GPU 边界**。

**三大架构错配**（常规统一服务器的失效模式）：

1. **碎片化执行闲置容量**：CPU/GPU 容量在突发性需求下被搁置——负载随时间保持低位但**突然尖峰**（工具调用瞬间、并行子任务突发）
2. **同质配置低效**：不同软件角色（编排/工具/LLM 推理）对 CPU 需求不同，统一配置无法匹配
3. **共享核微架构局部性损失**：多 agent 复用到共享核，破坏微架构局部性（cache 抖动、分支预测污染）

### 5.3 原理细节：Agora 原型的四机制

| 机制 | 原理 | 解决错配 |
|:-----|:-----|:---------|
| **动态收割空闲 CPU 核** | 检测 agentic 负载的 CPU 低水位，把闲置核临时分配给**共置的吞吐型工作**（co-located throughput work），同时**保护 agentic 尾延迟**（防工具尖峰） | 错配 1 |
| **超订 GPU 内存** | 每 GPU 放置更多 agent（显存超订），**预取下一 agent 状态**隐藏 swap 延迟 | 错配 2（内存侧） |
| **按角色池化核** | 把 CPU 核按角色（编排/工具/推理）分组，避免角色间干扰 | 错配 2（CPU 侧） |
| **亲和性感知调度** | 亲和调度恢复局部性（同一 agent 的连续执行固定在相同核） | 错配 3 |

**自动调参**：机制参数（收割阈值、超订比例、池大小）随工作负载自动调节。

### 5.4 结果与边界

- **提升利用率与服务器吞吐**，同时保持 agent 尾延迟
- **稀缺价值**：Azure 生产负载的一手数据——「CPU 在关键路径上」「执行结构决定负载形状」是**可复现的生产观察**，非仿真
- **局限**：未披露具体提升幅度数字；原型在 commodity server 上验证，专用架构（如 CXL 内存、加速器编排）未覆盖

### 5.5 知识库互证

- **与 08-10 TensorCast 互证**：TensorCast 认为「agent 工作负载是抽象层催化剂」——Agora 从**架构侧**给出同一结论的**生产证据**（CPU 上关键路径 = 控制面/数据面分离的必然性）
- **与 Agent 六层模型**（Prompt→Loop→工具面→Skills→编排→Channel）：Agora 的"编排在主机侧、CPU 上关键路径"正是六层中**编排层的物理实现代价**
- **与组织 4C**：架构错配 = 认知塑造权的物理层体现——硬件不匹配工作负载，利用率就泄漏

## 6. RAC：参考感知激活压缩

### 6.1 问题定义：拆分推理的通信瓶颈

**拆分推理（Split Inference）**：本地跑模型头/尾/工具 + 云端跑中间层——兼顾隐私与算力。但**本地-云-本地路径每轮调用都传输边界隐状态**，成为关键通信瓶颈。agent 场景尤其严重：**反复处理长而敏感的历史上下文**（工具结果、对话历史、检索片段——高度重复）。

### 6.2 技术框架：参考感知编解码器

RAC 的三种参考机制（对应三种传输方向/阶段）：

1. **Prefill 上行（uplink）参考**：检索**精确 token 历史片段**——agent 上下文中大量 token 与历史重复（工具输出、系统提示），直接以历史为参考压缩当前隐状态
2. **同轮 prefill 下行（downlink）参考**：**复用重建的上行状态**——同一轮内上行状态与下行边界状态高度相关
3. **Decode 参考**：用**轻量因果预测器**生成边界特定参考——decode 的隐状态序列可预测（自回归连续性），预测残差编码

**编解码核心**：
- **分组仿射对齐**（grouped affine alignment）：每组隐状态学一个仿射变换（scale+shift）对齐到参考
- **校准残差量化**（calibrated residual quantization）：量化残差（实际-参考），校准集上优化量化参数
- **可选 prefill 离群值**：保留离群维度（outliers），避免长尾误差
- **发送端线格式重建**（sender-side wire-format reconstruction）：发送端重建与接收端一致的格式，**同步后续参考**（保证收发双方参考一致，这是正确性的关键）

### 6.3 原理细节：为什么参考感知有效

- **熵的视角**：传输边界隐状态的信息熵，取决于「接收端能预测多少」。RAC 的三种参考 = **把接收端的先验知识最大化**——历史片段（精确已知）、上行重建（同轮已知）、因果预测（统计可预测）——剩余需要传输的只是**残差**
- **仿射对齐的意义**：不同层/位置的隐状态尺度差异大，直接量化残差会浪费位宽；仿射对齐把残差归一化到统一尺度再量化
- **校准 vs 在线**：离线校准（标定分布）+ 在线对齐（实际数据）结合——避免完全在线学习的部署复杂度和完全离线的分布漂移

### 6.4 结果与边界

- **TTFT 提升 1.24-2.72×、TPOT 提升 1.01-2.79×**（9 个模型-链路对）
- **12 个非困惑度任务分数变化 -0.40 ~ +2.50 点**（质量损失可控，部分任务甚至提升）
- **局限**：①参考检索的存储/计算开销；②跨设备（非模型-链路对）端到端验证；③与 KV 压缩的联合优化未展开

### 6.5 知识库互证

- **与 KV 四层命运 L2/L3**：拆分推理的边界传输 = 跨节点 KV/状态移动——RAC 把「320KB/token 线性」的搬移成本压缩 1.24-2.79×，直接缓解跨节点判决量
- **与四类冗余-I/O**：RAC 是 I/O 冗余（搬移）的定点消除——与量化（计算冗余）正交，可叠加
- **与 08-10 KV 分层与容错边界耦合（HiSparse）**：边界状态的可压缩性 → 边界切割点设计（哪层切）应把「可压缩性」纳入决策

## 7. 量化双发：CubicQuant + AdaMX

### 7.1 共同背景：量化格式的三角困境

LLM 权重量化需平衡：**重建精度 × GPU 执行规律性 × 元数据开销**。三类格式各有缺陷：
- **均匀整数**：每组的线性网格受限（无法匹配权重分布的非均匀性）
- **低比特浮点**（FP4/FP8）：固定指数-尾数结构，动态范围有限
- **学习码本**：灵活但解码不规则、元数据开销大

### 7.2 CubicQuant：参数化非均匀码本

#### 技术框架
- **格式**：单调三次曲线（monotonic cubic curve）——**两个形状参数 + 一个尺度**，把均匀间隔的幅度码映射到非均匀重建级
- **统一性**：**覆盖 1-8 位**权重载荷；**对称均匀整数是精确特例**（曲线取特定参数即退化回整数网格）
- **有效宽度**：`B + 64/G` bits/weight（B=载荷位宽，G=组大小）——64 位元数据（2 形状参数+1 尺度，按组共享）摊薄

#### 原理细节
- **为什么是三次曲线**：权重分布近似对称钟形（Gaussian/Laplace），需要**中心密集、尾部稀疏**的非均匀重建级；三次多项式族以最少参数（2 形状）表达足够灵活的单调映射，且**可解析积分**（推导 population distortion）
- **分布感知拟合**：针对 Uniform/Gaussian/Laplace 三种假设分布推导**群体失真**（population distortion）解析式，据此优化形状参数——**格式与数据分布匹配**
- **Dynamic A8 carrier**：激活侧用动态 8 位（Dynamic A8），权重用 CubicQuant——H200 实测显示**窄 GEMV 时模型 dtype 更快、行数增长时 Dynamic A8 更优**（激活量化收益随矩阵规模放大）
- **直接执行**：打包权重可直接 GPU 执行（无需反量化到高精度再做矩阵乘，对比学习码本需查表）

#### 结果
- **W4 vs 最优裁剪 4bit 均匀整数**：RMSE -3.90%（Uniform）、-13.49%（Gaussian）、-28.14%（Laplace）
- **W4 vs 最优枚举 4bit 浮点**：-3.90%、-9.44%、-6.27%
- **边界**：模型质量与跨设备端到端性能为**开放评估问题**（论文自述）

### 7.3 AdaMX：异构感知 Microscaling

#### 技术框架
- **问题**：MX 已成低比特推理标准，但 **MXFP4 仍显著掉点**——现有 MX 格式**固定元素格式或固定精度恢复方案**（跨块统一），只捕获有限量化异构
- **两级异构**：①**跨块**：不同块的偏好元素格式与精度恢复方案不同（有的块有离群值需更大动态范围、有的块分布均匀可用高尾数）；②**跨操作数**：权重与激活需要不同编码（权重静态可精细、激活动态需鲁棒）
- **AdaMX**：**每块选择精度恢复方案 + 每操作数选择表示**，且**不增加等效位宽（EBW）**——方案选择编码进共享元数据
- **双块尺寸**：一个设计覆盖两种块大小——**高精度操作点**（小块）与 **低 EBW 操作点**（大块，省存储）

#### 原理细节
- **22nm FD-SOI AI 加速器原型**：含所提解码器（scheme select）、计算单元（混合精度乘加）、量化逻辑——**不是纯软件方案，是格式+硬件协同设计**
- **能耗代价**：对比相同 MXFP4 加速器（FP4-only 乘法器），AdaMX 仅增加约 **1% 系统能耗**——异构选择的硬件代价几乎可忽略
- **精度恢复机制**：per-block 选择恢复方案（如 block 内用 FP4 大动态 vs 小尾数高精度 vs 非均匀码）→ 让每个块用自己最合适的表示

#### 结果
- **3B-70B LLM**：消除 **83%** MXFP4 精度损失（commonsense）、**82%**（MMLU）；NVFP4 损失消除 43%/27%
- **多模态泛化**：Gemma-4 12B 上 4 个 vision-language benchmark 全胜 MXFP4，保持 FP16 精度的 **96%**
- **低 EBW 点**：比基线更准且内存/能耗双降

### 7.4 知识库互证

- **量化三支柱（08-10）**：旋转×量化——CubicQuant/AdaMX 回答「量化格式还能怎么变」；与 GyRot（算法重构）、LightRot（硬件适配）同属「量化从标准格式走向自适应」浪潮
- **FP4 生态从硬件走向软件**：AdaMX 的「异构感知」= 软件/格式侧对硬件异构的响应；CubicQuant 的「参数化」= 格式侧摆脱固定网格
- **与四类冗余-计算**：量化直接降 FLOPs 精度成本；AdaMX 的 1% 能耗代价验证「用 1% 换 83% 精度损失」的杠杆率

## 8. 横向互证：六个切面如何咬合成一个系统

### 8.1 统一主线：约束下的最优分配

六篇论文全部是**分配问题**：

| 论文 | 稀缺资源 | 分配对象 | 分配机制 |
|:-----|:---------|:---------|:---------|
| GraceKV | KV 缓存预算 | 层/头/槽 | 全局竞争（树操作） |
| AoH | KV 内存+注意力计算 | 头（retrieval vs streaming） | 权重谱（静态） |
| HeteroPanacea | 异构算力 | 工作负载类型（PDAF） | 仿真搜索 |
| Agora | CPU/GPU 容量 | 角色（编排/工具/推理） | 动态收割+池化 |
| RAC | 网络带宽 | 边界状态信息 | 参考感知残差 |
| CubicQuant/AdaMX | 位宽（表示预算） | 权重/块的表示 | 参数化/异构自适应 |

**共同模式**：从「固定规则/固定格式」→「自适应/全局竞争」——这是推理系统成熟的标志（固定规则是工程初期的妥协，自适应是信息论意义上的逼近最优）。

### 8.2 正交性检查（可否叠加）

- **AoH（稀疏）× GraceKV（压缩）**：正交——先稀疏（去掉无关 token/头）再压缩（剩余部分做原型树）；AoH 判据静态、GraceKV 判据动态，可接力
- **量化（CubicQuant/AdaMX）× KV 压缩（GraceKV）**：正交——量化管权重，KV 压缩管缓存；但注意**量化降低 KV 精度会改变压缩的失真预算**，需联合校准
- **RAC（通信）× 量化（计算）**：正交——RAC 管传输、量化管计算；RAC 的仿射对齐实际上也隐式受益于低比特表示
- **HeteroPanacea（调度）× Agora（架构）**：互补——前者回答「怎么拆」（仿真），后者回答「拆了之后怎么利用」（生产机制）

### 8.3 与推理四类冗余的映射

| 冗余 | 本批论文的消除手段 |
|:-----|:-------------------|
| 时间（等待） | HeteroPanacea 解聚（阶段匹配硬件）、Agora 收割（利用空闲） |
| I/O（搬移） | RAC（边界传输压缩）、AoH（KV 读取减半） |
| 空间（浪费） | GraceKV（KV 预算）、CubicQuant/AdaMX（位宽） |
| 计算（重算） | AoH（稀疏注意力省计算）、量化（低精度乘加） |

### 8.4 与 KV 四层命运论

本批论文共同效果：**把 KV/状态留在更上层（L0/L1），推迟落入 L2/L3**——
- AoH 减 KV 体积 → L1 容量翻倍
- GraceKV 全局压缩 → L1 有效容量再增
- RAC 压缩跨节点状态 → 跨节点搬移成本下降
→ **「长上下文=落盘+检索」原则的杠杆点 = 压缩先行**。

## 9. 产业信号解读

### 9.1 解聚从概念走向可决策
HeteroPanacea 提供**仿真决策工具**——产业不必"赌"异构架构，可先仿真后投资。与 Vera-Rubin（GPU+LPU）路线直接衔接，**4 路 PDAF 是 2027+ 异构 NPU 的学术先导**。

### 9.2 Agentic 负载倒逼服务器架构
Agora 的三大错配 = **通用服务器在 agentic 时代的系统性失效**——「CPU 在关键路径」意味着**编排加速器（如 DPU/调度芯片）**有明确市场位置；「超订 GPU 内存 + 状态预取」是**CXL 内存扩展的直接用例**。

### 9.3 量化格式进入「自适应」战国
CubicQuant（参数化非均匀）与 AdaMX（异构感知 MX）指向同一方向：**固定格式（INT4/FP4/MXFP4）是过渡态，自适应格式是终局**——但代价是解码复杂度，**需要硬件协同设计**（AdaMX 的 22nm 原型是信号）。

### 9.4 国产硬件启示
- KV 压缩（GraceKV/AoH）是**纯软件**，国产卡可直接受益（无需硬件改动）
- 异构感知量化（AdaMX）需要硬件支持 → 国产 NPU 设计窗口期可提前布局「自适应解码器」
- 解聚调度（HeteroPanacea 结论）→ 国产异构集群（GPU+ASIC）的拓扑设计可参考
