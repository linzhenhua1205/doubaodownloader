## 摘要（TL;DR)

**核心命题**：权重知识与上下文知识是**两种完全不同形态的信息**——前者是**离线全局优化的压缩编码**（深层、原生、无干扰），后者是**在线临时注入的原始文本**（表层、需翻译、有噪声）。模型对前者的利用是「回忆自己的分布」，对后者的利用是「一次前向传播内的注意力分配」——**处理深度相差若干个数量级**。

**实证双证**：
1. **Lost in the Middle**（Liu et al., TACL 2023）：模型对长上下文利用不稳健，**中间位置信息显著退化**——外部信息利用受位置/注意力分配限制；
2. **Knowledge Conflicts**（Longpre et al., EMNLP 2021）：上下文与参数知识冲突时，模型**过度依赖记忆信息**（over-reliance，幻觉根源之一）——外部信息被「视而不见」。

**核心结论**：外部信息利用不深的本质 = **模型没有「消化」材料的时间与深度**。权重知识被数万亿 token 梯度反复打磨成「程序性记忆」；外部材料只有一次前向传播的机会，处于「工作记忆」层面——容量有限、易被稀释、需要主动加工。

**解决方案六式**：两阶段消化（编译-执行）、注意力聚焦（减少稀释+避开中间位置）、知识冲突管理（权威声明+冲突检测）、迭代检索（ReAct/Self-RAG）、外部知识参数化内化（微调）、认知工程（复述-批判-引用）。

> **机制核心（v1.1 深潜）**：上述差异的**计算图根源**是——权重知识嵌在**权重矩阵 W**（训练写入、推理恒定、与输入逐层相乘），上下文知识停在**残差流 r**（推理注入、逐层被读但从不写回 W）。一个是「函数本身」，一个是「函数的输入」；「深度利用」在计算图上 = 信息被**写回权重**而非只在残差流里被搬运。四个机制级证据支撑：FFN 是 key-value 记忆（Geva 2021）、事实可被 ROME 定位到中间层 FFN 低秩子空间并直接编辑（Meng 2022）、ICL 的本质是 induction heads 的**模式复制**而非新知识理解（Olsson 2022）、上下文在 prefill 后**冻结为 KV 快照**而权重始终动态参与。应对方案的工程化目标：**把「待消化的输入」改造成「接近权重的形态」**——结构化断言表、多轮编译、双通道仲裁、参数化内化。

## 一、双源知识的信息形态差异（第一性原理）

LLM 的知识来自两个独立通道，形态完全不同：

| 维度 | 权重知识（参数化） | 上下文知识（RAG/注入） |
|:-----|:-------------------|:----------------------|
| 形成方式 | 训练期梯度下降压缩 | 推理期 token 注入 |
| 表示形态 | 分布式稠密向量（隐式、叠加）| 序列 token（显式、离散）|
| 处理深度 | 全部 L 层反复投影、变换、融合 | 受注意力分配，每 token 有限深度 |
| 存储介质 | 参数（千亿级，常驻）| 上下文窗口（有限、易失）|
| 访问方式 | 直接激活（内存式）| 注意力软检索（逐层加权）|
| 信息密度 | 充分统计量（高度压缩）| 原始文本（低信息密度）|
| 生命周期 | 训练后固化（除非更新）| 当轮会话内有效 |
| 与推理的耦合 | 深度融合（与当前状态协同激活）| 外部条件（加性注入）|

**信息论视角**：权重知识是数据分布 `p_data` 的**充分统计量**——训练等价于把海量数据的信息压缩进参数（信息瓶颈定理：`I(参数; 数据)` 最大化）。上下文知识是**条件变量 c**：模型输出 `p_θ(y|x, c)`，c 的利用受 attention 计算预算（每 token 的注意力权重和 = 1）限制。

**一句话**：权重 = 「已消化的知识」（记忆），上下文 = 「待消化的材料」（输入）。

## 二、为什么权重知识输出「质量好」

用户观察完全正确，机制有四：

**① 原生性（原生态）**：权重知识与模型先验分布天然一致——输出是「回忆自己的分布」，流畅、连贯、自信，无「翻译」损耗。上下文知识是外部语言，模型要先「理解」再「转述」，多一层转换。

**② 深层加工**：权重信息参与所有 Transformer 层的计算——每层 self-attention 重新分配、FFN 反复变换。Geva et al. (2021) 证明 **FFN 层就是 key-value 记忆**：知识在多层 FFN 中被反复读取、组合、改写。上下文 token 只经历同样的层数，但**注意力权重必须与所有其他 token 竞争**——单条外部信息的有效处理深度远低于权重知识。

**③ 无干扰**：权重知识是模型自身的一部分，不存在输入噪声；外部文本可能引入无关 token，稀释关键信息的注意力（呼应倒U文档的 dil(L) 因子）。

**④ 表征对齐**：权重知识以模型内部表征存在，直接激活推理路径；外部文本是「表面形式」（surface form），需要先被投影进语义空间——**表层→语义的翻译损失**。检索到的材料表述方式与任务意图不完全对齐时，模型「读懂了字面，没接上意图」。

## 三、为什么外部信息利用不深（机制+实证）

### 3.1 机制层（四重损耗）

```math
U_{context} = \underbrace{A_{alloc}(L)}_{\text{attention dilution}} \times \underbrace{P_{pos}}_{\text{position}} \times \underbrace{C_{conflict}}_{\text{conflict}} \times \underbrace{T_{trans}}_{\text{translation}} \quad (0 \le U \le 1)
```

| 损耗 | 机制 | 数学/实证 |
|:-----|:-----|:---------|
| **注意力稀释** | 上下文越长，关键信息注意力权重被摊薄 | `A_alloc(L) = 1/(1+L·e^Δs)`（倒U文档 dil）|
| **位置效应** | 中间位置信息利用最差 | Lost in the Middle 实证 |
| **知识冲突** | 外部与参数冲突时模型偏好记忆 | Longpre 实证（over-reliance）|
| **表层翻译** | 外部文本需投影进内部语义空间 | 表征对齐损失 |

### 3.2 实证层（一手验证）

**实证 A：Lost in the Middle**（Liu et al., TACL 2023，arXiv:2307.03172 已抓取验证）
- 多文档 QA + key-value 检索任务：**相关信息在上下文开头/结尾时性能最高，在中间时显著退化**——即使对长上下文模型；
- 含义：外部信息的利用**强烈依赖位置**，模型不是「全局理解」材料，而是「就近检索」；
- 推论：一次性注入大量材料 = 把大部分材料放进「利用盲区」。

**实证 B：知识冲突**（Longpre et al., EMNLP 2021，arXiv:2109.05052 已抓取验证）
- 参数知识 vs 上下文知识冲突时，模型**过度依赖记忆信息**（memorized information），上下文被忽略——这正是幻觉的机制根源；
- 缓解方法（显式提示 + 上下文强化）使 OOD 泛化提升 4-7%；
- 推论：**外部信息的「权威性」在模型眼里低于权重知识**——除非显式声明优先级。

### 3.3 机制级证据链（v1.1 深潜）：四个一手实验揭示「权重=结构化存储，上下文=临时搬运」

> 前述四重损耗是**宏观现象**。本节用四个机制级证据回答「为什么权重知识有存储而上下文没有」——从**存储介质**层面看，两者的地位根本不对等。

**证据 C：FFN 层是 key-value 记忆（Geva et al., EMNLP 2021, arXiv:2012.14913）**
- 机制：MLP 层可重写为 `m(x) = Σ_i v_i · σ(k_i·x)`——每个神经元 `i` 是一个 **(key=k_i, value=v_i) 对**：`k_i` 是触发条件（key），`v_i` 是输出贡献（value）。推理时对输入 x 做**键匹配**（`σ(k_i·x)` 大 → 该记忆被激活），输出 = 匹配上的 value 加权和；
- 含义：**权重知识以「可寻址记忆」形态存储在 FFN 中**——训练 = 写入 (key, value) 对，推理 = 按相似性检索。这是「程序性记忆」的实现载体；
- 推论：权重知识的「深层利用」是**逐层反复键匹配**——每层 FFN 都是一次独立的记忆检索，L 层 = L 次检索的级联，检索结果逐步组合出答案。

**证据 D：事实可被定位到中间层 FFN 并直接编辑（Meng et al., NeurIPS 2022, ROME, arXiv:2202.05262 已抓取）**
- 机制：ROME 用因果干预（causal tracing）定位「对事实预测起决定性作用的神经元激活」，发现事实关联（如「巴黎→法国首都」）由**中间层 FFN 模块的少数（rank-one 低秩）计算**介导；直接修改这一层的 FFN 权重（rank-one 编辑）可**改写**该事实，且在新 counterfactual 数据集上同时保持 specificity（不影响无关输入）与 generalization（相关变体也更新）；
- 含义：**权重知识是「可定位、可编辑」的结构化存储**——每个事实是一个低秩子空间，而非均匀分布在所有参数里（部分反驳「分布式叠加=不可干预」的直觉）；
- 推论：这给「参数化内化外部知识」提供了**手术级路径**——不是只能整体微调，而是可以定点改写（§5.5 展开）。

**证据 E：ICL 的本质是模式复制而非知识理解（Olsson et al., 2022, arXiv:2209.11895 已抓取）**
- 机制：induction heads 是执行 `[A][B] ... [A] → [B]` 的注意力头——在上下文里发现 `[A][B]` 对后，当 `[A]` 再次出现时把注意力指向上文 `[B]` 位置并复制输出。该论文给出六条互补证据（小模型因果级、大模型相关级），并发现 induction heads 出现的**时刻与 ICL 能力突增（训练 loss 的 bump）精确重合**；
- 含义：**上下文学习的核心机制是「复制前文模式」，不是「深度理解新知识」**。模型从上下文学到的多是「任务结构」（怎么做），而非「新事实」（是什么）——新事实若要被利用，仍需走注意力软检索（§3.1）；
- 推论：这精确解释了用户观察——「外部信息没有深度解读」= 模型在上下文中**复制了表述模式，但没有把新事实写入任何可复用存储**。

**证据 F：上下文在 prefill 后冻结为 KV 快照（工程事实）**
- 机制：prefill 阶段一次性计算上下文的 Key/Value 并缓存（KV cache），后续生成阶段**KV 不再更新**；而权重矩阵 W 在每一步生成时都重新参与前向计算；
- 含义：上下文 = 推理期的**只读快照**（一次编码、全程复用），权重 = **活函数**（每步重算）。「深度加工」在计算图上的前提是信息参与多步迭代变换——上下文快照天然做不到；
- 推论：要把上下文变「活」，唯一办法是**多轮前向**——即 §5 的拆解-汇聚/迭代检索/蒸馏循环：每一轮都是一次新的快照+加工。

### 3.4 残差流双通道理论（v1.1 深潜）：为什么「深度」在计算图上是不对称的

> 把 Transformer 看作**残差流 + 权重更新**的信息流系统（Elhage et al. 2021 框架），双源知识的深度差异可以归结为**两个通道的读写权限不对称**。

```math
\text{residual stream: } \quad r^{(l+1)} = r^{(l)} + \underbrace{\text{Attn}_l(r^{(l)})}_{\text{context carry}} + \underbrace{\text{FFN}_l(r^{(l)})}_{\text{weight retrieval}} \qquad (\text{layer-wise additive})
```

| 属性 | 权重通道（W） | 上下文通道（r 中的 token） |
|:-----|:-------------|:--------------------------|
| 写入时机 | 训练期（梯度） | 推理期（embedding 注入） |
| 写入后行为 | **恒定**（W 不随输入变） | **随输入变**（每轮前向重新注入） |
| 参与计算的方式 | 与残差流**相乘**（变换） | 被 attention **搬运**到当前 token（加权求和） |
| 读取次数 | 每层 1 次 × L 层（级联变换） | 每次前向 1 轮（无级联累积） |
| 可迭代性 | 训练 epoch 级迭代修正 | 推理期无梯度，无法自修正 |
| 信息密度 | 充分统计量（数万亿 token 压缩） | 原始文本（低密度，含噪声） |

**三个不对称的推论**（这是「利用不深」的底层原因）：

1. **变换 vs 搬运**：权重知识经 W 做**非线性变换**（FFN 键匹配、逐层组合）；上下文 token 只被 attention **线性加权求和**搬运。线性搬运不改写信息形态，非线性变换才产生「理解」——上下文知识缺乏非线性加工机会；
2. **级联 vs 单轮**：权重知识的利用是 L 层**级联检索**（每层 FFN 读一次 → 结果进下一层）；上下文知识只在**当前 token 的 attention 计算**中参与，其「被利用」发生在每一层的注意力计算里但**不累积状态**（每层重新竞争注意力权重）；
3. **写回缺失**：上下文信息从不在前向传播中**写回权重**——即使模型「读懂了」，知识仍是输入的一部分，不是模型的一部分。人类「深度理解」= 知识被整合进认知结构（写回长期记忆），LLM 上下文注入没有这个写回通道。

> **一句话**：权重知识是「模型会的东西」，上下文知识是「模型看到的东西」。前者经 L 层非线性变换内化为能力，后者只在注意力软检索中临时借力——**处理深度的不对称是计算图结构决定的，不是 prompt 技巧可以抹平的**；但可以通过多轮前向（§5）人为制造「迭代写回」的近似。

### 3.5 用户观察的精确解释

「没有深度解读材料」= 四个损耗叠加的结果：
1. 材料注入方式（一次性全塞）→ 中间位置盲区 + 注意力稀释；
2. 材料与任务无显式关联 → 模型「引用」而非「消化」；
3. 材料与模型自身知识的关系未声明 → 冲突时模型走捷径（记忆）；
4. 模型没有「先读后思」的两阶段机会 → 表层处理，无深度推理。

## 四、深层解释：一次前向传播 vs 万亿 token 梯度

### 4.1 处理深度的数量级差异

| 通道 | 处理量 | 处理方式 | 结果 |
|:-----|:-------|:---------|:-----|
| 权重知识 | 数万亿 token × 多次 epoch | 梯度下降逐层修正 | 知识「溶入」参数分布，成为先验 |
| 上下文知识 | 1 次前向传播 | attention 分配一次 | 知识「停在」token 表示，未被迭代打磨 |

权重知识经历了 **O(参数 × 训练步数)** 次修正；上下文知识只有 **O(1)** 次前向传播。**「深度解读」本质上需要迭代加工——模型对外部材料只有一次机会**。

#### 4.1.1 处理深度的量化不等式（v1.1 深潜，D2/D5 补齐）

> 用**有效加工次数**（信息被非线性变换的次数）量化双通道的深度差异，得到可计算的量级差距。

```math
\text{parametric:} \quad D_{param} = L \times E \times \underbrace{N_{steps/epoch}}_{\text{grad steps per epoch}} \approx 10^2 \times 10^1 \times 10^{5\text{-}6} = 10^{8\text{-}9}
```

```math
\text{contextual:} \quad D_{ctx} = L \times 1 = 10^2 \quad (\text{one forward, L layers of attention carry})
```

| 项 | 数量级 | 说明 |
|:---|:------:|:-----|
| 层数 L | 10² | 7B~70B 模型 32~80 层 |
| 训练 epoch E | 10⁰~10¹ | 通用预训练 1~3 epoch（数据充分下） |
| 每 epoch 梯度步数 | 10⁵~10⁶ | 数万亿 token ÷ batch（~10⁶ token） |
| 上下文有效加工次数 | 10² | 每 token 每层被 attention 读一次 |
| **深度比 D_param/D_ctx** | **10⁶~10⁷** | 六到七个数量级 |

- **推论 1（数量级不可弥合）**：把外部材料「深度利用」到权重知识水平，需要 **10⁶ 次以上前向传播**——任何在线方案（RAG/长上下文/prompt 技巧）都不可能达到；工程目标应降级为「**从 10² 提升到 10³~10⁴**」（多轮消化循环），而不是「等于权重」；
- **推论 2（内化是唯一「等深度」路径）**：只有**微调/知识编辑**（把信息写回 W）才能获得与权重知识同量级的加工次数——这是 §5.5 的数学依据；
- **推论 3（量化目标）**：每增加一轮「编译-执行」循环，上下文加工深度 +10²；5 轮循环 ≈ 10³，仍比权重低 5 个数量级——**所以工程上限是「足够好」而非「等同」**，需与成本（每轮全量 prefill O(n²)）权衡。

**成本锚点**（与姊妹篇《推理显存与 KV Cache》同源）：Qwen3-8B 每 token KV 144 KiB、128K 上下文 prefill 约 4.83GB KV；每多一轮消化循环 = 多一次 prefill + 多一份 KV 驻留——深度提升按 10²/轮计，成本按全量前向计，需在 §5.8 决策树中权衡。

### 4.2 认知科学类比（程序性记忆 vs 工作记忆）

| 认知系统 | LLM 对应 | 特征 |
|:---------|:---------|:-----|
| **程序性记忆**（技能，自动化）| 权重知识 | 无需意识加工、执行流畅、抗干扰 |
| **工作记忆**（Baddeley 模型，容量 ~4 组块）| 上下文窗口 | 容量有限、需主动加工、易受干扰、快速遗忘 |

- 专家（权重）凭「直觉」给出高质量答案——因为技能已内化；
- 给专家一份新材料（RAG），专家需要「读、理解、组织」——而 LLM 的「读」只有一次 attention，相当于让专家**扫一眼**材料就作答。
- 人类的解法：读→复述→批判→应用（多轮加工）；LLM 默认跳过这些步骤。

### 4.3 为什么「看上去」权重知识更好

不是权重知识「更正确」，而是**输出路径更顺滑**：
- 权重路径：`参数分布 → 解码`（无缝）；
- 上下文路径：`外部文本 → attention 投影 → 与参数分布竞争 → 解码`（多损耗 + 竞争）。
- 权重知识回答「流畅自信」，上下文回答「迟疑引用」——**流畅性 ≠ 正确性**，但主观感受上「质量更好」。

## 五、解决方案：让外部信息「消化」为深层利用

> **v1.1 重构**：本节从「六个原则」升级为「**可执行的工程协议**」——每个方案给出触发条件、操作步骤、量化目标、成本与边界。先给决策树（§5.0），再给六个协议（§5.1~§5.6），最后是失效场景（§5.7）。

### 5.0 方案选择决策树（v1.1 新增）

外部材料到达后，按以下顺序决策（每个分支给出默认值）：

1. **Q1：材料是否需要「深度理解」后推理？**
   - 否 → 直接注入（例行任务，如翻译/摘要）→ 仅做 §5.2 注意力聚焦
   - 是 → **Q2**
2. **Q2：材料规模 vs 有效上下文（§3.4.5）？**
   - 材料 ≤ 0.3 × 有效上下文 → **Q3**（单轮可容纳）
   - 材料 > 0.3 × 有效上下文 → 先做「拆解-分层汇聚」缩规模（姊妹篇《大文件深度解读》§3.5：MapReduce 式切块+摘要树）→ **Q3**
3. **Q3：材料与模型权重知识的关系？**
   - 高度冲突（新旧数据/颠覆性结论）→ §5.3 冲突仲裁（双通道）
   - 部分补充（高频知识，每周反复用）→ §5.5 参数化内化（LoRA）
   - 一般补充（一次性/时效信息）→ **Q4**
4. **Q4：任务对「深度」的要求？**
   - 深度分析/综述/决策 → §5.1 多轮消化循环（编译-执行 × 2~3 轮）
   - 需要证据链/来源 → §5.6 认知工程（复述-批判-引用）+ §5.2 grounding
   - 探索性/动态信息 → §5.4 迭代检索（ReAct/Self-RAG）

**默认推荐组合**（本系统 CowAgent 落地）：`§5.1 两阶段消化 + §5.2 注入量控制 + §5.6 复述验证`——成本最低、收益最稳（P1 可证伪）。

### 5.1 多轮消化循环（编译-执行 ×N）——核心方案

```math
\text{Phase 1 (compile)}: \quad c' = \text{LLM}(c) \quad (\text{material} \to \text{structured parse})
```

```math
\text{Phase 2 (execute)}: \quad y = \text{LLM}(x, c') \quad (\text{reason on digested representation})
```

- **原理**：让模型先「读透」材料并用自己的表达重述（把在线临时编码「编译」成接近内部表征的形态），再基于编译结果推理——模拟人类的「先读后思」；「多轮」= 把「读→复述→批判→应用」的人类加工链逐轮显式化；
- **具体操作**（v1.1 协议化，每轮都是独立前向 = +10² 加工深度，§4.1.1）：

| 轮次 | 输入 → 输出 | 目的 |
|:-----|:-----------|:-----|
| **R1 compile** | 材料 → 断言表（subject/relation/object + 置信度 + 来源行号）| 提取关键论点清单 + 数据表 + 与任务的相关性标注 |
| **R2 execute** | 断言表 + 任务 → 初步推理 | 强制每条推理标注所用断言 ID（grounding）|
| **R3 verify** | 推理 + 原始材料 → 核对 | 断言是否有原文支撑？遗漏关键断言？（自检回路）|
| **R4 finalize** | 核对结果 → 最终答案 | 含引用标注 + 未验证项声明 |

- **量化目标**：R1 输出 ≤ 原文 20% 的 token（把信息密度提高 5 倍再进 R2）；R2 必须显式引用断言 ID（grounding 契约）；R3 是自检回路（呼应姊妹篇 for 循环的「校验断言」语义）；
- **收益**：N 轮前向 = N 轮加工，有效处理深度从 10² 提升到 N×10²（默认 N=2~3，4 轮以上边际收益 < 成本）；中间表征与任务意图对齐；
- **成本**：每轮 = 一次全量 prefill（O(n²)）+ 一次 KV 驻留；默认 2 轮 ≈ 2× 直灌成本，3 轮 ≈ 3×——**深度任务才用，例行任务走 §5.0 决策树直接注入**。

### 5.2 注意力聚焦（减少稀释 + 避开盲区）

| 技术 | 原理 | 操作 |
|:-----|:-----|:-----|
| 检索精化 | 减少噪声 token，提高信噪比 | 更小 chunk、更高相关性阈值、去重 |
| 关键信息前置 | 避开中间位置盲区 | 最重要材料放 prompt 开头（或结尾）|
| 显式引用（grounding）| 强制注意力落在材料 | 要求回答标注来源行/段落号 |
| 注入量控制 | 防稀释（倒U：L ≤ L*）| 只注入与任务直接相关的片段 |

### 5.3 知识冲突仲裁（v1.1 升级：从「声明」到「双通道协议」）

> 原「显式权威声明」是 prompt 层缓解（Longpre 实证 OOD +4-7%），但**仍把冲突裁决留给模型隐式完成**。v1.1 升级为**确定性双通道仲裁**——把隐式竞争变成显式比较（呼应证据 D：冲突本质是 logits 竞争，见 §3.3）。

**协议**（三通道对比，适用于材料与权重知识高度冲突的场景）：

| 步骤 | 输入 → 输出 | 说明 |
|:-----|:-----------|:-----|
| **Step 1（纯权重）** | 不看材料，模型基于自身知识回答 → 答案 A_weight | 走权重通道，无上下文干扰 |
| **Step 2（纯材料）** | 只看材料（不看任务提示/自身知识）→ 答案 A_material | 走上下文通道，无参数偏置 |
| **Step 3（仲裁）** | 比较两者 → 一致部分=高置信结论；冲突部分=冲突清单（A vs B + 各自依据 + 时效判断）| 决策责任交给人/规则（本系统「冲突显式化」思想）|

- **为什么有效**：Step 1/2 分别走**单一通道**，注意力与 logits 无竞争（§3.1 四重损耗最小化）；冲突从「模型内部的隐式偏置」变成「模型外部的显式清单」——**决策责任从模型转给人/规则**（AGENT.md「判断权归人」）；
- **量化目标**：冲突场景下，仲裁后的材料采信率应高于直接声明的基线（Longpre 的 4-7% 是「声明」的收益上限，仲裁协议目标是翻倍）；P3 可证伪；
- **成本**：3 次前向（权重1 + 材料1 + 仲裁1），只用于 Q3 判定的「高度冲突」分支（§5.0）；
- **边界**：材料本身错误时仲裁无效 → 需来源校验兜底（§5.6 R3 核对 + link-ref-audit 契约）。

### 5.4 迭代检索（ReAct / Self-RAG）

- 一次性注入 → 分步按需检索：每步推理聚焦当前子问题，注意力预算不被全量材料竞争；
- Self-RAG（Asai et al. 2023）：模型自主决定「何时检索、是否引用、答案是否被检索支持」——**把检索从「输入预处理」变成「推理过程的一部分」**；
- 收益：每次注入量小（稀释低）、位置可控（可前置）、检索与推理交替（深度加工）。

### 5.5 外部知识参数化内化（微调 / 知识编辑）——唯一「等深度」路径

- **为什么是唯一等深度路径**：§4.1.1 推导——只有把信息**写回 W**（内化），才能获得与权重知识同量级的加工次数（10⁸~10⁹ vs 10²）；其余方案都停留在残差流通道；
- **两条工程路径**（v1.1 具体化）：

| 路径 | 机制 | 适用 | 成本量级 | 风险 |
|:-----|:-----|:-----|:---------|:-----|
| **LoRA/微调** | 低秩适配器写回 W 子空间 | 高频知识（每周反复用）、领域语言 | 数据准备（千~万级样本）+ 训练小时级 | 灾难性遗忘（需混入原数据）|
| **知识编辑（ROME/MEMIT）** | 因果定位 → rank-one 改中间层 FFN 权重 | 少量（<100 条）高置信事实的**定点改写** | 秒~分钟级（无需训练）| specificity/generalization 平衡难（ROME 已优化）；数量多时副作用累积 |

- **ROME 与微调的选型**（证据 D 的工程化）：事实条数少（<100）且高置信 → ROME 定点改（秒级、可验证）；条数多/需领域能力 → LoRA 整体调；两者可叠加（先 LoRA 学领域，再 ROME 修事实）；
- **混合架构**：参数为底（内化高频/稳定知识）、检索为补充（时效/低频）——本系统「知识库 → 蒸馏进 system prompt」已有雏形，可升级为「月度 LoRA 蒸馏 + 每日 RAG」；
- **时效风险**：内化的知识会过时 → 定期评估「是否内化了过时知识」，过时条目用 ROME 定点改回（比整体重训成本低 10⁴ 倍量级）；
- **边界**：内化 ≠ 推理质量保证——知识正确但推理路径未训练，仍需 prompt 工程配合（§5.1/§5.6）。

### 5.6 认知工程（把「引用」变「理解」）——协议化

- **复述验证**：要求模型用自己的话重述材料要点（验证「读懂了」），再推理；
- **批判性分析**：对材料做假设检验、反驳、交叉验证（多视角加工，而非单遍引用）；
- **对比综合**：多份材料 → 先分别解析 → 再综合差异（并行处理 + 收敛，呼应 pipeline-multi-path 思想）；
- **v1.1 协议化**（三段式，与 §5.1 的 R3 核对呼应）：

| 步骤 | 操作 | 目的 |
|:-----|:-----|:-----|
| **S1 复述** | 用自己的话重述材料核心（≤300 字）| 验证模型「读懂了」而非「复读了」（激活 FFN 键匹配，§3.3 证据 C/E）|
| **S2 批判** | 对每个关键断言提问：有来源行号吗？与常识/已知冲突吗（→ §5.3）？时效性如何（数据日期 vs 当前）？| 把隐性错误变显式声明 |
| **S3 应用** | 只有通过 S1/S2 的断言进入推理，未通过的标记「未验证」| 保证结论可追溯（AGENT.md「断言有出处」落地）|

### 5.7 边界条件：六方案失效场景（v1.1 新增，D4 补齐）

| 方案 | 失效场景 | 判断信号 | 替代 |
|:-----|:---------|:---------|:-----|
| §5.1 多轮消化 | 材料本身矛盾/低质；任务无需深度 | 多轮后答案无变化；R3 核对发现断言互相矛盾 | §5.3 仲裁；换材料源 |
| §5.2 注意力聚焦 | 任务需要**全局**信息（综述/对比全貌）| 精化后遗漏关键点（用户反馈「缺了 X」）| 分层检索（先全局摘要再按需）|
| §5.3 双通道仲裁 | 材料与权重**都是错的**；材料错误 | 仲裁输出仍与事实不符 | 来源校验 + 人工复核 |
| §5.4 迭代检索 | 信息高度依赖单篇长文（拆开就断义）| ReAct 每步只取片段 → 上下文断裂 | 先全文编译（§5.1）再检索 |
| §5.5 参数化内化 | 知识高频变动（时效 < 1 周）| 内化后一周内频繁过期 | 保持 RAG，不内化 |
| §5.6 认知工程 | 材料为对抗性/误导性内容 | 复述看似合理但事实错误（S2 未捕获）| 多源交叉验证（三份独立源）|

## 风险与边界

- **两阶段消化增加 token 消耗**（多一次前向传播）→ 只用于深度任务，例行任务直接作答（质量-成本权衡，呼应倒U）；
- **注意力聚焦可能丢失全局信息**：材料太多时精化会漏关键点 → 分层检索（先全局摘要，再按需精化）；
- **微调内化有知识时效风险**：高频≠最新，需定期评估是否「内化过时知识」；
- **「权威声明」不能解决事实性错误**：材料本身错误时声明无效 → 需要来源校验兜底；
- **深度有上限**（§4.1.1）：在线方案最多把上下文加工从 10² 提升到 10³~10⁴，**不可能达到权重知识的 10⁸~10⁹**——工程目标是「足够好」而非「等同」，过度追求深度会边际收益递减（P7 验证）；
- **多轮消化循环的传播误差**：R1 断言表压缩会丢信息，R3 核对只能发现「断言 vs 原文」不一致，发现不了「断言 vs 事实」错误 → 关键结论需多源交叉验证；
- **知识编辑（ROME）的副作用累积**：编辑条数多（>100）时 specificity/generalization 平衡可能崩溃 → 大数量走 LoRA，编辑仅用于少量高置信事实；
- **网络受限说明**：四篇关键论文摘要经 arXiv 一手抓取验证（Lost in the Middle / Knowledge Conflicts 2026-08-10；ROME / Induction Heads 2026-08-11），其余引用为教科书/经典文献出处。
