# 🎯 量化损伤是乘法非加法：margin 收缩重新定义量化误差预算——FP4/FP8 生态的直接指导

> **概要**: 量化是 LLM 实际部署的方式，低于 4bit 已知会损伤模型。但**没人能说清「在给定 bit-width 下，模型哪些决策会改变」**——损伤是静默的：压缩后的 agent 停止调用工具、丢失一半安全拒绝，基准分数却几乎不动。已有工作假设量化添加固定大小的噪声（additive），这会让「高置信决策安全」的直觉成立。本文（arXiv:2608.06564，UCL）**直接测量决策本身**：二选一决策的 margin = 模型对所选选项的分数 − 次优选项的分数，在量化前后跟踪（16 模型 × 8 家族 × 3 量化方法 × 8→2 bit）。结论：**量化不是给 margin 加固定噪声，而是乘以一个随 bit-width 收缩的因子**（4bit 中位 0.86、3bit 0.33、2bit 0.00）——称为 **margin shrinkage（边际收缩）**。收缩减少大 margin 提供的保护，模型自身的小偏差决定失败方向：3bit 时「调用工具」的决策塌向不作为，而「选哪个工具」不受影响。拟合关系在留出决策上预测翻转率中位误差 1.8pp（拟合时未用任何翻转样本），逐决策预测的翻转概率是校准的不确定性估计（131,758 个预测上 ECE 0.004）。**同样的形式在每个模型中都成立，但常数是每个模型私有的、不可迁移。**

> **关键词**: 量化损伤 · margin shrinkage · 乘法噪声 · 决策翻转 · 校准不确定性 · FP4/FP8 · 量化误差预算 · 工具调用退化

## 〇、结论概要

**一句话：量化对决策的损伤不是「加噪」（固定大小、高置信安全），而是「乘性收缩」（margin 随 bit-width 指数收缩）——低 bit 下即使原本 margin 很大的决策也脆弱，而「模型自身的小偏差」而非「噪声大小」决定失败方向；这对 FP4/FP8 部署的误差预算分配给出全新指导：预算应按「margin 保护」而非「噪声幅度」分配。**

1. **损伤是乘性的**：量化把 margin 乘以因子 s(w)（4bit≈0.86、3bit≈0.33、2bit≈0.00）——不是加固定噪声。
2. **静默损伤可预测**：拟合关系可在留出决策上预测翻转率（中位误差 1.8pp），且逐决策翻转概率是校准的（ECE 0.004 / 131,758 预测）——**「哪些决策会坏」可以提前知道**。
3. **失败方向由模型自身偏差决定**：3bit 时「调用工具」塌向不作为、「选哪个工具」不受影响——损伤有选择性，与噪声无关。
4. **常数不可迁移**：乘法形式通用、常数私有——每个模型/bit-width 需各自测量。
5. **工程启示**：小配对小 margin 集（per model × bit-width）可预测哪些决策会坏；**成本匹配测试下，没有比「多一个 bit」更便宜的修复**。

## 一、问题：量化损伤的「静默性」

**量化是部署方式**：LLM 实际部署几乎都量化（内存/带宽受限）。<4bit 已知损伤，但损伤**不可见**：

| 现象 | 表现 |
|:-----|:-----|
| 基准分数几乎不动 | 平均精度掉 1-2%，看起来安全 |
| 工具调用停止 | agent 不再调用工具（行为级失效） |
| 安全拒绝丢失一半 | 拒绝率暴跌（安全级失效） |

**矛盾**：基准不动 vs 行为崩坏——**平均指标掩盖了决策级损伤**。已有工作假设「量化 = 加固定大小噪声」→ 推论「高置信（大 margin）决策安全」——这个直觉被本文推翻。

---

## 二、核心概念：margin 与 margin shrinkage

**margin 定义**（二选一决策）：

```
   margin = score(chosen option) - score(best alternative)
   # decision confidence: large margin => robust (hard to flip)
```

**量化前后跟踪 margin**，发现：

```
   margin_quantized = s(w) * margin_original

   s(w): margin shrinkage factor
   w = 4bit: s ~ 0.86 (median)
   w = 3bit: s ~ 0.33
   w = 2bit: s ~ 0.00 (randomized decisions)
```

**乘法 vs 加法的本质区别**：

| 假设 | 数学形式 | 推论 | 本文发现 |
|:-----|:---------|:-----|:---------|
| 加法（旧） | margin' = margin + noise | 大 margin 决策安全 | ❌ 错 |
| **乘法（本文）** | margin' = s * margin | 所有决策同比例收缩，大 margin 保护减弱 | ✅ |

**为什么乘法更危险**：加法噪声下大 margin 决策有「保护距离」；乘法收缩下**所有决策的保护距离同比例缩小**——原本 margin=10 的决策收缩到 margin=3（3bit），与原本 margin=3 的决策一样脆弱。**模型自身的 bias 此时接管失败方向**。

## 三、技术框架：从加法假设到乘法定律

```
   old framework (additive noise)      new framework (multiplicative)
   +---------------------+         +---------------------+
   | margin' = margin     |         | margin' = s(w)      |
   |        + noise(w)    |  -->    |        * margin     |
   |                     |         |                     |
   | claim: big margin    |         | claim: ALL margins   |
   | safe, high conf      |         | shrink equally,      |
   | has protection dist  |         | protection shrinks   |
   |                     |         |                     |
   | miss: bench flat =   |         | fix: bench flat !=   |
   |        safe          |         |        safe          |
   +---------------------+         +---------------------+
   | damage: additive ->  |         | damage: multiplicative|
   | independent of margin|         | proportional to margin|
   +---------------------+         +---------------------+
```

**从「噪声大小」到「margin 保护」的范式转移**：
- 加法框架：误差预算按「噪声幅度」分配（哪里噪声大补哪里）。
- 乘法框架：误差预算按「margin 保护需求」分配（哪些决策 margin 会被收缩到危险区，重点保护）。

## 四、量化数据与拟合方法

**实验规模**：

| 维度 | 覆盖 |
|:-----|:-----|
| 模型 | 16 个（8 个模型家族） |
| 量化方法 | 3 种 |
| bit-width | 8 → 2（含 4/3/2 低 bit 区） |
| 预测总数 | 131,758 个决策 |

**拟合方法**：
- 在训练子集上拟合「margin' = s(w) × margin」关系。
- **留出验证**：预测翻转率（拟合未用任何翻转样本）——中位误差 1.8pp。
- **校准性**：逐决策预测翻转概率 vs 实际翻转——ECE 0.004（131,758 预测）。

**关键严谨性**：翻转率预测没有用翻转样本拟合——纯外推预测，误差仍 <2pp → 乘法形式是**结构性规律**而非拟合假象。

## 五、关键发现拆解

| # | 发现 | 证据 | 工程含义 |
|:--|:-----|:-----|:---------|
| 1 | **乘法非加法** | 加法噪声模型在损坏的工具/安全决策上从不胜出 | 误差预算模型要重写 |
| 2 | **收缩因子随 bit 塌缩** | 4bit 0.86 / 3bit 0.33 / 2bit 0.00 | 3bit 是悬崖（margin 砍 2/3） |
| 3 | **损伤有选择性** | 3bit：工具调用塌向不作为，工具选择不受影响 | 行为级失效可预测、可针对 |
| 4 | **常数不可迁移** | 每模型独立拟合 | 部署需 per-model 测量 |
| 5 | **小样本可预测** | 小配对小 margin 集即可预测哪些决策坏 | 免全量生成评估 |
| 6 | **多一个 bit 最便宜** | 成本匹配测试：无修复比加 bit 更划算 | 低 bit 部署的经济账 |

**发现 3 的深层机制**（推断）：工具调用（是否调用）是「接近边界」的决策——基准模型对「调不调」本身 margin 小（倾向性弱），收缩后塌向默认行为（不作为）；工具选择（选哪个）是「远离边界」的决策——margin 大，收缩后仍安全。**选择性损伤 = 决策的原始 margin 分布 + 收缩因子的联合效应**。

## 六、FP4/FP8 生态的直接指导

**FP4/FP8 背景**：FP4 生态从硬件走向软件（08-10 量化三支柱），FP4 作为推理主格式的部署需要「误差预算分配」——本文直接指导：

| FP4/FP8 设计问题 | 本文回答 |
|:-----------------|:---------|
| FP4 哪些层/决策最危险？ | margin 收缩最狠的决策（工具调用类、安全拒绝类）——先测 margin 分布 |
| 混合精度该保护什么？ | 保护「margin 本就不大但关键」的决策路径，而非「噪声大的层」 |
| 如何验收 FP4 部署？ | 基准分数不够——必须测「决策翻转率」（工具调用/安全拒绝的行为级指标） |
| 校准不确定性可用吗？ | 可用——逐决策翻转概率是校准的（ECE 0.004），可做置信度门控 |

**对部署实践的转化**：
1. **验收指标升级**：从「平均精度」到「决策翻转率 + 行为级指标（工具调用率/拒绝率）」。
2. **per-model 测量清单**：部署前用配对小 margin 集测量收缩因子——建立「哪些决策会坏」清单。
3. **混合精度预算**：把 bit 预算花在「关键且 margin 收缩后危险」的决策路径上。
4. **置信度门控**：用校准的翻转概率做运行时降级（预测会翻转 → 走高精度路径）。

## 八、批判性审视

1. **二选一决策的局限**：margin 定义限二选一——真实 agent 是多选/自由生成，推广需扩展定义（top-2 差距近似）。
2. **常数私有的工程负担**：每模型每 bit-width 需配对小 margin 集测量——部署流水线成本增加。
3. **「多一个 bit 最便宜」的边界**：结论基于成本匹配测试——若内存/带宽约束极硬（无法加 bit），仍需其他修复（蒸馏/混合精度）。
4. **行为级指标的测量成本**：工具调用/安全拒绝的行为指标需要 agent 级评估环境——比基准分数贵。
5. **未覆盖训练侧缓解**：量化感知训练（QAT）是否改变乘法常数（让 s(w) 更缓）未讨论——可能的改进方向。
