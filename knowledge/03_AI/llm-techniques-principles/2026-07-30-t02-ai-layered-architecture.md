## 1. 核心架构

对话中提出一种企业组织类比驱动的AI分层架构：

```text
+---------------------------------------------+
|   顶层：少数高性能大模型（高管/总部决策层）    |
|   职责：全局统筹、跨域关联、顶层决策          |
|   输入：结构化摘要、指标Map、结论快照         |
|   输出：综合结论、决策指令                    |
+---------------------------------------------+
|                    ^ 结构化信息流               |
|                    v 按需回调                   |
+---------------------------------------------+
|   底层：大量轻量化小模型（一线执行团队）      |
|   职责：素材解析、信息提取、分类、预处理       |
|   输入：原始数据、用户请求、待处理材料         |
|   输出：结构化摘要、关键指标、风险标记         |
+---------------------------------------------+
```

---

## 2. 信息流规则（四层约束）

| 规则 | 描述 | 违反后果 |
|:-----|:-----|:---------|
| **R1: 不上传原始数据** | 小模型不得将海量原始文本直接向上传递 | 顶层上下文膨胀、注意力稀释 |
| **R2: 标准化输出** | 所有上层信息必须为结构化摘要/指标Map | 顶层推理结果不稳定 |
| **R3: 溯源绑定** | 每一条摘要结论绑定数据源索引ID | 无法深度核验时顶层误判 |
| **R4: 按需下沉** | 顶层存疑时下沉调用原始明细复核 | 底层遗漏关键信息无法发现 |

---

## 3. 架构优势

### 3.1 成本优化

- 大模型推理成本是小模型的 10-100 倍（按参数量估算）
- 通过将 80% 的简单任务分流到小模型，整体运行成本可降低 60-80%

### 3.2 上下文控制

小模型输出的摘要长度通常仅为原始输入的 1/50 到 1/100，顶层模型只需处理浓缩后的关键信息，规避长距离注意力退化问题。

### 3.3 职责解耦

各小模型可以垂直专精：

| 小模型类型 | 专精领域 | 输出物 |
|:-----------|:---------|:-------|
| 文本解析模型 | 文档拆解、关键词提取 | 结构化段落+关键词Map |
| 数据提取模型 | OCR、表格解析 | 结构化数据 |
| 分类模型 | 意图识别、内容分类 | 分类标签+置信度 |
| 摘要模型 | 内容浓缩 | 结构化摘要+关键数据 |

## 4. 最大隐患：摘要信息失真

### 4.1 问题的根源

架构的核心风险与企业的"中层汇报过滤"问题同构：

1. 小模型在提炼摘要时可能**遗漏关键变量**
2. 小模型可能**掩盖异常数据**（无意识行为，由模型"偷懒"倾向导致）
3. 顶层大模型**只依靠摘要做判断，无法察觉缺失信息**

### 4.2 后果量化

| 失真类型 | 底层影响 | 顶层后果 | 严重程度 |
|:---------|:---------|:---------|:---------|
| 遗漏关键限定词 | 如"短期有效"→提炼为"有效" | 错误判断策略持续性 | 🔴 灾难性 |
| 简化矛盾标注 | 两篇文档冲突→被摘要平滑化 | 顶层无感知继续错误推理 | 🔴 灾难性 |
| 丢失异常数据 | 摘要中省略异常指标 | 顶层基于正常数据做判断 | 🟡 严重 |
| 过度概括 | 多个结论合并为笼统陈述 | 顶层信息不足以做决策 | 🟡 严重 |

### 4.3 配套解决方案（架构不可或缺）

1. **标准化输出范式**：强制小模型输出统一结构Map，区分【确定结论】【潜在异常】【存疑内容】【原始素材索引】
2. **溯源链路**：上层结论绑定数据源ID，支持一键下沉
3. **抽样校验**：顶层常态化随机抽取部分任务绕过摘要直接核验原始数据
4. **分级上报**：高风险任务禁止仅上报摘要

## 5. 与现有技术实践的关联

### 5.1 Agent/RAG 体系

当前主流Agent平台正在践行类似思路：

| 实践 | 底层 | 顶层 |
|:-----|:-----|:-----|
| LangChain | 文档分割器、嵌入模型 | 大模型路由+推理 |
| LlamaIndex | 节点解析器、检索器 | 合成查询引擎 |
| AutoGen | 子Agent（执行具体任务） | 主Agent（规划+编排） |

**核心差异**：多数现有方案缺少**强制溯源+摘要质量校验**机制。

### 5.2 与提示词偷懒机制的联动

→ [**T03**](2026-07-30-t03-prompt-laziness-mechanism.md)：底层小模型执行时同样面临"偷懒"问题，需要通过强约束提示词保证摘要质量。

## 6. 完整运行流程

```text
① 用户请求/原始数据 -> 下发至底层集群
② 小模型完成运算 -> 输出结构化摘要+指标Map+风险标记
                      同时保留原始结果并建立索引
③ 汇总信息推送至顶层大模型
④ 大模型基于精简信息开展全局整合、跨域推理
⑤ 当发现信息冲突/不确定/风险超标 -> 通过索引回调原始明细
⑥ 输出综合结论
```
