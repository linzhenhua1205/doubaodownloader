## 1. 结论概要

1. **接口 = 开发者与模型的"合同"**：模型训练完只是权重，被用起来靠六个面——API 形态(怎么调)、参数(怎么调优)、模型信息(怎么选)、论文模型卡(怎么信)、软件适配(怎么接入)、宣传生态(怎么火)。**六面缺一，模型就只是论文里的数字**。
2. **OpenAI 兼容 = 事实标准**：2026 年模型要生存必须兼容 OpenAI API（Chat Completions/Embeddings），Anthropic 兼容是加分项（吃编码代理生态）——**兼容性 = 生态杠杆, 接口即分发渠道**。
3. **工程能力 > 智商**：工具调用(Tool calling)、结构化输出(JSON schema)、长上下文、流式——**决定模型能否被 Agent 集成；集成能力决定实际价值**。
4. **参数三层陷阱**（本库实证）：`ollama run` 参数仅交互会话生效 / OpenAI 兼容端点不解析 num_ctx / temperature 对推理(reasoning)模型基本无效——**参数生效范围因接入方式而异, 必须分层验证**。
5. **双视角总纲**：开发者=把模型做成产品（六面全做）；使用者=把产品用出价值（选对模型/参数/接入、控成本）。

## 2. 接口六面全景

```
①API形态    REST / OpenAI兼容 / Anthropic兼容 / SDK / 流式 / 批量
②参数体系    生成控制 / 上下文 / 工程化 / 推理 / 成本
③模型信息    model id / 上下文窗口 / 知识截止 / license / 路由
④论文模型卡    技术报告 / model card / 架构参数 / 评估基准
⑤软件适配    Ollama / vLLM / 编码代理 / 框架SDK / 云托管
⑥宣传生态    开源License / 榜单 / HF / 框架合作 / 开发者社区
```

## 3. ① API 形态（开发者要建什么 / 使用者怎么选）

### 开发者视角：四件套必做

| 端点 | 用途 | 关键设计 |
|:-----|:-----|:---------|
| `/chat/completions`(OpenAI兼容) | 对话 | **事实标准, 必做** |
| `/embeddings` | 向量化 | RAG 生态刚需 |
| 原生 REST(如 `/api/chat`) | 高级控制 | 暴露模型特有参数 |
| Anthropic 兼容(`/v1/messages`) | 编码代理 | 吃 Claude Code 生态(如 Ollama 已做) |

**进阶设计**：
- **流式(stream)**：SSE 分块输出——交互体验刚需
- **工具调用(tools/tool_choice)**：Agent 集成的前提——**没有它模型进不了 Agent 生态**
- **结构化输出(response_format: json_schema)**：工程落地的前提
- **usage 返回**：prompt/completion tokens + **缓存命中/未命中拆分**（成本可观测性, DeepSeek 用 `deepseek_usage` 固定名）
- **批量端点**：异步批处理, 降价 50% 级

### 使用者视角：选型规则

| 场景 | 选 | 理由 |
|:-----|:---|:-----|
| 通用应用 | OpenAI 兼容 | SDK 生态即插即用 |
| 编码代理 | Anthropic 兼容/本地 | Claude Code/OpenCode 接入 |
| 本地部署 | Ollama 原生 | 一条命令+Modelfile |
| 高吞吐 | 批量端点 | 成本砍半 |
| 隐私 | 本地推理 | 数据不出设备 |

## 4. ② 参数体系（开发者要暴露什么 / 使用者怎么调）

### 参数五族

| 族 | 参数 | 语义 | 使用者建议 |
|:---|:-----|:-----|:-----------|
| **生成控制** | temperature / top_p / top_k / repeat_penalty | 随机性/多样性 | 0.1-0.3 工程任务, 0.7+ 创意 |
| | max_tokens / max_completion_tokens | 输出上限 | 按任务预算, 防截断 |
| | stop / seed | 终止/复现 | seed 用于可复现测试 |
| **上下文** | context_window / num_ctx / num_predict / num_keep | 工作记忆大小 | **显存预算内最大化**(本库 4G 实证) |
| **工程化** | response_format / tools / tool_choice | 结构化/工具 | Agent 集成的开关 |
| **推理** | thinking / reasoning_effort | 推理深度 | **注意: temperature 对推理模型基本无效** |
| **成本** | stream / parallel / cache 控制 | 吞吐/复用 | 缓存命中率是成本胜负手 |

### 参数三层生效陷阱（本库实证, 必读）

| 接入方式 | num_ctx 生效? | temperature? | 结论 |
|:---------|:--------------|:-------------|:-----|
| `ollama run` CLI | ✅ 仅会话 | ✅ | 交互可用, 会话失效 |
| Ollama 原生 API | ✅ 需传 options | ✅ | 必须显式传 |
| OpenAI 兼容端点 | ❌ 不解析 | ⚠️ 部分 | **必须 Modelfile 固化或环境变量** |

**开发者职责**：参数分层文档化（哪些参数在哪种端点生效）、默认值设计（模型默认 temperature 是否合理）、提供模型特有参数透传（reasoningEffort 等）。
**使用者职责**：**先查文档再调参, 先验证再上线**——不要假设参数在任意端点生效。

## 5. ③④ 模型信息与论文模型卡（开发者要写什么 / 使用者怎么信）

### 模型卡(model card)必填八项

| 项 | 内容 | 使用者作用 |
|:---|:-----|:-----------|
| 架构 | 层数/头数/参数量/**激活参数(MoE)** | 推理成本估算 |
| 上下文 | 窗口大小+支持长度 | 任务适配 |
| 训练数据 | 规模/来源/截止 | 知识新鲜度判断 |
| 评估 | 基准分数+**条件** | **防"刷榜式"误判** |
| 量化 | 各档位精度/体积 | 显存选型 |
| License | 商用条款 | 合规判断 |
| 限制 | 已知短板/风险 | 场景规避 |
| 部署 | 推荐硬件/框架 | 落地路径 |

**论文参数要点**：MoE 模型要区分**总参数 vs 激活参数**（如 480B 总参数仅激活部分, 成本按激活算）；评估分数必须看**测试条件**（相同 prompt/温度/基线才有可比性）——**本库铁律: 数据=数值+单位+基线+条件**。

**使用者判断法**：模型卡 = 官方自述（营销属性）→ 用**第三方独立基准**(LMArena 盲测/社区实测)三角验证；排行榜分数 ≠ 你的场景表现——**按自己的任务跑 10 条用例再定夺**。

## 6. ⑤ 软件适配（开发者要铺什么 / 使用者怎么接）

### 适配矩阵（2026 现状）

| 软件 | 模型接入方式 | 开发者要做 | 使用者价值 |
|:-----|:-------------|:-----------|:-----------|
| **Ollama** | 模型库上架+Modelfile | 提交 GGUF/配置 | 一条命令本地跑 |
| **vLLM/TGI** | 服务化部署 | 提供 Safetensors+配置 | 高吞吐生产 |
| **llama.cpp** | GGUF 量化 | 发布量化档位 | 端侧/低配跑 |
| **OpenCode/Claude Code** | Anthropic/OpenAI 兼容 | 兼容 API | 编码代理可用 |
| **LangChain/OpenAI SDK** | OpenAI 兼容 | 兼容即通 | 框架无缝切换 |
| **云托管** | API 服务 | 上线+定价 | 免运维 |

**洞察**：适配的本质 = **"兼容一次, 处处可用"**——模型越兼容，分发渠道越广。Ollama 的 Anthropic 兼容让开源模型进 Claude Code、ollama launch 进 OpenCode——**适配是模型的"渠道铺货"**。

## 7. ⑥ 宣传与生态（开发者要运营什么 / 使用者怎么看）

### 生态运营五动作

| 动作 | 目的 | 案例 |
|:-----|:-----|:-----|
| 开源 License(宽松) | 降低采用门槛 | Meta Llama/Apache 2.0 |
| 榜单参与(LMArena/MMLU) | 建立能力心智 | 各家标配 |
| HF/GitHub 上架 | 分发+star 营销 | star 是信任状 |
| 框架合作(ollama 上架/vLLM 支持) | 渠道铺货 | OpenAI gpt-oss 上 Ollama |
| 开发者社区/文档 | 降低使用摩擦 | 教程/示例/降价 |

### 使用者辨别法（防 star 通胀/刷榜）

- **star 与活跃度脱钩**（本库 MEMORY 实证：AFFiNE 活跃 vs AppFlowy 13 日冰点）→ 看 commit 频率/issue 响应
- 榜单分数看条件 → 独立基准交叉验证
- **"宣传火 ≠ 生态好 ≠ 模型强"**：三层分别验证（营销→集成→实测）

## 8. 双视角行动清单

### 模型开发者（把模型做成产品）

```
① API: OpenAI兼容必做 + 原生REST + 工具调用 + 结构化输出 + usage明细
② 参数: 五族齐全 + 生效范围文档化 + 默认值合理 + 特有参数透传
③ 模型卡: 八项齐全 + 评估条件透明 + 量化档位发布
④ 适配: Ollama/vLLM/GGUF/云托管四通道铺货
⑤ 生态: 开源策略 + 榜单 + 框架合作 + 社区运营
⑥ 可观测: usage 缓存拆分 + 错误码 + 限流文档
```

### 使用者（把产品用出价值）

```
① 选模型: 任务→模型卡→独立基准三角验证 → 自测10条用例
② 选参数: 工程0.1-0.3/创意0.7+ / max_tokens按预算 / 上下文显存内最大化
③ 防陷阱: 参数生效范围先查文档 / 推理模型勿调temperature / Ollama用Modelfile
④ 控成本: 缓存命中率监控 / 批量端点 / 蒸馏降级 / 本地混合
⑤ 工程化: 工具调用+结构化输出+流式 三件套
⑥ 防营销: star≠活跃≠强 / 分数看条件 / 按自己场景验证
```

## 9. 认知贯通

```
接口六面 = 认知全息图的"对外契约":
  模型卡/论文 = 命名(让世界知道你是谁)
  API/参数   = 组合(让世界能调用你)
  软件适配   = 行动(让世界能集成你)
  宣传生态   = 组织(让世界愿意用你)

最深洞察: 模型竞争已从"智商竞赛"转向"接口竞赛"——
  同样的能力, 谁兼容性好/生态广/成本低, 谁赢
  (LangChain 实验实证: 模型没变, Harness 优化追平 53 个百分点差距)
  → 对使用者: 别只比模型智商, 要比"能接进你的系统吗/成本多少/稳不稳"
```

## 10. 一句话总结

> **模型的对外接口是"开发者与模型之间的合同"**——六面(API形态/参数/模型信息/论文模型卡/软件适配/宣传生态)决定模型从"权重"到"产品"的距离。**OpenAI 兼容是入场券、工具调用是 Agent 生态的门票、模型卡透明是信任基础、生态适配是分发渠道**。开发者要做的是"六面全做把模型做成产品"，使用者要做的是"选对模型/调对参数/防住陷阱/控住成本"——**接口竞赛时代, 兼容性=生态杠杆, 工程能力>智商**。
