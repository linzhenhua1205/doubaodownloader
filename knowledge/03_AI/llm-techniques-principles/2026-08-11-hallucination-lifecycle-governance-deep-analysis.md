## 摘要（TL;DR)

**核心命题**：幻觉不是单点问题，是**数据-训练-推理三阶段各自缺陷的累积**。任何只在单阶段治理的方案都会在其他阶段漏气——推理阶段的 RAG 再好，也救不了训练时被 RLHF 奖励黑客固化的错误偏好；训练阶段的 DPO 再强，也补不了数据阶段被重复语料「记忆化」的错误事实。

**三阶段根因一句话**（各自独立、可叠加）：
1. **数据阶段**：模型把「语料中的统计规律」当「事实」——语料有噪声、重复、过时，模型就「记忆」错误统计；
2. **训练阶段**：next-token 目标优化的是「流畅性」不是「事实性」；RLHF 优化的是「人类偏好」不是「真值」——事实正确性从未进入训练目标；
3. **推理阶段**：生成时模型只有「内部记忆」可依，无外部事实锚点；解码随机性 + 上下文冲突 + 注意力稀释使错误被放大输出。

**核心结论**：幻觉治理 = **把「事实性」显式编码进三阶段的每一个环节**——数据阶段过滤错误（预算）、训练阶段把事实性写进目标（防线）、推理阶段用外部锚点+验证回路兜底（兜底）。**推理阶段是投入产出比最高的治理点**（无需重训、可即时生效、可迭代），本系统 CowAgent 优先落地推理层。

**六篇一手论文证据**（2026-08-11 arXiv 抓取验证）：数据去重使记忆化输出降低 10 倍（Lee 2021, ACL 2022）；DPO 以分类损失替代 RLHF 的 RL 训练实现偏好对齐（Rafailov 2023）；CoVe 验证链在 Wikidata/长文生成等任务降低幻觉（Dhuliawala 2023）；SelfCheckGPT 采样一致性黑盒检测优于灰盒方法（Manakul 2023）；生成约束缩放可免训练缓解记忆增强 LLM 幻觉（Kollias 2024）；综合综述确认根因覆盖数据收集→架构→推理全生命周期（Alansari 2025）。

## 一、幻觉定义与分类（第一性原理）

### 1.1 定义

**幻觉（Hallucination）** = 模型生成的**语法流畅、但事实错误或缺乏外部证据支持**的内容（Alansari & Luqman 2025 定义）。

关键：幻觉 ≠ 随机错误。幻觉是**流畅的错误**——它利用模型「语言能力正常」的表象掩盖「事实能力缺失」，因此比明显错误更危险（用户/下游系统默认信任流畅输出）。

### 1.2 分类学（MECE）

| 分类轴 | 类别 | 定义 | 示例 | 对应治理阶段 |
|:-------|:-----|:-----|:-----|:-------------|
| **与源材料的关系** | 内在（Intrinsic）| 输出与提供的上下文/知识源矛盾 | 检索到「A 公司收购 B」，输出「A 被 B 收购」| 推理（冲突管理）|
| | 外在（Extrinsic）| 输出无法从任何给定源验证（编造）| 编造不存在的论文 DOI、引用 | 推理（锚点缺失）|
| **错误性质** | 事实性（Factual）| 与客观事实不符 | 说「巴黎是英国首都」| 数据+训练（知识错误）|
| | 忠实性（Faithfulness）| 与用户意图/上下文不符 | 用户问 A 答 B，答非所问 | 推理（意图对齐）|
| **发生时机** | 记忆型（Memorized）| 训练数据本身错误，模型「忠实记忆」| 训练语料里的错误信息被复述 | **数据阶段** |
| | 泛化型（Generalization）| 训练数据正确，模型错误泛化 | 训练见过 A→B，错误推广到 A'→B' | **训练阶段** |
| | 生成型（Generation）| 解码时随机性/上下文导致错误 | 采样温度高导致事实漂移 | **推理阶段** |

**生命周期视角**（Alansari & Luqman 2025 综述核心框架）：幻觉根因贯穿**数据收集 → 架构设计 → 训练 → 推理**全链路。本报告按用户要求聚焦三阶段：**数据处理 → 训练 → 推理使用**。

### 1.3 统一根因模型

```text
Data quality            Training objective         Inference grounding
 errors/duplicates        fluency vs factuality     no external anchor
      |                         |                         |
      v                         v                         v
  bad statistics        memorized / mis-            generation without
  memorized             generalized parameters      fact check
      |_________________________|_________________________|
                              |
                              v
                      HALLUCINATION OUTPUT
      (three defects multiply: any stage at zero -> correct)
```

三阶段缺陷是**乘性叠加**的：任一阶段为零（完全无缺陷）则输出正确；但实际三阶段都有缺陷，幻觉概率 ≈ 三缺陷的联合。**推理阶段治理是「最后一道闸门」**——即使前两阶段缺陷已固化进权重，推理层仍能拦截大部分输出级错误。

## 二、数据处理阶段：根源是「语料即真相」

### 2.1 产生原因（数据阶段）

| # | 原因 | 机制 | 量化实证 |
|:-:|:-----|:-----|:---------|
| **D1 重复数据（记忆化）** | 语料含大量近重复片段，模型把高频串「背诵」下来，输出时逐字复述 | Lee et al. 2021 发现：C4 中**单个 61 词英文句子重复 60,000+ 次**；训练集存在大量近重复样本和长重复子串 | **>1% 的无提示输出逐字复制自训练数据**；去重后记忆化输出降低 **10 倍**（ACL 2022）|
| **D2 噪声/错误标注** | 网络语料本身含错误事实、过期信息、恶意内容；自动化标注（如蒸馏标签）传播误差 | 模型无法区分「语料里的断言」与「真实事实」——它学的就是统计分布，不是真值 | 综合综述确认：数据噪声是幻觉首要根因（Alansari 2025）|
| **D3 分布偏差** | 语料对某些领域/群体/表述方式过度或不足代表 → 低频真实事实被高频错误替代 | 模型对高频分布的「先验偏好」压过低频正确信息 | — |
| **D4 知识截止/过时** | 训练时点之后的事实模型不知道，但模型不「知道它不知道」→ 用旧知识答新问题 | 参数化知识的时效性硬约束（姊妹篇《参数化 vs 上下文》§4.1.1：权重固化于训练期）| — |
| **D5 测试污染** | 测试/基准数据混入训练集 → 评估虚高，掩盖真实幻觉率 | train-test overlap 影响标准数据集 **>4%** 的验证集（Lee 2021）| — |

### 2.2 应对策略与具体方法（数据阶段）

| 策略 | 具体方法 | 原理 | 量化目标 |
|:-----|:---------|:-----|:---------|
| **去重** | ① 精确去重（exact match）② 近重复去重（MinHash / SimHash / 模糊匹配）③ 长重复子串检测；Lee et al. 开源工具可处理 C4 规模 | 删除高频串，防止「背诵」；同时降低 train-test overlap 使评估可信 | 记忆化输出 -10×；overlap <1% |
| **质量过滤** | ① 规则过滤（长度/语言/毒性）② 分类器过滤（质量模型打分，如 Gopher/Chinchilla 质量启发式）③ 嵌入相似度去低质簇 | 提高语料信噪比，减少 D2 | 按领域设定质量阈值（如 perplexity 分位数）|
| **事实验证标注** | 对事实密集型语料做知识抽取 + 外部源（维基/权威库）核对，错误断言剔除或修正 | 把「语料断言」升级为「已验证事实」再入训练 | 事实断言准确率 >95%（按领域）|
| **时效管理** | 语料加时间戳；过期知识降权或移出；建立「知识截止」声明 | 让模型对「新事实」的盲区显式化（配合推理层 RAG 补新）| 截止日期后事实不要求模型知道 |
| **分布校准** | 领域采样配比优化（低资源领域过采样）；多语言均衡 | 减少 D3 偏差导致的系统性错误 | 按任务分布设定采样权重 |
| **数据溯源登记** | 每条训练样本记录来源（URL/批次/时间）——幻觉溯源时能定位「这个错误是哪条数据教的」| 为训练后治理（知识编辑）提供索引 | 全量样本可溯源 |

> **数据阶段的本质**：**输入侧防御（预算）**。它不消除训练/推理缺陷，但把「错误统计被记忆」的概率降到最低。**成本最高、见效最慢**（影响数月后的下一版模型），但对高频重复性幻觉的根治最彻底。

## 三、训练阶段：根源是「优化目标与事实解耦」

### 3.1 产生原因（训练阶段）

| # | 原因 | 机制 | 关键点 |
|:-:|:-----|:-----|:-------|
| **T1 目标函数与事实解耦** | 预训练优化 next-token prediction——目标是「预测下一个词」，不是「说真话」；流畅性高 ≠ 事实性高 | 模型学到的是语料分布 P(w)，不是世界模型 Truth(w)；两者在多数 token 上重合，在事实边界处分离 | 这是训练阶段幻觉的**第一性根源** |
| **T2 容量压缩损失** | 模型参数容量有限，数万亿 token 压缩进千亿参数必然丢信息；低频细节最容易被压缩掉 | 信息瓶颈（姊妹篇《参数化 vs 上下文》§4.1.1：D_param ≈ 10⁸~10⁹ 加工次数仍不够）| 容量越大幻觉越低（有规模曲线）|
| **T3 RLHF 奖励黑客** | RLHF 优化「人类偏好得分」而非「事实正确」；模型学会迎合偏好（流畅、自信、迎合用户）而非求真 | 奖励模型本身可能偏好「听起来对」而非「是对的」；PPO 训练不稳定加剧 | 奖励模型是第二层幻觉源 |
| **T4 蒸馏误差传播** | 教师模型幻觉 → 学生蒸馏时「学错」；且蒸馏抹平不确定性（学生更自信）| 错误通过蒸馏链路放大（呼应语料库篇 r^L 失真模型）| 蒸馏层数越多误差越大 |
| **T5 知识冲突内化** | 参数知识与新训练数据冲突时，模型倾向保留旧偏好（over-reliance on memorized info, Longpre 2021）| 权重更新无法「定点」修正（除非知识编辑）| 与推理层冲突管理同源（姊妹篇 §5.3）|

### 3.2 应对策略与具体方法（训练阶段）

| 策略 | 具体方法 | 原理 | 量化/实证 |
|:-----|:---------|:-----|:----------|
| **事实性纳入偏好优化（DPO/RLHF with factuality reward）** | ① 偏好数据构建：同一 prompt 采样多个回答，人工/自动标注「事实正确 vs 事实错误」对；② DPO 直接以分类损失对齐偏好（Rafailov 2023）——比 PPO-RLHF 稳定、轻量 | 把「事实正确」作为偏好信号写进训练目标 | DPO 在 sentiment/summarization/dialogue 匹配或超过 PPO-RLHF（arXiv:2305.18290）|
| **事实验证 SFT** | 用「检索增强的正确答案」微调（把 RAG 结果当 SFT 目标）；错误答案作负样本 | 让模型见过「正确的事实锚定回答」长什么样 | 指令微调阶段注入事实语料 |
| **校准训练（学会说不知道）** | ① 训练「拒答」行为：低置信问题回答「我不知道/无法确认」② 不确定性校准（token 概率校准到置信度）③ RLHF 奖励「诚实拒答」而非「强行回答」| 把「不知道」从失败变成受奖励行为 | 拒答率与准确率联合优化 |
| **知识编辑（定点修正）** | ROME/MEMIT：因果定位事实所在的中间层 FFN 低秩子空间 → rank-one 改写（姊妹篇 §5.5 已展开：<100 条高置信事实秒级修正，同时保持 specificity/generalization）| 训练后**手术级**修正，不需重训 | ROME 在 zsRE 任务有效，counterfactual 数据集同时保持 specificity+generalization（arXiv:2202.05262）|
| **蒸馏防传播** | ① 教师模型先做幻觉过滤再蒸馏 ② 学生蒸馏时对教师低置信输出降权 ③ 蒸馏 + 事实验证混合 | 切断 T4 错误传播链 | 蒸馏层数受控（r^L 模型：r=0.9,L=3 → 保真 0.73）|
| **训练数据溯源联动** | 训练后出现幻觉 → 回溯到 T1 源头数据 → 修正数据 → 知识编辑定点改 | 数据-训练-推理三阶段闭环 | — |

> **训练阶段的本质**：**中间防线**。它把「事实性」写进模型的行为偏好（DPO）和参数（知识编辑）。成本高（需训练/微调）、见效慢（需重训周期），但解决的是「系统性、结构化」幻觉——**模型对某类知识的整体错误认知**。

## 四、推理使用阶段：根源是「生成时无事实锚点」

### 4.1 产生原因（推理阶段）

| # | 原因 | 机制 | 关键点 |
|:-:|:-----|:-----|:-------|
| **I1 解码随机性** | 采样温度/top-p 引入随机性 → 在事实边界处「随机漂移」到错误分支 | 模型对事实有概率分布，采样落在非最高概率（但可能错误）的分支 | 温度越高幻觉越多（有实测曲线）|
| **I2 上下文知识冲突** | 上下文与参数知识冲突时，模型过度依赖记忆（over-reliance），上下文被「视而不见」| Longpre 2021 实证：OOD 泛化仅靠显式缓解提升 4-7%（姊妹篇 §3.2 实证 B）| 权重知识的 logits 更「稳定」（低方差），上下文注入的 logits 更「脆弱」|
| **I3 注意力稀释/位置效应** | 长上下文导致关键信息注意力摊薄（分母竞争 1/n）；中间位置信息利用最差（Lost in the Middle）| 姊妹篇《大文件深度解读》§3.4 已推导：softmax 归一化 Σw=1 → 单 token 权重期望 1/n | 30K tokens 前后 2 份占 80%+ 注意力 |
| **I4 检索注入噪声** | RAG 检索到无关/低质/错误片段 → 模型「引用错误源」| 检索相关性不完美 + 注入量失控（倒U：L > L* 后质量下降）| 注入量与质量倒U（姊妹篇倒U文档）|
| **I5 提示诱导** | 引导性提问（leading question）、预设错误前提（"为什么 X 是 Y？" 当 X 不是 Y 时）| 模型顺从用户预设，不纠正错误前提 | 权威性不对称（用户 vs 模型）|
| **I6 无外部验证回路** | 单次前向生成，无「生成后校验」——错了就是错了，没有自纠机制 | 与训练阶段「多次迭代」形成对比（姊妹篇 §4.1.1：上下文只有 10² 加工次数）| 这正是推理层可治的空间 |

### 4.2 应对策略与具体方法（推理阶段）

| 策略 | 具体方法 | 原理 | 量化/实证 |
|:-----|:---------|:-----|:----------|
| **验证链 CoVe（Chain-of-Verification）** | 四步：① 起草初始回答 ② 规划验证问题（fact-check 自己的草稿）③ **独立回答**验证问题（不让草稿 bias）④ 生成最终修正回答 | 把「单次生成」变成「生成-验证-修正」回路；独立回答是关键（避免 confirmation bias）| CoVe 在 Wikidata 列表题/MultiSpanQA/长文生成降低幻觉（arXiv:2309.11495）|
| **采样一致性检测 SelfCheckGPT** | 对同一 prompt 采样 N 个回答 → 逐句检查 N 个回答间一致性 → 不一致句标记为疑似幻觉 | 事实是有「共识」的——真知识采样多次会一致，幻觉会互相矛盾 | WikiBio 上 AUC-PR 显著高于灰盒方法（arXiv:2303.08896）|
| **自一致性（Self-Consistency）** | 采样 N 个 CoT 路径 → 多数投票取最终答案 | 多数路径 = 模型最稳定的知识通路 | 推理准确率提升（CoT 系列实证）|
| **解码约束** | ① 低温度（≤0.3）用于事实型任务 ② 约束解码（事实三元组约束生成）③ 生成约束缩放：缩放记忆增强 LLM 的 readout 向量即可免训练缓解幻觉 | 减少解码随机性漂移；几何启发式约束生成 | 约束缩放优于 SOTA 知识编辑方法，且训练-free（arXiv:2407.16908）|
| **RAG 治理** | ① 检索精化（更小 chunk/更高阈值/去重）② 注入量控制（≤ 0.3×有效上下文，倒U 曲线 L≤L*）③ 关键信息前置（避中间盲区）④ 显式引用（grounding：标注来源段落）⑤ 冲突仲裁（双通道：纯权重答案 vs 纯材料答案 → 显式比较）| 提高外部锚点的质量；把「隐式冲突」变「显式仲裁」（姊妹篇 §5.3 协议）| 冲突场景材料采信率翻倍目标（P6 验证中）|
| **认知工程（复述-批判-引用）** | S1 复述材料（验证读懂了）→ S2 批判断言（来源/冲突/时效）→ S3 只让通过检查的断言进推理 | 强制「组织语义」而非「模式复制」（姊妹篇 §5.6 协议）| 结论可追溯 |
| **置信度阈值 + 拒答** | ① token 级不确定性（熵/概率）阈值 ② 答案级自评置信（SelfCheckGPT 分数）③ 低于阈值 → 「无法确认」+ 建议查证 | 把「不确定」显式化，不强行输出 | 与训练层校准训练联动 |
| **事实锚点注入（工具/外部源）** | 生成前先查证（检索/API/计算器）；生成中允许工具调用（ReAct）；生成后链接外部源验证 | 把「记忆」换成「查询」——事实来自外部锚点而非参数 | 工具可及的任务幻觉显著下降 |

> **推理阶段的本质**：**输出侧兜底**。它不需要重训、可即时生效、可随反馈迭代，是**投入产出比最高的治理点**。但它**不根治**数据/训练缺陷——只能拦截「输出级」错误，无法修复「参数级」错误认知（那是知识编辑/重训的职责）。

## 五、三阶段协同：预算-防线-兜底

```text
   Data Stage (budget)       Train Stage (defense)      Inference Stage (net)
  ______________________   ______________________   ______________________
 | dedup / filter /     | | DPO / calibration /   | | CoVe / SelfCheck /  |
 | verify                | | knowledge edit        | | RAG / abstain /     |
 | reduce bad stats     | | factuality in target  | | anchor               |
 | memorization         | | fix systematic errors | | intercept output     |
 |______________________| |______________________| |______________________|
      affects next model         affects next model        immediate
      cures high-freq dup        cures systematic          intercepts
      errors                     errors                    output errors
      highest cost / slowest     mid cost / mid            lowest cost / fastest
```

**协同原则**：
1. **越靠前越根治，越靠后越便宜**——理想是数据+训练根治，现实是推理兜底（重训周期长、成本高，推理层当天可部署）；
2. **三阶段不是替代关系**：推理层拦截不了「参数级系统性错误」（模型坚信 1+1=3 时，CoVe 验证链也会自信地验证错误）；训练层也补不了「新事实」（模型没学过 2026 年新闻，DPO 也无法让它知道）；
3. **推荐组合**（本系统实践）：`推理层 RAG 治理 + CoVe 验证 + 知识冲突仲裁` 为 P0 即时落地；`高频知识蒸馏/内化` 为 P1 中期；`数据质量审计` 为 P2 长期（影响下版模型）。

## 风险与边界

- **推理层治理不根治参数级错误**：模型系统性认知错误时，CoVe 的「独立验证」也会错（验证者也错）——需多源交叉验证兜底；
- **治理有成本**：CoVe 多 2-4 次前向、SelfCheckGPT 多 N 次采样、RAG 增加检索延迟——**只用于高风险任务**，例行任务直接生成（质量-成本权衡）；
- **拒答策略双刃剑**：过度拒答降低可用性（把「不确定」当「不知道」）——需校准阈值，配合「给依据+建议查证」而非裸拒答；
- **数据去重不解决所有问题**：去重治「记忆化」，不治「泛化错误」——噪声语料即使去重后仍是噪声；
- **知识编辑副作用**：>100 条编辑后 specificity/generalization 可能崩溃（姊妹篇 §5.5）——大数量走 LoRA；
- **DPO 依赖偏好数据质量**：偏好标注本身错误时，DPO 固化错误偏好（奖励模型是第二层幻觉源）——偏好数据需事实验证；
- **网络受限说明**：本报告 6 篇关键论文摘要均经 arXiv 一手抓取验证（2026-08-11），其余引用为本知识库已验证姊妹篇与经典文献。
