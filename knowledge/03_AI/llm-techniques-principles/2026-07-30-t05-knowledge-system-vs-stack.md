## 1. 核心命题

对话中提出两个关键论断：

1. **知识 ≠ 知识系统**——零散知识是原材料，知识系统是工艺流程，只有系统才能实现普惠
2. **前置加工 ≠ 场景化后加工**——基座决定下限，后加工决定上限

---

## 2. 知识 vs 知识系统

### 2.1 根本差异

```text
堆砌知识库（仅有原材料）:
  文档/资料/素材 -> 存入向量库 -> 用户自行检索 -> 效果靠运气

知识系统（建设完整体系）:
  结构化知识库 + 检索策略 + 调用规则 + 输出约束 + 分工流程
  -> 用户只需提出业务诉求 -> 系统自动完成所有复杂操作
```

### 2.2 普惠的本质

> 普惠 = 降低普通人使用知识的门槛

- 使用者不需要精通提示词、注意力机制、模型约束
- 系统内置上下文规范、摘要范式、校验逻辑、任务分发
- 复杂的调参与信息筛选全部封装在系统内部

### 2.3 现实鸿沟

| 层次 | 堆砌方式 | 系统化方式 |
|:-----|:---------|:-----------|
| 存储 | 文档直接存入向量库 | 知识分类+实体关系+时效管理 |
| 检索 | 单纯向量相似度检索 | 多策略路由（关键词+语义+规则混合） |
| 调用 | 用户自行写提示词 | 标准化Skill调用+约束自动注入 |
| 校验 | 无 | 溯源链+抽样校验+冲突检测 |
| 迭代 | 靠人工 | 案例复盘→Skill优化→自动化闭环 |

## 3. 前置加工 vs 后场景化加工

### 3.1 前置加工（模型/基座层面）

代表路线：多模态预训练、基座模型能力塑造、底层表征优化

| 特点 | 描述 |
|:-----|:------|
| 定位 | 通用能力建设，打造智能底座 |
| 投入 | 极高（百亿级参数训练，万卡集群） |
| 技术门槛 | 高度集中（少量巨头、实验室） |
| 产出特征 | 广谱但无场景偏好 |
| 交付形态 | 裸模型通过API输出，直接使用效果不佳 |

### 3.2 后场景化加工（应用层面）

代表路线：基于成品模型底座，面向垂直领域二次工程化塑造

| 维度 | 内容 |
|:-----|:------|
| 提示词 | 领域专属规范、上下文传递标准 |
| 知识调度 | 分片、摘要生成标准、大小模型分层调度 |
| 质量保障 | 行业输出模板、校验规则、异常回溯 |
| 封装 | 标准化Skill+自动化工作流 |

### 3.3 核心认知

> 基座解决"模型能不能看懂、能不能推理"
> 场景后加工解决"模型能不能按照行业要求稳定、合规、高质量输出"

同一套基座：

- 不加场景适配 → 输出飘忽、偷懒、深度不足
- 经过场景层二次约束 → 稳定性、可用性量级提升

## 4. 商业与落地关系

```text
前置基座研发
  +-- 底层供给，基础设施
  +-- 适合巨头、顶级实验室
  +-- 技术红利有限，长期可被开源稀释

场景化后加工
  +-- 价值变现层，普惠落地层
  +-- 大量中小企业、解决方案商的主战场
  +-- 场景知识+业务流程+交付标准不可通用复制
      -> 长期稀缺能力
```

> **延伸判断**：很多团队本末倒置，一味追求自研底层模型，忽视应用层系统建设。最终底座完成了，缺少场景化流程，产品上线体验参差不齐。底座是下限，场景化知识应用系统决定产品最终上限。

---

## 5. 与分层架构的完整闭环

→ [**T02**](2026-07-30-t02-ai-layered-architecture.md)

我们之前讨论的所有结论形成完整闭环：

1. 模型天然偷懒 → 输出依赖输入上下文和显式约束
2. 单一模型成本高 → 最优架构是大小模型分层
3. 分层架构稳定运行 → 需要固化为知识调度系统
4. 基座提供基础智力 → 场景后加工决定产品最终上限
