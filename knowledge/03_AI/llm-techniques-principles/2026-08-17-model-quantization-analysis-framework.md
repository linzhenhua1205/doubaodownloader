## 1. 一句话结论

**量化的本质是信息论工程妥协：用最少比特保留权重中真正影响输出的信息。** 方案分水岭不在比特数（INT4/INT8），而在三个决策点：**谁决定舍入（权重 vs 激活）、如何补偿误差（逐层 vs 逐通道 vs 逐组）、何时量化（PTQ vs QAT）**。论文一手证据表明：**AWQ 的"保护 1% 显著权重"理论**是理解所有量化方案差异的钥匙 [1]。8G 显存部署：7B INT4 是甜点区（权重 ~4GB），方案排序 **AWQ > GPTQ > GGUF**，引擎 llama.cpp/vLLM 二选一。铁律：**评估看下游任务精度不看 PPL，embedding/lm_head 保 FP16 是底线**。

## 2. 量化第一性原理（信息论视角）

### 2.1 权重为什么能压缩


> FP16 权重 W ∈ R^(d×d)：16 bit/值，但真实信息量远低于 16 bit
> 原因：① 相邻权重相关（低秩结构）② 分布近似高斯（集中均值附近）③ LLM 过参数化对扰动鲁棒
>
> 量化 = k bit 格点近似：W_q = round(W/s)×s + z（s=缩放因子, z=零点）


**核心洞察：量化误差的度量单位是「输出扰动」‖W·x − W_q·x‖，不是「权重偏差」‖W − W_q‖。** 所有高级量化方案都在回答同一问题：**如何用最小比特预算最小化最终输出的扰动？**

### 2.2 误差放大路径


> W_q = W + ε；输出 (W+ε)·x = W·x + ε·x
> ε·x 随网络深度累积（LLM 数百层逐层传递）
> → 关键层（注意力头/FFN 首层）误差放大比非关键层致命
> → 混合精度量化的理论依据


**推论**：方案优劣 = 对「哪些权重/通道/层对输出扰动最大」的感知能力。这是 GPTQ/AWQ/GGUF 差异的本质。

### 2.3 输出扰动的分解（谁在主导误差）


> ‖W·x − W_q·x‖ ≈ Σ_channel |x_i| × |W_i − W_q,i|   （忽略交叉项）
> → 误差 = 权重误差 × 激活幅值
> → 两个优化抓手:
>    ① 减小权重误差（GPTQ: Hessian 补偿）
>    ② 保护大激活通道（AWQ: 缩放）—— 激活幅值大 → 误差权重高


> 这正是 AWQ "看激活分布而非权重"的第一性推导基础（见 §5）。

## 3. 方案谱系（MECE 分类）

### 3.1 按时机：PTQ vs QAT

| | PTQ（训练后量化） | QAT（量化感知训练） |
|:--|:--|:--|
| 流程 | 成品模型 + 少量校准数据离线量化 | 训练/微调中模拟量化误差 |
| 校准数据 | 需要（几百条，决定质量） | 不需要 |
| 成本 | 低（GPU 小时级） | 高（重训/微调） |
| 质量 | 好（GPTQ/AWQ 类算法） | 上限最高 |
| 适用 | **部署量化主流** | QLoRA 微调等特殊场景 |

### 3.2 按对象：权重量化 vs 权重+激活量化

| | W-only（如 W4A16） | W&A（如 W8A8） |
|:--|:--|:--|
| 难度 | 低（只动静态权重） | 高（激活逐 token 变化，需动态缩放） |
| 引擎 | 通用（llama.cpp/Transformers） | 专用内核（TRT-LLM/vLLM FP8） |
| 提速 | 中（省显存为主） | 高（激活搬运减半） |
| 代表 | GPTQ/AWQ/GGUF | TensorRT-LLM/vLLM FP8 |

**判断**：8G 显存瓶颈是容量不是速度 → W-only 足够；服务器高吞吐才需 W&A。

### 3.3 按粒度：逐层 vs 逐通道 vs 逐组（关键！）


> 逐层（per-tensor）：整层一个缩放因子，粗粒度，误差大
> 逐通道（per-channel）：每输出通道一个缩放，INT8 标配
> 逐组（per-group）：每 g=128 个权重一组，INT4 标配


**第一性原理**：权重分布不均匀——少数大权重（outlier）主导输出。**分组量化 = 在「粒度过细撑爆缩放开销」与「粒度过粗误差大」之间取最优**，g=128 是主流平衡点。

## 4. 三大主流 PTQ 方案深度对比

| 维度 | GPTQ | AWQ | GGUF (llama.cpp) |
|:-----|:-----|:-----|:-----------------|
| 算法本质 | **逐层误差最小化**：二阶 Hessian（OBS 近似）迭代补偿 | **激活感知缩放**：保护激活值大的通道 | 分块量化 + 混合精度（k-quants）+ 格式封装 |
| 误差补偿 | 迭代式（量化一个权重即更新其余补偿） | 静态缩放（×缩放因子保护 outlier） | 无迭代补偿（靠块内混合精度） |
| 校准数据 | 需要（Hessian 估计） | 需要（激活统计） | 需要（少数即可） |
| 推理速度 | 快 | **最快**（GPU 友好） | 中（CPU 优化好） |
| 质量 | 好（理论最严谨） | **最好**（论文实证常优于 GPTQ） | 好（取决于 k-quants 配置） |
| 硬件适配 | GPU（CUDA） | GPU（CUDA/ROCm） | **CPU+GPU 混合（最广）** |
| 生态 | HF 原生、vLLM/TRT-LLM | vLLM/TRT-LLM/llama.cpp | llama.cpp/Ollama/Jan 本地全家桶 |
| 典型配置 | W4A16 (g=128) | W4A16 (g=128) | Q4_K_M（混合精度） |

**本质差异**：


> GPTQ：全局最优视角——"量化这个权重扰动多少输出？Hessian 估，然后补偿"
>      → 数学最严谨，依赖 Hessian 近似质量，校准数据敏感
> AWQ：局部保护视角——"哪些通道激活大（重要）？给更大缩放因子"
>      → 一次缩放、无需迭代，简单且实证更稳（论文原文：no backpropagation or reconstruction [1]）
> GGUF：工程封装视角——"量化权重+tokenizer+元数据打成单文件，每层可选不同比特"
>      → 非算法创新，是"混合精度配置 + 格式标准化"的胜利

## 5. AWQ 论文深度剖析：1% 显著权重理论（一手数据）

### 5.1 核心发现（论文原文）[1]

> "AWQ finds that **not all weights in an LLM are equally important**. Protecting only **1% salient weights** can greatly reduce quantization error. To identify salient weight channels, we should refer to the **activation distribution, not weights**."

**翻译**：不是所有权重同等重要——**保护 1% 的显著权重就能大幅降低量化误差**；识别显著通道要看**激活分布**而非权重本身。

### 5.2 数学机制：等效变换（无需混合精度）


> 问题: 显著通道需要高精度（混合精度）→ 硬件不友好
> AWQ 解法: 数学推导证明"放大显著通道可降低量化误差"
>   W' = W × s（显著通道乘缩放因子 s）
>   W'_q = quant(W × s)，反量化时除以 s 恢复
>   → 等效于给显著通道更高分辨率，但硬件仍是统一精度 ✅


**例子**：某通道权重幅值 [0.1, 0.5, 2.0, 3.5]，激活幅值 [0.8, 0.9, **5.2**, **6.1**]：

> 通道 3/4 激活大 → 误差权重高（见 §2.3 分解式）
> 给通道 3/4 乘 s=2 后再量化:
>   [0.1, 0.5, 4.0, 7.0] → INT4 格点误差相对值更小
>   反量化 /2 → 显著通道精度提升，非显著通道略损
> → 总输出扰动下降（论文实证）


### 5.3 关键优势（论文原文）[1]

| 优势 | 说明 |
|:-----|:-----|
| **无需反向传播/重建** | 纯激活统计 → 计算快、不过拟合校准集 |
| **泛化到不同领域/模态** | 不依赖校准集过拟合 → 代码/数学/指令微调/多模态首次支持 |
| **硬件友好** | 统一精度（无混合精度）→ 直接上专用内核 |
| **配套 TinyChat** | 高效灵活的推理实现（论文附带） |

### 5.4 论文局限

- 摘要未给具体 PPL/精度数字（需读正文）
- 缩放因子 s 的选取是启发式（激活统计），最优性无理论保证
- 相比 GPTQ 的迭代补偿，AWQ 对极端 outlier 分布的保护有限

## 6. 量化效果评估

### 6.1 指标

| 指标 | 含义 | 适用 |
|:-----|:-----|:-----|
| PPL（困惑度） | 测试集负对数似然 | 语言流畅性（**不足以单独决策**） |
| 任务精度（MMLU/GSM8K 等） | 下游任务正确率 | **真实能力（推荐）** |
| 显存/速度 | 部署占用与吞吐 | 放得下、跑得快 |

### 6.2 必测清单（量化前后对比）


> ① 同一测试集：FP16 基线 vs INT4 的 PPL/精度差（PPL 退化 <0.5 可接受）
> ② 长上下文：量化后 KV cache 复用质量（注意力退化测试）
> ③ 关键层检查：embedding/lm_head 是否保 FP16（很多方案默认做，需确认）
> ④ 边界测试：代码/数学/中文生僻词（量化最易暴露退化的场景）


**警告**：PPL 下降 ≠ 任务精度不变（推理类任务退化 > 语言建模类）——**评估必须看下游任务**。已有 llama.cpp 文档实证：不同量化格式在不同任务退化不一致（IFEval 敏感、MMLU 缓），无法从 PPL 预测退化模式。

## 7. 落地实操：8G 显存跑 7B INT4

### 7.1 显存预算（第一性原理）


> 7B 模型：
>   FP16 权重      = 7B × 2B = ~14 GB   ❌ 8G 装不下
>   INT4 权重      = 7B × 0.5B = ~3.5-4 GB ✅
>   KV cache(4K)  ≈ 0.5-1 GB
>   激活/临时缓冲   ≈ 1-2 GB
>   → INT4 总量 ~6-7 GB，8G 勉强放下（余量小）
>   → 建议 INT4 + 上下文 ≤8K；更大需 GGUF 部分 CPU offload（--n-gpu-layers）


**结论**：7B INT4 是 8G 显存极限甜点区。想更长上下文/更大模型 → GGUF + CPU offload 或降级 3B/4B。

### 7.2 方案选择建议

| 需求 | 推荐 | 理由 |
|:-----|:-----|:-----|
| 纯本地 + CPU/GPU 混合 + 跨平台 | **GGUF Q4_K_M + llama.cpp/Ollama** | 兼容性最好、支持 offload、社区活跃 |
| GPU 优先 + 追求质量 | **AWQ + vLLM** | 同比特质量最优（论文实证 [1]）、吞吐高 |
| HF 生态 + 快速验证 | GPTQ + Transformers/TRT-LLM | 生态成熟、教程多 |
| 服务器多卡/生产 | FP8 (W8A8) + TensorRT-LLM | 精度损失小、吞吐高 |

**5060 8G 推荐**：**GGUF Q4_K_M（llama.cpp/Ollama）起步 + AWQ 备选**——先保证能跑通，质量不满意再试 AWQ。

### 7.3 常见坑

1. **显存超卖**：权重算对了但激活/上下文暴涨 → OOM。解法：固定 max context + 流式输出
2. **只看 PPL**：PPL 没差但任务崩。解法：必跑下游任务实测
3. **引擎差异**：同一 GGUF 在不同引擎 kernel 不同，速度差 2×。解法：实测为准
4. **校准数据错配**：中文模型用英文校准集 → 中文退化。校准数据要贴合实际使用语言/领域
5. **显著通道保护缺失**：用不支持激活感知的方案（如朴素 round-to-nearest）量化激活敏感模型 → 用 AWQ 类方案或提升分组粒度
