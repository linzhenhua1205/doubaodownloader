## §0 执行摘要

**Agent 的产出上限不由模型单独决定，而由三个变量共同决定：模型能力（算力底座）、知识接入（Agent 能拿到什么信息）、知识机制（团队如何保证知识的质量与可调用性）。当模型能力越过基本门槛后——这个门槛今天已经很低——前两个变量中"知识接入"和第三个变量"知识机制"成为主导，模型退化为同质化商品。** [来源: 本文推导]

三个核心判断：

1. **模型是同质化的，知识是差异化的**：前端模型（GPT-4o 级 / Claude 级 / DeepSeek 级）在通用任务上的能力差距持续收窄，而每个团队的领域知识（排障案例、设计决策、踩坑教训）天然不可复制。**同样的模型，喂给它"通用互联网知识"和喂给它"团队十年沉淀"，产出是两个物种** [来源: 本文推导 + §2.4]。

2. **知识决定上限的五个机制**：感知带宽（检索可达）、记忆容量（组织记忆体外化）、推理起点（复利效应）、判断依据（质量门禁）、行为约束（方法论封装）——五个机制分别对应认知五维的增强路径 [来源: 本文 §3 + 认知目的篇 §2]。

3. **本系统 100+ 天实证**：同一个模型（deepseek-v4-flash）在"裸对话态"下产出的是泛泛而谈，在"全平台态"（3800+ 文件知识库 + 106 技能 + 79 脚本 + 门禁体系）下产出的是可验证的深度分析——**同一算力，上限差了一个数量级**。这一实证直接把结论钉死：Agent 的上限在团队知识，不在模型 [来源: 本文 §4]。

**一句话**：模型决定 Agent 的"下限不低"，团队知识决定 Agent 的"上限多高"。**在模型能力已商品化的 2026 年，团队知识是 Agent 能力唯一的差异化杠杆** [来源: 本文推导]。

## §1 命题拆解：三个变量，谁决定上限

### 1.1 "上限"指什么：产出质量的上限而非能力的上限

先把命题中的"上限"精确定义，避免歧义 [来源: 本文推导]：

| 解读 | 定义 | 是否本文讨论对象 |
|:-----|:-----|:----------------|
| 能力上限 | 模型能做什么（benchmark 分数） | ❌ 由模型决定 |
| **产出上限** | Agent 在真实业务中交付的质量 | ✅ **本文讨论对象** |
| 效率上限 | 单位成本/时间内的产出 | ✅ 附带讨论 |

**关键区分**：模型决定的是"能力天花板"（benchmark 可测），但真实业务中**能力天花板极少被触达**——Agent 实际产出的质量被"信息可得性、任务定义清晰度、知识质量"这些非模型因素卡住。**绝大多数 Agent 失败案例不是模型不会，而是没拿到该拿的知识、没有可依据的判断标准** [来源: 本文推导 + 半任务陷阱篇]。

### 1.2 三变量模型：Agent 产出 = f(模型 × 知识接入 × 知识机制)

把命题形式化为三变量乘积模型 [来源: 本文推导]：

```text
Agent Output Ceiling = Model Capability x Knowledge Access x Knowledge Mechanism

Model:            base reasoning/generation ability (same for all users)
Knowledge Access: what info the agent can retrieve (differs by team)
Knowledge Mechanism: how knowledge is processed/gated/packaged (differs by team)
```

| 变量 | 决定什么 | 团队可控性 | 2026 年现状 |
|:-----|:---------|:----------:|:-----------|
| 模型能力 | 推理深度、语言质量、指令遵循 | 低（选型可控制） | 同质化，差距收窄 |
| 知识接入 | Agent 的感知带宽、记忆容量、推理起点 | 高 | 多数团队 ≈ 0（没有库） |
| 知识机制 | 知识的可信度、可检索性、可复用性 | 高 | 多数团队 ≈ 0（有库无管） |

**乘积结构的含义**：三变量是**乘法**不是加法——任何一个变量为 0，产出上限就是 0。团队没建知识库（接入=0），模型再强，Agent 也只是"记忆力好的对话机器人"；团队有库无机制（机制=0），Agent 会检索到垃圾并自信地输出垃圾 [来源: 本文推导]。

### 1.3 模型变量为什么正在退化为常量

模型变量从"主导变量"退化为"常量"的三个趋势 [来源: 本文推导 + 行业观察]：

1. **能力趋同**：开源/闭源模型在通用基准上的差距持续收窄（Claude/GPT/DeepSeek 在 SWE-bench Verified 上的差距从数量级缩小到个位数百分比）；对大多数业务任务，模型选型已不构成产出质量的瓶颈 [来源: 行业公开基准，2025-2026 趋势]。

2. **成本趋零**：API 价格持续下降（flash 级模型输入已低至 $1/M token 量级），"用更好的模型"不再是边际收益最高的投资——**同样的钱，投在知识建设上的 ROI 远高于投在模型升级上**（知识是复利资产，模型升级是一次性折旧）[来源: 本文推导 + MEMORY.md token 成本实证]。

3. **可替代性**：模型可以随时换（OpenAI→Claude→DeepSeek 迁移成本低），但**团队知识无法迁移**——换模型不掉产出，换团队才掉产出。这决定了长期竞争壁垒必然落在知识侧 [来源: 本文推导]。

**推论**：当模型变量趋同时，三变量乘积的方差几乎全部来自"知识接入 × 知识机制"——**这就是命题"上限不在模型而在团队知识"的数学依据** [来源: 本文推导]。

## §2 第一性原理：为什么知识决定上限

### 2.1 类比：CPU 与程序——算力决定速度，程序决定产出

最直观的第一性类比 [来源: 本文推导]：

```text
model  ~ CPU:    compute capability, same for everyone who buys it
KB     ~ Program+Data: what the machine actually runs on / with
output ~ throughput of the system: determined by program quality
```

- 同样一颗 CPU，跑空循环和跑训练好的模型，产出天差地别——**算力是必要条件，程序才是决定产出的变量**。
- Agent 的"程序"就是它的知识接入路径（检索什么）+ 知识机制（怎么用）；模型只是"CPU"。
- 买 CPU 人人平等，写程序才是护城河——**模型的商品化让"人人有 CPU"，团队知识就是各自的"程序"** [来源: 本文推导]。

### 2.2 信息论视角：Agent 产出 = 输入信息质量 × 处理能力

从信息论推导 [来源: 本文推导，参照香农信息论 + GIGO 原则]：

```text
output quality  <=  input information quality  x  processing capability
                  (what the agent retrieves)     (the model)
```

- 香农：信息 = 不确定性的降低。Agent 的每一步推理都消耗信息——**输入的信息量（已消除的不确定性）直接限制输出的信息量**。
- GIGO 严格化（知识管理价值链篇 §5.1）：**摄取质量决定利用上限**——喂给 Agent 的如果是"没有来源、没有条件、没有验证"的碎片，Agent 的输出再流畅也是精致的错误 [来源: 知识管理价值链篇 §5.1]。
- 关键推论：**模型再强，也无法从"没有信息"中推理出"信息"**——推理只能重组已有信息，不能凭空创造。Agent 的知识接入决定了它的"信息总量上限" [来源: 本文推导]。

### 2.3 认知科学视角：模型是工作记忆，知识库是长期记忆

类比人脑认知架构 [来源: 本文推导 + Agent 深度使用方法论 §2.1]：

| 人脑 | Agent | 容量 | 决定什么 |
|:-----|:------|:-----|:---------|
| 工作记忆 | 上下文窗口（L2） | 有限（128K-1M token） | 单轮处理广度 |
| **长期记忆** | **知识库（L3）** | **近乎无限** | **跨任务的知识积累** |
| 遗忘机制 | 上下文裁剪/蒸馏 | 有损 | 信息的持续可用性 |

- 认知科学：工作记忆容量约 4±1 组块；Agent 的上下文窗口同样有限——**模型"记不住"是物理限制，知识库就是 Agent 的体外长期记忆**（认知卸载的机器版）[来源: 本质篇 §1.3]。
- 关键推论：**Agent 的记忆能力不由模型决定（上下文窗口人人一样），由团队知识库决定（存了什么、能否检索到）**——这正是"组织记忆体外化"在 Agent 时代的放大 [来源: 本文推导 + 本质篇 §1.3]。

### 2.4 经济视角：模型边际成本趋零，知识是唯一壁垒

从生产要素经济学推导 [来源: 本文推导 + 本质篇 §1.4]：

| 生产要素 | 边际成本 | 是否可复制 | 竞争含义 |
|:---------|:--------:|:----------:|:---------|
| 模型推理 | 趋零（API 降价） | 完全可复制（人人可用） | 无壁垒 |
| 通用知识 | 趋零（互联网公开） | 完全可复制 | 无壁垒 |
| **团队领域知识** | **沉淀后趋零，但沉淀成本高** | **不可复制（隐性经验）** | **唯一壁垒** |

- 知识是唯一"越用越值钱、边际成本趋零"的生产要素（本质篇原理三），而**团队领域知识**（排障案例/设计决策/踩坑教训）是其中唯一不可复制的部分——公开知识谁都能查到，团队经验只有团队有。
- **ROI 推论**：投资模型升级 = 一次性折旧（下季度有新模型）；投资团队知识 = 复利资产（每次复用都在增值）。**在模型商品化的背景下，理性团队的边际投资应流向知识建设** [来源: 本文推导 + 本质篇 §1.4]。

## §3 团队知识决定 Agent 上限的五个机制（MECE）

把"团队知识如何决定 Agent 上限"拆成五个互斥穷尽的机制，对应认知五维（感知/记忆/理解/推理/判断）+ 行为层 [来源: 本文推导 + 认知目的篇 §2]：

| # | 机制 | 对应认知维 | 机制描述 | 失效表现 |
|:-:|:-----|:---------|:---------|:---------|
| M1 | 感知带宽 | 感知 | 检索决定 Agent "看到什么" | 库里有但搜不到 = 等于没有 |
| M2 | 记忆容量 | 记忆 | 组织记忆决定 Agent "记得什么" | 重复踩坑、重复决策 |
| M3 | 推理起点 | 推理 | 复利效应决定 Agent "站在多高的肩上" | 每个任务从零推演 |
| M4 | 判断依据 | 判断 | 质量门禁决定 Agent "信什么" | 自信地输出错误结论 |
| M5 | 行为约束 | 元认知 | 方法论封装决定 Agent "怎么做" | 每次任务重新发明流程 |

### 3.1 机制一：感知带宽——检索决定 Agent "看到什么"

**原理**：Agent 的知识接入 = 检索路径的质量。检索不到的知识，对 Agent 而言不存在——**放错位置 = 找不到 = 没有**（本质篇 §2.2 阶段 3 失败模式）[来源: 本质篇 §2.2]。

**量化机制**：

```text
Agent perception bandwidth = hit rate x relevance x retrieval cost
```

**本系统实证**：knowledge/ 3593 文件 / 17,156 内部链接 / 每文件 4.8 链接 / 24% 跨模块——交叉网络把"找到相关知识"从 O(n) 翻目录降为 O(1) 链接跳转 [来源: 规模效益篇 §2.2]。**没有这个网络，Agent 检索"PCIe Gen6 信号完整性"会淹没在 3593 个文件里；有这个网络，3 跳内到达目标** [来源: 本文推导]。

**团队含义**：感知带宽是知识库的"地基"——**主题目录 + 索引 + 交叉链接** 三件套决定 Agent 的第一跳质量。多数团队的 Agent 表现差，第一步就死在"检索不到" [来源: 本文推导]。

### 3.2 机制二：记忆容量——组织记忆决定 Agent "记得什么"

**原理**：Agent 的上下文窗口有限（工作记忆），跨会话/跨任务的知识保持依赖外部记忆（长期记忆）——**团队知识库就是 Agent 的长期记忆体** [来源: Agent 深度使用方法论 §2.1 + 本质篇 §1.3]。

**三重视角**：

| 记忆失效模式 | 人脑版 | Agent 版 | 知识库对策 |
|:------------|:-------|:---------|:-----------|
| 时间遗忘 | 6 个月后忘决策理由 | 会话裁剪后丢上下文 | 知识归档 + 每日蒸馏 |
| 人员流失 | 专家离职带走经验 | 模型更新/换供应商丢行为 | 技能封装 + 知识沉淀 |
| 组织熵增 | 新人重复踩坑 | 新 Agent 实例从零开始 | 组织记忆体外化 |

**本系统实证**：每日 23:50 蒸馏 + Candidate.md 提案机制——Agent 的"记忆"从会话级（会丢）升级为组织级（持久）；08-18 深度分析引用 10+ 旧文档，证明"记得"旧知识直接抬高了本次产出起点 [来源: 本系统实证 + 规模效益篇 §4.3]。

**团队含义**：**Agent 的记忆容量 = 团队知识库的沉淀深度**。没有知识库的 Agent 每轮都是"第一次来上班的新人"；有知识库的 Agent 是"带着全团队 10 年经验的老兵" [来源: 本文推导]。

### 3.3 机制三：推理起点——复利效应决定 Agent "站在多高的肩上"

**原理**：知识库的复利效应（新知识建在旧知识上，指数 O(e^t)）让 Agent 每次任务的推理起点不断抬高——**不重复发明轮子、不重复推演已证结论** [来源: 规模效益篇 §1.1]。

**量化模型**：

```text
Agent task output = existing knowledge base + reasoning increment
                    ^^^^^^^^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^
                    compound asset (team)   model capability (same)
```

- 裸模型做深度分析：从零调研 → 产出"框架堆名词"的泛泛之谈（推理起点 = 通用知识）。
- 平台态 Agent 做深度分析：先检索旧文档 → 站在 100 天积累上 → 产出"引用 10+ 旧文档的深度报告"（推理起点 = 团队知识）。
- **同样的模型推理增量，起点不同，终点差一个数量级** [来源: 本文推导 + 本系统实证]。

**本系统实证**：08-18 单日 4 篇深度文档（本质篇/规模效益篇/认知目的篇/本文），每篇复用旧文档 10+ 篇——**产出速度与深度都来自复利起点，不是模型变强了** [来源: 认知目的篇 §5.4]。

**团队含义**：推理起点是团队知识对 Agent 最隐蔽也最强大的杠杆——**它不改变单次推理，改变的是所有推理的共同基线** [来源: 本文推导]。

### 3.4 机制四：判断依据——质量门禁决定 Agent "信什么"

**原理**：Agent 与人的最大区别是**没有天然的怀疑心**——它会对检索到的内容一视同仁地自信。**知识质量直接决定 Agent 的判断质量**：喂给它的知识有来源、有条件、有验证，它的判断就可靠；喂给它"看起来有道理"的碎片，它就自信地输出错误 [来源: 本文推导 + 认知目的篇 §2.2 判断维]。

**本系统实证（质量门禁五件套）** [来源: 规模效益篇 §7 + 知识加工流水线 §5]：

| 机制 | 保证什么 | Agent 受益 |
|:-----|:---------|:-----------|
| S/A/B/C 素材分级 | 可信度分层 | 检索时按可信度排序 |
| R6 来源标注机器校验 | 断言有出处 | 引用时给出可追溯来源 |
| doc-final-check 门禁 | 格式/链接/来源合规 | 不被坏数据污染 |
| 深度五铁律 | 防止"框架堆名词" | 产出质量下限 |
| 素材批判使用（RULE §6） | 关键数据交叉验证 | 不采信单一来源 |

**关键推论**：**知识机制是"Agent 的判断力"的工程化实现**——人靠经验怀疑，Agent 靠门禁怀疑。没有门禁的团队知识，对 Agent 是"污染源"而非"资产"（堆积吞噬信任）[来源: 本文推导 + 认知目的篇 §0]。

**团队含义**：知识质量不是"锦上添花"——**在 Agent 时代，知识质量直接决定 Agent 判断质量，判断质量决定业务风险**（错误排障建议 = 生产事故）[来源: 本文推导]。

### 3.5 机制五：行为约束——方法论封装决定 Agent "怎么做"

**原理**：模型知道"怎么回答"，但不知道"你的团队怎么做这件事"——**方法论（SOP/规范/流程）是团队知识中最具操作性的部分，封装成技能后直接约束 Agent 行为** [来源: Agent 深度使用方法论 §六 + 技能四法门]。

**本系统实证**：106 项技能 = 方法论封装 [来源: 规模效益篇 §5]：

| 技能类型 | 封装了什么 | 对 Agent 的约束 |
|:---------|:-----------|:----------------|
| knowledge-doc-writer | 深度文档 6 步工作流 | 不裸写、必走门禁 |
| light-research-ethics | 科研伦理审查 | 默认检查学术不端 |
| fault-diagnosis | 故障排查方法论 | 系统化排查而非瞎猜 |
| RULE.md 铁律 | 落盘纪律 | 未落盘 = 未完成 |

**关键机制**：技能 = "团队怎么做这件事"的显式化——**把老师傅的隐性流程变成 Agent 可遵循的显性接口**。没有技能封装，Agent 每次任务都"自由发挥"（每次都不一样）；有技能封装，Agent 每次都"按团队标准做法执行"（可预期、可审计）[来源: 本文推导 + 技能四法门]。

**团队含义**：**行为约束是团队知识对 Agent 的"方向盘"**——知识决定 Agent 知道什么，方法论决定 Agent 怎么做。两者缺一，Agent 或有知识无章法、或有章法无知识 [来源: 本文推导]。

## §4 本系统实证：同一个模型，两种上限

### 4.1 对照实验：deepseek-v4-flash 的裸对话态 vs 平台态

本系统提供了一个天然的对照实验：**同一个模型（deepseek-v4-flash），两种运行环境** [来源: 本系统实证]：

| 维度 | 裸对话态（无知识库） | 平台态（全平台） |
|:-----|:-------------------|:----------------|
| 知识接入 | 只有模型参数内通用知识 | 3800+ 文件知识库 + 106 技能 + 79 脚本 |
| 知识机制 | 无门禁、无来源、无验证 | Q6 门禁 + S/A/B/C 分级 + 来源标注 |
| 行为约束 | 自由发挥 | RULE.md 铁律 + 技能工作流 |
| 典型产出 | "框架堆名词"的泛泛分析 | 引用 10+ 旧文档的深度报告 |
| 质量保障 | 无（说错无法发现） | write+log+commit 三缺一禁止收尾 |
| **产出上限** | **通用知识水平** | **团队知识水平（高一个数量级）** |

**关键证据链**：本系统 08-17 质量事故复盘记录了"浅层回答"的教训，随后 RULE.md 立下深度分析五铁律（必须走 skill / 未落盘=未完成 / ≥8 turns 或 ≥3 次工具调用 / 质量>token / 当轮分析当轮落盘）——**同样的模型，加了知识机制后产出质量立即改观**，这不是模型升级的结果，是知识机制升级的结果 [来源: MEMORY.md 深度分析铁律 + RULE.md]。

### 4.2 知识接入的量化证据

| 指标 | 数值 | 对 Agent 上限的含义 | 来源 |
|:-----|:-----|:-------------------|:-----|
| 知识文件 | 3,593 个（8 模块） | 感知带宽的原料 | 规模效益篇 §2.1 |
| 交叉链接 | 17,156（4.8/文件） | 检索路径 O(1) 可达 | 规模效益篇 §2.2 |
| 跨模块链接 | 4,130（24%） | 跨域联想能力 | 规模效益篇 §2.2 |
| 技能封装 | 106 项 | 行为约束的接口 | 规模效益篇 §5.1 |
| 脚本工具 | 79 个 | 机制的机器化 | 规模效益篇 §5.3 |
| 检查器 | 60+ | 判断依据的工程化 | 规模效益篇 §7.3 |

**结论**：这些数字不是"知识库的成就"，而是**Agent 的能力底座**——每一项都在抬高 Agent 的感知/记忆/推理/判断/行为五维上限 [来源: 本文推导]。

### 4.3 知识机制的量化证据

| 机制 | 实证 | 对产出质量的贡献 |
|:-----|:-----|:----------------|
| 涌现判据（链接密度≥3） | 4.8 ✅ | 知识从"集合"变"网络" |
| 跨模块交叉（≥10%） | 24% ✅ | 跨域推理成为可能 |
| 自举循环 | 今日文档引 10+ 旧文 ✅ | 复利起点持续抬高 |
| 深度五铁律 | 08-17 后强制 | 产出质量下限锁死 |
| 门禁体系 | doc-final-check 必跑 | 坏数据不进入 Agent 视野 |

**关键观察**：四个涌现判据中三个已成立，第四个（复用事件埋点）半成立——**这恰好说明：知识网络已经搭好，下一步跃迁在"调用侧可观测性"，不在模型侧** [来源: 规模效益篇 §3.3 + 本文推导]。

### 4.4 从"模型赌注"到"知识赌注"的战略转移

本系统的战略演变本身就是命题的实证 [来源: MEMORY.md + 本系统实证]：

```text
Phase 1 (Day 1-30):    bet on model  -- does a stronger model lift output?
Phase 2 (Day 31-60):   bet on mechanism -- gates/pipeline/distill?  YES
Phase 3 (Day 61-100):  bet on knowledge -- 3800+ files/106 skills?  YES
Phase 4 (Day 100+):    bet on flywheel -- cognition->output loop   YES 4 deep docs/day
```

**教训**：本系统 100+ 天里模型换了（deepseek 系列升级），但**产出质量跃迁的拐点都发生在知识/机制升级时，而非模型升级时**——这是"上限在团队知识"最直接的实证 [来源: 本系统实证]。

## §5 反证与边界：知识不是万能的

诚实标注命题的边界，避免把"知识决定上限"推向极端 [来源: 本文推导]：

### 5.1 模型下限：知识弥补不了推理缺陷

- 知识是"燃料"，模型是"引擎"——**劣质引擎烧再好的燃料也跑不快**。如果模型推理能力不足（幻觉率高、长链推理崩坏），知识接入只能部分补偿。
- **边界条件**：命题成立的前提是"模型能力越过基本门槛"——2026 年主流模型已满足（SWE-bench Verified 60%+ 量级）；但**低于门槛的模型（小模型/弱模型）仍会被模型能力卡死** [来源: 本文推导 + 行业基准]。

### 5.2 知识上限：认知墙与囤积主义

- **认知墙**：人的领域逻辑、底层原理理解有物理上限——知识库增强的是"可达带宽"，不替代"深度理解"（认知墙篇 §1）；Agent 同理，**知识接入再多，也无法让 Agent 理解它没有训练过的深层原理** [来源: 认知墙篇 §1]。
- **囤积主义**：库大不是功绩，库好用才是——**知识堆积（无检索无机制）对 Agent 是负担而非资产**：检索噪音上升、判断被污染（堆积吞噬信任）[来源: 认知目的篇 §1.1 + 规模效益篇 §1.2]。

### 5.3 机制失效：有库无管 = 死库

- 团队知识 ≠ 团队知识机制。**多数团队不是没有知识，是知识躺在个人电脑/聊天记录/离职员工脑子里**——没有沉淀、没有索引、没有门禁的"知识"对 Agent 不可见 [来源: 本文推导]。
- **死库的三种形态**：有库无检索（放进去就找不到）、有库无门禁（垃圾进垃圾出）、有库无接口（Agent 无法调用）——三者任一，知识变量对 Agent 的贡献 ≈ 0 [来源: 本文推导 + 本质篇 §2.2]。

### 5.4 边际递减：知识投入的拐点

- 知识建设的边际收益递减：初期（建库/建索引）ROI 最高，后期（扩充长尾/深度加工）ROI 下降——**理性策略是优先沉淀高频高价值知识（A 类容器），而非追求文件数**（本质篇 §1.4 经济学铁律）[来源: 本质篇 §1.4]。
- **40% 红线**：AI 探索投入 ≤40% 的约束同样适用于知识建设——**知识建设是手段不是目的，产出才是目的**；知识投入的拐点应以"产出加速"而非"文件增长"衡量 [来源: MEMORY.md + 认知目的篇 §7]。

## §6 对团队的启示：三条行动路径

### 6.1 知识资产化：把隐性经验变成可检索资产

**目标**：让 Agent 能检索到团队知识（机制一/二）。

| 动作 | 具体做法 | 参考 |
|:-----|:---------|:-----|
| 排障复盘必沉淀 | 问题关闭 24h 内写 RCA（根因+影响+对策） | 本质篇 §9.2 垂直沉淀链 |
| 设计决策留推导 | 方案写"为什么这么选"而非只写结论 | 本质篇 §9.3 |
| 评审纪要归档 | 否决理由、取舍依据入库 | 本质篇 §9.3 |
| 统一命名/目录 | 主题聚合，不按来源归档 | 本质篇 §10.3 主题>来源 |

**判断标准**：**团队知识的"资产化率" = 可检索的隐性经验 / 团队全部隐性经验**——目标是让 Agent 能"看到"老师傅脑中的东西 [来源: 本文推导]。

### 6.2 知识管线化：让知识经历受控加工而非随手堆放

**目标**：保证 Agent 检索到的知识可信（机制四）。

| 动作 | 具体做法 | 参考 |
|:-----|:---------|:-----|
| 素材与成品分离 | import/ 素材区 vs knowledge/ 成品区 | 本质篇 §3.2 |
| 来源分级 | S/A/B/C 可信度分级，关键数据交叉验证 | 知识加工流水线 §5 |
| 质量门禁 | 发布前机器验收（格式/链接/来源） | 规模效益篇 §7 |
| 门禁>自觉 | 机器验收替代"我认为没问题" | 本质篇 §10.3 |

**判断标准**：**知识污染率 = 无来源/无条件/未验证条目 / 总条目**——目标趋近于 0。污染率高的知识库，对 Agent 是负资产 [来源: 本文推导]。

### 6.3 知识接口化：让 Agent 能标准化调用团队知识

**目标**：把知识从"给人看"升级为"给人+Agent 共同调用"（机制五）。

| 动作 | 具体做法 | 参考 |
|:-----|:---------|:-----|
| 方法论封装 | 高频任务封装为技能（SKILL.md） | 规模效益篇 §5 |
| 规范机器化 | CheckList → 检查脚本 → 门禁 | 本质篇 §9.2 L5 自动化 |
| 检索标准化 | 统一检索接口（语义+关键词） | 本质篇 §6 |
| 场景绑定 | 知识标注适用场景，检索按场景过滤 | 本质篇 §7.2 |

**判断标准**：**Agent 任务复用率 R = 任务中调用团队知识的比例**——R 长期 < 30% 说明接口失效或内容不可达，优先修检索而非扩存储（认知目的篇 §7.2）[来源: 认知目的篇 §7.2]。

### 6.4 度量：如何验证"团队知识真的抬高了 Agent 上限"

| 指标 | 定义 | 观测方式 |
|:-----|:-----|:---------|
| 复用率 R | 新任务引用既有知识的比例 | git log + 交叉引用统计 |
| 检索命中率 | 检索请求成功命中比例 | memory_search 日志埋点 |
| 单文档边际成本 | 每新增深度文档的耗时/调用量 | 会话日志 |
| 重复问题率 | 已归档问题被重新提问比例 | 会话日志归类 |
| 产出吞吐 | 单位时间深度产出数 | 周报统计 |

**度量原则**：可埋点、可对比、可归因——**避免"AI 自报收益"式的主观评估** [来源: 认知目的篇 §5.3 + MEMORY.md]。

## §7 结论

1. **命题成立**：Agent 的产出上限 = 模型能力 × 知识接入 × 知识机制；模型已商品化（变量趋同），**团队知识成为主导变量**——上限在团队知识，不在模型 [来源: 本文推导]。

2. **五个机制**：感知带宽（检索）、记忆容量（组织记忆）、推理起点（复利）、判断依据（门禁）、行为约束（方法论）——五者 MECE 覆盖"看到什么→记得什么→站在多高的肩上→信什么→怎么做"的完整认知链 [来源: 本文 §3]。

3. **本系统实证**：同一模型（deepseek-v4-flash）在裸对话态 vs 平台态（3800+ 文件 / 106 技能 / 79 脚本 / 门禁体系）下产出上限差一个数量级——**100+ 天里质量跃迁的拐点都发生在知识/机制升级时，而非模型升级时** [来源: 本文 §4]。

4. **边界诚实**：命题前提是"模型越过基本门槛"；知识堆积（无机制）对 Agent 是负资产；知识投入有边际递减拐点——**理性策略是优先沉淀高频高价值知识 + 建立质量门禁** [来源: 本文 §5]。

5. **行动路径**：知识资产化（沉淀隐性经验）→ 知识管线化（受控加工）→ 知识接口化（Agent 可调用）→ 度量验证（复用率/命中率）——**三步一量，团队知识就变成 Agent 能力的复利资产** [来源: 本文 §6]。

**最终一句话**：**模型决定 Agent 的下限不低，团队知识决定 Agent 的上限多高；在模型商品化的时代，投资团队知识是提升 Agent 产出上限唯一有复利的杠杆** [来源: 本文推导]。
