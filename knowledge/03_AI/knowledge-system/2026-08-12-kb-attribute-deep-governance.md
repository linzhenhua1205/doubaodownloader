## 核心命题

属性不只是「用来筛选的字段」，**每一类属性背后都对应一套底层运行机制**。把「属性表象 → 底层原理机制 → 可落地的进阶动作」三层打通，才能实现对素材的深度治理（自迭代、自愈、权重修正、风险预警），而不是只做字段记录。认知深度决定了知识库能走多远——浅度用是过滤，中度用是统计，深度用是让系统自运转。

## 关键洞察

### 1. 五大类属性的「表象 → 机制 → 动作」三层拆解

**① 时序类属性**（创建/修改/访问时间、版本号、Diff 日志、编辑次数）
- 机制：副本版本链（不物理覆盖）；修改触发时序衰减权重 + 审计链路；Diff 识别变更类型（微调/改结论/整段重构）
- 动作：时序衰减权重计算；变更风险识别（短时间反复修改 → 标记「不稳定知识」降权 + 人工复核）；版本回溯与分支（内部修订版/对外发布版）；操作者行为审计

**② 溯源来源类属性**（作者、原始来源、引用链路、被引用次数、抓取批次）
- 机制：知识存在有向引用图（自媒体→知乎→课件→论文）；作者/来源自带先天置信基线；被引用次数代表共识程度
- 动作：溯源校验（低置信素材追溯源头，上游是 S 级论文则小幅提权，源头断裂打「孤源标记」）；作者信誉分体系（按冲突率/错误率给作者打分）；溯源断链清理；共识度排序（高被引原理图谱优先遍历）

**③ 物理存储类属性**（大小、Token 量、分片位置、冷热层级、压缩率、OCR 错误率）
- 机制：向量算力与 token 量正相关；超大切片嵌入漂移；冷热分层是成本与延迟的取舍；大文件拆多切片共享源文件 ID
- 动作：自动切片优化（超大二次细切、过小合并）；冷热自动迁移；存储成本统计（识别臃肿库）；损坏素材自愈（OCR 错误率过高自动重解析）

**④ 行为统计类属性**（命中次数、访问次数、下载次数、被采纳次数、报错次数、跳过次数）
- 机制：交互行为构成动态反馈闭环，是后天置信度修正的核心数据源；高命中低采纳 → 噪声向量；高访问高报错 → 事实错误需治理
- 动作：动态置信度自动迭代（采纳加分/报错扣分/跳过降权）；噪声向量清洗（高命中零采纳的切片临时下线）；热门知识缓存（高频访问预加载内存）；冷门知识归档（零访问进待审）；用户行为画像（域内高频访问主题 → 推荐补素材）

**⑤ 权限域属性**（归属域、ACL、共享范围、脱敏标记）
- 机制：域间嵌套隔离 + 受控单向同步；共享触发脱敏规则
- 动作：跨域同步流水线（小组审核通过 → 脱敏同步企业域）；权限自动回收（退出域收回编辑权）；越权访问审计（记录跨域读取日志）

### 2. 统一逻辑链路：认知深度三级

1. **浅度**：只在查询里 where 过滤字段
2. **中度**：统计聚合做报表（作者产出量、库存储大小）
3. **深度**：利用属性背后运行规则做自动迭代、自愈、权重修正、数据治理、风险预警 → 知识库形成自运转闭环

### 3. 配套 attr 系列命令

```bash
attr show --entity id=xxx                # 查看全维度属性
attr diff-version --eid=xxx v1 v2        # 版本差异对比
attr recalc-confidence --domain team_a   # 根据访问统计刷新动态置信度
attr detect-unstable --expert hardware_exp  # 依据修改波动标记不稳定实体
attr trace-source --eid=xxx              # 溯源上游来源链路
attr storage-tier-auto-migrate           # 按大小和访问量批量迁移冷热存储
```

## 🔍 深度辨析报告

### 原理解析

「属性 → 机制 → 动作」三层模型是**数据驱动治理（data-driven governance）**的完整落地框架，其理论根基是：

- **属性即观测**：行为统计属性（采纳/报错/跳过）是系统对自身质量的**观测信号**，对应控制论中的「反馈测量」——没有观测就没有闭环。这与本系统 MEMORY.md 记录的「统计铁律：A/M/R/D 四状态由用户聚合，AI 自报收益不可靠」完全一致：观测信号的可信度决定了闭环质量。
- **机制即模型**：每类属性背后假设了一个机制模型（版本链、引用图、冷热分层、反馈闭环、域隔离）——「认知深度」本质是**从数据表象反推生成机制**（reverse-engineering the generative process），这正是第一性原理在数据治理中的应用。
- **动作即控制**：进阶动作（降权/提权/清洗/迁移/回收）是控制论中的「执行器」——测量→建模→控制三步构成完整闭环，让知识库从被动存储变为主动自愈系统。

### 与本知识库体系的对接

- **高度呼应本系统已有实践**：MEMORY.md 中「系统腐化防治四层（契约/探测/重构/编码约束）」与「行为统计 → 治理动作」同构；「check 脚本收敛」就是属性治理的自动化执行器。
- **缺口**：本系统目前缺「行为统计类属性」——没有记录每条知识被采纳/报错/跳过的计数，无法做动态置信度迭代；「越用越聪明」在本系统尚停留在静态分级层面。
- **可落地动作**：P0 = 在 knowledge/log.md 或文档头部增加「采纳/报错」计数追踪（至少从调研类文档开始）；P1 = 把「不稳定知识检测」（短时间高频修改降权）脚本化，与 [知识库质量方法论](2026-07-07-knowledge-quality-methodology.md) 的检查器合并。

### 批判性评估

- ✅ **强项**：三层模型把「属性」从静态描述升华为动态治理的观测层，打通了「记录 → 理解 → 行动」的完整链路；行为统计闭环正是「越用越聪明」的机制解释。
- ⚠️ **挑战 1：观测信号的噪声**——行为统计依赖「被采纳/报错」的定义明确性：LLM 回答时如何判定「采纳」？用户不点反馈默认算通过还是跳过？信号定义不清会让动态置信度失真（本系统已有 AI 自报收益不可靠的教训）。
- ⚠️ **挑战 2：冷启动与稀疏性**——长尾知识几乎无交互，行为统计无法覆盖；需要「先天置信度为主 + 后天修正为辅」的混合策略，而非全依赖反馈。
- ⚠️ **挑战 3：治理动作的副作用**——自动降权/下线/归档若判定错误，会造成「误杀」优质知识或「掩盖」真实问题；需要人工复核闸门。
- ❌ **未覆盖**：属性本身的版本管理（属性 schema 变更如何追溯）、隐私边界（行为画像涉及用户行为数据合规）。
