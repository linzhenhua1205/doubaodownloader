## 第1章：愿景定位

### 1.1 核心命题

> **从"AI帮我记"到"组织因AI而聪明"。**

当前知识库是28个模块、1082个文件的**个人知识仓库**。但真正的组织级知识管理需要回答：

| 问题 | 当前状态 | 目标状态 |
|:-----|:---------|:---------|
| **谁来沉淀？** | 用户主动说"存一下" | 对话自动提取、主动推送 |
| **谁在用？** | 一个人 | 团队/组织多角色 |
| **怎么找？** | 语义搜索（memory_search） | 多层检索+推荐+问答 |
| **怎么演化？** | 人工写+整理 | AI驱动自动提炼/归并/淘汰 |
| **怎么访问？** | 飞书对话 | 飞书+Web+CLI+API+钉钉... |
| **怎么链接？** | 手动交叉引用 | 自动实体识别+关系图谱 |

### 1.2 四层能力模型

```text
Layer 4: 🧠 组织智能层
  知识演化、跨人员关联、自动洞察、决策支持

Layer 3: 🔍 检索与问答层
  语义搜索、RAG问答、图谱导航、个性化推荐

Layer 2: 🗂️ 知识资产层
  Markdown化、分类、标签、实体链接、版本管理

Layer 1: 🔌 接入与采集层
  多渠道对话归档、文件导入、网页抓取、RSS
```

| **AI对话归档** | `doubao-share` skill（豆包链接解析+知识库写入） | 🟢 已就绪 |
| **语义检索** | `memory_search`（向量语义+关键词混合搜索） | 🟢 已就绪 |

## 第3章：架构设计

### 3.1 存储结构演进

```text
当前：                         目标：
knowledge/                    knowledge/
+-- concepts/                 +-- public/           <- 组织公共知识
+-- tools/                    |   +-- concepts/
+-- server-hardware/          |   +-- tools/
+-- ...                       |   +-- server-hardware/
+-- index.md                  |   +-- ...
                              +-- org/              <- 组织特有的沉淀
                              |   +-- projects/     <- 项目知识
                              |   +-- meetings/     <- 会议沉淀
                              |   +-- decisions/    <- 决策记录
                              |   +-- playbook/     <- SOP/标准操作
                              +-- users/            <- 个人知识区
                              |   +-- alice/
                              |   +-- bob/
                              |   +-- {user}/
                              +-- index.md
                              +-- log.md
```

### 3.2 三层知识分类

| 分类 | 定义 | 示例 |
|:-----|:------|:------|
| **公开知识** | 行业通用、无归属 | 技术概念、行业报告、论文笔记 |
| **组织知识** | 组织特有、全员共享 | 项目文档、架构决策、SOP、会议记要 |
| **个人知识** | 个人经验、不强制共享 | 个人笔记、思考碎片、学习心得 |

**隔离原则**：

- 公开知识 → 全员可读+可贡献
- 组织知识 → 按角色/项目授权
- 个人知识 → 仅本人+管理员可见


## 第4章：分阶段演进路线图

### Phase 1: 知识固化 ● 当前（第1-2周）

**目标**: 用已有工具完成知识资产化

| 任务 | 工具/方法 | 产出 |
|:-----|:---------|:-----|
| 批量Markdown化存量文档 | `markdown-converter` | 统一格式的知识资产 |
| AI对话自动归档 | `doubao-share` 升级 | 所有AI对话→知识库 |
| 个人/组织目录隔离 | 重构 `knowledge/` 目录 | `public/` `org/` `users/` |
| RSS持续采集 | 定时任务 + `scheduler` | 行业动态自动入库 |

### Phase 2: 主动抽取 ● 第3-4周

**目标**: 对话中自动提炼知识，无需用户说"存一下"

| 任务 | 方案 | 关键挑战 |
|:-----|:------|:---------|
| 自动提取Agent | 监听对话流，识别可沉淀内容 | 判定阈值（什么值得存） |
| 知识分类 | 自动判定 public/org/personal | 边界模糊时的兜底策略 |
| 去重合并 | 语义相似度+关键实体匹配 | 避免碎片化堆积 |
| 质量评分 | 新鲜度×引用频次×来源可信度 | 量化标准定义 |

### Phase 3: 组织沉淀 ● 第5-8周

**目标**: 多人协作、跨人员知识关联

| 任务 | 方案 |
|:-----|:------|
| 多用户身份 | 飞书/钉钉用户绑定，对话来源识别 |
| 跨人员关联 | 相同实体→不同人视角→自动合并聚合 |
| 知识推荐 | 基于当前对话上下文的主动推荐 |
| 决策记录 | 组织级决策的自动抽取（谁、什么、为什么） |

### Phase 4: 知识演化 ● 第9周+

**目标**: 知识库自我进化，不再依赖人工维护

| 机制 | 说明 |
|:-----|:------|
| **自动淘汰** | 6个月无人访问→标记为「冷知识」→归档 |
| **自动合并** | 相似度>0.85的多篇→提议合并 |
| **知识缺口发现** | 高频搜索但无命中→标记为「待补充」 |
| **反直觉洞察** | 跨域关联发现（如：BMC故障模式×存储可靠性） |
| **被动变主动** | AI主动推送「你可能需要知道」 |

## 第5章：多通道访问设计

### 5.1 通道矩阵

| 通道 | 输入能力 | 输出能力 | 优先级 |
|:-----|:---------|:---------|:-------|
| **飞书Bot**（当前） | 自然语言对话+文件上传 | 文本回复+文件发送 | P0 |
| **Web界面** | 搜索框+可视化浏览 | 知识图谱+目录树+全文 | P1 |
| **CLI工具** | 命令行查询+批量导入 | JSON/文本输出 | P2 |
| **REST API** | 编程查询+写入 | JSON响应 | P2 |
| **钉钉/企微** | 自然语言对话 | 文本回复+卡片 | P1 |

### 5.2 统一查询入口

```text
无论哪个通道，查询都走同一套语义引擎：

用户问题
   |
   v
+----------------------+
| 意图理解              |
| - 是查知识？查人？查项目？|
| - 模糊还是精确？       |
| - 要不要搜网页补充？    |
+----------+-----------+
           v
+----------------------+
| 三层搜索              |
| ① 向量语义搜索(主)     |
| ② 关键词精确搜索(辅)   |
| ③ 图谱关系搜索(深度)   |
+----------+-----------+
           v
+----------------------+
| 结果融合              |
| - 按相关性排名         |
| - 标注来源层级(公/组/人)|
| - 附加上下文+引用      |
+----------+-----------+
           v
+----------------------+
| 通道适配              |
| - 飞书->纯文本+链接     |
| - Web->渲染+图谱       |
| - API->JSON结构化      |
+----------------------+
```

## 第6章：关键设计原则

### 6.1 写为先，检索为后

```mermaid
graph LR
    A[内容产生] --> B[Markdown写入]
    B --> C[索引更新]
    C --> D[向量化]
    D --> E[图谱关联]
    E --> F[可检索]
```

- **Markdown是真理源**（source of truth），索引/向量/图谱都是从它派生
- 任何查询先试搜索，找不到才找人问
- 搜不到本身就是知识缺口信号

### 6.2 知识分级，权限跟随

```text
公开 <------------ 全员自由访问
  |
  v
组织 --- 默认全员可读，贡献需审核
  |
  v
个人 --- 本人+管理员
  |
  v
保密 --- 指定角色/加密
```

### 6.3 自动为主，人工为辅

| 环节 | AI自动 | 人工干预 |
|:-----|:-------|:---------|
| 提取 | ✅ 自动 | 审核修正 |
| 分类 | ✅ 自动 | 重分类需求 |
| 去重 | ✅ 提议 | 确认合并 |
| 质量 | ✅ 评分 | 手动加分 |
| 淘汰 | ✅ 标记 | 确认删除 |
| 关联 | ✅ 发现 | 确认关联 |

## 第8章：下一步行动

### 近期可做的（不依赖新技能）

1. **目录重构**：将 `knowledge/` 拆为 `public/` + 当前内容归入公共区
2. **对话自动记录**：每次有价值的对话后主动写 `users/{user}/` 下
3. **多平台对话归档扩展**：`doubao-share` 模式复制到 Claude/ChatGPT/通义千问
4. **入口统一**：所有检索行为统一路由到 `memory_search`，不在别处再建一套

### 需要新建的技能

1. `knowledge-extractor` — 从对话流自动提取知识实体
2. `knowledge-query` — 复合语义检索+图谱导航的对外统一接口
3. `org-km-gateway` — 多通道访问适配层（飞书/Web/API/CLI）
