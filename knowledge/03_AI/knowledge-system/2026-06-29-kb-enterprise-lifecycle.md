## 二、阶段一：方案评估

### 痛点诊断

通过用户访谈、现场观察、问卷调查识别企业核心痛点：

| 典型痛点 | 量化目标示例 |
|:---------|:------------|
| 信息孤岛，检索效率低 | 用户自助解决率提升至 80% |
| 知识传承断层 | 新人上手周期从 3 月缩至 1 月 |
| 客服重复咨询高 | 人工会话量降低 40% |
| 合规风险 | 回答准确率 ≥ 95%，来源可溯 |

### 成本效益分析

```python
# 节省人力成本估算公式
节省成本 = AI处理会话数 × 人工单次时长 × 客服时薪
         = 总会话数 × AI应答率 × 平均时长 × 时薪
```

## 三、阶段二：指标拆解

### 北极星指标拆解

以"用户自助解决率"为目标示例：

```text
用户自助解决率
+-- 触达率（用户愿用知识库）
+-- 意图识别准确率（理解用户想问什么）
+-- 知识召回率（Top-3 中是否包含答案）
+-- 答案采纳率（用户是否认可回答）
+-- 多轮解决率（复杂问题的成功率）
```

### 各环节关键指标

| 环节 | 核心指标 | 目标值 |
|:-----|:---------|:-------|
| 检索 | 召回率 (Recall) | ≥ 85% |
| 检索 | 精确率 (Precision) | ≥ 90% |
| 问答 | 答案采纳率 | ≥ 80% |
| 运营 | 知识覆盖率 | ≥ 95% |
| 运营 | 知识更新及时率 | ≤ 24h |

## 四、阶段三：系统设计

### 技术架构（三层）

```text
+-------------------------------------+
|  应用层                              |
|  智能问答 / 文档检索 / 客服辅助       |
|  Web UI / API / 嵌入第三方系统        |
+-------------------------------------+
|  检索层                              |
|  混合检索(向量+关键词) + Rerank      |
|  向量库(Milvus/Qdrant/Chroma)       |
+-------------------------------------+
|  数据层                              |
|  PDF/DOC/MD/Excel 解析 -> 清洗 -> 分块 |
|  Embedding -> 向量化 -> 入库           |
+-------------------------------------+
```

### 数据预处理关键参数

| 处理步骤 | 参数建议 | 说明 |
|:---------|:---------|:------|
| 分块大小 | 500-1500 字符 | 技术文档取上限，QA 取下限 |
| 分块重叠 | 10%-20% | 防止上下文断裂 |
| 向量维度 | 768-1536 | 取决于嵌入模型 |
| 检索 Top-K | 3-5 | 平衡质量与 Token 消耗 |
| 相似度阈值 | ≥ 0.65 | 过低引入噪声 |

### 检索增强策略

```text
用户查询
    |
    v
+--------------+   +--------------+
| 向量检索      |   | BM25关键词    |
| (语义相似)    |   | (精确匹配)    |
+------+-------+   +------+-------+
       |                  |
       +------+-----------+
              v
     +----------------+
     | RRF 结果融合     |
     | Top-50 -> Top-3  |
     +--------+-------+
              v
     +----------------+
     | Rerank 重排序   |
     | 提升精准度      |
     +--------+-------+
              v
        最终结果
```

## 五、阶段四：需求验证

### POC 选型策略

| 验证阶段 | 推荐工具 | 周期 | 投入 |
|:---------|:---------|:-----|:-----|
| 快速验证 | AnythingLLM + Ollama | 1 天 | 个人笔记本 |
| 方案验证 | Dify + Qwen | 1 周 | 1 台服务器 |
| 企业级验证 | RAGFlow/MaxKB + 生产模型 | 2-4 周 | 完整硬件 |

### 验证 checklist

- [ ] 是否覆盖核心业务场景？
- [ ] 知识召回率是否达标？
- [ ] 回答准确率与人工对比如何？
- [ ] 系统响应时间是否满足要求？
- [ ] 权限管控是否满足合规？

## 六、阶段五：落地运营

### 知识库维护机制

| 维护类型 | 策略 | 频率 |
|:---------|:-----|:------|
| 批量更新 | 定时全量刷新 | 每日/每周 |
| 增量更新 | 事件触发（新文档/修改） | 实时 |
| 版本回滚 | 保留前 3 个版本 | 灰度发布 |

### 持续优化的反馈闭环

```text
用户反馈(有用/无用)
    |
    v
+--------------+
| 问题分析      |
| 为什么未命中？ |
+------+-------+
       v
+--------------+    +--------------+
| 归因分类      | ->  | 规则优化      |
| 缺失/不准确/  |    | 更新知识/调整  |
| 检索偏差      |    | 分块/重训练    |
+--------------+    +------+-------+
                           v
+--------------+
| 效果复验      |  -> 回到反馈收集
+--------------+
```

### 运营所需角色

| 角色 | 职责 |
|:-----|:------|
| 知识管理员 | 文档审核、发布、版本管理 |
| 业务专家 | 知识内容产出、准确判断 |
| AI 工程师 | 检索优化、模型调优 |
| 运营分析师 | 效果评估、迭代建议 |
