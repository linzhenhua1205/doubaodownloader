## 核心命题

海量数据绝对不能单库混堆，必须**分库隔离 + 路由分发**；把 MoE（混合专家）思想引入知识库形成 **MoE-KB 架构**，叠加「权限信任域」纵向层级，构成知识域 × 信任域的双维路由体系——这是让知识库从「混沌大池子」走向「接近人类认知的域隔离 + 专家路由」的架构路径。

## 关键洞察

### 1. 混堆单库的三大致命负担

1. **检索算力负担**：全库向量索引巨大、距离计算耗时；低质碎片稀释优质向量，高价值知识点被噪声淹没，还要反复重排额外消耗 token
2. **知识逻辑负担**：论文原理、自媒体观点、过时新闻、行业案例混在同一向量空间，跨领域乱匹配，模型需额外推理纠错
3. **运维迭代负担**：更新/清洗要遍历全库，不同数据源切片规则与置信规则互相冲突，无法批量自动化治理

### 2. 三种分库拆分逻辑（可并行）

| 分库逻辑 | 划分依据 | 典型库 | 用途 |
|:---------|:---------|:-------|:-----|
| **可信度隔离** | 数据源等级+置信度 | 基石库 S(>0.9) / 体系库 A(0.7-0.9) / 经验库 B(0.5-0.7) / 线索库 C(<0.5) | 原理→只路由 S+A；案例→路由 A+B；**禁止默认全库检索** |
| **领域/业务隔离** | 垂直领域 | 算力硬件库 / 软件工程库 / 财经产业库 | 向量空间互不干扰；单域扩容清洗；可定制切片/嵌入/置信规则 |
| **时效冷热隔离** | 时效性 | 热库(近1-2年,常驻内存) / 温库(3-10年,磁盘) / 冷库(10年+,归档) | 控制算力成本 |

### 3. MoE-KB：把混合专家架构平移到知识库

| MoE 原生组件 | 知识库映射 |
|:------------|:-----------|
| 多个独立**专家模块**（各专精一域） | 每个独立知识库 = 一个领域专家库（S 基石/硬件/软件/经验案例/线索溯源） |
| **门控网络 Gate**（判断域，只激活少数专家） | 路由网关：意图分类 + 域识别 + 置信阈值配置，**禁止广播式全库检索** |
| **输出加权融合** | 聚合层：`向量相似度 × 域匹配权重 × 置信度` 加权合并，冲突优先采信高域优先级+高置信 |

**MoE-KB 优势**：算力只调用 2-3 个专家库；向量空间纯净不跨域误匹配；单域更新清洗不动全局；新增垂直领域直接新建 Expert 库接入网关，不重构架构。

### 4. 信任域体系：不只是知识领域，还有社交/权限/信任域

嵌套层级域树：`个人域 → 小组域 → 企业部门域 → 公司域 → 行业域 → 省份公共域 → 国家公共域`

不同域三个核心差异：
1. **信息边界隔离**：小组域内部方案只在小组可见；企业域内部财报外部访问不到；公共域全域可访问。不分域 → 内部涉密被外部误召回泄露，外部杂乱数据污染内部私有知识
2. **信任规则随域变化**：家庭域靠情感信任背书；小组域靠协作交叉验证；企业域靠流程审批（审批文档置信远高于私下闲聊）；公共域靠官方发布/学术评审。**用公共域规则处理私有域信息，或私有域混入公网低质信息，是知识库失败的常见原因**
3. **跨域通信受控**：小组域可向上同步脱敏结论到企业域但原始草稿不能流出；企业域可引用公共域国标论文，公共域不能读企业内部数据；家庭域几乎不对外开放

### 5. 双维 MoE 路由完整架构

```
用户请求 → 权限网关（裁剪无权域）→ MoE 领域门控（激活少量对应专家知识库）
→ 多库召回加权融合 → 冲突校验（按域优先级+置信度裁决）→ 输出结果
```

- **第一层：权限信任域**（纵向层级，控制能不能看）→ 权限网关过滤
- **第二层：知识领域专家库**（横向 MoE 专家，控制检索哪块知识）→ 领域门控路由

### 6. 现实类比：人际沟通本身就是天然 MoE 域系统

和家人沟通调用「家庭域专家心智模块」（亲情信任逻辑）；和同事开会切换到「小组企业域模块」（流程证据逻辑）；和行业专家交流切换到「公共行业域模块」（论文数据共识逻辑）。人脑自动做了域隔离+专家模块路由，AI 知识库接近人类认知就必须复刻这套机制。

## 🔍 深度辨析报告

### 原理解析

MoE-KB 的本质是**把大模型 MoE 的「条件计算（conditional computation）」思想移植到数据检索层**：MoE 的核心创新是「不是所有参数都参与每个 token 的计算」，MoE-KB 对应「不是所有知识库都参与每个查询的检索」——两者共享同一个效率哲学：**用路由（routing）替代全量计算，用专业化（specialization）替代通用化**。

信任域体系则对应信息论/安全领域的**最小权限原则 + 数据分类分级**：域树本质是一个权限层次结构（类似于 RBAC 中的角色层级 + Bell-LaPadula 模型的"不能向上读、不能向下写"），跨域受控同步对应安全领域的**单向信息流控制**。对话用「家庭-小组-企业-国家」做类比，实际是数据主权（data sovereignty）在个人知识库层面的复刻。

双维路由（权限域×知识域）本质是**两个正交的过滤维度**：权限域解决「能不能看」（访问控制），知识域解决「看哪块」（检索范围）。这与数据库的「行级安全（RLS）× schema 分库」是同一结构。

### 与本知识库体系的对接

- **直接对应本系统实践**：本知识库的模块划分（02_rd / 03_AI / 04_person / 05_tools / 07_industry-research）本质就是「领域分库」；MEMORY.md 的「系统三位一体」就是多库隔离思想的实践。
- **权限域是本系统缺口**：当前 knowledge/ 全部文件无权限分级（单人使用场景可接受），但若未来多用户/企业化部署，域体系是必补架构。
- **可落地动作**：领域分库已有 → 补「跨库路由意图分类」和「分库元索引表」（记录每库领域/置信区间/更新周期），可对照 [知识索引治理](../02_rd/00_shared/README.md) 的注册表机制。

### 批判性评估

- ✅ **强项**：MoE 类比精准且非牵强（路由-专家-融合三步完整映射）；信任域体系补齐了纯技术分库缺失的「权限/信任」维度，使架构从「怎么存」延伸到「谁能用」。
- ⚠️ **挑战 1：路由准确性是生死线**——MoE 中门控网络是训练出来的，知识库路由若用规则/小模型分类，误路由直接导致召回失败；对话未给出路由分类器方案。
- ⚠️ **挑战 2：域划分粒度**——「粗分大类库+库内标签分片」vs「细碎小库」的平衡需要数据支撑，对话给了避坑提醒但无数值指导。
- ⚠️ **挑战 3：域间知识重复**——同一知识可能跨域存在（论文既在公共域又在小组成员笔记中），重复存储与一致性同步问题未解决。
- ❌ **未覆盖**：多库间的统一嵌入模型选择（每库定制嵌入 vs 全局统一，影响跨库可比性）、域迁移时的向量重嵌入成本。
