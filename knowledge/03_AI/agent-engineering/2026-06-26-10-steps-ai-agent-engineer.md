## 核心观点

AI Agent 工程师处于 **软件工程、机器学习、提示词工程和系统设计** 的交汇处。**不需要 AI 博士学位**——需要的是扎实的基础、实际项目，以及将工具连接成可运行系统的能力。

## 十条学习路线

| 阶段 | 内容 | 关键产出 |
|:----|:-----|:---------|
| **① 编程基础** | Python（变量/函数/OOP/异步/文件处理/API 交互/JOSN 解析） | 构建 Python 应用：读取 PDF → 调 LLM → 返回摘要 |
| **② LLM 工作机理** | Token/上下文窗口/嵌入/注意力/Transformer/温度/幻觉/RAG vs 微调 | 先调 API，再研究底层概念，建立实践直觉 |
| **③ 提示词工程** | 系统指令设计 · JSON schema 强制 · 工具调用约束 · zero-shot/few-shot/CoT | 构建聊天机器人/简历解析器/代码审查工具 |
| **④ API 与工具调用** | REST API · 认证 · 速率限制 · 函数调用 · 结构化输出 · Webhook | 完整工作流：搜索→提取→总结→存储→输出给用户 |
| **⑤ Agent 框架** | LangChain / LangGraph / LlamaIndex / CrewAI / AutoGen | **先理解工作流，再学框架**——框架是生产力工具而非智能本身 |
| **⑥ RAG** | 嵌入 · 向量数据库 · 分块 · 语义搜索 · 混合搜索 · 重排序 | 构建 PDF 聊天机器人（嵌入+检索+提示注入+记忆一站式练手） |
| **⑦ 记忆与状态** | 短期/长期/情景/语义记忆 · 对话历史 · 状态管理 · 上下文压缩 | Agent 记住用户偏好、先前操作、任务进度 |
| **⑧ 多 Agent 系统** | 研究 Agent + 编码 Agent + 评审 Agent 协同 | **从 1 Agent + 1 Tool + 1 Memory 起步**，避免过度工程化 |
| **⑨ 部署与生产工程** | 监控 · 日志 · 成本优化 · 延迟降低 · 缓存 · 速率限制 · 安全 · 评估管道 | Docker + FastAPI + PostgreSQL + 可观测性工具 |
| **⑩ 作品集** | AI 研究助手 · 多文档 RAG 聊天 · 编码助手 · 自主网络研究 Agent | 展示工具使用 + 记忆 + 检索 + 结构化输出 + 编排 + 部署 |

## 推荐学习顺序

```text
Python 基础 -> API 和 JSON -> LLM 基础 -> 提示词工程 -> 工具调用
-> RAG 系统 -> Agent 框架 -> 记忆系统 -> 多 Agent 编排 -> 生产部署
```

## 初学者四大常见错误

1. **追逐每一个新框架**：概念比工具重要，理解工作流就能快速学新框架
2. **忽视软件工程**：AI Agent 仍是软件系统，干净架构和后端基础不能跳
3. **构建过于复杂的 Agent**：简单系统通常效果更好、更容易维护
4. **跳过评估**：评估正在成为最有价值的 AI 工程技能之一

## 最终思考

> 成功的工程师不一定是使用最复杂框架的人；他们是理解智能系统如何运行、如何失败、以及如何交付可靠结果的人。

软件的未来正在从静态应用转向智能系统，而 AI Agent 工程师就是构建这个未来的人。

## 🤔 个人思考

### 1. 这篇文章与"Agent 工程化四件套"的对照

今天归档的前四篇（Agent OS / 工具链工程化 / GEPA / Workflow Runtime）构成了一套**自底向上的工程方法论**：

| 维度 | Agent 工程化四件套 | 本文学到的 |
|:-----|:-----------------|:-----------|
| 目标用户 | 已有基础、想深入工程化的开发者 | **零基础起步、系统规划路线**的人 |
| 视角 | 架构设计 / 代码实现 | 学习路径 / 技能树 / 成长阶段 |
| 方法论密度 | 极高（1.5万字+） | 适中（入门友好） |

两者是**互补而非重复**——可以先按本文规划学习方向，再到工程化系列深入每个技术细节。

### 2. 最有价值的三个洞察

**①「先理解工作流，再学框架」**——这和我归档的 Workflow Runtime 文章内核完全一致：把流程从框架中抽象出来，框架只是实现工具，不是思考起点。

**②「评估正在成为最有价值的 AI 工程技能之一」**——大多数人在写提示词和搭框架，很少有人认真评估召回率、工具调用准确率、成本基准线。这是从"爱好者"到"专业者"的分水岭。

**③「从 1 Agent + 1 Tool + 1 Memory 起步」**——很多人的第一个项目就上多 Agent 编排，结果是 debug 时间 >> 设计时间。这个建议和我归档的 Agent OS 文章中"确定性优先"原则完全吻合。

### 3. 一个值得补充的缺口

这篇文章覆盖了"学什么"和"学什么顺序"，但**没有涉及"如何判断自己到了哪个阶段"**。如果能补充阶段评估标准（例如：阶段③的标志是能写出稳定输出 JSON 的 prompt、阶段⑥的标志是能设计分块策略并解释为什么选这个块大小），会更有落地价值。
