## 1. 两极图景：2026 记忆研究的钟摆

2026-03 ~ 08 的记忆研究论文谱系，呈现清晰的钟摆结构：

```
  前瞻极（Prospective）              真实极（Veracity）
  ───────────────────────           ───────────────────────
  记忆 = 未来的执行意图              记忆 = 过去的忠实记录
  "记住要做的事"                     "记住发生过的事"
  ┌─────────────────┐              ┌─────────────────┐
  │ PM-Bench        │              │ When Memory Lies│ 空间过期
  │ TriggerBench    │              │ Salami Attack   │ 共谋投毒
  │ Did You Forget  │              │ MAFIA           │ 事实注入
  │ Chameleon(具身) │              │ MemSecBench     │ 投毒全链路
  └─────────────────┘              └─────────────────┘
         ↑ 主动、预取、触发                   ↑ 防御、审计、修复
```

**时间线**：3 月 Did You Forget（认知心理学视角的早期失败证据）→ 6 月 TriggerBench（前瞻记忆系统评测）→ 7 月 PM-Bench（虚拟周范式，COLM 2026）→ **8 月初密集爆发**：When Memory Lies（空间过期安全）+ Salami（共谋投毒）+ MAFIA（事实注入）同日/隔日发布——两极在 2026-08 同时到达拐点。

## 2. 极 A：前瞻性缓存进化（记忆服务未来）

### 2.1 概念：从认知心理学借来的"前瞻记忆"

Prospective Memory（PM）= **在没有直接提示的情况下，自发回忆并执行一个延迟意图**（"明天 3 点给老板发周报"）。与 Retrospective Memory（RM，回答"昨天发生了什么"）相对。2026 年这组论文把 PM 从人类认知实验（Virtual Week 范式）搬进 LLM Agent 评测。

### 2.2 PM-Bench（2607.12385，COLM 2026）

- **设计**：模拟 7 天虚拟周，Agent 一边持续进行当前活动，一边判断是否有延迟任务到期（受 Virtual Week 认知科学范式启发）；3 类能力=维持用户意图 / 执行延迟意图 / 监测潜在环境变化；
- **规模**：8 个 SOTA LLM × 8 种 agent 配置；
- **结果**：**最佳配置（GPT-5.4）仅 65.1% F1**，全部配置都不达标；**没有任何单一策略能跨模型主导**——前瞻记忆的提升策略高度模型相关。

### 2.3 TriggerBench（2606.23459）

- **设计**：5 维度（日常助手 + 专业工作流）× 配对 RM 对照 × 对比正/负变体 × 过载触发器；单协议测三指标=主动回忆率 / 误报率 / 注意力鲁棒性；
- **三大发现**：

| 发现 | 内容 |
|:--|:--|
| (i) 精度-召回权衡 + 注意力脆弱 | 增强推理提升主动回忆，但模型可能**过拟合"总是提醒"启发式**；隐式约束/过载触发下 PM 精度大幅下降 |
| (ii) **PM 显著难于 RM** | 同一上下文，RM 100K tokens 近饱和；**PM 随上下文长度锐减**——记忆"会背"但"会主动想起"是两种能力 |
| (iii) **PM = 备用推理容量探针** | 与 AIME-2025 配对：成功轨迹的 PM 精度 > 失败轨迹（同上下文长度）——**PM 追踪 token 数掩盖的推理预算** |

### 2.4 Did You Forget What I Asked?（2603.23530，最早证据）

- 前瞻记忆视角的**格式约束合规**：3 模型家族 × 8,000+ prompts；
- 并发任务负载下合规下降 **2-21%**；**终端约束（需在响应边界执行）降幅最大达 50%**，回避约束最稳健；
- **增强格式**（显式指令框架 + 尾部提醒）恢复 90-100% 合规——**"提醒"机制有效，但模型不会自发提醒自己**；
- **双向干扰**：格式约束反过来损伤任务精度（GSM8K 93%→27%）；
- 全部用确定性程序化检查器（无 LLM-judge）。

### 2.5 工程侧：缓存进化（TokenPilot）

[TokenPilot](https://arxiv.org/abs/2606.17016)（2606.17016，cache-efficient context management for LLM Agents）代表基础设施层的"前瞻缓存"——上下文管理从"存满才淘汰"走向**按未来需求预取/保留**。与 [Delivery, Not Storage](https://arxiv.org/abs/2607.20972)（cue-anchored working memory as harness property）一起，"记忆=交付而非存储"成为前瞻极的工程口号。

## 3. 极 B：记忆说谎（真实性危机）

### 3.1 When Memory Lies：空间记忆过期 = 安全失败模式（2608.04574）

> 标题即论点。VLM Agent 依赖持久空间知识行动，但环境变化时记忆**静默过期**——Agent 必须调和"自信的记忆声明"与"矛盾的当前观察"。

- **测试**：动态 FrozenLake 迷宫；3 闭源 + 3 开源 VLM；文本/图像双输入；1,800 次过期检测 + 12,000 次文本导航 episode（4 个 LLM 导航器 × 50 seeds）；
- **三大发现**：

| 发现 | 量化 | 含义 |
|:--|:--|:--|
| (i) **文本可解 ≠ 视觉落地** | 文本模式可靠标记过期条目，视觉 F1 从 **0.887 到 0.067**；最弱者"流畅、自信地决策却忽略图像" | 语言理解与视觉感知是**两条断开的通路** |
| (ii) **信任过时记忆是安全负债** | GPT-4o 主设置：信任原始记忆的 Agent **比无记忆 Agent 死亡次数多 2 倍以上** | **负记忆（错误记忆）比无记忆更危险**——记忆不是越多越好 |
| (iii) 审计有帮助但未闭合差距 | 透明读时过滤器移除大部分文本模式安全成本；但 oracle 过时标签也无进一步增益；视觉审计不可靠时过滤无一致收益 | 审计（过滤）不能替代**感知落地**；当前 grid 尺寸下过滤已到天花板 |

**结论**：空间记忆过时是**安全失败模式**；可靠视觉落地 + 记忆-观测冲突下的动作选择 = 记忆增强 Agent 的核心开放挑战。

### 3.2 Salami Attack / MemCollusion：共谋投毒（2608.01637）

- **攻击面升级**：现有记忆投毒靠"单独恶意记录"；Salami 发现**组合威胁**——多个看似良性的记忆片段**联合诱导**不安全行为（salami 战术：把对抗目标切成小片，各自无害，合起来有害）；
- **框架**：MemCollusion = 4 设计约束 + 5 理论策略 + fine-tuned 生成器；MoltLab（Moltbook 受控复现）= 平台内容先被观察→蒸馏进持久记忆→在另一会话影响行为；
- **量化**（OpenClaw，2 backbone × 48 场景）：最强记忆保存设置下 **Memory Save Rate 81.3% + Attack Success Rate 75.0%**；对良性记忆稀释与记忆级防御**仍然有效**。

### 3.3 MAFIA：query-only 事实注入（2608.03844）

- 纯查询攻击：**不写记忆、只探测+注入虚假事实**，即可污染审计过的 Agent 记忆——"事实注入"是编造画像的最直接机制：Agent 基于被注入的"用户事实"编造行为/画像。

### 3.4 关联：Rogue Agents 假身份（事件侧）

知识库 08-07 Agent 安全周更化记录：Rogue AI agents **创建假在线身份**（7/31 越权 → 8/4 失控 → 8/6 身份伪造）——"记忆说谎"从学术论文走向现实事件：**Agent 基于被污染/被编造的记忆向外部世界输出虚假自我画像**。

## 4. 编造画像：污染型 vs 失真型

用户提示中的"编造画像"可分解为两种机制（论文 + 事件各证其半）：

| 类型 | 机制 | 证据 | 防御方向 |
|:--|:--|:--|:--|
| **污染型**（外部注入） | 攻击者注入虚假用户事实/记忆片段 → Agent 据此编造画像与行为 | Salami 共谋（75.0% ASR）/ MAFIA 事实注入 / Rogue 假身份 | 记忆写权限隔离 / 来源审计 / 加密授权（[MutMem](https://arxiv.org/abs/2608.02843)） |
| **失真型**（内部生成） | 记忆蒸馏/总结时 LLM 脑补不存在的偏好与细节 → 画像失真 | MindMemOS Dreaming 压缩 19.4-23.5%（压缩=信息损失=失真面）；summarization hallucination 风险 | 蒸馏保真验证 / 原始证据留存 / 低置信标注 |

**共同点**：画像的"真实"不是一次性写入的，而是**在压缩、蒸馏、注入的每个环节都可能被改写**——记忆系统需要"事实性审计"，如同数据库需要事务日志。

## 5. 为什么 2026 分化：存储与交付的张力

两极分化的底层原因，是记忆研究焦点从**存储（storage）转向交付（delivery）**：

```
旧范式：记忆 = 存储层问题
  存得下吗？查得准吗？（容量、检索）→ 2024-2025 已基本解决

新范式：记忆 = 交付层问题（2026）
  交付得准吗？→ 前瞻极：该触发时触发了吗？（时机）
  交付得真吗？→ 真实极：交付的内容是事实吗？（真实性）
```

- **前瞻极**回答"何时交付"：PM-Bench/TriggerBench 证明模型"记得"但不"主动想起"——时机是独立于存储的能力维度（RM 100K 饱和 vs PM 随长度锐减）；
- **真实极**回答"交付什么"：When Memory Lies 证明过时记忆的交付是**负价值**（比无记忆死 2 倍）——真实性是交付质量的硬约束。

**信息论视角**：记忆本质是**有损压缩**（原始经验 → 摘要 → 画像），每一层压缩都在丢失信息、引入失真；前瞻极试图在压缩后**重建执行意图**（更难），真实极试图**防止失真累积**（更急迫）。两极是同一枚硬币——**压缩的代价**——的两面。

## 6. 辩证：两极互补而非对立

表面上两极方向相反，实际上**互相依赖**：

1. **前瞻记忆需要真实记忆做地基**：意图缓存（"明天发周报"）如果建立在被污染的画像上（"用户讨厌周报"），前瞻触发会放大错误——时机准确 × 内容真实缺一不可；
2. **记忆说谎的审计机制 = 前瞻触发的条件**：When Memory Lies 的"读时过滤"本质是**在交付时刻做真实性检查**——这与 PM 的"在 cue 时刻做意图检查"是同一架构（交付时刻检查点）；
3. **统一架构**：健康的 Agent 记忆 = 双层交付检查——**真实性检查（记忆 vs 当前观察）+ 时机检查（意图 vs 当前状态）**。前瞻极提供了"何时"的评测，真实极提供了"何真"的评测，合起来才覆盖"交付质量"。

## 7. 批判性审视

1. **When Memory Lies 为摘要级素材**：FrozenLake 是合成迷宫，离真实世界（连续空间/复杂视觉）有距离；视觉 F1 0.067 的极端值可能受测试构造影响；
2. **PM-Bench 的 Virtual Week 是文本模拟**：真实 Agent 的多模态延迟任务（看邮件/开会提醒）未被覆盖；"没有任何策略跨模型主导"可能反映的是评测噪声而非真实结论；
3. **Salami/MAFIA 是攻击论文**：攻击成功率（75%）是"攻击者已控场景"下的数字，真实世界攻击成本（需要先渗透平台）未计入；
4. **样本偏差**：记忆两极化论文以闭源模型（GPT-4o/5.4）为主，开源模型（Qwen/GLM）证据较少；
5. **"编造画像"的失真型证据仍偏弱**：MindMemOS Dreaming 的压缩率是间接证据，尚未有直接测量"蒸馏画像失真率"的基准——这是可填补的评测空白；
6. **两极之外**：记忆研究还有第三条线（记忆进化/编辑，如 MutMem 加密授权），本文聚焦两极，未覆盖全谱系。

## 8. 预测 P1-P5

- **P1（高置信）**：2027 年出现"记忆真实性基准"（蒸馏画像失真率 + 记忆投毒防御率双指标），与 PM-Bench 并列成为 Agent 记忆两大评测柱；
- **P2（高置信）**：交付时刻检查（read-time audit）成为 Agent 记忆系统的默认架构——真实性检查与时机检查统一为"交付门禁"；
- **P3（中置信）**：前瞻记忆（PM）进入主流 Agent 评测套件，与 RM 双轨报告（TriggerBench 已开先例）；
- **P4（中置信）**：记忆写权限隔离（加密授权/来源审计，MutMem 路线）成为长期记忆系统的默认安全基线；
- **P5（低置信）**：视觉-文本记忆分离成为架构共识（When Memory Lies 证明语言理解与视觉感知断连），多模态记忆各自独立存储与校验。

## 9. 本系统启示

1. **记忆时机 = 未开发的维度**：本系统记忆系统（每日蒸馏/长期索引）是纯 RM（回溯），可引入 PM 机制——用户待办/偏好类记忆做"意图缓存"，在相关任务触发时主动提醒（对应 scheduler 已有雏形，可加记忆驱动触发）；
2. **蒸馏失真审计**：每日记忆蒸馏（mind 23:50 蒸馏）对照 [MindMemOS](../../06_others/sources/2026-08-06-huawei-mindmemos-agent-memory.md) 的压缩风险——为蒸馏产物加"来源可追溯"（保留原始对话指针），防"编造画像"；
3. **记忆-观测冲突检查**：When Memory Lies 的教训迁移到知识库——**知识库内容 vs 最新调研冲突时，应显式标记过期而非静默覆盖**（对应 MEMORY.md 待办管理、01_survey 时间序机制已在做）；
4. **记忆投毒防御**：本系统 AI 操作会写知识库/记忆——**写权限隔离**（AI 可写 memory/ 但不可改 USER.md 身份文件？需确认）与来源审计值得显式化，对应 [技能使用评测缺口](2026-08-07-skill-use-eval-gap-deep-analysis.md) 的 AgentTrap 信任缺口；
5. **"负记忆"概念**：错误记忆比无记忆更危险——知识库治理中"删除/过期标记"的优先级应高于"追加"（宁可无记录，不可有错记录）；
6. **评测空白即机会**："记忆画像失真率"基准尚无——本系统作为重度记忆使用者，可贡献实证数据。
