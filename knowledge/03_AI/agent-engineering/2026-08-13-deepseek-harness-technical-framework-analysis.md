## 〇、结论概要

1. **定位**：DeepSeek Harness 是 DeepSeek 补齐"模型→工作流"最后一公里的战略产品。模型负责"想"，Harness 负责把"想"稳定落地为真实世界的执行。它不是又一个开源 Agent 框架，而是对标 **Claude Code / Codex 的完整 Coding Agent**，并进一步扩展为**开放生态底座**（plugin/skill/MCP/orchestrator/aggregator/UI 六方向）。

2. **底层原理**：Harness 的本质是**把大模型的概率生成转化为确定性执行系统**——通过上下文管理（对抗 1M token 窗口溢出）、工具编排（意图→真实世界操作）、沙箱执行（安全边界）、反馈循环（错误→自我修正）四重机制，解决 LLM 单独使用时"只会聊天、不会干活"的根本缺陷。核心经济杠杆是 **Prompt Caching 缓存命中率**（DeepSeek 缓存命中 0.02 元 vs 未命中 1 元/百万 token，差 50 倍）。

3. **团队与节奏**：2026 年 3 月崔添翼（前 Jane Street 量化交易工程师）加入组建 Harness 团队，7 月底 V4-Flash 模型卡已使用 Harness（minimal 模式+max 推理强度）跑出亮眼代码 Agent 成绩，8 月 1 日公开招募内测、8 月 5 日划定生态边界。节奏极快，5 个月从 0 到内测。

4. **竞争判断**：DeepSeek Harness 的真正对手不是开源 Agent 框架，而是 **Claude Code（年化收入 $2.5B、占 GitHub 公开提交量 4%）和 Codex**。差异化在于：开放多模型生态 + 极致性价比（单次任务约 $0.028，约为 Claude Code 1/7）+ 国产合规（Claude Code 被工信部 NVDB 确认安全后门）。"便宜模型打出豪华战绩"是其核心叙事。

5. **风险**：生态冷启动、长程任务可靠性未经验证、多模型适配工程复杂度、用户迁移成本。但 V4-Flash 单周 10 万亿 token 调用量登顶全球，说明模型侧弹药充足。

## 一、背景：为什么 DeepSeek 要亲自下场做 Harness

### 1.1 黄仁勋×LangChain 对话：Harness 成为行业共识

2026 年 7 月初，黄仁勋与 LangChain 创始人 Harrison Chase 26 分钟公开对话，**全程未提 GPU 和算力，反复只讲一个词：Harness**。黄仁勋的论断是"未来的公司将建立在 Harness 之上"。

这个信号的意义：当 NVIDIA 掌门人在公开对话中不提芯片而讲软件层，说明行业竞争的主战场已从"造算力"迁移到"用算力"——**Harness 是把算力转化为业务价值的最后一层转化器**。

### 1.2 LangChain 实验：模型没变，分数追平，成本降 90%

LangChain 同期公布实验：用 NVIDIA Nemotron 3 Ultra 跑 Deep Agents 评测，**不改模型权重**，仅调整系统提示词、工具描述和中间件：

| 指标 | 调整前 | 调整后 |
|:--|:--:|:--:|
| Deep Agents 评测分数 | 基线水平 | **0.86**（最高分 0.87，差 0.01） |
| 单次评测成本 | $43.48 | **$4.48**（降 90%） |

**核心结论：模型没变，周围的系统变了。** Harness 不负责生成下一个 token，但决定：模型何时调用工具、访问哪些文件、任务拆成几步、出错后如何回退、执行到哪一步可以结束。这正是 Harness 的价值边界——**它不产生智能，但决定智能能否稳定兑现**。

### 1.3 DeepSeek 的"补课"：模型出海了，工程生态没跟上

**背景事实**：
- 2026 年 5 月 1 日，美国独立开发者 Hunter Bown 用 DeepSeek 模型做的终端编程 Agent，几天内 Star 冲到 11,000+，登顶 GitHub 全球 Trending——**DeepSeek 模型已足够好，海外开发者已围绕它构建 Agent**；
- 但开发者直接调用 DeepSeek 模型，或把它接入 Claude Code/OpenCode 等第三方 Agent 时，**真正决定开发体验的 Harness 掌握在别人手里**；
- 模型是 DeepSeek 的，体验是别人的。**DeepSeek 若想真正做自己的 Coding Agent，必须补回这一层**。

**V4-Flash-0731 模型卡的关键细节**：模型卡中明确写到"公开的代码 Agent 测试，使用了**尚未发布的 DeepSeek Harness**，执行 minimal 模式，同时开启 max 推理强度"——即那些亮眼成绩不是裸模型跑出来的，而是 **V4-Flash + Harness + 最大推理强度**的组合结果。这既是能力展示，也是官方对 Harness 价值的首次背书。

## 三、核心架构：五大模块与底层原理

### 3.1 总览：Model + Harness = Agent 的职责切分

```
┌─────────────────────────────────────────────────────────┐
│                    DeepSeek Harness                      │
│                                                          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────────┐  │
│  │ 上下文    │ │ 工具调用  │ │ 执行沙箱  │ │ 反馈循环    │  │
│  │ 管理器    │ │ 编排系统  │ │ (隔离)   │ │ (自我修正)  │  │
│  └──────────┘ └──────────┘ └──────────┘ └────────────┘  │
│  ┌───────────────────────────────────────────────────┐   │
│  │          会话持久化 / 断点续传 (长程任务)            │   │
│  └───────────────────────────────────────────────────┘   │
│              ▲                    │                      │
│    需求/上下文 │                    │ 执行结果/错误反馈     │
│              ▼                    ▼                      │
│  ┌─────────────────────────────────────────────────┐    │
│  │         LLM（DeepSeek V4 系列 / 多模型）           │    │
│  │         负责：理解、推理、生成方案                 │    │
│  └─────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
        Model + Harness = Agent
```

**职责边界**：
- **Model**：理解需求 → 推理 → 生成方案/代码/工具调用意图
- **Harness**：调度上下文 → 编排工具 → 隔离执行 → 捕获反馈 → 持久化状态 → 驱动自我修正

### 3.2 上下文管理器：百万 Token 的智能压缩与检索

**问题**：LLM 上下文窗口有上限（DeepSeek V4 为 1M token），但长任务（多轮对话+工具结果+代码库扫描）极易撑爆窗口。

**机制**（行业主流方案，DeepSeek Harness 同类）：
1. **阈值触发压缩**：上下文达到窗口阈值的 80% 时触发（如 200K 窗口→167K 触发，预留 min(20K, 窗口/4) 给摘要、min(13K, 窗口/8) 给后续对话）
2. **保留最近 N 轮**：最后 3 轮完整对话（user/assistant/tool_call/tool_result 全部保留）不动
3. **历史摘要化**：保留区之前的历史由 LLM 生成摘要，摘要必须保留四类信息：**用户关键诉求、已完成操作、双方达成的共识、待办事项**
4. **动态检索注入**：从代码库/历史会话/外部知识源实时抽取相关片段精准注入 Prompt（RAG 式）
5. **事实沉淀到长期记忆**：避免摘要压缩丢失关键信息

### 3.3 工具调用编排：链式调用/重试/降级

- **链式调用**：多个工具按逻辑顺序组合执行（如 读文件→改代码→跑测试→看结果）
- **自动重试**：LLM 层重试 3 次、指数退避+随机抖动（基数 500ms、上限 30s），仅重试 429/5xx/408，400/401 不重试；工具层单工具失败不中断整体流程，失败作为 tool_result 返回给模型自行决策
- **失败降级**：工具调用失败自动尝试恢复或切换替代方案
- **并行执行**：无依赖的工具并行（如同时读 3 个文件）
- **能力范围**：文件系统读写、终端命令、浏览器自动化、第三方 API、MCP 工具

**Schema 约束三层防线**：
1. **Prompt 约束**：系统提示词定义行为边界（基础，非强制）
2. **工具 Schema**：每个工具 JSON Schema 校验参数（类型/必填/取值范围），不合规拒绝执行并返回模型重生成——**MCP 工具 Schema 需清洗**（展开 $ref、拍平 anyOf 联合类型，防模型生成错误参数格式）
3. **HITL 审批**：写操作（write_file/execute_command）执行前审批，策略分 auto/suggest/never 三档；路径检查器+命令检查器拦截越权操作；拒绝结果作为 tool_result 返回，模型可换方式达成目标

### 3.4 执行沙箱：安全隔离与结果捕获

- **隔离执行**：模型生成的代码在隔离环境运行，与宿主系统完全隔离，防恶意/错误代码破坏
- **完整捕获**：输出结果、运行日志、错误堆栈结构化返回上层
- **安全意义**：这是 Agent 从"Demo"走向"生产"的必要条件——**没有沙箱的 Agent 等于让模型直接操作生产环境**

### 3.5 反馈循环：自我修正的自动化闭环

```
生成代码 → 沙箱执行 → 捕获输出/报错 → 反馈给模型
    ↑                                            │
    └────────── 模型自我诊断 → 生成修正方案 ←──────┘
```

- 沙箱执行结果、错误信息、性能指标自动回传模型
- 模型基于反馈诊断根因、生成修正方案、再次进入沙箱验证
- 这是 Harness 实现"写代码→运行→看报错→修改"自动化闭环的核心

### 3.6 会话持久化与断点续传

- 长程任务状态持久化，中断后从断点恢复
- 保障复杂任务（多轮重构、大型迁移）的连续性与可靠性
- 跨会话记忆：用户偏好/项目规则跨会话保留（/clear 只清短期记忆与对话历史，长期记忆不受影响）

### 3.7 泄露架构细节：Sub-agent / KV Cache 智能复用 / 跨会话记忆

据社区流传的架构信息（尚未官方确认，标注为泄露级）：

| 特性 | 说明 | 底层价值 |
|:--|:--|:--|
| **Sub-agent** | 主 Agent 派生子 Agent 处理子任务（如摘要压缩、并行调研） | 对抗上下文窗口上限；任务分解并行化 |
| **KV Cache 智能复用** | 复用已计算的 KV Cache 避免重复 prefill | 推理成本大幅下降（配合 DeepSeek 缓存机制） |
| **跨会话记忆持久化** | 长期记忆跨会话存活 | 连续工作流，Agent 记住用户偏好与项目规则 |

> ⚠️ 标注：以上三点来自社区转述（paicoding/知乎等），未经官方架构文档确认，作为线索参考而非事实。

## 四、底层原理第一性拆解

### 4.1 Harness 的本质：把"概率生成"变成"确定性执行"

LLM 的本质是**概率性 token 生成器**——它在每个位置输出的是下一个 token 的概率分布。而真实世界的执行系统需要的是**确定性**：文件写入了没有？命令执行成功没有？任务完成没有？

```
概率世界（Model）                    确定性世界（执行）
┌──────────────┐     Harness     ┌──────────────────┐
│ P(next token)│ ──────────────→ │ 文件已写入/命令已  │
│ 只会"说"     │   意图→动作      │ 执行/任务已完成    │
│ 无状态/易遗忘 │   反馈→纠错      │ 有状态/可恢复      │
└──────────────┘   边界→安全      └──────────────────┘
```

**Harness 是概率世界与确定性世界之间的翻译层与保险层**：把模型的意图翻译为动作（工具编排），用反馈把执行结果翻译回模型的输入（反馈循环），用沙箱保证翻译错误不造成破坏（安全边界），用持久化保证翻译过程可中断恢复（状态管理）。

### 4.2 上下文经济学：缓存命中率是成本胜负手

DeepSeek 的定价结构（V4）揭示了 Harness 成本模型的命门：

| 场景 | 价格（每百万 token 输入） | 倍差 |
|:--|:--:|:--:|
| 缓存命中（cache hit） | **0.02 元** | 1× |
| 未命中（cache miss） | 1 元 | **50×** |

**含义**：Agent 每轮对话都带着巨大的系统提示词+历史（几万到几十万 token），若每次都不命中缓存，成本线性爆炸。**Harness 的 Prompt 组织方式直接决定缓存命中率**：
- 静态内容（身份/人格/模式指令/审批策略）放最前 → 最长公共前缀命中
- 动态内容（工具结果/对话历史）放后面 → 前缀稳定
- 经验法则：**Prompt 前 4 层静态化，缓存命中率最大化**

DeepSeek Harness 的"单次任务约 $0.028"正是缓存机制+KV Cache 复用+minimal 上下文共同作用的结果——**成本优势不只是模型便宜，更是 Harness 把"便宜"结构化放大了**。

### 4.3 为什么 53 个百分点的差距来自 Harness

社区流传数据：**同一模型在不同 Harness 下表现可差出 53 个百分点**。第一性解释：
1. **上下文质量**：同样的模型，喂 20K 精心组织的上下文 vs 喂 200K 混杂上下文，推理质量天差地别（注意力稀释）
2. **工具可用性**：Harness 决定模型"能用什么工具"——工具丰富度+Schema 清晰度决定任务可达边界
3. **纠错能力**：反馈循环决定模型能否从失败中恢复——无反馈循环的 Agent 一次失败即任务终止
4. **成本预算**：Harness 决定 token 分配策略（小任务小模型、大任务大模型），影响整体效率

**结论：模型是发动机，Harness 是底盘+变速箱+导航。发动机排量相同，整车性能取决于底盘调校。**

## 七、使用方案

### 7.1 当前状态：内测中

- **2026-08-01 起**：公开招募内测，优先 plugin/skill/MCP/Agent 开源项目方，赠送 API 额度
- **普通用户**：暂无法直接下载使用
- **社区接入**：有开源项目的开发者可在 X 回复 GitHub ID+项目地址报名

### 7.2 成本模型：$0.028 的由来

社区实测：配合 DeepSeek 低价缓存机制，单次真实编程任务平均成本约 **$0.028**，约为 Claude Code 的 1/7。

成本构成拆解（估算）：
```
单任务成本 ≈ Σ(每轮 LLM 调用 token 数 × 单价)
          其中：输入 token 主要靠缓存命中（0.02 元/百万）
               输出 token 为主要变量
DeepSeek V4 缓存命中输入价 0.02 元/百万 vs 未命中 1 元/百万
→ Harness 通过 Prompt 前缀静态化最大化命中率
```

对比锚点：V4-Flash 单周调用量 10 万亿 token 登顶全球；智能指数仅比 GPT-5.6 Luna 低 1 分，平均基准任务成本 $0.03（Claude Fable 5 的约 1/100）。

### 7.3 接入路径与部署形态

| 形态 | 说明 | 适用场景 |
|:--|:--|:--|
| API 接入（内测） | 官方内测通道，赠送额度 | 开发者/开源项目 |
| 私有化部署 | 企业本地部署 | 金融/政务/医疗等安全敏感行业 |
| 生态接入 | plugin/skill/MCP/orchestrator/aggregator/UI 六方向 | 生态伙伴 |
| 模型解耦 | 标准化接口支持多模型 | 已有非 DeepSeek 模型资产的企业 |

## 八、风险与挑战

| # | 风险 | 分析 |
|:--|:--|:--|
| R1 | **先发巨头挤压** | Claude Code 年化 $2.5B、占 GitHub 公开提交 4%；Codex 生态成熟。后来者需在生态和用户习惯上突破 |
| R2 | **生态冷启动** | Harness 价值高度依赖 plugin/skill/MCP/UI 生态丰富度，建设需长期积累 |
| R3 | **长程任务可靠性** | 多轮推理+工具调用+失败重试的复杂场景，从内测到生产级稳定交付需大量工程验证 |
| R4 | **多模型适配复杂度** | 不同模型上下文机制/工具调用格式/推理特性各异，适配维护成本高（社区已见各家 Prompt Caching 模式不兼容：GLM 用 glm-prompt-cache、DeepSeek 用 automatic-prefix-cache、Kimi 用 moonshot-context-cache） |
| R5 | **用户迁移成本** | 开发者已习惯 Claude Code/Cursor 工作流，切换面临学习成本与工具链重构 |

**对知识库的启示**：DeepSeek Harness 与知识库 harness 研究线强相关——HarnessOpt-Bench 表明"LLM 优化 harness 是可测量能力"，DeepSeek 亲自下场做 harness 是这一研究方向的产业验证；后续应跟踪其内测放量后的实际性能数据（尤其 minimal/max 推理强度的实际效果差异）。

## 九、行业影响与展望

1. **对 DeepSeek**：Harness 是"模型性价比→工作流性价比"的转化层。模型已登顶（V4-Flash 单周 10 万亿 token），Harness 决定能否把性价比优势稳定转成用户留存。**豆包下载量超 DeepSeek 的启示：谁离用户工作流更近，谁留下用户。**

2. **对行业**：黄仁勋"公司建立在 Harness 之上"的论断 + DeepSeek 下场，标志着 **Agent 工程化从"可选优化"变为"战略必争"**。模型能力差距在收敛，工程层差距在扩大。

3. **对中国市场**：Claude Code 被工信部确认后门 + DeepSeek Harness 国产自研，**合规性成为国内 Agent 工具选型的决定性变量**。政企/金融/医疗市场将率先切换。

4. **技术趋势**：Harness 未来五年成为主题。核心竞争维度：上下文管理、Memory 管理、多 Agent 协作、提示词优化。**拥有 Harness 工程经验的人才将成为稀缺资源**（DeepSeek 面试题已覆盖：三路径架构、上下文压缩、混合检索、记忆分层、容错设计、Schema 约束、HITL 审批——见 paicoding 13 题）。

5. **展望**：若 DeepSeek Harness 内测顺利，2026H2-2027 可能看到：①正式版发布+多模型接入；②与 DeepSeek 推理基础设施（V4 缓存/KV Cache 复用）深度整合的成本杀手锏；③中国 Agent 工具市场格局重塑（国产三强 Qoder/Kimi Code/Zcode + DeepSeek Harness 混战）。
