## 1. 核心命题与结论速览

> **核心命题**：记忆研究 2026 年的范式转移——从「**存什么**」（记忆=存储问题：容量/检索/组织）转向「**什么能信、能信多久**」（记忆=信任问题：真实性/时效性/来源）——不是学术口号，而是被三篇论文量化的**可靠性危机**。其中 Personalization Mirage 对本系统的含义最直接：**我们的运行模型（DeepSeek-v4-flash）OI 44.6%，意味着画像蒸馏产物中近一半可能是模型「编造」的用户属性**。治理不是可选项，是记忆系统的安全组件。

**五个核心论断**：

1. **范式转移 = 从「记忆是仓库」到「记忆是信任对象」**：「存什么」范式解决的是「找得到」（Recall），「什么能信」范式解决的是「信得过」（Trust）——后者的失败模式是**静默的**（不报错、不提示、内容看似合理），比「找不到」危险一个数量级。
2. **OI 是内生的，不是投毒**：Salami 式投毒（81.3% 保存率）是**外部注入**，防御靠写权限隔离；OI 是**模型自身在生成画像时编造**（12/12 模型 35-49%），防御必须靠**证据溯源 + 分层标注**——防御面从「写权限」扩展到「推断治理」。
3. **自我监控反转是信任架构的颠覆**：模型自评 OI 与实测 OI 负秩相关（ρ=-0.60）——「让 AI 自检画像是否准确」不仅无效，而且**自检结果与真实准确性负相关**。信任只能建立在外部验证链上（用户显式确认/行为佐证/来源标注），不能建立在模型自评上。
4. **本系统画像机制的信任缺陷是结构性的**：USER.md/MEMORY.md 的画像条目**无证据标注、无来源分级、无时效衰减、只增不修**——完美复现 Mirage 的「静默画像污染」条件（推断累积几乎不修订，top5 移除率仅 0.4-5%）。
5. **治理方案核心 = 三层证据标注 + 四态生命周期**：L1 用户显式陈述 > L2 行为观察 > L3 模型推断；L3 必须经佐证升级才能固化，否则只入暂存层——**把「画像」从「记住的事实」重新定义为「带证据的假设」**。

## 2. 范式转移再论证：从「存什么」到「什么能信、能信多久」

### 2.1 两个范式的本质差异

| 维度 | 「存什么」范式（2023-2025） | 「什么能信」范式（2026-） |
|:-----|:--------------------------|:--------------------------|
| 核心问题 | 记忆存哪、怎么检索、怎么组织 | 记忆**凭什么可信**、**多久有效**、来源是什么 |
| 记忆的定义 | 信息（需要保存的数据） | **证据（可追溯到源的断言）** |
| 失败模式 | 找不到（Recall miss） | **信错了（Trust violation，静默）** |
| 主要指标 | 检索精度、覆盖率 | 失真率（OI）、过期率、溯源完备度 |
| 代表工作 | Mem0/MemGPT/RAG | Scrub Jay / Mirage / When Memory Lies |
| 技术重心 | 向量库/索引/压缩 | **标注/验证/衰减/溯源** |

**关键差异**：「存什么」范式的失败是**可见的**（检索不到 → 用户发现）；「什么能信」范式的失败是**不可见的**（检索到了错误信息 → 用户**不知道**自己被骗了）。**静默性**是信任范式比存储范式更难的根本原因——错误画像一旦进入长期记忆，会持续污染后续所有决策，且不产生任何错误信号。

### 2.2 三篇论文如何证明转移

| 论文 | 维度 | 关键量化 | 证明什么 |
|:-----|:-----|:---------|:---------|
| **Personalization Mirage**（2608.04570） | 身份 | OI 35-49%（均值 41.6%，12/12 模型）；仅 24-31% 个性化内容有证据支撑；ρ=-0.60 自我监控反转；多轮累积 R²>0.90、top5 移除率 0.4-5% | **模型在「记住用户」时系统性编造**，且自检不可靠、错误不修订 |
| **When Memory Lies**（2608.04574） | 空间 | 视觉 F1 0.887→0.067；信任过时记忆比无记忆失败多 2 倍 | **过期的记忆比没有记忆更危险**——「能信多久」是硬约束 |
| **Scrub Jay**（2608.04746） | 时间 | 类型条件衰减 GenGap +0.108；消融衰减后塌缩 5.7× | **按内容类型设定保质期**是有效方案——「能信多久」可以被工程设计 |

> **三篇合起来回答了一个问题**：记忆的价值不在「存了多少」，而在「**交付时是否真实、准时**」——Mirage 证明「身份真实」可能缺失（编造画像）、When Memory Lies 证明「空间真实」会过期（环境变了）、Scrub Jay 证明「时间真实」需要衰减（类型保质）。**「真实+准时」成为记忆价值的新定义**（与 [记忆两极化](2026-08-07-memory-research-polarization-deep-analysis.md) 统一主线闭环）。

### 2.3 转移的深层原因

1. **记忆从「缓存」变成「资产」**：Agent 长程任务（Days-long）让记忆复用率上升——错误记忆的**复利效应**显现（Mirage Accum：错误画像静默累积 = 负记忆复利）。缓存丢一次损失小，资产错一次损失大。
2. **模型能力提升暴露了「生成性污染」**：早期模型检索失败是「查不到」（显式）；强模型会把检索失败**填补成看似合理的编造**（隐式）——能力越强，编造越难察觉（OI 反而是弱模型最高 Qwen3-8B 48.7%，需注意这是「能力弱→更易编造」的另一种表现）。
3. **评测从任务成功率转向真实性**：当个性化任务成功率饱和，研究者开始问「成功是不是建立在编造画像上」——**OI 类指标（失真率）成为新评测柱**（对应五篇深潜 P2 预测）。

## 3. 本系统画像机制现状审计

### 3.1 当前四层记忆结构

| 层 | 文件 | 更新频率 | 内容类型 | 当前信任管理 |
|:---|:-----|:--------:|:---------|:------------|
| **L0 身份层** | `USER.md` | 年更 | 用户身份/偏好（静态） | 人工维护，无证据标注 |
| **L0 长期层** | `MEMORY.md` | 月更 | 长期事实/决策/教训 | 主动记录，无证据标注 |
| **L1 日常层** | `memory/YYYY-MM-DD.md` | 日更 | 当天进展/讨论记录 | 直接写入，无来源分级 |
| **L2 知识层** | `knowledge/` | 持续 | 结构化知识 | **有**来源分级（L1-L3 数据链，08-07 供应链文档先例） |

### 3.2 结构性信任缺陷清单

对照 Mirage 的失败模式，本系统画像机制的缺陷是**结构性**的（不是执行问题，是设计问题）：

| # | 缺陷 | Mirage 对应 | 风险等级 |
|:-:|:-----|:------------|:--------:|
| D1 | **画像条目无证据标注**——USER.md/MEMORY.md 直接写「用户偏好 X」，无「用户说过/做过/我推断」来源字段 | OI 的直接温床：无法区分 Grounded vs 推断 | 🔴 高 |
| D2 | **只增不修**——画像一旦写入几乎不被推翻（无「新证据推翻旧画像」机制） | top5 移除率 0.4-5% = 静默画像污染 | 🔴 高 |
| D3 | **无时效衰减**——「用户 2024 年做 X」至今仍是画像，无类型保质期 | Scrub Jay 缺失：所有记忆同等持久 | 🟠 中 |
| D4 | **蒸馏无失真审计**——每日蒸馏（memory/）直接产生画像，无 OI 度量 | 失真率不可测 → 不可治理 | 🟠 中 |
| D5 | **自检依赖**——画像更新依赖「AI 自评记住了」 | ρ=-0.60：自评与真实负相关 | 🟠 中 |

> **现状结论**：本系统的画像蒸馏**恰好复现了 Mirage 的全部失败条件**（无标注 + 不修订 + 自检依赖），且运行模型 OI 44.6%——**这不是「未来可能出问题」，是「正在持续产生 ~44% 的编造画像」**。

## 4. 画像蒸馏的三层证据标注设计（核心方案）

### 4.1 三层证据来源体系

参照知识库已有的 L1-L3 数据链（08-07 供应链文档），画像条目引入**证据来源三级标注**：

```text
Evidence Source Levels (for profile entries)
+------------------------------------------------------------------+
| L1 Explicit   user directly states: "I prefer X"                 |
|   -> strongest, self-attested, irreversible unless user revokes  |
| L2 Behavioral user action observed: user did X repeatedly        |
|   -> grounded in logged behavior, needs L1 confirmation to fix   |
| L3 Inferred   model concludes: "user seems to prefer X"          |
|   -> lowest, must be corroborated by L1/L2 before promotion      |
+------------------------------------------------------------------+
Rule: L3 alone is a HYPOTHESIS, not a profile entry.
      Promote L3 -> L2 on 2nd independent behavioral observation.
      Promote L2 -> L1 on explicit user confirmation.
      OI = L3 entries that were never corroborated but treated as fact.
```

| 层级 | 定义 | 示例 | 可信度 | 处置规则 |
|:-----|:-----|:-----|:------:|:---------|
| **L1 显式陈述** | 用户直接说出的偏好/事实/决策 | 「我是服务器研发专家」「先结论再展开」 | ★★★ | 直接固化；用户撤销时删除 |
| **L2 行为观察** | 从用户行为/交互记录观察到的模式 | 「用户在 3 次深度分析中都要求数据可验证」 | ★★ | 二次独立观察可升级；写行为证据 |
| **L3 模型推断** | 模型从上下文推测的画像 | 「用户可能偏好 X（未验证）」 | ★ | **只入暂存层，不写入正式画像** |

**与 OI 的对应**：OI（过度推断）= 模型把 L3 当作 L1/L2 使用（无证据支撑却当作事实写入画像）。**分层标注的直接效果 = 让 OI 从「不可见」变成「可审计」**——凡是 L3 且未佐证的内容，就是潜在 OI，进入待验证队列而非正式画像。

### 4.2 画像条目的四态生命周期

```text
        L3 inference            L2 behavior x2           L1 user confirm
  NEW ----------------> CANDIDATE ----------------> FIXED ----------------> ACTIVE
  (hypothesis)          (behavioral evidence)       (explicitly stated)     (in use)
     |                       |                            |                    |
     | stale/no corrob.      | new contradicting evidence | user revokes       | type decay
     v                       v                            v                    v
  DISCARDED              DEMOTED (to NEW)               REVOKED            ARCHIVED
```
（四态：NEW 暂存 = L3 推断未验证；CANDIDATE 候选 = 有 L2 行为证据；FIXED 固化 = 有 L1 显式确认；ACTIVE 生效 = 使用中。离开路径：过期丢弃/反证降级/用户撤销/类型保质期到期）

| 状态 | 含义 | 进入条件 | 离开条件 |
|:-----|:-----|:---------|:---------|
| **NEW（暂存）** | L3 推断，未验证 | 模型推断产生 | 佐证升级 / 过期丢弃 |
| **CANDIDATE（候选）** | 有 L2 行为证据 | 2 次独立行为观察 | 用户确认 / 反证降级 |
| **FIXED（固化）** | 有 L1 显式确认 | 用户直接陈述 | 用户撤销 / 时效衰减 |
| **ACTIVE（生效）** | 正在使用的画像 | 固化后进入 | 类型保质期到期 |

> **核心规则**：**L3 永不经 L2 直达 L1**；「模型认为用户偏好 X」永远不能直接变成「用户偏好 X」——中间必须有行为佐证或显式确认。这直接对抗 OI 的「推断即固化」路径（Mirage 的静默累积正是因为没有这条规则）。

### 4.3 标注语法与元数据

画像条目采用轻量标注（不破坏可读性，兼容现有 Markdown）：

```markdown
<!-- profile entry template -->
- **Pref: quantitative-driven** ([src: L1-explicit, 2026-08-07 session] user: "no conclusions without data")
- **Role: tech decision-maker** ([src: L2-behavior, 3 deep-dives all required 5-look-3-decide])
- **Focus: AI infra** ([src: L3-inferred, pending] <- staging, promote after 2 behavioral evidences)
```

中文说明：标注语法为「来源层级-类型 + 时间 + 一句话证据」三元组；L3 条目带「待佐证」标记并驻留暂存层，2 次行为佐证后升级。

| 字段 | 内容 | 示例 |
|:-----|:-----|:-----|
| `来源` | L1/L2/L3 + 类型 | `L1-显式` / `L2-行为` / `L3-推断` |
| `时间` | 证据产生日期 | `2026-08-07` |
| `证据` | 一句话证据描述 | `用户原话"…"` / `连续 N 次…` |
| `状态` | NEW/CANDIDATE/FIXED/ACTIVE | `待佐证` / `已固化` |
| `保质期` | 类型条件（可选） | `偏好-长期` / `项目-短期` |

## 5. 对抗 OI 的五项治理机制

| # | 机制 | 原理 | 对应缺陷 | 落地方式 |
|:-:|:-----|:-----|:---------|:---------|
| **G1 证据标注** | 画像条目强制来源字段（§4.3） | OI 可审计化——编造从「隐形」变「可见」 | D1 | 画像写入模板化，检查脚本校验来源字段 |
| **G2 外部验证** | L3 升级必须经 L2 行为/L1 显式确认；不依赖模型自评 | 对抗 ρ=-0.60 自评反转 | D5 | 用户确认（对话中显式确认偏好时打标）；行为日志二次观察 |
| **G3 修订机制** | 新证据可推翻旧画像：ACTIVE 状态显式标记 REVOKED/DEMOTED | 对抗「只增不修」（top5 移除率 0.4-5%） | D2 | 画像条目维护纳入每日蒸馏流程：检查冲突证据 |
| **G4 时效衰减** | 按内容类型设保质期（Scrub Jay 类型条件衰减） | 对抗「所有记忆同等持久」 | D3 | 画像条目元数据加类型字段：身份-长期/偏好-中期/项目-短期 |
| **G5 失真审计** | 自建 OI 小基准：随机抽样画像条目验证 Grounded vs 推断 | 失真率可测才可治理（Mirage 提供量化基准 41.6%） | D4 | 月度审计：抽 N 条画像核证据链，算本系统 OI 率 |

**机制协同**：G1 是基础（让失真可见）→ G2 是核心（外部验证对抗自评反转）→ G3/G4 是维护（对抗累积与过期）→ G5 是闭环（度量治理效果）。**五机制共用同一底层逻辑：把「记住」变成「带证据地相信」**——与本系统知识库的 L1-L3 数据链、来源分级、素材边界声明完全同构，画像治理是知识库治理的「人维度」延伸。

**可证伪预测**（基于五篇深潜 P1-P5 + 本方案）：

## 7. 风险与批判

1. **方案基于单篇论文（Mirage）的探索性发现**：Self-Monitoring Inversion 为原文自认的探索性结果（n=12、宽 CI [-0.90, +0.06]、p=0.044 边缘显著）——ρ=-0.60 可能是小样本噪声，G2 的「不依赖自评」设计需要更稳健的证据
2. **OI 44.6% 的直接外推有偏差**：Mirage 评测是「画像生成任务」的专用设置，本系统蒸馏任务的 OI 率未必相同——44.6% 是**警示性参考**而非本系统实测值（G5 正是为了实测）
3. **标注成本的权衡**：全量来源标注增加维护负担（每日蒸馏 + 画像维护的认知负载）——方案采用「轻量标注」（内联字段），但长期维护成本仍需评估（对应 MEMORY 的 token 成本纪律）
4. **L2 行为观察的隐私边界**：行为日志佐证涉及用户数据使用——需限定在会话记录范围内，不做外部行为追踪
5. **「L3 永不过 L2」的过度严格**：部分画像（如「用户偏好先结论后展开」）可能永远得不到显式确认，严格规则会导致画像稀疏——需设计「L2 双证据+时间窗」的默认升级路径（可配置阈值）
6. **范式转移叙事可能夸大**：「存什么→什么能信」是研究前沿趋势，但主流 Agent 记忆系统（Mem0/MemGPT）仍是存储范式主导——转移是**方向性**判断（对应 H3/H4 证伪条件），不是已完成事实
