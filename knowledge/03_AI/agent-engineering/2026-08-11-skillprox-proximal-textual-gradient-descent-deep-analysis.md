## 〇、结论概要

**一句话：SkillProx 把「技能文本编辑」从无约束的启发式操作，升级为「带近端约束的文本空间优化」——用前向重执行闭环诊断、后向效用审计管理知识单元，让技能像参数一样被「优化」而非被「修补」。**

1. **三个针对性缺口**：①诊断与结果之间缺显式反馈闭环；②删除被当普通编辑而非知识整合机制；③缺少「复杂度 vs 效用」的复合目标约束。
2. **近端（proximal）的引入**：受近端梯度下降启发——每次更新不跑太远，把「技能复杂度惩罚」作为近端项，避免技能失控膨胀或语义漂移。
3. **前向-后向框架**：前向 = 闭环诊断演化（重执行验证 + 回滚 + 接受/拒绝记忆）；后向 = 知识单元分解 + leave-one-out 效用审计 + 验证门控整合/降级/移除。
4. **结果**：3 骨干 × 3 benchmark × 6 基线平均 +3.0 pp；消融证明两阶段互补（闭环 -1.5 pp、Prox -2.5 pp）；OOD 泛化显著优于 SkillOpt（后者过拟合 IID 风格）。

## 一、问题：技能精炼的三个缺口

**技能的本质**：轻量、可复用、文本制品——加载进 agent 上下文（不更新权重）。技能积累 = agent 适应重复任务的主要机制。**形式化**（论文式 1）：技能 X = 主指令文件 SKILL.md + 可选 references/ 目录，可分解为知识单元集合 Q(X)={q1,...,qm}。

**已有方法链**：迭代任务执行 → 失败诊断 → 轨迹引导文本更新。但存在三个结构性缺口：

| 缺口 | 表现 | 后果 |
|:-----|:-----|:-----|
| **无结果反馈闭环** | 诊断 → 编辑 → 结束，不验证编辑效果 | 改了可能更差，回归静默累积 |
| **删除非专门机制** | 删除=通用编辑操作，无「该不该删」的判定 | 过时/有害知识滞留，技能膨胀 |
| **无复杂度约束** | 技能只增不减、越改越长 | 上下文占用↑、检索/加载成本↑、可维护性↓ |

**动机实证**（论文 §3.2 一手）：
- **开环 vs 反馈控制**：10 次 Qwen3.6-27B 训练，开环技能演化 OJ 硬精度 **50.30±2.50** vs 反馈控制变体 **51.40±1.51**——「看起来合理的诊断」不一定「实际提升性能」
- **负效用单元**：leave-one-out 识别出「移除后验证性能反而提升」的知识单元；一个代表案例中，效用感知整合使技能大小 **-3.12%** 同时 OJ 硬精度 **46%→54%**

**核心洞察**：技能演化本质上是「文本空间中的优化问题」——目标函数 = 任务损失 + 技能复杂度。已有方法没有把这个优化显式化，导致演化缺乏约束与验证。SkillsBench（Li et al. 2026）也证明：一次性合成技能跨异构任务增益不均甚至为负——这推动从「静态技能构建」转向「技能演化」。

## 二、技术框架：前向-后向近端框架

```
   SkillProx forward-backward framework (proximal-gradient inspired)
   +-------------------------------------------------------------+
   |  FORWARD STAGE (closed-loop diagnostic evolution)           |
   |  +-----------------------------------------------------+    |
   |  | 1. execute task batch B_k with current skill X_k     |    |
   |  | 2. diagnose failures -> generate edit direction      |    |
   |  | 3. Patcher produces candidate X~ from same snapshot  |    |
   |  | 4. re-execute SAME batch with candidate (Gate_fwd)   |    |
   |  | 5. accept / rollback + keep reject reason as memory  |    |
   |  | 6. feed outcomes into next diagnosis (closed loop)   |    |
   |  +-----------------------------------------------------+    |
   |                          |                                   |
   |                          v                                   |
   |  BACKWARD STAGE (utility-aware proximal refinement, Prox)   |
   |  +-----------------------------------------------------+    |
   |  | 1. decompose skill into L2 sections + L3 ref groups  |    |
   |  | 2. frozen leave-one-out utility audit on split V     |    |
   |  | 3. candidate set by cell utility (tau = -0.001)      |    |
   |  | 4. single-pass validation-gated shrinkage:           |    |
   |  |    consolidate / demote / remove (StructOK + gates)  |    |
   |  +-----------------------------------------------------+    |
   +-------------------------------------------------------------+
   |  Composite objective: min J(X) = L_T(X) + lam * G(X)        |
   +-------------------------------------------------------------+
```

**两阶段分工**：
- **前向 = 演化（evolution）**：让技能变得更好——闭环诊断 + 重执行验证 + 回归回滚 + 接受/拒绝语义历史。
- **后向 = 整合（consolidation）**：让技能保持精炼——知识单元审计 + 效用驱动删减 + 结构有效性检查。

**关键流程细节**（论文 §4.2 一手）：诊断器使用「失败轨迹 + 对比成功轨迹 + 近期历史 + 上一轮拒绝原因」提出编辑方向；每轮最多 3 次尝试；首个严格硬精度提升即终止；若均未严格提升则选硬/cell 精度字典序最优者，但仍需过门控，否则保持 X_k 不变。

## 三、原理细节：文本梯度下降的物理解释

**近端梯度下降（Proximal Gradient Descent）原型**：

```
   min f(x) + g(x)
   - f: smooth loss (task loss)
   - g: non-smooth regularizer (complexity / sparsity)
   update: v_k = x_k - eta * grad f(x_k)      # forward gradient step
           x_{k+1} = prox_{eta*lam*g}(v_k)   # backward proximal step
```

**文本空间的对应**（论文 Table 1 一手）：

| 优化概念 | 标准 PGD | 文本空间对应（SkillProx） |
|:---------|:---------|:--------------------------|
| 目标 | 复合任务损失 f + 复杂度正则 g | 两阶段任务优化 + 文本复杂度控制 |
| 前向方向 | 解析梯度 -∇f | 从任务轨迹推断的自然语言编辑方向 |
| 前向更新 | v_k = x_k − η∇f(x_k) | 诊断→补丁→同批重执行→拒绝反馈→回滚 |
| 后向步 | 解近端子问题 | 冻结效用审计 + 语义收缩 + 结构检查 + 验证门控 |
| 局部性 | 距离惩罚 ‖x−v‖²/2η | 局部单目标编辑 + 软压缩上限 ρ |
| 收缩强度 | 由 ηλ 控制 | 候选/质量/范围分别由 τ、δh、δc、ρ 控制 |
| 分析 | 平滑性假设下收敛 | 有限终止 + 经验门控 + 严格复杂度降低 |

**关键设计——「近端」为什么必要**：无约束文本编辑会漂移——每轮诊断都往「更具体」改，技能膨胀到过拟合任务批次；近端项（复杂度惩罚）把更新拉回「简洁」区域，类似权重衰减/投影。这是 SkillProx 与朴素「失败→编辑」方法的核心差异。

**闭环反馈的物理意义**：传统方法诊断→编辑是**开环**（open-loop）——编辑质量不可见；SkillProx 前向阶段重执行同一批次并测量结果（hard accuracy + cell accuracy 双指标），把结果喂回诊断——**闭环**（closed-loop）控制，回归可检测、可回滚。

**诚实的边界**（论文 §3.3 一手）：技能文本是离散不可微的，不直接存在数值梯度或标准近端算子；实现**不显式优化式 2**，也不把 η、λ 作为输入——只保留「前向-后向职责划分」：诊断演化 = 非精确的性能导向前向算子，效用感知整合 = 离散的后向算子。

## 四、数学形式化与完整推导（式 1-11）

### 4.1 问题形式化（式 1-2）

- `式 1: Q(X) = {q1, ..., qm}` —— 技能分解为知识单元（指令段/引用资源）
- `式 2: min J_λ(X) := L_T(X) + λ·G(X), λ ≥ 0` —— L_T = 未知任务分布上的期望损失；G(X) = SKILL.md + 所有活动引用文件的字符总数（文本复杂度）

**推导意义**：式 2 是**概念性框架**而非实现目标——文本技能离散不可微，方法不把 λ 作为显式输入。它的价值是给出「性能导向更新 + 复杂度导向整合」的统一理论基底，并据此识别出已有方法缺失的两个组件（结果验证 + 效用正则）。

### 4.2 前向门控推导（式 5）

`式 5: Gate_fwd(X̃_k^(j)) = 1[H_Bk(X̃) ≥ H_Bk(X_k)] × 1[C_Bk(X̃) ≥ C_Bk(X_k)]` —— H = hard accuracy（硬精度：整体正确）；C = mean cell accuracy（单元格平均精度）；双条件都满足 → 门控=1（接受），否则=0（拒绝/回滚）

**推导逻辑**：
1. **双指标门控的必要性**：hard accuracy 是最终目标，但粒度粗（一个任务整体对错）；cell accuracy 提供细粒度信号（部分正确的进步也可检测）——两者 AND 防止「整体提升但细节退化」或「细节提升但整体未变」的误判
2. **同批重执行**：候选在**同一任务批次 B_k** 上重执行——排除批次漂移干扰，比较公平
3. **3 次尝试 + 字典序**：首个严格 hard 提升终止（快路径）；无严格提升则最多 3 次、选 (cell, hard) 字典序最优者、仍须过门控
4. **边界**：门控只约束当前批次 B_k——不隐含跨迭代/验证集/测试集的单调性（论文明确声明）

### 4.3 效用审计推导（式 6-8）

- `式 6: Q(X_f) = {q1, ..., qn}` —— 解析为 n 个 L2 sections + L3 reference groups
- `式 7: u_i^hard = H_V(X_f) − H_V(Ablate(X_f, q_i))`；`u_i^cell = C_V(X_f) − C_V(Ablate(X_f, q_i))` —— hard/cell 边际效用
- `式 8: I_τ = {i : u_i^cell < τ}, τ = −0.001` —— 候选集：负效用单元；处理顺序按 `(u_i^cell, u_i^hard)` 升序字典序

**推导逻辑**：
1. **Ablate 定义**：L2 单元 → 移除整个 section；L3 单元 → 移除引用文件及所有指针
2. **边际效用语义**：u > 0 表示移除会降低性能（保留价值高）；u < 0 表示**移除后性能反升**（负效用——冗余/冲突/过度泛化的实例特定知识）
3. **冻结审计**：所有效用在前向完成后一次性测量、全程冻结——避免审计过程本身的开销
4. **τ 阈值的含义**：只选负效用单元（u_cell < -0.001）作为候选——**后向阶段是「只删不增」的收缩过程**，与「前向只增不减」的编辑形成镜像
5. **注意**：审计只决定候选资格与顺序；实际 trial 仍需在当前状态下重新评估（因为前面的合并可能已移除目标）

### 4.4 Prox 单遍验证门控收缩（式 9-11）

- `式 9: StructOK(T_m) = 1 且 G(T_m) < G(X^(m))` —— 结构有效 + 严格复杂度降低
- `式 10: H_V(T_m) ≥ H_V(X^(m)) − δh`（δh=0，验证硬精度不降）；`C_V(T_m) ≥ C_V(X^(m)) − δc`（δc=0.02，cell 精度最多降 2pp）；`1 − G(X^(m))/G(X_f) < ρ`（ρ=0.10，累积压缩软上限）
- `式 11: X^(m+1) = T_m`（全部门控通过）| `X^(m)`（否则）

**推导逻辑**：
1. **严格复杂度降低**（式 9）：每个被接受的编辑必须让文本变短——后向阶段单调收缩（这是「近端」在文本空间的离散实现：向「简单」方向投影）
2. **性能容差**（式 10）：δh=0 要求验证硬精度**只许升不许降**（保守）；δc=0.02 允许 cell 精度最多降 2pp（给结构重组留空间）
3. **软压缩上限**（ρ=0.10）：在**当前技能 X^(m)** 上评估而非 trial 本身——所以 ρ 不是最终压缩比的硬上限，而是「是否继续尝试下一次收缩」的停止阈值；最终压缩比可能越过 10%
4. **有限终止**：候选集有限 + 每候选至多一次 → 收缩必然终止；被拒 trial 直接删除，接受 trial 替换活动技能

### 4.5 实现性质与收敛性分析（论文 §4.5 + 附录 B）

| 性质 | 陈述 |
|:-----|:-----|
| 终止性 | Prox 候选集有限、每候选处理至多一次 → 有限次 trial 后必然终止 |
| 单调性 | 每个被接受编辑严格降低文本复杂度；被拒 trial 不改变技能 |
| 非收敛保证 | 验证门控仅提供逐编辑的验证集经验约束——**不隐含测试集单调性或经典 PGD 收敛** |
| 收缩强度 | 由 τ（候选覆盖）、δh/δc（性能容差）、ρ（压缩范围）联合决定 |
| τ 的解读 | τ 扫描是「阈值诱导的经验权衡曲线」而非精确的 λ 正则化路径 |

| | **SkillProx** | **54.5±0.5** | 86.2±0.3 | **80.0±1.3** |

**三个结论**（论文 §5.2 一手）：
1. **净正信号**：对初始 Human Skill，Qwen3.5-27B +13.0 pp（38.3→51.3）、Qwen3.6-27B +17.8 pp（36.7→54.5）、4B 小幅正（20.3→21.0）——技能作为可优化制品把基线转为稳定正增益
2. **IID 全胜**：3 骨干全部 IID 第一；4B 上超 EvoSkill +14.3 pp、Trace2Skill +11.0 pp、SkillGrad +1.7 pp；**方差最低**（±0.5 vs SkillOpt ±7.6）——增益稳定非初始化幸运
3. **OOD 泛化**：仅用 SpreadsheetBench 优化却迁移到不同格式/输出空间的 WikiTQ/HiTab；**与 SkillOpt 的过拟合形成尖锐对比**（4B 上 SkillOpt WikiTQ 26.0/HiTab 16.0 崩溃，SkillProx 78.5/69.2）

### 5.3 消融（Table 3 一手，Qwen3.6-27B）

| 变体 | 精度 | Δ |
|:-----|:----:|:--:|
| w/o closed-loop diagnosis（只保留 Prox） | 53.0±1.0 | −1.5 |
| w/o Prox（只保留闭环前向） | 52.0±1.0 | **−2.5** |
| **SkillProx（full）** | **54.5±0.5** | — |

**推导**：去掉 Prox 的损失更大（-2.5 > -1.5）→ 任务驱动的前向编辑会累积冗余/实例特定内容，需要近端收缩控制；但 Prox 也需要「优化后的前向技能」而非原始基础技能——两阶段互补，full 方差最低。

### 5.4 τ 扫描 Pareto 前沿（Figure 2 一手）

| τ 阈值 | OJ 硬精度 | 压缩比 |
|:-------|:--------:|:------:|
| 无 Prox（τ=-∞） | 50.3% | 0% |
| **τ=-0.001** | **52.3%** | **25.7%** |
| τ=0.005 | 52.0% | 41.5% |
| τ=0.050 | 51.0% | 74.9% |
| >80% 压缩 | 开始下降 | — |

**推导**：多个 Prox 设置同时实现「更高压缩 + 更高精度」——适度收缩还能去除重复规则与上下文干扰；压缩超 ~80% 才开始性能下降。这是**技能精简与性能的双赢区间**（25-75% 压缩）。

### 5.5 模型规模与技能长度（Table 4 一手）

| 指标 | Qwen3.5-4B | Qwen3.5-27B |
|:-----|:----------:|:-----------:|
| 总长度 | 40.4k±8.6k | 27.9k±12.9k |
| 主文件 | 14.8k±3.3k | 15.4k±3.5k |
| References | 25.6k±9.1k | 12.6k±11.1k |
| Prox 压缩 | 29.4% | 19.0% |

**推导**：4B 技能比 27B 长约 45%，差异几乎全在 references（4B 是 27B 的两倍）——**模型越小越需要外部补充指导**；主文件收敛到相近 ~15k 字符；27B 内技能长度与 IID 精度负相关（更长的技能不一定更有效）。

## 六、应用场景四象限

### 6.1 表格/文档操作自动化（论文实证场景）

- **SpreadsheetBench**：真实世界电子表格操作（公式生成/数据整理）——技能编码「如何操作表格」的程序性知识
- **落地映射**：任何「重复性结构化任务」——财务对账、数据清洗、报表生成；技能从失败操作中学习纠错规则，闭环演化持续改进

### 6.2 表格 QA 与知识检索（OOD 迁移证明）

- **WikiTQ / HiTab**：表格问答——格式与输出空间与训练完全不同，证明技能学到的是**泛化操作原则**而非过拟合表格样式
- **落地映射**：跨域迁移场景——在 A 域学到的「表格理解技能」直接迁移到 B 域（运维报表 QA、日志分析、工单摘要）

### 6.3 技能生命周期管理平台（核心场景）

| 生命周期阶段 | SkillProx 对应机制 | 工程收益 |
|:-------------|:------------------|:---------|
| 技能创建 | 前向闭环演化（诊断→编辑→验证→回滚） | 防止「改坏」累积 |
| 技能维护 | 后向效用审计（leave-one-out） | 删除过时/有害知识 |
| 技能精简 | Prox 收缩（压缩 25-75% 性能不降反升） | 上下文占用下降 |
| 技能退役 | 负效用单元移除（τ 门控） | 知识库熵减 |

**落地映射**：企业 Agent 平台的技能市场/技能库治理——这正是本地 `skills/` 目录 + 6 步注册纪律要解决的工程问题（SkillProx 给出学术版方法）。

### 6.4 小模型技能增强（规模迁移洞察）

- 4B 模型受益最大（references 需求翻倍、Prox 压缩 29.4%）——**外部技能库是弱模型的「外置能力增强」**
- 落地映射：边缘/端侧 Agent（资源受限）用技能库弥补模型能力差距——SkillProx 的闭环验证是**无训练**的（冻结模型 + 纯推理），适合低成本持续优化

## 七、竞品优劣势对比（六系统矩阵）

### 7.1 竞品地图（论文 Related Works 一手）

```
Skill lifecycle landscape
+-- Skill synthesis (one-shot): Trace2Skill / EvoSkill / CoEvoSkills / SkillComposer / Skill-it!
+-- Skill self-evolution (continuous)
|   +-- Open-loop textual gradient: SkillGrad (textual grad + momentum) / SkillOpt (textual LR + held-out gate)
|   +-- Closed-loop + proximal: SkillProx (this paper)
|   +-- RL training line: SkillRL (recursive skill-augmented RL)
+-- Text-space optimization base: TextGrad (NL feedback backprop) / GEPA (reflective + Pareto prompt evolution)
+-- Evaluation: SkillsBench (cross-task skill effectiveness)
```

**三线解读**：技能合成（一次构建，冷启动）→ 技能自进化（持续优化，本文位置）→ RL 训练（端到端强化）——构成技能生命周期三段论；TextGrad/GEPA 是通用文本优化底座，SkillProx 将其移植到技能制品。

### 7.2 六系统对比矩阵

| 维度 | **SkillProx** | SkillGrad | SkillOpt | EvoSkill | Trace2Skill | SkillRL |
|:-----|:-------------|:----------|:---------|:---------|:------------|:--------|
| 类别 | 自进化·闭环 | 自进化·开环 | 自进化·开环 | 合成 | 合成 | RL 训练 |
| 前向验证 | **同批重执行门控** | 无（直接提交） | held-out gate | 验证选择 | 无 | RL 奖励 |
| 删除机制 | **效用审计专门机制** | 普通编辑 | 普通编辑 | 普通编辑 | 无 | 隐式 |
| 复杂度控制 | **近端收缩（ρ/τ）** | momentum（隐式） | 文本学习率 | 无 | 无 | 无 |
| OOD 泛化 | **强（78.5/69.2）** | 中（69.7/65.4） | **崩溃（26.0/16.0）** | 中 | 弱 | 未报告同设置 |
| IID 精度（4B） | **21.0** | 19.3 | 15.3 | 6.7 | 10.0 | 未报告 |
| 训练成本 | **无（冻结推理）** | 无 | 无 | 无 | 无 | **高（RL）** |
| 可审计性 | **高（单元级效用）** | 中 | 中 | 低 | 低 | 低 |
| 方差稳定性 | **±0.5 最低** | ±0.9 | ±7.6 高 | ±4.4 | 0~9.6 | 未报告 |

### 7.3 逐竞品优劣势分析

**vs SkillGrad（最强梯度基线，2605.27760）**：
- 优势：SkillGrad 开环（诊断即提交，不验证效果）+ 删除当普通编辑；SkillProx 闭环验证 + 效用审计 → IID 4B +1.7 pp、WikiTQ +8.8 pp、HiTab +3.8 pp
- 劣势：SkillGrad 的 momentum（历史梯度动量）在长演化中可能更平滑——SkillProx 的 3 次尝试上限可能漏掉需要更多轮探索的编辑

**vs SkillOpt（2605.23904）**：
- 优势：SkillOpt 用「文本学习率 + held-out gate」限幅，但**OOD 崩溃**（4B WikiTQ 26.0 vs 78.5）——held-out gate 只看验证集、无压缩约束 → 过拟合 IID 风格；SkillProx 的 ρ 压缩 + 双指标门控泛化更强
- 劣势：SkillOpt 的方差大（±7.6）说明其探索更激进——某些种子可能到达 SkillProx 未达的区域

**vs EvoSkill / Trace2Skill（合成线）**：
- 优势：合成线一次构建、无反馈；SkillProx 持续演化 → 4B IID 超 EvoSkill +14.3 pp、Trace2Skill +11.0 pp
- 劣势：合成线的价值在**冷启动**（从零快速得到可用技能）；SkillProx 需要初始技能（Human Skill）作为优化起点——**两者是流水线关系而非替代**

**vs SkillRL（2602.08234，RL 训练线）**：
- 优势：SkillProx **无训练成本**——冻结模型 + 纯推理，小模型也能跑；可审计性高
- 劣势：RL 训练的技能可能更优（端到端奖励优化）；若 RL 成本持续下降（MEMORY 预判 H4），文本优化优势收窄

**vs TextGrad / GEPA（文本优化底座）**：
- 定位：TextGrad（自然语言反馈反向传播）、GEPA（反思 + Pareto 引导）是**通用文本优化器**；SkillProx 是**技能制品专用**——复用其思想但聚焦技能结构（L2/L3 单元分解、复杂度正则）

### 7.4 竞品启示（第一性提炼）

1. **「开环 → 闭环」是技能演化的分水岭**：开环方法（SkillGrad/SkillOpt）把诊断当真相；闭环（SkillProx）把执行结果当裁判——OOD 差异（78.5 vs 26.0）证明闭环是泛化的必要条件
2. **删除是「知识整合」不是「编辑」**：负效用单元移除（46%→54%）证明技能健康需要**主动熵减**——这与本地「技能三维查重 + 6 步注册」的哲学一致
3. **合成与演化是流水线**：EvoSkill/Trace2Skill（合成）→ SkillProx（演化）→ SkillRL（强化）——**技能生命周期三段论**，任何单点方法都不完整

## 九、批判性审视

1. **文本梯度是隐喻**：LLM 生成的「编辑方向」不是真梯度——无数学保证收敛；「近端」是启发式约束而非凸优化性质。论文诚实标注「不显式优化式 2、不取 λ 输入」——价值在工程而非理论。
2. **leave-one-out 的近似性**：逐单元独立贡献假设单元间无交互——技能中知识单元常有协同（A+B 才有用），O(1) 近似可能低估协同单元价值（论文未做 pairwise/Shapley 审计）。
3. **重执行成本**：前向阶段每轮编辑都要重执行任务批次（最多 3 次 × K 轮）——成本随批次规模线性增长；附录 B 虽给复杂度分析，但长任务/大批次场景开销显著。
4. **基准场景单一**：全部实验基于表格类任务（Spreadsheet/WikiTQ/HiTab）——技能演化在代码生成、工具使用、多步规划等场景未验证。
5. **+3.0 pp 的基线选择**：对比的是「最强梯度式基线」（SkillGrad）——更强基线（SkillRL 类 RL 训练）可能缩小差距；H4 已预判此风险。
6. **技能结构假设**：L2/L3 单元分解假设技能有固定层级（sections/references）——对自由格式技能（单文件无结构）分解粒度存疑。
7. **冷启动依赖**：需要初始技能（Human Skill）——零基础场景（无人工技能）需先合成（EvoSkill 类）再演化，流水线衔接未在论文中验证。
