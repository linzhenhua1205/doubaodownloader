## 一、核心架构总览

五层自进化机制，按深度递进：

| 层级 | 改进内容 | 触发时机 | 进化深度 |
|:-----|:---------|:---------|:---------|
| **L1 基础记忆和知识维护** | 记忆 / 知识 / 提示词 | 每次对话中 | 记录 |
| **L2 上下文智能总结** | 记忆 | 上下文超限时 | 保留 |
| **L3 会话后主动复盘** | 技能 / 记忆 / 提示词 / 任务 | 会话空闲后 | 行动 |
| **L4 梦境记忆整理（Deep Dream）** | 长期记忆 | 每天定时（23:55） | 沉淀 |
| **L5 源代码自更新** | 代码 | 被动/主动触发 | 自我重构 |

> **设计原则**: 实现修改能力不难，难的是 **改得克制、改得可控**。

## 二、L1：基础记忆和知识维护（每次对话中）

在每次对话中，Agent 通过工具决策 + 系统提示词引导，判断有价值信息并持久化。

### 三类信息维护

| 类别 | 存储位置 | 注入方式 | 维护原则 |
|:-----|:---------|:---------|:---------|
| **记忆** | MEMORY.md（核心）+ memory/YYYY-MM-DD.md（天级） | 核心记忆注入每次系统提示词 | 必须精炼，天级记忆仅检索时加载 |
| **知识库** | Markdown 源文件 + 向量化数据库 | 按主题组织，页面间交叉引用 | 搜索学习/深度研究时主动沉淀 |
| **提示词** | AGENT.md / RULE.md / USER.md | 加载进入系统提示词 | 实时修改，贴合用户习惯 |

## 三、L2：上下文智能总结（上下文超限时）

解决 Agent 在长对话中不丢失信息的问题。四步处理：

```text
工具结果超长 -> 轮次超限裁剪 -> Token超限压缩 -> 溢出兜底
```

| 步骤 | 操作 | 是否调用LLM | 特点 |
|:-----|:-----|:-----------|:-----|
| **① 截断超长工具结果** | 工具结果超阈值时保留首尾两段+省略说明 | ❌ 纯字符串 | 第一道防线，挡住大部分增长 |
| **② 按完整轮次裁剪** | 以「一轮完整对话」为最小单位裁掉最早一半 | ✅ 提炼总结→写天级记忆 | 保证工具调用入参/结果成对保留 |
| **③ 按 Token 压缩** | 轮次少时每轮压缩（只留首条提问+末条回复） | ❌ | 精细裁剪 |
| **④ 溢出兜底** | API 抛出溢出时，总结后激进截断 | ✅ | 最后保险 |

## 四、L3：会话后主动复盘（最核心层）

主动性强、价值最高的一层。会话空闲后（默认 10 分钟空闲 + ≥6 轮对话），Agent 主动回顾、修复问题。

### 4.1 进化内容

| 内容 | 描述 | 设计取舍 |
|:-----|:-----|:---------|
| **优化和创建技能** | 修复有问题的技能 / 把可复用流程固化为新技能 | ⭐ **主要价值，最核心** |
| **收尾未完成任务** | 承诺了但没做完或临时故障中断的任务 | ⭐ **主要价值** |
| **补齐记忆/知识/提示词** | 查缺补漏 | ⚠️ 兜底，其他层已覆盖 |

### 4.2 两个关键设计取舍

1. **技能和未完成任务是主要价值**，记忆/知识/提示词只作兜底
2. **修复源头而非只记录问题**：问题根因在技能时，改技能而非记一句「技能 X 有错」

### 4.3 安全可控三原则

| 原则 | 实现 |
|:-----|:------|
| **隔离执行** | 独立异步临时任务，工具集大幅收紧，不污染主对话 |
| **变更可回滚** | 改动前自动备份，用户说「撤销」即可还原 |
| **变更可追溯** | 持久化变更记录于 Web 控制台「记忆-自主进化」页面 |
| **未变更不打扰** | 有实际改动才推送，否则静默 |

## 五、L4：梦境记忆整理 Deep Dream（每天 23:55 定时）

全局视角的每日自进化，解决长期记忆两个核心问题：**不断膨胀** 和 **自相矛盾**。

### 执行流程

```text
读取核心记忆 + 天级日记
    v
去重、合并相近条目、修剪
    v
提炼新信息并替换旧信息
    v
输出精炼核心记忆（≤50条）
    v
生成叙事风格的「梦境日记」
```

### 合并规则

| 规则 | 说明 |
|:-----|:------|
| 含义相近的多条 | 合并成一条更高密度表述 |
| 值得永久记住的新信息 | 从天级日记萃取（偏好/决策/规则/经验/教训） |
| 新旧记忆冲突 | 以新条目替换旧条目 |
| 冗余条目 | 临时记录/空条目/被覆盖的 → 直接清理 |
| **输出规模** | 核心记忆控制在 **约 50 条以内** |

### 安全保护

- 当天无新日记 → 跳过，绝不空覆写
- 日记和消息分别做哈希去重，不重复写入
- 提示词强约束整理真实性，避免凭空生成不存在的记忆

## 六、L5：源代码自更新（进行中讨论）

Agent 在运行中修改自身代码并重启——解决外置技能/工具无法解决的问题。

### 两个难点

| 难点 | 解决方案（cow self-restart CLI） |
|:-----|:--------------------------------|
| 改坏代码影响启动 | 运行自检：依赖导入或解释器错误中止重启 |
| 关闭当前进程并启动新进程 | 脱离于当前进程树的接力进程，优雅关闭旧进程并启动新进程 |

### 版本冲突问题

开源场景中，本地修改代码后相对主干分支形成分叉，后续官方更新需人工或 Agent 解决冲突。
