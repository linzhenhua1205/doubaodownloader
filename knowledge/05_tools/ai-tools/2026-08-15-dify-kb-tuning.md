## 一、结论概要

AI 助手回答不完整/不准确的**根源多在知识库构建环节**，调优三维度：分段设置、索引方式、检索参数。核心是让"切块粒度"匹配"问题粒度"，让"检索信号"匹配"语义需求"。

| 维度 | 关键决策 | 默认值 → 推荐值 |
|:-----|:---------|:----------------|
| 分段 | 通用 vs 父子 vs Q&A | 500 Tokens → 800 Tokens（专业文档） |
| 重叠 | 上下文衔接 | 10%-25% |
| 索引 | 经济 vs 高质量 | 经济（预算有限）→ 高质量（语义场景） |
| 检索 | 向量 vs 全文 vs 混合 | 混合检索 + ReRank |
| 阈值 | Score 过滤 | 0.5 → 0.8（提升相关性） |

**核心结论**：
1. **分段粒度决定召回精度**：句子级检索精准但缺上下文，段落级有上下文但噪声多——父子分段两者兼得
2. **索引方式决定语义能力**：经济索引靠关键词，高质量索引靠 embedding，复杂问答必须后者
3. **混合检索 + ReRank 是性价比最高的调优**：召回提升约 30%，重排后 Top 命中率显著改善

## 二、分段设置：内容拆分策略

### 2.1 通用分段（默认）

| 参数 | 默认 | 说明 |
|:-----|:-----|:-----|
| 分隔标识符 | `\n\n` | 按段落拆分 |
| 最大长度 | 500-4000 Tokens | 段长影响上下文完整度 |
| 重叠长度 | 建议 10%-25% | 避免边界信息丢失 |

**Q&A 模式**（社区版）：自动生成问答对，采用「Q to Q」匹配（问题→问题相似度），比传统「Q to P」（问题→段落）精度更高，适用于 FAQ 类文档。

### 2.2 父子分段

双层结构：**父块提供上下文 + 子块负责检索**。

| 层级 | 拆分规则 | 默认长度 | 作用 |
|:-----|:---------|:---------|:-----|
| 父块 | 按 `\n` 段落 / 全文（保留前 10000 Tokens） | 500 Tokens | 提供完整上下文 |
| 子块 | 按句子 | 200 Tokens | 精准定位关键词 |

**适用场景**：跨段落引用、故障代码查询（如 E103）、需要上下文连贯性的业务知识库。

## 三、索引方式：检索效率核心

### 3.1 经济索引

- **策略**：离线向量引擎（预计算存储）+ 关键词索引（类似书籍目录）
- **适用**：预算有限、内容简洁（如 FAQ）
- **代价**：语义理解弱，同义词/近义表达召回差

### 3.2 高质量索引

- **策略**：依赖嵌入模型（Embedding Model）生成向量索引，支持语义级检索
- **适用**：法律/技术文档等复杂问答场景
- **优势**：跨表达方式召回（"退款政策"↔"如何退钱"）

## 四、检索调优技巧

| 技巧 | 操作 | 效果 |
|:-----|:-----|:-----|
| 混合检索 | 向量 + 全文检索并行 | 兼顾语义与关键词精确匹配 |
| ReRank 重排 | Cross-Encoder 二次排序 | Top 命中率提升 ~30% |
| Score 阈值 | 0.5 → 0.8 | 过滤低相关片段，减少幻觉 |
| 检索 TopK | 3 → 5（复杂问题） | 提高答案覆盖率 |

**调优逻辑**：阈值提高会牺牲召回率换取精确率——按问题类型动态调整：事实性问题要精确（阈值高），综述性问题要全（阈值低）。

## 五、推荐搭配案例

### 案例 1：通用分段 + 高质量索引（专业文献问答）

| 配置项 | 值 |
|:-----|:-----|
| 场景 | 学术论文/研究报告问答 |
| 分段 | 800 Tokens/段，100 Tokens 重叠，删除 URL/邮件地址 |
| 索引 | OpenAI 嵌入模型生成向量索引 |
| 效果 | 语义匹配精度提升，快速定位相关研究成果 |

### 案例 2：父子分段 + 高质量索引（智能客服）

| 配置项 | 值 |
|:-----|:-----|
| 场景 | 智能家居客服（说明书/FAQ） |
| 父块 | 500 Tokens/段落 |
| 子块 | 200 Tokens/句子 |
| 索引 | 混合检索（向量 + 关键词） |
| 效果 | 故障代码（如 E103）毫秒级响应，跨产品咨询连贯 |

## 六、调优决策矩阵

| 内容类型 | 分段策略 | 索引方式 | 检索模式 |
|:---------|:---------|:---------|:---------|
| FAQ / 短问答 | Q&A 模式 | 经济索引 | 关键词为主 |
| 技术手册 / 长文档 | 父子分段 | 高质量索引 | 混合 + ReRank |
| 法律 / 合同 | 父子分段（大父块） | 高质量索引 | 混合 + 高阈值 |
| 多语言内容 | 通用分段（小段） | 高质量索引 | 向量为主 |

**落地顺序**：先按内容类型选分段 → 再按预算选索引 → 最后用真实问题调阈值/ReRank，每次改动用一组测试问题回归验证。
