## 一、AI 生成前端页面的三种主流方式

| 方案 | 原理 | 代表工具 | 优势 | 局限 |
|:----|:-----|:---------|:-----|:-----|
| **自然语言提示词驱动** | 文字描述 → 代码 | 通用 LLM | 门槛最低 | 提示词极长·信息易遗漏·AI风味固化(蓝紫渐变) |
| **Design-to-Code** | 解析设计源文件(Figma/Pixdo) | Pixso D2C, Figma-Context-MCP | 像素级还原·代码规范 | 强依赖源文件·不支持截图/手绘·需平台对接 |
| **像素级视觉方案** | 多模态看图写码 | v0.dev, Screenshot-to-code | 丢图即出码·门槛低 | 框架绑定(React/Tailwind)·无组件库感知·还原精度有限 |

## 二、核心方案：图像识别增强 + 组件库 Skills

在像素级方案基础上，通过 **Skills 注入结构化分析能力 + 组件库知识**，弥补组件适配、框架适配短板。

### 2.1 图像识别增强 Skill（`image-analyze-improvement`）

**作用**：将截图/手绘图转为**结构化的 UI 描述语言（UIDL）**

#### 四维分析模型

| 维度 | 含义 | 核心问题 |
|:-----|:-----|:---------|
| **Position** | 布局结构、层级、相对位置 | 组件在何处展示？ |
| **Content** | 组件类型、文本、数据内容 | 展示哪些信息？ |
| **Interaction** | 交互行为、状态变更逻辑 | 内容如何动态变化？ |
| **Style** | 视觉表现、尺寸、颜色规范 | 呈现何种视觉效果？ |

#### 描述规范

- **顺序**：整体→局部，上→下，左→右
- **位置**：使用精准方位（上方/下方/左侧/右侧/居中），禁用「旁边、附近、周围」
- **层级**：父子（包含/嵌套于）+ 兄弟（并列/相邻）
- **尺寸**：具体数值（16px）/ 比例 / 占满宽度
- **颜色**：十六进制 + 语义化命名（主题蓝、警告橙）
- **文字**：所有可见文字完整提取

#### 输出模板：Markdown + JSON 双格式

Markdown 描述布局结构，JSON 输出结构化 UIDL（含 layout.sections[].children[].states/interactions）。

### 2.2 DevUI 组件 Skill（`vue-devui-practices`）

**作用**：将 UIDL 落地为符合 DevUI 组件库规范的业务代码

#### Skill 目录结构

```text
vue-devui-practices/
+-- SKILL.md
+-- references/
|   +-- DESIGNS.md          # 设计规范（Design Token）
|   +-- Form-表单.md
|   +-- Input-输入框.md
|   +-- Icon-图标.md
|   +-- ...
+-- demo/
    +-- table-virtualScroll.md
```

#### 核心流程

1. **识别组件需求** → 映射到 DevUI 组件清单
2. **读取组件文档** → `Read` references 目录中的 API/Demo 文档
3. **读取设计规范** → `DESIGNS.md` 中的颜色/圆角/间距/字体 Token
4. **生成页面代码** → 符合 DevUI 规范的 Vue 组件代码（`d-button`/`d-form`/`d-input` 等）

## 三、端到端组合实践

### 三 Skill 串联流程

```text
截图/手绘稿
    v
① 图像识别增强 Skill -> 结构化 UIDL（布局+组件+交互）
    v
② DevUI 组件 Skill -> 符合设计规范的页面代码
    v
③ 接口调用生成 Skill -> 类型定义 + API 调用 + Mock + 调试
    v
完整的可交互企业级页面
```

### 实践案例：IP白名单访问控制页面

- Step1：上传截图 → 图像识别 Skill 分析 → DevUI Skill 生成页面
- Step2：输入后端接口设计 → 接口调用 Skill 生成接口定义 + Mock
- Step3：表格查询、搜索、分页功能全部正常可用
- 后端接口未就绪也不阻塞开发（自带 Mock 机制）

## 四、方案优势总结

| 对比项 | 本方案 | 纯提示词 | Design-to-Code | v0.dev 等 |
|:-------|:-------|:---------|:---------------|:----------|
| 输入门槛 | 截图即可 | 写长提示词 | 需设计源文件 | 截图即可 |
| 组件库适配 | ✅ 可配置 | ❌ 无 | 需定制映射 | ❌ 无 |
| 框架适配 | ✅ 可替换 | ❌ 随机 | 支持多框架 | React 为主 |
| 手绘稿支持 | ✅ | ❌ | ❌ | 有限 |
| 代码规范性 | ✅ 组件级 | ❌ 自由发挥 | ✅ 高 | Tailwind |
| 定制门槛 | 低（改 Skill 配置） | - | 高（对接平台） | 低但受限 |

> 核心思路：用 Skill 做"看图"和"写规范代码"两件事的桥梁，组件库自带设计规范（间距/颜色/圆角/阴影），AI 只需调用 `<d-button>` 而非重复写 `<button class="px-4 py-2 rounded...">`。

## 五、适用场景

- 团队有固定组件库（DevUI / Element Plus / Ant Design / Naive UI 等）
- 需要快速从设计稿/截图生成页面原型
- 追求代码规范性和组件复用性
- 希望减少从设计到开发的手工转换成本
