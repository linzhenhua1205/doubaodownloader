## 1. 核心命题（一句话）

> **大文档拆解 + 逐点强化的本质：把 AI 的"上下文瓶颈"转化为知识单元的"增量加工"，把"一次读完"变成"逐点精炼"。**
> 文档是线性的（作者视角），知识是网络的（可复用单元）——拆解就是完成这个转换。

## 2. 为什么必须拆解（三个第一性原理）

### 2.1 注意力经济学
- LLM 对长上下文的注意力质量随长度衰减（**lost in the middle** 现象：中部信息利用率显著低于头尾）
- 拆解后每个信息点获得**完整注意力预算**，提取/强化质量远高于一次性全文处理
- 推论：不是"上下文够长就不用拆"，而是"拆解 = 给每个知识点分配专属注意力"

### 2.2 认知带宽
- 人一次性读大文档 → 浅层扫描（读了就忘）；逐点加工 → 深度理解（提取即内化）
- AI 同样：一次性总结 → 泛化摘要（信息密度低）；逐点提取 → 精炼知识（信息密度高）

### 2.3 知识颗粒度
- 文档是"作者视角的线性叙述"，信息点是"可复用的独立单元"
- 拆解 = 从"读书"到"建卡"：单点知识可检索、可引用、可独立演化（对应知识库"索引+交叉链接+分类"体系）

## 3. 三层拆解模型

| 层 | 内容 | 产物 | 手段 |
|:---|:-----|:-----|:-----|
| **L1 结构层** | 标题层级/章节/段落/图表/引用 | 大纲树 | LLM 抽取 + 脚本校验 |
| **L2 语义层** | 原子信息点（含元数据：位置/类型/置信度/来源） | 信息点清单 | LLM 提取 + 人复核 |
| **L3 价值层** | A/B/C/D 分级 + 依赖关系 | 强化优先级排序 | 人工决策（不可自动化） |

**关键**：三层必须分离。先结构后语义，先提取后分级——跳过结构层直接提取会导致信息点丢失上下文锚点。

## 4. 信息点类型学（MECE 六类）

| 类型 | 定义 | 示例 | 首选强化方式 |
|:-----|:-----|:-----|:-------------|
| **事实点** Fact | 可验证断言/数据/事件 | "2026 全球 AI 优化型 IaaS 支出 +96%" | 查证来源、补基线/条件 |
| **论证点** Argument | 推理链/观点/对比 | "推理负载将超过训练负载" | 补全推理链、找反方视角 |
| **方法点** Method | 流程/步骤/工具 | "五层可观测性框架" | 补步骤细节、边界条件 |
| **规范点** Norm | 标准/规则/要求 | "告警必须绑定 owner+playbook" | 补依据、适用范围 |
| **行动点** Action | 任务/待办/决策 | "需确认飞书 API 权限" | 转任务系统、定优先级 |
| **元信息点** Meta | 来源/背景/局限 | "数据来源 Gartner（2026-08）" | 标注置信度、时效性、验证状态 |

**MECE 校验**：每个信息点必须且只能归入一类；跨类信息点需拆分（如"数据+结论"拆成事实点+论证点）。

## 5. 拆解流水线（7 步）

```
P1 预扫描 → P2 大纲抽取 → P3 语义分块 → P4 逐块提取 → P5 去重合并 → P6 分级排序 → P7 强化管线
```

| 阶段 | 输入 → 输出 | LLM/脚本分工 | 质量门 |
|:-----|:-----------|:-------------|:-------|
| **P1 预扫描** | 文档 → 统计（字数/章节/图表/引用）+ 结构识别 | 脚本为主 | 识别文档类型（报告/论文/会议记录→提取模板不同） |
| **P2 大纲抽取** | 文档 → 结构化大纲树 | LLM | 大纲覆盖全部章节，无遗漏 |
| **P3 语义分块** | 大纲 → 分块清单（每块 1-3k tokens，章节为天然边界） | 脚本切分 | 块间无重叠、块内主题单一 |
| **P4 逐块提取** | 每块 → 信息点列表（六类 + 元数据 + 原文锚点） | LLM 逐块 | 信息点原子化（单点单义）、锚点可回溯 |
| **P5 去重合并** | 全局信息点 → 去重后清单 | 脚本（哈希/相似度）+ LLM 确认 | 跨块重复点合并，保留最强版本 |
| **P6 分级排序** | 清单 → A/B/C/D + 依赖图 | **人工决策** | A 类 ≤30%；依赖关系显式化 |
| **P7 强化管线** | A/B 类点 → 强化后卡片 | LLM 逐点 + 人复核 | 见第 6 节质量保障 |

**暂存区隔离**：P1-P4 产物全部进暂存区（`tmp/decompose/<doc>/`），不直接写入知识库；P6 后才路由。

## 6. 逐点 AI 强化（6 种操作 + 优先级）

### 6.1 六种强化操作

| 操作 | 内容 | 适用类型 | 产出 |
|:-----|:-----|:---------|:-----|
| **查证** Verify | 交叉验证、来源追溯、基线补全 | 事实点 | 来源+条件+置信度 |
| **扩展** Elaborate | 补原理/背景/数据/上下文 | 事实点、方法点 | 原理链、数据补充 |
| **对比** Contrast | 反方观点、边界条件、替代方案 | 论证点 | 辩证视角、适用边界 |
| **关联** Link | 知识库已有文档交叉引用 | 全部 | 双向链接 |
| **结构化** Structure | 转表格/卡片/可复用模板 | 方法点、规范点 | 标准格式卡片 |
| **失败模式检查** FMEA | 幻觉/过度延伸/逻辑跳跃/夸大自检 | 强化后必做 | 缺陷清单+修正 |

### 6.2 强化优先级策略（资源有限时）

1. **价值优先**：A 类 > B 类 > C/D 类（C/D 只提取不强化）
2. **依赖链优先**：先强化基础事实点，再强化依赖它的论证点（避免空中楼阁）
3. **同类批量**：同类型信息点用同一提示模板批量强化（上下文复用，成本低）
4. **异类逐个**：论证/方法点逐个精加工（质量敏感，不可批量化）

### 6.3 强化提示模板骨架（单点强化）

```
[角色] 知识强化引擎
[任务] 对给定信息点进行 {查证|扩展|对比|结构化} 强化
[输入] 信息点（原文锚点: {位置}）+ 原文上下文块
[约束]
  1. 强化内容必须基于原文或已验证来源，禁止凭空补充
  2. AI 新增内容用 【强化】标记，与原文分离
  3. 无法验证的断言标注"未验证"
  4. 输出格式: 强化后卡片（含来源/条件/置信度）
[输出] Markdown 卡片
```

## 7. 质量保障（防熵增，衔接毛净熵框架）

> 净产出 = 毛产出 − 漂移修复成本 − 熵增治理成本（knowledge/03_AI/methodology/2026-08-05-ai-output-gross-vs-net-entropy.md）

| 保障项 | 机制 |
|:-------|:-----|
| **来源可追溯** | 每个信息点保留原文位置锚点（章节/段落/页码），强化后仍可回溯 |
| **强化/原文分离** | AI 补充用【强化】标记，可一键剥离还原原文 |
| **幻觉防护** | 强化只基于原文 + 已验证外部源；无源补充必须标注"未验证" |
| **抽样复核** | 每批强化后人工抽检 10%（与 40% 红线监控联动：AI 生成内容占比监测） |
| **版本管理** | 强化前后 diff 可对比，不满意可回退 |

## 8. 工程实现（状态追踪 + 断点续传）

```jsonc
// info-points.json —— 信息点主清单（单一事实源）
{
  "doc_id": "2026-08-13-gartner-iaas",
  "points": [
    {
      "id": "P-001",
      "origin": "§原文核心内容/第3段",
      "type": "fact",              // fact|argument|method|norm|action|meta
      "grade": "A",                // A|B|C|D
      "status": "enhanced",        // extracted|verified|enhanced|reviewed
      "summary": "2026年AI优化型IaaS支出+96%至420亿美元",
      "anchor": "原文精确引用",
      "enhanced": "【强化】...补充来源与基线",
      "links": ["knowledge/xx.md"],
      "reviewed": false
    }
  ]
}
```

- 状态机：`extracted → verified → enhanced → reviewed`，断点可续
- 每文档独立 `tmp/decompose/<doc_id>/` 目录：大纲.md / 分块/ / 信息点.json / 强化卡片/
- 完成并复核后：路由入知识库 + log 追加 + 暂存区清理

## 9. 与既有方法论体系衔接

| 既有体系 | 衔接点 |
|:---------|:-------|
| AI 生产流水线方法论（pipeline-orchestrator 6 阶段） | 拆解流水线 = input-qa（P1-P3）→ multi-path（P4 逐块并行）→ convergence（P5 去重）→ verification-loop（P6-P7 循环强化）→ expert-gate（人工复核）的实例化 |
| 输出毛净熵（毛利/净利/熵治理） | 拆解强化是"确定性外壳"的实践：信息点清单+状态机把 AI 显性熵转为确定性约束 |
| 40% 红线监控 | 强化后 AI 生成内容占比纳入监控；【强化】标记使剥离可量化 |
| discover 技能（问题提取/分类/关键词） | P4 提取可与 discover 复用；discover 的问题分类 = 信息点类型学的前身 |
| depth-completer（深度补齐） | 强化操作"扩展/对比"深度化时调用，防止"框架堆名词" |

## 10. 风险与反方视角

| 风险 | 对策 |
|:-----|:-----|
| **过度拆解**：信息点碎片化，失去上下文 | 保留父级引用（大纲树锚点）；相邻点合并阈值 |
| **强化幻觉**：AI 补充引入错误 | 强化/原文分离 + 来源标记 + 抽检 10% + FMEA 自检 |
| **熵增**：中间文件泛滥 | 状态追踪 + 文档级暂存区 + 完成后清理 |
| **拆解成本 > 价值** | 价值分层先行：低价值文档只做 P1-P2 摘要，不逐点强化 |
| **依赖链断裂**：先强化论证点后事实点 | 依赖图强制排序（P6 输出依赖图） |

## 11. 落地建议（最小可行流程）

1. **试点**：选 1 份典型大文档（如 NVIDIA 全栈可观测性分析，346 行），跑完整 7 步流水线
2. **模板固化**：产出信息点类型学 + 强化提示模板，沉淀为可复用技能
3. **批量推广**：对迁移暂存区/拆解暂存区待处理大文档批量执行（P1-P4 全自动，P6 人工）
4. **质量基线**：抽样复核通过率 ≥90% 视为流水线合格
