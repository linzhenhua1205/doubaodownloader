# 多笔记系统迁移整合方案（体量校准版）

> **创建**: 2026-08-13 | **状态**: 方案设计（待用户确认后启动 P0）
> **背景**: 用户 8 套笔记系统（纸件/XML/OneNote/Markdown/AI文档/得到笔记/飞书/cowagent）迁移整合
> **体量实测**（2026-08-13 用户确认）: 纸件 60 本约 5 万页手写稿（按天记录 20页/天×200天/年×10年，时间线型流水账）；OneNote ~100G；XML 含文本/XMind/FreeMind 三种；飞书为个人空间全类信息；XMind 200 文件 + FreeMind 200 文件

## 1.5 体量结构细节（2026-08-13 二次确认）

| 源 | 结构细节 | 迁移策略影响 |
|:---|:---------|:------------|
| 纸件 | 按天记录，20页/天 × 200天/年 × 10年；**时间线型流水账**（工作/学习/生活混杂，主题比重无法统计） | 索引卡按**时间粒度**（每本≈1个月，标时间范围+关键事件）；A 类识别靠索引卡阶段人工标注，不做全量 OCR |
| 飞书 | 主要用**知识库**（非云盘/妙记） | 导出路径清晰：目录结构映射 knowledge/ 模块 |
| XMind | 200 文件（.xmind=zip 内 content.xml/json） | 全自动批量转换，思维导图价值密度高 |
| FreeMind | 200 文件（.mm 纯 XML 大纲） | 全自动批量转换 |

## 1. 目标态与核心判断

**目标态**: 以 cowagent（knowledge/ + memory/）为唯一主干，其余 7 源通过「价值分层 + 归一化管线」汇入，源系统只读冻结、不删除。

**核心原则**: 这不是搬家，是炼矿——先选矿（价值分级）、再冶炼（转换+清洗）、最后成材（归类+索引）。全量搬运会把 8 套系统的垃圾一并带入，稀释知识库。

**⚠️ 体量校准结论（第一性原理：成本收益曲线）**:

| 源 | 体量 | 全量数字化成本 | 结论 |
|:---|:-----|:--------------|:-----|
| 纸件 | 5 万页手写 | OCR+校对 3-10 分钟/页 ≈ **2500-8300 小时（1-4 人年）** | ❌ **必须放弃全量**，走「索引化 + 1% 精 OCR」 |
| OneNote | 100G | 全下载=存储/带宽成本 | ⚠️ 文本先导出（占比小），附件建清单按需取 |
| XML(文本/XMind/FreeMind) | 未知 | 脚本批量转换 | ✅ 全自动可行 |
| 飞书 | 个人空间 | API/手动导出 | ⚠️ 视 API 权限 |
| Markdown/AI文档/得到 | 中等 | 低成本 | ✅ 快线 |

**战略放弃是方案的核心**：可检索、可追溯、可提取 > 100% 数字化。

## 2. 第一性原理：迁移本质是四层问题

| 层 | 问题 | 自动化度 |
|:---|:-----|:--------:|
| L1 格式 | 8 种格式 → Markdown | 90% 脚本化 |
| L2 保真 | 附件/图片/表格/层级/手写 | 90% 脚本化 |
| L3 结构 | 各源分类体系 → knowledge/ 模块映射 | 60% 半自动 |
| L4 价值 | 哪些值得进知识库 | ❌ 只能靠人 |

## 3. 价值分层决策模型（四象限，迁移前逐篇打标）

| 象限 | 特征 | 处置 | 预估占比 |
|:-----|:-----|:-----|:--------:|
| A 高价值高频 | 当前工作技术资料/常用参考 | 全量精迁移 → knowledge/ 主模块 | ~20% |
| B 高价值低频 | 历史决策/教训/复盘/方法论 | 归档迁移 → knowledge/（日期前缀） | ~30% |
| C 低价值高频 | 待办/临时/会议速记 | 不迁移，转任务系统 | ~20% |
| D 低价值低频 | 旧剪报/过期资讯/草稿 | 打包 PDF 冷归档 | ~30% |

## 4. 三条流水线（按收益/成本比排序）

```
L1 快线（全自动, 1-2天）: Markdown / XML文本 / XMind / FreeMind → 脚本转 Markdown
L2 中线（半自动, 2-3天）: OneNote 文本 / 飞书 / AI文档 / 得到 → 导出 + LLM 清洗
L3 慢线（人工, 1-2个月）: 纸件 → 索引卡 + 选择性 OCR（每周 2-3 本）
```

### 4.1 XML 三形态解析（唯一格式不明源，已确认三种）

| 子格式 | 文件形态 | 解析方案 |
|:-------|:---------|:---------|
| 文本 XML | .xml（自定义结构） | 先抽样看结构 → xpath 提取节点 → Markdown |
| XMind | .xmind（本质 zip 含 content.xml/content.json） | 解 zip → 解析 content → 大纲转 Markdown 列表 |
| FreeMind | .mm（纯 XML 大纲） | xml.etree 解析节点 → 缩进列表转 Markdown |

### 4.2 OneNote 100G 处理（重点）

- **文本优先**：OneNote Md Exporter / ConvertOneNote2MarkDown 导出文本+结构（文本通常只占 100G 的小部分）
- **附件清单化**：附件/图片/嵌入文件只建 manifest（路径+大小+所在页），**不全部下载**
- **按需取用**：迁移文档中引用附件时，再从清单定位下载
- **存储分离**：附件不进 git 仓库 → 放 NAS/对象存储，知识库文本用相对链接引用

### 4.3 纸件 5 万页处理（重点）

**全量 OCR 否决理由**：中文手写 OCR 识别率 50-90%（视字迹），校对成本为 OCR 的 3-5 倍，综合 3-10 分钟/页 → 5 万页 = 1-4 人年。不可接受。

**替代方案：索引卡模式（数字索引 + 物理本体）**

1. **书目台账**：60 本 → 每本一页索引卡：主题 / 时间跨度 / 字迹评估 / 章节目录（主题+页码）
2. 索引卡进知识库 `04_person/` 或专门目录，形成"可检索的书目"
3. **A 类精 OCR**：当前工作直接相关的页（预估 <1000 页），拍照/扫描 + OCR + 人工校对
4. 其余：原位物理保留，需要时按索引卡定位（找得到比全数字化更重要）

**扫描成本参考**：高速扫描仪双面 60 页/分钟 → 5 万页纯扫描约 14-28 小时（分批），手机拍照约 70 小时；仅建议对 A 类执行。

## 5. 五阶段迁移管线（暂存区隔离）

```
P0 盘点 → P1 批量转换 → P2 清洗去重 → P3 分类路由 → P4 索引重建 → P5 验证收尾
```

> 铁律：所有源先无脑转 Markdown 进 `import/migration/` 暂存区，不直接写入 knowledge/ 主结构。清洗/分级/去重全部在暂存区完成。

| 阶段 | 内容 | 耗时 |
|:-----|:-----|:-----|
| P0 盘点 | MANIFEST.md 台账（含 60 本书目）+ 抽样校准四象限 | 0.5-1 天 |
| P1 批量转换 | L1 快线脚本；每篇 frontmatter（source/original_path/value） | 1-2 天 |
| P2 清洗去重 | 噪声清理、标题+哈希相似度聚类（>0.8 标记待确认）、多主题拆分 | 1-2 天 |
| P3 分类路由 | A→业务模块 / B→日期归档 / D→冷归档；遵循 knowledge-wiki 规范 | 1-2 天 |
| P4 索引重建 | kb-global-index.py + kb-log-append.py | 0.5 天 |
| P5 验证 | format-validator + link-validator；源冻结 90 天后清理 | 0.5 天 |

**L1+L2 数字化部分约 5-8 人天；L3 纸件索引化约 1-2 个月（每周 2-3 本）**

## 6. 存储架构（100G 体量下的硬约束）

```
git 仓库（knowledge/）: 纯文本 Markdown（预计 <5G）→ 正常 git 管理
附件库（NAS/对象存储）: OneNote 附件 + 纸件扫描 PDF（100G+）→ 不进 git
链接方式: Markdown 中相对路径/符号链接引用附件库
```

## 7. 风险与对策

| 风险 | 对策 |
|:-----|:-----|
| 全量搬运稀释知识库 | 价值分层先行，仅 A/B 进主结构 |
| 5 万页纸件成本失控 | 索引卡模式 + 1% 精 OCR，战略放弃全量 |
| OCR 错误污染纸件内容 | 仅 A 类 OCR，抽检 10%，标注"OCR 未校对" |
| OneNote 转换丢表格/嵌套 | 转换后抽样比对，附件 manifest 兜底 |
| 去重误删 | >0.8 相似度只标记不删 |
| 100G 附件撑爆 git | 文本/附件双轨存储 |
