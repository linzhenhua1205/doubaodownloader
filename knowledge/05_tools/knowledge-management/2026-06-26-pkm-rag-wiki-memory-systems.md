## 一、核心心智模型

> **一句话总结**: PKM 和 Wiki **组织**知识结构。RAG **检索**知识。记忆系统**演化**智能体上下文。

**混淆根源**: 将"知识"视为单一事物。实际上知识有六个层次：

- 捕获 → 结构化 → 检索 → 解读 → 复用 → 演化
- 不同系统优化不同的阶段

---

## 二、四大范式详析

### 1. PKM（个人知识管理）

| 维度 | 说明 |
|:-----|:------|
| **驱动方** | 人类 |
| **优化目标** | 个人演化（理解如何随时间变化） |
| **容错性** | 容忍模糊 |
| **经典系统** | Obsidian / Logseq / Notion / Zettelkasten |
| **成功关键** | **为复用而优化，而非为捕获** |
| **失败模式** | 只收集不综合 → "个人垃圾填埋场" |

> PKM 不是文档——文档追求清晰，PKM 容忍模糊。

### 2. Wiki

| 维度 | 说明 |
|:-----|:------|
| **驱动方** | 团队 |
| **优化目标** | 共享结构（当前正确答案） |
| **容错性** | 要求清晰 |
| **经典系统** | Confluence / MediaWiki / BookStack / DokuWiki |
| **成功关键** | 社会契约：这个页面就是知识存在的地方 |
| **失败模式** | 信息过时制造虚假信心 |

> Wiki 应该是"无聊的"——稳定知识被保存的地方，而非创意诞生的地方。

### 3. RAG（检索增强生成）

| 维度 | 说明 |
|:-----|:------|
| **驱动方** | 机器 |
| **优化目标** | 机器检索（哪些文档相关？） |
| **容错性** | 要求精确检索 |
| **成功关键** | 底层文档质量决定 RAG 成败 |
| **失败模式** | 分块差 / 检索弱 / 无元数据 / 无评估体系 |

> **核心观点**: RAG 不是知识策略，RAG 是**访问策略**。它帮助机器访问知识，但不决定哪些知识是有效的、被维护的或有用的。

### 4. AI 记忆系统

| 维度 | 说明 |
|:-----|:------|
| **驱动方** | 智能体 |
| **优化目标** | 连续性（智能体应记住什么？） |
| **容错性** | 要求治理 |
| **经典理念** | MemGPT-style / 情景记忆 / 语义记忆 / 反思型智能体 |
| **成功关键** | 记忆决定什么跨越时间存续 |
| **失败模式** | 存储过多 / 记忆中毒 / 隐私风险 / 缺少遗忘机制 |

> **核心观点**: AI 记忆 ≠ 长上下文。长上下文让模型在当前会话看到更多，记忆决定什么跨越时间存续。

## 三、核心差异速查表

| 维度 | PKM | Wiki | RAG | AI 记忆 |
|:-----|:-----|:-----|:-----|:--------|
| **驱动方** | 人类 | 团队 | 机器 | 智能体 |
| **优化目标** | 个人演化 | 共享结构 | 机器检索 | 连续性 |
| **核心问题** | 我的理解如何变化？ | 当前答案是什么？ | 哪些文档相关？ | 智能体应记住什么？ |
| **容错性** | 容忍模糊 | 要求清晰 | 要求精确检索 | 要求治理 |

## 四、四种组合模式

| 模式 | 管线 | 适用场景 |
|:-----|:------|:---------|
| **PKM → Wiki** | 私下笔记→连接想法→提炼→发布稳定知识→共享参考 | 个人研究→组织知识 |
| **Wiki → RAG** | 维护Wiki→索引→检索→有根有据的回答→链接原文 | 最干净的RAG模式之一 |
| **RAG + 记忆** | RAG检索外部事实→记忆存储上下文→智能体结合→未来行为改善 | RAG回答"知识库怎么说"，记忆回答"关于用户/项目重要的是什么" |
| **PKM + AI助手** | 人类捕获→AI总结建议链接→人类编辑验证→Wiki或发表 | AI增强PKM，但不拥有真相所有权 |

## 五、五大常见架构错误

| # | 错误 | 正确理解 |
|:-:|:-----|:---------|
| 1 | 把 RAG 当 Wiki | RAG 不创建权威结构，它只从已有内容检索 |
| 2 | 把记忆当数据库 | 记忆是选择性上下文，数据库存储精确事实 |
| 3 | 把 PKM 当文档 | PKM 可以混乱，文档不应该 |
| 4 | 把 Wiki 当思考工具 | 用 PKM 做粗糙思考，用 Wiki 做持久知识 |
| 5 | 把长上下文当记忆 | 上下文只在会话中有用，记忆是持久的、可更新的 |

## 六、知识系统光谱

```text
人类思考 <------------------------------------> AI 连续性

   PKM          Wiki          RAG        AI 记忆
(个人演化)    (共享结构)    (机器检索)    (智能体连续性)
```

**方向很重要**：知识通常始于个人想法 → 变成共享结构 → 被索引用于机器检索 → 成为持久智能体行为的一部分。

**LLM Wiki 的定位**：

```text
PKM -> Wiki -> LLM Wiki -> RAG -> AI 记忆
               ^
          (预结构化知识)
```

LLM Wiki 将知识预先结构化为页面/摘要/实体/链接，更接近编译型知识系统。

## 八、治理要求

| 系统 | 治理重点 |
|:-----|:---------|
| PKM | 什么保持私密？什么发布？什么删除？ |
| Wiki | 谁负责每个页面？上次审核？权威版本？ |
| RAG | 哪些来源被索引？是否引用来源？效果如何评估？ |
| AI 记忆 | 什么被记住？用户能否查看/删除？错误记忆如何纠正？ |

> 记忆需要最严格的治理，因为它能无声地影响未来行为。

---

## 最终结论

> 用 PKM 来思考。用 Wiki 来共享真相。用 RAG 来检索。用记忆来保持连续性。
> 未来不是一统天下，而是**分层的知识架构**。
