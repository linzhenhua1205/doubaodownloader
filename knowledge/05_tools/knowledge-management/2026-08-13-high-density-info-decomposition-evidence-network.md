## 1. 核心命题

> **高密度信息拆解 = 信息解压（Decompression）+ 证据网络（Evidence Graph）。**
> 大文档拆解是**分割**（把宽的切窄），高密度拆解是**解码**（把密的展开）——且解码产物还要递归解码；周边信息论证不是单点强化，而是**以信息点为圆心、按证据强度分层构建证据网络**。

**两者的本质差异**：

| 维度 | 大文档拆解 | 高密度信息拆解 |
|:-----|:-----------|:---------------|
| 问题形态 | 广度问题（长、稀释） | 深度问题（密、浓缩） |
| 核心操作 | 分割 partition | 解码 decode + 递归 |
| 失败模式 | 漏点（覆盖不全） | **压缩损失**（概括丢信息） |
| 论证方式 | 单点强化（查证/扩展/对比） | 证据网络（多源分层论证） |
| 产物 | 信息点清单 | 信息点 + 证据链 |

## 2. 为什么高密度信息需要不同的拆解方法

### 2.1 信息密度定义
```
信息密度 = 有效信息点数 / 千字
- 大文档（报告/论文）：密度低，稀释度高 → 拆解靠"找"（提取）
- 高密度文本（规格书/论断/数据表/技术评论）：密度高 → 拆解靠"解"（解码）
```

### 2.2 高密度信息的四个特征（决定了拆解方式）

| 特征 | 含义 | 拆解含义 |
|:-----|:-----|:---------|
| **多维参数浓缩** | 一句话含多个维度（"UALink 1.0 基于 PCIe 物理层，16 端口 x16 全互联，双向 901GB/s"） | 每维度拆成独立信息点 |
| **隐含假设** | 断言背后有未言明前提 | 显式化前提，验证前提才验证断言 |
| **术语依赖** | 一个词 = 一个知识体系（"CXL 池化""MoE 并行"） | 术语触发递归解压 |
| **浓缩推理链** | 结论句省去推理过程 | 还原推理链，逐环验证 |

### 2.3 大文档拆解对高密度句的失败模式
- 逐块提取时对高密度句做"概括"→ **压缩损失**：参数丢了、条件丢了、口径丢了
- 对策：提取命中高密度句时**必须触发解码**（不概括，只展开）

## 3. 递归解压模型（粒度金字塔 + 原子性判据）

### 3.1 粒度金字塔

```
文档 → 段落 → 句子 → 命题(claim) → 原子事实
                                  ↑
                          递归解压发生在这里
```

### 3.2 原子性判据（递归终止条件，三选一满足即停）

| 判据 | 定义 | 例子 |
|:-----|:-----|:-----|
| **可独立验证** | 能找到至少一个来源或反例 | "GB200 NVL72 域内 72 GPU 全互联" ✅ |
| **单一语义** | 不能再拆（再拆就是术语解释而非信息点） | "NVLink 5 带宽 1.8TB/s" ✅ |
| **可复用** | 脱离上下文仍有独立意义 | "CXL 3.0 支持内存池化" ✅ |

**递归触发规则**：解码产物若含"浓缩词"（术语/数值/论断连接词如"因此""基于"）→ 标记为待解压子点，进入下一轮。

### 3.3 解压成本控制
- 递归深度上限 3 层（超过则合并为"术语表条目"而非信息点）
- 每条高密度句的解压产物 ≤8 个子点（超出说明句子本身可拆分，回退到句子级分割）

## 4. 高密度信息类型学与解码模板（MECE 四类）

| 类型 | 特征 | 解码模板（必填字段） |
|:-----|:-----|:---------------------|
| **规格点** Spec | 参数×值×单位×条件 | 参数名 / 数值 / 单位 / 适用条件 / 对比基线 / 来源 / 时间 |
| **论断点** Claim | 浓缩推理链 | 前提 / 推理步骤 / 结论 / 适用边界 / 反方条件 |
| **数据点** Data | 数值带口径 | 数值 / 口径定义 / 时间 / 地域 / 来源 / 置信度 / 对比基线 |
| **概念点** Concept | 一个词 = 一个体系 | 定义 / 构成要素 / 边界 / 相关概念 / 演化史 |

**解码示例（规格点）**：
> 原文："UALink 1.0 基于 PCIe 物理层，16 端口 x16 全互联，双向 901GB/s"
> 解码产物：
> - 协议基础：PCIe 物理层（复用 SerDes/电气规范）
> - 拓扑：16 端口 x16 全互联（域内全对等）
> - 带宽：双向 901GB/s/端口（条件：x16 链路）
> - 隐含假设：需 PCIe 6.0 速率级物理层（触发子解压）

## 5. 周边信息论证：证据网络构建（核心新增）

### 5.1 六类周边信息（MECE）

| 类别 | 回答的问题 | 作用 | 采集路径 |
|:-----|:-----------|:-----|:---------|
| **来源信息** Source | 谁说的？何时？权威性如何？ | 建立可信度基线 | 原文追溯、作者/机构检索 |
| **佐证信息** Corroboration | 还有谁这么说？ | 一致性验证 | 知识库检索、网络搜索 |
| **反证信息** Refutation | 谁反对？边界在哪？ | 划定适用边界 | 反方检索、边界案例 |
| **背景信息** Context | 为什么这么说？前因后果？ | 语境还原 | 历史沿革、上下游文档 |
| **衍生信息** Derivation | 所以呢？影响什么？ | 价值提取 | 推理链延伸、应用场景 |
| **关联信息** Association | 和什么相关？对比谁？ | 网络定位 | 相邻概念、对比对象 |

### 5.2 证据强度分级（论证等级）

| 等级 | 来源类型 | 判定权重 | 示例 |
|:----:|:---------|:--------:|:-----|
| **L1 第一手** | 规格书/标准/论文/原始数据 | 1.0 | UALink 联盟规范、JEDEC 标准 |
| **L2 二手权威** | 官方文档/知名机构报告/原厂白皮书 | 0.7 | NVIDIA 官方博客、Gartner |
| **L3 三手传播** | 技术博客/自媒体/转载 | 0.4 | 技术社区文章 |
| **L4 推断** | 无直接来源的推理 | 0.2 | AI 推导、个人判断 |

> 衔接知识考古方法论 §9.1 来源可信度矩阵（知识库已有），此处做"单信息点"维度的等级化。

### 5.3 证据网络构建流程（三圈扩展）

```
        ┌── 第三圈: 背景/关联/衍生 ──┐
        │   ┌── 第二圈: 佐证/反证 ──┐ │
        │   │   ┌── 第一圈: 来源 ──┐ │ │
        │   │   │    ● 信息点      │ │ │
        │   │   └─────────────────┘ │ │
        │   └───────────────────────┘ │
        └─────────────────────────────┘
```

1. **第一圈（必做）**：找直接来源（原文锚点、知识库检索、规格书/标准）→ 确认"谁说的、依据什么"
2. **第二圈（A/B 类必做）**：跨源找佐证 ≥1 个 + 反证 ≥1 个 → 一致性 + 边界
3. **第三圈（A 类选做）**：背景/关联/衍生 → 语境 + 网络 + 价值

### 5.4 相关度过滤（防周边污染）
- 周边信息 ≠ 相关：每条周边信息必须回答"它如何影响对信息点的判断？"
- 不能回答的一律丢弃；每条周边信息记录"关联强度"（直接佐证/间接相关/仅背景）

## 6. 验证螺旋：论证-完善迭代循环

```
断言 → 找佐证 → 找反证 → 修正断言 → 再验证
        ↑                                │
        └──────── 循环直到闭合 ───────────┘
```

### 6.1 每轮迭代的四步
1. **提出/修正断言**（解压后的信息点，带等级标记）
2. **找佐证**（≥1 个 L1/L2 来源 或 ≥2 个 L3 一致来源）
3. **找反证**（边界反例、相反数据、质疑理由）
4. **修正**：根据反证收窄断言（加条件/改表述/降置信度）

### 6.2 循环退出条件（证据链闭合判定）
- ✅ 无新反证出现（连续 2 轮无新增反证）
- ✅ 至少 1 个 L1 来源 或 2 个独立 L2 来源
- ✅ 断言已按反证修正（若反证成立，则断言降级为"争议观点"并保留双方）

### 6.3 三态终局
| 终局 | 判定 | 处置 |
|:-----|:-----|:-----|
| **成立** | 证据链闭合，无致命反证 | 入知识库，标注证据等级 |
| **争议** | 佐证反证并存 | 入知识库，双观点并列，标注"争议" |
| **证伪** | 反证成立，断言不成立 | 不丢弃：入"反例档案"，标注为何被否（防重复踩坑） |

## 7. 工程实现（信息点 + 证据链数据模型）

```jsonc
// info-point.json —— 高密度点解压 + 证据链（在上轮大文档拆解模型的 evidence 字段上扩展）
{
  "id": "P-042",
  "origin": "原文位置锚点",
  "type": "claim",                  // spec|claim|data|concept
  "grade": "A",
  "decoded": [                      // 递归解压产物
    {"sub_id": "P-042a", "claim": "UALink 复用 PCIe 物理层", "depth": 1}
  ],
  "status": "closed",               // extracted|decoding|verifying|challenging|refining|closed
  "evidence": [                     // 证据网络
    {"kind": "source", "level": "L1", "source": "UALink 联盟规范 1.0", "link": "url", "strength": 1.0},
    {"kind": "corroboration", "level": "L2", "source": "NVIDIA 官方博客", "link": "url", "strength": 0.7},
    {"kind": "refutation", "level": "L3", "source": "社区质疑帖", "link": "url", "strength": 0.4}
  ],
  "verdict": "成立",                // 成立|争议|证伪
  "confidence": 0.9,                // 证据加权置信度
  "reviewed": false
}
```

- **置信度公式**：`confidence = Σ(证据强度 × 等级权重) / Σ(等级权重)`，反证扣减
- 状态机升级：`extracted → decoding → verifying → challenging → refining → closed`
- 周边信息采集优先级：**知识库检索 → 原文追溯 → 网络搜索 → 领域专家判断**
- 每文档独立 `tmp/decompose/<doc_id>/evidence/` 存证据快照

## 9. 风险与反方视角

| 风险 | 对策 |
|:-----|:-----|
| **过度解压**：一个点拆出 20 个子点 | 原子性判据 + 递归深度 ≤3 + 产物 ≤8 |
| **证据收集成本 > 价值** | 只对 A/B 类建完整证据网络；C/D 类止于 L1 来源确认 |
| **反证过度**：证伪到怀疑一切 | 证据链闭合阈值（连续 2 轮无反证即闭合） |
| **周边信息污染**：周边≠相关 | 相关度过滤（必须回答"如何影响判断"） |
| **L4 推断混入证据** | 等级权重 0.2 + 强制标注"推断" |
| 反方视角：L1 来源也可能错（标准修订/厂商夸大） | 时间戳记录 + 来源版本号；证据链本身可复审 |

## 10. 落地建议

1. **试点**：选 1 条高密度论断（如"推理负载将超过训练负载"或"UALink 复用 PCIe 物理层"），跑完整验证螺旋（含三圈证据收集）
2. **模板固化**：四类解码模板 + 证据链 JSON 结构，沉淀为可复用技能
3. **与拆解流水线融合**：大文档拆解 P4 集成"高密度句识别 → 触发解码"
4. **质量基线**：A 类点证据链闭合率 ≥80%，证伪档案 ≥1 条/批（证明真的在找反证）
