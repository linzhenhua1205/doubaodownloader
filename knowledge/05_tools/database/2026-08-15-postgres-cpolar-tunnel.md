## 一、结论概要

**cpolar** 是内网穿透工具，把本地 PostgreSQL（默认 5432）暴露到公网，**无公网 IP 也能远程访问**：

| 要素 | 说明 |
|:-----|:-----|
| 核心原理 | 隧道：公网地址 → 加密隧道 → 本地 5432 |
| 管理界面 | 本地 `http://localhost:9200` |
| 隧道协议 | TCP（数据库场景） |
| 地址类型 | 临时（免费，24h 随机变化）/ 固定（专业版付费） |

**核心结论**：
1. **七步流程**：装 PG → 本地验证 → 装 cpolar → 登录 → 建隧道 → 取公网地址 → 公网测试
2. **临时地址免费但 24 小时内随机变化**，固定地址需升级专业版
3. **连接参数易错点**：公网连接用**隧道公网端口**，不是本地 5432
4. **安全权衡**：内网穿透=数据库暴露公网，必须配强密码 + 限源 + 尽量短生命周期

## 二、内网穿透原理

### 2.1 工作链路

| 环节 | 说明 |
|:-----|:-----|
| 公网客户端 | 连接 cpolar 公网地址（如 `xxx.cpolar.top:port`） |
| cpolar 云节点 | 转发到本地 cpolar 客户端 |
| 本地 cpolar 客户端 | 转发到 localhost:5432 |
| PostgreSQL | 本地服务响应 |

- 本质：**反向隧道**，公网 → 云 → 本地，穿透 NAT
- 数据库无需公网 IP，也无需修改 `listen_addresses` 为 `*`（仍监听 localhost 即可）

### 2.2 与直连对比

| 维度 | 直连公网 | cpolar 穿透 |
|:-----|:---------|:------------|
| 公网 IP | 需要 | 不需要 |
| 防火墙开放 | 需放行 5432 | 只需运行 cpolar 客户端 |
| 地址稳定性 | 固定 IP | 临时地址会变 |
| 安全面 | 端口直接暴露 | 多一层隧道（但仍是公网可达） |

## 三、七步配置流程

### 3.1 Step 1-2：本地安装与验证

```bash
# install PostgreSQL locally, set password, keep port 5432
# verify local connection with psql or Navicat
psql -U postgres -h localhost -p 5432 -d postgres
```

- 确认本地连接成功**再继续**，避免穿透后排查混淆

### 3.2 Step 3-4：cpolar 安装与登录

```bash
# install cpolar (download from official site for your platform)
# start service and open web UI
curl -L https://www.cpolar.com/static/downloads/install-release-cpolar.sh | sudo bash
sudo systemctl start cpolar
# open browser to local management console
# http://localhost:9200  → login with cpolar account
```

### 3.3 Step 5：创建 TCP 隧道

| 参数 | 值 |
|:-----|:---|
| 协议 | TCP |
| 本地地址 | 5432 |
| 域名类型 | 随机临时 TCP 端口 |
| 地区 | China（就近） |

- 在 cpolar Web UI → 隧道管理 → 创建隧道
- 创建后在"在线隧道列表"获取**公网 TCP 地址**（含随机端口）

### 3.4 Step 6-7：公网连接测试

```bash
# connect using public address + tunnel port (NOT local 5432)
psql -h <public-addr> -p <tunnel-port> -U postgres -d postgres
```

- 工具（Navicat/DBeaver）同样用公网地址+隧道端口
- 验证通过 → 临时方案完成

## 四、临时 vs 固定地址

| 维度 | 临时（免费） | 固定（专业版） |
|:-----|:------------|:---------------|
| 地址 | 随机，24h 内变化 | 预留固定地址 |
| 稳定性 | 需频繁更新连接串 | 永久有效 |
| 费用 | 免费 | 付费 |
| 适用 | 临时调试/演示 | 长期开发/家庭服务器 |

### 固定地址配置（专业版）

1. cpolar 官网 → 预留 → 保留 TCP 地址（生成固定公网地址）
2. 本地隧道管理 → 编辑隧道 → 端口类型改"固定 TCP 端口"，填预留地址
3. 在线隧道列表确认固定地址生效
4. 用固定地址 + 对应端口验证

## 五、安全注意事项

| 风险 | 缓解措施 |
|:-----|:---------|
| 数据库暴露公网 | 强密码（>16 位混合字符）+ scram-sha-256 |
| 隧道地址被扫描 | 用完即删隧道；定期更换地址 |
| 明文传输 | 穿透 + 数据库 SSL 双加密 |
| 账号泄露 | 限数据库账号只授所需权限 |
| 隧道常驻 | 不使用时停止 cpolar 服务 |

> ⚠️ **核心认知**：内网穿透是"方便优先"的方案，任何暴露公网的数据库都需按公网暴露标准加固。

## 六、替代方案对比

| 方案 | 原理 | 适用 | 成本 |
|:-----|:-----|:-----|:-----|
| **cpolar 穿透** | 反向隧道 | 无公网 IP 的临时/轻量访问 | 免费/低 |
| frp/ngrok 自建 | 自建穿透服务器 | 有公网服务器的稳定方案 | 服务器成本 |
| VPN/跳板机 | 二层/应用层隧道 | 企业内网访问 | 中 |
| 云数据库公网地址 | 云厂商托管 | 有预算的正式环境 | 高 |

## 七、易错点与最佳实践

### 易错点

| # | 场景 | 坑 | 对策 |
|:-:|:-----|:---|:-----|
| 1 | 用本地 5432 连公网 | 端口对不上 | 用隧道公网端口 |
| 2 | 本地未先验证 | 穿透后问题难排查 | 先本地连通再穿透 |
| 3 | 临时地址当固定用 | 24h 后连接失效 | 确认地址类型 |
| 4 | 忽略安全加固 | 公网裸奔 | 强密码+SSL+限权 |
| 5 | 隧道常驻不关 | 长期暴露风险面 | 用完即停 |
| 6 | 选错地区节点 | 延迟高 | 选 China 就近节点 |

### 最佳实践

1. **先本地后穿透**：每一步验证通过再进下一步
2. **安全加固先行**：开穿透前先改密码、限权限、开 SSL
3. **生命周期管理**：临时任务用临时地址，用完删隧道
4. **记录连接串**：公网地址+隧道端口+账号，存档备查
5. **正式环境不用穿透**：穿透适合开发/演示，生产走 VPN/云数据库
