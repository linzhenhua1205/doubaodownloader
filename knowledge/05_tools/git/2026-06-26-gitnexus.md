GitNexus 是一个开源代码知识图谱工具，通过 Tree-sitter 解析代码语法结构，构建函数/类/文件/调用链/社区的多维知识图，并通过 MCP 协议暴露给 AI Agent 进行智能代码分析。

## 核心架构

```text
GitNexus/
+-- gitnexus/              # CLI + MCP 核心
|   +-- src/
|   |   +-- index.ts       # CLI 入口
|   |   +-- cli/           # 命令实现
|   |   +-- core/          # 核心引擎
|   |   +-- mcp/           # MCP 服务器
|   |   +-- tools/         # LadybugDB 工具层
|   +-- package.json
+-- gitnexus-web/          # Web UI (React)
|   +-- src/
|   +-- package.json
+-- ldb/                   # LadybugDB 嵌入引擎
```

### 关键层

| 层 | 技术 | 作用 |
|:--|:-----|:-----|
| **语法解析** | Tree-sitter | 15+ 语言 AST 解析 |
| **图存储** | LadybugDB (e.lb) | 嵌入式图数据库，存储节点+边 |
| **图算法** | graphology | 社区检测、中心性分析、最短路径 |
| **嵌入** | ONNX Runtime | 本地运行 code-bert 模型做向量检索 |
| **协议** | MCP (Model Context Protocol) | 标准化 AI Agent 通信 |
| **前端** | React + vis-network | 图谱可视化 + AI 对话 |

## 支持的语言

> 15+ 语言通过 Tree-sitter 解析：TypeScript、JavaScript、Python、Java、Go、Rust、C、C++、C#、Ruby、PHP、Swift、Kotlin、Scala、Solidity

## 知识图谱结构

### 节点类型 (Node Types)

- `file` — 代码文件
- `function` — 函数定义
- `class` — 类定义
- `method` — 方法定义
- `variable` — 变量/常量
- `interface` — 接口定义
- `type` — 类型定义
- `import` — 导入声明
- `export` — 导出声明
- `dependency` — 外部依赖
- `test` — 测试文件
- `config` — 配置文件

### 边类型 (Edge Types)

- `calls` — 函数调用关系
- `extends` — 类继承关系
- `implements` — 接口实现
- `imports` — 导入依赖
- `contains` — 文件包含关系
- `defines` — 定义关系
- `references` — 引用关系
- `depends_on` — 依赖关系
- `test_of` — 测试与代码关系
- `version` — 版本演进
- `community` — 社区归属

### 社区检测

Graphology 的 Louvain 算法自动检测代码社区（模块/功能聚簇），支持：

- 按社区过滤节点
- 分析社区间依赖关系
- 识别循环依赖

## 部署方式

### 1. CLI + MCP (推荐)

```bash
# 全局安装
npm install -g gitnexus

# 验证
gitnexus --version

# 进入代码库根目录，一键索引
cd /path/to/codebase
npx gitnexus analyze

# 配置 MCP
npx gitnexus setup

# 启动 MCP 服务
npx gitnexus mcp
```

### 2. Web UI

```bash
git clone https://github.com/abhigyanpatwari/GitNexus.git
cd GitNexus/gitnexus-web
npm run dev
```

Web UI 可配置本地模型，但大型工程会卡顿。需与本地 CLI + MCP 联动才能达到完整效果。

### 3. 自定义编码调用 MCP

通过 HTTP 调用本地模型（如 Qwen3-Coder），配合 GitNexus MCP Server 实现：

1. 用户提问 → AI Agent
2. Agent 调用 MCP 工具从 LadybugDB 检索代码依赖/上下文
3. MCP 返回结构化代码知识
4. 连同用户问题一起送给大模型分析
5. 生成精确的代码分析结果

> 采用混合向量检索方式，提问需有一定精度

## MCP 工具清单

GitNexus MCP Server 暴露以下工具供 AI Agent 调用：

| 工具名 | 功能 |
|:-------|:-----|
| `query_knowledge_graph` | 通用知识图谱查询（节点/边/社区） |
| `get_node_context` | 获取特定节点的上下文（函数/类等） |
| `find_related_nodes` | 查找相关节点 |
| `get_call_chain` | 获取调用链 |
| `get_community_info` | 获取社区信息 |
| `get_impact_analysis` | 影响分析 |
| `get_structure_info` | 获取代码库结构 |
| `detect_changes` | 检测变更 |
| `get_recent_files` | 获取最近修改的文件 |
| `find_entry_points` | 查找入口点 |
| `run_impact_analysis_from_memory` | 基于记忆的影响分析 |
| `search_code` | 搜索代码 |
| `explain_node` | 解释节点 |
| `get_common_flow` | 获取公共执行流 |
| `get_modified_nodes` | 获取已修改的节点 |
| `get_modified_node_details_from_memory` | 获取已修改节点的详细信息 |

## 多仓库支持

- **Group 机制**：将多个相关仓库组成 Group，支持跨仓库调用链追踪
- **契约桥接**：跨仓库的函数调用、接口实现可以桥接识别
- **社区跨库**：社区检测可跨仓库进行

```text
Node.js ^22.0         # 运行时

graphology             # 图算法库
ONNX Runtime           # 本地推理引擎
Commander              # CLI 框架
commander-prompts      # 交互式 CLI
```

## 关键特性

- **完全本地化**：所有分析在本地完成，代码不出域，适合信安场景
- **无依赖安装**：npm install -g 全局安装，零配置
- **MCP 协议兼容**：可与任何支持 MCP 的 AI Agent 集成
- **增量索引**：支持增量更新，不重复解析未修改文件
- **嵌入搜索**：本地 ONNX 模型提供语义级别的代码搜索

## 应用场景

1. **新成员 onboarding** — 快速理解大型代码库的模块划分与调用关系
2. **代码审查** — 修改前的 impact analysis 降低引入 bug 风险
3. **重构规划** — 通过社区检测识别高耦合模块
4. **Bug 定位** — 从错误栈回溯调用链，定位根因
5. **AI Agent 辅助编码** — 让 AI 理解私有代码上下文后再回答问题

## 已知限制

- Web UI 在大型工程下会卡顿（建议使用 CLI + MCP 方式）
- 向量检索的混合检索方式对提问的精度有一定要求
- 需 Node >= 22.0 环境
