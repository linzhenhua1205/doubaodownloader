# SSOT 权威源声明（Manifest）

> **用途**: 声明项目内每类设计参数的唯一权威源文档（Tier 0），防止跨文档参数漂移。
> **原则**: AI 查询/引用/生成必须先读 SSOT；禁止从派生文档转引；不一致记录待同步，不自动修改。

---

## 1. SSOT 层级定义

| Tier | 角色 | 说明 | 示例 |
|:----:|:-----|:-----|:-----|
| **Tier 0** | SSOT 基准 | 唯一维护设计参数的文档，所有派生文档以此为基准 | `30-deliverables/00-design/<topic>.md` |
| **Tier 1** | 派生文档 | 从 SSOT 提取/演绎，不单独维护设计参数 | 拓扑图、评审报告、方案对比 |
| **Tier 2** | 引用文档 | 仅引用，出现不一致时一律以 SSOT 为准 | 会议纪要、测试记录 |

## 3. 变更传播规范

```text
ADR 裁决 / 设计变更
   -> 1. 修改 SSOT 文档 (唯一允许改参数的地方)
   -> 2. 填写变更影响分析 (哪些 T1/T2 受影响)
   -> 3. 逐项回写派生文档 (加取代头注, 不静默覆盖)
   -> 4. 运行交叉比对脚本验证无残留
   -> 5. 更新 Manifest 映射表 (变更记录)
```

## 4. AI 行为准则

- 回答任何设计参数前，必须优先读取 SSOT 文档，禁止仅凭记忆或派生文档回答
- 参数输出时标注来源位置，如 `<param> @ <value> (SSOT §x.x)`
- AI 生成新文档引用参数，必须直接从 SSOT 提取，不允许从 T1/T2 转引
- 新增参数必须写入 SSOT 文档，而非其他文档
- 在非 SSOT 文档读到不一致参数时：以 SSOT 为准答复 + 记录差异到待同步项 + 不自动修改（走变更传播流程）
- AI 不得基于「我的理解」或「行业常识」修改 SSOT 设计参数

> 违反溯源规范: 任何无法追溯至 SSOT 或一手 Datasheet 的参数视为「未验证信息」，接收方有权拒绝采纳。
