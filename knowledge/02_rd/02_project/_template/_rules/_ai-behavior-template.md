# AI 行为准则（项目级约束）

> **用途**: 项目场景下 AI 的行为约束——「约束做成基础，不是消失掉」。
> **性质**: 硬约束。违反即视为任务不合格。
> **修订**: 每次裁决/事故后审查是否需更新；修订走「失败模式 → 规则 → 机制」转化链并留痕。

---

## 1. 开工准则（每次任务第一步）

- [ ] 读取 `_index.md`（项目知识地图）——先获取项目全景再动手
- [ ] 读取 `_manifest/ssot-manifest.md`——确认权威源
- [ ] 读取 `_rules/` 本文件与 quality/naming——确认约束
- [ ] 输出「项目状态摘要」：当前主线 / 最近裁决 / 待决问题 / 当前有效文档

## 2. 查询与生成准则

- 回答项目设计参数前，必须读取 SSOT 文档，禁止仅凭记忆或派生文档回答
- 生成新文档引用参数，必须直接从 SSOT 提取并标注来源位置
- 引用外部资料必须带来源分级标注（一手/二手/三手）+ 出处 + 日期
- 关键可验证断言必须有外部出处（内部引用 ≤60%，Q10 信源配比）

## 3. 禁止操作（红线）

- 禁止基于「我的理解」或「行业常识」修改 SSOT 设计参数
- 禁止在非 SSOT 文档「顺手」同步参数——必须走变更传播流程
- 禁止自动回写受影响文档——回写必须经人确认
- 禁止静默废弃文档——失效必须由 ADR 决策驱动
- 禁止跳过验证门禁收尾（未落盘 + 未 commit = 未完成）

## 4. 状态变更准则

- 文档状态（草稿/评审中/已裁决/生效/已失效）由人确认，AI 只提出建议
- 生效条件 = 评审通过 + 验证通过（双门槛）
- 修订必产生新版本（不覆盖历史，Changelog 记录）

## 5. 每次收尾检查清单

- [ ] 文档已落盘（write 完成）
- [ ] 交叉链接有效（链接检查通过）
- [ ] 格式门禁通过（doc-final-check）
- [ ] 参数与 SSOT 一致（交叉比对）
- [ ] _index.md 已更新（状态摘要 + 文档地图 + 决策索引 + 待办）
- [ ] log 已追加 + git commit 完成
