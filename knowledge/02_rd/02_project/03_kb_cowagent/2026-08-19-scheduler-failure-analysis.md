## 1. 结论概要

**近期定时任务失效是「单线程调度 + 任务耗时 > 排程间隔 + 10 分钟补跑窗口」三重叠加的系统性缺陷**，非单一故障。核心链条：

```text
agent_task 同步执行耗时 10~17 分钟（平均 ~13 分钟）
        ↓
单线程调度循环被阻塞，后续任务排队延迟
        ↓
延迟超过 10 分钟（600s）catch-up window
        ↓
任务被 overdue 机制静默跳过（仅 warning 日志，无告警）
        ↓
last_run_at 不更新 → 任务显示"失效"，当日产出缺失
```

**关键数字**：
- 08-19 凌晨 **7 个任务被跳过**（约占夜间任务 20%），08-15~08-19 累计 **26+ 次跳过**
- 每任务平均耗时 ~13 分钟，排程间隔仅 10 分钟 → **积压是必然，不是偶然**
- 08-15 07:11 日报任务本身也险被跳过（实证 overdue 700s）
- 08-19 14:11~17:55 **5 个 CowAgent 实例并行运行**（多实例风险，恰逢白天无任务未造成重复执行）

**已修复**：① 恢复被禁用的 git 检查任务；② 9 个高频跳过任务错峰至空窗；③ catch-up window 600s→1800s（代码级）；④ overdue 跳过留痕（可观测）。

## 3. 根因分析

### R1（主根因）单线程同步调度 + 任务耗时 > 排程间隔 → 积压必跳过

**机制**（scheduler_service.py `_check_and_execute_tasks`）：
- 调度循环为**单线程同步**：`_execute_task()` → `agent_reply()` 同步等待 agent 完成（数分钟）
- 循环内一个任务执行期间，后续任务全部等待
- `_is_task_due` 的 catch-up window 仅 **600s**：任务在计划点后 10 分钟内未被处理即**跳过并重排到下一天**

**量化**（08-19 凌晨实测，run.log）：

| 指标 | 数值 | 说明 |
|:-----|:-----|:-----|
| 任务平均耗时 | ~13 分钟 | 相邻任务开始时间差，10~17 分钟 |
| 任务排程间隔 | 10 分钟 | 01:00~06:30 每 10 分钟 1 档 |
| catch-up window | 600s | 代码硬编码 |
| 单日跳过率 | 20%（7/35） | 08-19 凌晨 |
| 单任务 token 预算 | ≤20K | design-005，但**执行时间无硬约束** |

**必然性推导**：任务耗时 T≈13min > 间隔 I=10min → 每执行 1 个任务净积压 3min → 执行 k 个任务后第 k+1 个任务延迟 ≈3k min → 3k > 10 即 k≥4 时开始跳过 → **每 5 个任务跳过 1 个是数学必然**。

### R2 任务执行耗时过长（~13 分钟/任务）

- agent 多步工具调用串行：搜索 → 抓取 → 阅读 → 写作 → 落盘 → git commit
- 无单任务执行超时控制（agent_reply 无 timeout 参数）
- 部分来源慢/重试消耗时间（design-005 的 fail-fast 已缓解 token 但未约束时间）

### R3 git 检查任务被禁用后未闭环恢复（b7ebae03）

- 08-16 11:40 禁用（SSH 认证问题），辩证分析文档（08-16 12:45 提交）明确"**待 SSH 认证解决后可按需恢复**"
- 实际：SSH/HTTPS 双通道已就绪（MEMORY: "origin=HTTPS；origin-old=SSH 备用"），但任务**未恢复** → 6:55 git 保障链路缺失

### R4 多实例并行风险（08-19 14:11~17:55 实证 5 实例）

- cow-alive-check.log：08-19 16:01/16:34/17:22 检测到 **5 个 CowAgent 进程**（PID 2928578-2928582）
- run.log：14:11:23 "Scheduler loop started" ×5、"Service initialized" ×4
- **风险**：`_claim_task` 防重入是**实例内互斥**，跨实例无效 → 5 实例并行时同一任务会被执行 5 次（当日白天无任务，未酿成重复执行；但 17:55 全部进程消失，由保活重启收敛为 1 实例 PID 5925）
- 多实例来源待查（疑为 14:11 多次 cow start 竞争，cow-alive-check 对 multi 仅告警不处理）

### R5 静默失败无告警闭环

- overdue 跳过仅 warning 日志 → 无飞书推送 → 用户 08-19 才发现
- scheduler/task-log/README.md 停留在 07-27 "首日创建"，**执行日志机制从未启用**
- 辩证分析（08-16）提出的"任务成功率看板"（4.4 节）未落地

## 5. 优化建议

### A. 代码级（CowAgent）

| # | 建议 | 价值 | 风险/备注 |
|:-:|:-----|:-----|:---------|
| A1 | **单任务执行超时控制**：agent_reply 加 timeout（如 10 分钟），超时终止并记失败 | 根治积压（耗时>间隔的源头） | 需处理超时后的清理（cancel_event 已存在，可复用） |
| A2 | **调度循环并行化**：agent_task 用线程池并发执行（受 API 并发/成本约束限流） | 43 任务×13min→理论并行后窗口大幅缩短 | 夜间 token 峰谷价：并行=同时打 API，需评估成本；建议先 A1 |
| A3 | **overdue 跳过告警**：skipped_count 当日 ≥2 推送飞书 | 消除静默失败 | 低成本高价值 |
| A4 | **多实例自动收敛**：cow-alive-check 检测 multi 时保留 PID 文件匹配实例、kill 其余 | 防重复执行 | ⚠️ 杀进程属破坏性操作，需用户确认后实施 |
| A5 | 调度器启动去重：app.py 初始化加进程级文件锁（fcntl） | 防 08-19 14:11 五实例重现 | 需查清 14:11 五次 start 的来源（保活?手动?） |

### B. 体系级（workspace）

| # | 建议 | 价值 | 状态 |
|:-:|:-----|:-----|:-----|
| B1 | **任务成功率看板**（辩证分析 4.4 落地）：统计近 7 日 计划/执行/跳过（用 skipped_count），周报输出 | 发现静默失败 | 新字段已就绪，可写脚本 |

| B3 | 任务耗时监控：相邻执行时间差 >12 分钟告警（积压预警） | 提前干预 | 可并入 B1 脚本 |
| B4 | 08-19 14:11 多实例根因审计：查 shell history / nohup.out / 保活日志 | 防复发 | 待查 |

| 建议 | 拒绝原因 |
