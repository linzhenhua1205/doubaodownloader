## 一、结论概要

**外部报告的判断基准与实际体系存在系统性偏差**——它把"AI 定时任务调度表"误读为"人的工作时间表"，导致多项结论失真。辩证结论：

| 类别 | 结论 | 说明 |
|:-----|:-----|:-----|
| ❌ 失真结论 | 5 项 | "每日工作 12 小时"、"5 项任务×25 分钟"、"08:00 后无任务"、"任务冲突"、"缺监控"均不成立或部分不成立 |
| ⚠️ 有参考价值 | 3 项 | 信息重复风险、任务密度观察、竞品分析增强——方向对但需按真实体系落地 |
| ✅ 真实问题（外部未识别） | 2 项 | C1 禁用任务误报、C2 20:30 超窗口真实违规、DESIGN_DOC 路径漂移（3 个实际缺陷） |

**核心判断**：调度体系设计本身**合理**（夜间窗口是刻意的 token 成本策略，非疏漏）；外部报告的"优化建议"（改白天执行、引入 Notion、加 CI/CD）**与系统设计原则冲突，不应采纳**；真正值得做的是**文档同步 + 合规修复**。

## 二、事实基准：真实调度体系 vs 外部报告认知

### 2.1 真实体系（2026-08-16 实测）

| 维度 | 实际值 | 说明 |
|:-----|:-------|:-----|
| 任务总数 | **49** | scheduler/tasks.json 实时 |
| 启用 | 48 | 1 个禁用（git 提交检查 6:55，因 SSH 认证问题有意禁用） |
| 每日执行 | **43** | 工作日任务（cron 第 5 段 `*`） |
| 时间窗口 | **21:00 ~ 08:00** | design-011 §6 强制规范，非外部所述"全天" |
| 执行模式 | **AI 自动执行** | 非"人工作"；AI 按 cron 触发，每任务 ≤20K tokens |
| 高峰分布 | 01:00-07:00 每小时 5-6 个任务 | 每 10 分钟一档，夜间密集排布 |

**任务构成**（按职能）：
- **调研类 39+**：industry-insight runner（硬件/技术/市场 3 组 + 30+ 单主题）
- **日报类 1**：知识库日报 07:00
- **周报类**：知识库周报（周日 23:10）等
- **专项报告类 3**：special-reports（周日 21:15/21:30/21:40）
- **治理/质检类**：Skills 质检（周日 21:00）、同步检查（周日 20:30）、健康检查等

### 2.2 外部报告的认知（对照）

| 外部报告说法 | 实际 | 偏差性质 |
|:------------|:-----|:---------|
| "每日 01:10-23:30 约 12 小时" | 夜间窗口 21:00-08:00（AI 执行） | **把 AI 调度误读为人工作** |
| "每日 5+ 项追踪任务" | 43 个每日任务 | 低估 8 倍（也许只看到部分） |
| "5 项×约 25 分钟/项 ≈120 分钟" | 43 任务×~10-15 分钟（AI） | 数量级错误 |
| "6:55 提交、7:00 知识维护存在时间冲突" | 6:55 已**禁用**；7:00 日报独立 | 基于过期信息 |
| "缺少 08:00 后任务" | 窗口规范就是 21:00-08:00（刻意） | **未理解设计意图** |
| "缺自动化监控/API/竞品工具" | 已有 cow-alive-check、system-guardian、competitor-analysis skill | 部分成立（见第四节） |

## 三、外部反馈逐条辩证

| # | 外部建议 | 辩证判定 | 依据 |
|:-:|:---------|:---------|:-----|
| 1 | "任务密度过大，每日 5 项×25 分钟超负荷" | **不成立**。43 任务是 AI 自动执行非人工作；单任务 ≤20K tokens 有预算约束；夜间执行利用低谷价（8/17 新价后更关键） | design-011 §4.7、§6；MEMORY token 成本策略 |
| 2 | "将固定时间改为灵活触发（08:00-20:00）" | **方向错误**。白天执行 = 高峰期 token 成本 +186%（8/17 峰谷新价）；固定窗口保证日报审计链完整（07:00 日报依赖 06:30 前全部调研产出） | MEMORY：8/17 峰谷新价；design-012 日报链路 |
| 3 | "增加 08:00-09:00 夜间复盘任务" | **语义混乱**。08:00-09:00 不是夜间；现有 07:00 日报已是每日复盘终点 | design-011 §6 |
| 4 | "6:55 与 7:00 冲突" | **已处理**。git 检查任务已禁用（b7ebae03），当前不存在冲突；待 SSH 认证解决后可按需恢复 | scheduler 实测 |
| 5 | "引入 Notion/Confluence/飞书多维表格" | **与知识库体系冲突**。knowledge/ 已有 index+log 双轨、git 版本控制、向量检索；外部工具割裂数据 | design-009/010 |

## 四、真实优化空间（基于事实）

### 4.1 C2 合规修复（唯一需执行的调度变更）

**问题**：知识库同步检查 `30 20 * * 0`（周日 20:30）不在允许窗口（21:00-08:00）。
**建议**：改为周日 `21:05`（避开 21:00 质检、21:15/21:30/21:40 专项报告的拥挤段）。
**操作**：scheduler delete 44c7fe82 → create（名字不变"知识库同步检查"，cron 改 `5 21 * * 0`）。
**风险**：换 ID，但任务名是稳定锚点（design-011 P1/P2），配置不失配。
**状态**：⚠️ 需用户确认后执行（涉及 delete+create）。

### 4.2 调研去重增强（P1，成本低）

现状：runner 内建"grep 历史 + 只记增量"去重（单任务内、同主题内）。
缺口：**跨主题交叉**（如互联/交换机/硬件组同日报道同一厂商新品）。
建议：verify 阶段增加"交叉主题提示"——把当日 01_survey 各模块产出的**标题关键词**合并检查，重复信号标注"已见于 X 模块"。
价值：避免 3 个模块各写一条重复动态，减少 token 与噪音。

### 4.3 竞品分析自动化（P2）

现状：server-competitor-analysis skill 存在，但为**人工触发**。
建议：增加每周竞品追踪任务（如周日 22:00，与 special-reports 错开），输出 `knowledge/02_rd/03_management/08_competitive-analysis/YYYY-MM-DD.md`。
前置：需在 research_topics.json 增加配置 + 确认输出目录 index/log。

### 4.4 任务成功率看板（P2）

现状：有进程保活（cow-alive-check）+ 合规检查，但**无任务执行成功率统计**。
建议：scheduler 已记录 `last_run_at`；可加脚本统计近 7 日"计划 vs 实际执行"（含失败/跳过），每周输出到周报。
价值：发现静默失败（如 web 源连续失效导致产出降级）。

### 4.5 不建议采纳项（明确拒绝）

| 外部建议 | 拒绝原因 |
|:---------|:---------|
| 改白天执行（08:00-20:00 灵活触发） | 违背 token 成本策略（高峰 +186%），破坏日报依赖链 |
| 引入 OpenBOM/API 自动化供应链 | 数据源未验证；现有调研已覆盖 BOM 成本 |
| 引入 Jenkins/GitLab CI | 对知识库过度工程化；git push 已自动化（--async） |
| 引入 Dify/LangChain 检索 | 与自建向量检索体系重复 |

## 六、结论

1. **体系设计合理**：夜间窗口（21:00-08:00）+ AI 自动执行 + token 预算约束，是**刻意的成本与可靠性设计**，外部报告"12 小时工作""缺夜间任务"等判断基于错误基准，不成立。
2. **外部反馈价值有限但有启发**：信息重复、竞品自动化、监控增强 3 点方向正确，已转化为 4.2/4.3/4.4 行动项。
3. **真实缺陷在文档同步**：任务数从 42 增长到 49（+16.7%），spec 快照滞后；check 脚本路径漂移；1 个任务超窗口。这些是"体系正常运行中的维护欠账"，已部分修复。
4. **需要用户决策**：C2 修复（20:30→21:05 迁移）涉及 scheduler delete+create，待确认后执行。

| 指标 | 数值 | 基线/条件 |
|:-----|:-----|:---------|
| 任务总数 | 49 个（enabled 48） | scheduler/tasks.json 2026-08-16 快照 |
| 每日执行任务 | 43 个 | cron 第 5 段 `*` |
| 单任务 token 预算 | ≤20K tokens | design-011 §4.7 |
| 时间窗口 | 21:00~08:00（11 小时） | design-011 §6 ALLOWED_HOURS |
| 高峰排布密度 | 每 10 分钟 1 档 | 01:00-07:00 每小时 5-6 任务 |
| 白天执行成本增量 | +186% | 8/17 峰谷新价（flash miss 输入 1→1.5/3.0 输出 2→4.5/9.0） |
| 外部报告任务数误读 | 5+ 项 vs 实际 43 项（低估 8.6×） | 对比基准见 §2.2 |
