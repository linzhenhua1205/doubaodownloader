## 摘要（TL;DR）

**核心命题**：上下文质量函数 **Q(L) 不是 L 的单调增函数**——它由「信息覆盖饱和」与「注意力稀释 + 错误累积」两股力量合成，呈现**先线性上升 → 平台 → 下降**的形态（倒 U 型/平台型）。超过饱和点后，增加上下文**同时降低质量与推高成本**，是最差的双输区。

**三个数学结论**（推导见正文）：

1. **成本二次爆炸**：会话总成本 C(n) = p·(nS + a·n²/2)——固定开销随轮次线性、历史累积随轮次**二次增长**。基线实证的「9.3% 长会话吃大头」正是二次项的实证。
2. **质量-上下文倒 U**：Q(L) = Q_max·cov(L/L_need)·dil(L)·e^(-n·ε̄)——信息不足时线性上升，全覆盖后进入平台，噪声稀释后下降；错误累积使质量对轮次 n **单调指数衰减**。
3. **压缩不是免费**：压缩比 r 必有信息失真 D(r)（率失真理论下界），被压信息一旦后续被需要，重读成本会**吃掉压缩收益**——「压缩-失忆循环」是数学必然而非工程意外。

**参数设置结论**：最优上下文预算 B* ≈ S + L_need·(1+δ)（δ≈10-20% 余量）；最优轮次 n* = (B-S)/a；超过 n* 必须**主动摘要（平台期摘要）而非阈值一刀切**；模型选择按「质量需求 λ vs 模型能力 Q_max」决策——大模型轮次少，小模型轮次多，存在成本交叉点。

## 一、问题重述：为什么「越大越详细」是直觉误区

直觉上「给模型更多上下文 = 更详细 = 更好」，但存在三个反作用力：

| 反作用力 | 机制 | 数学本质 |
|:---------|:-----|:---------|
| 注意力稀释 | softmax 归一化下，噪声 token 摊薄关键 token 的注意力权重 | dil(L) ∝ 1/(1+L·e^Δs) |
| 错误累积 | 每轮推理/工具操作引入错误 ε，历史中的错误信息反向误导后续决策 | P_correct ∝ e^(-n·ε̄) |
| 压缩-失忆循环 | 上下文超预算 → 强制压缩 → 丢失工具链/结论 → 重读重做 → 更多请求更大上下文（正反馈） | 见 §4 率失真 |

**第一性原理**：LLM API 是**无状态的**——每轮请求必须完整重发上下文；而模型对上下文的利用是**有损的**（注意力权重总和归一）。「发送成本」随长度线性增长，「利用效率」随长度衰减。两者交叉处即最优长度，超过即双输。

## 二、数学框架：Token 成本结构

### 2.1 会话成本模型

设会话共 n 轮（turns），记：

- S = system prompt tokens（每轮固定重发）
- a_i = 第 i 轮新增 tokens（用户消息 + AI 回复 + 工具回读）
- 均值近似 a = E[a_i]，则第 i 轮请求的上下文长度：

```math
L_i = S + \sum_{j<i} a_j \approx S + a \cdot i
```

会话总 input tokens：

```math
C_{in}(n) = \sum_{i=1}^{n} (S + a\cdot i) = nS + a \cdot \frac{n(n+1)}{2}
```

**结构拆解**：

```math
C_{in}(n) = \underbrace{nS}_{\text{linear: fixed overhead}} + \underbrace{\frac{a}{2}n^2}_{\text{quadratic: history}} + O(n)
```

**关键推论 C1（二次爆炸）**：轮次翻倍，固定开销翻倍，但历史累积项 **4 倍**。n=10→20，C 增 ~3 倍；n=20→40，C 增 ~3.7 倍。基线实证「>40 turns 会话单会话 5-20M tokens」= 二次项的实证（n=40, a≈2K → a·n²/2 = 1.6M + 固定项）。

### 2.2 成本函数（¥）

```math
C(n) = p_{miss}\cdot C_{in}(n) + p_{hit}\cdot h\cdot C_{in}(n) + p_{out}\cdot C_{out}
```

其中 h = 前缀缓存命中率，p_miss/p_hit/p_out 为单价（DeepSeek v4 Flash：未命中 ¥1.00/M、命中 ¥0.02/M、输出 ¥2.00/M——命中价差 50×）。

**关键推论 C2（固定开销的乘数效应）**：S 的每一 token 被重发 n 次，总成本贡献 n·S——**system prompt 是唯一"纯重复、零新增信息"的消耗项**，砍它收益最大（基线实证 84% 占比、118K→18K 省 85% 已验证）。

### 2.3 压缩触发条件

预算 B（max_context_tokens），当第 i 轮满足：

```math
L_i = S + a\cdot i > B \quad\Longrightarrow\quad i > n_{max} = \frac{B - S}{a}
```

即**超过 n_max 轮后每轮必触发压缩**。基线旧配置 B=50K、S=118K → B-S < 0 → **从第 1 轮起 available 即为负，每轮必压缩**——「优化前系统长期在预算边缘运行」的数学解释。

## 三、数学框架：质量-上下文模型（核心）

### 3.1 三因子分解

设任务所需信息量为 I_req（tokens），上下文 L 提供的信息覆盖：

```math
cov(L) = \min\left(1,\ \frac{L}{L_{need}}\right), \quad L_{need} = \frac{I_{req}}{\rho}
```

（ρ = 上下文信息密度；L_need = 任务所需最小上下文）

注意力稀释（Transformer softmax，关键 token 数 K，噪声均值相似度 s_n，关键相似度 s_k）：

```math
dil(L) = \frac{e^{s_k}}{e^{s_k} + L\cdot e^{s_n}} = \frac{1}{1 + L\cdot e^{\Delta s}}, \quad \Delta s = s_n - s_k < 0
```

错误累积（每轮错误概率 ε_i，均值 ε̄）：

```math
P_{corr}(n) = \prod_{i=1}^{n}(1-\varepsilon_i) \approx e^{-\bar{\varepsilon}\cdot n}
```

综合质量：

```math
Q(L,n) = Q_{max} \cdot \underbrace{\min\left(1,\frac{L}{L_{need}}\right)}_{cov} \cdot \underbrace{\frac{1}{1+L\cdot e^{\Delta s}}}_{dil} \cdot \underbrace{e^{-\bar{\varepsilon}\, n}}_{err}
```

### 3.2 曲线形态分析（三个区间）

| 区间 | 条件 | 主导项 | 质量行为 | 边际质量收益 |
|:-----|:-----|:-------|:---------|:------------|
| I 信息不足 | L < L_need | cov | 线性上升 | **正**（值得加） |
| II 平台期 | L_need ≤ L ≤ L_dil | 无主导 | 平台 | **≈0**（加了白加） |
| III 稀释区 | L > L_dil = 1/e^Δs | dil | 下降 | **负**（加了反降） |

**关键推论 Q1（倒 U/平台形态）**：质量对上下文不是单调的。L > L_dil 后，**增加上下文同时降低质量并推高成本**——这是「越大越详细越好」直觉的反例数学形式。

**关键推论 Q2（质量对轮次单调衰减）**：Q 对 n 有因子 e^(-n·ε̄) 恒衰减——**每多一轮，质量期望下降、成本二次上升**。最优策略 = 用最少的轮次完成既定任务（在模型单轮能力允许下）。

### 3.3 信息论视角（信噪比）

上下文 = 信号 + 噪声。任务相关信息量 I_req，总上下文 L，则：

```math
SNR = \frac{I_{req}}{L - I_{req}} \quad\Longrightarrow\quad L > 2I_{req} \Rightarrow SNR < 1
```

上下文超过所需信息 2 倍后，噪声已超过信号——模型从"检索关键信息"退化为"噪声中找信号"。**"详细"的价值由相关信息量决定，不由上下文体积决定**。

## 四、数学框架：压缩的率失真代价

### 4.1 率失真下界

压缩（把 H 压缩为 H' = r·H，r = 保留率）必伴随失真 D(r)。率失真理论：

```math
D_{min}(r) = \inf_{p(\hat{H}|H):\ E[\hat{H}]\leq rH} E[d(H,\hat{H})] > 0, \quad \forall r < 1
```

即**任何有损压缩都有非零失真下界**——"无损压缩不丢失信息"只对可逆编码成立，语义摘要本质是有损的。

实用模型：压缩后有效信息保留

```math
I_{keep} = r^{\alpha}\cdot I, \quad \alpha \in (0,1)
```

（α<1 表示语义摘要还有结构损耗：细节链接、工具链、中间结论丢失）

### 4.2 压缩的总成本

```math
C_{compress}^{total} = C_{compress} + p_{need}\cdot C_{redo}
```

其中 p_need = P(后续任务需要被压缩的信息)。基线样本「151→6 messages」r ≈ 0.04，I_keep ≈ 0.04^α·I（α=0.5 时仅保留 20%）——工具链被剥光后，后续任务需重新调查（重读）。

**关键推论 D1（压缩-失忆循环的数学必然）**：若 p_need·C_redo > C_saved，压缩是**净亏损**。基线「压缩 358 次 → 模型重读重做 → 更多请求 → 更大上下文 → 再压缩」正反馈，正是 p_need 高场景（长会话任务高度依赖前文结论链）下压缩亏损的实证。

### 4.3 压缩的质量损失

压缩后质量：Q' = Q_max·cov(L'_need)·…，其中 L'_need 因信息缺失上升 → 质量跌回 I 区间（信息不足）。**压缩 = 把会话质量状态从平台期打回爬升期**。

## 五、优化求解：最优预算 / 轮次 / 模型

### 5.1 最优上下文预算

目标：满足质量约束下最小化成本（或最大化质量-成本比）。

```math
\min_{B}\ C(B) \quad s.t.\quad Q(L) \geq Q_{req}
```

由 §3.2 曲线形态，最优 L 位于平台期起点：

```math
L^{*} = L_{need}\cdot(1+\delta), \quad \delta \in [0.1, 0.2]
```

（δ 为应对任务间波动的安全余量；超过 L_dil 毫无收益，低于 L_need 质量不足）

对应预算：

```math
B^{*} = S + L^{*} = S + L_{need}\cdot(1+\delta)
```

**注意**：B 不是越大越好——B 越大，system 之外的历史越容易膨胀到二次项；B 的职责是**设上限防失控**，质量的保证靠**控制 n 与 a**（轮次与每轮信息量），而非放大 B。

### 5.2 最优轮次

```math
n^{*} = \frac{B^{*} - S}{a} = \frac{L_{need}(1+\delta)}{a}
```

超过 n* 的会话，正确动作不是扩大 B，而是：
1. **主动摘要**（在平台期、信息尚未被压缩丢弃时，保留结论链）——turns ≥ n* 时触发；
2. **任务分流**（session 拆分：一个会话一个子任务，避免跨任务上下文污染）。

基线 P0 设置 turns 20→8 的合理性：a ≈ 2K-8K（含偶发工具回读），B=110K、S=18K → n* = (110-18)/2~8 = 11~46——turns=8 落在保守侧，安全。

### 5.3 模型选择决策

任务复杂度 λ（推理深度需求）→ 质量需求 Q_req(λ)。模型 m 的能力上限 Q_max(m)、单价 p_m。

**决策规则**：

```math
m^{*} = \arg\min_{m}\ C_m(n_m) \quad s.t.\quad Q_{max}(m) \geq Q_{req}(\lambda)
```

轮次关系（大模型单轮正确率高，试错少）：

```math
n_{big} < n_{small}, \quad \text{when } \lambda \text{ is high the gap widens}
```

**成本交叉点**：小模型单位成本低但轮次多（错误累积），大模型单位成本高但轮次少。交叉条件：

```math
p_{big}\cdot (n_{big}S + a n_{big}^2/2) < p_{small}\cdot (n_{small}S + a n_{small}^2/2)
```

λ 低（例行任务：日报/检查/归档）→ Q_req 低 → 小模型 + 少思考（基线 P2-1 的数学依据）；λ 高（深度分析/设计）→ 大模型，但**用少轮次 + 高单轮质量**，而非大模型 + 长上下文。

### 5.4 缓存与有效单价

```math
p_{eff} = h\cdot p_{hit} + (1-h)\cdot p_{miss}, \quad h = P(prefix unchanged)
```

system prompt 冻结期 → h↑。p_eff 从 ~¥1.00/M 可降至 ~¥0.32/M（h=70%）——**system 稳定性是 50× 价差的钥匙**（基线 P1-3）。

## 八、交付质量保障：外部验证替代上下文

低 token 预算下保证交付质量的核心机制：**把验证从"模型上下文内推理"外移到"确定性工具校验"**（约束脚本化）：

```math
Q_{deliver} = Q_{model} \cdot (1 - e^{-\mu\cdot V}) - e^{-\bar{\varepsilon}\,n} \approx Q_{model} \cdot (1 - e^{-\mu V})
```

- check_md_format / link-validator / 断言核对等**确定性校验不消耗模型推理 token**，却可把质量从"模型自证"提升为"机器证明"；
- 基线实证：检查类命令高频执行（check_md_format 182 次、link-validator 44 次）——**这些是质量的正杠杆**，应保留而非砍掉（区别在于输出截断：只回传 FAIL 行 + 计数）；
- 结论：**质量 ≠ 上下文大，质量 = 推理质量 × 外部验证**。

## 十、风险与边界

- **模型假设**：a（每轮新增）为均值近似，工具回读呈长尾（50K chars 单次）——轮次预算需按最坏情形留余量；
- **L_need 不可精确已知**：任务所需信息量是估计值，δ 余量即为此设；深度任务建议逐任务评估而非全局固定；
- **错误率 ε̄ 依赖模型与任务**：例行任务 ε̄ 低（Q2 衰减慢，可多轮），深度设计 ε̄ 高（必须少轮次高单轮质量）；
- **压缩并非全有害**：信息已归档到知识库（永久存储）后，会话内压缩=从工作区换到仓库，p_need 低时合理——**先归档后压缩**是压缩的正确姿势；
- **缓存冻结期的更新延迟**：紧急改动需绕过冻结例外（基线 P1-3 已注）。
