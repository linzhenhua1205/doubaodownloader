## 1️⃣ L5 层定位与工作全景

### 1.1 L5 在六层金字塔中的角色

```text
L6 -- 需求 -> 架构（已确定「做什么、选什么」）

L5 -- 架构 -> 集成 --- ★ 本层：把架构决策变成可综合的 RTL
      v 产出：SoC 顶层 RTL | 总线互联 | 地址映射表 | 中断表
      v 关键活动：IP 例化 · 互联生成 · 集成验证
      v 时间占比：~25% · 工作量最大的一层

L4 -- 集成 -> 实现（综合/时序）
L3 -- 实现 -> 验证
L2 -- 验证 -> 制造
L1 -- 制造 -> 测试
```

**核心洞察**：L5 是 **工作量最大** 的一层（25%），也是 **最容易引入 Bug** 的一层。大部分 SoC 的集成缺陷来自 L5 的接口错配、CDC 遗漏、地址冲突等「低级但致命」的错误。

### 1.2 L5 工作流全景

```text
+---------------------------------------------------------------------+
|                    L5 集成工作流                                        |
|                                                                     |
|  输入：L6 产出物                                                    |
|    +-- 架构框图 + IP 选型表 + 引脚定义 + 约束传递矩阵                  |
|                                                                     |
|  Phase 1: 集成准备（~10%）                                            |
|    +-- IP 交付物验收（RTL/验证环境/文档）                              |
|    +-- 集成环境搭建（版本管理/编译脚本/仿真环境）                       |
|    +-- IP 级快速验证（确认 IP 本身功能正常）                           |
|                                                                     |
|  Phase 2: 顶层集成（~40%）                                            |
|    +-- 顶层 RTL 编写（例化所有 IP + 互联）                            |
|    +-- 总线互联生成（AXI/AHB/APB）                                   |
|    +-- 地址映射实现（Decoder/Protection）                             |
|    +-- 中断路由实现（VIC 连接 + 中断分配）                            |
|    +-- 时钟/复位网络生成                                              |
|                                                                     |
|  Phase 3: 集成验证（~30%）                                            |
|    +-- 顶层编译通过检查                                                |
|    +-- 地址可达性验证（所有寄存器可正确访问）                           |
|    +-- 中断完整性验证（所有中断源可达 VIC->CPU）                       |
|    +-- CDC 静态检查（无 CDC 违规）                                   |
|    +-- 功耗意图交付（UPF/CPF）                                        |
|                                                                     |
|  Phase 4: 集成签核（~20%）                                            |
|    +-- 集成报告生成                                                    |
|    +-- 问题跟踪关闭                                                    |
|    +-- 交付至 L4 团队                                                  |
|                                                                     |
|  检查点 G5：集成签核 -> 通过后进入 L4（综合）                            |
+---------------------------------------------------------------------+
```

### 1.3 L5 核心原则

| 原则 | 说明 |
|:-----|:------|
| **接口契约化** | 每个 IP 的接口必须明确约定协议/时序/电气规范 |
| **可追溯性** | 每根顶层连线可追溯到架构文档中的定义 |
| **自动化优先** | 总线互联/地址解码/中断路由尽量自动化生成（减少手工 RTL） |
| **左移验证** | 集成验证尽早开始，不等待所有 IP 就绪 |
| **增量集成** | 按子系统分批集成，每批验证通过才加下一批 |

## 2️⃣ SoC 顶层 RTL 集成方法论

### 2.1 顶层 RTL 结构

```text
soc_top.v
+-- 模块声明与参数定义 (/defines)
+-- 引脚声明 (padring——芯片级 IO)
+-- 时钟/复位生成 (/clk_rst_gen)
|   +-- PLL 例化与配置
|   +-- 时钟门控 (CG) 例化
|   +-- 时钟分频器
|   +-- 复位同步器
+-- IP 例化层 (/ip_instances)
|   +-- CPU 子系统 (CPU + L2 Cache + SCU)
|   +-- 内存子系统 (DDR Ctrl + PHY)
|   +-- NPU/加速器子系统
|   +-- 外设子系统 (UART/I2C/SPI/GPIO)
|   +-- 安全子系统 (OTP/TRNG/AES/Hash)
|   +-- 系统控制 (VIC/WDT/Timer/DMA)
|   +-- 调试子系统 (JTAG/TRACE)
+-- 互联层 (/interconnect)
|   +-- AXI 交叉开关/NoC
|   +-- AHB 多层总线
|   +-- APB 桥配置总线
|   +-- 地址解码器 (Slave Select)
+-- 全局控制层 (/global_ctrl)
|   +-- 系统配置寄存器 (SCU/System Reg)
|   +-- 中断路由 (VIC 连接)
|   +-- 电源管理逻辑 (PMU)
+-- 安全逻辑层 (/security)
    +-- 防火墙配置
    +-- Secure Boot FSM
    +-- 密钥接口
```

### 2.2 集成顺序策略

推荐 **自底向上** 的增量集成策略：

```text
Step 1: 基础基础设施（~1 周）
  时钟/复位/PLL -> 仿真验证

Step 2: CPU 子系统 + 系统控制（~1 周）
  CPU + VIC + Timer/WDT + DMA -> 基本中断和定时工作

Step 3: 内存通路（~1 周）
  DDR Ctrl + PHY + AXI 互联 -> CPU 可访问内存

Step 4: 安全通路（~2 周）
  OTP + TRNG + AES + Secure Boot FSM -> BootROM 可加载

Step 5: 外设子系统（~2 周）
  各 APB 外设逐步加入 -> 每加一个验证一个

Step 6: 高性能加速器（~2 周）
  NPU/GPU/VPU 加 AXI Master -> 全系统数据通路

Step 7: 调试/DFT 集成（~1 周）
  JTAG + TRACE + Scan Mux -> 可调试
```

**为什么自底向上？**

1. 每个阶段都有「可工作的子系统」
2. 问题定位范围逐层收缩
3. 若顶层编译失败，回退范围明确

### 2.3 IP 例化模板规范

每个 IP 例化必须使用一致的结构：

```verilog
// ========================================================
// Module: uart0
// IP:    ns16550_uart (vendor: xxx, version: v2.1)
// Doc:   ip_repo/uart/ug_uart_v2.1.pdf
// Integrator: lzh, date: 2026-07-21
// ========================================================

ns16550_uart #(
    .FIFO_DEPTH   (16),
    .HAS_MODEM    (0)
) u_uart0 (
    // ---- 总线接口 (APB) ----
    .PCLK         (clk_apb      ),  // APB clock domain
    .PRESETN      (rst_apb_n    ),  // APB reset (active low)
    .PSEL         (apb_sel_uart0),  // Slave select (from decoder)
    .PADDR        (apb_addr     ),  // APB address [15:0]
    .PWRITE       (apb_write    ),  // APB write strobe
    .PWDATA       (apb_wdata    ),  // APB write data [31:0]
    .PENABLE      (apb_enable   ),
    .PREADY       (apb_ready_uart0),
    .PRDATA       (apb_rdata_uart0),

    // ---- 中断输出 ----
    .INTR         (irq_uart0    ),  // Interrupt to VIC (id: 5)

    // ---- 外部引脚 ----
    .SIN          (pad_uart0_rxd),
    .SOUT         (pad_uart0_txd)
);
```

**例化规范**：

1. 每个 IP 添加头部注释模块名/供应商/版本/文档路径/集成者/日期
2. 接口分组（总线/中断/引脚/时钟/复位）注释清晰
3. 信号名遵循统一的命名约定
4. 未连接的端口显式标注（`// NC` 或注释说明）

## 3️⃣ 总线互联设计深化

### 3.1 总线互联决策矩阵

L6 确定了总线拓扑类型。L5 需要决定具体的互联参数：

| 参数 | 权衡维度 | 选择原则 |
|:-----|:---------|:---------|
| **数据宽度** | 带宽 vs 面积 | Master 最大宽度 + 关键 slave 适配 |
| **时钟频率** | 性能 vs 功耗 | 匹配最快的 Master |
| **地址宽度** | 寻址空间 vs 译码复杂度 | 覆盖所有 IP 地址空间 + 余量 |
| **Outstanding 深度** | 并发 vs 缓存开销 | 主要 Master 的 pipeline 能力 |
| **仲裁策略** | 公平 vs 优先级 | 关键 Master（CPU/NPU）高优先级 |
| **保护支持** | 安全性 vs 实现复杂度 | 有安全需求时启用 |
| **缓存属性** | 一致性 vs 简单 | 多主共享数据时需一致性 |

### 3.2 AXI 交叉开关配置方法

```verilog
// AXI 交叉开关配置示例（4 Master × 6 Slave）

axi_crossbar #(
    .NUM_SLAVE_PORTS    (4),         // Master 数量（从交叉开关角度看是 Slave 端口）
    .NUM_MASTER_PORTS   (6),         // Slave 数量（Master 端口）
    .DATA_WIDTH         (128),
    .ADDR_WIDTH         (32),
    .ID_WIDTH           (4),         // 支持 16 个 outstanding 事务
    .SLAVE_ADDR_MAP     ({           // 地址映射：每 Slave 的基地址+掩码
        32'h1000_0000, 32'h000F_FFFF,   // S0: DDR Ctrl (16MB)
        32'h2000_0000, 32'h0000_FFFF,   // S1: SRAM (64KB)
        32'h4000_0000, 32'h00FF_FFFF,   // S2: NPU (16MB)
        32'hA000_0000, 32'h000F_FFFF,   // S3: PCIe Ctrl (1MB)
        32'hB000_0000, 32'h03FF_FFFF,   // S4: Display Ctrl (64MB)
        32'hC000_0000, 32'h0000_03FF    // S5: APB 桥 (1KB)
    }),
    .CONNECTIVITY       (16'b1111_1111_1111_1111)  // 全连接
) u_axi_crossbar (
    .ACLK               (clk_axi),
    .ARESETN            (rst_axi_n),

    // Slave 端口（连接 CPU/NPU/DMA/GPU）
    .S_AXI              ({s_axi_gpu, s_axi_npu, s_axi_dma, s_axi_cpu}),

    // Master 端口（连接 DDR/SRAM/NPU/PCIe/Display/APB）
    .M_AXI              ({m_axi_apb, m_axi_disp, m_axi_pcie,
                          m_axi_npu, m_axi_sram, m_axi_ddr})
);
```

**交叉开关配置检查点**：

- [ ] SLAVE_ADDR_MAP 的地址范围无重叠？
- [ ] 各 Master 的 ID 宽度足够支持并发事务数？
- [ ] CONNECTIVITY 矩阵确认所有通路正确？
- [ ] 每个 Master 的带宽需求与交叉开关总带宽匹配？

### 3.3 AHB→APB 桥接设计

低速外设（UART/I2C/SPI/GPIO）通过 APB 总线连接。桥接设计关键：

```verilog
// AHB-to-APB Bridge（单 Master、多 Slave）
// APB slave 通过地址高位选择

apb_bridge #(
    .NUM_SLAVES     (12),
    .ADDR_MAP       ({                       // 基地址  → Slave
        32'hC000_0000,   // S0: UART0
        32'hC000_1000,   // S1: UART1
        32'hC000_2000,   // S2: I2C0
        32'hC000_3000,   // S3: I2C1
        32'hC000_4000,   // S4: SPI0
        32'hC000_5000,   // S5: SPI1
        32'hC000_6000,   // S6: GPIO
        32'hC000_7000,   // S7: Timer
        32'hC000_8000,   // S8: WDT
        32'hC000_9000,   // S9: RTC
        32'hC000_A000,   // S10: PWM
        32'hC000_B000    // S11: ADC Ctrl
    })
) u_apb_bridge (
    .HCLK           (clk_ahb),
    .HRESETN        (rst_ahb_n),
    .HSEL           (hsel_apb),
    .HADDR          (haddr),
    .HWDATA         (hwdata),
    .HRDATA         (hrdata_apb),
    .HWRITE         (hwrite),
    .HTRANS         (htrans),
    .HREADY         (hready_apb),
    .HREADY_OUT     (hready_out_apb),
    .PADDR          (paddr[15:0]),
    .PWRITE         (pwrite),
    .PENABLE        (penable),
    .PSEL           (psel[11:0]),
    .PWDATA         (pwdata),
    .PRDATA         (prdata[11:0]),
    .PREADY         (pready[11:0]),
    .PSLVERR        (pslverr[11:0])
);
```

**桥接设计规则**：

1. APB 外设每个占用 4KB 地址空间（标准）
2. 地址对齐到 4KB 边界（A[31:12] = 基地址, A[11:0] = 寄存器偏移）
3. APB 桥支持 1-cycle 等待（无需在 APB 侧插入额外 wait）
4. 未使用的 APB slave 地址范围返回 error（PSLVERR）

### 3.4 总线互联的带宽规划验证

在集成阶段必须做互联带宽的定量验证：

| 主设备 | 峰值带宽 | 典型带宽 | 突发特性 | 延迟敏感度 |
|:-------|:--------:|:--------:|:---------|:----------:|
| CPU（读/写） | 6.4GB/s | 2.0GB/s | 随机（缓存行） | 中 |
| NPU（读模型） | 4.0GB/s | 3.0GB/s | 大块顺序 | 高 |
| NPU（写中间结果）| 4.0GB/s | 2.5GB/s | 大块顺序 | 高 |
| Display Ctrl（读）| 2.0GB/s | 1.5GB/s | 固定行刷新 | 极高 |
| DMA（块传输） | 3.2GB/s | 1.0GB/s | 块状 | 低 |
| **总需求** | **19.6GB/s** | **10.0GB/s** | — | — |

**带宽充足性检查**：

```text
Interconnect 总带宽 = Width × Freq × Efficiency
  示例：AXI 128bit @ 400MHz × 0.7（效率因子） = 11.2GB/s

验证结论：
  - 峰值总需求（19.6GB/s）> 可用带宽（11.2GB/s）-> 峰值冲突不可避免
  - 典型需求（10.0GB/s）< 带宽（11.2GB/s）-> 典型场景充足
  - 瓶颈缓解：
    ① NPU 使用独立 DDR channel（不通过交叉开关）
    ② Display 使用独立显示 SRAM（不竞争 DDR）
    ③ CPU 缓存命中时减少 DDR 访问
```

## 4️⃣ 地址映射与空间规划

### 4.1 地址空间划分规范

| 地址范围 | 大小 | 分配 | 属性 | 总线域 |
|:---------|:----:|:-----|:-----|:-------|
| 0x0000_0000 - 0x0000_FFFF | 64KB | Boot ROM | 只读（安全） | AXI |

### 4.2 地址解码器设计

```text
地址解码器逻辑：从总线的地址信号推断目标 Slave

if (addr >= 32'h0000_0000 && addr < 32'h0001_0000)
    slave_sel = BOOT_ROM;         // 0x00000 - 0x0FFFF
else if (addr >= 32'h0001_0000 && addr < 32'h0002_0000)
    slave_sel = INTERNAL_SRAM;    // 0x10000 - 0x1FFFF
else if (addr >= 32'h1000_0000 && addr < 32'h2000_0000)
    slave_sel = DDR_CH0;          // 0x10000000 - 0x1FFFFFFF
...
else
    slave_sel = DECODE_ERROR;     // 未映射地址 -> 返回错误
```

**地址解码器设计规则**：

1. 未映射地址必须返回 slave error（PSLVERR/HRESP=ERROR）
2. 地址空间重叠检测：自动化脚本检查所有地址窗口无重叠
3. 地址范围边界对齐到最小粒度（通常 4KB）
4. 保留地址空间用于未来扩展

## 6️⃣ 多时钟域集成方法

### 6.1 时钟域划分原则

**时钟域划分检查表**：

| IP | 时钟源 | 频率 | 时钟域 | 与其它域交互？ | CDC 处理 |
|:---|:-------|:----:|:------:|:--------------:|:---------|
| CPU Core | PLL0_OUT | 800MHz | CLK_CPU | L2 Cache | — |
| L2 Cache | PLL0_OUT | 800MHz | CLK_CPU | DDR Ctrl(异步) | 异步 FIFO |
| DDR Ctrl | PLL1_OUT | 400MHz | CLK_DDR | AXI(异步) | 异步桥 |
| AXI 互联 | PLL1_OUT | 400MHz | CLK_BUS | NPU(同频)/APB | — |
| NPU | PLL1_OUT | 400MHz | CLK_BUS | DDR Ctrl(同总线) | — |
| APB 桥 | PLL2_OUT | 100MHz | CLK_PER | AXI(异步) | 同步器 |
| UART | PLL2_OUT | 100MHz | CLK_PER | — | — |
| I2C | PLL2_OUT | 100MHz | CLK_PER | — | — |
| WDT | RC32K | 32KHz | CLK_WDT | System Bus(异步) | 双级同步器 |

### 6.2 CDC 设计规则

**六条不可违反的 CDC 规则**：

| 规则 | 说明 | 违反后果 |
|:-----|:------|:---------|
| **R1: 单 bit 控制信号必须双级同步** | 双级 FF 同步（无逻辑介入） | 亚稳态传播 |
| **R2: 多 bit 数据必须用异步 FIFO** | 不允许多 bit 直接跨越 | 数据采样不一致 |
| **R3: 使能信号必须与时钟同步** | 使能不能来自不同时钟域的脉冲 | 丢失/重复触发 |
| **R4: 握手协议需要确认回路** | REQ→跨域→ACK→跨域返回 | 协议违规 |
| **R5: 复位必须跨域同步** | 异步复位同步释放 | 复位撤销时序违规 |
| **R6: 静态检查所有 CDC 路径** | 工具检查 + 人工复核 | CDC 遗漏 |

### 6.3 异步 FIFO 设计要点

```text
异步 FIFO 深度计算：

FIFO_Depth ≥ (Write_Rate / Read_Rate) × Burst_Size × Safety_Factor

示例：
  写侧：AXI @ 400MHz, 128bit, 可连续写 16 拍
  读侧：DDR Ctrl @ 400MHz, 128bit
  -> Write_Rate / Read_Rate ≈ 1（同频）
  -> Burst_Size = 16
  -> FIFO_Depth ≥ 16 × 1.5（安全因子）= 24 -> 选 32

异步 FIFO 检查清单：
  □ 使用格雷码指针（Gray code pointer）
  □ 空/满标志生成正确
  □ 读写指针跨域后同步正确
  □ 仿真验证 full/empty 在边界正确行为
```

### 6.4 时钟门控集成

```text
时钟门控单元选型：

  ICG（Integrated Clock Gate）单元：
    +-- 标准 ICG（Latch + AND）：最常用，集成在库中
    +-- ICG 使能同步：使能信号在时钟域内同步后输入 ICG
    +-- ICG 输出延迟控制：CLK_GATED 比 CLK 多一个 latch 延迟

  ICG 使能生成规范：
    always @(posedge clk) begin
      if (rst_n == 0)
        clk_en <= 0;
      else if (ip_idle_condition)
        clk_en <= 0;   // IP 空闲 -> 关时钟
      else if (ip_active_condition)
        clk_en <= 1;   // IP 需要工作 -> 开时钟
    end

验证要求：
  □ 空闲时所有可门控 IP 的时钟被关闭
  □ 唤醒时时钟开启延迟不超过 1 个时钟周期
  □ DFT 模式下时钟强制开启（scan_enable）
```

### 7.3 复位同步器设计

```verilog
// 异步复位同步释放（每个时钟域必须使用）
module rst_sync (
    input  wire clk,
    input  wire rst_async_n,    // 异步复位（低有效）
    output wire rst_sync_n      // 同步后复位
);

reg [2:0] rst_meta;

always @(posedge clk or negedge rst_async_n) begin
    if (!rst_async_n) begin
        rst_meta <= 3'b0;
    end else begin
        rst_meta <= {rst_meta[1:0], 1'b1};
    end
end

assign rst_sync_n = rst_meta[2];

endmodule
```

**复位同步规则**：

1. 每个时钟域独立做异步复位同步释放
2. 复位撤销时必须同步到时钟域内才释放
3. 复位有效时不需要同步（异步复位立即生效）
4. 多个复位源用 AND 组合后送入 rst_sync

## 1️⃣2️⃣ 常见集成失败模式与案例

### 12.1 失败模式汇总

| # | 模式 | 症状 | 根因 | L5 阶段发现？ | 修复成本 |
|:-:|:-----|:-----|:-----|:-------------:|:--------:|
| I1 | **地址冲突** | 写 A 外设却修改了 B 的寄存器 | 两个外设地址范围重叠 | 集成仿真 | 低（改地址映射） |
| I2 | **中断丢失** | 外设触发中断但 CPU 无响应 | 中断线未连接到 VIC | 集成验证 | 低（改顶层连线） |
| I3 | **CDC 违规** | 跨时钟域数据随机损坏 | 多 bit 信号未用异步 FIFO | CDC 检查 | 中（加同步器） |
| I4 | **时钟门控错误** | IP 时钟门控后无法唤醒 | 唤醒逻辑在门控时钟域内 | 功耗仿真 | 中（改 RTL） |
| I5 | **复位依赖错误** | 子系统复位后其他 IP 挂死 | 复位顺序依赖未满足 | 复位序列仿真 | 高（加复位同步） |
| I6 | **总线死锁** | 多 Master 并发访问时系统挂死 | 仲裁器/回环路径 | 随机仿真 | 高（改互联架构） |

### 12.2 典型案例：CDC 违规导致数据损坏

```text
情景：NPU 通过 AXI 写 DDR，跨时钟域路径存在 CDC 违规

细节：
  NPU 在 CLK_NPU（300MHz）域内生成写地址和数据
  AXI 互联在 CLK_BUS（400MHz）域内工作
  两个域之间有异步桥但不包含全部 AXI 通道信号

违规路径：
  NPU -> AXI 写地址（多 bit）-> 未经过异步 FIFO -> 直接到 DDR Ctrl

结果：
  约 1/10^5 概率写地址采样错误 -> 写到错误的 DDR 地址
  NPU 推理结果经常错误 -> 定位花费 2 周

修正：
  在 NPU 输出侧补 AXI 异步桥 -> 避免所有多 bit 信号直接跨域
```

### 12.3 典型案例：地址冲突

```text
情景：UART0 和 I2C0 配置了相同基地址

地址映射表：
  UART0: 0xC000_0000 - 0xC000_0FFF
  I2C0:  0xC000_0000 - 0xC000_0FFF  <- 与 UART0 冲突

发现方式：
  自动化地址检查脚本 -> 报告重叠
  修改：I2C0 基地址改为 0xC000_2000

教训：
  地址映射必须通过自动化脚本检查重叠
  人工检查不可靠（地址数量多时极易遗漏）
```

## 1️⃣3️⃣ L5 集成检查清单

### 13.1 集成准备

- [ ] 所有 IP 的 RTL/验证环境/文档已验收？
- [ ] 集成环境搭建完成（版本管理/编译脚本/仿真环境）？
- [ ] IP 级快速验证全部通过？
- [ ] 集成计划确定（按子系统分几批增量集成）？

### 13.2 顶层 RTL

- [ ] 顶层 RTL 结构清晰（时钟/复位/IP/互联/全局控制分层）？
- [ ] 每个 IP 例化有头部注释（供应商/版本/文档/集成者）？
- [ ] 未连接端口已标注说明？
- [ ] 参数化配置正确（所有参数与 IP 选型一致）？

### 13.3 总线互联

- [ ] 总线拓扑与架构文档一致？
- [ ] 地址映射表已确认无冲突？
- [ ] 仲裁策略已确定（公平/优先级/带宽保证）？
- [ ] 未映射地址返回错误（非悬空）？
- [ ] 带宽规划已做验证（典型场景不饱和）？

### 13.4 中断系统

- [ ] 中断映射表完成（中断号→中断源→优先级→CPU）？
- [ ] 所有中断源物理连接到 VIC？
- [ ] 中断优先级分配合理？
- [ ] NMI 中断源已确认（WDT/安全报警/致命错误）？

### 13.5 时钟/复位

- [ ] 时钟域划分表完成？
- [ ] 所有跨时钟域路径有 CDC 处理？

- [ ] 每个时钟域都有复位同步器？
- [ ] 时钟门控使能设计正确（不在门控后域内产生使能）？

### 13.6 电源

- [ ] UPF 文件完成并通过编译？
- [ ] 电源域划分与架构文档一致？
- [ ] 隔离/保持/上电时序已定义？

### 13.7 安全

- [ ] 安全/非安全总线物理分离？
- [ ] 防火墙配置仅安全模式下可写？
- [ ] Secure Boot FSM 在 RTL 中实现？

### 13.8 签核

- [ ] 顶层编译零错误零警告？
- [ ] 集成 smoke test 全部通过？
- [ ] Lint 检查 clean？
