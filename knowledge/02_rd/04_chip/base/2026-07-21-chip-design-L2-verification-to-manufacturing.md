## 1️⃣ L2 层定位与工作全景

### 1.1 L2 在六层金字塔中的角色

```text
L6 -- 需求 -> 架构
L5 -- 架构 -> 集成
L4 -- 集成 -> 实现
L3 -- 实现 -> 验证

L2 -- 验证 -> 制造 --- ★ 本层：送厂制造前的最终检查
      v 产出：GDSII | DRC/LVS 报告 | Mask 数据
      v 关键活动：物理验证 · DFM 检查 · Tape-out 签核
      v 时间占比：~10% · 决定芯片能否被制造的关键层

L1 -- 制造 -> 测试
```

**核心洞察**：L2 是 **出错成本最高** 的一层。一旦 Tape-out 后才发现问题，修复周期为 3-6 个月，费用 $50万-$200万。L2 的核心目标是在 Tape-out 前消除所有「可被制造厂拒绝」的问题。

### 1.2 L2 工作流全景

```text
+---------------------------------------------------------------------+
|                    L2 物理验证至 Tape-out 工作流                      |
|                                                                     |
|  +----------+   +----------+   +----------+   +----------+         |
|  |物理验证   |->  |DFM 优化   |->  |Tape-out   |->  |Mask 制造  |        |
|  |          |   |          |   |签核       |   |          |         |
|  | . DRC    |   | . CMP    |   | . 签核对  |   | . Mask   |         |
|  | . LVS    |   | . OPC    |   |   照表   |   |   layout |         |
|  | . ERC    |   | . AA     |   | . 数据    |   | . Mask   |         |
|  | . ANT    |   | . 冗余   |   |   格式   |   |   inspection|       |
|  |          |   | . 热点   |   | . 交付    |   | . Mask   |         |
|  +----------+   +----------+   +----------+   |   cleanup|         |
|                                                +----------+         |
|  检查点 G2：Tape-out 签核 -> GDSII 交付至晶圆厂                       |
+---------------------------------------------------------------------+
```

## 2️⃣ 物理验证体系

### 2.1 物理验证四维检查

| 检查类型 | 全称 | 检查内容 | 违反后果 |
|:---------|:-----|:---------|:---------|
| **DRC** | Design Rule Check | 最小线宽/间距/面积/密度等物理规则 | 晶圆厂无法制造 |
| **LVS** | Layout vs Schematic | 版图与电路网表一致 | 功能不正确 |
| **ERC** | Electrical Rule Check | 电源网络/地/浮空节点 | 芯片无法正常工作 |
| **ANT** | Antenna Rule Check | 天线效应 | 栅氧损坏 |

### 2.2 DRC（设计规则检查）

#### 2.2.1 DRC 规则分类

| 规则类别 | 典型规则（28nm LP） | 检查对象 | 违反后果 |
|:---------|:--------------------|:---------|:---------|
| **最小线宽** | Poly: 40nm, Metal1: 50nm | 所有层 | 开路或桥接 |
| **最小间距** | Poly-Poly: 50nm, Metal-Metal: 60nm | 同层图形 | 短路 |
| **最小面积** | Contact: 0.04µm², Via: 0.05µm² | 孔/接触 | 连接不良 |
| **包边** | Gate over Active: 各侧≥20nm | 栅极 | 漏电增加 |
| **密度** | 每 100µm² 密度 20-80% | 所有层 | CMP 平坦化问题 |
| **宽度依赖间距** | Width >10µm 时间距加倍 | 宽金属线 | 应力开裂 |
| **孔阵列** | 相邻 Via 间距≥0.26µm | Via 阵列 | 短路风险 |
| **阱连接** | NW 每 10µm 接 VDD | N-well | 闩锁效应 |

#### 2.2.2 DRC 检查流程

```text
+---------------------------------------------------------------------+
|                    DRC 签核流程                                        |
|                                                                     |
|  输入：GDSII + 晶圆厂 DRC deck                                      |
|                                                                     |
|  Step 1: DRC 规则加载                                                |
|    +-- 晶圆厂提供最新版 DRC runset                                   |
|    +-- 确认版本号与工艺基线一致                                       |
|                                                                     |
|  Step 2: 全芯片 DRC 运行                                             |
|    +-- 时间：数小时 ~ 数天（取决于芯片规模）                           |
|    +-- 内存：每百万门 ~ 2-4 GB                                      |
|    +-- 输出：DRC 结果数据库                                           |
|                                                                     |
|  Step 3: DRC 结果分类                                                |
|    +-- True Violation: 真正违规 -> 必须修复                           |
|    +-- Waived: 已评估免责的违规（需记录）                              |
|    +-- False: 虚假违规 -> 检查 runset 版本                             |
|                                                                     |
|  Step 4: DRC 修复闭环                                                |
|    +-- True Violation -> 修改版图 -> 局部 DRC -> 全芯片 DRC            |
|    +-- 修复周期：通常需要 3-5 轮                                     |
|                                                                     |
|  输出：DRC 零违规签核报告                                              |
+---------------------------------------------------------------------+
```

#### 2.2.3 DRC 签核条件

| 条件 | 合格标准 | 不合格处理 |
|:-----|:---------|:-----------|
| 全芯片 DRC 零违规 | 0 True Violation | 不可 Tape-out |
| DRC Waiver 清单 | 已评审 + 晶圆厂确认 | 未确认不可 Tape-out |
| DRC runset 版本 | 与晶圆厂推荐版本一致 | 不一致必须更新 |
| DRC 覆盖率 | 全芯片无 blind spot | 补充 DRC rule |

### 2.3 LVS（版图与电路一致性检查）

#### 2.3.1 LVS 检查项

| 检查项 | 说明 | 通过标准 |
|:-------|:-----|:---------|
| **器件一致性** | 版图中的器件类型/尺寸/参数与网表一致 | 100% 匹配 |
| **连接一致性** | 版图中的所有节点连接与网表一致 | 无开路/无短路 |
| **器件数量** | 版图器件总数 = 网表器件总数 | 完全一致 |
| **电源/地连接** | VDD/VSS 正确连接 | 无浮空电源节点 |
| **未连接端口** | 所有端口在版图中物理连接 | 零未连接 |

#### 2.3.2 LVS 结果解读

```text
LVS 报告示例：

  +----------------------------------------------+
  |  LVS Report Summary                           |
  |  ---------------------------                  |
  |  Layout Cells : 1                              |
  |  Source Cells : 1                              |
  |  Layout Devices: 245,678                      |
  |  Source Devices: 245,678                      |
  |  Layout Nets   : 98,432                      |
  |  Source Nets   : 98,432                      |
  |  ---------------------------                  |
  |  ⚠ LVS NOT MATCHED                            |
  |  ---------------------------                  |
  |  Net mismatch count: 2                        |
  |    - Net N45236: layout=open, source=connected|
  |    - Net N78901: layout=short, source=separate|
  |  Device mismatch count: 7                     |
  |    - 5 devices: W/L mismatch                  |
  |    - 2 devices: type mismatch                 |
  +----------------------------------------------+

  LVS 不匹配的排查步骤：
  1. 确认 DRC 通过（很多 LVS 问题由 DRC 违规引起）
  2. 分析 Net Mismatch -> 开路/短路的物理位置
  3. 分析 Device Mismatch -> 尺寸/类型的偏差
  4. 修复版图 -> 局部 LVS -> 全芯片 LVS
```

### 2.4 ERC（电气规则检查）

| 规则 | 检查内容 | 通过标准 |
|:-----|:---------|:---------|
| **浮空节点** | 所有输入引脚有驱动 | 零浮空 |
| **电源短路** | VDD 与 VSS 之间无低阻路径 | 零短路 |
| **浮空阱/衬底** | 所有阱/Body 正确偏置 | 零浮空 |
| **跨电源域连接** | 不同 VDD 的信号有隔离 | 按设计意图 |
| **三态总线** | 无多驱动/无驱动 | 无冲突 |

## 3️⃣ 可制造性设计（DFM）

### 3.1 DFM 关注的核心问题

| 制造问题 | 表现 | DFM 方法 | 良率改善 |
|:---------|:-----|:---------|:--------:|
| **CMP 平坦度** | 金属密度不均导致凹陷/凸起 | 密度平衡（25-75%） | 3-5% |
| **OPC 误差** | 光刻边缘圆角/缩短 | 避免锐角/长条形 | 2-5% |
| **天线效应** | 栅氧击穿 | 跳层/加保护二极管 | 0.5-2% |
| **热点** | 光刻分辨率不足的区域 | 识别+修改版图 | 5-10% |
| **通孔阻变** | Via 开路/高阻 | 冗余通孔 | 2-5% |
| **应力** | 封装应力导致开裂 | 避免大块金属 | 1-3% |

### 3.2 密度平衡规则

```text
CMP 密度规则（28nm LP）：
  +-----------------------------------------------------------------+
  |  密度窗口：滑动窗口 100µm × 100µm                               |
  |                                                                 |
  |  Layer     Min_Density   Max_Density    Target                  |
  |  -------  ------------  ------------    ----------              |
  |  STI      15%           70%             35-50%                  |
  |  Poly     20%           70%             35-50%                  |
  |  Metal1   25%           75%             40-60%                  |
  |  Metal2   25%           75%             40-60%                  |
  |  Metal3+  20%           70%             35-55%                  |
  |  TopMetal 15%           80%             40-60%                  |
  |                                                                 |
  |  密度修正方法：                                                    |
  |  - 密度过低 -> 插入 dummy fill（浮空金属块）                         |
  |  - 密度过高 -> 切槽（slotting）或分散图形                           |
  +-----------------------------------------------------------------+
```

### 3.3 冗余通孔（Redundant Via）

```text
通孔是良率损失的首要来源：

单孔规则（不可接受）：
  □ Via 阵列中仅放单一通孔 -> 一个孔失效 = 开路
  □ 建议：每个连接至少 2 个通孔

冗余通孔插入规则：
  □ Single Via -> 空间允许时插双孔
  □ Double Via -> 空间足够时插三孔
  □ 孔间距 ≥ 最小间距 × 1.2

良率影响：
  □ 单孔 -> 通孔良率 99.5% -> 连接良率 99.5%
  □ 双孔 -> 通孔良率 99.5% -> 连接良率 99.9975%
  □ 三孔 -> 通孔良率 99.5% -> 连接良率 99.9999%
```

### 3.4 OPC 与热点修复

```text
光学临近效应校正（OPC）：
  制造厂在 Mask 上做 OPC
  设计团队：识别并修复「热点」（Hotspot）

典型热点类型：
  1. 端对端间隔过小（Line End Gap）
  2. 窄线与宽线相邻（Density Transition）
  3. 长平行走线（Parallel Run Length）
  4. 尖锐转角（Sharp Corner）

热点修复方法：
  +-----------------------------------------------------------------+
  |  原始     |  修复后     |  方法                               |
  |  --------+------------+-------------------------------------- |
  |  -+       |  -+ +--    |  端端间距 < spec -> 加钩子/锤头       |
  |   |       |   | |      |                                      |
  |  -+       |  -+ +--    |                                      |
  |           |            |                                      |
  |  #### ##  |  ########  |  密度突变 -> 加渐变过渡线             |
  |           |            |                                      |
  |  -------  |  ---+---   |  长平行走线 > 100µm -> 插入跳层       |
  |  -------  |  ---+---   |                                      |
  +-----------------------------------------------------------------+
```

## 4️⃣ Tape-out 流程与检查清单

```text
+---------------------------------------------------------------------+

|    +-- ERC 零违规                                                     |
|    +-- ANT 零违规                                                     |
|    +-- DFM 检查通过（晶圆厂 checklist）                               |

|    +-- 所有签署人完成签字                                              |

|    +-- OPC 执行                                                       |
```

## 5️⃣ Mask 数据准备

### 5.1 Mask 数据流

```text
GDSII（设计数据）
  |
  +-- MDP（Mask Data Preparation）
       +-- 数据格式转换（GDSII -> MEBES）
       +-- OPC（光学临近效应校正）
       +-- MRC（Mask Rule Check）
       +-- Fracture（图形切分 -> 曝光场）
       +-- Job Deck（MDP 发布文件）
              |
              +-- Mask 写入
                   +-- EB（电子束直写）
                   +-- Laser（激光写入，低精度层用）

Mask 层数（以 28nm LP 为例）：
  +-- 逻辑层：~45 层 (含 M1-M10 + Poly + Active + ...)
  +-- 光刻层：~35 层
  +-- 非光刻层：~10 层 (Dummy/Well/etc.)
```

## 6️⃣ 良率预估与优化

### 6.1 良率模型

```text
Die 良率 = f(工艺成熟度, 芯片面积, 缺陷密度, 冗余设计)

泊松模型（最常用）：
  Y = e^(-D0 × A)
  其中：D0 = 缺陷密度，A = 芯片面积

更精确的 Murphy 模型：
  Y = [(1 - e^(-D0 × A)) / (D0 × A)]²

示例（28nm, D0=0.1/cm²）：
  A=10mm² -> Y = e^(-0.1×0.1) = 99.0%  ✓
  A=50mm² -> Y = e^(-0.1×0.5) = 95.1%  ✓
  A=200mm²-> Y = e^(-0.1×2.0) = 81.9%  ⚠
  A=600mm²-> Y = e^(-0.1×6.0) = 54.9%  ✗
```

### 6.2 良率驱动设计方法

| 设计选择 | 对良率的影响 |
|:---------|:-------------|
| **Die 面积控制** | 面积减半 → 良率提升约 40% |
| **冗余通孔** | 通孔相关失效减少 90%+ |
| **ECC 纠错码** | 内存单元位出错可纠正 |
| **容错设计** | 少量失效不影响功能 |
| **边缘裕度** | 工艺偏差容忍度增加 |
| **散热平衡** | 热斑减少 → 漏电/时序一致 |

### 6.3 良率提升措施优先级

```text
良率提升 ROI 排序：

   1. 通孔冗余 + 密度平衡（低成本高回报）
   2. ECC 覆盖所有 SRAM（中等成本高回报）
   3. 热点修复（中等成本高回报）
   4. 关键路径时序裕度增加（增加功耗）
   5. Die 面积缩减（需改 RTL/架构）
   6. 容错/冗余设计（大改架构）
```

## 7️⃣ 常见制造阶段失败模式

| # | 模式 | 症状 | 根因 | 发现阶段 | 修复成本 |
|:-:|:-----|:-----|:-----|:--------:|:---------|
| M1 | **DRC 违规遗漏** | 晶圆厂拒绝流片 | DRC runset 版本过旧 | Tape-out 前 1 周 | 高（延期）|
| M2 | **LVS 不匹配** | 版图有额外器件 | 手工 ECO 未更新 LVS | Tape-out 前 | 中 |
| M3 | **密度违规** | CMP 导致金属凹陷 | 未做密度检查 | Mask 制造 | 非常高 |
| M4 | **热点未修复** | 光刻良率低于预期 | 热点识别遗漏 | 量产阶段 | 极高 |
| M5 | **Mask 数据错误** | Mask 图形断裂 | MDP fracture 错误 | Mask 制造 | 极高 |
| M6 | **温差导致时序违规** | 高温测试时频 fail | 未在温度 corner 验证 | 量产测试 | 高（降频）|
