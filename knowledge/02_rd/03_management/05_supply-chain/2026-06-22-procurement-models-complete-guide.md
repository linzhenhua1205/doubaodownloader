## 1. 采购的基本概念与分类框架

### 1.1 什么是采购

采购（Procurement）是指**组织为获取所需的商品或服务，而进行的需求识别、供应商选择、合同签订、订单下达、验收付款的全过程管理活动**。

采购不等于「买东西」——它涵盖了从战略层（供应商策略、品类策略）到执行层（下单、跟单、收货）的完整链条。

### 1.2 采购的分类维度

采购模式可以从以下五个维度进行分类，每个维度回答一个核心问题：

```text
维度一：买什么？          -> 按采购对象分类（物料/设备/服务/软件）
维度二：怎么买？          -> 按采购方式分类（招标/比价/单一来源/框架协议）
维度三：跟谁买？          -> 按供应商关系分类（现货/优选/战略/竞争）
维度四：什么时候买？      -> 按采购时机分类（备货/JIT/预约/紧急）
维度五：谁来买？          -> 按组织模式分类（集中/分散/混合/品类管理）
```

五个维度不是独立的——一个实际的采购活动同时落在五个维度的某个格子里。例如：

> 服务器研发团队采购一批 **NVIDIA B300 GPU**（对象=战略物料），通过 **年度框架协议下单**（方式=框架协议），向 **NVIDIA 授权分销商**采购（关系=供应受限品），在 **项目开发阶段提前备货**（时机=提前备货），由 **公司中央采购部统一谈判**（组织=集中采购）。

### 1.3 采购的双重属性

采购活动具有**战略属性**和**执行属性**的双重特征：

```text
战略属性（管理供应商资源）：
  供应商寻源与评估 -> 品类策略制定 -> 合同谈判 -> 供应商关系管理
  +- 影响：成本结构、供应安全、创新获取

执行属性（管理订单与交付）：
  需求发起 -> 价格确认 -> PO 下单 -> 交期跟踪 -> 验收对账 -> 付款
  +- 影响：项目进度、库存周转、资金占用
```

服务器研发采购的独特之处在于：**战略属性极强**——CPU/GPU/内存等核心器件选型直接决定产品竞争力，而**执行属性要求极高**——BOM 中数百个料号缺一个就装不出整机。

## 2. 按采购对象分类

这是最基础的分类方式，决定了采购的流程、周期和管控要求。

### 2.1 BOM 物料采购

**定义**：采购构成最终产品的物理部件，是服务器研发中最核心的采购活动。

**服务器研发的典型 BOM 物料分层**：

```text
层级 0：核心芯片（占 BOM 成本 60-80%）
  +-- GPU：NVIDIA B300 / AMD MI355X / 国产算力芯片
  +-- CPU：Intel Xeon 6 / AMD EPYC Turin / 国产信创 CPU
  +-- 内存：DDR5 RDIMM / HBM（绑定 GPU 出货）
  +-- 存储：NVMe SSD / SATA SSD / HDD

层级 1：关键模组（占 BOM 成本 10-15%）
  +-- 网卡：CX7/CX8、OCP Mezzanine Card
  +-- 电源：PSU（3kW+/5kW+）
  +-- 背板：PCIe Switch 板／NVMe 背板
  +-- 散热模组：冷板／风扇模组／热管

层级 2：通用器件（占 BOM 成本 5-10%）
  +-- PCB 板：主板 / 中背板 / 子卡
  +-- 连接器：板对板 / IO 面板 / 电源连接器
  +-- 被动器件：电容/电阻/电感
  +-- 线缆：SAS/SATA/NVMe/电源线 缆

层级 3：辅料包材（占 BOM 成本 1-3%）
  +-- 机箱结构件：导轨 / 面板 / 把手
  +-- 包材：纸箱 / 泡棉 / 防静电袋
  +-- 辅材：螺丝 / 导热垫 / 标签
```

**采购特征对比**：

| 层级 | 采购周期 | 供应商数量 | 价格谈判空间 | 供应风险 | 典型采购模式 |
|:-----|:---------|:-----------|:-------------|:---------|:------------|
| 核心芯片 | 8-16 周 | 1-3 家 | 低（卖方市场） | 极高 | 战略合作+长单锁价 |
| 关键模组 | 4-12 周 | 2-5 家 | 中 | 高 | 框架协议+报价单 |
| 通用器件 | 2-8 周 | 3-10+ 家 | 中高 | 中 | 竞价+比价 |
| 辅料包材 | 1-4 周 | 5-20+ 家 | 高 | 低 | 现货/小额采购 |

### 2.2 设备与固定资产采购

**定义**：采购用于研发、测试、生产的非消耗性设备。

**服务器研发中的典型设备采购**：

| 设备类别 | 典型物品 | 单价区间 | 采购周期 | 关键考量 |
|:---------|:---------|:---------|:---------|:---------|
| **测试设备** | 示波器（8GHz+）、逻辑分析仪、协议分析仪（PCIe/NVMe） | ¥10万-100万 | 8-16 周 | 带宽/通道数/软件选项 |
| **信号测量** | 网络分析仪、频谱分析仪、误码仪 | ¥20万-200万 | 12-20 周 | 频率范围/精度 |
| **环境测试** | 温箱、振动台、老化房 | ¥5万-50万 | 6-12 周 | 温控范围/均匀性 |
| **负载工具** | 电子负载、Power Analyzer、热成像仪 | ¥2万-30万 | 4-8 周 | 功率范围/采样率 |
| **开发板** | FPGA 开发板、CPU/GPU 参考设计板 | ¥1万-10万 | 2-8 周 | 参考价值/文档完整性 |
| **生产设备** | 烧录器、自动测试机台、包装线 | ¥10万-500万 | 8-24 周 | 产能/UPH |

**与 BOM 采购的关键差异**：

- 单次采购金额大但频率低（一次买用 3-5 年）
- 需要技术评估（是否满足研发需求）和固定资产管理（折旧/盘点）
- 采购决策涉及 CAPEX 预算审批（比 OPEX 流程更严格）

### 2.3 软件与知识产权采购

**定义**：采购软件授权、IP 许可、EDA 工具、操作系统等非实物资产。

**服务器研发中的典型软件采购**：

| 软件类别 | 具体产品 | 计价模式 | 年费区间 | 采购方式 |
|:---------|:---------|:---------|:---------|:---------|
| **EDA 工具** | Cadence/Synopsys/Mentor PCB 设计 | 年度订阅/node-locked | ¥10万-200万 | 年度续费+技术绑定 |
| **仿真软件** | Ansys（热/结构/电磁） | 模块按需 + 核数 | ¥5万-80万 | 按需采购 |
| **BMC/IPMI** | AMI MegaRAC / 自研 OpenBMC 授权 | Royalty/项目授权 | ¥20-100/台 | 授权绑定出货量 |
| **BIOS/UEFI** | AMI Aptio / InsydeH2O | Royalty + 开发费 | ¥10-50/台+年费 | 绑定芯片组 |
| **OS 授权** | Windows Server / RHEL / SUSE | Core-based 订阅 | ¥2,000-10,000/台 | OEM 预装或 BYOL |
| **调试工具** | Trace32 / JTAG 调试器 License | 节点授权 | ¥3万-15万 | 按需购买 |
| **安全认证** | TPM 固件 / Secure Boot 方案 | 项目授权 | ¥5万-30万 | 随方案采购 |

**特点**：

- 通常是订阅制（年度续费）或 Royalty 模式（按出货量付）
- 软件采购的技术评估复杂——涉及兼容性、版本策略、License 管理
- 部分软件与硬件绑定（如 AMI BIOS 通常绑定 Intel 平台）

### 2.4 服务采购

**定义**：采购第三方提供的专业服务，不是「物品」而是「能力/工时」。

**服务器研发中的典型服务采购**：

| 服务类别 | 具体内容 | 计价模式 | 典型供应商 |
|:---------|:---------|:---------|:-----------|
| **认证测试** | UL/CE/FCC/CCC 安全认证、OCP 认证、NVMe 集成认证 | 按认证项目 | UL / TÜV / SGS / Intel 认证实验室 |
| **兼容性测试** | 与主流 OS/Hypervisor 的兼容性认证 | 按平台 | Microsoft WHQL / Red Hat / VMware |
| **电磁兼容 (EMC)** | 辐射/传导/ESD/Surge 测试 | 按测试时数 | 第三方 EMC 实验室 |
| **可靠性测试** | HALT / HASS / 加速老化测试 | 按项目 | 第三方可靠性实验室 |
| **云服务** | 开发测试用云资源（AWS/GCP/Azure/阿里云） | 按用量（按时/按量） | AWS / 阿里云 / 腾讯云 |
| **制造服务 (EMS)** | PCBA 焊接、整机组装、老化测试 | 按板/台 + NRE | Foxconn / Flex / Wistron / 广达 |
| **物流服务** | 样品快递、批量货运、保税仓储 | 按重量/体积/距离 | DHL / FedEx / 顺丰|
| **法律/专利** | 专利检索、侵权分析、许可谈判 | 按时/按项目 | 专利律所 |
| **翻译/文档** | 产品手册/技术文档翻译 | 按字数/页数 | 翻译公司 |

**特点**：

- 服务质量的衡量难度大——不像物料可以量尺寸测性能
- 服务采购的交付物通常是「报告/证书/通过测试」——验收标准需要提前明确
- 部分服务具有强时间窗口（认证测试排期通常要提前 1-3 个月预约）

### 2.5 工程样品采购

**定义**：在正式量产前，采购工程样片（ES/QS/EVT 阶段）用于研发验证。这是服务器研发特有的采购类型，介于「研发需求」和「正式生产」之间。

**典型工程样品**：

| 样品种类 | 来源 | 获得方式 | 价格特征 | 用途 |
|:---------|:------|:---------|:---------|:-----|
| CPU 工程样片 (ES/QS) | Intel/AMD | NDA 约束下的申请分配 | 免费或象征性收费 | 平台开发/BIOS 验证 |
| GPU 工程样片 | NVIDIA/AMD | NDA + 额度分配 | 高价（参考价 2-5×） | 兼容性/性能验证 |
| 新内存颗粒 (DDR5 新制程) | Samsung/SK Hynix/Micron | 样品申请 | 免费或低价 | 兼容性验证 |
| 新 SSD 样片 | Samsung/Kioxia/WD | 样品申请 | 免费或低价 | NVMe 兼容性验证 |
| 新网卡样片 | Mellanox/Intel/Broadcom | 样品申请 | 免费（战略客户） | 驱动验证 |
| 新 BMC 芯片 (AST2700) | ASPEED/Nuvoton | NDA 约束下的申请 | 免费（开发板需要购买） | 初期平台开发 |
| 新电源模组 | Delta/Lite-On/Flex | 样品购买 | 参考价 1-2× | 电气验证 |
| EVT 主板 | 自有/EMS | 自产或外包打样 | PCB + 焊接费 | 整机功能验证 |

**特点**：

- 工程样片通常通过 **NDA 渠道**获取——需要签署保密协议
- 样片数量极其有限（CPU/GPU 可能全球只有几十片），分配逻辑复杂
- 样片可能处于「非最终状态」——有 Errata、固件不完整
- 样片采购不是「花钱就能买到」——供应商对战略客户优先分配

## 3. 按采购方式/流程分类

这个维度回答「怎么买」——交易的流程和合规要求。

### 3.1 招标采购

**定义**：通过公开或邀请方式，向多家供应商发布采购需求，通过评审选择最优方案。

**适用场景**：

- 采购金额大（超过公司规定门槛，如 ¥50 万以上强制招标）
- 供应市场竞争充分（多家供应商能满足需求）
- 规格/需求可以清晰描述

**服务器研发中的典型招标案例**：

```text
案例：EMS 制造服务招标

参与方：Foxconn / Flex / Wistron / 广达 / 天弘 (5 家)
招标范围：整机组装 + 功能测试 + 包装出货（年预估量 1 万台）

流程：
  1. RFQ 发布：技术规格（SOP/BOM/测试规范）+ 商务条件（年量/付款条款）
  2. 供应商答疑：技术澄清会（1 天）+ 商务澄清（邮件）
  3. 报价回收：5 家提交密封报价
  4. 评标：技术标（60%）+ 商务标（40%）
     - 技术评分项：直通率(20%)、交期达成率(15%)、NRE 费用(15%)、产能弹性(10%)
     - 商务评分项：单台报价(20%)、付款条件(10%)、账期(10%)
  5. 议标：与 Top 2 商务谈判，获得最终报价
  6. 定标：选定供应商，签署年度框架合同
```

**优缺点**：

| 优点 | 缺点 |
|:-----|:------|
| 流程透明，合规性强 | 周期长（4-8 周） |
| 获得市场竞争价格 | 不适用于紧急需求 |
| 可同时评估技术与商务 | 供应商参与成本高 |
| 大金额采购的法定要求 | 不适合战略创新采购 |

### 3.2 比价采购

**定义**：向至少 3 家供应商询价，选择性价比最优的方案。比招标简单，但仍保留竞争性。

**适用场景**：

- 采购金额中等（如 ¥5 万-50 万）
- 需求明确、规格标准化
- 时间相对充足

**服务器研发中的典型比价案例**：

```text
案例：PCB 板打样比价

参与方：深南电路 / 沪电股份 / 景旺电子 / 博敏电子 (4 家)

询价单内容：
  板材：Megtron 6（高速材料）
  层数：24 层
  板厚：3.0mm
  铜厚：1oz 内外层
  表面处理：ENIG
  交期：加急 7 天 / 常规 14 天
  数量：5 pcs + 2 pcs 备用

比价结果示例：
  深南：¥8,500（常规）/ ¥15,000（7 天）<- 技术评分最高
  沪电：¥7,200（常规）/ ¥13,500（7 天）<- 价格最低
  景旺：¥9,000（常规）/ ¥16,000（7 天）<- 报价最高
  博敏：¥7,800（常规）/ ¥14,200（7 天）<- 性价比中

决策：深南电路（理由：多层高速板经验丰富，良率高）
```

### 3.3 单一来源采购

**定义**：向唯一供应商采购，不进行竞争性比价。需要特殊理由和审批。

**适用条件**（满足任意一条即可）：

1. **技术独占性**：只有这一家能提供所需产品（如 Intel CPU 只能从 Intel 或其授权分销商买）
2. **专利/版权保护**：受知识产权保护（如 AMI BIOS）
3. **紧急情况**：时间窗口不允许走正常流程（如产线停线紧急补料）
4. **延续性要求**：与已有系统/设备的兼容性约束（如必须用同一品牌 PCIe Switch）
5. **战略合作**：前期已深度投入，切换成本极高（如绑定芯片组的 EDA 工具）

**服务器研发中的典型单一来源采购**：

```text
案例 1：GPU 采购（NVIDIA B300）
  理由：技术独占性。AI 训练市场 NVIDIA 占 80%+，B300 没有替代品
  风险：供应商议价能力极强，供货分配权在厂商
  应对：签订 LTSA（长期供应协议），锁定价格和产能

案例 2：AMI BIOS 授权续费
  理由：前期已基于 AMI BIOS 做了大量定制开发，切换成本 > ¥500 万
  风险：Royalty 费率每年谈判，可能逐年涨价
  应对：评估开放源码 uEFI（TianoCore/EDK II）作为 long-term 替代方案

案例 3：产线紧急补料（某型号电容断料）
  理由：产线停线损失 ¥10 万/小时
  风险：供应商可能趁机涨价 2-3×
  应对：容忍加价，事后评估备选供应商
```

**管理要点**：

- 单一来源采购需要特殊审批（通常需要 VP 以上签字）
- 定期复核「单一来源的理由是否仍然成立」
- 即使是单一来源，也要进行价格合理性分析（成本构成拆解、历史价格对比）

### 3.4 框架协议采购

**定义**：与供应商签订长期框架协议，约定价格、条款和合作条件。实际下单时不需要每次谈判。

**这是服务器研发中最常用的采购模式**——BOM 物料几乎全部走框架协议。

**框架协议的要素**：

```yaml
框架协议 (Master Agreement / LTSA) 核心条款：
  Scope: 覆盖的物料范围（如「所有 NVIDIA GPU 产品线」）
  Price: 价格锁定或定价公式
    - Fixed Price：全年锁定单价
    - Periodic Price：季度/半年重新定价
    - Volume-Based：基于年采购量的阶梯价格
  Volume: 承诺采购量（年预估量，不一定有约束力）
  Lead Time: 标准交期 + 加急交期 + 加急费
  Payment: 账期（30/60/90 天）、付款方式
  Warranty: 保修条款
  Termination: 终止条款（Notice Period）
```

**服务器研发中的框架协议案例**：

```text
案例：DDR5 RDIMM 框架协议

供应商：Samsung / SK Hynix / Micron（三家各签）
协议类型：LTCA（Long Term Capacity Agreement）

条款要点：
  1. 价格机制：每季度基于 DRAMeXchange 市场价格 + 固定折扣（如市场价 - 5%）
  2. 产能预留：支付 ¥100 万保证金，锁定每月 500K 条产能
  3. 交期：常规 6 周，加急 3 周（+10% 加急费）
  4. 最小起订量 (MOQ)：单次下单 ≥ 5K 条
  5. 年度预估：承诺年采购量 ≥ 500 万条，未达标则调整下年折扣

典型下单流程：
  每月初 -> 采购部发需求预测（滚动 3 个月）-> 供应商确认 capacity -> 每周按实际需求下 PO
```

**框架协议 vs 现货采购**：

| 维度 | 框架协议 | 现货/单次采购 |
|:-----|:---------|:--------------|
| 价格 | 较低（长期合作价） | 较高（含现货溢价） |
| 供应保障 | 高（预留产能） | 低（看现货库存） |
| 灵活性 | 中（有承诺量约束） | 高（想买就买） |
| 管理成本 | 高（协议谈判/关系管理） | 低（不需长期维护） |
| 适用 | 核心批量物料 | 小批量/研发样品/辅料 |

### 3.5 小额采购/零星采购

**定义**：金额小（如 < ¥1 万）、频率低、不走正式采购流程的采购。

**服务器研发中的典型小额采购**：

- 买几颗样品芯片（如 ¥500 的 DC/DC 电源芯片）
- 买一套螺丝刀/热风枪（¥300）
- 买几根定制调试线缆（¥800）
- IT 设备配件（外接硬盘/转接线/USB Hub）

**管理方式**：

- 通常用采购卡（P-Card）或备用金直接购买
- 月结或年度汇总报销
- 不需要招标和合同
- **关键风险**：小额采购「蚂蚁搬家」式分散大额采购，规避审批流程

### 3.6 竞价采购/电子竞标

**定义**：通过在线竞价平台，供应商在限定时间内实时竞价，价低者得。

**适用场景**：

- 标准规格产品（多个供应商可提供相同规格）
- 供应市场竞争充分
- 价格是主要决定因素

**服务器研发中适用竞价采购的物料**：

- 标准 0805/0603 电阻电容
- 标准螺丝/螺母/垫片
- 通用线缆（SATA 线/电源线）
- 包材（纸箱/泡棉）
- 标准风扇模组

**不适用竞价的情况**：

- 技术复杂度高（需要技术评估的）
- 质量验证周期长（如 PCB、电源模块）
- 供应受限或稀缺的（如 GPU/HBM）

## 4. 按供应商关系分类

这个维度回答「跟谁买」——供应商在供应体系中的定位。

### 4.1 现货采购（Spot Buy / Ad-hoc）

**定义**：不建立长期供应关系，每次采购都独立询价和下单。

**特征**：

- 无长期承诺，按需操作
- 价格通常高于长期协议价
- 主要面向标准品或样品
- 管理成本低（不需要维护关系）

**服务器研发中的现货采购场景**：

- 研发打样阶段的小批量器件（每种 5-10 颗）
- 从 DigiKey / Mouser / 贸泽这类现货分销商购买
- 缺料紧急补货（从市场上采购高价现货）
- 2nd Source 样品验证（买不同品牌对比测试）

### 4.2 优选供应商采购（Preferred Supplier）

**定义**：公司评估认定的首选供应商，获得优先采购权但不是独家。

**特征**：

- 通过了公司的供应商认证（QSA/QPA）
- 价格和质量有竞争力
- 通常有框架协议约束价格和条款
- 不排除使用其他供应商

**服务器研发中的优选供应商示例**：

```text
PCB 板（优选供应商）：
  - 深南电路（高速 PCB，主流）
  - 沪电股份（高速 PCB，备选）
  - 景旺电子（普通 PCB）
  不是首选时仍需比价

电源模组（优选供应商）：
  - Delta（全球最大，品质稳定）
  - Lite-On（成本优势）
  - Flex（定制能力强）
```

### 4.3 战略合作采购（Strategic Partnership）

**定义**：与供应商建立深度合作关系，不只是在交易层面。

**战略合作的特征**：

- 联合研发：供应商参与产品早期设计（JDM/ODM 模式）
- 信息共享：共享需求预测、技术路线图
- 长期绑定：通常 3-5 年合作期
- 优先供应：缺货时优先分配产能
- 价格优惠：获得最优价格条款

**服务器研发中的战略合作案例**：

```text
案例：服务器厂商与 NVIDIA 的战略合作

合作内容：
  1. 产品规划阶段：NVIDIA 提前 12-18 个月分享 GPU 技术路线图
  2. 联合设计：NVIDIA 提供参考设计（NVIDIA HGX Baseboard）
  3. 样品优先：新 GPU 工程样片优先分配给战略客户
  4. 产能锁定：支付保证金锁定 HBM/CoWoS 产能
  5. 价格保护：在市场缺货时获得保护价

对服务器厂商的价值：
  - 新品上市时间比竞争对手快 1-2 个季度
  - GPU 缺货时能拿到更多配额
  - 联合研发降低设计风险

对 NVIDIA 的价值：
  - 获得稳定的需求预测
  - 参考设计被广泛采用，降低客户支持成本
  - 形成生态锁定
```

**另一个方向：与 EMS 的战略合作**：

```text
案例：服务器厂商与 Foxconn 的战略合作

合作模式：JDM（Joint Design Manufacturing）
  - Foxconn 参与结构设计、散热设计
  - 服务器厂商负责系统架构、芯片选型、固件开发
  - Foxconn 负责 PCB Layout、试产、量产、全球物流

关键条款：
  - 专线产能：Foxconn 为战略客户保留专属 SMT 产线
  - 全球交付：支持在墨西哥/印度/捷克等地的本地化交付
  - 成本透明：BOM 成本+加工费模式（Open Book）
  - NRE 共担：新机型 NRE 费用由双方按比例承担
```

### 4.4 受管制/受限采购（Constrained Sourcing）

**定义**：供应受外部因素严格限制，供应方处于强势地位。

**特征**：

- 供应高度集中（寡头或垄断）
- 供应方分配产能和配额
- 买方议价能力弱
- 通常需要长期承诺来换取供应

**服务器研发中受限采购的典型**：

```text
受限品类 Top 5：
  1. GPU：NVIDIA 80%+ 市占率，HBM/CoWoS 产能瓶颈
  2. CPU（x86）：Intel + AMD 双寡头
  3. HBM：SK Hynix + Samsung + Micron 三寡头
  4. FPGA（高端）：Xilinx（AMD）+ Intel Altera
  5. BMC：ASPEED 全球 65-70% 市占率

管理策略：
  - 接受「供应商是爷」的现实，建立高层关系
  - 加入供应商的战略客户计划（获更多配额）
  - 用长期不可撤销订单锁定产能
  - 评估国产替代方案（对冲制裁/缺货风险）
  - 提前 12 个月做需求规划（不能临时下单）
```

### 4.5 内部关联采购（Intercompany / Related Party）

**定义**：向集团内部关联公司采购。

**服务器研发中的典型内部关联采购**：

- 向集团内的散热子公司采购液冷冷板
- 向集团内的 PCB 工厂采购电路板
- 向集团内的 ODM 子公司采购整机
- 向集团内的软件部门采购固件/管理软件

**管理要点**：

- 转移定价必须符合税务合规要求（独立交易原则）
- 质量/交期标准不能因为是内部关系就降低
- 定期做外部比价，确保内部价格不高于市场价

## 5. 按采购时机分类

这个维度回答「什么时候买」——采购与项目进度的关系。

### 5.1 提前备货 / 长周期物料采购

**定义**：在需求明确前，基于预测提前下单备货。

**适用**：

- 交期长的物料（核心芯片 8-16 周）
- 供应受限的物料（GPU/HBM）
- 价格可能上涨的物料（内存/Flash）

**服务器研发中的典型提前备货**：

```text
案例：B300 GPU 提前备货（提前 6 个月）

时间线示例：
  T-6 月：基于 NPI 规划确定 B300 需求预测（3,000 pcs）
  T-5 月：向 NVIDIA 提交不可撤销订单（Non-cancellable Order）
  T-4 月：支付 10% 预付款（≈ ¥1,200 万）
  T-3 月：NVIDIA 分配 wafer / CoWoS 产能
  T-2 月：GPU 封装完成，进入出货排程
  T-1 月：NVIDIA 发货到指定仓位
  T+0 月：到货入库，用于 EVT/DVT 阶段
```

**风险**：

- 预测不准导致库存积压（GPU 跌价风险大）
- 产品延迟导致提前买的物料闲置
- 错过备货窗口就买不到（GPU 产能已排满）

### 5.2 JIT 采购（Just-in-Time）

**定义**：在需要时才下单采购，不设或少设安全库存。

**适用**：

- 交期短（1-2 周内）
- 供应稳定（不缺货）
- 需求不确定

**服务器研发中的 JIT 采购**：

- 标准被动器件（电阻电容——供应商多且备有现货）
- 通用包材（纸箱/托盘——供应商 3-5 天交货）
- 标准螺丝/线缆（供应商备有库存）

**注意**：

- JIT 的精髓不是「零库存」，而是「零等待」——需要供应商有可靠的现货和快速响应
- 服务器行业整体毛利率低，库存持有成本敏感——JIT 是盈利管理的重要手段
- 但核心芯片绝对不能用 JIT——交期和供应风险太高

### 5.3 预约采购（Reservation / Allocation）

**定义**：提前预约供应商的产能或分配额，实际采购时再确认数量和交期。

**与提前备货的区别**：

```text
提前备货：下单->付钱->供应商供货（库存风险在买方）
预约采购：预约容量->每月确认需要多少（库存风险部分共享）
```

**典型场景**：

- 与代工厂预约排产产能（按月释放 PO）
- 与存储厂商预约 DRAM/NAND wafer 产能
- 与电源厂预约 PSU 产线时间

### 5.4 紧急采购（Emergency Procurement）

**定义**：在需求急迫时启动的非常规采购流程，通常伴有溢价。

**触发条件**：

- 研发过程中发现缺 BOM 物料
- 产线停线待料
- 测试设备故障需要急修
- 客户紧急需求

**服务器研发中的紧急采购案例**：

```text
案例：某型号电源模块停线缺料

背景：
  - 产线正在生产的 200 台机器缺 200 颗特定型号的电源模块
  - 常规交期 6 周
  - 产线停工损失 ¥10 万/小时

紧急采购执行：
  1. 优先渠道：联系原厂 Delta，请求加急出货（+20% 加急费）
  2. 现货渠道：从市场上搜索现货（¥200/颗 vs 正常 ¥80/颗）
  3. 替代方案：使用同规格的 Lite-On 替代料（需要研发确认兼容性）
  4. 租借方案：向兄弟公司借调 200 颗（先用，后续补还）

结果：
  通过加急出货+部分现货，3 天内完成补料
  额外成本：¥24,000（+75% 溢价），避免的停线损失：¥240,000+
```

**紧急采购的管理要求**：

- 需要快速审批通道（但事后要补常规流程）
- 记录紧急采购的原因（用于后续改进）
- 评估如何避免同类紧急情况再次发生

### 5.5 研发阶段采购 vs 量产阶段采购

研发阶段的采购和量产阶段的采购有本质区别：

| 维度 | 研发阶段采购 | 量产阶段采购 |
|:-----|:------------|:-------------|
| **目的** | 样品验证/原型制作/兼容性测试 | 满足批量交付需求 |
| **数量** | 小批量（5-100 pcs） | 大批量（1,000-100,000+ pcs） |
| **单价** | 高（样品价，通常 2-5× 量产价） | 低（协议锁定价格） |
| **交期要求** | 急（项目进度驱动） | 计划性（按预测下单） |
| **供应商选择** | 技术能力优先 | 综合能力（成本+质量+交期） |
| **议价重点** | 获取样品和技术支持 | 降低单价和保障供应 |
| **质量管控** | 功能验证 | 批次一致性+SPC |
| **库存策略** | 少量现货（不够再买） | 安全库存+JIT+备货 |
| **采购主流程** | 简化的研发采购 | 正式的大批量采购 |

**分阶段的 BOM 采购策略示例**：

```text
NPI 阶段（新产品导入）：
  +- Prototype (EVT)：从授权分销商买现货，不建 MOQ
  +- Pilot Run (DVT)：走框架协议小批量下单，价格按协议
  +- MP (量产)：框架协议大批量下单，锁定季度价格+产能

各阶段典型的采购前置时间：
  EVT：2-4 周（少量现货）
  DVT：4-6 周（小批量）
  MP：8-12 周（大批量需排产）
```

## 6. 按采购组织模式分类

这个维度回答「谁来买」——采购职能的组织方式。

### 6.1 集中采购（Centralized Procurement）

**定义**：所有采购由公司中央采购部门统一执行。

**适用**：品类一致、规模效应显著的采购。

**服务器公司中的集中采购典型**：

```text
中央采购部负责的采购范围：
  1. 核心芯片：GPU/CPU/DRAM/SSD（全球统一谈判）-> 年采购额数十亿
  2. 关键模组：电源/背板/网卡（统一签框架协议）
  3. EMS 制造：全球各厂区统一招标和定价
  4. 物流服务：全球物流服务统一采购

优点：
  - 规模效应 -> 更低的价格
  - 统一供应商管理 -> 减少管理成本
  - 采购流程标准化 -> 合规性强

缺点：
  - 响应不灵活（研发急用物料要等总部流程）
  - 不了解本地需求
  - 对非核心物料的管理粒度粗
```

### 6.2 分散采购（Decentralized Procurement）

**定义**：各业务部门/区域自行组织采购。

**适用**：本地化、小额、紧急的采购。

**服务器公司中的分散采购典型**：

```text
研发部门可自行采购的范围（通常有金额限制，如 ≤ ¥5 万/单）：
  1. 研发打样物料（研发从小分销商买样品芯片）
  2. 测试设备配件（特定接口的转接板/线缆）
  3. 办公/实验消耗品（焊锡/助焊剂/酒精）
  4. 紧急研发工具（某工程师买了一台特定型号的示波器探头）

优点：
  - 响应快（研发不用等采购部流程）
  - 了解特定需求（研发懂自己要什么）

缺点：
  - 价格高（单次采购量小，无竞争）
  - 管理分散，可能重复采购
  - 缺乏供应商准入评估
```

### 6.3 混合采购（Hybrid / Center-led Procurement）

**定义**：中央采购负责战略和框架，本地/部门负责执行和下单。这是大多数服务器公司采用的模式。

**运营模式**：

```text
中央采购部（CoE — Center of Excellence）：
  负责：
  - 供应商寻源和认证
  - 框架协议谈判（锁定价格和条款）
  - 核心供应商关系管理
  - 采购流程和系统建设

业务部门（研发/制造）：
  负责：
  - 在框架协议下自主下单
  - 日常交期跟踪
  - 验收和确认
  - 非核心/小金额采购

边界示例：
  ✗ 研发不能自己谈判 GPU 价格（中央签协议）
  ✓ 研发可以在框架协议内向授权分销商下单
  ✗ 研发不能自行引入新的 PCB 供应商（中央认证）
  ✓ 研发可以在优选供应商范围内选择
  ✓ 研发可以自行购买 ≤ ¥2 万的实验设备
```

### 6.4 品类管理模式（Category Management）

**定义**：按物料品类设置采购经理，负责该品类的全生命周期管理。这是现代采购组织的主流模式。

**服务器公司的品类组织示例**：

```text
CPO（首席采购官）
+-- 半导体品类
|   +-- GPU/NPU/ASIC（1 人）
|   +-- CPU/芯片组（1 人）
|   +-- 内存/HBM（1 人）
|   +-- 存储/SSD（1 人）
|
+-- 机电品类
|   +-- 电源/散热（1 人）
|   +-- 连接器/线缆（1 人）
|   +-- PCB/PCBA（1 人）
|   +-- 机箱/结构件（1 人）
|
+-- 制造与服务品类
|   +-- EMS/CM（2 人，按区域）
|   +-- 测试/认证（1 人）
|   +-- 物流/仓储（1 人）
|
+-- 非生产品类
|   +-- IT/软件（1 人）
|   +-- 设备/固定资产（1 人）
|   +-- 行政/间接物料（1 人）
|
+-- 采购运营组
    +-- 采购系统（SAP Ariba/Oracle）（1 人）
    +-- 供应商质量（SQE 团队）
    +-- 采购分析/数据（1 人）
```

**品类经理的职责**：

- 制定品类策略（Make/Buy、供应商基盘、成本模型）
- 供应商寻源、评估、准入、淘汰
- 年度价格谈判和协议管理
- 供应风险管控（单一来源识别、替代方案）
- 市场趋势分析（价格走势、技术路线图）

## 7. 服务器研发全生命周期的采购全景

以上是从五个维度切分采购模式，实际研发过程中采购是以「项目」为维度协同运作的。以下用服务器研发项目的时间线展示各类采购如何协同。

### 7.1 概念与规划阶段（Phase 0）

**核心采购活动**：信息收集、供应商早期介入、成本估算

```text
时间：T-12 月 ~ T-6 月（产品规划阶段）

采购活动：
  □ 与核心芯片厂商（Intel/NVIDIA/AMD）技术交流，获取 Roadmap
  □ 与 EMS 厂讨论新产品导入计划，估算 NRE 费用
  □ 收集主要元器件价格趋势（GPU/DRAM/SSD 行情分析）
  □ 评估认证测试需求（UL/CCC/CE）和供应商
  □ 建立目标 BOM 成本预算（Target Cost）

关键输出：
  - 目标 BOM 成本分解表
  - 核心器件选型列表（含供应商和成本）
  - NPI 采购时间表
```

**涉及的采购模式**：

- 战略合作采购（供应商 Roadmap 共享）
- 品类管理（各品类经理提供市场行情）

### 7.2 工程验证阶段（EVT）

**核心采购活动**：样品获取、打样采购、小批量验证

```text
时间：T-6 月 ~ T-3 月

采购活动：
  □ 申请 CPU/GPU ES 样片（NDA 渠道，提前 4-6 周）
  □ 从现货分销商采购 EVT 用通用器件（DigiKey/Mouser）
  □ PCB 打样（快速打样厂，1 周交期）
  □ 采购开发/调试工具（JTAG 调试器/逻辑分析仪）
  □ 采购测试用 SSD/内存（少量现货）
  □ 采购样机电源模组（从电源厂借样或买样）

关键输出：
  - EVT 样机（5-20 台）
  - 初步 BOM 清单（含供应商信息）
  - 兼容性测试结果
```

**涉及的采购模式**：

- 工程样品采购（核心芯片 ES 样片）
- 小额/零星采购（从现货分销商买器件）
- 比价采购（PCB 打样）

### 7.3 设计验证阶段（DVT）

**核心采购活动**：小批量 M-PCB、量产级物料验证、产能锁定

```text
时间：T-3 月 ~ T-1 月

采购活动：
  □ 从供应商批量申请正式样本（NVIDIA B300 QS->MP 样片）
  □ 小批量 PCB 试制（正式 PCB 厂，标准交期）
  □ 按议定价格小批量采购内存/SSD（走框架协议）
  □ 关键模组进入试产（散热器小批量开模）
  □ 与 EMS 讨论量产准备，确认产能预留
  □ 开始批量认证测试预约（FCC/CE/CCC 排期）

关键输出：
  - DVT 样机验证报告
  - 量产物料清单（AVL — Approved Vendor List）
  - 量产 BOM 成本确认
  - 供应商产能承诺
```

**涉及的采购模式**：

- 框架协议采购（在框架协议下小批量下单）
- 提前备货（长周期物料开始备货）
- 单一来源（如果某些器件只有一家）
- 服务采购（认证测试预约）

### 7.4 量产准备阶段（PVT/MP）

**核心采购活动**：量产物料下单、产能锁定、成本控制

```text
时间：T-1 月 ~ T+0 月（正式量产）

采购活动：
  □ GPU 大批量下单（不可撤销 PO，预付 10-30%）
  □ 内存/SSD 正式下单（按月释放，滚动 3 个月预测）
  □ 全 BOM 物料下达采购订单（约 500-1,000 个料号）
  □ EMS 开工单（安排 SMT 排程）
  □ 安全库存设定（核心芯片按 2-4 周备货）
  □ 质检安排（IQC 方案、供应商出货检验）
  □ 物流安排（空运/海运/保税）

关键输出：
  - 量产 BOM + 采购订单
  - 物料齐套确认 (Kitting Report)
  - 供应商出货计划
```

**涉及的采购模式**：

- 框架协议采购（全部在已有框架协议下执行）
- JIT 采购（短交期物料按需到货）
- 提前备货（核心芯片备 2-4 周安全库存）
- 战略合作采购（与 EMS 的日常协同）

### 7.5 量产后持续管理

**核心采购活动**：成本优化、供应风险管控、第二供应商开发

```text
持续进行的采购活动：

成本优化（每季度）：
  □ BOM 成本复盘：对比目标成本 vs 实际成本
  □ 关键物料价格谈判（内存/SSD/电容 季度调价）
  □ 替代料验证（更低成本的 2nd Source）
  □ 设计优化降本（DTC — Design to Cost）

供应风险管控（持续）：
  □ 单一来源物料识别和替代计划
  □ 供应商财务健康监控
  □ 产能缺口预警（GPU/内存缺货预测）
  □ 地缘政治风险（关税/制裁/禁运）应对

供应商管理（持续）：
  □ 年度供应商绩效评估（QCDS — Quality/Cost/Delivery/Service）
  □ 供应商现场审核（QSA/QPA）
  □ 新供应商引入（2nd Source / 国产替代）
  □ 供应商退出管理
```

| | 服务 | 低 | 高 | 次优 | 中 | 中 | 按需 |
| **方式** | 招标 | 最高 | 最低 | 最优 | 高 | 最高 | 量产 |
| | 比价 | 高 | 中 | 优 | 中 | 中 | DVT起 |
| | 单一来源 | 中 | 低 | 差 | 高 | 低 | ES样品 |
| | 框架协议 | 高 | 中 | 优 | 高 | 高 | EVT后量产 |
| | 小额 | 低 | 最高 | 差 | 低 | 低 | 研发打样 |

| | 受限 | 极低 | 极低 | 差 | 被动 | 中 | 全周期 |
| **时机** | 提前备货 | 高 | 低 | 次优 | 高 | 高 | EVT(芯片) |
| | JIT | 中 | 高 | 最优 | 中 | 中 | 量产标准件 |
| | 预约 | 中 | 中 | 次优 | 高 | 中 | 量产前 |
| | 紧急 | 最低 | 最高 | 最差 | 紧急 | 低 | 紧急情况 |
| **组织** | 集中 | 最高 | 最低 | 最优 | 高 | 高 | 量产批采 |
| | 分散 | 最低 | 最高 | 差 | 低 | 低 | 研发样品 |
| | 混合 | 中 | 中 | 优 | 中 | 中 | 全周期推荐 |
| | 品类管理 | 高 | 中 | 最优 | 高 | 最高 | 成熟企业 |

### 8.2 采购模式选型决策树

```text
采购需求产生
  |
  +- 是否是核心BOM物料？---否--> 跳到非BOM采购
  |   |
  |   +- 是核心芯片(GPU/CPU/HBM)？
  |   |   |
  |   |   +- 是 -> 战略合作采购（高层对接+框架协议+提前备货）
  |   |   |     +- 份额由供应商分配 -> 受限采购管理策略
  |   |   |
  |   |   +- 否 -> 是否有框架协议？
  |   |       +- 是 -> 在框架协议下下单
  |   |       +- 否 -> 是否单一来源？
  |   |           +- 是 -> 单一来源谈判+签署框架协议
  |   |           +- 否 -> 招标/比价 -> 签署框架协议
  |   |
  |   +- 是否是其他关键器件(PCB/电源/散热)？
  |       |
  |       +- 是 -> 比价+优选供应商+框架协议
  |       +- 否（标准件/通用件）？
  |           +- 量大批稳 -> 竞价+JIT供货
  |           +- 量小样品 -> 现货采购或小额采购
  |
  +- 否：非BOM采购
  |   +- 设备 -> 比价/招标+固定资产审批
  |   +- 软件 -> 评估技术绑定程度
  |   |   +- 强绑定(EDA/BIOS) -> 单一来源+年度续费
  |   |   +- 可替换 -> 比价+按需采购
  |   +- 服务 -> 技术评估+比价+明确交付物
  |   +- 紧急 -> 简化流程+事后补充正式手续
  |
  +- 按组织划分
      +- 战略级（GPU框架协议）-> 中央采购
      +- 运营级（BOM 下单）-> 混合模式
      +- 小額（实验物料）-> 分散采购
```

### 8.3 按物料属性推荐采购模式

| 物料属性 | 采购模式推荐 | 理由 |
|:---------|:------------|:------|
| **关键器件·卖方市场** | 战略合作 + 长单锁价 + 提前备货 | 供应安全比价格重要 |
| **关键器件·竞争市场** | 招标 + 2nd Source 同步认证 | 引入竞争降低成本 |
| **通用器件·量大** | 框架协议 + 竞价 + JIT | 成本最低化，库存最小化 |
| **通用器件·量小** | 现货采购 / 小额采购 | 管理成本最低 |
| **研发样品·新品** | 样品申请 + 小额采购 | 快速获取为主 |
| **研发样品·标品** | 现货分销商（DigiKey/Mouser） | 品类全、响应快 |
| **服务·认证** | 招标 + 年度协议 | 保证排期和价格 |
| **服务·咨询** | 比价 + 按项目 | 灵活且有竞争 |
| **设备·标准** | 比价 + 统一采购 | 降低采购成本 |
| **设备·专用** | 单一来源 + 技术评估 | 满足技术要求 |
| **软件·平台绑定** | 单一来源 + 年度协议 | 切换成本太高 |
| **软件·通用** | 比价 + 按需 | 选择灵活 |

## 9. 采购管理的关键指标

### 9.1 成本类指标

| 指标 | 定义 | 服务器研发目标参考 | 意义 |
|:-----|:------|:------------------|:------|
| **BOM 成本达成率** | 实际 BOM 成本 / 目标 BOM 成本 | ≤ 100%（且 ≥ 95%） | 产品盈利基础 |
| **年度降价率 (YOY)** | 同物料今年均价 / 去年均价 - 1 | CPU/GPU: -2~-5%；内存: ±10~20%；SSD: -10~-20% | 反映采购谈判能力 |
| **采购支出与 BOM 比** | 采购总支出 / BOM 总成本 | 接近 1:1（正常情况） | 反映非 BOM 采购规模 |
| **NRE 费用控制** | NRE/模具/开模费用 vs 预算 | ≤ 预算 110% | NPI 成本控制 |
| **总拥有成本 (TCO)** | 采购价+运输+关税+检验+库存持有 | 视物料而定 | 真正成本，不止看单价 |

### 9.2 质量类指标

| 指标 | 定义 | 目标参考 |
|:-----|:------|:---------|
| **来料不良率 (PPM)** | 每百万颗来料中的不良数 | ≤ 500 PPM（核心芯片）；≤ 2000 PPM（通用器件） |
| **产线退料率** | 产线因物料问题退回的比例 | < 0.5% |
| **供应商质量问题停线次数** | 因供应商质量问题导致产线停线 | 0 次/月（目标） |
| **纠正措施关闭率** | 8D 报告在规定时间内关闭的比例 | ≥ 90% |

### 9.3 交付类指标

| 指标 | 定义 | 目标参考 |
|:-----|:------|:---------|
| **OTD（准时交付率）** | 按时到货的订单比例 | ≥ 95% |
| **物料齐套率 (Kitting Rate)** | 生产所需物料全部到位的比例 | ≥ 98%（量产前 3 天） |
| **采购前置时间 (Lead Time)** | 从下单到到货的天数 | 核心芯片 ≤ 16 周；标准件 ≤ 4 周 |
| **短缺次数** | 因缺料导致的产线停线/变更次数 | 0 次/月 |
| **安全库存周转天数** | 核心物料安全库存可供使用天数 | GPU: ≥ 4 周；通用: ≥ 2 周 |

### 9.4 供应商管理指标

| 指标 | 定义 | 目标参考 |
|:-----|:------|:---------|
| **供应商数** | 活跃供应商数量 | 核心品类 2-3 家；通用品类 3-5 家 |
| **单一来源比率** | 无可替代的物料占比 | < 5%（应持续降低） |
| **供应商绩效评分** | 年度 QCDS 综合评分 | ≥ 80 分（满分 100） |
| **新供应商引入周期** | 从寻源到通过认证的时间 | ≤ 6 个月 |
| **供应商淘汰率** | 每年淘汰的供应商比例 | 10-15%（保持供应链活力） |

### 9.5 采购运营效率指标

| 指标 | 定义 | 目标参考 |
|:-----|:------|:---------|
| **采购订单处理周期** | 从需求发起到 PO 发出的时间 | 常规 ≤ 2 天；紧急 ≤ 4 小时 |
| **非核心采购自动化率** | 通过系统自动完成（非人工）的采购订单比例 | ≥ 80% |
| **采购人员人均管理 SKU 数** | 每个采购经理管理的物料号数 | 200-500 个 |
| **紧急采购占比** | 紧急采购金额 / 总采购金额 | < 5% |
| **采购合规率** | 按公司规定流程执行的采购比例 | ≥ 98% |

## 10. 采购风险与管控

### 10.1 服务器研发采购的八大风险

| # | 风险 | 描述 | 影响 | 发生概率 | 管控措施 |
|:-:|:-----|:------|:------|:---------|:---------|
| 1 | **核心芯片断供** | GPU/CPU 产能不足，拿不到货 | 产品无法交付，出货延后 | 高 | 战略合作+不可撤销订单+预付 |
| 2 | **单一来源依赖** | 关键器件只有一家供应商 | 被动接受涨价/减产 | 高 | 识别+替代方案开发 |
| 3 | **价格剧烈波动** | 内存/Flash 行情大涨 | BOM 成本超预算 20%+ | 中高 | 期货锁价+季度议价+浮动价格机制 |
| 4 | **器件 EOL/停产** | 供应商停止生产某型号 | 需要重新设计验证 | 中 | EOL 预警+Last Buy+替代替代料 |
| 5 | **交期延误** | 供应商产能不足或物流问题 | 项目延期 | 中高 | 安全库存+多源供应+交期预警 |
| 6 | **质量事故** | 批次性来料不良 | 产线停线+召回风险 | 中 | IQC+供应商出货检+质量协议 |
| 7 | **合规风险** | 出口管制/关税/环保法规 | 货物被扣/无法出口 | 中 | 合规审查+产地多元化 |
| 8 | **采购欺诈** | 假货/翻新件/虚报价格 | 产品可靠性风险 | 低 | 供应商资质审核+原厂验证 |

### 10.2 风险管控矩阵

```text
                影响程度
                低        中        高
  发生概率
     高      | 通用器件涨价  | 标准件断供   | 核心芯片断供 |
             | (风险接受)    | (加备选)     | (需要绝对规避) |
     中      | 小额采购舞弊  | 设备到货延迟  | 内存价格暴涨  |
             | (流程管控)    | (追交期)     | (期货对冲)   |
     低      | 供应商更名    | EOL 停产     | 出口管制     |
             | (接受)       | (Last Buy)   | (需要绝对规避)|
```

### 10.3 采购管理的三层防线

```text
第一层：流程和系统（防错）
  +-- 供应商准入流程（必须资质审核过关才能合作）
  +-- 采购系统审批流（金额分级审批）
  +-- PO/合同模板标准化（减少法律风险）
  +-- 供应商门户（可查订单/交期/质量记录）

第二层：监控和预警（发现）
  +-- BOM 成本变化预警（超预算 5% 自动通知）
  +-- 供应商财务健康监控（Dun & Bradstreet 评分）
  +-- 市场行情跟踪（DRAMeXchange/LME/集邦）
  +-- 交期异常自动告警（预计到货日期延迟即时通知）

第三层：应急和恢复（处理）
  +-- 关键物料 2nd Source 验证（已就绪的替代方案）
  +-- 核心芯片安全库存（不低于 4 周用量）
  +-- 紧急采购授权（单次 ¥50 万内可先买后批）
  +-- 替代料快速验证流程（48 小时工程确认）
```

## 11. 采购关系生命周期：一次性·潜在合作·长期例行

采购不仅是「买什么」和「怎么买」，更是 **「跟谁买到什么深度」**。从关系生命周期角度，采购活动可分为三大类，每类的管理方式截然不同。

### 11.1 一次性交易采购

**定义**：仅本次采购，不预期未来持续合作。双方没有长期承诺，交易完成后关系即结束或休眠。

**适用场景**：

- 研发样品的偶发性采购（如从 DigiKey 买 5 颗不常用芯片）
- 特定项目的单次服务（如找某家机构做一次专项认证测试）
- 从已退出合作关系的供应商那里买售后备件
- 代购/中转采购（帮兄弟公司代为采购，一次性的）

**服务器研发中的典型一次性采购**：

| 场景 | 具体举例 | 采购方式 | 备注 |
|:-----|:---------|:---------|:------|
| 样片补料 | 某工程师从贸泽买 3 颗少见的 FPGA | 在线下单，P-Card 支付 | ¥300-2,000 |
| 专项认证 | 找一家没合作过的德国实验室做 TUV 认证 | 单次合同+预付 | ¥5-20 万 |
| 闲置设备 | 从其他公司买一台闲置的二手示波器 | 单次合同+验货 | ¥3-10 万 |
| 紧急替代 | 正常供应商断货，从一家新的贸易商买现货 | 单次 PO+加急 | 价格通常高 20-50% |

**管理要点**：

- 即使是一次性采购，也要做基本的供应商背景审查（避免假货）
- 一次性采购不意味着「零管理」——验收、付款、发票仍需闭环
- 如果同一供应商出现第二次一次性采购，应主动评估是否升级为潜在合作
- **关键风险**：以「一次性」之名绕过供应商准入流程

### 11.2 潜在合作采购

**定义**：尚未签订长期协议，但在本次采购中评估供应商，作为未来长期合作的「试金石」。

**本质**：这是一次 **带评估目的的采购**——买的不只是产品/服务，还有供应商的能力证明。

**潜在合作的完整流程**：

```text
阶段 1：筛选（2-4 周）
  +-- 从市场搜索候选供应商（3-5 家）
  +-- 资质预审：营业执照/行业资质/客户参考/财务状况
  +-- 技术初评：产品规格/技术能力/样品评估
  +-- 现场审核（必要时）：QSA（质量体系审核）+ QPA（过程审核）

阶段 2：试单（4-8 周）
  +-- 小批量下单（确认质量、交期、服务水平）
  +-- 样品验证（研发测试+可靠性测试）
  +-- 交期考验（是否按承诺时间到货）
  +-- 沟通评估（响应速度、问题处理能力）

阶段 3：评估（2 周）
  +-- 综合评分（技术 40% + 质量 30% + 交期 20% + 服务 10%）
  +-- 对比已有供应商（是否有切换价值）
  +-- 决策：纳入 AVL / 继续观察 / 放弃

阶段 4：扩量（4-12 周）
  +-- 如评估通过，逐步增加订单量
  +-- 纳入框架协议（价格+条款谈判）
  +-- 正式加入 AVL -> 常态合作
```

**服务器研发中的潜在合作典型**：

```text
案例：某国产散热器厂商的潜在合作评估

背景：现有供应商 Delta 价格偏高，希望引入国产替代

筛选阶段（第 1-3 周）：
  - 从 5 家国产散热器厂中筛选出 2 家：酷冷/AVC
  - 资质审核通过，均服务过华为/中兴等客户

试单阶段（第 4-8 周）：
  - 各采购 50 套液冷冷板用于 DVT 样机
  - 研发测试：热阻/压降/泄漏率/耐压测试
  - 结果：厂家 A 热阻达标但压降超标 15%；厂家 B 全部达标
  - 交期：厂家 A 准时到货 80%；厂家 B 100%

评估结论：
  - 厂家 B 纳入 AVL，开始下一批量产前样品确认
  - 厂家 A 保持观察，要求改善后再次送样
```

**关键要点**：

- 潜在合作采购的核心产出不是「这批货」，而是 **供应商评估报告**
- 试单的批次数量要足够判断稳定性（通常 ≥ 3 批）
- **不要向供应商隐瞒评估意图**——反而要明确告知这是试单，以便观察其真实配合度

### 11.3 长期例行合作采购

**定义**：与已认证的供应商建立长期合作关系，按约定规则自动或半自动执行采购流程。

**特征**：

- 供应商已纳入 AVL（Approved Vendor List）
- 有框架协议约束价格/条款/交期
- 采购流程标准化（系统下单，不需要每次审批）
- 定期绩效评估（季度/年度）

**长期例行合作的形态**：

| 形态 | 绑定程度 | 典型场景 | 管理方式 |
|:-----|:---------|:---------|:---------|
| **框架协议** | 中 | 内存/SSD/PCB 按月下单 | 品类经理负责年度谈判，研发按需下单 |
| **VMI (供应商管理库存)** | 高 | 标准件/包材 | 供应商设仓库在厂区附近，按消耗补货 |
| **JIT/JIS** | 高 | 大型结构件/机箱 | 按生产排程准时到线，不设库存 |
| **战略合作** | 极高 | GPU/CPU/HBM | 高层对接+联合研发+产能锁定 |
| **自动补货** | 中 | MRO/辅料 | 系统按设定的最低库存自动生成 PO |

**长期例行合作的管理节奏**：

```text
每天/每周：
  +-- 按预测/订单在系统内下 PO
  +-- 交期跟踪（系统自动+采购员逐单确认）
  +-- 到货验收（IQC 抽检或免检）

每月：
  +-- 对账（PO->收货单->发票 三单匹配）
  +-- 滚动预测（更新未来 3 个月需求）
  +-- 质量月报（来料 PPM + 产线退料）

每季度：
  +-- 价格谈判（按框架协议条款调整价格）
  +-- 绩效评分（QCDS 评估）
  +-- 异常回顾（质量问题/交期问题 8D 关闭）

每年：
  +-- 年度合同续签/重新招标
  +-- 供应商现场审核（QSA/QPA 复评）
  +-- 战略回顾（合作方向/技术路线图对齐）
```

### 11.4 关系生命周期管理

采购关系不是静态的，会经历完整的生命周期：

```text
+---------------------------------------------------------+
|                    供应商生命周期                        |
|                                                         |
|  寻源 -> 准入 -> 试单 -> 常态合作 -> 深度绑定 -> 衰退 -> 退出 |
|   |       |       |       |         |       |       |   |
|   搜索    审核    小批量  框架协议  战略合作  份额减少  淘汰 |
|   |       |       |       |         |       |       |   |
|   潜在合作期 <----> | <----> 长期例行期 <----> | <----> 退出期  |
+---------------------------------------------------------+
```

**每个阶段的核心管理动作**：

| 阶段 | 核心动作 | 周期 | 关键风险 |
|:-----|:---------|:-----|:---------|
| **寻源** | 市场扫描、比对初步方案 | 持续进行 | 信息过时/渠道单一 |
| **准入** | 资质审核、QSA 审核、样品确认 | 2-4 周 | 审核走过场 |
| **试单** | 小批量订单、质量验证、服务评估 | 4-12 周 | 试单太松导致正式合作后问题频发 |
| **常态合作** | 框架协议下按订单执行、月度评估 | 持续 | 例行化管理导致关系退化 |
| **深度绑定** | 联合研发、产能锁定、高层互访 | 持续 | 依赖度过高，切换成本上升 |
| **衰退** | 份额下降、新供应商引入 | 按需 | 被动衰退（供应商出问题前没预警） |
| **退出** | 收尾订单、知识产权归还、模具返还 | 4-12 周 | 退出流程不完整导致后续纠纷 |

**服务器研发中的关系转移实例**：

```text
案例：某电源模块供应商的关系生命周期

阶段 ① 寻源（T-12 月）：
  - 新项目需要 3kW+ 高效率电源模块
  - 市场调研发现一家台湾厂商 G，技术指标领先

阶段 ② 准入（T-10 月）：
  - 资质审核通过，现场审核通过
  - 送样 10 只做初步测试

阶段 ③ 试单（T-8 月 ~ T-6 月）：
  - 小批量采购 100 只，在 EVT 样机中测试
  - 效率达标、EMC 通过、交期 OK -> 纳入 AVL

阶段 ④ 常态合作（T-6 月 ~ T+12 月）：
  - 签署年度框架协议，价格锁定
  - 每月按 BOM 需求下 PO，月均 2,000 只

阶段 ⑤ 深度绑定（T+12 月 ~ T+36 月）：
  - 下一代产品联合设计（JDM 模式）
  - 厂商 G 获得下一代电源项目的独家设计权
  - 高层建立直接对话通道

阶段 ⑥ 衰退（T+36 月 ~ T+48 月）：
  - 国产电源厂商已能提供同等性能方案
  - 厂商 G 价格不降，份额开始转移
  - 保持 40% 份额，逐步下调

阶段 ⑦ 退出（T+48 月 ~ T+52 月）：
  - 最后一批订单交付完成
  - 已签署的设计图纸和 IP 做交接
  - 开模费用清算，模具返还或买断
```

### 11.5 三大关系类型的决策逻辑

```text
本次采购需求 -> 评估未来是否还会需要 ->
  |
  +- 不会（一次性/极偶发）-> 一次性交易采购
  |   +- 最简流程：在线下单、P-Card、单次合同
  |
  +- 可能会（有潜在合作价值）-> 潜在合作采购
  |   +- 评估流程：供应商筛选 -> 试单 -> 评估 -> 决定是否升级
  |
  +- 一定会（持续需求）-> 长期例行合作
      +- 直接走已有框架协议，如无则启动寻源流程
```

**服务器研发的典型对应**：

| 关系类型 | 占比（按金额） | 典型物料/服务 | 管理重心 |
|:---------|:-------------|:--------------|:---------|
| 一次性交易 | ~5% | 极少数样品、一次性认证、二手设备 | 流程简洁+避免风险 |
| 潜在合作 | ~10% | 新替代料验证、新服务商评估、国产替代 | 评估准确性+试单设计 |
| 长期例行合作 | ~85% | GPU/CPU/内存/SSD/PCB/EMS/框架协议物料 | 成本优化+供应保障 |

## 12. 采购成本管控与出账体系

采购不等于「花钱」——同样一笔支出，是 **费用还是成本？是 CAPEX 还是 OPEX？走项目预算还是部门预算？** 这些会直接影响财务处理和盈利核算。

### 12.1 费用 vs 成本：本质区别

这是采购中最基本也最容易混淆的概念：

| 概念 | 定义 | 会计处理 | 服务器研发举例 |
|:-----|:------|:---------|:--------------|
| **费用（Expense）** | 当期消耗、不形成实物资产的支出 | 计入当期损益（利润表） | 研发人员工资、测试服务费、认证费、云资源消耗 |
| **成本（Cost）** | 构成产品实体的支出 | 计入存货（资产负债表），随销售结转为营业成本 | BOM 物料的采购价、NRE 分摊、运输费 |

**一句话区分**：**成本进了产品，费用花了就没了**。

### 12.2 CAPEX vs OPEX：资本化 vs 费用化

这是另一个关键区分维度：

| 支出类型 | 含义 | 会计处理 | 审批流程 | 服务器研发举例 |
|:---------|:-----|:---------|:---------|:--------------|
| **CAPEX**（资本性支出） | 购买长期资产（使用寿命 > 1 年） | 固定资产入账，按折旧期分摊 | 严格（通常需 VP/CFO 审批） | ¥50 万示波器、¥200 万 EMC 暗室、¥10 万仿真服务器 |
| **OPEX**（运营支出） | 日常运营消耗 | 当期费用化 | 较宽松（部门预算内审批） | 每月¥5 万测试用云资源、¥2 万/次认证费、BOM 物料成本 |

**CAPEX vs OPEX 的采购影响**：

```text
同一个东西，不同的用法可能导致不同的财务处理：

场景 1：买一台电子负载
  自用 -> CAPEX（固定资产，¥8 万，分 5 年折旧）
  租用 -> OPEX（租赁费，¥2,000/月，当月费用化）

场景 2：购买 EDA 工具
  买断永久授权（¥50 万）-> CAPEX（分 5 年摊销）
  年度订阅（¥12 万/年）-> OPEX（当年费用化）

场景 3：开发用 FPGA 开发板
  用完可复用 -> CAPEX（¥3 万，固定资产）
  用完废弃 -> OPEX（低值易耗品，一次性费用）

财务偏好（企业视角）：
  +-- 盈利好的时候 -> 偏好 CAPEX（抵税+资产积累）
  +-- 盈利压力大 -> 偏好 OPEX（灵活+不占资产负债表）
```

### 12.3 预算管理

采购必须受预算约束——问题是谁的预算、什么预算。

**服务器研发中涉及的预算类型**：

| 预算类型 | 覆盖范围 | 负责主体 | 典型金额（年） | 审批层级 |
|:---------|:---------|:---------|:--------------|:---------|
| **项目研发预算** | NPI 项目（从概念到 PVT）的全部研发支出 | 项目经理/研发总监 | ¥500万-5,000万 | CTO / 产品线 VP |
| **量产 BOM 预算** | 量产阶段物料采购支出 | 品类经理/产品经理 | ¥5亿-50亿 | CPO / 事业部总经理 |
| **部门运营预算** | 研发部门的日常运营（测试设备/工具/差旅/培训） | 部门经理 | ¥100万-500万 | 研发 VP |
| **战略储备预算** | 用于突发机会/应急（如 GPU 锁价备货） | CPO / CFO | ¥1,000万-1亿 | CFO / CEO |
| **CAPEX 预算** | 固定资产采购（仪器/设备/软件买断） | 各业务部门 | ¥200万-2,000万 | CFO / 资本委员会 |

**预算与采购的对应关系**：

```text
                    +-------------+
                    |  年度预算   |
                    |  (计划阶段)  |
                    +------+------+
                           |
                    +------v------+
                    |  预算分解   |
                    |  项目预算    |
                    |  部门预算    |
                    |  CAPEX预算   |
                    +------+------+
                           |
              +------------+------------+
              |            |            |
        +-----v-----+ +---v----+ +---v------+
        | 研发样机   | | 量产BOM | | 测试设备  |
        | 使用项目预算| | 使用量产| | 使用CAPEX |
        | 费用化     | | 成本化  | | 预算      |
        +-----------+ +--------+ +----------+
```

**预算不足时的应对策略**：

```text
预算不够 -> 方案优先级排列（按 IRR/ROI 排序）
  +- 必须做的（影响项目进度的）：申请追加预算
  +- 可以推后的（优化非瓶颈）：排入下期
  +- 可以改方案的（降级替代）：换更便宜的方案/租代替买

服务器研发实例：
  需求：买一台 ¥300 万的 32GHz 示波器
  预算：CAPEX 只剩 ¥150 万
  方案：
    - 短期：租用（¥8 万/月，用 3 个月应付当前项目）✓
    - 中期：买一台 ¥150 万的 20GHz 配置（不急用 32GHz）✓
    - 长期：申请下年 CAPEX 预算补足高端配置 ✓
```

### 12.4 成本归属：项目费用化 vs 产品成本化

这是服务器研发采购中最微妙也最常被问到的会计问题：

```text
研发阶段采购的物料 -> 到底算「项目费用」还是「产品成本」？

规则（以一般会计准则为例）：

+-------------------------------------------------+
|            研发样机物料 -> 费用化                 |
|               （记入研发费用）                    |
+-------------------------------------------------+
|              量产 BOM 物料 -> 成本化              |
|          （记入存货，随销售结转为成本）             |
+-------------------------------------------------+
|         研发样机->转为量产销售 -> 成本化            |
|               （从研发费用转出）                   |
+-------------------------------------------------+
```

**服务器研发各阶段的成本归属**：

| 阶段 | 采购内容 | 会计处理 | 出账路径 |
|:-----|:---------|:---------|:---------|
| **EVT 样机物料** | ES CPU/GPU/少量 DDR5/PCB 打样 | ✅ 研发费用（费用化） | 项目号 R&D-XXX |
| **DVT 样机物料** | QS GPU/工程样片/小批量 BOM | ✅ 研发费用（费用化） | 项目号 R&D-XXX |
| **PVT 试产物料** | 正式量产物料 | ⚠️ 存货（成本化），若试产机作废则转回费用 | 存货科目→试产报废转费用 |
| **MP 量产物料** | 全 BOM 量产物料 | ✅ 存货（成本化） | 存货 → 销售成本 |
| **测试认证费用** | UL/FCC/CE 认证费 | ✅ 费用化（研发费用） | 项目号 R&D-XXX |
| **测试设备** | 示波器/温箱/逻辑分析仪 | ✅ 资本化（CAPEX，按年折旧） | 固定资产科目 |
| **开发工具 License** | EDA/仿真软件年费 | ✅ 费用化（研发费用） | 部门预算 |
| **NRE（一次性工程费）** | EMS 开模费/夹具费 | ⚠️ 可资本化（与量产挂钩）或费用化 | 视会计准则和分摊方式而定 |

**实操中的常见争议与处理**：

```text
争议 1：EVT 样机做完后卖掉怎么办？
  处理：样机销售收入冲减研发费用（净额法）

争议 2：DVT 阶段的 SSD 和内存，后续可量产用吗？
  处理：如果可以用于量产机，转入存货科目（成本化）
  关键判断：DVT 和量产间隔时间不宜过长（> 6 个月可能导致库存老化）

争议 3：PVT 试产产生的 50 台样机怎么处理？
  处理：
    +-- 送客户验证 -> 费用化（销售费用或研发费用）
    +-- 内部测试使用 -> 费用化（研发费用）
    +-- 转为正式销售 -> 成本化（存货结转）

争议 4：NRE 开模费 ¥50 万，怎么算？
  处理方案 A：全款费用化（简单，适合小规模 NRE）
  处理方案 B：按量产数量分摊 ¥5/台（成本化，适合大批量）
  处理方案 C：50% 费用化 + 50% 分摊（折中方案）
  选择依据：① 会计准则规定；② 量产的确定性；③ 财务政策偏好
```

### 12.5 出账流程

**出账**（Cost Allocation / Charging）是指采购支出如何分配到不同的成本中心、项目或产品线。

**出账的基本路径**：

```text
采购支出 -> PO 生成 -> 到货验收 -> 发票校验 -> 财务入账
                                          |
                                    +-----+------+
                                    |             |
                              +-----v----+  +-----v----+
                              | 自动出账   |  | 手工分摊   |
                              |           |  |           |
                              | 采购订单上 |  | 先记入某帳 |
                              | 指定了成   |  | 户，月末   |
                              | 本中心/项  |  | 按比例分   |
                              | 目号      |  | 摊到各成本 |
                              +----------+  +----------+
```

**服务器研发中的出账实例**：

```text
实例 1：B300 GPU 采购出账

PO 信息：
  物料：NVIDIA B300 GPU × 500 pcs
  单价：¥240,000/pcs
  总金额：¥1.2 亿
  用途：量产 BOM

出账方式：
  +- 成本中心：量产 BOM（默认）
  +- 存货科目：原材料-芯片
  +- 不涉及部门预算

实例 2：同一批 B300 GPU，其中 10 颗给
     研发部门做下一代平台验证

出账方式：
  +- 10 pcs × ¥240,000 = ¥240 万
  +- 从存货中转出 -> 研发费用
  +- 成本中心：R&D-XXX（项目号）
  +- 归属项目：下一代 GPU 平台预研项目

实例 3：测试设备租赁费

PO 信息：
  内容：Agilent 示波器租赁 3 个月
  金额：¥24 万（¥8 万/月）
  使用者：硬件部 + 信号完整性组

出账方式：
  +- 初始 PO 挂某个成本中心A
  +- 月末按使用比例分摊
      +- 硬件部 60% -> ¥14,400/月
      +- SI 组 40% -> ¥9,600/月
  +- 出账依据：设备使用日志
```

### 12.6 预算执行监控

采购的核心管控环节之一是 **「有没有预算」**：

```text
需求发起 -> 预算检查 ->
  |
  +- 有预算且余额充足 -> 继续采购流程
  |
  +- 有预算但余额不足 -> 预算调整（从其他项目挪用/申请追加）
  |
  +- 无预算 ->
      +- 紧急采购 -> 先执行后走预算追加（需 VP+ 审批）
      +- 非紧急 -> 暂停，进入下期预算计划
```

**预算执行率的监控指标**：

| 指标 | 定义 | 目标参考 |
|:-----|:------|:---------|
| **预算执行率** | 已支出/已承诺 / 年度总预算 | 按进度均衡（月均 ~8.3%） |
| **预算偏差率** | (实际支出 - 预算) / 预算 | ±5% 以内 |
| **预算超支项目占比** | 超出预算 10% 以上的项目比例 | < 10% |
| **预算外采购占比** | 无预算的采购金额 / 总采购金额 | < 2% |
| **CAPEX 预算利用率** | 实际 CAPEX 支出 / 获批 CAPEX 预算 | 80-100% |

**服务器研发特有的预算管理实践**：

```text
痛点：研发项目经常面临「预算年初定、需求年中变」的困境
  - 年初计划做 A 项目，年中发现 B 项目更紧急
  - GPU 突然涨价 20%，BOM 预算不够
  - 客户要求新增认证测试，之前没预算

应对机制：
  ① 预算弹性：预留 10-15% 的预算池用于应对变化
  ② 季度预算刷新：每季度调整一次预算分配
  ③ 预算跨项目调配：经 VP 审批，允许项目间 10% 以内挪动
  ④ 超预算流程：>10% 需 VP 审批，>30% 需 CFO 审批
```

## 13. 选型与比价机制

选型和比价是采购活动中的核心决策环节——决定了成本基线和供应商格局。

### 13.1 供应商选择的三阶段评估

不应把选型等同于「比价格」。完整的供应商选择应是三阶段递进：

```text
第一阶段：技术筛选（Technical Screening）
  目的：确定哪些供应商能满足需求规格
  方法：
    +-- 技术规格对标：看产品指标是否满足要求
    +-- 样品测试：送样验证（研发进行功能/性能/可靠性测试）
    +-- 技术方案评审：评估技术路线是否合理
    +-- 兼容性评估：是否与现有系统兼容

  输出：技术合格供应商名单（Shortlist）
  标准：不满足技术要求的淘汰，满足的进入下一轮

第二阶段：商务评估（Commercial Evaluation）
  目的：在技术合格供应商中比较高性价比
  方法：
    +-- 价格对比（含总持有成本 TCO）
    +-- 付款条件对比（账期/预付比例/保函）
    +-- 交期和产能对比（Lead Time / Capacity）
    +-- 服务水平对比（技术支持的响应/SLA）

  输出：商务评分 + 推荐排序

第三阶段：综合决策（Final Decision）
  目的：综合考虑技术和商务，加上战略因素做出最终选择
  考虑因素：
    +-- 技术与商务评分加权汇总
    +-- 供应商战略地位（是否已有合作关系）
    +-- 供应安全（单一来源风险 / 地缘政治 / 制裁）
    +-- 替代方案可行性（自己造 / 换方案 / 找其他供应商）
    +-- 长期布局（是否有助于培养竞争格局）

  输出：选定供应商 + 理由记录
```

### 13.2 比价数量策略：找几家合适？

**基本原则**：要能形成有效竞争，但不要让供应商觉得「白费功夫」。

**比价数量指南**：

| 采购类型 | 建议询价数量 | 理由 |
|:---------|:------------|:------|
| **战略物料/大额采购** | 3-5 家 | 需要充分竞争+供应商投入意愿高 |
| **常规物料/中等金额** | 3 家 | 3 家足以形成竞争，再多边际效用递减 |
| **小额采购** | 2-3 家 | 简单比价即可，不用太复杂 |
| **单一来源** | 1 家 | 无需比价（但要做价格合理性分析）|
| **紧急采购** | 1-2 家 | 时效优先，事后补流程 |
| **首次合作的潜在供应商** | 3-5 家 | 需要足够的样本评估供应商能力 |

**为什么通常是「3 家」**？

```text
最少 2 家 -> 可以比价但容易串通（A 和 B 合谋抬高）
3 家       -> 形成三角竞争，串通难度增加
4-5 家     -> 竞争更充分，但供应商准备成本高（可能不愿参与）
6 家+      -> 边际收益递减，管理成本上升

实践经验：大额采购（¥100 万+）建议 4-5 家，常规采购 3 家即可。
```

**供应商数量的反面教训**：

```text
情况 1：只找 1 家询价
  问题：没有竞争参照，容易被报高价
  补救：即使只有 1 家可用，也要做「虚拟比价」
    - 成本拆解：材料费+加工费+管理费+利润 = 合理价格
    - 历史价格对比：去年同产品价格走势
    - 公开市场价格：参考市场行情（如 DRAMeXchange 价格）

情况 2：找 10 家询价
  问题：
    - 供应商准备报价花时间，质量低（敷衍了事）
    - 后续评标工作量巨大
    - 供应商知道竞标者多，不愿报实价（预留砍价空间）
    - 下次再找他们，响应意愿降低

情况 3：每次都找同一批供应商
  问题：长期合作的供应商可能形成「默契报价」
  应对：每 1-2 年引入 1-2 家新供应商参与比价
```

### 13.3 综合评分模型

比价不是单纯的「价低者得」。技术复杂度越高，评分的维度越丰富。

**通用评分模型**：

```text
总分 = 技术评分 × 权重T + 商务评分 × 权重B

典型权重分配（按采购类别）：

  +-----------------------+----------+----------+----------+
  |      采购类别          | 技术权重 | 商务权重 | 服务权重  |
  +-----------------------+----------+----------+----------+
  | 核心芯片（GPU/CPU）     |   50%    |   35%    |   15%    |
  | 关键模组（电源/散热）    |   40%    |   45%    |   15%    |
  | 通用器件（电阻/电容）    |   20%    |   70%    |   10%    |
  | EMS 制造服务            |   30%    |   50%    |   20%    |
  | 软件/工具              |   35%    |   45%    |   20%    |
  | 认证/测试服务           |   40%    |   40%    |   20%    |
  +-----------------------+----------+----------+----------+
```

**服务器研发的选型评分卡示例（以电源模组为例）**：

```yaml
评分卡：服务器电源模组供应商选择

技术评分（权重 40%）：
  效率（80Plus 等级）     30分  金牌=20, 铂金=25, 钛金=30
  功率密度（W/inch³）    25分  >100=25, >80=20, >60=15
  纹波/噪声              20分  <50mV=20, <100mV=15, <150mV=10
  保护功能               15分  OVP/OCP/OTP/UVLO 各4分
  认证完备性             10分  齐全=10, 缺1项=7, 缺2项=4

商务评分（权重 45%）：
  单价（¥/W）            30分  最低价满分，其余按比例
  账期                   20分  >90天=20, 60天=15, 30天=10
  NRE 费用              15分  没有=15, ¥5万内=10, ¥10万=5
  Lead Time             15分  <4周=15, <6周=10, <8周=5
  年降价承诺             20分  >5%=20, >3%=15, >1%=10

服务评分（权重 15%）：
  技术支持响应            30分  4小时=30, 24小时=20, 48小时=10
  本地 FAE 覆盖          25分  有本地团队=25, 只有远程=10
  质保期                 25分  >5年=25, 3年=15, 1年=5
  备品备件               20分  有本地备件库=20, 需调货=10

评分结果示例：
  供应商 A：技术(38)+商务(40)+服务(13) = 91
  供应商 B：技术(35)+商务(38)+服务(12) = 85
  供应商 C：技术(40)+商务(32)+服务(14) = 86
  → 推荐供应商 A
```

### 13.4 技术-商务分离原则

**核心原则**：评估技术和评估商务的人必须分离，防止「技术按商务倾向打分」或反过来。

```text
技术团队：
  - 只评估「能不能用」——规格达标、质量可靠、技术方案合理
  - 不知道价格信息（甚至不知道哪些供应商在竞标）
  - 输出：技术评分，标注达标/不达标

采购/商务团队：
  - 只评估「合不合算」——价格、账期、交期、服务条款
  - 知道所有供应商的价格信息
  - 输出：商务评分，含比价分析

综合决策：
  - 技术和商务分开评分后，由采购委员会综合决策
  - 决策依据：总分 + 战略因素
```

**为什么技术-商务必须分离**？

```text
案例：某 PCB 厂商选型

技术团队（开发部）的天然倾向：
  - 倾向技术最强的供应商（深南电路），因为技术方案最成熟
  - 但深南报价比沪电高 30%

如果技术和商务一起评：
  - 技术可能「技术分给高理由」让深南中标
  - 实际根本不需要那么高的技术水平

分离后的正确决策：
  - 技术：深南=95 沪电=90 -> 均达标
  - 商务：深南=70 沪电=95 -> 沪电显著领先
  - 综合：沪电中标 ✓

正确与否的关键问题：
  「深南多出的 5 分技术能力，是否值得多花 30% 的成本？」
  如果答案是肯定的（如 PCIe 6.0 信号完整性只有深南能做），
  经过综合评审也可以选深南——但需要明确的理由记录。
```

### 13.5 框架协议下的下单约束

框架协议签署后并非「随便下单」，仍有约束机制：

```text
框架协议的核心约束：

1. 价格约束
   - 只能按协议约定的价格下单
   - 如需变动价格，须走价格变更流程（季度调价或市场联动）

2. 份额约束
   - 如有多家供应商，约定份额分配比例
   - 典型分配：7:3（主供:次供）、6:3:1（主供:次供:备用）
   - 份额可定期调整（基于绩效评估）

3. 品类约束
   - 框架协议覆盖哪些品类（不可越界）
   - 如新品类加入，需要补充协议

4. 金额约束
   - 单笔订单上限（如 ≤ ¥500 万/单）
   - 月/季度下单总量（不能超过协议约定的产能预留）

5. 下单前置条件
   - 研发确认：物料在 AVL 中且状态有效
   - 质量确认：IQC 基准书已签核
   - 预算确认：有足够预算余额
```

## 14. 物料编码与供应商管理体系

采购活动的基础设施是 **编码体系**——让每个物料和每个供应商都有唯一标识，可追踪、可分析、可管控。

### 14.1 物料编码体系

**物料编码（Part Number / Material Code）** 是采购管理的「身份证」。没有编码的物料无法进入系统，也就无法下单、收货、核算。

**服务器 BOM 物料编码的典型结构**：

```text
+---------------------------------------------------------+
|                     物料编码结构                          |
|                                                         |
|   XXX - XXXX - XXXXXX - XXX                              |
|    |       |       |        |                             |
|    |       |       |        +- 版本号（001/002...）        |
|    |       |       |                                      |
|    |       |       +- 顺序号（000001-999999）              |
|    |       |                                              |
|    |       +- 品类代码（如 CHIP=芯片, MODU=模组, PCB=板卡） |
|    |                                                      |
|    +- 物料大类（E=电子, M=机械, P=包材, S=软件, ...）      |
+---------------------------------------------------------+

示例：
  E-CHIP-300256-001  -> 电子类·芯片·NVIDIA B300 GPU（版本 1）
  E-MODU-400178-002  -> 电子类·模组·Delta 3kW PSU（版本 2）
  M-PCBA-200345-001  -> 机械类·PCBA·AI 服务器主板（版本 1）
  S-LICN-100567-001  -> 软件类·License·AMI BIOS 授权（版本 1）
```

**物料编码的管理原则**：

```text
原则 1：一物一码
  - 同一供应商的同一型号 = 一个编码
  - 不同供应商的兼容品 = 不同编码（方便追踪来源）
  - 同一物料的不同版本 = 不同编码（版次管理）

原则 2：编码即元数据
  - 从编码可以追溯品类、供应商、版本
  - 但不能「含义过载」——编码太复杂反而难以维护

原则 3：编码由系统自动生成
  - 人工编码容易出错（重复/冲突/不规范）
  - 在 ERP/PLM 系统中申请，系统分配唯一码

原则 4：编码生命周期管理
  +-- 创建：新物料引入时分配编码
  +-- 激活：可用于采购/生产的编码
  +-- 冻结：已停用但仍有库存的编码（不可新采购，可用库存）
  +-- 废弃：彻底停用的编码（超 2 年无交易记录的定期清理）
```

**服务器研发中的编码管理实例**：

```text
场景：引入一颗新的国产 SSD（替代 Samsung PM9A3）

流程：
  1. 研发确认规格 -> 在 PLM 系统中申请新物料编码
  2. 填入物料信息：
     物料类型：电子-存储
     供应商：YANGTZE（长江存储）
     型号：PC411-2TB
     封装：M.2 2280
     替代关系：替代 Samsung PM9A3（E-STOR-200345）
     编码自动生成：E-STOR-300788-001
  3. 审批流程：研发经理 -> 品类经理 -> 物料数据管理员
  4. 分配后进入 AVL，通知采购和 ERP 系统同步
```

### 14.2 供应商编码与分级

供应商也有编码——这是采购关系管理的基础。

**供应商编码结构**：

```text
V - XXXXXX - XX
|    |       |
|    |       +- 地区代码（CN/US/JP/TW/...）
|    |
|    +- 顺序号（000001-999999）

示例：
  V-300456-CN  -> 深南电路（中国）
  V-400178-TW  -> Delta（台湾）
  V-500234-US  -> NVIDIA（美国）
```

**供应商分级体系**：

```text
L1 - 战略级（Strategic Partner）
  - GPU/CPU/HBM 原厂、EMS 主力供应商
  - 高层互访 + 联合研发 + 信息共享
  - 每年 ≥ 2 次高层会议

L2 - 核心级（Preferred Supplier）
  - 关键模组供应商（电源/散热/PCB/SSD）
  - 签署框架协议 + 年度谈判
  - 每季度绩效评估 + 每年现场审核

L3 - 常规级（Approved Supplier）
  - 通用器件供应商（电容/电阻/连接器）
  - 框架协议或报价单
  - 年度绩效评估，每 2 年现场审核

L4 - 交易级（Transactional Supplier）
  - 备品备件、一次性服务、小额供应商
  - 按单次交易管理
  - 无需现场审核

L5 - 观察级（Probationary）
  - 新引入的供应商（潜在合作阶段）
  - 试单期内，限制交易金额
  - 完成试单评估后升级或淘汰
```

**供应商编码与分级的应用**：

```text
系统层面：
  - 下单时：只有 AVL 中的编码才能生成 PO
  - 价格管控：不同级别对应不同的价格审批流程
      L1 级：品类经理可审批
      L2 级：品类经理可审批
      L3/L4 级：采购主管可审批
  - 质量管控：不同级别对应不同的 IQC 抽检比例
      L1 级：免检或减量抽检（AQL=0.1）
      L2 级：正常抽检（AQL=0.4）
      L3 级：加严抽检（AQL=1.0）
      L4/L5 级：全检或 AQL=2.5
```

### 14.3 采购责任人制度

每个核心物料和供应商都必须有明确的 **责任人**——不能出现「没人管」的情况。

**服务器研发采购的双责任人制度**：

```yaml
双责任人制度：

采购负责人（Sourcing Owner）：
  - 角色：品类经理 / 采购主管
  - 职责：
    · 供应商谈判和合同管理
    · 价格和条款管理
    · 供应商绩效评估
    · 供应风险监控
    · 新供应商引入
  - 对接对象：供应商销售/客户经理

技术负责人（Technical Owner）：
  - 角色：研发工程师 / 技术专家
  - 职责：
    · 技术规格定义和确认
    · 样品验证和测试
    · 质量异常技术分析
    · 替代料技术评估
    · 版本/变更管理
  - 对接对象：供应商 FAE / 研发工程师
```

**供应商关系维护的例行动作**：

| 频率 | 采购负责人（商务侧） | 技术负责人（技术侧） |
|:-----|:--------------------|:--------------------|
| **每周** | 订单交期跟踪、紧急协调 | 质量异常处理、技术问题解答 |
| **每月** | 对账、价格确认、月度绩效回顾 | 样品测试进展同步 |
| **每季度** | 季度谈判、价格调整、份额评估 | 季度技术交流、roadmap 对齐 |
| **每半年** | 供应商现场审核 | 联合技术研讨会 |
| **每年** | 年度合同续签、战略会议 | 技术路线图对齐会议 |

### 14.4 供应商关系危机的处理

当合作出现问题，需要有明确的升级和处置机制：

```text
供应商问题 -> 认定问题级别 ->

级别 1（轻微）：
  问题：交期延迟 1-3 天 / 来料 PPM 轻微超标
  处理：采购负责人与供应商直接沟通
  时效：24 小时内响应

级别 2（中等）：
  问题：交期延迟 1 周+ / 批次性质量不良 / 价格单方面调整
  处理：采购负责人 + 品类经理介入
  时效：48 小时内给出解决方案

级别 3（严重）：
  问题：断供风险 / 重大质量事故 / 合规违规
  处理：CPO 介入 + 启动应急替代方案
  时效：立刻响应

级别 4（致命）：
  问题：供应终止 / 强制停供 / 直接客户项目产生严重影响
  处理：VP+ 高层级介入 + 紧急替代供应商启动
  时效：立即，不计成本
```

## 15. 采购廉洁与反腐败

采购是公司腐败风险最高的领域之一——手握供应商选择权和定价权，利益诱惑巨大。建立系统性的廉洁机制是采购管理的底线要求。

### 15.1 利益冲突申报

**核心原则**：任何可能影响采购决策公平性的个人利益关系，必须主动申报。

**需要申报的利益冲突场景**：

```text
关系冲突：
  - 采购人员/决策人直系亲属在候选供应商任职
  - 采购人员/决策人持有候选供应商股份（上市公司 > 5% 需申报）
  - 与供应商员工存在私人借贷、合伙经营关系

利益冲突：
  - 供应商提供的任何个人馈赠（现金/礼品/购物卡）
  - 接受供应商宴请（超过公司规定标准，如单次 > ¥200）
  - 供应商承担个人差旅/娱乐费用
  - 供应商为采购人员提供个人服务（装修/代购/子女教育等）

任职冲突：
  - 离职员工在供应商处任职（冷却期通常 1-2 年）
  - 前供应商员工刚入职本公司并负责原供应商业务
```

**利益冲突的管理流程**：

```text
每年年初：全员签署《利益冲突声明》
  +- 列出：本人及直系亲属的关联企业/持股情况

采购项目前：参与决策人员主动声明
  +- 发现冲突 -> 主动回避（不参与该供应商的决策）
  +- 未申报被发现 -> 纪律处分

离职/入职：
  +- 离职员工去供应商 -> 与原公司的采购业务冷却期 ≥ 1 年
  +- 前供应商员工入职 -> 不能负责原供应商的采购业务 ≥ 2 年
```

### 15.2 「从友商处购买」的腐败风险

用户特别提到这一点——这是服务器行业采购中一个非常敏感的问题。

**为什么「从友商处购买」要特别警惕**：

```text
友商 = 直接竞争对手
从竞争对手处购买 -> 潜在的合规/腐败风险链：

风险 1：信息泄露
  - 友商通过供货了解你的产品规格、BOM 结构、采购量
  - 你的技术规划（Roadmap）可能在供货谈判中被动暴露

风险 2：利益绑定
  - 如果你从友商采购核心部件，友商的定价策略会直接影响你的成本
  - 友商可能通过供货价格控制你的利润空间
  - 双方可能形成「你中有我、我中有你」的复杂利益关系

风险 3：滋生腐败
  - 友商之间的采购容易绕过正常比价流程（「都是兄弟公司，不用比了」）
  - 采购人员可能利用关系获得个人利益（回扣/返点/安排亲属入职）
  - 内部+外部两条线勾结，审计难度极大

风险 4：竞争法风险
  - 在某些司法管辖区，竞争对手之间的交易可能被审视为垄断行为
  - 价格信息共享可能被视为价格合谋的证据
```

**如何应对「友商交易」**：

```yaml
控制原则：
  ① 一般性原则：优先从非竞争关系的供应商采购
  ② 如必须从友商采购（如 GPU 只有 NVIDIA 一家），需满足：
     - 公开透明的比价流程（不能因为是友商就跳过）
     - 采购人员与友商销售不得有个人关系
     - 交易信息严格限制在采购和法务范围内
     - "Chinese Wall"（防火墙）——技术团队不参与友商采购谈判
  ③ 绝对禁止：
     - 与友商共享客户信息、定价策略、产品路线图
     - 通过友商采购来规避正常采购流程
     - 个人接受友商的任何形式的利益输送
```

**服务器研发中「友商采购」的真实案例**：

```text
场景：公司A（服务器厂商）从公司B（另一家服务器厂商）
     采购定制化的 AI 服务器机箱

审查要点：
  - 公司B 是否有独立的机箱制造业务？还是转卖自己的剩余产能？
  - 公司A 的研发团队是否在交易中接触了公司B 的整机设计？
  - 采购价格是否经过比价？还是「既然是兄弟公司就按市场价」？

合规要求：
  ✓ 需法务审核采购合同，标注为「竞争敏感交易」
  ✓ 采购对接人员不与公司B 的销售团队有个人交往
  ✓ 价格必须经过第三方成本分析验证
  ✓ 交易信息不定期接受内部审计
  ✗ 禁止：研发工程师私下与公司B 的技术团队讨论产品规划
```

### 15.3 防火墙机制

**防火墙（Chinese Wall / Segregation of Duties）** 是防止采购腐败的核心制度设计。

**采购流程中的职责分离**：

```text
           +---------------------+
           |   需求发起（研发）    |
           |   提出采购需求       |
           +----------+----------+
                      |
           +----------v----------+
           |   供应商选择（采购）  |
           |   寻源·比价·评估     |
           +----------+----------+
                      |
           +----------v----------+
           |   价格谈判（品类经理） |
           |   锁定价格和条款     |
           +----------+----------+
                      |
           +----------v----------+
           |   下单执行（采购执行） |
           |   在框架协议下下单   |
           +----------+----------+
                      |
           +----------v----------+
           |   验收确认（研发/质量）|
           |   确认到货和品质     |
           +----------+----------+
                      |
           +----------v----------+
           |   付款（财务/应付）   |
           |   三单匹配后付款     |
           +---------------------+
```

**四个必须分离的岗位**：

```text
岗位分离一刀切规则：

① 选供应商的人 ≠ 价格谈判的人
   - 供应商筛选由品类经理负责
   - 价格谈判由采购主管或 CPO 负责
   - 防：品类经理与供应商达成「默契」

② 下单的人 ≠ 验收的人
   - PO 由采购执行团队发出
   - 实物验收由研发/质量团队签收
   - 防：虚假到货/虚报数量

③ 验收的人 ≠ 付款审批的人
   - 验收确认由使用部门完成
   - 付款申请由采购或使用部门发起
   - 付款审批由财务负责
   - 防：虚假验收骗取付款

④ 预算审批的人 ≠ 采购执行的人
   - 预算审批由预算委员会/VP 负责
   - 预算内的采购由采购团队执行
   - 防：突破预算限制的采购
```

### 15.4 采购审计与追溯

**采购审计**不是「查账」——而是系统性检查采购活动是否合规、高效、可追溯。

**审计覆盖的主要领域**：

```text
1. 合规审计（每半年）
   +-- 是否经过必要的审批流程？
   +-- 是否进行了竞争性比价？
   +-- 单一来源采购是否有合理理由？
   +-- 利益冲突声明是否签署？

2. 价格审计（每季度）
   +-- 实际采购价格 vs 框架协议约定价格 -> 是否有偏差？
   +-- 采购价格 vs 市场行情 -> 是否在合理范围内？
   +-- 年度降价目标是否达成？
   +-- 紧急采购的加价率是否合理？

3. 供应商审计（每年）
   +-- 供应商绩效评分是否按标准执行？
   +-- 新供应商引入是否通过了完整的认证流程？
   +-- 供应商关系维护是否有不当交往？
   +-- 供应商投诉是否有记录和处理？

4. 流程审计（每年）
   +-- PO 审批流程是否被绕过？
   +-- 紧急采购比例是否异常偏高（> 5%）？
   +-- 采购订单是否被分割成小额规避审批？
   +-- 系统权限是否被滥用？
```

**采购追溯的数据要求**：

```text
每笔采购必须可追溯以下信息：

基本信息：
  +-- PO 编号、物料编码、供应商编码
  +-- 采购数量、单价、总金额
  +-- 采购员、审批人、验收人
  +-- 下单日期、交货日期、验收日期

决策信息：
  +-- 供应商选择的依据（比价记录/招标记录/单一来源理由）
  +-- 价格确定的依据（报价单/谈判记录/框架协议条款）
  +-- 份额分配的决策记录
  +-- 任何例外情况的审批记录

追溯期：采购记录保存 ≥ 7 年（法律法规要求）
```

### 15.5 举报与问责机制

**举报渠道**：

- 独立举报热线/邮箱（不接受采购部门自己管理举报）
- 匿名举报保护制度
- 举报人保护（不得对举报人打击报复）

**问责分级**：

```text
一级违规（轻微）：
  行为：接受供应商 ¥500 以下的小礼品未申报
  处理：书面警告 + 廉洁培训 + 记录在案

二级违规（中等）：
  行为：未按流程审批的采购 / 未经比价就确定供应商
  处理：通报批评 + 扣发年度奖金 10-30%

三级违规（严重）：
  行为：接受供应商 ¥1,000 以上现金/礼品 / 利益冲突未申报
  处理：记大过 + 降职/调岗 + 扣发年度奖金 50-100%

四级违规（致命）：
  行为：索贿/受贿 / 与供应商串通损害公司利益 / 虚假采购套利
  处理：立即辞退 + 追究法律责任 + 列入行业黑名单
```

**特别规定——与友商交易的额外审查**：

```yaml
与竞争对手的采购交易，除普通采购审计外，还需：
  +-- 每笔交易由法务独立审查
  +-- 交易记录单独归档（便于合规调查）
  +-- 采购人员定期轮岗（同一人不能负责友商采购 > 2 年）
  +-- 采购金额异常变动自动预警（设定阈值）
  +-- 每年由外部审计机构专项审计
```

## 16. 新增导入的整合工作量管理

**核心洞察**：采购不只是「买回来」，更是「让新东西在已有平台上跑通」。当供应链引入一个新供应商、一个新部件、一个新型号，甚至一个新信号/特性时，它不是在空地上盖楼——而是在**一栋已经装满设备的楼里加一间新房**。每一堵墙都要打穿、每根管线都要接上、每个接口都要验证。

这就是「打通」的代价：工作量不随新增量线性增长，而是**随已有体系的复杂度指数增长**。

### 16.1 新增一个供应商——要打通多少层？

你以为只是「签个合同，加个联系人」？实际上：

```text
引入一家新供应商（以国产散热器厂商为例）的打通路径：

第 1 层：商务准入
  +-- 供应商资质审核（营业执照/行业认证/客户参考/财报）
  +-- QSA 审核（质量体系：ISO9001/IATF16949/QC080000）
  +-- QPA 审核（过程审核：产线/设备/工艺能力）
  +-- ESG 审查（环境/社会/治理——大型企业越来越严格）
  +-- 法务审查（合同模板/赔偿条款/保密协议）

第 2 层：样品验证
  +-- 样品送样（3-10 pcs，用于初步评估）
  +-- 研发功能测试（热阻/流阻/耐压/绝缘/寿命）
  +-- 可靠性测试（温度循环/振动/湿热/盐雾）
  +-- 兼容性测试（与已有系统是否匹配——如液冷的快插接头是否兼容）

第 3 层：系统打通
  +-- 供应商编码创建（在 ERP 中分配 V-XXXXX-XX 编码）
  +-- 供应商门户开通（EDI/订单/发票/对账系统接入）
  +-- 价格维护（在系统中创建价格记录，含有效期）
  +-- 采购条款设定（账期/起订量/交期/最小包装）
  +-- 付款信息维护（银行账户/发票类型/税务信息）

第 4 层：质量打通
  +-- IQC 基准书制定（来料检验标准/抽样方案/AQL 值）
  +-- 质量协议签署（客诉处理/8D 流程/赔偿条款）
  +-- 产品环保认证（RoHS/REACH/卤素/冲突矿产披露）
  +-- 首批来料全检（新供应商前 3 批 100% 检验）

第 5 层：产线打通
  +-- 物料导入产线（SOP 更新/工装夹具适配/程序烧录）
  +-- 首件验证（First Article Inspection — FAI）
  +-- 小批量试产（50-200 pcs，跟踪直通率）
  +-- 量产放行（签署 PSW — Production Part Submission Warrant）

综合工作量：从寻源到量产放行
  +-- 最短周期：12-16 周（加急，各项并行）
  +-- 正常周期：24-32 周（逐层推进）
  +-- 投入人力：采购 1 人 + 研发 1 人 + 质量 1 人 + SQE 0.5 人
  +-- 总工时：约 40-80 人天（不含测试等待时间）
```

**关键结论**：新增一个中等复杂度供应商（不是螺丝螺母这种简单品类），完整打通需要 **3-6 个月**和 **40-80 人天**。如果一年引入 20 家新供应商，仅打通工作就要吃掉 **1,200 人天**——相当于 **6 个全职人力**。

### 16.2 新增一个部件——要在 BOM 里打几个孔？

部件是 BOM 的基本单元。新增一个部件（即使它和已有部件型号相似），它要「打通」的路径和从零开始差不了太多：

```text
新增一个部件（例如一颗国产 SSD 替换进口 SSD）的打通路径：

第 1 层：编码打通（PLM -> ERP）
  +-- 物料编码申请（系统分配 E-STOR-XXXXXX-001）
  +-- 物料主数据维护（描述/规格/封装/重量/环保标志）
  +-- 替代关系建立（替代哪个已有编码？主替/备替/平替？）
  +-- 生命周期状态设定（开发中 -> 可采购 -> 量产）

第 2 层：技术打通
  +-- 规格书审查（datasheet 关键参数对比）
  +-- 样品测试（功能/性能/功耗/温度范围）
  +-- 兼容性矩阵更新（在哪些主板/平台上验证过？）
  +-- 驱动/固件验证（NVMe 驱动兼容性、固件版本要求）
  +-- 信号完整性测试（PCIe Gen5 信号质量——每条 lane 都要过 eye diagram）

第 3 层：质量打通
  +-- 可靠性测试（TBW/DWPD/MTBF 验证）
  +-- 环境测试（高温/低温/湿热/振动）
  +-- ALT（加速寿命测试——可能要 1-2 个月）
  +-- 认证（CE/FCC/UL——如果之前没认证过，要 4-8 周）

第 4 层：供应链打通
  +-- 价格谈判 + 价格记录创建
  +-- 交期确认 + 最小起订量设定（MOQ/SPQ）
  +-- 安全库存策略设定（备 2 周还是 4 周？）
  +-- 首单下单 + 物流验证（到货周期/包装方式/标签规范）
  +-- 备品备件策略（售后阶段是否备料？备多少？）

第 5 层：生产打通
  +-- BOM 版本升级（ECO — Engineering Change Order）
  +-- 产线物料切换方案（切换时间点/旧料消耗/新料引入）
  +-- 烧录程序/工装准备（如果部件需要预烧录）
  +-- 量产首件确认（第一台量产的整机功能测试）

综合工作量：
  +-- 简单替代（pin-to-pin 兼容、同封装同接口）：4-8 周
  +-- 功能替代（同功能但不同接口）：8-16 周
  +-- 全新品类（之前没用过的部件类型）：16-32 周
  +-- 平均人力投入：20-50 人天
```

**管理工作量不是「1 个料号 = 1 个单位工作量」**——而是：

```text
新增部件难度系数：
  +-- Level 0：同品牌同型号换版本号（如 SSD 固件升级）
  |   需要打通：BOM 版本更新 + 少量兼容性验证
  |   工作量：2-5 人天
  |
  +-- Level 1：同品牌同品类换颗粒（如 Samsung 1TB->2TB）
  |   需要打通：BOM 更新 + 功能验证 + 可靠性
  |   工作量：5-10 人天
  |
  +-- Level 2：不同品牌但同品类（如 Samsung -> YMTC SSD）
  |   需要打通：全套技术验证 + 质量 + 供应链
  |   工作量：20-40 人天
  |
  +-- Level 3：不同品牌不同品类（如 SSD -> 傲腾）
  |   需要打通：编码 + 技术 + 质量 + 供应链 + 生产全覆盖
  |   工作量：40-60 人天
  |
  +-- Level 4：全新品类（如首次引入 CXL 内存模组）
      需要打通：除 Level 3 全部 + 架构评审 + 平台适配 + 固件开发
      工作量：80-120 人天
```

### 16.3 新增一个型号——用户看到的是 SKU，后台是复杂工程

一个新服务器 SKU（例如从 H800 平台衍生的 H800-Lite），表面上只是 BOM 略有不同，实际上：

```text
新增一个 SKU 的打通路径：

第 1 层：商业打通
  +-- 产品型号创建（用于销售目录/报价系统）
  +-- 定价策略（与已有 SKU 的价格梯度/定位）
  +-- 配置器维护（CPQ — Configure Price Quote 系统）
  +-- 销售材料（规格书/白皮书/兼容性列表）
  +-- 客户报备（会不会和已有 SKU 抢客户？）

第 2 层：BOM 打通
  +-- BOM 搭建（从已有 SKU 复制->修改->审核->发布）
  +-- BOM 差异分析（与母 SKU 有哪些不同？这些差异谁验证过？）
  +-- 物料齐套分析（新 BOM 中的所有料号是否都可采购？状态是否正常？）
  +-- 成本核算（新 BOM 的 BOM Cost + 加工费 + 物流 -> 毛利率是否达标？）

第 3 层：制造打通
  +-- NPI 导入（试产计划/测试方案/良率目标）
  +-- SOP 差异更新（与母 SKU 不同的工序/工位）
  +-- 测试程序更新（功能测试/老化测试/BIT 测试项差异）
  +-- 包装方案（纸箱/泡沫/标签/附件——不同 SKU 包装通常不同）
  +-- 出货物流（不同 SKU 可能走不同渠道/不同仓库）

第 4 层：售后打通
  +-- 备件策略（该 SKU 专用备件 / 与母 SKU 共用备件）
  +-- 维修手册编写（差异部分）
  +-- 客服培训（让客服能回答「H800-Lite 和 H800 有什么不同？」）
  +-- 生命周期管理（何时 EOL？EOL 后备件供到何时？）

综合工作量：
  +-- 少量定制（换几颗 DIMM/SSD 容量）：5-10 人天
  +-- 中等定制（换 CPU/GPU/网卡）：15-30 人天
  +-- 全新衍生机型：30-60 人天
```

**SKU 膨胀的代价**——每多一个 SKU：

```text
+-- 库存持有成本上升（每个 SKU 都要备安全库存）
+-- 采购复杂度上升（更多料号需要管理）
+-- 质量管控碎片化（更多验证组合）
+-- 售后成本上升（更多备件 SKU）
+-- 工程师思维负担上升（「这个板子跑的是哪个版本？」）

业界经验：每增加 1 个 SKU，全链条年度额外管理成本 ≈ SKU 单价的 10-30%
——体现在：更多的 NRE、更多的测试、更多的文档、更多的版本冲突。
```

### 16.4 新增一个信号/特性——你最看重的「封装后的工作量」

这个维度最隐蔽也最容易被低估。**新增一个信号**（电气特性），意味着一块印好的 PCB 上多了一条走线，但这条线背后要打穿的层数远超想象：

```text
新增一个信号/特性（例如在已有主板设计上新增 I3C 总线）
的打通路径：

+---------------------------------------------------------+
|                   信号级「打通」全景                       |
|                                                         |
|  信号层（电气）：                                         |
|  +-- 方案评审：为什么要加这个信号？现有的 I2C 不够用？    |
|  +-- 芯片选型：哪颗 I3C Master/Slave？跟已有芯片兼容？   |
|  +-- 原理图设计：引脚分配/Pull-up 电阻/中断/时序         |
|  +-- PCB Layout：走线规则/阻抗匹配/等长/差分对/屏蔽     |
|  +-- 信号完整性仿真：SI/PI 仿真 — 眼图是否合格？         |
|  +-- PCB 打样 + 调试：上板验证信号质量                    |
|                                                         |
|  固件层（控制）：                                         |
|  +-- BMC/BIOS 驱动开发（I3C 控制器驱动）                 |
|  +-- 中断处理 / DMA / 轮询策略                           |
|  +-- 与已有系统的交互（I3C ↔ I2C 桥接/协议转换）         |
|  +-- 固件版本管理与升级方案                               |
|                                                         |
|  兼容性层（生态）：                                       |
|  +-- 与 GPU/BMC/CPU 的 I3C 互操作测试                    |
|  +-- 与已有器件的时序兼容性（新信号 vs 旧器件的电压域）  |
|  +-- OS 驱动验证（Linux 内核是否支持这个 I3C 控制器？）   |
|  +-- 认证测试（如果信号涉及安全/合规——如 TPM 的信号）     |
|                                                         |
|  量产层（交付）：                                         |
|  +-- PCB 改版（新信号需要新增走线 -> 增加层数？）          |
|  +-- SMT 工艺变更（新器件封装/回流焊曲线）                |
|  +-- 测试覆盖（ICT/FCT 测试项是否覆盖新信号？）           |
|  +-- 维修文档（FAE 和维修团队知道新信号的测试点）         |
+---------------------------------------------------------+
```

**为什么「新增一个信号」有时比「新增一个部件」更贵**：

```text
对比：

新增部件（PMIC 换型号）：
  通常是 pin-to-pin 兼容 -> 不需要改 PCB
  工作量集中在验证和编码 -> 15-25 人天

新增信号（加 I3C 总线）：
  可能需要改 PCB -> 1 次 PCB 改版 = 6-8 周 + ¥5-15 万打样费
  需要驱动开发 -> 2-4 周固件开发
  需要 SI 仿真 -> 3-5 人天
  需要兼容性测试 -> 2-3 周
  影响范围从板扩展到整系统
  总工作量：60-120 人天 + ¥10-30 万 NRE

信号级打通的特点：
  - 投入大：不只是一个零件，而是一个系统级的改动
  - 连锁反应：改一个信号可能影响 3-5 条已有信号线
  - 不可逆：PCB 一旦投板，信号路径就固定了（不像软件可以发补丁）
  - 跨团队：需要硬件/固件/测试/生产至少 4 个团队参与
```

**服务器研发中的真实案例**：

```text
案例：在已有 AI 服务器平台增加 OCP 3.0 Mezzanine 网卡信号

背景：客户要求在已有 E104 主板上增加一组 OCP 3.0 信号
      （已有设计只支持 OCP 2.0）

打通路径：
  ① 技术评估（2 周）
     - OCP 3.0 需要 PCIe Gen5 ×16 信号 + I2C + PERST/WAKE 控制信号
     - 已有 PCB 没有预留 OCP 3.0 位置 -> 需要增加 4 层 PCB
     - 影响范围：CPU 引脚分配更改 + 12 条差分对 + 8 个控制信号

  ② 设计改动（4 周）
     - 原理图：CPU PCIe lane 重新分配（影响其他 PCIe 设备）
     - Layout：新增区域 + 走线规则 + 等长 + 差分阻抗控制
     - SI 仿真：确认 32Gbps PCIe Gen5 信号质量

  ③ 验证（4 周）
     - PCB 打样（2 周 + ¥8 万）
     - 信号实测（眼图测试/TDR/串扰）
     - OCP 3.0 互操作性测试（与 Mellanox CX7 网卡验证）
     - 兼容性测试（Linux/Windows 驱动、PXE 启动）

  ④ 生产导入（2 周）
     - 新 PCB 版本切换（ECO 发布 + 库存切换）
     - SMT 打件验证 + AOI 测试
     - 整机功能测试更新

  总工期：12 周（3 个月）
  总投入：约 80-100 人天 + ¥8-15 万 NRE
  连锁影响：此改版导致 E104 其他 2 个已有变种 SKU 也需跟进改版
```

### 16.5 整合工作量的评估与管理框架

**为什么「新增」的工作量总是被低估**——因为每层打通都被当作「小事」：

```text
每个「小事」单独看确实不大：
  +-- 加个物料编码：5 分钟
  +-- 做一次兼容性测试：2 天
  +-- 更新一次 BOM：1 天
  +-- 签一份质量协议：3 天
  +-- 跑一轮可靠性：1 周
  +-- 做一次产线导入：2 天

但累计在一个新物料身上：
  5 分钟 + 2 天 + 1 天 + 3 天 + 1 周 + 2 天 = 至少 3-4 周
  而且每一项都不能跳过——漏掉任意一项，量产时可能翻车。

加上 10 个新物料同时推进：
  每个物料 3-4 周 -> 但很多步骤是串行的（不能并行）
  实际需要的人力 = 10 × 20 人天 = 200 人天
```

**打通工作量评估模板**：

```yaml
新增导入工作量评估表

项目名称：[新增部件/供应商/信号名称]
新增类型：供应商 / 部件 / SKU / 信号特性
打通等级：Level 0 / 1 / 2 / 3 / 4

+-----------------+------+------+------+------+
|   打通项         | 工时  | 周期  | 负责  | 依赖  |
+-----------------+------+------+------+------+
| 资质审核         | 3天  | 2周  | 采购  | 无   |
| 样品申请+验证     | 5天  | 3周  | 研发  | 资质  |
| 物料编码创建      | 0.5天| 1天  | 采购  | 验证  |
| 价格维护         | 0.5天| 1天  | 采购  | 编码  |
| IQC 基准书       | 2天  | 1周  | 质量  | 样品  |
| 可靠性测试        | 3天  | 4周  | 质量  | 样品  |
| 小批量试产        | 5天  | 2周  | 制造  | 全部  |
| BOM 更新+ECO     | 1天  | 3天  | 研发  | 试产  |
| 量产放行         | 0.5天| 1天  | 质量  | BOM   |
+-----------------+------+------+------+------+
| 合计（串行）      | 20天 | 12周  | 4人  | -    |
+-----------------+------+------+------+------+
```

**减少打通工作量的策略**：

```text
策略 1：平台化——减少「从零打通」的频率
  +-- 定义标准化接口（统一的电源/散热/管理信号定义）
  +-- 预留扩展能力（PCB 上预布线、预置焊接位）
  +-- 新部件在前一代平台上先验证，再引入新平台

策略 2：替代方案优先于全新引入
  +-- 能用现有 AVL 中的物料，不引入新供应商
  +-- 能用 pin-to-pin 兼容的，不重新走线
  +-- 能用已有 SKU 衍生，不创建全新 SKU

策略 3：批量打包打通
  +-- 每季度集中做一次新物料引入（不是零零星星天天搞）
  +-- 一批新物料走同一套验证流程（共享测试夹具/测试方案）
  +-- 同类物料一起做兼容性测试（节省环境搭建时间）

策略 4：打通流程标准化+模板化
  +-- 每个新增类型有 CheckList（确保不漏项）
  +-- 打通流程固化到系统中（系统自动催办下一步）
  +-- 历史打通数据积累 -> 可预测新打通的工作量
```

### 16.6 打通工作量的量化影响——采购决策中必须算的「隐性成本」

每一笔采购决策，都不只看「物料单价 × 数量」，还要看 **打通成本**：

```text
真正成本 = 物料价格 + 整合打通成本

整合打通成本 ≈ 物料单价 × 系数

系数参考（经验值）：
  +-- Level 0（版本更新）：物料单价的 1-3%
  +-- Level 1（同品牌升配置）：物料单价的 3-8%
  +-- Level 2（新品牌同品类）：物料单价的 8-20%
  +-- Level 3（新品类）：物料单价的 20-50%
  +-- Level 4（全新品类）：物料单价的 50-100%

举例：
  一颗国产 SSD 单价 ¥2,000
  Level 2 打通（新品牌同品类）：¥2,000 × 15% = ¥300/颗的隐性整合成本
  如果年产 10 万台，一批次用 10,000 颗
  总隐性成本 = ¥300 × 10,000 = ¥300 万
  这个成本远超 SSD 本身的单次议价空间（通常 ¥50-100/颗的降价空间）

启示：
  从「便宜 5%」的替代物料中切换，如果打通成本超过节省金额，
  在经济上就是不可行的——除非有战略理由（供应安全/国产化）。
```

**打通成本在采购决策中的应用**：

```text
情况：现有 Samsung SSD ¥2,100/颗，国产替代 ¥2,000/颗

方案 A：不切换
  - 物料成本：¥2,100/颗 × 10,000 颗 = ¥2,100 万
  - 打通成本：0（已有供应商，无需打通）
  - 总成本：¥2,100 万

方案 B：切换国产
  - 物料成本：¥2,000/颗 × 10,000 颗 = ¥2,000 万（节省 ¥100 万）
  - 打通成本（Level 2）：¥2,000 × 15% × 10,000 = ¥300 万
  - 总成本：¥2,000 万 + ¥300 万 = ¥2,300 万
  - 实际上比不切换贵了 ¥200 万

但如果同时有战略理由（国产化率要求 / 供应安全），
¥200 万的额外成本就是「为战略买单」——需要明确算清，不能稀里糊涂。
```

### §16.6 采购管理参数打通

前文聚焦于技术侧的打通（供应商→部件→SKU→信号），但采购自身同样有一整套参数需要打通，才能在新供应商/新部件导入后，让采购流程跑通、订单能下、货能到、款能付。

采购管理参数打通的本质是：**让新增的「供应商 × 部件 × 商务条件」三元组能在采购信息系统（ERP/SRM）中完成注册、关联、验证，使后续的订单管理、交付跟踪、对账结算、供应商绩效评价有据可依。**

#### 16.6.1 供应商基础信息打通（第一层）

每一家新供应商首次导入时，必须在采购系统中建立完整的档案。缺少任何一项，后续流程都会卡住。

| 信息类别 | 具体字段 | 打通目标系统 | 典型问题 |
|:---------|:---------|:-------------|:---------|
| **主体资质** | 统一社会信用代码·企业全称（中英文）·法定代表人·注册地址·注册资本·成立日期·营业范围 | ERP 供应商主数据 / SRM | 中文名与英文名不一致，海关/税务系统验证失败 |
| **联系信息** | 采购对接人·技术对接人·财务对接人·24h 紧急联系人·办公地址·工厂地址 | SRM / OA 通讯录 | 对接人离职后无移交，半年无人响应 |
| **银行信息** | 开户行（中英文）·银行账号·SWIFT Code·税号 VAT No. | ERP 财务模块 | 账号变更未及时更新，导致付款退回 |
| **资质认证** | ISO9001/ISO14001/ISO27001·UL/CE/FCC·RoHS/REACH·出口管制 ECCN | 供应商门户 / 合规系统 | 证书过期未被发现，出货被海关卡 |
| **合同与条款** | 框架协议版本·保密协议 NDA·质量协议 QA·通用商务条款（Payment Terms/Incoterms/Warranty） | SRM / 合同系统 | 合同版本混乱，出现「以哪个版本为准」的纠纷 |

> **打通标准**：首单下单前，以上 5 类信息必须 100% 完整，缺任何一项则系统拦截下单动作。

#### 16.6.2 型号/物料信息打通（第二层）

新供应商带着新部件来了，除了技术侧验证通过的信号和规格外，采购侧需要为这个「供应商 × 部件」建立唯一的物料-供应商关联。

| 信息项 | 说明 | 打通目标 |
|:-------|:-----|:---------|
| **厂商物料号 (MPN)** | 供应商自己定义的型号，如 Samsung MZOL21T9HCJR | ERP 物料主数据 "Manufacturer Part Number" |
| **内部物料编码 (Internal PN)** | 企业自有的编码规则（§14.1），MPS-SSD-00321 | ERP 物料主数据 "Item Code" |
| **物料描述** | 标准化的规格描述，如 SSD 2.5" 7.68TB NVMe PCIe 5.0 | ERP 物料主数据 / 采购订单描述字段 |
| **厂商批次号格式** | 批次/日期编码规则，用于追溯 | ERP 收货模块 / WMS |
| **最小包装量 (MPQ)** | 最小下单量/包装量，如 1 tray = 40 pcs | ERP 采购参数（影响 MOQ 计算） |
| **生命周期状态** | Active / NRND / EOL / EOL_with_LTB | 采购系统自动触发生效/冻结/替代 |
| **替代料关系** | 主选/次选/备选 的优先级+切换条件 | ERP BOM 模块 / SRM 来源分配 |
| **报价有效期** | 报价单的有效期，过期后自动失效 | SRM 价格表模块 |

> **打通标准**：以上 8 项信息在系统间双向同步。ERP 中的物料编码变更，自动通知 SRM；SRM 中供应商报价更新，自动同步到 ERP 价格表。

#### 16.6.3 商务条件打通（第三层）

这是采购特有的参数，技术团队通常不关心，但直接影响每一笔订单的生成和执行。

| 商务参数 | 说明 | 打通方式 |
|:---------|:-----|:---------|
| **付款条件 (Payment Terms)** | Net 30 / Net 60 / 预付 30%+尾款等 | 绑定至「供应商 + 物料」组合，下单时自动带入 PO |
| **交货条款 (Incoterms)** | EXW / FOB / CIF / DDP 等 | 绑定至供应商档案，影响运费归属和风险转移点 |
| **贸易合规 (Export Control)** | ECCN / EAR / 是否受制裁名单 | 与供应商资质绑定，触发出口管制自动审查 |
| **关税与增值税率** | 适用于该物料的 HS Code 下的税率 | 绑定至物料编码，自动计算到岸成本 |
| **物流方式** | 空运 / 海运 / 陆运 / 快递 / 默认方式 | 绑定至「供应商 + 目的地」，下单时默认带出 |
| **订单最小金额/数量** | MOQ (Minimum Order Qty) / Minimum Order Value | 绑定至物料级，低于 MOQ 自动拦截或提示 |
| **交期前置时间 (Lead Time)** | 标准交期 + 加急交期，区分研发打样/量产 | 绑定至物料级，自动影响 MRP 计算中的计划到货日期 |
| **价格阶梯 (Price Break)** | 100pcs: ¥100; 500pcs: ¥95; 1,000pcs: ¥88 | 绑定至物料，下订单时按数量自动匹配价格档 |
| **关税分摊方式** | 谁承担关税 | 绑定至 Incoterms+物料组合 |
| **运费归属** | 是否含运费 | 绑定至 Incoterms |

> **打通标准**：以上 10 项商务参数在 SRM/ERP 中与「供应商 + 物料」一对一绑定，下单时自动填充。系统应阻止「商务参数缺项」的采购订单生成。

#### 16.6.4 历史关系与评价数据打通（第四层）

新供应商导入不只是「录入信息+开订单」，还要继承和建立供应商的历史关系档案。这影响到后续的订单分配权重和合作深度决策。

| 数据类别 | 具体内容 | 数据来源 | 用途 |
|:---------|:---------|:---------|:-----|
| **合作历史** | 合作起始日期·累计订单量·累计金额·历史订单数量 | ERP 历史数据 | 评价供应商的稳定性和依赖度 |
| **交付绩效 (OTD)** | 按月的准时交付率·提前天数/延误天数·延误原因分类 | ERP 收货模块 → 自动统计 | 决定该供应商在下一轮订单分配中的权重 |
| **质量绩效 (PPM)** | 来料批次合格率·退货率·产线不良 PPM·RMA 率 | IQC / QMS 系统 | 影响质量审核周期和免检资格 |
| **价格竞争力** | 历史报价趋势·与市场价对比·每次调价幅度和频率 | SRM 价格表 + 市场情报 | 评价议价空间和涨价风险 |
| **配合度评估** | 紧急需求的响应速度·技术问题的协作意愿·产线支持的到位率 | 采购员 + 技术部门主观评价（季度打分） | 影响关键研发阶段的供应商选择 |
| **合规记录** | 环保违规·劳动用工·反腐败审计·数据安全事件 | 合规系统 / 第三方审计 | 影响供应商资质（可能触发降级或淘汰） |
| **服务水平 (SLA)** | 技术支持的响应时间·现场支持窗口·备件更换周期 | 供应商合同 + 实际记录统计 | 影响供应商分级（L1-L5） |

> **打通标准**：供应商评价数据按月自动汇总，按季度生成供应商记分卡（Scorecard），记分卡结果自动影响下一季度的订单分配权重。

#### 16.6.5 软件/License 采购参数打通（第五层）

软件采购与硬件部件采购有本质不同，其参数体系更为复杂，需要独立管理。

| 参数维度 | 硬件部件 | 软件/License | 打通注意点 |
|:---------|:---------|:--------------|:-----------|
| **计量单位** | PCS / EA | License / Seat / Core / Node / Subscription | ERP 计量单位必须独立定义，不能混用 |
| **计价方式** | 单价 × 数量 | 年订阅费 / 永久授权费 / 按用量计费 / 按核数计费 | 采购合同条款与 ERP 价格表结构需自定义，标准模块可能不支持 |
| **有效期** | 无限期（消耗品） | 有明确起止日期·续约必须提前触发的窗口期 | ERP 中需要「有效期管理」模块，自动触发续约提醒 |
| **授权绑定** | 无 | 绑定至设备 MAC/SN·绑定至用户·浮动授权-FlexLM | 授权管理不在 ERP 范畴，需要专门的 License 管理系统对接 |
| **维护服务** | 通常含在质保中 | 独立合同·维护费率（通常为授权费的 15-25%/年） | 采购系统中需单独开立维护服务行项目 |
| **审计合规** | 来料验收 | 授权数量是否超配·使用范围是否超出约定 | 需要 License 审计工具（如 Flexera/ServiceNow SAM）对接 |
| **升级权利** | 硬件版本变更需重新采购 | 含在维护合同中的升级权利·Major/ Minor 版本区分 | 合同条款必须明确定义升级范围 |
| **终止条款** | 退货/报废 | 停止使用的通知期·数据迁移窗口·许可证摘除要求 | 需在供应商档案中记录终止条款，到期前自动触发提醒 |

> **软件采购打通的特殊性**：建议独立的 License 管理系统（如 Flexera / ServiceNow SAM）与 ERP 对接，由采购系统完成商务流程，由 License 管理系统完成授权分配和合规审计。不要试图在 ERP 中管理所有软件参数。

#### 16.6.6 采购参数打通的典型工作量

每次新增一个供应商 + 一批部件进入采购体系，各层打通的典型工作量如下：

| 参数层 | 打通内容 | 典型工作量 | 瓶颈环节 |
|:-------|:---------|:-----------|:---------|
| **L1 供应商基础** | 资质·联系·银行·认证·合同 | 1-3 天/供应商 | 合同法务审核（最长可达 2 周） |
| **L2 型号/物料** | MPN·内部编码·描述·生命周期·替代料 | 1-2 天/物料 | 替代料关系梳理（需要技术确认） |
| **L3 商务条件** | 付款·Incoterms·MOQ·LeadTime·价格阶梯 | 0.5-1 天/物料 | 价格阶梯谈判（商务博弈） |
| **L4 历史评价** | 首次合作无历史→建立基线，后续逐月累积 | 首月人工录入基线，后续自动 | 首次合作的评价无数据可用 |
| **L5 软件/License** | 授权模式·有效期·续约·维护·审计 | 3-5 天/产品 | License 管理系统对接（系统级） |

> **完整打通周期**：一家全新供应商 + 10 个新物料从信息录入到可正式下单，通常需要 **3-6 周**（主要瓶颈在合同法务审核和价格谈判）。

#### 16.6.7 采购参数打通的常见翻车案例

| 场景 | 症状 | 根因 | 预防 |
|:-----|:------|:-----|:------|
| **付款延期** | 供应商不发货，理由是「账上欠款已超净到期日」 | 供应商银行账号变更后未同步到 ERP，付款被退回 | 供应商档案中设「账号变更自动触发通知」 |
| **关税纠纷** | 货物到港后被海关扣押，供应商和采购互相推卸 | Incoterms 条款为 EXW，但采购方以为含运费 | 每次下单时 PO 抬头强制显示 Incoterms |
| **MOQ 陷阱** | 研发只需 5 片样品，PO 被系统拦截→最低 100 片 | MOQ 绑定在量产物料上，研发打样无独立路径 | 研发打样和量产下分别使用不同的物料编码 |
| **EOL 断供** | 产线正在爬坡，供应商通知该型号已 EOL | 物料主数据的生命周期状态未更新，无人跟踪 | 设置 EOL 自动预警（提前 180 天/90 天/30 天） |
| **授权超配** | 审计发现 License 使用数超出购买数 30%，面临百万级追缴 | License 管理系统与采购系统未打通，买了多少和用在哪里对不上 | 每笔软件采购自动同步到 License 管理系统 |
| **价格失效** | 订单按半年前报价下单被拒，物料已涨价 20% | 报价有效期过期未冻结，供应商不认旧价 | SRM 中设报价自动失效机制，过期系统自动阻止下单 |

> **原则**：采购参数打通的投入是一次性的，但一旦打通，后续每一笔订单的执行效率、准确率、合规性都会受益。**翻车一次的代价通常超过打通投入的数倍。**
