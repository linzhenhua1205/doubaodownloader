## 1. 引言与核心命题

### 1.1 服务器供应链的特殊性

服务器制造与消费电子、汽车等行业的供应链有本质差异：

| 特性 | 服务器供应链 | 消费电子供应链 | 汽车供应链 |
|:-----|:------------|:--------------|:-----------|
| **物料种类** | 10万+种（含电子/结构/互联/固件） | 1-3千种 | 2-5万种 |
| **BOM层级** | 5-8级（芯片→模组→板卡→整机→机柜→集群） | 2-3级 | 4-6级 |
| **关键器件交期** | 12-52周（GPU/CPU/Switch） | 4-12周 | 8-26周 |
| **定制化程度** | 高（每客户不同配置） | 低（标准品） | 中（平台化） |
| **变更频率** | 高（芯片迭代快，客户需求多变） | 中（季度/年度） | 低（车型周期长） |
| **数据敏感性** | 极高（客户配置即商业机密） | 中 | 中 |

**核心矛盾**: 服务器供应链是典型的多品种、小批量、高定制、长交期场景，叠加芯片级技术迭代快（18-24月一代），信息流、物流、资金流之间的**一致性保障**比任何行业都更具挑战。

### 1.2 AI能解决什么

AI在供应链中的核心价值不是"替代人"，而是**在三个维度补强人工处理的天花板**：

| 维度 | 人工极限 | AI补强 |
|:-----|:---------|:-------|
| **信息处理量** | 日处理50-100条工单/邮件/文档 | 毫秒级处理10万+条，提取关键结构化信息 |
| **跨源关联** | 依赖经验记忆，漏关联率高 | 结构化+语义关联，发现人工忽略的模式 |
| **异常检测** | 事后发现，滞后1-3天 | 实时/准实时告警，前置到事中甚至事前 |
| **文档/格式转换** | 人工逐份处理，1份/人·小时 | 批量自动化，1份/秒 |
| **一致性校验** | 抽样检查，覆盖率<10% | 全量逐行校验，覆盖率100% |

> **关键洞察**: 供应链中最贵的不是物料本身，而是"信息不一致产生的沉默成本"——账实不符、BOM版本错配、PO与发票对不齐、交期承诺与产能不匹配。AI的第一价值是**消灭信息孤岛和一致性鸿沟**。

## 2. 服务器工厂物料体系全景

### 2.1 物料层级分类

服务器物料按供应链管理维度，可分为**六大类**：

#### A. 电子元器件（主动件）

| 物料类别 | 典型件 | 交期 | 供应商格局 | 管理要点 |
|:---------|:-------|:----:|:----------|:---------|
| **CPU** | Intel Xeon/AMD EPYC/国产化 | 12-26周 | 寡头 | 长周期锁单、假货识别 |
| **GPU** | NVIDIA H100/B200/国产 | 16-52周 | 独家或寡头 | 配额管理、价格波动 |
| **内存** | DDR5 RDIMM/LRDIMM | 8-16周 | 三星/海力士/美光 | 批次追踪、假货检测 |
| **存储** | NVMe SSD/SATA SSD | 8-16周 | 多源 | 固件版本追踪、寿命管理 |
| **网络芯片** | PCIe Switch/Retimer/PHY | 12-26周 | Broadcom/Microchip/Astera | 固件兼容性 |
| **电源管理** | VR Controller/DrMOS/PMBus | 8-16周 | MPS/Infineon/Renesas | 替代料管理 |
| **管理芯片** | BMC/ASPEED/FPGA | 8-12周 | 寡头 | 固件漏洞追踪 |

#### B. 被动件

| 物料类别 | 典型件 | 单价范围 | 管理要点 |
|:---------|:-------|:--------:|:---------|
| **电阻/电容/电感** | MLCC/钽电容/功率电感 | ¥0.01-5 | 用量大、批次一致性、替代料库 |
| **连接器** | 板对板/线对板/IO接口 | ¥0.5-50 | 多供应商、Pin-to-Pin兼容性 |
| **晶体/振荡器** | 晶振/TCXO | ¥1-10 | 频率精度、温度特性 |
| **保护器件** | TVS/ESD/PTC | ¥0.1-3 | 浪涌保护等级匹配 |

#### C. PCB与结构件

| 物料类别 | 典型件 | 加工工艺 | 管理要点 |
|:---------|:-------|:---------|:---------|
| **PCB光板** | 多层板(16-30层)、HDI | 压合→钻孔→电镀→阻焊 | 层叠结构版本、阻抗管控 |
| **散热器** | 铝挤/VC/热管模组 | 挤压/焊接/CNC | 界面材料、平面度 |
| **机箱/支架** | 钣金件、压铸件 | 冲压/折弯/焊接/喷涂 | 尺寸公差、表面处理 |
| **液冷组件** | 冷板/快接头/管路 | 焊接/钎焊/组装 | 泄漏率、材料兼容性 |

#### D. 线缆与互联

| 物料类别 | 规格 | 管理要点 |
|:---------|:-----|:---------|
| **高速线缆** | PCIe Gen5/6/QSFP/SAS | 信号完整性认证、长度规格 |
| **电源线** | 18AWG/16AWG/14AWG | 载流量、压接端子匹配 |
| **信号排线** | FFC/FPC/IDC | Pin距、锁扣方向、耐折寿命 |
| **背板互联** | 中板/正交背板 | 对插对准度、信号完整性 |

#### E. 包装与辅料

| 物料类别 | 管理要点 |
|:---------|:---------|
| **包装箱/缓冲材料** | ESD防护、跌落测试、定制泡沫 |
| **标签订** | 标签/序列号/防伪标 | 条码一致性、防篡改 |
| **辅料** | 导热硅脂/导热垫/三防漆 | 工艺要求、保质期管理 |

#### F. 软件与固件

| 物料类别 | 典型件 | 版本管理要点 |
|:---------|:-------|:-------------|
| **BIOS固件** | AMI/Insyde/定制化 | 功能版本+补丁版本+客户定制版本 |
| **BMC固件** | OpenBMC/AMI | 功能版本+安全补丁+OEM配置 |
| **CPLD/FPGA固件** | 逻辑代码 | 功能版本+烧录工具兼容性 |
| **驱动/工具** | NVIDIA驱动/MegaRAID | 操作系统兼容矩阵、Certification状态 |
| **OS预装** | Ubuntu/CentOS/Windows Server | License管理、镜像版本 |

### 2.2 物料编码体系

服务器物料编码通常采用**意义编码 + 流水号**混合策略：

```text
A  B  C  --  DDDD  --  EE  --  FF  --  GGGG
|  |  |      |         |      |       +- 流水号
|  |  |      |         |      +- 版本号（01-99）
|  |  |      |         +- 封装/规格码
|  |  |      +- 物料分类码（4位）
|  |  +- 物料大类（电子/结构/包装...）
|  +- 使用场景（研发/量产/售后）
+- 公司代码
```

**物料编码与AI的关系**：物料编码本身是结构化的，但供应链中的大量信息存在于**非结构化数据**中——供应商邮件中的替代料推荐、规格书中的参数、产线异常报告中的描述——AI的提取+关联能力是关键。

### 2.3 物料状态生命周期

```text
概念选型 ---> 样品认证 ---> 小批量验证 ---> 可量产 ---> 量产 ---> 退市
   |            |              |              |         |        |
   |            |              |              |         |        |
   v            v              v              v         v        v
 评估中       验证中         试产中         已批准     活跃使用    EOL
                          (DVT/PVT)                   (MP)
   +---- 技术选型 ----+       +--- 供应链导入 ---+
```

**AI切入点**：物料状态转换的驱动因素散落在不同系统（PLM→ERP→MES→QMS），AI可以自动采集并判断状态变更的合理性，提前预警"卡在过渡态"的物料。

## 3. 加工信息与生产过程

### 3.1 服务器生产全流程（SMT→Assembly→Test→Pack）

```text

|   SMT    |--->|  组装    |--->|  测试    |--->|  老化    |--->|  包装    |
|  (贴片)  |    | (整机)   |    | (功能)   |    | (Burn-in)|    | (出货)   |
+----------+    +----------+    +----------+    +----------+    +----------+
     |               |               |               |               |
     v               v               v               v               v
 锡膏印刷        板卡组装      功能测试          老化测试        参数标定
 贴片机          CPU安装      全量Checklist     48h/72h        序列号关联

 AOI检测        散热器安装    PCIe链路测试     异常记录打标    封箱/称重

 ICT测试        线缆连接      OS启动            良率统计        MES关单
 FCT测试        机箱组装      Benchmark         老化数据归档
```

### 3.2 SMT阶段（表面贴装）

SMT是服务器主板制造的核心环节，也是**加工信息密度最高**的阶段：

| 工序 | 输入信息 | 产出信息 | AI切入点 |
|:-----|:---------|:---------|:---------|
| **锡膏印刷** | 钢网文件、锡膏型号、温湿度 | 印刷厚度/偏移量（SPI数据） | 印刷缺陷预测（基于SPI+环境参数） |
| **贴片** | 贴片程序、Feeder布局、物料盘 | 贴装坐标、贴装压力（AOI数据） | 偏移趋势分析、飞料预警 |
| **回流焊** | 温度曲线（Profile）、链速 | 炉温曲线实况（KIC数据） | 炉温偏移自动补偿、虚焊预测 |
| **AOI检测** | 标准图像、判定阈值 | 缺陷坐标/类型/图片 | 缺陷分类（漏焊/桥连/立碑/缺件） |
| **X-Ray** | BGA焊点标准 | X光图像（BGA/QFN） | 焊球空洞率自动判定 |
| **ICT/FCT** | 测试程序、边界值 | Pass/Fail、失效Pin | 测试覆盖率分析、失效模式聚类 |

**关键数据流**——每条SMT产线每分钟产生：

- ~200条SPI数据点（印刷厚度/面积/偏移）
- ~500个贴装坐标记录
- ~50张AOI图像（含缺陷品）
- ~100条炉温采样点

**总量**: 一条产线单班（8h）产生约 **30-50万条结构化和半结构化数据**。

### 3.3 整机组装阶段

| 工序 | 关键活动 | 加工信息 | AI切入点 |
|:-----|:---------|:---------|:---------|
| **CPU安装** | 开箱→对准→扣压→贴散热 | CPU序列号、扣压力矩、散热膏均匀度 | 安装力矩异常检测、序列号OCR录入 |
| **GPU安装** | 对准PCIe槽→固定→供电线缆 | GPU序列号、金手指检查、供电座连接确认 | 安装角度检测、供电座视觉确认 |
| **内存插装** | 对准槽位→压入→锁扣 | 内存序列号（SPD读取）、安装力 | 序列号自动关联、漏插检测 |
| **散热器安装** | 涂导热膏→固定→扭矩管理 | 导热膏厚度、螺丝扭矩、平面度 | 扭矩曲线异常检测、涂布质量AOI |
| **线缆连接** | 电源/信号/管理线束布放 | 线缆走向、连接器锁扣状态、标签位置 | 线缆错接检测、标签OCR核对 |
| **机箱合盖** | 前后面板安装→侧盖锁紧 | 盖板序列号、螺丝扭矩 | 漏装螺丝检测、盖板序列号录入 |

### 3.4 测试与老化阶段

测试是服务器生产中最耗时的环节（占生产周期40-60%），也是**数据密度最高的环节**：

| 测试类型 | 测试内容 | 典型时长 | 数据量 | AI切入点 |
|:---------|:---------|:--------:|:------:|:---------|
| **功能测试（FCT）** | 上电自检、BMC初始化、PCIe枚举 | 5-15min | ~5,000条日志 | 异常日志自动分类、根因定位 |
| **内存测试** | MemTest86/LTP/DDR5训练 | 30-60min | ~50,000条 | 失败模式聚类、Bad DIMM预测 |
| **存储测试** | NVMe/SATA识别、读写验证 | 10-20min | ~2,000条 | 性能基线偏离检测 |
| **网络测试** | 网卡识别、吞吐量、Ping | 5-10min | ~1,000条 | 链路质量预判 |
| **压力测试** | CPU/GPU满载、功耗测试 | 30-60min | ~20,000条 | 性能一致性分析、Thermal Throttling检测 |
| **老化测试（Burn-in）** | 48-72h持续运行 | 48-72h | ~100万+条 | 早期失效预测、趋势异常检测 |

**老化测试的AI价值**：老化是人力成本最高、但数据最丰富的环节。传统做法是"跑满72h不出错即Pass"，但：

- **趋势异常**：温度缓慢爬升、风扇转速逐渐增大→可能预示散热界面退化
- **间歇性错误**：每小时出现1-2次Correctable Error→可能预示芯片即将失效
- **性能漂移**：性能从第12h开始下降→可能预示供电不稳

这些模式**人工难以从100万+条日志中识别**，但对AI来说是典型的时序异常检测问题。

### 3.5 包装与出货阶段

| 工序 | 关键信息 | AI切入点 |
|:-----|:---------|:---------|
| **序列号关联** | 整机SN↔板卡SN↔关键器件SN（物料追溯链） | OCR+条码自动关联、异常关联检测 |
| **配置确认** | PO配置↔实际配置↔测试结果↔包装清单 | 四维一致性校验（AI强项） |
| **标签生成** | 客户标签、运输标签、合规标签 | 标签内容OCR校验、格式合规检查 |
| **称重测量** | 整机重量、外箱尺寸 | 异常重量预警（缺件/多余物） |
| **出货文件** | 装箱单、发票、COO、Certificate | 文档自动生成、多语言翻译、合规审查 |

## 4. 备件管理业务全景

### 4.1 备件分类

服务器领域的备件按使用场景分为**四大类**：

#### A. 售后备件（Aftermarket Spares）

| 备件类型 | 典型件 | 覆盖周期 | 管理挑战 |
|:---------|:-------|:---------|:---------|
| **现场可更换单元（FRU）** | 电源模块、风扇模组、硬盘背板 | 3-7年 | 长生命周期下的EOL替代 |
| **板卡级备件** | 主板、Riser卡、IO模块 | 3-5年 | 固件版本兼容性（新旧混用） |
| **芯片级备件** | CPU、GPU、内存模组 | 3-5年 | 步进版本差异、Errata追踪 |
| **线缆套件** | 电源线/信号线/光模块 | 3-7年 | 使用频率差异大、缓存水位难定 |

#### B. 生产备件（Manufacturing Spares）

| 备件类型 | 用途 | 管理要点 |
|:---------|:-----|:---------|
| **NPI试产备件** | 新机型试产用关键件 | 量少种类多、验证批次限制 |
| **产线周转备件** | 设备维修替换件（SMT吸嘴/夹具） | 工装寿命管理、预报周期 |
| **返修备件** | 维修返回品替换 | 与新品隔离、等级区分 |

#### C. 维保备件（Warranty & Service）

| 备件类型 | 覆盖场景 | 管理挑战 |
|:---------|:---------|:---------|
| **SLA备件** | 4h/Next Business Day/现场 | 区域分布优化、紧急调拨 |
| **大客户专享备件池** | 头部客户指定库 | 独立库存、独占金额大 |
| **返厂维修周转件** | RMA替换 | 逆向物流跟踪、翻新品质管控 |

#### D. 工程样板（Engineering Samples）

| 类型 | 用途 | 管理要点 |
|:-----|:-----|:---------|
| **EVT样品** | 设计验证 | 数量少、去向追踪 |
| **DVT样品** | 设计验证 | 版本管理、回收管控 |
| **PVT样品** | 量产验证 | 与量产物料隔离、使用后报废处理 |

### 4.3 备件管理的典型痛点（AI可介入）

| 痛点 | 问题表现 | 传统做法 | AI方案 |
|:-----|:---------|:---------|:-------|
| **需求预测不准** | 热门备件缺货，冷门备件积压 | 经验+简单移动平均 | 多维时序预测（维保单趋势+装机量+季节+大客户活动） |

| **逆向物流黑洞** | 坏件发出后去向不明、翻新率低 | Excel+人工追踪 | 全链路追踪系统+自动化状态更新 |
| **备件用量与维保不匹配** | 现场换件记录与维保合同不符 | 季度人工对账 | 自动对账引擎（工单↔合同↔备件消耗） |

## 7. 管理类AI应用场景

### 7.1 合规与内控管理

#### 7.1.1 合同合规审查

**输入**: 供应商合同/P0F/采购协议
**AI处理**: RAG + 条款抽取 + 风险词库匹配
**输出**: 风险条款标记 + 合规等级 + 修改建议
**典型问题检测**:

- 赔偿上限是否低于行业惯例（通常为合同额的50-100%）
- 知识产权条款是否合理（是否将供应商背景IP也纳入共享）
- 保密期限是否过长/过短
- 违约责任是否对等
- 管辖权条款是否有利于己方

#### 7.1.2 出口管制合规

**输入**: 物料BOM + 客户信息 + 最终用途声明
**AI处理**: 实体识别（ECCN/HTS代码） + 受限方名单匹配
**输出**: 合规风险等级 + 建议操作（是否需要许可证）
**典型场景**: 含特定美国原产芯片的服务器是否可出口到受管制国家/实体

### 7.2 供应商管理

#### 7.2.1 供应商评估报告自动生成

**输入**: 供应商季度QBR数据 + 来料良率 + 交期OTD + 价格趋势
**AI处理**: 多维度评分计算 + 趋势分析 + 异常标注

**输入**: AOI拍摄的缺陷图片

**对比传统AOI vs AI增强AOI**:

| 维度 | 传统AOI | AI增强AOI |
|:-----|:---------|:-----------|

### 10.3 测试过程AI应用

**输出**: 建议补货量 + 经济订货批量 + 安全库存水位

### 11.2 RMA处理

#### 11.2.1 RMA分类与路由

**输入**: 客户退回申请（文本描述/故障现象/日志）
**AI处理**: 故障描述理解 → 分类 → 路由到对应处理组
**输出**: RMA类型（DOA/故障/误报/人为损坏）+ 建议处理方式

**分类体系**:

```text
RMA类型
+-- DOA（开箱即坏）-> 优先换新
+-- 真实故障
|   +-- 硬件故障 -> 维修/换板
|   +-- 固件问题 -> 固件升级
|   +-- 配置问题 -> 重新配置指导
+-- 误报（NTF） -> 退回测试后标记NTF
+-- 人为损坏 -> 报价维修
```

#### 11.2.2 退回品检验自动判定

**输入**: 退回品外观照片 + 序列号 + 故障描述
**AI处理**: 外观损伤检测 + 序列号验证 + 故障一致性检查
**输出**: 判定结果（保修/有偿维修/拒收）+ 建议维修方案

### 11.3 逆向物流

#### 11.3.1 坏件翻新判定

**输入**: 坏件检测数据 + 外观检查 + 剩余寿命评估
**AI处理**: 可修复性评估 → 翻新 vs 报废判定 → 翻新方案推荐
**输出**: 翻新可行性等级 + 翻新成本估算 + 翻新后质量预测

#### 11.3.2 翻新件与正品件的隔离

**AI能力**: 自动标记翻新件（序列号特殊前缀） + 禁止翻新件进入新品渠道

## 12. AI对账与差异分析专章

### 12.1 对账全景——为什么要对账

供应链中的"账"不是单数，而是**多维度、多系统、多角色的交叉验证**：

```text
  +----------+     +----------+     +----------+
  | 财务账    |     | 实物账    |     | 合同账    |
  | (ERP)    |     | (WMS/MES) |     | (CRM/CLM)|
  +----+-----+     +----+-----+     +----+-----+
       |                 |                 |
       |    +------------+-----------------+--+
       |    |            |                 |  |
       v    v            v                 v  v
  +---------------------------------------------+
  |           多源对账引擎（AI核心）              |
  +---------------------------------------------+
  | PO ↔ Invoice ↔ Goods Receipt ↔ Contract     |
  | BOM(Design) ↔ BOM(Production) ↔ BOM(After)  |
  | SN(Plan) ↔ SN(Actual) ↔ SN(Customer)        |
  | Price(Contract) ↔ Price(PO) ↔ Price(Invoice)|
  +---------------------------------------------+
```

### 12.2 核心对账场景

#### A. 三单匹配（PO↔GR↔Invoice）

这是供应链对账最基础、最核心、量最大的场景：

```text
          +------------------+
          |  PO（采购订单）    |
          |  物料A × 100pcs    |
          |  ¥50/pcs          |
          +--------+---------+
                   |
          +--------v---------+    +------------------+
          | GR（收货单）      |    | Invoice（发票）    |
          |  物料A × 98pcs    |    |  物料A × 98pcs    |
          |  (2pcs不良拒收)   |    |  ¥49.5/pcs        |
          +--------+---------+    +--------+---------+
                   |                       |
                   +----------+------------+
                              |
                     +--------v---------+
                     |   对账差异        |
                     |  数量: 100-98=2 ✅ 可解释(拒收) |
                     |  单价: 50-49.5=0.5 ❌ 问题      |
                     |  金额: 5000-4851=149 ❌         |
                     +------------------+
```

**AI与传统对账的差异**:

| 维度 | 传统对账 | AI对账 |
|:-----|:---------|:-------|
| **处理量** | 月结时人工突击，覆盖核心供应商 | 日清日结，全量覆盖 |
| **差异处理** | 逐条人工判断，容易疲劳遗漏 | 自动分类+根因推断+优先级排序 |
| **模式发现** | 依赖经验，"感觉这个供应商总有问题" | 数据驱动模式发现（某个物料+某个批次总是价差） |
| **预测能力** | 无 | 从趋势预测下月可能出现的差异类型 |

#### B. BOM一致性对账

设计BOM（EBOM） ↔ 制造BOM（MBOM） ↔ 采购BOM（PBOM） ↔ 备件BOM（SBOM）

**AI检查点**:

- 编码一致性：同一个物料在不同BOM中编码是否一致
- 用量一致性：单个产品用量在不同BOM中是否一致
- 版本一致性：ECO变更后，所有BOM是否同步更新
- 替代料一致性：替代关系在各BOM中是否维护一致

#### C. 配置对账（客户PO ↔ 生产配置 ↔ 出货配置）

这是服务器行业特有的高价值对账场景：

- 客户PO指定了CPU型号/GPU数量/内存容量/硬盘配置/网卡规格
- 生产BOM据此生成具体物料清单
- 测试验证实际配置
- 出货文件反映最终配置

**AI自动校验**: PO配置 → BOM配置 → 测试结果 → 出货配置 → 四维一致性

### 12.3 AI对账引擎架构

```text
                    +---------------------------------+
                    |      数据接入层                   |
                    |  ERP  WMS  MES  PLM  CRM  SCM   |
                    |  (API/DB/FTP/Webhook)            |
                    +--------------+------------------+
                                   |
                    +--------------v------------------+
                    |      数据清洗与对齐层             |
                    |  - 主数据匹配（统一物料编码）      |
                    |  - 时间窗口对齐（不同系统时差）    |
                    |  - 单位/币种统一                  |
                    |  - 异常值/缺失值处理              |
                    +--------------+------------------+
                                   |
                    +--------------v------------------+
                    |      规则引擎层                   |
                    |  - 基础规则（数量/单价/总价匹配）  |
                    |  - 业务规则（MOQ/折扣/浮动定价）  |
                    |  - 合规规则（税率/海关编码）      |
                    |  ⇒ 自动通过/自动标记差异          |
                    +--------------+------------------+
                                   |
              +--------------------+--------------------+
              |                    |                    |
              v                    v                    v
    +-----------------+ +-----------------+ +-----------------+
    |  可自动解决的差异 | |  需人工判断的差异 | |  异常模式发现    |
    |  例：汇率波动     | |  例：单价变更     | |  例：某个供应商   |
    |  -> 自动标记说明   | |  -> 推送审批      | |  总价差偏大     |
    +-----------------+ +-----------------+ +-----------------+
```

### 12.4 差异分类与处理优先级

| 差异类型 | 严重度 | AI处理 | 人工介入 |
|:---------|:------:|:-------|:---------|
| **单价差异 > 5%** | 🔴 致命 | 自动标记，触发复核流程 | 必须人工确认 |
| **数量差异 > 2%** | 🔴 致命 | 自动标记，检查收货/退货记录 | 差异部分暂缓付款 |
| **币种错误** | 🔴 致命 | 自动阻止，要求重新提交 | 供应商重新开票 |
| **税率不符** | 🟡 重要 | 自动标记，比对税率表 | 财务确认税率 |
| **总价差异（四舍五入）** | 🟢 轻微 | 自动容差内放行（如<¥10） | 无需（月末汇总） |
| **日期差异（1-2天）** | 🟢 轻微 | 自动放行，标记备注 | 无需 |
| **物料编码格式不同** | 🟡 重要 | 自动映射（同物异码） | 确认映射关系后入库 |

### 12.5 老数据验证策略

与脱敏报告一致的原则——**时间隔离验证**：

| 验证场景 | 数据窗口 | 目的 |
|:---------|:---------|:-----|
| 对账规则训练 | 历史12个月已结算数据 | 训练差异分类模型，验证准确率 |
| 对账规则验证 | 历史3个月已对账数据 | 对比AI结果与人工结果的一致性 |
| 异常模式发现 | 历史24个月全量数据 | 发现人工未曾发现的重复性差异模式 |
| 趋势基线建立 | 历史36个月数据 | 建立季节性/周期性差异基线 |

## 15. 风险与约束

### 15.1 数据敏感性（最重要约束）

| 风险 | 说明 | 缓解措施 |
|:-----|:------|:---------|
| **客户配置泄露** | AI处理中接触到客户定制配置 | 所有客户配置数据不出安全域、老数据验证 |
| **供应商价格泄露** | 对账引擎处理真实价格 | 对账引擎本地部署、差分聚合发布 |
| **SN关联风险** | 追溯链中SN暴露 | SN脱敏后用于分析、实时系统严格控制权限 |

### 15.2 技术风险

| 风险 | 说明 | 缓解措施 |
|:-----|:------|:---------|
| **OCP识别误差** | 复杂表格/手写体OCR准确率不足 | 人工复核+置信度阈值 |
| **LLM幻觉** | AI生成不存在的物料/流程信息 | RAG强制引用 + 来源标注 + 人工终审 |
| **预测偏差** | 备件需求预测在极端情况失效 | 置信区间输出 + 安全库存兜底 |

### 15.3 组织风险

| 风险 | 说明 | 应对 |
|:-----|:------|:------|
| **一线员工抵触** | "AI要替代我"的恐惧 | 明确定位为辅助工具、不替代人决策 |
| **流程依赖** | 过度信任AI输出导致审查松懈 | 强制人工终审原则、AI输出标记置信度 |
| **数据孤岛** | 各部门系统数据不愿共享 | 高层推动、明确数据Owner和数据共享协议 |
