## 1. 核心论点：采购方式必须匹配技术成熟度

### 1.1 一句话结论

> 在技术/供应商均处于 **POC/早期阶段** 时，采购的首要问题不是"哪家更便宜"，而是"**谁愿意跟我们合作、谁有能力一起把东西做出来**"。

——"多供应商比价"是量产期（Technology Mature / Multiple Qualified Suppliers）的合法做法，但在早期创新阶段（Technology Emerging / Single or No Qualified Supplier），它不仅无效，而且会摧毁你与潜在合作伙伴之间的信任基础，最终导致"谁都不愿意跟你深度合作"。

### 1.2 采购与技术的交互模型

```text
技术成熟度
    ^
成熟  |  +===============+
(Mature)|  |  竞争型采购     |  <- 多供应商比价、竞标、竞价
    |  |  (Competitive)  |
    |  +===============+
    |
    |     +===============+
中期  |     |  技术型采购     |  <- 技术验证、集成评估、成本建模
(Growing)|     |  (Technical)   |
    |     +===============+
    |
    |        +===============+
早期  |        |  关系型采购     |  <- 联合设计、独占合作、优先权
(Emerging)|        |  (Relational)  |
    |        +===============+
    |
    |           +===========+
概念  |           |  准入型采购   |  <- 能不能搭上话？愿不愿意卖？
(Concept)|           |  (Access)   |
    |           +===========+
    +---------------------------------------> 时间
              POC         EVT/DVT         MP
```

**核心矛盾的高发地带**: 当技术处于早期（POC/概念阶段），而采购部门以量产思维（竞争型采购）介入时——**"你们为什么要只选一家？多做几家比较啊！"**——冲突就爆发了。

## 2. 两阶段本质差异：POC vs MP

### 2.1 生产型采购与创新型采购的本质区别

这不是"同样的工作在不同阶段"，而是**完全不同的两件事**。

| 维度 | 生产型采购（MP） | 创新型采购（POC/联合开发） |
|:-----|:----------------|:--------------------------|
| **采购的本质** | 交易（Buying） | 合作（Partnering） |
| **核心目标** | 成本最低、交付稳定、质量达标 | 技术领先、可行性验证、独家优先 |
| **供应商数量** | 多供（2-3家） | 单供或寡供（1-2家） |
| **关系深度** | 浅（标准化合同/条款/交接） | 深（联合路线图/共享IP/人员互驻） |
| **成功标准** | 价格达标率、交付准时率、品质合格率 | 技术指标是否达成、是否按时POC完成 |
| **信息对称度** | 高（成熟产品、公开参数、行业标杆价） | 低（技术路线未定、参数不确定、无对标基准） |
| **切换成本** | 低（换一家供应商重新送样即可） | 极高（联合开发投入不可逆，切换=从头再来） |
| **采购角色** | 合同管理员、议价者、供应商管理 | 关系建筑师、创新催化者、风险分担设计者 |
| **研发角色** | 技术方案审核、样品测试 | 联合设计、需求定义、技术路线共同决策 |
| **谁主导** | 采购主导，研发提供技术支持 | 研发主导，采购提供商务框架 |

### 2.2 分阶段对比总表

从 IPD 研发流程的视角看各阶段的采购特征：

| IPD阶段 | 研发阶段 | 采购模式 | 供应商策略 | 核心矛盾 |
|:-------:|:---------|:---------|:-----------|:---------|
| **TR1-TR2** | 概念/可行性 | 准入型 | 识别谁能做，建立初步联系 | 供应商不搭理你 |
| **TR3** | 计划/POC | 关系型+技术型 | 选定1-2家深度合作 | "为什么不比价？" |
| **TR4-TR5** | 开发/验证 | 技术型 | 锁定合作，加速认证 | 方案变更的商务谈判 |
| **TR6** | 小批量试产 | 技术型→竞争型过渡 | 开始评估替代方案 | 二供导入的时间窗口 |
| **MP** | 量产 | 竞争型 | 多供平衡、竞价 | 持续降本与质量稳定 |

## 3. 为什么"POC期做多供应商比较"是错的

### 3.1 问题前置：谁在和谁比？

执行层（研发）听到"多供应商比较"时的理解：

> "我们正在跟供应商A做联合POC，双方工程师在一起调参数、改固件、做适配。现在老板说去看看供应商B和C。但我们跟A的技术沟通才刚刚跑通，跟B和C要从头开始再走一遍——而且B和C很可能还没到愿意跟我们深入合作的程度。"

决策层（管理/采购）说"多供应商比较"时的理解：

> "我们要防止被单一供应商绑定，要有议价筹码，要有备份方案。这在供应链管理中是基本原则。"

**问题在于**：双方说的"多供应商"根本不是一个东西。

| 视角 | 口中的"多供应商比较" | 实际意指 | 合不合理 |
|:-----|:--------------------|:---------|:--------|
| **决策层** | 战略层面的"避免锁定" | 规模化后的二供策略 | ✅ 合理但时机不对 |
| **执行层** | 战术层面的"同时对接多家" | 每家都要投入资源做联合开发 | ❌ 当前阶段不可行 |
| **采购** | 流程层面的"招投标比价" | 让几家在同等条件下报价 | ❌ 条件根本不成熟 |

### 3.2 五大致命伤害

#### 伤害 #1：资源被稀释——研发的带宽有限

联合POC不是买标准品——它需要**双方的工程师坐在一起**：

- 你的研发团队：理解对方方案、做集成适配、调试
- 对方的FAE团队：提供技术方案支持、参与联合调试

做一家需要投入的工程师资源 = X。做三家 = 3X。

问题是：**POC阶段研发团队的人力是固定的**。如果要求同时和三家供应商做联合POC，结果往往不是"比较了三家后选最好的"，而是"三家都没有真正深入合作，每家都只做了皮毛，POC结果全部不合格"。

#### 伤害 #2：信任被摧毁——没有供应商愿意当"备胎"

供应商的视角：

> "你同时找了三家做POC，说白了就是拿我当备胎。那我有什么动力把核心技术细节跟你共享？有什么必要把FAE最好的工程师派给你们？"

**供应商的理性选择**：

- 如果供应商A知道你在同时接触B和C → A不会投入最优质的资源
- 如果A判断你的量不大、且忠诚度低 → A会把你放在"普通客户"级别
- 你同时做三家的POC，每家投入度都是30%，没有一家做到100% → 结果是三家都做不好，然后得出"市场上不行"的结论

#### 伤害 #3：联合开发的互惠逻辑被破坏

POC阶段的联合设计，本质是一个**互惠**过程：

```text
你方投入：需求定义、集成资源、应用场景验证、早期订单承诺
                     ⇅
供应商投入：技术方案、FAE支持、早期样品、定制化适配、优先供应
```

当你要求"多供应商比较"时，你打破了互惠中的**信任前提**——你向供应商传递的信号是"我不打算跟你深度绑定，你只是候选之一"，那么供应商的理性选择就是"那我也不投入太多资源"。

**互惠被打破后的结果**：

```text
"多供应商比较"指令
        v
供应商感知到"我只是候选之一"
        v
供应商降低投入（不派最佳FAE、不共享核心技术细节）
        v
POC质量下降、周期拉长
        v
你的结论："这家也不行，再看看别家"
        v
换下一家 -> 循环
```

#### 伤害 #4：无法对等地比较——POC结果不可比

"多供应商比较"的前提是能在**同等条件下**比较。但POC阶段这个前提不成立：

| 对比维度 | 为什么不可比 |
|:---------|:------------|
| **POC范围** | 每家供应商的理解不同、投入不同，A做了深度场景验证，B做了规格对齐——产出不对等 |
| **对接深度** | 你团队跟A合作了三周建立了默契，跟B刚认识三天——关系深度不同，无法比较"产品好坏" |
| **样品成熟度** | 有的供应商给工程样品、有的一年前量产、有的刚流片回来——成熟的版本自然表现更好 |
| **FAE水平** | 派来的FAE经验差异巨大——好的FAE能把60分的方案做出80分，差的能把80分的方案做成60分 |
| **你方投入** | 你的研发团队对不同供应商的投入天然不对称——跟熟悉的方案花的时间少、表现好，跟陌生的方案花时间多、问题多 |

**结论**：在这个阶段"做比较"，你比较的**不是供应商的产品**，而是**你们的合作深度和双方的投入度**。

#### 伤害 #5：错失窗口期——时间才是最贵的成本

在技术快速迭代的行业（AI服务器/芯片/互联），**POC窗口期通常只有3-6个月**。在这段时间里：

```text
正确的做法：
  集中资源做1家 -> POC快速通过 -> 产品定型 -> 进入量产验证
  总耗时：3-4个月

错误的做法：
  分散资源做3家 -> 每家只做60% -> 没有一家通过 -> 再选一家重新做
  总耗时：6-8个月
```

**时间成本 > 任何可能的差价收益**。晚一个季度进入市场，可能意味着丢失整代产品的市场机会。

### 3.3 一个思想实验

> 假设现在是2023年，你的公司想做AI服务器，需要采购HBM（高带宽内存）。
>
> 当时全球只有SK海力士能量产HBM3。你去找SK海力士说：
>
> **"我们想把你们的HBM放到我们的AI服务器方案里。不过按照公司的采购流程，我们需要至少三家供应商做比较。你能把HBM3样品给我们做POC，同时我们也在跟三星和美光谈。"**
>
> SK海力士的反应会是：
> A. "好的，我们把最先进的HBM3样品和技术支持给你们。"
> B. "等你们确定了再来谈，我们的产能优先给忠诚客户。"
> C. "既然这样，HBM3优先供应给NVIDIA，你们排队。"（历史上的真实情况）
>
> **正确答案是C**。

这就是"POC期要求多供应商比较"的代价——**在你需要用"诚意"换取"合作"的时候，你选择用"比价"换来了"排队"**。

## 4. 采购模式的四阶段演进模型

### 4.1 阶段零：能不能买到？——准入型采购（Technology Access）

**核心问题**：这个技术/产品存在吗？对方愿意卖给我吗？

**典型场景**：

- 新技术刚出来（如 2025 年的 HBM4、PCIe Gen6 Retimer）
- 产能被头部客户锁定
- 供应商只服务 Tier 1 客户
- 对方是否需要 NDA、信用审核、PO 门槛

**核心策略**：

| 策略 | 说明 |
|:-----|:------|
| **找对门** | 先搞清楚谁是决策窗口——Sales? FAE? 代理商? 不同窗口策略不同 |
| **借力** | 通过ODM/OEM间接采购、通过代理商打破僵局 |
| **技术敲门** | 用技术问题代替RFQ作为第一次接触——FAE天然愿意回答技术问题 |
| **预期管理** | 给对方清晰的增长预期，即使初期量小 |
| **高层对接** | 瓶颈型/战略型器件需要公司层面而不是采购层面的对接 |

**关键交付物**：

- 供应商可接触 ✅ / ❌
- 样品可获得性
- 最低交易条件（MOQ/Lead Time/信用）

**衡量标准**：能不能买得到？——不问价格，问有没有。

### 4.2 阶段一：愿不愿意合作？——关系型采购（Partnership Building）

**核心问题**：对方是否愿意为我们的需求投入资源？能否进行联合设计？

**典型场景**：

- 你和供应商都处于POC阶段，技术方案未定型
- 需要双方工程师一起调优
- 供应商方案需要针对你的场景做定制化

**核心策略**：

| 策略 | 说明 |
|:-----|:------|
| **排他/优先权** | 在早期阶段给予供应商"优先合作"地位，换取对方深度投入 |
| **联合路线图** | 双方对齐技术路线图，确保长期绑定 |
| **资源对等投入** | 明确双方投入的人员和时间，避免单方面消耗 |
| **分阶段承诺** | 不要求对方一次性承诺产能，但给逐步放量的路线图 |
| **信息共享** | 共享你的需求预测、场景定义、技术约束，让对方可以有针对性地投入 |

**关键策略：为什么要做"独家"或者"准独家"**

在POC阶段，**主动选择一家深度合作**，比"保持多家接触"更有利：

| 做法 | 深度合作（1家） | 多供接触（3家） |
|:-----|:--------------|:---------------|
| 供应商投入度 | 高（≈100%） | 低（≈30%/家） |
| POC质量 | 高 | 低 |
| POC周期 | 短 | 长 |
| 供应商信任度 | 高 | 低 |
| 后续商务空间 | 锁定后议价空间小（交易成本） | 理论上空间大（但没做成） |
| 切换成本 | 高（但这是POC成功后才面对的问题） | 低（但POC都没成功） |

**关键洞察**：POC期的目标不是"降低切换成本"，而是**"确保POC成功"**。POC都不成功，切换成本再低也没有意义。

**关键交付物**：

- NDA + 联合开发协议签署
- 双方人员对接机制建立
- 技术路线图对齐文件
- POC 计划书

### 4.3 阶段二：能不能集成？——技术型采购（Technical Integration）

**核心问题**：对方的方案在我们的系统中是否能稳定工作？集成复杂度多高？

**典型场景**：

- POC 通过了，但需要做系统级验证
- 需要适配你的固件/BMC/管理接口
- 可靠性测试、压力测试、兼容性验证
- 开始小批量供货

**核心策略**：

| 策略 | 说明 |
|:-----|:------|
| **技术认证闭环** | 建立完整的技术认证流程（EVT→DVT→PVT） |
| **质量协议** | 量化质量指标（DPPM/良率/失效模式） |
| **成本建模** | 基于实际测试结果建立总拥有成本（TCO）模型 |
| **替代方案预研** | 在不影响当前合作的前提下，技术层面开始评估其他方案 |
| **技术保护条款** | 在合同中约定技术变更通知、版本兼容性责任 |

**关键交付物**：

- 技术认证报告
- 小批量试产报告
- 成本模型分析
- 替代方案评估文档（技术层面，非商务层面）

### 4.4 阶段三：划不划算？——竞争型采购（Competitive Bidding）

**核心问题**：在多个合格供应商之间，如何最优分配份额？

**适用前提**：

- ✅ 至少有两家以上供应商通过了技术认证
- ✅ 技术方案已稳定，不需要联合开发
- ✅ 市场供应充分，没有产能瓶颈
- ✅ 切换成本可以量化并可接受
- ✅ 供应商关系从"合作伙伴"转为"供应关系"

**核心策略**：

| 策略 | 说明 |
|:-----|:------|
| **多供份额分配** | 主供50-60%+二供20-30%+三供10-20%，动态调整 |
| **年降谈判** | 基于学习曲线和规模效应谈判年度降价 |
| **QBR** | 季度供应商绩效评估，驱动持续改进 |
| **替代竞争** | 保持第二/三供应商的认证状态，产生竞争压力 |
| **招标/竞价** | 标准化器件的定期竞价 |

**关键交付物**：

- 供应商绩效评分卡
- 年度商务谈判协议
- 多供分配方案

### 4.5 阶段演进总图

```text
时间轴：--- Concept --- POC --- EVT --- DVT --- PVT --- MP --- EOL
              |         |       |        |        |       |
采购模式：  准入型    关系型   技术型    技术型   竞争型  竞争型
              |         |       |        |        |       |
供应商：     无人理   选1家   锁定1家  评估2供   多供    多供
              |         |       |        |        |       |
研发投入：    低        极高    高       中       低      维护
              |         |       |        |        |       |
采购投入：    高(敲门)  中      中低     高       极高    中
              |         |       |        |        |       |
"多供应商"：  ❌不适用  ❌有害   ⚠️技术预研  ✅开始可   ✅必须做
                                                        ✅必须做
```

## 5. "多供应商"的正确打开方式

"多供应商"本身没有错——错的是在错误的时间做了正确的事。

### 5.1 什么阶段该做什么

| 阶段 | 供应商策略 | 多供应商的含义 |
|:-----|:-----------|:---------------|
| **概念期** | 广泛扫描，建立清单 | 信息收集意义上的"多看几家"——看技术路线，不看报价 |
| **POC期** | 选1-2家深度合作 | ❌ 不要同时在多家做联合POC |
| **EVT期** | 锁定1家主供+预研备选 | 技术层面评估替代方案，但不投入商务谈判 |
| **DVT/PVT期** | 主供认证+二供导入启动 | 开始正式引入第二家做技术认证 |
| **MP早期** | 主供+二供量产验证 | 二供小批量供货，验证质量一致性 |
| **MP成熟期** | 多供份额动态分配 | 多供应商竞价、份额调整、年降谈判 |

### 5.2 渐进式引入策略

正确的"多供应商策略"是一个**渐进过程**，而不是一个**一次性决策**：

```text
Step 1: POC阶段 -> 选1家主攻
    |
    +- 成功 -> 进入EVT
    |
    +- 失败 -> 换另一家做POC（串行，不是并行）

Step 2: EVT阶段 -> 技术层面预研第二家（研发调配少量资源做评估）
    |
    +- 发现第二家技术可行 -> 记录为"候选方案"
    |
    +- 发现不可行 -> 继续聚焦主供

Step 3: DVT阶段 -> 正式启动第二家认证
    |
    +- 认证通过 -> PVT阶段作为二供
    |
    +- 认证不通过 -> 继续寻找或保持独家

Step 4: MP阶段 -> 多供并行

```

**关键原则**：二供的引入**在时间序列上**与主供错开，而不是在POC阶段"同时引入"。

### 5.3 联合开发中的合作契约设计

当你决定在POC阶段与一家供应商深度合作时，如何避免后续被"锁定"带来的被动？

**解决方案不是"保持多家接触"（这会毁了POC），而是在合作契约中设计保护条款**：

| 保护机制 | 设计方式 | 平衡点 |
|:---------|:---------|:-------|
| **分阶段承诺** | 不要一次性承诺全部量，而是"通过POC→进入EVT，EVT通过→进入PVT" | 对方获得确定性的阶梯增长，你保持阶段性选择权 |
| **IP归属约定** | 联合开发产生的IP归属提前约定 | 避免后续被技术绑架 |
| **技术退出条款** | 如果供应商在某个时间点未达到技术指标，你有权终止合作 | 给你退出路径，同时给供应商压力 |
| **定价锁定** | 在POC阶段约定"研发定价"和"量产定价"的关系 | 避免POC过后被漫天要价 |
| **信息透明** | 对方的技术路线图、产能规划、定价机制保持透明 | 建立信任，减少"信息不对称"带来的锁定恐惧 |

**核心思想**：用**合同条款**解决"被锁定"的恐惧，而不是用**同时对接多家**这种破坏信任的方式。

## 6. 组织内的"鸡同鸭讲": 为什么研发和采购总掐架？

### 6.1 角色天然冲突

| 维度 | 研发 | 采购 |
|:-----|:-----|:-----|
| **KPI** | 技术领先、按时交付、性能达标 | 成本控制、供应安全、流程合规 |
| **时间观** | 技术节奏（流片/验证/调试周期） | 财年节奏（季度降本/年度招标） |
| **供应商观** | 技术合作伙伴（一起做东西） | 交易对手（管理风险/控制成本） |
| **对"唯一"的看法** | "说明我们眼光一致，合作深入" | "太危险了，被锁定了怎么办" |
| **对"多供"的看法** | "分散精力，每家都做不好" | "分散风险，保持议价能力" |

这些冲突不是谁对谁错——是各自的职责和指标不同导致的**系统性矛盾**。

### 6.2 "研发主导"vs"采购主导"的条件

一个简单的决策矩阵：

| 技术成熟度 | 市场供应格局 | 应该由谁主导 | 采购模式 |
|:----------|:------------|:------------|:---------|
| 不成熟（POC） | 寡头/独家 | **研发主导**，采购配合 | 关系型/准入型 |
| 不成熟（POC） | 充分竞争 | 研发主导，采购早期介入 | 技术型 |
| 中等成熟 | 寡头 | 研发+采购联合主导 | 技术型 |
| 中等成熟 | 充分竞争 | 采购主导，研发技术支持 | 竞争型过渡 |
| 成熟 | 寡头 | 采购主导，研发配合 | 竞争型（受限） |
| 成熟 | 充分竞争 | **采购主导**，研发评审 | 竞争型 |

**关键规律**：**技术不确定性越高、供应集中度越高，采购越应该由研发主导**。反之亦然。

### 6.3 采购的角色进化——从"砍价员"到"供应商关系建筑师"

不能把"POC期不让做多供应商比较"理解为"不要采购介入"——恰恰相反，采购在POC期的角色**更加重要**，只是**不是砍价**：

| 采购的阶段角色 | POC期 | MP期 |
|:--------------|:------|:-----|
| **关系建立** | 主导——帮研发找到对的门、搭线 | 维护——供应商日常关系管理 |
| **合同设计** | 主导——设计保护条款、分阶段承诺 | 执行——长期合同履约管理 |
| **风险识别** | 主导——识别供应风险、单一依赖风险 | 监控——供应风险持续跟踪 |
| **技术评估** | 配合——协助研发评估供应商资质 | 不参与 |
| **价格谈判** | 不参与（或只设上限） | 主导——竞价、年降、招标 |

**POC期采购的价值不是"把价格打下来"，而是"把这个合作做起来"**。

## 7. 典型案例

### 7.1 反面案例：POC期要求三供比价导致全面翻车

**背景**：某服务器厂商研发团队在2025年评估下一代PCIe Gen5 Retimer芯片选型。

**经过**：

| 时间 | 事件 | 详情 |
|:-----|:-----|:------|
| T0 | 研发识别3家候选供应商 | A（行业龙头），B（追赶者），C（新进入者） |
| T0+1M | 公司要求"三家同时做POC" | 采购部门要求三家同时送样，以便"充分比较" |
| T0+1M | 三家开始对接 | 研发团队只有3名工程师，每家分1人对接 |
| T0+2M | 供应商A发现B和C也在做 | A的FAE资源从"每周驻场3天"改为"每周电话1次" |
| T0+3M | 三家POC都未完成 | 每家都有技术问题，但都卡在自己拿不到足够FAE支持 |
| T0+4M | 决策延期 | 项目延期一个季度 |
| T0+5M | 最终选了A | 但A的FE资源已分配给了其他客户 |
| T0+8M | A方案量产 | 比原计划晚了4个月 |

**根因分析**：

1. **资源分散**：研发团队3个人根本无法同时支撑3家POC
2. **信任破裂**：供应商A得知"被比价"后主动降低投入
3. **窗口错失**：4个月的延期导致产品错过了客户的采购窗口

**教训**：如果最初集中精力做A一家POC（3个月完成），然后有充裕的时间在EVT阶段再评估B和C（即使最终仍选A，时间上也更从容）。

### 7.2 正面案例：战略性供应商的分阶段合作

**背景**：某AI服务器厂商在2024年想做支持OAM（OCP Accelerator Module）标准的AI服务器，需要与一家GPU模块供应商深度合作。

**做法**：

| 阶段 | 动作 | 供应商策略 |
|:-----|:-----|:-----------|
| 概念期 | 调研了5家GPU模块供应商的技术路线 | 广泛扫描 |
| POC期 | 选定AMD作为POC合作伙伴，签订联合开发协议 | **独家深度合作** |
| POC期 | 双方的架构师每周一次联合技术会议 | 深度绑定 |
| EVT期 | POC通过后，开始接触NVIDIA做技术预研（不投入商务） | 技术评估备选 |
| DVT期 | 正式引入NVIDIA作为第二家技术认证 | 多供开始 |
| PVT期 | AMD主供70%+NVIDIA认证通过 | 多供成型 |
| MP期 | AMD 60% + NVIDIA 40%，动态调整 | 竞争型采购 |

**成功要素**：

1. **POC阶段不搞"虚假的公平"**——集中资源做一家，快速通过验证
2. **分阶段引入备选**——POC通过后再评估第二家，而不是POC阶段同时做
3. **保护条款**——与AMD的合作协议中包含了清晰的IP归属和分阶段承诺
4. **采购的角色**——采购在POC期做的是合同设计和风险条款，不是砍价

## 8. 决策检查清单

当你面临"要不要在POC阶段做多供应商比较"的决策时，按顺序问自己以下问题：

### 第一关：阶段判断

```text
□ 我们的技术/方案处于什么阶段？
   -> POC/概念期 -> 跳到第二关
   -> 已有成熟方案/量产 -> 多供应商比较合理，可以执行

□ 供应商的技术处于什么阶段？
   -> 也处于早期POC/尚未规模量产 -> 跳到第二关
   -> 已量产/已有多家客户验证 -> 考虑多供
```

### 第二关：可行性判断

```text
□ 市场上现在有几家供应商能做？如果只有1-2家 -> "多"不存在
□ 这些供应商是否愿意跟我们深度合作？
   -> 如果对方也不确定 -> 先建立关系，不谈比较
□ 我们的研发团队能同时支撑几家POC？
   -> 能支撑3家以上 -> 可考虑并行（但需评估信任影响）
   -> 只能支撑1-2家 -> 串行更优
```

### 第三关：价值判断

```text
□ "多供应商比较"能带来什么好处？
   -> 价格优势？ -> POC阶段没有基准价，无从比较
   -> 供应安全？ -> 等到POC过了再评估备选也来得及
   -> 技术优选？ -> 技术优选应该在POC前就做完（概念期扫描）

□ "独家合作"会带来什么风险？
   -> 被锁定？ -> 可以通过合同条款（分阶段承诺/IP归属/退出条款）解决
   -> 后续议价被动？ -> 可以在POC阶段锁定量产定价公式

□ 时间成本 vs 可能的收益？
   -> 多供并行导致的延期损失，是否大于可能的差价？
```

### 决策规则

> **如果通过三关检查后，结论仍然是"POC阶段需要多供应商比较"，请自问最后一个问题：**
>
> **"如果当初我们1家专心做3个月就完成了POC，剩下的时间再从容评估第二家，是不是比3家一起做6个月都做不完更高效？"**

## 9. 总结：采购的智慧在于知道"什么时候用什么方法"

### 核心追问再审视

回到最初的问题：

> **"早期POC阶段，别人可能也是处于POC阶段，需要进行联合设计。你让研发进行多供应商考虑，是否合适？"**

答案是：**非常不合适**。在POC阶段要求多供应商比较，本质上是**用一个错误的问题去解决一个不存在的问题**。

| 你认为的问题 | 实际的问题 |
|:------------|:-----------|
| "我们被单一供应商锁定怎么办？" | "我们连能不能买到/有没有人愿意合作都没确定" |
| "我要多家比较才能选到最好的" | "你在POC阶段根本无法对等地比较" |
| "这是供应链管理的标准做法" | "这是量产期的标准做法，不是创新期的" |

### 三条基本规律

**规律一：采购模式必须与技术成熟度对齐**

> 技术越不成熟，采购越应该倾向**关系型/准入型**，而不是竞争型。
> 采购的"标准流程"在创新场景下并不适用。

**规律二：先解决"有没有"，再谈"贵不贵"**

> ```text
> 正确的顺序：
> 能买到吗？ → 愿意合作吗？ → 能集成吗？ → 划不划算？
> (准入)        (关系)          (技术)        (竞争)
> ```
>
> 跳过一个阶段，上层阶段的策略就是空中楼阁。

**规律三：独家是POC成功的必要条件**

> 在POC阶段，"独家"不是风险——它是换取供应商深度投入的**筹码**。
> 你的"独家的承诺"换来了对方的"最优质的资源"。
>
> 真正的风险不是独家，而是**在没有得到任何实质性好处的情况下就把独家用掉了**。

### 给研发的建议

- POC阶段**主动选定一家**深度合作，精力集中才能出成果
- 用合同条款（而非"保持多家接触"）来控制锁定风险
- 把"多供应商评估"的时间窗口放在POC**之后**，而不是**同时**

### 给采购/管理的建议

- POC阶段**不要用量产期的KPI来考核采购**
- 把采购的角色从"砍价员"调整为"合作建筑师"
- 在POC阶段，采购的价值体现在：**能否帮研发找到愿意合作的供应商、能否设计出保护性的合作条款**——而不是"价格比去年降了多少"

### 给战略层的建议

> **什么时候应该让研发"做多供应商比较"？答案是：当你确认至少有2家供应商已经通过了技术认证、产能充足、且愿意跟你做生意的时候。**
>
> **在那之前——先帮研发解决"能不能买到"和"谁愿意合作"的问题。**
