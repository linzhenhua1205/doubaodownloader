## 核心命题

构建三层闭环数据稽核体系（日自动扫描→周人工复核→月全域对账），解决服务器研发过程中隐性漏填、逻辑冲突、跨系统不一致、长期历史数据失真等数据质量问题，保障研发管理数据资产的可信度。

### 推行三阶段

```text
第1月：基础搭建期
  +-- 确定稽核覆盖的数据域 + 字段清单
  +-- 完成3大规则库系统开发（完整性/准确性/一致性）

  +-- 定义角色与RACI矩阵，确定4组专员人选

第2月：试运行期
  +-- 自动化日度稽核上线试运行 + 异常推送
  +-- 周度人工复核流程跑通（含首次全量复核）
  +-- 周会通报机制建立
  +-- 收集规则bug白名单反馈，迭代校验逻辑

第3月：稳定运行期
  +-- 月度全域对账流程首次执行
  +-- 首期KPI考核数据产出
  +-- 优化规则库（将高频缺陷固化为自动规则）

```

## ⚙️ 第四部分：稽核规则 SQL 伪代码（系统实现参考）

以下伪代码展示如何在数据库层面实现自动化稽核规则，供开发团队直接参考。

### 4.1 完整性稽核

```sql
-- 规则：项目类必填字段完整性检查
SELECT
    p.project_id,
    p.project_name,
    CASE WHEN p.tr_milestone IS NULL THEN '无TR时间' END AS tr_check,
    CASE WHEN p.di_target IS NULL THEN '无DI目标' END AS di_check,
    CASE WHEN p.quality_owner IS NULL THEN '未绑定质量接口人' END AS qa_check,
    CASE WHEN p.delivery_baseline IS NULL THEN '无交付基线' END AS baseline_check
FROM projects p
WHERE p.updated_at >= CURRENT_DATE - INTERVAL '1 day'
  AND (p.tr_milestone IS NULL OR p.di_target IS NULL
       OR p.quality_owner IS NULL OR p.delivery_baseline IS NULL);
```

```sql
-- 规则：问题工单根因完整性（已闭环但根因为空）
SELECT
    t.ticket_id, t.summary, t.status, t.closed_at
FROM tickets t
WHERE t.status = '已闭环'
  AND (t.root_cause IS NULL OR t.root_cause = '')
  AND t.updated_at >= CURRENT_DATE - INTERVAL '1 day';
```

### 4.2 准确性稽核

```sql
-- 规则：时间逻辑校验（TR时间早于单据创建时间）
SELECT
    tr.project_id, tr.tr_name, tr.planned_date, prj.created_at
FROM tr_milestones tr
JOIN projects prj ON tr.project_id = prj.project_id
WHERE tr.planned_date < prj.created_at
  AND tr.updated_at >= CURRENT_DATE - INTERVAL '1 day';
```

```sql
-- 规则：数值区间校验（负载率>120%无备注）
SELECT
    w.project_id, w.resource_name, w.workload_rate, w.remark
FROM workload w
WHERE w.workload_rate > 120
  AND (w.remark IS NULL OR w.remark = '')
  AND w.updated_at >= CURRENT_DATE - INTERVAL '1 day';
```

```sql
-- 规则：业务联动校验（P0故障无应急方案）
SELECT
    t.ticket_id, t.severity, t.summary, t.emergency_plan
FROM tickets t
WHERE t.severity = 'P0'
  AND (t.emergency_plan IS NULL OR t.emergency_plan = '')
  AND t.status != '已关闭'
  AND t.updated_at >= CURRENT_DATE - INTERVAL '1 day';
```

### 4.3 一致性稽核

```sql
-- 规则：TR时间跨表不一致（仪表盘 vs 变更单）
SELECT
    d.project_id, d.tr_date AS dashboard_tr_date,
    c.tr_date AS change_tr_date,
    ABS(EXTRACT(EPOCH FROM (d.tr_date - c.tr_date)) / 86400) AS day_diff
FROM dashboard_tr d
JOIN change_orders c ON d.project_id = c.project_id AND d.tr_name = c.tr_name
WHERE ABS(EXTRACT(EPOCH FROM (d.tr_date - c.tr_date)) / 86400) > 1
  AND (d.updated_at >= CURRENT_DATE - INTERVAL '1 day'
       OR c.updated_at >= CURRENT_DATE - INTERVAL '1 day');
```

```sql
-- 规则：工单状态与周报状态不同步
SELECT
    t.ticket_id, t.status AS system_status,
    r.status AS weekly_status
FROM tickets t
JOIN weekly_reports r ON t.ticket_id = r.ticket_id
WHERE t.status != r.status
  AND t.updated_at >= CURRENT_DATE - INTERVAL '1 day';
```

## 🔄 第五部分：异常处理决策树

### 5.1 完整性异常处理路径

```text
发现完整性异常
    |
    +-- 必填字段为空 -> 推送责任人 -> 24h/12h内补全
    |                        |
    |                        +-- 按时补全 -> 复核通过 -> 销项
    |                        +-- 超期 -> 自动升级 -> 部门负责人督办
    |
    +-- 特殊场景无法填写 -> 添加白名单备注 -> 复核确认 -> 豁免
```

### 5.2 准确性异常处理路径

```text
发现准确性异常
    |
    +-- 时间逻辑错误 -> 检查是否为业务特例
    |                  +-- 是 -> 添加备注说明
    |                  +-- 否 -> 修正时间数据
    |
    +-- 数值异常 -> 核实原始数据来源
    |              +-- 录入错误 -> 修正数值
    |              +-- 数据源异常 -> 反馈平台排查
    |
    +-- 业务联动冲突 -> 追溯完整业务链，确定哪个环节数据失真
                        +-- 工单闭环但根因为空 -> 补填根因+加固措施
                        +-- P0无应急方案 -> 补充应急止损方案
                        +-- 产线异常未关联批次 -> 关联硬件批次+固件版本
```

### 5.3 一致性异常处理路径

```text
发现跨表数据不一致
    |
    +-- 确定哪个系统是权威数据源（Source of Truth）
    |   +-- 权威方数据正确 -> 修正另一系统数据
    |   +-- 权威方数据错误 -> 修正权威方 -> 向下游系统同步
    |
    +-- 差值产生根因排查
    |   +-- 接口同步bug -> 修复接口，重跑同步
    |   +-- 人工漏录 -> 补录缺失数据
    |   +-- 数据过滤规则差异 -> 统一过滤逻辑
    |
    +-- 修复后执行全量重新对账 -> 确认一致
```

## ⚡ 第八部分：常见风险与应对预案

| 风险 | 概率 | 影响 | 预警信号 | 应对措施 |
|:-----|:----|:-----|:---------|:---------|
| 自动化稽核误报率过高 | 高 | 低 | 日推送消息过多，责任人无视 | 设置白名单机制，首周人工校准规则阈值 |
| 人员不配合整改 | 中 | 高 | 12h/24h闭环率 < 60% | 逾期自动升级至部门负责人，纳入绩效 |
| 跨系统数据无法对接 | 中 | 高 | 月度对账无法执行 | 先做内部系统自检对账，外部系统逐步接入 |
| 历史数据清洗量过大 | 中 | 中 | 月度任务耗时>2天 | 分批清洗：按项目关闭时间倒序，每月处理12个月 |
| 稽核变成形式主义 | 中 | 高 | 整改率100%但问题重复出现 | 将「机制沉淀」纳入考核，验证规则是否新增到系统 |
| 新员工不熟悉规范 | 低 | 中 | 新项目完整率突然下降 | 入职数据规范培训+导师检查数据后方可提交 |
