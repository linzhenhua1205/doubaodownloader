## 2. 全研发周期流程管控与关键节点

### 2.1 IPD 流程与 AI 服务器整机研发的融合

服务器整机研发全流程匹配 IPD 每个 TR 节点：

```text
需求输入 -> 机型定义 -> 预布局 -> 原理图/结构堆叠
-> 样板试制 -> 测试验证 -> 基线固化
-> 量产导入 -> 降本 -> 机型延伸 -> 退市
```

### 2.2 各阶段输入-活动-输出全景

| 阶段 | 前置输入 | 核心活动 | 必出交付物 | 后置依赖 |
|:-----|:---------|:---------|:-----------|:---------|
| **P0 需求分析** | 市场洞察、客户需求、友商对标 | 产品定义、场景定义、需求分解 | 产品需求规格书 (PRD) | P1 概要设计 |
| **P1 概要设计** | PRD、技术可行性评估 | 架构选型、方案权衡、跨域同步 | 系统架构方案、HLD 文档 | P2 详细设计 |
| **P2 详细设计** | HLD 方案、器件选型清单 | 原理图设计、Layout、堆叠设计 | 原理图、CAD、BOM 初版 | P3 样机制作 |
| **P3 样机验证** | 样板、测试计划 | 功能/性能/可靠性/合规测试 | 测试报告、DVT 报告 | P4 量产导入 |
| **P4 量产** | DVT 通过、BOM 锁定 | 小批量试产、良率爬坡 | MP 基线、SOP | 持续交付 |
| **P5 生命周期** | 量产基线 | 降本、延伸、维护 | 降本报告、ECN | EOL 退市 |

### 2.3 TR 节点全视图

| TR 节点 | 阶段映射 | 交付物 | 决策权限 | 决策门槛 |
|:--------|:---------|:-------|:---------|:---------|
| **TR1** | P0 → P1 | 需求分析、场景定义、市场评估 | IPMT | "为什么做"——机会明确 |
| **TR2** | P1 → P2 | 可行性评估、方案选择、风险识别 | PDT Leader | "做什么"——技术路线确认 |
| **TR3** | P2 启动 | 系统架构方案、关键部件选型、接口定义 | 系统架构师 | "怎么做"——方案锁定 |
| **TR4** | P2 → P3 | 详细设计（布局/拓扑/散热/供电/DFX） | PDT Leader | 方案锁定，可制造性确认 |
| **TR4A** | P3 启动 | PCB 出带、BOM 初版、样机计划 | 硬件经理 | 样板制作启动 |
| **TR5** | P3 → P4 | 样板验证、功能测试报告、安规预检 | IPMT | 原型通过，可试产 |
| **TR6** | P4 → P5 | 量产基线固化、BOM 锁定、产能确认 | IPMT | 可量产，可交付 |

> 🔗 **关联材料**: 详细板级 Review 清单见 [2026-07-06-33-board-design-review-checklist.md](../../01_product/00_hardware/01_hw-core/2026-07-06-33-board-design-review-checklist.md)，概要设计跨域协同见 [2026-07-06-34-product-hld-cross-domain-checklist.md](../../01_product/00_hardware/01_hw-core/2026-07-06-34-product-hld-cross-domain-checklist.md)

### 2.4 各阶段关键活动详解

#### 需求输入阶段

- 汇总产品、市场、客户、行业标准各方需求
- 明确机型定义（训练/推理/边缘）
- 确定关键技术指标与约束条件（功耗/尺寸/性能/成本目标）
- **输出**: 产品需求规格书 (PRD)，含配置矩阵初版

#### 概要设计阶段

- 系统架构方案制定：互联拓扑、散热架构、供电架构、管理架构
- 多领域联合评审（结构/散热/互联/电源/BMC 同步进行）
- 关键部件选型锁定：GPU/CPU/Switch/Retimer/VR/连接器
- **输出**: HLD 文档 + 多领域 Review 纪要

#### 详细设计阶段

- 原理图设计、Layout 规划、SI/PI 仿真
- 结构堆叠设计、散热仿真、结构件开模
- DFX 全面评审（DFM/DFT/DFS/DFR/DFP/DFEE）
- **输出**: BOM 初版 + 原理图 + 设计评审报告

#### 验证与基线

- 样板试制与功能测试（EVT → DVT → PVT）
- 安规/EMC 认证测试
- 基线固化，BOM 锁定，版本管控
- **输出**: 测试报告 + 认证证书 + 定量基线

#### 量产与后生命周期

- 量产导入，质量管控（MP8 校验、温循/ORT）
- 降本（国产替代、模块复用、议价）
- 机型延伸（8→16→32 卡梯度）
- ECN 变更管理与退市物料管理

### 2.5 研发活动与四大要素的关系

| 要素 | 核心关系 | 关键问题 | 典型失败案例 |
|:-----|:---------|:---------|:-------------|
| **① 活动 ↔ 组织架构** | 必须采用"强矩阵、全栈拉通、责任到人"模式 | 谁负责什么？ | 矩阵过弱导致推诿 |
| **② 活动 ↔ 外部形势** | 外部（政策/供应链/技术）决定方向 | 外部在变什么？ | 忽视政策导致项目流产 |
| **③ 活动 ↔ 信任** | 跨部门信任决定研发速度 | 如何建立信任？ | 信息不对称导致重复工作 |
| **④ 活动 ↔ 认知** | 对技术/市场/供应链的认知决定成败 | 我们真正懂吗？ | 认知盲区导致方案错误 |

## 3. TR评审要素与决策门禁

### 3.1 评审要素全景

每个 TR 节点的评审按以下四维进行：

| 评审维度 | 权重 | 评审内容 | 评审人 |
|:---------|:----:|:---------|:-------|
| **市场与需求** | 25% | 需求匹配度、市场时机、竞争力 | 产品经理 |
| **技术方案** | 35% | 方案合理性、风险可控性、创新点 | 系统架构师 |
| **成本与交付** | 25% | BOM 成本、开发周期、资源规划 | PDT Leader |
| **质量与可靠性** | 15% | DFX 规划、测试覆盖、可靠性目标 | 质量代表 |

### 3.2 TR1 评审要素（概念决策 — "为什么做"）

| 评审项 | 标准 | 常见否决项 |
|:-------|:-----|:-----------|
| 市场机会明确性 | TAM/SAM/SOM 量化，目标客户画像清晰 | ✗ 市场规模凭感觉 |
| 需求可追溯性 | 每项需求可追溯到客户/政策/友商 | ✗ 需求无来源 |
| 竞争定位 | 明确差异化竞争点 | ✗ "大家都在做" |
| 技术可行性 | 关键技术有预研基础或已有参考 | ✗ 需突破的根本性技术无对策 |
| 法规与合规 | 目标市场准入要求已识别 | ✗ 忽视出口管制/信创要求 |

**通过标准**: 产品机会明确、技术可行、市场窗口合理 → 批准进入概念阶段

### 3.3 TR2 评审要素（计划决策 — "做什么"）

| 评审项 | 标准 | 常见否决项 |
|:-------|:-----|:-----------|
| 方案对比 | ≥2 个备选方案，含优劣势分析 | ✗ 仅有一个方案 |
| 风险评估 | 关键技术风险项目有应对预案 | ✗ "没什么风险" |
| 关键路径 | 项目主计划、依赖关系、关键路径明确 | ✗ 无里程碑计划 |
| 成本目标 | 目标成本分解到子系统 | ✗ 无成本预算 |

**通过标准**: 技术路线选定、方案可行、资源到位 → 批准进入计划阶段

### 3.4 TR3 评审要素（开发决策 — "怎么做"）

| 评审项 | 标准 | 常见否决项 |
|:-------|:-----|:-----------|
| 架构方案 | 系统架构图、接口定义、拓扑全面性 | ✗ 缺少关键接口定义 |
| 关键器件选型 | CPU/GPU/Switch/VR/Retimer 选型报告 | ✗ 选用即将 EOL 的器件 |
| SI/PI 仿真 | 高速信号预仿真，满足眼图裕量 | ✗ 无 SI 仿真 |
| 热设计 | TDP 核算，散热方案可行 | ✗ 功率密度超出散热能力 |
| 供电方案 | VR 选型匹配功耗需求，Phase 数合理 | ✗ VR 效率不在最佳区间 |
| 机械结构 | 堆叠方案、尺寸链、结构可行性 | ✗ 结构干涉 |

### 6.2 缺陷管理与收敛曲线

```text
缺陷数量
   ^
   |  ✦ EVT (样板)
   |   \
   |    ✦  -- DVT (测试阶段)
   |    |\
   |    | ✦ --- PVT (验证阶段)
   |    | |\
   |    | | ✦ ---- MP (量产)
   |    | | |
   |    | | |  ----> 收敛目标: DVT末 ≤10 Open
   +----+-+-+----------> 时间
```

**缺陷管理原则**:

- 缺陷等级: Critical(阻塞量产) / Major(影响发布) / Minor(可接受)
- 收敛标准: MP 前所有 Critical/Major 闭环，Minor 可管理
- **零已知缺陷进入下一阶段**（Critical 级别）

## 10. 架构决策方法论与冲突仲裁

### 10.1 架构决策五问框架

在 AI 服务器整机设计的每个关键决策点，用以下五问引导：

| # | 问题 | 输入 | 输出 |
|:-:|:-----|:-----|:-----|
| **Q1** | 我们在干什么？ | 产品需求、场景定义 | 决策范围与约束 |
| **Q2** | 有哪些可选方案？ | 行业方案、供应商方案 | 方案清单 |
| **Q3** | 各方案的优势劣势？ | 性能/成本/风险/生态/TTM | 对比矩阵 |
| **Q4** | 我们的优先约束是什么？ | 目标成本、性能指标、时间窗口 | 权重排序 |
| **Q5** | 如果判断错了，最坏结果是什么？ | 风险分析 | 备选方案/B计划 |

### 10.2 常见冲突场景与仲裁策略

| 冲突场景 | 冲突方 | 核心矛盾 | 仲裁原则 |
|:---------|:-------|:---------|:---------|
| **散热 vs 高密度** | 散热工程师 vs 架构师 | 散热空间 vs 计算密度 | TDP 是硬约束 → 优先满足散热再压密度 |
| **成本 vs 性能** | 采购 vs 研发 | 选用高端器件 vs 成本目标 | 目标成本是铁律，超额必须经过 PDT Leader 审批 |
| **国产化 vs 性能** | 信创 vs 性能评测 | 国产芯片性能差距 | 按客户场景分级：信创项目≥60%国产率 |
| **标准化 vs 定制化** | 产品经理 vs 研发 | 通用平台 vs 客户定制 | 70/30 原则：70% 模块复用，30% 按需定制 |
| **进度 vs 质量** | PM vs 质量 | 按时交付 vs 充分验证 | 质量门禁不可跳，可调整功能范围 |

### 10.3 决策记录模板（ADR）

每项重大架构决策应归档为 ADR (Architecture Decision Record)：

| 字段 | 内容 |
|:-----|:------|
| **ADR ID** | ADR-{YYYYMMDD}-{序号} |
| **标题** | 简要说明决策内容 |
| **背景** | 需要决策的上下文 |
| **约束** | 技术/成本/时间/合规约束 |
| **选项** | ≥2 个备选方案 |
| **决策** | 最终选择 + 理由 |
| **后果** | 正面/负面影响 |
| **日期** | 决策日期 |
| **决策者** | 署名 |

### 11.2 市场驱动策略

| 方向 | 具体动作 | 时间线 | 成功标志 |
|:-----|:---------|:-------|:---------|

```text
  +- 自研能力（核心壁垒）     +- 降本迭代（规模效应）
           |                         |
           +--------- 融合点 ---------+
                 平台化 + 模块化
                 IPD流程管控
                 双供保障 + 强矩阵组织
```

## 12. 结论与展望

1. **AI 服务器行业至少还有 2 年增长期**，随后国产化替代将成为主线
   - **2026-2028**：高速增长，以性能导向为主
   - **2028+**：国产化成为刚需，转向成本与合规导向

2. **16卡→32卡演进**是未来 2-3 年的核心升级路径
   - 技术切换窗口：2027 年前后
   - 关键使能技术：224G SerDes、液冷、PCIe 6.0 Switch、开放 Scale-up 互联

3. **液冷+国产化+AI 赋能研发**是构建竞争壁垒的三大支柱
   - 液冷：PUE < 1.2 已成为准入标准
   - 国产化：政策驱动 + 成本优势
   - AI 赋能：研发效率提升 30%+

4. **POC 验证→模块化复用→基线固化**是经过验证的高效研发范式
   - 先证明可行性
   - 再沉淀为可复用模块
   - 最终固化基线实现规模化

5. **标准参与+生态融合**是决定长期竞争力的关键变量
   - 参与标准 = 影响未来方向
   - 开放生态 = 降低客户锁定风险
