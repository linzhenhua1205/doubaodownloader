### 1.3 业务案例(Business Case)框架

```text
收入模型: Σ(单价×数量×市场份额) / 按产品线/区域
成本模型: BOM(60-75%) + 制造(5-10%) + NRE(3-5%) + 运营(10-15%)
利润分析: 毛利率≥35%(AI服务器), 净利率≥10%
盈亏平衡: 月销量≥N台(按3年摊销NRE)
ROI: 3年累计收入/总投资 ≥ 3:1
敏感性: GPU价格±20% -> 毛利率变动±5pp
```

## 二、TR1 — 产品需求与概念

### 2.1 客户需求访谈SPIN框架

| 问题类型 | 示例 | 目标 |
|------|------|------|
| **S**ituation(现状) | 当前AI训练集群规模？使用哪些GPU型号？ | 了解背景 |
| **P**roblem(痛点) | 最大瓶颈在哪？GPU利用率是否满意？ | 挖掘问题 |
| **I**mplication(影响) | 利用率每低10%带来多少额外成本？ | 量化后果 |
| **N**eed-payoff(价值) | 如果利用率提升至70%，能节省多少？ | 构建愿景 |

### 2.2 PRD(产品需求规格书)十章模板

| 章节 | 内容 | 责任人 |
|:---:|------|:---:|
| 1 | 版本历史/修订记录 | PM |
| 2 | 项目背景与商业目标 | PM |
| 3 | 目标客户画像与使用场景 | PM+市场 |
| 4 | 产品概述(一句话定位+核心竞争力) | PM+SA |
| 5 | 关键硬件规格(GPU/CPU/内存/存储/网络/散热) | SA+HW |
| 6 | 核心功能与非功能需求(性能/可靠/安全) | SA |
| 7 | 竞争分析(竞品对标+差异化策略) | PM |
| 8 | 商业论证(市场规模/收入预测/ROI) | PM+财务 |
| 9 | 项目时间线与里程碑(TR1→TR6) | PM |
| 10 | 风险与依赖(技术/供应链/合规/市场) | PM |

### 2.3 IPD需求层级分解 (来自华为IPD体系)

```text
RR(原始需求: 客户原话)
  v 翻译
IR(初始需求: 以内部语言重新描述)
  v 分解为
+------------------+------------------+
| PB(客户问题/痛点)  | SF(系统特性)        |
|  v 转化为          |  v 分解为          |
| SR(系统需求)       | SR(系统需求)        |
+------------------+------------------+
                      v 分配到
                   AR(分配需求: 硬件/固件/软件/结构/散热)
```

**需求验证**: 每条SR必须可测试、可度量、可追踪→对应测试用例

### 2.4 华为一线"铁三角"模式

| 角色 | 职责 | 对应IPD阶段 |
|------|------|:---:|
| **AR(客户经理)** | 维护客户关系、挖掘新商机 | TR1-TR2 |
| **SR(解决方案专家)** | 将客户需求转化为技术方案 | TR1-TR3 |
| **FR(交付专家)** | 确保方案可交付、可落地 | TR4-TR6 |

### 3.2 IPD三级架构与Gate评审

```text
决策层(IPMT): 集成组合管理团队 — 投资决策/资源分配/Go/Kill
  v DCP决策评审点
管理层(PMT/PDT): 组合管理/产品开发 — TR技术评审
  v TR1-TR6 Gate
执行层(TRT/TDT): 技术评审/技术开发 — 执行活动
```

**IPD L1-L6流程分级**:

- L1: 流程分类(映射公司战略)
- L2: 流程组(端到端价值流切割)
- L3: 完整业务闭环
- L4: 特定环节(如TR3设计评审)
- L5: 最小执行活动(如阻抗仿真检查)
- L6: 原子化操作指令(如检查标准模板)

**华为"僵化→优化→固化"三阶段**: L1-L4标准化, L5-L6末端灵活

### 3.3 TR评审详细标准

| TR | 评审要点 | 通过标准 | 典型交付物 |

## 四、TR4 — 缺陷管理与质量保证

### 4.1 缺陷分级与SLA

| 级别 | 定义 | 响应 | 解决 | 超标升级 | 示例 |
|:---:|------|:---:|:---:|:---:|------|
| **P0** | 致命/阻断(系统不可用) | ≤1h | ≤24h | 2h→总监 | 无法开机/液冷泵停 |
| **P1** | 严重/主功能失效 | ≤4h | ≤72h | 8h→经理 | GPU不可用/NVLink降级 |
| **P2** | 一般/有规避方案 | ≤24h | ≤1周 | 48h→组长 | 降级可用/性能不达标 |
| **P3** | 轻微/不影响功能 | ≤72h | 按迭代 | — | 显示异常/cosmetic |

### 4.2 缺陷管理工具与流程

```text
发现(自动化测试/人工/客户) -> Jira/禅道录入 -> Triage(分类分级) ->
分配责任人 -> 根因分析(5Why/鱼骨图) -> 修复 -> Code Review ->
验证(回归测试) -> 关闭 -> 月度缺陷分析(Pareto/趋势)
```

**缺陷度量**: DDP(缺陷发现率)≥95%、缺陷密度≤0.5/KLOC、缺陷逃逸率≤5%

### 4.3 TR技术评审检查单(完整版)

**通用项**:

- [ ] 技术方案满足SR需求(双向追踪)
- [ ] 关键技术风险已识别并有缓解计划
- [ ] 接口定义完整(硬件/固件/软件)
- [ ] DFX(DFM/DFT/DFR/DFS)已考虑
- [ ] 成本符合目标(≤预算110%)

**TR3(设计评审)专项**:

- [ ] 原理图评审完成(SI/PI/PDN)
- [ ] BOM物料交期确认(长交期件已锁定)
- [ ] 结构3D装配干涉检查通过
- [ ] 热仿真结果满足结温要求
- [ ] 固件架构定义完成

**TR4(验证评审)专项**:

- [ ] P0/P1缺陷全部关闭
- [ ] 关键性能指标达标(SPEC/MLPerf/NCCL)
- [ ] 可靠性测试通过(MTBF≥30000h)
- [ ] 认证预测试通过(EMC预扫/安规预检)
- [ ] Beta客户反馈收集

## 五、TR5 — 发布管理

### 5.1 发布Checklist (完整版)

```text
□ 缺陷: P0/P1全部关闭, P2≤5个且有规避方案
□ 性能: 基准测试达标(SPEC CPU≥目标, NCCL带宽≥90%理论, MLPerf≥基准)
□ 认证: CCC/UL/CE/EMC/环保证书齐全且在有效期内
□ Beta: ≥3个客户, ≥4周验证, 反馈闭环
□ 文档: 硬件手册/运维手册/BMC指南/故障排查指南/安装指南
□ 固件: 版本定版(Git tag), 签名验证, A/B升级方案
□ 备件: 备件清单+最小库存量+订购流程
□ 服务: 服务SLA定义, 培训完成(≥2名认证工程师)
□ 合规: SBOM(SPDX格式)完成, 开源许可证审查
□ 发布: 内部发布公告+客户通知+官网更新
```

### 5.2 Beta验证计划

| 要素 | 内容 |
|------|------|
| 选型标准 | 典型场景覆盖(训练/推理/混合), 不同规模(单机/小集群) |
| 周期 | 4-8周, 含2周磨合+6周正式运行 |
| 数据采集 | 性能指标/可靠性/功耗/温度/运维日志 |
| 反馈闭环 | 每周例会, 问题追踪, 3周整改后再验证 |
| 退出标准 | 客户满意度≥4/5, 关键问题关闭, 运维SOP可执行 |

### 5.3 版本命名与固件管理

**版本命名**: `平台_GPU_PSU_日期` (如 `B200_NVL72_3200W_20260626`)
**固件版本矩阵**: BMC/BIOS/CPLD/GPU VBIOS/SSD FW/DPU FW/PSU FW — 每版本对应一组哈希值
**升级策略**: Canary 1台 → 5% → 25% → 100%, 每阶段观察≥24h
**回滚**: A/B分区, 升级失败自动回滚, BMC记录
