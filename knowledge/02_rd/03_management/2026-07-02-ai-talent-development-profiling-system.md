## 1. 背景与目标

### 1.1 痛点分析

| # | 痛点 | 传统做法 | 问题 |
|:-:|:-----|:---------|:-----|
| P1 | 培训材料人工编写成本高 | 专家讲师花数月编写PPT/文档 | 内容更新慢、覆盖面有限、与最新项目脱节 |
| P2 | 出题质量参差不齐 | 培训负责人手动出题 | 题目分布不均、难度不可控、知识点遗漏 |
| P3 | 掌握度评估粗放 | 卷面分数 | 无法细粒度定位薄弱知识点，只看总分 |
| P4 | 错题难以复用 | 纸质/电子错题本手工整理 | 缺乏系统化复习策略，错题随学随忘 |
| P5 | 人才画像靠主观 | 主管打分+360评价 | 评估标准不统一、缺乏客观数据支撑 |
| P6 | 培训效果难量化 | 培训满意度问卷 | 无法回答"学了能做什么"和"哪些有效" |

### 1.2 目标定义

```text
系统总目标: 构建AI驱动的"采集->生成->训练->评估->画像->改进"人才培养闭环
```

| 子目标 | 指标要求 |
|:------|:---------|
| 知识采集自动化率 | ≥ 90% 内部知识文档自动入库 |
| 培训材料生成效率 | 从2周/份缩短到2小时/份 |
| 出题覆盖率 | 覆盖全部知识点的三级难度(基础/进阶/专家) |
| 掌握度评估精度 | 知识点级粒度，与专家评估一致率 ≥ 85% |
| 人才画像客观性 | 基于 ≥ 200维数据指标，摒弃纯主观评价 |
| 培训ROI可量化 | 培训前后技能差距Δ量化到每个知识点 |

## 3. 知识库引擎（知识基座）

知识库是整个系统的地基。没有高质量的知识库，培训材料生成、出题、评估全部失准。

### 3.1 知识源接入矩阵

| 知识源类型 | 接入方式 | 数据格式 | 更新频率 | 优先级 |
|:----------|:--------|:---------|:--------|:------|
| Confluence/Wiki | REST API 爬取 | HTML/Markdown | 每日增量 | P0 |
| Git 代码仓库 | Git clone + 定期同步 | 代码文件 | 每次提交 | P0 |
| 技术设计文档 | 文件导入/API | PDF/Word/Markdown | 按版本 | P0 |
| 故障复盘(RCA) | Jira API | 结构化JSON | 事件驱动 | P0 |
| 产品手册/规格书 | 文件批量导入 | PDF/Word | 按版本 | P1 |
| 工单/FAQ | ServiceNow/Zendesk API | 文本 | 实时 | P1 |
| 会议录音/培训录像 | 转写服务 | 音频→文本 | 按需 | P2 |
| 外部技术资料 | RSS爬取/DOI | 网页/论文 | 每日 | P2 |

### 3.2 知识处理管道

```text
原始文档
    |
    v
+-------------+
| 格式解析     |  PDF->text, DOCX->markdown, HTML->clean text, 代码->AST摘要
|  (Parser)   |
+------+------+
       v
+-------------+
| 分块/清洗    |  语义分块(2000 tokens/块, 100 tokens overlap)
|  (Chunking) |  去重(Semantic dedup, 相似度>0.95合并)
+------+------+
       v
+-------------+
| 元数据标注   |  知识源/作者/版本/时间/标签/领域/难度等级
|  (Metadata) |
+------+------+
       v
+-------------+
| 向量化嵌入   |  bge-m3(768维) 或 text2vec-large-chinese(1024维)
|  (Embedding)|  存储到 Milvus, 索引类型 IVFFlat(训练聚类数=nlist)
+------+------+
       v
+-------------+
| 知识图谱构建  |  实体抽取(LLM): 技术概念/组件/协议/人物/项目
|  (KG)       |  关系抽取(LLM): 依赖/包含/前置/冲突/扩展
|              |  存储到 Neo4j
+------+------+
       v
+-------------+
| 质量评分     |  完整性(覆盖率) + 准确性(人工抽检) + 时效性(版本标记)
|  (Quality)  |
+-------------+
```

### 3.3 知识图谱 Schema（示例：服务器技术培养）

```text
(:TechnicalDomain {name: "BMC带外管理"})
    --[:HAS_CONCEPT]-->(:Concept {name: "IPMI", level: "base"})
    --[:HAS_CONCEPT]-->(:Concept {name: "Redfish", level: "base"})
    --[:HAS_CONCEPT]-->(:Concept {name: "PLDM", level: "adv"})
    --[:HAS_CONCEPT]-->(:Concept {name: "MCTP", level: "adv"})

(:Concept {name: "Redfish"})
    --[:REQUIRES]-->(:Concept {name: "REST API"})
    --[:REQUIRES]-->(:Concept {name: "JSON Schema"})
    --[:RELATED_TO]-->(:Concept {name: "DMTF Standards"})

(:Person {name: "张三", role: "trainee"})
    --[:MASTERS {level: 0.85, last_assessed: "2026-06-30"}]-->(:Concept {name: "Redfish"})
    --[:LEARNING {priority: "high"}]-->(:Concept {name: "PLDM"})

(:Document {title: "Redfish规范v2025.1", source: "DMTF"})
    --[:COVERS]-->(:Concept {name: "Redfish"})
    --[:HAS_VERSION]-->(:Version {number: "2025.1"})
```

### 3.4 知识质量度量

| 度量维度 | 指标 | 目标值 | 检测方法 |
|:---------|:-----|:------|:---------|
| **完整性** | 领域知识覆盖率 | ≥90% 核心概念已入库 | 与专家定义的覆盖清单对比 |
| **准确性** | 人工抽检通过率 | ≥95% 无事实错误 | 每月随机抽检5%知识块 |
| **时效性** | 版本标注率 | 100% 知识块含版本标签 | 自动化扫描元数据 |
| **一致性** | 同一概念定义冲突率 | ≤2% | 知识图谱语义一致性检查 |
| **可用性** | 检索Top-5命中率 | ≥85% | 测试集召回评估 |

## 4. 智能培训材料生成

### 4.1 生成工作流

```text
指令输入: "为新人工程师生成BMC带外管理培训材料，覆盖IPMI/Redfish/PLDM/MCTP"
    |
    v
+-------------------------------------+
| 阶段1: 知识图谱检索                  |
| 查询Neo4j: MATCH (c:Concept)        |
| WHERE c.domain="BMC"                |
| RETURN c ORDER BY c.level           |
| -> 获取概念层级结构 + 前置依赖关系     |
+--------------+----------------------+
               v
+-------------------------------------+
| 阶段2: 向量检索补充                   |
| 对每个核心概念进行向量检索             |
| TOP-K = 5 高相似度知识块              |
| -> 获取详细技术内容                     |
+--------------+----------------------+
               v
+-------------------------------------+
| 阶段3: 大纲生成(LLM)                  |
| LLM根据层级结构+内容生成:             |
| +-- 学习路径(前置->核心->进阶)          |
| +-- 章节大纲(含预期学习目标)           |
| +-- 每章节预计时间                    |
| -> 结构化大纲输出(JSON)               |
+--------------+----------------------+
               v
+-------------------------------------+
| 阶段4: 逐章节内容生成(LLM)             |
| 每章节以"知识库检索结果+大纲"为context |
| +-- 理论讲解(含原理图+流程图)          |
| +-- 实际操作步骤                       |
| +-- 典型场景/案例                      |
| +-- 常见误区/Trap提醒                  |
| +-- 课后自测题(嵌入)                  |
| -> 完整的培训文档(Markdown/PPT/视频脚本)|
+--------------+----------------------+
               v
+-------------------------------------+
| 阶段5: 质量审查                       |
| +-- 事实准确性(与知识库交叉核对)       |
| +-- 逻辑连贯性(LLM自检+人工抽检)      |
| +-- 难度适配性(是否匹配目标学员层级)   |
| +-- 引用完整性(每个claim标注知识源)    |
+--------------+----------------------+
               v
        交付培训材料 (支持多格式导出)
```

### 4.2 多格式输出

| 输出格式 | 用途 | 生成方式 | 包含内容 |
|:---------|:-----|:---------|:---------|
| **Markdown文档** | 在线阅读/知识库 | 直接生成 | 全部内容+图表+链接 |
| **PPT/Keynote** | 面授培训 | LLM生成大纲→模板渲染 | 核心要点+图表+案例 |

```text
    v

+--------+----------+
         v
+-------------------+     +-----------+

|                   |     | θ_new =   |

         |                      |
         v                      v

    +-- 已答题数量 ≥ 最小题目数(如15)

         |
         是
         v
   输出θ值(能力评估)
   + 知识点级掌握度向量
```

**IRT (Item Response Theory) 三参数模型**:

$$P_i(\theta) = c_i + \frac{1 - c_i}{1 + e^{-a_i(\theta - b_i)}}$$

| 参数 | 含义 | 取值范围 | 说明 |
|:----|:-----|:---------|:-----|
| $\theta$ | 学员能力值 | (-3, 3) 标准化尺度 | 0为平均水平 |
| $a_i$ | 题目区分度 | (0, 2) | 越大越好区分高低能力者 |
| $b_i$ | 题目难度 | (-3, 3) | 越大越难，$b=0$为中等难度 |
| $c_i$ | 猜测概率 | (0, 0.5) | 选择题的蒙对概率，通常0.25 |

## 6. 掌握度评估模型

### 6.1 多维度掌握度定义

```text
掌握度 = f(答题正确率, 答题速度, 实操通过率, 时效衰减, 知识关联度)
```

| 评估维度 | 数据源 | 权重 | 计算方式 |
|:---------|:-------|:----|:---------|
| **答题正确率** | 测验记录 | 40% | 该知识点下所有题目的加权正确率（难度越高权重越大） |
| **答题速度** | 答题日志 | 10% | 相对基准时间的比值，越快表明越熟练 |
| **实操通过率** | 实验环境操作 | 25% | Lab考试/仿真环境的任务完成率 |
| **时效衰减** | 时间戳 | 15% | 指数衰减: $e^{-t/\tau}$, $\tau=90$天（半衰期约62天） |
| **知识关联掌握** | 知识图谱 | 10% | 依赖的前置知识点掌握度平均值 |

### 6.2 知识点掌握度计算公式

$$M_{k,u} = 0.4 \times \frac{\sum_{q \in Q_k} w_q \cdot c_q}{\sum_{q \in Q_k} w_q} + 0.1 \times \min\left(1, \frac{t_{base}}{t_{avg}}\right) + 0.25 \times L_{pass} + 0.15 \times e^{-t_{days}/90} + 0.1 \times \frac{\sum_{p \in Pre_k} M_{p,u}}{|Pre_k|}$$

| 符号 | 含义 |
|:----|:-----|
| $M_{k,u}$ | 学员u对知识点k的掌握度(0~1) |
| $Q_k$ | 关联知识点k的题目集合 |
| $w_q$ | 题目q的权重(基于难度和Bloom层级) |
| $c_q$ | 题目q是否答对(0/1) |
| $t_{base}$ | 基准答题时间 |
| $t_{avg}$ | 实际平均答题时间 |
| $L_{pass}$ | 实操通过率(0~1) |
| $t_{days}$ | 距最后答题天数 |
| $Pre_k$ | 知识点k的前置知识集合 |

### 6.3 掌握度状态定义

| 掌握度区间 | 状态 | 颜色 | 含义 | 建议动作 |
|:----------|:----|:----|:-----|:---------|
| [0.90, 1.00] | ✅ 精通 | 深绿 | 可独立教学/答疑 | 安排为导师或参与更高级课题 |
| [0.75, 0.90) | 📗 熟练 | 浅绿 | 可独立完成任务 | 正常推进，定期复习 |
| [0.55, 0.75) | 📘 基础 | 蓝色 | 需查阅资料完成任务 | 安排针对性练习 |
| [0.35, 0.55) | 🟡 薄弱 | 黄色 | 完成任务需指导 | 安排专项突破+一对一辅导 |
| [0.00, 0.35) | 🔴 未掌握 | 红色 | 基本概念不清 | 纳入强制培训计划 |

### 6.4 评估触发场景

```text
+------------------+
| 主动触发          | 学员主动发起测验/实训
+------------------+
| 被动触发          |
| +-- 完成课程      | 课程完成后自动评估
| +-- 项目交付后    | 实操代码/方案提交后评估
```

### 7.2 智能复习策略（基于间隔重复）

采用 **SM-2 算法** 的改进版，配合知识点关联度做联合复习安排：

```text
每次复习后的下一次复习间隔 =
    base_interval × ease_factor × (1 + 0.2 × knowledge_connections)

其中:
- base_interval: 初始间隔(首次1天，第二次3天，第三次7天...)
- ease_factor: 难度系数，初始2.5，答对+0.1(最多3.0)，答错-0.2(最少1.3)
- knowledge_connections: 关联知识点数量(0~5)，关联越多间隔越长
```

**复习节奏示意**：

```text
答对情况     第1次   第2次    第3次     第4次      第5次
正常:        1天后   4天后    12天后    30天后     75天后
困难:        1天后   2天后     5天后    10天后     20天后
轻松:        2天后   8天后    24天后    60天后    150天后

错题累计->每天3-5题集中复习->掌握后移入"已掌握"库
```

### 7.3 错题归因分析

LLM分析错题，自动归类错误类型并提供针对性的"知识补强建议"：

| 错误类型 | 判定条件 | 占比(典型) | 补强策略 |
|:---------|:---------|:----------|:---------|
| **概念混淆** | 选项选择方向正确但细节错误 | 35% | 推荐对比阅读材料(如IPMI vs Redfish对比表) |
| **知识盲区** | 完全未接触过的知识点 | 25% | 推送到必修课列表，安排专项学习 |
| **理解偏差** | 题干理解错误/场景判断错误 | 20% | 推荐场景化案例学习+实操练习 |

| **计算错误** | 涉及定量计算/配置参数错误 | 8% | 安排专项计算练习+公式卡片 |

### 12.2 伦理与合规原则


**竞争差异化定位**: 我们处在左上角——**技术深度高但产品成熟度待建**。核心壁垒:

### 16.2 北极星指标定义

```text
组织技能密度指数 (Skill Density Index, SDI)

SDI = α × M_avg + β × C_cover + γ × A_activity

参数:
- M_avg: 全员知识点掌握度均值(0~1)     权重α=0.5
- C_cover: 核心知识域覆盖率(0~1)       权重β=0.3
- A_activity: 学习活跃度(0~1)         权重γ=0.2
  (活跃度 = 月活跃学员/全员 × min(1, 月人均学时/20h))

目标:
- 第1年: SDI ≥ 0.55
- 第2年: SDI ≥ 0.70
- 第3年: SDI ≥ 0.80
```

### 17.3 连贯性验证清单

> 每季度执行一次连贯性审计，确保"目的→指标→方案→监控"不走偏

```text
□ Q1: 业务目的是否仍然有效？
   - 组织战略是否变化？
   - 培训优先级是否调整？
   - 是否有新的合规要求？

□ Q2: 量化指标是否仍能反映业务目的？
   - SDI是否仍然对应组织能力目标？
   - 是否有指标已过时？
   - 是否需要新增指标(如新业务域)？

□ Q3: 技术方案是否有效支撑指标达成？
   - 哪些方案效果好(ROI高)？
   - 哪些方案效果不如预期？
   - 是否有更好的技术替代方案？

□ Q4: 监控手段是否覆盖全部关键路径？
   - 是否存在"监控盲区"？
   - 告警阈值是否需要调整？
   - 数据质量是否可靠？

□ Q5: 是否存在执行偏差？
   - 团队是否在"做正确的事"？
   - 资源是否投到最有价值的地方？
   - 是否需要调整阶段路线图？
```
