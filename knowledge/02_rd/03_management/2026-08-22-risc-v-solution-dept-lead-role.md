## 1. 核心命题

RISC-V 芯片公司的解决方案部门，本质是**芯片硬件能力、开源软件生态、客户商业落地三者之间的枢纽**。与 ARM 芯片公司不同，RISC-V 厂商的 SDK/固件/BSP 生态高度碎片化，解决方案部门的使命不是简单做售前方案，而是**抹平生态鸿沟、收敛基线、治理碎片化**，把芯片裸核能力包装成客户可直接量产使用的系统方案。该岗位是「业务 + 系统技术 + 开源生态 + 组织管理」的复合角色，其核心价值主张可概括为：**建立公司生态防火墙、控制技术债务、沉淀可量产可复用的方案资产、平衡客户交付与长期产品路线**。

## 3. 关键洞察

### 3.1 ARM vs RISC-V 解决方案部门的核心差异

| 维度 | ARM 芯片公司 | RISC-V 芯片公司 |
|:-----|:-------------|:----------------|
| SDK/固件基线 | 成熟统一（厂商闭源交付） | 高度碎片化，需解决方案部自建基线 |
| 软件栈资产 | 厂商提供完整 SDK/安全栈 | OpenSBI/U-Boot/BSP/工具链需自行收敛 |
| 客户迁移 | 生态迁移成本低 | ARM→RISC-V 迁移是常态，需迁移评估体系 |
| 碎片化风险 | 低（厂商强管控） | **高**（私有指令/私有补丁/私有 DTS 泛滥） |
| 开源社区 | 少量贡献 | 核心竞争力：上游 Linux/OpenSBI/LLVM 社区补丁 |
| 解决方案部定位 | 售前+方案包装 | **生态防火墙 + 基线治理 + 商业化枢纽** |

**核心洞察**：RISC-V 芯片公司的竞争力不在核（PPA），而在「**生态收敛能力**」——谁能把碎片化的开源栈收敛成客户可量产的系统方案，谁就赢。解决方案部是这家公司的「生态防火墙」[⚠️ 材料自述，逻辑合理]。

### 3.2 解决方案部的三重角色定位

```
+---------------------------------------------------------------+
|  Solution Dept = Eco-Firewall + Commercial Hub + Demand Hub   |
+---------------------------------------------------------------+
|  Up:    align chip roadmap, define solution-level product line |
|  Hori:  connect Sales-Solution-Product-Chip-BSP-FAE workflow  |
|  Down:  manage team (architect/BSP eng/POC eng/doc eng)       |
|  Out:   customers + ecosystem partners + open-source community |
|  Loop:  customer pain -> MRD -> chip/software stack iteration  |
+---------------------------------------------------------------+
```

### 3.3 五大风险管控（RISC-V 公司特有）

1. **碎片化风险**（生命线）：私有指令/私有扩展/私有补丁无序膨胀 → 软件栈越维护越重
2. **对外承诺风险**：把社区能力当量产能力许诺 → 商务纠纷
3. **定制化风险**：无边界客户定制 → 解决方案团队沦为外包
4. **项目风险**：bring-up/工具链/BSP 迁移卡点 → 提前预警
5. **基线失控风险**：GCC/LLVM/内核/固件版本混乱 → 兼容性灾难

## 4. 七大核心工作维度（RISC-V 叠加版）

### 维度 1：战略与业务规划
- 匹配每一代 RISC-V 芯片输出解决方案路线图（参考板/固件基线/SDK/行业套件/OS 适配清单）
- 赛道分层：MCU / 边缘 AI / 服务器 RISC-V；原型验证客户 / POC 客户 / 量产客户
- 对齐 RVA23/RVM23 Profile、PMP/sPMP、PLIC、RVV 等标准规范，**避免私有扩展泛滥**

### 维度 2：需求管理与芯片/软件反向输入（RISC-V 权重极高）
- 三类需求分流：方案层可解决 / 需 BSP-固件-工具链迭代 / 需改 CPU 核或自定义指令
- 管控碎片化：评估客户私有扩展诉求，判断是否纳入标准 Profile 或拒绝
- 闭环：客户需求 → 内部评审 → 研发排期 → 版本交付 → 客户验证 → 反馈迭代

### 维度 3：RISC-V 专属技术体系与方案资产建设（核心重活）
> ARM 厂商 SDK 高度成熟；RISC-V 大量资产必须由解决方案部主导沉淀、收敛基线

| 资产类别 | 具体内容 |
|:---------|:---------|
| 硬件参考资产 | 参考设计板、BOM、原理图、PCB 参考、FPGA 原型平台 |
| 固件 & Boot 基线 | OpenSBI、U-Boot、UEFI（如有），统一 SBI 调用接口 |
| 工具链基线 | GCC/LLVM 版本、RuyiSDK 适配、OpenOCD 调试基线 |
| BSP 与设备树 | Linux 内核 BSP、Zephyr/FreeRTOS BSP、DTS，向上游推进补丁 |
| OS 生态适配 | Linux 发行版、OpenHarmony、RTOS、KVM/RISCV-HV 虚拟化 |
| 文档资产 | 移植手册、ARM→RISC-V 迁移指南、调优手册、故障排查手册 |

### 维度 4：客户项目与售前交付
- 重大客户项目技术总负责人：方案宣讲、POC 定义、投标应答、技术谈判
- **ARM 迁移评估**：迁移工作量、风险点、迁移路径识别
- POC 交付物：开发板/镜像/工具链/测试用例 + 测试报告；**严禁过度承诺 RISC-V 生态能力**
- 故障分层定位：芯片硬件 / SBI 固件 / BSP 内核 / 工具链 / 客户应用

### 维度 5：生态伙伴 & 开源社区建设（RISC-V 企业核心竞争力）
- 商业生态：OS/RTOS/ODM/算法/中间件厂商联合方案、联合测试、联合白皮书
- 开源社区：向上游 Linux/OpenSBI/U-Boot/LLVM/Zephyr 提交补丁，跟进 RISC-V 国际标准
- 开发者生态：开发板、样例代码、demo 降低上手门槛

### 维度 6：团队与组织管理
- 岗位设置：RISC-V 解决方案架构师、BSP/固件方案工程师、POC 验证工程师、文档工程师
- 团队必备技能：RISC-V 特权架构、PLIC 中断、OpenSBI、设备树、LLVM/GCC 工具链、RTOS/Linux BSP
- 开源补丁管理流程：区分内部私有补丁 vs 上游主线补丁

### 维度 7：市场赋能与案例资产
- 白皮书/方案 PPT/标杆案例/技术解读，突出 RISC-V 差异化价值（自定义指令/成本/安全扩展）
- TCO/ROI 模型：量化 ARM→RISC-V 迁移的综合投入产出，**不做 ARM 平替**

## 5. 能力模型：五大模块

| 模块 | 核心能力 | RISC-V 特有要求 |
|:-----|:---------|:----------------|
| **业务与商业** | 行业洞察、需求甄别、ROI 意识、跨部门对齐、风险-承诺管控 | 判断哪些私有扩展值得投入研发 vs 拒绝 |
| **RISC-V 系统技术**（硬核门槛） | 特权架构、固件-Boot 栈、工具链、OS/BSP 栈、整机视角、ARM 迁移评估 | 不需要手写 RTL，但须看得懂根因、能做架构取舍 |
| **方案与项目交付** | 方案架构设计、POC 统筹、技术评审、文档赋能、故障攻关指挥 | 平衡「上游化」vs「快速交付客户」矛盾 |
| **开源生态与伙伴治理**（特有核心） | 开源社区认知、伙伴管理、开发者生态、碎片化风险治理 | **碎片化治理是 RISC-V 公司生命线** |
| **组织管理** | 团队搭建、OKR 拆解、流程体系、内部赋能、冲突管理 | 处理「客户短期诉求 vs 产品长期路线」冲突 |

**常见能力短板（避坑）**：
1. 只懂芯片硬件，低估生态碎片化工作量
2. 无底线承接定制 → BSP/私有补丁爆炸
3. 不懂开源社区，一味堆私有补丁 → 长期维护成本爆炸
4. 纯售前思维，不关心落地风险与基线版本管理
5. 只懂技术，缺商业判断力

**能力分级**：入门（懂芯片+写 PPT）→ 合格（懂全栈+独立方案+管 POC）→ 优秀（架构取舍+商业与开源平衡+体系搭建+反向需求+生态风险管控）

## 6. KPI 体系与岗位边界

### KPI 参考（四象限）

| 类别 | 关键指标 |
|:-----|:---------|
| 业务指标 | 标杆客户 POC 完成数；重大项目赢单率；客户平均导入周期；定制项目占比；量产标杆案例数 |
| 技术资产 | RISC-V 标准化方案数；固件/BSP/工具链基线完备度；方案文档覆盖率；**上游社区补丁提交数**；客户需求闭环率 |
| 客户质量 | 方案相关满意度；方案问题闭环时效；客户迁移返工率；POC 已知风险泄露率 |
| 组织 | 团队人效；RISC-V 内部培训完成率；流程落地完成度；需求输入被产品/研发采纳数 |

### 岗位边界（避免越位）

1. 不做芯片 RTL/CPU 核研发，但输出系统侧需求给芯片团队
2. 不直接背销售业绩，但对方案完备度、POC 交付质量、技术可行性负责
3. 不做现场 FAE 驻场，但负责复杂系统架构定义、攻关，交付物移交 FAE
4. 不主导内核/BSP 底层编码，但负责定义基线、需求、验收标准

## 7. 补齐知识点：RISC-V 生态治理关键技术

> 本节为深度分析补齐的知识体系，把对话中提及但未展开的技术概念系统化。

### 7.1 RISC-V 启动链路（Boot Chain）

```
Power-on -> ROM Bootloader -> OpenSBI (M-mode) -> U-Boot (S-mode) -> Linux Kernel
                                  |                        |
                            SBI spec interface        Device Tree (DTS)
```

| 组件 | 运行特权级 | 职责 |
|:-----|:-----------|:-----|
| OpenSBI | M-mode | 提供 SBI 运行时服务（定时器/IPI/控制台），是 RISC-V 的「BIOS 层」 |
| U-Boot | S-mode | 引导加载，加载内核与 DTB |
| Linux Kernel | S-mode | 操作系统主体 |
| PMP/sPMP | M-mode | 物理内存保护，安全隔离基础 |
| PLIC/CLINT | — | 平台级中断控制器 / 核心本地中断定时器 |

> 对应知识库已有文档：RISC-V 特权架构与 PMP 详见 [2026-07-21-import-risc-v-chip-design-overview.md](../04_chip/risc-v/2026-07-21-import-risc-v-chip-design-overview.md)

### 7.2 为什么 RISC-V 比 ARM 更容易碎片化（第一性原理）

| 根源 | 机制 | 后果 |
|:-----|:-----|:-----|
| ISA 开放可扩展 | 厂商可自由添加私有指令/扩展 | 软件栈不通用，二进制不兼容 |
| 无单一厂商管控 | 无 ARM 式强生态治理者 | 工具链/内核/固件版本各自为政 |
| 开源基线分散 | 社区主线 vs 厂商私有补丁双轨 | 补丁无法回主线，维护成本累积 |
| Profile 机制年轻 | RVA23 等 Profile 2023 年才成熟 | 早期芯片不遵循，存量碎片化 |

**治理手段**：遵循 RVA23/RVM23 Profile → 收敛工具链/固件/内核基线 → 私有扩展走标准流程评估 → 补丁上游化 → 二进制兼容性治理。
