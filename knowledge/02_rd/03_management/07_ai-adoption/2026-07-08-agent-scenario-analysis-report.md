## 1. 报告说明

### 1.1 本报告定位

这是从 **"活动类型"** 角度切入的场景分析报告——不论哪个岗位/领域，只要你在做这类活动，都可以找到对应的 Agent/AI 导入方案。

**核心问题**：Agent + Skills + 必要的脚本，能导入到服务器研发的哪些活动中？

### 1.2 三层能力组合

每个场景涉及以下三个能力的组合：

```text
+-------------------------------------------------------------+
|                    Agent（大脑）                              |
|  · 理解目标 -> 拆解任务 -> 选择工具 -> 检查结果                  |
|  · LLM 驱动，负责判断和决策                                    |
+--------------------------+----------------------------------+
                           | 调用
+--------------------------v----------------------------------+
|                 Skills（能力包）                              |
|  · 封装具体场景的执行流程和检查标准                             |
|  · 包含：触发病例 + 执行步骤 + 输出规范 + 审核要点              |
+--------------------------+----------------------------------+
                           | 触发
+--------------------------v----------------------------------+
|               Scripts/CLI（执行器）                           |
|  · 具体的命令行工具、脚本、API 调用                            |
|  · 输入->处理->输出，确定性强                                    |
+-------------------------------------------------------------+
```

### 1.3 场景成熟度分级

| 等级 | 代号 | 说明 | 所需条件 |
|:----|:-----|:------|:---------|
| ✅ **Ready** | 数据/工具就绪 | 现有知识库/knowledge + 通用 LLM 可直接启动 | 零或低额外投入 |
| 🔧 **Build** | 需少量脚本 | 需开发 1~2 个 CLI/脚本 + 封装 Skill | 几天~1 周开发 |
| 🏗️ **Construct** | 需一定建设 | 需知识库结构化 + API 集成 + 多 Agent 编排 | 1~4 周建设 |
| 🏭 **Platform** | 需平台支撑 | 需跨系统数据打通 + 审查流程 + 权限管理 | 月度级平台建设 |

### 3.2 深度场景：Test Fail Log 根因分析 (Agent+Skill+Script)

#### 现状

- 测试人员每天面对几十~上百条 fail log
- 当前做法：搜内网→问群里"有人见过这个么"→猜→问开发
- 一个常见问题可能要 30 分钟~几天才能定位

#### Agent 方案

```text
输入：fail log 文本/crash dump 文件路径
 |
 v
Step 1 [Script]: Log Parser -> 提取关键特征（错误码/调用栈/时间戳/模块名）
 |
 v
Step 2 [Agent+Skill]: 特征匹配 Skill
   +-- 知识库 RAG -> 匹配历史已知问题（问题->原因->措施->验证）
   +-- 相似度排名 -> 返回 Top 3 最可能的根因
   +-- 置信度标注 -> 高/中/低（低置信度时标注"建议人工确认"）
 |
 v
Step 3 [Agent]: 生成分析报告
   +-- 问题归类（环境/固件/硬件/配置/波动）
   +-- 根因推断（含推理链条）
   +-- 排查方向建议（先做什么后做什么）
   +-- 关联的已知问题（超链接到知识库）
 |
 v
输出：分析报告（可发群/可归档）
```

#### 所需 Skill 定义

| Skill 名称 | 触发条件 | 输入 | 输出 |
|:-----------|:---------|:-----|:------|
| `fail-log-analyzer` | 用户发送 log/crash dump | log 文本或文件路径 | 根因分析报告 |
| `rma-classifier` | 用户发送 RMA 描述 | RMA 文本描述 | 根因标签+严重程度 |
| `trend-anomaly-detector` | 周期性触发 | 测试结果数据 | 异常标注+趋势摘要 |

#### 所需 Scripts

| 脚本 | 功能 | 语言/工具 |
|:-----|:------|:----------|
| `log-parser.py` | 提取 log 特征（错误码/调用栈/时间戳/模块） | Python + regex |
| `dump-analyzer.sh` | Crash dump 关键信息提取 | bash + gdb/coredumpctl |
| `rma-parser.py` | RMA 文字标准化+特征提取 | Python + NLP |
| `test-result-aggregator.py` | 测试结果汇总+趋势计算 | Python + SQL/API |

### 4.2 深度场景：群聊信息筛选与关键信息提取 (Agent+Skill)

#### 现状

- PM/架构师同时在 5~10 个工作群
- 每天上千条消息，关键决策/问题/进度容易被淹没
- 翻历史记录找人+具体讨论很耗时

#### Agent 方案

```text
输入：群聊消息流（实时/历史）
 |
 v
[Skill: message-filter]
Step 1 [Agent]: 消息分类
   +-- 🚨 问题/异常（需关注）
   +-- ✅ 决策/结论（需记录）
   +-- 📅 待办/Action（需追踪）
   +-- 📢 通知/公告（需知悉）
   +-- 💬 普通讨论（可忽略）
   +-- 🎉 闲聊（归档）
 |
 v
Step 2 [Agent]: 关键信息提取
   +-- 每个分类提取：时间+人物+关键内容
   +-- 问题类：标注严重程度+紧急程度
   +-- 决策类：标注决策内容+影响范围
 |
 v
Step 3 [Agent+Script]: 生成日报/摘要
   +-- 按群汇总 -> 今日关键信息速览
   +-- 按话题聚合 -> 跨群关联信息
   +-- 未解决问题清单 -> 待跟进
 |
 v
输出：日报/关键信息速览（可推送到个人）
```

#### 所需 Skill

| Skill 名称 | 触发条件 | 输入 | 输出 |
|:-----------|:---------|:-----|:------|
| `message-summarizer` | 定时触发或用户请求 | 群聊消息流 | 分类摘要+关键信息 |
| `action-extractor` | 会议/消息中提取待办 | 消息/会议纪要 | 待办列表+负责人+时间 |
