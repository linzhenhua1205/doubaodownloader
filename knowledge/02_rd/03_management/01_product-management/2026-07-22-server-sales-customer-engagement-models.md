## 1. 核心矛盾：为什么"给场景"和"给型号"不是非此即彼

### 1.1 表面现象：销售与客户的鸡同鸭讲

```text
销售A: 这个供应商上来就问"你跑什么模型？多少参数？"
       我给不出来啊，我只知道要买AI服务器...

客户B: 那个供应商上来就是"我们有 HGX B200 8卡机"
       我怎么知道HGX B200是什么？我就想要能跑LLaMA的...

问题: 两边都在用自己的语言说话
      销售说场景 -> 客户听不懂硬件含义
      客户说型号 -> 销售其实也不知道具体适配什么
      价格谈判 -> 都不知道在比什么
      深度定制 -> 双方都没有耐心
```

### 1.2 本质：信息不对称 + 能力不对称的双重错位

| 维度 | 销售方掌握的信息 | 客户方掌握的信息 | 缺口 |
|:-----|:----------------|:-----------------|:-----|
| **场景层** | 知道"训练/推理/微调"的硬件需求差异 | 知道自己"想做什么业务" | 场景 → 参数 → 型号 的翻译能力 |
| **参数层** | 知道算力(TOPS/TFLOPS)、显存、带宽的技术数据 | 知道预算、部署条件、交付时间 | 技术参数与业务价值的对价 |
| **价格层** | 知道BOM成本和利润空间 | 知道竞争对手报价和预算上限 | 双方信息的不可见性 |
| **交付层** | 知道品控、供应链状态 | 知道运维能力和部署环境 | 承诺与现实之间的缝隙 |

### 1.3 四种对接模式的本质定位

```text
需求明确度（客户侧）
      高                     低
  +--------------+----------------------+
  |              |                       |
  |  模式二      |   模式一              |
  |  型号驱动    |   场景驱动            |
  |  "我要HGX"   |   "跑L70B推理"       |
  |              |                       |
  +--------------+----------------------+
  |              |                       |
  |  模式三      |   模式四              |
  |  价格驱动    |   需求协作            |
  |  "预算3亿"   |   "一起设计优化"     |
  |              |                       |
  +--------------+----------------------+
  能力明确度（客户侧）             低
```

**关键洞察**: 四种模式不是谁好谁坏，而是**不同客户在不同阶段用不同模式**。同一个客户可能在前期用场景驱动，中期用型号对标，后期转价格谈判或深度定制。

## 2. 模式一：应用场景描述驱动

### 2.1 典型对话

```text
客户: "我们想买一批服务器来跑大模型，主要是推理。"
销售: "你们的模型参数量多大？输入输出token长度多少？QPS要求多少？"
客户: "...什么是QPS？"
```

### 2.2 特征

| 维度 | 描述 |
|:-----|:------|
| **触发条件** | 客户刚接触AI基础设施，无专业团队或刚组建 |
| **客户能力** | 知道业务目标，不懂硬件参数和架构设计 |
| **销售要求** | 需要从场景到参数到型号的"翻译能力" |
| **核心竞争力** | 行业知识(知道不同场景的硬件需求差异) + 咨询能力 |
| **典型毛利率** | 25-50%（含咨询溢价）|
| **客户满意度** | 高(如果翻译对了) |低(如果推荐错了) |

### 2.3 场景翻译对照表

**训练场景需求 → 硬件参数映射**:

| 场景描述 | 核心指标 | 推荐配置范围 | 说明 |
|:---------|:---------|:-------------|:-----|
| 7B模型全参数训练 | 算力 + 显存 + 互联带宽 | 8×H100/B200 | 单节点可训练 |
| 70B模型全参数训练 | 显存 + 大规模互联 | 64~512 GPU集群 | 需要3D并行 |
| 70B模型LoRA微调 | 显存为主 | 4~8 GPU | 显存够就行,算力要求低 |
| 稠密MoE(如Mixtral)训练 | 高显存 + 高带宽互联 | 8×H100 80GB+ | 显存敏感 |
| 万亿参数模型训练 | 全维度(算力+显存+带宽+存储) | 万卡集群 | 超节点(128+) |

**推理场景描述 → 硬件参数映射**:

| 场景描述 | 核心瓶颈 | 推荐配置 | 关键参数 |
|:---------|:---------|:---------|:---------|
| 7B在线对话(batch=1) | 显存带宽 | 1×L40S/T4 | 显存够,TPT<50ms |
| 70B在线推理(高并发) | 显存 + 算力 | 8×H200/B200 | 需要TP+PP,吞吐优先 |
| 130B离线批量推理 | 算力为主 | 8×H100 | 批量大,算力利用率高 |
| 视频生成(Sora类) | 显存(时序维度) | 8×H100 80GB+ | 显存需求大 |
| RAG检索增强推理 | CPU+GPU混合 | 4×GPU + 大内存CPU | CPU处理向量检索 |

**企业场景描述 → 硬件参数映射**:

| 场景描述 | 真实需求 | 最容易"过度配置"的地方 |
|:---------|:---------|:----------------------|
| "做AI转型,买几台机器" | 可能只需要10-20T算力 | 容易被忽悠买64卡 |
| "数据安全,私有部署" | 数据不出内网 | 不需要万卡集群 |
| "AI辅助编程" | 代码生成模型推理 | 4×A100足矣 |
| "智能客服" | 中小模型推理,CPU处理 | GPU利用率可能很低 |
| "视频审核" | 多模态模型推理 | 需要考虑I/O吞吐而非仅GPU |

### 2.4 场景驱动的"翻译陷阱"

| # | 陷阱 | 典型场景 | 后果 |
|:-:|:-----|:---------|:-----|
| 1 | **过度推荐** | 客户说"做AI"就推8卡H100 | 客户用不满,性价比极低,退货/投诉 |
| 2 | **低估显存** | 推荐4卡跑70B模型 | 显存不够,模型放不下 |
| 3 | **忽略互联** | 推荐多卡但不用NVLink | 跨卡通讯成为瓶颈 |
| 4 | **忽略存储** | 只算GPU不算数据加载 | GPU空转等数据 |
| 5 | **忽略网络** | 多机场景用低带宽网络 | NCCL通讯瓶颈 |
| 6 | **忽略软件栈** | 说"能跑"但客户搭不起来 | 买了却用不了 |

### 2.5 场景驱动的最佳实践

```ascii
销售流程:
Step 1: 五问法锁定场景
  Q1: "你们当前/计划跑什么模型？参数量多少？"
  Q2: "是训练还是推理？在线还是离线？"
  Q3: "预期的并发用户数/QPS是多少？"
  Q4: "目前有多少数据？增长速度？"
  Q5: "有没有必须满足的延迟要求？"

Step 2: 三查法验证能力
  +- 查同类: 找3个同场景客户的配置方案
  +- 查反例: 找同场景失败案例, 什么配置不够
  +- 查基线: 主流模型在不同GPU上的benchmark

Step 3: 提供场景->配置映射表
  客户说"70B推理" ↔ 8×B200(TP=4,PP=2) ↔ $XX万
  让客户理解: "你这个场景, 业界普遍怎么配"
```

## 3. 模式二：型号/规格驱动

### 3.1 典型对话

```text
客户: "我要20台 HGX B200 8卡机，GPU B200 SXM，CPU用Xeon 6980P。"
销售: "好的，我们报个价。"
```

### 3.2 特征

| 维度 | 描述 |
|:-----|:------|
| **触发条件** | 客户有专业团队（或参考了成熟方案）|
| **客户能力** | 能写详细技术规格书，甚至已参考NVIDIA参考设计 |
| **销售要求** | 快速响应+不犯错，按规格对表报价 |
| **核心竞争力** | 价格优势 + 交付速度 + 品牌/资质/服务 |
| **典型毛利率** | 8-15%（白牌）| 20-40%（品牌）|
| **客户满意度** | 低(价格敏感，容易比价) | 取决于交付和服务 |

### 3.3 型号驱动的"真假"识别

不是所有"说型号"的客户都真的懂。需要分辨：

```ascii
真懂的客户:
  ✅ 能说出具体GPU型号和数量的原因
  ✅ 能接受替代方案并评估优劣
  ✅ 对技术细节(PCIe带宽/散热方案/固件)有追问
  ✅ 通常有现成的运维团队
  ✅ 议价聚焦在"同配置下更低价格"

假懂的客户（套壳/中间商）:
  ❌ 只说品牌和型号，说不出为什么
  ❌ 对替代方案不感兴趣，只要"和XX一样"
  ❌ 对技术细节不追问，只关注"能不能出"
  ❌ 通常是渠道商/集成商，不是最终用户
  ❌ 议价聚焦在"能不能更便宜,我加价卖"
```

### 3.4 型号驱动下的三种业务形态

| 形态 | 客户画像 | 销售策略 | 利润水平 |
|:-----|:---------|:---------|:--------:|
| **品牌销售** | 政府/金融/国企，必须走品牌采购 | 按官方价报价，展示售后服务 | **高**(30-60%溢价) |
| **白牌/ODM销售** | 互联网/Tier2云厂商，有自研能力 | 按BOM+合理利润报价，拼交付 | **低**(5-10%) |
| **渠道/集成商** | 中间商对接终端客户 | 给渠道价，留出渠道利润空间 | **中**(15-25%) |

### 3.5 型号驱动 vs 场景驱动的快速转换

实战中，销售人员要在两种模式间快速切换。**客户说型号不一定真懂，但他不懂的时候需要你帮助翻译**：

```ascii
客户说型号                 销售应该回应
--------------------------------------------------
"我要A100 80G"      ->  "好的。请问跑什么场景？
                       最近H200/B200也出来了，
                       如果做推理的话B200有FP8加速..."

"我要H800"           ->  "H800主要面向训练。
                        如果推理为主，我们有性价比更高的方案..."

"我要Dell R760xa"   ->  "Dell的机器是不错的。
                        如果关注性价比，我们有同配置但便宜30%的方案..."

"我要浪潮NF5688"    ->  "NF5688是成熟方案。
                        但我们最近出了新款，NVLink带宽提升2倍..."
```

**黄金法则**: 客户说型号 → 先确认需求(场景) → 再提供最匹配的方案(不一定是客户说的型号)。

## 4. 模式三：价格优先驱动

### 4.1 典型对话

```text
客户: "我们预算3亿，要建一个1000卡集群。"
销售: "总预算包含了哪些？基建？网络？运维？软件？"
客户: "...就是买GPU服务器的预算。"
```

### 4.2 特征

| 维度 | 描述 |
|:-----|:------|
| **触发条件** | 客户有固定预算，且对市场行情有一定了解 |
| **客户能力** | 知道"多少钱能买多少卡"的大致行情 |
| **销售要求** | 在预算约束下做最优配置组合 |
| **核心竞争力** | 方案设计能力 + 供应链成本控制 |
| **典型毛利率** | 5-15%（最薄利的模式）|
| **客户满意度** | 取决于"用同样的钱买到更多还是更少" |

### 4.3 价格驱动的"预算拆解"艺术

**客户说"3亿建集群"时，实际分布往往是**:

```ascii
"3亿预算"的真实分布:

  GPU卡 (H100 80G × 1000张)      $2.8-3.0M/100张  -> $28-30M  <- 最大头
  服务器主机 (100台8卡机)          $50-80K/台       -> $5-8M
  网络 (InfiniBand 400G × 100)    $15-20K/端口     -> $1.5-2M
  存储 (NVMe + 分布式)            $2-5M/100卡      -> $2-5M
  机房基建 (电力+液冷+改造)        $3-5M/100卡      -> $3-5M
  软件/平台 (调度+监控+容器)       $1-3M            -> $1-3M
  运维/人力 (第一年)               $1-2M            -> $1-2M
  -------------------------------------------------
  总计: $42-55M  <- 远超3亿（约$40M）

  所以"3亿建1000卡" -> 实际上只能建500-700卡
  或者在"不含基建/网络/存储"的条件下
```

**销售人员的关键价值**: 帮客户准确定位"预算能做什么"，而不是简单地说"不够"。

```ascii
预算 -> 配置的翻译模型:

  "预算300万" -> 8卡A100/H100单机 (不含网络)
  "预算500万" -> 8卡H100 + 简单网络 (单机训练)
  "预算1000万" -> 16卡(2台) + IB网络 (小集群预研)
  "预算5000万" -> 64卡 + 存储 + 网络 (完整小型集群)
  "预算1亿" -> 128卡 + 完整基础设施 (中型训练集群)
  "预算3亿" -> 512卡 + 存储 + 网络 + 液冷 (中型集群)
  "预算10亿" -> 1000-2000卡 + 全套 (大型集群)
  "预算30亿+" -> 3000-10000卡 + 超节点 (CSP级)
```

### 4.4 价格驱动中最容易被忽视的隐性成本

| 隐性成本项目 | 占采购价比例 | 客户往往不知道 | 销售可以利用 |
|:-------------|:-----------:|:---------------|:-------------|
| **机房电力改造** | 10-30% | ✅ 不知道 | 提供"总拥有成本"方案 |
| **液冷改造** | 15-25% | ✅ 不知道 | 预装液冷方案增值 |
| **散热(风冷改液冷)** | 20-40% | ✅ 不知道 | 差异化的液冷方案 |
| **网络布线** | 5-10% | ✅ 不知道 | 一体化交付 |
| **运维人力(3年)** | 20-40% | ✅ 不知道 | 托管运维服务 |
| **软件许可** | 5-15% | ✅ 不知道 | 预装+开源方案降低成本 |
| **备件/维保** | 3-8%/年 | ⚠️ 部分知道 | 服务合同增值 |

**策略**: 低价竞标时，用隐性成本做差异化。价格透明化时，帮客户看清TCO全貌。

## 5. 模式四：深度需求协作—JDM/ODM

### 5.1 典型对话

```text
客户: "我们明年需要1000台定制化的AI训练服务器，B200 GPU，但我们有自己的散热方案..."
销售: "我们做JDM，从架构设计到量产交付全流程配合。先聊聊你们的具体需求？"
```

### 5.2 特征

| 维度 | 描述 |
|:-----|:------|
| **触发条件** | 客户有明确的定制需求和大体量(>100台/年) |
| **客户能力** | 有自研硬件团队或架构师，能提设计要求 |
| **销售要求** | 研发团队对接、NRE报价、PM管理能力 |
| **核心竞争力** | 研发能力 + 供应链整合 + 品质控制 |
| **典型毛利率** | JDM: 15-25%(含NRE) | ODM: 8-15%(纯制造) |
| **合作周期** | JDM: 6-11个月 | ODM: 3-6个月 |
| **客户粘性** | **极高**(换了麻烦, 有沉没成本) |

### 5.3 JDM的商业模型: NRE + 量产

```ascii
JDM四阶段收支模型:

Phase 1: 需求对接（1-2个月）
  客户: 提需求 -> 研发: 输出方案 -> 反复review
  收入: NRE首期($1-2M)
  成本: 人力5-10人×2月 -> 利润: 薄

Phase 2: 方案设计（2-3个月）
  架构设计、散热仿真、结构设计、原理图
  收入: NRE二期($2-3M)
  成本: 人力20-40人×3月 -> 利润: 持平

Phase 3: 样机验证（3-4个月）
  加工样机、功能/性能/可靠性测试、客户验收
  收入: NRE尾款($1-3M) + 样机费
  成本: 人力+物料 -> 利润: 微利

Phase 4: 量产交付（持续）
  月产能爬坡, 持续出货
  收入: 量产单价×量($8-15K/台)
  成本: BOM+组装+品控 -> 利润: 5-10%

累计: NRE $4-8M + 量产利润 $0.5-1.5K/台
```

### 5.4 "自研vs采购"临界点对销售策略的影响

根据超节点市场分析的[自研批判分析](../../../07_industry-research/03_server/04_industry/2026-07-20-supernode-market-critique/2026-07-20-02-self-dev-vs-procurement.md)，自研临界点取决于品牌溢价：

```ascii
品牌溢价率     自研临界点(台/年)     销售话术
------------------------------------------
 5%             不可行                 "我们比你自己做还便宜"
15%             20-30台               "你的量做自研不划算"
25%             8-12台                "我们的研发团队你养不起"
40%             4-6台                 "你做自研要干6个月,我们直接出"
60%             2-3台                 "你买品牌的吧,自研风险太大"

关键判断:
  - 客户年需求量<10台  -> 推荐品牌/标准品(模式二)
  - 客户年需求量10-50台 -> 推荐标准品or轻定制(模式二->四)
  - 客户年需求量50-200台 -> JDM模式(模式四)
  - 客户年需求量>200台  -> CSP级客户, 他们自己厉害...
    但如果绑定深, 可以做ODM代工(模式四的变体)
```

### 5.5 JDM中的"用研发费保护利润"

JDM的核心风险是"研发投入高，量产没保障"。需要设计好NRE结构：

```ascii
NRE阶段付费结构（保护供应商利益）:

  +- Phase1 (需求):      付款30%  <- 先收钱再干活
  +- Phase2 (设计):      付款30%  <- 关键节点验证后
  +- Phase3 (样机):      付款30%  <- 样机验收后
  +- Phase4 (量产):      付款10%  <- 量产稳定后

  关键保护条款:
  1. NRE不可退还 — 无论是否量产, NRE是设计费
  2. Phase间设"Go/No-Go决策点" — 不通过不继续
  3. 承诺最小订单量(MOQ) — 否则NRE需要重新谈
  4. 设计知识产权归属 — 谁出钱谁持有, 但供应商有复用权
```

### 7.3 客户"AI成熟度"与模式匹配

客户在AI基础设施采购中的成熟度分为四级，每级匹配不同模式：

```ascii
Level 1: 好奇者 (AI成熟度最低)

  匹配: 模式一(场景驱动, 配咨询)
  策略: 给入门方案(4卡+预装软件)
  风险: 容易"过度推荐", 伤害长期关系

Level 2: 实验者
  特征: 已经有几个PoC了, 知道跑什么模型
  匹配: 模式一->模式二(场景->型号)
  策略: 给性价比方案, 帮助做benchmark
  机会: 从实验到生产的升级需求

Level 3: 规模化者
  特征: 已有生产集群, 需要扩容
  匹配: 模式二(型号对标) / 模式三(预算约束)
  策略: 兼容性+性能+性价比
  机会: 替换现有供应商/技术栈升级

Level 4: 自研者
  特征: 有硬件团队, 自己设计优化
  匹配: 模式四(JDM/ODM)
  策略: 研发能力展示+产能承诺
  风险: 容易被"学会就踢开"
```

## 8. 客户采购决策链解构

### 8.1 典型决策角色

一个AI服务器采购的决策链通常涉及4-6个角色：

```ascii
角色                   关注点                   在哪个模式里最关键
----------------------------------------------------------------
① AI科学家/算法团队    技术性能(TFLOPS/显存/带宽)  模式一、模式二
② IT基础设施团队       运维能力(兼容/部署/管理)    模式二、模式四
③ 采购/商务            价格+交付+合同              模式三
④ CFO/VP               预算+ROI                    模式三
⑤ CEO/业务负责人       战略价值+竞争差异           模式一(场景层)
⑥ 法务/合规            资质+安全+国产化            模式二(品牌)
```

### 8.2 模式间的决策链差异

```ascii
模式一(场景驱动):
  CEO/AI科学家发起 -> IT评估 -> 采购比价 -> CEO审批
  最需要说服: AI科学家 (技术说服力)
  销售需要: 场景案例 + 技术benchmark

模式二(型号驱动):
  IT/采购发起 -> 品牌入围 -> 比较报价 -> 定标
  最需要说服: 采购 (价格+品牌)
  销售需要: 报价单 + 品牌资质

模式三(价格驱动):
  CFO/采购发起 -> IT做配置 -> 多方比价 -> 最低价中
  最需要说服: 采购 (价格+交付)
  销售需要: 成本优势 + 差异化TCO

模式四(JDM):
  AI科学家+IT联合发起 -> 技术评审 -> 样机验证 -> 量产
  最需要说服: AI科学家+IT团队 (技术深度)
  销售需要: 研发团队 + 成功案例
```

### 8.3 面对"中间商"的特殊策略

真实市场中大量存在渠道/集成商/套壳商（终端客户实力弱，依赖中间商）：

```ascii
中间商类型及应对策略:

  ① 纯转手型
     从供应商买, 加价卖给终端客户, 不加任何技术价值
     策略: 给渠道价, 控制终端价格(别让加价太高伤害品牌)
     风险: 终端客户不满意会迁怒品牌

  ② 集成型
     买服务器 + 配软件/网络/存储 = 整体解决方案
     策略: 提供技术培训 + 联合方案, 让他们卖方案而非单卖硬件
     机会: 可以从"卖盒子"升级到"被嵌在方案里"

  ③ 套壳品牌型
     买白牌机器, 贴自己的牌子卖
     策略: 严格ODM合同 + MOQ + 不泄露NVIDIA关系
     风险: 可能学会后找更便宜的ODM

  ④ 融资租赁型
     从供应商买, 租给客户(按GPU小时/按月)
     策略: 提供批量价 + 品质保证, 协助租赁方案设计
     机会: 市场扩大受益
```

## 9. 国内AI服务器市场的特殊性

### 9.1 与海外市场的关键差异

| 维度 | 海外市场 | 国内市场 | 对销售模式的影响 |
|:-----|:---------|:---------|:-----------------|
| **GPU供应** | 相对充足(禁令前) | **严重受限**(受制裁) | 国内方案≠国外型号, 场景翻译更重要 |
| **客户偏好** | 品牌/ODM自由选择 | 品牌要求+信创要求 | 国产化替代是刚需, 不是选项 |
| **采购流程** | 标准化比价 | 招标+关系+资质 | 模式二(品牌) + 模式三(价格)混合 |
| **价格透明度** | 较透明 | 不透明(不同客户不同价) | 销售谈判空间更大, 但也更混乱 |
| **技术成熟度** | 大部分客户懂行 | 大量客户正在学 | 模式一(场景驱动)更普遍 |
| **服务体系** | 成熟的Dell/HPE服务 | 参差不齐 | 服务可以作为核心差异化 |
| **中间商密度** | 低(直销为主) | **非常高**(分销/渠道/集成) | 模式二(型号)常见, 中间商各加一次价 |

### 9.2 国产化替代对销售模式的影响

**国产芯片（昇腾/寒武纪/海光等）带来的模式差异**：

```ascii
国外GPU(NVIDIA)           国内GPU(昇腾等)
----------------------------------------
模式二更常见              模式一更重要
"我要H800"                "我要能跑LLaMA的国产方案"
客户能说型号              客户说不清型号
BOM透明                   性能/BOM不透明
场景->性能预测准确          场景->性能需要实测验证

影响:
  1. 国内销售需要更强的"场景翻译"能力
  2. 国产芯片的benchmark数据是核心竞争力
  3. "能不能跑"比"跑多快"更关键
  4. 售后支持和技术驻场是差异化来源
```

### 9.3 国内市场的"三不买"原则

```text
第一不买: 没试过的
  国内客户普遍要求PoC(概念验证), 不接受PPT销售
  -> 模式一和模式四都需要提供测试环境

第二不买: 不熟悉的供应商
  信任圈层: 已有的供应商 > 朋友推荐的 > 有成功案例的 > 来推销的
  -> 新客户开拓周期长, 模式一需要"养客户"

第三不买: 服务没有保障的
  国产GPU + 国产软件栈 = 问题无穷
  没有现场支持的供应商 = 买了就是给自己找麻烦
  -> 模式一/模式四需要配套服务团队
```

## 10. 套壳与品牌溢价：谁在中间赚差价

### 10.1 三层套壳模型

AI服务器市场有清晰的"套壳链"：

```ascii
芯片层 (NVIDIA/AMD/Intel)
    |
    |  GPU $25-35K/颗
    v
ODM层 (广达/纬创/英业达/富士康)
    |
    |  整机 $150-250K/台 (8卡)  <- 白牌, 不含品牌溢价
    v
品牌商层 (Dell/HPE/联想/浪潮/Supermicro)
    |
    |  整机 $200-400K/台  <- 含品牌溢价(+20-60%)
    v
渠道/集成商层 (神州数码/中科曙光/新华三)
    |
    |  整机 $250-500K/台  <- 再加一笔渠道费
    v
终端客户
```

### 10.2 各层的对接模式差异

| 层级 | 典型的对接模式 | 竞争核心 | 利润来源 |
|:-----|:-------------|:---------|:---------|
| **ODM层**(制造整机) | 模式二+模式四 | 成本+品质+交付 | 制造效率(5-10%) |
| **品牌商层**(贴牌) | 模式二(品牌溢价) | 品牌+服务+资质 | 品牌溢价(20-60%) |
| **渠道/集成层**(转手) | 模式二(型号/价格) | 客户关系+垫资 | 渠道利润(10-30%) |
| **方案商层**(集成) | 模式一(场景咨询) | 技术方案+集成 | 方案溢价(30-100%) |

### 10.3 供应商需要认清的"三层套壳"

作为供应商（假设你是ODM/白牌厂商），你的客户可能是两端任一种：

```ascii
场景1: 直接对接终端客户
  你的角色: 标准品供应商
  模式: 模式一/模式二
  利润: 中(10-20%)
  风险: 客户关系维护成本高

场景2: 对接品牌商(被贴牌)
  你的角色: ODM代工厂
  模式: 模式四(JDM/ODM)
  利润: 低(5-10%)
  风险: 品牌商可能压价或换厂

场景3: 对接渠道商(转手)
  你的角色: 白牌供应商
  模式: 模式二(型号+渠道价)
  利润: 低(5-10%)
  风险: 不知道终端客户是谁, 被渠道绑架

场景4: 对接方案商(集成)
  你的角色: 硬件供应方
  模式: 模式一(方案商是你的"场景翻译官")
  利润: 低-中(10-15%)
  机会: 方案商的场景能力是你的放大器
```

### 10.4 "Dell为什么能卖贵"——品牌溢价根源

理解品牌溢价的结构，能帮助制定销售策略：

```ascii
Dell/HPE卖$300K vs ODM卖$200K的差价$100K:

  ① 品牌信任溢价: $30-50K
     客户相信Dell的品质管控和全球服务
     -> 如果你没有品牌, 你需要成功案例和第三方认证来弥补

  ② 采购合规溢价: $20-30K
     政府/国企只能买品牌
     -> 如果你的客户没有合规要求, 省下这笔

  ③ 服务合同溢价: $15-25K
     3年7×24上门服务
     -> 如果你能提供同等级服务, 可以加回来

  ④ 融资便利溢价: $10-20K
     Dell的租赁/分期方案更灵活
     -> 如果客户不缺现金, 省下这笔

  ⑤ 惯性溢价: $5-10K
     IT团队只会用Dell的iDRAC, 换品牌有学习成本
     -> 如果客户有运维能力, 省下这笔

  合计: $80-135K  <- 卖得贵的"理由"
```

## 11. 常见陷阱与反模式

### 11.1 六大销售陷阱

| # | 陷阱 | 表现 | 后果 | 根治方法 |
|:-:|:-----|:-----|:-----|:---------|
| 1 | **唯型号论** | 客户说什么就是什么, 不追问场景 | 客户用着发现不对, 退货/投诉 | 先确认"为什么是这个型号" |
| 2 | **过度配置** | 客户说AI就推顶配, 不管实际需求 | 客户嫌贵/用不满, 口碑差 | 先做load estimation |
| 3 | **忽略软件栈** | 只卖硬件, 不管能不能跑起来 | 客户买了不会用, 怪你 | 提供预装/调优服务 |
| 4 | **承诺不可交付** | 为了签单承诺做不到的交付时间 | 违约赔偿+信任崩塌 | 交付承诺必须经PM确认 |
| 5 | **价格战无底线** | 只有降价一条路 | 利润归零, 客户不珍惜 | 用服务/方案/交付做差异化 |
| 6 | **过度定制** | 客户说什么都改, 没有标准品基线 | 研发资源被耗光, 没有利润率 | 80%标准+20%定制 |

### 11.2 客户类型与对应的"销售反模式"

```ascii
面对L0 CSP客户:
  反模式: 按品牌方式报价(高溢价)
  正确: 按ODM方式报价, 拼交付和品质

面对L2 大型企业:
  反模式: 给一堆技术参数(对牛弹琴)
  正确: 用业务语言说价值, 用案例证实力

面对L3 创业公司:
  反模式: 因为客户小而忽视(以后会变大)
  正确: 用标准化方案低价切入, 培养客户

面对渠道商:
  反模式: 给终端客户价(渠道没利润)
  正确: 给渠道价+技术支持+联合市场活动

面对"套壳商":
  反模式: 把核心技术都告诉他(被复制)
  正确: 签NDA+控制Know-How交付粒度
```

### 11.3 最危险的三种客户（可能不接）

```ascii
Type A: 要你JDM但量不够
  症状: "帮我定制个方案, 先买2台试试"
  风险: 你投入研发做定制, 他2台后不买了
  应对: 定最小订单量(MOQ), NRE先行

Type B: 给你假场景
  症状: "我们做万亿模型"但团队才3个人
  风险: 你投入大量时间做方案, 他买不起
  应对: 先确认客户预算, 再按预算反推场景

Type C: 价格猎手
  症状: 每次打都说"再降5%我就签"
  风险: 降了5%还有下5%, 没有忠诚度
  应对: 设置底线, 用服务/方案/付款条件做最后让步
```

## 12. 销售流程最佳实践

### 12.1 需求发现阶段的"四层漏斗"

```ascii
L1: 客户是谁
  + 行业? 规模? AI成熟度? (参考§7客户分类)
  + 判断: 应走模式一/二/三/四?

L2: 客户要什么
  + 能说清场景? 能说清型号? 先问价格? 知道要定制?
  + 判断: 触发哪种模式?

L3: 客户的真实约束
  + 预算(明确? 模糊? 需要方案定义?)
  + 时间(急? 有时间规划? 定制来得及?)
  + 团队(有运维? 需要培训? 需要驻场?)
  + 判断: 方案的边界条件

L4: 决策链
  + 谁发起?
  + 谁评估?
  + 谁有否决权?
  + 判断: 销售路径(见§8)
```

### 12.2 报价阶段的策略选择

| 客户类型 | 报价策略 | 说明 |
|:---------|:---------|:------|
| **场景驱动**(不懂型号) | 方案报价(含服务) | 不要报"GPU×数量", 报"70B推理方案" |
| **型号驱动**(懂型号) | 透明报价 + 可选配置 | 价格透明化, 靠服务/交付差异化 |
| **价格驱动**(先问价) | 分项报价(TCO可视化) | 不要只报总价, 帮客户看清怎么省 |
| **JDM/ODM**(定制) | NRE分段 + 量产阶梯价 | 用NRE保利润, 量产后阶梯降价 |

## 13. 未来趋势：从卖盒子到卖能力

### 13.1 AI服务器销售模式的三次跃迁

```ascii
Phase 1: 卖盒子 (2020-2024)
  --------------------------------
  销售模式: 型号+价格(模式二+三)
  客户群体: CSP+少量大企业
  销售能力: 配置报价能力
  利润: 8-15%

  v AI大模型爆发, 需求井喷, 客户群大幅扩大

Phase 2: 卖方案 (2024-2026) <- 当前阶段
  --------------------------------
  销售模式: 场景+方案(模式一为主)
  客户群体: 从CSP扩展到L2~L3
  销售能力: 行业知识+方案设计
  利润: 15-30% (含方案溢价)

  v 越来越多人懂AI, 标准品需求增加, 利润率受压

Phase 3: 卖能力 (2027+)
  --------------------------------
  销售模式: 全模式并⾏, 但销售的核心是"帮客户成功"
  客户群体: 全客户层覆盖
  销售能力: 全栈(硬件+软件+运维+优化)
  利润: 服务化订阅(硬件利润变薄, 服务利润增长)

  预测: "按GPU小时计费"的超节点租赁将替代大量销售
```

### 13.2 平台化/租赁化对销售模式的影响

```ascii
传统模式: 客户买硬件 -> 自己运维 -> 自己调优
销售模式: 模式一/二/三/四 (一次性的)

新兴模式: 平台租算力 -> 按GPU小时付费 -> 免运维
销售模式: "销售"变成了"客户拓展"(持续性的)
  + 从"卖设备"变成"部署设备到我平台"
  + 从"一次性收入"变成"持续订阅"
  + 从"拼价格"变成"拼服务质量"
  + 从"解决方案销售"变成"合作伙伴拓展"

影响:
  1. 传统销售团队需要转型: 卖盒子->卖服务
  2. 场景理解更重要: 客户租算力需要知道"租来干什么"
  3. 价格战被"服务差异化"取代: 网络/存储/运维质量
  4. 客户关系从"交易"变成"合作": 长期服务合同
```

### 13.3 销售人员的能力模型升级

| 能力维度 | 传统模式(2023) | 当前模式(2026) | 未来模式(2027+) |
|:---------|:--------------|:--------------|:----------------|
| **技术能力** | 知道型号参数 | 知道场景映射 | 知道全栈优化 |
| **咨询能力** | 不需要 | 需要(场景翻译) | **必须**(价值顾问) |
| **商务能力** | 报价+谈判 | 方案报价+TCO | 服务合同+SLA |
| **客户关系** | 采购关系 | 技术+商务 | **全角色**(从CEO到运维) |
| **行业知识** | 通用 | AI场景 | 细分行业(医疗/金融/制造) |

## 14. 总结：你的模式不是选择题，是组合拳

### 14.1 四种模式不是"选一个"，而是"都会用"

```text
同一个客户的生命周期:

  初期接触 (不懂AI)      ->  场景驱动  (教客户)
  中期比较 (学会了)      ->  型号对比  (比产品)
  商务谈判 (确定了)      ->  价格+TCO (拼方案)
  长期合作 (互信了)      ->  JDM定制  (深度绑定)

  ^ 每一位销售人员都需要掌握这四种模式
  ^ 同一个客户可能在不同阶段需要不同模式
  ^ 模式切换能力 = 销售能力的核心指标
```

### 14.2 核心结论

| 维度 | 结论 |
|:-----|:------|
| **场景驱动(模式一)** | 最赚钱的、最需要能力的、客户最感激的模式。适用于客户AI成熟度低时。 |
| **型号驱动(模式二)** | 门槛最低的、最透明的、竞争最激烈的模式。适用于客户AI成熟度高时。 |
| **价格驱动(模式三)** | 最薄的、最易被替代的、最不值得走极端的模式。做TCO差异化而非单纯降价。 |
| **深度协作(模式四)** | 最绑定的、投入最大的、护城河最深的模式。适用于大体量客户。 |

### 14.3 最后一句

> **"卖AI服务器不是卖显卡，是帮客户从不确定性中找到确定性。"**
> 客户不知道买什么的时候 → 你能给他方案(模式一)
> 客户知道买什么的时候 → 你能比他更好(模式二/四)
> 客户只问多少钱的时候 → 你能让他看到价值而非价格(模式三)
