## 1. 核心框架：选型与报价的「双螺旋」关系

### 1.1 常见的错误认知

| 错误认知 | 实际情况 |
|:---------|:---------|
| "研发先选好型号，采购去询价就行" | 选型决策已锁死了80%的成本结构，采购只有20%的操作空间 |
| "报价只是商务谈判的事" | 报价的底线由选型方案决定——芯片选型定了，BOM成本天花板就定了 |
| "报价高了就换便宜的型号" | 临时换型涉及重新验证、兼容性、固件适配，总成本可能更高 |
| "选型只看技术指标" | 技术指标最"先进"的方案往往不是总成本最优的方案 |

### 1.2 双螺旋模型

选型和报价不是串行关系（先选型后报价），也不是并行关系（各做各的），而是**螺旋交织、相互迭代**的关系：

```text
     +--------------+          +--------------+
     |   选型决策    | <---------->   报价反馈   |
     |              |   信息流     |              |
     | 功能·性能·生态|  <- 成本约束-> | 价格·交期·条款 |
     | 兼容性·风险   |  <- 技术限制-> | 供应·替代方案   |
     +------+-------+          +------+-------+
            |                          |
            v                          v
     +-----------------------------------------+
     |          最终决策（技术+商务交集）          |
     |   -> 技术可行 + 商业可承受 + 风险可管控    |
     +-----------------------------------------+
```

**关键洞察**: 选型决策做了 **60-80%的成本锁定**；采购谈判解决的是剩下的 **20-40%的价格波动空间**。

### 1.3 选型-报价决策矩阵

```text
                    +--- 供应商议价能力 ----+
                    |  强             弱   |
+--------------+---------------------------+
|              |                           |
| 方案锁定程度  |  强  | 🚨 被动接价   | ✅ 正常议价   |
|  (技术决定)   |     | (NVIDIA GPU)  | (PCB制板)     |
|              +---------------------------+
|              |  弱  | ✅ 可替代谈判   | 🏆 充分竞争   |
|              |     | (网卡/SSD)     | (电容/电阻)   |
+--------------+---------------------------+
     ^                               ^
  选型决定了你在     报价决定了你最后付多少钱
  矩阵中的位置         但在强锁定区域空间有限
```

## 2. 选型如何驱动报价——五种力量

### 2.1 竞争替代力

选型**决定了该物料有多少供应商能参与报价**，直接决定了竞争强度。

| 选型策略 | 可参与报价的供应商数 | 预计价格空间 | 典型物料 |
|:---------|:-------------------:|:-----------:|:---------|
| 指定唯一型号 | 1家（单一来源） | **5-15%** | NVIDIA B300/B200 GPU、Intel Xeon CPU |
| 指定品兼容 | 2-3家（对标替代） | 10-20% | DDR5 RDIMM、NVMe SSD |
| 定义规格参数 | 3-5家（方案竞争） | 15-30% | PSU电源、风扇模组、PCB制板 |
| 开放功能标准 | 5+家（充分竞争） | 20-40% | 通用电容/电阻、标准连接器、线缆 |

**核心原则**：**选型时的「替代自由度」直接决定了报价时的「议价空间」**。如果选型时只写了一个厂牌的PN，采购就只能被动接价。如果选型时留下了"兼容替代"的余地，采购就有了筹码。

### 2.2 技术锁定力

某些选型决策会形成**技术锁定（Technology Lock-in）**，大幅降低切换意愿，从而削弱议价能力。

```text
技术锁定强度分级：

🔒 锁定级别 5: 芯片平台级
   例：选 Intel Xeon -> 整个主板/BIOS/散热/结构围绕它设计
   切换成本：重新设计主板 + 验证周期 6-12 个月
   对报价的影响：Intel 清楚你换不了，年涨 3-5% 你也要接受

🔒 锁定级别 4: 固件/生态级
   例：选 AMI BIOS -> 大量定制化开发完成
   切换成本：重写定制代码 + 重新认证 + ¥500万+
   对报价的影响：授权费/Royalty逐年涨，有恃无恐

🔒 锁定级别 3: 接口/协议级
   例：选 PCIe Switch 品牌 -> 周边设计适配
   切换成本：重新验证信号完整性 + 可能改板
   对报价的影响：有一定议价能力，但不大

🔒 锁定级别 2: 软件兼容级
   例：选 OS/驱动支持的型号
   切换成本：驱动验证 + 兼容性测试（周级别）
   对报价的影响：容易切换，供应商一般不过分

🔒 锁定级别 1: 无锁定
   例：标准阻容件、通用连接器
   切换成本：零成本即时切换
   对报价的影响：几乎无影响，以行市价成交
```

**核心原则**：**在选型时评估「切换成本」并提前规划「锁定管理策略」**。不是所有锁定都要避免（合理的锁定是技术竞争力），但必须清楚自己正在"被锁定"以及对应的商业代价。

### 2.3 市场稀缺力

选型决定了该物料处于什么类型的市场，直接影响价格走势。

| 市场类型 | 选型特征 | 价格走势 | 报价策略 |
|:---------|:---------|:---------|:---------|
| **卖方市场**（1-2家垄断） | GPU/HBM/高端FPGA | 价格逐年上升 | 长单锁价+产能预留 |
| **双寡头**（2家竞争） | CPU(Intel/AMD)、DRAM(Samsung/SK Hynix) | 跟随供需波动 | 利用两家竞争获取最优价 |
| **充分竞争**（5+家） | 电容/电阻/PCB/标准连接器 | 逐年下降 | 定期比价+年度招标 |
| **新兴市场**（技术迭代快） | PCIe Gen6 Retimer/CXL Switch | 先高后低 | 关注技术成熟度曲线 |

**市场稀缺力随时间变化**：

```text
价     GPU/HBM（长期卖方市场）
格     ^
趋     |    DDR5（波动剧烈，周期性强）
势     |
      +----------------------------> 时间
          电阻电容（稳定下降）
```

### 2.4 技术复杂度力

选型涉及的技术复杂度影响报价的构成——不仅仅是物料成本，还有技术支持成本。

| 复杂度 | 选型特征 | 报价超出物料成本的部分 |
|:-------|:---------|:---------------------|
| 低（标准器件） | 有规格书就能用，无需原厂支持 | 0-5%（纯物流+利润） |
| 中（技术器件） | 需要参考设计、FAE支持 | 10-20%（含技术支持分摊） |
| 高（平台器件） | 需要联合开发、定制固件、Errata修复 | 30-50%（含研发投入分摊） |
| 极高（战略器件） | 需要长期联合开发、产能绑定额度分配 | 50-100%+（含稀缺溢价） |

**核心原则**：报价超过物料成本的部分，**本质上是在为「技术支持的确定性」和「供应风险的降低」买单**。选型应该在两者之间做平衡。

### 2.5 生命周期力

选型所处的**产品生命周期阶段**决定了价格走势方向。

```text
                 成熟期
              +--------+
引入期       | 价格平稳 |   衰退期
+-----+      | 竞争充分 |   +-----+
| 高价 |      | 利润透明 |   | 升价 |
| 少量 |      +--------+   | 停产 |
| 独家 |                     | 替代 |
+-----+                     +-----+
  v                           v
 价格高企                  越接近EOL价格越贵
 但趋势快速下降            （停产前最后一波涨价）
```

| 阶段 | 选型策略 | 价格特征 | 报价关注点 |
|:-----|:---------|:---------|:----------|
| **新产品导入(NPI)** | 选最新一代，获取技术领先 | 报价最高，但快速下降 | 锁定首批折扣价、要求价格保护 |
| **成熟产品** | 选已验证的主流型号 | 价格稳定，供应充足 | 开展年度降价谈判、引入第二供方 |
| **EOL/停产前** | 评估切换时机 | 价格可能上涨（停产前最后一波） | 确认Lifetime Buy条款、最后购买批次量 |
| **停产后** | 不得不选替代型号 | 价格非常高（现货市场） | 提前启动替代选型 |

## 3. 报价如何约束选型——三条反馈回路

### 3.1 总拥有成本（TCO）反馈回路

报价不是单点价格，而是**整个使用周期的总成本**。选型时忽略TCO会导致决策偏差。

```text
BOM价格（显性成本）
    |
    +-- 芯片本身的价格
    +-- 配套物料成本（散热器/电源/PCB层数增加）
    +-- 制造成本（工艺复杂度/良率损失）
    +-- 测试成本（是否需要特殊测试设备）

TCO（总拥有成本 ≈ BOM价格 × 1.3~2.5）
    |
    +-- 技术支持成本（FAE工时/定制开发/固件适配）
    +-- 验证成本（认证/兼容性测试/信号完整性）
    +-- 供应风险成本（缺料风险/替代物料/加急费）
    +-- 切换成本（如果换型号/换供应商的代价）
    +-- 运营成本（功耗/散热/维护/备件）
```

**典型TCO偏差案例**：

| 场景 | 只看BOM决策 | TCO视角 | 结论 |
|:-----|:-----------|:---------|:-----|
| GPU选型 | 选B300（$30K）vs A100（$10K） | B300的单Token成本比A100低40% | 选贵的反而省钱 |
| 内存选型 | 选服务器DDR5（$200/条）vs 消费级DDR5（$100/条） | 消费级RMA率×5、不兼容 | 消费级"便宜"反而更贵 |
| PCB选材 | 选普通FR-4（$5/sqft）vs 高速M6（$15/sqft） | 普通材料信号损耗大，需要加Retimer | 高速材料摊平更优 |
| 电源选型 | 白牌PSU（$200）vs 品牌PSU Delta（$350） | 白牌效率低3%、故障率高2× | 品牌TCO更优 |

### 3.2 替代方案反馈回路

报价太高会倒逼选型**寻找替代方案**，形成"报价→选型修正"的回路：

```text
    报价高于目标价格
         |
         v
  +------------------+
  | 第一反应: 谈判压价 | <- 如果供应商有弹性，直接解决
  +--------+---------+
           | 谈判不成功
           v
  +------------------+
  | 第二反应: 需求降级 | <- 降规格/减功能/换兼容型号
  |                  |   例: 600W PSU -> 550W PSU
  |  风险: 性能妥协   |        液冷方案 -> 风冷方案
  +--------+---------+
           | 仍不满足
           v
  +------------------+
  | 第三反应: 全面换方案| <- 换技术路线/换供应商
  |                  |   例: NVIDIA -> AMD GPU
  |  风险: 周期延长   |        Intel -> AMD CPU
  +--------+---------+
           | 最极端情况
           v
  +------------------+
  | 第四反应: 自研替代 | <- 投入研发资源自己做
  |                  |   例: 自研BMC -> 替代ASPEED
  |  风险: 投入巨大   |        自研Switch -> 替代Broadcom
  +------------------+
```

**关键问题**：报价反馈应该在选型决策的 **哪个时间点介入**？

- ❌ **太晚**（选型已锁定，方案已出图）：替代成本极高，只能硬着头皮接受高价
- ✅ **合适**（选型进行中，多种方案并行评估）：有选择余地，多方询价形成竞争
- ❌ **太早**（需求不明确，技术方案未成形）：无法准确定义规格，报价缺乏可比性

### 3.3 供应风险反馈回路

报价不仅仅反映价格，还承载了**供应稳定性的信号**。

| 报价信号 | 可能的隐含义 | 对选型的影响 |
|:---------|:------------|:------------|
| 报价远低于市场均价 | 供应商不熟悉需求，后续可能加价；或低价抢单后断供 | 需要供应商资质审核，不能只看价格 |
| 报价远高于市场均价 | 供应商产能紧张，不想接单；或认为贵司不是战略客户 | 评估替代供应商，或接受溢价保证供应 |
| 正常报价但交期异常长 | 该物料市场整体紧缺 | 考虑备选型号，或提前锁定产能 |
| 正常报价但不给LTSA | 供应商不愿长期绑定 | 评估该供应商的战略合作意愿 |
| 报价含"市场浮动条款" | 价格受外部因素影响大 | 需要设置价格上限，或采用固定价合约 |
| 报价特别低但MOQ很大 | 供应商想清库存 | 确认是否为EOL物料，评估长期供应 |

## 4. 接口设计：选型-报价之间需要哪些信息交换

### 4.1 从选型到报价的信息传递

研发团队在做选型时，应该**同步输出**给采购/商务团队以下信息，才能让报价有质量：

| 信息项 | 内容 | 传递时机 | 对报价的价值 |
|:-------|:-----|:---------|:------------|
| 需求规格书(SOW) | BOM料号的完整技术参数、认证要求 | 选型草案完成时 | 让供应商据此准确报价 |
| 目标价格(Should Cost) | 基于BOM拆解的目标价 | 选型进行中 | 指引供应商报价方向 |
| 年预估量 | 各料号的年需求预估(分型号/分场景) | 选型确认后 | 争取阶梯价格、框架协议 |
| 项目时间线 | NPI/EVT/DVT/MP各阶段时间节点 | 选型启动时 | 明确样品和批量交付节奏 |
| 替代清单 | 已评估的可替代型号+差异说明 | 选型完成后 | 为议价提供筹码 |
| 技术评估报告 | 各候选型号的优劣评分 | 选型评审时 | 商务谈判时明确"技术底线" |
| 风险清单 | 供应风险/技术风险/认证风险 | 贯穿全程 | 报价中包含了风险溢价 |

### 4.2 从报价到选型的反馈信息

采购/商务团队收到报价后，应向研发反馈以下信息：

| 反馈项 | 内容 | 对选型的价值 |
|:-------|:-----|:------------|
| 价格区间 | 各家报价的对比（含隐性费用） | 确认选型在可承受范围内 |
| 供应约束 | 交期、MOQ、产能限制 | 影响NPI排期和量产规划 |
| 替代建议 | 供应商推荐的替代型号（可能更便宜） | 扩展选型方案选择空间 |
| 趋势预警 | 价格走势（涨价/降价/缺货预警） | 提前决策是否备货或切换 |
| 商务条款 | 账期、保修、技术支持等级 | 影响TCO和运维成本 |
| 供应商评级 | 供应商的技术能力、交付表现、配合度 | 评估长期合作可行性 |

### 4.3 接口数据流

```text
研发团队                              采购/商务团队
   |                                       |
   |-- 选型方案(3选1或5选2) ---------------->|
   |   含: 技术参数·年量预估·样品需求        |
   |                                       |-- RFQ发布 -> 供应商
   |                                       |
   |<--- 报价反馈(价格+交期+条款+风险) ----|
   |   含: 各家对比·替代建议·ROI分析         |
   |                                       |
   |-- 选型调整(基于报价反馈修正方案) ------>|
   |   含: 最终选型·目标价·锁定理由          |
   |                                       |-- 商务谈判 -> 确定供应商
   |                                       |
   |<--- 锁定确认(合同·价格·交期) --------|
   |   含: 合同条款·LTSA·服务级别            |
   |                                       |
```

**关键原则**：**最少2轮、最多3轮迭代**。超过3轮说明需求定义不够清晰或选型方向有问题。

## 5. 工作开展方式——五个关键环节

### 5.1 环节一：选型前市场扫描（确定"有谁可选"）

**时机**：正式选型启动前2-4周

**工作内容**：

```text
① 初步收集 -> 列出该品类所有潜在供应商（含国内/国外）
② 分类分级 -> 头部(技术领先) / 主流(性价比) / 新锐(差异化)
③ 产能摸底 -> 各供应商的产能规模、产线利用率、Lead Time
④ 初步报价 -> 向所有潜在供应商发RFI(信息征询函)，获得初步价格范围
⑤ 生态调研 -> 了解该供应商在其他客户的份额、口碑、配合度
```

**关键产出**：**「市场地图」**——哪些供应商可选、各自的技术定位和价格区间

**常见错误**：跳过此环节，直接基于经验选择2-3家"熟悉的"供应商询价→错过潜在的性价比更优选择。

### 5.2 环节二：并行选型+初步报价（"多方案同步"）

**时机**：选型方案概念阶段

**工作内容**：

```text
研发层面：
  ① 确定2-3个候选技术方案（可能采用不同供应商的器件）
  ② 每个方案输出：技术评估+兼容性分析+切换成本估算
  ③ 每个方案附带：目标价(Should Cost) + 可接受的最低价(Should Not Exceed)

采购层面：
  ① 向候选供应商同步发RFQ（需求规格）
  ② 要求供应商分项报价（物料+开发费+NRE+技术支持）
  ③ 获取每个方案2-3家的初步报价（含交期+MOQ）
```

**关键产出**：**「技术-商务对照表」**——每个方案的技术评分+预估成本范围

**为什么一定要并行**：

| 方案 | 串行方式(先选型后报价) | 并行方式(同步展开) |
|:-----|:---------------------|:-----------------|
| 时间 | 选型2周→报价2周→调整1周=5周 | 选型+报价并行=3周 |
| 质量 | 选型时不知报价，可能选错 | 选型时有报价参考，决策更优 |
| 议价力 | 只跟1家谈，被动 | 多个方案，能形成跨方案竞争 |

### 5.3 环节三：技术-商务联合评审（"交叉验证"）

**时机**：初步报价收回后，最终选型确定前

**工作内容**：

```text
评审维度：

技术维度 (R&D主导)：
  +- 功能满足度：是否100%满足需求？
  +- 性能余量：超出需求N%？（预留未来迭代空间）
  +- 兼容性：与现有系统的集成难度
  +- 生态适配：驱动/固件/社区支持
  +- 技术风险：Errata/成熟度/供货连续性

商务维度 (采购主导)：
  +- 价格竞争力：与市场基准价、Should Cost对比
  +- 供应保障：Lead Time/MOQ/产能弹性
  +- 合作意愿：研发支持、FAE响应、信息透明度
  +- 战略价值：是否有助于构建长期供应商关系

风险维度 (共同评估)：
  +- 单一供应风险：是否独家？切换成本？
  +- 地缘风险：中美贸易/出口管制/关税
  +- 替代性：方案B/方案C的可用性
  +- 生命周期：EOL计划/技术演进路线
```

**决策规则**：

```text
通过标准（必须同时满足）：
  ✅ 技术评分 ≥ 80分（满分100）
  ✅ 价格 ≤ 目标价的120%
  ✅ 供应风险等级 ≤ 中（可管控）

Plus加分项：
  ⭐ 技术评分 > 90 -> 可接受价格上浮至130%
  ⭐ 价格 < 目标价90% -> 技术评分可放宽至70分
  ⭐ 供应商承诺LTSA -> 优先选择
```

### 5.4 环节四：报价验证与谈判（"确认底线"）

**时机**：最终选型锁定后，正式采购前

**工作内容**：

```text
报价验证：
  ① 成本拆解验证：物料成本+制造成本+运输+利润（验证报价合理性）
  ② 历史价格对比：上次采购价/市场基准价/友商参考价
  ③ 条件验证：不同的量价关系（年量1K vs 10K vs 100K）

谈判准备：
  ① 确定谈判底线(BATNA): 最差能接受什么方案？
  ② 准备B计划：如果这家谈不拢，备选方案是什么
  ③ 权责匹配：价格让步换什么？(量承诺/账期/技术支持)

谈判要素（按权重排序）：
  1. 价格（含阶梯价、价格保护、降价机制）
  2. 供应保障（交期、产能预留、MOQ灵活性）
  3. 技术支持（FAE工时、定制开发、Errata修复）
  4. 商务条款（账期、保修、终止条件）
  5. 战略合作（未来产品优先权、联合开发）
```

### 5.5 环节五：持续跟踪与复盘（"闭合环路"）

**时机**：采购后持续

**工作内容**：

```text
跟踪指标：
  +-- 价格合规率：实际采购价 ≤ 报价时约定的价格？
  +-- 供应达成率：交期达成率、缺货次数
  +-- 质量表现：进料不良率、早期失效率(DoA)
  +-- 配合度：FAE响应时间、问题解决效率

复盘机制：
  +-----------------------------------------+
  | 选型-报价复盘会议（每季度一次，研发+采购+供应商共同参与） |
  +-----------------------------------------+
  | ① 报价时的预测 vs 实际的偏差分析        |
  | ② 选型决策对TCO的实际影响  reviewed     |
  | ③ 供应商承诺兑现情况评估                |
  | ④ 下次选型的改进点（经验沉淀到知识库）  |
  +-----------------------------------------+
```

## 6. 需要关注的十二个关键点

### 6.1 选型阶段的「成本信息不对等」

> **问题**：研发工程师在做选型时，通常**不知道器件的价格**。

| 影响 | 典型场景 |
|:-----|:---------|
| 选了一个性能最好的型号 | 结果比性能相近的竞品贵3倍 |
| 忽略了价格走势 | 选了一个即将涨价的型号，量产时成本超预算 |
| 低估了配套成本 | 某芯片便宜$10，但需要加2层PCB和专用散热器，整机成本多$50 |

**应对**：

- 研发选型人员应获取该品类的**价格参考范围**（采购提供）
- 建立**选型成本数据库**——常见器件的价格区间、趋势
- 选型评审时强制包含**成本影响分析**项

### 6.2 报价中的「隐藏成本陷阱」

> **问题**：报价单上的价格往往不是全部成本。

| 隐藏成本 | 来源 | 幅度 |
|:--------|:-----|:----:|
| NRE(一次性工程费) | 工具费、治具费、软件定制 | 可能占首单的20-50% |
| 加急费 | 缩短交期的额外费用 | 常规价的30-100% |
| 包装运输费 | 特殊包装/加急运输 | 3-10% |
| 最低起订量(MOQ) | 一次必须下够数量 | 可能导致过量采购 |
| 年度涨价 | 合同约定的价格调整机制 | 年涨3-8% |
| 技术支持费 | FAE现场支持、培训 | 按天计费 ¥2K-5K/天 |
| ROYALTY/IP许可 | 技术授权费 | 按出货量收取 |
| 认证/合规费 | 安规/EMC认证 | 每个认证¥5-30万 |
| 关税/进出口费用 | 跨国采购的附加税 | 5-25% |
| 替换/退货损失 | 踩坑后换料的沉没成本 | 难以量化但巨大 |

**应对**：

- 要求供应商提供**全成本报价单**（含所有费率）
- 使用**总获取成本(TAC)** 而非单价做决策
- 将NRE/模具费等一次费用与单价分开评估

### 6.3 报价的有效期与价格波动风险

> **问题**：供应商的报价通常在 **7-30天** 内有效。

| 风险 | 表现 | 后果 |
|:-----|:-----|:-----|
| 选型周期长 | 选型评审+审批流程走完，报价已过期 | 重新报价发现涨价10-20% |
| 市场波动 | DRAM/NAND/GPU价格急剧变化 | 报价与实际成交价差大 |
| 汇率波动 | 跨国采购的人民币/美元报价 | 未经锁汇，汇率波动吃掉利润 |

**应对**：

- 要求报价时锁定价格周期：**至少30天，争取90天**
- 核心器件（GPU/DRAM/CPU）争取 **LTSA锁价** （年框锁定价格）
- 设置价格保护条款：约定价格波动超过±5%时双方重新协商

### 6.4 「指定替代」的双刃剑效应

> **问题**：选型时指定了"兼容替代"（如注明第二供方），本意是增加竞争。

| 正面效应 | 负面效应 |
|:---------|:---------|
| 增加议价筹码 | 供应商可能不重视：「反正不是独家，降低支持优先级」 |
| 降低供应风险 | 两家供应商可能都降价抢单，但都不全力保障产能 |
| 有退路保障 | 实质上变成了两家都只提供部分支持，反而不如一家全力配合 |

**应对**：

- **主供+备供策略**：确定主供应商（获70-80%份额），备供保留技术验证
- 主供的价格优惠对应**份额承诺**和**排他性合作**条款
- 备供长期维持在"已验证可替代"状态，但不实际切换

### 6.5 「技术评分」与「商务评分」的权重博弈

> **问题**：选型评审时，技术分和商务分的权重决定了最终选择。

| 权重倾向 | 结果 | 风险 |
|:---------|:-----|:-----|
| 技术分权重过高(80%+) | 选了技术最好但价格极高的方案 | 产品没有利润空间 |
| 商务分权重过高(80%+) | 选了最便宜但性能/质量有风险的方案 | 产品质量问题返修/客诉 |
| 两者均衡但维度定义不清 | 评审标准模糊，沦为各说各话 | 研发说技术重要，采购说成本重要 |

**应对**：建立**双层评判机制**

```text
第一层（Hard Gate - 硬门槛）：
  必须同时满足：技术分≥70 AND 价格≤150%目标价
  不满足任意一条 -> 直接淘汰

第二层（Weighted Scoring - 加权评分）：
  技术分 60% + 商务分 30% + 风险分 10%
  其中技术分细分：核心功能满足度30%、性能余量10%、兼容性10%、生态10%
  商务分细分：价格竞争力15%、供应保障10%、合作意愿5%
```

### 6.6 样品阶段与量产阶段的「价格脱钩」

> **问题**：样品阶段的价格和量产阶段的价格往往无直接关系。

| 阶段 | 价格特征 | 常见陷阱 |
|:-----|:---------|:---------|
| 工程样品(ES) | 免费或低价（供应商策略性投入） | ⚠️ 样品便宜不代表量产便宜 |
| 小批量(MP1) | 中高价（含分摊NRE+加急费） | ⚠️ 第一批量产价高别意外 |
| 大批量(MP3+) | 真正体现竞争力和规模效应的价格 | ⚠️ 必须提前谈好阶梯价机制 |

**应对**：

- 样品阶段就要求供应商提供 **「从样品到量产的price roadmap」**
- 关键条款：**价格保护机制** (Price Protection)：

  ```text
  例：某SSD框架协议
  样品(1-100pcs): $200/ea
  小批量(100-1000pcs): $160/ea
  稳定量产(1000-10000pcs): $140/ea
  大批量(10000+): $120/ea
  → 研发选型时按$120评估，而不是看样品价$200
  ```

- 在选型评估时就以**量产目标价**为准，不以样品价做决策

### 6.7 平台化选型对报价的长期锁定效应

> **问题**：一个平台上的选型决定会影响未来3-5代产品的报价。

```text
平台选型决策树状扩散：

          选型决策A（如选定Intel Xeon平台）
              |
      +-------+----------+
      v                   v
  主板设计规格        散热模组设计
      |                   |
  +--+--+            +--+--+
  v     v            v     v
PCB  电源   CPU散热器  系统风扇
层数 需求    (定制品)  (通用品)
      |                   |
  +--+--+            +--+--+
  v     v            v     v
连接器 Debug    加工模具 备品备件
选型  接口      (定制费) (长期锁价)
```

**关键洞察**：**平台选型的成本不只是一颗CPU的钱，而是整个生态体系的成本**。

**应对**：

- 平台级选型（CPU/GPU/芯片组）需要做 **「平台总成本分析」**——含所有配套器件
- 评估平台切换成本，作为议价的筹码： 「如果你涨价过多，我们会在下一代换平台」
- Intel/AMD/NVIDIA的年度提价政策：提前获取路线图+价格趋势，规划切换窗口

### 6.8 自制与外购的「报价基准」

> **问题**：报价的合理性需要用「自制的成本」来校验。

| 物料类型 | 外购报价 | 自制成本估算（Should Cost） | 决策 |
|:---------|:---------|:--------------------------|:----|
| 标准PCIe Switch | Broadcom $200 | BOM估算$80+研发分摊 | 外购合理（技术壁垒） |
| 定制线缆 | ¥15/条 | BOM¥5+人工¥8+分摊¥3=¥16 | 外购合理 |
| 简单结构件 | ¥30 | 模具费¥5万+单价¥8 | 外购划算（未达批量） |
| 核心算法 | ¥200万/授权 | 自研需3人年×¥50万=¥150万 | 自研更优 |

**核心方法**：**Should Cost建模**——基于物料成本+制造成本+合理利润，倒推价格的合理区间。

**简单Should Cost公式**：

```text
Should Cost = (BOM直接物料成本 + 直接人工) × (1 + 制造业合理毛利率)

其中：
  - BOM直接物料：按公开市场价+分销商加价率估算
  - 直接人工：按工序工时×当地时薪估算
  - 制造业合理毛利率：标准件15-25%，定制件25-40%，高技术件40-60%
```

### 6.9 多品类组合的「交叉谈判」机会

> **问题**：单一物料选型去谈价格，不如组合物料一起谈有效。

```text
单一物料谈判：
  选型A(SSD) -> 找Samsung报价 -> 年量10K -> 单价$140
  选型B(DRAM) -> 找Samsung报价 -> 年量50K -> 单价$180

  结果：SSD和DRAM各自谈，Samsung不会因为买得综合多而给更好折扣

组合物料谈判：
  选型A(SSD) + 选型B(DRAM) + 选型C(其他)

  打包给Samsung：年量SSD10K + DRAM50K + 其他30K = 总交易额$XXX万
  -> 要求：总价额外折扣5-10%
```

**适用条件**：

- 同一供应商提供多个品类（Samsung: SSD+DRAM+其他存储）
- 供应商重视大客户的综合交易额而非单一品类利润
- 采购规模达到供应商的大客户门槛

### 6.10 「工程师偏好」对报价的隐性影响

> **问题**：研发工程师的人脉关系/使用习惯/对供应商的个人偏好可能影响选型客观性。

| 偏好来源 | 表现 | 对报价的影响 |
|:---------|:-----|:------------|
| 熟人关系 | "我一直用XX公司的芯片，他们FAE老王很帮忙" | 可能排斥其他供应商参与比价 |
| 使用习惯 | "我熟悉这款开发工具/调试环境" | 倾向于选同样的平台，不考虑成本变化 |
| 技术崇拜 | "XX品牌是行业标杆" | 愿意为品牌溢价买单，忽略性价比方案 |
| 培训影响 | "我去过XX的培训，他们技术确实领先" | 信息输入偏差，放大某供应商优势 |

**应对**：

- 建立客观的选型评估标准（量化打分）
- 强制至少邀请2家供应商参与选型（即使研发觉得"一家就够了"）
- 选型评审中设置**红队审查**角色（专门找选型方案的缺陷和风险）

### 6.11 报价的「版本管理」问题

> **问题**：选型和报价过程跨周甚至跨月，报价版本容易混乱。

| 场景 | 问题 | 后果 |
|:-----|:-----|:-----|
| 共发了3轮RFQ，报价变化 | 不知道哪一版是有效的 | 商务谈判时产生争议 |
| 选型方向调整后未重新报价 | 在旧报价基础上做了选型决策 | 实际价格与预期不符 |
| 不同部门收到不同报价 | 研发收到的和采购收到的不一致 | 研发以为成本可控，采购说不是 |

**应对**：建立报价版本管理流程

```text
报价版本规范
  v0.1 - 初步询价(RFI阶段)
  v1.0 - 正式报价(RFQ回应)
  v1.1 - 修正报价(技术澄清后)
  v2.0 - 最终报价(谈判后锁定)
  v2.1 - 合同价格(签署后固化)

  ⚠️ 每次报价变更必须标注变更内容和原因
  ⚠️ 最终选型评审必须引用最新报价版本号
```

### 6.12 地缘政治/贸易限制的报价影响

> **问题**：2026年的地缘政治环境使报价跨越单纯商业范畴。

| 因素 | 影响 | 对选型的启示 |
|:-----|:-----|:------------|
| 出口管制(EAR/CCL) | 含美国技术的器件受限 | 国产替代品可能溢价但供应安全 |
| 关税加征 | 中国产器件出口美国加税 | 供应链区域化影响报价结构 |
| 实体清单 | 供应商/客户被列入 | 选型时需评估供应链安全性 |
| 原材料禁运 | 钯/稀土/高纯硅限制 | 涉及这些材料的器件有涨价风险 |

**应对**：

- **供应安全指数**作为选型评审的必选项（权重不低于10%）
- 国产化选型：接受适度的性能和价格折中，换取供应链安全
- 建立**多来源策略**：关键器件至少2个来源（一主一备，最好分散在不同国家）

## 7. 常见失败模式与根因分析

### 7.1 「选-报脱节」模式

| 表现 | 研发选了型号才告诉采购去询价 → 价格出来发现远高于预期 → 被迫从头来 |
|:-----|:----------------------------------------------------------------|
| **根因** | 流程设计问题：选型和报价之间缺乏信息交换点和决策同步点 |
| **损失** | 项目延期2-4周，设计反复 |
| **解决** | 在研发流程的TR1-TR2阶段引入采购评审节点，选型方案必须附带初步成本评估 |

### 7.2 「锚定偏差」模式

| 表现 | 研发先入为主认定了某个品牌/型号 → 后面所有评估都倾向于它 → 实际报价很高但硬着头皮接受 |
|:-----|:-------------------------------------------------------------------------|
| **根因** | 认知偏误：首次获得的信息（锚定信息）过度影响了后续判断 |
| **损失** | 多付10-30%，或选了一个不是最优的方案 |
| **解决** | 选型启动时严禁指定品牌型号，只定义功能规格和性能要求，采购先发RFI获得价格区间 |

### 7.3 「低估配套成本」模式

| 表现 | 芯片报价看起来合理 → 量产时发现需要加散热器/改PCB/加测试设备 → 总成本超预算20-50% |
|:-----|:-----------------------------------------------------------------------|
| **根因** | 只关注了芯片本身的价格，忽略了系统集成的边际成本 |
| **损失** | 整机BOM成本超预算 |
| **解决** | 选型评审时必须附带「系统级BOM对比」——含器件+配套+验证的总成本分析 |

### 7.4 「过度压价反噬」模式

| 表现 | 采购把价格压到极致（利润空间趋零） → 供应商利润太低，技术支持消极 → 交付质量下降 → 最终损失更大 |
|:-----|:-----------------------------------------------------------------------------|
| **根因** | 零和博弈思维：认为"供应商利润 = 我方损失" |
| **损失** | 隐性成本（质量/交付/支持）远大于省下来的价格 |
| **解决** | 采用**总成本最优**而非**单价最低**的评估策略；给供应商合理利润空间换取优质服务 |

### 7.5 「一人多角」模式

| 表现 | 研发工程师同时负责技术评估和价格谈判 → 技术上满意了就不愿再压价 → 或过度压价导致供应商推诿 |
|:-----|:----------------------------------------------------------------------------|
| **根因** | 角色冲突：同一人无法同时做好"技术把关"和"商务博弈" |
| **损失** | 既没拿到最优价，也没选到最优方案 |
| **解决** | 明确职责分离：研发负责技术评分和方案推荐，采购负责商务谈判和最终价格确认 |

## 8. 最佳实践：高阶选型-报价联动案例

### 8.1 案例一：GPU选型中的TCO报价博弈

```text
背景：研发团队需要在AI训练服务器中选配GPU
候选方案：
  A. NVIDIA H100 (80GB) — $25,000/颗，供应受限，交期20周
  B. NVIDIA B200 (192GB) — $35,000/颗，新一代，交期26周
  C. AMD MI355X (192GB) — $28,000/颗，兼容ROCm，交期12周

研发倾向：B200（性能最高，生态最成熟）
报价反馈：B200 $35,000远超预算上限$28,000

第一次迭代：
  采购拿着B200报价和A+C的对比数据反馈->研发评估

  B200 TCO分析：
  采购价: $35,000
  + 配套散热(1,200W TDP): +$2,500
  + 电源升级: +$800
  + 液冷改造成本分摊: +$1,200
  = 每GPU总成本: $39,500

  vs MI355X (750W TDP):
  采购价: $28,000
  + 配套散热: +$1,200
  + 标准电源: +$400
  + 风冷可行: +$0
  = 每GPU总成本: $29,600

  -> MI355X的总成本比B200低25%，性能差异在可接受范围内
  -> 研发调整选型，以MI355X作为主力方案

第二次迭代：
  采购以MI355X方案作为筹码与NVIDIA谈判
  -> NVIDIA提供"教育/科研折扣" + B200降价至$31,000
  -> 但供应仍紧张，交期无法缩短

最终决策：
  短期内：AMD MI355X（可获得性+成本优势）
  长期评估：NVIDIA B200（保留技术验证，等待供应缓解）
```

```text
  Kioxia (方案C): 比Samsung便宜8%，供应稳定
  长江存储 (方案D): 性价比突出，但PCIe Gen4带宽有限

联合评审：
  +--------------------------------------+
  | 技术维度：                              |
  |  方案B(Gen6) 性能最优，但新品有EOL风险  |
  |  方案C(Gen5) 成熟稳定                   |
  |                                        |
  | 商务维度：                              |
  |  方案B报价$1,200，砍到$1,050(谈判后)    |
  |  方案C报价$780，砍到$720(年量承诺后)    |
  |                                        |
  | 风险维度：                              |
  |  方案B供应紧张，交期16周                |
  |  方案C供应充足，交期6周                 |
  +--------------------------------------+

最终方案：
  短期(当前项目)：方案C(Kioxia CM7) — 成熟稳定，成本可控
  中期(下一代)：方案B(PM1763) — 保留设计预留，等Gen6市场成熟
  长期(国产化)：方案D — 技术储备，等Gen5产品线成熟
```

### 8.3 案例三：PCB选型中的Should Cost反向校验

```text
背景：AI服务器主板24层高速PCB选型

供应商A (深南电路)：报价¥8,500/panel (4pcs/panel)
供应商B (沪电股份)：报价¥7,200/panel
供应商C (景旺电子)：报价¥9,000/panel

研发倾向：深南电路（技术评分最高）

Should Cost 建模验证：
  BOM物料成本（按公开报价）:
    基材 Megtron 6: ¥1,200/panel
    半固化片(PP) × 23层: ¥800/panel
    铜箔: ¥200/panel
    油墨/表面处理: ¥300/panel
    = 直接物料约 ¥2,500

  制造成本（按工序估算）:
    内层: ¥600 | 压合: ¥400 | 钻孔: ¥500 | 电镀: ¥400
    外层: ¥300 | 阻焊: ¥200 | 表面处理: ¥400 | 测试: ¥300
    = 制造成本约 ¥3,100

  Should Cost = (¥2,500 + ¥3,100) × (1 + 20%合理利润)
              = ¥6,720/panel

  实际报价 vs Should Cost:
    深南 ¥8,500 -> 溢价26% -> 偏高
    沪电 ¥7,200 -> 溢价7% -> 合理
    景旺 ¥9,000 -> 溢价34% -> 偏高

谈判：
  以沪电报价¥7,200和Should Cost¥6,720为基准与深南谈判
  -> 深南调整至¥7,600（年量承诺10,000 panel）
  -> 同时以沪电为备选施压
  -> 最终以¥7,400成交（仅比Should Cost高10%）

选型决策：
  深南电路（技术最佳 + 经过Should Cost验证的价格合理）
```

## 10. 总结：建立选型-报价的良性循环

### 10.1 核心理念

选型与报价不是"先做技术后谈商务"的线性关系，而是**螺旋迭代、相互校准**的闭环过程。

```text
          选型方案 ----> 报价反馈
              ^              |
              |    相互校准    |
              |              v
          决策锁定 <---- 方案修正
```

**高质量选型-报价交互的四个特征**：

| 特征 | 表现 |
|:-----|:------|
| 🎯 **同步** | 选型和报价并行开展，而不是串行接力 |
| 🔄 **迭代** | 至少2轮交互，基于反馈优化方案 |
| 📊 **量化** | 用数据决策(TCO/Should Cost)，而非直觉 |
| 🤝 **协同** | 研发+采购形成联合团队，不是各做各的 |

### 10.2 团队能力要求

| 角色 | 需要的能力 | 培养方式 |
|:-----|:-----------|:---------|
| **研发工程师** | 成本意识（选型时知道大概价格区间） | 采购部门定期给研发做价格培训 |
| | TCO思维（不只盯着芯片单价） | 建立选型-成本对照案例库 |
| | 供应商管理意识（适当的议价配合） | 参与供应商技术交流+商务谈判 |
| **采购工程师** | 技术理解力（能看懂Datasheet的关键参数） | 参与研发选型评审、产品技术培训 |
| | 市场洞察力（知道价格走势和供需变化） | 建立价格数据库、行业报告订阅 |
| | 风险评估能力（识别供应风险信号） | 与研发共建供应风险矩阵 |

### 10.3 组织机制建议

```text
组织机制设计：

① 选型-报价联席会议（每月一次）
   参与者：研发主管 + 采购主管 + 项目负责人
   议程：① 选型中的成本问题 ② 报价反馈的选型建议
         ③ 供应商评估更新 ④ 案例复盘

② 价格数据库（持续维护）
   内容：各品类物料的历史报价、成交价、市场价
   用途：为Should Cost提供基准，为选型决策提供参考

③ 联合供应商评估（每季度一次）
   参与者：研发+采购+质量+供应商
   评估维度：技术能力·价格竞争力·交付表现·配合度

④ 知识沉淀机制
   每次选型-报价闭环后，记录：
   - 选型时的价格预测 vs 实际成交价
   - 供应商报价的合理性和诚信度
   - 下次类似选型的改进建议
```

---

> **核心理念**: 选型决定了你**能买到什么**，报价告诉你要**花多少钱**。两者的关系不是谁压倒谁，而是通过有序的交互机制，找到"技术可行+商业可承受+风险可管控"的最优解。
>
> **行动建议**: 从下一个选型项目开始，做到"选型启动即通知采购"、"每份报价都做Should Cost验证"、"每个选型决策都经联合评审"——这三个动作能避免80%的选型-报价矛盾。
