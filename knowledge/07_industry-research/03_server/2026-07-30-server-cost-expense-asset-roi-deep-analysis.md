## §0 执行摘要

本文是服务器产销研BG成本费用管理的**执行操作手册**，核心解决八个实操问题：

### 回答的八个问题

| # | 问题 | 答案定位 |
|:-:|:-----|:--------|
| 1 | 成本和费用到底有什么区别？如何准确区分？ | §1 三要素本质 |
| 2 | 研发费用在Charter/中试等不同阶段怎么拆？每个部门花什么钱？ | §3.2-3.3 研发分阶段拆解 |
| 3 | 资产怎么判断？什么算资产什么不算？谁来判断？ | §4 资产识别判定 |
| 4 | 人均费用怎么定义？多少算合理？ | §5 人均费用定义 |
| 5 | ROI模型怎么建？用于投资决策/目标执行/绩效牵引分别怎么用？ | §6 ROI经营模型 |
| 6 | ROI使用中容易掉进什么坑？ | §6.4 六大陷阱 |
| 7 | 人力怎么预测？不是拍脑袋，有逻辑有公式地拍？ | §7 人力预测方法论 |
| 8 | BOM成本/非BOM费用/资本支出怎么预测？ | §8 其他成本预测 |

### 一句话原则

```text
成本 -> 与产品产出直接相关（跟着产品走）
费用 -> 与期间经营相关（跟着时间走）
资产 -> 未来多个期间受益（跟着价值走）
```

## §1 三要素本质：成本·费用·资产的根本区分

### 1.1 三要素的根本逻辑

三者不是会计学概念的游戏，而是决定了**管理责任落在谁头上、什么时候影响利润、能不能算ROI**。

**判断树**：

```text
这笔支出发生了 -> 问三个问题：

Q1：它是否与「单台产品」的产出直接相关？
  +-- 是 -> 问Q2
  +-- 否 -> 属于「费用」-> 计入当期利润表
            +-- 研发费用（研发部门用工/实验/测试）
            +-- 销售费用（销售团队/市场活动/渠道）
            +-- 管理费用（管理团队/IT/法务/财务）
            +-- 财务费用（利息/汇兑）

Q2：它是否在多个期间（>12个月）持续受益？
  +-- 是 -> 属于「资产」-> 分期折旧/摊销
  |       +-- 固定资产（设备/产线/车辆/房产）
  |       +-- 无形资产（专利/软件/资本化研发）
  +-- 否 -> 属于「成本」-> 计入存货，产品卖出时转为销售成本
            +-- 直接材料（BOM元器件）
            +-- 直接人工（产线工人工资）
            +-- 制造费用（产线折旧/水电/厂房租金）
```

**三要素的利润影响时间差异**：

```text
           T0       T1       T2       ...     Tn
费用    ----o-------- 一次性计入当期利润，全部影响

成本    ----o--------o--------o--------o---
        采购入库   产品完工   产品卖出
        (存货)     (存货)   (转入销售成本)

资产   ----o----------------------------o---
        购置        按折旧年限分期计入费用
        不计入利润  每年一小部分影响利润
```

### 1.2 错误分类的后果

| 错误类型 | 表现 | 当期后果 | 远期后果 |
|:---------|:-----|:---------|:---------|
| 费用→成本 | 研发样品领料计入存货 | 利润虚高 | 存货积压后减值反噬 |
| 成本→费用 | 生产设备耗材计入当期费用 | 利润虚低 | 产品毛利率失实 |
| 费用→资产 | 不满足条件的研发支出资本化 | 利润虚高 | 未来摊销压力+审计风险 |
| 资产→费用 | 应资本化的大额设备一次性进费用 | 利润被大幅压低 | 失去资产追踪 |

**谁负责判断**：

| 判断事项 | 执行部门 | 复核部门 | 最终批准 |
|:---------|:--------|:--------|:--------|
| BOM元器件→成本 | 采购部+成本BP | 财务BP | 财务负责人 |
| 产线人工→成本 | 制造部 | 成本BP | 制造负责人 |
| 研发样品→成本vs费用 | 研发项目经理+财务BP | 研发财务BP | 研发负责人 |
| 设备购置→资产vs费用 | 使用部门+采购部 | 财务BP | BG负责人(>¥X万) |
| 研发资本化→无形资产 | 研发负责人+财务BP | 集团财务 | 集团CFO |

## §2 成本拆解：从BOM到交付全链条

### 2.1 成本的三层结构

```text
+---------------------------------------------------------+
| 销售成本（COGS）= 产品卖出时从存货转入利润表的成本      |
|                                                         |
|  第一层：直接材料（Direct Material）                    |
|  +-- BOM元器件：GPU/CPU/DRAM/SSD/PCB/电源/机箱等       |
|  +-- 包材：纸箱/泡沫/托盘/标签/防静电袋                 |
|  +-- 附件：电源线/网线/导轨/说明书/光盘                 |
|  +-- 选配件：客户单独选购的光模块/网卡/扩展卡          |
|  占COGS比例：75-85%                                     |
|                                                         |
|  第二层：直接人工（Direct Labor）                       |
|  +-- SMT贴片线操作员                                    |
|  +-- 装配线装配工                                       |
|  +-- 测试线测试员                                       |
|  +-- 包装线包装工                                       |
|  占COGS比例：2-4%                                       |
|                                                         |
|  第三层：制造费用（Manufacturing Overhead, MOH）        |
|  +-- 变动MOH：水电/辅材/物流搬运                       |
|  +-- 固定MOH：产线折旧/厂房租金/生产管理/质检          |
|  +-- 外协加工费：SMT外协/表面处理/特殊工艺              |
|  占COGS比例：8-12%                                      |
|                                                         |
|  COGS合计 = 直接材料 + 直接人工 + 制造费用              |
+---------------------------------------------------------+
```

### 2.2 直接成本·间接成本·制造费用的分部门归属

**直接成本（可以直接算到单台产品上的成本）**：

| 成本项 | 定义 | 归属部门 | 核算方法 | 凭证 |
|:-------|:-----|:--------|:--------|:-----|
| GPU/CPU/DRAM | BOM中核心器件 | 采购部 | 按标准成本×BOM用量 | 采购入库单+领料单 |
| SSD/硬盘 | BOM中存储器件 | 采购部 | 同上 | 同上 |
| PCB/电源/机箱 | BOM中结构件 | 采购部 | 同上 | 同上 |
| 线缆/包材/附件 | BOM中辅料 | 采购部 | 同上 | 同上 |
| SMT贴片人工 | 产线直接作业 | 制造部-SMT车间 | 工时×工时费率 | 工时记录 |
| 装配人工 | 产线装配作业 | 制造部-总装车间 | 工时×工时费率 | 工时记录 |
| 测试人工 | 产线测试作业 | 制造部-测试车间 | 工时×工时费率 | 工时记录 |

**间接成本/制造费用（无法直接算到单台，需分摊）**：

| 费用项 | 内容 | 归属部门 | 分摊依据 | 分摊公式 |
|:-------|:-----|:--------|:--------|:---------|
| 产线折旧 | SMT/装配/测试设备年折旧 | 制造部 | 机器工时 | 产品机器工时占比×总折旧 |
| 厂房租赁 | 生产车间租金 | 行政部→制造部 | 面积 | 产品占用面积比×总租金 |
| 生产管理 | 车间主任/班组长工资 | 制造部 | 直接人工工时 | 产品DL工时占比×总管理工资 |
| 质量检验 | IQC/IPQC/OQC人员工资 | 质量部-制造质量 | 检验批次 | 产品检验批次占比×总检验费 |
| 水电能源 | 生产用电/用水 | 制造部 | 机器工时 | 产品机器工时占比×总水电 |
| SMT外协 | SMT贴片外发加工 | 制造部-工艺 | 直接归集 | 按外协合同价×板数 |
| 物料搬运 | 仓库物流人员 | 供应链-仓储 | 材料成本占比 | 产品材料成本占比×总搬运费 |
| 设备维修 | 产线设备维保 | 制造部-设备 | 机器工时 | 产品机器工时占比×总维修费 |

**制造费用分摊实操案例**：

```text
背景：某月生产AI服务器A 500台 + 通用服务器B 2,000台

直接归集数据：
  A单台BOM成本 ¥180,000，直接人工3小时×¥50=¥150
  B单台BOM成本 ¥15,000，直接人工1小时×¥50=¥50

制造费用总额：¥800,000
  +-- 产线折旧 ¥400,000（按机器工时分摊）
  |     A 2小时/台×500=1,000h, B 0.5h/台×2,000=1,000h
  |     A分摊：1,000/2,000×¥400,000=¥200,000, 单台¥400
  |     B分摊：1,000/2,000×¥400,000=¥200,000, 单台¥100
  +-- 生产管理¥200,000（按直接人工工时）
  |     A DH=500×3=1,500h, B DH=2,000×1=2,000h
  |     A分摊：1,500/3,500×¥200,000=¥85,714, 单台¥171
  |     B分摊：2,000/3,500×¥200,000=¥114,286, 单台¥57
  +-- 水电¥200,000（按机器工时）
        A分摊¥100,000, 单台¥200
        B分摊¥100,000, 单台¥50

最终成本：
  A单台成本 = ¥180,000 + ¥150 + ¥400 + ¥171 + ¥200 = ¥180,921
  B单台成本 = ¥15,000 + ¥50 + ¥100 + ¥57 + ¥50 = ¥15,257

毛利率计算：
  A售价¥250,000 -> 毛利率(¥250K-¥181K)/¥250K=27.6%
  B售价¥20,000 -> 毛利率(¥20K-¥15.3K)/¥20K=23.7%
```

### 2.3 成本核算：标准成本法

**标准成本法的运作逻辑**：

```text
标准成本 = 标准BOM成本 + 标准直接人工 + 标准制造费用

标准BOM成本 = Σ(各器件标准单价 × BOM用量)
  标准单价：每年年初核定，年中一般不调整除非价格波动>10%

标准人工 = 标准工时 × 标准工时费率
  标准工时：经IE测定的正常作业时间+宽放时间（5-10%）
  标准费率：年度预计直接人工总成本/年度预计总工时

标准MOH = 标准工时 × 标准MOH费率
  标准MOH费率 = 年度预计MOH总额/年度预计总工时
```

**差异分析（谁负责）**：

| 差异类型 | 计算方式 | 责任部门 | 管理动作 |
|:---------|:--------|:--------|:--------|
| BOM价格差异 | (实际单价-标准单价)×实际用量 | 采购部 | 谈判/替代料/换供应商 |
| BOM用量差异 | (实际用量-标准用量)×标准单价 | 制造部+研发 | 损耗率控制/DfX优化 |
| 人工效率差异 | (实际工时-标准工时)×标准费率 | 制造部 | 产线平衡/培训/自动化 |
| 人工费率差异 | (实际费率-标准费率)×实际工时 | HR+制造部 | 用工结构优化/排班 |
| MOH耗费差异 | 实际MOH-预算MOH | 制造部 | 各项费用预算控制 |
| MOH效率差异 | (实际工时-标准工时)×标准MOH费率 | 制造部 | 产能利用率提升 |

**谁维护标准成本**：

| 角色 | 职责 | 更新频率 |
|:-----|:-----|:--------|
| 成本BP | 标准成本核定与维护 | 年度（年中如有重大变化可调） |
| 采购部 | 提供BOM器件标准单价 | 季度（跟踪价格趋势） |
| 制造部IE | 提供标准工时 | 年度（产线变动时更新） |
| 财务BP | 审核标准成本合理性与差异分析 | 月 |

## §3 费用拆解：按业务域×研发阶段×执行部门

### 3.1 费用的大类划分

```text
期间费用总额 = 研发费用 + 销售费用 + 管理费用 + 财务费用

（注：成本是跟着产品走的，费用是跟着期间走的）
```

**四大期间费用的核心区别**：

| 费用类别 | 本质 | 驱动因素 | 占收入比（服务器行业参考） |
|:---------|:-----|:---------|:------------------------:|
| 研发费用 | 为未来产品创造投入 | 研发项目数量×人员编制 | 6-10% |
| 销售费用 | 获取订单的投入 | 销售团队规模+市场活动 | 3-5% |
| 管理费用 | 维持组织运转的投入 | 组织复杂度×合规要求 | 2-3% |
| 财务费用 | 资金使用的成本 | 有息负债规模+汇率波动 | 0-2% |

### 3.2 研发费用：按IPD阶段全生命周期拆解

这是最需要精细化管理的一部分——研发费用的投入形态在不同阶段完全不同。

**IPD全生命周期阶段定义与费用特征**：

```text
阶段0：Charter阶段（概念启动）
阶段1：概念阶段（Concept）
阶段2：计划阶段（Plan）
阶段3：开发阶段（Develop）
阶段4：验证/中试阶段（Validate/Pilot）
阶段5：发布/量产阶段（Launch/Ramp）
```

## §4 资产识别与判定标准

### 4.1 固定资产vs费用的判断流程

**判断树：一笔设备采购支出是资产还是费用？**

```text
这笔支出是否满足以下任意条件之一？
  +-- ① 使用寿命>12个月？
  +-- ② 单位价值>¥5,000（或企业设定的固定资产标准）？
  +-- ③ 可独立使用/可辨认？
  |
  +-- 全部满足 -> 按固定资产处理
  |   +-- 确定资产类别
  |   +-- 设置折旧年限/残值率
  |   +-- 财务BP创建资产卡片 -> 按月折旧
  |
  +-- 任一项不满足 -> 按费用处理
      +-- ① 使用<12个月+金额<¥5,000 -> 一次性计入当期费用
      +-- ② 使用<12个月+金额>¥5,000 -> 计入长期待摊费用（分期摊销）
      +-- ③ 使用>12个月+金额<¥5,000 -> 计入低值易耗品（一次或分次摊销）
```

**服务器行业常见固定资产及折旧标准**：

| 资产类别 | 包含内容 | 折旧年限 | 残值率 | 年折旧率 | 管理归属 |
|:---------|:---------|:-------:|:-----:|:-------:|:---------|
| 生产设备 | SMT贴片机/回流焊/波峰焊/装配线/测试线 | 8-10年 | 5% | 9.5-11.9% | 制造部 |
| 检测设备 | 示波器/逻辑分析仪/信号发生器/频谱仪 | 5-8年 | 5% | 11.9-19% | 测试部/研发 |
| 环境试验设备 | HALT箱/温箱/振动台/冲击台 | 8-10年 | 5% | 9.5-11.9% | 质量部(可靠性) |
| EMC测试设备 | 暗室/天线/接收机/LISN | 8-10年 | 5% | 9.5-11.9% | 质量部(认证) |
| 研发工作站/服务器 | 研发用高性能PC/仿真服务器 | 3-5年 | 0% | 20-33% | IT部+研发 |
| 网络设备 | 交换机/路由器/防火墙 | 5年 | 0% | 20% | IT部 |

### 4.2 无形资产（研发资本化）的判断流程

**研发支出资本化的五个条件（必须同时满足）**：

```text
条件1：技术可行性 — 关键技术验证通过（TR3评审通过）
条件2：完成意图 — 管理层正式立项+批准预算
条件3：未来收益 — 有明确客户订单/市场预测
条件4：资源保障 — 研发团队+资金到位
条件5：可靠计量 — 项目核算体系完备（工时+费用归集）
         v
  全部满足 -> 开发阶段支出可资本化 -> 形成无形资产
  任一不满足 -> 支出全部费用化
```

**具体判断流程（谁执行）**：

```text
Step 1：项目启动时预判
  研发项目经理 -> 在项目立项书中标注「预计资本化起点」
  财务BP -> 复核条件是否满足
  -> 形成《研发项目资本化评估表》

Step 2：TR3评审时正式确认
  TR3评审委员会 -> 评审技术可行性是否达标
  研发财务BP -> 正式确认资本化起点
  -> TR3通过后次日起的研发支出可资本化

Step 3：按月归集
  研发助理 -> 收集工时+费用凭证
  财务BP -> 按项目归集资本化金额
  -> 每月末汇总《研发资本化月度明细表》

Step 4：项目验收（TR7）后开始摊销
  研发财务BP -> 确认资本化总额
  -> 按预计受益年限（3-5年）开始摊销
```

**资本化核算案例**：

```text
项目A研发投入总¥500万：
  ① Charter+Concept阶段（TR3前）：¥30万 -> 全部费用化
  ② Plan+Develop阶段（TR3->TR6）：¥350万 -> 可资本化
  ③ Pilot/验证阶段（TR6->TR7）：¥90万 -> 可资本化
  ④ 量产支持阶段（TR7后）：¥30万 -> 全部费用化

资本化金额：¥350万+¥90万=¥440万（资本化率88%）
摊销：¥440万/5年=¥88万/年（直线法，残值0）

对比效果：
  如果不资本化：当期研发费用¥500万
  如果资本化：当期研发费用¥60万+摊销¥88万=¥148万
  当期利润差异：¥500万-¥148万=+¥352万
```

## §5 人均费用定义与实操口径

### 5.1 四层口径定义

人均费用不是单一数字，有四个口径，分别用于不同管理场景：

```text
口径层级         包含内容                          用途

L1：人均薪酬   工资+奖金+社保公积金+福利          招聘预算/HC审批
  L2：人均直接   L1 + 差旅+办公+通讯+培训         部门费用管控
  L3：人均全成本 L2 + 分摊费用(IT/HR/财务/行政)   产品线盈利分析
  L4：人均含折旧 L3 + 分摊折旧+摊销               投资回报/BG级P&L
```

**各口径的详细构成**：

#### 口径L1：人均薪酬

| 项目 | 占比（参考） | 说明 |
|:-----|:----------:|:-----|
| 基本工资 | 55-60% | 岗位标准工资，年度调薪 |
| 季度/年度奖金 | 15-25% | 按绩效系数（0.8-1.5）发放 |
| 社保公积金（企业承担） | 18-22% | 五险一金企业部分，地区差异大 |
| 福利（餐补/交通/体检等） | 3-5% | 按企业标准发放 |
| **人均薪酬合计** | **100%** | **¥20-60万/年（按岗位和地区）** |

**人均薪酬的岗位差异**（以年计，参考值）：

| 岗位类型 | 一线城市 | 二线城市 | 三线/产业园 |
|:---------|:--------:|:--------:|:----------:|
| 研发工程师（硬件/软件/固件） | ¥40-70万 | ¥30-50万 | ¥25-40万 |
| 研发高级/架构师 | ¥60-100万 | ¥45-70万 | ¥35-55万 |
| 测试工程师 | ¥25-40万 | ¥20-30万 | ¥15-25万 |
| 制造工程师(PE/TE/IE) | ¥25-40万 | ¥20-30万 | ¥15-25万 |
| 产线操作员 | ¥10-15万 | ¥8-12万 | ¥6-10万 |
| 销售经理 | ¥30-60万（含提成） | ¥25-45万 | ¥20-35万 |
| 产品经理 | ¥40-70万 | ¥30-50万 | ¥25-40万 |
| 项目管理 | ¥30-50万 | ¥25-40万 | ¥20-30万 |
| 行政/HR/财务 | ¥20-35万 | ¥15-25万 | ¥12-20万 |
| 中层管理（部门经理） | ¥60-100万 | ¥45-70万 | ¥35-55万 |

#### 口径L2：人均直接费用

```text
人均直接费用 = 人均薪酬 + 人均差旅 + 人均办公 + 人均通讯 + 人均培训

分岗位参考值（年）：
  研发人员：¥45-75万/年（薪酬占85%，其他占15%）
  销售人员：¥40-70万/年（薪酬占70%，差旅占20%，其他占10%）
  制造人员：¥15-25万/年（薪酬占90%，其他占10%）
  管理人员：¥35-60万/年（薪酬占80%，其他占20%）
```

#### 口径L3：人均全成本

```text
人均全成本 = L2 + 分摊费用（IT系统/HRBP/财务BP/行政/法务等）

分摊费用计算：
  IT系统分摊 = 该部门IT系统采购/维护年费 ÷ 部门人数
  HRBP分摊 = HRBP团队总成本 × 该部门人数占比
  办公场地分摊 = 该部门占用面积 × 单位面积租金
  法务分摊 = 法务部总成本 × 该部门工作量占比

示例（研发工程师）：
  L2人均直接费用：¥55万/年
  IT系统分摊：¥3万/年（每人工作站+EDA工具授权）
  HRBP分摊：¥2万/年
  办公场地分摊：¥4万/年
  法务分摊：¥1万/年
  L3人均全成本：¥65万/年
```

#### 口径L4：人均含折旧

```text
人均含折旧 = L3 + 人均折旧+摊销

人均折旧 = 该部门固定资产总额 ÷ 折旧年限 ÷ 人数
人均摊销 = 该部门受益的无形资产摊销 ÷ 人数

示例（研发部门）：
  L3人均全成本：¥65万/年
  人均设备折旧：¥3万/年（测试设备+工作站折旧分摊）
  人均无形资产摊销：¥2万/年（资本化研发支出摊销）
  L4人均含折旧：¥70万/年
```

### 5.2 各口径的用途与计算案例

| 口径 | 用途 | 谁使用 | 示例 |
|:-----|:-----|:-------|:-----|
| L1 | 招聘预算/HC审批 | HR+招聘经理 | 新招1名硬件工程师=¥45万/年预算 |
| L2 | 部门运营费用标准 | 部门负责人 | 销售部人均¥55万/年，10个人=¥550万预算 |
| L3 | 产品线盈利分析 | 产品线总经理 | 产品线总费用占收入比达标？ |
| L4 | 投资回报/BG P&L | BG负责人/CFO | 研发效率评估：人均产出收入比 |

**人均费用预算编制案例**（研发部，50人）：

```text

L3全成本预算（含分摊）：
  L2：¥1,205万
```

### 5.3 人均费用的行业参考基准

| 指标 | 服务器行业 | 一般电子制造 | 互联网 | 说明 |
|:-----|:---------:|:----------:|:-----:|:-----|
| 人均年收入 | ¥300-800万 | ¥150-300万 | ¥100-300万 | 研发占比多少决定人均营收 |

### 5.4 人均费用的执行管理机制

**人均费用不是年度制定一次就不管了，需要季度回顾**：

| 管理动作 | 频率 | 执行者 | 输出 |
|:---------|:----|:------|:-----|
| 制定年度人均费用基准 | 年度 | HR+财务BP | 各岗位人均费用标准 |
| 月度实际监控 | 月 | 财务BP | 人均费用实际vs预算偏差表 |
| 季度偏差分析 | 季 | 部门负责人+财务BP | 偏差原因+纠正措施 |
| 年度回顾调整 | 年 | HR+财务BP+BG负责人 | 下一年人均费用标准调整 |

**人均费用超标的处理流程**：

```text
人均费用实际vs预算偏差

偏差＜5%：-> 正常监控，无需措施
偏差5-10%：-> 部门负责人分析原因，提交说明
偏差10-20%：-> 冻结该部门新HC审批，要求降本方案
偏差＞20%：-> 正式管理干预，BG负责人介入
```

## §6 ROI经营模型：从定义到落地执行

### 6.1 ROI的四个层次

ROI不是单一公式。不同决策层级用不同的ROI模型：

```text
               | ROI层级          | 适用场景         | 决策者
               |                   |                  |
  L1 项目ROI  -+ 项目总利润/总投资  | 单个研发项目     | 产品线负责人
               |                   | 立项评审         |
               |                   |                  |
  L2 产品ROI  -+ 产品累计利润/开发  | 产品线投资决策   | 产品线总经理
               |  投资              | 产品EOL决定      |
               |                   |                  |
  L3 部门ROI  -+ 部门产出/部门总成本| 部门绩效评价     | 部门负责人
               |                   | 资源配置         |
               |                   |                  |
  L4 BG级ROI  -+ BG税前利润/BG总  | 资本配置         | BG负责人
               |  投入              | 投资回报评价     | CFO
```

### 6.2 各层次ROI的详细公式与使用场景

#### L1 项目ROI

**公式**：

```text
项目ROI = 项目生命周期内的累计净利润 / 项目总投入 × 100%

项目总投入 = 研发费用(¥) + 资本化摊销(¥) + 固定资产投资(¥) + 市场推广费用(¥)
累计净利润 = Σ(各年产品毛利 - 分摊费用 - 摊销 - 税费)

回收期（Payback Period）= 累计净利润 ≥ 总投入的月份/季度数
```

**AI服务器开发项目ROI计算案例**：

```text
项目投入：
  研发费用（全部费用化）：¥500万
  设备投资（测试设备）：¥100万（按5年折旧，残值0）
  市场推广：¥50万
  项目总投入：¥500万+¥100万+¥50万=¥650万
  （注：设备¥100万中¥20万/年折旧计入年度费用）

项目产出预测（3年生命周期）：
  Year 1：销售800台，售价¥250K，毛利率25%
      毛利 = 800×¥250K×25% = ¥5,000万
      减：折旧¥20万+分摊费用¥300万+税费¥600万 = ¥920万
      净利润Year 1 = ¥4,080万

  Year 2：销售1,200台，售价¥230K（竞争降价），毛利率22%
      毛利 = 1,200×¥230K×22% = ¥6,072万
      减：折旧¥20万+分摊费用¥350万+税费¥780万 = ¥1,150万
      净利润Year 2 = ¥4,922万

  Year 3：销售600台，售价¥200K（EOL清尾），毛利率18%
      毛利 = 600×¥200K×18% = ¥2,160万
      减：折旧¥20万+分摊费用¥200万+税费¥250万 = ¥470万
      净利润Year 3 = ¥1,690万

累计净利润 = ¥4,080 + ¥4,922 + ¥1,690 = ¥10,692万
项目ROI = ¥10,692/¥650 = 16.45 = 1,645%
回收期 = 3个月（Year 1 Q3实现累计净利润>¥650万）
```

**项目ROI的使用场景**：

| 场景 | 使用方法 | 决策标准 |
|:-----|:---------|:--------|
| 项目立项评审 | 比较不同项目的ROI和回收期 | ROI>300%且回收期<18个月 |
| 项目优先级排序 | ROI×战略价值矩阵（四象限） | 高ROI+高战略=优先 |
| 项目终止决策 | 已投入资金vs剩余预期回报 | 沉没成本不决策，剩余潜力>继续投入=继续 |

#### L2 产品ROI

**公式**：

```text
产品ROI = 产品生命周期内产生的毛利 / (开发投入 + 市场投入) × 100%

产品生命周期：从Charter开始到EOL/MPP结束的全周期
开发投入：Charter->Launch阶段全部研发+认证+市场费用
毛利贡献：产品销售毛利 - 品牌/渠道分摊 - 售后成本
```

**产品ROI vs 项目ROI的区别**：

| 维度 | 项目ROI | 产品ROI |
|:-----|:--------|:--------|
| 范围 | 单个开发项目 | 整个产品线（可能含多个项目） |
| 时间 | 项目周期（通常1-3年） | 产品生命周期（通常3-5年） |
| 包含 | 仅研发相关投入 | 含全部运营费用 |
| 用途 | 决定是否开发 | 决定是否继续投资/EOL |

#### L3 部门ROI

**公式**：

```text
部门ROI = 部门产出 / 部门总成本 × 100%

部门总成本 = L3人均全成本 × 人数 + 部门直接费用

不同部门的产出定义：
  研发部产出 = 新产品收入贡献（按产品收入×产品技术归属系数）
  销售部产出 = 销售订单额 + 回款额
  制造部产出 = 产出台数 × 单台标准人工+MOH - 实际制造费用
  采购部产出 = 采购降本金额（对比上一年度单价）
  质量部产出 = 因质量改善减少的损失（返工/退货/索赔减少额）
```

**部门ROI使用注意事项**：

| 部门 | 产出度量难点 | 替代方案 | 权重建议 |
|:-----|:-----------|:---------|:--------|
| 研发部 | 新产品收入受多重因素影响 | 使用「开发效率+质量+成本达标率」综合指标 | 不作为绩效考核唯一依据 |
| 销售部 | 客户关系长期价值难量化 | 加入客户满意度/市场占有率指标 | ROI占60%，战略指标占40% |
| 制造部 | 产能利用率受市场影响 | 区分可控/不可控因素 | 弹性预算基础上的MOH控制率 |

#### L4 BG级ROI

**公式**：

```text
BG级ROI = BG息税前利润(EBIT) / BG占用资本 × 100%

BG占用资本 = 固定资产净值 + 存货 + 应收账款 - 应付账款
           = 运营资金 + 固定资产净值

ROIC（Return on Invested Capital）：
  ROIC = NOPAT（税后经营利润） / 投入资本
```

**BG级ROI的行业参考**：

| 指标 | 优秀 | 良好 | 需改善 |
|:-----|:---:|:---:|:-----:|
| ROIC | >25% | 12-25% | <12% |
| ROE | >20% | 10-20% | <10% |
| 投入资本周转率 | >3x | 1.5-3x | <1.5x |
| EBIT利润率 | >10% | 6-10% | <6% |

### 6.3 ROI模型的三大用途

#### 用途一：投资决策

**ROI在立项评审中的使用流程**：

```text
新项目提案
    v
① 计算项目ROI（研发财务BP+项目经理）
    +-- 投入估算（研发费用+设备+市场）
    +-- 产出估算（销售收入预测×毛利率）
    v
② 与门槛值比较
    +-- ROI > 300% ? -> 财务可行
    +-- ROI 100-300% ? -> 需战略理由
    +-- ROI < 100% ? -> 除非战略必需否则不投
    v
③ 风险调整后的ROI（不确定因素下的敏感性分析）
    +-- 悲观场景（销量-30%，价格-10%）
    +-- 基准场景
    +-- 乐观场景（销量+20%）
    v
④ 多项目优先级排序（ROI × 战略价值矩阵）

        高ROI            低ROI
高战略  ★★★★★ 优先投资   ★★★★ 准战略投资
低战略  ★★★ 财务导向    ★★ 不投或延后
```

**投资决策门槛值（建议）**：

| 项目类型 | 最低ROI门槛 | 最晚回收期 | 通过概率 |
|:---------|:----------:|:---------:|:--------:|
| 平台型研发（通用架构/平台板） | >200% | <24个月 | 中（高ROI+高战略） |
| 定制开发（大客户AI集群） | >100% | <18个月 | 高（订单已锁定） |
| 新技术预研（Charter类） | 不适用 | 不适用 | 战略决策，不依赖ROI |
| 降本项目 | >500% | <12个月 | 高（确定性高） |
| 产能投资 | >15%(IRR) | <3年 | 看市场需求确定性 |

#### 用途二：目标执行

**ROI与年度目标分解的联动**：

```text
集团/董事会下达：BG级ROIC ≥ 18%
    v
分解到BG管理层：
    BG级目标：EBIT≥¥1.8亿，占用资本≤¥10亿
    v
分解到产品线：
    产品线A：EBIT≥¥1.0亿（ROIC 22%）
    产品线B：EBIT≥¥0.5亿（ROIC 15%）
    产品线C：EBIT≥¥0.3亿（ROIC 12%）
    v
分解到部门（链式驱动）：
    研发部：新产品收入≥¥3亿 + 研发费用率≤8%
    销售部：订单≥¥12亿 + 回款率≥85%
    制造部：单台MOH≤¥800 + 直通率≥97%
    采购部：年度降本≥¥1,500万
    v
分解到个人：
    研发工程师：×个设计任务按时交付 + 质量达标
    销售经理：¥XX万订单 + 客户满意度≥4.5分
```

**ROI的月度跟踪机制**：

```text
每月经营分析会：
  +-- 查看：BG级ROIC × 产品线ROI × 项目ROI完成率
  +-- 比较：实际 vs 预算（偏差分析）
  +-- 例外：偏差>10%的项目需专项分析
  +-- 行动：偏差>20% -> 纠正措施或项目终止建议
```

#### 用途三：绩效牵引

**ROI与绩效考核的耦合**：

| 层级 | 考核对象 | ROI指标 | 权重建议 | 激励关联 |
|:-----|:---------|:--------|:-------:|:---------|
| BG负责人 | 事业部总裁 | BG级ROIC | 30% | 年度奖金+期权 |
| 产品线负责人 | 产品线总经理 | 产品ROI | 30% | 年度奖金+晋升 |
| 项目经理 | 项目总监 | 项目ROI达标率 | 20% | 项目奖金 |
| 部门负责人 | 各部门部长 | 部门ROI | 15% | 部门绩效奖金包 |
| 基层员工 | 个人 | 间接（团队目标） | 5-10% | 个人绩效系数 |

**ROI绩效牵引的实操注意事项**：

```text
✅ 正确做法：
  - ROI作为长期导向指标（年度考核），不是月度考核
  - 结合滞后指标（财务结果）和领先指标（研发进度/客户获取）
  - 设定ROI底线（太低就自动触发复盘）
  - 按业务阶段调整权重（开发期ROI权重低，成熟期权重高）

❌ 错误做法：
  - 月度考核ROI（ROI天然是长期指标，月度波动随机）
  - ROI与短期奖金强挂钩（导致短视行为）
  - 对不同阶段的产品用同一ROI标准
  - ROI是唯一考核指标（需要平衡增长与盈利）
```

### 6.4 ROI使用的六大陷阱与对策

| # | 陷阱 | 表现 | 后果 | 对策 |
|:-:|:-----|:-----|:-----|:-----|
| T1 | **ROI虚高** | 忽略平台共用性：只算了直接项目投入，没算共享平台/公共组件成本 | 看起来ROI很高，实际平台分摊后很低 | 分摊共享平台成本到各项目，按使用量或收入比例 |
| T2 | **比较基准不一致** | 不同产品线用不同的贴现率/折旧方法/资本化比例 | ROI不可比，投资优先序错误 | 全BG统一ROI计算规则，由集团财务BP审核 |
| T3 | **仅看ROI忽视战略** | 只投高ROI短平快项目，不投平台/基础研发 | 短期盈利好，长期技术空心化 | 定义战略权重：战略项目即使ROI低也保留一定投资比例（如20%） |
| T4 | **ROI与预算脱节** | 立项时ROI很高，执行中预算没控制住 | ROID（ROI偏差）：立项ROI 500%，实际-50% | 立项时就锁定预算，超预算需重新计算ROI |
| T5 | **回收期焦虑** | 只看回收期不看全周期回报 | 砍掉前期投入大但长期回报好的项目 | 设定回收期上限（如24个月），但结合NPV全周期评估 |
| T6 | **ROI责任人不明确** | 项目经理算ROI但不对ROI结果负责 | ROI沦为空谈，花钱时没人管回报 | ROI责任人=项目负责人，纳入绩效合同 |

## §7 人力预测方法论

### 7.1 人力预测的核心逻辑

**人力预测不是「拍脑袋」而是「合理算」**。核心逻辑链：

```text
业务需求 -> 工作量 -> 人月 -> 人数 -> 人力成本

业务需求（输入）    工作量（换算）         人数（输出）
  +----------+     +--------------+     +----------+
  | 新项目×5  | --->| 每个项目需要  | --->| 研发团队  |
  | 产品线×3  |     | 工程师12人×   |     | 编制60人  |
  | 客户维保  |     | 6个月 = 360  |     | +运维20人 |
  +----------+     | 人月          |     +----------+
                    +--------------+
```

**五种预测方法按场景选择**：

```text
                            预测精度
                              |
                     o 定额法（最高精度）
                     o 行业对标法
                     o 工作量法（适用于项目制）
                     o 回归法（需要历史数据）
                     o 比例法（最简单，精度最低）
                              |
                              v
                          简单快速
```

### 7.2 五种预测方法+适用场景+操作步骤

#### 方法一：比例法（最简单，精度★★）

**适用场景**：管理/行政/HR等支持部门、年度预算粗略估算、0->1阶段无历史数据

**操作步骤**：

```text
Step 1：确定基准指标（如研发总人数、收入规模）
Step 2：确定比例系数（行业经验值或行业基准）
Step 3：计算

公式：
  管理人数 = 研发总人数 × 管理系数（1:8~1:12）
  IT人数 = 研发总人数 × 4-6%
  HR人数 = 员工总数 × 0.8-1.2%

案例：
  研发总人数规划200人
  -> 管理人员（部门经理+总监）= 200/10 = 20人
  -> IT支持 = 200×5% = 10人
  -> HR = (200+100+50)×1% = 3.5->4人
  -> 财务 = 350×1% = 3.5->4人
  -> 行政 = 350×1.5% = 5人
```

#### 方法二：工作量法（最常用，精度★★★★）

**适用场景**：研发项目人力预测（主力方法）

**操作步骤**：

```text
Step 1：列出未来周期内的项目清单
Step 2：每个项目估算工作量（人月）
Step 3：按角色拆分（高级/中级/初级）
Step 4：加入缓冲（10-20%）
Step 5：平铺到时间线上形成人力需求曲线

公式：
  项目人力需求(人月) = Σ(各活动工作量) × (1 + 缓冲系数)
  年度平均人数 = Σ(各月人力需求) / 12

研发项目人力预测模板：

项目A：8-GPU AI服务器，周期12个月
  +-- Concept（2个月）：系统架构师×2 + 产品经理×2 = 8人月
  +-- Plan（2个月）：硬件×5 + 固件×3 + 结构×2 + 测试×3 = 26人月
  +-- Develop（6个月）：硬件×10 + 固件×8 + 软件×5 + 结构×3 + 测试×8 = 204人月
  +-- Pilot（1.5个月）：硬件×5 + 固件×3 + 测试×8 + PE×3 = 28.5人月
  +-- Ramp（0.5个月）：硬件×2 + 测试×3 = 2.5人月
  +-- 合计：269人月 × 1.15缓冲 = 309人月
  +-- 折合年度平均人数：309/12 = 25.8人（取整26人）
  +-- 人力成本：26人 × L2人均¥55万 = ¥1,430万

项目B：通用服务器常规升级，周期8个月
  合计：135人月，折合平均17人
  人力成本：17人 × L2人均¥45万 = ¥765万
```

**工作量估算的方法论**：

```text
工作量估算方法（按精度排序）：

方法a：类比估算（最常用）
  基于类似历史项目的实际工时数据
  精度：±20%
  操作：找过去最相似的项目 -> 取其实际工作量 -> 调整差异因素

方法b：参数估算（次常用）
  使用历史数据建立的参数模型
  精度：±15%
  操作：确定关键参数（如PCB层数/器件数/功能点数）× 单位参数工时

方法c：三点估算（最佳实践）
  乐观(O)/最可能(M)/悲观(P)三个值加权平均
  精度：±10%
  公式：E = (O + 4M + P) / 6
  案例：某模块预计工时：O=60人天, M=80人天, P=140人天
        E = (60+4×80+140)/6 = 87人天（比80更稳健）

方法d：自下而上估算（最精确）
  分解到每个任务->估算每个任务工时->汇总
  精度：±5%
  成本：耗时最长
```

#### 方法三：定额法（精度最高★★★★★）

**适用场景**：制造/测试等有明确产能标准的岗位

**操作步骤**：

```text
Step 1：确定产出计划（月产量/季度产量）
Step 2：确定单位产出所需人工定额（经IE测定的标准工时）
Step 3：计算所需总工时
Step 4：除以单人工时 -> 所需人数

公式：
  直接产线人数 = 月产量 × 单台标准工时 / (月工作天数×8h×出勤率)
  测试人数 = 月产量 × 单台测试工时 / (月工作天数×8h×出勤率)

案例：
  月产量目标：3,000台服务器
  单台装配标准工时：4小时（含测试）
  月工作天数：21.75天
  出勤率：92%（含年假/病假/培训）

  所需人数 = 3,000×4小时 / (21.75天×8h/天×92%)
            = 12,000 / 160 = 75人

  需考虑：工时缓冲（计划外返工/加急单）= 75×1.1 = 83人
```

#### 方法四：回归法（需要历史数据，精度★★★★）

**适用场景**：有2年以上历史数据、相关性强

**操作步骤**：

```text
Step 1：收集历史数据（如收入、项目数、客户数）
Step 2：建立回归模型（人员 = a + b×驱动因子）
Step 3：验证模型R²（拟合优度）
Step 4：代入未来驱动因子预测值

简单线性回归案例：
  历史数据：过去24个月的销售收入与销售团队人数
  回归结果：销售人数 = 5 + 0.0012 × 月销售额（¥万）
          R² = 0.85（拟合度高）

  下季度预测月均销售额¥8,000万
  -> 销售人数 = 5 + 0.0012×8,000 = 5+9.6 = 15人

注意：回归法需要足够的样本量和稳定的业务模式
     业务模式变化时（如从直销转渠道），回归模型失效
```

#### 方法五：行业对标法（精度★★★）

**适用场景**：新建团队/进入新市场、无历史数据

**操作步骤**：

```text
Step 1：确定对标对象（类似规模的服务器企业/部门）
Step 2：收集对标指标（人均产出/人配比）
Step 3：调整差异因素（业务模式/技术栈/自动化水平）

对标指标案例：
  服务器企业研发团队比例：总员工数×40-55%
  人均支撑产品数：每人同时支撑2-3个在研项目
  研发人员配比：硬件:固件:软件:测试 = 3:2:2:3
  测试设备配比：每3个开发配1个测试工程师

对BG调整：
  本BG定制化比例高->测试人员比例上调
  本BG平台复用率高->开发人员比例下调
```

**五种方法的选择决策树**：

```text
有标准产能/定额？
  +-- 是 -> 用定额法（制造/测试岗）
  +-- 否 -> 有历史项目数据？
              +-- 是 -> 有类似项目？
              |         +-- 是 -> 用类比法（研发项目）
              |         +-- 否 -> 用参数法/三点估算
              +-- 否 -> 有行业对标数据？
                          +-- 是 -> 对标法
                          +-- 否 -> 比例法（最粗略）
```

### 7.4 人力预测的常见偏差与校正

| # | 偏差类型 | 表现 | 原因 | 校正方法 |
|:-:|:---------|:-----|:-----|:---------|
| B1 | **乐观偏差** | 预测人力偏少，执行中不够用 | 项目经理低估工作量 | 强制加入15-20%缓冲系数 |
| B2 | **资源闲置** | 预测过多，实际利用率低 | 为保住HC故意多报 | 按利用率考核：低于70%说明多报 |
| B3 | **技能错配** | 总人数对但技能不对 | 招人时没考虑实际技能需求 | 按角色分开预测（高级/中级/初级） |
| B4 | **时间错配** | 人力到岗时间滞后于需求峰值 | 招聘周期未考虑 | 提前3-6个月启动招聘 |
| B5 | **流失率低估** | 边招边流失，净增低于预期 | 没算流失率 | 按部门历史流失率×0.8+行业均值×0.2 |
| B6 | **入职延迟** | 已批准的HC迟迟招不到人 | 招聘市场匹配慢 | 分阶段到岗（Q1立即招Q2-3到岗） |

**流失率的预测与计入**：

```text
部门年度流失率预测 = 历史12个月实际流失率 × 调整系数

调整系数：
  行业人才市场紧张（如AI/GPU相关）-> 1.2-1.5
  部门有降薪/裁员传闻 -> 1.3-1.8
  公司正在扩张期（人才流入）-> 0.7-0.9

案例：
  系统研发部历史流失率 12%
  AI人才市场竞争激烈 -> 调整系数1.3
  预测流失率 = 12% × 1.3 = 15.6%

  影响：
    年初规划35人，年度净增加5人
    需招聘人数 = 净增5人 + 流失替补(35×15.6%=5.5人) = 11人
    比不考虑流失多招一倍！
```

## §8 其他成本预测方法论

### 8.1 BOM成本预测

**核心逻辑**：

```text
BOM成本预测 = 各器件预测单价 × BOM用量
```

**器件单价预测的五种方法**：

```text
+----------+--------------------+------------------+-----------+
| 器件类型 | 预测方法           | 预测精度         | 数据来源  |
+----------+--------------------+------------------+-----------+
| GPU      | 供应商报价+市场调研 | ±10-20%（波动大）  | NVIDIA报价 |
|          | 按季度梯度模型      |                  | 市场现货价|
+----------+--------------------+------------------+-----------+
| CPU      | 供应商报价（稳定）  | ±5%              | Intel/AMD  |
|          | 结合Roadmap预判     |                  | 官方报价   |
+----------+--------------------+------------------+-----------+
| DRAM     | 周期模型（Worst-case| ±10-25%（波动最大）| DRAMeXchange|
|          | 6个月周期顶峰-谷底）|                  | TrendForce |
+----------+--------------------+------------------+-----------+
| SSD      | 长期降价趋势模型    | ±5-8%            | 供应商季度  |
|          | -3%至-5%/季度       |                  | 报价       |
+----------+--------------------+------------------+-----------+
| PCB/结构 | 按设计复杂度＋材料  | ±5%              | 供应商报价  |
|          | 成本模型估算        |                  |           |
+----------+--------------------+------------------+-----------+
| 被动/连接 | 历史价格+通货膨胀   | ±3-5%            | 历史采购价  |
| 器等     | 调整                |                  | 大宗商品   |
+----------+--------------------+------------------+-----------+
```

**BOM成本预测综合案例**：

```text
产品：8-GPU AI服务器（2027年量产）

GPU（8×H200）：
  2026Q4：$20K/颗（当前供应商锁定报价）
  2027Q1：$20K（持平，新产品刚发布）
  2027Q2：$19K（量产后微降）
  2027Q3：$17K（竞争加剧+下一代产品即将发布）
  2027Q4：$15K（预测降价，下一代产品替代）
  年加权均价：$17.8K/颗
  年GPU成本：8×$17.8K = $142.4K

DRAM（2TB DDR5）：
  当前$1.1K/128GB，预测2027年跌20%
  年DRAM成本：16×$0.88K = $14.1K

SSD（30TB NVMe）：
  当前$10K/30TB，按季度-4%
  年SSD成本：$10K×0.96^4 = $8.5K

BOM总成本预测（年度加权）：
  GPU $142.4K + CPU $15K + DRAM $14.1K + SSD $8.5K + 其他$20K = $200K
  相比当前BOM $250K，同比下降13%
  主要降幅来自GPU（从$20K->$17.8K）和SSD降价
```

**BOM降本目标的分解**：

```text
年度BOM降本目标：¥5,000万（对比上年度实际BOM总额）

自上而下分解：
  采购部降本：¥3,000万（通过谈判+替代料+多源竞争）
  研发部DfX降本：¥1,500万（通过设计优化降低BOM用量）
  制造部降本：¥500万（通过工艺优化降低辅材+损耗）

自下而上汇总验证：
  谈判降价：¥1,500万（11个大类器件×平均降幅5%）
  替代料降本：¥800万（8个器件引入第二供应商）
  平台共用降本：¥700万（与通用服务器共用平台）
  DfX优化：¥1,000万（PCB改版/连接器优化/电源优化）
  损耗降低：¥500万（产线直通率提升->废料减少）
  其他：¥500万（包装/物流/仓储优化）
  合计：¥5,000万 ✓
```

### 8.2 非BOM费用预测

**研发费用预测模型**：

```text
研发费用 = 人力成本（L2人均×人数） + 样机物料 + 认证测试 + 工具设备 + 其他

驱动因素：
  人力成本 = 在研项目数 × 每项目平均人数 × L2人均薪酬
  样机物料 = Σ(各项目打样次数 × 每次样机成本)
  认证测试 = 新产品数 × 平均认证费用（3C+UL+CE ≈ ¥50万/品）
  工具设备 = 新增工作站/服务器/测试仪器/EDA授权

预测案例（2027年研发费用）：
  在研项目：6个（3个全新+3个升级）
  研发总人力：60人（在岗）+ 5人（新增）= 65人
  L2人均费用：¥55万/人
  人力成本：65×¥55万 = ¥3,575万

  样机物料：6个项目×平均¥120万/项目 = ¥720万
  认证测试：3个新品×¥50万 = ¥150万
  工具设备：¥200万（新增工作站+测试仪器）
  其他：¥200万（差旅/培训/专利/办公）

  研发费用预测 = ¥3,575 + ¥720 + ¥150 + ¥200 + ¥200 = ¥4,845万
  研发费用率=¥4,845万/收入¥6亿=8.1%（含资本化前的研发费用）
```

**销售费用预测模型**：

```text
销售费用 = 销售团队薪酬 + 渠道费用 + 市场活动 + 售前支持

驱动因素：
  销售团队 = 销售人数 × L2人均
  渠道佣金 = 渠道收入 × 佣金比例（通常3-8%）
  市场活动 = 年度市场活动计划总预算
  售前支持 = FAE人数 × L2人均

预测案例：
  销售人数：20人（含售前FAE 5人）
  销售L2人均：¥50万/人（含提成）
  团队薪酬：20×¥50万 = ¥1,000万

  渠道收入：¥2亿 × 5%佣金 = ¥1,000万
  市场活动：展会×3（¥50万/次）+ 研讨会×6（¥10万/次）+ 广告¥50万 = ¥260万

  销售费用预测 = ¥1,000 + ¥1,000 + ¥260 = ¥2,260万
  销售费用率 = ¥2,260/¥6亿 = 3.8%
```

### 8.3 资本支出(CAPEX)预测

**CAPEX的四类驱动因素**：

| CAPEX类型 | 驱动因素 | 预测方法 | 年金额参考(¥10亿BG) |
|:----------|:---------|:--------|:----------------:|
| 产能扩张 | 产能利用率>85%+未来需求增长 | ① 需求预测→② 产能缺口→③ 投资需求 | ¥1,000-3,000万 |
| 设备更新 | 设备使用年限+技术迭代 | 按设备台账的年度更新计划 | ¥500-1,000万 |
| IT/数字化 | 数字化转型路线图 | 按数字化规划的年度投入 | ¥300-800万 |
| 厂房/基建 | 业务扩张+搬迁/扩建需求 | 按基建计划 | 非标 |

**产能投资预测案例**：

```text
当前产能：5,000台/月，利用率95%（近满负荷）
需求预测：下年度月均需求6,000台（增长20%）

产能缺口：6,000 - 5,000 = 1,000台/月

解决方案：新建一条装配测试线
  投资：¥1,500万（设备¥1,200万+安装调试¥200万+其他¥100万）
  产能增量：1,200台/月（含15%余量）
  折旧（8年）：¥1,500/8 = ¥187.5万/年

  CAPEX预算：¥1,500万（T0投入）
  不含后续运维费用（入MOH）
```

**CAPEX预算的审批门槛**：

| 金额范围 | 审批层级 | 需要材料 | 审批周期 |
|:--------|:--------|:---------|:--------|
| <¥10万 | 部门负责人 | 采购申请单 | 1-3天 |
| ¥10-50万 | 产品线负责人 | 投资立项申请+3家报价 | 1周 |
| ¥50-200万 | BG负责人 | ROI分析+供方评估+技术方案 | 2周 |
| ¥200-500万 | 集团投资委员会 | 完整投资方案+风险评估+备选方案 | 1个月 |
| >¥500万 | 集团董事会 | 战略审查+全生命周期财务模型 | 2-3个月 |
