## §0 执行摘要

服务器制造运营正经历从**标准化产品制造**到**复杂系统集成制造**的范式跃迁。核心变化来自三个驱动力：

1. **交付层级的跃升**：从 L6-L8（板卡/准系统/整机）向 L9-L12（整机柜/超节点/集群/AI工厂）的演进，使制造复杂度从 O(10²) 部件/节点 跃升到 O(10⁵) 器件/超节点
2. **时间压缩的悖论**：AI基础设施的竞争节奏迫使 EVT 阶段即需发货，但产品复杂度此时仍处于快速收敛期
3. **供应链的结构性反转**：GPU 占 AI 服务器 BOM 的 65-75%，对品牌商/OEM 而言，利润空间被数学锁定在 5-10%

这些变化对制造运营带来六个新挑战：**EVT发货管控**、**超节点直通率**、**物料供应保障**、**价格波动应对**、**小批量柔性**、**多物料管理**。

本报告以第一性原理为分析起点，逐层解析每个挑战的本质约束、失效模式与应对策略。核心结论：

| 挑战 | 本质 | 核心策略 |
|:-----|:-----|:---------|
| EVT发货 | 技术风险 vs 市场窗口的博弈 | 分段验收+风险清单+软硬件分离交付 |
| 直通率 | 串联链路的数学极限 | 模块化自测+降级模式+跨层级热备份 |
| 物料供应 | 寡头垄断下的分配博弈 | 长单锁定+多供应商培育+替代料认证 |
| 价格波动 | 供需周期的三次传导 | 期货式锁定+库存缓冲+BOM设计预留 |
| 小批量 | 固定成本被稀释 | 柔性产线+平台化+配置器上库自动化 |
| 多物料 | 组合爆炸的管理成本 | 优选目录+替代料矩阵+自动兼容验证 |

## §1 服务器研发运营与经营活动全景

### 1.1 七领域活动模型

服务器企业的经营活动可以划分为**七个相互耦合的领域**，每个领域对应一组活动集合与知识体系：

```text
                    +---------------------+
                    |    管理领域(§1.8)    | <- 神经系统：方向·节奏·决策
                    +---------+-----------+
                              | 规划/协调/监控
         +--------------------+--------------------+
         v                    v                    v
   +----------+        +----------+        +----------+
   | 研发领域  |        | 平台领域  |        | 制造领域  |
   | (§1.2)   |        | (§1.6)   |        | (§1.3)   |
   | 产品创造  |        | 资产沉淀  |        | 产品交付  |
   +-----+----+        +-----+----+        +----+-----+
         |                    |                   |
         +--------+-----------+----------+--------+
                  |                      |
            +-----v-----+          +-----v-----+
            | 供应链领域  |          | 经营领域   |
            | (§1.4)    |          | (§1.5)    |
            | 物料保障   |          | 价值实现   |
            +-----------+          +-----------+
                  |                      |
                  +----------+-----------+
                             v
                      +----------+
                      | 职能领域  |
                      | (§1.7)   |
                      | 基础保障  |
                      +----------+
```

**核心洞察**：七个领域不是部门，而是活动集合。一个硬件工程师的活动同时跨研发（原理图设计）、平台（复用性审查）、制造（DFM支持）、管理（TR评审）。

### 1.2 研发领域（R&D）

**定位**: 产品从「概念」到「蓝图」的价值创造核心。

| 子领域 | 核心活动 | 关键产出 |
|:-------|:---------|:---------|
| **系统架构** | 需求分析·方案设计·芯片选型·互联拓扑·DFX审查 | 架构规格书·方案决策记录·Trade-off分析 |
| **硬件设计** | 原理图设计·Layout指导·元器件选型·信号完整性SI·电源完整性PI | 原理图·Layout Guide·BOM·设计审查报告 |
| **结构设计** | 机箱/机柜·导轨/面板·散热器·线缆走线·密封设计 | 3D CAD·2D工程图·结构BOM·DFM报告 |
| **散热设计** | TDP仿真·CFD建模/风道·液冷冷板·歧管设计·测试验证 | 热仿真报告·散热方案·温度测试数据 |
| **PCB/SI设计** | 叠层设计·阻抗控制·高速信号优化·串扰抑制·电源层规划 | Stackup·Layout·SI仿真报告·Design Rule |
| **BMC/固件** | OpenBMC/BMC·BIOS/UEFI·CPLD/FPGA·Redfish接口 | 固件版本·功能特性·兼容矩阵 |
| **测试验证** | 功能测试·兼容测试·压力测试·RDT/老化·认证测试 | 测试报告·Bug追踪·可靠性评估 |
| **NPI工程** | DFM审查·试产跟线·工艺设计·SOP编制·转产评审 | DFM检查表·试产报告·工艺文件 |

**关键特征**: 研发活动是「上游成本锁定者」——设计阶段锁定了70-80%的产品成本、80%的制造质量和90%的上市时间。一个NPI设计阶段的DFM审查漏检，在量产阶段可能需要10-100倍的纠正成本。

### 1.3 制造领域（Manufacturing）

**定位**: 把BOM和图纸变成客户手中的产品——企业的「交付引擎」。

| 知识域 | 核心活动 | 关键指标 |
|:-------|:---------|:---------|
| **生产计划与排程** | MPS(周)/MRP(物料需求)/APS(排程)/ATP(交期承诺) | 计划达成率≥98%·交期准交率 |
| **SMT工艺工程** | 锡膏印刷·回流焊接·波峰焊接·AOI/SPI/X-Ray检测·工艺参数优化 | 直通率(FPY)·CPK≥1.33·DPMO |
| **整机组装** | 主板安装·CPU/GPU安装·散热器装配·线缆连接·液冷管路·面板/导轨 | 装配一次良率·装配工时·误装率 |
| **测试工程** | 烧录·BIT(自检)·FCT(功能测试)·RDT(老化)·YOLT(拷机)·系统级验证 | 测试覆盖率·GRR·测试时间 |
| **质量管理(制造端)** | SPC·FMEA·QC七大手法·8D·停线标准·良率管理 | 直通率·不良率(PPM)·OQC批合格率 |
| **仓储物流** | 入库/出库·FIFO·VMI/JIT·成品包装·发运·逆向退货 | 库存周转率·盘点差异率·发运准时率 |
| **精益改善** | 5S·看板·VSM(价值流)·Kaizen·TPM·SMED | OEE·改善节省金额·浪费消除项 |
| **NPI导入** | EBOM→PBOM→MBOM·试产/跟线·问题闭环·转量产评审 | 试产良率·RTM完整度·转量产周期 |

**制造领域的「铁三角」约束**:

```text
           质量(直通率)
             /\
            /  \
           /    \
          /      \
         /________\
    成本(效率)    时间(交期)
```

- **高端定制**（超节点）：质量优先，直通率 > 99.5%，成本可接受
- **标准产品**（通用服务器）：成本优先，规模效应驱动
- **紧急交付**（CSP紧急扩容）：交期优先，产线预留buffer，溢价收费

### 1.4 供应链领域（Supply Chain）

**定位**: 企业的「血管系统」——保证物料在正确时间以正确数量到达正确位置。

| 活动 | 描述 | 关键输出 |
|:-----|:------|:---------|
| **供应商开发(SER)** | 新供应商寻源·认证审核·QCDST评估·AVL目录 | 供应商认证报告·合格供应商清单 |
| **战略采购** | 关键物料长期协议(LTA)·价格谈判·产能锁定·长周期备料 | LTA合同·价格协议·产能预留确认 |
| **采购执行** | PO下达·跟单催货·到货入库·品质异常处理·对账付款 | PO·到货计划·异常报告 |
| **物料计划(MRP)** | 需求预测·安全库存设置·物料齐套检查·缺料预警·慢动/呆滞管理 | MRP计划·齐套报告·缺料清单 |
| **供应商绩效** | Scorecard评估·QBR(季度业务评审)·淘汰/晋升 | 供应商Scorecard·QBR纪要 |

**AI服务器供应链的特殊性**:

| 特征 | 通用服务器 | AI服务器 | 影响 |
|:-----|:----------|:---------|:-----|
| GPU/CPU/交换芯片 | 标准化 | 寡头垄断(NVIDIA/AMD/Broadcom) | 供应风险集中在3-5家供应商 |
| 长周期部件 | 8-12周 | 16-26周(GPU/HBM Switch) | 需求预测窗口被迫拉长 |
| BOM占比 | CPU 15-20% | GPU 65-75% | 品牌商/ODM利润空间被数学锁定 |
| 供应商锁定 | 多源替代 | NVIDIA 单源(GPU/Network) | 议价能力极弱 |
| 价格波动 | 温和(3-5%/年) | 剧烈(涨价10-30%/季 近年) | 利润波动风险大 |

### 1.5 经营领域（Business Operations）

**定位**: 企业的「价值实现系统」——让产品从成本和投资转化为收入和利润。

| 活动 | 描述 | 主责角色 |
|:-----|:------|:---------|
| **产品定价** | 成本+利润模型 vs 市场比价模型·价格策略·促销/折扣 | 产品线管理 |
| **订单管理** | 客户订单接收·交期承诺(ATP)·订单变更·退换货 | 销售运营(SSO) |
| **渠道管理** | 直销/渠道伙伴·区域渠道布局·渠道激励·渠道培训 | 渠道管理 |
| **合同与商务** | 合同谈判·合规审查·出口管制审查·保密协议 | 法务/商务 |
| **客户关系** | 大客户管理(KAM)·客户满意度·技术支持·售后维保 | 销售/服务 |
| **财务管控** | 收入确认·应收账款AR·回款催收·坏账管理 | 财务 |
| **经营分析** | 收入/成本/利润分析·产品线损益·差异分析·ROI分析 | 财务/Business Ops |

**经营领域的核心矛盾**: 研发要堆料（高BOM成本保证性能）、销售要降价（获取市场份额）、制造要稳定（长交期保证良率）——这些诉求在经营层面必须统一收敛为**产品的利润模型**。

### 1.6 平台领域（Platform）

**定位**: 企业的「资产银行」——将研发项目的一次性投入转化为可复用的平台资产。

平台领域回答的核心问题是：**如何让10个新项目不做10次独立的研发，而是在3个已验证平台上搭积木？**

典型的服务器平台层级：

```text
                     +----------------------+
                     |    整机平台/机型系列   | － 2U4GPU/4U8GPU/8U10GPU
                     |    (Product Platform) |    AI/通用/存储/边缘
                     +----------+-----------+
                                | 积木式组合
           +--------------------+--------------------+
           v                    v                    v
     +-------------+   +--------------+   +--------------+
     |  Hardware    |   |   Software    |   |   Mechanical |
     |  Platform    |   |   Platform    |   |   Platform   |
     +-------------+   +--------------+   +--------------+
     | CPU方案      |   | BMC基线 v2.3 |   | 2U机箱(通用) |
     | PCH方案      |   | BIOS基线 v1.8 |   | 4U机箱(通用) |
     | Power方案    |   | Redfish SDK   |   | 导轨(通用)   |
     | BMC方案      |   | 诊断工具集    |   | 面板(系列)   |
     | 时钟方案     |   | OS兼容列表    |   | 散热器(通用) |
     | PMBus/VR方案  |   | CI/CD基线     |   | 液冷方案(C)  |
     +-------------+   +--------------+   +--------------+
```

**行业典型平台复用率目标**:

- 同代平台内：硬件 70%+ · 软件 90%+ · 结构 60%+
- 跨代传承：硬件 30-40% · 软件 60%+ · 结构 50%+

### 1.7 职能领域（Functions）

**定位**: 企业的「保障系统」——让其他领域有资金、有人才、有物料、有合规保障。

| 职能 | 核心职责 | 与制造运营的交汇点 |
|:-----|:---------|:------------------|
| **财务管理** | 核算/预算/成本分析/资金/税务 | BOM成本核算、制费分摊、投资分析 |
| **人力资源** | 招聘/培训/绩效/薪酬/组织发展 | 制造人员排班、技能培训、计件薪酬 |
| **法务与合规** | 合同/知识产权/出口管制/数据隐私 | 出口管制审查(RoHS/REACH)、销售合同审核 |
| **采购与供应商管理** | 寻源/认证/谈判/跟单/绩效 | 物料供应商准入、价格谈判、交付保障 |
| **IT服务管理** | ITIL/服务台/CMDB/变更管理 | MES/ERP/PLM/SCM系统运维 |
| **基建/厂务** | 厂房/洁净车间/动力/暖通/消防 | 产线扩建规划、动力保障、环境监控 |

### 1.8 管理领域（Management）

**定位**: 企业的「神经系统」——让所有领域按同一个方向、同一个节奏运作。

| 管理体系 | 核心机制 | 与制造运营的交汇点 |
|:---------|:---------|:------------------|
| **IPD流程(TRI→TR6)** | 14个领域协同·5-6个评审Gate·DCP决策 | TR4 DFM审查·TR5试产·TR6转量产 |
| **项目管理(PJM)** | WBS/甘特图/风险管理/挣值 | NPI项目计划·交期跟踪·Risk管理 |
| **绩效管理** | KPI/OKR设计·目标分解·评估 | 制造KPI:OEE·直通率·交期达成率 |
| **经营分析** | 收入/成本/利润分析·差异分析 | 月度经营会:制费分析·良率影响·降本达成 |
| **质量管理体系** | ISO9001/TS16949·内审/外审·CAPA | 制造质量体系·过程审核·客户投诉8D |

### 1.9 领域间冲突与协同机制

七个领域的目标天然存在冲突：

| 冲突对 | 研发说 | 制造说 | 经营说 | 协调机制 |
|:-------|:------|:------|:------|:---------|
| 研发 vs 制造 | 「这个设计性能最优」 | 「这个设计没法生产(DFM不通过)」 | — | DFM审查·TR4制造预布局评审 |
| 制造 vs 经营 | — | 「给我稳定的订单批量」 | 「客户要急单紧急交付」 | 产能预留协议·急单溢价流程 |
| 研发 vs 供应链 | 「用最好的料(A供应商独家)」 | — | 「成本太高降本30%」 | AVL目录·替代料认证·目标成本管理 |
| 平台 vs 研发 | 「复用上一代平台」 | — | — | 架构评审·平台决策·偏差审批 |

这些冲突不是「管理有问题」，而是**业务本质决定的张力**——好的管理体系不是消除冲突，而是建立高效的冲突裁决机制。

### 2.2 订单触发阶段

**核心活动**: 接收客户订单 → 交期确认(ATP) → 订单录入ERP

**交期承诺(ATP)的三层判定**:

| 层次 | 判定逻辑 | 支撑数据 | 响应时间 |
|:-----|:---------|:---------|:--------:|
| **L1 成品库存** | 成品库有货？ | ERP即时库存 | 秒级 |
| **L2 在制/在途** | 已排产或在途？ | MES在制信息 + 供应商在途 | 小时级 |
| **L3 物料+产能** | 物料齐套+产能可用？ | MRP齐套率 + 产能模型 | 天级 |

**典型订单类型**:

| 类型 | 特征 | ATP策略 | 交期 |
|:-----|:------|:--------|:----:|
| **批量订单(BTO)** | 客户批量下单，按库存生产(MTS) | 成品库存直接满足 | T+1~5天 |
| **配置订单(CTO)** | 客户选配，按订单配置(Assembly to Order) | 半成品+配置组装 | T+5~15天 |
| **定制订单(ETO)** | 客户定制硬件/固件，按订单工程(Engineer to Order) | NPI流程+定制采购 | T+30~90天 |
| **框架订单** | 年度框架，分批释放交期 | 产能预留+长周期备料 | 按释放指令 |

**AI服务器的特殊订单形态**: CSP通常采用**框架订单+滚动交期释放**模式——年初锁定量价，按月度/季度释放实际交期。这对制造端的产能柔性和物料弹性提出极高要求。

### 2.3 计划与备料阶段

**核心活动**: MPS排产 → MRP运行 → 物料齐套检查 → 采购下达 → 到货检验入库

```text
ERP销售订单
    |
    v
+------------------+     +------------------+
|  MPS主生产计划     |----->|  粗产能评估       |
|  (周计划排程)      |     |  (瓶颈工序产能)   |
+------+-----------+     +------------------+
       |
       v
+------------------+     +------------------+
|  MRP物料需求计划   |----->|  物料齐套检查      |
|  (BOM展开+库存冲销) |     |  (定量/按期)      |
+------+-----------+     +--------+---------+
       |                          |
       v                          v
+------------------+     +------------------+
|  采购订单下达      |     |  自购物料到库      |
|  (PO->供应商确认)   |     |  (IQC检验->入库)   |
+------------------+     +------------------+

       +----------+---------------+

          |  (可开始生产)     |
```

**齐套检查的本质**：一个产品的BOM可能有 500-2000 个料号。只要缺1颗料，整机无法上线生产。这是「短板效应」——100%的物料齐套率是开始生产的前提条件。

**AI服务器特殊挑战**：

- **超节点BOM料号数**: 3000-8000+/柜（vs 传统服务器 300-600/台）
- **GPU/HBM/交换芯片**: 长周期(16-26周) + 配额分配(非按需采购)
- **液冷部件**: 定制化程度高，标准化率低，备料难度大

**服务器级SMT与消费板级的差异**:

| 维度 | 消费级 | 服务器级 |

### 2.7 老化与可靠性测试阶段

**核心活动**: 通过长时间运行(高温/高负载)暴露早期失效

**老化(Burn-in)的工程原理** — 「浴盆曲线」理论：

```text
失效率 λ(t)
    ^
    |       早期失效区        稳态使用寿命区         磨损老化区
    |      (制造缺陷暴露)     (随机失效)           (寿命终止)
    |     ▔▔▔▔▔▔▔▔▔▔
    |    /                  \                      /
    |   /                    \                    /
    |  /                      \                  /
    | /                        \________________/
    |/
    +----------------------------------------> 时间 t
                     老化窗口
               (老化将早期失效
                在出厂前暴露)
```

**老化的阶段与条件**:

| 老化类型 | 温度 | 时长 | 负载 | 目的 |
|:---------|:----|:-----|:-----|:-----|
| **常温老化(RDT)** | 25-35°C | 4-8h | 中低负载(BIT循环) | 基础功能稳定性 |
| **高温老化(HTO)** | 45-55°C | 12-48h | 满载 | 加速缺陷暴露(热应力) |
| **全负载拷机(YOLT)** | 40-50°C | 24-72h | GPU/CPU双满载 | GPU/NVLink稳定性 |
| **温循(TCT)** | -40~85°C | 20-50cycle | 待机 | 焊点/连接器可靠性 |

**超节点老化面临的问题**:

- 单台老化功耗100-200kW(8节点满载) → 老化房供电/散热能力是瓶颈
- 72小时全负载拷机的电费成本极高 → 测试时间长度的经济平衡
- 超节点级别的组合爆炸使测试全覆盖几乎不可能 → 需要抽样策略+设计保证

### 2.8 成品检验与包装阶段

**核心活动**: 出厂检验(OQC) → 包装 → 备货 → 出运

**OQC检查项**:

| 检查维度 | 检查内容 | 样本 | 允收标准(AQL) |
|:---------|:---------|:----|:-------------|
| **外观检验** | 划痕·毛刺·色差·丝印·标签 | 全检 | 致命缺陷0 · 主缺陷≤0.65% |
| **功能复测** | 通电·POST·网络·温控·LED | 全检 | 100%合格 |
| **包装检查** | 包材·缓冲物·标识·附件 | 抽检 | ≤1.0% |

## §3 EVT阶段发货的挑战与应对

### 3.1 为什么EVT阶段就要求发货

工程验证测试(EVT)是产品从「原型」到「量产」的早期阶段——按经典IPD流程，EVT(TR4)阶段的产品还存在已知的设计风险和功能不完整项。传统上EVT只做内部验证，不发客户。

**迫使EVT发货的市场力量**:

```text
NVIDIA GPU 迭代节奏: 18-24个月一代
    v
CSP AI建设窗口: 12-18个月部署一个超节点集群
    v
服务器厂商竞争: 谁先交付谁锁定客户
    v
结果: EVT阶段即发货成为"新常态"
```

具体驱动因素：

1. **GPU供应稀缺性**：GPU配额有限，拿到即生产，不等完全验证
2. **客户建设窗口**：CSP数据中心交付窗口固定(如Q4投产)，延迟即错过整个建设周期
3. **竞争压力**：竞争对手若能在EVT发货，决策者面临「不做就被抢单」的压力
4. **NVIDIA的推进**：NVIDIA参考设计覆盖率越来越高，OEM的设计工作量减少，EVT风险降低

### 3.2 EVT发货的核心风险

| 风险类别 | 具体表现 | 概率 | 影响严重度 |
|:---------|:---------|:----:|:----------:|
| **硬件缺陷** | PCB设计错误·信号不完整·电源不稳定 | 中(30-40%) | 🔴 致命(现场换板) |
| **固件缺陷** | BMC/BIOS/CPLD Bug·配置错误·兼容问题 | 高(60-80%) | 🟡 中(OTA修复) |
| **散热问题** | 风道不达标·液冷泄漏·热点超温 | 中(20-30%) | 🔴 致命(停机) |
| **互联问题** | NVLink不稳定·RDMA丢包·同步失败 | 高(40-60%) | 🔴 致命(集群不可用) |
| **制造质量** | DFM问题·装配良率低·ESD损伤 | 中(20-30%) | 🟡 中(维修/更换) |
| **认证缺失** | 安规/EMC未完成·出口管制审查中 | 低(10-15%) | 🔴 致命(扣关/退货) |
| **可维护性** | 现场可更换性差·诊断手段缺失 | 低(10%) | 🟡 中(运维效率低) |

**风险评估第一性原则**: EVT阶段发货不是「能不能做」的问题，是「什么风险可以接受、什么风险不能接受」的问题。固件Bug可以通过OTA修复 → 可接受。但液冷管路设计缺陷导致泄漏 → 不可接受。

### 3.3 EVT发货的管控策略

**策略一：分段验收**

将EVT发货按风险等级分为三类：

```text
P0 — 致命风险(不可发货)
   +-- 硬件设计缺陷(改板)
   +-- 安全隐患(泄漏/短路/火灾)
   +-- 互联拓扑兼容性(不可修复)

P1 — 高风险(有限发货+限制使用场景)
   +-- 散热余量不足(限制负载)
   +-- 少数接口兼容问题(白名单)
   +-- 固件稳定性(标注已知问题)

P2 — 中等风险(正常发货+短期修复承诺)
   +-- 性能未达预期(后续优化)
   +-- 管理接口不完整(OTA补全)
   +-- 认证进行中(提供在办证明)
```

**策略二：风险清单(Risk Register)**

每台EVT发货的超节点附一份风险清单：

```json
{
  "unit_serial": "SN20260730-0001",
  "evt_delivery_version": "v0.9.1",
  "known_risks": [
    {
      "id": "RISK-001",
      "description": "GPU 0-3在重负载下温度比目标高3-5°C",
      "severity": "中",
      "mitigation": "建议前端进风温度≤25°C·限制GPU功耗至350W",
      "fix_version": "v1.0(hardware ECO-001, 预计DVT阶段修复)"
    },
    {
      "id": "RISK-002",
      "description": "BMC Redfish EventService接口在特定条件下返回500",
      "severity": "低",
      "mitigation": "不使用EventService即可回避·不影响监控系统",
      "fix_version": "v0.9.3 固件更新(已安排)"
    }
  ],
  "customer_acknowledgement": "已确认并签字",
  "valid_until": "2026-09-30"
}
```

**策略三：软硬件分离交付**

```text
EVT发货 = 硬件发货 + 软件补丁通道

硬件(物理发货):
  +-- PCB+组件: v1.0(锁定不变)
  +-- 结构件/散热: v1.0(锁定)
  +-- 特殊: 预留ECO改板空间

软件(OTA持续更新):
  +-- BMC 固件: v0.9.2 -> v0.9.3 -> v1.0(每周更新)
  +-- BIOS: v1.0.1 -> v1.1.0(两周更新)
  +-- CPLD: r02 -> r03 -> r04(随需更新)
  +-- 诊断工具: 持续迭代
```

**原则**: 硬件如果发现不可逆转的问题(改板)，EVT不能发货。软件问题不影响发货，走OTA更新通道。

**策略四：现场驻场工程(Escalation)**

EVT发货的产品必须配备: 现场FAE工程师(at least 1人/项目) + 远程研发支持热线 + 备件库位(在客户数据中心附近预存关键备件)。核心原则——**EVT发货不是"卖出去就完了"，是"客户陪着你做现场验证"**。

### 3.4 EVT发货的合同与责任界定

| 条款 | 传统量产合同 | EVT发货合同 | 差异说明 |
|:-----|:-----------|:------------|:---------|
| **验收标准** | 按规格书全项验收 | 按风险清单签字确认验收 | EVT接受已知缺陷 |
| **保修承诺** | 标准保修(3年/5年) | 缩短保修+加速响应(如7×24×4h) | 质量风险对等 |
| **罚款条款** | 交期/性能不达标有罚金 | 免除罚金或设上限 | 承认风险共享 |
| **更新承诺** | 固件版本锁定 | 承诺OTA更新到DVT版本 | 持续修复义务 |
| **退货权利** | 7-30天无理由退换 | DVT阶段前可退货(若发现P0问题) | 客户有退出机制 |

**关键原则**: EVT发货不是标准的买卖关系，是**研发合作延伸**——客户获得更早的算力、厂商获得现场验证数据、双方分担风险。

## §4 超节点/整机柜制造的直通率挑战

### 4.1 超节点制造的复杂度量级

超节点制造的复杂度不是线性的——它与节点数、互联度、子系统数呈**组合爆炸关系**。

**复杂度对比**:

| 维度 | 单台服务器(2U) | 整机柜(8节点) | 超节点(NVL72) |
|:-----|:--------------|:-------------|:--------------|
| 构成部件数 | ~500-800 | ~5,000-8,000 | ~15,000-25,000 |
| 焊点数(PCBA) | ~30,000-50,000 | ~400,000-600,000 | ~1,200,000-2,000,000 |
| 线缆数量 | ~20-50根 | ~200-500根 | ~800-2,000根 |
| 液冷接头数 | 0 | ~20-40个 | ~300-600个 |
| 固件版本一致性检查 | 1节点×3固件 | 8×3=24 | 72×3=216 |
| GPU间互联验证 | 8个GPU×N/2对 | 8节点间~28对 | 72GPU间~2556对 |
| 单柜功耗 | ~1-3kW | ~15-30kW | ~100-200kW |
| 总重量 | ~30-60kg | ~300-600kg | ~800-1,500kg |

**关键洞察**: 超节点的一个机柜包含约15,000-25,000个独立可失效的组件。每个组件的可靠性的乘积决定了直通率的上限。

### 4.2 直通率的数学约束

直通率(First Pass Yield, FPY) = 每个工序合格率的乘积。

**数学公式**:

```text
FPY = Πᵢⁿ (1 - pᵢ)

其中:
  n = 工序数
  pᵢ = 第i道工序的缺陷率
```

**实际计算**:

以超节点制造为例，简化但不失本质：

| 工序链 | 工序 | 单工序良率 | 累计良率 |
|:-------|:-----|:----------:|:--------:|
| 第1段 | SMT贴片(×8块大板) | 99.5%^(8) = 96.1% | 96.1% |
| 第2段 | 固件烧录(×8节点) | 99.0%^(8) = 92.3% | 88.7% |
| 第3段 | 整机组装(×8节点) | 98.0%^(8) = 85.0% | 75.4% |
| 第4段 | 液冷装配+密封测试 | 97.0% | 73.1% |
| 第5段 | 老化测试(72h) | 95.0% (老化失效率5%) | 69.5% |
| 第6段 | 全互联测试(2556对) | 99.9%^(2556) ≈ 7.7% | **5.3%** |

**致命结论**: 如果每对GPU互联的连通性测试良率为99.9%，72颗GPU全部互联通过的概率仅约7.7%——直通率被互联测试这一道工序「一刀切」到个位数。

**超节点直通率的三个数学障碍**:

1. **串联乘法极限**: 工序越多、每工序合格率不能100%，最终直通率趋于0
2. **组合爆炸测试**: 全互联测试的对数随节点数呈O(N²)增长，即使单对良率99.99%，N=72时也只剩97%
3. **修复再测试成本**: 单对互联故障修复后需要全互联重测，而不是只测坏的那一对——因为修复操作可能影响周围连接

### 4.3 超节点制造的三重失效模式

**模式一：硬件级失效（需要换料/重工）**

| 失效类型 | 占比(估计) | 修复代价 | 影响直通率的方式 |
|:---------|:----------:|:--------:|:----------------|
| GPU不良 | ~1-3% | 换GPU+重测全互联 | 降低首次通过率 |
| 主板PCBA缺陷 | ~0.5-1% | 换板+重装+全测 | 需拆装/重装 |
| 液冷接头泄漏 | ~0.5-2% | 更换接头+密封测试+24h保压 | 增加工时 |
| 电源模组不良 | ~0.3-0.5% | 换PSU+验证 | 相对简单 |
| 线缆端接不良 | ~0.5-2% | 重新端接/换线+特定互联重测 | 需定位具体连接 |

**模式二：固件级失效（可OTA修复，不需要硬件更换）**

| 失效类型 | 占比(估计) | 修复方式 | 对直通率的影响 |
|:---------|:----------:|:---------|:--------------|
| BMC初始化失败 | ~2-5% | 重新烧录/上电 | 增加重试次数 |
| BIOS配置错误 | ~1-3% | 重新配置 | 不影响最终良率 |
| GPU固件版本不匹配 | ~3-5% | 统一刷写 | 影响首次通过率 |
| 网络配置不一致 | ~5-8% | 自动配置修复 | 影响首次通过率 |

**模式三：测试级误判（伪失效）**

| 失效类型 | 占比(估计) | 根因 | 处理方式 |
|:---------|:----------:|:-----|:---------|
| 测试脚本Bug | ~5-10% | 测试覆盖度不足/边界条件未覆盖 | 修复脚本+重测 |
| 测试环境问题 | ~3-5% | 温度偏差·供电不稳·测试治具接触不良 | 环境校准后重测 |
| 测试顺序依赖 | ~2-3% | 测试A通过但测试B失败→A的条件改变了 | 调整测试顺序 |
| 边界条件误报 | ~1-2% | 参数在规格边缘但仍在限内 | 放宽阈值+人工判断 |

**关键发现**: 固件级失效+测试级误判占总失效的**60-70%**，但这两类都是可修复/可规避的。真正的硬件级失效只占30-40%。

### 4.4 直通率提升策略

**策略一：模块化自测（解耦连接）**

将互联测试从「全量串联」改为「模块自测+少量跨模块验证」：

```text
传统方法:
  [节点1] - [节点2] - [节点3] - ... - [节点8]
    全部互联必须一次通过 -> 直通率乘积效应

改进方法:
  [节点1] - [自测通过] - [交换背板]
  [节点2] - [自测通过] - [交换背板]
  [节点3] - [自测通过] - [交换背板]
  ...
  [节点8] - [自测通过] - [交换背板]

  各节点先自测通过 -> 插入背板 -> 只测试与背板的连接
  背板在出厂时已完成自身测试
  -> 将8个节点的串联测试变为8个并行测试+1个交叉验证
```

**效果**: 将O(N²)的互联测试降为O(N)的模块化测试，直通率从5.3%提升到~60-70%。

**策略二：降级模式（允许部分失效）**

定义明确的降级运行模式：

| 降级级别 | 定义 | 客户接受度 | 后续修复 |
|:--------:|:-----|:----------:|:---------|
| **无降级** | 全部规格达标 | ✅ 正常交付 | — |
| **L1 降级** | 1-2颗GPU不可用/FW降速运行 | ⚠️ 需确认 | 现场更换 |
| **L2 降级** | 部分NVLink降速(非满规格) | ⚠️ 需确认 | 计划性维修 |
| **L3 降级** | 液冷分配单元故障/以备用模式运行 | 🚩 紧急 | 立即维修 |

**策略三：热备份与冗余设计**

- **GPU NVLink降级**: NVL72中即使1颗GPU的NVLink链接全部断裂，其他71颗仍可正常工作(在软件配置下)
- **PSU N+1冗余**: 厂商提供额外1-2个PSU，即使1个故障仍不影响运行
- **液冷CDU主备**: 配置主备CDU(冷却分配单元)，主单元故障可切换

**策略四：并行容器化测试（缩小时钟）**

将72h老化分拆为：16h基线老化(100%产品) + 8h全负载(全部) + 剩余时间差异化(按产品批) 。对直通率影响：缩短约50%的总测试时间，同时降低不必要通过测试标准。

### 4.5 实践案例：NVL72的超节点制造策略

NVIDIA GB200 NVL72 是目前量产的最复杂超节点。其制造策略反映了行业前沿做法：

| 措施 | 具体做法 | 效果 |
|:-----|:---------|:-----|
| **Cable Cart预装配** | 所有线缆在独立工站预裁/预标/预组装，线缆组件作为一个独立子装配体 | 减少机柜内布线错误70%+ |
| **GPU Tray模块化** | 每2颗GPU+NVSwitch组成独立Tray，单独组装/测试后插入机柜 | 测试并行度高 |
| **液冷系统预填充** | 在独立工站预填充冷却液+预密封测试 | 减少机柜内液冷泄漏风险 |
| **光学检测自动化** | AOI+AI视觉检测BGA焊点/连接器安装 | 检测速度提升10× |
| **数字孪生辅助调试** | 在调试前通过Digital Twin预演连接拓扑 | 减少调试时间50%+ |
| **运输专用吊具** | 定制吊装夹具+FIFO作业指导 | 减少运损40%+ |

### 5.2 价格波动的传导机制

**服务器物料价格波动的三层传导**:

```text
Layer 1: 上游晶圆/原材料
  +-- 硅晶圆(12英寸): 季度波动 0-5%
  +-- HBM(DRAM):  季度波动 -10%~+30% (波动剧烈)
  +-- 铜/金(线缆/连接器):  全球商品价格 年度波动 ±15%
  +-- PCB基板(CCL/玻纤布): 季度波动 ±5-10%
  +-- 被动件(MLCC/电阻):  供应波动 ±3-5%

Layer 2: 芯片/组件级
  +-- GPU: 年度锁价+产能配额 (实际成本由NVIDIA决定)
  +-- HBM: 绑定GPU(独立计价) 季度涨价10-15%(2025-2026)
  +-- CPU(Intel/AMD): 年度调价 -2%~+5%
  +-- NAND(SSD):  季度波动 -10%~+20%
  +-- 电源/散热:  原材料驱动, 年度波动 ±5%

Layer 3: 系统集成
  +-- 服务器整机BOM: 综合波动 季±5-10%
  +-- 超节点BOM: GPU主导, 价格年变化可达10-20%
```

## §6 小批量制造与多物料管理方案

### 6.1 小批量制造的本质挑战

小批量制造不是「量少了只是换个方式做」，而是**根本不同的制造逻辑**：

| 维度 | 大批量制造 | 小批量制造 | 根本矛盾 |
|:-----|:----------|:-----------|:---------|
| **经济模型** | 规模效应分摊固定成本 | 固定成本被少量产品分摊 | 单位制造成本上升30-50% |
| **换线频次** | 周/月换一次 | 日/班次换线多次 | 换线损失时间占比从1%→10-20% |
| **良率学习曲线** | 充分时间学习+优化 | 等不到学习曲线收敛 | 良率长期在低水平 |
| **供应商意愿** | 大订单争抢 | 小订单优先级低 | 物料供应保障困难 |
| **测试覆盖率** | 有足够样本做GRR | 需要少样本高置信度 | 统计方法不适用 |
| **自动化投资** | 可摊销 | 难以回收 | 自动化&装备投入受限 |

**小批量制造的「盈亏临界点」**:

```text
总成本 = 固定成本(设备/模具/工程) + 可变成本(物料/人工)×数量

大批量: 固定成本被分摊到 ~10,000台 -> 单位固定成本 ¥10-50
小批量: 固定成本被分摊到 ~100台   -> 单位固定成本 ¥1,000-5,000

-> 同一产品的单位制造成本在小批量时可能是大批量的5-10倍
```

**超节点的特殊处境**: 超节点目前是「大批量中的小批量」——虽然单台BOM高达数百万美元，但一年全球需求仅数万柜。对供应链而言，这个量级仍属于小批量。

### 6.2 柔性产线设计原则

**原则一：模块化工站**

```text
传统流水线:  A -> B -> C -> D -> E (串联, 单产品)
柔性产线:
      A ---> B1 ---> C1 ---> D ---> E
         ↘   B2 ---> C2 --↗
         ↘   B3 ---> C3 --↗

A=通用预处理  B=不同配置组装站  C=不同测试站
D=通用检验  E=通用包装
```

- A/D/E 是固定工作站(不换线)
- B1-B3/C1-C3 是并行可切换的配置站(按订单切换)
- 实现**不停线换配置**

**原则二：快速换型(SMED)**

| 换线步骤 | 传统做法 | 改进做法 | 时间节省 |
|:---------|:---------|:---------|:--------:|
| 锡膏钢网更换 | 拆下旧的→清洁→安装新的→校准 | 双台车式(一台在用/一台预热) | 15min→3min |
| 贴片机Feeder更换 | 逐个更换 | 整体供料台车+离线备料 | 20min→5min |
| 测试程序切换 | 现场调试 | 预存配置+一键加载 | 30min→2min |
| 工装治具更换 | 螺栓固定式 | 快换式(气动/磁吸) | 10min→1min |
| 作业指导书切换 | 重新打印 | 电子看板(屏幕自动切换) | 5min→0min |

**原则三：通用工装覆盖**

- 所有产品共用同一套SMT治具(通过可调节定位销适配不同板尺寸)
- 整机组装采用通用导轨+快速定位设计
- 测试治具采用模块化Pogo Pin阵列，通过软件定义测试点

### 6.3 多供应商物料管理体系

**为什么要多供应商?**

| 单供应商风险 | 多供应商收益 |
|:------------|:------------|
| 供应中断 | 备选供应源保障 |
| 价格垄断 | 竞争性定价 |
| 质量事故影响大 | 分摊质量风险 |
| 技术创新依赖 | 多源技术跟进 |
| 灾难/地缘政治 | 地理分散风险 |

**多供应商管理的关键挑战**:

1. **替代料认证成本**：每颗替代料需要经过完整的认证流程 → 从选型→测试→验证→发布，平均2-4个月
2. **BOM膨胀**：每个料号对应多个供应商的替代料号 → BOM管理复杂度指数级上升
3. **配置器复杂性**：替代料组合在产品配置器中形成组合爆炸
4. **一致性维护**：各供应商的固件/驱动版本需要对齐

**多供应商管理的制度化框架**:

```text
+---------------------------------------------------------+
|                    AVL(Approved Vendor List)                   |
|  每个料号下1个Primary(主供) + 1-2个Secondary(备选)             |
+---------------------------------------------------------+
|                                                         |
|  供应商分级:                                              |
|  +----------+  +----------+  +----------+  +----------+ |
|  | Level 1  |  | Level 2  |  | Level 3  |  | Level 4  | |
|  | 战略级    |  | 优选级    |  | 候选级    |  | 观察级    | |
|  | 长期合作  |  | 常规采购  |  | 正在认证  |  | 试用/监控 | |
|  +----------+  +----------+  +----------+  +----------+ |
|                                                         |
|  认证流程 (Primary->Secondary切换时间):                    |
|  GPU: 4-6月 (NVIDIA->AMD->无)                              |
|  CPU: 2-3月 (Intel↔AMD)                                 |
|  SSD: 1-2月 (三星->SK->美光)                              |
|  PSU: 1-2月 (台达->光宝->群光电能)                         |
|  液冷组件: 2-3月 (认证+接口适配)                          |
|  被动件: 2-4周 (MLCC/电阻/电容)                          |
+---------------------------------------------------------+
```

**替代料切换的时间窗口与触发条件**:

| 切换级别 | 触发条件 | 切换时间 | 客户通知 | BOM调整 |
|:---------|:---------|:--------|:---------|:--------|
| **紧急切换** | 供应商断供/质量灾难 | 24h-7天 | 紧急通知+确认 | ECO紧急变更 |
| **计划切换** | 成本优化/性能提升 | 30-60天 | 正常通知 | ECO正常变更 |
| **储备切换** | 长期风险缓释(认证备用) | — | 无需通知 | 不切换(已认证但不用) |

### 6.4 配置器与BOM管理体系

当同整机的可选物料>10,000种时，配置器(Configurator)是管理组合爆炸的核心工具。

**配置器上库6步法**:

```text
Step 1: 需求参数化
  将产品规格拆分为可配置参数
  +-- CPU类型: Intel Xeon 6 / AMD EPYC 9005
  +-- GPU数量: 0/2/4/8颗
  +-- 内存: 16/32/64/128/256/512GB
  +-- 存储: HDD×N / SSD×N / 混合
  +-- 网络: 25/50/100/200/400GbE
  +-- 散热: 风冷(标准)/液冷(可选)

Step 2: 规则引擎建立
  定义参数之间的约束关系(哪些可以/不可以组合)
  +-- "GPU=8 -> 散热=液冷" (8GPU必须液冷)
  +-- "CPU=Xeon 6 -> 内存=DDR5 6400" (绑定)
  +-- "网络=400GbE -> NIC=ConnectX-8" (绑定)

Step 3: BOM自动生成
  输入配置参数 -> 系统自动生成唯一MBOM
  Steps: 参数 -> 规则引擎 -> 匹配物料 -> 组合BOM -> 校验完整性

Step 4: 价格实时计算
  BOM成本 + 制费 + 利润 -> 即时报价
  支持批量折扣·客户合同价·物料价格波动更新

Step 5: 测试验证
  生成的配置通过兼容性规则校验(物理/电气/固件兼容性)
  不通过 -> 回退修改规则

Step 6: 上线发布
  配置器发布 -> 销售人员可自助配置报价
  后端ERP/MES自动接收配置订单
```

**BOM版本管理体系**:

```text
EBOM(工程BOM): 研发角度 -> 功能单元
    |  ECO工程变更
    v
PBOM(工艺BOM): 工艺角度 -> 装配单元
    |  工艺拆分
    v
MBOM(制造BOM): 制造角度 -> 采购/装配子件
    |  工单释放
    v
SBOM(服务BOM): 售后角度 -> 可替换单元(FRU)
```

| **质量↔客户** | EVT发货责任不清 | 实施「风险清单客户签字」+ 现场FAE驻场制度 |

## §8 变更管理体系（Engineering Change）

> **定位**: 从「设计锁定」到「量产维护」之间的连接器——让产品在生命周期内持续优化而不失控。

### 8.1 变更的核心命题

服务器产品的工程变更不是「改个设计这么简单」——每笔变更的代价包括：

| 变更代价维度 | 量化评估 | 典型值 |
|:------------|:---------|:------|
| **物料报废** | 旧BOM物料呆滞/废弃 | ¥10万~500万/次（视变更范围） |
| **产线切换** | 换线损失工时+重培训 | 4-24h停线 |
| **验证成本** | 重新做功能/兼容/可靠性测试 | ¥5-50万/次 |
| **认证更新** | 安规/EMC/能效重新认证 | ¥10-50万+认证周期2-4月 |
| **现场升级** | 已发货产品的召回/现场升级 | 不定（最严重） |

**工程变更管理的核心目标**：在「改的收益」和「改的成本」之间找到最优平衡——不抑制必要的改善，但阻止无谓的反复。

### 8.2 ECN/ECO 的分类与流程

**按变更影响范围分类**:

| 类别 | 定义 | 审批层级 | 典型周期 | 示例 |
|:-----|:-----|:---------|:--------|:-----|
| **Class-I (颠覆性)** | 影响形式/功能/接口/安全 | 产品线+质量+客户确认 | 4-12周 | CPU平台切换、散热方案变更 |
| **Class-II (重要)** | 影响性能/兼容性/互换性 | 研发+质量+供应链会签 | 2-6周 | 替代料认证、固件版本升级 |
| **Class-III (一般)** | 生产便利性/成本优化/不影响功能 | 工程部门审签 | 1-3周 | 物料品牌替换(同规格)、包装优化 |
| **Class-IV (紧急)** | 安全/质量问题需立即停线 | 紧急审批通道 | 24-72h | 发现批次性缺陷、供应商质量事故 |

**标准 ECN(工程变更通知) 流程**:

```text
变更需求提出(研发/制造/供应商/客户)
    |
    v
+------------------------------+
|  Step 1: 变更影响评估          |
|  - 功能/性能/接口影响          |
|  - BOM/成本/交期影响           |
|  - 认证/合规影响                |
|  - 现场已发货产品影响            |
|  - 客户配置兼容性               |
+----------+-------------------+
           |
           v
+------------------------------+
|  Step 2: 变更分类与审批         |
|  Class-I -> 产品线负责人审批     |
|  Class-II -> 跨部门会签          |
|  Class-III -> 工程审批           |
|  Class-IV -> 紧急通道(先停线)    |
+----------+-------------------+
           |
           v
+------------------------------+
|  Step 3: 变更验证               |
|  - 工程验证(实验室)             |
|  - DFM审查(制造可行性)          |
|  - 小批试产(验证制造良率)       |
|  - 客户确认(如涉及客户配置)      |
+----------+-------------------+
           |
           v
+------------------------------+
|  Step 4: 变更实施               |
|  - BOM更新                     |
|  - 库存处理(旧料消耗/报废/退货)  |
|  - 产线切换(临时/永久)          |
|  - 已发货产品处理(升级/召回/知情)|
+----------+-------------------+
           |
           v
+------------------------------+
|  Step 5: 变更关闭               |
|  - 验证变更效果(良率/成本/性能)  |
|  - 文档归档(ECN编号+关联BOM版本) |
|  - 经验反馈(FMEA更新)           |
+------------------------------+
```

### 8.3 变更多发的深层原因与管控难点

| 原因 | 表现 | 根因 | 应对策略 |
|:-----|:-----|:-----|:---------|
| **设计未冻结就转产** | TR5后还在改电路 | 时间压力导致提前转产 | 强制 TR5 Gate 检查清单 |
| **规格定义不完整** | 产线发现装配干涉 | 前期DFM审查不充分 | 强化TR4 DFM评审(含生产方) |
| **来料变更未通知** | 替代料切换导致兼容问题 | 供应商管理体系不完善 | 供应商变更必须提前通报(AIAG PPAP) |
| **客户需求变更多** | 配置器BOM频繁调整 | 需求管理不到位 | 需求冻结窗口+变更费用 |
| **成本压力驱动变更** | 降本变更引入新风险 | 降本指标与质量平衡失控 | 降本变更必须附带风险评估 |

**变更管理的核心纪律**: **「做对一次比改对十次便宜」**——设计阶段的质量成本占整个产品生命周期成本的70%以上。每在研发阶段花1块钱发现并解决的设计缺陷，对应的返工成本大约是：实验室阶段 ¥1 → 试产阶段 ¥10 → 量产阶段 ¥100 → 客户现场 ¥1,000。

### 8.4 BOM 版本与基线管理

BOM 变更的核心难题是**版本管理**——同一产品在不同时间点有不同的 BOM 版本：

```text
BOM 版本树示例:

                    v1.0 (初始发布)
                    |
              +-----+-----+
              |            |
            v1.1        v1.2
        (ECN-001)    (ECN-002)
        换料A->B      加测温度
              |            |
        +-----+--+     +--+-----+
        |        |     |        |
      v1.1.1  v1.1.2  v1.2.1  v1.2.2(当前)
     (ECN-003)(ECN-004)(ECN-005)(ECN-006)
      产地变更  包装优化  降本备选  ROHC合规
```

**关键实践**:

- **ECN 唯一编号**: 每笔变更对应独立编号，关联所有受影响的 BOM/图纸/文档
- **生效点控制**: 必须明确变更的生效点(从哪批次/哪台SN开始)，防止新旧错混
- **双重追溯**: 从产品SN能回溯到BOM版本，从BOM版本能查到所有ECN历史
- **变更冻结窗口**: 量产开始后设定冻结窗口(如3个月内不引入非必要变更)，给制造端喘息

### 8.5 变更管控的数字化工具

| 工具类型 | 代表系统 | 功能 | 与制造的关系 |
|:---------|:---------|:-----|:------------|
| **PLM** | Windchill/Teamcenter/3DEXPERIENCE | ECN全生命周期·BOM版本·关联文档 | 为MES/ERP提供变更后的BOM基线和ECN单据 |
| **MES** | 自建/定制 | 变更生效点管理·新旧料切换控制 | 精确控制变更落在哪台产品生效 |
| **ERP** | SAP/Oracle | 成本核算·库存报废处理 | 变更对成本和库存的财务影响 |
| **QMS** | 自建/定制 | 变更的验证结果和质量影响 | 变更后的质量监控反馈闭环 |
| **配置器** | 自建 | 客户可配置参数变更管理 | 客户配置不因变更而失效 |

## §9 运营体系的运作流程定义

> **定位**: 运营不是「接单→生产→发货」的线性流水——而是一个自适应的闭环系统，由战略→计划→执行→检查→改进的系列流程组成。

### 9.1 运营体系的层次模型

运营体系的运作流程可以定义为三个层次：

```text
                      运营体系三层模型
    +----------------------------------------------+
    |  L3: 战略与规划层 (年度/季度)                  |
    |  - 年度经营计划(SP/BP) -> 重点任务分解            |
    |  - 产能规划(Capacity Planning)                 |
    |  - 产品路线图(Roadmap) -> NPI项目立项             |
    |  - 供应商战略(Sourcing Strategy)                |
    +----------------------------------------------+
    |  L2: 运营调度层 (月度/周/日)                    |
    |  - S&OP产销协同 -> 月度预排产                    |
    |  - MPS主生产计划 -> 周排程                       |
    |  - MRP物料需求 -> 采购到货计划                    |
    |  - 日排产(DPS) -> 工单释放                       |
    +----------------------------------------------+
    |  L1: 执行与控制层 (日/班次/实时)                 |
    |  - 产线投料 -> SMT -> 组装 -> 测试 -> 发货          |
    |  - 质量监控(SPC) -> 异常停线 -> 在线改善           |
```

### 9.3 运营体系的六大核心流程

| 流程名称 | 输入 | 输出 | 频率 | 主责 |
|:---------|:-----|:-----|:----|:-----|
| **① S&OP 产销协同** | 销售预测+产能+库存 | MPS计划+采购计划 | 月度 | 计划部 |
| **② 订单交付(Order-to-Delivery)** | 客户订单+交期承诺 | 产品交付+签收单 | 日常 | SSO+生管 |
| **③ NPI转量产(TR5→TR6→MP)** | 验证通过的产品设计 | 量产BOM+工艺+SOP | 按项目 | NPI经理 |
| **④ 工程变更(ECN/ECO)** | 变更需求+影响评估 | 变更实施+BOM更新 | 按需 | 工程部 |
| **⑤ 质量闭环(Quality Loop)** | 质量问题+客诉 | 8D报告+措施+改善 | 日常 | 质量部 |
| **⑥ 售后支持(Customer Support)** | 客户故障报修 | 修复+备件+满意 | 日常 | 服务部 |

### 9.4 流程定义的方法论

一条好的运营流程必须回答「5W1H」：

| 要素 | 含义 | 示例(以ECN流程为例) |
|:-----|:-----|:--------------------|
| **Why** | 为什么需要这个流程 | 保证变更受控，避免产线混乱 |
| **What** | 流程输出什么 | 变更实施指令+更新BOM版本 |
| **Who** | 谁执行/谁审批/谁知道 | 工程部发起·质量部会签·生产部执行 |
| **When** | 什么时间触发/完成 | ECN评审每周一次·紧急24h内 |
| **Where** | 在哪里做/用哪个系统 | PLM系统创建·MES系统生效 |
| **How** | 怎么做(步骤+工具+表单) | 见流程图(§8.2标准流程) |

**流程管控的「三不放过」原则**:

- 没有书面流程 → 不做（先定义再执行）
- 没有步骤表单 → 不做（先建模板）
- 没有明确Owner → 不做（流程没人负责=无人流程）

### 9.5 运营体系的仪表盘(KPI)

| 维度 | KPI | 目标 | 监控频次 | 预警阈值 |
|:-----|:----|:----|:--------|:---------|
| **交付** | 交期准时率(OTD) | ≥98% | 周 | <95%→预警·<90%→升级 |
| **交付** | 交期缩短天数(CT) | 较上期↓10% | 月 | 增长→分析原因 |

| **成本** | 制费占比 | 年度目标 | 月 | 超标→分析效率瓶颈 |
| **质量** | 直通率(FPY) | ≥98% | 日 | <95%→停线分析 |
| **质量** | 客户投诉率 | ≤0.5% | 月 | >1%→专项改善 |

| **存货** | 库存周转天数 | 年度目标 | 月 | 超期→呆滞分析 |

## §10 质量保证体系

> **定位**: 质量不是检验出来的，是设计出来的、制造出来的、管理出来的。质量保证体系覆盖从设计到交付的全链路。

### 10.1 质量体系全景

服务器质量保证体系包含四个相互耦合的质量域：

```text
                          质量保证体系
                              |
        +---------------------+---------------------+
        |                     |                     |
   +----+----+          +----+----+          +----+----+
   |  设计质量  |          |  制造质量  |          |  供应商质量 |
   |  (DQ)    |          |  (MQ)    |          |  (SQ)    |
   +---------+          +---------+          +---------+
   | DFSS    |          | SPC     |          | IQC     |
   | DFM/DFA |          | CPK     |          | QSA     |
   | FMEA    |          | FPY     |          | SQM     |
   | DVP&R   |          | 8D      |          | PPAP    |
   | ECN验证  |          | OQC     |          | 来料审核 |
   +---------+          +---------+          +---------+
                             |
                        +----+----+
                        |  软件质量 |
                        |  (SQE)   |
                        +---------+
                        | CI/CD   |
                        | 代码审查  |
                        | 自动化测试 |
                        | 灰度发布 |
                        | 版本管理  |
                        +---------+
```

### 10.2 产品质量（设计质量 DQ）

**设计质量的核心工具**:

| 工具 | 阶段 | 目的 | 服务器行业典型应用 |
|:-----|:-----|:-----|:------------------|
| **DFSS(六西格玛设计)** | TR1-TR3 | 从源头锁定质量 | 散热器的CFD仿真+DOE验证最优风道 |
| **DFM(可制造性设计)** | TR3-TR4 | 保证设计可制造 | PCB拼板·BGA间距·连接器方向·螺丝规格统一 |
| **DFA(可装配性设计)** | TR3-TR4 | 保证装配效率 | 盲插连接器设计·模块化免工具拆卸·防呆设计 |
| **FMEA(失效模式分析)** | TR3-TR4 | 提前识别失效模式 | 电源FMEA: 功率MOS失效→备援→报警逻辑 |
| **DVP&R(设计验证计划)** | TR4-TR5 | 验证设计是否达标 | 每项设计规格→对应测试用例→通过判定标准 |
| **RAS(可靠性可用性可维护性)** | 全流程 | 系统级质量指标 | 故障注入测试·容错验证·FRU可更换性验证 |

**服务器产品设计质量的关键检查点**:

| 检查点 | 检查内容 | 通过标准 | 不通过的后果 |
|:-------|:---------|:---------|:------------|
| **TR3 DFM审查** | PCB工艺可行性·BGA POB·装配干涉 | 所有DFM项通过 | 不可进入Layout阶段 |
| **TR4 原理图审查** | 信号完整性·电源完整性·时序 | SI/PI仿真通过 | 不可发板 |
| **TR4 FMEA审查** | 关键失效模式+应对方案 | RPN≤100 | 不可进入样机阶段 |
| **TR5 验证报告** | 所有规格的测试结果 | 规格符合率≥95% | 不可进入NPI |
| **TR6 量产准入** | 量产良率·测试覆盖率·过程能力 | CPK≥1.33·FPY≥95% | 不可转量产 |

### 10.3 制造质量（MQ）

**制造质量的三道防线**:

```text
第一道防线: 来料控制(IQC)
  +-----------------------------------+
  |  IQC（进料检验）                     |
  |  - 外观/尺寸/标签/包装检查            |
  |  - 关键参数的抽样测试                 |
  |  - 供应商COA(出厂报告)验证             |
  |  - 不合格->退货/特采/分选              |
  |  抽样标准: AQL 0.65%(关键) / 1.0%(主要)|
  +--------------+--------------------+
                 |
第二道防线: 过程控制(IPQC)
  +-----------------------------------+
  |  IPQC（制程检验）                    |
  |  - SMT: SPI/AOI/X-Ray全检           |
  |  - 组装: 首件确认+巡检+扭矩抽查      |
  |  - 测试: 第一次通过率(FTP)监控       |
  |  - 老化: 温度/电压/电流实时监控       |
  |  控制方法: SPC控制图(X-bar/R图)      |
  |  停线规则: CPK<1.33 -> 停线分析       |
  +--------------+--------------------+
                 |
第三道防线: 出厂检验(OQC)
  +-----------------------------------+
  |  OQC（成品检验）                     |
  |  - 外观全检(划痕/毛刺/标签/色差)      |
  |  - 功能复检(抽检)                   |
  |  - 包装完整性检查                    |

```

**制造质量的核心指标**:

| 指标 | 计算方法 | 行业基准 | 预警值 | 停线值 |
|:-----|:---------|:--------|:------|:------|
| **直通率(FPY)** | 一次性通过所有测试的比率 | ≥98% | <95% | <90% |
| **DPMO** | 百万机会缺陷数 | ≤50 | >100 | >200 |
| **过程能力(CPK)** | 制程稳定性的统计度量 | ≥1.33 | <1.33 | <1.0 |
| **首次通过率(FTP)** | 测试一次性通过率 | ≥95% | <90% | <85% |
| **OQC批合格率** | 出厂检验批次合格率 | ≥99% | <97% | <95% |

### 10.4 软件质量（SQE）

服务器产品的软件质量具有特殊性——固件(BMC/BIOS/CPLD)的问题可以在制造阶段修复(在线烧录)，但出厂后修复成本急剧上升：

**软件质量保证的分层策略**:

| 层次 | 阶段 | 方法 | 覆盖范围 | 时间 |
|:-----|:-----|:-----|:---------|:----|
| **L0 代码级** | 开发阶段 | 代码审查·静态分析(Coverity)·单元测试 | 100%关键模块 | 开发每个迭代 |
| **L1 功能测试** | 开发阶段 | 自动化测试·API测试·CLI测试 | 全功能覆盖 | 每版本 |
| **L2 集成测试** | 开发-TR4 | Redfish一致性·固件兼容性矩阵·升级/降级 | 全接口+协议 | 每次版本发版 |
| **L3 系统测试** | TR4-TR5 | 长时间稳定性(72h+)·压力测试·故障注入 | 全系统+边界 | 每个TR里程碑 |
| **L4 客户场景** | TR5 | 与客户OS/Hypervisor兼容·性能基线 | 主流客户场景 | 转产前 |
| **L5 灰度发布** | 客户现场 | 小批量部署+监控+自动回滚 | 真实场景 | 现场 |

**服务器固件质量的特殊挑战**:

| 挑战 | 根因 | 应对策略 |
|:-----|:-----|:---------|
| **硬件绑定** | 每个硬件配置(BOM)需独立的固件验证 | 自动化兼容性矩阵·CI/CD持续集成 |
| **版本碎片化** | 不同客户/场景运行不同的固件版本 | 固化基线版+定制补丁版 |
| **实时性要求** | BMC在特定时间窗口内必须响应 | 压力测试+确定性分析 |
| **升级失败恢复** | 升级过程中断电导致设备变砖 | 双Bank机制+Recovery模式 |
| **安全漏洞** | 固件漏洞的安全影响范围大 | SBOM(软件物料清单)·CVE跟踪·OTA打补丁 |

### 10.5 器件质量（Component Quality）

器件质量不只是IQC来料检验——它覆盖从选型到退役的全生命周期：

| 阶段 | 活动 | 关键输出 |
|:-----|:-----|:---------|
| **选型阶段** | 器件供应商评估·技术规格审核·产品变更通知(PCN)审查 | 优选器件目录(AVL)·器件规格认证报告 |
| **认证阶段** | 新器件可靠性测试(HTOL/HAST/TCT)·失效率评估·替代料认证 | 器件认证报告·失效率(FIT)数据 |
| **来料阶段(IQC)** | 外观/尺寸/电性抽样·批次一致性·RoHS/REACH合规 | IQC检验报告·COA合规 |
| **量产阶段** | 上线DPPM监控·批次性缺陷预警·供应商品质管理(SQM) | DPPM报告·供应商Scorecard |
| **失效阶段** | FRACAS(失效报告分析)·8D/CAPA·根因分析·纠正措施 | 8D报告·CAPA验证 |
| **退市阶段** | EOL通知·最后采购(LTB)·替代方案实施 | 替代料认证·LTB采购计划 |

**器件可靠性数据的计算**:

```text
失效率 FIT (Failures In Time)
  定义: 每10⁹小时失效数
  示例: 某MOSFET的FIT=10 -> 10⁹小时(114,155年)内预计失效10只
  服务器典型要求: ≤20 FIT/器件（消费级可放宽到100+）

DPPM (Defective Parts Per Million)
  定义: 每百万件中缺陷数
  示例: 某批次SSD DPPM=500 -> 每100万片中有500片不良
  服务器典型要求: ≤500 DPPM（消费级可到2000+）
  高端超节点目标: ≤100 DPPM（每批次）

寿命 Lx (年)
  定义: 在x%可靠度下的使用年限
  示例: L₁₀=5年 -> 90%的器件可工作5年以上
  服务器典型要求: L₁₀≥5年（企业级）/ L₁₀≥3年（AI训练）
```

### 10.6 IQC（来料检验）的详细运作

IQC 是制造质量的第一道防线，其实质是在「供应商质量控制能力」与「产线物料切换成本」之间的平衡：

**IQC 检验策略的差异化**:

| 物料类别 | 检验策略 | 抽样方案 | 检验内容 | 检验时间 |
|:---------|:---------|:---------|:---------|:---------|
| **A类(关键)** GPU/CPU/交换芯片 | 全检+供应商COA验证 | 100% | 外观+功能+ESD | 4-8h/批 |
| **B类(重要)** HBM/SSD/PSU/PCB | 加严抽样 | AQL 0.65% | 外观+尺寸+参数+功能 | 2-4h/批 |
| **C类(一般)** 连接器/线缆/包材 | 正常抽样 | AQL 1.0% | 外观+基本尺寸 | 1-2h/批 |
| **D类(免检)** 标准件(螺丝/垫片) | 免检或跳批 | 信赖供应商 | 仅查COA | 10min/批 |
| **E类(全退)** 批量问题/新供应商首件 | 拒收/全检分选 | 100%分选 | 严重时整批退货 | — |

**IQC 不合格处理流程**:

```text
IQC检验不合格
    |
   ++---------------+
   | 判定不合格严重程度  |
   | 致命(Major) / 一般(Minor) |
   ++---------------+
    |
   ++----------------------+
   |  处理路径选择             |
   |                        |
   |  (1) 退货(RTV)          | <- 致命缺陷/批量性问题
   |  (2) 特采(Concession)   | <- 一般缺陷+工程师评估可用
   |  (3) 分选(Sorting)      | <- 可筛选(100%分选)
   |  (4) 降级(Deviation)    | <- 用于非关键位置
   +------------------------+
```

**IQC前置/免检的条件**:

- 供应商通过 QSA(质量体系审核)并持续满足要求
- 连续 12 个月 DPPM < 100
- 供应商提供全批次 COA 且数据可信
- 对达到上述条件者，IQC 可转为「跳批检验」(每5-10批抽一批)甚至「免检」(定期审核)

### 11.4 备件管理体系（Spare Parts）

备件管理是售后支持的「物流中枢」——没有备件，再好的技术也不能恢复客户业务：

```text
备件库存量 = 装机量 × 年失效率 × 补货周期 × 安全系数

示例:
  超节点出货 1000柜，GPU年失效率 2%，补货周期(进口) 4周
  安全系数 1.5(考虑波动)
  -> 备件库存 = 1000 × 0.02 × 4/52 × 1.5 = 2.3 ≈ 3颗
```

**备件管理的三个层次**:

| 层次 | 位置 | 备件范围 | 补货方式 | 响应时间 |
|:-----|:-----|:---------|:---------|:--------:|
| **L1 现场备件** | 客户数据中心现场 | 高频故障件(PSU/风扇/线缆) | 自动补货 | 即用 |
| **L2 区域备件中心** | 区域仓(华北/华东/华南) | 全品类FRU | 按单发运 | 4-8h到达 |
| **L3 中央备件中心** | 总部备件仓 | 全品类+EOL囤货 | 批量补货 | 24h发出 |

**FRU(现场可更换单元)确定原则**:

| FRU判定 | 条件 | 示例 |
|:--------|:-----|:------|
| **是FRU** | 故障率>0.5%/年+现场更换可行(不需要回流焊/专用工具) | PSU·风扇·SSD·DIMM·NIC |
| **不是FRU** | 故障率低+更换需回流焊/专用设备 | 主板·GPU OAM基板(考虑中) |
| **边界情况** | 可换但成本高·需培训 | GPU(可FRU·但需ESD环境+熟练度) |

| **转二线率** | 从一线转至二线 | ≤20% | 工单追踪 |

## §12 制造体系深化：生产运营·工程技术·EMS·精益生产

### 12.1 生产运营（Production Operations）

生产运营是制造体系的「运行指挥中心」——让产线高效、有序、均衡地运转：

**生产运营的三大核心职能**:

| 职能 | 主责 | 日常活动 | 关键产出 |
|:-----|:-----|:---------|:---------|
| **生产计划** | 生管(PMC) | 日排产·工单释放·物料调度·紧急插单处理 | DPS·工单·物料配送单 |
| **生产执行** | 生产主管+班组长 | 产线投料·人员排班·产量追踪·异常停线处理 | 产出日报·OEE数据·停线记录 |
| **生产统计** | 生产统计员 | 产出数·不良数·工时·物料消耗·达成率 | 日报/周报·KPI看板 |

**日生产运营节奏**:

```text
08:00 — 早会(15min)
  +-- 昨日报表回顾(产出/质量/异常)
  +-- 今日计划发布(工单/交期/重点注意事项)
  +-- 物料齐套确认
  +-- 资源确认(人员到岗/设备状态)

08:15~12:00 — 上午生产
  +-- 首件确认(换线后首件)
  +-- 生产过程巡检
  +-- 异常处理(实时)
  +-- 上午产出盘点(11:30)

12:00~13:00 — 午休

13:00~17:00 — 下午生产
  +-- 生产过程控制
  +-- 产出追踪 vs 计划
  +-- 尾件确认(16:30)

17:00~17:30 — 交接班/收尾
  +-- 产出确认(工单关闭)
  +-- 异常问题交接
  +-- 次日物料确认
  +-- 日报填写+数据录入

17:30~18:00 — 晚会(复盘)
  +-- 今日计划达成
  +-- 异常/改善点总结
  +-- 明日重点事项确认
```

**生产运营的关键管理粒度**:

| 粒度 | 频次 | 关注指标 | 管理动作 |
|:-----|:----:|:---------|:---------|
| **班次/小时** | 实时 | 产出率·停线时间·缺料红灯 | 即时调整·异常上报 |
| **日** | 每日 | 计划达成率·FPY·OEE·缺料 | 晚复盘·日清日结 |
| **周** | 每周 | 交期达成·良率趋势·产能利用率 | 周例会·差异分析 |
| **月** | 每月 | SKU良率·OEE趋势·制费占比·KPI盘点 | 月度运营会·改善计划 |

### 12.2 工程技术（Engineering & Technology）

制造工程技术不是「修机器的」——它是制造体系的技术引擎，持续改进工艺和效率：

| 工程角色 | 缩写 | 核心职责 | 与研发的接口 |
|:---------|:-----|:---------|:------------|
| **工艺工程师** | PE/ME | SMT工艺参数(锡膏/回流焊)·工艺路线设计·SOP编制·DFM审核 | TR4阶段介入·DFM审查 |
| **测试工程师** | TE | 测试方案设计·测试程序开发·测试治具设计·测试覆盖率GRR | 测试大纲设计·DVP对接 |
| **工业工程师** | IE | 工时测定·产线平衡·车间布局·物流路线设计·产能模型 | OEE目标设定 |
| **设备工程师** | EE | 设备选型·维护保养·TPM·故障处理·备件管理 | 设备规格验收 |
| **自动化工程师** | AE | 自动化方案设计·机器人编程·自动测试实施·MES接口 | 自动化需求对接 |
| **质量工程师** | QE | SPC·CPK·FMEA·过程审核·8D·持续改进 | 质量目标设定·转产评审 |

**制程工程(PE)的典型工作**:

```text
新产品导入(NPI)阶段:
  1. 接收研发EBOM+Gerber -> 编制PFMEA
  2. 确定工艺路线(SMT->组装->测试->包装)
  3. SMT钢网设计·回流焊温区曲线设定
  4. 装配SOP编制(含爆炸图+作业要点)
  5. 首件确认->小批量验证

量产维护阶段:
  1. CPK监控(定期计算焊膏厚度/BGA空洞率)
  2. 工艺参数调优(DOE验证)
  3. 良率异常分析->改善措施
  4. 辅助治具优化(工装寿命管理)

工程变更(ECN)阶段:
  1. 新物料/新工艺的工艺可行性评估
  2. 变更后的SOP更新
  3. 变更首件验证
```

**测试工程(TE)的典型工作**:

| 测试层级 | 测试内容 | 覆盖率目标 | 测试工时 |
|:---------|:---------|:----------:|:--------:|
| **ICT(在线测试)** | 开路/短路·元件值·IC上电·BGA Jet | ≥95%缺陷覆盖 | 2-5min/板 |
| **FCT(功能测试)** | 各接口功能·固件版本·I2C读/写 | 100%功能规格 | 5-15min/板 |
| **Burn-in(老化)** | 高温负载·长时间运行 | 早期失效暴露 | 4-72h |
| **系统级测试** | OS启动·GPU识别·NVLink带宽·压力 | 端到端验证 | 30-60min/节点 |
| **超节点级测试** | 全拓扑连通·跨节点协同·液冷保压 | 系统级 | 4-12h/柜 |

### 12.3 EMS（电子制造服务）模式

EMS 是服务器制造中常见的商业模式——制造外包的核心逻辑是「让专业的人做专业的事」：

**EMS 的三种合作模式**:

```text
                   +--------------------------+
                   |  EMS模式选择矩阵            |
                   |                            |
                   |  控制力^                    |
                   |    |                        |
                   |  JDM|    自建工厂             |
                   |  共同设计                   |
                   |    |      (内制100%)         |
                   |    |                        |
                   |  ODM|                        |
                   |  委托设计+制造               |
                   |    |                        |
                   |  EMS|                        |
                   |  纯代工                     |
                   |    +-------------------->   |
                   |              控制力          |
                   +--------------------------+
```

| 模式 | 定义 | 品牌商(Gan) | EMS | 适合场景 | 典型份额 |
|:-----|:-----|:------------|:----|:---------|:--------:|
| **纯EMS** | 按图纸/BOM/工艺文件生产 | 提供完整设计+物料 | 仅做贴片+组装+测试 | 稳定产品·大规模量产 | 30-40% |
| **ODM(含设计)** | EMS负责设计+制造 | 提规格+验收 | 完整产品开发+生产 | 标准品·多客户共享平台 | 40-50% |
| **JDM(联合设计)** | 品牌商与EMS联合开发 | 核心架构+规格 | 配合设计+工艺支持 | 复杂/定制产品·超节点 | 10-20% |
| **自建工厂** | 自制100% | 完整 | 无 | 核心技术/保密产品 | <5% |

**EMS合作的关键管控点**:

| 管控点 | 品牌商职责 | EMS职责 | 关键合约条款 |
|:-------|:----------|:--------|:------------|
| **物料采购** | 冻结BOM+指定AVL | 按AVL采购+IQC | 长单锁定·价格透明 |
| **工艺标准** | 提供工艺规格+DFM要求 | 按标准生产 | SIP(检验标准规格)附件 |
| **过程审核** | 定期产线审核+质量巡检 | 开放产线 | 审计权条款 |
| **品质标准** | 提供AQL/GRR/CPK目标 | 达到标准 | 质量协议(QA) |
| **知识产权** | 提供技术资料 | 保密+不仿制 | NDA+IP归属 |
| **产能保障** | 年度预测+滚动交期 | 预留产能 | 产能预留条款 |

### 12.4 精益生产体系（Lean Production）

精益生产不是「减少浪费」这么简单——它是一种**制造哲学**：用最少的资源(人/物料/时间/空间)创造最大的客户价值。

**精益的七大浪费与服务器应用**:

| 浪费类型 | 定义 | 服务器制造中的具体表现 | 消除策略 |
|:---------|:-----|:---------------------|:---------|
| **① 过量生产** | 早生产/多生产 | 备料过多导致板卡库存积压 | 拉动式生产(看板)·按订单生产 |
| **② 等待** | 人/设备等物料/上道工序 | SMT等PCB到料·组装线等测试放行 | 线平衡优化·看板拉动 |
| **③ 搬运** | 物料非必要移动 | 板卡在不同楼层的流转 | U型线布局·AGV自动搬运 |
| **④ 过度加工** | 做了客户不要求的事 | 100%全检但客户只要求抽样 | 根据DPPM动态调整检验频率 |
| **⑤ 库存** | 物料/在制/成品过多 | 线边库积压、WIP过高 | 拉动生产+Kanban+SMED |
| **⑥ 动作** | 不必要的动作 | 找工具·翻物料·重复弯腰 | 5S工作站·工具挂板·操作标准 |
| **⑦ 不良修正** | 返工/重检 | CPU安装方向错误·线缆接反 | 防呆设计(Poka-Yoke)·标准化 |

**精益工具箱在服务器制造中的应用**:

| 工具 | 目的 | 在服务器制造中的应用 |
|:-----|:-----|:--------------------|
| **5S(整理/整顿/清扫/清洁/素养)** | 工作场所有序化 | SMT料盘架5S: 料盘分类·FIFO标识·干净无尘 |
| **看板(Kanban)** | 拉动式生产信号 | SMT料架看板: 每盒料贴看板卡·用完即传信号给前道 |
| **SMED(快速换型)** | 切换时间压缩 | SMT换线: 离线备台车(钢网/Feeder/程序→换线仅3min) |
| **TPM(全员维护)** | 设备综合效率提升 | AOI设备TPM: 每日点检·周清洁·月校准·OEE看板 |
| **VSM(价值流图)** | 识别全链路浪费 | 从PCB进厂→SMT→组装→测试→包装全流程VSM |
| **Poka-Yoke(防呆)** | 预防错误 | GPU安装方向防呆(非对称定位销)·线缆防呆(不同色/转头) |
| **Kaizen(持续改善)** | 小步快跑改善 | 每周改善会: 一线员工提出+验证+标准化 |
| **JIT(准时制)** | 只在需要时提供所需数量 | 物料按工单配料·线边库仅存2h用量 |

**精益推行的铁三角**:

| 维度 | 成功要素 | 失败原因 |
|:-----|:---------|:---------|
| **人的参与** | 一线员工参与改善(提案制度) | 仅管理层推进无一线配合 |
| **工具的使用** | 选对工具用到位 | 赶时髦盲目使用(如引入Kanban但无拉动机制) |
| **系统的支撑** | 精益KPI纳入月度运营考核 | 精益是一阵风运动式推进 |

**在EMS工厂推行精益的挑战**:

| 挑战 | 原因 | 应对策略 |
|:-----|:-----|:---------|
| **精益收益分成** | 精益省的钱归EMS还是品牌商？ | 合同中约定精益收益共享机制(50/50) |
| **多客户共线** | EMS同时生产多个品牌，排产/换线受限 | 品牌商与EMS签订产能锁定协议 |
| **品牌商变更** | 品牌商的ECN打乱EMS的精益节奏 | 固定变更窗口期·减少临时变更 |
| **人员流动性** | EMS工厂员工流动率高达30-50%/年 | 标准作业可视化(培训新人更快)·关键岗位多能工 |
| **数据边界** | 品牌商要数据·EMS不愿给 | 协议约定数据共享范围(质量/效率/成本) |
