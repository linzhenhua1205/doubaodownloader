## 1. 核心命题

> 上一轮（文件级）解决「给定文件 → 深度解读」；本主题（**语料库级**）解决「给定一个系统/库 → **不知道结论在哪 → 主动发现并提炼**」。
> 本质区别：**探索 ≠ 检索**——检索是 query→hits 的收敛过程，探索是 corpus→patterns 的发散过程。

| 维度 | 文件级深度解读（上篇） | 语料库级探索提炼（本篇） |
|:-----|:-----------------------|:-------------------------|
| 输入 | 单文件/多文件（已知对象） | 整个语料库（未知目标） |
| 核心动作 | 解析→表示→综合 | **发现候选→验证→蒸馏** |
| 目标 | 读懂一份文件 | 找出语料里有什么、什么在变化、什么异常 |
| 规模 | 10^3-10^6 tokens | 10^7-10^10 tokens（万级文件） |
| 失败模式 | 摘要失真 | **漏报**（埋没的信号）与**误报**（虚构的模式） |

## 2. 规模三定律：什么量级需要什么策略

| 量级 | 总 token | 策略 | 代表手段 |
|:-----|:---------|:-----|:---------|
| 单文件 | <10^5 | 直读/分层摘要 | 上篇四段管线 |
| **语料库** | 10^6-10^8 | **两段式：先索引聚类，再针对发现目标深挖** | 向量库+主题建模+图谱 |
| **持续流动** | 增量 10^4-10^6/天 | 增量记忆/图谱维护 | mem0/cognee/graphiti |

**为什么语料库必须「两段式」**（第一性）：

- 万级文件总 token 远超任何上下文窗口，且**注意力稀释随规模超线性恶化**（T07 §2.1）；
- 直接对全库做一次「综合提炼」= 把 10^7 token 压进 10^5 窗口，压缩比 100:1 以上，**信息瓶颈决定结论必然失真**；
- 正确路径：第一段**粗粒度探索**（索引+聚类+图谱，机器可确定性完成）产出**候选主题/实体/社区**；第二段**细粒度提炼**（对候选做深度分析，LLM 发挥所长）产出结论。
- 机器做确定性筛选（不漏、不漂移），LLM 做语义深化（理解、关联、判断）——**各用所长**。

## 3. 原理层：探索-提炼-推理闭环

### 3.1 三个动作的定义与边界

```text
EXPLORE  : corpus -> candidates (hypotheses / topics / anomalies / entities)
           (divergent: answer unknown, find where the questions are)

DISTILL  : candidates -> conclusions (validated, sourced, confidence-scored)
           (convergent: verify and compress candidates into conclusion assets)

REASON   : conclusions + scenario context -> decisions / answers
           (application: conclusions as premises for scenario reasoning)
```

### 3.2 探索的两个互补策略

| 策略 | 方向 | 机理 | 代表组件 | 适用 |
|:-----|:-----|:-----|:---------|:-----|
| 自底向上（数据驱动） | 语料→结构 | 聚类/主题/图社区发现，**发现涌现结构** | BERTopic、HDBSCAN、GraphRAG 社区检测 | 不知道关心什么时，先摸清语料全貌 |
| 自顶向下（目标驱动） | 意图→语料 | 多代理漫游/全局查询，**沿目标逐层下钻** | gpt-researcher、open_deep_research、GraphRAG Global Search | 有方向但不知道证据在哪 |

**关键机理**：完整探索 = 两策略组合——先用自底向上建「语料地图」（有哪些主题簇/实体群/社区），再用自顶向下在感兴趣的地图上「定点深挖」。**没有地图的探索是盲搜，没有下钻的地图是空架子**。

### 3.3 提炼的信息瓶颈与置信度模型

提炼的本质 = **有损压缩的保真控制**。结论的置信度由三因子决定：

```text
confidence(conclusion) = f( evidence_count, consistency, source_quality )
                          evidence        consistency    source quality
```

- **证据数**：跨文档重复出现的模式比单点断言可信（统计显著性）；
- **一致性**：多源结论相互印证 vs 冲突（冲突需显式标记，进入复核）；
- **来源质量**：一手源 > 二手转述 > 无出处（对应 RULE.md 素材批判性使用原则）。

**提炼的三个层次**（MECE）：

| 层次 | 输入 | 输出 | 典型方法 |
|:-----|:-----|:-----|:---------|
| 统计提炼 | 全库元数据 | 分布/趋势/异常（数值可验证） | 聚类统计、时间序列、共现矩阵 |
| 语义提炼 | 文本块/实体 | 主题、关系、因果链 | 主题建模、图谱聚合、全局摘要 |
| 论证提炼 | 多源观点 | 对比表、共识、分歧、缺口 | 研究代理、多路交叉验证 |

### 3.4 闭环与增量

```text
        +---------------- incremental feedback <----------------+
        v                                                       |
[corpus] -> EXPLORE -> candidates -> DISTILL -> conclusions -> REASON -> decisions
                                                    |
                                                    +-> conclusions written back to index/graph (memory)
```

持续流动语料的关键：**提炼出的结论必须回流到索引/图谱**（mem0/cognee/graphiti 的定位），否则每次探索都从零开始，无法积累。这对应本系统「一切内容经受控管线入 knowledge/」的治理原则。

## 3.5 原理深潜：语料库级探索的三重挑战（v1.1 深度补齐）

> 本节回答「**为什么语料库级探索如此困难**」的三个第一性问题。注意力机制的本质限制（softmax 竞争/有效上下文/KV 成本）已在姊妹篇 §3.4 完整推导，本篇**直接引用**，只补充语料库级特有的增量挑战。

### 3.5.1 挑战一：上下文限制 × 无 query 的探索困境

**基础限制（引用姊妹篇 §3.4）**：注意力是软检索（每 token 权重期望 1/n）、有效上下文 ≪ 名义上下文、长上下文按 O(n²) 计算 + O(n) 存储付费。语料库级（10^7-10^10 tokens）使这些限制**从"性能问题"升级为"可行性问题"**：

```
单文件级:   10^5 token 压缩进 10^4-10^5 有效上下文  → 压缩比 ~10:1，勉强可行
语料库级:   10^7-10^10 token 压缩进 10^5 有效上下文 → 压缩比 100:1 ~ 100,000:1
            信息瓶颈（§3.3）决定结论必然失真
```

**语料库级特有的增量困境——「探索没有 query」**：

```
检索（RAG）的前提是有一个 query 向量作为相似性锚点；
探索（EXPLORE）恰恰是「不知道问什么」——没有锚点，向量检索无从发起。
  → 探索阶段的相似性检索天然失效
  → 必须依赖无监督结构发现（聚类/图谱社区/主题建模）作为替代锚点
```

> **推论**：这正是 §3.2 两策略必须组合的机制原因——自底向上聚类 = **在没有 query 的情况下用数据自身结构制造锚点**（语料地图）；自顶向下深挖 = **有了锚点之后的定向检索**。**没有地图的探索是盲搜**不是比喻，而是"无锚点检索不可行"的数学事实。

**机器确定性筛选为什么不可替代（可逆性论证）**：

```
LLM 压缩（摘要/提炼）: 不可逆操作——被滤掉的信息无法恢复（信息论：H(X|Y) > 0）
机器筛选（聚类/索引）: 可逆操作——被分到某簇的文档仍保留原样，可随时回查
  → 探索层必须用机器确定性筛选（不漏、可回查），
     LLM 只做语义深化（在候选集上判断）——「各用所长」的机制依据
```

### 3.5.2 挑战二：一致性——语料库级特有的四类不一致

文件级解读只面对"一份文档内部的逻辑一致性"；语料库级面对**跨文档、跨时间、跨表示**的一致性，这是蒸馏正确性的前提。四类不一致（MECE）：

| # | 不一致类型 | 表现 | 后果（若未治理） |
|:-:|:-----------|:-----|:-----------------|
| 1 | **实体不一致** | 同一实体多表述：「NVIDIA GB200」「NVL72」「Blackwell 机柜」指向同一物；缩写/别名/翻译差异 | 关联挖掘断裂：图谱中同一实体分裂成多个节点，社区检测失真 |
| 2 | **冲突不一致** | 源 A 说 X，源 B 说 Y（数据口径/观点分歧/过时信息） | 蒸馏产物自相矛盾；LLM 汇聚时"取平均"式妥协，两边都不对 |
| 3 | **时效不一致** | 语料随时间演化：2025 年的结论 vs 2026 年的反例 | 旧结论未标记时效 → 被当作当前事实使用（知识库记忆研究已证：信任过时记忆比无记忆危害更大） |
| 4 | **蒸馏失真（传递不一致）** | 分层汇聚时每层摘要引入转述误差，逐层放大 | 顶层结论与原文偏离（蒸馏失真随层数指数增长，见下） |

**蒸馏失真的数学模型**：

```
设每层汇聚的语义保真度 = r（0<r<1，r=1 表示无损）
L 层汇聚后的保真度 = r^L

  r = 0.9（每层损失 10%）, L = 3 → 总保真 0.729（损失 27%）
  r = 0.7（摘要转述损失大）, L = 3 → 总保真 0.343（损失 66%）
  → 分层摘要的层数必须受控，且每层必须用「断言级汇聚」而非「散文转述」
    （断言可字段级校验，转述不可）
```

> **工程铁律**：蒸馏链路的层数 L 与每层保真 r 是**乘积关系**——减少层数、提高每层保真（结构化断言替代散文摘要）比任何单点优化都有效。

### 3.5.3 挑战三：查找时「内在关联性」难以挖掘

用户场景的核心诉求之一是「查找时能挖到内在关联」。为什么难？**五个机制性原因**：

**① 相似性 ≠ 关联性（最根本）**：

```
向量检索回答「和 query 像不像」（相似性/近邻）
综合分析需要「和 query 有什么关系」（关联性：因果/对比/依赖/矛盾）
  相似的文档可能无关（同一话题的两篇独立文章）
  关联的文档可能不相似（「需求」→「技术方案」→「竞品」是不同文本）
  → 纯向量检索对关联挖掘的结构性失效（姊妹篇 §3.2 已述，此处是语料库级放大）
```

**② 索引粒度切断了跨段关联**：chunk 化把文档切成独立片段，关联常藏在**跨 chunk 的上下文**中（§3.5.6 上篇已述切分断义）；语料库级 chunk 数量 10^5-10^7，跨块关联的组合空间爆炸，无法靠穷举。

**③ 多跳关联需要显式路径**：A→B→C 的间接关联，向量检索只能直接命中 A 或 C；中间跳 B 若不在同一块/同一文档，检索链路断裂。**多跳推理 = 图遍历问题，不是相似性问题**。

**④ 长尾弱信号被统计噪声淹没**：关联强度常用共现频率度量；稀疏共现（出现 2-3 次的关联）与随机共现（噪声）在统计上不可区分——阈值设高漏掉弱信号，设低引入大量噪声（§6 选型原则 4「漏报比误报更贵」的机制来源）。

**⑤ 关联的三种形态需要三种机制（MECE）**：

| 关联形态 | 定义 | 挖掘机制 | 典型输出 |
|:---------|:-----|:---------|:---------|
| **共现关联** | 一起出现（统计共现） | 共现矩阵 / PMI 点互信息 | 「X 常与 Y 同现」 |
| **结构关联** | 实体-关系-属性（显式建模） | 实体抽取 + 关系抽取 + 图谱 | 「X 依赖 Y / X 是 Y 的竞品」 |
| **推理关联** | 跨跳推导（隐式路径） | 图遍历 + LLM 语义验证 | 「X 影响 Z（经 Y 传导）」 |

> **核心洞察**：共现关联是**统计可发现**的（机器确定性强），结构关联是**抽取可构建**的（LLM 抽取+图存储），推理关联是**遍历可推导**的（图算法+语义校验）——**三层关联的挖掘复杂度递增，对应的表示层需求也递增（矩阵→图谱→图算法）**。这解释了为什么图谱路线（GraphRAG/LightRAG）是语料库级关联挖掘的主战场。

## 3.6 解法模式：摘要-分层汇聚-一致性治理-关联挖掘（v1.1 深度补齐）

> 本节把解法从「组件罗列」升级为「算法本质 + 保真控制 + 治理机制」。姊妹篇 §3.5 已推导 for 循环/MapReduce 的复杂度本质（m(n/m)²+k² ≪ n²），本篇聚焦语料库级特有的三个解法维度。

### 3.6.1 提供摘要的本质：把单步大压缩分解为多步小压缩

「给 AI 提供摘要再分析」为什么有效？——**信息瓶颈的分步化解**：

```
单步直灌压缩:  10^7 token → 10^4 token 摘要   （单步 1000:1，信息瓶颈必然失真）
分层摘要:      10^7 → 10^6 → 10^5 → 10^4      （每步 ~10:1，逐步保真控制）
  每步只做小压缩（10:1），可用断言级汇聚保持字段精度，
  总压缩比相同（1000:1），但每步的失真可校验、可回查
```

| 维度 | 单步摘要 | 分层摘要（RAPTOR 树/MapReduce） |
|:-----|:---------|:-------------------------------|
| 压缩比/步 | 100-1000:1 | 5-10:1 |
| 失真可校验 | 不可（原文已弃） | 可（每层保留来源 ID） |
| 信息选择 | 模型一次性隐式选择（随机性强） | 每层显式汇聚（断言合并/投票） |
| 注意力竞争 | 全部信息一次竞争 | 每层只在当前层内竞争（姊妹篇 §3.5.1） |

> **为什么"给摘要"比"给原文"更好（反直觉但可证明）**：摘要 = **把注意力竞争的"分母"从全语料缩小到摘要规模**（姊妹篇 §3.5.1 信噪比 ∝ 1/块大小），同时**把信息选择的职责从"模型单步隐式判断"移交为"多步显式汇聚"**——选择的可控性提高了。前提是摘要必须**分层**且**带来源**（否则退化为单步压缩）。

### 3.6.2 分层汇聚的两种形态与保真控制

| 汇聚形态 | 结构 | 代表 | 保真控制手段 |
|:---------|:-----|:-----|:-------------|
| **树状汇聚**（摘要树） | 自底向上合并摘要 | RAPTOR、LangChain MapReduce | 每层保留来源 ID；层数 L 受控（§3.5.2 失真模型） |
| **图状汇聚**（社区摘要） | 实体图 → 社区 → 全局摘要 | GraphRAG 社区检测 | 社区粒度可调（Leiden 分辨率参数）；摘要附实体证据链 |

**保真控制三原则**（对应 §3.5.2 蒸馏失真模型）：

1. **层数最小化**：能 2 层完成不搞 3 层（r^L 乘积衰减）；
2. **断言优先于散文**：汇聚时合并「断言+来源+置信度」而非重写一段话（字段级可校验）；
3. **每层留证据**：任何汇聚输出必须能回查到下一层/原文（证据链 = 可逆性保证）。

### 3.6.3 一致性治理：实体解析 + 冲突清单 + 时间戳（解法对应 §3.5.2）

| 不一致类型 | 治理机制 | 工程手段 | 开源组件 |
|:-----------|:---------|:---------|:---------|
| 实体不一致 | **实体解析 + 规范化** | 别名表/实体链接/LLM 规范化到 canonical 名称 | GraphRAG entity resolution、graphiti（时序实体）、llm-graph-builder |
| 冲突不一致 | **冲突清单 + 触发复核** | 汇聚层显式输出冲突条目（不静默取平均）；分歧进入人工/复核回路 | discover L2 冲突检测、consensus voting、STORM 分歧面板 |
| 时效不一致 | **时间戳 + 时效衰减** | 每条结论带 valid_from/valid_to；过期结论降权或标记 deprecated | graphiti（时间线）、时序 RAG、知识库记忆时效衰减（本系统 G4 机制） |
| 蒸馏失真 | **断言级汇聚 + 证据链** | 每层只合并结构化断言；层数受控（§3.6.2） | RAPTOR/GraphRAG + verification loop |

> **一致性治理的优先级**：实体解析是**地基**（实体错则关联错、冲突检测错、时效标记错——四类不一致中实体不一致是源头）；冲突与时效是**语义**（决定结论可用性）；蒸馏失真是**过程**（决定可信度）。**先治地基，再治语义，过程控制贯穿全程**。

### 3.6.4 关联挖掘：共现 → 图 → 多跳（解法对应 §3.5.3）

三形态关联的完整挖掘管线：

```text
L0 共现挖掘（统计层）:
    chunk × chunk 共现矩阵 / PMI → 候选关联（弱信号，需过滤）
        ↓ 过滤（阈值 + LLM 验证「真的有关系吗」）
L1 结构构建（抽取层）:
    实体解析（§3.6.3）→ 关系抽取（LLM）→ 知识图谱（带置信度边）
        ↓
L2 关联发现（遍历层）:
    社区检测（关联的聚类：GraphRAG Leiden）→ 多跳路径搜索（A→B→C）
    全局摘要（关联的叙事化：社区摘要）
        ↓
L3 推理验证（语义层）:
    LLM 验证路径语义（「X 经 Y 影响 Z」是否成立）→ 输出带证据链的关联结论
```

| 关联形态 | 挖掘机制 | 失败模式 | 组件 |
|:---------|:---------|:---------|:-----|
| 共现 | PMI/共现矩阵 | 长尾弱信号被噪声淹没（§3.5.3-④） | txtai、统计提炼层 |
| 结构 | 实体+关系抽取 | 实体不一致 → 节点分裂（§3.5.2-①） | LightRAG、GraphRAG、llm-graph-builder |
| 推理 | 图遍历+语义验证 | 图谱不完整 → 路径断裂（假阴性） | GraphRAG local/global search、多跳检索器 |

> **关键机制**：图谱把「关联发现」从**模型在长上下文中隐式串联**（不可控、易漏）转变为**确定性图遍历 + LLM 语义验证**（可控、可解释）——这正是 GraphRAG 在语料库级综合问答上优于 naive RAG 的机制原因（上篇 §3.2 已述，此处补遍历层细节）。

### 3.6.5 边界条件：语料库级解法的失效场景（v1.1 补齐 D4）

| # | 失效场景 | 原因 | 应对 |
|:-:|:---------|:-----|:-----|
| 1 | **语料 < 10^5 token** | 两段式/图谱过度设计（成本 > 收益） | 直接分层摘要（姊妹篇四段管线） |
| 2 | **强一致性命中场景**（法律/金融合规） | 实体解析误差不可容忍（0.1% 错 = 法律风险） | 人审闸门 + 全量实体清单人工复核 |
| 3 | **高频流式更新** | 批式图谱（GraphRAG）重建成本随更新频率线性上升 | 选流式图谱（graphiti）或 Lambda 批+流双轨（§3.5.4 上篇） |
| 4 | **多语言语料** | 跨语言嵌入对齐质量差 → 聚类/实体解析失真 | 分语言子库探索 + 语言无关信号（结构/引用）兜底 |
| 5 | **探索漏报不可完全消除** | 任何聚类都有阈值，极端长尾必然漏（§3.5.3-④） | 定期全量重聚类 + 漏报审计（对比人工抽样） |
| 6 | **蒸馏层数失控** | r^L 指数衰减（§3.5.2） | 硬性层数上限 + 每层保真抽检 |

## 6. 选型建议（按诉求）

| 你的诉求 | 推荐组合 | 理由 |
|:---------|:---------|:-----|
| 摸清语料全貌（不知道有什么） | Docling + Milvus + BERTopic/GraphRAG | 先建地图：主题簇/社区即候选 |
| 有方向但找证据 | 向量库 + 研究代理（gpt-researcher） | 目标驱动多轮下钻 |
| 持续流动语料 | mem0/cognee + 增量图谱 | 结论回流，避免重复探索 |
| 生产级高并发 | Milvus/Qdrant + Haystack | 索引+编排均生产化 |
| 全栈快速落地 | RAGFlow/MaxKB（语料→问答+分析） | 开箱即用，运维成本低 |

**关键选型原则（第一性）**：

1. **先地图后深挖**：任何语料库探索，先花 20% 成本建地图（索引+聚类+图谱），再花 80% 精力在图上定点深挖——避免盲搜；
2. **探索的产出是假设不是结论**：candidates 必须经过提炼层验证（证据数/一致性/来源质量）才能成为结论——跳过验证 = 把噪声当信号；
3. **增量回流决定长期价值**：无记忆的探索是重复劳动，有记忆的探索是复利——结论必须回流索引/图谱；
4. **漏报比误报更贵**（探索场景）：漏掉一个信号 = 损失一次机会；误报一个模式 = 浪费一次验证。所以探索层用确定性聚类（不漏），提炼层用 LLM 判断（辨真伪）。

## 7. 与本地工程互证（黄金案例）

本系统 `discover/` 三级流水线 = 语料库探索提炼的开源生态同构实现，且**方法论领先**：

| 本系统组件 | 对应开源类别 | 具体对照 |
|:-----------|:-------------|:---------|
| `discover/` L1 文件级 | 解析层（Docling/MinerU） | 18,895 import 文件逐文件提取问题/关键词 |
| `discover/` L2 汇聚级 | 提炼层（GraphRAG 汇聚） | 分类聚合、冲突检测、维度对齐 |
| `discover/` L3 洞察级 | 论证提炼（研究代理） | 跨专题关联、趋势研判、决策输出 |
| `knowledge-special-reports` | 统计提炼层 | 目录演化分析、代码提交分析（元数据级） |
| `session-intent-analysis` | 探索层（话题发现） | 从会话日志提取话题边界与任务切换 |
| `kb-daily-survey-coverage` | 统计提炼 | 38 领域覆盖矩阵（语料地图的本地实现） |
| `knowledge/index.md` | 索引层 | 手动维护的轻量「地图」 |

**差距（可借鉴点）**：

1. **无向量索引**：探索靠关键词+目录结构，语义相似发现能力为零——对应 MEMORY.md 待办「启用 embedding 是最高杠杆」；
2. **无主题聚类**：38 领域矩阵是人工预设的分类，BERTopic 式自动主题发现可补「人工盲区」；
3. **结论未结构化回流**：知识文档结论散在 Markdown，未机器可读化——mem0/graphiti 的增量记忆模式可借鉴；
4. **探索-提炼未自动化闭环**：目前靠人工触发，可参照 Haystack pipelines 将「索引→聚类→提炼→回流」固化为定时流水线。

**核心启示**：本系统在**方法论与流程层**已覆盖开源生态 80% 能力（甚至更严），缺的是**表示层基础设施**（向量+图谱）与**自动化闭环**——这与上篇（文件级）结论完全一致，两篇互相印证：**表示层是本地知识库系统下一步最高杠杆投入**。

## 8. 结论

1. **原理**：语料库级探索提炼 = 探索（发散找候选）+ 提炼（收敛验证压缩）+ 推理（应用）三动作闭环；探索分自底向上（聚类/图谱地图）与自顶向下（目标驱动下钻）两策略，必须组合；提炼的置信度由证据数×一致性×来源质量决定；
2. **规模**：万级文件必须两段式（先机器确定性索引聚类，再 LLM 语义深化），直接全库压缩必失真；持续流动语料必须结论回流（增量记忆）；
3. **组件**：2026-08-10 实查 19 个语料库级组件——索引层（Milvus 45.6K/Qdrant 33.9K/Chroma 29.0K）、探索层（LightRAG 38.7K/GraphRAG 35.4K/BERTopic 7.8K）、提炼层（Haystack 26.2K/gpt-researcher 28.9K）、记忆层（mem0 62.9K/cognee 29.9K/graphiti 29.7K）；生态已成熟可组装；
4. **对本地系统**：discover 三级流水线是开源同构且方法论更严的本地实现；明确缺口 = 向量索引 + 自动主题发现 + 结论结构化回流 + 探索提炼自动化闭环——两篇姊妹篇互相印证同一结论。
