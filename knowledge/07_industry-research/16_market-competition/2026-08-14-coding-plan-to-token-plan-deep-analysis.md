## 1. 结论先行

**一句话结论**：国内 AI 编程从 Coding Plan（固定席位订阅）转向 Token Plan（按 token 计量），本质是 **AI 编程从"人力替代品"定价逻辑走向"算力商品"定价逻辑**——当模型能力足够强、用户使用强度差异足够大、且 API 价格降到可被直接比较的量级时，固定订阅制的"价格歧视"失效，按量计费成为供需双方都更公平、更可治理的帕累托改进。

**五个关键结论**：

| # | 结论 | 依据 |
|:-:|:-----|:-----|
| 1 | **不是国内单方面切换，而是全球收敛**：Cursor 已采用"订阅内用量+超量按量"混合模式；Copilot 引入第三方模型按 provider 列表价计费；Anthropic 曾试点纯 token 计费被用户反弹暂停——**token 化是全球趋势，国内（阿里/智谱/DeepSeek）只是走得更激进** | Cursor 官方定价页（08-14 抓取）、GitHub Changelog（08-13）、知识库 06-29/07-07 记录 |
| 2 | **核心驱动力是成本结构失配**：订阅制假设"用户平均用量"，但 AI 编程用量分布是**幂律**——重度 Agent 用户月耗可达轻度用户的 100 倍。固定订阅要么让重度用户"薅穿"厂商成本，要么让轻度用户补贴重度用户。Token Plan 让付费与边际成本对齐 | meth-016 判断框架：月 token 量 × 单价 vs 订阅价 |
| 3 | **国产模型价格战把"token 单价"打到可比较量级**：DeepSeek V4 Flash 缓存命中 ¥0.02/M、未命中 ¥1/M、输出 ¥2/M（8/17 起峰谷定价）；GLM-5.2 开源 SOTA。当 API 价格透明可查，订阅制的隐含 token 单价（¥59/月 ÷ 可用量）就失去了信息优势，用户可精确计算 ROI | DeepSeek API 官方定价页（08-14 抓取） |
| 4 | **企业治理需求是 Token Plan 的 B 端推手**：研发团队需要 cost center 分摊、用量审计、预算上限。订阅制按人头无法回答"每个 token 花多少钱"，Token Plan 天然支持（OpenCost 已实现 K8s 推理 token 级成本追踪） | 知识库 08-07 OpenCost 记录 |
| 5 | **对个人/小团队，最经济的方案是"免费层 + 按量 API"组合**，而非订阅制——除非你是每日 8 小时重度 Agent 用户 | 本文 §5 决策框架 |

## 2. 现象校准

### 2.1 "从 coding plan 切换到 token plan"的准确含义

用户观察"国内都从 coding plan 切换到 token plan"，需要校准为三个层次：

| 层次 | 变化 | 代表 |
|:-----|:-----|:-----|
| **L1 纯订阅 → 订阅+超量按量** | 订阅仍存在，但用量上限明确，超出按 token 计费（混合模式） | Cursor（08-14 官方页确认）、GitHub Copilot AI credits |
| **L2 订阅 → 纯 token 计量** | 取消固定席位，全部按用量付费 | Anthropic Agent SDK（曾试点，06 月被用户反弹暂停）、部分 API 优先产品 |
| **L3 平台化多模型按量** | 平台内不同模型按各自 provider 价格计费（usage-based billing） | GitHub Copilot Gemini 3.7 Flash 按 provider 列表价计费（08-13）、Cursor Bugbot usage-based |

**关键校准**：Cursor 并没有取消订阅——`Pro $20/月` 仍在，但官方 FAQ 明确"Every plan includes a set amount of model usage. On-demand usage allows you to continue using models after your included amount is consumed, billed in arrears"——即 **订阅变成了"预付费折扣包"，超量自动转按量**。这是"订阅制"与"token 制"的融合形态，而非谁取代谁。

## 3. 底层逻辑

### 3.1 第一性原理：AI 编程服务的成本结构

AI 编程（尤其是 Agent 化编程）服务的边际成本**不是零**：

```
单次 Agent 请求成本 = 输入 tokens × 单价 + 输出 tokens × 单价
                   ≈ (上下文注入 + 工具调用轮次 × 上下文重放) × 单价

实测参考（知识库 GLM-5.2 文档）：
  一次完整"需求→多端可部署产物"的长程任务 ≈ 85万 tokens
  1M 上下文窗口接近用满
```

**关键量化**：一个重度 Agent 开发者（每天 20 次 Agent 请求 × 平均 3 万 tokens/次）月消耗 ≈ **1800 万 tokens**；一个轻度用户（每天 5 次简单补全 × 平均 2000 tokens/次）月消耗 ≈ **30 万 tokens**。**两者差 60 倍**——这正是订阅制无法公平定价的根本原因。

### 3.2 五层逻辑拆解

```
为什么 Token Plan 会赢？
┌─────────────────────────────────────────────────────────┐
│ L1 成本结构：订阅制 = 平均定价 → 幂律用量下必失配        │
│     ↓ 重度用户薅穿成本，轻度用户补贴重度用户              │
│ L2 供给侧：模型能力跃迁 → Agent 化 → 单任务 token 暴涨     │
│     ↓ 85万 tokens/任务成为常态，订阅"无限量"承诺难以为继  │
│ L3 价格透明度：API 地板价 → token 单价可查可比            │
│     ↓ 订阅制的隐含单价失去信息优势                        │
│ L4 企业治理：cost center / 审计 / 预算上限 → 按量天然支持  │
│     ↓ OpenCost 已实现 token 级追踪                        │
│ L5 厂商策略：Token Plan 转嫁算力成本波动 + 获取精确用量数据 │
│     ↓ DeepSeek 峰谷定价 = 用价格信号管理算力负载          │
└─────────────────────────────────────────────────────────┘
```

#### L1 成本结构失配（最根本）

- 订阅制本质是**保险模型**：所有订阅者分摊平均成本，但 AI 编程的用量分布是**极端幂律**（Pareto：20% 用户消耗 80% tokens）
- 对厂商：重度用户的实际算力成本 >> 订阅费 → 亏损；厂商被迫限制用量（如通义灵码免费版 50 轮/月），体验劣化
- 对用户：轻度用户为用不上的额度付费；重度用户担心被限流——**双方都不满意**
- Token Plan：付费 = 实际边际成本，供需两侧激励对齐

#### L2 Agent 化导致单任务 token 暴涨

- 2026 年编程范式从"补全/对话"转向"Agent 长程任务"：Claude Code / Trae / Qoder / Kimi Code / Cursor Agent
- Agent 任务 = 长上下文（整个代码库）+ 多轮工具调用 + 多次上下文重放 → 单任务轻松消耗 10万-85万 tokens（GLM-5.2 实测文档佐证）
- 订阅制下"无限 Agent 请求"的承诺 = 对厂商的**无上限负债**；Cursor 被迫引入"Extended limits"分级（Pro/Pro+/Ultra 3x/20x），本质是**用量分层定价的雏形**

#### L3 价格透明化

- 2025-2026 国产模型价格战：DeepSeek V4 Flash 缓存命中 ¥0.02/M（合 $0.003/M）——比 2024 年 GPT-4 时代低了 3 个数量级
- 当 API 价格公开可查，用户可计算：订阅 ¥59/月 ÷ 实际可用量 = 隐含 token 单价；若隐含单价 > 公开 API 单价，则订阅无价值
- **信息经济学**：订阅制靠"打包模糊定价"获利，token 化把定价权交还给透明的单位成本

#### L4 企业治理（B 端刚需）

- 企业采购 AI 编程工具的决策者关心：钱花在哪？每个团队/项目消耗多少？是否超预算？
- 订阅制按人头（per-seat）无法回答"每个 token 花多少钱"；Token Plan + 用量面板（Cursor Admin Dashboard / Copilot cost center / OpenCost）直接对齐 FinOps
- 2026 企业 AI 开支进入"ROI 审计期"（Rippling 自建 ROI 工具实证）——**可计量是治理的前提**

#### L5 厂商策略（供给侧动机）

- **风险转嫁**：GPU 算力价格波动（HBM 涨价 5×）下，订阅制让厂商承担全部成本波动；token 制把成本波动转嫁给用量方
- **数据获取**：Token Plan 让厂商获得精确的模型用量/场景分布数据，支撑模型路由（Cursor Router 预测器 -68% 成本）与容量规划
- **峰谷定价**：DeepSeek 8/17 起峰谷定价（高峰 9-12/14-18 点 2 倍价）= 用价格信号引导错峰，优化算力利用率——**这是算力商品化的标志性操作**，只有 token 计费才能实现

## 4. 国内经济方案全景对比

### 4.1 对比维度说明

用户要求"综合成本"= **大模型质量 × 支持调用次数 × 成本** 三维度。定义：

- **模型质量**：参考知识库 08-03 模型能力对比（LLMRank 评分口径）：Kimi K3=57（第一梯队）、GLM-5.2=50-54 区间（第二梯队开源 SOTA）、DeepSeek V4 Flash=50（第二梯队地板价）、Qwen3.8=46+（第三梯队）
- **调用次数**：该方案在预算内可支撑的月调用量（按典型 Agent 任务 3万 tokens/次估算）
- **成本**：月度实际支出（含免费额度折算）

### 4.3 成本敏感性分析（关键）

**示例：一个中等强度开发者（月 100 次 Agent 请求 × 3万 tokens = 300 万 tokens，输入:输出=3:1）**

## 5. 决策框架

### 5.1 三步决策法

```
Step 1: 测用量 → 用 API 或免费层跑 1 周，记录 token 消耗
Step 2: 算账 → 月 tokens × 单价 vs 订阅价（meth-016 判断式）
Step 3: 选模型档 → 你需要 46 分（够用）还是 61 分（前沿）？
```

### 5.2 场景化建议

| 场景 | 推荐方案 | 理由 |
|:-----|:---------|:-----|
| 个人轻度（<50 轮/月） | 通义灵码免费版 / 免费 API 额度 | 零成本，够用 |
| 个人中度（100-300 次/月） | **DeepSeek V4 API（主力）+ 免费 IDE 插件** | 成本 ¥5-30/月，国产开源档质量足够 |
| 个人重度 Agent 用户（>500 次/月） | DeepSeek V4 Pro / GLM Coding Plan | 按量成本可控，订阅防超支 |
| 团队（10-50 人） | 通义灵码企业版 / 混合（订阅+API 兜底） | 治理需求优先，per-seat 便于分摊 |
| 追求前沿模型（61 分） | Cursor Pro/Pro+ / Kimi Code | 模型能力是订阅溢价的核心来源 |
| 隐私/离线/成本硬约束 | 本地部署（Ollama + Qwen/GLM 开源） | 一次性硬件摊薄，长期边际成本趋零 |

### 5.3 组合策略（推荐）

**"免费层 + 按量 API + 订阅兜底"三层结构**：

```
日常简单任务  → 免费层（通义灵码免费版 / Copilot free）
主力开发任务  → DeepSeek V4 API 按量（成本 ¥10-30/月）
关键复杂任务  → 订阅制前沿模型（Cursor/Kimi，按需）
```

这个组合兼顾成本与能力：国产开源档模型（46-54 分）承担 80% 日常任务，前沿模型（57-61 分）只用于 20% 高价值任务，综合成本可压到纯订阅制的 1/5-1/10。

## 6. 风险与趋势预判

### 6.1 风险

| 风险 | 说明 | 缓解 |
|:-----|:-----|:-----|
| **峰谷定价波动** | DeepSeek 8/17 起高峰 2 倍价，成本不可预期 | 错峰执行批量任务；监控用量面板 |
| **价格战不可持续** | 国产 API 地板价靠补贴/低毛利，可能回调 | 锁定年付/预留额度；关注厂商财报 |
| **模型质量差距** | 开源档（46-54 分）与前沿（61 分）在复杂任务上仍有差距 | 分层使用，不迷信单一方案 |
| **订阅制反扑** | 厂商可能用"订阅+硬用量上限"限流（如 Cursor Ultra 20x） | 计算实际可用量，避免"名义订阅实为按量" |
| **治理缺失** | 按量模式下个人开发者可能失控（token 账单膨胀） | 设预算告警（OpenCost / API 用量面板） |

### 6.2 趋势预判（2026H2-2027）

1. **"订阅=预付费折扣包"成为标准形态**：Cursor 已示范，国内（智谱/月之暗面）将跟进——订阅不再代表"无限量"，而是"折扣 + 上限"，超出自动按量
2. **峰谷/动态定价普及**：DeepSeek 8/17 起峰谷定价是行业首例，将带动国产厂商跟进（算力商品化定价）
3. **模型中立平台化**：Copilot 已接入 Kimi K3/Gemini/MAI 多模型按 provider 计费——平台从"卖单一模型"转向"卖模型市场"，token 计费是支撑多模型分账的基础设施
4. **FinOps 工具爆发**：token 级成本追踪（OpenCost）从 K8s 推理向开发工具链延伸——"每个 token 花多少钱"成为研发管理的标配问题
5. **免费层成为获客漏斗**：通义灵码免费版 50 轮/月、DeepSeek 赠送余额——免费层用于培养使用习惯，按量层承接溢出需求
