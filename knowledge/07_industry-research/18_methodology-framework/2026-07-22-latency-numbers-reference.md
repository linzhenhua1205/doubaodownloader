### 2.2 互连线延迟

#### 2.2.1 不同工艺下的线延迟对比

| 工艺 | 局部线 (10μm) | 中等线 (1mm) | 全局线 (10mm) | 线延迟占总延迟比 |
|:-----|:-------------:|:------------:|:--------------:|:----------------:|
| 180nm | ~0.5 ps | ~5 ps | ~500 ps | ~30% |
| 90nm | ~0.8 ps | ~15 ps | ~800 ps | ~40% |
| 45nm | ~1.2 ps | ~40 ps | ~1200 ps | ~55% |
| 28nm | ~1.5 ps | ~80 ps | ~1500 ps | ~60% |
| 16nm | ~1.8 ps | ~150 ps | ~1800 ps | ~65% |
| 7nm | ~2.0 ps | ~300 ps | ~2200 ps | ~70%+ |
| 5nm | ~2.5 ps | ~500 ps | ~2500 ps | ~75%+ |
| 3nm | ~3.0 ps | ~700 ps | ~3000 ps | ~80%+ |

> **核心洞察**: 在线延迟占主导的节点下，**物理布局的远近**比逻辑优化更重要。

#### 2.2.2 互连线延迟公式

```text
t_wire ≈ 0.5 × R_wire × C_wire = 0.5 × ρ × ε × L² / (W × t)

其中:
  R_wire = ρ × L / (W × t)     — 导线电阻
  C_wire = ε × W × L / H        — 导线电容（简化平行板模型）
  L = 线长, W = 线宽, t = 线厚, H = 介质高度
```

**关键结论**: 互连线延迟与线长 **L² 成正比**。中继器 (Repeater) 将平方退化回线性关系。

#### 2.2.3 典型互连结构传输延迟

| 互连结构 | 信号速度 | 延迟常数 | 10mm 传输延迟 |
|:---------|:--------:|:--------:|:-------------:|
| 全局铜互连 (顶层厚金属) | ~1.5×10⁸ m/s | ~6.7 ns/m | ~67 ps |
| 中间层铜互连 | ~1.0×10⁸ m/s | ~10 ns/m | ~100 ps |
| 局部铜互连 (底层细线) | ~0.5×10⁸ m/s | ~20 ns/m | ~200 ps |
| 硅通孔 (TSV, 3D stacking) | — | ~2-5 ps/TSV | — |
| 片上光互连 (未来) | ~2.0×10⁸ m/s | ~5 ns/m | ~50 ps |

### 2.3 时钟与时序

#### 2.3.1 时钟域基本参数

| 参数 | 典型值 | 说明 |

#### 4.2.2 板级传播延迟物理约束

```text
光速: c ≈ 3×10⁸ m/s = 30 cm/ns
PCB 信号: v ≈ 0.45-0.55c ≈ 15-16.5 cm/ns
⇒ 1 ns 在 PCB 上 ≈ 15-16 cm 走线
⇒ 1 mm 走线 ≈ 6-7 ps
```

**常见板级物理约束**:

- 标准 ATX 主板宽度 ~24 cm → 跨板延迟 ~1.5 ns
- 服务器主板 ~33×30 cm → 对角线 ~45 cm → ~2.8 ns
- 大型背板 (14-16 slot) ~50 cm → ~3.1 ns
- 内存走线等长约束 (DDR5, 目标 ±1mm) → 时序裕度 ~±7 ps


## §12 延迟快速估算公式

> 本节提供不需要计算器的延迟/带宽/排队速算公式，适用于"口算"场景。

### 12.1 传输延迟

```text
t_transmission = 数据量 / 带宽

速算:
  数据量 1KB @ 10Gbps  ≈ 0.8 μs  (精确: 1KB × 8 / 10Gbps = 0.8 μs)
  数据量 1MB @ 100Gbps ≈ 80 μs  (精确: 1MB × 8 / 100Gbps = 80 μs)

经验法则:
  "8x" 规则: 延迟(μs) ≈ 数据量(字节) × 8 / 带宽(bps) × 10⁶
  或: 1KB 在 1Gbps = 8μs, 在 10Gbps = 0.8μs, 在 100Gbps = 0.08μs
```

### 12.2 排队延迟 (M/M/1)

```text
t_queue = (ρ / (1 - ρ)) × t_service   (M/M/1 模型)

其中:
  ρ = 利用率 (0-1), t_service = 平均服务时间

速算:
  ρ=0.50 -> t_queue = 1.0 × t_service  (平均等待=服务时间)
  ρ=0.75 -> t_queue = 3.0 × t_service
  ρ=0.90 -> t_queue = 9.0 × t_service
  ρ=0.95 -> t_queue = 19 × t_service
  ρ=0.99 -> t_queue = 99 × t_service

经验法则:
  "利用率超过 70%, 排队延迟开始快速增长"
  "利用率超过 90%, 排队延迟是服务时间的 ~10x"
  实际系统在 ρ>0.8 时应当扩容或降载
```

### 12.3 串行化延迟

```text
t_serial = 数据包大小 (bit) / 链路速率 (bps)

速算:
  最小以太网包 (64B + 20B 开销) = 84B
    @ 1Gbps: 84B × 8 / 1Gbps = 672 ns ≈ 0.7 μs
    @ 10Gbps: ~67 ns
    @ 100Gbps: ~6.7 ns
    @ 400Gbps: ~1.7 ns

  MTU 1500B 包:
    @ 1Gbps: 1500B × 8 / 1Gbps = 12 μs
    @ 10Gbps: 1.2 μs
    @ 100Gbps: 0.12 μs = 120 ns

经验法则:
  每增加 10 倍速率, 串行化延迟减少到 1/10
  高带宽主要减少大包的串行化延迟, 对小包影响有限
```

### 12.4 Little's Law

```text
L = λ × W

其中:
  L = 系统中平均请求数 (In-flight)
  λ = 到达率 (请求/秒)
  W = 平均响应时间 (秒)

应用示例:
  目标响应时间 W=10ms, 系统容量 L=100 in-flight
  -> 最大吞吐 λ = L/W = 100 / 0.01 = 10,000 req/s

经验法则:
  "in-flight 请求数 = 延迟 × 吞吐"
  这是系统容量规划的核心公式
  高延迟系统需要更多并发才能达到同等吞吐
```

### 12.5 Amdahl 定律的延迟形式

```text
t_optimized = t_parallelizable / N + t_serial

其中:
  t_optimized = 优化后总延迟
  t_parallelizable = 可并行化部分延迟
  N = 并行度
  t_serial = 不可并行化的串行部分

速算:
  如果 90% 可并行, 10% 串行:
    N=2 -> t_opt = 0.9/2 + 0.1 = 0.55 (= 原始 55%)
    N=8 -> t_opt = 0.9/8 + 0.1 = 0.2125 (= 原始 21%)
    N=∞ -> t_opt = 0.1 (= 串行部分成为瓶颈)

经验法则:
  "串行部分决定延迟下限"
  优化延迟时, 先找到串行瓶颈, 而不是盲目增加并行度
```

### 12.6 网络延迟分解

```text
RTT = t_propagation × 2 + t_serial × 2 + t_queue × 2N + t_processing × N

其中:
  t_propagation = 单程传播延迟 = 距离 / (光在介质中的速度)
  t_serial = 串行化延迟 = 包大小 / 链路速率
  t_queue = 交换机每跳排队延迟
  N = 跳数
  t_processing = 交换机每跳处理延迟 (转发决策)

速算:
  同数据中心 RTT ≈ 2 × 距离(km)/204 + 串行化 × 2 + 跳数 × (500-2000ns)
  ≈ 5-20 μs/km (光纤) + 设备延迟

经验法则:
  "1m 光纤 ≈ 5ns 传播延迟"
  "1km 光纤 ≈ 5μs 传播延迟"
  "交换机延迟 300-1500ns/跳"
  "短距 RTT 主要由设备延迟决定, 长距由光速决定"
```

### 13.3 常见误解辨正

| 误解 | 事实 |
|:-----|:------|
| **"高带宽 = 低延迟"** | 带宽影响吞吐（能做多少），延迟是独立属性（多快开始）。1Gbps 和 400Gbps 的光纤传播延迟是一样的（~5ns/m）。带宽减少**串行化**延迟，不影响传播延迟。 |
| **"光纤比铜缆快"** | 光纤的光速 (~2.04×10⁸ m/s) 和铜缆的电信号速度 (~1.5-2.0×10⁸ m/s) 在同一量级。光纤的优势是距离、带宽、抗干扰，不是信号速度。 |
| **"DDR5 的 CL 值比 DDR4 高所以更慢"** | CL 是从周期数变时间数。DDR4-3200 CL22 = 13.75ns，DDR5-6400 CL42 = 13.125ns。实际时间延迟**几乎没变**。 |
| **"SSD 比 HDD 快 100 倍"** | 延迟上确实如此（~50μs vs ~10ms ≈ 200x），但顺序带宽差距仅 ~3-10x。场景不同结论不同。 |
| **"TCP 很慢，应该全用 RDMA"** | RDMA 在小消息场景下优势明显（~1-2μs vs ~10-50μs），但在大消息下带宽是主要瓶颈，TCP 的差距缩小。且 RDMA 管理成本（内存注册/保护域）显著高于 TCP。 |
| **"Tail Latency = Avg × 固定倍数"** | 尾延迟与平均延迟没有固定关系。在负载增加时，99.9th 可能从 2× 跳到 50×（排队效应）。测量才知道。 |
| **"加缓存一定能降低延迟"** | 缓存降低**平均**延迟，但可能增加**尾延迟**（缓存未命中的代价更高）。且缓存一致性维护可能引入额外延迟。 |
| **"云计算比自建延迟高很多"** | 同可用区内云主机网络延迟 ~0.1-0.5ms（含虚拟化开销），和自建物理机 ~0.05-0.2ms 差距在一个量级内。跨可用区（同城）才显著增加。 |
| **"PCIe Gen5 比 Gen4 快一倍"** | 带宽确实翻倍，但延迟**没有翻倍**（~80-150ns vs ~60-120ns，仅 ~25% 改善）。带宽主要减少串行化延迟，对传播和处理延迟影响有限。 |
| **"AI 推理延迟等于模型计算时间"** | 推理延迟 = 计算 + 数据传输 + 通信（多卡）+ 框架调度 + 预处理/后处理。小模型场景下，框架和数据搬运开销可能占 50%+。 |
