## §0 执行摘要

知识库工程的核心目标不是「装更多东西」，而是**确保每一条知识产出可溯源、可验证、有归属**。这与代码工程的追求（可测试、可维护、可复现）**底层逻辑完全同源**。

**核心体系**：

```text
Skill (加工单元 — 能力边界契约)
   v 产出原始知识条目
Clipper (校验器 — 准入控制)
   v 通过后入库
四层信息模型 (raw -> processed -> core -> meta)
   v 持续治理
巡检健康度 (周期性自我检测)
```

**关键原则**：

1. **不信任默认产出**：每一条知识产出必须通过显式校验才允许入库
2. **权限分层**：原始数据只读，加工数据可编辑但需标注来源，深度知识需人工复核
3. **溯源强制**：结论必须绑定原始素材索引，缺失溯源直接阻断流程
4. **单点维护约束**：所有校验规则集中在 `00_rules/`，不分散到各业务模块

## §1 为什么知识工程需要约束体系？

### 1.1 知识工程与代码工程底层同源

| 代码工程 | 知识工程 |
|:---------|:---------|
| 函数/模块 → 输入输出契约 | Skill → 加工能力契约 |
| 编译器/类型检查 → 语法校验 | Clipper → 结构/格式校验 |
| 单元测试 → 逻辑正确性验证 | 溯源校验 → 事实正确性验证 |
| CI/CD → 自动化质量流水线 | 知识CI → 自动化知识加工流水线 |
| 代码审计/Review → 人工复核 | 置信标签+人工审查 → 深度知识核准 |

**核心认知**：知识库模块、服务器/超节点系统，底层逻辑同源——分布式体系下，**每个处理单元必须具备自检、入参校验、输出合规检查**。

### 1.2 知识工程特有的三大质量威胁

| 威胁 | 表现形式 | 在代码工程中不存在的原因 |
|:-----|:---------|:-----------------------|
| **幻觉** | AI生成无依据的伪知识 | 编译器不会编造不存在的函数 |
| **片面结论** | 仅考虑单一场景，忽略了完整约束 | 单元测试要求覆盖全部分支 |
| **过时信息** | 旧知识未标记过期，被当作有效内容使用 | 代码版本被Git明确标记 |

## §2 Skill + Clipper 双层约束体系

### 2.1 Skill：加工单元的能力契约

Skill 是知识加工的基本单元，定义清晰的输入输出边界。

**Skill 契约结构**：

```text
Skill 名称
+-- 功能描述      # 这个Skill负责什么加工
+-- 输入要求      # 数据格式、Schema、约束条件
|   +-- 必填字段
|   +-- 可选字段（含默认值）
+-- 输出契约      # 产出物格式、质量要求
|   +-- 产出物Schema
|   +-- 通过条件（Clipper校验规则引用）
+-- 异常处理      # 输入不合格/执行失败时的行为
|   +-- 重试策略
|   +-- 降级方案
+-- 依赖关系      # 前置Skill、共享数据
```

### 2.2 Clipper：质量校验器

Clipper 是知识质量的剪刀手——在每个准入节点进行质量检查。

**Clipper 校验类型**：

| 校验类型 | 内容 | 严重程度 |
|:---------|:------|:--------:|
| 格式校验 | 是否符合Schema规范、字段完整性 | 阻断 (Block) |
| 溯源校验 | 结论是否绑定原始素材索引 | 阻断 (Block) |
| 事实校验 | 量化数据是否可验证、矛盾检测 | 告警 (Warn) |
| 一致性校验 | 新旧知识是否冲突 | 告警 (Warn) |
| 时效性校验 | 信息是否过时/需更新 | 提示 (Info) |

**Clipper 输出示例**：

```json
{
  "status": "BLOCKED",
  "rule": "traceability_check",
  "reason": "结论「跨节点Load/Store延迟≤1μs」缺少原始来源索引",
  "suggestion": "补充标定测试报告链接或厂商官方规格文档索引",
  "blocking": true
}
```

### 2.3 双层协同：流水线中的定位

```text
输入素材
    v
[前置检查] -> Clipper: 素材格式合格？
    v (通过)
Skill A: 信息提炼/结构化
    v
[过程拦截] -> Clipper: 核心字段完整？
    v (通过)
Skill B: 深度分析/推演
    v
[后置校验] -> Clipper: 溯源+事实+一致性检查
    v (通过)
入库 -> 标记置信标签 -> 人工抽样复核
```

## §3 约束检查的触发时机模型

### 3.1 前置检查 (Pre-Check)

素材进入加工流水线之前：

```text
素材质量门：
+-- 格式验证          -> 是否符合可解析格式
+-- 完整性验证        -> 关键字段是否缺失
+-- 源可信度评估      -> 来源可靠性分级
+-- 去重检测          -> 是否已有相同内容
```

### 3.2 过程拦截 (Mid-Process)

加工过程中监听异常信号：

```text
处理中拦截点：
+-- 字段必填检查      -> Skill输出是否满足Schema
+-- 边界值校验        -> 量化数据是否在合理范围内
+-- 业务规则检查      -> 是否违反领域规则
+-- 运行时异常捕获    -> Skill执行失败的处理
```

### 3.3 后置校验 (Post-Validation)

加工完成后，入库前：

```text
最终质量门：
+-- 全字段完整性检查  -> 必填字段100%覆盖
+-- 溯源链完整检查    -> 每一条结论都可追溯到raw层
+-- 交叉验证          -> 跨Skill产出是否一致
+-- 置信度评估        -> 自动分配置信等级
+-- 入库标记          -> 置信度高 -> 直接入库
                        置信度中 -> 待人工复核
                        置信度低 -> 退回Skill重做
```

## §4 四层信息模型与每一层的约束规则

### 4.1 四层模型概览

| 层 | 名称 | 内容 | 修改权限 | 溯源要求 | 置信标签 |
|:---|:-----|:------|:--------:|:---------|:---------|
| L1 | **Raw** (原始信息) | 外部导入素材、原始日志、截图、文档原稿 | **只读** | 来源URL必须留存 | 来源可靠性分级 (A/B/C) |
| L2 | **Processed** (加工信息) | AI初步提炼、脚本清洗结构、要点摘录 | 可编辑 | 必须标注来源raw索引 | 标注处理时间 + 使用的Skill版本 |
| L3 | **Core** (深度知识体系) | 体系化方案、架构设计、原理分析、权衡判断 | 仅可追加修订 | 必须标注来源L2/L1索引 | 置信等级 (verified / reviewed / draft) |
| L4 | **Meta** (元数据) | 索引、血缘关系、校验记录、约束清单、变更日志 | 自动维护 | 自动关联 | N/A |

### 4.2 层间流转的血缘追踪

```text
L1: raw/test_report_0715.md
       v (Skill: 结构化提取)
L2: processed/test_report_summary.md
  +-- source: L1/test_report_0715.md
  +-- skill_version: extractor_v2.1
       v (Skill: 深度分析)
L3: core/network_latency_analysis.md
  +-- source: L2/test_report_summary.md
  |            L1/test_report_0715.md
  +-- confidence: reviewed
       v (自动)
L4: meta/lineage.yaml
  +-- uid: k_00128 -> L3/core/... -> L2/... -> L1/...
```

**强制规则**：任何结论如果无法正向/反向追踪到 L1 原始数据，则**不被认可为有效知识**。

## §5 Discovery 自动化流水线设计

### 5.1 流水线架构

将「从线索/问题自动滚动产出结构化知识条目」的完整工作流设计为：

```text
Discovery 线索 (问题/方向/关键词)
    v
Stage 1: 素材检索拉取
    +-- 知识库已有内容的语义检索
    +-- 外部来源 (web/news) 按需抓取
    v Clipper：素材可信度评估
Stage 2: Skill拆解任务
    +-- 识别需要哪些加工Skill
    +-- 编排执行顺序 (依赖DAG)
    v Clipper：任务合法性检查
Stage 3: 多轮信息萃取
    +-- 结构化摘要生成
    +-- 量化数据提取与交叉验证
    v Clipper：溯源绑定
Stage 4: 初步知识产出
    +-- 输出初稿 (L2/L3 格式)
    +-- 置信等级自动评估
    v Clipper：最终质量门（溯源+事实+一致性）
Stage 5: 入库/标记待检
    +-- 高置信 -> 自动入库 (标记为draft)
    +-- 中置信 -> 待人工复核
    +-- 低置信 -> 退回Stage 2/3
```

### 5.2 灰度验证策略

| 版本 | 范围 | 自动化程度 | 质量控制 |
|:-----|:------|:----------:|:---------|
| V0.1 | 线索→素材提取+初稿生成 | 50% | 全部输出至审核目录，人工100%审查 |
| V0.2 | + 接入Clipper校验流水线 | 70% | 自动拦截不合格内容，输出校验报告 |
| V0.3 | + 开放小范围自动入库 | 85% | 增加随机抽样巡检 (10%深度复审) |
| V1.0 | + 回流学习 + 质量看板 | 90% | 持续监控置信度分布 |

### 5.3 溯源阻断机制

**核心规则**：每一条结论必须绑定原始素材索引，缺失溯源直接阻断流程。

```yaml
溯源阻断条件:
  - L3结论无对应的L2来源引用
  - L2加工信息无对应的L1 raw层引用
  - 量化数据无来源标注（测试报告/规格文档/官方数据）

阻断后动作:
  - 产出物标记为"unsourced_trash"
  - 自动跳转到审核目录，不进入主知识库
  - 生成审计日志，记录缺失的溯源环节
```

## §6 Token 成本约束机制

将成本控制嵌入每一条工作流，避免无节制调用LLM。

### 6.1 分层调度策略

| 处理类型 | 执行路径 | 模型花费 |
|:---------|:---------|:--------:|
| 素材清洗/格式化/降噪 | **本地脚本预处理** | 0 Tokens |
| 简单结构化/要点提取 | 低成本模型 | 低级 |
| 事实推理/深度知识合成 | 高阶模型 | 高级 |
| 缓存复用 (相同输入) | 直接返回缓存结果 | 0 Tokens |

### 6.2 分级模型路由

```text
输入内容
    v
复杂度评估
+-- 简单任务 (< 200 tokens, 格式化/提取)
|   +-- 路由到低成本模型
+-- 中等任务 (200-2000 tokens, 摘要/结构化)
|   +-- 路由到中成本模型
+-- 复杂任务 (> 2000 tokens, 深度分析/权衡)
    +-- 路由到高阶模型
```

**额外规则**：

- 建立准入白名单：明确哪些内容**不进入**LLM流水线，仅本地离线处理
- 重复查询自动缓存：相同输入直接返回缓存结果
- 定期复盘Token消耗，建立成本监控看板

## §7 知识库健康度巡检机制

类比服务器集群巡检，知识库同样需要常态化运维。

| 巡检项 | 周期 | 检测目标 |
|:-------|:----:|:---------|
| 孤立页面检测 | 每周 | 无任何入链引用的废弃页面 |
| 重复概念检测 | 双周 | 相同/相近内容的多份冗余 |
| 矛盾结论检测 | 双周 | 新旧知识互相冲突 |
| 死链接检测 | 每周 | 索引/文档中的断裂引用 |
| 时效性检查 | 月 | 标记超期未更新的知识条目 |
| 置信度分布查看 | 月 | 各层级置信标签的分布状况 |

**输出**：《知识库健康度报告》，包含：

- 页面总数、有效条目数、废弃数
- 重复/矛盾条目清单
- 死链接清单及其影响的文档范围
- 置信度热力图（哪些领域置信度偏低）
- 建议优先处理的维护项
