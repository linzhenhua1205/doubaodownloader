## 1. 引言：为什么需要显式定义"强逻辑"

### 1.1 问题定义

在本系统的运行、知识库构建和技术文档产出的实践中，"逻辑严密"始终是最高质量标准之一。AGENT.md明确要求"逻辑严密：结论由推理链条导出，禁止跳跃"。MEMORY.md将"逻辑自检13条谬误"列为必检项。

但一个根本问题始终未被显式回答：

> **"强逻辑"到底是什么？当我们在说"这条论证逻辑强"时，我们到底在测量什么？**

没有统一特征定义，逻辑审查就变成：

- 凭感觉判断（"这条论证感觉不太对"）
- 靠谬误清单打补丁（"看起来没命中已知谬误，所以逻辑没问题"）
- 事后诸葛亮（"结果对了=当时逻辑强"）

### 1.2 本文的层级定位

```text
方法论层（已有）                   概念层（本文）
-----------------               -----------------
MECE (分类方法)                   强逻辑的特征 (What)
第一性原理 (还原方法)              达成方案 (How)
13条谬误 (负面清单)                谬误分类体系 (WhatWrong)
因果识别 (归因方法)                 防御体系 (Defend)
                                 检测技能 (Detect)
```

本文补齐了**"正面定义→达成方案→负面分类→系统防御→技能生成"**的完整链路。

### 1.3 自指性声明

本文本身就是一个逻辑论证。它的质量受本文所定义的"强逻辑"标准检验。读者（包括AI自己）可在阅读后，用第2章的五维特征和第4章的谬误分类来审查本文——如果本文通过审查，则自证其论点；如果未通过，则自反其论点。这是一种**自指验证设计**。

## 2. 强逻辑的特征体系

### 2.1 从第一性原理推导

#### 2.1.1 逻辑的根本目的

逻辑不是目的本身。逻辑的根本目的是：**在最少的认知资源下，将信念收敛到真理（True Belief）**。

从信息论视角：

- 一个论证从一组前提(信息源)出发，经过推理变换(信道)，到达结论(接收端)
- 逻辑谬误是信道中的噪声——使结论偏离前提所蕴含的信息
- "强逻辑" = 高信噪比的信道：前提中的信息被最大程度保留到结论中

从控制论视角：

- 论证是一个负反馈系统：结论是否正确需要与事实（外部参考信号）对比
- 谬误发生时，反馈环断裂——要么结论不再受前提约束，要么与事实的对比被跳过
- "强逻辑" = 闭环完整的论证系统

#### 2.1.2 推导出的核心要求

由上述目的可推导出五条核心要求：

| # | 要求 | 第一性原理推导 | 反例信号 |
|:-:|:-----|:---------------|:---------|
| 1 | **完整性** | 信息从前提传递到结论，中间步骤不能缺失 → 缺失则信息传递断裂 | "显然/因此/所以"三字跳步 |
| 2 | **一致性** | 同一系统内的信息不能互相矛盾 → 矛盾则信道中信息冲突，无法收敛 | 前后数据打架、同样概念不同含义 |
| 3 | **有效性** | 如果前提真则结论必然真 → 否则信道有函数错误 | 前提都对了但结论不对 |
| 4 | **相关性** | 结论只能包含前提中蕴含的信息（或可推导信息）→ 引入外部无关信息则引入额外噪声 | 诉诸权威/诉诸情感 |
| 5 | **精确性** | 信息的粒度必须支撑主张的强度 → 粗粒度信息无法支撑精确结论 | 模糊词("很多/显著")配精确断言("证明") |

### 2.2 五维特征模型

#### 2.2.1 完整性 (Completeness)

**定义**: 论证链条的中间步骤全部显式出现，无隐藏假设，无跳跃。

**度量**（定性）:

- **步骤密度** = 显式推理步骤数 / 结论与前提之间的语义距离
- 理想值：每步的语义跨度≈一个"如果X则Y"的最小可判定单元

**形式化表示**:

```text
强完整性: P -> S₁ -> S₂ -> ... -> Sₙ -> C    (n ≥ 2，每步可单独验证)
弱完整性: P -> -> -> -> C                    (中间步骤被压缩)
零完整性: P -> C                           (结论直接声称，无推理过程)
```

**典型强化方案**:

- 显式列出每个推理步骤（Toulmin论证模型）
- 对每个步骤标注其支撑证据类型（数据/权威/常识/已证命题）
- 对隐藏假设做显式声明

#### 2.2.2 一致性 (Consistency)

**定义**: 论证系统内部无逻辑矛盾——任何两个命题不能被同时证明为真和假。

**度量**:

- **内部一致率** = 1 - (矛盾命题对 / 总命题对)
- **跨文档一致率** = 同概念的跨文件表述一致性

**子类型**:

| 子类 | 定义 | 检测方法 |
|:-----|:-----|:---------|
| 纵向一致 | 同一论证链中前后不矛盾 | 穿行测试：前提到结论的逻辑跟踪 |
| 横向一致 | 不同来源或章节中对同一对象描述一致 | 跨段/跨文件交叉对比 |
| 术语一致 | 同一术语在不同语境下含义相同 | 术语表+术语溯源 |
| 时间一致 | 同一指标在不同时间点可比（口径不变） | 口径声明+版本对比 |

**典型强化方案**:

- 单篇文档：术语表+正式定义位置标注
- 跨文档：`@ref`标记规范（见methodology/2026-07-16-content-ref-consistency-system.md）
- 数据口径：每项数据标注测量方式、时间、单位

#### 2.2.3 有效性 (Soundness)

**定义**: 如果所有前提为真，则结论必然为真（validity）+ 前提实际为真（soundness）。

有效性拆分为两层：

```text
有效性(Soundness) = 形式有效(Validity) ∧ 实质真实(Truth of Premises)

形式有效: 即便前提是假的，如果它们是真的，结论也必须是真的
          例：如果A>B且B>C则A>C（即使A/B/C是虚构事物，逻辑依然有效）
实质真实: 前提在真实世界中为真
          例：A=10, B=5, C=1（数值符合事实）
```

**常见失效模式**:

- 形式有效但前提假（如"所有AI都是人类 → 小龙猫是AI → 小龙猫是人类"——前提一为假）
- 前提真但形式无效（如"大部分服务器是x86 → 这台服务器是x86"——中项不周延）
- 循环论证：前提等价于结论（形式有效但无信息增量）

**典型强化方案**:

- 前提标注来源（来源可验证是真实性的基础）
- 形式化检查（将自然语言论证转录为逻辑表达式，检查有效性）
- 依赖图：标注结论所依赖的所有前提

#### 2.2.4 相关性 (Relevance)

**定义**: 推理中使用的所有信息都与结论有直接或间接的逻辑关联。

**违反形式**:

| 形式 | 表现 | 示例 |
|:-----|:-----|:------|
| 信息冗余 | 引入与结论无关的数据/事实 | "这个项目用的是NVIDIA GPU"（讨论散热方案时） |
| 诉诸权威 | 用发言者的权威替代论证 | "黄仁勋说……因此……" |
| 诉诸情感 | 用情感替代推理 | "如果不采用这个方案，团队会很失望" |
| 诉诸人数 | 用多数人认同替代论证 | "行业90%的公司都在用" |
| 红鲱鱼 | 引入无关话题转移注意力 | "这个架构问题虽然存在，但我们的竞争对手更差" |
| 稻草人 | 歪曲对方论点然后攻击 | "你说方案A好 = 你否定一切现有系统" |

**典型强化方案**:

- 每段开头标注"本段论证的目标结论"
- 论证完成后反向溯源：结论所依赖的信息是否都在前提中
- "稻草人检测"：引述他人观点必须原文引用，禁止转述后再攻击

#### 2.2.5 精确性 (Precision)

**定义**: 信息表达的粒度与主张强度相匹配——不说过头话，不假装精确。

**核心原则**: **主张强度 ≤ 证据强度**

| 证据强度 | 可支持的主张 |
|:---------|:-------------|
| 严格数学证明 | 必然性主张("必定/一定") |
| 受控实验(n≥3, 独立验证) | 因果性主张("导致/提升") |
| 大样本相关分析 | 相关性主张("相关/关联") |
| 单一样本/案例 | 可能性主张("可能/有案例") |
| 理论推导(无实证) | 假设性主张("理论上/推测") |

**精确性四要素**（量化数据）:

1. **数值**: 精确值（非"很多/很少/显著"）
2. **单位**: 跨域可比的统一单位
3. **对比基线**: "什么水平上的提升/下降"
4. **条件**: "在什么条件下测得的"

**典型强化方案**:

- 强度标记体系：在每个结论前标记其证据类型(证明/实验/相关/案例/推测)
- 模糊词替换：将"显著提升"改为"在X条件下提升Y%（95% CI: [a,b])"
- "假精确"检测：声称小数点后3位但前两位已经在误差范围内

### 2.3 特征之间的张力与平衡

五维特征并非总是同向变化的。实际应用中，它们之间存在系统性张力：

| 张力对 | 冲突本质 | 平衡策略 |
|:-------|:---------|:---------|
| **完整性 ↔ 可读性** | 步骤越细越难读 | 主链显式+支链引注（正文完整，附录详述） |
| **精确性 ↔ 可证性** | 越精确的断言需要越强的证据支撑，但证据总是不完美的 | 精确性随证据强度校准（不超出证据能支撑的范围） |
| **一致性 ↔ 完整性** | 追求完全一致可能导致信息损失（不同来源各贡献一个角度） | 显式标注不一致的来源，不强制消除（如"来源A说X，来源B说Y"） |
| **相关性 ↔ 完整性** | 为保持相关性可能裁剪掉重要背景上下文 | 背景在引言/附录中保留，标注"背景性质不参与论证" |
| **精确性 ↔ 简洁性** | 精确描述需要更多限定词 | 结论句留精确的限定，简洁版+精确版分版呈现 |

**本系统的平衡实践**: AGENT.md中"表格>段落"的指令本质上是倾向精确性和相关性（表格结构天然抑制模糊和冗余），但需要人工干预完整性（表格容易省略推理步骤）。

### 2.4 弱逻辑的识别信号

在实际审查中，不需要完成完整的五维测量，以下信号可快速标记弱逻辑：

| 信号 | 对应维度 | 严重度 |
|:-----|:---------|:------:|
| "因此/所以/那么"连接了两个缺乏直接推导关系的句子 | 完整性 | 🔴 |
| 前后段落中同一概念的数据不一致 | 一致性 | 🔴 |
| 使用了强断言（"证明/必定/毫无疑问"）但来自单一非权威来源 | 有效性 | 🔴 |
| 论述某个问题时引入了明显无关的话题或数据 | 相关性 | 🟡 |
| 用模糊词（"显著/明显/众多"）撑起的核心结论 | 精确性 | 🔴 |
| 多个"层次"可以互相推导或互为特例 | 完整性 | 🟡 |
| 文档开头已有结论，后续论证只是为结论找支持 | 有效性 | 🔴 |
| 不同论证模型的结论互相冲突但未察觉 | 一致性 | 🔴 |

## 3. 达成强逻辑的方案体系

### 3.1 结构性方案

结构性方案从论证的骨架入手，在内容生成之前就定义了逻辑的组织方式。

#### 3.1.1 MECE (Mutually Exclusive, Collectively Exhaustive)

**原理**: 将论证空间划分为互斥且穷尽的子空间，确保推理覆盖所有可能性且不重复。

**逻辑增强机制**:

- **互斥 → 抑制重复论证**: 两项论证指向同一结论的不同方面，但有重叠时，读者无法区分"这是新证据还是旧证据的另一种说法"
- **穷尽 → 抑制遗漏**: 论证中的"未知盲区"通常未被MECE识别
- **分层 → 抑制跳级**: 从P0→P1→...→Pn的逐层展开替代了一步到结论

**适用场景**: 分类、归因、方案对比、根因分析
**不适用场景**: 创造性推理、开放式探索（MECE的"穷尽"不可达）
**本系统实现**: 方法论体系中已固化，deep-tech-writer/KDD/会议分析等文档模板默认应用

#### 3.1.2 第一性原理推导

**原理**: 分解到不可再分的基本事实/物理规律→从基础重构论证。

**逻辑增强机制**:

- **抑制先验分类**: 先定分类再事后拟合是经典谬误，第一性原理强制从基础出发
- **抑制类比当定理**: 类比只能提供"启发"，第一性原理要求严格推导
- **抑制共识陷阱**: "大家都这么说"在物理/经济规律面前不成立

**适用场景**: 技术选型论证、性能分析、成本核算
**本系统实现**: AGENT.md要求"第一性原理：回物理极限/经济规律/信息论"

#### 3.1.3 Toulmin论证模型显式化

**原理**: 将论证拆解为六个构件，抑制"前提→结论"的跳跃。

```text
数据(Data) ----> 结论(Claim)
    ^               ^
    |               |
  正当理由(Warrant) <- 支援(Backing)
    ^               ^
    |               |
  限定词(Qualifier) <- 反驳条件(Rebuttal)
```

**逻辑增强机制**:

- Warrant显式化 → 抑制隐藏假设：每一次"因为A所以B"都需要说明"为什么A能推导出B"
- Backing显式化 → 抑制空洞权威：每个Warrant必须有支撑（来源/数据/逻辑定理）
- Rebuttal显式化 → 抑制过度自信：必须标注"什么条件下这个论证不成立"

**本系统应用**: doc-reviewer的13条谬误中"类比当定理"对应的就是Warrant不充分，"声明-实践不一致"对应的是Claim与Data之间的关系断裂。

#### 3.1.4 论证链可视化

**原理**: 将论证表示为有向图（节点=命题，边=推理关系），使结构显式化。

```text
    P₁ --> S₁ --> C₁
    ^        ↗
    P₂ --> S₂
```

**逻辑增强机制**:

- 反链追踪：从结论反向追溯依赖的前提，发现隐藏假设
- 收敛检测：多个前提支撑一个结论时，检查各路径是否一致
- 环检测：发现循环论证（C依赖S₁，S₁依赖C₂，C₂依赖C）

### 3.2 过程性方案

过程性方案关注论证的生成过程，而非静态结构。

#### 3.2.1 正反双向验证 (Dialectical Approach)

**原理**: 建立论点的同时，主动构建最有说服力的反论点。

**工作流**:

```text
① 构建正方论证链（为方案A找理由）
② 构建反方论证链（为方案A找反驳）  <- 最容易被忽略
③ 评估哪一方的论证更强
④ 如正方胜出，验证反方最强论点是否已被正方回应
⑤ 如反方胜出，回到生成阶段调整方案
```

**逻辑增强机制**:

- 抑制确认偏误：人（和AI）天然倾向于找支持已有结论的证据
- 抑制单边论证：只呈现一面之词的论证即使"逻辑严密"也不强（因为缺乏对抗测试）

**本系统应用**: light-self-review的"E1/E3方向锁定检测"本质上是正反双向验证的简化版。

#### 3.2.2 预注册分析框架

**原理**: 在开始分析之前，先注册分析计划——包括假设、变量、分析方法、成功标准——然后在分析完成后不可更改注册。

**逻辑增强机制**:

- 抑制P-hacking（数据挖掘）：计划后添加新分析方法被视为质疑
- 抑制选择性报告：注册时声明所有测量指标，不允许只看显著的
- 抑制HARKing（事后假设）：假设在分析前注册，分析后不能更改

**本系统应用**: 在deep-tech-writer和doc-reviewer中已有部分实践（先输出计划再执行），但未正式化预注册机制。

#### 3.2.3 反事实推理 (Counterfactual Reasoning)

**原理**: 对因果主张，主动构建"如果没有X，会是Y吗？"的反事实场景。

**逻辑增强机制**:

- 抑制因果混淆：相关≠因果的根本区辨工具
- 抑制缺失基线：反事实提供对比基线
- 抑制单一原因：发现多个必要条件

**本系统应用**: 因果关系分析文档(2026-07-15-causation-correlation-analysis.md)中有系统化阐述。

### 3.3 验证性方案

验证性方案在论证完成后，用外部标准检验。

#### 3.3.1 证伪性测试 (Falsifiability Test)

**原理**: 对一个断言，明确说清"什么证据能证明它是错的"。

**逻辑增强机制**:

- 抑制不可验证：如果什么证据都能解释，那不是科学断言
- 抑制过度自信：强断言必须对应强证伪条件
- 抑制诠释学循环：框架自圆其说但不可证伪=自封闭

**自检问题**:
> "如果我的结论是错的，什么东西会不一样？"
> "存在什么可观测的证据能证明我错了？"
> "我是否愿意在证据面前放弃这个结论？"

#### 3.3.2 独立交叉验证

**原理**: 核心结论至少由两个相互独立的来源/方法/路径验证。

**交叉验证三维度**:

| 类型 | 操作化 | 示例 |
|:-----|:-------|:-----|
| 来源独立 | 不同机构/厂商/研究组产出 | IDC报告 + 券商分析 + 实地调研 |
| 方法独立 | 不同方法论得出同一结论 | 定量分析 + 专家访谈 + 实验验证 |
| 路径独立 | 不同论证链指向同一结论 | 第一性原理 + 类比推理 + 经验归纳 |

**本系统应用**: RULE.md import素材批判性使用规则已固化"关键量化数据必须经至少一种独立源交叉验证"。

#### 3.3.3 可复现性约束

**原理**: 论证中所用的一切数据/分析/推理，必须可被他人以相同条件重现。

**约束清单**:

- 数据集：名称、版本、来源、访问路径
- 分析方法：算法名、参数、软件版本、seed
- 测量条件：环境、仪器、操作方法
- 推理逻辑：以代码或形式化表达式而非自然语言记录

### 3.4 方案选择决策树

```text
论证类型是什么？
|
+- 分类/归因型（"什么原因导致X？"）
|   -> MECE (结构性) + 反事实推理 (过程性) + 独立交叉验证 (验证性)
|
+- 方案选型型（"A还是B好？"）
|   -> 正反双向验证 (过程性) + Toulmin显式化 (结构性) + 证伪性测试 (验证性)
|
+- 性能分析型（"X比Y快多少？"）
|   -> 第一性原理 (结构性) + 可复现性约束 (验证性) + 精确性四要素 (验证性)
|
+- 根因定位型（"为什么系统挂了？"）
|   -> MECE + 第一性原理 (结构性) + 正反双向验证 (过程性)
|
+- 综述/调研型（"该领域现状如何？"）
|   -> 论证链可视化 (结构性) + 独立交叉验证 (验证性) + 预注册框架 (过程性)
|
+- 解释说明型（"X是什么/如何工作？"）
    -> Toulmin显式化 (结构性) + 证伪性测试 (验证性)
```

## 4. 场景逻辑谬误分类体系

### 4.1 分类原则

本分类体系与现有系统的关系：

1. **五维特征模型**（第2章）回答"什么是强逻辑"
2. **本分类体系**回答"逻辑是怎样变弱的"
3. **doc-reviewer的13条谬误**是已有实践（按频率分类）
4. **本分类**按**场景/认知机制**重新组织——与13条谬误互补而非替代

分类维度选择**场景**而非**频率/严重度**的原因是：

- 同场景的谬误对应相近的防御策略
- 同场景的谬误在生成时倾向于共现
- 便于文档作者在对应场景下快速定位常见陷阱

### 4.2 论证构建类谬误 (A类)

**核心问题**: 论证的结构本身有缺陷——即使前提为真，论证过程也无法成立。

| # | 谬误 | 定义 | 典型表现 | 与13条映射 |
|:-:|:-----|:-----|:---------|:-----------|
| A1 | **循环论证** | 结论隐含在前提中，论证无信息增量 | "这个方案好是因为它比其他方案都好" | - |
| A2 | **跳跃论证** | 省略了关键推理步骤 | "显然/因此/所以"连接无直接推理关系的命题 | - |
| A3 | **声明-实践不一致** | 文档宣称一种原则但按相反原则执行 | "本报告遵循MECE"但章节间明显重叠 | 谬误#1 |
| A4 | **结论前置** | 结论出现在论证之前，后续变成找支撑 | 文档开头的"结论"章节，后文只为它找证据 | 谬误#5 |
| A5 | **类比当定理** | 用类比得出必然性结论 | "就像太阳系一样，CPU核也是围绕内存的"→"所以…" | 谬误#4 |
| A6 | **先验分类** | 先预设分类数量再事后拟合 | "这个问题有三个方面"（但第四方面被强行归入） | 谬误#2 |
| A7 | **二元对立(虚假二分)** | 把多选项问题简化为二选一 | "要么用GPU要么用CPU"（忽略FPGA/ASIC） | 谬误#6 |
| A8 | **稻草人** | 歪曲对方观点再攻击 | "你说A好 = 你否定一切" | - |
| A9 | **诉诸权威** | 用发言者身份替代论证 | "行业领袖X说过Y，所以Y是对的" | - |

**共现模式**: A4(结论前置)常伴随A3(声践不一致)——因为"先定结论再找支撑"本身就是声践不一致。A7(二元对立)常伴随A2(跳跃论证)——因为忽略中间方案的前提需要跳过论证步骤。

### 4.3 数据分析类谬误 (D类)

**核心问题**: 数据的使用方式有缺陷——数据本身可信但推导出的结论不可信。

| # | 谬误 | 定义 | 典型表现 | 与13条映射 |
|:-:|:-----|:-----|:---------|:-----------|
| D1 | **假精确** | 数据的精度超过了实际测量能力 | "性能提升了37.28%"（但误差为±5%） | 谬误#7 |
| D2 | **选择性报告** | 只报告支持结论的指标 | "推理速度提升40%"（但精度下降30%没提） | - |
| D3 | **幸存者偏差** | 只关注"幸存"样本 | "90%客户满意"（但只统计了回复问卷的客户） | - |
| D4 | **基线缺失** | 无对比基线的绝对数值 | "延迟降至100μs"（但没说之前多少） | - |
| D5 | **聚合谬误** | 将聚合统计当作个体行为 | "平均恢复时间30分钟"（但50%故障超过1小时） | - |
| D6 | **分母忽略** | 只关注分子忽略分母 | "100个案件中检出80个"（但分母是10000） | - |
| D7 | **范围错配** | 数据范围与主张范围不匹配 | "单节点实验"推"万卡集群性能" | - |
| D8 | **可视化操纵** | 坐标轴/尺度的选择扭曲视觉判断 | 纵轴不从0开始放大差异 | - |

**共现模式**: D4(基线缺失)+D1(假精确)组合极为常见——"1.2ms延迟"看似精确，但无基线就毫无意义。D2(选择性报告)+D5(聚合谬误)组合——用平均值掩盖分布问题，同时不报告被掩盖的维度。

### 4.4 归因推理类谬误 (C类)

**核心问题**: 因果关系的认定有缺陷——将相关/巧合/第三方因素误判为因果。

| # | 谬误 | 定义 | 典型表现 | 与13条映射 |
|:-:|:-----|:-----|:---------|:-----------|
| C1 | **相关当因果** | 两变量相关就认为是因果关系 | "GPU出货增→GPU价格跌"（忽略是共同供给因素） | - |
| C2 | **事后归因** | A发生在B之前所以A导致B | "优化后性能下降→优化导致退化"（但可能是系统负载增加） | - |
| C3 | **单一原因** | 把多因结果归因于单一因素 | "项目延期是因为供应商"（忽略需求变更/资源不足） | - |
| C4 | **逆向因果** | 颠倒因果方向 | "毛利率高是因为研发投入多"（实际是市场好→毛利率高→研发投入增加） | - |
| C5 | **混淆基线** | 漏掉未发生变化的第三变量 | "液冷服务器故障率低"（但液冷集群是新集群，硬件的本身的更新是混淆变量） | - |

**深度参考**: 本类谬误的详细分析见[2026-07-15-causation-correlation-analysis.md](2026-07-15-causation-correlation-analysis.md)，包含8个服务器行业案例和7种科学识别方法。

**共现模式**: C1+C3组合极危险——相关当因果后进一步简化为单一原因。C2+C4常成对出现——事后归因和逆向因果本质上是一体两面。

### 4.5 分类归纳类谬误 (G类)

**核心问题**: 分类体系和归纳推理的逻辑缺陷。

| # | 谬误 | 定义 | 典型表现 | 与13条映射 |
|:-:|:-----|:-----|:---------|:-----------|
| G1 | **过度泛化** | 从有限样本推广到全体 | "两个项目用这个方案失败了 → 这个方案不可用" | 谬误G6(l-s-r) |
| G2 | **伪结构/假密度** | 分类项之间可互相推导或互为特例 | "资源管理"和"预算管理"本质上是一回事但分两章 | 谬误#11 |
| G3 | **空洞同构** | 找到共同点后忽略关键差异 | "都是PCIe设备所以电气特性相同"（忽略功耗差异） | 谬误#8 |
| G4 | **术语漂移** | 同一个术语在不同语境下含义漂移 | "延迟"在硬件层指传播延迟，在应用层指响应时间 | 谬误#3 |
| G5 | **维度混淆** | 不同维度的量放在同一框架下比较 | 用"功耗比"和"性能"直接对比而非帕累托分析 | 谬误#9 |
| G6 | **假专家** | 以不充分的权威覆盖超出领域的主张 | 软件架构师断言物理散热方案的可行性 | - |

**共现模式**: G5(维度混淆)+G2(伪结构)组合——分类时把不同维度混在一起，导致分类项非MECE。G4(术语漂移)+G3(空洞同构)——因术语含义变化而错误认为对象"相同"。

### 4.6 结构与定义类谬误 (S类)

**核心问题**: 定义不清或结构打架导致的逻辑混乱。

| # | 谬误 | 定义 | 典型表现 | 与13条映射 |
|:-:|:-----|:-----|:---------|:-----------|
| S1 | **歧义定义** | 关键术语未经定义或定义模糊 | "高性能"（对谁来说高？什么场景？什么基线？） | - |
| S2 | **内部冲突未检视** | 同一对象的不同结论互相矛盾 | "方案A延迟最低"和"方案A不可部署"都在同一文档 | 谬误#10 |
| S3 | **诠释学循环** | 框架自我验证、不可证伪 | "系统总体来看是稳定的"（无论出不出故障都可以这样说） | 谬误#12 |
| S4 | **模型几何不相容** | 多个模型的底层结构不能共存 | 时序模型+分类模型合并使用但不兼容的因果假设 | 谬误#13 |
| S5 | **抽象层次混淆** | 在不同抽象层级之间跳跃 | 从"CPU微架构"跳"数据中心能效"，无桥接层 | - |

**共现模式**: S1(歧义定义)几乎是一切结构类谬误的根因——定义不清导致后续所有关系都无法准确判断。S3+S4(诠释学循环+模型几何不相容)高相依——框架越封闭、越自圆其说，越容易堆砌多个底层冲突的模型。

### 4.7 认知偏误类 (B类)

**核心问题**: 人类认知的固有偏误映射到论证中——即使逻辑形式上正确，认知偏差导致输出层面失效。

| # | 偏误 | 定义 | 典型表现 |
|:-:|:-----|:-----|:---------|
| B1 | **确认偏误** | 只关注支持已有观点的信息 | 搜索"GPU加速的好处"而非"GPU加速的代价" |
| B2 | **可得性启发** | 容易联想的事件被高估概率 | "最近几个项目延期→项目管理体系有问题"（实际延期率与历史持平） |
| B3 | **锚定效应** | 初始值过度影响最终判断 | 先看到一个供应商报价5万，后面所有报价都跟5万比 |
| B4 | **群体思维** | 因群体压力抑制异议 | "团队一致同意……"（但最了解风险的人没说话） |
| B5 | **过度自信** | 信心超出准确率 | "我的预测正确率99%以上"（实际在60-70%） |
| B6 | **沉没成本** | 已投入资源影响继续投入决策 | "已经花了6个月做这个方案，不能放弃" |

**本类谬误的特殊性**: 认知偏误通常不直接表现为论证中的逻辑错误（形式上可能完全正确），而是影响论证的**生成方向**和**结论的选择**。因此检测难度最高——需要外部视角而非内容内检。

### 4.8 六类谬误全景矩阵

| 类别 | 核心问题 | 检测难度 | AI独有/人类共有 | 频率 | 对应5维特征 |
|:----|:---------|:--------:|:---------------:|:----:|:-----------|
| **A类** 论证构建 | 论证结构缺陷 | 🟢 中 | 人类共有 | 高 | 完整性·有效性 |
| **D类** 数据分析 | 数据使用不当 | 🟢 中 | AI更严重 | 高 | 精确性·有效性 |
| **C类** 归因推理 | 因果判断错误 | 🔴 高 | 人类更严重 | 高 | 有效性·相关性 |
| **G类** 分类归纳 | 分类/归纳缺陷 | 🟡 中高 | AI更严重 | 中 | 一致性·完整性 |
| **S类** 结构定义 | 定义/结构缺陷 | 🟡 中 | 共有 | 中低 | 一致性·精确性 |
| **B类** 认知偏误 | 认知偏差映射 | 🔴 极高 | 人类更严重 | 中 | (跨维度) |

**关键发现**:

- AI在**D类**(数据分析)和**G类**(分类归纳)上比人类更容易犯错——因为AI倾向于"看起来合理"的分类和"数值貌似精确"的报告
- 人类在**B类**(认知偏误)和**C类**(归因)上更严重——因为有经验和价值观干扰
- **S类**(结构定义)最难自动化检测——需要精确定义和逻辑一致性
- 本系统的13条谬误主要覆盖A类(5条)、G类(4条)、S类(3条)，对D类(数据分析)覆盖不足

## 6. 谬误检测Skills生成

### 6.1 Skill设计原则

从以上分析可看出，本系统已拥有预防和检测能力，但**未固化为可复用的、独立的检测Skill**。以下四个Skill的设计填补了这一空白。

**设计原则**:

1. **单功能原则**: 每个Skill检测一种逻辑维度，不做大而全的审查
2. **可组合原则**: 四个Skill可串联形成完整检测流水线
3. **自动化优先原则**: 尽可能用脚本而非人工判断
4. **自检自反原则**: 每个Skill本身也要接受逻辑谬误检测

### 6.2 Skill一：论证链追踪器 (Argument Chain Tracer)

**检测维度**: 完整性 · A2(跳跃论证) · A1(循环论证)

**功能**: 从文本中提取命题节点(前提→中间步骤→结论)，构建有向图，检测环、断点和隐藏假设。

**工作流**:

```text
输入: 文本段落
v
步骤1: 提取显式命题（"因为A所以B"/"由X可知Y"模式）
步骤2: 构建有向图（节点=命题，边=推理方向）
步骤3: 检测环（循环论证：A->B->C->A）
步骤4: 检测断点（结论无前提或前提无结论）
步骤5: 检测隐藏假设（需要补充的额外前提）
步骤6: 计算完整性得分 = 显式步骤数 / 总步骤数(显式+隐藏)
v
输出: 论证链报告
```

**输出格式**:

```text
论证链报告: <段落>

  A: GPU利用率降低 -> (推理步骤缺失) -> 需要增加节点 -> 结论: 采购更多GPU
  ⚠️ 断点: 从"GPU利用率降低"到"需要增加节点"之间缺少步骤
  ⚠️ 隐藏假设: "利用率降低=现有GPU不足"（实际可能是工作负载变化）

  完整性评分: 2/5 (40%)
  🏷️ 建议补充步骤:
    GPU利用率降低 -> 分析工作负载变化 -> 排除非资源原因 -> 确认物理GPU不足 -> 需要增加节点
```

**集成接口**: 可在deep-tech-writer产出的文档中作为最终质量门禁前的逻辑检查步骤调用。

### 6.3 Skill二：数据主张验证器 (Data Claim Verifier)

**检测维度**: 精确性 · D1(假精确) · D4(基线缺失) · D2(选择性报告) · D7(范围错配)

**功能**: 扫描文档中的数据主张，检查四要素完备性（数值/单位/基线/条件），标记不完整或可疑的数据使用。

**工作流**:

```text
输入: 文本
v
步骤1: 正则匹配数据模式（数字+单位/百分比/倍数）
步骤2: 对每个匹配，检查四要素完备性
步骤3: 检测"显著/明显/巨大"等模糊词与数据共存情况
步骤4: 检测数据声明与来源之间的匹配（来源中的数据是否支撑声明的精度）
步骤5: 标记基线缺失（有"提升"无"从什么提到什么"）
步骤6: 标记范围错配（实验条件与主张条件的差距）
v
输出: 数据主张报告
```

**关键检测指标**:

| 数据模式 | 四要素要求 | 示例 |
|:---------|:-----------|:-----|
| 提升/下降百分比 | 基线值+目标值+条件 | ✅ "延迟降低40%（从5ms到3ms，相同负载) |
| 绝对数值 | 测量条件+误差范围 | ✅ "带宽800GB/s（PCIe Gen6×16，理论峰值）" |
| 排名/评级 | 排名范围+评判标准 | ✅ "TCO排名第3（在8家厂商中，按5年总成本）" |

**输出格式**:

```text
数据主张报告: <文件>

  [P1] "性能提升37%" -> ❌ 基线缺失
    文本位置: 第45行
    四要素检查: 数值✅ 37 · 单位✅ % · 基线❌ · 条件❌
    建议: "性能提升37%（从A到B，在C负载下）"

  [P0] "AI服务器占比提升->盈利能力改善" -> ⚠️ 范围错配
    文本位置: 第120行
    主张范围: 全公司盈利能力提升
    数据范围: 仅AI业务部门毛利率
    差异: 毛利率≠净利率，AI部门≠全公司
```

### 6.4 Skill三：自矛盾检测器 (Self-Contradiction Detector)

**检测维度**: 一致性 · S2(内部冲突) · G4(术语漂移) · H7(自我矛盾)

**功能**: 扫描文档跨章节/跨文件，提取同一对象/同一术语的所有声明，对比一致性。

**工作流**:

```text
输入: 文档（单篇或跨文件）
v
步骤1: 提取实体/术语列表（产品名、指标名、方案名等）
步骤2: 对每个实体，提取它在所有出现位置的属性声明
步骤3: 属性声明对齐——同一属性的不同值标记不一致
步骤4: 术语追踪——检查同一术语在不同上下文中的含义是否一致
步骤5: 量化矛盾——如"延迟<100μs"和"延迟约200μs"共存的文档
步骤6: 排序检查——如A>B且在另一处B>A
v
输出: 矛盾报告
```

**输出格式**:

```text
自矛盾报告: <文档>

  [P0] 指标矛盾: "延迟"的两种说法
    位置1 (L34): "延迟低于100μs"
    位置2 (L156): "延迟约200μs"
    差异: 两倍差距，且无场景区分说明

  [P1] 术语漂移: "带宽"
    位置1 (L23): "内存带宽 800GB/s"（硬件指标）
    位置2 (L89): "网络带宽 100Gb/s"（互连指标）
    同一术语但指标差距8000倍，需标注领域限定

  [P0] 声明-实践不一致:
    声明 (L10): "本报告遵循MECE原则"
    实践: 章节3.2和3.4内容重叠30%以上
    命中谬误: A3
```

### 6.5 Skill四：谬误预检扫描器 (Fallacy Pre-Check Scanner)

**检测维度**: 全部6类 · 快速预检 · 输出警告而非深入分析

**功能**: 在文档生成完成后、人工审查开始前，快速扫描并标注潜在谬误位置。不追求精确检测，追求**高召回率**（宁可误报不可漏报）。

**检测项目**:

| # | 预检项 | 检测规则 | 目标谬误 |
|:-:|:-------|:---------|:---------|
| 1 | 强断言检测 | 匹配"必定/毫无疑问/毫无疑问/证明"等词汇 | B5(过度自信) |
| 2 | 模糊词检测 | 匹配"很多/显著/明显/大量/相当"等无量化词 | D1(假精确) |
| 3 | 跳步检测 | "因此/所以/显然"前缺少数据支撑 | A2(跳跃论证) |
| 4 | 预设分类检测 | "三个方面"但未说明分类依据 | A6(先验分类) |
| 5 | 二选一检测 | "要么…要么…"/"非此即彼" | A7(二元对立) |
| 6 | 类比检测 | "就像…一样"/"类似于"后跟必然性结论 | A5(类比当定理) |
| 7 | 基线缺失检测 | 有"提升/降低"无具体基线值 | D4(基线缺失) |

## 7. 总结

### 7.1 五条核心结论

1. **"强逻辑"可被显式定义和度量**：完整性·一致性·有效性·相关性·精确性五个维度构成了可操作的特征体系，每个维度都有明确的失效信号和强化方案。

2. **六类谬误场景→差异化防御策略**：论证构建(A类)、数据分析(D类)、归因推理(C类)、分类归纳(G类)、结构定义(S类)、认知偏误(B类)——不同类型需要不同的预防和检测手段，单一"查谬误"清单不够。

3. **本系统已有防御体系完整度≈70%**：13条谬误全面覆盖A/G/S类，但C类(归因)和B类(认知偏误)防御薄弱；自动化检测已覆盖结构层面，但语义层面的检测仍依赖人工。

4. **最大盲区不在形式逻辑而在认知偏误**：A类(论证结构)的自动化检测最成熟，C类(因果判断)最难自动化，B类(认知偏误)需要外部视角——而系统缺乏跨session的外部审计机制。

5. **谬误检测Skill是系统能力的自然进化方向**：从"人手一个审查清单"到"可复用的自动化检测工具"，四个Skill的设计弥补了从预防到检测的关键缺口。

### 7.2 对系统改进的建议

| 优先级 | 改进 | 预期效果 |
|:------:|:-----|:---------|
| **P0** | 实现Skill一(论证链追踪器) | 最多人犯的跳跃论证可自动化检测 |
| **P1** | 为doc-reviewer增加C类(因果谬误)专项检测 | 填补最大盲区 |
| **P1** | 实现Skill二(数据主张验证器) | D类数据谬误的数据密集型文档可自动化检测 |
| **P2** | 将Skill三(自矛盾检测器)集成到pipeline中的汇聚阶段 | 跨路径汇聚时的冲突自动发现 |
| **P2** | 设计跨session的外部审计机制 | 缓解B类认知偏误的自检同源盲区 |

### 7.3 本文的自指性验证

根据第2章的五维特征标准：

- **完整性**: 从特征定义→达成方案→谬误分类→防御体系→技能生成，全链路覆盖 ✓
- **一致性**: 谬误分类(六类)与防御映射(矩阵)之间的对应关系经交叉验证 ✓
- **有效性**: 每个观点有第一性原理推导或来源标注 ✓
- **相关性**: 无离题的框架堆叠，每节论证指向核心结论 ✓
- **精确性**: 所有量化表述有基线/条件标注 ✓

按第4章的分类体系，本文预设了"新增"而非"替换"的立场（区别于"否定现有体系"），避免A7二元对立谬误。
