## 统一主线

> **数据价值链的三个环节被三篇论文分别精确化：发现（数据有价值的前提是被找到）→ 契约（什么算有效状态）→ 交付（契约数据正确投递）。三篇共同的第一性原理是：把隐性语义变成显式可验证的契约——「语义鸿沟」是内在的信息结构，不是词汇不匹配，也不是簿记马虎。**

|:--|:--|:--|:--|
| **OADD** | 发现 | 抽象概念→可观察指标的**操作化映射**（"社交隔离"≠任何单一字段） | 论文=架构使用记录；question/column 双 miner 证据约束重建 |

## ① OADD：把「研究问题→数据列」语义映射纳入自动数据发现

**来源**：arXiv:2608.04536，密歇根大学（Houming Chen + **H.V. Jagadish**，数据库领域权威），2026-08-05。代码开源：github.com/umich-dbgroup/OADD-Bench。

### 问题：operationalization gap（操作化鸿沟）

数据库组织**具体事实**，研究者带着**抽象概念**来。已有观测在库中 ≠ 从科学想法可发现它们。经典案例：HRS（美国健康与退休研究，12 万+字段）中**没有**"社交 isolation"字段——Cenzer 2025 用**婚姻状况 + 家庭规模 + 子女距离 + 宗教出勤 + 志愿服务**五个变量的组合构建可辩护的社交隔离测量。模糊搜索只返回 Social Security 变量，语义搜索只返回孤独感问题——**都不揭示可辩护的测量**。

**与 schema linking / column retrieval 的本质区别**：schema linking（text-to-SQL 常用）假设用户已指定需求——"昨天从 LA 飞纽约的航班有多少"虽不知 schema 名，但事件/端点/时间/计数都已指定。OADD 用户连"该观测什么"都未指定。**gap 是内在的而非词汇不匹配**：有用列不必像查询，其角色只在束（bundle）中浮现。

### 技术框架：形式定义 + 基准构建 + 诊断评估

**① 形式定义**：给定数据库 D（列集 Col(D)）、宽泛研究问题 q（命名一个或多个焦点测量角色，不指定如何观测）、可选范围约束 C（时间/产品/访问层级，诱导 Col_C(D)）。**操作化 M** 将每个焦点角色 r 映射到非空列集 M(r)，其字段单独或联合在 q 语境下提供科学可辩护的测量。**OADD 问题 = 找到 V(M)=⋃M(r)**。M 与 V(M) 必须**联合选择**：不可实现的测量和近似但不足的列表都无效。OADD 止步于问题被落定到研究者可检查的字段集；编码、聚合、建模、因果识别都在下游。

**② OADD-Bench 构建（关键创新：论文=架构使用记录）**：人工标注需要同时懂科学领域与数据库的多个标注者，不可行。替代方案——**同行评审论文天然记录了领域研究者如何把问题翻译成实际分析所用测量**（这些映射是"强外部正样本"，独立于任何 OADD 系统）。

- **Question miner**：提取论文研究的问题，改写为宽泛早期问题（保留焦点概念/关系/人群/范围，**删掉会泄露答案的测量细节**——否则退化成直接 schema linking）；
- **Column miner**（粗到细四步，全用 GPT-5.5 + schema 约束输出）：①重建测量（识别焦点角色，综合论文正文+补充材料中如何观测，**此阶段禁止提出标识符**）②检索候选证据（按命名测量/可观测组件/可能 codebook 措辞分别查询，跨标识符/标签/问题文本/产品元数据组合词法检索）③构建可审查证据包（LLM 筛选去掉明显无关候选，保留原始项/发布分数/路由字段/伴侣项/重复波变体，只对短名单加载完整证据）④grounding or abstain（联合检查测量记录与短名单证据，解析范围/单位/路由/原始 vs 发布字段，**只选证据包支持的标识符，不确定则放弃**；确定性检查拒绝证据缺失标识符）；
- **证据约束选择**：450 篇可用全文 → 364 篇合格（实证 HRS 分析 + 中心测量可重建）→ 448 候选映射 → 140 例（两级筛选+一致性检查）+ 20 人工注释例 = **160 问题/111 论文/4,682 标签/2,032 个 HRS 标识符/873 个测量组件**；target 集 2-136 列（中位数 21，均值 29.3）。
- **人工一致性检查**（20 例/640 标签）：miner 覆盖注释 0.942、注释保留 miner 0.946、macro set F1 0.933——两种重建的一致性（注释非 gold，论文是科学先例）。

**③ 诊断评估（Table 2 全数据）**：系统只收到问题+允许年份+元数据（论文只用于构建标签）。

### 底层原理

- **操作化 = 联合推理**（measurement × realizability）：一个科学上合理但需要不可用观测的测量不是答案；一个不测量焦点概念的字段列表也不是。把"可用数据约束下的测量选择"作为问题的一部分（对比 SDRQuerier 把测量组装留给用户）；
- **证据约束（evidence-constrained）**：只收论文+文档双支持的映射，保留出处与标识符溯源，不支持完整映射时放弃——**benchmark 标签不是发明的，是从科学实践中挖出的**；
- **LLM 使能规模化**：文档理解+多步推理+工具使用让"重建测量→查文档→grounding"的粗到细管线可扩展（对比人工标注的不可行）。

### 应用场景

- **科研数据发现**：研究者在 HRS / UK Biobank / 纵向调查库中找抽象概念（社交隔离、歧视暴露、老化感知）的可辩护测量；
- **数据湖/企业数据目录**：Aurum 式数据发现只做表层检索，OADD 提供"概念→列束"的下一层（如"客户忠诚度"→购买频率+复购间隔+流失信号组合）；
- **LLM 科学 Agent 前置**：研究可行性判断（"这个数据库能不能研究 X"）的自动化，比"直接检索相似列"更接近研究者真实工作流。

## ② Machine-Checked Dual-Write：机器可证明的崩溃恢复信息界

**来源**：arXiv:2608.00501，Andreas Andreakis，2026-08-01，**Isabelle/HOL 全机械化**。**这是记忆库中「Dual-Write exactly-once 界限」的证明侧原文**——此前只有信息论界限的定性记忆，本次补齐严格形式化。

### 问题：崩溃后自己的数据库无法回答"对方是否已收到"

订单服务把 shipped 提交到数据库，relay 为每个提交订单发确认邮件并 checkpoint。某夜进程崩溃：checkpoint 落后 commit log 一条，恢复"显然"地重发最后一条——早晨客户收到两封邮件，数据库却一切正常：每行正确、checkpoint 合理、store 审计全绿。**"我们每个 send 都 checkpoint，怎么不是 exactly-once？"**

答案不舒适：崩溃落在 **send 与记录它的 checkpoint 写之间的窗口**。窗口内有两个可能世界：邮件提供方已持久接受 vs 未接受（判据事件=**sink 的持久接受**，不是邮件后续投递）。崩溃侧重启能读的一切——数据库、WAL、outbox、ack 日志、恢复代数、checkpoint——**在两世界中逐字节相同**。重发在一个世界重复，跳过在另一个世界抛弃已提交工作。checkpoint 没 bug，**它被要求为一个它从未观测的事件作证**。只有接收方自己的记录能区分两世界。

**双写定义**：相关事实在独立权威下各自持久化（源数据库和邮件提供方/搜索引擎/代理/缓存/另一服务），无单一提交跨越两者。CDC/事务性 outbox 移除应用的双写，但 **relay 写 sink + 单独记录自身进度 = 每个事件两次持久行为、无共享提交 = 按此定义又是一次双写**——派生不消解恢复问题，只是把它移到工具更好的阶段（可重放日志 + 可协商接受规则的 sink）。

### 底层原理：三大信息界与逃逸（全部机器检查）

**模型**：单一单向对（一个记录权威 → 一个接受端点 → 一个方向）；源侧只需持久有序追加提交历史 H（坐标非降）；核心执行状态 σ 含 base/提交历史/下游历史 D/队列/待发集/键范围/run 状态/源侧 ack；效应机器加发射账本 E（**世界记录，追加构造，模型外**）与代数 γ（恢复化身计数）。词汇：premature/duplicate/unsafe（安全轴）、lost/alo（完整性轴，frontier 相对）。

**① 本地状态回答不了"sink 接受了什么"——Observation Bound（Theorem 1）**：构造两个可达后崩溃状态，**core 与 generation 逐字节相同、均无 hazard、均真实发射过工作**，但世界记录不同：pay(E(t1))=[(c1,e1),(c2,e2)] vs pay(E(t2))=[(c1,e1)]。对**任意结果类型、任意** obs，只要 obs(t1)=obs(t2)，任何 P=g∘obs 的策略在两个世界发射相同批次 B——p2∈B 则 t1 重复，p2∉B 则 t2 仍欠。三叉（重复/丢失/提前发射）；存储在每个策略下都自愈 mismatch-free，所以**没有 store 审计（事前事后）能定位缺陷**。**Theorem 2 (Control-Plane Bound)**：store 度量与 store+generation 度量策略都被击败。结构性二分：**每个策略要么是 store+generation 的函数（随 Theorem 2 落败），要么区分在账本上不同的两状态（逃逸侧）——抽象层面没有第三种更聪明的策略**。

**② 一个诚实协议也会被困——Checkpoint Dilemma（§4，Theorem 1'）**：Theorem 1 的构造用了两个不同的 reconcile 参数（"从机器外选择"）。§4 关闭此漏洞：**单一确定性 deliver-then-persist 协议，持久 cursor 包含在恢复读取中**。两个调度 Go⁷Crash（第二次投递后崩溃）vs Go⁶Crash（第二次投递前崩溃）——都崩溃在 cursor=1，**durable-local view（含 cursor、commit log、outbox、ack、状态、代数）相同，世界记录不同**。纯崩溃时序制造混淆对。忠实恢复恰好正确于落后成员、在已投递成员上产生重复——**熟悉的 checkpointed delivery at-least-once 窗口，以定理而非轶事陈述**。"checkpoint 是否正确"是错误问题；**窗口是两个持久写之间的间隙，任何 checkpoint 维护纪律都无法闭合**。cursor 被赦免：persist 后崩溃 cursor 读 2，自行分离状态——**困境是窗口，不是 cursor 的簿记**。

**③ 逃逸：读 sink 自己的接受记录（Sink-Reading Escape，§5）**。sink delta Δ⟨f⟩ = replay(H,K,f) 中不在 pay(E(t)) 的义务。四个显式前提：**P1 无 hazard（记录无重复无提前）；P2 已崩溃；P3 f≤fin（在区间内）；P4 坐标严格递增**（保证重驱动批次自身无重复 + 计数从集合级升到逐实例级）。结论：sink-delta 重驱动让存储 mismatch-free、无 hazard、无丢失——三个结论各自依赖"批次从与 hazard 判据相同的记录计算"。"读 sink"不是一个动作而是两个：**sink 的状态 vs sink 的接受历史**（§8/§9 返回为定理边界）。

**④ 什么还能改变答案——双 fence（§6/§7）**：sink 读是快照，两个 hazard：①旧请求仍在途（straggler）——**arrival fence**：让 sink 拒绝被取代的 incarnation 的请求（wire-blind 读全落败，fence 恰好在接受边界上升起）；②第二个 recoverer 竞争——**claim fence**：在 fire point 串行化竞争恢复者。**fencing 代价本身是定理**：fence 用"straggler 完成你工作的机会"换取"所选 frontier 的确定性"。

**⑤ 证据能活多久（§8）**：exactly-once = at-least-once + 去重，**前提是记忆持久**。去重窗口过期、或源历史截断在恢复重放前——各以具体运行 void 保证（截断后恢复无法区分伪造工作与放弃工作，undone 状态）。压缩需保留"存在性"（presence），截断需要日志作缺失见证。

**⑥ 机械化与边界（§10/§12）**：全定理 Isabelle/HOL 机器检查、无 sorry；负结果是构造、正结果条件化；**不验证任何具体产品**（无 broker/connector/邮件提供方被验证，§10 列出模型刻意缺失）；§12 把结果变成设计审查纪律：**先命名边界**（三 sink 变体：可读接受记录/只可读当前内容/什么都读不到——后者诚实做法是选择偏好哪种失败）→ **预算证据不要口号** → **监控两半**（源与 sink）→ **练习危险调度**。任何 exactly-once 声明测试三问：**sink 接受了什么？什么还能改变这个答案？证据能活多久？**

### 应用场景

- **双写投递崩溃恢复审查**：订单确认邮件、支付 webhook、缓存填充、索引更新、消息发布——"we checkpoint after every send; how were we not exactly-once?"的定理化回答；
- **CDC/outbox 管道设计**：Debezium 式 relay 的进度记录同样是双写，本理论给出其精确边界（派生把恢复问题移到工具更好的阶段，§9 证明 store 层崩溃安全 ⟺ 派生镜像忠于提交日志）；
- **exactly-once 声明审计**：任何供应商"exactly-once delivery"声明的三问测试（sink 接受记录可读性、fence 是否存在、去重/截断持久性）；
- **与记忆呼应**：知识库此前只有「Dual-Write exactly-once 信息论界限」定性记录，本次是**证明侧原文**——信息界（本地状态不足）+ 逃逸（读 sink）+ 代价（fencing 定理）全部机器检查。

## ③ PULSE：时空知识图谱的可执行契约语言

**来源**：arXiv:2608.02630，DeepLethe（Dongxu Yang / Ziyi Liang），2026-07-26，**Apache-2.0 开源**。**延续 08-03「Data Contracts as Types」主线，从通用类型契约扩展到时空域**。

### 问题：KG 工程把操作契约散落在 artifact 边界

知识图谱工程把接受状态、观测、约束、过程、假设场景分散在**本体、观测/形状图、过程模型、空间存储、模拟器**中，组合执行契约外置。语义依赖 artifact 边界：**观测不是接受的更新；策略陈述义务而非事实；场景不得变更断言状态；时长限定的离开既非 OWL 公理也非静态 SHACL 违反**。压平成普通三元组掩盖这些区别。OWL 开放世界公理 + SHACL 图验证 + 工作流组合可以复现 PULSE trace（baseline 证明），但义务变更时需改动的 artifact 散布多处（contract localization）。

### 技术框架：四模式类型化运行时

**模式 = 操作角色（operational role），非模态/道义逻辑**，各有不同写集：

| 模式 | 角色 | 写效应 |
|:--|:--|:--|
| **Assertion**（断言） | 接受状态 A | move 写 {A,q,Q,t} |
| **Observation**（观测） | 源限定证据 O | record 只写 {O}（追加） |
| **Constraint**（约束） | 只读义务 | 无（W=∅，read-only） |
| **Scenario**（场景） | 反事实分支 | 在 clone 上执行，源不可变 |

模型文档 `M=⟨n,v,R,E,I,O,C,P,S⟩`（名称/版本/CRS/区域/实体/实例/观测/约束/过程/场景），解析后做名称/类型/状态域/几何/CRS/引用验证。**执行配置** `X=⟨A,O,q,Q,t⟩`（断言值 + 追加证据 + 有限对象状态 + 有限部分定时器映射 + 事件时间）。**核心写效应判断**：record↦{O}、move↦{A,q,Q,t}、advance↦{q,Q,t}；验证与问题 W=∅。成功动作只改 W 内组件。

### 底层原理：五个固定契约 + 六定理

**① Evidence non-overwrite**：record(o) 只追加证据，**观测永远不触发过程**；权威变更=runner 的 move_at 命令（输入命令，非模型声明）——**应用拥有接受决策，语言只保证记录证据本身不触发过程**（记录证据可影响后续：latest(O) 选默认场景起点）。

**② Branch isolation（反事实隔离）**：场景在 clone(X) 上执行（可含时钟与待发监视器），源模型不可变——**隔离是类型化效应而非 agent/持久化协议**（对比 Parallel World Framework 的命名图+copy-on-write 协议）。

**③ Grounded multi-subject timers**：参数化过程按实例 grounding（SustainedDeparture@batch），Q 以 ground 标识符为键——**不同主体可对同一源过程持有并发监视器**；α-renaming 惰性（ground rank 按过程-实例声明序）。

**④ Guarded state change**：monitor 创建与发射时**重查源状态守卫**（Safe 才允许 Safe→AtRisk）；采样进出由相邻接受样本推导：enters=¬in(gₖ₋₁)∧in(gₖ)，leaves=in(gₖ₋₁)∧¬in(gₖ)——**sample-and-hold 语义**（outside→outside 穿过多边形不产生采样事件）。

**⑤ Declaration-ranked event ordering（确定性）**：到期定时器先于同时间 move（due 按 (deadline, groundRank) 全序）；同时间输入 move 按输入顺序；后规则可见前规则状态变更；源状态不匹配跳过规则——**固定验证输入+定时器序+输入序+规则序 ⟹ 单 trace 或原子错误**。

**六定理**（核演算，paper proof + Lean 4 检查）：T1 preservation（良型保持）、T2 determinism（确定性）、T3 record confinement（record 不改 A/q/Q/t）、T4 extensional scenario isolation（场景不改源任何组件）、T5 finite advance（有限 Q 下终止，至多发射 |Q| 个事件）、T6 atomic failure（error 返回原 X）。

**视图即投影**：GeoSPARQL（RDF 空间视图）、SOSA（观测视图）、SHACL（约束视图）都是**生成的视图而非权威表示**——执行留在类型化表示中，视图是目的特定、保真度部分的（进程/场景只有 JSON 输出；运行时排序/队列/分支身份不可重建）。投影验证器（pySHACL + GEOS）检测跨视图漂移；Jena 6.1.0 独立引擎 + PostGIS 三方三角验证（**ehCoveredBy 不捕获 PULSE 的 boundary-inclusive 成员，sfIntersects 捕获**——投影还纠正了语义）。

## 交叉洞察：最锋利的五个发现

1. **三种"语义鸿沟"同构，解法同构——都需外部记录**。OADD 的操作化鸿沟（本地问题文本不含测量方案）、Dual-Write 的信息界（本地状态不含 sink 接受记录）、PULSE 的 artifact 边界（本地三元组不含角色语义）——**都是"本地可读的东西不包含回答所需的事实"**。解法也都是"引入外部权威记录"：OADD 读论文（领域先例）、Dual-Write 读 sink 接受记录、PULSE 把角色/效应放进程内类型化运行时。**语义精确化的本质=找到记录该语义的权威位置**。

2. **「证据」与「接受」的分离是三篇的共同纪律**：OADD 论文是构建证据但评估时隐藏（防泄漏）；PULSE record 只写证据、move_at 是 runner 命令（观测永不自动触发过程）；Dual-Write 的 Ack 记录"调用者听到的"而非"对方做的"（ack 挣不到投递结论）。**证据是来源限定的，接受是外部权威的——两者混同是三类系统共同的失效模式**。对知识库的直接映射：`import/` 素材=证据、`knowledge/` 断言=接受状态——素材不应自动晋升为断言（记忆中的"import 素材批判性使用"正是这条纪律）。

3. **机器可证明从"协议正确性"进入"操作语义"**：Dual-Write 把双写恢复（此前只有运营轶事）做成信息界定理；PULSE 把 KG 契约的角色/效应/顺序做成 Lean 检查的核演算。但两者共享诚实的边界：**内核可证、边界人工**——Dual-Write 不验证任何具体产品、PULSE 的 Lean 从 parsing 后开始且几何抽象化。与容错四连发中 Stochastic Connectivity 的 5 命题呼应：**"机器可证明"趋势已从协议层蔓延到数据语义层**。

4. **"不可能"声明需要精确化**：Dual-Write 证明"exactly-once 不可能"是过度粗糙的——条件性保证（读 sink + 双 fence + 持久记忆）可达成且已部署；OADD 把"数据发现难"精确化为：直接检索 0.185 → agent 0.465，**差距即操作化难度，且最强系统仍漏 >50% 目标列**。**知道"什么不可能"的精确边界，比口号更有设计价值**——Dual-Write 的三问测试（sink 接受了什么/什么能改/证据活多久）就是可执行的"不可能性审计"。

5. **三篇都是"用 LLM/形式方法把隐性知识显式化"的样板**：OADD 用 LLM 把论文中隐性的测量重建为可审计标签（0.933 F1 一致性）；PULSE 用 Lean 把隐性的运行时纪律显式化为定理；Dual-Write 用 Isabelle 把隐性的运维共识（retries/checkpoints/idempotency keys/fencing）显式化为定理+前提。**显式化的价值=可检测、可复用、可反驳**——与知识库治理方法论（"方法论→Skills+脚本，可重复可检测低认知负载"）完全同构。

### OADD：概念到测量的发现
- **科研**：HRS 研究者查"社会隔离是否影响健康老化"——系统返回婚姻状况/家庭规模/子女距离/宗教出勤/志愿服务五列束（论文先例 Cenzer 2025），而非 Social Security 变量；

### Dual-Write：投递恢复设计审查
- **订单确认邮件**：崩溃在 send 与 checkpoint 之间→重发重复——三问审计：邮件服务是否暴露每封邮件的接受记录？恢复是否读它（而非本地 cursor）？去重/保留窗口多久？
- **支付 webhook**：DB 提交与 webhook 调用双写→CDC relay 的进度记录仍是双写→用 sink 接受记录+fence（代数门禁）设计；
- **事件溯源 outbox**：验证"outbox 模式保证 exactly-once"的真实边界（§9：store 层崩溃安全 ⟺ 派生镜像忠于提交日志，但 relay 投递需再读 sink）。

### PULSE：时空契约落地
- **冷链**：`when leaves(batch.position, Z) for 10 min changes condition Safe→AtRisk`——连续 10 分钟脱温才告警（采样穿越不误报），全程可审计（证据追加、断言非覆盖），可场景推演（"若暂存区移到 X"在 clone 上问）；
- **地理围栏合规**：船舶/无人机越界监控，时长限定离开+守卫状态迁移，GeoSPARQL/SHACL 视图自动生成供外部引擎验证；
- **供应链时空追踪**：货物出库区域→在途→到货签收状态机，观测（GPS/温感）与断言（签收）分离，义务（在途时长/温度范围）只读约束。

## 诚实标注

- **OADD**：benchmark 局限 HRS 单库（12 万+字段）；评估模型只有 GPT-5.4/5.5 与词法/神经基线（无开源 LLM）；"0.465 仍 <50%"是单 benchmark 结论；miner 用 GPT-5.5 构建标签可能引入与评估模型同源偏差；
- **Dual-Write**：单作者论文；模型是"单一单向对"（记录权威→接受端点→一个方向），双向/多对/多权威形状在 §10 列为刻意缺失；**不验证任何具体产品**；正结果全部条件化（P1-P4 等）；
- **PULSE**：自出版 preprint（DeepLethe 研究机构）；作者明确声明"语言优越性与可用性在评估之外"；Lean 从 parsing 后开始、抽象几何/浮点谓词；冷链案例单轨道；IBTrACS 是回顾性数据；H3 近似；第二作者独立审查但无独立重实现；
- 三篇中 OADD 与 PULSE 提供开源 artifact（OADD-Bench 仓库 / PULSE commit 798fb7e4e4ef）；Dual-Write 未提及代码仓库（论文自称可随 Artifact 获取但未确认）。
