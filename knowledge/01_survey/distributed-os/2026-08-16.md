## 集合通信库与多路径优化

- **NIMBLE / OSU（2604.00317, 2026-04）**: 针对 NCCL/MPI+UCX 依赖静态最短路径路由或哈希多rail条带化导致链路利用率不均的问题，提出运行时通信编排系统 NIMBLE——容量归一化最小拥塞优化（multiplicative-weights 算法求解）+ CUDA-aware GPU kernel 级 RDMA 流水（经中间 GPU 与 rail 匹配 NIC 转发）；端到端驱动、无需改应用，保持顺序性/确定性。H100-SXM4 全 NVLink + 4×NDR400 rails 上：intra-node 带宽最高 **2.3x**、inter-node 吞吐 **3.8x**；skewed All-to-All 超 NCCL/MPI 最高 **5.2x**，端到端 LLM MoE 工作负载 **1.35x**，均衡流量下与基线持平（URL: https://arxiv.org/abs/2604.00317）

- **FlexLink（2510.15882, 2025-10）**: 首个把 NVLink+PCIe+RDMA NIC 三类异构链路聚合为单一通信织物的集合通信框架——两阶段自适应负载均衡动态切分流量，避免慢链路拖累快链路；8×H800 上 AllReduce/AllGather 较 NCCL 基线提升 **26%/27%**（仅将 2-22% 流量卸载到此前闲置的 PCIe/RDMA NIC），NCCL API 兼容、无损 drop-in 替换（URL: https://arxiv.org/abs/2510.15882）

- **HetCCL（2601.22585, 2026-01）**: 面向异构 GPU 集群的集合通信库——统一厂商后端并启用跨 GPU 的 RDMA 通信，无需驱动修改；机制上复用优化的厂商库（NVIDIA NCCL + AMD RCCL）实现跨厂商互通；同构场景匹配 NCCL/RCCL 性能，异构环境唯一可扩展方案，现有深度学习应用零改动（URL: https://arxiv.org/abs/2601.22585）

- **Nezha（2405.17870, 2026-02 更新版）**: 首个协议无关多rail网络系统——统一抽象协调 SHARP（网内计算）、自适应 RDMA（GLEX）与 TCP，解决静态单rail绑定利用率低、TCP-RDMA 异构协议同步延迟、主流库缺跨协议协调三大问题；协议感知动态负载均衡（冷/热启动状态机），单rail故障 **200ms** 内自愈重路由；8 节点集群吞吐较 MPTCP 高 **74%（TCP-TCP）/80%（TCP-SHARP）**，128 节点超算训练效率较 Gloo 高 **2.36x**（URL: https://arxiv.org/abs/2405.17870）

## GPU-initiated 通信与 RDMA 容错

- **GPU-Initiated Networking (GIN) for NCCL / NVIDIA（2511.15076, 2025-11）**: NCCL 2.28 引入 Device API 三模式（LSA-NVLink/PCIe、Multimem-NVLink SHARP、GIN-网络RDMA）；GIN 三层架构=host 侧 Device API 通信子初始化+设备侧 CUDA kernel 远程内存操作+双语义网络插件（GPUDirect Async Kernel-Initiated 经 DOCA GPUNetIO 直连 GPU→NIC / Proxy 经 lock-free GPU→CPU 队列兼容标准 RDMA 网络）；已与 DeepEP 集成验证，device-initiated 通信进入 NCCL 统一运行时（URL: https://arxiv.org/abs/2511.15076）

- **SHIFT / 上交+UW（2512.11094, 2025-12）**: 首次证明 RDMA 跨 NIC 容错三难（Trilemma）：Cross-NIC RDMA failover 无法同时满足 Exactly-Once 执行、Receiver-NIC 透明性、零拷贝数据路径；利用 NCCL 等主导训练框架的幂等批量传输容忍宽松内存序（仅需保序通知）的观察，在 rdma-core 中实现用户态 SHIFT 层，PyTorch 分布式训练验证：正常开销可忽略、可屏蔽致命 NIC 故障与链路异常、训练免昂贵重启（URL: https://arxiv.org/abs/2512.11094）
