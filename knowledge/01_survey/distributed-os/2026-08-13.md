## §1 新增信号

- **NVIDIA 官方: How to Choose Full-Stack Observability for NVIDIA AI Factories**（2026-08-12, Jorge Cardoso, NVIDIA Technical Blog, NCCL tag）: 官方 48 天静默（06-25 后）首篇 NCCL 关联文章，提出 AI 工厂**五层全栈可观测性框架**（平台/GPU/网络/集群作业/推理服务）与**组件→工具映射矩阵**：DCGM（GPU 利用率/功耗/NVLink/XID-ECC）、NVSM（DGX 系统健康）、UFM（IB 端口/BER/拥塞）、NetQ（Spectrum 以太网/RoCE）、NMX（rack-scale NVLink）、BCM（集群聚合）、Run:ai/NIM（推理 SLO）。**核心概念**: ① **gray failure 级联**——分布式训练 BSP 模型对 straggler 极度敏感，单条 IB 链路 BER 漂移（SymbolErrorCounter/Effective_BER 指标）→ NCCL all-reduce 重传阻塞单 rank → 吞吐塌陷到最慢 rank（"tail-at-scale"）；② **top-k 告警集绑定 SLO/SLI**，反对指标堆砌（"watermelon metrics" 外绿内烂）；③ 最小工具覆盖原则（green cell 全覆盖 + 最少工具），统一 Prometheus/Grafana 分层 triage（L1 总览 → L2 厂商 UI 深钻）。**分布式OS视角**: NVIDIA 首次把「可观测性选择」从产品罗列上升为**决策框架**——故障域枚举→工具映射→告警精简→验收标准，与 B300 现场报告（08-08 收录）同属「运维实证」体裁，且其 gray failure 级联模型是集群 RAS 设计的官方背书。URL: https://developer.nvidia.com/blog/how-to-choose-full-stack-observability-for-nvidia-ai-factories/

- **SCOUT: Symmetric Consensus Outlier Detection for Failure Localization in LLM Pre-Training**（arXiv 2608.11034, 2026-08-12, Zhuang Wang 等, cs.DC）: LLM 预训练**故障定位**——BSP 同步把 rank 本地 stall/降速/数值错误传播为作业级症状，掩盖故障源；现有 in-process 监控在 trainer 阻塞/终止后失报，post-mortem 日志滞后。SCOUT 用**对称共识离群检测**（rank 间对等比较）在同步屏障处定位离群 rank，无需中心监控。**分布式OS视角**: 与 NVIDIA gray failure 模型（今日 §1 首条）互为镜像——官方给出故障传播模型，SCOUT 给出无中心故障定位算法；预训练故障定位从「事后日志分析」走向「同步点在线检测」，是 RAS 面在 LLM 训练场景的核心增量。URL: https://arxiv.org/abs/2608.11034

- **ClusterBench: A Framework for Cluster-Wide Continuous Benchmarking and Regression Testing**（arXiv 2608.10956, 2026-08-12, Aditya Ujeniya 等, cs.DC）: 数据中心需要**校验整集群安装**而非单节点——单次提交把相同基准调度到每个节点（cluster-aware scheduling），在验收期与后续周期执行。**分布式OS视角**: 把「基准测试」从单机工具升级为**集群级连续回归测试面**——与 08-08 收录的 B300 现场报告（规模化验收）互补：一个讲验收方法论，一个给可执行框架；集群健康度从「节点健康」转向「全集群一致性」度量。URL: https://arxiv.org/abs/2608.10956

- **C2C-Explorer: An Exploration Framework for Chip-to-Chip Interconnect Architectures in LLM Cloud Computing Systems**（arXiv 2608.08611, 2026-08-09, Jiayi Li 等, cs.DC, 补追 Tue 11 Aug 批次）: 面向 LLM 云计算的 **C2C（chip-to-chip）互联架构探索框架**——解决多处理器芯片系统 C2C 硬件设计三挑战（工作负载多样化/拓扑空间大/评估成本高）。**分布式OS视角**: 直接命中本专题 P1 面（UALink/CXL/PCIe/NVLink 互联架构设计）——C2C 互联设计从「厂商私有点」走向「可系统探索的设计空间」，与超节点（NVL72 级）互联架构评估同向。**交叉登记**: 建议 reliability-testing 专题关注（互联架构评估=RAS 前置）。URL: https://arxiv.org/abs/2608.08611

- **FlashBoot: Sub-Second Weight Loading for Large Models at Rack Scale**（arXiv 2608.08482, 2026-08-09, Issac Zhu 等, cs.DC, 补追 Tue 11 Aug 批次）: 旗舰 MoE 模型参数量与专家数双轴增长，弹性部署时多节点多 GPU 需快速进入 serving-ready——权重加载成为显著瓶颈；提出**机架级亚秒权重加载**方案。**分布式OS视角**: 权重加载=分布式OS存储/IO 面与冷启动的交汇点（08-11 收录 cold-start initscripts 的相邻面）——弹性推理（autoscaling）的启动路径正在成为独立优化对象，存储层次（本地 NVMe/远端内存池）与通信路径共同决定加载延迟。URL: https://arxiv.org/abs/2608.08482

- **OasisKV: Scaling In-Decode KV Cache Beyond HBM with Lookahead Sparse Prefetching**（arXiv 2608.08097, 2026-08-08, Can Xiao 等, cs.DC, 补追 Tue 11 Aug 批次）: LLM 推理服务受**内存而非算力**约束，长上下文/长推理下 KV cache 主导内存占用与流量；提出**lookahead 稀疏预取**把 in-decode KV cache 扩展到 HBM 之外（CPU/持久层），预取受注意力模式引导。**分布式OS视角**: KV 生命周期管理再下一城——08-10 HiSparse（层级放置）+ 今日 OasisKV（预取）+ ImpactHO（迁移）三线汇聚，「KV 分层命运」（L0 HBM→L3 持久）从框架落地为**可运行系统族**，推理内存管理层成为分布式OS最活跃研究面之一（趋势 11 强化）。URL: https://arxiv.org/abs/2608.08097

- **ElastiCo: Elastic Configuration and Interference-Aware Orchestration for GPU Clusters**（arXiv 2608.07971, 2026-08-08, Jinghao Wang 等, cs.DC, 补追 Tue 11 Aug 批次）: 现代 GPU 集群须同时服务训练与离线 LLM 推理，现有调度器视为孤立资源消费者、静态分配，导致 GPU 容量利用不足；提出**弹性配置 + 干扰感知编排**。**分布式OS视角**: 训练/推理混部（co-location）的干扰模型成为调度器核心组件——与 08-02 HorizonServe（SLO 异质）合流，集群调度从「资源份额」走向「干扰感知弹性」，是超节点集群管理（万卡混部）的工程前沿。URL: https://arxiv.org/abs/2608.07971

## 🧠 趋势判断

1. **one-sided 抽象迭代**：「窗口」模型 → 「通道+计数器」模型（RAMC）—— **维持**
2. **GPU 自主 I/O 全面化**：GORIO + GNStor + LGNNIC（SmartNIC GNN）汇聚，CPU 从 I/O 关键路径持续退位 —— **强化**（LGNNIC 补追，SmartNIC 卸载谱系再添一员）
3. **远端并发控制是解聚软件栈核心空白**：RDMA 哈希表综述（CWSN'26）三挑战 —— **维持**
4. **分布式推理 = 机密计算底座**：MOSAIC 确认 RDMA 分布式推理已是非机密 AI 标准形态 —— **维持**
5. **通信可观测性成为 NCCL 生态新前线**：NIXT + NCCL Inspector + **官方全栈可观测性框架**（08-12）—— **强化**（官方 48 天静默终结，gray failure 级联模型成官方口径）
6. **配置面成为大规模训练性能第一变量**：Exemplar Cloud 四案例 8%~53% 差距 —— **维持**
7. **多租户隔离的粒度选择成为工程决策**：NVIDIA 官方「按需求选隔离粒度」+ ElastiCo 干扰感知 —— **强化**（混部干扰模型进调度器）
8. **超大规模自研芯片厂商的集合通信栈全面自研化**：HCCL 编译式模型 + 片上 NMC 卸载 —— **维持**
9. **GPU 通信系统编程成为 LLM 能力评测新战场**：CommBench 证明 GPT-5.5 仅 30.7% 达标 —— **维持**
10. **「运维实证」成为分布式训练论文新体裁**：B300 现场报告 + Exemplar Cloud + **官方可观测性决策框架 + ClusterBench** —— **强化**（验收/回归测试工具化）
11. **推理内存管理（KV 分层）上升为分布式OS核心面**（强化）: HiSparse（层级放置 08-10）→ **OasisKV（HBM 外预取）+ ImpactHO（迁移）**——「放置/预取/迁移」三机制齐备，KV 生命周期管理从单点走向系统化 —— **强化**
12. **推理服务质量契约化**：Cascade + HorizonServe 合流，SLO 达标率×吞吐成为调度目标 —— **维持**
13. **预训练故障定位走向同步点在线检测**（今日新增）: SCOUT 对称共识离群检测 + 官方 gray failure 模型互为印证——BSP 同步屏障成为故障定位天然锚点，无中心化定位算法成 RAS 新方向 —— **新增**
