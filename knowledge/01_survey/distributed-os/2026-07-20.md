## 1️⃣ 🔬 SysOM-AI: 阿里巴巴80,000 GPU生产级跨层性能诊断 (arXiv:2603.29235) 🔥

- **来源**: arXiv:2603.29235, "SysOM-AI: Continuous Cross-Layer Performance Diagnosis for Production AI Training" (2026-03-31)
- **作者**: Yusheng Zheng, Wenan Mao, Shuyi Cheng, Fuqiu Feng, Guangshui Li, Zhaoyan Liao, Yongzhuo Huang, Zhenwei Xiao, Yuqing Li, Andi Quinn, Tao Ma (阿里巴巴)
- **标签**: `Production Observability` · `Performance Diagnosis` · `eBPF` · `NCCL` · `80,000 GPUs` · `Cross-Layer`

### 背景与核心问题

生产级 AI 训练性能诊断极度困难。原因：

| 挑战 | 具体表现 |
|:-----|:---------|
| **级联效应** | 细微 OS 级问题可引发 GPU 延迟和网络降速的级联放大，波及数千 GPU |
| **工具局限** | 现有工具局限于单一系统层，开销大（10-30%），缺乏持续部署能力 |
| **人工诊断** | 跨层问题的人工分析需要数天时间 |

**SysOM-AI 的命题**: 能否做到**持续、跨层、低开销**的生产可观测性，使诊断从**天级→分钟级**？

### 系统设计

#### 核心方法: OS级仪表 + 分层差分诊断

| 组件 | 技术 | 说明 |
|:-----|:-----|:------|
| **CPU 栈** | 自适应混合栈展开 (adaptive hybrid stack unwinding) | 持续 profiling CPU 状态 |
| **GPU Kernel** | 内核追踪 (GPU kernel tracing) | 监控 GPU kernel 执行行为 |
| **NCCL 事件** | eBPF 仪表 (eBPF-based tracing) | 捕捉 NCCL 通信事件，包括集合操作延迟、同步等待等 |

#### 关键技术特性

| 指标 | 数据 |
|:-----|:------|
| **部署规模** | **80,000+ GPU** |
| **运行时长** | **1年+** 持续生产部署 |
| **性能开销** | **<0.4%**（对比现有工具 10-30%） |
| **诊断问题** | **94 个确认生产问题** |
| **诊断速度** | 中位数 **~10 分钟**（从原来的数天） |
| **实现方式** | OS 级 + eBPF，无需修改用户代码 |

### 诊断覆盖的问题类型

SysOM-AI 能诊断的 94 个生产问题涵盖：

| 问题层面 | 示例 |
|:---------|:------|
| **OS/内核** | 调度延迟、内存碎片、cgroup 限制不当 |
| **网络** | TCP 重传、NCCL 同步等待异常、RoCE PFC 死锁 |
| **GPU** | 慢 kernel、GPU 内存泄漏、ECC 错误导致的重置 |
| **应用** | 负载不均衡、通信模式异常、梯度同步瓶颈 |

### 意义

1. **🏭 已证明的万卡级方案**: 80,000 GPU 一年+的生产验证是史上最大规模 AI 训练可观测性部署之一
2. **⚡ 极低开销的关键**: <0.4% 的开销使 continuous profiling 成为可能——无需在出问题时才"插桩"
3. **🔗 NCCL 层面 eBPF 仪表**: 直接捕获 NCCL 通信事件，为集合通信性能诊断提供了 OS 级可视性
4. **🆚 与 NCCLbpf (07-11) 互补**: NCCLbpf 是单点 NCCL 策略验证（eBPF 执行 NCCL 插件策略），SysOM-AI 是全局跨层可观测性——两者组合 = "策略验证 + 性能诊断"
5. **🆚 与 ARGUS (07-16) 互补**: ARGUS 是微软万卡追踪 <2% 开销，SysOM-AI 是阿里 8 万卡 <0.4%——两大云厂商方案可对照

## 2️⃣ 🌐 NetKV: 网络感知 Decode 实例选择 — 解耦推理拓扑优化 (arXiv:2606.03910)

- **来源**: arXiv:2606.03910, "NetKV: Network-Aware Decode Instance Selection for Disaggregated LLM Inference" (2026-06-02)
- **作者**: Mubarak Adetunji Ojewale (单作者)
- **标签**: `Disaggregated Inference` · `Network-Aware Scheduling` · `KV Cache` · `TTFT` · `Fat-Tree` · `Mooncake`

### 背景与核心问题

**解耦 LLM 推理**中，KV cache 必须在 decode 开始前遍历数据中心网络 → 传输时间直接进入 **TTFT (Time to First Token)** 预算。

当前调度器的问题：

| 当前做法 | 忽略什么 | 后果 |
|:---------|:---------|:-----|
| 只考虑 compute load | 拓扑距离和动态拥塞 | KV cache 可能被调度到网络远端 |
| 只考虑 prefix-cache locality | 网络条件变化 | TTFT 不可预测 |
| 静态路由 | 路径拥塞 | SLO 达标率下降 |

### NetKV 设计

#### 核心理念: 网络成本显式纳入调度决策

**系统架构**:
```
Prefill Instance ---> KV Cache ---> Network ---> Decode Instance
                            ^                       |
                            +-- NetKV Scheduler -----+
                                    |
                            Network Cost Oracle
                                    |
                            Topology + Congestion info
```

| 组件 | 功能 |
|:-----|:------|
| **Network Cost Oracle** | 薄层 operator-to-scheduler 接口，提供拓扑距离+动态拥塞信息 |
| **NetKV Scheduler** | O(\|D\|) 每请求贪心算法（per-request greedy） |
| **Tier Rankings** | 层级排序**对过时遥测数据具有鲁棒性**（provably robust to stale telemetry） |

#### 理论保证

论文证明：**忽略网络项会使仅缓存感知调度在上下文长度增长时任意次优**（arbitrarily suboptimal as context length grows）。

### 性能数据

| 指标 | 数据 | 对比基线 |
|:-----|:------|:---------|
| **平均 TTFT 降低** | **-21.2%** | vs round-robin |
| **平均 TTFT 降低** | **-17.6%** | vs 调优的 cache+load 感知调度器 |
| **SLO 达标率提升** | **+20.1 百分点** | vs 最优基线 |
| **TBT 开销** | **<0.5 ms** 所有测试条件下 | 无网络感知方案劣化严重 |
| **仿真环境** | 64-GPU, 4-tier fat-tree | Mooncake traces |

| 不需要修改 | 具体 |
|:-----------|:------|
| Transport | 无需改 RDMA/TCP 协议栈 |
| Inference Engine | 无需改推理引擎代码 |
| Hardware | 无需改 GPU/网卡/交换机 |

### 意义

1. **⚡ 解耦推理的核心瓶颈实证**: 首次量化网络拓扑+拥塞对 TTFT 的独立影响——**21.2% 的改善仅来自调度，不碰任何硬件**
2. **📐 理论证明的厚度**: "忽略网络项任意次优"是一个重要的理论结果——为解耦推理调度设计提供了信息论方向的指引
3. **🔧 极低接入成本**: 薄层 oracle 接口 + 无修改 transport/inference/hardware——生产部署路径清晰
4. **🆚 与 Disaggregated Inference 系列互补**: 与 07-15 的 StageFrontier（同步阶段记账）、07-16 的 CUCo（Agent 算通协同）、07-19 的 ASAP（异步解耦 MoE 推理）一起，构成了解耦推理优化的完整拼图
