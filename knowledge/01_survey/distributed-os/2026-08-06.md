## §1 新增信号

- **NVIDIA Exemplar Cloud: Lessons for Unlocking Full Performance on AI Infrastructure**（NVIDIA Technical Blog, 2026-07-30）: 相同 H100/GB200 NVL72/GB300 NVL72 硬件构建的集群，训练吞吐可差 **8%~12%**（同模型同 batch size），根因是 kernel/hypervisor/BIOS/NCCL 四层配置各自损失几个百分点后复合累积，导致无法通过 95% Exemplar 阈值。**案例1**（GB200 NVL72 VM 跑 DeepSeek-V3 MoE FP8，慢 12%）：perf 显示 24% CPU 周期耗在 `arm_smmu_cmdq_issue_cmdlist`——虚拟化下每次 map/unmap 的 SMMU invalidation 陷入 host 并串行化；启用 **CMDQV/VCMDQ**（SMMUv3 Command Queue Virtualization，guest 直发 invalidation 免 VM exit）后 MoE 迭代时间回到 RA 容差内。**案例2**（H100 SXM5，慢 12%）：BIOS 把 C-state 锁在 C1（"低延迟"默认值，对 AI 训练反而是错的）→ 空闲核持续耗包功率、忙核抢不到 turbo（3.0 vs 3.8 GHz）+ 18% NUMA-remote 访问；改 C6 + cpuset 隔离 + numactl 绑定后恢复 9%。**案例3**（GB300 NVL72 + ConnectX-8 SuperNIC 1.6 Tbps，512 GPU 慢 31%）：`NCCL_IB_QPS_PER_CONNECTION` 从默认 1 提到 4，AllGather 375ms→262ms、ReduceScatter 389ms→273ms；但明确警告 **QPS 是 fabric/消息大小相关的，不能全局照搬**。**案例4**（B200 VM，慢 13%~53%）：`NCCL_TOPO_FILE` 在 VM 上设置了但未传入 enroot 容器（变量没传播 + /etc/nccl/topo.xml 没挂载）→ NCCL 静默回退 auto-detection，AllGather/ReduceScatter 2~4× 慢、无任何报错；`--mount type=bind` 后关闭差距。**相关性**: 极高——四个案例分别命中分布式 OS 的虚拟化层（SMMU/IOMMU 序列化）、电源/拓扑调度层（C-state/NUMA/cpuset）、集合通信配置层（NCCL QPS）、容器隔离层（env/topo 传播），是"AI 集群 OS 编排"主题的第一手工程素材。URL: https://developer.nvidia.com/blog/nvidia-exemplar-cloud-lessons-for-unlocking-full-performance-on-ai-infrastructure/

- **How to Run Isolated Tenant Kubernetes Clusters on Shared GPU Infrastructure**（NVIDIA Technical Blog, 2026-08-03）: 每个团队一个专用 K8s 集群往往隔离过度——运维成本高、GPU 池碎片化。文章探讨在**共享 GPU 基础设施上运行隔离租户集群**的架构取舍（命名空间级隔离 vs 独立集群 vs 混合），核心论点是"按需选择隔离粒度"：团队级隔离需求通常低于组织级，共享控制面 + 租户级资源配额（GPU 份额/节点池/污点容忍）可在保证隔离的同时提升 GPU 利用率。**相关性**: 高——资源调度与隔离主题直接命中；与 08-02 收录的 MemExchange（多租户内存再分配）同属"多租户资源共享"谱系，但此篇聚焦 K8s 控制面层而非内存数据面。URL: https://developer.nvidia.com/blog/how-to-run-isolated-tenant-kubernetes-clusters-on-shared-gpu-infrastructure/

## 🧠 趋势判断

1. **one-sided 抽象迭代**：「窗口」模型 → 「通道+计数器」模型（RAMC），19.6k 进程/带宽+100-130% —— **维持**
2. **GPU 自主 I/O 全面化**：GORIO + GNStor 汇聚，CPU 从 I/O 关键路径持续退位 —— **维持**
3. **远端并发控制是解聚软件栈核心空白**：RDMA 哈希表综述（CWSN'26）明确三挑战 —— **维持**
4. **分布式推理 = 机密计算底座**：MOSAIC 确认 RDMA 分布式推理已是非机密 AI 标准形态 —— **维持**
5. **通信可观测性成为 NCCL 生态新前线**：NIXT（arXiv）+ NVIDIA 官方 NCCL Inspector+Prometheus 博客汇聚，profiling 从"测带宽"走向"归因定位" —— **维持**
6. **配置面成为大规模训练性能第一变量**（今日新增）：Exemplar Cloud 四案例证明 8%~53% 的性能差距全部源于 OS/虚拟化/容器配置复合累积（SMMU 序列化、C-state/NUMA、NCCL QPS、env 传播），而非硬件或算法——"分布式 OS 的配置面"（而非数据面）是 AI 集群性能差异的最大来源，且多为**静默失败**（NCCL 回退 auto-detection 无报错）——**新增**
