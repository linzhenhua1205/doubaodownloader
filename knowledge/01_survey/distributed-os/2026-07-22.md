## 1️⃣ 🏆 NCCL SoL: 达到物理极限的GPU集合通信微秒级延迟 (arXiv:2607.16100, Jul 17) 🔥🔥🔥

> **含NVIDIA NCCL负责人 Sylvain Jeaugey + ETH Torsten Hoefler** — 这是2026年NCCL社区最重要的学术论文

### 核心命题

集合通信长期被**带宽优化主导**，但长序列解码推理中大量**小消息体集合操作**直接位于Token生成的关键路径上——**每微秒延迟都影响吞吐和成本**。本文系统研究如何在scale-up网络内逼近硬件**Speed-of-Light (SoL)** 下界。

### 三大设计原则

| 原则 | 传统做法 | NCCL SoL 做法 |
|:-----|:---------|:--------------|
| **Barrier-Free Sync** | 通信前必须全局同步（top/bottom barrier）| **消除同步屏障**，利用 NCCL Device API 直接触发 |
| **Symmetric Memory** | 使用独立通信缓冲区，需拷贝 | 利用 NCCL **Symmetric Memory** 零拷贝直接访问 |
| **Multicast** | 点对点传输后多播复制 | 硬件 **multicast** 能力（NVLink/NVSwitch 原生支持）|

### 技术实现

基于 **NCCL Device API**（GIN, 06-28/07-01）构建低延迟接口，实现**自定义collective kernel**：

```
NCCL Device API -> 自定义 barrier-free 同步原语 -> 
Symmetric Memory 零拷贝 -> 硬件 multicast -> 
微秒级 SoL 逼近
```

### 性能数据

| 指标 | 数据 |
|:-----|:------|
| SoL 逼近度 | **距绝对 SoL 下界 <7%**（微秒级） |
| 减少方法 | 同机箱小消息 latencies **大幅削减** |
| LLM 推理 | **inter-token latency 和吞吐显著改善** |
| HPC 传统负载 | **cuSOLVERMp 加速**（证明不仅 AI 受益） |
| 接口 | NCCL Device API + 自定义 kernel（现有 NCCL 生态兼容） |

### 📌 深度洞察

**这篇文章在追踪体系中的定位极其特殊**——它不是在NCCL之上做应用层优化，而是**从NCCL内部、在Device API层、直接逼近物理极限**。

**与系列的关系**:
- 与 `SiFAR (07-21)` 互补：SiFAR 消除 All-Reduce 的同步屏障（软件层），NCCL SoL 在 Device API 层消除 barrier + 利用 multicast
- 与 `GIN (06-28/07-01)` 同源：都基于 NCCL Device API，但 GIN 聚焦 GPU-Initiated RDMA，NCCL SoL 聚焦 scale-up 网络极致延迟
- 与 `CTA-Pipelining (07-10)` 互补：CTA-Pipelining 利用 CTA 级依赖并发执行，NCCL SoL 利用硬件 multicast 消除通信延迟
- 与 `OptiNIC (07-01)` 对照：OptiNIC 在 RoCE NIC 层去掉重传，NCCL SoL 在 scale-up NVLink 层逼近物理极限

## 2️⃣ 🧮 LAGA: MLA训练通信减半 — 1.98× 集合通信压缩 (arXiv:2607.17644, Jul 20)

### 核心命题

DeepSeek-V3 等模型的 **Multi-head Latent Attention (MLA)** 在 Megatron-Core 中有两种实现：显式（训练用）和吸收式（推理用）。但吸收式虽然在推理中削减集合通信（只收集压缩 latent），**移植到训练时反而是内存陷阱**——中间变量膨胀 20-34%，最高 9.2GB。

### LAGA 设计

LAGA (Latent All-Gather Attention) **保留吸收式的 latent-gather 通信优势**，但**放弃吸收式重算方案**，改为从收集的 latent 在本地重建每头 K/V：

```
吸收式:     收集 latent -> 吸收重算 K/V -> 增大内存 20-34%
LAGA:       收集 latent -> 本地重建 K/V -> 内存仅 +0.5%
              v
        集合通信量 × 1.98 减少
```

### 性能数据

| 指标 | LAGA vs 显式(训练基线) | 对比说明 |
|:-----|:-----------------------|:---------|
| 集合通信量 | **↓1.98×**（近减半） | 关键收益 |
| 激活内存 | **+0.5%**（基线），吸收式 +20-34% | 无内存陷阱 |
| 精度偏差 | SP=1 **比特一致**；SP=2-8 **<1e-3** | 精度无损 |
| 单节点 attention 吞吐 | **↑1.04-1.06×** | 融合 kernel |
| 跨节点 attention 吞吐 | **↑1.07-1.24×** | 所有序列长度领先 |
| 硬件 | 8× Ascend 910B + DeepSeek-V3 真实维度 | 国产化验证 |

### 📌 深度洞察

LAGA 的价值远超一个"fix"——它揭示了 MLA 训练中一个被 Megatron-Core 硬编码禁用的设计空间。本质上：**吸收式的通信优势（收集压缩 latent）和解码的内存优势（吸收重算）在训练场景是互斥的**——LAGA 证明你可以取通信优势而放弃内存优势（因为训练更受困于通信）。

**与系列的关系**:
- 与 `Move the Query (07-11)` 形成对照：Move the Query 让 RDMA 感知 MLA 拓扑跨实例调度；LAGA 从集合通信协议层面削减 MLA 训练通信量
- 与 `UBEP (07-21)` 互补：二者都致力于削减 MoE/注意力层的集合通信——UBEP 在 All-to-All 层，LAGA 在 AllGather 层
- 与 `GIFT (07-21)` 可叠加：GIFT 压缩梯度通信质量，LAGA 减少 MLA 前向/反向通信量——作用于不同阶段

## 3️⃣ 🔄 ExpertPlex: MoE专家共享 + 通信解耦 — goodput 2.01× (arXiv:2607.18002, Jul 20)

### 核心命题

解耦推理中 prefill-decode 分离各自持有完整 MoE 副本 → **95% 以上重复权重**。但将 prefill 和 decode 共置又会引入**网络干扰**（prefill 的大流量干扰 decode 的延迟敏感通信）。

### 创新架构

```
传统解耦:  [prefill 实例全套 MoE]     [decode 实例全套 MoE]  -> 权重重复 95%+
ExpertPlex: [attention 解耦] + [MoE 专家共享] + [attention-initiated MoE 通信]
                                     v
                             权重重复消除 95%+ + 网络干扰消除
```

### 关键技术

| 技术 | 描述 | 解决的问题 |
|:-----|:------|:----------|
| **专家共享** | MoE 参数跨 prefill/decode 共享，attention 模块解耦 | 重复权重 95%+ |
| **自适应持久化 kernel** | tile 粒度动态调度 expert 计算，隔离执行 | 计算效率 + 隔离性 |
| **Attention-Initiated MoE 通信** | attention 模块触发 MoE 的 token 路由通信，避免与 decode 流量竞争 | **网络干扰消除** |
| **tile-to-cluster 模型** | 端到端优化模型最大化 goodput | 系统级优化 |

### 性能数据

| 对比基线 | Goodput 提升 |
|:---------|:-------------|
| vs 实例级 prefill-decode 分离 | **↑2.01×** |
| vs prefill-decode 共置 (Green Context) | **↑1.66×** |
| 模型验证 | MiniMax-M2.7 + GLM-5.1-FP8 |

### 📌 深度洞察

ExpertPlex 的 **Attention-Initiated MoE 通信** 是核心创新——它不是简单地"把专家共享了"，而是设计了 attention 模块主动触发 MoE 的通信流程，让 prefill 和 decode 两个阶段的 MoE 通信在时间上错开，避免在共享网络上竞争带宽。

**与系列的关系**:
- 与 `UBEP (07-21)` 对照：UBEP 优化 MoE 单阶段（推理时 All-to-All），ExpertPlex 优化两阶段编排（prefill↔decode 共享+隔离）
- 与 `ASAP (07-19)` 互补：ASAP 全异步化 DP↔EP 同步，ExpertPlex 用 attention-initiated 触发实现 prefill↔decode 协同
- 与 `DisagMoE (07-08)` 对比：DisagMoE 在训练场景解耦预填充，ExpertPlex 在推理场景解耦 attention 并共享 MoE
