## §1 新增信号（昨日未收录）

- **RAMC: Remote Access Memory Channels over HPE Slingshot**（arXiv:2606.05094, 2026-06-03, Sandia National Labs）: 现有 one-sided 框架（MPI RMA/OpenSHMEM）依赖单片共享内存模型，假设对称内存区域或需阻塞式集合操作创建窗口；PGAS/UPC 隐式模型最终仍依赖显式机制；MPI partitioned API 提供持久点对点接口但牺牲 RDMA 动态灵活性。RAMC 以**持久单向通信通道**为核心概念，利用 Slingshot 独有**内存区域计数器**实现高效完成通知（免轮询/免显式 fence）。热扩散基准扩展至 **19.6k 进程 / 250 节点**无压力；微基准较 Cray 专有 MPI：libfabric 1.15.2 下 1B-4KiB 消息带宽提升 **100-130%**、libfabric 2.3.1 下 30-45%；小消息延迟仍为改进方向。**意义**: one-sided 通信的"通道+计数器"抽象提供比 window 模型更灵活、可扩展到万进程以上的替代范式，对国产互连软件栈设计有借鉴价值。URL: http://arxiv.org/abs/2606.05094

- **GORIO: GPU-Centered Remote I/O for Graph ANNS over NVMe-oF**（arXiv:2607.04415, 2026-07-07）: 现有远端存储路径 CPU-centric：CPU 形成 I/O 请求、驱动传输进度、决定 GPU 何时恢复计算——与图 ANNS（下一数据访问在 GPU 图遍历内部被发现）天然错配。GORIO 将查询演进、page-miss 生成、pending-query 状态、恢复决策全部留在 GPU，CPU 仅作 NVMe-oF 传输与完成代理；两层设计：GPU-direct 远程 I/O 路径（本地页缓存 miss 转为 split-phase 远程操作）+ ANNS 专用调度（图遍历与远程页服务重叠）。SIFT1M DiskANN 式负载 + RDMA NVMe-oF：较 SOTA 远程 I/O 参考路径快 **1.31×**、较直接远程页缓存路径快 **4.89×**。**意义**: "GPU 发起一切 I/O"从本地扩展到远端，CPU 从 I/O 路径中退位为纯代理，与 GPU-direct/NVMe-oF 生态趋势一致。URL: http://arxiv.org/abs/2607.04415

- **Hash Table Design for RDMA: Challenges and Opportunities**（arXiv:2606.24073, 2026-06-23, CWSN 2026 全文）: 同行评审综述，系统化梳理 RDMA 远端哈希表三大挑战：① 单次逻辑哈希表访问可能对应一次或多次远程网络访问，冲突处理与探测进一步放大 RDMA 请求数；② 远端 CPU 被绕过，依赖远端线程的传统并发控制不再适用；③ RDMA NIC 资源（队列、缓存、内存注册、原子操作）受限，对哈希表结构施加新约束。给出优化方向与应对策略（面向 IoT 大数据场景）。**意义**: 为内存解聚/远端 KV 场景的哈希表设计提供全景参考，明确"探测链=网络往返链"是核心成本来源。URL: http://arxiv.org/abs/2606.24073

- **Prism: Profiling-Driven Adaptive Distributed Transformer Inference on Embedded Edge**（arXiv:2605.25682, 2026-05-25, ACM）: 边缘设备分布 Transformer 推理多基于仿真、忽视硬件通信开销。Jetson Orin Nano（WiFi）实测关键发现：**瓶颈不仅是网络带宽，更是 CPU-GPU staging**——Jetson 集成 GPU 无 PCIe/NVLink 通路，NCCL 不可用，所有跨设备通信须经 GLOO 并在 CPU 内存 staging，开销随数据量增长，使 full-tensor 交换在中等模型（ViT）各 batch 下都慢于单设备推理。Prism 组合 Segment Means 压缩 + 轻量离线 profiling，运行时自适应选择本地/分布式执行：较静态分布式 full-tensor 交换延迟降 **65-77%**、能耗降 **34-52%**。**意义**: 用实测数据（而非仿真）打破"分布式必然更快"假设——profiling 驱动自适应是边缘推理的关键使能。URL: http://arxiv.org/abs/2605.25682

## 🧠 趋势判断

1. **one-sided 抽象迭代：从"窗口"走向"通道+计数器"** — RAMC 证明内存区域计数器可替代轮询/显式 fence 完成通知，扩展至 19.6k 进程；为国产互连（UB/其他）one-sided 软件栈提供可借鉴范式
2. **GPU 自主 I/O 全面化** — GORIO（GPU 发起远程 I/O）与昨日 GNStor 方向（GPU-native AFA）汇聚：CPU 从 I/O 关键路径持续退位，GPU-direct 从"数据面"扩展到"控制面"
3. **远端并发控制是解聚软件栈的核心空白** — RDMA 哈希表综述明确：绕过远端 CPU 后传统并发控制失效，需要为 NIC 受限资源（队列/原子操作）重新设计数据结构——这是解聚内存 OS 的共性难题
4. **"分布式最优"假设需实测校验** — Prism 在边缘场景用数据推翻"分布式更快"共识；对服务器集群的启示：CPU-GPU staging 开销在无 NVLink 平台上不可忽略，profiling 驱动执行路径选择成为通用模式
