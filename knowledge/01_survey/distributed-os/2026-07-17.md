## 1️⃣ 🏆 MatrixFSDP: 通信无关矩阵优化器 — 54.6× 优化器步延迟降低

**来源**: arXiv:2607.05895 (2026-07-07) · 作者: Ming Gao, Yanwu Xu, Hao Zhang
**链接**: https://arxiv.org/abs/2607.05895

### 问题

矩阵优化器（如 Muon）通过正交化动量平滑的矩阵更新（Newton-Schulz）来改善收敛，但完整 2D 矩阵输入与 **FSDP/ZeRO-3 参数分片**产生根本冲突：

| 方案 | 做法 | 问题 |
|:-----|:-----|:------|
| **Naive FSDP+Muon** | 每步从分片重建完整矩阵 | 优化器步需额外 weight-sized 通信 |
| **ZeRO-1 owner placement** | 全参数常驻 owner rank | 80GB GPU 无法容纳大模型完整参数 |
| **MatrixFSDP (本文)** | 改变 ZeRO-3 分片布局而非优化器 | 无需优化器步矩阵集体通信 |

### 核心设计

MatrixFSDP 的思路精巧：**不是消除通信，而是改变通信的位置**。

- **对于每个 2D 权重**，一个 DP rank 持有整个矩阵（owner），其他 rank **持有空分片**
- **非矩阵张量**（bias/LayerNorm/embedding）打包到尾部 owner 仍用 AdamW
- 普通 backward reduction 直接将完整 Muon 输入送达 owner rank
- Newton-Schulz 在 owner 本地执行，**零优化器步矩阵集体通信**
- 关键技术：MatrixShard 元数据、balance-aware owner 规划器、确定性 owner-segment P2P 集体通信、owner-buffer pinning、owner-shard checkpoint resharding

### 性能数据

| 配置 | 对比 FSDP2-Muon | 加速比 |
|:-----|:----------------|:------:|
| **单节点** (8×A100, 1 node) | 优化器步延迟 | **4.2×** |
| **多节点** (64×A100, 8 nodes) | 优化器步延迟 | **54.6×** |
| 端到端训练 | 全流程 | **2.15×** |
| 大模型适配 | ZeRO-1 owner 超出80GB | ✅ MatrixFSDP 可运行 |

### 洞察

**关键**: 矩阵优化器的通信问题不是"必须通信多少"，而是**通信发生在哪一步**。MatrixFSDP 将通信从"优化器步的额外集体通信"转化为"backward 中的自然 AllGather"——同样传输量，不同时机，效果天壤之别。**避免通信比优化通信更有效**。

## 2️⃣ ⚡ Pulse: 扩散模型自动流水线并行 — 89% 通信消除，2.3× 吞吐

**来源**: arXiv:2606.19163 (2026-06-17) · **ICDCS'26 (International Conference on Distributed Computing Systems)**
**链接**: https://arxiv.org/abs/2606.19163 · 作者: Boran Sun 等 11 位 (刘方明团队)

### 问题

扩散模型（DiT/Sora/Wan2.2）与纯 Transformer 不同：主干常采用 **UNet 式编码器-解码器结构**，存在异构层和**长程 skip connection**。在传统流水线并行下：

- skip activation 和梯度需要**跨多个流水线边界传输**（P2P 通信成为主导瓶颈）
- 大量**非局部依赖**导致流水线效率严重下降

### 核心设计 — Pulse 三大协同技术

| 组件 | 功能 |
|:-----|:------|
| **① Skip-aware DP partitioner** | 将 skip-connected 的编码器-解码器层**放在同一设备**上，消除 skip 通信；支持对称 collocation 约束下的异构 workload 平衡 |
| **② ILP schedule synthesizer** | 为 stage-to-device 映射生成**气泡高效波调度**（bubble-efficient wave schedules） |
| **③ Hybrid parallelism tuner** | 在内存和网络约束下选择最优 pipeline/data-parallel 度 + microbatch size |

### 性能数据

| 指标 | 数据 |
|:-----|:------|
| **通信量减少** | **89%**（skip 通信完全消除） |
| **训练吞吐提升**（通信受限硬件） | **2.3×** |
| 适用场景 | DiT/Sora/Wan2.2 等扩散生成模型 |

### 洞察

**关键**: Pulse 的核心洞察是 **skip locality 应成为流水线并行的第一类优化目标**。不是优化 skip 通信的带宽/延迟，而是**直接从放置层面消除它**。这与传统流水线并行假设"各层必须按序放置"形成对比——对于 UNet 结构，跨阶段的 skip 连接使得按序放置反而低效。将 skip 连接的层 collocate 后，本地缓存激活值比跨节点传输便宜若干个数量级。

## 3️⃣ 🔄 NVIDIA Nonuniform Tensor Parallelism (NTP): 动态TP度适配保Goodput

**来源**: [NVIDIA Technical Blog](https://developer.nvidia.com/blog/enhancing-goodput-in-large-scale-llm-training-with-nonuniform-tensor-parallelism/) (2026-07-06) · 作者: Farshad Ghodsian, Dheevatsa Mudigere, Daiyaan Arfeen, Ankit More (NVIDIA Compute Architecture Group)
**代码**: Megatron Core developer branch · NVIDIA Resiliency Extension (NVRx)

### 背景

大规模 LLM 训练跨越数千 GPU、运行数周至数月，**设备暂时不可用**是常态而非异常。传统方案（drop replica/fast checkpoint/hot spare）虽能恢复训练，但不可用期间的吞吐损失不可避免。

### 核心思路

**NTP** 不是容忍故障后恢复，而是在故障期间**保持 DP replica 持续贡献有用工作**：

```
正常:      TP-8 -> 8 GPU 全速
GPU故障:   TP-8 -> 自动降为 TP-7 (7 GPU 继续计算)
补偿:      动态功耗提升 -> 7 GPU 超频达到 8 GPU 水平
恢复:      自动升回 TP-8 (overlapped resharding 开销 <1%)
```

### 三大支柱

| 技术 | 说明 |
|:-----|:------|
| **动态 TP 度适配** | 检测 GPU 中断后自动降低 TP degree（如 8→7），剩余 GPU 继续工作，避免整个 replica 丢失 |
| **动态功耗提升** | 借助增强供电/散热设计，**对活性 GPU 临时提频**，补齐因减少 GPU 而损失的算力 |
| **高效 resharding** | tensor shard redistributiuon 与 backward computation + 参数同步 **overlap**，开销 **<1%** |

### 技术规格

| 指标 | 数据 |
|:-----|:------|
| 支撑硬件 | NVIDIA Blackwell / Blackwell Ultra (NVLink 72 GPU scale-up domain, 1,800 GB/s) |
| Resharding 开销 | **<1%**（通过 backward + sync overlap 隐藏） |
| 适用规模 | Up to 72 GPU 的 TP domain |
| 下一步研究 | **Nonuniform Expert Parallelism (NEP)** — 将相同思路扩展到 MoE |

### 洞察

**关键**: NTP 代表了大模型训练弹性从"故障后恢复"到**"故障中持续产出"**的范式转变。结合三个层面的协同——软件层面动态TP降级、硬件层面动态功耗提升、调度层面 overlapped resharding——使得集群 goodput 接近理论上限。这是与 MatrixFSDP (避免通信) 互补的思路：**不完美但持续，比完美但中断更有价值**。
