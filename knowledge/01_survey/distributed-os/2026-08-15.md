## §1 新增信号

- **vToken: Token-Level Virtualization for Reclaimable KV Caches**（arXiv 2608.13263, 2026-08-13, Yuanhang Gao 等, cs.AI/cs.OS, **Fri 14 Aug 批次**）: LLM serving 内存瓶颈下，PagedAttention 用**固定块**管理 KV 减少分配器碎片，但近期 KV eviction 算法以 **token 粒度**运行——块级管理 vs token 级驱逐不匹配 → **块内碎片**使大量已分配 KV 内存不可回收。vToken 是轻量 **token 级虚拟化层**：token-table 间接层解耦「逻辑 token 活性」与「物理块放置」，异步 repack 存活 token 实现物理回收；保持 PagedAttention 内核与 CUDA Graph 兼容。vLLM 实现，H2O/Random/Scissorhands 评估：每请求 retained KV blocks **−27.2%~−72.3%**，SLA 约束吞吐 **+1.37×**，受限 active-KV 预算下最大并发 **+2×**，策略集成 footprint 从 500+ 行降到 <50 行。**分布式OS视角**: **「回收」机制正式落地**——08-10 HiSparse（放置）→ 08-13 OasisKV（预取）+ ImpactHO（迁移）→ 今日 vToken（回收），「KV 分层命运」（L0 HBM→L3 持久）四机制闭环齐备；且 vToken 以**虚拟化层**形式解决（间接层+异步 repack），与 GPU 显存虚拟化（CUDA VMM）同构，推理内存管理从「策略」走向「系统原语」。URL: https://arxiv.org/abs/2608.13263

- **OpScale: Operator-level Provisioning and Autoscaling for LLM Serving**（arXiv 2608.13499, 2026-08-13, Xingqi Cui 等, cs.DC, **Fri 14 Aug 批次**）: 云 GPU 集群 LLM serving 的成本效率与 SLO（TTFT）权衡中，autoscaling 是核心机制，但**扩缩容单元未定**——现有方案把整个模型视为单体单元（monolithic），粒度粗无法捕捉推理负载细粒度动态 → 突发流量下 SLO 违背或 GPU 利用率不足。表征发现**算子级异构性**显著，算子级弹性是可行扩缩原语。OpScale 是算子级编排框架（profiling→provisioning→placement→runtime serving），解决细粒度带来的复杂度与空间爆炸。生产 trace（40 A100 + 24 GB200）评估：**SLO 达标下 GPU −36.3%、功耗 −28%**，或固定成本预算下**吞吐 +44%**。**分布式OS视角**: 扩缩容粒度从「模型」下钻到「算子」——调度/供给从「整模型资源画像」走向「算子级资源画像」，与 GPU 虚拟化/细粒度切分（MIG/CUDA MPS 演进）同向；集群管理从「模型=最小调度单位」松动，是弹性编排的粒度革命（趋势 14 新增依据）。URL: https://arxiv.org/abs/2608.13499

- **TEMPO: Makespan-Aware Expert-Parallel Load Balancing Across Memory- and Compute-Bound Regimes**（arXiv 2608.13057, 2026-08-13, Jie Li 等, cs.DC, **Fri 14 Aug 批次**）: EP（expert-parallel）MoE serving 每层在最慢 GPU 同步。现有 dispatcher（EPLB/LPLB/UltraEP 均衡 token 数、METRO 均衡激活专家数）假设 expert 耗时与单一代理线性相关——两代数据中心 GPU 实测**均不成立**：低于 n*≈156-168 tokens 时 HBM 权重流主导（成本挂在**激活副本**而非 token），高于时 grouped GEMM 按 128-tile M 取整（**拆分 expert 引入 padding 计算**）。提出 max-affine 双态成本模型 t=max(a+bG, c+βN)；实测批次显示代理派发在建模 block time 上差 **1.4-1.6×**（p95 达 1.7×），且**赢家随态翻转**。将逐批派发形式化为固定费用 makespan 问题（两 GPU 全复制 NP-hard），TEMPO 在关键路径外毫秒级求解，SGLang 集成进程外运行、派发与计数收集融合为单内核。8-GPU Testbed A：最差基线 1% 内、混合态最多赢 **15.5%**；Testbed B：Qwen3-235B 吞吐 **+4-6%**、p99 **−15.6%**；DeepSeek-V3（通信主导，态外）仅机制成本。**核心主张是相图而非普适胜利**——部署前可预测两种结局。**分布式OS视角**: **EP 调度代理指标的「第一性修正」**——token 计数/专家计数均非线性真实成本，成本模型须显式区分 memory-bound（HBM 权重流）与 compute-bound（GEMM tile 取整）双态；与 08-13 RoutePack（专家放置）同面互补，是 MoE 调度的成本模型深化（趋势 12 强化依据）。URL: https://arxiv.org/abs/2608.13057

- **Ready Cohorts: Bounding GPU Opportunity and Avoiding Host Round Trips in LLM-Agent Control**（arXiv 2608.12123, 2026-08-12, Josef Liyanjun Chen, cs.DC/cs.OS, **Thu 13 Aug 批次**）: LLM-Agent 服务反复执行模型调用与工具调用之间的小型确定性转换（route outcome→update state→emit next effect）。问：该控制路径何时暴露足够并发工作给 GPU？GPU 计算的路由决策留在设备端会怎样？用固定分区份额 F、精确离线份额 P*、局部上界 U、在线达成份额 A 形式化 **ready-cohort 边界**；851-session 公开 trace 静态泊松重放（10 万目标活跃会话、K=256、50ms 启动期限）：F=30.19%、P*=43.00%、U=45.85%，精确打包恢复固定窗口边界损失的 81.83%。独立机制研究：GPU 计算的二元决策**留在设备端**（替代回传 4 字节给 host 再重派发），4 种 GPU 放置下 36 配置全快，行中位比 **1.19x-2.39x**；14,557,440 次批量调用全部匹配 host oracle；固定嵌套设备图（不消除 host 决策）在 5 放置 60 配置全慢。**分布式OS视角**: LLM-Agent 控制路径的「GPU 机会边界」量化——agent 编排从「host 为中心的控制回路」走向「设备端决策」，与 GORIO（GPU 自主 I/O）、GPU-initiated 通信（趋势 2）同构：**CPU 从控制路径持续退位**的又一实证，agent 化工作负载成为分布式OS控制面新场景。URL: https://arxiv.org/abs/2608.12123

## 🧠 趋势判断

1. **one-sided 抽象迭代**：「窗口」模型 → 「通道+计数器」模型（RAMC）—— **维持**
2. **GPU 自主 I/O 全面化**：GORIO + GNStor + LGNNIC 汇聚，CPU 从 I/O 关键路径退位 —— **强化**（Ready Cohorts：GPU 控制路径决策留在设备端，CPU 从「agent 控制回路」退位，控制面与 I/O 面双线退位）
3. **远端并发控制是解聚软件栈核心空白**：RDMA 哈希表综述（CWSN'26）三挑战 —— **维持**
4. **分布式推理 = 机密计算底座**：MOSAIC 确认 RDMA 分布式推理已是非机密 AI 标准形态 —— **维持**
5. **通信可观测性成为 NCCL 生态新前线**：NIXT + NCCL Inspector + 官方全栈可观测性框架 —— **维持**（官方 08-12 文章后无新增，低频供给）
6. **配置面成为大规模训练性能第一变量**：Exemplar Cloud 四案例 8%~53% 差距 —— **维持**
7. **多租户隔离的粒度选择成为工程决策**：NVIDIA 官方「按需求选隔离粒度」+ ElastiCo 干扰感知 —— **维持**
8. **超大规模自研芯片厂商的集合通信栈全面自研化**：HCCL 编译式模型 + 片上 NMC 卸载 —— **维持**
9. **GPU 通信系统编程成为 LLM 能力评测新战场**：CommBench 证明 GPT-5.5 仅 30.7% 达标 —— **维持**
10. **「运维实证」成为分布式训练论文新体裁**：B300 现场报告 + Exemplar Cloud + 官方可观测性框架 + ClusterBench —— **维持**
11. **推理内存管理（KV 分层）上升为分布式OS核心面**（强化）: HiSparse（放置 08-10）→ OasisKV（预取）+ ImpactHO（迁移 08-13）→ **vToken（回收 08-15）**——「放置/预取/迁移/回收」**四机制闭环齐备**，且回收以虚拟化层原语实现（间接层+异步 repack），推理内存管理从策略集合走向系统层 —— **强化**（四机制闭环）
