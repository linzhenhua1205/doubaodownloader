### arXiv 学术动态（cs.DC 运维/可靠性相关）

- **Docker Logs API 精确恢复契约**（arXiv:2608.01564, 08-03）: 提出 source-bounded exactness（源受限精确恢复）契约——每条保留的源记录最终恰好出现一次于持久化采集输出；修复后的 LogDeck 60/60 次精确 vs 未改 Grafana Alloy 20/60；因果对照 5000 条记录退出场景下按容器 ID 重获取 20/20 恢复、裸发现 0/20——结论：生命周期重获取（lifecycle reacquisition）而非持久化位置决定日志精确恢复，对运维平台日志链路可靠性设计有直接指导意义。https://arxiv.org/abs/2608.01564

- **SLIM: 饱和感知 LLM 服务性能建模**（arXiv:2607.29575, 07-31）: 硬件画像证明吞吐饱和源自 decode 阶段 attention kernel——随 active-context 长度增长的近似恒定算术强度驱动 DRAM 带宽饱和（非单纯 batch 增大）；配套 BCA 工具在满足时延约束下为 OPT 模型识别出最多 55GB 可避免 GPU 内存分配——运维容量管理与性能建模的半解析新路径。https://arxiv.org/abs/2607.29575

- **Aries: 面向 Agent 服务系统的全栈实验框架**（arXiv:2607.29069, 07-31）: 分离任务语义与执行配置，重建跨组件 agent 轨迹+关联系统遥测；结论①token 中心指标遗漏非推理瓶颈 ②保留额外上下文收益递减且降低服务容量 ③工具沙箱长空闲/短突发交替，快照式状态管理使挂起成本高昂——agent 服务场景可观测性度量体系的直接挑战。https://arxiv.org/abs/2607.29069

- **分布式计算连续体性能指标分类法**（arXiv:2607.28407, 07-30）: 结构化分类 DCCS 性能指标（计算/网络/应用级+可持续性/可观测性/数据局部性/迁移感知/碎片化等新兴维度），给出数学定义与采集要求（单节点/多节点/全系统、运维监控 vs 实验评估）——运维指标体系设计的学术框架。https://arxiv.org/abs/2607.28407

- **HDFS 日志块异常检测流式方案**（arXiv:2607.29383, 07-31）: 并行计算处理历史日志 + LLM-BiLSTM 混合模型检测异常块 + Kafka 流式管道实时检测——分布式存储日志异常检测从离线走向实时。https://arxiv.org/abs/2607.29383

## 趋势研判

- **日志采集可靠性走向"契约化"**: Docker Logs API 精确恢复研究（2608.01564）把日志采集从"尽力而为"提升为可证明契约（source-bounded exactness），生命周期重获取成关键变量——运维平台日志链路需按契约设计而非依赖持久化位置。
- **可观测性从"采集数据"升级为"建模预测"**: SLIM 半解析性能模型（2607.29575）与 DCCS 指标分类法（2607.28407）显示运维分析正从指标堆叠走向可解释数学模型——容量规划从经验转向推导。
- **Agentic serving 带来可观测性新挑战**: Aries（2607.29069）实证 token 中心指标遗漏非推理瓶颈、沙箱资源突发性破坏传统容量假设——Agent 时代运维度量体系需重构。
- **OTel 生态双线扩张**: 语言版图（Dart/Flutter CfC）+ 分发通道治理（Swift 迁离 CocoaPods），观测标准向全栈蔓延的同时暴露生态依赖维护成本。
