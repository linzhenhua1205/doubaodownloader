## 一、arXiv 研究动态（AIOps / 异常检测 / 根因分析）

- **ARGUS：MCP 接地的大模型 K8s 事故根因分析助手**（arXiv 2608.23084, 08-24）: 通过标准化 MCP 服务器接入 K8s 状态、Prometheus 指标、Loki 日志、NATS 消息，LLM 在 Slack 事故频道直接输出结构化诊断摘要。10 个 K8s 事故场景故障注入测试全部正确定名根因，MCP 成功率 0.91。**核心发现=诊断/处方不对称**：6 名值班工程师信任诊断输出但持续怀疑修复建议——对自治事故处理系统的信任瓶颈在"下一步做什么"而非"哪里坏了"。https://arxiv.org/abs/2608.23084
- **ROUTELLM：LLM 挖掘运维邮件列表构建 BGP 路由异常检测**（arXiv 2608.22812, 08-24, IEEE ICNP 2026）: 从 NANOG/AusNOG 公开邮件列表用 LLM 提取 232 个已核验路由异常事件，把公开数据集规模从 18 提升 11.89 倍；ROUTELLM 事件级准确率 87.13%、消息级 94.65%，超最强基线 55.30%/68.50%。**启示**：运维工单/邮件列表是 LLM 挖掘训练数据的富矿，可复制到数据中心事故库建设。https://arxiv.org/abs/2608.22812
- **频域证据增强 LLM 零样本时序异常检测**（arXiv 2608.24113, 08-25）: 在保留去季节化时域输入同时，用 FFT 构造全局+局部两级频域证据，显式暴露周期性结构偏移类异常；在 AnomLLM 框架 + InternVL2-LLaMA3-76B/Qwen2.5-VL-72B-Instruct/Gemini-2.5-Flash/GPT-4o 上验证优于纯时域基线。**对监控平台**：把频域特征作为 LLM 可观测性分析的输入证据，是提升零样本异常识别的低成本路径。https://arxiv.org/abs/2608.24113

## 三、趋势小结

- **主线1 · MCP 成为 AIOps agent 数据接入标准**：ARGUS（K8s RCA）与 Radar（语料，见 ai-apps 组）同日出现 MCP 接地，运维平台接入层正从"私有数据接口"走向"标准化 MCP 服务器"，跨组织复用成为可能。
- **主线2 · 诊断-处方不对称是自治运维信任瓶颈**：ARGUS 实验显示 LLM 定位根因可靠（10/10）但修复建议不被信任——自治事故处理的产品设计应把"自动诊断+人工处方"作为当前阶段的合理边界。
- **主线3 · LLM 从运维语料（邮件列表/工单/日志）中挖掘训练数据成为数据稀缺解法**：ROUTELLM 数据集扩 11.89 倍、LLM 零样本 TSAD 频域增强，指向"以数据飞轮补模型能力"的路线。
