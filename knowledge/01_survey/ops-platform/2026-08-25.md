## 一、CNCF Blog 重磅（Atlassian 生产级自动化 RCA 首次公开全文）

- **Atlassian 自动化 RCA: 多信号相关 + 依赖图溯源**（CNCF Blog, 2026-08-24）: Atlassian 规模（数百微服务跨多区域）下生产事故遥测爆炸，oncall 人工 RCA 是"串行认知昂贵流程"（开仪表盘→看日志→查上游）；其方案把**假设生成完全自动化**， responders 直跳验证与处置。架构三要素：①独立信号异常检测（**模块化可插拔**——指标用 MAD/百分位带统计法、trace 查结构异常（意外异常/新错误传播模式/延迟尖峰）、日志用聚类找新/罕见错误簇；统一 schema 归一化 timestamp/service/signal_type/severity_score/details）；②时间相关（滑动窗口 ±5 分钟聚簇，**S_temporal = (1/N(N-1))×Σexp(-|ti-tj|/τ)**，且用序列指纹+重放折叠去重——同一因果链在事故中反复重放，不去重单模式 100 次重放产生 100 个 bundle）；③依赖图溯源（OTel span 父子关系构建生产流量实时服务图，找 sink node 后向上游遍历，**S_path = (1/m)×ΣS_anomaly(Ui)×w_edge×exp(-α×Δt)**，组合置信度 **S_overall = w1×S_temporal + w2×S_path** 排名输出 Top-N 假设）。亮点：**叙述模板（narrative templates）生成人类可读证据**——"15:24-15:28 payment-service /charge 错误率 4x（基线 0.2%→观测 0.8%），先于 checkout-service /complete 延迟尖峰（p99 340ms→2100ms）……"工程师不会仅凭置信度分数行动，需要可读证据链。经验教训：统计方法（MAD）比复杂 ML 先有用；模块化让系统先以 metrics-only 上线再增量加 trace/log；依赖图是最强先验（时间相关 alone 产生过多假设——很多服务异常是被影响而非故障源）；下一步是 **LLM 编排 agent 把 one-shot RCA 变为迭代式**（agent 可请求补充遥测/精化假设）+ 扩展信号类型（基础设施指标/部署事件/feature flag/合成检查）→ 从"哪个服务坏了"走向"什么变更导致的"。来源: https://www.cncf.io/blog/2026/08/24/automating-root-cause-analysis-at-scale-multi-signal-correlation-for-cloud-native-incident-response/

## 二、arXiv 学术前沿（RCA 评估范式升级 + 扩缩容不确定性化）

- **Beyond Fault Localization: LLM Agent 微服务 RCA 的轨迹级研究**（arXiv:2608.21310, 2026-08-21）: 现有 RCA 评估只看"端点正确性"（是否定位到责任服务），不揭示**诊断的证据基础与故障传播路径**——而这两者正是 oncall SRE 判断"是否值得行动"的依据；提出轨迹级框架，以人工 curated 的服务级故障传播路径评估 agent 执行，在公开微服务 RCA benchmark 上分析 **3,500 条轨迹**——**RCA 评估从"结果对不对"升级到"过程证据足不足"**（与 08-24 Agent-Native Telemetry 的"可验证证据"完全同向，评估标准与遥测设计两线并进）。来源: https://arxiv.org/abs/2608.21310
- **LongRCA Bench: 长时程 Agent 失败的职责与根因诊断基准**（arXiv:2608.15242, 2026-08-15）: 长时程 agent 执行失败时，结局级评估看不出"决定性错误在哪一步进入轨迹"；现有失败归因基准多限短轨迹；LongRCA Bench 含 **5 域 1,140 条无注入错误失败轨迹**（中位 145 步），提供独立评分的"负责角色"与"最早决定性根因步骤"双标签——**agent 运维排障的数据集/基准缺口正在被填补**（为运维平台 agent 失败诊断提供标准评估集）。来源: https://arxiv.org/abs/2608.15242
- **SLO-Scaler: 不确定性感知的 SLO 驱动微服务扩缩容**（arXiv:2608.18390, 2026-08-18）: K8s HPA 阈值响应流量尖峰太慢；预测式方法产出点预测、**忽略预测不确定性**导致过度供给或振荡扩缩；SLO-Scaler 用贝叶斯方法预测短时请求率、尾延迟与 **SLO 违反概率**——容量决策从"点预测"走向"不确定性量化"（与 08-24 FleetSieve 决策关键 profiling、08-17 Safety-Gated 泄漏门控同属"资源决策智能化"主线，不确定性显式建模成为共性）。来源: https://arxiv.org/abs/2608.18390
- **Making Deployments Safe at Meta: 部署健康检查基础设施**（arXiv:2608.20513, 2026-08-20）: Meta 首次公开 Service Health Checker——跨数千异构服务的**基于预防的分布式部署健康检查系统**：check 作者用模板化指标查询+阈值+工作流谓词组合，与**分层分批 rollout 集成、回归自动触发回滚**——部署安全从"发布后监控"前移到"变更闸门"，是云巨头 CI/CD 可靠性工程的系统性公开（运维平台变更管理模块的直接参照）。来源: https://arxiv.org/abs/2608.20513
- **Too Sure to Be Safe: 日志异常检测的模型校准**（arXiv:2608.17965, 2026-08-18）: LLM 日志异常检测器存在**过度自信**问题（校准缺失导致误报/漏报边界不可信）；提出校准方法提升可靠性——与 08-23 HDFS LLM-BiLSTM 日志管线衔接，日志 LLM 化进入"可靠性工程"阶段（精度之外补校准维度）。来源: https://arxiv.org/abs/2608.17965
- **From LLM Inference to Agentic Workloads: Serving 系统特征化**（arXiv:2608.15127, 2026-08-15）: Agentic 应用把 AI serving 从孤立模型推理转为**长时程工作负载**（LLM 协调工具/环境/持久状态）——serving 系统的负载模型/容量规划范式需要重构，为 LLM 运维平台给出工作负载特征化基线。来源: https://arxiv.org/abs/2608.15127

## 小结（洞察）

1. **RCA 进入"证据链工程化"阶段** —— 学术侧评估范式升级（Beyond Fault Localization 轨迹级 3,500 条、LongRCA Bench 1,140 条长轨迹）与产业侧生产级实现公开（Atlassian 全文）同日共振：**"定位对服务"不再是终点，"可验证的证据链+故障传播路径"成为 RCA 的核心交付物**。运维平台 RCA 模块的验收标准应随之升级（输出假设必须携带可审计证据，而非仅置信度分数）。
2. **生产级 RCA 落地范式已成型（可直接对标）** —— Atlassian 给出完整技术栈：统计检测器（MAD/百分位带）+ 统一 schema 归一化 + 时间滑动窗聚簇 + 依赖图溯源 + **叙述模板生成人类可读证据**；四条经验（统计优先于复杂 ML、模块化增量上线、去重必需、依赖图最强先验）与 eIRWR（08-23 学术）互证——**模块化+图先验+叙述化输出是 RCA 落地三要素**。
3. **扩缩容/容量决策不确定性化成为主线** —— SLO-Scaler（贝叶斯 SLO 违反概率）接续 FleetSieve（08-24）/Safety-Gated（08-17）：点预测→不确定性量化的迁移在 K8s/LLM 舰队/微服务三场景同步发生，运维容量模块应把"不确定性量化"作为显式设计维度。
4. **云巨头部署安全工程首次系统性公开** —— Meta Service Health Checker（分层 rollout+自动回滚）补齐"变更管理"环节实证；结合 Azure Brain（08-24）与 Atlassian，云巨头的 AIOps 实证已覆盖**判定→诊断→变更→部署**全链路。
