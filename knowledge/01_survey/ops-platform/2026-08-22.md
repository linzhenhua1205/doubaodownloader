## 一、arXiv 学术前沿（RCA 向底层系统扩散）

- **KernelDiag: Agent 内核崩溃根因诊断框架**（2026-07-20）: 现有 LLM-RCA（微服务/分布式系统有效）不适用于内核调试——底层 artifact 稀疏、诊断证据异构（syscalls/logs/crash reports）、非线性故障传播需方法级细粒度推理；KernelDiag 以 log-to-code 映射对齐异构证据 + artifact 专用 Agent 迭代推理 + Evidence Graphs 结构化因果组织，KGYM 真实基准上 **无显式提示的困难场景 Top@k 提升最高 4x/2x**（文件级与方法级均超 SOTA）——**RCA 从应用层向 OS 内核层专用化，对服务器 OS 运维平台是直接信号**。来源: https://arxiv.org/abs/2607.17722
- **FailureAtlas: 多提供商 LLM 网关故障模式分类学**（2026-07-20）: LLM 网关（跨 foundation-model API 路由/负载均衡/限流的反向代理）故障两轴分类——**origin layer**（Network/Transport、Streaming/Protocol、State/Session、Model Behavior、Governance/Cost）× **detectability**（Loud vs Silent），5 条已核实条目附机理 RCA + 3 条可复现脚本；**核心发现：最具运营破坏性的故障是"静默失败"——返回 HTTP 200、通过全部标准健康检查、却破坏应用状态，必须语义级可观测性才能检测**（实测发现并发竞态致历史丢失、流式索引冲突污染 tool-call payload）——LLM 网关运维分层与可观测性建设的重要参考。来源: https://arxiv.org/abs/2607.17525
- **Microflow: 微架构因果可观测性框架**（2026-07-14）: 将 causality 提升为一等分析对象，MFIR 中间表示统一软件语义/指令/微架构事件/硬件资源依赖，支持 stall→根因直接遍历 + 反事实关键路径分解；SPEC CPU 2017 上揭示聚合指标不可见的瓶颈（leela 隐藏分支误预测成本、mcf 跨循环迭代争用）——**硬件性能 RCA 方法论向可查询化演进**。来源: https://arxiv.org/abs/2607.13184

## 小结（洞察）

1. **RCA 方法论向底层系统扩散** —— KernelDiag（内核崩溃）、Microflow（微架构）表明 RCA 已从微服务/LLM 推理层下沉到 OS 与硬件层，服务器运维平台"跨层 RCA"（应用→OS→硬件）能力需求明确，与超节点/服务器智能运维规划直接相关。
2. **LLM 网关"静默失败"是新盲区** —— 返回 200 但破坏状态的故障要求语义级可观测性；网关层（路由/限流/流式协议）需独立于通用监控的检测手段，是可观测性平台的下一个增量市场。
3. **国内路线分化固化** —— 一体化运维 PaaS（嘉为蓝鲸/锐捷乐享）vs 纯 AIOps（Davis AI）vs 云原生可观测（Datadog/Splunk）三线并进；"AI 自治运维"与"Agentic Ops"成为 2026 选型话语体系。
4. **受监管行业 AIOps 落地路径成型** —— 金融四阶段模型 + 等保合规约束，说明国内 AIOps 采购将"合规 + 自主闭环"并重，平台需内置审计与权限控制能力。
