- **One-command OpenTelemetry setup on Linux hosts**（2026-07-23）: 推出 Linux 裸机主机一键部署方案，将 OTel 作为系统依赖安装（此前 K8s 有 Operator、Lambda 有扩展，裸机一直是空白）——补齐服务器/物理机带内遥测的部署路径。https://opentelemetry.io/blog/2026/one-command-otel-setup-linux/

- **OpenTelemetry Go Compile-Time Instrumentation v1**（2026-07-16）: Go 编译时插桩正式 v1，补齐"无代理语言"最后缺口——Java/Python/Node/.NET 早有启动期 attach agent，Go 程序静态编译导致长期缺席，现可在编译期注入遥测且零运行时开销。https://opentelemetry.io/blog/2026/go-compile-time-instrumentation-v1/

- **OpenTelemetry 达成 CNCF 毕业**（2026-07-15）: 与 Kubernetes、Prometheus 同级毕业；官方回顾发展历程并给出"毕业后下一步"（稳定化、生态扩展、教育）——可观测性标准事实地位进一步巩固。https://opentelemetry.io/blog/2026/otel-graduated-now-what/

- **Lambda 函数落地 OTTL**（2026-07-22）: OTTL（Collector 转换语言）支持 Lambda 函数，用于敏感数据脱敏、schema 归一化、属性契约强制——遥测管道内复杂转换不再受限于内置函数集。https://opentelemetry.io/blog/2026/lambda-powered-functions-ottl/

- **OTel @ KubeCon Japan 2026**（2026-07-23）: 横滨 7/28-30 的 KubeCon 官方列出全部 OTel 相关 session（Collector 演进、OTTL、云原生可观测性实践等）——国内可关注会后纪要。https://opentelemetry.io/blog/2026/kubecon-japan-2026/

- **Spring Boot declarative config 支持**（2026-07-14）: Spring Boot starter 2.26.0 起支持声明式配置（与 Java agent 同 YAML schema，内嵌 application.yaml）——配置形态统一化趋势延伸到主流框架。https://opentelemetry.io/blog/2026/voyage-of-small-environment-variable/

## 趋势研判

- **带内遥测部署壁垒瓦解**: OTel Linux 一键部署（裸机）+ Go 编译时插桩 v1（静态编译语言）连续落地，带内遥测在服务器物理机场景的部署成本大幅下降——与 BMC 带外监控形成"双轨遥测"互补格局，与 08-07 日报判断一致。
- **AIOps 向"执行"演进**: 华为/IBM/腾讯云同期发声均指向"自动化+智能化闭环"，AIOps 从分析（哪里着火）走向执行（自动处置），国内社区共识为"云原生+行业化+自治化"三方向。
- **eBPF 成运维技术底座**: 本周 arXiv 连出 eBPF 依赖发现 + eBPF 访问控制两篇，eBPF 在可观测性之外向安全/迁移领域扩展，成为内核级运维的统一机制。
- **绿色调度进入可部署阶段**: LLM 推理按电网碳排放实时路由（2608.06188）给出多区域验证与一年回放，carbon-aware 运维从理念走向生产可行性。
