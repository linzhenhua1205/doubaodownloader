## 核心发现

### arXiv 学术动态（cs.DC 08-13 提交批次 13 条全量扫描，7 条运维相关，编号 12633-13499 全部 > 昨日最大 12146，URL 已逐条 curl 验证 200）

- **OpScale: LLM Serving 的 Operator 级供给与自动扩缩容**（arXiv:2608.13499, 08-13）: 云 GPU 集群 LLM serving 的核心未决问题——"扩缩容单元应该是什么"？现有方案把整个模型当作单一缩放单元（monolithic），无法捕捉推理负载的细粒度动态，突发流量下要么 SLO 违例（TTFT）要么资源浪费；OpScale 把缩放单元下沉到 operator 级（模型内部算子粒度），在严格用户 SLO（首 token 时延）约束下做供给与扩缩容。扩缩容粒度从"模型级"下沉到"算子级"——调度主线的又一维度（承接 08-13 RoutePack 训练内部、08-14 Ready Cohorts 控制面的下沉趋势）。https://arxiv.org/abs/2608.13499

- **Contract-Grade Verifier: LLM 生成 GPU kernel 的对抗级正确性验证器**（arXiv:2608.12700, 08-13）: LLM 生成 kernel 的"高正确率"来自单一宽松测试（固定 shape 随机输入跑一次、输出接近参考即通过），该测试无法发现静默错误——正常数值掩盖 NaN/Inf、运行间结果不一致、shape 变化即失效、fp16 累积 vs fp32 参考差异；论文构建 12 个对抗性验证维度的 contract-grade verifier，并配套原生 Blackwell 反向实现（Gated-Linear-Recurrence 家族）。"AI 参与生产链路正确性验收"主升浪的核心实证件——LLM 代码生成的验收从"宽松冒烟测试"走向"合约级对抗验证"。https://arxiv.org/abs/2608.12700

- **InFactPlanner: 可持续地理分布式 LLM 数据中心规划**（arXiv:2608.12915, 08-13）: LLM 推理爆发使可持续性关注从一次性训练转向持续服务，基础设施决策直接塑造能源/碳排放/水耗/服务质量；但运营商常需在大型基础设施建成前比较部署方案，直接测量昂贵且不可行；InFactPlanner 是 trace-driven what-if 决策支持框架，支持单站点与地理分布式 AI 数据中心部署方案对比。数据中心规划进入"可持续 what-if"维度——容量规划的长期视角从性能/成本扩展到碳与水。https://arxiv.org/abs/2608.12915

- **TEMPO: 内存受限与计算受限两 regime 下的 Expert-Parallel 负载均衡**（arXiv:2608.13057, 08-13）: EP MoE serving 每层同步于最慢 GPU；现有调度器（EPLB/LPLB/UltraEP 按 token 数、METRO 按激活专家数）假设专家耗时与单一维度线性相关，实测两代数据中心 GPU 上均不成立——token 数低于阈值（~156-168）时 HBM 权重流主导，成本挂在激活副本而非 token；高于阈值时分组 GEMM 将 token 四舍五入为 128-tile M-tile，拆分专家反而引入填充计算；max-affine 耗时模型 t=max(a+bG, c+βN) 统一两 regime。MoE 负载均衡从"启发式单维度"走向"两 regime 显式建模"（承接 08-13 RoutePack 的 MoE 主线）。https://arxiv.org/abs/2608.13057

- **vToken: KV Cache 的 Token 级虚拟化与可回收性**（arXiv:2608.13263, 08-13）: LLM serving 的内存瓶颈核心：KV cache 随序列长度与 batch 增长；PagedAttention 用固定大小内存块降低分配器级碎片，但近年 KV eviction 算法在比块管理更细的 token 粒度上操作——错配导致块内碎片，大量已分配 KV 内存不可回收；vToken 提供轻量 token 级虚拟化层，解耦逻辑 token 活性与物理块放置，维护稳定逻辑 token 视图。推理内存管理从"块级"下沉到"token 级"——细粒度资源回收新机制。https://arxiv.org/abs/2608.13263

- **Meshlib: Sidecar-less 服务网格的应用内进程策略执行**（arXiv:2608.13107, 08-13）: 服务网格依赖每 pod sidecar 代理，每次请求冗余应用层解析带来显著时延与资源开销；去 sidecar 而不损失安全保证是核心挑战；Meshlib 基于 Cilium 控制面扩展构建 sidecar-less mesh，以非侵入式应用绑定库执行 L7 策略。平台基础设施演进——服务网格从"sidecar 代理"走向"进程内策略执行"（与 eBPF 数据面、Cilium 生态同向）。https://arxiv.org/abs/2608.13107

- **Validation-Centric AI-Assisted GPU 移植: 25 万行遗留气象模拟代码**（arXiv:2608.13122, 08-13）: CLI 型 AI agent 加速大型遗留科学应用 GPU 移植，但此类应用是长期积累的科学资产（与观测对比、领域研究验证的信用沉淀），移植必须保持科学有效性；论文以 CReSS（25 万+ 行遗留气象模拟）为案例提出验证中心的 AI 辅助移植工作流。"验证优先"原则从 LLM kernel 生成（Contract-Grade Verifier）扩展到遗留科学代码移植——AI 参与生产链路的正确性验收成为通用约束。https://arxiv.org/abs/2608.13122

## 趋势研判

- **调度/弹性主线再添两维**: 本轮 OpScale（扩缩容单元从模型级下沉到算子级）+ TEMPO（EP 负载均衡从单维度启发式走向两 regime 显式建模）——调度优化对象已覆盖任务级→训练内部（RoutePack）→serving 扩缩容单元→内存/计算受限 regime 建模，粒度不断细分且互相独立成线。
- **"AI 生产链路正确性验收"主升浪双实证**: Contract-Grade Verifier（12 维对抗验证，LLM kernel）+ Validation-Centric Porting（科学有效性，遗留代码）同日出现——AI 产出物进入生产链路的验收标准从"宽松冒烟测试"升级为"对抗级/验证中心"方法论，与 08-13 Workflow Cards、08-14 Dispatch 可靠性实证构成完整谱系。
- **推理内存管理下沉到 token 级**: vToken 把 KV cache 回收粒度从块级（PagedAttention）推进到 token 级，直接回应 eviction 算法与块管理错配的碎片问题——推理成本优化进入细粒度资源回收阶段。
