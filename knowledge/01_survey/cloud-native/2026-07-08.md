## 1️⃣ 🔴 Agent-substrate：Agent 沙箱不够，还需高效运行时调度

**来源**: CNCF Blog (2026-07-07)
**链接**: https://www.cncf.io/blog/2026/07/07/why-sandboxing-your-agent-is-not-enough/
**作者**: Lin Sun (Solo.io), CNCF Ambassador

**关键信息**:

- 两个独立但互补的 Agent 运行时项目正在形成：

| 维度 | agent-sandbox | agent-substrate |
|:----|:-------------|:---------------|
| **隶属** | K8s SIG Apps (Sandbox CRD + Controller) | 独立项目（可能后续加入基金会） |
| **核心关注** | **安全性**: 身份/持久存储/生命周期/隔离 | **效率**: 大规模/资源密度/低延迟/动态生命周期 |
| **运行时模型** | 每个 agent 一个 pod | 按需唤醒，worker pod 与 agent actor 解耦 |
| **资源消耗** | 持续运行，闲置浪费 | suspend/resume，on-demand serverless 模式 |
| **隔离技术** | gVisor / Kata Containers | gVisor / Kata + 共享 worker 池 |

- **agent-substrate 核心创新**:
  - Agent 不持续运行 pod，而是在安全 worker pod 中短时爆发执行
  - 闲置时 suspend，被调用时在任何可用 worker 上 resume
  - Worker pod 生命周期与 agent "actor" 完全解耦
  - 类比：**Agent 从"Deployment 模式"转向"Serverless Function 模式"**

- **与 kagent 集成验证**: 6 个 AIRE agent 只需 1 个 worker pod
  - 6 个 agent 映射为 6 个 actor templates
  - 共享一个 worker pod（kagent-default）
  - 并发增加时水平扩展 worker pool 即可

**影响判断**: 这是 AI Agent 基础设施从"安全第一"进化到"安全+效率"的关键一步。对于数据中心运维来说，agent-substrate 的模型意味着 **AI Agent 的编排正在从"每个 Agent 一个 Pod"的粗粒度模式，走向"共享 Worker 池 + 按需唤醒"的 Serverless 化模式**，这与 K8s Serverless (Knative) 的演进路径一致。KubeCon Japan 2026 (7/28-30) 上预计会有更多演示。

## 3️⃣ 🟡 etcd 3.7.0-beta.0 发布：RangeStream + 重构清理

**来源**: Kubernetes Blog (2026-05-20)
**链接**: https://kubernetes.io/blog/

**关键信息**:

- **RangeStream 特性**: 这是 etcd 社区长期请求的功能，显著改善 Watch 大规模集群时的流式传输效率
- 重构和清理：SIG-Etcd 对本版本进行了内部架构重新梳理
- 这是 etcd v3.7 系列的第一个 beta 版本，正式版预计年底前

**影响判断**: RangeStream 对大规模 K8s 集群（万节点级）的 API Server Watch 性能有直接改善。之前 Server-Side Sharded List/Watch (v1.36) 优化了 API Server 端，etcd RangeStream 则进一步优化了存储层。

## 4️⃣ 🟡 Headlamp 生态扩展：CAPI / Volcano / Knative 三插件齐发

**来源**: Kubernetes Blog (2026-06-25)
**链接**: https://kubernetes.io/blog/

**关键信息**:

- **Cluster API plugin**: 支持通过 Headlamp UI 管理 CAPI 集群生命周期
- **Volcano plugin**: 可视化 Volcano 批量调度作业（AI/ML/HPC 工作负载）
- **Knative plugin**: Serverless 工作负载可视化管理
- 同时 K8s 博客发布了 K8s Dashboard → Headlamp 迁移指南

**影响判断**: Headlamp 正在成为 K8s 生态的统一可扩展 UI 层，三插件分别对应集群管理 (CAPI)、AI/批处理调度 (Volcano)、Serverless (Knative)——覆盖了当前 K8s 最重要的三个扩展场景。
