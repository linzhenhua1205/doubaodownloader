## 1️⃣ 🔴 DRA GA + NVIDIA GPU Driver 进 K8s SIGs：GPU 调度进入新时代

**来源**: CNCF Blog (2026-07-01)
**链接**: https://www.cncf.io/blog/2026/07/01/understanding-dynamic-resource-allocation-in-kubernetes/
**作者**: ChengHao Yang, CNCF Ambassador

**关键信息**:

**DRA 时间线**:
| 事件 | 版本/日期 | 意义 |
|:----|:---------|:-----|
| DRA **Alpha** | K8s v1.26 (2022) | 首次引入 DRA API |
| DRA **GA** | **K8s v1.35** (2026 Q2) | 生产就绪 |
| NVIDIA DRA Driver 进 K8s SIGs | **2026 Q2** | 官方标准化的关键一步 |
| 设备健康上报 | K8s **v1.36** (2026 Q3) | Pod 能区分设备故障 vs 应用错误 |
| 文档 Beta 标签移除 | 2026-06 | 稳定性验证完成 |

**DRA 相比传统 Device Plugin 的核心优势**:

| 维度 | Device Plugin (旧) | DRA (新) |
|:----|:------------------|:---------|
| **调度触发时机** | Pod 调度到节点后分配 | **调度时感知设备约束，与调度一体化** |
| **设备选择粒度** | 只能按类型/数量 | **CEL 表达式精确选择**（型号/显存/架构/驱动版本） |
| **多容器共享** | 不支持同一 Pod 内多容器共享 GPU | ✅ 原生支持 |
| **时间片共享** | 需额外配置 | **DRA TimeSlicing Config** 内建 |
| **首选/回退** | nodeSelector/Affinity 复杂组合 | **firstAvailable** 语义：首选A5000→回退T10 |
| **设备健康** | 失败时只有 Error | **设备级健康上报**，区分设备/应用故障 |
| **组合能力** | 无 | **DRA + Cluster Autoscaler** 未来可按 GPU 需求扩容节点 |

**DRA 四种实战场景** (来自 CNTUG Infra Labs 验证):

1. **一个 GPU 给两个容器共享** — ResourceClaim 声明 1 GPU，Pod 两个容器同时引用
2. **GPU 型号首选+回退** — ResourceClaimTemplate 用 firstAvailable + CEL 表达式，优先选 A5000，不够时回退 T10
3. **按显存容量选择** — CEL `device.capacity["gpu.nvidia.com"].memory.isGreaterThan(quantity("20Gi"))`
4. **GPU Time Slicing 模式** — DRA 原生支持 TimeSlicing Config，4 Pod 共享 1 GPU

**影响判断**: ⭐ **2026 年云原生基础设施最重要的架构演进之一**。DRA 从根本上解决了 K8s 调度 GPU 时的\"先调度后分配\"问题，使调度器能感知设备拓扑、容量、型号、健康状态后一体决策。对 AI 训练/推理集群的**GPU 利用率提升、多租户隔离、异构 GPU 混部**有直接影响。

## 2️⃣ 🔴 etcd v3.7.0 GA 发布：RangeStream 里程碑

**来源**: Kubernetes Blog (2026-07-08)
**链接**: https://kubernetes.io/blog/

**关键信息**:

- **RangeStream 特性正式 GA**: etcd 社区长期请求的核心功能，显著优化大规模集群的 Watch 流式传输效率
- **内部重构**: 对旧代码做清理和模块化，降低后续维护成本
- 这是 etcd v3.6 之后的首个 minor 版本

**影响判断**: RangeStream + K8s v1.36 Server-Side Sharded List/Watch 构成**端到端 Watch 扩展性改进**。对于万节点级集群意味着 API Server Watch 压力减轻、etcd 存储层流式传输效率提升。建议近期内升级 etcd 到 3.7.0。

## 4️⃣ 🟡 K8s v1.36 "Haru" 关键特性全景

**来源**: K8s Blog (2026-06)
**链接**: https://kubernetes.io/blog/

**K8s v1.35 → v1.36 关键特性演进**:

| 特性 | v1.35 (GA) | v1.36 新增 | 对运维影响 |
|:----|:----------|:-----------|:----------|
| **DRA** | ✅ GA | **设备健康上报** + 更多驱动 | GPU 故障隔离 |
| **PSI 压力指标** | Beta | ✅ **GA** | 资源压力预警标准化 |
| **Pod 垂直扩缩容** | Beta (Pod 级) | ✅ **Beta**（Pod 级资源，原 Container 级 GA） | 更细粒度的资源调整 |
| **用户命名空间** | 默认启用 | ✅ **GA** | 容器安全隔离增强 |
| **Pod 级资源管理** | — | **Alpha** | 精细化 QoS |
| **Workload-Aware 调度** | Alpha | ✅ 演进 | 负载感知调度 |
| **混合版本代理** | — | **Beta** | 升级期间 API 兼容性 |
| **内存 QoS** | — | **Tiered Memory Protection** | 分层内存保护 |

**影响判断**: v1.36 的 PSI GA + Pod 级资源管理 Alpha + 内存 QoS 构成了**节点资源管理能力的显著增强**，对运维团队构建资源压力预警、精细化 QoS 策略有直接帮助。

## 5️⃣ 🟡 ingress-NGINX 退役导航 & Gateway API v1.5

**来源**: CNCF Blog (2026-07-09) · K8s Blog (2026)
**链接**: https://www.cncf.io/blog/2026/07/09/navigating-the-ingress-nginx-retirement/

**关键信息**:

- **SIG Network 于 2026年3月正式退役 ingress-nginx 控制器**
- 仍使用旧版 ingress-nginx 面临的风险：
  - ⚠️ 未修补的 CVE
  - ⚠️ 特性开发完全停止
  - ⚠️ 不再有安全补丁
- **推荐迁移路径**：Gateway API（v1.5 已发布，多项特性进 Stable）
- **迁移工具**: ingress2gateway 1.0 已发布

**影响判断**: ingress-nginx 是过去 8 年 K8s 最广泛使用的入口控制器之一。**建议运维团队尽快规划迁移**到 Gateway API。Gateway API v1.5 已将多项特性稳定化，迁移窗口有限。
