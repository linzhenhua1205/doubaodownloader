## 一、🔴 K8s GPU 调度 & 动态资源分配

### 1.1 DRA 实战指南 — CEL 选择器 + TimeSlicing + Device Health

CNCF Blog, Jul 1, 2026 | ChengHao Yang (CNCF Ambassador)

> 全文实战教程：从零搭建 DRA 环境，覆盖 4 个场景

**关键信息**:

- **NVIDIA dra-driver-gpu 已正式进入 K8s SIGs**，文档去除了 Beta 标签
- 环境: K8s v1.35.3 + Containerd 2.2.2 + GPU Operator v26.3.1 + DRA Driver v25.12.0
- Cluster API + OpenStack 构建集群

**4 个实战场景**:

| 场景 | 核心机制 | 关键价值 |
|:----|:---------|:---------|
| **I. 两个容器共享一块 GPU** | `ResourceClaim` 声明一个 GPU，Pod 两个容器共同引用 | 多容器共享设备不再依赖 Device Plugin |
| **II. CEL 选择器 + firstAvailable** | `firstAvailable` 多级偏好，CEL 用 `device.attributes["gpu.nvidia.com"].productName` 选型号 | 按 GPU 型号优先级调度，A5000 不够时回到 T10 |
| **III. 内存约束 CEL 匹配** | `device.capacity["gpu.nvidia.com"].memory.isGreaterThan(quantity("20Gi"))` | 按显存硬约束选 GPU，不满足则 Pending 不降级 |
| **IV. DRA 下 GPU TimeSlicing** | `sharing.strategy: TimeSlicing` + `timeSlicingConfig.interval: Long` | 4 个 Pod 共享同一 GPU，无需声明切片数 |

**核心差异 vs Device Plugin**:
- ✅ 不再需要 nodeSelector/Affinity 约束同类型设备
- ✅ 不再需要手动管理设备数量
- ✅ 从 K8s v1.36 开始支持 Device Health Reporting（区分设备故障 vs 应用故障）
- ✅ 将来 Cluster Autoscaler 可感知 GPU 稀缺并自动扩缩节点

**来源**: https://www.cncf.io/blog/2026/07/01/understanding-dynamic-resource-allocation-in-kubernetes/

## 二、🔴 CNCF 云原生 AI 基础设施

### 2.1 Data Storage in Cloud Native AI 白皮书

CNCF TAG Infrastructure, Jul 8, 2026

> 核心观点: 传统存储架构在 AI 场景下存在三大瓶颈 (小文件陷阱/解耦瓶颈/负载特征变化)

**三阶段存储模型**:

| 阶段 | 存储特征 | 关键技术 |
|:----|:---------|:---------|
| **Model Training** | 长时吞吐型，随机数据混洗+同步写突发（checkpointing） | CSI/COSI, 分布式缓存, Fluid |
| **Model Inference** | 延迟敏感型，尖峰流量+快速加载 | KV Cache, Prefix Cache, 内存架构 |
| **Agentic AI** | 闭环推演架构，短/中/长三级记忆 | 可变状态跟踪、事件持久化、会话档案 |

**架构层级**:
- Data Lake House + Vector DB (Milvus/Parquet/Iceberg)
- Caching & Data Locality (Fluid)
- 标准化接口 (CSI + COSI + FUSE CSI)
- 实时数据管道 (CDC + Kafka)

**来源**: https://www.cncf.io/blog/2026/07/08/the-cncf-data-storage-in-cloud-native-ai-white-paper/

## 三、🟡 CNCF 项目动态

### 3.1 Security Profiles Operator v1.0.0 GA

CNCF Blog, Jun 26, 2026 | Sascha Grunert (Red Hat)

- **8 个 CRD 全部升级到 v1 稳定版**：SeccompProfile/SelinuxProfile/AppArmorProfile/ProfileRecording/ProfileBinding 等
- 通过第三方安全审计: 0 critical vulns
- CRD 清理: 共用基于 K8s conditions 的状态类型，枚举值 PascalCase 统一，全字段 +optional/+required 标记
- 安全加固:
  - RawSelinuxProfile: 新增 `enableRawSelinuxProfiles` 关闭开关 + 校验准入 webhook
  - SelinuxProfile: Permissive boolean → mode enum (Enforcing/Permissive)
  - AppArmor: 严格 regex 校验 + 禁止覆写已加载 profile
  - 正则回溯攻击防护: 贪婪量词替换为有界模式
  - 零宕机迁移: 转换 webhook 透明处理 v1alpha1/v1alpha2/v1beta1 → v1
- **KEP 6061 联动**: OCI Artifact-Based Security Profile Distribution 即将进入 kubelet 原生支持
- **来源**: https://www.cncf.io/blog/2026/06/26/security-profiles-operator-v1-stable-apis-security-hardened-and-shaping-upstream-kubernetes/
