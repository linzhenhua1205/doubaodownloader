## 二、Kubernetes 官方动态（K8s Blog 2026 增量补录）

- **Kubernetes Dashboard → Headlamp 迁移 Step-by-Step 指南**（2026-07-13，K8s Blog/Microsoft）: 官方给出从 Dashboard 迁移到 Headlamp 的完整步骤——两者展示集群资源方式不同：Headlamp 桌面版复用 kubeconfig 直连多集群，Web 版支持浏览器管理；配合 08-24 已收录的 Headlamp 插件三连发（Cluster API/Knative/Volcano），**K8s UI 生态正从 Dashboard（只读浏览）走向 Headlamp（可扩展运维前端）**，迁移指南落地意味着官方默认 UI 交接窗口打开。来源: https://kubernetes.io/blog/2026/07/13/kubernetes-dashboard-to-headlamp/
- **Operating AI/ML Workloads on Kubernetes: Headlamp 的 Kubeflow 插件**（2026-07-13，K8s Blog）: 数据科学 notebook/分布式训练/超参调优/多步 ML 流水线在 K8s 上运行时，Headlamp 插件提供 Kubeflow 工作负载可视化——K8s 已"quietly 成为 AI/ML 默认平台"（原文），UI 层开始补齐 AI 负载的运维可观测。来源: https://kubernetes.io/blog/2026/07/13/introducing-headlamp-plugin-for-kubeflow/
- **Building a Custom Metrics Exporter for Kubernetes**（2026-07-14，K8s Blog）: 内置 CPU/内存指标之外的扩展——队列消息数、批处理耗时等业务信号通过自定义 metrics exporter 接入 HPA（水平自动扩缩容）；**扩缩容决策从"节点资源"走向"业务信号"**，是 AI 推理类负载按请求/队列深度弹性的前置能力。来源: https://kubernetes.io/blog/2026/07/14/custom-metrics-exporter-kubernetes/
- **Spotlight on WG Device Management**（2026-06-24，K8s Blog）: 设备管理工作组全景——DRA（Dynamic Resource Allocation）GA 后设备接入的标准化路径（GPU/NPU/加速卡统一声明与分配），与 v1.34 的 Pods Report DRA Resource Health（设备健康上报进调度闭环）衔接；对服务器厂商含义：**设备健康/故障信号经 DRA 进入 K8s 调度决策是设备侧与编排侧的标准接口**。来源: https://kubernetes.io/blog/2026/06/24/wg-device-management-spotlight-2026/
- **Spotlight on SIG Storage**（2026-06-15，K8s Blog）: 存储 SIG 现状与方向——卷组快照（Volume Group Snapshots）GA、DRA 存储类资源、CSI 驱动演进；K8s 存储层继续围绕"有状态 + AI 负载"补能力（快照/克隆/恢复语义）。来源: https://kubernetes.io/blog/2026/06/15/sig-storage-spotlight-2026/

## 三、运维运营与平台工程（The New Stack 增量）

- **Amazon EKS 多 GB 容器镜像秒级拉取**（2026-08-10，TNS）: EKS 侧优化镜像分发——多 GB 级 AI/ML 镜像（含模型权重层）拉取从分钟级降至秒级，核心在分层/懒加载/P2P 分发组合；**镜像分发速度成为 AI 弹性伸缩（秒级拉起新副本）的隐形瓶颈**，与 08-19 已收录的 Subaru 镜像拉取 60x 案例（CNCF）构成"镜像分发提速"双证据。来源: https://thenewstack.io/accelerating-eks-image-pulls/
- **AI SRE：为什么公司应该（尝试）自建**（2026-07-30，TNS）: 观点文——AI SRE 不能只买现成 AIOps 产品：自建能沉淀"自家系统的根因知识"，采购工具只能给通用告警；作者主张以 LLM 辅助 RCA（根因分析）而非替代人，与 08-21 已收录的 Atlassian 多信号关联 RCA（CNCF）同属"AI 进运维"主线——**AI SRE 的价值在垂直领域知识而非通用推理**。来源: https://thenewstack.io/ai-sre-root-cause-analysis/
- **操作 Kubernetes controllers 规模化经验：从意图到执行**（2026-07-17，TNS）: 大规模运营 K8s controllers 的工程实践——声明式意图与最终执行之间的差距（reconcile 失败、重试风暴、多 controller 竞态）如何治理；对平台团队：**controller 的幂等与背压设计决定控制面稳定性**，万卡集群控制面扩展必须先解决 controller 层。来源: https://thenewstack.io/kubernetes-controllers-at-scale/
- **5 步构建服务架构与运营韧性**（2026-07-25，TNS）: 可操作框架——服务拓扑梳理/故障域隔离/依赖限流/演练常态化/复盘闭环五步，把"韧性"从口号变成流程；与 08-24 已收录的 EKS auth 81% 迁移鸿沟同属"存量运维债务治理"主题（无量化，方法论条目）。来源: https://thenewstack.io/build-resilient-service-architecture/
- **DNS 是基础设施：该按基础设施来管**（2026-07-30，TNS）: DNS 在云原生架构中的关键路径地位——内部服务发现（CoreDNS/NodeLocal DNS）与外部 DNS 策略的统一治理；观点：DNS 故障是"低概率高杀伤"事故源，运维欠账最多。来源: https://thenewstack.io/dns-is-infrastructure/
