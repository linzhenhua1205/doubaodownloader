## 三、运维自动化 / AIOps

- **KubeElasti ProbeResponse：健康检查不再唤醒服务**（07-29, KubeElasti Maintainers）: Scale-to-zero 的隐藏杀手——**健康检查把已缩容服务重新拉起**。方案：在 Resolver 层直接回复健康检查 200 OK，不触发扩容，服务保持真正 idle，同时 LB/uptime 监控不受影响。GPU 负载/授权软件的 idle 时间从不可能变为可行。
  https://www.cncf.io/blog/2026/07/29/your-kubernetes-health-checks-are-accidentally-waking-your-services-heres-the-fix/

- **KEDA × Amazon SQS 事件驱动扩缩容**（07-31, Itgix）: CPU/内存利用率无法反映真实压力——worker pod 空闲但 SQS 队列堆积数千消息。以 SQS queue depth 为指标驱动 KEDA 扩缩容。
  https://www.cncf.io/blog/2026/07/31/scaling-kubernetes-pods-with-keda-based-on-amazon-sqs-queue-depth/

- **NRI 运行时供应链验证**（07-30, Sascha Grunert, containerd）: 现有供应链验证工具（Kyverno/OPA Gatekeeper/Sigstore Policy Controller）都在 **K8s API 层（admission webhooks）** 拦截 pod 创建、检查签名与证明；文章探讨通过 **Node Resource Interface (NRI)** 在运行时层补充验证能力，覆盖 admission 之后的环节。
  https://www.cncf.io/blog/2026/07/30/runtime-supply-chain-verification-using-the-node-resource-interface-nri/

## 📊 本期观察

1. **AI 进入"基建化"深水区**：NVIDIA 公开背书 K8s 为 AI OS（82% 生产采用），CoHDI/Confidential Containers 晋级补齐**硬件解耦**与**机密计算**两块拼图——AI 基础设施正从"能跑"走向"可信+可组合"。
2. **GPU 利用率是运维新战场**：Kubeflow×Cilium 案例证明 60% 空闲常是**配置层静默问题**而非硬件瓶颈，拓扑感知 CNI 与调度器协同将成为标准动作。
3. **Scale-to-zero 终于工程化**：KubeElasti ProbeResponse 解决了健康检查唤醒的经典死结，为 GPU/授权软件 idle 计费场景扫清障碍。
4. **供应链安全下探到运行时**：admission webhook（API 层）→ NRI（运行时层）双层验证成为新方向。
5. **Agent 重塑平台工程**：WSO2/kapa.ai 两条线索一致指向——平台需为 Agent 提供一等公民身份、权限与知识接入。
