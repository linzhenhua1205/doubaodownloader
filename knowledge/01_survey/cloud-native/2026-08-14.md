## 主线：Agent 运行时基础设施——中国实验室的开源竞赛

- **TNS/DeepSeek 开源 DeepSeek Harness：一切皆插件的 agent 运行时**（2026-08-13, Frederic Lardinois）: 周四开源、Node.js 实现、MIT 协议、developer preview，数小时内 GitHub 33,000+ stars。核心主张="everything is a plugin"且字面执行：**模型适配器、工具注册表、会话日志、agent 循环本身都是可替换插件**，文档称"没有需要 patch 的特权核心"，扩展=在旁边挂一个插件。底层架构基于 **Cordis**（"时空可组合性 meta-framework"，北大×DeepSeek 三人论文基础），解决动态组合+组件依赖感知。四预设：**Standard**（完整 coding agent：文件系统/shell/web 搜索/subagents/plan mode）/ **Minimal**（仅 bash + str_replace_editor 两工具）/ **Code**（工具不暴露为 function call，而是生成 TypeScript SDK 让模型写程序对之调用——5 次往返压成 1 次调用）/ **Creator**（自定义预设：继承 Standard+运行时检查+插件实验）。关键设计=**append-only 会话日志**：凡到达模型的输入必须可从日志重建，resume/fork/replay/transcripts/telemetry/web UI 全基于单一事件流——新增模型可见输入=新增 session event。沙箱严格：本地后端用 **Linux Landlock**（DeepSeek 自写 Node addon）/macOS Seatbelt/Windows ACL restricted-token。**不绑定自家模型**：provider 目录含 Anthropic/OpenAI/AWS Bedrock/Azure/Gemini Enterprise Agent Platform；双 subagent provider 可直接委派 Claude Code/Codex（默认关闭，解析宿主 PATH）；含 MCP client + Agent Client Protocol + 读 AGENTS.md/CLAUDE.md。暂不接受外部 PR（引导去 Discussions/写插件），官方宣称"仓库是 idea/官方 showcase/灵感来源，非 mandate"。竞争语境：阿里 Qwen Code、字节 Trae Agent（2025 中）、月之暗面 Kimi CLI（2025-10）、智谱 ZCode（2026-07）。https://thenewstack.io/deepseek-harness-open-source-plugins/

## 主线：平台工程×LLMOps——AI pipeline 的所有权与成本治理

- **CNCF Blog/LLMOps 与平台工程：谁拥有 AI pipeline？**（2026-08-13, Daniel Bryant, Syntasso）: 核心论点=LLMOps 不是 MLOps 换标签（Google Cloud 称其 MLOps 专门子集），差异在**规模与评估**：LLM 微调/服务成本更高，输出要"安全可信"而非单一 accuracy 数字——更难度量。所有权图景三分：DevOps（交付 ticket）/ 平台工程（self-service golden path）/ MLOps（MLflow/Kubeflow/W&B 平行栈），再加 LLMOps 就是第三个平行栈（prompts/vector stores/RAG pipelines），对治理者不可见。**有用的问题不是"谁拥有 pipeline"而是"谁拥有哪一层、是否有人跨层协调"**。引用 CNCF TAG App Delivery Platforms Whitepaper 三层模型：Products（顶）/ Platforms（中，最薄合理集成层）/ Capability Providers（底）——模型微调任务、向量库、prompt 注册表、推理端点"功能上只是另一种平台 capability"。生态工具：Backstage（产品层 golden path）、Crossplane（底层组合）、Kratix/KusionStack/KubeVela（中层编排，让 LLM pipeline 走与其它工作负载相同的 self-service 接口）。**最大运营风险不是幻觉 chatbot 而是 shadow LLMOps**：团队自建 RAG pipeline 对接未审查 vector store——"用 prompts 重演 Jenkinsfile 时代的 shadow-IT"；修复=让平台快速说 yes+内建治理，而非拖慢团队。四条具体治理措施：①governed APIs（微调任务/prompt 部署/推理端点走统一 self-service 接口）②请求时策略执行（成本上限/数据驻留/模型访问控制在 job 启动前检查，而非账单到了才发现）③human approval（触碰 PII 或自主决策的模型变更需审批）④审计轨迹（"什么变了、为什么、谁批准的"——监管与安全团队要答案）。结论：LLM pipeline 只是平台能力的又一消费者，需要与人类开发者/自主 agent 相同的护栏；"LLMOps 不需要自己的王国，它需要一个愿意让它进来的、运营良好的平台"。https://www.cncf.io/blog/2026/08/13/llmops-and-platform-engineering-who-should-own-the-ai-pipeline/

- **TNS/AI pipeline 成本：demo 之后贵 10×，token 优化是架构纪律不是定价练习**（2026-08-13, Hafiz Hassan, Andela 赞助）: 论点="最贵的 bug 不是幻觉，而是用户永远注意不到的数千多余 token"；切换更便宜模型经常不如先问"为什么模型处理这么多 token"。五生产级技术（含量化收益）：①**explicit prompt caching**——静态前缀（system instructions/schema/few-shot）加 cache breakpoint，服务端复用预计算 attention，最高 **-90% 成本**+TTFT 显著降低；②**embedding 语义缓存**——余弦相似度阈值 0.92 拦截近似重复查询，**100% 消除冗余推理 token**；③**滚动对话摘要**——多轮聊天全量重放是 O(N²) token 增长，超 4 turns 用轻量模型压缩为叙事摘要+最近 K turns，输入增长有界；④**结构化工具输出修剪**——agent function calling 时 API 响应 70-90% 是冗余字段，中间层过滤器仅保留 LLM 推理所需 schema 字段（**-70~90% tool token**）；⑤**intent-based 模型路由**——轻量分类器把简单请求派给 budget-tier、复杂推理派给 frontier（**-50~80% 成本**不降质）。进阶：上下文压缩（LLMLingua 类，RAG prompt **-30~60%**）、微调替代零样本长 prompt（1000 tokens 规则 → 20 tokens 内化进权重）。KPI 三件套：cache hit ratio（重复任务 >60%）、token-to-value ratio（输出/输入）、cost per resolution（按 workflow release 监控）。"3 层 token audit"：Input（system prompt 缓存？tool schema 裁剪？）/ State（对话历史 4 turns 后截断或摘要？）/ Routing（简单分类任务自动降级？）。终局："未来生产 AI 不属于造最大 prompt 的团队"。https://thenewstack.io/ai-pipeline-token-optimization/

## 主线：云原生基础设施演进——P2P 分发的轻量化

- **CNCF Blog/Dragonfly 轻量部署：去掉 Manager/MySQL/Redis 的 P2P 分发**（2026-08-13, Wenbo Qi, Dragonfly Maintainer）: 标准安装除 Scheduler/Seed Client/Client 外还需 Manager（控制面：web console/OpenAPI 集成/多集群关系/动态配置分发）+MySQL+Redis——对"单集群只解决 registry 拉取过载"场景过重。**轻量模式**用两个原生 K8s 原语替换 Manager 控制面：①**ConfigMap 动态配置**——manager.addr 未设置时 Scheduler/Client 从本地 /etc/dragonfly/dynconfig.yaml 加载（Helm chart mount），refreshInterval 默认 1 分钟热更新，Pod 无需重启；参数如 seed peer 并发上传上限 loadLimit 2000、candidate parent 3、filter parent 15、peer 上传上限 200，均暴露为 Helm values（GitOps 对齐）。②**headless Service 调度器发现**——Client 的 dynconfig.yaml 指向 `dragonfly-scheduler.<ns>.svc.cluster.local:8002`，DNS 解析发现全部 Scheduler Pod IP + 健康检查过滤，StatefulSet 扩缩容自动感知；静态 IP 场景用 scheduler.addrs 列表覆盖。三部署模式（Helm chart 默认禁用 Manager/MySQL/Redis，轻量即基线）：Lightweight（仅三组件，单集群/边缘/CI 首选）/ Lightweight+Redis（持久任务+缓存元数据）/ With Manager（web console/OpenAPI/preheat API/PAT）。配套 **dragonfly-injector**（mutating admission webhook）：给应用 Pod 注入 dfget/dfcache/dfstore 工具+dfdaemon Unix socket，让 ML 模型/数据集/构建产物等次级资产也走 P2P 下载，无需改 base image（cert-manager 签发 webhook TLS）。运维含义=镜像分发控制面可退化到"零数据库状态"，升级无 DB 迁移脚本，状态存本地磁盘缓存可随时从 origin 重建。https://www.cncf.io/blog/2026/08/13/lightweight-dragonfly-deployment-p2p-distribution-without-the-database-stack/

## 侧线：模型与定价

- **TNS/Gemini 3.7 Flash：DeepSWE 65.3% 的模型不是 Google 承诺的那个**（2026-08-13, Amanda Caswell）: 3.6 Flash 发布三周后即发 3.7 Flash（新 workhorse，面向 coding agents+自动化工作流）。基准跃升：FrontierCode 1.1 Main **43.6%**（3.6 Flash 34.4%）、DeepSWE v1.1 **49%→65.3%**（"瘦模型持续超配其级别"，呼应 DeepSeek 小模型超旗舰）、WebDev Arena 1538→1588、GDP.pdf 22→34%、AutomationBench 17→30.4%。**thinking_level 三档**（low 延迟敏感/medium 默认/ high 复杂推理）替代 numeric thinking_budget；关键成本观=总 token 消耗（agent 循环全程）比单价更重要。定价策略：**$0.75/$3.75 per M tokens（输入/输出）**，3.6 Flash 同步降价至年底；**2027-01-01 翻倍至 $1.50/$7.50**——促销定价抢开发者心智（呼应 OpenAI 降价潮、"blank-check AI coding era is dead"），携带大上下文或高推理 token 的 agent 明年成本×2。迁移成本真实：去掉 temperature/top_p/top_k、thinking_level 替代 thinking_budget、删 candidate_count、移除 prefilled turns、标准化 server-side previous_interaction_id。Gemini 3.5 Pro 仍缺席（6 月承诺→"soon"→已在训 Gemini 4）——"开发者等待的模型不总按时到达"是 frontier labs 通病。https://thenewstack.io/gemini-3-7-flash-agents/

## 本期观察线

1. **Agent 运行时进入"插件化+事件溯源"收敛期**：DeepSeek Harness 的 append-only session log（resume/fork/replay/telemetry 全基于单事件流）+ 全插件架构，与 08-11 OpenAI Agent Plugins 1.0.0、08-13 Agentic AIOps 观察同向——harness 从"可运行脚本"升级为"可组合、可审计、可重建状态机"，中国实验室以 MIT 开源+全兼容（Claude Code/Codex/MCP）切入，竞赛焦点从模型能力转向运行时工程
2. **AI pipeline 治理 = 平台工程的又一次"吞并"**：LLMOps 所有权之争的答案（CNCF）= 不建第三平行栈，把 LLM 能力当作平台 capability 走 golden path——与 08-12 policy as code、08-13 token 成本治理构成"AI 负载平台化"完整叙事；shadow LLMOps 与 shadow-IT 同构，治理=请求时策略+审计轨迹而非拖慢
3. **成本治理从"选便宜模型"升级为"架构级 token 纪律"**：prompt caching -90% / 工具输出修剪 -70~90% / 意图路由 -50~80% / 上下文压缩 -30~60%，全部是架构决策；Gemini 3.7 Flash 促销价半年后翻倍是"定价钩子"典型——**按当前价做架构选型的企业在 2027-01 面临隐性成本翻倍**，与 08-13 Grok 4.6 "任务总成本≠token 单价"观察同链
4. **控制面退化是云原生组件新卖点**：Dragonfly 去掉 DB 栈的轻量模式（ConfigMap+headless Service 替代 Manager）与 08-11 KYAML 简化、08-12 Buildpacks 标准化同一趋势——**平台组件在"能力完整"与"单集群可用"之间提供可裁剪档位**，无状态化降低运维心智负担
