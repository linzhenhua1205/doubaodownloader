## 一、Kubernetes 版本与核心组件

- **Kubernetes v1.37 "Garhwal" 正式发布**（Kubernetes Blog, 2026-08-26, https://kubernetes.io/blog/2026/08/26/kubernetes-v1-37-release/）: v1.37 引入新 Stable/Beta/Alpha 特性，其中 metrics.k8s.io API 毕业转 stable（已由 tech 组收录）；发布节奏与 v1.36（2026-04 发布，60+ 特性）保持一致——K8s 维持一年三版的固定节拍，云原生平台升级窗口需按此节奏规划

- **etcd v3.7.0 发布：RangeStream 长请求特性落地**（Kubernetes Blog / SIG Etcd, 2026-07-08, https://kubernetes.io/blog/2026/07/08/announcing-etcd-3.7/）: 核心存储组件首个新 minor 版本，交付长期请求的 RangeStream 特性（流式范围读取，降低大 key 空间读取的 RPC 内存峰值）——对大规模集群 API server 读路径的稳定性意义直接，是升级 v1.37 前的依赖项排查重点

- **controller-runtime Cache 工作原理深度解析**（Kubernetes Blog, 2026-07-29, https://kubernetes.io/blog/2026/07/29/controller-runtime-cache-explained/）: 解释 informer/cache 双写机制与 watch 失效处理，说明 controller 为何不会打垮 API server；原文曾发布后修订多处技术错误——社区对 controller 最佳实践的纠错机制在起作用，运维侧应关注版本修订

- **KYAML：YAML 美化打印工具**（Kubernetes Blog, 2026-08-11, https://kubernetes.io/blog/2026/08/11/how-to-pretty-print-kubernetes-yaml-as-kyaml/）: 针对 YAML 多表示法（block/flow/别名）混乱问题推出标准美化工具，kubectl 输出规范化的小生态补充

## 二、可观测性

- **OpenTelemetry 进入 AI 基础设施时代**（The New Stack, 2026-05-21, https://thenewstack.io/opentelemetry-hits-general-availability/）: OTel 已成云计算遥测事实标准后，向 AI 基础设施扩展——LLM 调用/向量库/Agent 追踪成为新遥测维度；配套实证：Jaeger + ClickHouse 后端对 1000 万 span 实现 8.6× 压缩（https://thenewstack.io/jaeger-clickhouse-storage-backend/, 2026-05-24），可观测性存储成本压降路径清晰

- **可观测性有数据问题，AI 将使其恶化**（The New Stack, 2026-08-26, https://thenewstack.io/opentelemetry-observability-telemetry-storage/）: 高基数/高维度遥测的采集与存储成本失控，而 AI Agent 产生的 trace 数据量级更大；观点：可观测性团队需从"全采全存"转向采样治理 + 数据分级，否则成本曲线不可持续

- **Telemetry 管线控制 AI Agent 成本**（The New Stack, 2026-08-25, https://thenewstack.io/agentic-ai-telemetry-costs/）: 遥测管线（采集/路由/富化/降采样）成为 Agent 成本治理的关键杠杆——token 用量、工具调用、延迟数据经管线回流到 FinOps 层，Agent 可观测性从"排障"延伸为"计费依据"

- **AI Agent 追踪成为应用数据**（The New Stack, 2026-08-26, https://thenewstack.io/agent-traces-application-data/）: Agent 执行 trace（工具调用链/上下文窗口状态）被重新定位为业务数据而非仅运维数据——平台团队需设计 trace 的留存、隐私与重放策略，可观测性语义模型面临扩展

## 三、平台工程与 AI 运维

- **Microsoft Agent Lightning v1.0：Agent 运行时入平台工程**（The New Stack, 2026-08-26, https://thenewstack.io/microsoft-agent-lightning-harness/）: 微软发布 Agent 编排运行时 v1.0，把 Agent 生命周期（编排/沙箱/权限/可观测）纳入平台工程范畴——云原生平台的"工作负载"定义从容器向 Agent 扩展

- **Platform Engineering ROI：自建平台的真实成本**（The New Stack, 2026-08-09, https://thenewstack.io/real-cost-diy-platform/）: 量化自建内部平台的成本模型（IDP 团队人力/维护/升级 vs 商业平台许可），结论：平台工程 ROI 需按"开发者生产力杠杆"而非纯成本核算，中小规模组织自建需谨慎

- **自建 AI SRE 的实践路径**（The New Stack, 2026-07-30, https://thenewstack.io/ai-sre-root-cause-analysis/）: 用 AI Agent 做根因分析（RCA）的企业实践——AI SRE 定位为"事故调查副驾"而非替代人，人机分工：AI 负责多信号关联与模式匹配，人负责变更判断与归因决策

- **DRA 终结 K8s GPU 调度痛点**（The New Stack, 2026-08-06, https://thenewstack.io/kubernetes-dra-gpu-scheduling/）: Dynamic Resource Allocation 让 GPU 以细粒度（显存分片/共享）声明式调度（v1.34 GA→v1.36 演进已由 tech 组收录）；运维视角增量：DRA 的配额/健康上报模型将 GPU 故障处理从节点级下沉到资源级，是 AI 集群 K8s 化的关键使能项

## 四、集群运营实践

- **AWS 弃用 EKS 认证方式，81% 集群仍在使用**（The New Stack, 2026-08-19, https://thenewstack.io/kubernetes-fleet-security-management/）: AWS 弃用的 EKS 认证方法（IRSA 前身相关）仍被 81% 集群采用——云厂商弃用节奏与存量集群迁移滞后形成安全敞口，平台团队应优先审计认证路径的弃用清单

- **AWS 百万级集群运营的 zonal 故障经验**（The New Stack, 2026-07-10, https://thenewstack.io/eks-zonal-shift-resilience/）: AWS 从跨数百万 EKS 集群的运行中学到的 zonal 故障模式：依赖单一 AZ 的 control plane 组件、PVC 与节点亲和导致的故障放大；韧性设计从"多 AZ 部署"细化到"故障域感知调度"

- **大规模 Kubernetes controller 运维：从意图到执行**（The New Stack, 2026-07-17, https://thenewstack.io/kubernetes-controllers-at-scale/）: 大规模运营 controller 的实战教训——reconcile 幂等性、限流与重试风暴、cache 一致性是三类主要事故源；生产级 controller 需内置背压机制而非依赖默认 client 限流

- **边缘 Kubernetes 撞墙，Fleet 管理是出路**（The New Stack, 2026-08-20, https://thenewstack.io/edge-kubernetes-fleet-management/）: 边缘单集群运维成本/网络隔离/版本漂移问题使 K8s 边缘化受阻，转向 fleet 管理（声明式多集群策略 + 中央控制面）——与 Cluster API v1.12（2026-01，in-place 升级/链式升级）形成互补路线

- **EKS 秒级拉取多 GB 容器镜像**（The New Stack, 2026-08-10, https://thenewstack.io/accelerating-eks-image-pulls/）: EKS 优化镜像拉取（分层懒加载/并发拉取/节点缓存亲和），多 GB 镜像从分钟级降至秒级——大模型/GPU 镜像（数十 GB 级）场景下，镜像分发成为 AI 工作负载冷启动的关键瓶颈

- **KubeVirt VM 跨集群迁移：EVPN 方案**（The New Stack, 2026-08-08, https://thenewstack.io/kubevirt-evpn-vm-migration/）: KubeVirt VM 无法跨集群迁移的根因是 L2 网络域隔离，EVPN（VXLAN 控制面标准化）提供跨集群 L2 扩展——虚拟化工作负载云原生化后的网络层解

## 五、供应链安全

- **容器镜像未签名：AI 时代的定时炸弹**（The New Stack, 2026-08-14, https://thenewstack.io/unsigned-container-images-ai/）: 生产环境容器镜像签名覆盖率仍低，而 AI 工作负载镜像（模型权重 + 推理栈）供应链更长、攻击面更大；建议将 cosign/notation 签名验证纳入 CI 准入与运行时准入策略

- **npm 攻击将 provenance 证明变为伪装**（The New Stack, 2026-08-07, https://thenewstack.io/npm-supply-chain-worm-attack/）: 攻击者利用 provenance attestation 机制本身做伪装（签名看似可信的恶意包）——供应链安全工具链自身成为攻击面，验证策略需叠加"来源信任链"而非单一签名
