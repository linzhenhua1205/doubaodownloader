## 一、🔴 Kubernetes v1.37 前瞻（7/31 发布，8/26 正式发布）⭐ 核心

> 来源: https://kubernetes.io/blog/2026/07/31/kubernetes-v1-37-sneak-peek/

### 1.1 弃用与移除（Deprecations / Removals）

- **kube-proxy ipvs 模式正式弃用**（重大决策）: ipvs 模式自 v1.8 引入以解决 iptables 性能瓶颈，但**内核 ipvs API 无法完整实现 Kubernetes Services**，底层仍依赖 iptables（KEP-3866「The ipvs mode of kube-proxy will not save us」）。时间线：**v1.40 默认禁用**（feature gate 仍可选）→ **v1.43 完全移除**（KEP-5495）。启动时已输出 deprecation 警告。
  - 检查当前模式：`kubectl -n kube-system get configmap kube-proxy -o jsonpath='{.data.config\.conf}' | grep 'mode:'`
  - 影响面：大规模集群 ipvs 部署需提前规划迁移路径（iptables / nftables / eBPF 方案）

- **Static Pods 禁止引用 Secrets/ConfigMaps**（bug 修复）: Static Pod 不经 API Server 创建，本不应读取 API 资源，但历史 bug 允许通过 configMapRef/secretRef 引用。v1.37 起严格禁止，`PreventStaticPodAPIReferences` feature gate 已移除（kubernetes/kubernetes#140226）。

- **cgroup v1 支持进入倒计时**: 自 v1.35 `failCgroupV1` 默认 true，v1.37 仍可用 `failCgroupV1: false` 临时覆盖，但计划未来完全移除（KEP-5573）。**In-Place Pod Resizing、Tiered Memory Protection 等高级资源管理能力完全依赖 cgroup v2**——存量 cgroup v1 集群需尽快迁移。

- **kubectl run --filename/-f 弃用**: 生成的 Pod 总是纯由 CLI 参数（NAME/--image）构建，-f 标志冗余（kubernetes/kubernetes#138671）。

### 1.2 Breaking Changes

- **SELinuxMount 毕业 GA 并默认启用**: 卷以 `-o context=<label>` 挂载（CSI 驱动 opt-in `.spec.seLinuxMount: true`），取代递归 relabel。⚠️ **单一挂载只能持有一种 SELinux context**——同节点不同 SELinux label 的 Pod 共享卷（此前递归 relabel 可共存）可能启动失败；保留旧行为需设置 `seLinuxChangePolicy: Recursive`。无 SELinux 的集群不受影响。

### 1.3 Featured Enhancements

- **Metrics API（metrics.k8s.io）毕业 GA** ⭐: 在 Beta 停留近 **9 年**后转正（KEP-5207）。提供 Pod/Node CPU 与内存用量标准接口，支撑 **HPA 与 kubectl top**。无功能变化，v1 与 v1beta1 过渡期并行可用。

- **Kubelet in UserNS（Rootless Mode）→ Beta**（KEP-2033）: 节点组件在 Linux 用户命名空间内以**非特权用户**运行（命名空间内仍表现为 root），减少宿主机 root 面，限制节点组件漏洞影响半径。

- **Volume Health Monitor 重置为 Alpha**（KEP-1432）: v1.21 首度实现后重置，引入 **4 个新 CSI RPC**：`ControllerListVolumeHealth`/`ControllerGetVolumeHealth`（控制器侧，结果写入 `PVC.status.healthStatus`）、`NodeGetVolumeHealth`（节点侧，写入 `Pod.status.volumeHealth`）、`NodeGetStorageHealth`（驱动健康，写入 `CSINode.status.storageHealth`）。错误词汇机器可解析（Inaccessible/Degraded 等），控制器/节点两侧报告独立展示。

### 1.4 时间表

- **v1.37 正式发布：2026-08-26（周三）**

## 📊 本期观察

1. **kube-proxy ipvs 弃用是 2026 年最大运维迁移信号**: 从 iptables → ipvs → 现在 ipvs 也"救不了我们"（KEP-3866 直言），三层演进揭示内核数据面 API 与 K8s Service 语义的鸿沟。未来方向明确指向 **nftables / eBPF（kube-proxy 替代方案）**。大规模集群运维需在 v1.40（默认禁用）前完成迁移评估。
2. **Metrics API GA 是 HPA 生态的里程碑**: 近 9 年 Beta 后转正，说明 K8s 核心计量接口已稳定——自定义 metrics exporter（如 7/14 文章）与 HPA 的集成将获得正式契约。
3. **Kubelet Rootless 化与 Volume Health Monitor 重置 Alpha** 双线并进：控制面安全（最小特权）与存储可观测性（机器可解析健康状态）是 v1.37 的两大隐藏主题，对大规模集群运维的故障定位效率有直接价值。
4. **Headlamp 正在成为 K8s 官方 UI 事实标准**: Kubeflow/CAPI/Volcano/Knative 插件一周内密集发布 + Microsoft 官方迁移指南，Dashboard 迁移窗口已开启。
5. **静态 Pod 安全收紧**（禁止引用 Secret/ConfigMap）提示：绕过 API Server 的路径持续被修补，安全基线向"一切皆经 API"收敛。
