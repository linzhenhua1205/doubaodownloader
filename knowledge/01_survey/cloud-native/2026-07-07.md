## 1️⃣ 🔴 K8s v1.36 完整特性矩阵：User Namespaces GA + DRA 持续推进 + Pod-Level Resource

**来源**: Kubernetes Blog (2026-05 系列)
**链接**: https://kubernetes.io/blog/

**关键信息**: K8s v1.36 (Haru) 是功能密度极高的版本，核心特性如下：

| 特性 | 状态 | 影响 |
|:----|:----:|:-----|
| **User Namespaces** | **GA** | 全面无 root 运行，安全基线升级 |
| **DRA: More Drivers, New Features** | GA 持续演进 | 更多 GPU/NVIDIA 驱动 + Device Health Reporting |
| **Pod-Level Resource Managers** | **Alpha** | Pod 粒度的资源管理器隔离 CPU/内存配额 |
| **In-Place Vertical Scaling (Pod-Level)** | **Beta** | Pod 级别原地扩缩容（之前是 Container 级别） |
| **PSI Metrics for K8s** | **GA** | 内存/IO 压力指标正式可用 |
| **Server-Side Sharded List and Watch** | 新特性 | API Server Watch 扩展性大幅提升 |
| **Declarative Validation** | **GA** | 声明式校验取代 Admission Webhook 部分场景 |
| **Admission Policies That Can't Be Deleted** | 新特性 | 防误删准入策略，合规场景刚需 |
| **Mixed Version Proxy** | **Beta** | 多版本 API Server 混用代理 |
| **Tiered Memory Protection + Memory QoS** | 新特性 | NUMA 层级内存保护 |
| **Workload-Aware Scheduling** | 演进中 | 根据实际负载特征调度 |
| **Fine-Grained Kubelet API Authorization** | **GA** | kubelet 端口精细授权 |
| **SELinux Volume Label Changes** | **GA** | SELinux 卷标签自动化 |
| **Staleness Mitigation for Controllers** | 新特性 | Controller 数据陈旧度可观测 |
| **Volume Group Snapshots** | **GA** | 一致性组快照 |
| **Gateway API v1.5** | Stable | Ingress2Gateway 1.0 GA |
| **Agent Sandbox** | 新特性 | K8s 上运行 AI Agent 沙箱 |

**影响判断**: v1.36 完成了从 v1.35 DRA GA 到全链路 Pod 资源管理的跨越。User Namespaces GA + Pod-Level Resource Managers + PSI Metrics GA 三者结合，标志着 K8s **多租户安全与资源隔离基线已进入生产级**。Server-Side Sharded List/Watch 对万节点集群的 API Server 扩展性是关键改进。

## 2️⃣ 🔴 K8s AI 治理政策详解 + CodeRabbit 上线

**来源**: Kubernetes Blog (2026-06-26)
**链接**: https://kubernetes.io/blog/2026/06/26/open-source-maintainership-in-the-age-of-ai/

**关键信息**:

- **AI Policy 核心条款**:
  1. **透明度优先**: 使用 AI 辅助必须披露（一句 "This PR was written in part with the assistance of generative AI" 即可）
  2. **人类责任**: 禁止 AI 列为合著者，禁止 "assisted-by"/"co-developed" 署名，禁止 AI 签署 commit
  3. **CLA 检查启用 co-author**: 如果 co-author 是 AI 则无法通过 CNCF CLA 检查
  4. **人类参与**: Reviewer 期望与人类沟通；不能用 AI 回复 review；无法解释的 PR 将被关闭
  5. **验证义务**: 贡献者必须通过 code review + 测试 + 个人理解验证 AI 生成的代码

- **CodeRabbit 已上线** (mid-2026): Kueue、JobSet、Agent-Sandbox 等子项目开始试点 AI PR 审查工具
- Copilot 工具的使用受限：需要贡献者拥有 Copilot License
- 下一步探索：AI 技能减少 Maintainer 倦怠、AI 辅助失败测试分类、K8s 运维 AI 技能

**影响判断**: K8s AI Policy 是**云原生社区首个明确的 AI 辅助开发治理政策**，将影响 CNCF 所有项目的 PR 管理流程和 CI/CD 中的 AI Code Review 工具选型。该政策平衡了创新（允许 AI 辅助）与问责（人类必须负责）。

## 3️⃣ 🔴 K8s WG Device Management：GPU/TPU/加速器硬件管理标准化

**来源**: Kubernetes Blog (2026-06-24)
**链接**: https://kubernetes.io/blog/

**关键信息**:

- WG Device Management 于 KubeCon EU 2026 成立，聚焦 AI/Edge/Telecom 工作负载的硬件管理需求
- 核心目标：标准化 GPU、TPU、FPGA、NPU 等多种加速器在 K8s 上的资源建模与调度
- 与 DRA 工作组紧密协作，确保 DRA 框架能承载各种新硬件类型
- 关键工作项：
  - 设备健康状态报告标准化（v1.36 Device Health Reporting 的 WG 推动）
  - 多设备拓扑感知调度（GPU Direct RDMA 跨节点拓扑）
  - 设备固件/驱动版本管理和升级编排

**影响判断**: 随着 AI 工作负载占比快速上升，WG Device Management 的成立标志着 K8s 从"容器编排器"正式迈向"异构计算编排器"。与 DRA 的配合将决定 K8s 能否真正成为 AI 基础设施的控制面。
