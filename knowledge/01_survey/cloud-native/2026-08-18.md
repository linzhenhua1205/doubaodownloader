## AI 运维与 Agent 生产边界

- **TNS/ElevenLabs MCP 连接器：Claude 可直接删生产语音 Agent**（08-17）: ElevenLabs 托管 MCP connector 允许 Claude 检查并修改生产环境语音 Agent——但聊天确认≠经过测试的部署流程；AI 运维 Agent 获得生产写权限后，\"对话式确认\"与\"受控发布\"之间的安全落差成为 AIOps 新风险面，运维责任边界（谁为 Agent 的生产操作背书）进入讨论。https://thenewstack.io/elevenlabs-mcp-voice-agents/
- **TNS/Agent Plugins 治理缺位：Anthropic 定标准却不主持治理**（08-17）: Anthropic 定义了 Agent Plugins 格式标准（AI 工具/技能打包规范），但未牵头该格式的治理（governance）——标准制定者与生态治理者分离的\"标准孤儿\"风险；与 MEMORY 中 Agent 生态标准化主线（dsh 生态第三阶段）共振：Agent 工具格式的互操作与中立治理是 2026 平台工程新课题。https://thenewstack.io/agent-plugins-portability-gaps/
- **CNCF/可观测策略即代码：VictoriaMetrics×Kyverno 实践**（08-12）: 将策略（policy）做成可观测的代码——策略执行效果可被监控/审计而非黑盒拦截；云原生治理从\"策略门禁\"走向\"策略可观测\"（policy as code + observability 融合），是运维运营精细化信号。https://www.cncf.io/blog/2026/08/12/good-apps-arent-born-theyre-guided-building-observable-policy-as-code/
- **CNCF/服务网格可观测双源陷阱：zero+zero=two 实战**（08-11）: Istio+Kiali 默认指标栈（Prometheus）在双数据源（网格指标+应用指标）下出现重复计数（zero+zero=two）——网格可观测性落地中指标源去重与命名空间隔离是常见坑，Coralogix×VictoriaMetrics 给出工程解法；服务网格运维从\"装好看板\"进入\"指标口径治理\"阶段。https://www.cncf.io/blog/2026/08/11/a-practical-guide-to-solving-when-zerozerotwo-in-mesh-observability/

- **TNS/Per-developer 环境目标失效：Agent 移动了球门**（08-15，补录）: 平台工程多年追求的\"每人一套开发环境\"（per-developer environments）被 coding agent 改变目标——Agent 需要的是可验证/可并行的运行时而非人工开发环境；平台工程的交付对象从\"人\"转向\"Agent 运行时\"，云原生平台的价值锚点迁移。https://thenewstack.io/new-tenant-is-change/
