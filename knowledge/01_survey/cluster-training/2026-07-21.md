### 1. GPU集合通信逼近物理极限 — "Every Microsecond Matters"

| 属性 | 内容 |
|:----|:------|
| **论文** | Every Microsecond Matters: Achieving Near Speed-of-Light Latency in GPU Collectives |
| **链接** | [arXiv:2607.16100](https://arxiv.org/abs/2607.16100) |
| **作者** | Siyuan Shen, Anton Korzh, John Bachan, Tiancheng Chen, Arnav Goel, Ludwig Schneider, Pouya Kousha, Zhenhao He, Sylvain Jeaugey, Kamil Iskra, Nishank Chandawala, **Jeff R. Hammond, Torsten Hoefler** |
| **方向** | 通信调度 — GPU集体通信延迟优化 |
| **核心指标** | **7%以内**的绝对Speed-of-Light(SoL)下界 |
| **核心方法** | ① barrier-free同步 ② 对称内存+multicast ③ NCCL device-side API自定义collective kernel |
| **意义** | 长上下文LLM推理中大量小collective位于token生成关键路径，微秒级延迟直接影响性能与成本 |

**详细解读**:
- 现有NCCL针对带宽优化，但在decode-heavy推理场景中，小消息collective延迟是关键瓶颈
- 三项关键技术：barrier-free同步（消除同步开销）、对称内存与multicast利用（减少数据搬移）、基于NCCL device-side API的低延迟collective kernel接口
- 微基准测试小/中消息延迟降至SoL 7%以内
- 端到端：改善LLM推理的inter-token延迟与吞吐，同时加速cuSOLVERMp等HPC负载
- **地位**: Hoefler组作品，系统性地将GPU collective延迟推向物理极限

### 2. GPU有损压缩突破"预测-吞吐"权衡 — FSZ

| 属性 | 内容 |
|:----|:------|
| **论文** | FSZ: Breaking the Prediction-Throughput Trade-off in GPU Lossy Compression |
| **链接** | [arXiv:2607.15413](https://arxiv.org/abs/2607.15413) |
| **作者** | Jiajun Huang |
| **方向** | Checkpoint压缩 — GPU有损压缩 |
| **核心指标** | **10.95×** vs cuSZp-P, **2.92×** vs cuSZp-O, **676 GB/s**压缩吞吐 |
| **核心方法** | ①跨块预测状态传递 ②每tile自适应多阶预测 ③单次四路评估 |
| **接收** | **SC26** |

**详细解读**:
- 现有GPU有损压缩器用固定一阶预测器+独立块处理，压缩率受限
- FSZ在单CUDA kernel内完成三项互强化的算法创新：
  - 跨块预测状态：256-element tile间传递Lorenzo预测状态，消除7/8边界残差
  - 每tile自适应多阶预测：从一阶/二阶/centering变体中自适应选择
  - 单次四路评估：利用有限差分数学生质，单次数据读取评估全部变体
- GH200实测：同时实现最高平均吞吐(676 GB/s压缩, 785 GB/s解压)
- **对万卡集群意义**: 大幅降低Checkpoint存储开销和I/O时间

### 3. PagedWeight — MoE动态运行时权重量化

| 属性 | 内容 |
|:----|:------|
| **论文** | PagedWeight: Efficient MoE LLM Serving with Dynamic Quality-Aware Weight Quantization |
| **链接** | [arXiv:2607.16184](https://arxiv.org/abs/2607.16184) |
| **作者** | Yuchen Yang, Yifan Zhao, Anisha Dasgupta, Sasa Misailovic |
| **方向** | KV Cache优化 — MoE服务Weight-KV Cache平衡 |
| **核心指标** | **FP16等价精度**节省**72%** GPU内存, **1.94×**吞吐提升 |
| **核心方法** | 运行时动态量化MoE权重，根据内存压力自适应调整expert精度 |

**详细解读**:
- 在KV-cache密集型服务场景中，MoE面临权重内存需求与增长的KV Cache之间矛盾
- PagedWeight在运行时动态调整expert权重量化精度，平衡任务精度、内存消耗与吞吐/延迟
- 在类似内存预算下，质量比现有量化方法提升**39.3%**（吞吐损失≤4.1%）
- **创新点**: 首次将MoE权重量化从训练时静态转为运行时动态，与KV cache内存竞争联合管理

### 5. AI负载能源优化建模 — EMO

| 属性 | 内容 |
|:----|:------|
| **论文** | EMO: Energy Efficiency Modeling and Optimization for AI Workloads |
| **链接** | [arXiv:2607.12324](https://arxiv.org/abs/2607.12324) |
| **作者** | Jiyu Luo, Shaoyu Chen, Jingwei Sun, Shengcai Liu, Ke Tang, Guangzhong Sun |
| **方向** | 训练优化 — AI负载能源效率 |
| **核心指标** | **15-28%** 能耗降低, 仅**2-5%**性能损失 |

- 对万卡集群: 训练能耗优化可直接转化为TCO降低，且无需修改模型

### 6. 多Provider LLM有状态Failover — ContinuityBench

| 属性 | 内容 |
|:----|:------|
| **论文** | ContinuityBench: A Benchmark and Systems Study of Stateful Failover in Multi-Provider LLM Routing |
| **链接** | [arXiv:2607.15899](https://arxiv.org/abs/2607.15899) |
| **作者** | Vishal Pandey, Gopal Singh |
| **方向** | Checkpoint/容错 — LLM推理有状态故障切换 |
| **核心指标** | **99.20%** CPR [95% CI: 98.27%, 99.63%] |
| **核心方法** | History-Forwarding策略+异步指数退避+jitter |

**详细解读**:
- 问题: 生产环境中主API提供商中断后，无状态failover会静默丢弃对话历史
- 新指标: CPR(连续性保持率) + CLO(连续性延迟开销)
- 有状态代理架构: History-Forwarding跨异构LLM端点重建对话状态
- 标准无状态架构的CPR近乎0%
- 对推理系统: 多Provider切换场景下的推理连续性保障机制

### 7. 系统级KV Cache优化综述 (ACL'26 Findings)

**arXiv:2607.08057** — "Towards Efficient LLM Serving: A Survey on System-Aware KV Cache Optimization"

发表于ACL'26 Findings，从系统行为视角组织KV Cache优化工作为三个维度:
- **执行与调度(时间维度)**: 预填充/解码阶段的KV操作
- **放置与迁移(空间维度)**: 跨存储层级的KV Cache放置
- **表示与保留(结构维度)**: 量化/驱逐/压缩等表示优化

同时分析了跨行为协同设计和行为-目标链接。适合作为KV Cache优化领域的系统性入口。

## 📌 本期核心趋势

1. **GPU Collective逼近物理极限**: Hoefler组将collective延迟推至SoL 7%以内——barrier-free同步+对称内存利用是关键技术。长上下文LLM推理中微秒级优化直接转化为token延迟收益。**"通信延迟不再只是工程优化，已成物理边界问题"**

2. **Checkpoint压缩进入新量级**: FSZ(SC26)的10.95×压缩比+676 GB/s吞吐意味着Checkpoint I/O时间可从分钟级降至秒级。这对万卡集群频繁Checkpoint场景影响显著

3. **KV Cache压缩全面理论化**: 本周出现7项相关工作从不同理论方向推进——率失真优化(RDKV)、可微分学习(LKV)、范围搜索(Louver)、排队论稳定性(KV Stable)、频域分析(CacheTune)。**启发式时代正在结束**

4. **推理系统容错受到关注**: ContinuityBench首次系统化研究多Provider LLM推理的有状态failover机制，99.20%连续性保持率验证了History-Forwarding策略有效性

5. **AI能源优化进入系统级**: EMO(SC26)展示了无需修改模型、仅通过运行时频率调度即可实现15-28%能耗降低，对万卡集群TCO有直接价值
