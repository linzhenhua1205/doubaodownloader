## 一、国产算力集群训练实践（昇腾生态）

### 1.1 SLAI T-Rex：昇腾 SuperPOD 上万亿参数 MoE 全参后训练

- **SLAI T-Rex: Full-Parameter Post-training of the DeepSeek-V4 Family on Ascend SuperPOD**（arXiv:2607.20145，2026-07-22，73 页 22 图 20 表）：昇腾 NPU SuperPOD 上完成 DeepSeek-V4 模型家族的全参数后训练（CPT+SFT）端到端工程实践。核心贡献是**三层层次优化框架**：模型级并行（model-level parallelism，适配昇腾拓扑的并行布局）→ 计算-通信编排（computation-communication orchestration，重叠通信与 kernel 执行）→ 低层 kernel 执行（针对 NPU 微架构的算子优化）。系统最终实现 **34.22% MFU**，较开源基线配方提升 **2.93x**，且保持训练稳定性。在此之上建立 CPT 和 SFT 流水线用于复杂运筹优化（OR）任务：数据集含 10K 高质量 SFT 样本，覆盖四类任务与三种问题表示（求解器验证的合成优化文档 + 领域资源）；微调后模型在 OR 任务上平均 zero-shot Pass@1 达 **71.81%**，超过 GPT-5.4-Mini 3.98pp、超过基础 DeepSeek-V4-Flash 11.27pp。URL: https://arxiv.org/abs/2607.20145

> **分析：34.22% MFU 在国产算力语境下意味着什么？** 需要先建立基准坐标系：NVIDIA H100/H200 集群上主流 LLM 预训练 MFU 通常 40-55%（Megatron-LM 基线 45%±、DeepSeek 自研配方宣称 55%+），而 34.22% 的 MFU 低于此区间约 10-20 个百分点。但判读时必须考虑三点语境：其一，**这是"后训练"而非预训练**——CPT/SFT 阶段 batch 更小、序列模式更多样、调度碎片更多，天然比预训练更难达到峰值 MFU；其二，**昇腾 NPU 的软件栈成熟度落后 CUDA 生态数年**，开源基线配方（大概率是为 GPU 调优的 DeepSeek-V3 开源工程）直接移植到 NPU 会遭遇 kernel 缺失、通信原语低效、显存管理不匹配三重损耗，2.93x 的提升幅度说明优化前的基线可能只有 ~11.7% MFU；其三，**34.22% 是"优化后"而非"天花板"**——报告为工业实践型文档，未声称逼近硬件理论峰值。对用户的决策含义：国产算力集群的 MFU 差距本质是**软件栈缺口而非硬件算力差距**，这与"国产 GPU 单卡算力已追平、生态差距为主"的行业判断一致；在超节点产品规划中，为昇腾预留的调优预算（算子库/通信库/并行编排）应视为必要成本而非可选项。

## 二、并行策略新维度：结构感知与数据驱动

### 2.1 veScale-FSDP：打破固定分片格式的结构感知 FSDP

- **veScale-FSDP: Flexible and High-Performance FSDP at Scale**（MLSys 2026，OpenReview）：FSDP（=ZeRO-3）因其内存效率与对模型代码的最小侵入性而成为大规模训练主力，但现有 FSDP 系统依赖**固定 element-wise 或 row-wise 分片格式**，与 block-structured 计算（如 MoE 专家的块状权重、2D 权重矩阵的 tile 化、FlashAttention 类算子）冲突，导致现代结构感知模型的训练支持缺失。veScale-FSDP 提出灵活分片格式以桥接两者。URL: https://openreview.net/forum?id=3Lj8R0F48P

### 2.2 FCP：上下文并行的变长序列适配

- **Unleashing Scalable Context Parallelism for Foundation Models Pre-Training via FCP**（MLSys 2026，OpenReview）：上下文并行（CP）已被广泛用于支持基础模型预训练中不断增长的上下文长度，但现有设计无法处理训练数据集**序列长度的大幅变化**（变长序列是真实语料的常态），导致次优性能：要么对短序列过度切分（计算低效 + 过度通信），要么处理长短序列混合时负载失衡。FCP 针对该 gap 提出可扩展的 CP 方案。URL: https://openreview.net/forum?id=MPVycRsIn6

### 2.3 DCP：数据驱动的运行时自配置

- **Training Variable Long Sequences with Data-Centric Parallel**（arXiv:2608.07524，2026-07-14）：变长序列训练的传统方案在效率与易用性间二选一——静态配置（如固定并行度）简单但负载不均，复杂方法（动态重配置）代码侵入大。DCP 的核心理念是**让数据本身驱动运行时**：根据每个 batch 的序列长度动态调整直接运行时设置（并行大小、梯度累积、重计算策略）。32 张 H200 上最高 **2.88x 加速**；设计上泛化性强，任意模型仅需 **10 行代码**集成。作者建议将其作为变长序列分布式训练的鲁棒基线。URL: https://arxiv.org/abs/2608.07524

### 2.4 FlowTrain：VLM 训练的流式解耦

- **FlowTrain: Flow-Based Decoupled Training for Industrial-Grade Vision-Language Models**（arXiv:2606.23087，2026-06-22）：工业级 VLM 分布式训练效率远低于纯文本 LLM——现有方案要么单片设计（异构模块统一并行度），要么分离部署但按 batch 同步流水线执行。FlowTrain 将 VLM 训练重构为**生产者-消费者数据流**，通过统一内存池协调：编码器与主干可独立进展（全局虚拟地址空间）；提出异构并行分配器（按吞吐匹配问题为各模块指定专属并行策略）+ 动态打包调度器（按实际 LLM 侧计算成本运行时构建均衡 micro-batch）。真实工作负载上 **>50% MFU**、吞吐最高提升 **1.7x**，显著缩小与纯 LLM 训练的差距。URL: https://arxiv.org/abs/2606.23087

### 2.5 Tevatron 3.0：学术预算下的 MoE reranker 训练

- **Tevatron Meets Megatron: Expert-Parallel LLM Reranker Training on an Academic Budget**（arXiv:2608.00916，2026-08-02）：现代 reranking 配方（十亿级 cross-encoder、MoE 骨干、强教师蒸馏）已超出大多数学术团队的训练基础设施能力。Tevatron 3.0 将 Megatron-Core 训练后端集成进 Tevatron，同时保留数据流水线、评估流程与 HuggingFace 兼容 checkpoint。基准显示：可比数据并行设置下 Megatron 匹配 FSDP 的 reranker 质量与训练效率，推荐单节点配置下快至 **22%**；支持 LoRA 与全参微调。关键突破：**专家并行（EP）使 30B 参数 Qwen3-30B-A3B MoE reranker 训练成为可能（PyTorch FSDP1 不可行）**。BEIR-15 对照实验显示 MoE reranker 匹配 dense 8B 质量，激活参数不足一半、推理吞吐显著更高。URL: https://arxiv.org/abs/2608.00916

> **分析：三条并行路线为何同时转向"结构/数据感知"？** veScale-FSDP、FCP、DCP、FlowTrain 表面领域各异（分片格式、上下文并行、变长序列、VLM 异构模块），深层共享一个判断：**并行度与布局的"最优解"不再能用静态常量表达**。传统并行策略（TP/PP/DP/ZeRO）的假设是模型同构、序列等长、计算均匀——但 MoE（块状权重）、长上下文（序列长度跨数量级变化）、VLM（编码器-主干算力悬殊）三个现代趋势同时击穿该假设。解法分两条路径：veScale-FSDP/FlowTrain 走"**结构感知**"路径（分片格式/并行分配器匹配计算结构），FCP/DCP 走"**运行时自适应**"路径（按实际序列长度动态调节）。对万卡集群的意义：并行策略选择正从"训练前一次性决策"变为"训练中持续调节"，这要求集群软件栈（调度器、通信库、checkpoint）支持在线重配置——与 08-22 收录的 DynaTrain（秒级并行度切换）形成上下游闭环。另外注意 veScale 是字节跳动开源的 FSDP 系（veScale 框架），其 MLSys 2026 论文入选说明国产大厂系统工作在国际顶会持续产出。

## 三、KV cache 系统化：从推理优化到全栈自由度

### 3.1 Prefill 加速：FlashPrefill V2

- **FlashPrefill V2: Block-Sparse Prefill Attention for Long-Context LLM Serving**（arXiv:2608.19758，2026-08-20）：长上下文推理中 prefill 阶段的二次复杂度注意力是计算瓶颈。V2 在 V1 原型（瞬时模式发现 + 基于 max 的动态阈值）基础上向生产级演进：① 引入**均值修正项**抑制近似误差，极端稀疏度下性能退化可控；② 按 FlashAttention-3/4 最新实现重设计稀疏注意力算子（PackGQA 内存访问、warp specialization、pingpong 流水线），支持 **FP8 推理**；③ 原生支持 **paged KV cache 与 continuous batching**，可作为 SGLang 等现代推理框架的 attention 后端。NVIDIA H20（部署最广的推理加速器之一）实测：128K 上下文下 FP8 较 FlashAttention-2 快 **47.26x**、BF16 快 27.19x；FP8 下仍较 FA3/4-aligned dense 基线快 **30.49x**。URL: https://arxiv.org/abs/2608.19758

### 3.2 路由与调度：CacheRoute / GraniKV

- **CacheRoute: Planned Prefix-Affinity Routing for Large-Scale LLM Serving**（arXiv:2608.19677，2026-08-20）：前缀缓存仅在重复请求回到仍持有前缀 KV 的服务器时才省 prefill。Cache-blind 负载均衡打散复用、固定亲和会压垮单服务器——CacheRoute 用**周期性路由计划**化解：高请求率 key 进入稳定 warm set 并按预期负载放置（热 key 允许多目的地）。Llama-3.3-70B fp8 × 60 H100 实测：**176±11 QPS @ 3.5s p99 SLO**，为五个基线中最强的 **2.3x**；KV cache 命中率从 cache-blind 均衡的 64.1±1.3% 升至 **93.2±0.5%**。两个 32B 工作负载给出反例：亲和回收的 KV 工作太少时，残余负载偏斜会缩小甚至抹掉收益——因此作者建议部署前用 shadow replay 门控，而非仅凭工作负载统计开启亲和。URL: https://arxiv.org/abs/2608.19677

- **GraniKV: Asymmetric Granularity KV-Cache Paging for Multi-Agent Systems with Long Shared Prefix**（arXiv:2608.15584，2026-08-16）：生产级 paged-serving 引擎对 KV cache 用统一分页粒度，但多智能体工作负载的两块区域需求相反：长共享前缀要**连续性**（HOT 池），每请求后缀要**细粒度分配**（COLD 池）。GraniKV 首创非对称分页粒度 + 每步调度器在双后端（计算/内存/通信受限）间选路。Lp=16K 共享 token 时较生产基线：Llama-3.1-8B/TP=1 输出吞吐 **2.16x**、Qwen-2.5-14B/TP=2 1.98x、Qwen-2.5-32B/TP=4 1.57x；异构多智能体（不同 prompt）场景 **1.95x** 持续（batch-global cascade 归零到 parity，存储层单独扛起收益）。URL: https://arxiv.org/abs/2608.15584

### 3.3 内存回收与压缩：vToken / AATC / BSR

- **vToken: Token-Level Virtualization for Reclaimable KV Caches**（arXiv:2608.13263，2026-08-13）：PagedAttention 用固定大小块减少分配器碎片，但现代 KV 驱逐算法在 token 粒度工作，与块级管理错配造成**块内碎片**——大量已分配 KV 内存不可回收。vToken 是轻量 token 级虚拟化层：token-table 间接寻址解耦逻辑 token 活性与物理块放置，异步 repacking 回收活跃 token。保留 PagedAttention kernels 与 CUDA Graph 兼容。vLLM 中配合 H2O/Random/Scissorhands 实现：较 Naive-Evict 基线每请求保留 KV 块减少 **27.2%-72.3%**，SLA 约束吞吐提升至 **1.37x**；受限 active-KV 预算下最大并发扩展 **2x**；每策略集成足迹从 500+ 行降至 <50 行。URL: https://arxiv.org/abs/2608.13263

- **KV Cache Compression Through the Lens of Transform Coding**（arXiv:2608.14191，2026-08-14）：现有 KV 量化以缓存自身重构误差最小化为目标，未考虑误差如何经注意力传播。作者证明：白噪声量化模型下**注意力感知失真可分解为跨 token/通道可因式分解的加性 key/value 贡献**，从而把经典信号处理的变换编码（transform coding）+ 逆注水（reverse water-filling）引入 KV 压缩：AATC 在标定集上分配 bit 以最小化注意力感知失真。Llama-3.1-8B-Instruct / Qwen-2.5-7B-Instruct 上跨 LongBench/RULER/GSM8K/MMLU-Pro/MATH-500 评估，**~5.8x 压缩近无损**（各基线至少在某设置下退化）。URL: https://arxiv.org/abs/2608.14191

- **Bounded-State Restoration: Decoupling Local Restore Capacity from External LLM State**（arXiv:2608.17826，2026-08-18）：分层 KV cache 系统可把长上下文执行状态保留在 GPU 内存之外，但保留容量不等于本地可执行所需内存。论文隔离出**恢复工作集（RWS）**——恢复期间生命周期重叠的峰值本地暂存状态。BSR 将"完整发现"与"本地驻留"分离：不物化全部命中即可探测完整可复用前缀，再通过最多 W 块的窗口安装确认状态；请求级提交规则保证部分安装永不暴露为有效前缀（失败回退低档位或确定性重算）。DeepSeek-V4-Flash TP=2 × 两个 DGX Spark 节点实测：外部状态从 1.956 增长至 **31.277 GiB/rank**，而 L1 RWS 在 W=32 时保持 **500.75 MiB/rank**（63.96x 外部状态/本地活跃暂存比）；SSD 优化把 512K 恢复 TTFT 从 43.1s 降至 **17.6s** 而不改 RWS。URL: https://arxiv.org/abs/2608.17826

### 3.4 恢复与一致性：KV-Rescue / Rollback Consistency

- **KV-Rescue: Recovering Reasoning Language Model KV Eviction Loss via Stepwise Interleaving**（arXiv:2608.15797，2026-08-16）：KV 驱逐在激进预算下不仅降精度，还会引发**失控退化**（输出不连贯/重复直到长度上限）。论文量化该损失主因是"信息缺口"而非"能力缺口"：驱逐的 7B 模型与全上下文 1.5B 模型错误互补，二者 oracle 选答可恢复 79% 的精度差距。KV-Rescue 用轻量全上下文 helper 与主模型交错推理步骤共享轨迹，在线熵/可压缩性检测器提前终止退化候选。5 个数学基准 × Qwen2.5-Math 7B/72B：驱逐预算 B=64 时平均恢复 **87%** 精度损失；解码成本分析显示遏制失控退化平均减少主模型 **43%** token 生成。URL: https://arxiv.org/abs/2608.15797

- **Aborted but Not Forgotten: KV-Cache Retention Breaks Rollback Consistency in Language Agents**（arXiv:2608.15939，2026-08-16）：状态化语言 agent 假设拒绝分支可通过从应用 transcript 清除来回滚，但若 serving session 在逻辑中止后仍保留 KV 状态，模型会继续注意应用认为已丢弃的内容——形式化为**回滚一致性（rollback consistency）**缺失。核心失败是跨层：正确逻辑回滚不一定与保留的推理状态组合。7 个开源权重家族（3.8B-36B）上，仅保留 KV 就在 63 个受审单元中翻转 25 个受保护效果（攻击 token 全程不在请求中）；重建缓存关闭全部通道；交易本地缓存恢复即可修复，无需全局缓存清空。URL: https://arxiv.org/abs/2608.15939

### 3.5 Agent/工具场景与新型架构：ReCache / WhiteMatter / DeltaLog

- **ReCache: Efficient KV Cache Reuse and Compression for Tool-Augmented LLM Agents**（arXiv:2608.19662，2026-08-20）：agentic 模型反复以不同组合/顺序编码工具与技能 schema，破坏标准前缀缓存的复用。ReCache 独立缓存资源表征：**resource-wise attention** 消除跨资源交互、赋予资源本地位置，产生组合不变的 KV 块；再按贡献选择层-KV头组路由 + 结构/语义剪枝保留仅调用关键字段。7 个公开工具/技能数据集：resource-wise attention 匹配 dense 调用性能（82.3% vs 82.4% Inv-F1）且 TTFT 提速 **3.655x**；完整框架 KV 张量内存 -92.43%、注意力加速 1.423x。URL: https://arxiv.org/abs/2608.19662

- **WhiteMatter: All-to-All Cross-Layer Connections via KV Mixing**（arXiv:2608.18486，2026-08-19）：Transformer 每层只注意自己深度产生的 KV，尽管自回归解码时存在更深的表征。WhiteMatter 让每个注意力层注意每个历史 token 的所有层表征：router 把 L 层状态混合进 **k 个 KV 通道**（k 控制缓存大小，k<L 即压缩），各消费层注意其中一个通道。预训练实验：优于 +50% 层数的 vanilla Transformer；**50% KV 压缩**保留大部分增益。URL: https://arxiv.org/abs/2608.18486

- **DeltaLog: Deferred Materialization of Recurrent States for Linear Attention Decoding**（arXiv:2608.15533，2026-08-16）：线性注意力模型用循环状态更新替代二次方 prefix 计算，但现有解码实现每生成一个 token 都物化并回写全量循环状态，状态维护成为主要内存流量。DeltaLog 将状态表示为 **dense base state + 有界紧凑更新日志**：多数解码步骤仅追加紧凑因子，周期性 merge 步骤把累积更新折回 base。GDN/KDA/RWKV6 实现：循环状态更新 kernel 加速至 **1.86x**、写流量减至 **7.83x**、端到端 1.05-1.20x。URL: https://arxiv.org/abs/2608.15533

> **分析：KV cache 为何在 2026-08 集中爆发系统性创新？** 一个合理的因果解释链条是：**长上下文成为主流能力 → KV 内存随序列长度线性膨胀 → 单机内存墙首先被击穿 → 系统被迫把 KV 从"单机缓存"重构为"分布式/分层/可回收资源"**。本月论文恰好覆盖该重构的四个子域：**prefill 侧**（FlashPrefill V2 把稀疏注意力算子推到生产级并接入 SGLang 生态）、**调度侧**（CacheRoute 证明路由计划可以同时拿到亲和收益与负载均衡——此前被认为是 trade-off）、**回收侧**（vToken 解决驱逐粒度与分页粒度错配、AATC 用信息论给出压缩的理论下限）、**恢复侧**（BSR 把"发现"与"驻留"解耦，让外部状态恢复的工作集有界化）。更值得注意的是两个新方向：**正确性**（Rollback Consistency 揭示 KV 保留会破坏 agent 回滚语义——这是安全审计维度的空白）与**架构协同**（WhiteMatter 把 KV 通道数变成架构自由度，KV-Pipe 在 08-22 已证明它同时是流水线均衡自由度）。对集群训练优化的直接含义：RL post-training 中 rollout 的 KV 管理（08-22 TideRL/MISA-T 已收录）与本月的通用 KV 系统化工作互为表里——**训练侧正在消费推理侧的一切 KV 优化成果**，反之推理侧的量产需求也在定义训练侧的数据布局（长上下文训练数据的 KV 局部性）。

## 四、硬件-内核协同：Blackwell 与存储级扩展

### 4.1 FlashAttention-4：面向 Blackwell 不对称硬件缩放

- **FlashAttention-4: Algorithm and Kernel Pipelining Co-Design for Asymmetric Hardware Scaling**（MLSys 2026；arXiv:2603.05451，2026-03）：FlashAttention-3 面向 Hopper（H100），而产业已快速转向 Blackwell（B200/GB200），其性能特征因**不对称硬件缩放**而根本不同：tensor core 吞吐翻倍，而共享内存带宽、指数单元等功能单元增长更慢或不变。FA-4 的针对性技术：① 利用全异步 MMA 与更大 tile 尺寸的**重设计管线**；② **软件模拟指数与条件 softmax 重缩放**，削减非 matmul 运算；③ 利用 tensor memory 与 2-CTA MMA 模式减少共享内存流量与 backward 原子加。B200 BF16 实测：较 cuDNN 9.13 快 **1.3x**、较 Triton 快 **2.7x**，达 **1613 TFLOPs/s（71% 利用率）**；实现完全用 CuTe-DSL（Python 嵌入）完成，编译时间较传统 C++ 模板方案快 **20-30x** 而表达力完整。URL: https://arxiv.org/abs/2603.05451 · https://openreview.net/forum?id=KstQlYR1kN

### 4.2 高带宽闪存（HBF）：MoE 容量墙的存储级答案

- **Beyond Capacity: Scalable MoE LLM Inference via High-Bandwidth Flash with Direct GPU and HBM Paths**（arXiv:2608.14333，2026-08-14）：MoE 权重增长使 HBM 容量/成本承压，HBF 提供更大容量但常规设计让 HBF 权重经 HBM 中转（直连 GPU-HBF 通道闲置）。该工作同时利用**两条独立专家交付路由**：直连路径（HBF→GPU）+ 中继路径（HBF→HBM base die→GPU），整专家分配到两路由并发转移（无副本、无共享中继瓶颈）；early expert determination 提前识别后续专家使 HBF 读延迟与前置计算重叠；不可变专家权重与可变 KV cache 分离管理减少流量干扰。事件驱动 continuous-batching 仿真（实测 GPU 计算延迟校准）：代表工作负载下较"全部经 HBM base die 交付"设计吞吐 **1.94x**、端到端 **1.90x**。URL: https://arxiv.org/abs/2608.14333

- **Potential Applications of HBF in LLM Serving Systems**（arXiv:2608.13127，2026-08-13）：系统视角审视 HBF 作为 HBM 的容量扩展：价值 = 为只读型模型状态对象扩大驻留集——MoE 服务可承载更多专家副本，多模型服务减少模型加载、支持热模型复制；仿真显示收益依赖**保留 HBM 驻留执行路径**、用 HBF 仅扩展权重驻留集（与 4.2 第一条的双路并发互为补充而非竞争）。URL: https://arxiv.org/abs/2608.13127

### 4.3 Pallas：AI-RAN 场景的主动 KV 迁移

- **Pallas: A Proactive KV Cache Migration Framework for LLM Inference in AI-RAN**（arXiv:2608.16477，2026-08-17）：蜂窝切换会把活跃请求与其推理状态分离（用户附着新 gNB，KV 留在源端）。Pallas 在切换前**主动**准备推理状态：触发时把 token 序列切为稳定历史前缀（目标端本地 prefill 重建）+ 演变后缀（源端流式传输 KV 块），切换时两端组装为最新 KV。3 个 LLM × 100-500Mbps 链路（vLLM 原型）：平均服务中断时间（SIT）较目标端恢复方案降 **2.28-89.68x**，平均 token 间延迟（ITL）较源端转发降 16.0%-50.0%。URL: https://arxiv.org/abs/2608.16477

> **分析：为什么 2026 年的内核与存储创新同时指向"注意力"？** FlashAttention-4 与 HBF 双路论文的巧合点在于：**注意力的数据访问模式（KV 的流式重读 + MoE 的权重按路由取用）正在定义新硬件的优化目标**。FA-4 的核心洞察——Blackwell 上 tensor core 与共享内存带宽增长脱钩——意味着"把更多工作搬进 MMA、减少非 matmul 单元参与"成为唯一可行路线，软件模拟指数/条件 softmax 本质是**用算力换带宽**。HBF 双路的本质同样是**用第二条物理通道换带宽**（直连 GPU-HBF 绕过 HBM base die 的共享瓶颈）。两条路线的共同经济学：**带宽（而非算力）是 AI 基础设施的稀缺资源**——这与 08-22 记录的"带宽增速滞后于算力增速"判断一致，且正在从"软件层的通信压缩"（SignMuon/AGoQ）延伸到"硬件层的存储/互联架构"。对超节点产品决策的启示：若 HBF/高带宽存储进入主流 GPU 路线图，MoE 集群的"专家权重分布"（HBM vs HBF vs 远端）将成为新的容量-带宽优化问题，与现有 UALink/CXL 内存池化议题直接衔接。

## 五、去中心化与容错训练新进展

### 5.1 IsoLoCo：模型合并方法进入低通信训练

- **Can Model Merging Improve Aggregation in DiLoCo? / IsoLoCo**（arXiv:2607.03011，2026-07-03）：低通信分布式训练（local SGD / DiLoCo）通过周期性聚合独立训练的本地模型省通信，但随着本地模型数量与本地步数增长，其相对 FLOP-matched 数据并行金标准的性能退化。论文将 local SGD/DiLoCo 的伪梯度聚合步骤与**任务算术式模型合并**（task arithmetic）建立显式类比，系统评估多种 SOTA 合并方法，识别 **Iso-C** 为最有前景者：DiLoCo SGD + Iso-C 聚合不仅超过简单伪梯度平均，甚至超过带 momentum 的 DiLoCo（自身无 momentum）。由此提出 **IsoLoCo**：Iso-C 适配分布式训练 + Nesterov momentum。语言模型预训练多 worker 实验：**worker 数越多 IsoLoCo 相对 DiLoCo 优势越大**，且跨模型规模与内部步数保持。URL: https://arxiv.org/abs/2607.03011

### 5.2 Pipelined Gradient Coding：抗 straggler 的流水线化

- **Pipelined Gradient Coding**（arXiv:2607.20739，2026-07-22，ITW 2026 扩展版）：分布式训练常见 straggler 拖慢全局。传统梯度编码（GC）在多个 worker 间复制数据集分区，用冗余梯度替换 straggler 缺失梯度——但要求每个 worker 每步评估多个分区，可能增加总训练时间。该工作把 GC **流水线化**：梯度评估跨多步分段，每个 worker 每步只评估单个数据集分区；为分数重复（FR）与循环重复（CR）两种代表性放置方案推导收敛保证。云基础设施仿真与实验显示：不仅显著减少训练时间，还**加速收敛**（vs GC 与其他基线）。URL: https://arxiv.org/abs/2607.20739

### 5.3 LLM 与光网络的共生：WAN 训练的传输层使能

- **LLMs and Optical Networks: A Symbiotic Relationship**（arXiv:2606.30278，2026-06-29）：LLM 大规模训练需要地理分布式（geo-distributed）算力，这对光传输提出新要求，关键技术使能包括 **WAN-aware 集合通信库（CCL）算法、ZR+ 可插拔光模块、空芯光纤（Hollow Core Fiber）**；反向地，LLM 也赋能新型自主网络管理。该文把"跨数据中心训练"与"光网络能力"绑定为共生关系——超节点之外的第二层互联（数据中心间）正在成为训练系统的设计变量。URL: https://arxiv.org/abs/2606.30278

> **分析：去中心化训练的"聚合方法"竞争说明了什么？** DiLoCo 家族（DiLoCo → Factored Gossip → IsoLoCo）的演进主线是**同步机制**（频率 → 精度 → 聚合算子），而 IsoLoCo 的独特贡献在于把聚合本身从"简单的参数平均/伪梯度"升级为"经过合并方法学验证的算子"。模型合并社区（task arithmetic、TIES、Iso-C）积累了"如何融合多个独立训练模型"的丰富方法——这些方法本质上是低通信分布式训练的聚合步骤的泛化。其因果链：本地模型数量上升 → 平均聚合的统计效率下降（各模型漂移加大）→ 需要显式处理权重冲突的合并算子 → Iso-C 的"等方向"特性恰好匹配本地 SGD 的伪梯度几何。**工程含义**：如果 IsoLoCo 在大规模得到验证，"多站点各自训练 + 定期合并"的联邦式训练将获得比 DiLoCo 更强的收敛保障，这与 PowerScale（08-22 收录）的层次化同步、FoMoE 的专家联邦化（08-22 收录）共同构成"WAN/低带宽训练"的完整工具箱——对跨机房、跨云的算力调度（用户关注点之一）是直接相关信号。

- **ProfInfer: An eBPF-based Fine-Grained LLM Inference Profiler**（MLSys 2026，OpenReview）：基于 eBPF 的细粒度 LLM 推理剖析器——在 kernel 侧零侵入采集推理性能信号。对集群训练优化的意义在于：RL post-training 中推理（rollout）与训练共享集群，推理侧剖析能力是资源编排的前置条件。URL: https://openreview.net/forum?id=tYHWS7YPof

- **XProf: An Open, Scalable, and Extensible Profiling System for the Modern ML Stack**（MLSys 2026，OpenReview）：面向现代 ML 软件栈（框架-运行时-算子-硬件多层）的开源、可扩展、可扩展的剖析系统。与 08-22 收录的 StageFrontier（0.2% 开销常开信号）互补：XProf 定位"深度剖析平台"，StageFrontier 定位"常开指向性摘要"。URL: https://openreview.net/forum?id=KqRLAdGK6C

### 6.4 MAC-Attention 与 Axon：算子与可移植性

- **MAC-Attention: a Match–Amend–Complete scheme for fast and accurate attention computation**（MLSys 2026，OpenReview）：Match–Amend–Complete 三阶段方案实现快速且准确的注意力计算——匹配缓存/历史计算结果，修正近似，补全缺口，在精度与速度间取新工作点。URL: https://openreview.net/forum?id=b6HBRCejb7

- **Axon: Write Once, Run Everywhere——Shape-Safe and Framework-Agnostic LLM Architectures**（arXiv:2608.19889，2026-08-20）：开源 LLM 生态实际依赖单一平台（PyTorch），若该平台停摆则整个生态承压。Axon 是强类型 DSL（Haskell 风格语法），以语言规范而非特定框架愿景为基础协作，可自动编译到 PyTorch / PyTorch+Triton / JAX / MLX / vLLM 的独立实现。467 次推理基准（135M-32B）：较 Transformers 参考实现中位加速 PyTorch +7%、Triton +12%、JAX +91%、MLX +107%；部署为 vLLM 原生架构（PagedAttention + KV cache）时中位加速 **58%**。URL: https://arxiv.org/abs/2608.19889

> **分析：工具层信号的三点含义。** 第一，**eBPF 化**（ProfInfer）与**标准化 trace**（Chakra）表明 ML 系统可观测性正在从"应用内插桩"走向"内核/标准层"——这与 08-22 CCL-D/StageFrontier 的"轻量常开"路线一致，且更深入系统栈；第二，Axon 的"平台锁定风险"叙事（单一开源框架停摆威胁）在当前国产化语境下有特殊共鸣——若 PyTorch 生态的供应中断风险成为现实考量，"框架无关 DSL"将是从 CUDA 锁定之外的第二层解耦手段，但其实际采用取决于编译后端质量与社区治理；第三，MLSys 2026 的工业-学术混合生态（字节 veScale、AWS KeysAndValues、MLCommons Chakra）表明**集群训练优化已进入"标准制定 + 平台化"阶段**，单点论文创新正被标准化工具吸收——对知识库建设而言，跟踪 MLSys/OSDI 的工业轨比跟踪单篇论文更有杠杆。

## 七、趋势总结与行动建议

### 7.1 四条趋势主线（因果链视角）

1. **国产算力从"跑得通"到"跑得好"**：昇腾 SuperPOD 上 34.22% MFU 证明全栈工程化（并行编排+通信重叠+kernel 优化）可把开源基线提升 2.93x——国产集群的竞争焦点正从单卡算力转向软件栈成熟度，且与"MFU 差距 = 软件缺口"的判断自洽。驱动因素：国产替代刚需 + 开源模型（DeepSeek 系）提供基准工作负载。收敛方向：国产集群的调优知识资产化（配方文档、算子库、通信拓扑适配）。

2. **并行策略"运行时化"**：veScale-FSDP（结构感知分片）、FCP（变长 CP）、DCP（数据驱动配置）、FlowTrain（模块专属并行）共同把并行度从编译期常量变为运行时变量。驱动因素：MoE 块状权重、长上下文序列长度跨度、VLM 异构模块击穿"同构等长"假设。收敛方向：在线重配置 + 结构感知分片成为主流训练框架标配。

3. **KV cache 全栈系统化 + 正确性觉醒**：prefill（FlashPrefill V2）/路由（CacheRoute）/回收（vToken）/恢复（BSR）/压缩（AATC）五子域同时推进，且 Rollback Consistency 首次提出"KV 保留破坏逻辑回滚"的安全语义缺口。驱动因素：长上下文 + agentic/RL 工作负载使 KV 成为集群级稀缺资源。收敛方向：KV 管理与训练/推理调度合并为统一资源平面（与 08-22 的 TideRL/MISA-T 判断一致）。

4. **带宽稀缺驱动硬件-内核协同**：FA-4 用算力换带宽（软件模拟指数）、HBF 双路用第二条物理通道换带宽、Axon 用 DSL 换可移植性——全部指向"带宽是稀缺资源"这一经济学共识。驱动因素：tensor core 增长快于片上/片外带宽。收敛方向：存储层级（HBM/HBF/CXL）与互联层级（UALink/NVLink/WAN-CCL）成为训练优化的硬件主战场。
