## 1. 🏗️ 大规模分布式训练并行策略

### 1.1 HSPMD: 层级异构 SPMD 注释——Hetu v2（重点 ⭐）

- **作者**: Haoyang Li, Fangcheng Fu, Hao Ge 等
- **来源**: arXiv:2504.20490v2 (cs.DC), **OSDI 2026**（本次为接收更新版）
- **核心问题**: SPMD(Single-Program Multiple-Data)范式中，假设对称工作负载划分——这在**空间异构**(混合硬件、故障设备)和**时间异构**(不均匀序列长度)场景下不成立
- **核心创新**: 在 Hetu v2 中提出 **HSPMD**:
  1. **渐进式图特化**(progressive graph specialization): 允许不同设备有不同的执行逻辑
  2. **动态图切换**(dynamic graph switching): 适应时序变化
- **评估场景**: (a) 异构设备、(b) 不稳定设备、(c) 混合长度数据——匹配或超越专门系统
- **意义**: **OSDI 2026 接收意味着异构训练编排的范式级进展**。SPMD 统一抽象本已是现代 DL 训练的标配(FSDP/DeepSpeed 的核心)，HSPMD 在不牺牲编程简洁性的前提下扩展了 SPMD 的表达能力

### 1.2 Syncopate: 融合内核内细粒度计算通信重叠（重点 ⭐⭐）

- **作者**: Xinwei Qiang, Yue Guan, Zhengding Hu, Keren Zhou, Yufei Ding, Adnan Aziz
- **来源**: arXiv:2601.20595v3 (cs.DC), **OSDI 2026**（本次为接收更新版）
- **核心问题**: 现有分布式编译器在流级别粗粒度重叠整个计算 kernel 和通信 kernel——这需要额外 kernel 启动、在 kernel 边界做全局同步、当最慢的 tile 拖长通信 tail 时留下大量空闲
- **核心技术: Syncopate**:
  1. **communication chunk 抽象**: 将通信粒度与 kernel 结构和后端机制解耦
  2. **chunk 级计划**: 可从现有分布式编译器移植、直接由用户编写、或从可复用模板实例化
  3. **源码到源码编译**: 基于 Triton，自动对齐计算与 chunk 可用性
- **关键数据**:
  - 多 GPU 工作负载上平均端到端加速 **1.3×**，最高 **4.7×**
  - 开源
- **意义**: **"融合内核内细粒度重叠"是通信压缩的下一个增长点**。之前的主流思路(CommFuse 等)是在 kernel 级别做 overlap，Syncopate 将粒度进一步下移到 chunk(即 kernel 内部的 tile 级别)。**OSDI 2026 接收**确保了其系统贡献的权威性

### 1.3 FSA: Flash Sparse Attention——NSA 的小 GQA 组适配（重点 ⭐）

- **作者**: Ran Yan, Youhe Jiang, Zhuoming Chen, Haohui Mai, Beidi Chen, Binhang Yuan
- **来源**: arXiv:2508.18224v2 (cs.DC), 本次为更新版
- **核心问题**: NSA(Native Sparse Attention)是 SOTA 的可训练稀疏注意力方案。但其 kernel 实现的循环顺序只在**每个 GQA 组内查询头数较大**时才高效。而**主流 LLM 广泛采用小 GQA 组**(如 Llama-3 等)——这个不匹配严重限制了 NSA 的适用性
- **FSA 方案**: 替代 kernel 实现，使 NSA 能在各种流行 LLM(不同数量的小头 GQA 组)上高效运行
- **关键数据**:
  - kernel 级延迟降低最高 **3.5×**，平均 **1.6×**
  - 端到端训练加速最高 **1.25×**，平均 **1.09×**
  - 推理 prefill 阶段加速最高 **1.36×**，平均 **1.11×**
- **意义**: NSA 已证明 trainable sparse attention 可匹敌 full attention 精度，但 kernel 实现限制其适用面。**FSA 填上了从算法到产品化的最后一步工程鸿沟**。对万卡集群训练来说，sparse attention 的前向/反向加速直接转化为成本节省

## 2. 📡 PD 分离部署

### 2.1 ELDR: 专家局部性感知解码路由——PD 分离 MoE 推断（重点 ⭐⭐🔥）

- **作者**: Sangjin Choi, Sukmin Cho, Yifan Xiong, Ziyue Yang, Youngjin Kwon, Peng Cheng
- **来源**: arXiv:2607.00466 (cs.DC), 提交 2026-07-01（周四新刊）
- **核心问题**: PD 分离 LLM 服务中，每个请求在 prefill 后分配到 decode worker。现有 decode 路由器**只平衡负载**——对 MoE 模型，这只完成了"一半"：负载相等的 worker 可能因 batch 激活的专家集合不同而延迟差异显著（因为每个 decode 步需要加载 batch 激活的所有不同专家的权重）
- **技术创新**:
  1. **专家签名构建**: 从请求的 prefill 专家激活中，构建预测解码时激活专家的签名
  2. **离线空间划分**: Balanced K-means 将签名空间划分为 decode worker 分区
  3. **在线 locality-band 路由**: 将请求发送到签名匹配最佳且负载最低的 worker
  4. **签名缓存**: 与 KV Cache 共索引(KV-block 粒度)，在 prefix caching 下保持签名精确
- **关键数据**:
  - 部署于 vLLM，评估至 **40 GPU** 规模
  - 对三个 MoE 模型和两个工作负载，median TPOT 降低 **5.9-13.9%** vs 最强的四种负载均衡基线
  - 模型输出不变（路由不影响生成逻辑）
- **意义**: **MoE 模型的 PD 分离路由不仅仅是"哪个 worker 不忙"，更要考虑"哪个 worker 的专家缓存最匹配"**。ELDR 的专家签名方法相比于通用 MoE 调度，首次将"专家局部性"引入 PD 分离的 decode 阶段。这与 CrossPool(06-29 跟踪)的跨 worker 专家缓存池化形成互补——CrossPool 让专家权重在各 worker 间共享，ELDR 确保请求被路由到最可能已有其所需专家的 worker

### 2.2 SmoothAgent: 超前上下文工程——为 Agent 多轮推断预计算 KV Cache（重点 ⭐）

- **作者**: Zaifeng Pan, Qianxu Wang, Zhengding Hu, Chang Chen, Yue Guan, Yanbo Zhou, Steven Swanson, Yufei Ding
- **来源**: arXiv:2607.00151 (cs.DC), 提交 2026-06-30（周四新刊）
- **核心问题**: LLM-based Agent 执行多轮工作流时上下文持续增长。Agent 框架依赖上下文工程策略(offloading/reduction/isolation)控制上下文长度。但每次变换都会**错位现有 KV Cache 并触发重新 prefill**，增加 TTFT
- **关键发现**: 上下文变换具有**段可分解性**(segment-decomposable)——前缀变换与未来 tokens 无关。因此，变换可以提前执行
- **核心技术**:
  1. **超前编程模型**: 允许 Agent 框架将上下文变换表达为异步操作
  2. **运行时主动执行变换**: 提前准备转换后的 KV Cache，直接替换无需阻塞
  3. **超前感知调度器**: 在 LLM serving 系统中支持异步请求与延迟关键型工作负载共存
- **关键数据**: TTFT 降低最高 **11.9×**
- **意义**: 虽然面向 Agent 场景而非 PD 分离，但其**"提前准备 KV Cache 以避免重新 prefill"**的思路与 PD 分离中 KV 传输预取直接相关。在 PD 分离架构中，prefill-to-decode 的 KV 传输也可以通过类似"超前准备"机制减少等待时间

## 4. 💾 KV Cache 优化

### 4.1 MosaicKV: 动态二维 KV Cache 压缩——序列 × 通道（重点 ⭐⭐🔥）

- **作者**: Sheng Qiang, Ruiwei Chen, Yinpeng Wu, Jinyu Gu, Zhichao Hua, Yubin Xia, Binyu Zang, Haibo Chen
- **来源**: arXiv:2607.00760 (cs.LG, cs.DC), 提交 2026-07-01（周四新刊）
- **核心问题**: 现有 KV Cache 压缩要么只针对序列维度(top-k 稀疏)，要么只针对通道维度(量化/低秩)——单一维度剩余空间有限。同时压缩两维本可释放更大空间，但直接应用会带来显著精度损失
- **核心技术: MosaicKV**:
  1. **动态二维压缩**: 利用 KV Cache 内元素的非均匀重要性分布——为每个 KV 向量找出重要元素，在 KV cache segment 粒度选择压缩策略
  2. **压缩 KV Cache 管理**: 利用欠利用的 GPU 和 CPU 资源维护压缩 KV Cache 并加速注意力计算(解决细粒度稀疏和压缩管理开销问题)
- **关键数据**（在 H800 GPU 上评估）:
  - 注意力计算最高 **16×** 加速
  - 解码延迟降低 **4.8×**
  - 吞吐提升 **7.3×**
  - 内存减少 **3×**
  - 在 LongBench 和 RULER 上平均精度损失仅 **1.76%**
- **意义**: **"同时压两维"是 KV Cache 优化的下一个范式**。之前 07-01 跟踪的 SeKV 做的是"序列维的语义分组+通道维的 SVD 低秩"，MosaicKV 做的是"序列维动态稀疏+通道维量化"的组合。两篇工作同一天出现，标志着领域共识正在形成：**单一维度的 KV Cache 压缩已触及天花板，二维联合压缩才是下一阶段**

### 4.2 GSRQ: 亚 1-bit KV Cache 量化—— Gain-Shape Residual Quantization（重点 ⭐⭐🔥）

- **作者**: Soosung Kim, Minjae Park, Eui-Young Chung, Jaeyong Chung
- **来源**: arXiv:2607.01065 (cs.LG), **已接收 ICML 2026**（周四新刊）
- **核心问题**: Vector Quantization(VQ)尤其是 Residual Quantization(RQ)是推动 KV Cache 存储进入**亚 1-bit 领域**的 promising 方法。但大多数 VQ 方法仍使用标准 Euclidean **ℓ₂ K-means** 作为核心码本学习基元
- **关键发现——质心收缩问题**: Euclidean centroid averaging 会引入**质心收缩**(centroid shrinkage)，削弱 ℓ₂ 失真中的角度对齐项，使得方向保真度更难维持
- **核心技术: GSRQ**:
  1. **Gain-Shape K-means (GSKM)**: 替代 K-means 的 drop-in replacement，改善方向保真度，同时匹敌甚至在某些场景下改善 ℓ₂ 失真
  2. **GSRQ**: 将 GSKM 的加权扩展融入 RQ 流水线
- **关键数据**（LLaMA-3-8B）:
  - @1-bit: LongBench 平均准确率从 **11.34→33.54**，提升 **22.20 个百分点** vs VQLLM
  - 跨多个比特率显著优于强 KV Cache 量化基线
- **意义**: **亚 1-bit KV Cache 达到可用的关键突破**。之前 KV Cache 量化多在 2-4 bit 高质量、1-bit 可行性边缘徘徊。GSRQ 让 1-bit 量化从"几乎不可用"(11.34)跨越到"有实用价值"(33.54)，且被 **ICML 2026 接收**。这与 MosaicKV(4.1)形成路线对比：MosaicKV 走的是"稀疏+量化"二维组合，GSRQ 走的是"更好的量化基元"路线

### 4.3 ISPA: 实例特定参数吸收——将 KV Cache 蒸馏进模型权重（ECCV 2026）

- **来源**: arXiv:2607.00712 (cs.CV), **ECCV 2026**
- **核心**: 将一部分层从全注意力(F-Layer)切换到局部注意力(L-Layer)，将历史上下文"吸收"进模型权重中——通过闭式最小二乘计算实例特定的权重调制来补偿缺失的历史
- **关键数据**: 可移除高达 **50%** 的 KV Cache，视觉质量近无损
- **评价**: 针对视频生成的 KV Cache 压缩。虽不是 LLM 推理场景，但其**"将 KV Cache 吸收进权重"**的思想与 06-29 跟踪的 KernelFlume(attention 节点无权重)形成了有趣的对称——一边是将注意力节点拆为独立弹性单元，一边是将注意力历史融入权重
