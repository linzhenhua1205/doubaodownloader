## ⭐ Speculative Decoding

### 1. D-Cut: Adaptive Verification Depth Pruning for Batched SD
- **arXiv**: [2607.14647](https://arxiv.org/abs/2607.14647) (cs.CL, 2026-07-16)
- **问题**: 高并发下长 draft 浪费大量 rejected tokens 的验证开销，可能比自回归更慢
- **方法**: 跨请求联合选择 draft tokens，集中验证预算到高接受概率 tokens；运行时成本模型自适应裁剪深度
- **关键指标**: 高并发下 **1.26×→1.65×** 加速提升；MoE模型 **3.0×** vs 自回归
- **亮点**: 首次发现 acceptance lengths 在并发请求间变化显著，需跨请求修剪

### 2. EcoSpec: Cost-Aware Speculative Decoding for MoE
- **arXiv**: [2607.12696](https://arxiv.org/abs/2607.12696) (cs.CL, 2026-07-14)
- **问题**: 置信度驱动 SD 引入 **expert scattering**——高概率 draft tokens 路由到 disjoint experts，增加 expert-weight 内存流量
- **方法**: 在 draft-tree 选择中纳入边际 expert 激活成本预测；轻量 expert predictor + 动态 expert buffer
- **关键指标**: DeepSeek-V3.1 671B **1.62×** 加速；Qwen3-235B-A22B / GPT-OSS-120B 验证
- **亮点**: 首次揭示 MoE 推理中 SD 的 expert scattering 问题，成本感知选路

### 3. Progressive Tree Drafting (PTD)
- **arXiv**: [2607.10661](https://arxiv.org/abs/2607.10661) (cs.CL, 2026-07-12)
- **方法**: 渐进式树结构 + 分步剪枝，单次前向探索多条语义路径；无需训练、模型无关
- **关键指标**: **2×** 解码加速（多个 benchmark），训练-free

### 4. DSpark: Confidence-Scheduled SD with Semi-Autoregressive Drafting
- **arXiv**: [2607.05147](https://arxiv.org/abs/2607.05147) (cs.AI/cs.CL, 2026-07-06)
- **方法**: 半自回归 draft 架构（并行主干+轻量顺序模块）+ 置信度调度验证
- **关键指标**: DeepSeek-V4 生产系统: per-user 生成速度 **60-85%** 提升；shift Pareto frontier
- **亮点**: 已部署于 DeepSeek-V4 在线流量下的生产级方案

### 5. VIA-SD: Intra-Model Routing for SD *(ICML 2026)*
- **arXiv**: [2606.12243](https://arxiv.org/abs/2606.12243) (cs.CL, ICML 2026)
- **方法**: 多层级验证——直接接受 → slim-verifier 再生 → 完整模型验证
- **关键指标**: 拒绝率 **↓0.10-0.22**；**10-20%** 加速 vs 强 SD 基线；**2.5-3×** vs 非 drafting

### 6. JetSpec: Breaking Scaling Ceiling of SD *(ICML 2026)*
- **arXiv**: [2606.18394](https://arxiv.org/abs/2606.18394) (cs.CL, 2026-06-16)
- **方法**: 因果并行 draft head（融合目标模型隐藏状态），克服双向 block-diffusion 的 branch 不一致问题
- **关键指标**: MATH-500 **9.64×** 加速；开放域对话 **4.58×** (H100)

### 7. Dustin: Draft-Augmented Sparse Verification for Long-Context SD *(ICML 2026)*
- **arXiv**: [2606.24957](https://arxiv.org/abs/2606.24957) (cs.CL, ICML 2026)
- **方法**: 利用 draft 模型的 lookahead 信号 + 目标模型历史 attention，识别关键 tokens；稀疏估计最小 attention head 子集
- **关键指标**: 32k 序列长度: self-attention **27.85×** 加速；E2E 解码 **9.17×** 加速

## ⭐ KV Cache 优化

### 8. KVpop: Predictive Online KV Cache Pruning
- **arXiv**: [2607.05061](https://arxiv.org/abs/2607.05061) (cs.LG, 2026-07-06)
- **方法**: 学习固定预算 KV eviction 策略，以 novel future-attention target 监督 keep/drop 决策；延迟记忆 scorer（推迟几步评分利用近未来上下文）
- **关键指标**: Qwen3-4B: 75% 压缩 **98%** full-attention 性能；88% 压缩 **97%**
- **亮点**: 首个以未来 attention 信号监督 eviction 的方法

### 9. IntentKV: Cross-Turn Intent-Aware KV Pruning for Agents
- **arXiv**: [2606.09916](https://arxiv.org/abs/2606.09916) (cs.LG, 2026-06-06)
- **方法**: session 级 QueryMemory 记录跨-turn 意图；memory-attention 规则+零初始化残差头交叉注意力
- **关键指标**: 8k KV 预算下峰值 request tokens **↓23.9%**(Qwen3-8B), **↓30.7%**(Qwen2.5-14B)；最差 KV 读取 **↓92.6%** (411M→31M)
- **亮点**: 保持 prefix cache 兼容性（slot-map 重定向 eviction）

## ⭐ PD 分离部署

### 10. AMPD: Efficient Multi-round LLM Inference over PD Disaggregation
- **arXiv**: [2602.14516](https://arxiv.org/abs/2602.14516) (cs.DC, 2026-02-16)
- **问题**: 多轮推理在 PD 分离下出现 interleaved prefill-decode 模式，增量 prefill 和资源分配子优化
- **方法**: 自适应确定 prefill workloads 在哪里执行以及如何调度；规划算法推导最优资源分配和并行策略
- **关键指标**: SLO attainment **显著提升** vs SOTA 基线

### 11. Lynx: Progressive Speculative Quantization for KV Transfer
- **arXiv**: [2607.01831](https://arxiv.org/abs/2607.01831) (cs.DC, 2026-07-02)
- **问题**: 长上下文 PD 分离中 KV cache 需完整到达后才能解码
- **方法**: 打破"KV cache 是不可分割整体"假设——分 Anchor（高比特）+ Residual（低精度）分裂传输；解码在 Anchor 收到后猜测性开始
- **关键指标**: TTFT **↑1.43×** vs 8-bit KV 量化；匹配 BF16 精度；accuracy **↑5.1%** vs SOTA
- **亮点**: 首次实现"渐进推理"——解码在 KV 完整到达前启动

## ⭐ Checkpoint 容错

### 12. TierCheck: Tiered Checkpointing for LLM Training
- **arXiv**: [2605.17821](https://arxiv.org/abs/2605.17821) (cs.DC, 2026-05-18)
- **方法**: 三 tier（本地 peer 内存差分 checkpoint → 异步远程持久化），按故障异质性对齐存储层
- **关键指标**: 40B 模型: E2E checkpoint 时间 **<10s**；支持高频 checkpointing
- **亮点**: 严格全局一致性而不停滞训练

### 13. MoEvement: Sparse Checkpointing for Fast & Reliable MoE Training *(NSDI'26)*
- **arXiv**: [2412.15411](https://arxiv.org/abs/2412.15411) (cs.DC, NSDI'26)
- **方法**: 稀疏增量 snapshot expert 子集 → 稀疏到稠密转换；pipeline stage 边界上行日志实现局部恢复
- **关键指标**: checkpoint overhead **↓4×**；recovery overhead **↓31×**；ETTR ≥0.94 (MTBF 低至10min)；**8×** 整体训练加速
- **亮点**: 64 experts 验证，不牺牲同步训练语义

### 14. LLMTailor: Layer-wise Selective Checkpointing
- **arXiv**: [2602.22158](https://arxiv.org/abs/2602.22158) (cs.DC, PDSW'25, 2026-02-25)
- **方法**: 基于层更新非均匀性，选择性 checkpoint 更新显著的层；checkpoint-merging 框架过滤组装各层
- **关键指标**: Llama3.1-8B checkpoint 大小 **4.3×** 缩小；Qwen2.5-7B checkpoint 时间 **2.8×** 加速

## ⭐ 分布式训练并行策略

### 15. LongStraw: Long-Context RL Beyond 2M Tokens
- **arXiv**: [2607.14952](https://arxiv.org/abs/2607.14952) (cs.LG, 2026-07-17) cross-list cs.DC
- **方法**: 架构感知百万 token RL 后训练栈：共享 prompt 不记录 autograd → 仅保留模型状态 → 短 response branches 逐条重放
- **关键指标**: 8×H20: 2.1M 位置 grouped Qwen scoring+backward；32×H20: GLM-5.2 全78层 2.1M 验证
- **亮点**: 固定 GPU 预算下突破长 context RL 训练制约

### 16. Bebop: MTP in RL Training - Breaking Entropy Bounds
- **arXiv**: [2606.12370](https://arxiv.org/abs/2606.12370) (cs.LG, 2026-06-10)
- **问题**: MTP acceptance rate 在 RL 训练中因 entropy 上升而显著退化
- **方法**: 端到端 TV loss 直接优化多步拒绝采样接受率；证明 probabilistic rejection sampling 优于 greedy
- **关键指标**: 接受率达 **95%**；额外吞吐 **↑25%**；E2E 加速 **1.8×** (Qwen3.5/3.6/3.7)
- **亮点**: 揭示 entropy-bound 负线性关系，pre-RL 训练 MTP 持效果一致

## ⭐ GPU 可靠性与运维

### 17. HeaRank: GPU Failure Ranking *(KDD 2026)*
- **arXiv**: [2607.15115](https://arxiv.org/abs/2607.15115) (cs.DC, KDD 2026, 2026-07-16)
- **问题**: GPU 故障时间点预测因强随机性+低信噪比而本质上不可行
- **方法**: Learning-to-Rank 框架，基于稳定历史故障模式计算全局风险排名；从"预测时间"转向"排名风险"
- **关键指标**: AUC **0.83**；Top 5% 节点捕获 **64%** 故障（vs 生产系统 21%）
- **亮点**: 范式转变——绝对时间预测→相对风险排序

### 18. LEO: GPU Stall Root Cause Analysis *(SC'26)*
- **arXiv**: [2604.20032](https://arxiv.org/abs/2604.20032) (cs.DC, SC'26)
- **方法**: 跨厂商(NVIDIA/AMD/Intel) GPU stall 根因分析；从 stall 指令向后切片，考虑寄存器依赖和厂商特有同步机制
- **关键指标**: 21 workloads 三平台: 几何平均 **1.73-1.82×** 加速
- **亮点**: 相同 kernel 在不同 GPU 架构上可能需要不同优化

## 📌 本期核心趋势

1. **MoE SD 进入"成本感知"时代**: EcoSpec 揭示 expert scattering 问题 → D-Cut 扩展到跨请求联合修剪 → DSpark 在生产系统验证。SD 不再仅关注 acceptance rate，还关注验证阶段的内存/计算成本

2. **KV Cache → 预测性+面向意图**: KVpop (future-attention target) + IntentKV (cross-turn 意图) — eviction 从"当前注意力"转向"预测未来重要性"

3. **PD 分离 → 渐进/推测推理**: Lynx 打破"KV cache 必须完整到达"铁律，解码可在传输完成前启动，对长上下文场景影响深远

4. **容错体系三层分化加速**: TierCheck(三层tier/10s) + MoEvement(sparse expert/4×↓) + LLMTailor(层选/4.3×↓) — checkpoint 从"大而全"走向"差异+分层+选择性"

5. **GPU 运维范式转变**: HeaRank (KDD'26) 证明精确预测故障时间理论上不可行 → 转向相对风险排名，为万卡集群调度提供新工具
