## ⭐ Speculative Decoding

### 1. AdaFlash: 自适应推测解码 via On-Policy蒸馏扩散Drafter
- **arXiv**: 2607.19223 (2026-07-21)  
- **核心**: 在 DFlash 扩散 drafter 基础上引入 **on-policy 蒸馏** — 用 target model 的验证结果在线微调 drafter，使 draft 分布更贴近 target。  
- **指标**: 在 SpecBench 上 **平均1.37× walltime加速**，相比 DFlash 的1.22×有明显提升。  
- **意义**: 将"验证反馈"闭环引入扩散式 drafting，补齐 DFlash 类方法的训练-推理分布漂移短板。

### 2. D-cut: 批量推测解码的自适应验证深度剪枝
- **arXiv**: 2607.14647 (2026-07-16)  
- **核心**: 高并发场景下长 draft 的拒绝 token 浪费计算。D-cut 根据 **批量接受率动态裁剪验证深度**：接受率高 → 保留深树；接受率低 → 提前截断。  
- **指标**: 批量场景下 **1.26× → 1.65× 加速比提升**（相对固定深度基线）。  
- **意义**: 首个面向批量推测解码的自适应验证深度策略，直接适配 vLLM 等 Serving 框架。

### 3. SpecLA: 线性注意力模型的推测解码
- **arXiv**: 2607.16673 (2026-07-18)  
- **核心**: 线性注意力模型（Mamba、RWKV等）的 KV cache 被替代为变长循环状态。SpecLA 设计了 **状态感知的验证过程**，使 drafter 和 target 的状态传递兼容推测解码框架。  
- **指标**: 在 Mamba-2.8B 目标上 **1.5-2.0× 加速**。  
- **意义**: 首个将推测解码推广到非 Transformer 线性注意力架构的工作。

### 4. ADSD: 推测解码的对抗性攻击 — Acceptance Collapse
- **arXiv**: 2607.21804 (2026-07-23) | 🔴 Security  
- **核心**: 设计对抗性 prompt 使 target-drafter 的 **接受率系统性崩溃**：通过微小输入扰动诱导 drafter 在关键 token 上偏离 target，使验证阶段批量拒绝。  
- **指标**: **接受率从~90%降至<10%**（特定攻击prompt下），端到端延迟退化 3-5×。  
- **意义**: 首次揭示推测解码的 **安全攻击面** — 后续所有 SD 系统需追加对抗鲁棒性设计。

### 5. TIGER: 多模态推测解码
- **arXiv**: 2607.11131 (2026-07-13)  
- **核心**: 视觉-语言 VLM 场景中，drafter 在视觉关键区域容易偏离 target。TIGER 引入 **文本条件视觉门控路由 + 接受率对齐损失**。  
- **指标**: LLaVA-1.5-7B 上 **1.32× 加速**，比基线 multimodal SD 稳定。  
- **意义**: VLM 场景的 SD 优化不再依赖纯文本模式。

### 6. Lossless but Not Free: 消费级硬件上的SD实证分析
- **arXiv**: 2607.17283 (2026-07-19)  
- **核心**: 在消费级 GPU（RTX 4090/3090）上实证分析推测解码的真实成本：**draft+verify 双模型的内存竞争** 导致在内存带宽受限的消费级卡上加速比仅为理论值的 40-60%。  
- **关键结论**: SD 在高端 A100/H100 上优势显著，但在消费级硬件上，负载增加带来的 batch size 减少反而可能拖慢 1.2-1.5×。揭示了 SD "无损失但不是免费的" 本质。

### 7. DominoTree: 条件树结构 Drafting
- **arXiv**: 2607.08642 (2026-07-09)  
- **核心**: 结合 block-diffusion 的并行性 与 树搜索的结构保真度 — 先做 position-wise marginal 采样生成候选块，再用 domino 条件概率表剪枝为树结构，平衡覆盖率与接受率。  
- **指标**: 比 DFlash 提升 **5-10% 接受率**，略快于 DDTree。

### 8. Unlocking Parallelism via Progressive Tree Drafting
- **arXiv**: 2607.10661 (2026-07-12)  
- **核心**: 渐进式树扩张 — drafter 不一次性固定树结构，而是 **逐层扩展验证通过的路径**，利用已验证的 token 作为下一层 draft 的条件。无需额外训练。  
- **指标**: 约 **1.4× 加速**（LLaMA-7B, 无额外 drafter 训练）。  
- **特点**: 无训练开销，适合快速部署。

## ⭐ KV Cache优化

### 1. VarRate: 无训练可变速率KV压缩
- **arXiv**: 2607.15498 (2026-07-16)  
- **核心**: 解决 token-selection 方法（SnapKV/Ada-KV）一旦驱逐不可恢复 和 quantization 方法固定比特率的矛盾。VarRate 设计 **可变保留率 × 可变量化位宽** 联合调度 — 每层自适应选择最佳压缩配比。  
- **指标**: 长上下文（128K）下 **比单纯量化或驱逐方法节省 40-50% 显存**，困惑度退化 <1%。  
- **意义**: 将 "驱逐 vs 量化" 两派统一到可变配比框架。

### 2. MosaicKV: 动态二维KV Cache压缩
- **arXiv**: 2607.00760 (2026-07-01)  
- **核心**: 将 KV cache 分为 **"高保真区域"（最近+最相关tokens）和"低保真区域"（历史+低分 tokens）**，前者保留高精度，后者采用强压缩（低比特量化 + 高频裁剪）。  
- **指标**: 64K 上下文下相较 H2O 降低 **60% 显存**，吞吐量提升 **2.1×**。  
- **方法**: 动态区域划分基于滑动窗口注意力分布统计。

### 3. MemDecay: 区域感知 KV Eviction for LLM Agents
- **arXiv**: 2607.10582 (2026-07-12)  
- **核心**: LLM Agent 的上下文由指令、工具输出、中间推理等多区域组成，传统逐 token 驱逐策略不分区域。MemDecay 按 **区域赋权重**：指令/工具结果高保留，中间推理流低保留。  
- **指标**: Agent 任务（WebShop/ALFWorld）上 **保留 75% 性能下压缩 6× 显存**。  
- **意义**: 首个针对 Agent 场景的细粒度 KV 管理方案。

### 4. Codec-Gauge: 学习压缩友好通道变换
- **arXiv**: 2607.20538 (2026-07-10)  
- **核心**: 在 K/V 向量进入压缩器前插入一个小型 **正交通道变换层**（post-training learned），将信息密度重新分布到主成分上，使后端量化/压缩更高效。  
- **指标**: 在主流压缩方案（KIVI/Atom）上额外节省 **5-10% KV 显存** 而不增加推理延迟。  
- **意义**: 压缩器的 "前端预处理" — 与现有压缩方法正交可叠加。

### 5. Coverage-Driven KV Cache Eviction
- **arXiv**: 2606.29563 (2026-06-28)  
- **核心**: 提出 **覆盖率指标** — 衡量当前缓存窗口中 token 对后续注意力查询的覆盖能力，优于传统的 attention score 排序。  
- **指标**: 在 LongBench 上 **比 SnapKV 提升 3-5% 准确率**，相同压缩比。

### 6. How Query Visibility Changes KV-Cache Compression Rankings
- **arXiv**: 2607.11942 (2026-07-11) | 🔍 Audit  
- **核心**: 审计发现：大部分 KV 压缩方法在 **query-aware 场景下评估**（查询已附加到上下文后压缩），但实际部署中 KV cache 应跨多查询复用（query-blind）。当切换为 query-blind 评估时，**方法排名剧烈变化** — 有些"最佳"方法退化到随机基线。  
- **结论**: **当前 KV 压缩评估范式存在系统性偏差**，推荐 query-blind 标准化评估协议。

### 7. The Risk of KV Cache Compression
- **arXiv**: 2607.01520 (2026-07-01) | 🔴 理论  
- **核心**: 从信息论角度证明，**任何有损 KV 压缩都会引入注意力分布的不可逆偏差** — 这种偏差在长链推理任务中会被积累放大。  
- **理论贡献**: 给出压缩比 vs 下游任务准确率的理论下界。  
- **警示**: 对依赖 KV 压缩的 Serving 系统，需在压缩比和推理可靠性间做权衡设计。

### 8. Survey: System-Aware KV Cache Optimization
- **arXiv**: 2607.08057 (2026-07-09)  
- **范围**: 系统层面 KV 基础设施综述（sKis），覆盖：内存管理（vLLM PagedAttention/SGLang）、缓存复用（前缀缓存/跨请求共享）、近存储计算（CXL-SSD KV offload）、压缩/量化集成。  
- **价值**: 全栈分类体系，含 80+ 引用，可作为 KV 优化领域的系统级入门图谱。

## ⭐ 分布式训练与并行策略

### 1. LAGA: MLA序列并行的通信效率优化
- **arXiv**: 2607.17644 (2026-07-20)  
- **背景**: DeepSeek 的 Multi-head Latent Attention (MLA) 在 Megatron-Core 中有两种实现：**explicit form**（全维度通信）和 **absorbed form**（只通信压缩潜变量）。但 absorbed form 在训练阶段被 assert 禁止（`assert not (self.training and self.cache_mla_latents)`）。  
- **问题**: 禁止的吸收式 MLA 虽然在序列并行中通信量削减 **40-60%**（压缩维度 vs 全维度），但被锁在推理路径中。  
- **贡献**: LAGA（**L**atent **A**bsorbed **G**radient **A**llreduce） — 设计了一套兼容训练梯度的吸收式 MLA 序列并行方案：
  - 前向使用压缩潜变量通信（同推理）
  - 反向用重新计算的中间张量做 Allreduce  
- **指标**: 通信量较 explicit 方案减少 **45%**，端到端训练加速 **1.3×**（128 GPU 规模）。  
- **意义**: 修复 Megatron-Core 中 MLA 训练 ≈ 推理分离带来的性能鸿沟。

### 2. SiFAR: 同步无关的 All-Reduce 用于低延迟推理
- **arXiv**: 2607.08973 (2026-07-09)  
- **核心**: 推理阶段的 tensor parallelism all-reduce 需要全同步等待。SiFAR 设计 **异步 partial all-reduce** — 每个 GPU 完成部分 reduce 后即可开始后续计算，最终结果通过延迟保证机制聚合。  
- **指标**: tensor parallelism 解码延迟降低 **15-25%**，不影响输出质量。  
- **适用场景**: 推理模型/reasoning model 的交互式部署。  
- **代价**: 增加约 5% 的峰值通信带宽（非同步带来的缓冲区冗余）。

## 📌 本期核心趋势

1. **SD 的"工程化提升"成为主线** — 从 DFlash(扩散) → AdaFlash(on-policy蒸馏) → D-cut(批量自适应剪枝) → SpecLA(线性注意力)，SD 从学术理论走向框架级工程适配
2. **SD 安全首次被关注** — ADSD (Acceptance Collapse) 揭示对抗攻击可导致接受率从 90%→<10%，所有 SD 系统需追加鲁棒性审计
3. **KV 压缩评估范式面临颠覆** — Query Visibility Audit (2607.11942) 揭露 query-aware vs query-blind 评估下的排名反转，以及 Risk paper (2607.01520) 给出有损压缩的理论下界 — 压缩复用方案的可靠性仍是"信任但要验证"
4. **MLA 训练的通信瓶颈被打破** — LAGA 以吸收格式兼容训练/推理梯度，在 MLA 广泛采用的背景下（DeepSeek-V3/V4），这是万卡级 MLA 训练的关键工程突破
5. **二维KV压缩成为新共识** — MosaicKV (高/低保真区域)、VarRate (可变保留率+可变量化)、MemDecay (Agent区域感知) 三篇并进，均采用"分层差异化"思路而不再是全局一刀切
