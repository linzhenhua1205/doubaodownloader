## ⭐ 工业级推理引擎

### 1. RTP-LLM: Alibaba 生产级推理引擎
- **arXiv**: [2605.29639](https://arxiv.org/abs/2605.29639) (cs.OS, 2026-05-28)
- **背景**: 阿里集团内部引擎，服务 **100M+** 用户，覆盖 8B-235B 参数模型
- **架构亮点**:
  - **PD Disaggregation**: 解耦 compute-bound prefill / memory-bound decode
  - **多级分层 KV Cache**: 层级化缓存管理 + 高效 cache reuse
  - **模块化 SD**: 支持多种 SD 算法，运行时自适应
  - **自适应 KV 量化**: 分精度段适配
- **关键指标** (vs vLLM & SGLang):
  - 模型加载: **4.7-6.3×** 加速 (file-order-driven I/O + 并行 I/O-通信重叠)
  - TTFT P95: **↓35-37%**；cache reuse **↑215%**
  - SD 吞吐: **1.12-2.48×**；多模态推理: **1.86-2.52×**
  - 量化推理: batch latency **↓35-40%**，TTFT **1.9-3.0×**
- **工业价值**: 生产验证的完整推理栈，多级并行 + 模块化 SD + 分层 KV 的设计思路可作为万卡推理引擎参考

### 2. xLLM: JD 企业级推理框架
- **arXiv**: [2510.14686](https://arxiv.org/abs/2510.14686) (cs.DC, 2025-10-16 v1, 2026-03-03 updated)
- **创新**: 首创 **EPD (Encode-Prefill-Decode)** 三层分离——针对多模态输入在 PD 前增加独立的 Encode 阶段；全局 KV Cache 管理 + 分布式容错
- **关键指标**: Qwen 系列: **1.7×** vs MindIE, **2.2×** vs vLLM-Ascend；DeepSeek 系列: **1.7×** vs MindIE
- **亮点**: 协同在线/离线任务弹性调度，workload-adaptive 动态 PD 分离策略

## ⭐ Lossy → Lossless KV 压缩推理

### 3. VeriCache: Lossy KV Cache → Lossless 推理
- **arXiv**: [2605.17613](https://arxiv.org/abs/2605.17613) (cs.AR, 2026-05-17)
- **核心洞察**: 几乎所有 KV 压缩（token dropping / quantization）都是 lossy 的——短输出精度可接受，但长输出 diverges 越来越严重，导致 code generation / tool calling 灾难性失败
- **方法**: 用压缩 KV cache draft tokens → 用 **full KV cache** 做 parallel verification。**关键优化**: compressed-KV decoding (HBM-bound) 与 full-KV swap (PCIe/network-bound) 可并行化，因为两者绑定的瓶颈资源不同
- **关键指标**: **4×** 吞吐量（高于 full-KV 推理），输出与 full-KV **bit-identical**（lossless）
- **兼容性**: 支持 token-dropping + quantization 多种压缩方法，兼容传统 SD
- **亮点**: 从"KV压缩精度可接受"→"必须保证输出等价"的范式提升，对生产环境 KV cache 管理至关重要

### 4. LiteCache: GPU-Centric KVCache 子系统
- **arXiv**: [2511.14510](https://arxiv.org/abs/2511.14510) (cs.LG, 2025-11-18 v1, 2026-03-27 updated)
- **核心洞察**: 同一 attention head 内的相邻查询呈现**强方向相似性**，检索的 top-k KV 高度重叠 → 可 head 粒度重用 KV
- **方法**: QSAC (Query Similarity-Aware Cache) head 粒度缓存算法 + GPU-centric 同步控制器 + 推测性稀疏预取
- **关键指标**: 解码吞吐 **10.7-224.2%** 提升 (H100 & A40)；支持 **1M+** 序列长度
- **亮点**: CPU 开销极小，完全兼容 CUDA Graph 的 bulk execution 模式

## ⭐ Speculative Decoding 进展

### 5. Cassandra: 硬件-SD 协同设计 *(ISCA 2026)*
- **arXiv**: [2605.26558](https://arxiv.org/abs/2605.26558) (cs.AR, ISCA 2026, 2026-05-26)
- **方法**: algorithm-hardware co-designed **self-speculative decoding**。细粒度数据选择（优化剪枝+尾数截断）构建 training-free draft 模型 + 轻量 encoder-decoder 硬件模块（兼容商用 GPU/NPU）
- **关键指标**: **2.41×** vs BF16 基线；Llama 3 8B (RTX 4090): **1.81×** more tokens vs Eagle-3
- **工业价值**: 首个针对 self-SD 的 algorithm-hardware co-design，在消费级 GPU 上验证

### 6. Vegas: 验证引导的稀疏注意力 *(ICML 2026)*
- **arXiv**: [2602.07223](https://arxiv.org/abs/2602.07223) (cs.LG, ICML 2026, 2026-02-06)
- **核心洞察**: KV selection 的 criticality 已在 verification 过程中被**隐式计算**——无需单独的 KV selection 步骤
- **方法**: 将 verification 中计算的 attention scores 作为后续 drafting 的 sparse attention mask，实现 zero-cost KV selection
- **关键指标**: **1.25-2.81×** vs vLLM；**1.15-1.29×** vs SOTA 稀疏 self-SD
- **亮点**: 零开销复用 verification 的注意力分数做 drafting，优雅地闭环了"选→猜→验"流程

### 7. WhiFlash: 跨范式 SD (Autoregressive + Diffusion)
- **arXiv**: [2606.07710](https://arxiv.org/abs/2606.07710) (cs.LG, 2026-06-05)
- **核心发现**: 同序列内 drafting accuracy 在不同位置剧烈波动，静态单一范式有很大浪费
- **方法**: 首个跨范式 SD——token 级控制器在 autoregressive draft 和 diffusion parallel draft 之间**逐 token 切换**；Lazy Catch-up + KV-only Prefill 降低切换开销至 <7% per-round
- **关键指标**: **69.6%** vs EAGLE-3；**37.3%** vs DFlash
- **亮点**: 标志性工作——证明单序列内不同位置适合不同 drafting 范式，统一 controller 极具前瞻性

### 8. Nightjar: 自适应性 SD 开关
- **arXiv**: [2512.22420](https://arxiv.org/abs/2512.22420) (cs.DC, 2025-12-26)
- **核心洞察**: SD 在低负载时提升吞吐，但在高负载 compute-bound 环境反而因验证开销伤害性能
- **方法**: MAB 规划器动态选择 optimal speculative length → 适时**完全禁用 SD** 并 offload draft 模型到 CPU，释放 KV cache 空间
- **关键指标**: **14.76%** 更高吞吐；**20.18%** 更低延迟 vs 固定 SD
- **亮点**: 首次量化 SD 重启成本，提出"不一定总用 SD"的实用调度

### 9. SSV: 稀疏 Speculative Verification
- **arXiv**: [2605.19893](https://arxiv.org/abs/2605.19893) (cs.OS, 2026-05-19)
- **问题**: 动态稀疏注意力与 SD 不兼容——speculative verification 依赖跨查询共性，而稀疏注意力分配 query 特定布局限制 KV-block 重用
- **方法**: Overlap-aware grouped-query 执行 + refresh/reuse NSA 核融合 + profile-guided prompt-adaptive 编排
- **关键指标**: **3.49×** 端到端吞吐；**6.86×** 核加速(稀疏 speculative verification)
- **亮点**: 首次解决动态稀疏注意力与 SD 的结构性不兼容问题

## ⭐ 多 Agent 推理优化

### 10. Stateful Inference: 多 Agent Tool Calling 的持久化 KV
- **arXiv**: [2605.26289](https://arxiv.org/abs/2605.26289) (cs.LG, 2026-05-25)
- **问题**: 多 Agent tool calling 中每轮工具调用重新处理整个对话（85-95% prompt 未变）
- **方法**: **持久化 KV cache** 跨 turn 存活，仅增量吸收新 tokens；radix prefix cache 扩展至多 Agent 交织流量 + prompt-lookup SD
- **关键指标**: **2.1×** per-turn (6-turn)；**4.2×** median turn (35-turn)；E2E wall time **减半**
- **亮点**: 将每轮 O(n_t) 降为 O(Δ_t)，多 Agent 场景下效果显著

## ⭐ RL 训练优化

### 11. BPO: Branching Policy Optimization *(WAIC 2026)*
- **arXiv**: [2607.14171](https://arxiv.org/abs/2607.14171) (cs.LG, WAIC 2026, 2026-07-17)
- **核心洞察**: Agent sandbox 是 deterministic + snapshottable + resumable 的——这使 rollout 从 N 独立树 → 单树 N 叶，共享前缀可降低方差
- **方法**: 在 backbone 的高熵决策点自适应 snapshot → fork K 个替代动作 → 从 sibling returns 计算 per-step advantages
- **关键指标**: WebShop/ALFWorld/SWE-bench: **3.6-6.1** 绝对点提升 vs GRPO/RLOO；梯度方差**减半**；**38%** 更少的 policy update
- **亮点**: 对 RL post-training 的 rollout 拓扑提出根本性改变

## ⭐ 推理系统安全

### 12. GRIEF: LLM Serving 系统 Fuzzing
- **arXiv**: [2605.11202](https://arxiv.org/abs/2605.11202) (cs.CR, 2026-05-11)
- **方法**: 首个 LLM 推理引擎 greybox fuzzer——以 timed multi-request traces 为一等输入，检测 crash/hang/性能退化/静默输出污染
- **发现**: vLLM & SGLang **15** 个漏洞（**10** 个确认，**2 个 CVE**）→ KV-cache 隔离失败 / 跨请求性能干扰 / crash / liveness bugs
- **亮点**: 并发 + 缓存 + 状态复用 可导致静默跨请求污染 + noisy-neighbor DoS，是 LLM 基础设施的一等安全和可靠性边界

## 📌 本期核心趋势

1. **工业级推理引擎全栈打通**: RTP-LLM(阿里100M用户)+xLLM(京东EPD) 展示了 PD分离+分层KV+模块化SD+自适应量化在真实生产中的效果——不再单点优化而是全栈co-design

2. **Lossy→Lossless 推理**: VeriCache(4×, bit-identical) 确立了"KV压缩必须保证输出等价"的范式，对万卡推理集群部署影响深远

3. **SD 基础设施成熟**: Vegas(ICML'26 0-cost KV selec) + SSV(3.49×稀疏SD) + WhiFlash(跨范式) + Nightjar(自适应开关) + Cassandra(硬件协同,ISCA'26)——SD 从"单点加速"走向"全场景基础设施"

4. **推理系统安全成为新焦点**: GRIEF 在 vLLM/SGLang 发现 15 个漏洞含 KV 隔离失败——随着推理规模扩大，并发状态管理安全不容忽视

5. **多 Agent 场景倒逼推理架构**: Stateful Inference(持久化KV) + WhisFlash(跨范式SD) 都指向 Agent 长程交互场景对传统 stateless 推理架构的根本挑战
