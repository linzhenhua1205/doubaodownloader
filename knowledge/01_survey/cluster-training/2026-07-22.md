### 1. ExpertPlex — MoE的"共享Expert+分离Attention"新范式

| 属性 | 内容 |
|:----|:------|
| **论文** | ExpertPlex: A High-Goodput Disaggregated Serving System for MoE LLMs with Adaptive Persistent Kernels |
| **链接** | [arXiv:2607.18002](https://arxiv.org/abs/2607.18002) |
| **作者** | Bingyang Wu, Chao Jin, Zili Zhang, Xinming Wei, Yinmin Zhong, Ruidong Zhu, Chengxu Yang, Xin Jin, Yuliang Liu |
| **方向** | **PD分离部署** · MoE推理 |
| **核心指标** | **2.01×** goodput vs 实例级PD分离, **1.66×** vs PD合部 |
| **核心方法** | ① 共享MoE Expert + 分离Attention ② Adaptive Persistent Kernel ③ Tile-to-Cluster模型 |

**详细解读**:
- 现有PD分离方案对MoE模型效率低：每个实例是全模型副本，MoE权重越大，副本开销越大；预填充/解码配比难以适配动态负载
- ExpertPlex核心思想：**共享巨大的MoE Expert层，仅分离轻量的Attention模块**
  - Expert共享消除**95%以上**重复模型权重，动态稀疏计算被复用
  - Attention分离减少attention通信开销
- 三大技术创新：
  - **Adaptive Persistent Kernel** — tile粒度调度动态expert计算，隔离执行
  - **Attention-Initiated MoE通信** — 避免网络干扰，实现跨阶段通信-计算重叠
  - **Tile-to-Cluster模型** — 优化机制获取最大goodput
- 实验模型: MiniMax-M2.7, GLM-5.1-FP8
- **地位**: PD分离在MoE场景的新范式——不再实例级全副本分离，而是模型内"shared dense + disaggregated attention"

### 2. LAGA — Megatron-Core MLA吸收闭源禁用的深层原因与修复

| 属性 | 内容 |
|:----|:------|
| **论文** | A Training-Memory Regression in MLA Sequence Parallelism: Why Megatron-Core Forbids Absorption, and LAGA -- a Communication-Efficient Fix |
| **链接** | [arXiv:2607.17644](https://arxiv.org/abs/2607.17644) |
| **作者** | Changzheng Ma |
| **方向** | **分布式训练并行策略** · MLA序列并行性 |
| **核心指标** | **1.98×**通信缩减, 内存**0.5%**内匹配explicit, 吞吐**1.07-1.24×**提升 |
| **核心方法** | LAGA: Latent All-Gather Attention, 保留latent-gather通信但拒绝absorb reformulation |

**详细解读**:
- Megatron-Core中MLA有两个实现：显式(explicit)形式用于训练，吸收(absorbed)形式用于推理解码
- 吸收形式虽减少通信（只收集压缩后的latent），但Megatron-Core硬断言禁止训练使用
- **核心发现**: 吸收形式在训练中是"内存陷阱"——其中间变量尺寸为 `n_h×d_kv` per token，大于其替代的per-head K/V
  - 激活内存膨胀 **20-34%**
  - DeepSeek-V3规模(n_h=128, seq=16384, SP=8, eager kernel)达 **9.2 GB**
  - fused kernel下差距扩大到 **19.2 GB**——足以改变设备适配
- **LAGA方案**: 保留absorbed的latent-gather通信优势，但拒绝absorb重公式化——从收集到的latent本地重建per-head K/V
  - 按真实DeepSeek-V3维度在8×Ascend 910B上验证
  - SP=1时bit-identical, SP=2-8时等价于1e-3
  - 跨节点场景在所有序列长度上**均领先**
- **意义**: 首次系统性揭示Megatron-Core中MLA吸收训练禁用根因，并为DeepSeek-V3系列提供了一条低通信训练路径

### 3. HyMCache — CXL混合内存KV Cache的工程落地

| 属性 | 内容 |
|:----|:------|
| **论文** | HyMCache: A KV Cache Framework for Multi-Turn LLM Serving with CXL-Hybrid Memory |
| **链接** | [arXiv:2607.18141](https://arxiv.org/abs/2607.18141) |
| **作者** | Hakbeom Jang, Inho Song, Sam H. Noh, Jongryool Kim |
| **方向** | **KV Cache优化** · CXL内存分层 |
| **核心指标** | **3.0×** vs LMCache(单节点), **1.45×**(PD分离), 30%性能vs Mooncake但**16×少DRAM** |
| **核心方法** | CXL-HM + request级前缀预取 + 机会性写入缓冲 |

**详细解读**:
- 多轮/长上下文/Agentic负载使KV Cache重用成为关键，但GPU HBM和host DRAM成本太高
- CXL-HM是一种CXL接口背后的小容量设备DRAM+大容量SSD的混合内存
- 利用多轮KV Cache访问的**读主导·可预测·仅追加**特征，
  - 请求级前缀预取：将延迟敏感的读取staging在设备DRAM
  - 机会性写入缓冲：减少SSD写入放大
- 真实CXL-HM原型评估，包含单aggregator和PD分离两种配置
- vs 1TB分布式DRAM Mooncake：性能低~30%，但DRAM使用量仅1/16
- **地位**: CXL在KV Cache领域从实验走向工程验证——VS Mooncake的"30%性能换1/16成本"是现实的TCO取舍

### 4. HeaRank — GPU可靠性从"预测"到"排序"的范式转型

| 属性 | 内容 |
|:----|:------|
| **论文** | Don't Predict, Prioritize: Rethinking GPU Reliability Assessment |
| **链接** | [arXiv:2607.15115](https://arxiv.org/abs/2607.15115) |
| **作者** | Difeng Ma, Changhua Pei, Yuanwei Lu, Quan Zhou, Zexin Wang, Yibo Zhu, Daxin Jiang, Dan Pei, Jingjing Li, Gaogang Xie |
| **方向** | **Checkpoint/容错** · GPU可靠性评估 |
| **核心指标** | **AUC 0.83**, top 5%捕获**64%**故障 (vs 21%现行系统) |
| **核心方法** | Learning-to-Rank (LTR)框架HeaRank，基于历史故障模式稳定特征 |
| **接收** | **ACM SIGKDD 2026** |

**详细解读**:
- 核心洞察：精确预测GPU故障时间**本质上不可行**——DBE和GPU Lost在时序遥测中表现出强随机性和低信噪比
- 范式转换：从"预测绝对故障时间"→"排序相对故障风险"
- HeaRank利用稳定历史故障模式计算全局GPU节点风险排序
- 生产级集群验证：数万GPU
- **对万卡集群意义**: 风险感知调度+主动资源管理远比"预测何时坏"更实用——对于Checkpoint调度策略，可优先对高风险节点做高频Checkpoint

### 5. Talaria — 百亿参数LLM的Session-Aware Serverless Serving

| 属性 | 内容 |
|:----|:------|
| **论文** | Talaria: Session-Aware Serverless Serving of Hundred-Billion-Parameter LLMs |
| **链接** | [arXiv:2607.17181](https://arxiv.org/abs/2607.17181) |
| **作者** | Utopia Meng, Unicornt Zhao, Derek Li, Goalen Gao, Frank Du |
| **方向** | PD分离部署 · LLM Serverless推理 |
| **核心指标** | **5.3×** p50 SCT缩减, **2.6×** p95 (1000s→189s, 2296s→867s) |
| **核心方法** | 会话感知路由 + soft reservation + session-prefill + HBM地址稳定 |

**详细解读**:
- 问题: Serverless多模型系统独立调度每个请求，但工具调用Agent在短工具间隔内反复调LLM——session连续性被破坏
- Talaria将session连续性作为联合放置-准入决策
  - 路由器按模型驻留、KV局部性、实例压力排序放置
  - soft reservation为可能返回的请求预留budget
  - **Session-Prefill**: 在active模型槽关闭前准入符合条件的continuation
  - 实例级：保持HBM地址稳定 + 可主机恢复的KV + 模型切换时权重staging
- 单TP=8服务器上回放30个SWE-Bench models-sessions(960调用)跨3个>100B模型
- **核心意义**: 将PD分离的决策从"请求级独立路由"升级为"session级联合决策"

### 6. Roomie — 干扰感知的GPU模型合部调度

| 属性 | 内容 |
|:----|:------|
| **论文** | Roomie: Interference-Aware Colocation for Efficient Model Serving |
| **链接** | [arXiv:2607.16784](https://arxiv.org/abs/2607.16784) |
| **作者** | Youssouph Faye, Francescomaria Faticanti, Shubham Jain, Francesco Bronzino |
| **方向** | 通信调度 · 模型合部推理 |
| **核心指标** | **3×** SLO违规减少 |
| **核心方法** | occupancy-based分析模型 + 成对贪心启发式 + 在线放置算法 |

  - 在线放置算法为每个新模型选择最小预测减速的GPU
- 对万卡集群: 推理集群GPU利用率优化

### 7. SALT — 显著性感知Lexical Trie长上下文压缩

| 属性 | 内容 |
|:----|:------|
| **论文** | SALT: Salience-Aware Lexical Trie for Long-Context Compression |
| **链接** | [arXiv:2607.17486](https://arxiv.org/abs/2607.17486) |
| **作者** | Oteo Mamo, Hyunjin Yi, Joydhriti Choudhury, Shangqian Gao, Weikuan Yu |
| **方向** | KV Cache优化 · 长上下文压缩 |
| **核心方法** | 句子频率排序Trie + 多锚点检索 + 跨轮持久化 |

**详细解读**:
- 现有prompt压缩用标量相关性评分各句 → 紧预算下**主题坍塌**: 主导主题占用全部预算
- SALT将per-sentence关键词组织成基于句子频率的Trie结构，平滑内存分配并防止主题垄断
- 多锚点检索可激活query关键词对应的任意深度trie节点
- Trie在对话轮间持久化，支持多轮使用无需重编码文档
- 可与KV Cache方法组合，覆盖解码时延迟和内存
- **核心创新**: 从"句子独立打分"到"主题结构预算分配"的视角转换

## 📌 本期核心趋势

1. **MoE PD分离新范式诞生**: ExpertPlex打破"实例级全副本PD分离"的惯例，提出"共享Expert+分离Attention"架构。**这对大规模MoE推理的架构设计影响深远**——PD混合不再是实例级调度问题，而是模型内部结构问题

2. **MLA训练路径的深层诊断**: LAGA揭示Megatron-Core禁止MLA吸收用于训练的根因(20-34%内存膨胀)，并提供1.98×通信缩减的LAGA方案。**对DeepSeek-V3系列的低通信训练有直接价值**

3. **CXL-KV Cache从实验走向工程**: HyMCache在真实CXL-HM原型上验证了KV Cache的分层方案——以16×DRAM节省换取30%性能下降 vs Mooncake。**TCO驱动的存储层级决策已进入工程验证阶段**

4. **GPU可靠性从"预测"转向"排序"**: HeaRank(KDD'26)基于不可预测性证明，将评估范式从"何时故障"转为"谁更风险高"。**AUC 0.83+top5%→64%捕获率意味着可以设计风险感知Checkpoint策略**

5. **Session级PD决策兴起**: Talaria的session-aware routing将PD分离从请求级提升到session级——对一个session内多次推理做联合放置决策，p50 SCT降低5.3×
