## 1. 🏗️ 大规模分布式训练并行策略

### 1.1 MoP: Mixture-of-Parallelisms——MoE 模型训练的内存高效并行栈（重点 ⭐⭐🔥）

- **作者**: Xuan-Phi Nguyen, Shrey Pandit, Yiran Zhao, Semih Yavuz, Silvio Savarese, Shafiq Joty
- **来源**: arXiv:2607.01844 (cs.DC), 提交 2026-07-02（Fri 新刊）
- **核心问题**: MoE 模型训练需要多个并行维度（DP/TP/PP/EP/SP/CP）的组合，但现有方案多是**非最优的固定组合**，且 optimizer step（尤其是 large-momentum 优化器如 Adam 的 state）是内存的关键瓶颈
- **核心技术: MoP**:
  1. **层/阶段定制并行**: 在 MoE 训练管道的不同层和阶段组合与专化各种并行技术（含已有和新的变体）
  2. **CPU-GPU/GPU-GPU/节点间带宽约束下最大化效率**
  3. **Novel optimizer step 策略**: 实现高吞吐和高内存效率，支持 lossless 训练
- **关键数据**:
  - **<12 节点 8×H200**（即 96 GPU）训练**万亿参数 + 百万上下文长度**的模型
  - 吞吐量 **4.7×-8.2×** 对比强优化的 FSDP2 基线（差距随规模扩大而扩大）
  - FSDP2 基线在 64-128K 序列长度后 OOM，而 MoP 可持续到 **1M tokens**
- **意义**: **"并行不是选一个，而是编排组合"** 的基调。MoP 的核心洞察不同于 Auto-Parallelism（自动搜索最优配置），而是**手动/半自动设计针对 MoE 各阶段的专化并行策略**，尤其注意 optimizer step 这个被忽视的内存陷阱。这个 4.7-8.2× vs FSDP2 的数据与 ReMP（06-28 跟踪）的运行时重配置互补——ReMP 解决"运行时切换"问题，MoP 解决"初始时就最优"问题

### 1.2 SCAPE: 基于一阶动量的极端稀疏通信优化器（重点 ⭐⭐🔥）

- **作者**: Mingkai Zheng, Junlin Chen, Haotian Xie, Zhao Zhang
- **来源**: arXiv:2607.01678 (cs.LG, cs.DC), 提交 2026-07-02（Fri 新刊）
- **核心问题**: 梯度同步通信成本随模型大小和系统规模线性增长。现有通信压缩方法要么对原始梯度做稀疏化（对 Adam 式优化器在高度稀疏下不稳定），要么做量化（节省上限受位宽限制）
- **关键发现**: AdamS（Sign 变体）的**一阶动量 (first moment) 比原始梯度更适合做稀疏化决策**——它更稳定、噪声更低
- **核心技术: SCAPE**:
  1. **从一阶动量导出 mask**：而非从原始梯度
  2. **跨 worker mask 分区生成**: 对齐 optimizer sharding
  3. **mask 延迟使用**: 一步延迟使 mask 同步与计算重叠
  4. **单稀疏 buffer 重建二阶梯度的必要量**：避免额外 collectives
- **关键数据**（在 Megatron-LM 中实现，32 NVIDIA GH200 TACC Vista）:
  - GPT-345M / Llama-500M：**90% 和 99% 稀疏度下保持训练稳定、验证 loss 和下游任务精度**
  - Llama-500M：端到端预训练 wall-clock 加速 **43.3%**
  - Llama-1.8B：每步 **3.26×** 加速 vs 密集 AdamS
- **意义**: SCAPE 的核心洞察——**"不是压什么，而是从哪里导 mask"**——是对之前所有梯度稀疏化工作的关键提升。之前 CommFuse（06-29）做的是通信调度层面的优化，SCAPE 做的是**通信量本身的极致压缩（99%）且不损质量**。与 SCAPE 共享作者的 DeadPool（下面 §6.1）形成了"训练加速+容错"的配套组合

## 2. 📡 PD 分离部署

### 2.1 Load-Aware Prefill Deflection：让 decode 节点分担预填充（重点 ⭐⭐🔥）

- **作者**: Shrikara Arun, Anjaly Parayil, Srikant Bharadwaj, Renee St. Amant, Victor Rühle
- **来源**: arXiv:2607.02043 (cs.DC, cs.AI), 提交 2026-07-02（Fri 新刊）
- **核心问题**: PD 分离解除了 prefill 和 decode 相互干扰，但创造了新的不对称：**burst 下 prefill 节点饱和而 decode 节点计算未充分用**。进一步分析发现，P95 TTFT 只有 **2-23%** 花在实际 prefill 执行上，其余都被排队和跨节点 KV 传输占据
- **核心技术: 主动预填充偏离调度器**:
  1. **decode 节点以 chunked-prefill 步骤为预填充提供服务**，穿插在在线 decode batch 之间
  2. **路由决策**：对每个排队请求，估计其在 prefill 节点和每个 decode 节点的 TTFT，搜索最大 chunk schedule 同时保证 decode 不违反 TBT SLO
  3. **消除跨节点 KV 传输**：被偏离的请求直接在 decode 节点上做 prefill，无需传输 KV Cache
- **关键数据**（vLLM 实现 + DeepSeek-V2-Lite + 生产风格 trace）:
  - P95 TTFT **降低 81%**
  - SLO 达成度提升 **79%**
  - 路由决策开销亚毫秒级
- **意义**: **PD 分离的"第三个角色"正在出现**。过去 PD 分离只讨论 prefill 节点和 decode 节点两类，而预填充偏离引入了一种**混合角色（decode 节点在 decode 间隙做 prefill）**。这与 06-30 HMA-Serve（跨厂牌混合 PD）形成互补：HMA-Serve 解决"不同硬件配不同角色"，此篇解决"同一硬件动态切换角色"

### 2.2 HYPIC: Hybrid-Attention 模型的位置无关缓存（重点 ⭐⭐）

- **作者**: Yifei Liu, Juntong Wu, Yang Liu, Junhao Hu, Minghao Li, Xiaoxu Chen, Weihang Chen
- **来源**: arXiv:2607.01299 (cs.DC), 提交 2026-07-01（Thu/07-03 新刊区）
- **核心问题**: RAG/Agent 场景下，位置无关缓存(PIC)对全注意力模型很有效。但**Hybrid-Attention 模型**（全注意+线性注意混合）无法应用 PIC，因为线性注意层的 KV-Cache 是 per-request recurrent state，不支持 per-token 粒度复用
- **核心技术: Hypic**:
  1. **线性注意层**: 识别 **segment-cumulative transition operator** 为缺失的代数原语——缓存每段的 zero-start end-state，可近乎精确/常数时间组合独立缓存的段
  2. **全注意层**: 发现注意力偏差集中出现在**段边界**——仅在边界重计算小 seam window 即可恢复交叉段 lookback
  3. **Cache-miss prefill 并行化**: 利用段级自包含性跨实例并行化冷请求 prefill
- **关键数据**（4 个 Hybrid-Attention 模型、5 个 workload）:
  - TTFT 降低平均 **2.45×**
  - 峰值吞吐提升 **2.0×**
  - 精度损失 < 3.3 点
- **意义**: **Hybrid-Attention 模型的系统级优化严重滞后于其算法的流行度**。HYPIC 填补了这个空白：之前 PIC 工作中(SmoothAgent 07-02)主要针对全注意力模型。HYPIC 的关键洞察——**线性注意不是"没有 KV Cache"，而是"有不同的 state 原语"**——是让新一代高效架构(如 Mamba-2 混合)从"算法上可行"走向"系统上可服务"的桥梁

## 3. 🔄 通信调度

### 3.1 HCMS: 头分块多流 Pipeline——长序列并行注意力的通信计算重叠（重点 ⭐⭐）

- **作者**: Chao Yuan, Pan Li, Yingnan Sun, Jing Liu
- **来源**: arXiv:2607.01817 (cs.DC), 提交 2026-07-02（Fri 新刊）
- **核心问题**: 基于 all-to-all 的序列并行方法（如 DeepSpeed-Ulysses）在处理中长序列时**串行执行通信和计算**，导致硬件资源未被充分利用。Ring Attention 也有类似问题
- **核心技术: HCMS**:
  1. **注意力头分区为多个 chunk**
  2. **双 CUDA stream 实现细粒度通信-计算重叠**
  3. **正交兼容 FlashAttention/SDPA**，无需修改底层 kernel
  4. **支持不均匀分区、保持数值等价性**
- **关键数据**（4 个 GPU 平台、2-8 GPU 规模）:
  - 31K-56K tokens（典型视频生成序列长度）：Ulysses 加速 **10-17.5%**，Ring Attention 加速 **5-14.5%**
  - 端到端 Wan2.2 模型加速 **6.8%**
  - **理论分析**: HCMS 收益与通信比率 ρ 正相关，推荐 ρ>20% 时使用
- **意义**: HCMS 的核心思路与 Syncopate（07-02 跟踪，OSDI 2026）异曲同工——**"kernel 内部做细粒度 overlap"**——但 HCMS 更 Focus（专注序列并行注意力）也更工程化（双 CUDA stream + 不改 kernel）。两者形成互补：Syncopate 是从编译器角度做通用 overlap，HCMS 是从序列并行角度做专用 overlap

## 4. 🧠 Speculative Decoding / KV Cache 优化

### 4.1 Lynx: 渐进推测量 KV 传输——长上下文的 PD 分离加速（重点 ⭐⭐🔥）

- **作者**: Wenchen Han, Gingfung Matthew Yeung, Marco Barletta, William Toner, Amory Hoste, Adam Barker
- **来源**: arXiv:2607.01831 (cs.DC, cs.LG), 提交 2026-07-02（Fri 新刊，原投 SIGCOMM '26）
- **核心问题**: PD 分离中 decode 节点必须等待 KV Cache 传输完成才能开始解码。现有 KV 量化技术降低数据量但无法同时实现**低网络暴露延迟和高推理精度**
- **关键洞察**: KV Cache 的不同比特对注意计算贡献不平等——**最高有效位捕获注意力的粗糙结构，最低有效位细化精度**
- **核心技术: Lynx**:
  1. **分流渐进传输**: 将 KV Cache 分为高优先级 **Anchor 流**（最高有效位）和低优先级 **Residual 流**（剩余精度）
  2. **推测解码并行**: Anchor 流到达后立即开始解码，解码进行中并发传输 Residual 流
  3. **验证阶段**保证等价于高精度解码
- **关键数据**:
  - TTFT **匹敌激进 4-bit 量化**
  - 精度**匹敌 BF16** 高精度推理
  - TTFT 优于标准 8-bit KV 量化 **1.43×**
  - 精度优于 SOTA **5.1%**
- **意义**: **"KV 传输过程中的推测解码"是一个全新的系统设计空间**。Lynx 本质上是对"KV Cache 不可分割"假设的挑战，与 GSRQ（07-02 跟踪，ICML 2026）的"亚 1-bit 量化"解决问题不同——GSRQ 是从量化算法上减少传输量，Lynx 是从传输协议上让传输与解码**并发进行**。被引向 SIGCOMM '26 表明其网络视角的贡献被认可

### 4.2 PARTREP: 学习选择最需重复的 Token 做提示增强（重点 ⭐）

- **作者**: Andikawati P Widjaja, Yongjun Kim, Hyounghun Kim, Jaeho Lee
- **来源**: arXiv:2607.01792 (cs.CL, cs.LG), 提交 2026-07-02（Fri 新刊）
- **核心问题**: 对 decoder-only LLM，因果注意的不对称信息流导致**较早 token 的上下文grounding 较弱**。简单重复整个 prompt 可显著提升推理性能，但 **KV Cache 翻倍 + 注意力开销翻 4 倍**
- **核心技术: PartRep**:
  1. **Token 级 NLL（负对数似然）作为选择信号**：越"不可预测"的 token 越难从上下文恢复，越需重复
  2. **Lightweight gate 预测高 NLL tokens**：从早期层 hidden states 预测，prefill 中途早退选择，避免完整前向传播
- **关键数据**（8 个基准 × 3 模型族）:
  - 保留全重复**绝大部分收益**
  - KV Cache **仅 59.4%**
  - Prefill FLOPs **79.0%**
- **意义**: 虽不完全属于 Speculative Decoding，但**"选择性地增强 prompt 输入以改善因果注意的不对称性"**与 SD 的"用草稿模型快速生成候选"的思路互补。PARTREP 的 NLL-as-signal 可以视为一种**"KV Cache 层面的重要性采样"**

## 6. 📦 Checkpoint 容错

### 6.1 DeadPool: 零开销热插拔——无故障时零开销 + 故障恢复<40秒（重点 ⭐⭐🔥）

- **作者**: Haotian Xie, Junlin Chen, Mingkai Zheng, Lishan Yang, Zhao Zhang
- **来源**: arXiv:2607.01646 (cs.LG, cs.DC), 提交 2026-07-02（Fri 新刊）
- **核心问题**: LLM 训练在万卡规模下频繁遇到故障。现有方案要么在无故障时引入额外开销（同步写 checkpoint），要么恢复延迟高（永久节点故障需重调度整个 job）
- **核心技术: DeadPool**:
  1. **Off-critical-path in-memory checkpoint**: 利用不阻碍正常计算路径的路径创建内存冗余——**与计算重叠，零运行时开销**
  2. **通信器热重建协议**: 运行时用备用节点替换故障节点，无需终止整个 job
  3. **in-memory checkpoint 最小化重计算**
- **关键数据**（512 NVIDIA A100, 最大 65B 参数）:
  - 无故障时 **零 checkpoint 开销**
  - 永久节点故障后 **<40 秒** 热插拔恢复
- **意义**: **这与 06-28 跟踪的 Concordia（GPU kernel 级推理 checkpoint）形成完美对称**——Concordia 解决推理 checkpoint，DeadPool 解决训练 checkpoint。DeadPool 的"零开销"和"热插拔恢复<40 秒"是万卡训练的两个关键指标。其思路与一致检查点(consistent checkpoint)不同：**不追求全局快照，而是通过 off-critical-path 空间冗余 + 运行时通信器重建实现更低的恢复延迟**
