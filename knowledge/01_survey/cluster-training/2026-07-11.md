## 1. 🏗️ 大规模分布式训练并行策略

### 1.1 SCAPE: 基于一阶动量的极端梯度稀疏化通信（重点 ⭐⭐⭐🔥）

- **作者**: Mingkai Zheng, Junlin Chen, Haotian Xie, Zhao Zhang
- **来源**: arXiv:2607.01678 (cs.LG, cs.DC), 提交 2026-07-02
- **核心问题**: 数据并行和 sharded 训练中梯度同步和参数重构建开销随模型/规模线性增长。现有通信压缩方案：稀疏化 raw grad 在 Adam 类优化器下高稀疏度不稳定；量化受位宽约束且引入运行时开销
- **核心技术: SCAPE**:
  1. **一阶动量导出 mask**：利用 **AdamS 一阶动量(momentum)天然稳定性**——mask 从 momentum 统计量构造而非 raw gradient，避免剧烈抖动，可支撑 **90-99% 高稀疏度**且不影响 LLM 质量
  2. **跨 Worker 分区生成**：mask 生成按优化器 sharding 划分，与数据并行组对齐
  3. **隔步异步**：mask 使用延迟一步，使 mask 同步与计算重叠
  4. **单稀疏 buffer 重构**：从单个同步的稀疏 buffer 重构二阶动量所需信息，省去额外集合通信
- **关键数据**:
  - **GPT-345M / Llama-500M** 在 32×GH200(TACC Vista) 上预训练：**90-99% 稀疏度**下训练稳定、验证 loss 和下游任务精度保持
  - Llama-500M: 端到端预训练 wall-clock 减少 **43.3%**
  - Llama-1.8B: 每步 **3.26× 加速** vs 稠密 AdamS
  - 实现于 Megatron-LM
- **意义**: 与之前跟踪的 **Orth-Dion**(07-07, 低秩谱优化、QR 正交化) 互补——Orth-Dion 从优化器侧减少通信（低秩压缩），SCAPE 从梯度稀疏化侧出（动量导向 mask）。**同时实现 90%+ 稀疏度和质量保持是重要突破**，限制了此前 raw-grad 稀疏化方案的适用范围

### 1.2 CTA-Pipelining: 跨 GPU CTA 级流水线加速（重点 ⭐⭐）

- **作者**: Tingkai Liu, Muralidhar Andoorveedu, Sanjoy Das, Sanjay Patel, Volodymyr Kindratenko
- **来源**: arXiv:2607.07862 (cs.DC, cs.LG), 提交 2026-07-10
- **核心问题**: 现代多 GPU 系统通过一致性互连形成紧耦合共享内存结构，但软件仍将其视为高速网络。同时 LLM 服务对延迟敏感，需要超越 Tensor Parallelism 的延迟导向扩展方法
- **核心技术: CTA-Pipelining**:
  1. 利用 **CTA 级依赖关系**——允许依赖 kernel 在多 GPU 间**并发执行**
  2. 与 **CUDA CUTLASS/cuBLAS/NCCL** 兼容，无需修改底层库
  3. 作为 **与 TP 正交的扩展维度**——可叠加使用
- **关键数据**:
  - 2 层 GEMM（MLP 操作）：比 micro-batching 延迟减 **31.8%**，比 TP 减 **29.6%**
  - 8-GPU H200/B200 系统验证
- **意义**: 这是**第一个在 CTA 粒度上进行跨 GPU 流水线的方案**。现有 TP 在模型内细粒度切分，但每个 transformer layer 内仍需同步；CTA-pipelining 可在 layer 内部进一步重叠。对**低延迟推理场景（batch=1）** 尤其重要——PD 分离中的 decode 阶段也面临类似瓶颈

### 1.3 异构并行布局 — MLLM 训练（⭐⭐）

- **作者**: Yashaswi Karnati, Kamran Jafari, Akash Mehra 等 (NVIDIA?)
- **来源**: arXiv:2605.27678 (cs.LG, cs.DC), 提交 2026-05-26
- **核心问题**: 多模态大模型训练中——encoder 规模和上下文与 LLM backbone 差异大，单一 LLM 为中心的 TP/CP/PP/DP/EP 布局使 encoder 继承 LLM 的 sharding 选择，引入不必要通信或限制并行度。长上下文时 LLM 需要 CP 但 encoder 输入有界，矛盾更突出
- **核心技术: 异构并行**:
  1. **各模块独立布局**——端到端图中不同模块使用独立的并行配置和 rank 放置
  2. 支持 **colocated**（共享 GPU）和 **non-colocated**（不相交 rank 集）
  3. **边界通信器**：前向激活按目标布局 materialize，反向梯度路由回源，自动布局转换
  4. 调度扩展覆盖两种放置模式
- **关键数据**:
  - Colocated 异构：TFLOPS/GPU 提升 **49.3%**
  - Non-colocated 异构：聚合 token 吞吐 **13.0%**，TFLOPS/GPU **9.6%**
  - 收敛性 = 同构基线
  - 作为 Megatron-LM 扩展开源
- **意义**: 这是**首个支持模块级独立并行布局的框架**。当多模态模型大行其道（VLM/VLA），visual encoder + LLM backbone 各自最优并行度不同。**与 Dynamo/ThunderKittens 等运行时编译不同**，这套方案在 Megatron 静态图框架中实现，对生产训练系统更具可操作性

### 1.4 BACE-Pipe: 跨地域 LLM 训练的带宽感知流水线调度（⭐）

- **作者**: Han Zhang, Jianchun Liu, Hongli Xu
- **来源**: arXiv:2605.25375 (cs.DC), 提交 2026-05-24
- **核心问题**: GPU 稀缺迫使跨地域分布式训练成为刚需。跨地域带宽异构 + 电价差异使 PP 调度困难——现有方案要么延迟优先（电价贵），要么成本优先（JCT 长），多租户下带宽密集型长作业引发队首阻塞
- **核心技术: BACE-Pipe**:
  1. **动态作业优先级**：联合考虑计算时间和实时网络利用
  2. **带宽感知路径查找**：找到满足通信约束的跨地域 PP 路径，防止通信卡住流水线
  3. **成本最小化分配**：优先分配更低电价区域的 GPU
- **关键数据**:
  - 平均 JCT 减 **27.9%-64.7%**
  - 总电费减 **12.6%-30.6%**
  - 与 SOTA 基线比较
- **意义**: 跨地域训练的现实约束——**既有带宽异构又有电价差**。BACE-Pipe 验证了带宽感知+电价联合优化在真实约束下的可行性，为**多数据中心训练编排**提供可落地的方法

## 2. 🔄 推测解码与 KV Cache 优化

### 2.1 Lynx: 渐进式推测 KV 传输加速长上下文推理（重点 ⭐⭐）

- **作者**: Wenchen Han, Gingfung Matthew Yeung, Marco Barletta 等
- **来源**: arXiv:2607.01831 (cs.DC, cs.LG), 提交 2026-07-02
- **核心问题**: 长上下文推理中 PD 分离部署要求 KV Cache 跨网络传输。解码须等传输完成才能开始。量化可压缩数据量，但无法兼顾低网络暴露延迟和高推理精度
- **核心技术: Lynx**:
  1. **分裂流(Spilt-stream) KV 传输**——高位比特（Anchor 流）捕获注意力粗结构，低位比特（Residual 流）细化精度
  2. **渐进式传输**：Anchor 先传，decoding 可立即开始；Residual 在后台并发传输
  3. **推测验证**：解码基于不完整 KV 进行（推测），Residual 完成后验证以保证等价于高精度推理
- **关键数据**:
  - TTFT: 比 8-bit KV 量化改善 **1.43×**
  - 精度匹配 **BF16**（优于 4-bit 量化方案）
  - 支持多种模型和负载
  - 最初投稿 SIGCOMM'26
- **意义**: 挑战了"KV Cache 是不能分割的单元，须完整接收后才能使用"的假设。利用**不同位对注意力贡献不同**的事实，首次实现 KV 传输+解码的推测并行。对 **PD 分离跨数据中心部署**有直接影响——TTFT ≤ 推理 SLA 约束的关键瓶颈之一。与 07-10 的 VeriCache（有损 KV 无损化）互补：Lynx 优化传输过程，VeriCache 优化解码过程

### 2.2 WhiFlash: 跨范式推测解码（⭐⭐）

- **作者**: Young D. Kwon, Miles Williams, Rui Li, Alexandros Kouris, Stylianos I. Venieris
- **来源**: arXiv:2606.07710 (cs.LG, cs.AI), 提交 2026-06-05
- **核心问题**: 现有推测解码使用静态范式——AR 式 drafting（EAGLE 系列）或 Diffusion 式并行 drafting（DFlash）。但经验发现**单个序列内 drafting 精度波动剧烈**，静态/粗粒度路由无法利用
- **核心技术: WhiFlash**:
  1. **首个跨范式推测解码**——在 AR drafting 和 Diffusion 并行 drafting 之间做 **token 级路由**
  2. 轻量熵感知或学习型神经网络策略，权衡预期 token 增益和延迟
  3. 缓存优化：**Lazy Catch-up + KV-only Prefill** 使切换开销 < 每轮延迟的 7%
- **关键数据**:
  - 吞吐增益 **69.6%** vs EAGLE-3，**37.3%** vs DFlash
  - 切换开销 < 7%
- **意义**: 这是**首次意识到"不同 drafting 范式在同一序列不同位置各有优劣"**并做出 token 级切换。对推测解码下一个演进方向有启发：不再是单一范式优化，而是**范式融合与动态选择**。WhiFlash 的缓存管理技术（跨范式缓存复用）也有独立价值

### 2.3 Cassandra: 训练免费的自推测解码（ISCA'26）（⭐）

- **作者**: Soongyu Choi, Yuntae Kim, Muyoung Son, Joo-Young Kim
- **来源**: arXiv:2605.26558 (cs.AR), ISCA 2026
- **核心问题**: 推理模型在 decode 阶段开销大，近似方法降低精度，现有自推测解码低 batch 性能不够好
- **核心技术: Cassandra**:
  1. 算法-硬件协同设计的 **self-speculative decoding**——通过细粒度数据选择构建高性能、无额外训练 draft 模型
  2. **优化剪枝 + 尾数截断**找出权重和 KV Cache 中最重要的值
  3. 轻量 encoder-decoder 硬件模块适配商用 GPU/NPU
- **关键数据**:
  - 最高 **2.41×** 加速 vs BF16 基线
  - Llama-3-8B @ RTX 4090：同显存下比 EAGLE-3 多 **1.81×** tokens
  - ISCA'26 录用
- **意义**: 核心价值在**无训练自推测**——不同于 EAGLE/DFlash 需额外训练 draft model，Cassandra 用剪枝+尾数截断构造低成本 draft。硬件模块设计提升转化效率。与 07-10 的 Vegas(ICML'26, 验证导向稀疏注意力) 相比：Vegas 侧重 attention 稀疏，Cassandra 侧重参数/KV 精度约减

### 2.4 SimSD: 扩散 LLM 的推测解码（⭐）

- **作者**: Junxia Cui, Haotian Ye, Runchu Tian 等
- **来源**: arXiv:2606.02544 (cs.CL, cs.AI), 提交 2026-06-01
- **核心问题**: 扩散 LLM(dLLM) 使用 mask token + 双向注意力，与标准 token 级推测解码不兼容——causal mask 提供逐 token 有效上下文是 SD 验证的基础
- **核心技术: SimSD**:
  1. 引入 **reference tokens**（来自 draft 模型预测）和**注意力掩码调控**——让 dLLM 在单次前向中计算 draft tokens 的有效 logits
  2. 保留 dLLM 并行解码优势
  3. 训练无关，可与 KV Cache/blockwise 解码组合
- **关键数据**:
  - 最高 **7.46×** 解码吞吐
  - 生成质量保持/提升
  - SDAR 系 dLLM 验证
- **意义**: 首次将**推测解码应用在扩散 LLM**上。dLLM 正成为 AR LLM 的热门替代（并行生成），但传统 SD 依赖 causal mask——SimSD 的 **masking 策略是桥梁**，打开了 dLLM 推理加速的一个新维度。与 WhiFlash（跨范式路由）结合使用可实现进一步的加速叠加

### 2.5 Mistletoe: 推测解码的加速坍缩攻击（⚠️ 安全视角）

- **作者**: Shuoyang Sun, Chang Dai, Hao Fang 等
- **来源**: arXiv:2605.14005 (cs.CL, cs.LG), 提交 2026-05-13
- **核心问题**: 推测解码效率依赖平均接受长度 τ。draft model 近似 target model 分布的不完美性创造了新攻击面——小扰动可大幅降低 τ 而不影响输出质量
- **核心技术: Mistletoe**:
  1. 攻击目标是 **draft-target 一致性（agreement）**
  2. 联合优化：退化目标（减降低一致性）+ 语义保持目标（约束 target 输出分布）
  3. **零空间投影**：退化梯度向局部语义保持方向投影——抑制 draft 接受但不引入语义漂移
- **关键数据**:
  - τ **大幅降低**，推测加速完全坍缩
  - token 吞吐降低，输出质量和 perplexity 不变
- **意义**: 这是**首个针对推测解码系统的安全攻击**——揭示了一个机制级漏洞：draft-target 逼近误差 → 攻击表面。对生产部署有实际影响：**任何使用推测解码的服务（PD 分离推理引擎等）都需要关注此威胁向量**。可能的防御：draft 鲁棒性训练、验证阶段异常检测、多 draft 冗余

## 3. 💾 Checkpoint 容错与可靠性

### 3.1 TierCheck: 层次化 Checkpoint 容错（⭐⭐）

- **作者**: Shujie Han, Feng Jiang, Patrick P. C. Lee, Xiao Zhang 等
- **来源**: arXiv:2605.17821 (cs.DC), 提交 2026-05-17
- **核心问题**: LLM 训练被异构故障谱（GPU crash → 集群级断网）频繁中断。现有 checkpoint 系统使用单层存储后端，强制在保存开销和恢复速度之间取舍
- **核心技术: TierCheck**:
  1. **三层设计**：Local/Peer 内存→轻量差分快照（快速恢复），异步迁移→远程持久化
  2. **严格全局一致性**：不卡训练的前提下确保跨层一致
  3. **集群感知恢复**：恢复时快速感知集群拓扑
- **关键数据**:
  - 端到端 checkpoint 写入 **<10 秒**
  - 支持**高频率 checkpoint**（每迭代/每几迭代）
  - 40B 参数模型验证
  - 训练开销极低
- **意义**: TierCheck 与 06-17 跟踪的 **MoC-System**(ASPLOS'25, MoE 部分专家 checkpoint) 和 **MoEvement**(NSDI'26, 稀疏 checkpoint) 互补。三个方案覆盖不同场景：
  - **MoC-System**: MoE 模型的专家级细粒度 checkpoint
  - **MoEvement**: 增量稀疏 + pipeline-boundary 日志恢复
  - **TierCheck**: 通用的三层单-差异化 + 持久化 + 恢复分层策略，适用于稠密和 MoE

**与之前跟踪的对比**:

| 方案 | 年份/会议 | 适用模型 | 核心思路 | 关键指标 |
|:----|:---------|:---------|:---------|:---------|
| MoC-System | ASPLOS'25 | MoE | 部分专家 checkpoint + 两级管理 | 开销减 98.9% |
| MoEvement | NSDI'26 | MoE | 稀疏增量 + pipeline 日志恢复 | 恢复加速 31×, ETTR ≥0.94 |
| TierCheck | 2026-05 | 稠密/MoE | 三层分层 + 一致性+集群感知 | <10s 端到端 |
| SparrowRL | 2026-02 | RL-post | 稀疏 delta + lease 容错 | 79× 传输缩减 (CKPT 相关) |

## 4. ⚙️ 推理系统与调度

### 4.1 SMetric: 智能体场景的会话级 LLM 调度（重点 ⭐⭐）

- **作者**: Jiahao Wang, Kaizhan Lin, Kaixi Zhang, Jinbo Han 等 (上海交大/IPADS)
- **来源**: arXiv:2607.08565 (cs.DC, cs.AI), 提交 2026-07-10
- **核心问题**: LLM 调度方案多为人类交互设计。Agent 场景不同：(1) Agent 只在完整响应后行动→集群 TPS 是首要目标而非 per-token 延迟；(2) 请求间 KV$ 复用率 >80%（vs chat 54-62%）。现有调度器为最大化复用而优先路由到缓存实例→部分实例过载、部分闲置，限制 TPS
- **核心技术: SMetric**:
  1. **平衡会话级调度**——利用会话内局部性，每个会话的**第一个请求纯为负载均衡**路由，后续请求缓存感知路由
  2. 保持局部实例上的 KV 复用的同时平衡集群负载
  3. **会话轮次信息**作为调度指标——仅从用户输入派生，调度器保持无状态
- **关键数据**:
  - PD colocate + 全局 KV 存储：集群 TPS **+10-16%**
  - PD 分离：prefill TPS **+2-34%**
  - per-token 延迟也有改善
- **意义**: 这是**首个专门针对 Agent 场景的 LLM 调度器**。从负载均衡角度重新定义了 KV 复用的取舍——**少量首请求的负载均衡足以平衡集群**。生产环境（百亿级 BAILIAN 平台）数据验证了复用率特征。对**Agent 服务 + PD 分离部署**场景有直接指导意义

### 4.2 Non-GPU AI 加速器大模型推理的工程代价（⭐）

- **作者**: Zheng Yu
- **来源**: arXiv:2607.08215 (cs.DC), 提交 2026-07-10
- **核心问题**: 非 GPU AI 加速器（如华为 Ascend）作为 GPU 替代逐渐增多，但迁移工作负载的真实工程代价缺乏记录
- **主要发现**:
  1. 16-device Ascend 910 + CANN + vLLM-Ascend 部署 DeepSeek-V4-Flash
  2. **12 个源级 patches** 到厂商推理插件
  3. 为保持数值正确性需关闭多个高吞吐特性
  4. 8 大类平台限制：算子/特性支持不完整、脆弱的并行、低层 kernel 数值故障、不成熟的图编译、不稳定高级特性、弱可观测性、生态碎片化
- **意义**: 虽然不属于创新突破类，但记录了**国产加速器迁移的真实代价**——对评估非 GPU 方案的组织有重要参考价值。8 类限制清单可作**选型 check-list**
