## 一、执行摘要

本日窗口（arXiv 提交 2026-05-25 ~ 08-25，跨日查重后）与**集群训练优化**直接相关的新增量共 19 篇，按主题收敛为 **5 条主线**。核心判断：**训练系统优化的杠杆点正在从「算力/带宽的资源供给」转向「状态/时序的语义治理」**——优化器状态何时被传输、KV 以什么格式驻留、checkpoint 在什么语义下可安全恢复、kernel 由谁生成，这些「状态边界」问题正在成为新的收益来源。五条主线与量化证据：

1. **优化器状态时序成为可操作的训练自由度**：Delayed Optimizer-State Transport（2608.24593）在 12 条 0.3M Transformer 训练历史上证明，AdamW 的 moment 变量延迟传输会影响「短视训练决策」——全传输相对即时导数在 10/12 历史中降低 token-disjoint loss（平均收益 4.71×10⁻⁴，单侧符号检验 p=0.0193），且两个控制器在 60/96 个窗口选择不同的调度。这为「梯度聚合/通信步长如何与优化器状态解耦」提供了机制级判据：moment 状态与近期数据顺序是训练状态的可行动组件。
2. **RL 后训练的 critic 设计出现「特权非对称」范式**：Privileged Critic Training（2608.22976）证明 PPO 的 value function 在训练期访问真实退化状态（actor 只拿观测）即可让策略在部署时无传感器自适应——4 并发故障下成功率从 4.8%（naive）拉到 70.2%（oracle 82.4%，闭合 84% 差距）。这是 RLHF/RLVR 之外对「critic 信息不对称」的第一性验证，直接影响大规模 RL 训练中 value/actor 的数据管线设计。
3. **投机解码在批量与多模态场景遭遇「残差漂移/预算错配」结构性瓶颈**：ResiSpec（2608.24411）首次形式化多候选 SD 的 Residual Drift（候选被拒后残差目标分布偏离草稿预测），重排验证过程获 1.92× 加速；AgentSpec（2608.24004）指出大 batch 下 SD 加速衰减的两大主因（高拒绝率 + 动态 token 预算未充分利用），用「结构隔离草稿」将拒绝率压到极低。对集群训练的意义：rollout/数据生成管线是推理系统，SD 的批量化失效直接制约 RL 训练吞吐。
4. **KV 显存治理从「单点压缩」走向「成本轴对比与诚实负结果」**：More GPUs or a Smaller Cache?（2608.23962）把 TP（1-8 卡）与 KV 压缩（16/8/4-bit、keep-ratio 0.25）放到统一成本轴对比，结论是**压缩在成本上恒优于加卡 1.20-2.00×**，分界线在「模型参数量 ≈ 36B/80GB 卡」——低于此线压缩主导、加卡浪费；高于此线 TP 是入场券（70B 在单 A100 任何 KV 设置下都不可行，因为瓶颈是权重）。Elastic KV Cache（2608.23658）则发布了一个罕见的**诚实负结果**：prefill reserve 的动态回收机制可工作（毫秒级 decommit/几十毫秒 recommit），但 chunked prefill 已把收益吃掉了（TTFT 中位数仅差 ~1%），且 TP 会把 reserve 从 KV 的 16% 稀释到 2.7%。
5. **MLSys 2026 FlashInfer Contest 揭示了「kernel 优化工业化」的分工边界**：Agentic Kernel Optimization（2608.14560）用 19 亿 agent tokens 生成出 Fused MoE 92.68× / TopK 1101.02× / Sparse Attention 181.35×（相对 PyTorch）的 kernel，官方赛 Fused MoE 1.71× 超 FlashInfer 基线；但 Harness Engineering（2607.17979）的对照实验给出更精细的结论——**Agent-Assisted（人写优化方向+参考）全面优于 Full-Agent（全自动）**（五个算子 1.62×/18.05×/29.68×/1.12×/13.70× vs 基线），说明「专家约束 + agent 执行」是当前可靠形态。

## 二、主线 1：优化器状态时序与 RL 训练语义

### 2.1 Delayed Optimizer-State Transport：moment 状态延迟传输是训练状态的「可行动组件」

- **来源/标题**: Delayed Optimizer-State Transport Shapes Short-Horizon Training Decisions（arXiv 2608.24593，2026-08-25 提交）— https://arxiv.org/abs/2608.24593
- **要点**:
  - 问题：自适应优化器（AdamW）在 moment 变量中保留梯度历史，使「loss 权重的局部变化」能改变后续更新——这种**延迟传输**（delayed transport）是否大到足以改变「前瞻性短视决策」（prospective short-horizon decisions）？
  - 方法：在固定的未来 minibatch 序列上，对**完整的模型-优化器状态**做 8 步 AdamW 轨迹微分（differentiate eight-step AdamW trajectories through the complete model–optimizer state），再选择暴露匹配的 Math-Code loss 调度，独立评估。
  - 结果：12 条未使用的 0.3M Transformer 训练历史上，全传输相对「optimizer-aware 即时导数」在 10/12 历史中降低 token-disjoint loss（平均收益 4.71×10⁻⁴；精确单侧符号检验 p=0.0193）；两个控制器作用频率相同，但在 60/96 个窗口选择了不同调度。
  - 机制归因：交叉的 checkpoint-未来路径测试把重排序归因于「优化器状态 × 近期数据」的交互；独立的 Ising-CNN 实验证明删除 moment 状态传输会破坏准确的响应预测。全传输分数还在更大的候选库中集中了「精确 rollout 优胜者」，把有限幅度评估聚焦到短名单。
  - 结论：在这些确定的短路径上，**优化器记忆与近期数据顺序是可行动的训练状态组件**——提供了「何时需要有限视界（finite-horizon）而非单步干预」的机制级判据。

**分析：分布式训练中「moment 状态传输」的三层含义**。第一层是**数据并行的物理传输**——Adam 一阶矩 m、二阶矩 v 在每个 allreduce 步聚合后各 rank 保持一致，moment 从「本步梯度」到「下一步更新」的传导天然有一步延迟；这篇论文揭示的延迟传输不止于此，而是指 loss 权重调整经 moment 状态对后续多步更新的「记忆效应」。第二层是**通信步长与状态一致性的耦合**——若梯度累积（gradient accumulation）或通信降频（如 FSDP 的 sharded optimizer state + 低频 allreduce）改变了 moment 的更新节奏，就等于改变了「延迟传输」的时间常数；论文的 8 步轨迹微分给出了量化该效应的计算框架。第三层是**调度决策的输入**——当「换调度」被当作训练超参时，论文证明 moment 状态会让同一调度在不同数据顺序下表现不同（60/96 窗口选择不同），这意味着**数据顺序本身是待优化变量**，与数据管道（data pipeline）的 shuffle 策略直接挂钩。对集群训练工程师的实操含义：若要在不改动通信拓扑的前提下改善收敛，优先检查「数据顺序 × 优化器状态」交互（论文称 optimizer memory 与 near-future data order 是 actionable），而非盲目加大 batch 或调 LR。

### 2.2 Privileged Critic Training：PPO 的「特权非对称 critic」实现无传感器故障适应

- **来源/标题**: Privileged Critic Training Enables Sensor-Free Thruster Fault Adaptation in End-to-End RL（arXiv 2608.22976，2026-08-24 提交）— https://arxiv.org/abs/2608.22976
- **要点**:
  - 问题：欠驱动/多推进器机器人的故障适应需要在线识别「既非二元、又非完全可观测」的退化（连续退化/完全失效/卡死），经典故障检测需要部署期不存在的专用传感器，oracle 控制器（训练期看真实故障态）部署不可行。
  - 方法：RAFT（Recurrent Asymmetric Fault Tolerant）——PPO 的 value function 在**训练期**访问真实退化状态 d_gt，actor 只接收标准任务观测；策略带循环记忆（recurrent memory），训练用 privileged asymmetric critic。
  - 结果：浮动平台机器人（8 推进器 + 1 反作用轮）在最多 4 个并发推进器故障下，RAFT 成功率 70.2%（4 并发故障），闭合了从故障 naive 基线（4.8%）到 oracle 策略（部署时看完整退化状态，82.4%）之间 **84% 的差距**。
  - 开放性：全部代码、checkpoint、数据开源。

**分析：privileged critic 为什么能「无传感器」泛化——信息不对称是第一性杠杆**。经典的 asymmetric actor-critic（如 Sim-to-Real 的 teacher-student）把「特权信息」喂给 teacher 策略再蒸馏，而本篇直接喂给 critic，让 critic 学会「在何种状态下应该保守/激进」，actor 只需学会「根据可观测信号调到 critic 指引的行为」。其成立的机制是：value function 是期望回报的估计器，它不需要在部署期存在——**训练期用特权信息校准价值估计，部署期 actor 学会从观测中推断等价信息**。这与大规模 RL 后训练（RLHF/RLVR）的 critic 设计高度同构：reward model / value model 训练期可以访问真实 reward 与 ground-truth 标签（privileged），而 policy 部署时只有观测——本文为「critic 信息不对称是否值得专门设计」提供了受控实验证据（84% gap 闭合）。对集群训练的启示：① PPO 在万卡集群上的稳定训练依赖 critic 的方差控制，privileged critic 是降低价值估计方差的又一合法手段；② 故障注入训练（fault-injection RL）在训练基础设施容错（如节点故障下的自愈策略）中可直接复用该范式——critic 看「真实故障位图」，actor 只看「可观测的通信超时/重试计数」。

## 三、主线 2：投机解码——批量与多模态场景的结构性瓶颈与解法

### 3.1 ResiSpec：多候选投机采样的「残差漂移」与验证重排

- **来源/标题**: ResiSpec: Enhancing Multi-Candidate Speculative Sampling via Residual Distribution Shaping（arXiv 2608.24411，2026-08-25 提交）— https://arxiv.org/abs/2608.24411
- **要点**:
  - 现象：多候选 SD（multi-candidate speculative sampling）通过提出多样候选集提高 token 接受率，但被 **Residual Drift（残差漂移）** 卡住——初始候选被拒后，残差目标分布偏离草稿模型预测，后续候选失效，被迫进入昂贵的重采样。
  - 方法：ResiSpec 在验证过程中策略性地重塑 proposal 分布，把残差目标质量「锚定」在草稿模型的高置信区；数学上重对齐验证过程且**不牺牲输出精确性**（output exactness）。
  - 结果：相对 SOTA 多候选方法最高 **1.92× 加速**；代码开源（github.com/Czzzk/Resispec）。

### 3.2 AgentSpec：大 batch 下 SD 加速衰减的两大主因与结构隔离草稿

- **来源/标题**: AgentSpec: Speculative Decoding for Batch Inference of LLM Agents（arXiv 2608.24004，2026-08-25 提交）— https://arxiv.org/abs/2608.24004
- **要点**:
  - 问题：LLM agent 应用响应延迟高，SD 是保质量提速手段，但 SOTA SD 算法在**大 batch 下显著降速**，无法用于真实 agent 场景。
  - 系统性归因：两个主导因素——①投机 token 的**高拒绝率**；②**动态 token 预算未充分利用**（under-utilization of dynamic token budgets）。
  - 方法：AgentSpec ①结构隔离草稿（structure-isolated drafting）——把投机限制在 agent 工作流的语义连贯片段内，减少无关语义路径的草稿，拒绝率极低；②冗余感知预算分配（redundancy-aware budget allocation）——利用 agent 级信息更好利用推理中动态空闲的 token 预算。
  - 评测：5 种 workload × 4 个模型族（4 个模型），vLLM 实现，全面优于 SOTA。

### 3.3 LiLiCorr：为 DFlash 块并行草稿恢复联合分布连贯性

- **来源/标题**: LiLiCorr: Lightweight Likelihood Correlation of Parallel Drafts for Speculative Decoding（arXiv 2608.20530，2026-08-20 提交）— https://arxiv.org/abs/2608.20530
- **要点**:
  - 问题：diffusion 风格块头草稿（DFlash）一次前向预测整块未来 token，但按**逐位置边际**训练而非联合块分布——单个 token 合理、整块不连贯。
  - 方法：LiLiCorr 用轻量似然模型关联草稿已产出的逐位置边际分布：每位置保留 top-k 候选并联合处理，产出一个 in 向量和一个 out 向量；相邻候选匹配 = 前者的 out 与后者的 in 余弦相似度高；一次轻量网络前向产出全部向量，配对分数以批量矩阵运算并行计算，仅剩廉价贪心游走是串行。
  - 结果：相对 vanilla DFlash，接受长度在全部 benchmark 提升 9-19%；scoring head 只占块延迟约 2.8%；72 个设置（9 benchmark × 2 目标规模 × greedy/temperature-1 × 6 并发/2 输入长度/3 熵层）中 70 个取得最高吞吐；外推到 10× 训练长度仍保持领先。

### 3.4 FOVEA：多模态 SD 的「按需视觉证据检索」

- **来源/标题**: FOVEA: Focused On-Demand Visual Evidence Adaptation for Cache-Friendly Multimodal Speculative Decoding（arXiv 2608.22883，2026-08-24 提交）— https://arxiv.org/abs/2608.22883
- **要点**:
  - 受控实验发现：视觉需求随任务与解码阶段大幅变化——视觉输入并非越多越好（不足则弱化 grounding，过多则增开销并干扰草稿）。
  - 方法：FOVEA 构建可复用视觉记忆（reusable visual memory），按草稿状态动态检索有界子集；累计质量规则（cumulative-mass rule）决定选多少、选哪些；选中项聚合成视觉读出（visual readout），经轻量门控残差修正融合进草稿隐藏状态——**不把视觉 token 插入自回归上下文**，只修正传给 LM head 的表示。
  - 结果：多个 VLM 主干与多模态 benchmark 上提升接受率与端到端解码速度，相对自回归解码最高 **2.13×**。

### 3.5 多模态 SD 是否就绪于 diffusion 并行草稿？——综述与跨架构实证

- **来源/标题**: Is Multimodal Speculative Decoding Ready for Diffusion-Based Parallel Drafting? A Survey and Empirical Diagnosis（arXiv 2608.20743，2026-08-21 提交）— https://arxiv.org/abs/2608.20743
- **要点**:
  - 背景：块并行生成草稿（DFlash/DSpark，纯文本 LLM 日聊任务最高 3.6× 加速）在文本侧成熟，但多模态侧的适用性未决。
  - 贡献：①以模态为中心（Vision-Language / Video-Language / Audio / VLA）的综述；②统一分类学——把「草稿侧并行度」与「树构建、验证策略」等正交设计解耦；③跨架构实证对比（OCR/VQA/视觉推理/图像描述标准 benchmark，不同并行度）；④现有方法局限、开放挑战与方向。
  - 结论取向：现有多模态 SD 聚焦输入压缩/适配器对齐/候选覆盖/模态特定验证，**块并行生成草稿基本未探索**——这是明确的空白区。

**分析：投机解码的「批量化失效」是集群训练的直接瓶颈**。集群训练优化常被误解为纯训练侧问题，但 RL 后训练（RLVR/OPD）的 rollout 与数据生成管线本质是**大批量推理系统**——TailSieve（08-26 已收录）已证明 rollout 长尾是 makespan 主导因素，本日四篇（ResiSpec/AgentSpec/LiLiCorr/FOVEA）则从 SD 内部机制补全了另一块拼图：**SD 在训练负载下失效不是工程细节，而是算法结构问题**。AgentSpec 的归因最有诊断价值——「高拒绝率 + 动态预算未利用」是批量化场景的普适两因素，前者是草稿与目标分布错配（ResiSpec 的 Residual Drift 是同一现象的另一面），后者是调度器与 token 生命周期解耦（与 Elastic KV Cache 的「prefill reserve 闲置」同构）。三条因果链值得追踪：① 拒绝率 → 验证 batch 中废算占比 → 有效算力利用率（ResiSpec 的 1.92× 说明重采样是隐藏税）；② 预算未利用 → 空闲算力碎片 → 与 KV 弹性回收耦合的系统级浪费（AgentSpec 的冗余感知预算 = 调度器侧解法）；③ 草稿联合性 → 接受长度 → 端到端吞吐（LiLiCorr 证明 2.8% 开销换 9-19% 接受长度是稳赚杠杆）。对训练集群的落地建议：把 SD 视为「训练管线组件」而非「serving 优化」，在 rollout 引擎里同时评估「批量化 SD 算法选择」与「长尾路由」两个杠杆——08-26 的 TailSieve 2.59×（叠加 MTP/DFlash）与今日的 ResiSpec 1.92× 是正交可叠加的。

## 四、主线 3：KV 显存治理——成本轴对比、低秩/混合格式压缩与诚实负结果

### 4.1 More GPUs or a Smaller Cache?：TP 与 KV 压缩的统一成本轴对比

- **来源/标题**: More GPUs or a Smaller Cache? Tensor Parallelism versus KV Compression for Memory-Bound LLM Serving（arXiv 2608.23962，2026-08-25 提交）— https://arxiv.org/abs/2608.23962
- **要点**:
  - 背景：KV 显存告急时有两条路——TP 把权重与 KV 分片到 2/4/8 卡（代价：每层 all-reduce + 硬件账单随卡数增长）；KV 压缩（量化/驱逐）留在单卡（代价：一点质量）。两派各报各的指标（压缩报压缩比、并行报吞吐曲线），**几乎无人把两者放在同一成本轴**。
  - 方法：把 TP（degree 1-8）与 KV 压缩（16/8/4-bit、keep-ratio 低至 0.25）放到统一的「成本归一化轴」（每百万 token 成本 vs 延迟），用 A100/A40/H100 校准的 profiled simulator。
  - 结果：**找不到成本等价交叉点**——2 模型（Llama-2 7B/70B）× 3 GPU × 各级显存缓解下，**压缩恒便宜 1.20-2.00×**。分界线 = 模型规模 vs 设备显存，约 **36B 参数/80GB 卡**：低于此线压缩主导、加卡基本浪费；高于此线 TP 不是选择而是入场券（Llama-2-70B 在任何 KV 设置下单 A100 都不可行，瓶颈是权重，KV 压缩碰不到）。
  - 关键不对称：**TP 是唯一改善延迟的杠杆**（压缩因批处理争用让每 token 延迟变差 8-93%）；**压缩是唯一倍增每美元容量的杠杆**（16.5×，而 8 倍 GPU 花费只换 1.21×）。

### 4.2 PuzzleKV：页级低秩分解——训练/校准全免的 KV 压缩

- **来源/标题**: PuzzleKV: Page-Wise Low-Rank Decomposition for KV Cache Compression（arXiv 2608.23843，2026-08-24 提交）— https://arxiv.org/abs/2608.23843
- **要点**:
  - 观察：把每个 head 的 KV cache 切成固定长度逻辑页后，**单页内部存在显著低秩结构**——既有的低秩方法（固定投影空间/校准激活/共享基）都抓不住这种细粒度结构。
  - 方法：PuzzleKV 把每个完成的页当作独立压缩单元（training- and calibration-free），页内做低秩分解（dense + factorized），自回归解码中增量压缩新到期页。
  - 结果：约 60% 原始存储下达到 Full KV 的 96%+ 性能（两模型×全部 benchmark）；更激进时叠加量化，**18.7% 存储仍保持 93%+ Full KV 性能**；RULER 上显著超 Global SVD，LongBench 上与强基线竞争。

### 4.3 Minima-KV：混合格式分页注意力——FP8 anchor + TQ3 老页

- **来源/标题**: Minima-KV: Retention-Preserving KV Cache Compression with Mixed-Format Paged Attention（arXiv 2608.23834，2026-08-24 提交）— https://arxiv.org/abs/2608.23834
- **要点**:
  - 设计：保留保留性的层级——**近期与受保护的 anchor 页保持 FP8，较老的非 anchor 页打包为 TQ3**；每个存活请求的页保持可寻址；格式专属 kernel 计算部分注意力状态，经全局归一化 online-softmax 合并，实现无 dense shadow 的异构 decode。
  - 结果（Qwen3.6-27B、单 96GB RTX PRO 6000 Blackwell）：每存活 token 注意力 KV 18.3 KiB，相对 BF16 压缩 **3.50×**、相对 FP8 压缩 1.75×；16K RULER needle-in-a-haystack 匹配 dense 对照；LongBench v2（503 题）在 16K/32K/64K 上质量差仅 -0.80/-0.60/-0.40 百分点；59,008 token 双请求直解 canary：3.625× active-KV 压缩、0.9821× 吞吐、16 个全注意力层无回退、无 dense shadow。

### 4.4 Elastic KV Cache：可工作的回收机制 + 诚实的负结果

- **来源/标题**: Elastic KV Cache for LLM Serving: A Working Reclamation Mechanism, and Why Chunked Prefill Already Closes the Gap（arXiv 2608.23658，2026-08-24 提交）— https://arxiv.org/abs/2608.23658
- **要点**:
  - 机制：serving 引擎启动时为最坏 prefill activation 预留 reserve，decode 主导期闲置。Elastic KV cache 把 reserve 在 decode 期借给 KV 池、prefill 前归还，由调度器的一步前瞻驱动；纯用户态 CUDA 虚拟内存路径（每层两个物理 handle 映射进一个连续虚拟区间），attention kernel 不变、无需驱动补丁；decommit 几毫秒、recommit 几十毫秒，兼容 CUDA graphs 与 prefix caching，从不触发 OOM。静态提交同样内存是不安全的（prefill 突发会崩），动态切换是必须的。
  - **诚实负结果**：该机制只在「小 prefill chunk 严重伤害 prefill 延迟」时才有回报。受控实验（向活跃 decode 负载注入长 prompt）中该惩罚很小——8192 与 32768 chunk 的 TTFT 中位数仅差约 1%，因为 prefill 是计算密集而 decode 每序列每步只消费约 1 个 token。直接调低 max_num_batched_tokens 能回收比控制器更多的 KV，延迟几乎相同。reserve 还会被 TP 稀释：TP1 时占 KV 16%，TP4 时只剩 2.7%。论文精确给出了「回收 reserve 何时仍有价值」的条件，并把机制作为可复用用户态 elastic-VMM allocator 开源。

### 4.5 Memory-Sovereign Inference：存储后备推理的「可证伪证书」

- **来源/标题**: Memory-Sovereign Inference: Output-Exact Execution Beyond Full Residency（arXiv 2608.23805，2026-08-24 提交）— https://arxiv.org/abs/2608.23805
- **要点**:
  - 问题：存储后备推理（storage-backed inference）易被夸大——进程 RSS 不含计费的 page cache、进程本地设备读数不含板级用量、成功生成不能证明异步复用正确。论文给出**可证伪证书**：分离表示/语义需求/调度器请求/流量，并命名资源权威、精确性视界与测试过的复用转换。
  - 数据（Qwen3-Next 单身份）：stock router 在 32K prefill 选择全部 48×512 受管 layer-expert 对象；去重去交叠的规范并集给出 **43.59375 GiB 语义需求下界**，超过声明的 34 GiB 全驻留信封与 11 GiB host-hard + 24 GiB 物理设备信封。LRU64 执行保持在 host-hard/GPU 审计契约内。
  - 精确性：相对预指定零缓存 oracle，64 个 token ID、64 个完整 151,936 浮点 logit 行的每个字节、3,408 个路由事件、响应字节、记录的 consumer/destination 身份全部精确。
  - 对比：匹配的 source campaign 中，缓冲路径精确完成但撞 11 GiB host 上限并记录 33,481 次 memory.max 事件；阻塞单窗口直通路径与完整八窗口异步组件以正余量精确完成、零限制事件；6 个平衡对中，完整异步组件墙钟时间仅为阻塞直通路径的 32.3%（同物理源字节/输出）。

### 4.6 VisCache 与 HAP：视觉侧 KV/token 剪枝

- **来源/标题**: VisCache: Visual KV Cache Pruning for Efficient Vision Large Language Model Inference（arXiv 2608.24063，2026-08-25 提交）— https://arxiv.org/abs/2608.24063
- **要点**:
  - VisCache：免训练两阶段视觉 KV 剪枝——轻量 VLM 过滤时间冗余（选择性转发语义信息关键帧）+ PruneKV 外科手术式 KV 压缩（抛物线逐层预算分配 + 不对称更新：选择性剪 key 同时融合 value）。
  - 结果：最高 **2.35× 加速**、显著显存下降，仅 **19-28% KV 保留**即保持竞争性能，建立新的效率-性能 Pareto 前沿；代码开源（github.com/Wlklk/VisCache）。
- **来源/标题**: HAP: Head-Adaptive Visual Token Pruning via Cross-Modal Alignment（arXiv 2608.23921，2026-08-24 提交）— https://arxiv.org/abs/2608.23921
- **要点**:
  - 洞察：现有视觉 token 剪枝把 text-to-visual attention 在所有 head 上均匀平均打分，但**错位 head 主导平均**，放大背景 token、淹没细粒度线索。
  - 方法：PAQ（Prompt-Grounded Attention Quality）量化每个 head 把 prompt 与图像区域对齐的程度；基于 PAQ 三阶段剪枝：按目标 FLOPs 预算分层分组分配视觉 token 预算 → 组内用 PAQ 加权 softmax 聚合每 head attention → 按聚合矩阵幅度打分并保留预算。
  - 结果：18 benchmark 上 SOTA 权衡——LLaVA-1.5-7B（9 任务）仅保留 **5.6% token 保持 99.1% 原始性能**，超最强基线 AutoPrune 4.2 分；代码开源（github.com/baokou-fw2/HAP）。

**分析：KV 治理的「成本轴思维」与「诚实负结果」方法论价值**。三篇（4.1/4.4/4.5）合起来构成本日最具方法论分量的信号：**系统优化论文开始报告「统一成本轴」与「负结果」**。More GPUs or Smaller Cache 的 36B/80GB 分界线是一个可操作的决策规则——它把「加卡 vs 压缩」从经验选择变成参数量/显存的函数；其「TP 只改善延迟、压缩只倍增容量/美元」的不对称性，直接解释了为什么生产集群里两类手段并存而非替代。Elastic KV Cache 的负结果更有示范意义：机制本身成立（毫秒级 decommit）、前提却已被 chunked prefill 提前满足（TTFT 仅差 1%）——**这类「机制正确但收益被既有技术吸收」的结论，比又一个正结果更能省下工程试错成本**；其 TP 稀释数据（16%→2.7%）提醒：任何 per-GPU 预留型优化在 TP≥4 的集群上都会自然失效。Memory-Sovereign 的证书框架则把「存储后备推理」的验收从「跑通了」升级为「可证伪的契约审计」——对训练集群的 checkpoint/offload（如优化器状态 offload 到 CPU/盘）同样适用：RSS/设备读数口径、语义需求下界、精确性视界这三件套可直接迁移为 offload 验收标准。

## 五、主线 4：Checkpoint/执行编辑的形式化安全语义

### 5.1 When Can Agents Safely Checkpoint, Fork, Restore, and Merge?

- **来源/标题**: When Can Agents Safely Checkpoint, Fork, Restore, and Merge? Exact Checking for Execution Edits（arXiv 2608.22928，2026-08-24 提交）— https://arxiv.org/abs/2608.22928
- **要点**:
  - 问题：agent runtime 支持 Checkpoint（记录执行）/Fork/Restore/Merge 等「执行编辑」，但一次编辑**不能撤销已发出的授权或已发出的工具请求**——不安全的编辑可能重复授权同一工具动作、丢弃任务仍需的结果、或与编辑前已开始的调用冲突。agent 不可信，runtime 必须用执行记录判定「编辑必须为哪些历史动作负责、必须保留哪些必需结果」。
  - 方法：给出精确判定「编辑是否安全」的算法——枚举任务在不违反策略下可完成的所有路径，移除任何会使「仍必需结果」无法完成的方式；若无剩余则返回「不存在安全实现」的可检查证明；否则剩余方式精确描述 runtime 可允许的内容。覆盖 Checkpoint 与 6 种 Fork/Restore/Merge 形式，含扩展、原子强制与精确检查器所需信息。
  - 形式化：Lean 机械化有限检查器与 runtime 不变量，测试验证全部 6 种编辑形式；源码与 Lean 证明开源（github.com/eunomia-bpf/agent-check-restore-safety）。

**分析：从「保存-恢复」到「执行编辑的语义不变量」——checkpoint 的契约思维**。训练系统的 checkpoint 传统上只回答「能否恢复到某个权重快照」，本文把问题升级为「**在不可信执行者 + 不可撤销副作用（已发授权/已发请求）下，哪些编辑是安全的**」。这个框架对训练基础设施有三点迁移价值：① **断点续训的安全语义**——分布式训练里 checkpoint 恢复涉及已发出的梯度通信、已提交的 NCCL 集合操作、已写盘的日志，恢复点必须「保留未消费结果、不重复副作用」，与本文的「不能撤销已发授权」同构；② **容错自愈的验证工具**——Lean 机械化证明提示：训练系统最危险的恢复路径（如 FSDP shard 重分布、通信域重建）可以用形式化不变量做静态检查，而不是靠故障演练碰运气；③ **agentic 训练运维**——当训练运维脚本本身变成 agent（自动诊断-恢复-调参），「fork/merge 训练分支」的安全语义（如 A/B 实验分支合并）会成为新的系统问题，本文是首个精确语义。

## 六、主线 5：MLSys 2026 FlashInfer Contest——kernel 优化的工业化分工

### 6.1 Agentic Kernel Optimization：19 亿 agent tokens 生成 SOTA kernel

- **来源/标题**: Agentic Kernel Optimization: Generating State-of-the-Art GPU Kernels Without Hand-Written CUDA（arXiv 2608.14560，2026-05-25 提交）— https://arxiv.org/abs/2608.14560
- **要点**:
  - 实验：通用代码 agent 能否零手写 CUDA 生成 SOTA GPU kernel？负载 = FlashInfer-Bench 的 Fused MoE / DSA TopK Indexer / DSA Sparse Attention；NVIDIA B200；correctness-gated FlashInfer-Bench 协议。
  - 方法：Houmao 多 agent 编排框架（异构编码 agent），人类严格只做编排（定义工作流、强制正确性与反作弊约束、提供关键参考、停滞时重定向），不审查/不编辑 kernel 代码。
  - 结果：约 19 亿 agent tokens 后，相对 PyTorch 参考：Fused MoE **92.68×**、DSA TopK Indexer **1101.02×**、DSA Sparse Attention **181.35×**，且全面超 FlashInfer 基线；MLSys 2026 FlashInfer Contest 官方评测中，生成的 Fused MoE kernel 相对 FlashInfer 基线 **1.71×**，超过 agent-assisted 赛道第一名（1.68×）。

### 6.2 Harness Engineering：Agent-Assisted 全面优于 Full-Agent

- **来源/标题**: Harness Engineering for LLM-Driven GPU Kernel Generation（arXiv 2607.17979，2026-07-20 提交）— https://arxiv.org/abs/2607.17979
- **要点**:
  - 系统：分离「评估 harness」与「profile 支撑的优化控制器」——harness 强制编译/正确性/官方对齐计时/工件归档；控制器把 profiler 与负载证据转为有界候选生成决策；人类编写 skills 捕获算子约束、参考、profile 流程与晋升规则；Codex + Claude Code agent 在约束内生成候选 kernel。
  - 结果（MLSys 2026 FlashInfer Contest，NVIDIA Blackwell B200）：5 个算子定义上，保留的官方对齐工件相对 FlashInfer 基线平均延迟加速 **1.62× / 18.05× / 29.68× / 1.12× / 13.70×**；**Agent-Assisted kernel 全面优于 Full-Agent 工件**——专家提供的优化方向、高质量参考与负载上下文对可靠 AI 驱动 kernel 优化仍是关键。

### 6.3 AI-Assisted Gated DeltaNet Optimization on NVIDIA Blackwell

- **来源/标题**: Technical Report: AI-Assisted Gated DeltaNet Optimization on NVIDIA Blackwell（arXiv 2607.16831，2026-07-18 提交）— https://arxiv.org/abs/2607.16831

### 6.4 MLSYSIM：第一性原理的基础设施建模框架

- **来源/标题**: MLSYSIM: First-Principles Infrastructure Modeling for Machine Learning Systems（arXiv 2607.02558，2026-06-28 提交；DBLP CoRR 收录 abs/2607.02558）— https://arxiv.org/abs/2607.02558
- **要点**:
  - 动机：ML 系统跨度从亚毫瓦 MCU 到多吉瓦数据中心，实证 profiling 需要硬件在手，cycle-accurate 仿真每配置数小时——缺「快速全栈架构推理」工具。
  - 方法：第一性原理解析框架，把「系统的物理」形式化为**维度严格（dimensionally-strict）的 Python 引擎**；需求-供给抽象（demand-supply）解耦计算需求与硅供给/环境上下文；运行时强制单位完整性（静默换算错误不可能发生）；每个输入来自带类型、带溯源追踪的注册表（无来源数字无法进入分析）。
