## 🆕 本组增量：训练主线（4 条核心）

### 1. DTX：Throughput-First 训练加速器（2608.16953, 08-16, cs.AR）

- **来源/标题**: DTX: A Throughput-First Training Accelerator for Diffusion and Transformer Models（arXiv:2608.16953, 2026-08-16 提交）
- **核心主张**: 任何经由单个 FP32 加法器串行化的求和都是 loop-carried 依赖，会把机器钉死在 ~2 FLOP/cycle；DTX 的设计原则是**全芯片不存在任何此类串行链**——每个 reduction 都是流水线化二叉树的，每个 FP 算子都是两段流水、initiation interval = 1
- **量化数据**: 8×8 weight-stationary 脉动阵列（融合 bias/activation/cast epilogue）+ 8-lane 向量单元 + 8-lane 融合 AdamW 流水线 + 流水化 Philox 高斯源，由 4-slot VLIW 在统一 64 KB tile 空间联合发射 → **216 FLOP/cycle，约为 loop-carried 下限的 108 倍**；sky130 工艺流片验证脉动阵列 DRC-clean GDS 达 83.3 MHz post-route（对比同工艺节点优化 loop-carried MAC 基线快 1.9 倍）；解析式 iso-node 分解预估**每瓦吞吐比 GPU 高 6-10 倍**；on-device diffusion-MLP 运行 loss 从 56.4 降至 26.0（语义门控确认训练有效）
- **验证方法学亮点**: 无规范求和顺序 → 以 FP64 golden model 做容差验证，并保留 exact-equality 豁免；17/17 测试、107,108 元素零失败；违反前提的程序实测超预算 5,340 倍——说明验证边界设计本身可被攻击者探测
- URL: https://arxiv.org/abs/2608.16953

### 2. DepTGL：数据依赖感知的并行 TGNN 训练（2608.16305, 08-17）

- **来源/标题**: DepTGL: A Parallel Framework for Memory-based TGNN Training with Adaptive Temporal Data Dependency Management（arXiv:2608.16305, 2026-08-17）
- **问题**: 基于记忆的时间图神经网络（M-TGNN）维持递归更新的节点状态，现有分布式框架缺乏时间数据依赖管理机制——被迫严格按时间序更新，远程同步开销大，且时间事件流偏斜时负载严重失衡
- **方案三件套**: ① 混合时间依赖管理（时间事件缓存显式平衡通信与缓存开销 + 选择性依赖驱动通信）；② 梯度感知缓存同步策略（模型优化稳定后自适应抑制边界更新，减少冗余同步）；③ 负载感知时间剪枝（偏斜负载尖峰下消除辅助回放事件，缓解 straggler 效应）
- **量化数据**: 6 个真实时间图数据集上平均较 SOTA 基线提速 **4.99 倍**，精度保持可比
- **训练集群意义**: 时间/顺序依赖类模型（图神经网络、强化学习时序回放、增量学习）在分布式训练中常被当作"普通数据并行"处理而牺牲正确性/效率，DepTGL 给出"依赖管理显式化"的通用范式——对超节点集群中混合负载（既有稠密 Transformer 训练又有图/时序模型）的调度器设计有借鉴价值
- URL: https://arxiv.org/abs/2608.16305

### 3. BSR：有界状态恢复——把"恢复本地容量"与"外部 LLM 状态"解耦（2608.17826, 08-18）

- **来源/标题**: Bounded-State Restoration: Decoupling Local Restore Capacity from External LLM State（arXiv:2608.17826, 2026-08-18, 16 页 8 图）
- **核心概念**: 分层 KV cache 系统可把长上下文 LLM 执行状态保留在 GPU 内存之外，但"保留容量"并不决定"使其可执行所需的本地内存"——论文把后者隔离为**恢复工作集 RWS（Restoration Working Set）**，即恢复期间生命周期重叠的峰值本地暂存状态
- **量化数据（DeepSeek-V4-Flash, TP=2, 双 DGX Spark 节点实测）**: 无恢复扫描将外部状态从 1.956 扩展到 31.277 GiB/rank，而 W=32 时实测 L1 RWS 恒定 500.75 MiB/rank → **外部状态/活动暂存比高达 63.959 倍**；第二次全新 524K token 运行复现最大状态接受结果；SSD 优化将 512K restore TTFT 从 43.1 秒降至 17.6 秒且不改变 RWS
- **机制**: BSR 把"完整发现"与"本地驻留"分离——先探测完整可复用前缀而不在 L1 实体化整个命中，再通过至多 W 个 chunk 的可复用窗口安装已确认状态；请求级提交规则保证部分安装永不暴露为有效可复用前缀，失败时失效广告前缀并回退到更低有效层级或确定性重算
- **训练集群意义**: 长上下文训练/微调与 PD 分离部署中，KV 状态恢复（容错、session 迁移、rollout 续跑）的本地内存需求长期被忽视——BSR 给出"恢复成本与状态大小解耦"的理论上界（O(W) 峰值、Θ(|S|) 总传输），是 checkpoint/恢复子系统设计的新自由度
- URL: https://arxiv.org/abs/2608.17826

### 4. H100 并发负载响应实测：LDG 带宽的"过犹不及"现象（2608.15764, 08-16）

- **来源/标题**: Concurrency Response of Plain Global Loads on the NVIDIA H100（arXiv:2608.15764, 2026-08-16, 12 页 8 图, 三块 H100 80GB HBM3 SXM5 die 实测）
- **主结果**: 普通全局加载（LDG）路径的带宽在**很小的人均线程负载（K≈2）即达峰，之后下降约 35%**（K=2→8, 主配置）；下降在固定工作负载控制（K 间总逻辑加载数匹配）、升/降序扫描、双 die 复现（-35.0% / -35.2%）下均存活
- **机制线索**: 计数器显示 K=2→8 期间 DRAM 字节几乎不变而 L2-sector 流量上升；分配大小扫描（512MB→20GB, 均超 ~50MB L2）不改变下降，排除简单分配大小依赖；L2 命中率随 K 上升 → 聚合请求流确实随 K 变化，论文把 K 报告为"提供的软件 ILP"，硬件机制留作开放问题
- **补充测量**: async copy 对 plain load 在高峰提供深度下快 **2.1-2.9 倍**（双 die）；die-B 同 CTA 双流观测在 die-C 未复现（未合并统计）
- **训练集群意义**: memory-bound kernel（如 Attention/Softmax/归一化、KV 搬运、activation offload）的线程级并发配置存在**非单调最优**——过度 ILP 反而掉带宽；这是对"更多并发=更好"直觉的直接证伪，对超节点集群 kernel 调优（CUDA graph 捕获时的线程块配置、sparse attention 预取）提供反直觉的实测约束
- URL: https://arxiv.org/abs/2608.15764

## 📊 深度分析（5 段）

### 分析一：训练优化进入"加速器-系统-算法"三层同构期——DTX 是第一性原理训练硬件宣言

DTX 的核心贡献不是又一个 systolic array，而是把 Amdahl 定律的对手从"并行度"改写为"串行链"。任何经单 FP32 加法器串行化的求和，无论物理设计多先进，都把机器钉在 ~2 FLOP/cycle——这是数据依赖层面的硬下界，与工艺无关。DTX 的回应是结构性消除：所有 reduction 流水线化、所有 FP 算子两段流水且 initiation interval=1、连优化器（AdamW）和高斯采样（Philox）都做成流水线单元，最后用 4-slot VLIW 统一发射。216 FLOP/cycle ≈ 108 倍 loop-carried 下限，恰好说明"消除串行依赖"比"堆更多 MAC"更接近训练吞吐的本质瓶颈。把这条逻辑映射到集群层面：**万卡训练集群的 MFU 损失同样来自串行链**——pipeline bubble 是 stage 间串行依赖，AllReduce 等待是梯度依赖，checkpoint 冻结是训练/保存串行。DTX 提示的优化原则是"把每个串行环节转成流水线化的重叠结构"，这与 KV-Pipe（已收录 ai-frameworks 08-19）用 KV 共享把 PP stage 不平衡变成平衡旋钮、StateFlow（已收录本组 08-15）用序列级 pipeline 重叠状态传播是同一思想的三个实例化。值得注意 DTX 的验证方法学——FP64 golden + 容差 + exact-equality 豁免 + 反例探测（违反前提程序超预算 5,340 倍）——本身就是"AI 时代硬件正确性验收"的可复用模板，与 08-14 Contract-Grade Verifier（2608.12700, 已收录）呼应。

### 分析二：投机解码正从"推理优化技巧"演化为"训练集群基础设施"——三条证据链

第一，RL 后训练（RLHF/RLVR）的 rollout 阶段本质上是推理负载，而 rollout 通常占用 30-60% 的集群 GPU 时间——投机解码的 1.5-9.7 倍加速直接折算为训练迭代周期缩短。第二，本窗口的机制进展集中在"跳过/剪枝"而非"更快草稿"：Verifier Skipping 证明**调用验证器本身可以被跳过**（省 9.6-13.5% 调用），LibraSpec 把投机长度从"猜"变为"边际收益优化"，二者共同指向投机解码从"草稿质量竞赛"转向"验证成本治理"——这与 KV cache 治理从"压缩省内存"转向"生命周期管理"（ai-frameworks 08-19 分析一）是同一范式迁移在解码侧的表现。第三，投机解码开始反向供给训练系统：OasisKV（已收录 08-13）用投机解码的 lookahead tokens 预测未来重要 KV 块做预取，BSR（本篇）把恢复窗口与投机/预取机制结合——**草稿 token 不再是推理专属，而成为内存调度的预测信号**。对集群训练运营者，这意味着 rollout 侧的投机配置（draft 模型选择、投机长度、验证器跳过策略）应从"推理参数"提升为"训练调度参数"，纳入集群资源编排的优化变量。

### 分析三：KV 治理主线收敛后，训练侧增量向"恢复语义"与"硬件行为"两个缺口转移

08-16~08-17 的 7 篇 KV 论文已被 ai-frameworks 08-19 以"生命周期管理"框架收割（Pallas 主动迁移 / GraniKV 非对称粒度 / DeltaLog 延迟物化 / KV-Rescue 驱逐恢复 / Q-First 子层交换 / KV-Pipe 训练侧）。本日窗口的真实增量不在 KV 本身，而在两个被 KV 讨论遮蔽的缺口：**恢复语义**与**硬件行为**。恢复语义缺口由 BSR 填补——它把"恢复需要多少本地内存"从"外部状态有多大"中独立出来，给出 O(W) 峰值 / Θ(|S|) 总传输的理论分离，直接服务长上下文训练的容错恢复与 PD 分离下的 session 续跑；这修正了一个隐含假设：此前 checkpoint/恢复系统的资源规划都以"状态大小"为基准，BSR 证明**应以恢复工作集（RWS）为基准**，且 RWS 可通过窗口 W 显式有界。硬件行为缺口由 H100 并发响应实测填补——LDG 带宽随每线程 ILP 非单调（K=2 峰值后 -35%），说明 memory-bound kernel 的"线程越多越好"直觉在 Hopper 上不成立；这类 clean-room 微基准对超节点集群的意义在于：**kernel 配置（线程块大小、ILP 深度、async copy 与 plain load 的路径选择）存在可测的最优曲面**，且不同 die 间行为可复现（-35.0%/-35.2%），值得纳入集群性能调优的标准化测量集。

### 分析四：HBF/近存计算三条证据线汇合——训练集群的存储层次正在重定价

HBF 主题在本窗口出现密度异常：Beyond Capacity（HBF 直连 GPU/HBM 路径, 08-17）、Exploring HBF（CAL 探索篇, 08-17）、HBF Sucks（全栈表征, 08-16 提交）、MoE ReRAM NDP（08-17），加上 08-06 的 PLoRA（NDP 池化内存）与 OasisKV（KV 出 HBM）——**"把容量型数据从 HBM 挪出去"已成为系统社区共识方向**，争论只剩"挪到哪（HBF/ReRAM/CXL/NVLink 池）+ 以什么粒度（块/页/专家/恢复窗口）"。对训练集群的映射：训练侧最大的容量型数据是 checkpoint（百 GB-TB 级）与激活 offload（滚动窗口），其次是 KV（RL rollout 侧）；HBF 的高带宽顺序读特性与 checkpoint 的"大块顺序写读"模式天然匹配，但训练写频率远高于推理（每 N 步一轮 checkpoint），写放大与寿命预算必须纳入选型；MoE ReRAM NDP 则指向另一个自由度——**计算下沉到数据侧**，专家/适配器参数不再搬运，这与 08-15 已收录的 "Beyond Capacity" 在数据放置哲学上殊途同归。综合判断：未来 1-2 个季度，HBF 类介质的集群级评测（训练侧 checkpoint 吞吐、故障恢复 RTO）将是本专题值得跟踪的未饱和方向。

### 分析五：本窗口增量对超节点集群的落地映射（RAS × 调度 × 存储三线）

把本日 12 条增量放到超节点集群（万卡级、HVDC/液冷、RAS 体系）的运营视角下，可提炼三条可直接转化为工程动作的映射：

**RAS/容错线 → 恢复工作集（RWS）作为新容量规划单位**。当前集群的 checkpoint 与故障恢复规划以"状态体积"（GB/TB）为基准：故障后需多久恢复、恢复时需多少本地暂存，都由 checkpoint 大小决定。BSR 证明恢复所需本地峰值可独立有界（O(W) 窗口），且 512K 上下文场景下 SSD 优化把恢复 TTFT 从 43.1s 压到 17.6s（-59%）——这意味着**恢复 RTO 不再与模型规模线性挂钩**，长上下文训练的容错成本曲线被改写。工程动作：RAS 子系统评估将"恢复工作集"纳入节点资源预留模型，替代或补充"checkpoint 体积"维度；对 RL rollout 的 session 续跑，BSR 式前缀探测+窗口安装可直接降低热迁移内存需求。

**调度线 → 数据依赖显式化与 rollout 投机配置入调度**。DepTGL 对时间依赖类模型的"依赖管理显式化"范式，提示混合负载集群（Transformer 训练 + 图/时序模型 + RL rollout）的调度器不应把负载当作同质 batch；投机解码的三条进展（LibraSpec 动态长度 / Verifier Skipping 跳过验证 / S2-MoE 专家复用）则把 rollout 侧的 GPU 效率从"推理参数"提升为"训练调度变量"——集群调度器可将 draft 模型驻留、投机长度分布、验证器跳过策略纳入资源编排优化（如 LibraSpec 的边际判据可直接作为 GPU 分配的目标函数分量）。

**存储线 → HBF/近存介质进入训练存储候选清单**。checkpoint 的大块顺序写读模式与 HBF 高带宽特性匹配，但训练写频率（每 N 步一轮）远高于推理，写放大与寿命（TBW）必须专门评测；MoE ReRAM NDP 与 PLoRA 则示范"计算下沉到数据侧"如何把参数搬运换成就地执行。工程动作：存储选型评估矩阵增加"训练负载"列（checkpoint 吞吐、恢复 RTO、写寿命预算），与已收录的 HBF Sucks 全栈表征（tech 08-14）形成评测闭环。

**H100 并发响应实测则横切三条线**：memory-bound kernel 的 ILP 非单调最优意味着——无论 RAS 的恢复搬运、调度的 rollout 解码、还是存储的数据搬移，kernel 层配置都存在可测最优曲面，且跨 die 可复现（-35.0%/-35.2%），应纳入集群 kernel 调优基准集。

## 📌 趋势判断

4. **HBF/近存计算从"推理存储"扩展为"训练存储"候选**：checkpoint 大块顺序读写与 HBF 特性匹配，但写放大/寿命需训练负载专门评测——未来 1-2 季度跟踪其集群级评测（checkpoint 吞吐、恢复 RTO、TBW 预算）
5. **投机解码的"验证成本治理"范式与 KV"生命周期管理"范式同构**：本专题下一轮观察锚点：投机解码是否出现"跳过/剪枝"与"KV 分层"的联合优化系统（BSR 已露出苗头）
