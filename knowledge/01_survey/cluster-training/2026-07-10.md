## 1. 🏗️ 大规模分布式训练并行策略

### 1.1 DynaTrain: 子秒级在线并行切换的弹性 LLM 训练（重点 ⭐⭐⭐🔥）

- **作者**: Yuanqing Wang, Yuchen Zhang, Hao Lin, Junhao Hu, Chunyang Zhu, Quanlu Zhang, Boxun Li, Guohao Dai, Zhi Yang, Daning Cheng, Yunquan Zhang, Yu Wang
- **来源**: arXiv:2605.18815 (cs.LG, cs.DC), 提交 2026-05-12
- **核心问题**: LLM 训练本质动态——资源波动、RLHF 阶段切换、集群弹性持续改变最优并行布局，现有训练框架基于静态执行模型，重配置需 checkpoint-save→restart→load 耗费数分钟到数十分钟
- **核心技术: DynaTrain**:
  1. **Virtual Parameter Space (VPS)**: 将所有分布式训练状态统一到一个逻辑坐标空间——任何并行配置都是确定性映射，复杂的配置转换坍缩为可处理的几何交集
  2. **状态路由与转换层**: 在 VPS 之上执行 rank-local 转换，在内存感知+无死锁调度下传输状态
  3. **弹性设备管理器**: 用新世界构建与训练重叠来隐藏拓扑变更成本
- **关键数据**:
  - **70B 稠密模型重配置 <2 秒**，**235B MoE 模型 4.36 秒**
  - 比基于 checkpoint 的弹性系统快 **3 个数量级**
  - 在 dense/MoE 模型上验证到 235B 参数规模
- **意义**: DynaTrain 与 ReMP（06-28 跟踪，运行时切换）和 MoP（07-07 跟踪，初始并行编排）互补——**MoP 解决"初始最优"、ReMP 解决"运行时重配"、DynaTrain 解决"任意配置间在线无缝切换"**。DynaTrain 的 **VPS 抽象是统一定义所有并行策略的数学语言**，对弹性训练/RLHF 阶段变更/故障后重配等场景有深远影响。[代码开源](https://github.com/infinigence/ElasticMegatron)

### 1.2 SPARe: 面向 100k+ GPU 的堆叠并行与自适应重排序（重点 ⭐⭐⭐🔥）

- **作者**: Jin Lee, Zhonghao Chen, Xuhang He, Robert Underwood, Bogdan Nicolae, Franck Cappello, Xiaoyi Lu, Sheng Di, Zheng Zhang
- **来源**: arXiv:2603.00357 (cs.DC) · **ICML 2026**，提交 2026-02-27
- **核心问题**: 100k+ GPU 的 LLM 预训练系统中，故障成为常态而非例外，重启成本主导 wall-clock 训练时间。现有容错机制在重启主导场景下几乎无效
- **核心技术: SPARe**:
  1. **Stacked Parallelism**: 在梯度同步期间跨并行组堆叠冗余数据分片来屏蔽节点故障
  2. **Adaptive Reordering**: 自适应重排序执行以匹配可用节点拓扑
  3. **联合优化**: 冗余度和 checkpoint 频率联合优化最小化 time-to-train (TTA)
- **关键数据**:
  - **600k GPU 极端规模下 TTA 减少 40-50%** vs 传统复制
  - 计算开销保持在 **2-3× 常数**（传统复制随冗余线性膨胀）
  - 给出可承受故障数的封闭形式表达式
- **意义**: **SC '23 集群 19.4% GPU 故障率 + 65.4% 作业失败率**背景下，SPARe 是第一篇系统性设计重启主导极端规模容错方案的工作。其核心洞察——**不复用 checkpoint（慢）也不做完全复制（贵），而是利用并行组内冗余分片在同步阶段透明屏蔽故障**——为百卡→万卡→十万卡跨越提供了可行的容错路径。[ICML 2026]

### 1.3 FlowTrain: 流式解耦 VLM 训练（重点 ⭐⭐）

- **作者**: Zhida Jiang, Zhaolong Xing, Yang Pei, Xiaolong Chen, Yuanhang Xiao, Chengzhi Huang 等
- **来源**: arXiv:2606.23087 (cs.LG), 提交 2026-06-22
- **核心问题**: 工业级 VLM 分布式训练比单模态 LLM 效率低得多——现有方案要么对异构模块统一分配并行策略，要么解耦部署但按批同步 pipeline 执行，都未充分利用 VLM 的异构特性
- **核心技术: FlowTrain**:
  1. **流式解耦数据流**: 将 VLM 训练重构为生产者-消费者数据流，通过统一内存池协调——编码器和 backbone 在全局虚拟地址空间上独立推进
  2. **异构并行分配器**: 通过求解吞吐匹配问题为各模块分配定制并行策略
  3. **动态打包调度器**: 根据实际 LLM 端计算代价在运行时构建平衡的微批次
- **关键数据**:
  - **MFU >50%**（对齐 LLM-only 训练效率）
  - 吞吐 **1.7×** 提升 vs SOTA VLM 训练
  - 真实工作负载验证
- **意义**: VLM 培训正在成为超节点集群核心工作负载（GPT-4o 级别模型需要）。FlowTrain 的**执行解耦改变了分配和调度的优化目标**，其 "producer-consumer 数据流" 概念为跨模态训练提供了新范式

### 1.4 FoMoE: 打破全副本屏障——MoE 联邦训练（重点 ⭐⭐）

- **作者**: Lorenzo Sani, Zeyu Cao, Meghdad Kurmanji, Alex Iacob, Andrej Jovanovic, Yan Gao, Wanru Zhao, Nicholas D. Lane
- **来源**: arXiv:2606.19025 (cs.LG, cs.AI, cs.DC), 提交 2026-06-17
- **核心问题**: MoE 模型有稀疏数据路径，但分布式训练基础设施仍假设完全复制——每个站点都要保留完整模型副本。低通信方法（DiLoCo/Photon）减少同步频率却仍需完整副本
- **核心技术: FoMoE**:
  1. **专家层跨 Worker 分区**: 本地训练跳过非驻留专家，只在必要时传输
  2. **Skip-token 机制**: 对不属于本地专家的 tokens 跳过计算，提升吞吐
  3. **部分专家复制**: 在受控条件下选择性复制高负载专家
- **关键数据**:
  - 通信减少 **1.42×** vs 高效基线（DiLoCo），**45.44×** vs DDP
  - 经验吞吐加速 **1.4×**
  - 系统建模外推到 100B 级配置
- **意义**: FoMoE 打破了"每节点必须持全模型副本"的隐含假设——**这类似参数服务器思路但适用于 MoE 的稀疏特性**。对跨地理松散耦合 GPU 集群（低带宽）的 MoE 训练尤其重要，与 DiLoCo 思路互补（DiLoCo 减少同步频率，FoMoE 减少每同步的数据量）

## 2. 🧠 Speculative Decoding & KV Cache 优化

### 2.1 Dustin: 长上下文推测解码的稀疏验证框架（重点 ⭐⭐🔥）

- **作者**: WenHung Lee, Jian-Jia Chen, Xiaolin Lin, Pei-Shuo Wang, Chi-Chih Chang, Chun-Che Yang 等
- **来源**: arXiv:2606.24957 (cs.CL, cs.LG) · **ICML 2026**，提交 2026-06-23
- **核心问题**: 长上下文 LLM 的推测解码中，验证阶段 KV Cache 加载主导延迟。现有压缩方法要么静态 eviction 因 saliency shift 损失精度，要么动态选择引入高计算开销
- **核心技术: Dustin**:
  1. **Lookahead 信号融合**: 结合 draft 模型的 lookahead 信号与目标模型的历史注意力，在多步验证窗口中高保真识别关键 tokens
  2. **稀疏估计**: 限制重要性评分到最小注意力头子集，减少重计算延迟
- **关键数据**（Qwen2.5-72B @ 32K）:
  - self-attention 加速 **27.85×**
  - 端到端解码加速 **9.17×**
  - 精度损失可忽略
- **意义**: 长上下文场景下 KV Cache 已成为推测解码验证的主要瓶颈。Dustin 的核心洞察——**draft 模型的推测信号可以作为注意力稀疏性的自然指引**——这是 KV 压缩与推测解码的深层融合。ICML 2026 录用验证了其价值

### 2.2 VeriCache: 有损 KV Cache 无损化（重点 ⭐⭐）

- **作者**: Jiayi Yao, Samuel Shen, Kuntai Du, Shaoting Feng, Dongjoo Seo, Rui Zhang 等
- **来源**: arXiv:2605.17613 (cs.AR, cs.LG), 提交 2026-05-17
- **核心问题**: 几乎所有 KV Cache 压缩方法（token dropping/量化）都是有损的——短输出影响小，但长输出中输出逐渐偏离全 KV 解码，最终导致代码生成/tool calling 灾难性失败
- **核心技术: VeriCache**:
  1. **压缩 KV 作 draft → 全 KV 并行验证**: 将压缩/量化 KV Cache 视为 draft，验证正确性
  2. **关键优化**: 压缩 KV 解码（HBM 带宽瓶颈）与全 KV swap（PCIe/网络瓶颈）**不同类型瓶颈可并行**；压缩 KV 输出接近全 KV，长 drafting 窗口分摊每次 swap 开销
- **关键数据**:
  - **4×** 高吞吐 vs 全 KV 推理，**输出完全相同**
  - 支持 token dropping 和量化方法的统一压缩接口
  - 与传统推测解码可组合
- **意义**: VeriCache 解决了张量化/丢弃 KV Cache 的"不可信"问题——**"你想快，但你不能错"**。其核心洞察——压缩解码和 full-KV swap 利用不同资源瓶颈（HBM vs PCIe/网络）实现重叠——是系统级的精巧设计

### 2.3 Nightjar: 资源感知自适应推测解码（重点 ⭐）

- **作者**: Rui Li, Zhaoning Zhang, Libo Zhang, Huaimin Wang, Xiang Fu, Zhiquan Lai
- **来源**: arXiv:2512.22420 (cs.DC, cs.AI), 提交 2025-12-26
- **核心问题**: 推测解码在低负载（内存瓶颈）时提升吞吐，但高负载（计算瓶颈）时验证开销反而降低性能。现有方法使用固定推测长度，无法适应负载变化或决定何时停止推测
- **核心技术: Nightjar**:
  1. **MAB (Multi-Armed Bandit) planner**: 动态选择最优推测长度
  2. **主动禁用推测**: 高负载时推测不再有益，主动关闭推测解码
  3. **Draft 模型 offload**: 关闭推测阶段将 draft 模型卸载到 CPU 释放 GPU 内存用于 KV Cache
- **关键数据**:
  - 实时 LLM 服务场景：吞吐提升 **14.76%**，延迟降低 **20.18%**
  - 动态请求到达率下验证
- **意义**: 推测解码的核心矛盾——**"推测虽好，但在高负载下它的 overhead 可能吃掉收益"**。Nightjar 的负载感知自适应切换是工业部署的刚需

## 3. ⚡ 生产推理引擎

### 3.1 RTP-LLM: 阿里生产推理引擎（重点 ⭐⭐🔥）

- **作者**: Boyu Tan, Jiarui Guo, Zongwei Lv, Hanbo Sun, Tong Yang 等（阿里集团）
- **来源**: arXiv:2605.29639 (cs.OS), 提交 2026-05-28
- **核心内容**: 阿里巴巴生产级 LLM 推理引擎的完整设计与评估，已服务 **1 亿+** 用户
- **四大架构支柱**:
  1. **PD 分离架构**: 将计算密集的 prefill 与内存受限的 decode 分离，结合层级化多级 KV Cache 管理实现高效缓存复用
  2. **模型加载优化**: 文件顺序驱动 I/O + 并行 I/O 通信重叠 → 加载 **4.7-6.3×** 加速
  3. **模块化推测解码**: 支持多种推测算法
  4. **自适应 KV 量化 + 解耦多模态处理 + 多级并行**
- **关键数据**（8B-235B 模型架构，生产流量+可控基准）:
  - TTFT P95 延迟降低 **35-37%**，缓存复用提升 **215%**
  - 推测解码吞吐提升 **1.12-2.48×**
  - 多模态推理吞吐提升 **1.86-2.52×**
  - 量化推理批延迟降低 **35-40%** + TTFT **1.9-3.0×** 提升
- **意义**: 这是**目前公开的最接近超大规模生产部署的推理引擎论文之一**（与 vLLM/SGLang 同级）。其 PD 分离 + 多级 KV Cache + 自适应量化的组合方案，代表了当前工业界的主流技术方向。4.7-6.3× 模型加载加速和 215% 缓存复用改善是**生产中可直接感受到的改进量**

## 5. 📊 趋势总结

| 方向 | 本周关键信号 | 趋势判断 |
|:-----|:------------|:---------|
| **并行策略编排** | DynaTrain 实现子秒级在线切换，Piper 用 IR 抽象解耦策略与运行时 | 并行管理从"静态配置"走向"动态即时编排" |
| **弹性容错** | SPARe (100k GPU, ICML'26)、ReCoVer (512 GPU)、TierCheck | 极端规模容错从 checkpoint 转向**透明故障屏蔽**，TTA 是新的优化目标 |
| **推测解码工业部署** | Nightjar 自适应、RTP-LLM (阿里)、Dustin (ICML'26, KV+推测融合) | 推测解码从学术方法进入**生产级自适应部署**阶段 |
| **VLM 训练效率** | FlowTrain 50%+ MFU、FoMoE 打破全副本 | VLM 训练正对齐 LLM 训练效率，MoE 的通信特性催生新范式 |
| **KV Cache → 推测解码融合** | VeriCache (有损无损化)、Dustin (稀疏验证) | KV Cache 压缩与推测解码的边界模糊化，**相互增益** |
| **PD 分离成熟化** | RTP-LLM 产线验证、SMetric Agent 调度 | PD 分离已成为工业推理标配，Agent 场景驱动下一轮调度优化 |
