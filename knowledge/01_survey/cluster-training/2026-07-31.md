#### SLAI T-Rex: Ascend SuperPOD万亿参数训练 (⭐⭐⭐⭐⭐)
- **来源**: arXiv:2607.20145 (2026-07-22, 73页)
- **核心**: 在Ascend NPU SuperPOD上对DeepSeek-V4系列全参数post-training的层次优化框架
- **成果**: MFU **34.22%**，比开源基线提升**2.93×**
- **技术栈**: 模型级并行 → 计算-通信编排 → 底层kernel执行

- **URL**: https://arxiv.org/abs/2607.20145
- **已在**: `2026-07-30.md §14.1` 和 `2026-07-31.md §14.1` 记录，此处列举为基线条目

#### ScaleAcross Explorer: 跨数据中心训练优化 (⭐⭐⭐⭐⭐)
- **来源**: arXiv:2605.24326 (2026-05-22, Meta, 28页)
- **核心**: 跨多个数据中心建筑的"scale-across"训练范式，百余k GPU规模
- **三个设计维度**: 并行性放置·并行性调度·网络层技术
- **成果**: 相比生产配置**64.62%**训练加速，相比SOTA基线**37.59%**
- **URL**: https://arxiv.org/abs/2605.24326

#### ARGUS: 万卡集群生产级追踪与性能诊断 (⭐⭐⭐⭐⭐)
- **来源**: arXiv:2606.20374 (2026-06-18)
- **核心**: 10000+ GPU集群低开销、细粒度、always-on追踪系统
- **关键技术**: CPU调用栈+框架语义+GPU kernel沿训练调用层级联分解，组合开销<**2%**；压缩率~3700× (10MB→2.7KB/rank/step)
- **渐进式诊断框架**: 迭代时间级→阶段级→kernel级，自动隔离异常窗口/straggler rank/退化kernel
- **实战**: 已部署6个月以上，覆盖compute straggler/link degradation/pipeline-bubble amplification/FlashAttention JIT stalls等
- **URL**: https://arxiv.org/abs/2606.20374

#### NestPipe: 1500+加速器推荐系统训练 (⭐⭐⭐⭐⭐)
- **来源**: arXiv:2604.06956 (2026-04-08)
- **核心**: 推荐模型达万亿参数，集群扩至O(1k)时瓶颈转向embedding的lookup和通信
- **双层嵌套流水线**: (1) **DBP**双缓冲无staleness 5阶段流水线 (2) **FWP**冻结窗口流水线重叠All2All与稠密计算
- **成果**: 在1536 worker的GPU和NPU集群上**3.06×**加速，**94.07%**扩展效率
- **URL**: https://arxiv.org/abs/2604.06956

#### Pulse: Diffusion模型自动流水线并行 (⭐⭐⭐⭐)
- **来源**: arXiv:2606.19163, **ICDCS'26**
- **核心**: skip-aware动态规划分区 + ILP调度综合器，消除U-Net skip连接跨boundary通信
- **成果**: 通信量降低**89%**，通信瓶颈硬件加速**2.3×**
- **已在**: `2026-07-30.md §14.3` 和 `2026-07-31.md §14.3` 记录
- **URL**: https://arxiv.org/abs/2606.19163

#### DITRON: 分布式Tile级编译器 (⭐⭐⭐⭐⭐)
- **来源**: arXiv:2605.02953 (2026-05-02)

- **成果**: 
  - 孤立kernel: 比cuBLAS等**6-30%**加速
  - E2E推理(vLLM): **5-30%**

### 3.1 🏆 零开销/近零开销容错

#### PHOENIX: 零开销热替换Checkpoint (⭐⭐⭐⭐⭐)
- **来源**: arXiv:2607.01646 (2026-07-01)
- **核心**: 非关键路径内存checkpoint空间冗余 + 运行时通信器重构协议
- **成果**: 零checkpoint开销，热替换恢复<**40秒**
- **规模**: 512 NVIDIA A100 GPU, 65B模型
- **URL**: https://arxiv.org/abs/2607.01646

#### TierCheck: 三层分级Checkpoint (⭐⭐⭐⭐⭐)
- **来源**: arXiv:2605.17821 (2026-05-17)
- **技术**: 轻量差异checkpoint→本地/peer内存（快速局部恢复）+ 异步迁移基checkpoint→远程持久存储
- **关键**: 严格跨层全局一致性，不阻塞训练
- **成果**: 端到端checkpoint<**10秒**，支持高频checkpoint，最优平衡低开销+快恢复
- **URL**: https://arxiv.org/abs/2605.17821

#### ReCoVer: 容错Collective + 弹性训练 (⭐⭐⭐⭐⭐)
- **来源**: arXiv:2605.11215 (2026-05-11)
- **核心**: 单不变量（每迭代恒定microbatch数）→故障容错collective → 步内细粒度恢复 → 自适应微批次分配
- **设计**: parallelism agnostic，直接接入3D并行和HSDP
- **成果**: 512 GPU上256 GPU丢失仍保持训练轨迹；有效吞吐**2.23×**；处理**74.9%**更多token
- **URL**: https://arxiv.org/abs/2605.11215

## §4 RDMA/通信优化

> 覆盖窗口: 2024-05 ~ 2026-07 · 源: arXiv (2 queries)
> **5条发现**

### 4.1 🏆 多轨网络与协议级优化

#### Nezha: 多轨网络协议无关优化 (⭐⭐⭐⭐)
- **来源**: arXiv:2405.17870 (2024-05-28)
- **核心**: 首个协议无关多轨网络系统——统一SHARP/GLEX/TCP抽象 + 协议感知动态负载均衡 + 容错多轨协作
- **关键数据**: 
  - 比Gloo延迟低**1.7-4.3×**
  - 同构TCP: 比MPTCP吞吐高**74%**
  - 异构TCP-SHARP: 比MPTCP吞吐高**80%**
  - 128节点超算: 训练效率比Gloo高**2.36×**
  - 单轨故障200ms自恢复
- **URL**: https://arxiv.org/abs/2405.17870

#### ZipCCL: 无损压缩集通信库 (⭐⭐⭐⭐)
- **来源**: arXiv:2604.27844 (2026-04-30)
- **核心**: 理论指数编码利用LLM张量近高斯分布 + GPU优化压缩/解压kernel + 自适应通信策略
- **成果**: 64 GPU集群通信时间**1.35×**降低，E2E训练**1.18×**加速
- **注**: 无损，不影响模型质量
- **URL**: https://arxiv.org/abs/2604.27844

#### R²CCL: 容错集体通信库 (⭐⭐⭐⭐)
- **来源**: arXiv:2512.25059 (2025-12-31)
- **核心**: 快速连接迁移 + 带宽感知负载重分配 + 弹性collective算法，利用多NIC硬件
- **成果**: 训练overhead<**1%**，推理<**3%**，超AdapCC **12.18×**，超DejaVu **47×**
- **URL**: https://arxiv.org/abs/2512.25059

#### DisagMoE: MoE通信解耦 (⭐⭐⭐⭐⭐)
- 见§2.1。解耦Attention/FFN通信，1.8×加速。

#### UniEP: 统一EP MegaKernel (⭐⭐⭐⭐)
- 见§2.1。融合通信+计算，1.03-1.38×加速。

### 4.2 通信优化趋势判断

- **从单轨→多轨融合**: Nezha代表利用异构网络(IB+RoCE+TCP)协作的趋势
- **从有损→无损压缩**: ZipCCL证明训练数据的高斯分布特性可被无损压缩利用
- **从通信加速→通信容错**: R²CCL将故障视为通信问题的一部分，联合优化
- **从通用collective→MoE定制**: DisagMoE和UniEP展示了MoE通信的定制化趋势，不再用通用all-to-all

## §5 ⚡ 关键趋势判断

### 5.1 集群训练的三大范式转变

1. **从MFU竞争→运营效率竞争**:
   - MFU 34%（Ascend）和SOTA接近40-50%意味着纯计算效率提升空间收窄
   - ARGUS <2%开销的always-on观测 + 504 GPU auto-retry 33.3%等运营指标成为新焦点
   - 下一阶段瓶颈: **故障恢复效率 > 计算效率**

2. **从同构→异构集群成为常态**:
   - HexiSeq证明异构集群(混合GPU型号/网络)可高效利用
   - DisagMoE解耦Attention/FFN到不同GPU组——异构不仅仅"不同型号"而是异构工作负载
   - BACE-Pipe跨区域调度——地理异构成为新范式

3. **容错从事后→内建于系统**:
   - PHOENIX零开销热替换 + ReCoVer parallelism-agnostic + MoEvement NSDI'26
   - Checkpoint从"定期存盘" → "持续增量/稀疏/层级化"
   - 容错collective(R²CCL)将网络故障作为通信问题原位解决

### 5.2 技术栈分层趋势

| 层次 | 代表工作 | 创新方向 |
|:-----|:---------|:---------|
| **框架层** | MoP/ALTO/Pulse | 更灵活的并行模式选择 |
| **编译器层** | DITRON/FalconGEMM/Xe-Forge | 分布式tile级编译 |
| **通信层** | ZipCCL/Nezha/R²CCL | 无损压缩+多轨+容错 |
| **运行时层** | Asteria/ETC | 次要计算(优化器/checkpoint)剥离 |
| **观测层** | ARGUS | <2% always-on全栈追踪 |
