### 1️⃣ 🔐 PSAP: 同态加密推理的位翻转可靠性 — 首个BER安全边界标定

**来源**: [arXiv:2607.18342](https://arxiv.org/abs/2607.18342) · 2026-07-20 · cs.CR/cs.LG · **Sahaj Majavdia, Mahdi Taheri**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 结构化剪枝使神经网络在**同态加密(HE/CKKS)**下可行，但剪枝对模型可靠性的影响从未被系统研究——加密域故障注入(HE fault injection)成本高、难操作，业界缺少安全操作边界 |
| **核心方法** | ① **PSAP (Polynomial-Sensitivity-Aware Pruning)**: 按权重幅度+多项式激活敏感度+旋转成本联合打分，把剪枝集中到**容错区域**<br>② 提出 **int32 位翻转注入作为直接加密故障注入的保守代理**(proven safe proxy)<br>③ 实验矩阵: 2架构×2数据集×2数值表示×5位错误率 = 40全模型 + 108逐层实验 |
| **量化数据** | • PSAP 将灾难性层(>10pp精度下降)限制在**≤2个**，幅度剪枝基线为 **5-14个** → 最坏情况脆弱性降 **29×**<br>• 直接CKKS加密故障注入 → **安全操作边界 BER ~10⁻⁵**（int32注入可作保守代理）<br>• 故障关键结构层仅占参数 **1.1%** → 选择性加固开销极小<br>• Halevi-Shoup旋转 **-45.2%**(ResNet-32)；混合度数分配使乘法深度 **66→56层**，免bootstrapping级别推理 |
| **核心洞察** | 加密推理的可靠性从「不可测」走向「可标定」——BER 10⁻⁵ 边界与 1.1% 关键层为**选择性加固**提供靶点，与 GPU SDC 研究(07-10/07-30)同构: 关键位/关键层占比极小但决定整体脆弱性 |

### 2️⃣ 📐 Checkpoint Storm 自增强假设被形式化挑战 — 匿名资源零耦合

**来源**: [arXiv:2607.28377](https://arxiv.org/abs/2607.28377) · 2026-07-30 · cs.DC (理论) · **Brieuc Le Roux Tardif**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 独立训练任务共享存储有限带宽，checkpoint 写入的突发 I/O 被称为**自增强的"checkpoint storm"**——该自增强机制从未被严格建模 |
| **核心方法** | 用**耦合积分-发射振荡器**群体模型(→ Kuramoto / Mirollo-Strogatz 框架)形式化相位锁定，定义**匿名资源**(吞吐只取决于活跃用户数、不取决于谁在用)，对同质任务的存储争用/共享功率上限做双体返回映射分析 |
| **量化数据** | • 匿名资源下**无成对耦合**: 双体相位间隙返回映射为恒等(存储争用、功率上限、两者叠加均如此)——双体相互作用"不是弱而是**不存在**"<br>• 匿名性**冻结发射顺序**: 任意规模/上限下无轨迹能从外部到达同步态<br>• 幸存三阶效应: 所有N个写窗口重叠且上限不约束时, 映射 a_j ↦ ((N-j)/j)·a_j 具**倒数谱+单位行列式** → 同步是 ⌈N/2⌉-1 个扩张方向的**固定点而非吸引子**<br>• 无锁定≠无突发: 并发写者数量上尾仍高于独立相位值 |
| **核心洞察** | 挑战"checkpoint storm 自增强"共识——若存储资源匿名，同质任务不会自发同步成风暴，但**突发仍存在**(上尾偏高)。异质任务+约束上限才产生真实成对耦合。对集群 checkpoint 调度/压力测试设计有理论指导意义: 缓解重点应从「去同步化调度」转向「削峰上尾」 |

### 3️⃣ 🗄️ PRISM-POSIX: AI研究存储评估框架 — checkpoint IO 成为一等基准

**来源**: [arXiv:2607.21746](https://arxiv.org/abs/2607.21746) · 2026-07-23 · cs.DC/cs.AR · **Adithya Kumar, Aditya Basu, Jacob Kahn 等**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 现有存储基准只评峰值吞吐，无法捕捉 AI 研究的**突发、异构、动态演化** IO 模式(摄入/checkpoint/开发全阶段)——存储选型缺依据 |
| **核心方法** | PRISM 评估框架复现三类代表性 AI 研究工作负载: **数据摄入、分布式 checkpoint IO、开发者工作流**，沿可用性+性能双维度评估 POSIX 存储 |
| **量化数据** | • 案例研究: flash-backed **NFS** 在分布式 checkpoint 负载较 flash-backed **Lustre 快 3×** → 直接支撑集群存储选型<br>• 覆盖 GPU 集群真实负载形态而非合成峰值 |
| **核心洞察** | **checkpoint IO 从「存储附属负载」升格为「存储选型一等基准」**——与 07-21 起的 checkpoint 压力测试主线呼应。对可靠性测试的意义: 存储层故障(慢盘/带宽抖动)对 checkpoint 写路径的影响需要专门基准量化，而 PRISM 提供可复现模板 |

> ⚠️ **同名区分**: 本条目 PRISM = POSIX Storage 评估框架；07-30 收录的 LLM-PRISM (NVIDIA) = GPU SDC 故障建模；二者无关

### 4️⃣ 🐘 Ascend 910 现场研究: 非GPU加速器可靠性的真实代价

**来源**: [arXiv:2607.08215](https://arxiv.org/abs/2607.08215) · 2026-07-09 · cs.DC/cs.LG · **Zheng Yu**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 非GPU AI 加速器(昇腾)作为 CUDA 替代被广泛采用，但大模型推理迁移的**真实工程可靠性成本**缺乏现场记录 |
| **核心方法** | 16设备 Huawei Ascend 910 + CANN + vLLM-Ascend 部署两个真实负载: LLM-as-judge 安全对齐评估管线(W8A8 MoE, DeepSeek-V4-Flash) + 多模态医疗 VLM 基准(MMMU/MMMU-Pro)，记录全部补丁与故障 |
| **量化数据** | • 需要 **12个源码级补丁** 修复 vendor 推理插件<br>• **禁用多个高吞吐特性**才能保数值正确性<br>• 为**反复设备级故障**增加操作防护<br>• 8类平台局限: 不完整算子/特性支持、脆弱并行、底层内核**数值故障**、不成熟图编译、不稳定高级特性、有限扩展性、弱可观测性、生态碎片化 |
| **核心洞察** | 非GPU加速器的可靠性成本集中在**软件栈薄弱层**(数值故障+弱可观测性)，而非硬件本身——RAS 评估需把「vendor 软件成熟度」纳入考量。对国产算力选型是稀缺的一手量化参考 |
