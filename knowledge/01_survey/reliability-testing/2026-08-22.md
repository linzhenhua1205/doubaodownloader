## 二、核心发现（列表项）

### 2.1 SDC（静默数据损坏）表征——故障谱系中最难检测的一环（本日最重磅）

- **LLM-PRISM: Characterizing Silent Data Corruption from Permanent GPU Faults in LLM Training**（arXiv 2604.10390，2026-04-12，https://arxiv.org/abs/2604.10390）：首个**硬件落地（hardware-grounded）的 LLM 预训练 SDC 韧性表征研究**。方法链条：把 **RTL 级 GPU 故障仿真**（制造逃逸 + 硅老化导致的永久性缺陷）与**随机注入引擎**耦合，嵌入 Megatron-LM 训练框架，通过 **7,664 次训练运行**（横跨 FP16 / BF16 / FP8 三种数值格式）系统量化"故障类型 × 故障率 × 数值格式"三个维度对训练韧性（resilience）的影响。三个核心发现：**① 低频故障下 LLM 表现出天然韧性**——模型对低速率硬件缺陷有相当程度的容忍（梯度噪声淹没部分故障影响）；**② 但影响高度非均匀**——关键数据通路（critical datapaths）上的故障即使中等故障率也可导致**灾难性发散（catastrophic divergence）**，不是所有位都平等；**③ 数值格式显著调制韧性**——FP8 等低精度格式对故障更敏感（更窄的动态范围放大了错误传播），FP16/BF16/FP8 三档的韧性边界不同。价值：这是第一次把 SDC 研究从"测量硬件错误率"推进到"**测量训练算法对不同硬件缺陷的容忍边界**"，为"哪些故障必须检测、哪些可以忽略"提供了数据基础。

- **LLM-PRISM 与 RAS 体系的衔接**（定位）：SDC 之所以是可靠性体系的"暗物质"，在于它**不触发任何显式信号**——不崩溃、不超时、不报 ECC 错，只是权重/梯度被悄悄污染。传统 RAS（ECC 纠错、故障注入、心跳监控）覆盖"检测到错误"的域，SDC 落在"**错误发生了但没人知道**"的域。LLM-PRISM 的贡献是把这个问题变成可量化的：给定故障率 λ 与数值格式，训练发散概率是多少、哪些 datapath 值得加保护——这正是"检测优先级排序"（检测预算有限时先保护哪里）的第一性依据。与昨日收录的 SCOUT（arXiv 2608.11034，共识定位 + replay 验证 checkpoint 是否被 SDC 污染）形成互补闭环：**SCOUT 解决"如何发现污染"，LLM-PRISM 解决"哪些故障最可能造成污染、值得投入检测"**——一个在运行期，一个在设计期。

### 2.2 超大规模容错（100k+ GPU 时代的重启成本主导）

- **SPARe: Stacked Parallelism with Adaptive Reordering for Fault-Tolerant LLM Pretraining Systems with 100k+ GPUs**（arXiv 2603.00357，2026-05-27 更新，ICML 2026 正式录用，https://arxiv.org/abs/2603.00357）：面向**100k+ GPU 预训练**的容错框架，直面"重启成本主导（restart-dominant）"的新 regime。核心观察：万卡以上规模故障成为常态而非例外，**checkpoint-and-restart 的墙钟时间开销可能超过有效训练时间本身**；而传统复制（replication）方案在冗余度升高时开销线性膨胀。SPARe 的解法是 **Stacked Parallelism（堆叠并行）**——在梯度同步阶段把**冗余数据分片堆叠到并行组之间**（而非复制整个参数集），配合**自适应重排序（Adaptive Reordering）**掩盖节点故障。两个关键性质：**① 可用性堪比传统复制，但计算开销保持近常数 2~3x**（传统复制在高冗余下开销线性膨胀）；② 推导了**可承受故障数（endurable failure count）与计算开销的闭式表达式**，用 SimGrid 离散事件仿真验证，并**联合优化冗余度与 checkpoint 频率以最小化 time-to-train**。量化结论：极端规模（600k GPU）下 SPARe 将 time-to-train 比传统复制**降低 40~50%**。注意条件：这是仿真验证（SimGrid），且对比基线是传统复制而非 checkpoint-and-restart——引用时须注明。

- **SPARe 与已收录超大规模方案的对照**（定位）：08-20 已收录 Meta 的 **FT-HSDP**（O(100K) GPU 生产级，DP 副本为容错单元，stall 10min→3min、有效训练 44%→80%）——FT-HSDP 的冗余手段是**副本（replica）**，SPARe 的冗余手段是**冗余分片堆叠（stacked shards）**。两者的本质区别：FT-HSDP 每个 DP 副本持有完整参数副本（内存/显存开销随副本数线性），SPARe 把冗余嵌入分片结构（显存开销近常数）。这正对应传统复制与纠删码（erasure coding）在存储领域的经典取舍——**SPARe 是"纠删码思想"在训练容错中的应用**，用编码冗余换取可用性，代价是重排序/重计算的调度复杂度。

### 2.3 checkpoint 技术谱系深化（从"全量"到"选择性/稀疏/影子"）

- **GhostServe: A Lightweight Checkpointing System in the Shadow for Fault-Tolerant LLM Serving**（arXiv 2605.00831，2026-03-26，MLSys 2026，https://arxiv.org/abs/2605.00831）：LLM **推理（serving）**侧的 checkpoint 创新，核心对象是**流式 KV cache**（随序列长度增长、分布式服务中最脆弱的状态）。方法：**"影子（in the shadow）"保护**——在后台对 KV cache 应用**纠删码（erasure coding）**，把奇偶校验分片（parity shards）存到宿主内存；设备故障时从校验分片**快速重建丢失的 KV cache**，避免全量重算或全量复制。量化收益（单 batch、存在系统故障的条件下）：checkpoint 延迟降低最多 **2.7x**、恢复延迟 **2.1x**、中位响应延迟改善 1.2x（对比既有方法）。与 08-20 已收录的 **Concordia**（GPU-resident persistent kernel 推理 checkpoint）互补：Concordia 解决"**在哪个执行层做 checkpoint**"（设备驻留、绕过主机 CPU 关键路径），GhostServe 解决"**用什么冗余手段存 checkpoint**"（纠删码而非复制/全量）——推理场景的 KV cache 是 GB 级持续增长状态，两者的"低开销 + 快恢复"诉求一致，但冗余机制不同。

- **LLMTailor: A Layer-wise Tailoring Tool for Efficient Checkpointing of Large Language Models**（arXiv 2602.22158，2026-02-25，PDSW'25，https://arxiv.org/abs/2602.22158）：**选择性 checkpoint（selective checkpointing）**工具，基于一个已被观测到的现象：**训练中 LLM 各层更新高度非均匀**——有些层变化大、有些层几乎不变甚至完全不变。传统 checkpoint 无论 I/O 策略如何优化，都周期性地**全量**保存模型与优化器状态。LLMTailor 提供**层粒度合并框架**：从不同 checkpoint 中过滤/组装"显著更新"的层，形成复合 checkpoint，配合多种选择性策略使用。量化（条件：Llama3.1-8B / Qwen2.5-7B 基准）：checkpoint 体积最大缩减 **4.3x**（Llama3.1-8B）、checkpoint 时间最快 **2.8x**（Qwen2.5-7B），模型质量保持。注意边界：选择性 checkpoint 的恢复安全性依赖"未保存层确实无显著更新"的假设，若故障发生在层快速变化期，恢复质量有退化风险——论文未给出该边界下的最坏情况分析，引用时须注明。

- **BitSnap: Checkpoint Sparsification and Quantization in LLM Training**（arXiv 2511.12376，2025-11-18，https://arxiv.org/abs/2511.12376）：checkpoint **稀疏化 + 量化**双通道压缩。方法：**基于 bitmask 的稀疏化**——只保存显著变化的参数元素（与 AuroraRL 的 sparse delta 思路同源，但面向持久 checkpoint 而非网络传输）+ **基于聚类的量化**（cluster-based quantization）压缩值域。量化（不同规模 LLM 训练）：bitmask 稀疏化达 **16x 压缩比**且不损模型精度；聚类量化达 **2x 压缩比**、精度损失极小。本质洞察：**checkpoint 中大部分参数元素在相邻保存点之间几乎不变**（与 LLMTailor 的"层间非均匀"是同一现象的两个视角——一个看层粒度，一个看元素粒度），冗余度远高于直觉。与 LLMTailor 的对照：LLMTailor 是**层级选择性**（粗粒度、保精度、依赖层间非均匀性），BitSnap 是**元素级稀疏**（细粒度、配合量化、依赖元素间稀疏性）——两者可叠加（层筛选 + 层内稀疏），构成"两级选择性 checkpoint"的潜在组合。

- **Crab: A Semantics-Aware Checkpoint/Restore Runtime for Agent Sandboxes**（arXiv 2604.28138，2026-04-30，https://arxiv.org/abs/2604.28138）：**Agent 沙箱的语义感知 C/R（checkpoint/restore）运行时**，面向的是 RL rollout 分支、spot execution、安全回滚等场景的状态保存。核心问题：Agent 通过沙箱容器/microVM 行动，状态横跨文件系统/进程/运行时工件；现有方案两极分化——应用级恢复保留对话历史但丢失 OS 副作用，全量逐轮 checkpoint 正确但**在密集共置（dense co-location）下代价过高**。Crab 的关键洞察：**Agent-OS 语义鸿沟**导致超过 **75% 的 Agent 轮次不产生恢复相关状态**，绝大多数 checkpoint 是浪费。工程方案三件套：**① eBPF 检查器**分类每轮的 OS 可见副作用以决定 checkpoint 粒度；**② 协调器**把 checkpoint 对齐到轮次边界并与 LLM 等待时间重叠；**③ 主机级引擎**跨共置沙箱调度 checkpoint 流量。量化（shell 密集型与代码修复负载）：恢复正确性从 8%（仅对话历史）提升到 **100%**，checkpoint 流量最高削减 **87%**，运行时间开销保持在无故障执行的 **1.9%** 以内。与 Belayer（08-20 已收录，Agentic RL 训练容错）的关系：Belayer 在训练侧、Crab 在推理/执行侧，两者都处理"**LLM 上下文与外部环境状态的一致性**"——Crab 用"语义感知决定存什么"，Belayer 用"shadow worker + selective GPU state reuse 决定怎么恢复"，是同一问题（Agent 状态一致性）的存储侧与恢复侧。

### 2.4 边缘/嵌入式容错（补充观测）

- **Emulated Integrity Replica: Enabling Self-Healing on FPGA SoCs via Hierarchical Twins**（arXiv 2607.12298，2026-07-14，https://arxiv.org/abs/2607.12298）：**FPGA SoC 上的自愈框架**，面向 CNN 边缘推理。痛点：传统冗余（DMR/TMR 双/三模冗余）硬件资源代价高，软件方法（ABFT、checkpoint-restart、指令级重复、看门狗）有延迟/能耗开销或覆盖不足。方案 **EIR（Emulated Integrity Replica）**：利用 PL（可编程逻辑）中加速器执行时 **PS（处理系统）通常闲置的时间余量**，在 PS 上宿主两个互补孪生体——**Rabbit**（粗粒度行为模型，快速故障检测）+ **Tortoise**（细粒度门级模型，从 checkpoint 状态精确恢复）；加速器状态周期性捕获，用执行速度画像平衡性能开销与韧性。结论（在评估故障模型与负载假设下）：相对 DMR 基线达到高经验故障覆盖率，同时降低能耗与面积开销。相关性说明：这是**边缘 AI 场景**的容错方案（服务器场景相关性中等），但其"**用时间冗余换空间冗余**"（利用闲置周期做校验而非复制硬件）的思想，与服务器上"用带外/闲置资源做故障校验"同构——可作为可靠性设计模式库的一个条目。

## 三、分析性段落（因果链 / 原理展开 / 对比）

### 3.1 SDC 为什么是可靠性体系的"暗物质"：从"检测错误"到"量化容忍边界"

把 LLM-PRISM 放在可靠性工程的因果链上，可以看到它补上了最缺失的一环。一条完整的故障链是：**硬件缺陷发生 → 错误注入计算 → 数值被污染 → 训练发散/模型劣化 → 事后才发现损失**。传统 RAS 体系的监控点分布在链条前段：ECC 能纠/检内存与缓存错误（硬件层显式信号），心跳/超时能发现进程崩溃（软件层显式信号），故障注入测试能验证检测覆盖率（测试层显式信号）。但 **SDC 的全部危险在于链条中段没有任何显式信号**：永久性缺陷（制造逃逸、硅老化）在特定数据模式下产生错误结果，而错误结果与正常梯度噪声在统计上难以区分——训练继续运行、checkpoint 正常保存，直到某个 checkpoint 被污染并在恢复时被选中，损失才以"训练白跑"的形式爆发。这就是为什么 SCOUT（08-21 收录）要引入 replay 验证 checkpoint 干净度——它默认了"污染可能已经发生"。

LLM-PRISM 的独特价值在于把这个问题从"定性恐惧"变成"定量边界"：通过 7,664 次运行的系统扫描，它给出的是**韧性函数**——给定故障率、故障类型、数值格式，训练发散概率几何。这个函数直接支撑三个工程决策：**① 检测资源分配**——如果某个 datapath 的故障在 FP8 下 90% 概率导致发散，它就应该获得 ECC/校验保护或冗余计算，而低频且低影响的故障可以放行；**② 数值格式选型**——FP8 训练收益（吞吐/显存）与 SDC 脆弱性之间的权衡，需要韧性数据支撑而不是拍脑袋；**③ checkpoint 验证策略**——哪些 checkpoint 需要 replay 验证（高风险故障窗口内保存的），哪些可以信任。这与用户质量标准"数据可验证：来源+基线+条件"完全吻合——LLM-PRISM 的基线是"无故障参考轨迹 + RTL 级故障注入"，条件是具体故障模型与格式，引用时需一并注明。

### 3.2 checkpoint 技术谱系：第一性原理下的状态持久化成本分解

把本窗口（08-20~08-22）收录的全部 checkpoint 方案放在一条谱系轴上，可以看到它们其实是在回答同一个第一性问题：**"训练/服务状态要持久化什么、存哪里、以什么形式、多频繁？"** 拆解 checkpoint 的总成本 = **捕获成本（读状态）+ 传输成本（移动状态）+ 存储成本（占空间）+ 一致性成本（保证全局一致不阻塞训练）**，不同方案是在这四个维度上做不同的取舍：

| 方案 | 冗余/压缩手段 | 主要成本维度 | 适用场景 |
|:--|:--|:--|:--|
| 全量 checkpoint（基线） | 无 | 捕获+传输+存储全高 | 通用基线 |
| TierCheck（08-20） | 分层：内存差分 + 远程全量 | 传输（本地快/远程异步） | 训练，快恢复 + 持久 |
| PHOENIX（08-20） | off-critical-path 内存 checkpoint | 捕获（与计算重叠） | 训练，零开销 + 热插拔 |
| ReCoVer（08-20） | 迭代内细粒度恢复 | 捕获（微批次级） | 训练，保轨迹 |
| AuroraRL（08-20） | sparse delta + 流水线传输 | 传输（弱网 79x 缩减） | 弱网分布式 RL |
| Concordia（08-20） | GPU-resident persistent kernel | 捕获（设备驻留，绕过主机） | 推理 KV cache |
| GhostServe（今日） | 影子纠删码（erasure coding） | 存储（奇偶分片替代复制） | 推理 KV cache |
| LLMTailor（今日） | 层级选择性合并 | 捕获+存储（层粒度筛选） | 训练，减少 checkpoint 体积 |
| BitSnap（今日） | 元素级 bitmask 稀疏 + 量化 | 存储（16x+2x 压缩） | 训练，极致压缩 |
| Crab（今日） | 语义感知粒度决策（eBPF） | 捕获（75% 轮次免 checkpoint） | Agent 沙箱 |

读这张谱系可以得到三个结构性规律：**① 冗余手段的"纠删码化"**——从复制（FT-HSDP）到分片堆叠（SPARe）到奇偶分片（GhostServe），存储领域几十年前走过的"复制→纠删码"路径正在训练/推理状态持久化中重演，驱动力相同（副本成本线性 vs 编码成本近常数）；**② 压缩方向的"稀疏化"**——LLMTailor（层粒度）、BitSnap（元素粒度）、AuroraRL（传输粒度）共同利用了"训练更新高度稀疏"这一被低估的现象，checkpoint 冗余度远高于直觉（BitSnap 16x、Crab 75% 轮次免存）；**③ 语义感知成为新变量**——Crab 用"这轮有没有 OS 副作用"决定存不存，SCOUT 用"重放是否干净"决定 checkpoint 可信不可信——**"存什么"的决策从静态（周期全量）走向动态（按语义/按变化率）**，这是 checkpoint 技术最本质的范式转移：从"时间驱动"（每 N 步存一次）到"内容驱动"（有变化才存、有风险才验）。

### 3.3 SPARe 与 100k+ GPU 时代的容错经济学：为什么"复制"必然让位于"编码"

SPARe 的论文背景隐含一个残酷的规模定律：**集群越大，故障间隔（MTBF）越短，重启成本占比越高**。设单 GPU MTBF 为 M、集群规模为 N，则集群级故障间隔 ∝ M/N——N 从 1k 到 100k，故障间隔缩小两个数量级；而 checkpoint-and-restart 的恢复成本（全量保存 + 全量重载 + 重算丢失步）与模型规模正相关、与故障率线性叠加。当"故障恢复时间 > 两次故障间的有效训练时间"时，系统进入 **restart-dominant regime**——这正是 SPARe 要处理的 regime，也是 FT-HSDP 在 Meta O(100K) 集群上面对的 reality（stall 10min→3min 的优化就是在跟这个定律赛跑）。

传统复制（replication）的容错经济学是：冗余度 r 份，可用性提升但**计算/显存开销线性膨胀**——高冗余下"为容错付出的算力"本身成为巨大浪费。SPARe 的 **Stacked Parallelism** 打破了线性关系：把冗余数据分片**堆叠**进并行组的梯度同步结构，冗余参与计算（而非纯备份），因此开销保持近常数 2~3x（论文给出闭式表达式，仿真验证）。注意这里的因果链：**堆叠分片 → 梯度同步时天然形成冗余 → 节点故障时由幸存分片重构 → 自适应重排序掩盖故障 → 可用性≈复制但开销近常数**。量化结论 40~50% time-to-train 缩减（600k GPU、对比传统复制）的适用条件必须注明：SimGrid 仿真 + 对比基线是"传统复制"而非"checkpoint-and-restart"——与 ReCoVer 的 2.23x 有效吞吐（对比 checkpoint-and-restart，512 GPU）不在同一基线上，不能直接比较，但两者共同指向同一结论：**万卡级以上，容错必须内嵌进训练结构本身（collective/并行分片），而不是外挂的"定期保存"**。

### 3.4 恢复目标谱系：训练 / 服务 / Agent / 边缘——容错对象的分化

本窗口收录的论文展示了一个清晰的趋势：**容错的对象正在从"模型权重"扩展为"运行期状态"**。训练侧（TierCheck/ReCoVer/PHOENIX/SPARe）保护的是**权重 + 优化器状态**（静态、结构化、可压缩）；服务侧（Concordia/GhostServe/LUMEN）保护的是 **KV cache + 调度状态**（动态、随序列增长、GB 级持续变化）；Agent 侧（Belayer/Crab）保护的是**环境容器状态 + LLM 上下文的一致性**（语义化、横跨文件系统/进程/运行时工件）；边缘侧（EIR）保护的是**加速器执行状态**（时间敏感、资源受限）。四种对象的持久化特征完全不同——权重是"稀疏变化的稠密张量"，KV cache 是"持续追加的流"，Agent 环境是"事件驱动的副作用集合"，边缘加速器是"周期快照的执行流水"——因此恢复机制也必须分化：压缩（BitSnap/LLMTailor）、纠删（GhostServe）、语义决策（Crab）、时间冗余（EIR）。

这个分化对服务器产品研发的含义是：**可靠性设计不再是一个"checkpoint 模块"能覆盖的**。一台万卡训练集群上同时运行着预训练（权重 checkpoint）、推理服务（KV cache 保护）、Agent 任务（沙箱状态）、边缘推理（设备级自愈）——它们需要不同的故障模型、不同的冗余手段、不同的恢复 SLA。这恰好呼应 08-21 文件 3.5 节的结论："缺少跨抽象层可编排的恢复链"——今日的谱系进一步表明，**恢复链不仅要跨层（硬件→通信→框架→checkpoint→语义），还要跨负载类型**（训练/服务/Agent/边缘各有专属方案）。对产品而言，这意味着"训练平台可靠性编排层"（08-21 已提出的潜在需求）的设计输入更加具体：它需要为每种状态类型注册专属的 checkpoint 策略，而不是一个统一的保存/恢复接口。

## 五、趋势与信号（08-22 视角）

1. **SDC 从"隐性恐惧"走向"可量化边界"**：LLM-PRISM 用 7,664 次运行给出韧性函数，意味着"哪些故障必须检测、哪些可忽略"首次有了数据基础——对 RAS 体系（用户 P1 关注）是直接的输入：检测预算分配可以从"全保护"优化为"按韧性边界保护"。信号强度：高（首次硬件落地的预训练 SDC 表征）。
2. **容错冗余手段的"纠删码化"跨层蔓延**：SPARe（训练结构层）、GhostServe（服务状态层）同日出现"编码/分片冗余替代复制"的设计，叠加存储领域经典纠删码——三个抽象层独立收敛到同一模式，说明"复制成本线性"是各层共同的物理约束，编码是自然解。值得作为知识库"可靠性设计模式"专题的核心条目。
3. **checkpoint 从"时间驱动"转向"内容驱动"**：LLMTailor（层变化率）、BitSnap（元素稀疏性）、Crab（语义副作用）三个方案共同指向"有变化才存、有风险才验"——与 SCOUT 的"恢复前验证"合流，checkpoint 的智能度从"周期全量"跃迁到"按内容决策"。这是本窗口最清晰的范式转移信号。
4. **超大规模容错进入"结构内嵌"阶段**：SPARe（ICML 2026）表明 100k+ GPU 场景下容错不再是外挂 checkpoint，而是内嵌进并行/同步结构（堆叠分片、fault-tolerant collectives）——与 FT-HSDP 生产实践互为印证，restart-dominant regime 成为学术共识。
5. **可靠性追踪的源通道确认**：arXiv 搜索页连续三日 0 命中（查询语法问题），API 通道稳定高效——后续追踪默认走 export.arxiv.org/api/query，搜索页仅作备用；此结论已沉淀于执行基线（见 TRACKING.md 更新建议）。
