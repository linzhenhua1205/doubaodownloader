#### 1️⃣ 🧠 EBFT: 认知拜占庭容错 — Agentic基础设施的失效模型

**来源**: [arXiv:2607.16109](https://arxiv.org/abs/2607.16109) · 2026-07-17 · cs.DC/cs.LG/cs.MA · **Jun He, Deying Yu**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 传统 BFT/SMR 假设节点要么协议合规要么恶意，但 **agentic validator**（LLM 驱动的推理节点）可能出现「协议合规但语义无效」的背书——称为 **epistemic fault**。多个此类节点可构成满足常规检查的法定人数，却为无效状态转换签发证书：**共识达成 ≠ 语义正确** |
| **关键新概念** | ① **Honest Quorum Problem**: "honest"指协议合规而非语义正确，这类 quorum 能通过普通检查却产出非法证书<br>② **EBFT 模型**: 在传统拜占庭界之上增加两个置信度索引量——**e_δ**（Byzantine 集合外的一致无效背书上限，刻画语义安全风险）与 **u_ε**（降低 liveness 的不可用 validator 支持上限）<br>③ **相关性风险**: agentic validator 常共享模型权重/训练分布/prompt/工具链 → **高度易受相关性认知故障**（correlated epistemic faults）影响 |
| **核心成果** | 推导语义有效性/共识/活性的 quorum 阈值条件；给出 e_δ/u_ε 预算校准方法论；证明「添加名义上不同的 agent」仅当可测地降低无效背书或不可用支持的上尾浓度时才提升容错性 |
| **核心洞察** | 这是**首个面向 agentic 基础设施的容错模型**——把「AI 推理错误」从安全分析的黑盒变为可建模、可校准、可分配预算的一等公民。对自治集群、AI 运维、多 agent 决策系统有直接指导意义 |

#### 2️⃣ 📦 SparrowRL: 稀疏 Delta 检查点跨商品网络 RL 训练

**来源**: [arXiv:2602.11456](https://arxiv.org/abs/2602.11456) · 2026-02-11 · cs.DC · **Chaoyi Ruan 等 (上海交大/华为等)**

| 维度 | 内容 |
|:----|:------|
| **核心洞察** | RL 微调每步更新高度稀疏——**仅约 1% 参数元素变化** → 用稀疏 delta 检查点代替全量权重广播 |
| **核心方法** | 每步表示为稀疏 delta checkpoint；delta 提取与多流传输流水线化；传输与 rollout 生成重叠；异构 worker 用吞吐/带宽感知调度 + **lease-based 容错** |
| **量化数据** | Qwen3-8B 跨 4 地理区域：per-step payload **减 79×**、吞吐较全量广播提升 **2.4-9.5×**、与理想 RDMA 单数据中心基线的差距收窄至 **8.91%**；按 token/美元计比保留 RDMA 集群高 **1.21-1.59×** |
| **核心洞察** | 容错从「保命」变为「省钱」——lease 机制 + 稀疏同步让跨云/商品网络 GPU 成为可行的 RL 训练资源，直接挑战「RL post-training 必须专用 RDMA 集群」的假设 |

#### 3️⃣ 🔧 LM-Fix: 轻量 Bit-flip 检测与快速恢复框架

**来源**: [arXiv:2511.02866](https://arxiv.org/abs/2511.02866) · IEEE ICCD 2025 · **Ahmad Tahmasivand 等**

- 短测试向量遍历 + **hash 引导检查**检测 LLM 权重 bit-flip，本地修复无需全量重载
- **量化**: TVL=200 时检测 **>94% 单bit翻转**、**~100% 多bit翻转**；运行开销 **1%-7.7%**；恢复比全量重载 **快 100×+**
- **意义**: 生产环境低成本 LLM 可靠性保障，与 Rowhammer/SDC/jailbreak 攻击防御场景直接相关（代码已开源 github.com/ata990/lm-fix）

#### 4️⃣ 🎯 LLM 对 GPU 软错误的脆弱性 — 首个指令级故障注入研究

**来源**: [arXiv:2601.19912](https://arxiv.org/abs/2601.19912) · 2026-01 · cs.AR/cs.AI · **Duo Chai 等**

- **首个 LLM 推理指令级故障注入研究**：此前 GPU 可靠性研究聚焦通用应用或视觉 CNN，LLM 因注意力/残差结构脆弱性可能截然不同
- 从**模型架构、参数规模、任务复杂度**三维揭示 LLM 软错误脆弱性画像 → 指导更有效的容错机制设计
- **意义**: 与 07-30 的 Anatomy of SDC (RTL级) 形成互补——一个从硬件门级建模，一个从指令级度量 LLM 应用层敏感性

#### 5️⃣ ⚡ TurboFFT: 高性能容错 FFT

**来源**: [arXiv:2405.02520](https://arxiv.org/abs/2405.02520) · 2024-05 · cs.DC · **Shixun Wu 等**

- **双面 checksum** 方案：批量编码输入信号的不同线性组合 → 快速批量检错 + **在线纠错**（无需重算）
- kernel/thread/threadblock 三级设计探索 + kernel fusion 隐藏开销 + 模板化代码生成
- **量化**: 与闭源 cuFFT 相当或更优，**仅 7%-15% 平均开销**（即使数百次/分钟错误注入）；较现有容错 FFT 方案提升 **23%**

#### 6️⃣ 🔢 Grid 纠错码: 矩阵乘法的静默数据损坏防护

**来源**: [arXiv:2508.04355](https://arxiv.org/abs/2508.04355) · 2025-08 · cs.IT · **Hao Shi 等**

- 网格结构编码方案，针对分布式训练中矩阵乘法的 SDC：跨所有参与矩阵增强错误定位与校正
- **量化**: 三矩阵中最多 **2 个错误符号确定性校正（100% 可靠性）**，GPU 计算时间开销仅 **24%**
- **意义**: 为「SDC 无法靠重算缓解」的场景提供确定性纠错路径

#### 9️⃣ 🧱 TensorHub: RL 权重传输的 ROS 抽象

- **Reference-Oriented Storage (ROS)**: 利用在 GPU 上高度复制的模型权重，按需从持有者处读取，物理上不存储副本——自带容错与强一致性
- **量化**: 独立 rollout GPU stall 减 **6.7×**、弹性 rollout 权重更新加速 **4.8×**、跨数据中心 rollout stall 减 **19×**（已生产部署）

#### 🔟 📥 GetBatch: 容错流式批量对象检索

1. **容错边界从「节点」扩展到「认知层」**: EBFT 首次把 LLM 推理错误纳入容错模型——agentic 时代的故障不再只是硬件/网络，还包括「协议合规但语义错误」的推理节点

3. **LLM 可靠性研究形成完整梯度**: RTL门级注入（Anatomy of SDC）→ 指令级注入（本文4️⃣）→ 应用层检测（LM-Fix）→ 纠错编码（Grid-ECC/TurboFFT），从硬件到软件的全栈覆盖已闭合
