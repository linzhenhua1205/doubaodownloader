### 1️⃣ 🔀 TENT: 声明式切片喷洒引擎 — KV迁移的容错数据面

**来源**: [arXiv:2604.00368](https://arxiv.org/abs/2604.00368) · 2026-04-01 (v2: 07-23) · cs.DC · **Feng Ren, Ruoyu Qin, Teng Ma 等 (月之暗面/Moonshot AI)**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | LLM serving 转向 agentic 推理后，KVCache 成为一等公民移动资产，频繁迁移产生海量大象流。Mooncake Transfer Engine (TE) 在数千 GPU 上暴露缺陷：**命令式早期绑定路径选择** → 状态盲的 striping 忽视拥塞与**灰故障（grey failures）**，导致带宽搁浅与运维脆弱（常规故障需人工介入） |
| **核心方法** | **声明式编排引擎**：将传输意图与物理执行解耦<br>① 互联抽象为统一资源池，路径解析从初始化推迟到 **slice-time 延迟绑定**<br>② 应用只声明传输意图，TENT 基于实时遥测+预测成本模型将细粒度切片**喷洒**到 rails<br>③ **sub-50ms 透明自愈**：切片绕开故障/退化路径，无需应用层介入 |
| **量化数据** | • LLM 推理 (SGLang HiCache): 吞吐较 Mooncake TE **+1.36×**、P90 TTFT **-26%**<br>• RL 管线: Moonshot Checkpoint Engine 参数更新 **+20-26%**<br>• 消除 head-of-line 阻塞；生产数据面（多工业集群） |
| **核心洞察** | 容错从「检测→重路由」升级为「**设计时就把自愈内建在路径选择中**」——声明式+延迟绑定让灰故障（性能退化而非失效）也进入自愈范围。这是 KV 迁移可靠性的范式转变，与 07-30 的「绕开降级节点 allreduce」思路一致但下沉到数据面 |

### 2️⃣ 📐 RAPID-LLM: 韧性感知的LLM性能建模框架

**来源**: [arXiv:2512.19606](https://arxiv.org/abs/2512.19606) · 2025-12-22 · cs.PF/cs.DC · **George Karfakis, Faraz Tahmasebi, Binglu Chen 等 (UCLA)**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | LLM 训练/推理性能建模缺乏对**故障与退化链路**的显式支持——现有模拟器假设网络健康，无法回答「软链路故障对训练吞吐影响几何」 |
| **核心方法** | 统一建模框架：<br>① **DeepFlow 前端**: 从抽象 LLM 规格生成硬件感知的 operator 级 Chakra trace（模型形状/批大小/并行策略）<br>② **Astra-Sim 后端**: 在多维网络拓扑上执行，支持**拥塞感知路由 + 退化/故障链路**<br>③ 前端用 tile 模型估算 per-operator 延迟（SM 利用不足 + SRAM/L2/HBM 多级访存），并用激活 liveness 遍历剪枝不可行配置（recomputation/ZeRO/FDSP） |
| **量化数据** | • A100 验证: Llama 推理步延迟 & GPT 规模训练时间预测误差 **<10.4%**<br>• 通信负载与 ns-3 分组级结果匹配 **<8%**<br>• 案例: 混合并行配置穷举扫描、软链路故障敏感性量化、HBM 带宽节流评估 |
| **核心洞察** | **故障感知性能建模**是容错设计的定量基础——「故障下吞吐损失多少」终于可以事前仿真而非事后实测。对压力测试标准的意义：提供可复现的「故障注入→性能影响」仿真基准 |

### 3️⃣ 🛰️ SEU-3DGS: 单粒子翻转的比特级关键性分析与守卫

**来源**: [arXiv:2606.21791](https://arxiv.org/abs/2606.21791) · 2026-06-19 · cs.GR/cs.DC · **Faruk Alpay, Baris Basaran**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 3D Gaussian Splatting 广泛部署于**暴露于瞬态故障的硬件**（星载处理器/机器人边缘设备）——SDC 场景。模型是 GPU 显存中的大浮点参数数组，SEU 对应单比特翻转 |
| **核心方法** | GPU-resident 并行故障注入引擎：**380万+ 受控单比特翻转**，覆盖 4 场景×6 字段×所有位位置×3 数值格式 (fp32/fp16/bf16)，5.3 GPU-hours<br>→ 提出**支持守卫**：per-primitive 将参数 clamp 到训练观测的坐标框（每帧 76μs） |
| **量化数据** | • 关键性高度集中：多数翻转因高冗余感知不变，但**少量高阶位（尤其对数尺度符号位）将单个 primitive 放大至覆盖 75.7% 帧面积**<br>• 768,000 次守卫注入：最坏损坏足迹限制至 **11.68%** 帧面积<br>• 20000 次同时翻转剂量：未守卫渲染 10.6 dB → 守卫后 **21.8 dB**<br>• 闭式扰动界（IEEE-754 布局+管线激活）预测 per-bit 排序 |
| **核心洞察** | SDC 的「关键位集中性」在 3DGS 中极端化——少量高阶位决定成败。守卫（clamp）是「足够好的可靠性」的又一实例：**不纠正错误，只限制影响**。与 07-30 RangeGuard 思想同源，且给出可迁移的 per-bit 关键性量化方法 |

### 4️⃣ 💪 GPU Under Pressure: 遥测+性能计数器估算GPU应力

**来源**: [arXiv:2511.05067](https://arxiv.org/abs/2511.05067) · DTTIS'25 · **Giuseppe Esposito, Juan-David Guerrero-Balaguera 等 (Politecnico di Torino)**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 持续负载对 GPU 组件施加显著应力，可能诱发故障并损坏中间计算结果——**估算应用对 GPU 的应力**是预测可靠性（尤其老化效应）的前提 |
| **核心方法** | 组合**在线遥测参数 + 硬件性能计数器**评估 GPU 应力：<br>① 吞吐类计数器（资源利用效率）<br>② 指令发射量<br>③ stall 事件 |
| **核心结论** | 并行工作负载的应力可通过遥测+性能计数器的组合有效估算——为可靠性预测（aging 关注）提供**运行时应力度量** |
| **核心洞察** | 压力测试正在从「固定工况跑分」走向「**运行时应力感知**」——用性能计数器实时度量应力，为预测性维护与降频策略提供依据。这是服务器 RAS 中「健康监测」环节的 GPU 侧实现 |

### 5️⃣ ⏰ Denial of Deadline: 网络驱动的分布式推理精度崩溃

**来源**: [arXiv:2607.24692](https://arxiv.org/abs/2607.24692) · 2026-07-28 · cs.NI/cs.AI · **Jhonatan Tavori, Gur-Eyal Sela, Ion Stoica, Gil Zussman**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 分布式推理管线中，网络故障通常被视为性能问题（延迟上升）——但研究表明其可导致**精度崩溃**（正确性损失），形成一种被忽视的可靠性威胁 |
| **核心方法** | 分析网络延迟/丢包/超时如何在多阶段推理管线中传播，导致聚合结果失真或阶段输出降级 |
| **核心洞察** | 网络 QoS 从「性能变量」升格为「**正确性变量**」——可靠性工程需将网络条件纳入精度保障模型。与 SDC 类比：网络侧也存在「静默精度损坏」 |

## 🧭 趋势观察

1. **KV 迁移容错进入「设计时自愈」时代**: TENT 的声明式+延迟绑定将灰故障自愈内建到数据面——容错从「故障后恢复」前移到「路径选择时规避」，sub-50ms 自愈成为新基线
2. **故障感知建模工具链成形**: RAPID-LLM 提供「故障注入→性能影响」的可复现仿真基准——为压力测试标准提供定量基础设施（与 07-31 LLM 指令级注入互补：一个仿真、一个实测）
3. **「限制影响」替代「纠正错误」成为低成本可靠性主线**: SEU-3DGS 守卫（clamp）、RangeGuard（有界校正）、GPU Under Pressure（应力监测）共同验证：面向 AI 工作负载的可靠性设计正从精确 ECC 转向「感知+限制」的务实路线
4. **正确性边界从数据扩展到网络**: Denial of Deadline 提示网络条件可致精度崩溃——RAS 的故障模型需纳入网络 QoS 维度
