## 核心发现

- **arXiv/B300 全量微调运维报告：遥测分诊+负面结果+运维加固**（2026-08-06, arXiv:2608.05944）: Qwen3-32B(32.76B dense) 在 16×NVIDIA B300 双节点 FSDP/ZeRO-3 全量微调首批公开现场报告，产出4个可复用工件：①B300 校准功耗分诊表——按板级瓦数区分 计算/通信/数据饥饿/checkpoint-死锁/空闲 五态，揭示 NCCL hang 期间 utilization% 仍读 100% 的误报陷阱 ②诚实负面结果：per-step NFS 读取与本地预分词缓存持平(~53k tok/s，因语料落 page cache 且 job 计算受限)，此前"吞吐崩溃"实为 NFS/CPU 争用而非存储介质瓶颈 ③4/8/16-GPU 强扩展校准数据 ④epoch-end NCCL 死锁案例（per-rank token-packing 不平衡）+2.7秒预运行不变量门禁+外部 watcher，将数小时静默失败转为即时拒绝。可迁移结论：数据依赖型 DP 任务应看功率而非利用率；冒烟测试通过≠全量运行安全。来源: https://arxiv.org/abs/2608.05944

- **arXiv/Resume Means Resume：checkpoint/interrupt/resume 语义机器可查契约**（2026-08-04, arXiv:2608.03836）: 5个广泛部署的 agent workflow 框架对"恢复后已发生副作用如何处置"答案各异且均无机器可查契约。提出 RESUME CONTRACT 六属性（前缀续行/副作用恰好一次/fork 确定性/checkpoint 有效性/消费一次/恢复确定性）+fork-intent 与 liveness 义务；TLA+ 在 740 万状态边界穷尽校验、TLAPS 无界证明 196 义务、39 格故障矩阵。实测 LangGraph 1.2.9 持久化第二个 resume 值但从不使用、静默持久化 schema 无效状态、SIGKILL 后重执行已持久化工作——同一 API 上跨中断 exactly-once、跨崩溃 at-least-once；CrewAI 1.15.2 重执行已完成的 effect 方法；pydantic-graph 1.x 节点中崩溃后无法恢复；consume-once 顺序成立但并发失败（k 进程恢复同一暂停中断触发 effect k 次，40 格中 36 格饱和1.0）。参考实现 REMIT 以 Verus 验证恢复核心修复 fork/validity 格。来源: https://arxiv.org/abs/2608.03836

- **arXiv/应用失败率与机器计算效率框架**（2026-08-05, arXiv:2608.05408）: 面向 Exascale 级科学计算与大型 AI 训练设施，论证故障率/MTBF 应以使用量（node-hours）而非时间定义（应用异构性要求）；建模失败/checkpoint/重启三类使用量损失，更新 Daly(2006) 框架支持用户指定最小化损失的最优 checkpoint 使用间隔，推导机器计算效率（可用于科学计算的期望资源份额）；用 ORNL Frontier 一年生产运行数据验证。来源: https://arxiv.org/abs/2608.05408

- **arXiv/DNSSE：分布式并行 AI 程序的定向神经符号随机执行验证**（2026-08-08, arXiv:2608.07947）: 针对分布式 AI 程序"并行执行不确定+高维输入+非线性运算"使 fuzzing/符号执行单独失效的可靠性缺口，提出 LLM 引导调度预测+符号约束求解+覆盖引导随机变异混合框架；以线性时序逻辑(LTL)指定正确性，证明混合求解器 soundness/有界完备性/概率完备性并给出 LLM 引导探索期望成本分析；PyTorch+Ray 实现比最强基线多检出 2.9% 并发 bug，5 个分布式 AI 基准平均分支覆盖率 68.6%→91.6%。来源: https://arxiv.org/abs/2608.07947

- **arXiv/Deep4ge：DNN 训练轨迹故障检测与诊断**（2026-07-14, arXiv:2607.12868）: 深度系统常因实现级细微缺陷改变训练行为而失败，从训练轨迹可观测变化检测/诊断此类故障——为"训练行为异常≠硬件故障"的可靠性测试提供数据驱动路径（窗口边缘补录）。来源: https://arxiv.org/abs/2607.12868

- **arXiv/Emulated Integrity Replica：FPGA SoC 分层孪生自愈**（2026-07-14, arXiv:2607.12298）: 通过层级孪生(HiT)在 FPGA SoC 上启用自愈，属硬件级完整性复制可靠性机制（窗口边缘补录）。来源: https://arxiv.org/abs/2607.12298

- **跨组标注**: arXiv/SCOUT 预训练失败定位（2608.11034, 2026-08-11）已被 tech 组同日收录（集群训练故障定位视角）——本组从"可靠性测试方法论"看其价值为：对称共识异常检测使同步传播的 rank 本地停滞/数值错误在作业级症状中被定位到源，补齐"训练框架侧 vs 后验日志 vs 离线健康测试"三方诊断缺口。不重复收录。来源: https://arxiv.org/abs/2608.11034

## 趋势要点

- **可靠性测试从"事后诊断"前移到"运行期契约+不变量门禁"**：B300 报告的 2.7s 预运行不变量门禁、Resume 契约的机器可查六属性、DNSSE 的 LTL 正确性规格——三条线共同指向"把可靠性断言写进系统语义"而非依赖事后日志。
- **运维度量基准被挑战**：B300 报告证明 utilization% 在 NCCL hang 期间失真（功率更可靠）；Application Failures 论文主张故障率以 node-hours 而非时间计量——两个独立的"度量失准"修正信号，可靠性测试的度量层需要重新校准。
- **checkpoint 语义成为 agent 工作流框架的隐性可靠性雷区**：Resume 论文实测 5 框架无一满足完整契约、LangGraph 甚至跨中断/崩溃语义分裂——agent 编排层持久化的可靠性远未达标。
- **窗口内 arXiv 新提交密集**：cs.DC 下 07-16~08-16 一个月窗口内 fault/checkpoint/reliability/resilien 相关新论文 25 篇，其中 LLM 训练/推理容错、checkpoint 语义、程序验证三类占主体，与 08-15 追踪的"容错范式从重启恢复转向无缝降级"主线延续。
