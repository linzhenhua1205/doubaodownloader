### 1️⃣ FT-HSDP — Meta FAIR 十万卡容错 HSDP（arXiv:2602.00277）

| 维度 | 内容 |
|:----|:------|
| **来源** | arXiv:2602.00277 · Jan 30, 2026 · **Meta FAIR**（Omkar Salpekar, Rohan Varma, Kenny Yu 等 23 位作者） |
| **核心方法** | 提出 **Fault Tolerant Hybrid-Shared Data Parallelism (FT-HSDP)**，以数据并行副本为容错单元。两大关键技术：(1) **FTAR (Fault Tolerant All Reduce)**——CPU 驱动动态增删参与者的控制逻辑，GPU 负责数据传输以保持最佳性能；(2) **非阻塞追齐协议 (Non-blocking Catch-up)**——恢复中的副本可在最小 stall 下重新加入训练 |
| **设计原理** | 同步训练要求所有 GPU 同时健康 → O(100K) GPU 故障频发导致效率极低。FT-HSDP 解耦容错粒度到 DP 副本级别：故障时仅将含故障 GPU/server 的单个副本下线重启，其他副本继续训练 |
| **实验数据** | • **故障恢复 stall 时间**：10 分钟 → **3 分钟**（降低 70%）<br>• **有效训练时间比率**：**44% → 80%**（提升 1.82×）<br>• **模型精度**：异步恢复不造成任何可测量精度退化 |
| **规模** | O(100K) GPU 生产级验证 |
| **核心洞察** | FT-HSDP 揭示了十万卡规模下同步训练的不可持续性——44% 有效时间意味着超过一半的 GPU 周期浪费于故障等待。将容错粒度从"全局所有 GPU"细化为"DP 副本"是实用解法，且 FTAR 的 CPU/GPU 分工（CPU 做控制面、GPU 做数据面）为集合通信容错提供了可复用的架构模式 |
| **与前序工作对比** | 与 PHOENIX（热插拔零开销检查点，07-12 已记）互补：PHOENIX 关注永久节点故障下的快速替换，FT-HSDP 关注故障期间的连续训练（不换节点，只下线故障副本+追齐）。两者可叠加使用 |

### 2️⃣ TierCheck — 三层分级检查点（arXiv:2605.17821）

| 维度 | 内容 |
|:----|:------|
| **来源** | arXiv:2605.17821 · May 18, 2026 · **Patrick P. C. Lee 组（CUHK）** |
| **核心方法** | 提出 **TierCheck**，一种 cluster-aware 分级检查点系统。三层设计：<br>• **Tier 1（本地内存）**：轻量级差分检查点，快速写入 GPU 本地/peer 内存<br>• **Tier 2（Peer 内存）**：跨节点冗余副本，加速局部故障恢复<br>• **Tier 3（远程持久存储）**：异步迁移基检查点至远端持久化<br>核心挑战：跨层严格全局一致性（不 stall 训练）+ 快速 cluster-aware 恢复 |
| **设计原理** | LLM 训练面临异构故障谱——从常见 GPU 崩溃到灾难性集群级宕机。现有单层存储系统迫使你在"保存开销"和"恢复速度"之间做取舍。TierCheck 的核心洞察：**故障的异构性要求存储分层的异构性**——把高频轻量检查点放近端内存应对局部故障，基检查点异步刷远端应对全局故障 |
| **实验数据** | • 模型规模：**40B 参数**<br>• 端到端检查点时间：**< 10 秒**<br>• 支持高频检查点（传统单层方案无法同时做到快保存+快恢复）<br>• 训练开销低 |
| **与前序工作对比** | 与 BitSnap（检查点稀疏化+量化，16×压缩）和 LLMTailor（层选择性检查点，4.3×缩小）正交：TierCheck 解决的是存储层次设计 → 三者可组合使用：LLMTailor 决定存哪些层 → BitSnap 压缩所选层 → TierCheck 将结果分层存储 |

### 3️⃣ GPU SDC Anatomy — 生产级 GPU 静默数据损坏模式分析（arXiv:2605.04213 · **IEEE DSN 2026**）

| 维度 | 内容 |
|:----|:------|
| **来源** | arXiv:2605.04213 · May 5, 2026 · **Accepted at IEEE/IFIP DSN 2026 (Industry Track)**（NVIDIA 作者群：Chung-Hsuan Tung, Yanxiang Huang, Nirmal Saxena 等） |
| **核心方法** | 对某生产级数据中心 GPU 进行了超大规模的 **gate-level stuck-at fault injection**，消耗 **3,000,000+ 模拟小时**，覆盖 **63 个 CUDA 微基准测试**。提取了 GPU SDC 的三大特征维度：(1) 损坏类型分布 (2) 比特翻转行为 (3) warp 对齐空间相关性 |
| **关键发现** | • **NaN/+INF/-INF 仅占 SDC 结果的 1.01%**（依赖 NaN 检测的常规机制漏检率高达 99%）<br>• **单比特翻转占比 < 40%**（大多数是多比特/突发翻转，ECC 无法完全防护）<br>• **损坏地址存在周期性（periodicity）**——暗示有硬件结构级模式可建模<br>• 这些统计数据为 **distribution-aware 高层故障建模**和 **realistic software-based fault injection** 提供了理论依据 |
| **工程意义** | 这是已知公开文献中对生产级 GPU SDC 特性最详细的一次 gate-level 刻画。1.01% NaN 比率的发现直接挑战了"多数 SDC 会表现为 NaN/INF"的行业常识，说明现有基于 NaN 检测的软错误防护机制存在严重盲区。<40% 单比特翻转意味着 ECC 的保护覆盖率不足 60%，需要配合算法级 SDC 容忍（ABFT/checksum 等） |
| **与前序工作对比** | 与 Explore SDC（arXiv:2604.00726, CCGrid 2026，07-12 已记）互补：Explore SDC 关注 SDC 对 LLM 训练的影响及轻量检测方法，本工作从 gate-level 揭示 SDC 的底层硬件特征——两者构成"硬件特征 → 训练影响 → 检测方法"的完整链条 |

## 🧭 今日新增趋势判断

- **趋势十七** 🏭 **十万卡容错从理论走向生产验证** —— FT-HSDP（Meta）是首个公开的 O(100K) GPU 容错系统实战报告，44%→80% 有效训练时间的提升表明：十万卡规模下"全部同步"范式已被证伪，DP 副本粒度的异步容错正在取代全同步训练。与 PHOENIX（热插拔，512 GPU）、SPARe（ICML'26，模拟 600K GPU）形成从生产验证→物理集群→仿真预测的完整验证谱系

- **趋势十八** 🗂️ **检查点技术进入"分层+感知"多维优化时代** —— 2026上半年已出现四条正交优化路线：(1) 分层存储（TierCheck 三层架构）；(2) 层感知选择（LLMTailor 非线性层更新）；(3) 稀疏化+量化（BitSnap 16×压缩）；(4) 免持久化 P2P 迁移（ETC 2.33-6.37×）。这四条路线互相正交，为实际系统提供了灵活的"组合式"配置空间

- **趋势十九** 🔬 **GPU SDC 研究从宏观观测进入微观刻画** —— GPU SDC Anatomy（DSN 2026）的 3M+ 模拟小时 gate-level 注入首次揭示了 SDC 的底层特征（NaN 仅 1.01%、多比特翻转占 >60%、地址周期性），这与 Explore SDC 的应用层影响分析（CCGrid 2026）、TTrace 的静默缺陷检测（07-12）共同构成 "硬件特征 → 训练影响 → 在线检测"的完整闭环
