### 1️⃣ 🔀 ADA-ST: 跨层故障注入规划 — 3/4 故障传播面未被锻炼

**来源**: [arXiv:2607.16161](https://arxiv.org/abs/2607.16161) · 2026-07-17 · cs.DC/cs.SE · **Saurabh Kulkarni, Yuxin Yang 等（超大规模运营商）**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | GPU平台多层自愈管线（硬件/固件/管理软件/编排）间故障跨层传播可绕过检测、污染诊断、触发冲突修复——但常规故障注入**逐层孤立测试**，跨层场景未被覆盖 |
| **核心方法** | **ADA-ST**（自适应故障注入）：加权故障传播图引导跨层场景选择；四层图建模三代平台（Alpha/Beta/Gamma）；**FLAM**（Fault-Layer Abstraction Mapping）跨代迁移传播知识 |
| **量化数据** | • 平台Alpha：4年 **72,550 修复工单**，其中 **49% 涉及跨层故障传播**<br>• 现有静态测试仅覆盖 **20-25%** 建模传播边 → ~3/4跨层攻击面未锻炼<br>• ADA-ST 迭代选择达全边覆盖：Alpha 10轮 / Beta 12轮 / Gamma 9轮<br>• FLAM 跨代保真：Alpha→Beta 100%，Beta→Gamma 96%<br>• 物理点验证4条传播边全部确认；暴露缺陷: 遥测盲区、基于缺失的检测空档、多信号相关失效、L2→L3边界信任无验证传播 |
| **核心洞察** | 跨层传播是超大规模GPU集群故障的主通道（49%），而现有注入测试只覆盖 1/4 攻击面——**故障注入必须从单层走向跨层图驱动**。FLAM 知识迁移让新一代平台无需重做全部注入规划，与 07-30 多故障注入工具链形成方法论闭环 |

### 2️⃣ 🧩 UEP: 从位位置敏感度到非均匀错误保护（MICRO 2026）

**来源**: [arXiv:2607.19623](https://arxiv.org/abs/2607.19623) · 2026-07-21 · cs.AR · **Muhammad Husnain Mubarik 等（MICRO 2026 接收）**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 均匀 SECDED（12.5%存储开销）对所有位一视同仁——但 DNN 权重中低位分数位翻转几乎无影响，高位数/指数位翻转致灾难性崩溃，均匀保护过度保守 |
| **核心方法** | 16 工作负载（transformer+无注意力CNN）× 3 浮点格式逐位位置故障敏感度特征化；推导 **Xsafe 阈值**（低于该位阶翻转<1%退化）；设计 **UEP 码**：每缓存行数据类型标签+双分区 SRAM，非关键分区可降电压 |
| **量化数据** | • Xsafe 下限: **FP16:6 / BF16:4 / FP32:15** 位（最低有效分数位可免保护）<br>• 敏感度在指数-尾数边界**尖峰**——单比特翻转致灾难性崩溃<br>• ECC 节省 **37.5-62.5%**（无需重训练）；ECC 面积 **-27.8%**（vs 均匀SECDED）<br>• BF16 非关键分区双电压 → 读能量 **-17%**，宏面积开销 ~4%<br>• **870+ 故障注入运行**验证：连续2-3位突发翻转下选择性保护仍成立；扩散模型是保守下限驱动者，视觉编码器/NLU/韧性LLM可放宽 |
| **核心洞察** | 「保护所有位」不是最优——可靠性预算应按**位位置敏感度**差异化分配。Xsafe 阈值给出可落地的分区边界，是 SDC 防护从「全覆盖」走向「智能覆盖」的定量依据（呼应 08-02 PSAP 的 1.1% 关键层发现: 关键位占比极小但决定脆弱性） |

### 3️⃣ 🔐 CKKS CPU 容错: 同态加密瞬态故障的 100% 检测

**来源**: [arXiv:2607.18720](https://arxiv.org/abs/2607.18720) · 2026-07-21 · cs.CR/cs.AR · **Jianan Mu, Ge Yu, Tenghui Hua 等（华为/清华）**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | FHE 长密文数据流+高维模算术使其对瞬态硬件故障引起的**静默数据损坏(SDC)**高度脆弱——现有方案要么针对专用加速器，要么在 CPU 上开销巨大 |
| **核心方法** | OpenFHE 实现三层开销削减：①**模感知桶校验和**（利用宽CPU累加器减少模约减）②**数据流融合算子内检查**（校验和嵌入算子数据流，避免长密文多项式二次扫描）③**跨算子检查融合**（相邻算子间去冗余校验和，保端到端不变量） |
| **量化数据** | • 随机单比特瞬态故障下：**150,000 非崩溃损坏案例 100% 检测率**<br>• 运行时开销 **6.0-8.4%**（平均 6.8%）；相对直接校验和保护开销 **-4.9×**<br>• 宽故障率范围内应用精度接近无故障基线 |
| **核心洞察** | 与 08-02 的 PSAP（剪枝侧降低加密域脆弱性）互补——本文从**运行时检测侧**补全 CKKS 容错：模感知桶校验和把开销压到 ~7% 量级，使同态加密推理的 SDC 防护首次在 CPU 上工程可行。加密域可靠性测试从此有「剪枝加固 + 校验检测」双保险 |

### 4️⃣ ⚖️ CoG 权重校正: 位翻转容错无需重训练

**来源**: [arXiv:2607.15753](https://arxiv.org/abs/2607.15753) · 2026-07-17 · cs.LG/cs.AR · **Bahram Parchekani 等（IEEE Trans 在审）**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 安全关键 DNN 易受硬件/内存故障损坏权重——现有方案需重训练或改架构，成本高 |
| **核心方法** | **CoG（重心）引导权重校正**：利用层内权重空间特征，基于距离感知校正规则**检测并恢复故障权重**，无需重训练、无需架构修改；不同 BER 下注入验证 |
| **量化数据** | • BER 10⁻³ 下 LSTM 容错提升: StageNet **230×** / MTFNet **6.41×**，精度损失可忽略<br>• CNN: ResNet-18 **49.55×** / VGG-16 **20.79×**（同故障条件）<br>• 首个将 CoG 概念用于神经网络权重张量提升可靠性的工作 |
| **核心洞察** | 「纠正错误」路线的低成本实现——距离感知规则让故障权重按空间特性恢复，规避重训练成本。与 07-30 的 RangeGuard（有界近似误差校正）、08-02 的 PSAP（选择性加固）共同验证「**限制/纠正影响优于全覆盖防护**」的低成本可靠性主线 |

|:----|:------|
| **核心问题** | 大规模 AI 数据中心平台硬件验证需**全面故障注入测试计划**——目前人工编写（读自愈文档+BOM、枚举FRU失效模式、产出扁平单层测试用例），耗时易错、覆盖缺口晚现、依赖机构知识 |
| **核心方法** | 生成式 AI 多智能体架构：**摄入智能体**（异构输入归一化）→ **分类智能体**（部件描述/子类层级→功能域映射）→ **生成智能体**（归一化失效模式×域分类数据合成测试用例，补缺口+产边缘用例）；输出标准化 schema 直接导入验证软件 |

### 6️⃣ 📊 Deep4ge: DNN 训练轨迹故障检测公开数据集（ICSME'26）

**来源**: [arXiv:2607.12868](https://arxiv.org/abs/2607.12868) · 2026-07-14 · cs.SE · **Sigma Jahan（ICSME Data & Tool Track 2026）**

| 维度 | 内容 |
|:----|:------|
| **核心问题** | 深度学习系统常因细微实现故障（subtle faults）改变训练行为而失败——但社区缺乏带故障史、特征提取细节、可复用支持的**逐epoch训练运行公开数据集** |
| **核心方法** | 从 Stack Overflow 收集 59 个 TensorFlow/Keras DNN 程序，用 **27 种源码变换**引入 7 类已知故障，生成受控基准；每运行记录 4 评估指标 + **26 个逐epoch训练行为特征**（权重/梯度/激活/精度损失趋势/学习率/硬件使用） |
| **量化数据** | • **14,227 次训练运行**: 9,845 faulty + 4,382 baseline<br>• 支持三任务: 二元故障检测 / 多类故障诊断 / **部分训练轨迹早期故障预测**<br>• 数据集公开: doi.org/10.5281/zenodo.20337241 |
| **核心洞察** | 故障注入从「单点实验」走向「可复现基准」——Deep4ge 让训练轨迹级故障检测可横向对比，是 08-01 RAPID-LLM（故障感知建模）的数据侧补全。对训练框架故障自愈系统的评测有直接复用价值 |
