## §1 🔬 arXiv：算力平台调度与资源管理（8/4-8/6）

- **HorizonServe — Coordinating Request Scheduling with GPU Sharing for Omni-Model Serving**（arXiv 2608.01785, 8/4）: 提出请求调度与 GPU 共享的联合协调框架，面向多模型(omni-model)服务场景；核心是让调度器感知 GPU 共享状态做全局请求编排。来源: https://arxiv.org/abs/2608.01785
- **Efficiency and Cost Alignment in Batched LLM Serving via Resource-Fair Scheduling**（arXiv 2608.02244, 8/4）: 批处理 LLM 服务中效率与成本的错配问题，以「资源公平」替代「请求公平」调度，使吞吐效率与 token 成本对齐。来源: https://arxiv.org/abs/2608.02244
- **TAOT: Topology-Aware Optimal Transport for Dynamic Expert Replica Placement in MoE Training**（arXiv 2608.03676, 8/5, 腾讯）: 用最优传输(Optimal Transport)解决 MoE 训练中专家副本的动态放置，拓扑感知避免跨域通信热点——MoE 平台调度的新数学工具。来源: https://arxiv.org/abs/2608.03676
- **AFD-Ledger: Deployment Provisioning for Attention–FFN Disaggregation**（arXiv 2608.04502, 8/6, 清华 Mingxing Zhang 组）: 为 Attention-FFN 解聚提供部署供给(provisioning)方案，含 14 页/14 图/2 表的完整设计——解聚从「能不能拆」走向「怎么部署」。来源: https://arxiv.org/abs/2608.04502
- **When Does Disaggregation Pay? Simulating Prefill–Decode–Attention–FFN Specialization for Agentic LLM Inference**（arXiv 2608.03741, 8/5）: 用模拟回答解聚经济性问题——四角色(prefill/decode/attention/FFN)专业化在 Agentic 推理负载下何时值得，为平台架构决策提供成本边界。来源: https://arxiv.org/abs/2608.03741
- **Energy-Efficient LLM Serving via Disaggregated Attention–FFN and Flexible Frequency Scaling**（arXiv 2608.01891, 8/4）: 解聚 Attention/FFN + 动态频率调节(DVFS)双管齐下降低 LLM 服务能耗——解聚与能效管理结合。来源: https://arxiv.org/abs/2608.01891
- **DEFT: Joint Task Placement and DVFS for Energy-Efficient Multi-GPU Runtimes**（arXiv 2608.02122, 8/4, ICS'26 已录用）: 多 GPU 运行时中任务放置与 DVFS 联合优化，能效导向的 GPU 资源管理。来源: https://arxiv.org/abs/2608.02122
- **NIXT: A NCCL Inspector Exporter Tool for Observability of Collective Communication in Large Model Training**（arXiv 2608.01449, 8/4, IEEE IISWC 2026 已录用）: NCCL 集合通信的可观测性导出器——大模型训练平台从「看GPU利用率」下沉到「看NCCL通信内部状态」，与 NVIDIA 侧 NVLink/SHARP 诊断能力呼应。来源: https://arxiv.org/abs/2608.01449
- **PrefixPlace: Provable Prefix Key-Value Placement for LLM Serving under Heterogeneous Compute and Transfer Costs**（arXiv 2608.01655, 8/4）: 异构算力与传输成本下前缀 KV 的可证明最优放置——KV Cache 成为平台调度的显式资源维度。来源: https://arxiv.org/abs/2608.01655
- **Preserving Admission Responsibility in Multi-Tenant Large Language Model Prefix Caches**（arXiv 2608.01657, 8/4）: 多租户前缀缓存的准入责任(admission responsibility)保留——共享缓存场景下租户隔离与缓存准入的权责边界。来源: https://arxiv.org/abs/2608.01657
- **Analyzing GPU Performance in Virtualized Environments: A Case Study**（arXiv 2608.02414, 8/4）: GPU 虚拟化环境性能案例分析（18页/12图/5表）——虚拟化叠加层对 GPU 平台性能影响的系统测量。来源: https://arxiv.org/abs/2608.02414
- **Learning-Based Collaborative MEC for LLM Inference with Soft-Deadline Awareness**（arXiv 2608.02031, 8/4, IEEE GLOBECOM 2026）: Transformer 增强 PPO 的移动边缘协作 LLM 推理调度，软截止时间感知——边缘算力平台的强化学习调度。来源: https://arxiv.org/abs/2608.02031

## 🧠 平台视角解读

- **调度对象升级**: 本期 arXiv 显示调度粒度从「任务→节点」升级为「请求→GPU共享态」「专家副本→拓扑」「前缀KV→异构放置」三层并行演进——算力平台的核心竞争力正从排队器变为「结构感知的资源编排器」
- **可观测性纵深**: NIXT(NCCL级)+OpenCost(token级) 与 CNCF OTel 毕业共同指向：平台运维度量正在经历「利用率→通信内部状态→token成本」的细化，与 NVIDIA NVLink/SHARP 诊断、AIOps 数字孪生趋势同源
- **解聚从论文到产品**: Attention-FFN 解聚经济性模拟(2608.03741)+部署供给(AFD-Ledger)+能效(DVFS)三篇同周出现，加上 CoHDI 进 CNCF Sandbox——解聚化不再是「未来架构」，而是可部署、可核算、可优化的平台选项
- **国产平台信号**: 昇腾「集群自智引擎 CCAE + 大规模专家并行方案」显示国产智算平台在 MoE 推理场景的软件投入加速；官网新闻运营滞后是国产厂商信息获取的持续短板（需转投微信/公众号渠道）
