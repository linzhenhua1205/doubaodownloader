## 一、平台调度研究前沿（arXiv，本组增量）

- **SAEM: 推理阶段感知的 MoE 专家管理**（arXiv:2608.21614, 2026-08-22, DAC 2026 扩展版, Yujie Zhang/Bin Gao/Tulika Mitra）: Stage-Aware Expert Management for Memory-Efficient MoE Inference in Chain-of-Thought Reasoning——面向 CoT 推理的 MoE 内存高效专家管理；扩展版新增 AIME 2024 / GPQA-Diamond 评测与 prediction-oracle 上界分析。平台含义：CoT 的 thinking 阶段（长序列 + 密集 token 生成）与 answer 阶段专家活跃度/内存压力差异大，**专家生命周期管理需按推理阶段调度**（加载/驻留/卸载），与 MEMORY 中 MoE 硬件主线（Kimi K3 16-of-896 专家、RoutePack 阶段感知调度）同构——「阶段感知」是 2026 MoE 推理平台的新优化维度。https://arxiv.org/abs/2608.21614
- **XPerf: Agentic AI 工作负载的 LLM serving 基准框架**（arXiv:2608.20370, 2026-08-21, Michael Wang/Yikang Yue/Shaobo Li/Yirui Eric Zhou/Chen Wang/Jian Huang）: Benchmarking LLM Serving Systems for Agentic AI Workloads——为 agent 类负载（多轮工具调用/长会话/状态依赖）建立 serving 系统基准；与 08-25 已收录的 Aries（agent 服务全栈观测：token 中心指标漏掉非推理瓶颈）互为补充：**agent 工作负载正在成为 serving 评测的独立类别**，传统 token 中心基准（ShareGPT 类）对工具执行/沙箱开销不敏感。https://arxiv.org/abs/2608.20370
- **Intent Engine: 意图驱动编排的自然语言翻译层**（arXiv:2608.20388, 2026-08-21, Journal of Systems Architecture 179:103938, Koushikur Islam/Rodrigo N. Calheiros）: Natural-Language Intent Translation for Intent-Driven Orchestration in the Compute Continuum——把用户自然语言意图（"跑这个训练任务并保证容错"）翻译为可执行编排策略；算力平台的用户接口层从「API/规格声明」向「意图声明」抽象化，是调度器语义的又一次上移（资源请求 → 工作负载画像 → 意图）。https://arxiv.org/abs/2608.20388
- **Fleet-Scale Pod 部署的 VPC 原生网络**（arXiv:2608.22210, 2026-08-24, 托管 K8s 生产实践）: Fleet-Scale Pod Deployment with VPC-Native Networking in Managed Kubernetes——托管集群大规模 Pod 部署的网络语义（VPC 原生寻址替代 overlay 隧道），减少 CNI 封装开销与地址转换，属算力平台网络底座的生产级工程验证。https://arxiv.org/abs/2608.22210
- **Sync Tax: GPU Scale-Up 域的同步开销量化**（arXiv:2608.22503, 2026-08-23, Arjun Devraj/Lindsey Bowen/Rachee Singh）: Understanding the Synchronization Tax in GPU Scale-Up Domains——系统性刻画 scale-up 域（NVLink/UALink 域内多 GPU 紧耦合）的同步成本来源与放大效应；reliability 组 08-25 以「性能方向非容错」记录排除，本组以算力平台视角收录：**同步机制（barrier/锁/一致性协议）是 scale-up 域互连的隐性开销税**，超节点/GPU 池化设计的互联带宽规划需把同步税纳入（与 MoE 通信 -74%（TAOT）、EP 负载均衡等调度收益形成互补视角）。https://arxiv.org/abs/2608.22503
- **交叉引用（reliability-testing 已收录）**: The Lazy Pod That Lies（2608.19412, 08-19）——K8s 模型服务懒加载镜像的失败语义表征（懒拉取 16.9~17.6s 冷启动 vs eager 24.5~573.0s，但全读 105.3s 慢于 eager 72.4s、快照缓存耗尽致运行中 pod 读模型失败），属部署侧可靠性，详见 reliability-testing 08-25。本组不重复。

## 四、追踪结论（趋势线）

- **Agentic AI 负载重塑 serving 评测与调度**：XPerf（基准）+ 08-25 Aries（观测）+ LOCAL（端侧 agent 运行时）三篇互证——**agent 工作负载（工具执行/沙箱/长会话/状态依赖）正在成为 LLM serving 的独立评测维度与调度约束**，token 中心指标与静态批处理假设在 agent 场景系统性失真；算力平台需为「agent 会话级资源生命周期」预留弹性（会话挂起/恢复、沙箱资源突发）。
- **编排语义第四次上移：意图驱动**：从「资源规格声明」（request/limit）→「工作负载画像」（workload-aware scheduling）→「意图声明」（Intent Engine 自然语言翻译）——**编排的用户接口层正沿抽象化方向收敛**；意图驱动的落地瓶颈在意图歧义消解与可审计性，短期仍是研究前沿而非生产能力。
- **Scale-up 域同步税成为互联设计新变量**：Sync Tax 首次把 GPU scale-up 域（NVLink/UALink）内的同步开销显性化——超节点架构的互连带宽规划除数据面（AllReduce/EP 通信）外，需计入同步面（barrier/一致性）开销；与 MoE 调度收益（TAOT 通信 -74%）构成「互联效率」的一体两面。
- **MoE 推理的「阶段感知」成为平台级优化维度**：SAEM（CoT 阶段专家管理）与 MEMORY 中 MoE 主线（Kimi K3、RoutePack、Load Hijack）衔接——**专家生命周期（加载/驻留/卸载）按推理阶段动态调配**是 MoE 平台内存效率的下一个主战场。
- **产业侧与学术侧错位延续**：本日增量 100% 来自 arXiv（5 篇），CNCF 零增量（第 2 日）、国产源连续 5 日空缺——「学术活跃、产业沉寂」错位进入第 3 个追踪日，KubeCon China（09-07）是产业侧下一个预期爆点。
