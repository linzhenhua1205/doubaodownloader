## 📡 本期核心信号

- **训练×推理弹性共置成为 K8s 原生正式主题**：ElastiCo 证明训练作业保留整卡但周期性空闲、离线推理过度供给但突发性的互补结构，用"资源形状变换+弹性影子定价+干扰感知共置"三机制让两类负载安全共享 GPU——资源池化从"静态隔离"（上期 DRA 分数请求编码）走向"动态弹性共置"，64-GPU 实测 + 512-GPU 仿真下平均 JCT 降 2.94×、集群吞吐 +2.02×、GPU 利用率约 25%→46%
- **Agent 工作负载颠覆平台三大隐含假设**：Aries 用商业平台生产 trace 证明①token-centric 指标漏检非推理瓶颈 ②保留额外上下文收益递减但显著挤占 serving 容量 ③tool sandbox 呈"长空闲-短突发"交替、快照式状态管理使激进挂起代价高昂——agent-native 平台需 trajectory 级指标、自适应上下文管理与弹性 sandbox，直接冲击当前以"吞吐/token"计量的平台设计
- **模型分发走向"OCI artifact 互操作标准"**：Docker Model Runner 新增 `docker model package --format=cncf` 直接产出 ModelPack（CNCF 项目，Nutanix/Ant/Jozu/Red Hat）格式 OCI artifact——模型打包格式标准化类比容器镜像生态成型，推理平台部署链路的"格式紧耦合"开始解耦
- **K8s 资源治理从"效率优先"转向"安全优先"**：Safety-Gated Autoscaling 用五层安全管线把内存泄漏检测做成"阻断门"——检测到泄漏就拒绝扩容建议，杜绝"用更大容器掩盖 bug"；GKE 实测 what-if 节省 20-40%、泄漏门检测率 83%——垂直资源优化把安全约束提升为一等公民

## 📄 arXiv 论文（cs.DC · 8/8-8/10 提交为主，2608 批次）

- **ElastiCo: Elastic Configuration and Interference-Aware Orchestration for GPU Clusters（2608.07971，8/8，Submitted to Performance Evaluation）**: 现网 GPU 集群调度器把训练与推理当作孤立资源消费者、静态分配——训练作业整卡预留但周期空闲，离线推理过度供给但需求突发，GPU 容量持续闲置；ElastiCo 三机制：①Resource Shape Transformation 把每个作业暴露为"可行资源-性能配置族"②Elastic Shadow Pricing 用动态 per-resource 影子价格把多资源分配问题分解为每作业配置选择子问题 ③Interference-Aware Co-location 用硬件计数器+任务级特征预测 GPU 共享下的成对性能退化；实现为 K8s 原生中间件（无需用户代码修改），64-GPU 测试床+最多 512-GPU trace 仿真：平均 JCT 最多降 2.94×、集群吞吐 +2.02×、GPU 利用率约 25%→46%——训练×推理共置从"资源复用技巧"升级为"弹性配置+干扰建模"的系统化方法，与 08-10 记忆线"池化内存/共享"主题同链。https://arxiv.org/abs/2608.07971
- **Rethinking AI Cloud Infrastructure for Agentic Serving Systems with the Aries Experimentation Framework（2607.29069，7/31）**: 自主 Agent 用"重复推理+持久上下文+沙箱工具执行"耦合挑战传统 LLM serving 假设；Aries 全栈实验框架（任务语义与执行配置分离、跨组件 agent 轨迹重建并关联系统遥测、异构 sandbox 统一接口）在开放 harness/benchmark + 商业平台生产 trace 上得出三发现：①token-centric 指标漏检非推理瓶颈（上下文管理/工具执行开销）②保留额外上下文带来递减的准确性收益却降低 serving 容量 ③tool sandbox 长时间空闲与短资源突发交替，而快照式状态管理使激进挂起代价高；补充安全分析指出需缩小 sandbox 攻击面——为 agent-native serving 系统（trajectory 级指标、自适应上下文管理、弹性 sandbox）提供证据基座，与下方 CNCF"Observability for AI Agents"构成学术×实践互证。https://arxiv.org/abs/2607.29069
- **How Accurately Can the Energy Use of Spark Applications Be Estimated Based on Resource Utilisation?（2608.09359，8/10，会议论文）**: 云上受限用户无法访问节点级硬件能耗计数器，能耗/碳归因依赖功率模型+资源利用率 trace，但精度缺乏对照验证；以 Spark-on-K8s 为案例，把模型估计与 Intel RAPL package+DRAM 实测对比（AWS bare-metal 云 + 本地集群，多种 CPU 使用信号与内存系数）：相对 Spark 任务 trace，外部监控把 package 能耗 signed error 从 AWS -29.58% → -24.41%、本地 -24.00% → -16.22%——即使改进后仍存在 16-24% 低估，碳核算/能耗分账的精度缺口量化，为算力平台"能耗可观测性"提供基线（上期 OpenCost 是成本侧，本篇是能耗估计精度侧）。https://arxiv.org/abs/2608.09359
- **Safety-Gated Autoscaling: A Multi-Layered Defense Architecture for Kubernetes Vertical Resource Optimization（2607.26503，7/29）**: 过度供给是 K8s 浪费主源，但内置 HPA/VPA 反应式且"可能掩盖软件缺陷"（给泄漏负载更多内存）；Intelligent Cluster Optimizer 开源 operator 把安全作为一等公民——五层安全管线：基于线性回归 R² 评分的内存泄漏检测器作为"阻断门"（检测到泄漏即拒绝扩容建议，绝不用更大容器掩盖 bug）+ SLA 监控 + 断路器 + HPA/PDB 冲突检测 + 策略引擎，带回滚与 dry-run 人工审批；建议由百分位分析+Holt-Winters 预测生成、per-container Pareto 多目标平衡；1118 个自动化测试 80.3% 覆盖，GKE 实测 what-if 成本节省 20-40%、泄漏门 83% 检测率——K8s 资源治理范式从"效率优先"转向"安全约束优先"，为算力平台垂直扩缩策略提供可直接采纳的安全管线模板。https://arxiv.org/abs/2607.26503

## ☸️ CNCF / K8s 生态（8/4-8/12 窗口，与上期 4 条不重复）

- **Advancing AI model interoperability with Docker and ModelPack（8/12，Red Hat Andrew Block）**: AI 模型管理工具与"格式×存储后端"紧耦合限制跨框架迁移与分发；ModelPack 项目（维护者含 Nutanix/Ant/Jozu/Red Hat）用 OCI artifacts 定义模型构建开放标准（config descriptor `application/vnd.cncf.model.config.v1+json`、manifest `application/vnd.cncf.model.manifest.v1+json`），与 Docker Model Runner（DMR，`application/vnd.docker.ai.model.config.v0.1+json`）协作：DMR 新增 `docker model package --format=cncf` 直接产出 ModelPack 格式，OCI registry（Docker Hub/Quay）通用——"模型即 OCI artifact"双格式互通，推理平台模型分发链路的格式解耦信号，与 08-10 记忆线"模型/权重管理"主题衔接。https://www.cncf.io/blog/2026/08/12/advancing-ai-model-interoperability-with-docker-and-modelpack/
- **You can't debug what you can't see — Observability for AI Agents（8/4，StackGen 首席工程师）**: 生产 AI agent 系统运行实践——传统 APM 无法解释"agent 为何比往常多花 3 倍时间反复问同一个问题"（工具调用/上下文循环不在追踪范围）；为 agent 构建观测需覆盖工具调用、上下文管理与多步轨迹而非单次请求——与 Aries（arXiv 2607.29069）的"token-centric 指标漏检非推理瓶颈"互为印证，Agent 工作负载可观测性需求在学术与工程两侧同时浮现。https://www.cncf.io/blog/2026/08/04/you-cant-debug-what-you-cant-see-observability-for-ai-agents/
- **CNCF Announces Graduation of Cloud Native Buildpacks（8/11，官方公告）**: Buildpacks 正式毕业——容器构建标准成熟化（面向应用的可复现构建抽象），云原生构建链路的官方背书；对算力平台属弱相关但为 CNCF 生态成熟度信号（同窗口 KubeCon China 9/7-9 上海四会联合的预热面）。https://www.cncf.io/announcements/2026/08/11/cncf-announces-graduation-of-cloud-native-buildpacks-advancing-the-standard-for-container-builds/
