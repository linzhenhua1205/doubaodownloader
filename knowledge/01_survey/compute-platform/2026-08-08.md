## 📄 arXiv 论文（cs.DC · GPU调度/资源管理，8/3-8/7 提交）

- **When Does Disaggregation Pay?（HeteroPanacea，2608.03741，8/4）**: PD-A-F（Prefill-Decode-Attention-FFN）四阶段解聚系统级模拟框架，覆盖解聚量化/自动并行调度/NPU 异构三轴；仿真显示 Prefill-Decode 解聚吞吐较传统服务最高 +75%，4 路解聚在跨模型时一致性最佳——为 Vera-Rubin（GPU）+Groq LPU 异构 Agentic 推理平台提供"哪种硬件负责哪段"的量化依据。https://arxiv.org/abs/2608.03741
- **ISJL: Efficiency and Cost Alignment in Batched LLM Serving（2608.02244，8/3）**: 形式化"资源公平调度"——批内最长 KV 占用决定整批步耗时（max-driven 成本），短请求被长请求拖累；ISJL 算法证明全局竞争比下界 3/4，在 FCFS（批外部性大）与 LJF（牺牲批灵活性）之间取得双目标折中，与商用 API token 计费对齐。https://arxiv.org/abs/2608.02244
- **HorizonServe: Request Scheduling + GPU Sharing for Omni-Model Serving（2608.01785，8/3）**: Omni 模型（文本/语音/图像多模态统一后端）共享主干+分叉生成阶段带来异构 SLO；协调请求准入+GPU 分配，SLO 达成率最高 +4.9×（到达率扫描）/7.0×（下游重流量），分阶段首响应延迟 -38.4%~63.7%。https://arxiv.org/abs/2608.01785
- **PrefixShield: Admission Responsibility in Multi-Tenant Prefix Caches（2608.01657，8/3）**: 识别"准入责任鸿沟"——共享前缀缓存中一租户物化 KV 会驱逐另一租户的可复用状态；PrefixShield 计量新物化 KV 块+跨请求责任传递+负债期间门控复用提升，受害方缓存命中率较 LRU +9.39pp（4096 块规模从 4.92% 恢复到 84.87%）。https://arxiv.org/abs/2608.01657
- **AFlex: Energy-Efficient LLM Serving via Disaggregated Attention-FFN + DVFS（2608.01891，8/3）**: 发现 Attention/FFN 能量最优频率不同且随相位/负载变化；全局调度器+算子级 DVFS 控制器+交错 A/F 流水线，SGLang 实现（Qwen3-32B/Mixtral-8×7B，A800），每 token 能耗较 SOTA 解聚服务 -49%、较纯频率缩放 -48%，同时满足 TTFT/TPOT SLO。https://arxiv.org/abs/2608.01891
- **DEFT: Joint Task Placement and DVFS for Multi-GPU（2608.02122，8/3，ICS'26）**: 能效感知调度联合优化任务-设备分配与每 GPU DVFS，显式建模任务执行成本/GPU 间数据移动/DVFS 转换开销；CUDASTF 原型，L40S/L4 能耗 -14.8%/-4.8%、EDP -9.9%/-3.7%，性能损失 <1.5%。https://arxiv.org/abs/2608.02122
- **DeltaServe: Co-Serving Inference + LoRA Fine-Tuning（2607.28848，7/30）**: 将推理峰值预留的空闲 GPU 算力转化为 LoRA 微调吞吐（host-agnostic，仅需多 LoRA 批支持）；SLO 感知调度器+CUDA-graph 延迟模型，生产 trace 下微调吞吐较 LLMStation +2.9×（100% 推理 SLO 合规 vs 其 85%）。https://arxiv.org/abs/2607.28848
- **Libra: Long-Context Training Load Balancing via Bounded Sequence Pool（2607.23250，7/25，阿里）**: 长上下文训练注意力成本∝序列长度平方和，等长 packed 序列负载不均；以"注意力均衡池不必随 DP 增长"（大数定律）为缩放原则，Qwen3-Turbo 256K/1M 训练端到端吞吐较 Ulysses 最高 +2.54×，已在 32K-1M token 生产任务跑数十万 GPU 小时。https://arxiv.org/abs/2607.23250
- **Gleam: CUDA API Remoting for Cross-Device GPU Sharing（2607.23115，7/25）**: LAN 内异构设备 GPU 共享，模型权重自动缓存+异步执行+网络/竞争感知运行时调度，API remoting 效率 1.4-24.2×、系统吞吐最高 1.79×——边缘"算力池化"技术路线。https://arxiv.org/abs/2607.23115
- **TileSight: Tile-Centric Analytical GPU Performance Model（2607.22432，7/24）**: Triton/TileLang/CUDA Tile 时代缺少 tile 中心性能模型；从核内流水线重叠到核间缓存层次到节点间通信三层统一 tile 抽象，A100/H200/B200/B6000 单 GPU 延迟预测 MAPE 12.35%，32 GPU 分布式核 wMAPE 16.18%，vLLM 端到端 13.52%。https://arxiv.org/abs/2607.22432
- **Agentic CPU-GPU Scheduling for Heterogeneous AI Workloads（2607.22242，7/24）**: 画像 19 个 AI 工具发现 11 个 GPU 优先/4 个模糊/1 个 CPU 优先（PCIe 传输主导）/3 个中性——"全 GPU 优先"策略次优；LLM 智能体+算法运行时监控（运行均值/对称重探/交换重探/探索提示）13 场景全部达到暴力最优映射，零离线训练，超 HEFT/StarPU/all-GPU。https://arxiv.org/abs/2607.22242
- **ExpertPlex: High-Goodput Disaggregated Serving for MoE（2607.18002，7/20）**: 大规模 MoE 专家跨相位共享（去重 >95% 重复权重）+ 轻量注意力模块解聚；自适应持久内核+tile 粒度调度，MiniMax-M2.7/GLM-5.1-FP8 goodput 较实例级 PD 解聚 +2.01×、较 PD 共置 +1.66×。https://arxiv.org/abs/2607.18002
- **Talaria: Session-Aware Serverless Serving of 100B+ LLMs（2607.17181，7/19）**: 工具型 Agent 会话跨短工具间隙连续调用 LLM、携带长可复用 KV 前缀；路由按模型驻留/KV 局部性/实例压力排序+软预留+Session-Prefill 提前准入，SWE-Bench 30 会话（960 调用，3 个 100B+ 模型）p50 SCT 1000s→189s（5.3×）、p95 2296s→867s（2.6×）。https://arxiv.org/abs/2607.17181
- **HeaRank: Don't Predict, Prioritize GPU Reliability（2607.15115，7/16，SIGKDD'26）**: 生产集群 telemetry 显示 GPU 重大故障（DBE/GPU Lost）强随机、低信噪比，绝对时间预测本质困难；转向"相对风险排序"（Learning-to-Rank），AUC 0.83，在线部署 top 5% 节点捕获 64% 未来故障（现网系统仅 21%）——风险感知调度新范式。https://arxiv.org/abs/2607.15115
- **MoE Tile-Level Communication-Computation Overlap（2607.19539，7/21，ICPP'26）**: 持久计算核（覆盖本地专家+远程关键 tile 优先）+小分区 SM 上的持久通信核按 tile 就绪发段粒度传输，4×A100 三 MoE 模型端到端最高 +2.64×、MoE 层 +2.74×，无需侵入算子/通信原语。https://arxiv.org/abs/2607.19539
- **DualDecoder: Predictive Prefetch for Long-Context Inference（2607.26475，7/29）**: 稀疏 KV 缓存离载到 host 的检索管理辅助状态成高并发新瓶颈；关键 KV 条目可由前一推测 token 预测→预取与解码重叠（双 token 解码流水线+层感知传输调度），解码吞吐最高 +2.62×，保持延迟与质量。https://arxiv.org/abs/2607.26475
- **JoyNexus: Multi-Tenant Post-Training for VLA Models（2607.16074，7/17）**: 机器人 VLA 后训练（SFT/RL/评估）多租户服务：训练/推理/环境服务解耦 API 化+租户槽位隔离+异构数据组批共享骨干前向，解决"独占卡时计费下突发短负载双输"问题。https://arxiv.org/abs/2607.16074
