## 📡 本期核心信号

- **Scale-Up 拓扑感知从"芯片内 NUMA"走向"芯片间非均匀网络访问"**：NUNA（AMD）在多 die GPU 中发现 die 间走线延迟显著影响 latency-sensitive 集合通信，提出 NUNA-aware 路由（NAR）+ 放置（NAP），collective 最高 +1.8×、推理每 token 提速 7% 均值/28% 最大——GPU 规模扩张使"拓扑优化"进入 Scale-Up 网络的显式调度维度（与 08-07 记录的控制面/数据面分离原则互补）
- **池化内存从"容量共享"升级为"近数据处理（NDP）"**：PLoRA 将多 LoRA 适配器+KV 留在 CXL/NVLink 类池化内存中、仅回传规约结果，H100 上 1000 适配器 decode 延迟平均比 S-LoRA 低 6.6×，且链路吞吐在 32GB/s（CXL 3.1 的 1/4）即饱和——"链路停止起作用，盈余带宽换容量"，为 08-08 P10 复盘（CXL 池化对冲 DRAM 涨价）提供执行侧量化依据
- **解聚进入"跨厂商异构内存"阶段**：HMA-Serve 用 GDDR 加速器做 prefill + HBM GPU 做 decode（MemHA），goodput +3.2×、goodput-per-dollar +4.8×；同时暴露跨厂商两大障碍——KV 格式两端非原生、软件栈不共享（单厂商解聚的隐性前提）
- **算力平台安全出现"负载→电网" cyber-physical 新攻击面**：Bit2Watt（CHES'26）证明合法租户仅凭 GPU 工作负载调制即可诱发高频功率波动（1000 GPU/1MW/90% DER 场景 THD 升至 46.8%、阻尼比 -0.27），常规云/设施监控因高频分量弱捕获而难检测——与 800V HVDC/供电主题直接联动，调度器或需纳入功率谱约束
- **CNCF 生态：CoHDI 进 Sandbox**——Kubernetes 向"可组合解聚基础设施（Composable Disaggregated Infrastructure）"演进获得官方通道，GPU/内存池化的云原生标准化再进一步（呼应 08-08 解聚工程化主线）

## 📄 arXiv 论文（cs.DC · GPU 调度/资源管理/池化，8/1-8/6 提交为主）

- **NUNA: Characterizing and Mitigating Non-Uniform Network Access in Multi-Die GPU Scale-Up Systems（2608.00867，8/1，AMD）**: 定义"非均匀网络访问（NUNA）"——多 die GPU 规模增长使 die 间走线延迟成为不可忽略维度，先例研究只优化 socket 内计算/内存局部性而忽视 inter-GPU 通信的空间影响；提出 NUNA-aware 路由（NAR，选择空间感知 die 间路径）+ NUNA-aware 放置（NAP，threadblock/数据贴近 I/O），NAP 单独最多 1.5× collective 加速、NAP+NAR 组合最多 1.8×，LLM 推理每 token 时间平均 -7%（最大 -28%）——Vera-Rubin 级 Scale-Up 拓扑调度的直接输入。https://arxiv.org/abs/2608.00867
- **PLoRA: An NDP-Enhanced Pooled-Memory System for Cost-Efficient Multi-LoRA Serving（2608.05483，8/6）**: 多 LoRA 服务（1000+ 适配器）工作负载与 GPU 能力"倒挂"（TB 级内存 vs 几十 TFLOPS），且现网系统全部经 PCIe 从 CPU DRAM 阶段化适配器（每次访问付内核停机+host 拷贝）；PLoRA 把适配器+KV 留在 CXL/NVLink 池化内存、GPU 用 load/store 驱动"读-计算"接口仅回传规约结果，GPU 内存管理层按链路参数化成本模型选择 4 种 LoRA+2 种注意力执行策略；H100/1000 适配器 decode 延迟平均低于真机 S-LoRA 6.6×（额外面积 <3.4%），吞吐在短上下文 32GB/s 饱和（CXL 3.1 的 1/4），从 7B 到 1.2T 部署 per-GPU 需求随 TP 分片而下降，CXL 级到 NVLink 级织物无需改动运行。https://arxiv.org/abs/2608.05483
- **HMA-Serve: Efficient Disaggregated LLM Serving across Memory-heterogeneous Accelerators（2606.29986，6/29，MemHA）**: 指出解聚的隐性前提——单厂商 KV 格式两端原生、软件栈共享；跨厂商内存异构（GDDR prefill + HBM decode）打破两个前提，需相位级量化（prefill 用厂商原生低精度、decode 保持 BF16）+ 计算-传输流水线（每层 KV 传输与后续层 prefill 重叠）+ 延迟反量化（原始量化字节传输、decode GPU 惰性重建）；Qwen3 4B-32B 三生产 trace 下 goodput 最高 +3.2×、goodput-per-dollar +4.8×，生成质量无可测损失。https://arxiv.org/abs/2606.29986
- **Bit2Watt: A Cyber-Physical Vulnerability Exploiting GPU Workloads Across Power and Computing Infrastructures（2607.05993，7/7，CHES'26）**: 算力平台安全新范式——攻击者作为"合法租户"仅操控 GPU 负载产生受控高频功率调制，经电力电子接口（高 DER 渗透场景）放大谐波/阻尼退化并回传干扰计算服务；阻抗分析+功率系统仿真+GPU/光伏逆变器实机验证：同步最坏聚合 1000 GPU/1MW/90% DER 下电流 THD 升至 46.8%、阻尼比 -0.27，可触发保护机制甚至级联故障，并存在 Watt2Bit 反馈路径（DoS/EMI 侧信道隐蔽外传）；因高频分量被常规遥测弱捕获而难以检测——提示算力平台监控需把"功率谱"纳入租户侧行为基线。https://arxiv.org/abs/2607.05993
- **SPDP: Unified Static-Dynamic Pruning for Efficient LLM Inference（2607.21985，7/24，PVLDB'26）**: 统一静态剪枝（永久移除冗余权重、缺自适应性）与动态剪枝（随输入稀疏度自适应、缺规律性）；Tiled-CBC 位图压缩格式 + 双 GPU kernel（CUDA 核 spMspV 做激活感知动态共享内存位图解码 + Tensor Core SpMM 做 prefill）；推理优化 GPU 上比 SpInfer 平均 1.24-1.37×（最高 2.51×），稀疏度 +25% 下困惑度持平——推理平台稀疏执行的新 Pareto 前沿。https://arxiv.org/abs/2607.21985
- **MCHA: A Memory-Centric Hierarchical Architecture for Parallel-Sequential Computing（2608.04443，8/5，MICRO'26）**: 面向 MARL/神经形态/概率图模型等"并行-顺序"负载（常规架构全局 buffer 饱和+访存瓶颈）；分层通信策略降低全局内存带宽压力+事件驱动条件触发隐藏传输延迟；开源 cycle-accurate 模拟器验证 MARL 相对 A100 加速 153-2457×，主存访问占比 96%→5.44%，28nm 综合 2.92mm²/115.36mW@200MHz——算力平台"内存中心"形态的候选硬件基座。https://arxiv.org/abs/2608.04443
- **BaseRT: Advancing Best-in-Class LLM Inference with Apple M5 Neural Accelerators（2607.19438，7/21）**: M5 代每核内建神经加速器（Metal 4 tensor API 暴露）；BaseRT 原生运行时把 compute-bound GEMM 路由到 M5 神经加速器、memory-bound decode 留在专用 kernel；M5 Pro 上 15 模型配置（Qwen3/3.5/3.6/Llama 3.2/Gemma 4，sub-1B-35B）prefill 吞吐最高 6.4× vs llama.cpp、3.9× vs MLX（MoE 增益最大），decode 1.75×/1.33×——边缘/端侧推理平台的性能上限被"每核张量单元"重定义。https://arxiv.org/abs/2607.19438
- **COSM: A Cooperative Scheduling Framework for Concurrent PIM and CPU Execution on Mobile Devices（2606.30553，6/30，ISCA'26）**: 端侧 LLM 场景 CPU+PIM 共享内存并发（DRAM bank 冲突/总线拥塞）；低干扰 PIM 控制接口（不打断 CPU 访存的最大 PIM 命令流）+ 空闲感知调度（把 PIM 命令插入 CPU 访问序列的空闲窗口）；并发 LLM+移动负载 PIM 吞吐最高 +2.8×、CPU 性能损失 <2.0%——存算一体在移动平台的调度器级协同。https://arxiv.org/abs/2606.30553
