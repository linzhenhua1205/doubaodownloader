## 一、平台调度研究前沿（arXiv：索引延迟恢复，08-26 新提交可见）

- **Slasher: Power Flexibility for Cloud Datacenters**（https://arxiv.org/abs/2608.26021, 08-26, Microsoft Azure）: 通用数据中心电力调节系统——覆盖从单机架到区域多数据中心电网事件的功率调制场景（基础设施故障/电网故障/电网服务），协调数据中心资源在**满足功率目标的同时最小化对托管负载的影响**；基于生产云数据中心数据刻画降载杠杆、形式化功率调制控制问题。与 hardware 组 08-28 收录的 NVIDIA DSX MaxLPS（站点级电源管理）形成互补：**硬件侧"站点级功率调度"与软件侧"工作负载感知降载"正在同一问题域收敛**——电力灵活性成为算力平台的一等公民能力，而非散热/供电的附属话题。
- **ElastiCo: Elastic Configuration and Interference-Aware Orchestration for GPU Clusters**（https://arxiv.org/abs/2608.07971, 08-08）: 训练 + 离线推理弹性共置框架——三机制：Resource Shape Transformation（每个作业暴露为可行资源-性能配置族）、Elastic Shadow Pricing（动态 per-resource 影子价格把多资源分配分解为 per-job 配置选择）、Interference-Aware 编排。直击"训练作业整卡预留但周期性空闲、推理作业突发性过配"的 GPU 池化利用率痛点；**这是对 CNCF AI factory 文章"瓶颈是利用率而非模型服务"的学术侧答案**——弹性配置族 + 影子价格定价可作为池化调度器的经济学基座。
- **OpScale: Operator-level Provisioning and Autoscaling for LLM Serving**（https://arxiv.org/abs/2608.13499, 08-13）: 提出扩缩容粒度问题：现有方案以整个模型为 monolithic 扩缩容单元，粗粒度导致突发下 SLO 违约或 GPU 欠利用率；OpScale 实测算子级异构性（operator-level elasticity），做 profiling/provisioning/placement/runtime 四段算子级编排。**扩缩容粒度的下一跳：从模型级→算子级**，与 MoE 稀疏激活（部分专家热、部分冷）天然契合，对平台侧弹性伸缩策略设计有直接参考价值。
- **Beyond the Limits: Flexible and Congestion-Aware Cluster Scheduling**（https://arxiv.org/abs/2608.09308, 08-10）: 集群调度两大缺陷修复——(i) 软 SLO 限制：允许受控过承诺（overcommitment）与容忍短暂轻微违约，提升集群效率与能效；(ii) 共享资源（LLC/内存带宽）拥塞感知调度与重调度。与 2608.25712 的超卖框架互证：**"软 SLO + 受控过承诺"正在成为云集群提效的共识路径**（从"硬隔离"走向"可审计的软边界"）。
- **An Oversubscription and Service Pricing Exploitation-Based Profit Maximization Framework**（https://arxiv.org/abs/2608.25712, 08-26）: 产业云资源管理框架——超卖 + 异构服务定价双杠杆最大化利润：自适应集成学习预测 VM 资源利用、Fuzzy C-means 聚类相似负载 VM、区分 Delay Sensitive / Best-effort 两类定价模型。平台商业化视角：**超卖比例与定价模型联合优化成为多云/智算平台盈利模型的新研究点**（08-26 最新提交，索引恢复后的首日增量）。
- **Agentic CPU-GPU Scheduling for Heterogeneous AI Workloads**（https://arxiv.org/abs/2607.22242, 07-24）: 实测 19 个 AI 工具 GPU/CPU 偏好：11 个 GPU 优先、4 个模糊、1 个 CPU 优先（PCIe 传输主导）、3 个中立——**证明 blanket GPU-first 调度次优**；提出 LLM agent + 算法运行时监视器配对调度器（监视器用运行均值/对称再分箱扩展 LLM 可观察范围）。对异构平台含义：GPU 不是万能资源，**设备指派需要"按工具实测画像 + 运行时争用感知"**，与 ViBE（tech 组 08-28 收录）的变异性感知放置同向。
- **HorizonServe: Coordinating Request Scheduling with GPU Sharing for Omni-Model Serving**（https://arxiv.org/abs/2608.01785, 08-03）: Omni 模型（文本/语音/图像/多模态统一后端）单 GPU 上的共享阶段时间共享 + 并行阶段空间共享联合控制，按类别 profile 首响应延迟、保护 slack 受限请求。**GPU 共享调度对象从"同质 LLM token 流"扩展为"异构模态请求流"**——多模态时代共享调度的新维度。

## 五、追踪结论（趋势线）

- **"利用率"成为中西两侧平台叙事的共同主轴（第 2 个互证点）**: CNCF AI factory 文章（利用率而非峰值吞吐是 GPU 云的评分标准）+ ElastiCo（训练/推理弹性共置）+ OpScale（算子级扩缩容）+ Beyond the Limits（软 SLO 过承诺）+ 超卖定价框架——**学术与产业两侧同周指向"从硬隔离走向可审计的软边界/弹性共享"**；对国产平台的含义：池化调度器的经济学设计（影子价格/超卖定价/计量计费）将决定利用率上限，纯技术调度（亲和性/优先级）已不够。
- **电力灵活性成为平台层新能力维度**: Slasher（软件侧工作负载感知降载）+ DSX MaxLPS（硬件侧站点级功率调度）同日互证——**固定功率预算下的"功率-负载协同调度"从机柜级升维到站点/区域级**，对平台架构师：功率预算应进调度器约束（而非仅 PUE 指标）。
- **异构设备指派需要实证画像而非默认 GPU-first**: Agentic CPU-GPU 论文的 19 工具画像（仅 11 个 GPU 优先）提供反直觉数据——**平台调度默认策略"GPU 优先"在异构负载下次优**，与 ViBE（硬件变异性感知）同向，国产异构平台（昇腾/昆仑芯/寒武纪混合池）应建立 per-工作负载设备画像库。
- **Baidu 间歇性放行是源状态关键变化**: 若维持，中文增量通道从"搜狗独苗"变为"双通道交替"；Bing 相关性验证留待英文查询专项。KubeCon China（09-07）仍为产业侧最近爆点。
