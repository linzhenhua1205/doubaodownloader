## 一、平台调度研究前沿（arXiv GPU Scheduling 最新）

- **arXiv/Beyond the Limits (2608.09308, 08-10)**: 云集群调度的两条修正——①软 SLO 限制（允许受控超卖、容忍轻微瞬时违约，换取资源利用率与能效）；②共享资源（LLC 末级缓存/内存带宽）实时拥塞感知的调度与重调度。实测：软 SLO 较硬限制减少 49% 纠正性重调度动作且性能保证可接受；资源感知调度降低 8% 节点级拥塞并进一步缓解 SLO 违约。结论直指"硬 SLO 是云集群低效之源"——把 SLO 从"不可违反"改为"可控超卖"，是调度器提效的第一性修正。https://arxiv.org/abs/2608.09308
- **arXiv/ElastiCo (2608.07971, 08-08)**: 训练×离线推理弹性共置——现有调度器把两类负载当"隔离的静态资源消费者"，训练作业周期性空闲仍整卡独占、推理任务突发性需求却过度配卡。ElastiCo 三机制：①Resource Shape Transformation（每作业展开为可行"资源配置×性能"族）；②Elastic Shadow Pricing（动态影子价格把多资源分配分解为逐作业配置选择）；③Interference-Aware Co-location（硬件计数器+任务级特征预测 GPU 共享性能退化）。原生 K8s 中间件、零用户代码修改；64-GPU 实测+512-GPU trace 仿真：平均 JCT 降 2.94x、集群吞吐 2.02x、GPU 利用率约 25%→46%——"训练空闲期喂推理、推理突发期压训练"的收益量化。https://arxiv.org/abs/2608.07971
- **arXiv/HorizonServe (2608.01785, 08-03)**: Omni 模型（文本/语音/图像/多模态统一）单 GPU 服务调度——请求共享初始多模态 backbone 后分叉到下游生成阶段，同一 GPU 上出现异构首响应指标与 SLO。HorizonServe 协调准入控制+GPU 分配：按类画像首响应延迟、保护低余量（slack）请求、跨执行路径轮转共享阶段机会、下游阶段活跃时限制共享阶段 SM 配额。三类 Omni 负载×两 GPU 平台：SLO 达成率最高 4.9x（到达率扫描）/7.0x（下游重流量），逐类首响应延迟降 38.4–63.7%——GPU 共享从"统一模型"走向"模态异质 SLO 联合控制"。https://arxiv.org/abs/2608.01785
- **arXiv/Gleam (2607.23115, 07-25)**: LAN 内跨设备 GPU 共享的 CUDA API remoting——面向异构个人设备组成算力池（推理卸载），网络是主瓶颈（带宽受限+高频 API 调用+跨任务争用）。Gleam 三贡献：①模型权重自动缓存降带宽 + 异步执行消除频繁 API 调用的累积延迟；②运行时任务调度器显式建模网络条件×GPU 资源竞争，动态决定客户端-服务器 remoting 配对；③分布式执行下 CUDA context 一致性机制。异构 NVIDIA GPU 实测：API remoting 效率较 SOTA 提升 1.4–24.2x、系统吞吐最高 1.79x——"算力池化"从数据中心机架内延伸到 LAN 级异质设备（rCUDA 路线的现代化复兴）。https://arxiv.org/abs/2607.23115
- **arXiv/Agentic CPU-GPU Scheduling (2607.22242, 07-24)**: Agent 负载的设备级调度实证——19 个 AI 工具在 GPU/CPU 上画像：11 个 GPU 优先、4 个模糊、1 个 CPU 优先（PCIe 传输主导）、3 个设备中立，"全 GPU 优先"默认策略被证明次优。提出 LLM Agent 调度器+算法运行时监视器（运行平均/对称重探/交换重探/探索提示扩展 Agent 可观察性，但不替 Agent 决策），13 个场景（串行/并行争用/内存受限）全部达到暴力最优映射、零离线训练，优于 HEFT/StarPU/all-GPU——与昨日 SAGA/LOCAL 同属"Agent 负载重塑调度抽象"主线，但切入点是设备选择而非工作流编排。https://arxiv.org/abs/2607.22242

## 二、云原生算力平台动态（CNCF）

- **CNCF/LLMOps and platform engineering (08-13, Syntasso/Daniel Bryant)**: "AI 流水线归谁所有"的平台工程争论——数据科学家与平台工程师的职责边界：训练/评估/部署/回滚/成本治理各环节的 ownership 矩阵；核心论点：LLM 时代的平台工程需把"模型生命周期"纳入平台抽象（与既有 CI/CD 同构的 MLOps 流水线），否则每个团队各自造轮子导致平台碎片化——Kubeflow 统一 SDK 破百万下载（昨日已收录）正是这一收敛的实证。https://www.cncf.io/blog/2026/08/13/llmops-and-platform-engineering-who-should-own-the-ai-pipeline/
- **CNCF/Observability for AI Agents (08-04, StackGen/Sabith K Soopy)**: 传统 APM 无法回答"Agent 为什么同一问题问了三遍"——Agent 系统观测需追踪工具调用链、推理轨迹与 token 成本三要素；对算力平台的含义：Agent 负载的计费/调试/容量规划都依赖"一次任务=多步推理+多工具调用"的观测抽象，调度器与可观测性必须共享同一任务边界定义（与 SAGA 的"程序级调度"形成观测-调度两侧呼应）。https://www.cncf.io/blog/2026/08/04/you-cant-debug-what-you-cant-see-observability-for-ai-agents/
- **交叉引用（tech 组已收录）**: CNCF/Cloud Native platform sovereignty through multi-plane architecture (08-18, WSO2)——region 选择只是主权的一部分，控制面/数据面/治理面平面归属共同决定主权边界，详见 tech 组 08-22 日报。https://www.cncf.io/blog/2026/08/18/cloud-native-platform-sovereignty-through-multi-plane-architecture/

## 四、追踪结论（趋势线）

- **"软 SLO + 受控超卖"从提议走向量化**: Beyond the Limits（软 SLO 减 49% 重调度）+ ElastiCo（影子价格弹性共置，利用率 25%→46%）——连续两篇独立工作把"允许轻微违约换取整体利用率"从口号变成带实测的工程方法；平台层含义：GPU 集群的 SLA 承诺正在从"绝对不违约"转向"违约概率可控"，与 DriftSched（昨日）的 QoS 感知校准同向收敛。
- **共享粒度从"作业级"细化到"阶段级"**: HorizonServe 把 GPU 共享控制推进到 Omni 模型内部阶段（backbone 时间共享×生成阶段空间共享联合控制，SLO +7.0x）——上一代共享（MPS/MIG/HAMi）管设备边界，新一代在单卡内部按执行阶段做时间×空间联合优化。
- **Agent 负载开始反向定义调度与观测**: 昨日 SAGA/LOCAL（工作流级调度）、今日 Agentic CPU-GPU（设备选择，19 工具画像证"全 GPU 优先"次优）+ Agent 可观测性（CNCF）——Agent 从"调度器的额外负载类型"变为"调度抽象的重新定义者"，设备选择/工作流/观测三侧同步被 Agent 语义重构。
- **算力池化边界外扩到 LAN**: Gleam（CUDA remoting，吞吐 1.79x）把"资源池化"从机架内扩展到 LAN 级异质设备——与超节点/机架级（hardware 组 AMD Helios 72×MI455X 单一系统）形成"聚合大机 vs 池化小机"两路线并行的平台形态判断。
- **平台工程归属权成为云原生 AI 的组织学问题**: CNCF LLMOps 文章（08-13）与 Kubeflow SDK 统一（昨日）共同指向——平台抽象收敛（统一 SDK/流水线）正在倒逼组织分工收敛（谁拥有 AI 流水线），算力平台的技术选型与团队架构强耦合。
