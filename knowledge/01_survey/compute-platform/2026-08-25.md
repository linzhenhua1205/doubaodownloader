## 一、平台调度研究前沿（arXiv，本组增量）

- **OpScale: 算子级供给与弹性伸缩的 LLM 服务编排**（arXiv:2608.13499, 2026-08-13）: 直面 LLM 云 GPU 集群的基本设计问题——**弹性伸缩单元应该是什么**？现有方案把整个模型当单体伸缩单元（粗粒度，突发流量下 SLO 违例或 GPU 欠利用率），表征分析发现算子间异质性显著（prefill/decode 算子、注意力/FFN 算子的资源敏感度差异大），算子级弹性是可行原语；框架 = profiling→provisioning→placement→runtime 四段编排，处理细粒度的组合爆炸。生产轨迹评估（40×A100 + 24×GB200）：**SLO 达标下少用 36.3% GPU、功耗 −28%，或固定成本下吞吐 +44%**。https://arxiv.org/abs/2608.13499
- **HeaRank: 从"预测 GPU 故障时刻"转向"排序节点故障风险"**（arXiv:2607.15115, ACM SIGKDD 2026, 2026-08-16）: 生产集群遥测深度分析发现 GPU 重大故障（Double Bit Errors、GPU Lost）时序随机性强、信噪比低——**基于时间序列的绝对时刻预测本质不可行**；转向 Learning-to-Rank 框架，用稳定历史故障模式算全局风险排序：千卡级集群 AUC 0.83（远超启发式与 SOTA 排序算法），在线部署 top 5% 风险节点捕获 64% 未来故障，而现有生产系统仅 21%。平台含义：可靠性管理从"何时坏"（不可解）退为"谁更可能坏"（可解）——风险感知调度 + 主动资源管理（预迁移/预降级）成为务实路径。https://arxiv.org/abs/2607.15115
- **SMART-MIG: MF-MARL 的大规模 MIG 在线重分区调度**（arXiv:2606.29775, IPDPS 2026, 2026-06-29）: MIG 切分（multi-instance GPU）与作业调度联合决策；用 Mean-Field Multi-Agent RL 做大规模重分区 + 定制启发式做作业调度，**重分区组件计算复杂度与作业/GPU 数量无关（常数级）**；给出能耗与延迟的理论下界做基准：较静态分区方案能量-延迟效率 +18%，能耗仅高于理论下界 27%——"分区决策动态化"在可扩展性上首次被证明可行。https://arxiv.org/abs/2606.29775
- **Agentic CPU-GPU 协同调度: LLM agent 做设备映射**（arXiv:2607.22242, 2026-07-24）: 对 19 个 AI 工具做 GPU/CPU 画像：11 个 GPU-preferred、4 个 ambiguous、1 个 CPU-preferred（PCIe 传输主导）、3 个 device-neutral——**"全 GPU 优先"的默认调度是次优的**；提出 LLM agent + 算法运行时监控器组合（监控器用运行均值/对称重探/交换重探/探索提示扩展 agent 视野，但不规定映射）：13 个场景（串行/并行争用/显存受限）全部达到暴力最优映射，零离线训练，优于 HEFT/StarPU/all-GPU 基线。https://arxiv.org/abs/2607.22242
- **LOCAL: 端侧 agent LLM 连续学习的单 GPU 运行时**（arXiv:2608.15241, 2026-08-15）: 端侧/边缘算力平台的调度新约束——agent 推理与持续学习共享同一 GPU 时，调度器、adapter 版本管理与 KV cache 有效性必须协同（adapter 更新会使旧版本 KV cache 失效，cache 保留占用训练可用显存）；三组件共享状态（合作式调度器 + 版本感知 KV cache 管理器 + 多 agent 运行时）：单 24GB GPU 跑 7B 模型，前台队列等待 p95 降 3.1x（vs FIFO）、TTFT p95 降 1.55x（vs 不可抢占训练）、发布后首命中 prefill p99 −25.6%、跨 agent TTFT p99 −21.9%。https://arxiv.org/abs/2608.15241
- **Aries: Agent 服务系统的全栈实验框架与生产观测**（arXiv:2607.29069, 2026-07-31）: 用商业平台生产轨迹 + 开源 harness 实验证明三条反直觉结论：①**token 中心指标漏掉非推理瓶颈**（工具执行/沙箱状态是主要延迟来源）；②保留更多上下文收益递减且显著降低服务容量；③工具沙箱"长空闲 + 短资源突发"交替，快照式状态管理使激进挂起代价高昂——agent-native 服务系统需要轨迹级指标、自适应上下文管理、弹性沙箱资源。https://arxiv.org/abs/2607.29069
- **IORM: Oracle Exadata 分布式存储的跨代际 I/O 治理**（arXiv:2607.16578, IEEE IC2E 2026, 2026-07-18）: 生产级多阶段分布式调度器三机制：硬件感知成本建模（datasheet 固定成本归一化 I/O 记账，限额跨硬件代际不变）+ 量子限速器（有界结转积分，容忍数据库微突发同时保证长期 SLO）+ 分布式自适应反馈（重分配未用配额解决访问倾斜）。8 节点集群 100 并发租户卷实测：极端顺序倾斜下 5% 内收敛至配额、无租户间干扰、存储节点故障 15 秒恢复全吞吐——异构硬件池化的"记账公平性"工程范式。https://arxiv.org/abs/2607.16578
- **交叉引用（ops-platform 已收录）**: Safety-Gated Autoscaling (2607.26503) K8s 垂直扩缩容泄漏门控（83% 检测准确率、20–40% 成本节省估算）——资源决策的安全性约束与本文调度粒度/可靠性条目互补，详见 ops-platform 08-25。

## 二、云原生算力平台动态（CNCF/K8s）

- **交叉引用（tech 组已收录全文要点）**: CNCF《Does Kubernetes DRA Replace HAMi?》(08-07)——DRA 从"设备插件计数 API"走向"资源声明式账本"，是 GPU 共享语义的十年级收敛，详见 tech 组 08-25。
- **本组平台视角增量 ①: HAMi 进 CNCF incubating + DRA 路线的版本时间线**（CNCF, 2026-08-07 文章内嵌信息）: HAMi 于 2026-07-15 被 CNCF TOC 批准为 incubating 项目；DRA 核心 v1.34 GA、v1.35 默认启用，**consumable capacity（可消费容量）v1.36 beta 且默认开启**（消除最大采纳障碍）；HAMi-DRA v0.2.1 生产就绪（自 HAMi v2.9 起 DRA 模式为文档化安装选项），DRA monitor 默认启用 Prometheus 31995 端口——设备分片语义从"私有注解方言"（hami.io/vgpu-devices-allocated 字符串）迁移到"API 原生对象"（ResourceClaim status，kubectl/RBAC 可见）。https://www.cncf.io/blog/2026/08/07/does-kubernetes-dra-replace-hami/
- **本组平台视角增量 ②: 异构芯片池化的统一入口正在成型**（CNCF, 2026-08-07）: DRA 驱动的厂商覆盖 = NVIDIA 成熟 + Ascend/Enflame 到来 + Hygon DCU（自有 k8s-dcu-dra-driver）；而 HAMi 传统设备插件模式覆盖 12+ 设备族（含寒武纪 MLU、昆仑芯、沐曦、Iluvatar、MetaX、摩尔线程、AWS Neuron、Vastai）——**混异构集群短期仍走设备插件路径，DRA 是长期统一入口**；两个硬约束：①两种模式不可同集群混跑（两个账本各自记账互不可见）；②HAMi-DRA 不携带自有调度器，NVLink 拓扑感知放置需第三方调度器（Volcano/KAI 等）——"语义标准化"与"拓扑智能"分离是当前架构现实。https://www.cncf.io/blog/2026/08/07/does-kubernetes-dra-replace-hami/

## 四、追踪结论（趋势线）

- **调度控制粒度第四级下钻：算子级**。tech 组已归纳三级（集群→实例→专家），今日 OpScale 给出第四级——**算子级**：prefill/decode、注意力/FFN 的资源敏感度差异让"整模型伸缩"被证伪，36.3% GPU 节省来自把弹性粒度推到算子层；结合 Elastic EP（专家级）与 SMART-MIG（分区级），2026 年弹性调度的共同方向是**把伸缩决策推到资源消耗的最小语义单元**，代价是组合爆炸（OpScale 用 profiling+编排消解，SMART-MIG 用常数复杂度证明可扩展性）。
- **GPU 可靠性管理范式转向：从"预测时刻"到"排序风险"**。HeaRank 的 KDD 2026 实证（top 5% 捕获 64% 故障 vs 现状 21%）宣告"何时坏"不可解、"谁更可能坏"可解——对算力平台的 RAS 设计含义直接：**故障风险排序应成为调度器的第一类输入**（风险感知放置/预迁移），而非等待预测模型成熟；与集群训练组 ETC（弹性迁移）、BMC 带外遥测（tech 组）三线闭环。
- **设备语义标准化 = 异构池化的统一入口**。DRA consumable capacity 默认开启 + HAMi-DRA 生产就绪 + Ascend/Enflame/Hygon DCU 驱动跟进，意味着**GPU/XPU 分片请求正在成为 K8s 原生 API 语义**；国产侧"Token 标准化"讨论与 OpenCost token 成本追踪（tech 组）同向——**资源抽象单位（设备分片/token）标准化是 2026 算力平台的主干演进**，平台团队的选型窗口：v1.36+ 可控控制面的 NVIDIA 集群应立即评估 DRA 模式，混异构集群暂留设备插件路径。
- **国产平台动态恢复但信源可靠性待加固**。搜狗突破 3 日空缺（Token 标准化/DSV4 批量适配/异构池化标配），但命中来源多为转载/公号/博客，原文 URL 不可验证——国产算力平台增量质量受制于信源通道，昇腾/寒武纪/昆仑芯官方 release note 与信通院智算白皮书入固定源仍是最高优先级基建动作（连续 4 日标记）。
