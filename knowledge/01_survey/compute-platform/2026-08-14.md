## 📡 本期核心信号

- **RL post-training 成为算力平台调度主战场（三线齐发）**：MISA-T（混合 rollout 路由准入）、TideRL（就绪感知弹性调度）、RoutePack（MoE 专家放置×数据打包）三篇同日窗口（8/11-8/12）提交——RL 训练流水线的"调度×KV 容量×序列打包"三个耦合问题同日被独立解决，与 08-11 记忆线"调度范式→goodput（Cascade→MARS→TideRL）"直接延续；信号：RL 迭代训练已超越传统预训练成为调度器最活跃的优化对象，且三者共享"goodput/吞吐而非利用率"的度量转向
- **故障定位从"单点预测"走向"共识比较"**：SCOUT 用严格多数共识在等价副本间识别 outlier（对齐进度/时序/数值证据），关键设计是 out-of-band CPU observer——训练挂起时仍能响应诊断，直击 NCCL 假存活案（marin#7344）与 B300 报告"utilization% 100% 但 hang"的同款陷阱：进程内监控在故障时会失明，诊断必须外带
- **集群验收从单节点走向"全集群持续基准"**：ClusterBench 对集群内每个节点持续跑同构基准，实测同规格节点跨标本性能差达 5%（部件内 <1%），且空冷 vs 液冷节点的功率-频率-温度关系不同——"同规格=同性能"假设的量化证伪，为算力平台验收/回归测试提供差异基线
- **LLMOps×平台工程的所有权之争浮出水面**：CNCF 8/13 成员帖直接发问"谁该拥有 AI pipeline"——LLM 训练/推理流水线与平台工程的边界划分成为平台治理新议题，与 08-13"Agent 工作负载颠覆平台假设"构成治理侧呼应

## 📄 arXiv 论文（cs.DC · 8/11-8/14 提交，2608 批次，17 篇窗口精选 5 篇）

- **Scheduling Mixed RL Rollouts Beyond Prefix Locality（MISA-T，2608.11152，8/11）**: RL post-training 流水线中 RLVR/RLHF/agentic 三类 rollout 共享异步推理服务，序列结构与 KV 驻留时间差异巨大，prefix-aware 路由只优化缓存复用不控制 KV 容量竞争；MISA-T 是路由层准入策略——自适应会话准入+工作负载感知 KV 容量分配+驻留时间感知 KV 记账，不扭曲训练器指定的负载混合；rollout-only 消融在 Step3.7/Qwen3.6-35B-A3B 上较调优后的 cache-aware vLLM Router 吞吐 +53.3%/+43.6%（保持高 prefix cache 命中率），50 迭代混合实验吞吐 +35.6%、平均迭代时间 -22.8%——"混合反馈范式"进入调度器视野，KV 容量从 per-model 静态分配走向跨范式动态博弈。https://arxiv.org/abs/2608.11152
- **TideRL: Boosting Agentic RL Goodput with Readiness-Aware Scheduling（2608.10402，8/11）**: agentic RL 的 rollout 任务反复暂停等待外部环境、恢复时上下文增长、完成时间高度可变——训练 goodput（训练吞吐）比 GPU 占用率更重要，GPU 等待与重复 prefill 重算纯属开销；TideRL 三机制：Continuous Task Batching（保留有用 rollout 状态）、Resource-Aware Ref-Actor Pipelining（就绪积压与到达间隔决定解耦流式 vs 共置聚合）、Elastic Resource Scaling（用同一就绪信号在 rollout/训练间迁移 rank）；文本与多模态 agentic 负载下 RL 训练 goodput 最高较同步基线 5.6×、较异步基线 >33%，KV cache 命中率 1.58×、每步训练时间 -44.3%、总等待时间 -77.6%——就绪感知（readiness）成为 RL 调度的第一信号，弹性扩缩从吞吐优化转为 goodput 优化。https://arxiv.org/abs/2608.10402
- **RoutePack: Expert Placement and Attention-Aware Data Packing for MoE Reinforcement Learning（2608.12146，8/12）**: MoE 模型 RL 训练耦合两类负载均衡——序列组合决定数据并行微批的稠密注意力工作量，token 路由决定专家并行 rank 的稀疏专家工作量，单优化其一会把瓶颈转移到另一侧；RoutePack 分层规划器在 optimizer-step 窗口内联合"状态一致的逐层专家重路由"与"注意力+专家感知的数据打包"：先按聚合路由需求独立放置各 MoE 层专家，再把样本打包进 token 上限的执行行并优化 DP 布局（投影 EDP-shard 感知目标：窗口归一化线性二次注意力代理×每层物理 EP-rank 峰值）；Ling-3.0-Tiny/Flash 上专家重路由提升 trainer 实测 token 吞吐 +3.80%/+10.50%，路由感知打包再加 +4.86%/+3.98%，总计较基线 +8.85%/+14.89%——MoE RL 的"注意力打包×专家放置"联合优化，与 MISA-T/TideRL 构成 RL 调度三件套（路由/KV/打包）。https://arxiv.org/abs/2608.12146
- **SCOUT: Symmetric Consensus Outlier Detection for Failure Localization in LLM Pre-Training（2608.11034，8/11）**: 预训练中同步把 rank 局部停滞/减速/数值错误传播为作业级症状，进程内监控在 trainer 阻塞/终止后无法上报、事后日志只保留同步后的症状；SCOUT 设计原则：在等价副本间用严格多数共识识别 outlier——Consensus Collective Communication (C3) 抽象对齐副本进度/时序/数值证据，识别签名与 peers 不一致的 rank；out-of-band CPU observer 在训练挂起时保持响应，in-situ replay 在活作业旁复现顽固 straggler 与静默数据损坏（SDC）——replay 覆盖认证 checkpoint 数值完整性，防止恢复选择被 SDC 污染的状态；与 PyTorch/TorchTitan/Megatron-Core/DeepSpeed 无训练循环或框架源码修改集成，开源 github.com/LMResiliency/lm-resiliency——故障定位的"共识比较"范式，直击"假存活/静默失败"类故障（互证 08-10 NCCL 假存活案、08-11 B300 报告）。https://arxiv.org/abs/2608.11034
- **ClusterBench: A Framework for Cluster-Wide Continuous Benchmarking and Regression Testing（2608.10956，8/11）**: 数据中心需要验证整个安装而非单个节点（验收+定期回归），需要单次提交把相同基准派发到每个节点→集群感知调度；ClusterBench 内置 CPU/GPU/内存/互联/IO 五类基准，跨时间空间重复测量，与历史对比检测软件变更（内核更新/新库）引入的性能回归，测量构成硬件变异性研究数据集；NHR@FAU 三集群实测：单部件内变异 <1%，同规格跨标本变异达 5%，且功率-频率-温度相关性在空冷与液冷节点间不同——"同规格节点性能一致"假设的量化证伪，为算力平台验收测试与硬件变异性监控提供基线工具。https://arxiv.org/abs/2608.10956
