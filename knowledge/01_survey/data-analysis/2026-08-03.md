## 一、Agentic Lakehouse — 信任与契约层（本期主线）

- **来源: arXiv:2602.02335 — "Building a Correct-by-Design Lakehouse. Data Contracts, Versioning, and Transactional Pipelines for Humans and Agents"** (v2: 2026-03-17, 数据会议预印)
  - Bauplan 系统论文：针对并发/不可信变更下湖仓脆弱性（schema 运行时才暴露、开发/生产漂移、多表管道失败暴露部分结果）
  - **三个管道级正确性机制**: ① typed table contracts（转换边界可检查）② Git-like data versioning（可复现协作+审查）③ transactional runs（整条管道原子发布）
  - Alloy 轻量模型验证核心直觉，并暴露事务分支可见性的反例；核心哲学：**限制编程模型使非法状态不可表示**，而非事后打补丁
  - URL: https://arxiv.org/abs/2602.02335

- **来源: arXiv:2607.13339 — "Not Your Usual Type(s): Data contracts as types across languages and engines"** (2026-07-14, CDMS @ VLDB 2026)
  - Bauplan 新 SDK：将**数据契约作为类型**——用户（人或 agent）用 schema objects 注解输入/输出表，编码列类型、约束、文档、血缘
  - 基于 Bauplan 运营**百万级 jobs 超一年**的实践提炼；"everything-as-code" 哲学支持跨语言/引擎的数据流确定性+非确定性推理
  - 痛点定位: 管道节点边界弱规范（schema 检查晚、跨语言执行不一致、与业务语义脱节）
  - URL: https://arxiv.org/abs/2607.13339

- **来源: arXiv:2511.16402 — "Trustworthy AI in the Agentic Lakehouse: from Concurrency to Governance"** (2025-11-20, AAAI26 Trustworthy Agentic AI Workshop)
  - 论证「信任路径从基础设施开始」：传统湖仓不适配 agent 访问模式，围绕事务设计则治理自然跟随
  - **关键洞察**: MVCC 类比无法直接移植到解耦/多语言设置；Bauplan 重实现 data/compute 隔离（agent-first）
  - 交付自愈管道参考实现，将 agent 推理与正确性/信任保证耦合
  - URL: https://arxiv.org/abs/2511.16402

## 二、Agent 技能优化与评估范式

- **来源: arXiv:2606.01185 — "'Skill Issues': Data-Centric Optimization of Lakehouse Agents"** (v1: 2026-05-31 / v2: 2026-07-16, ADS @ VLDB 2026)
  - 核心观察: branching lakehouse 将 agent 评估从 **output-matching 问题转为 state-verification 问题**（agent 生成的管道代码产生可检查的湖仓状态变更）
  - 数据为中心优化流水线: 生成 task-verifier pairs → 隔离沙箱执行候选 skills → 轨迹级信号 + 程序化状态检查打分
  - **量化**: 数百任务初步评估，优化后 skills 提升 held-out reward **最高 28.6%**；结论：写路径数据工作流是优化 agent skills 的有用基座（超越只读任务）
  - URL: https://arxiv.org/abs/2606.01185

- **来源: arXiv:2603.13380 — "Querying Everything Everywhere All at Once: Supervaluationism for the Agentic Lakehouse"** (2026-03-10)
  - Agentic analytics 使湖仓成为多版本系统：agent 群在数据分支物化竞争管道，消费者需答案但不了解底层生命周期
  - 原型支持**跨分支查询**（而非单快照）：超赋值语义（supervaluationary semantics）评估路径；主流 OLAP 无可比能力，开源 demo 作为社区基线
  - URL: https://arxiv.org/abs/2603.13380

## 三、合成数据与领域治理

- **来源: arXiv:2605.11259 — "Template-as-Ontology: Configurable Synthetic Data Infrastructure for Cross-Domain Manufacturing AI Validation"** (2026-05-11)
  - **Template-as-Ontology 原则**: 单一 Python 配置模块（700-770 行，45 validated exports）同时作为时间步进制造模拟器规格 + AI 分析工具运行时领域 schema，**一致性由构造保证**而非集成
  - 五层流水线: simulation → PostgreSQL → CDC/Iceberg lakehouse → star schema → 12 参数化 AI 工具；66 实体类型 × 4 运营域，映射 ISA-95/IEC 62264
  - 六个行业模板（航空航天/制药/汽车/电子/饮料/仓储）同一框架代码运行；60 次校准实验确认参数可控性
  - **量化（幻觉抑制）**: 72 次工具调用实验（Qwen3-32B），ontology 约束消除工具参数捏造（约束 **0%** vs 未约束 **43%** 幻觉率，Fisher's exact test p < 10⁻¹²；0% 为架构性保证，对任意模型成立）
  - URL: https://arxiv.org/abs/2605.11259
