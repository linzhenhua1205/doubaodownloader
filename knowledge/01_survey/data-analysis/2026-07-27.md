## 1️⃣ Eudoxia — Composable Lakehouse 的 FaaS 调度模拟器

| 字段 | 内容 |
|:-----|:------|
| **来源** | arXiv:2505.13750 (cs.DB, cs.DC) |
| **发布时间** | 2025-05-19（数据库会议预印本） |
| **作者** | Tapan Srivastava, Jacopo Tagliabue, Ciro Greco |
| **关联系统** | **Bauplan**（Composable Data Lakehouse） |

### 架构要点

Bauplan 采用 **Composable DLH** 架构，统一 SQL 查询 + Python pipeline 的 **FaaS 运行时**，但 FaaS 引入了调度和优化的新挑战。

| 构件 | 说明 |
|:-----|:------|
| **Eudoxia Simulator** | 确定性模拟器，模拟数据湖仓工作负载的 FaaS 调度 |
| **编程模型** | 将 DLH 调度问题形式化：以 Function 为最小调度单元，pipeline 为 DAG |
| **可定制调度算法** | 用户可实现自定义调度策略（如 locality-aware / cost-aware / deadline-aware） |
| **开源** | 随论文发布社区版 |

### 设计意义

- 从 **Bauplan 编程模型出发**将调度的组合爆炸问题抽象为可模拟的形式化问题
- 厂商无需在生产环境迭代调度算法——Eudoxia 提供"廉价验证机制"
- 属于 Bauplan VLDB'26 系列的前置基础设施研究

## 2️⃣ Learned Cost Model — 跨引擎 SQL 优化器

| 字段 | 内容 |
|:-----|:------|
| **来源** | arXiv:2506.02802 (cs.DB, cs.LG) |
| **发布时间** | 2025-06-03 |
| **作者** | András Strausz, Niels Pardon, Ioana Giurgiu（IBM Research） |
| **场景** | Lakehouse 多引擎自动路由 |

### 架构要点

| 模块 | 功能 |
|:-----|:------|
| **Query Plan + Hint 优化** | 用优化的逻辑计划（而非原始 SQL）做输入 → 平均 Q-error 降低 **12.6%** |
| **Multi-task Learning** | 一个模型多个预测头（per-engine + per-provisioning），避免每个引擎各训练一个模型 |
| **Zero-shot 路由** | 对未见过的引擎仅需少量 fine-tune 即可扩展 |
| **Few-shot 路由** | 对已知引擎组合调度 |

### 性能数据

| 场景 | 工作负载总耗时降低 |
|:-----|:-----------------:|
| **Zero-shot**（随机路由 vs ML 路由） | **-25.2%** |
| **Few-shot**（随机路由 vs ML 路由） | **-30.4%** |

### 设计意义

- 解决实际企业痛点：同一份数据在 Lakehouse 中可以被 **Spark / Trino / Presto / DuckDB** 等多个引擎查询，但人工选引擎需要深厚经验
- 与 **LeJOT**（Databricks 成本编排，arXiv:2512.18266）形成互补：LeJOT 管成本，本工作管线性能路由
- 支持引擎热插拔：新增引擎只需追加一个预测头（fine-tune）

今日 arXiv 检索确认了一个持续趋势：**Composable Lakehouse 正在从理念走向工程化工具链**。

| 维度 | 工具/论文 | 解决的问题 |
