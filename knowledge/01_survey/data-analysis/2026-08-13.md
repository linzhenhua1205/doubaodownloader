## 发现清单

### 🟠 LLM × 数据管理（AI 辅助查询生成与执行）

- **An Extended Tutorial and Vocabulary for Relational Language Design in an Era of AI-Assisted Query Generation** (2608.12272, 2026-08-13, VLDB 2026 tutorial, Wolfgang Gatterbauer): AI 辅助查询生成时代的**关系查询语言设计**教程——当查询由 LLM 生成而非人写时，关系语言本身的词汇表/设计原则需要重新审视（可生成性/可校验性优先），为"面向 AI 的查询语言"提供统一术语框架；与 08-10 归档的语义算子编译引擎（2608.06677）、08-11 的 Carnot（2608.09532）同属"查询生成→执行"重塑线：Carnot 管执行、本教程管语言层设计。https://arxiv.org/abs/2608.12272

- **DexterSQL: Deep Schema Exploration and Rule-based Correction for Text-to-SQL Generation** (2608.11889, 2026-08-13, Anik Pramanik 等, UT Dallas): Text-to-SQL 的**深度模式探索 + 规则化修正**——对数据库 schema 做深度探索（列名/约束/外键语义）辅助 LLM 生成，并用规则引擎（而非仅模型自纠）修正生成结果；LLM×数据任务方向，与 08-10 的 MIRA（修复记忆，2608.06950）、08-11 的 SafeQL（搜索式精炼，2608.09260）构成 Text-to-SQL 治理三视角：**修（MIRA）→ 防（SafeQL）→ 生成期深度探索（DexterSQL）**。https://arxiv.org/abs/2608.11889

- **AI Query Compilation for Unified and Optimized Execution** (2608.10139, 2026-08-12, Yeounoh Chung / Helena Caminal / Fatma Ozcan, IBM Research, PVLDB 14(1)): **AI 查询的统一编译执行**——把 AI 负载（向量/图/关系混合查询）统一编译为优化执行计划，避免多引擎拼接的转换开销；与 08-10 语义算子编译引擎（2608.06677）同向：语义算子从解释到编译（06677 管算子层）、AI 查询整体编译（10139 管查询层），两条编译化路径汇合于"AI 负载原生执行"。https://arxiv.org/abs/2608.10139

### 🟢 数据发现与检索

- **Guided Table Retrieval for Structured Data Search** (2608.11644, 2026-08-13, Alekh Jindal 等): 结构化数据搜索的**引导式表检索**——在表检索中加入用户/任务引导信号（guided），提升"在数据湖/仓库中找到对的表"的命中率，把表检索从纯相关性排序升级为任务感知；与 08-11 的 Guixu（估值驱动发现，2608.07949）、08-07 的 Operationalization-Aware Data Discovery（2608.04536）同属数据发现线，三篇分别补上**引导（11644）/估值（07949）/可落地（04536）**三个维度。https://arxiv.org/abs/2608.11644

- **VQ-bench: A Composable Vector Quantization Framework** (2608.11240, 2026-08-13, cross-list cs.AI, Padaki/Ingber/Liberty): 向量量化的**可组合评测框架**——把 VQ 方法拆成可组合模块（量化器/码本/训练策略）统一评测，解决 VQ 社区各自为政、基准不可比问题；向量检索基础设施方向，延续"ANN 基础设施工程化"跨期线（08-09 MERIT 删除 → 08-10 RECAST 精确 → 08-11 InSituANN I/O → 本期 VQ 评测基准），从索引结构下沉到量化组件层。https://arxiv.org/abs/2608.11240

### 🟡 云与基础设施运营

- **Reverse Migration of Cloud Applications to On-premises** (2608.11640, 2026-08-13, Alekh Jindal 等): **云应用反向迁移到本地**（cloud repatriation）——分析哪些云应用适合迁回 on-prem、迁移的驱动因素（成本/合规/数据主权）与技术路径，与 08-11 的 ScaleSense（云数仓成本智能伸缩，2608.07945）构成成本主线两极：**ScaleSense 在云内省成本、11640 用迁回省成本**；对超节点/私有化部署场景有直接参考价值（万卡集群本就 on-prem）。https://arxiv.org/abs/2608.11640

- **Reinforcement Learning based DBMS Buffer Pool Auto-Tuning for Optimal Memory Utilization** (2608.11239, 2026-08-13, Yifan Wang 等, Orange 实验室): **RL 驱动的缓冲池自动调优**——用强化学习做 buffer pool 大小的自调节，目标是最优内存利用率（内存是数据中心稀缺资源），延续 ML×DB 自调优线（OtterTune 谱系）；与 08-11 ScaleSense 的资源预估（07945）互补：一个调内存池、一个调集群规模，都是"学习式资源决策"下沉数据库内核。https://arxiv.org/abs/2608.11239

### ⚪ 查询语义与数据模型

- **Time to Move on: Querying without Nulls and Bags** (2608.10863, 2026-08-12, Molham Aref/RelationalAI + Leonid Libkin + Wim Martens): **查询语义第一性原理立场文**——论证 SQL 的两大历史包袱 NULL（三值逻辑）与 bag（重复元组）是查询语言复杂性的根源，主张"没有 NULL 和 bag"的查询模型（关系代数的干净语义）；典型的"回物理/逻辑极限"式论证，与用户质量标准（第一性原理）高度契合；对 AI 辅助查询生成时代尤其相关——LLM 生成 SQL 的大量错误正源于 NULL/bag 语义的隐式规则（与 2608.12272 教程形成"语义根源×语言设计"呼应）。https://arxiv.org/abs/2608.10863

- **Property Graph Techniques in Relational Databases** (2608.11001, 2026-08-12, DBKDA 2026, Crowe/Laux): 关系数据库中实现**属性图技术**——如何在纯关系模型上高效承载属性图查询/遍历，避免引入专用图引擎；与 08-11 的 AkasicDB（统一向量-图-关系 DBMS，2608.09214）同向但路径相反：**AkasicDB 用单系统多模型、11001 用关系模型内嵌图能力**，两条路都在消除"多系统拼接"的图数据管线。https://arxiv.org/abs/2608.11001
