## 发现清单

### 🟠 LLM × 数据管理（流语义 / 管线验证 / Agent 记忆）

- **StreamReason-Bench: Can Large Language Models Reason about Event-Time Stream-Processing Semantics?** (2608.12348, 2026-08-14, Zhuoxi Wang 等): **流处理语义 × LLM 能力评估基准**——让 LLM 扮演 event-time 流处理器：给定带乱序事件的窗口查询，输出哪些窗口触发（含聚合值）、哪些事件作为 late data 被丢弃；答案来自 Dataflow 模型参考实现，可精确评分（row-F1）。600 个生成项覆盖 tumbling/hopping/session/processing-time 窗口：直接回答时**无模型超 34% exact match**，CoT 使 GPT-4o 从 0.34→0.48，仅一个默认推理的前沿模型接近解决（0.85）；processing-time 对照（无水印无 late）几乎全解——**硬点在 event-time/late-data 处理而非窗口计算**，session 窗口主要错在边界判定。信号：流处理管线交给 LLM（写 pipeline/日志告警 triage）前必须先过语义关，late-data 语义是最薄弱环节。https://arxiv.org/abs/2608.12348

- **Pipeline Denotational Design: Correct-by-Construction Data Pipelines at Zero Cost** (2608.12375, 2026-08-14, Nikos Karayannidis): **设计即正确（correct-by-construction）的数据管线方法论**——AI 生成管线代码规模化后瓶颈从"写"转向"验证"，而最致命的错误（grain 不一致悄悄放大聚合）逃过 schema/类型/抽样测试；PDD 在语义域（而非代码）设计管线：typed algebra（Pipeline Design Algebra）中每个良类型组合**构造上 grain 正确**，三层正确性（grain→behavioral class→domain）在设计期零成本建立（不访问数据），Pipeline Correctness 定理把其余收束为单一输入边界检查（数据质量而非代码正确性），并输出 SQL/PySpark 验证查询；同一设计可经运行时检查/部署期类型检查器/Agda-Lean 4 机器证明三级验证。信号：承接 08-13 隔离保证分层验证（2608.07793）——"验证一次复用多次"从查询延伸到管线，工程师角色转向"实例化预验证模式 + 校验紧凑规格"。https://arxiv.org/abs/2608.12375

- **FluctlightDB: A Memory Model of Data for AI Agents** (2608.12365, 2026-08-14, Ganesh S): 提出**把 Agent 长期记忆当作独立数据模型**——关系模型回答"哪些记录匹配谓词"、向量模型回答"哪些向量最近"，都不是为跨长会话的 cue-driven/provenance-weighted 回忆设计的；FluctlightDB 定义自有写语义（encoding/separation/consolidation/provenance）与读语义（记忆图上的 cue-driven 激活），以嵌入引擎（experience()/activate() 契约）实现，明确不宣称超越 Mem0/Zep/HippoRAG 类记忆层而是提供其下的引擎契约。数据（作者自述，基线注明）：LoCoMo 官方证据回忆指标 99.0%（10 会话, 1,982 gold spans, 2026-07 内部复现）；LongMemEval-S session_recall@8 97.6%（488/500）；BEIR SciFact 共享 MiniLM 下 nDCG@10 0.646 vs Chroma 0.645。信号：Agent 记忆层正在从"应用插件"下沉为"数据系统层"，与 08-11 Carnot/Guixu 的 Agent×数据管理线同向。https://arxiv.org/abs/2608.12365

### 🟢 数据生命周期与成本优化

- **Lifecycle-Aware Archival for Asymmetric Financial Datasets: A Production Study** (2608.12367, 2026-08-14, Tulika Manek 等, Razorpay): 金融交易库的**生命周期感知归档生产实践**——Razorpay 在 PostgreSQL Aurora v14 上管理数十 TB、峰值数千 TPS 写入的交易表，提出两个贡献：(1) 形式化 **Celebrity Partition Problem**：生命周期状态分区把所有活跃行集中到单一默认分区，带来 O(N×M) 规划开销、O(N) 执行 I/O 回归、每次状态迁移的写放大；(2) **ID 单调性去重**：利用 Snowflake ID/ULID 的时间编码，只把可能已归档的重插入路由到温库查询，无需 Bloom filter/幂等表/外部依赖。生产结果（已部署系统实测）：**热存储 -95%、月度数据库基础设施成本 -53%、p99 处理延迟 -60%、writer CPU 利用率 -51 个百分点**，峰值写 TPS 持续，主表零 schema 变更。信号：归档/分层存储从"批处理搬运"走向"生命周期一等公民"，量化收益极扎实，对超节点数据平台的分层存储设计有直接参考。https://arxiv.org/abs/2608.12367

- **ASAP: Reimagining the Data Lifecycle using Application Semantic-Aware Processing** (2608.12735, 2026-08-14, Milind Srivastava/Vyas Sekar 等): **应用语义感知处理范式**——观察可观测性/网络/安全等领域数据管线共同面对 CSP 问题（低 Cost × 大规模 × 高性能），而 AQP、sketching、压缩、rollup 等解法共享一个属性：**利用语义保持机会服务应用需求**；ASAP 主张把语义感知处理作为数据管线的第一等设计原则，跨域统一可解锁新优化：如分析直接跑在源端计算的 sketch 上、复用其他应用域原语；初步证据显示 CSP 权衡可改善**最多 3 个数量级**（多应用域）。信号：把散落各域的近似技术收拢为统一范式，与 08-11 ScaleSense 成本线互补——ScaleSense 在调度层省、ASAP 在数据表示层省。https://arxiv.org/abs/2608.12735

### 🟡 非结构化数据与文档分析

- **Structure then Query: Enabling Precise Analytical Queries over Unstructured Documents** (2608.13384, 2026-08-14, cross-list cs.IR, Teng Lin/Yuyu Luo/Nan Tang): **非结构化文档的结构化查询**（AnnoIndex）——文档占据企业/Web 数据主体，但基于向量相似度的模糊匹配难以支撑精确结构化分析；两组件：(1) **Annotation Index**：SchemaLoop 从原始语料自动生成分层标注 schema，轻量 LLM 抽取具体值，把散乱文本物化为可过滤/可查询的结构化索引，把属性抽取成本从在线查询摊销为一次性构建；(2) **Structured Query Engine**：把用户问题编译为 SQL 扩展执行计划，先用 Annotation Index 精确过滤文档，再按成本升序逐步抽取，**LLM 只处理需要深度语义理解的最小剩余语料**，抽取结果回填索引降低未来查询成本。三真实数据集平均 F1 0.87 超 SOTA，多跳 join/渐进推理查询鲁棒。信号：延续 08-10 Doc2DB-Bench（文档建库基准）线，Nan Tang 组把"文档→库"从评测推进到可用系统，与 08-11 数据发现线（Guixu）共同指向**非结构化数据的数据库化**。https://arxiv.org/abs/2608.13384

### ⚪ 学习式数据系统

- **Incremental Evaluation and Training in Relational Deep Learning** (2608.13023, 2026-08-14, cross-list cs.LG, Jakub Peleška/Gustav Šír): **关系深度学习（RDL）的增量评估与训练范式**——RDL 把多表数据库建模为时序异构图做端到端表示学习，但现有评测用静态单片段快照，忽略真实库的持续演化；提出多片段增量评估/训练：在既有大规模数据集上证明**多数预测任务存在时序概念漂移**，多种增量微调 regime 下**迁移学习在 RDL 中可行且高效**，增量微调模型一致优于昂贵的从头训练基线；配套新时序评估指标（近未来精度优先）。信号：数据系统的机器学习管线进入"持续学习"阶段，与 08-13 增量语义、数据漂移处理线呼应，对在线数据质量监控有参考。https://arxiv.org/abs/2608.13023
