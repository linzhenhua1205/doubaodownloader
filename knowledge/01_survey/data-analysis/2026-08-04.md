## 发现清单

- **Token-Native Storage: Read and Write in your Agent's Language** (2608.02376, 2026-08-04): 提出"以 Agent 语言为原生格式"的存储读写范式——存储层直接面向 LLM agent 的 token 语义而非仅字节/行，跨 Databases/CL/IR 三域；标志 lakehouse 从"人读 SQL"向"agent 读 token"的接口层迁移。https://arxiv.org/abs/2608.02376

- **Oasis: Hiding the Cost of Querying Parquet Files in the Datapath** (2608.02268, ETH Jonas Dann/Luca Tagliavini/Gustavo Alonso): 将 Parquet 查询成本隐藏进数据通路（datapath），试图消除 lakehouse 存储与计算间的查询开销墙——ETH Alonso 组延续其在硬件加速数据处理的路线，对 Parquet 生态查询路径优化有直接价值。https://arxiv.org/abs/2608.02268

- **TEngineDB-V: An OLAP-Native Vector Search System for Large-k Workloads at Tencent** (2608.00650, 腾讯): OLAP 原生向量检索系统，面向 large-k 工作负载（返回海量近邻而非 top-k 少数），将向量搜索与 OLAP 分析引擎一体化——国产大厂在"分析+向量"融合引擎的落地实践。https://arxiv.org/abs/2608.00650

- **CITBench: A Comprehensive Benchmark for Interactive Tabular Data Processing with LLMs** (2608.00018, 2026-08-04): 面向 LLM 交互式表格数据处理（CIT）的综合基准——补齐 agent 在表格分析场景的评测空白，与 08-03 归档的 state-verification 评估范式呼应，同为 agentic data 评测方向。https://arxiv.org/abs/2608.00018

- **Agentic Self-Healing for Data and AI Pipelines: An Affordable Vendor-Agnostic Architecture using Open-Source Software** (2608.01955, cross-list cs.ET): 基于开源组件构建厂商无关的 agentic 自愈架构，面向数据/AI 管道的故障自动恢复（19页5图）——延续 07-28 KubeCon 观察的"Agent 安全/自治运维"趋势进入数据管道域。https://arxiv.org/abs/2608.01955

- **Data Quality Profiling at Scale with Progressive Sampling: A Benchmark for Data-Centric AI Pipelines** (2607.25356, Laure Berti-Equille): 渐进采样驱动的规模化数据质量剖析基准，面向 data-centric AI 流水线（29页8图）——数据质量评估从离线抽样走向渐进式采样，与 07-31"数据质量价值化"主题连续呼应。https://arxiv.org/abs/2607.25356

- **Six Dimensions of Benchmarking Time-Series Databases** (2608.01459, 2026-08-04): 提出时序数据库基准测试的六维度框架——针对时序场景（写入吞吐/查询/压缩/容错等）建立可对比评测维度，为选型 TSDB 提供结构化判据。https://arxiv.org/abs/2608.01459

- **LayoutBench: Performance Benchmarking of Cloud Storage Layouts for Multimedia Data** (2607.28880, cross-list cs.DC, Tumanov组): 云存储布局（layout）性能基准，聚焦多媒体数据在云对象存储上的布局选择对端到端性能的影响——与 lakehouse 表布局优化同源问题在非结构化数据域的延伸。https://arxiv.org/abs/2607.28880

- **Fully Inductive Cardinality Estimation** (2607.28311, ISWC 2026): 全归纳式基数估计——对未见过的查询/数据分布也能直接估计基数，避免传统直方图/采样的"所见即所得"限制，对查询优化器代价模型有增强意义（34页8图）。https://arxiv.org/abs/2607.28311
