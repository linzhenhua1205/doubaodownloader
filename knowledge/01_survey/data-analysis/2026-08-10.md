## 发现清单

### 🟠 Agentic AI × 数据管理（本期主线）

- **Toward a Causal Data Management Ecosystem for Decision Making and Agentic AI** (2608.07214, 2026-08-10, ACM AI Leadership Summit 2026 收录, Qiu/Bonifati 等): 提出面向决策与 Agentic AI 的因果数据管理生态——把因果推断（causal inference）从分析后处理下沉为数据管理层的一等公民（因果图/因果查询/反事实分析作为数据管理原语），为 AI Agent 的决策提供可追溯、可反事实验证的数据底座；因果×数据管理×Agent 交叉方向，与 08-04 归档的 Agentic 数据访问四层（Token-Native Storage 等）同属"AI 负载重塑数据面"主线，但视角从"读写格式"上移到"决策语义"。https://arxiv.org/abs/2608.07214

- **From Interpretation to Compilation: A Compilation-Based Execution Engine for Semantic Operator Systems** (2608.06677, 2026-08-10): 语义算子系统的编译执行引擎——语义算子（semantic operators，如指标/维度/聚合语义）系统通常以"解释执行"（interpretation）方式运行，本文提出编译执行（compilation）路线：把语义算子编译为底层查询计划，消除解释层的运行时开销与语义漂移；语义层/指标层执行引擎方向，与 07-13 归档的语义层（semantic layer）讨论线衔接，回答"语义层性能如何不做解释器"的问题。https://arxiv.org/abs/2608.06677

- **Stateful Governance for Concurrent Agentic Systems** (2608.02764, 2026-08-05, cross-list cs.MA, 马里兰 Xiaodi Wu 组): 并发 Agentic 系统的有状态治理——多个并发 AI Agent 共享数据/资源时的治理机制：引入状态化治理原语（stateful governance），使并发 Agent 的访问/变更遵循可验证的治理策略，避免无状态检查被并发交错绕过；Agent 安全×数据治理交叉，与 08-08 归档的 Agent 安全周更化（越权→失控序列）呼应，把治理从"策略声明"推进到"并发可执行"。https://arxiv.org/abs/2608.02764

### 🟢 相似度搜索与索引

- **RECAST: A Region-Scoped Adaptive Index for Exact Similarity Search** (2608.06962, 2026-08-10, 澳门理工 Yining Liu 等): 精确相似度搜索的区域范围自适应索引——不依赖近似（exact 而非 ANN），按数据分布将搜索空间划分为区域（region-scoped），自适应调整区域索引结构以加速精确匹配；精确相似度搜索方向，与 08-09 归档的 MERIT（图 ANN 原地删除）、08-06 RaG-Tree 同属"相似度检索基础设施"跨期主线，但回归 exact 赛道（ANN 主导期对 exact 的再工程化）。https://arxiv.org/abs/2608.06962

- **Duration-constrained Interval Joins** (2608.06856, 2026-08-10, MDM2026 论文修正版, 大阪大学 Amagata 组): 持续时间约束的区间连接——区间数据（时间/空间区间）连接时加入持续时间约束（duration-constrained，如"重叠时长 ≥ θ"），给出高效连接算法；时空数据操作方向，与 08-09 归档的轨迹相似度下界（2608.01039）同属时空数据处理线，从"相似度检索"扩展到"区间连接算子"。https://arxiv.org/abs/2608.06856

### 🟡 LLM 驱动的数据任务

- **MIRA: Evidence-Verified Repair Memory for Text-to-SQL Correction** (2608.06950, 2026-08-10, Yining Liu/罗宇 等): Text-to-SQL 纠错的证据验证修复记忆——针对 LLM 生成 SQL 出错后的修复环节：维护"修复记忆"（repair memory），并对每条修复做证据验证（evidence-verified，如对照数据库执行结果/模式约束），过滤不可靠修复、提升纠错稳定性；LLM×数据任务方向，与 08-04 归档的 CITBench（交互式表格数据处理基准）、07-11/07-13 的 Text-to-SQL 线衔接。https://arxiv.org/abs/2608.06950

- **GPTKB 2.0: Browsing, Querying, and Auditing a Disambiguated LLM-Derived Knowledge Base** (2608.06992, 2026-08-10, cross-list cs.CL, Razniewski 组): LLM 派生知识库 GPTKB 2.0——提供消歧（disambiguation）后的浏览/查询/审计能力：用户可对 LLM 生成的知识库做浏览与审计，消歧处理实体指代；同日另有姊妹篇"Direct Construction of Disambiguated KBs from LLMs" (2608.03729, 8/5 cross-list)；知识库构建方向，与 08-06 归档的 GPTKB 1.0 线延续（2.0 新增查询/审计界面）。https://arxiv.org/abs/2608.06992

- **FinRank: An Evidence-Grounded Benchmark for Financial Question Answering and Retrieval over SEC Filings** (2608.07400, 2026-08-10, cross-list cs.AI): SEC 文件财务 QA/检索的实证基准——基于 SEC  filings 构建证据扎根（evidence-grounded）的财务问答+检索基准，要求回答可追溯到具体文件段落（防 LLM 幻觉）；RAG 基准方向，与 08-08 归档的 RAG-Stack（RAG 服务质量×性能共优化）同属 RAG 评测/工程线，从通用域下沉到金融垂直域。https://arxiv.org/abs/2608.07400
