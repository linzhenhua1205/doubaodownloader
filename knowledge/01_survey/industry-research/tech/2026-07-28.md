## §1 MoE 硬件影响（2026-07-28 新增 4 条）

| # | 来源 | 论文/博客 | 核心方法 | 关键数据 | 硬件影响 |
|:-|:----|:---------|:---------|:--------|:--------|
| 1 | 🟢 arXiv | **PagedWeight** (2607.16184, Yang et al., 2026-07-17) | 运行时动态 MoE weight 量化管理：在 KV cache 与 expert weights 之间动态平衡 GPU 内存分配，感知质量自动调整量化精度级别；暴露并导航 accuracy-memory-throughput 三目标 tradeoff | FP16 等效精度下 **72.0% GPU memory 节省** · **1.94× throughput** 提升 · 同内存预算质量比现有量化方法高 **39.3%** · 最大 4.1% throughput loss | ⭐⭐⭐⭐⭐ **MoE weight 与 KV cache 争夺 GPU 显存的比例是动态的**——固定精度分配是低效的。PagedWeight 证明运行时层面动态量化可以在不增加硬件成本的前提下"软件扩展 VRAM"。对 GPU 架构：weight 动态量化卸载到硬件单元（类似 Blackwell NVFP4 的 runtime 精度切换）可显著降低该方案的开销 |
| 2 | 🟢 arXiv | **TriRoute** (2607.06601, Balashov et al., 2026-07-06) | 单一轻量 controller 联合决策三条轴：(i) attention mode (skip/local/full), (ii) sparsely selected FFN experts (+null expert recovery MoD), (iii) KV-cache bit-width；用 Gumbel-Softmax straigh-through + top-k load-balance 训练；识别**跨轴routing-collapse cascade** 并设计 per-axis normalization + coupling-aware balancing loss | 160M-1.3B 参数 decoder-only 模型 · **Pareto dominate** 最优独立 MoD+MoE+KV-quantization 组合 · 稀有实体/code/arithmetic 的 tail-case 鲁棒性显著更好 | ⭐⭐⭐⭐⭐ **核心发现: attention 稀疏性、expert 选择、KV cache 精度三个条件计算维度是强耦合的**——一个轴的 collapse 会传播到其他轴。硬件含义：独立优化各轴有显著 leakage；未来 GPU 需提供统一的稀疏度/精度接口，而非每轴独立硬件模块 |
| 3 | 🟢 arXiv | **Moebius** (2606.26607, Wang et al., 2026-06-25) | 运行时 EP↔TP 无缝切换：EP 和 TP 作为同一模型的两个 layout（共用相同 expert weights 和 KV cache），切换只转移 owner-changed 的 slice。pre-shard model 在固定地址 + fused GPU-to-GPU transfer kernel 实现；不 drain in-flight requests | 8×H200 Qwen3-235B-A22B: 每个操作点匹配 **better static parallelism** · RL rollout **1.16-1.25×** · 单次切换 **215-434 ms** · 双 layout 共存仅 **2.4% memory overhead** | ⭐⭐⭐⭐⭐ **EP 和 TP 两种并行模式可以共存于 GPU 内存并实时切换**——且开销极低（2.4% 额外内存, 亚秒级切换）。硬件含义：(1) GPU 互联需支持任意 GPU pair 间的高带宽切片迁移（与 NCCL EP 的 ncclEpDispatch 语义互补）；(2) 内存架构需支持双 layout 同时在固定地址持有同一模型参数 |
| 4 | 🟢 arXiv | **Gimbal** (2606.15177, Sun et al., 2026-06-13) | 三层协调调度 for MoE serving：(i) request-level: SJF + priority-aware aging；(ii) engine-level: 负载感知 dispatch 考虑 KV cache 使用/queue pressure/MoE expert 压力；(iii) expert-level: 基于 MINLP 的 online expert 放置兼顾负载+源感知通信+迁移稳定性 | **TTFT ↓42.9%** · **TPOT ↓33.3%** · 高负载吞吐 **↑3.0%** — 对比 vLLM | ⭐⭐⭐⭐ **MoE 服务调度需要三层协同优化**——单层优化（仅负载均衡或仅 hot expert 迁移）无法避免 40%+ 的延迟损失。硬件含义：scale-up 域互联如能提供 low-latency expert 迁移能力，可减少 Gimbal 中 MINLP 驱动的调度保守性 |

### 🎯 本期最强硬件信号

**🚀 信号一: MoE Attention-Expert-KV 三条条件计算轴必须联合设计**（§1.2）

> TriRoute 不仅证明联合优化 Pareto 支配独立组合，还揭示了**跨轴 routing-collapse cascade** 这个根本耦合机制——attention 稀疏性 collapse 会传播到 expert 选择和 KV 精度。硬件含义：GPU 未来不应将 attention 稀疏化（Mixture-of-Depths）、FFN MoE、KV cache 量化作为三个独立硬件模块设计，而需要提供统一的稀疏精度控制接口。

**🚀 信号二: EP/TP 运行时切换仅需 215-434ms — 双 layout 共存成为新常态**（§1.3）

> Moebius 证明 EP 和 TP 共用同一份权重 + KV cache 的可行性。双 layout 共存的 2.4% 内存开销极低，而 215-434ms 的切换时间意味着：**GPU 互联带宽已达到足够支持 decode-step 间的 layout 重配置**。这对超节点有直接启示：NVL72 如能原生支持 EP↔TP 切换语义，可在不增加硬件的前提下覆盖在线/离线混合工作负载。

**🚀 信号三: MoE weight 量化需要运行时动态 — 固定的精度分配是结构性浪费**（§1.1）

> PagedWeight 的 72% 内存节省 + 1.94× 吞吐提升说明：**MoE 推理的 VRAM 瓶颈可以通过软件动态量化管理大幅缓解**，且不牺牲质量。对 GPU 架构：未来若提供 NVFP4 级别的**运行时精度切换硬件支持**（per-expert、per-layer 可变精度），PagedWeight 的开销会进一步降低。

### 10.1 🔴 SDC（静默数据损坏）— GPU/LLM 训练可靠性研究爆发

**2026 年是 GPU SDC 研究的大年**：DSN'26 和 CCGrid'26 均设有 SDC 专题，NVIDIA 与学术界联合发布多篇重量级论文。

| # | 论文/来源 | 机构 | 日期 | 核心方法 | 关键数据 |
|:-:|:---------|:----|:----:|:---------|:--------|
| 1 | **LLM-PRISM: Characterizing SDC from Permanent GPU Faults in LLM Training** (2604.10390, DSN'26 Industry) | NVIDIA + U of Rochester | 2026-04 | RTL 级 GPU 故障模拟 + 随机注入引擎嵌入 Megatron-LM；7,664 次训练跑遍 FP16/BF16/FP8 精度 | 首个硬件接地的大规模 LLM 预训练 SDC 弹性特征化工作。**LLM 抵抗低频故障但在中等故障率下关键数据路径可引发灾难性发散** |
| 2 | **The Anatomy of Silent Data Corruption: GPU Error Pattern Study** (2605.04213, DSN'26 Industry Track) | NVIDIA | 2026-05 | 面向生产级 GPU 的门级 stuck-at 故障注入，**300 万+模拟器小时** × 63 CUDA 微基准 | 🎯 **关键发现**: NaN/+INF/-INF 仅占 **1.01%** 的 SDC 结果；**单比特翻转 <40%**；损坏地址呈现周期性。这些数据直接推翻了业界常见假设 |
| 3 | **Exploring SDC as a Reliability Challenge in LLM Training** (2604.00726, CCGrid'26) | TU Berlin | 2026-04 | GPU 矩阵乘指令级故障注入，LLaMA 60M/350M/1.3B 受控实验 | NaN 传播、loss 尖峰、梯度范数异常的**轻量检测方法**可有效缓解有害 SDC |
| 4 | **V-ABFT: Variance-Based Adaptive Threshold for Fault-Tolerant GEMM** (2602.08043) | — | 2026-02 | 基于方差的 ABFT 自适应阈值。将阈值-实际误差比从 160-4200× 降至 **7-20×（FP32/FP64）** | **已集成至 NPU 和 GPU 的容错 GEMM 实现**。fused-kernel 可实现 **~1000×** 更细检测粒度 |
| 5 | **Grid-like Error-Correcting Codes for Matrix Multiplication** (2508.04355) | — | 2025-08 | 网格编码检测/纠正矩阵乘多计算错误 | 确定性纠正 **3 矩阵中 2 个错误符号 100%**，GPU 仅 **24% 计算开销** |
| 6 | **LM-Fix: Lightweight Bit-Flip Detection and Rapid Recovery** (2511.02866, IEEE ICCD'25) | — | 2025-11 | 短 test-vector + hash 引导的比特翻转检测 + 本地修复 | **>94% 单比特翻转检测**，近 100% 多比特，**恢复比全加载快 100×**，开销仅 **1-7.7%** |
| 7 | **Targeted Wearout Attacks in Microprocessor Cores** (2508.16868, HPCA'26) | — | 2025-08 | 软件驱动的**目标磨损攻击**：用户级程序通过控制输入加速特定位路径老化 | RISC-V FMA 管线 **>7× 磨损加速**，可实现针对性静默数据损坏 |

**🎯 SDC 判断**: 2026 年核心发现颠覆了 SDC 的两大传统假设——NaN/INF 仅 1.01%、单比特翻转 <40%。这对 RAS 设计有直接影响：ECC/watchdog 仅覆盖一部分故障模式，GPU 故障注入测试需要更精密的故障模型。
