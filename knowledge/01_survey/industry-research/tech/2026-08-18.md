## MoE→硬件影响

### 发现列表

- **arXiv 2606.00735/ViBE（05-30 提交）**: 首次系统处理 MoE 推理中的"工作负载倾斜 × 硬件性能差异"双重耦合——输入依赖的 token 路由与 GPU 制造差异/功耗/热况相互作用，制造"同步执行下的持久 straggler"。提出硬件感知专家放置（Variability-Informed Binning of Experts）：按 GPU 性能建模 + 专家激活画像，把高负载专家放快设备、低负载放慢设备。实测 SLO 达成率提升 14%，P90 TTFT 最多降低 45%；规模越大硬件差异影响越显著。https://arxiv.org/abs/2606.00735
- **arXiv 2605.11800/ROMER（05-12 提交）**: 首个基于真实芯片标定噪声模型的 MoE-on-模拟CIM 系统研究——模拟 compute-in-memory 的硬件噪声会破坏专家负载均衡、使干净训练的 router 决策持续次优。提出后训练校准：替换欠激活专家 + 基于分位数归一化重校准 router logits。在 DeepSeek-MoE / Qwen-MoE / OLMoE 上 perplexity 分别降低最多 58.6% / 58.8% / 59.8%。https://arxiv.org/abs/2605.11800
- **arXiv 2605.04754/AxMoE（ISVLSI 2026）**: 首次研究近似乘法器（EvoApproxLib 8 个 8-bit signed 乘数）对 MoE 架构的影响：不做近似感知重训练时 Dense 拓扑最鲁棒；重训练后 ResNet-20 可完全恢复、VGG 在激进近似下不可逆失效、ViT-Small 上 Hard MoE 在激进近似下反而优于 Dense——近似计算与 MoE 的软硬协同设计空间首次被刻画。https://arxiv.org/abs/2605.04754
- **arXiv 2608.13027/MoP（08-13 提交, cs.AR）**: "Mixture of Prefetchers"——性能异常驱动的 agent 自动研究流：每次迭代定位高影响 unexplained misses 到 PC，给 agent 硬件日志/源码/切片 trace，验证诊断后合成专用子 prefetcher。整个活动消耗 **19.1 亿 DeepSeek V4 Pro tokens**，SPEC CPU2006/2017 上 IPC 提升 61.1%（geomean），超过人工设计的 Alecto / Berti / Pythia 分别 14.5% / 21.6% / 23.6%；6nm 综合 110KB 片上存储、0.0347mm²。https://arxiv.org/abs/2608.13027

### 分析

**从"路由均衡"到"执行时间均衡"的范式转换。** 此前 MoE 调度优化（MEMORY 已有 RoutePack +8.85%/14.89%、TAOT 1.43x 加速/通信 −74%）都在 token 路由层面做文章，隐含假设是"负载均衡 ⇒ 延迟均衡"。ViBE 直接击穿这一假设：现代加速器的制造差异、功耗上限与热约束会让**名义相同的 GPU 执行时间差出可测量量级**，即使 token 分配完全均衡，硬件差异仍制造 straggler。因此优化目标从"token 分配均衡"转向"执行时间均衡"（binning experts to device speed），且因为工作负载/吞吐漂移，需要轻量重校准——这是把"调度"从纯软件问题升级为"软硬协同"问题的关键证据。对超节点设计的意义：**节点间 GPU 性能分档（binning）本身应该成为机柜/机群管理的一个一等公民概念**，而非仅靠路由层补偿。

**CIM/近似计算与 MoE 的"脆弱性-机会"双面。** ROMER 与 AxMoE 合起来给出一个完整图景：MoE 的稀疏激活结构在非理想硬件（模拟存储噪声、近似乘法）上比 Dense 更脆弱（负载失衡 + router 决策失稳），但通过后训练校准（ROMER：专家替换 + logits 归一化）或架构选择（AxMoE：Hard MoE 在激进近似下胜出）可以转脆弱为优势。结合 MEMORY 中 Skymizer HTX-301（28nm 无 HBM 跑 671B）的低成本路线，说明**"非 HBM 高带宽存储/低精度计算 + MoE 校准"正在形成一条与 HBM 路线平行的低成本推理技术栈**，值得服务器产品团队作为差异化方向持续跟踪。

### 分析

**云原生 AI 的"标准层"正在补齐。** 2026 年 K8s 上的 AI 基础设施从"拼装项目"走向"标准栈"：控制面有 Kubeflow（MLOps 运维标准）毕业，资源面有 DRA（v1.34 GA → v1.36 "Next Era"）与设备管理 WG，网络面有 Gateway API Inference Extension + v1.6 TCP/UDP，存储面有 CSI 生态 + 内存 QoS 分级。三层合起来回答的是同一个问题：**AI 集群的"可编程性"由谁定义**——Kubeflow 定义工作负载生命周期，DRA 定义设备语义，Gateway API 定义流量策略。对服务器厂商的含义：BMC/固件层应该向 DRA 的设备健康与可分配语义靠拢，而不是停留在"设备插件计数"时代。

**DRA vs HAMi 之争是"平台原生 vs 社区实践"的经典张力。** HAMi 类方案解决了"一个 GPU 分给多个 pod"的真实诉求，但建立在设备插件计数之上、能力边界（可观测、可协商、可恢复）天然受限；DRA 提供结构化语义但生态成熟度仍在爬坡。值得注意的中间态是 v1.36 的 Pod-Level Resource Managers（Alpha）与 In-Place Vertical Scaling（Beta）——**"资源可在 pod 生命周期内伸缩"正在成为 K8s 原生能力**，这对 GPU 分片/共享的调度模型有直接冲击：若 pod 级资源可原地伸缩，GPU 分片调度就不再需要"整卡粒度"的静态分配。

**CoHDI 是超节点/CXL 池化在软件侧的落点。** CoHDI 进入 CNCF Sandbox 与硬件侧 CXL 内存池化（见超节点标准专题）形成呼应：解聚硬件需要"可组合资源"的调度语义（发现、绑定、生命周期），而这恰是 K8s 生态的强项。对超节点架构的意义在于：**机柜级解聚（内存池、存储池、加速器池）的上层抽象将大概率由 K8s 生态接管**，服务器厂商的硬件必须为"可组合"预留标准接口而非私有方案。

**AI 网关层并购 = 推理成本的"收银台"争夺。** OpenRouter 70 亿美元+ 的估值说明 AI 推理入口的战略价值（模型路由、用量计费、Key 聚合）远超"工具"范畴——它是 LLM 经济学的"支付通道"。对基础设施团队的含义：**模型网关（gateway）与计费/审计的耦合正在加深**，服务器/算力平台若只提供裸算力而缺乏"token 级计量"能力（对照 OpenCost 的 inference cost tracking），将在价值链上让位于网关层。这与 CNCF OpenCost 1.121.0 的"每个 token 到底花多少钱"叙事同向。

**工具链演进的三个可跟踪指标**：① agent 单任务的 token 消耗与成功率（MoP 给出 19.1 亿/项目量级基线）；② 验证周期压缩倍数（Samsung 2 天是"天级"锚点）；③ 开源项目 AI 补丁占比与回退率（治理风险指标）。

### 分析

**超节点存在"整柜融合"与"机柜解聚"两条并行路线。** hardware 组今日已收录 AMD Helios（72×MI455X rack-scale 单系统）与 NVL72 整柜路线；本组增量在于**解聚路线的软件标准化信号**——CoHDI 入孵 CNCF 意味着"CXL 内存池 + 组合式硬件"不再是实验室概念，而开始有可编排的云原生抽象。两条路线的本质差异在资源所有权粒度：整柜路线把资源"焊死"在机柜内（强耦合、低延迟、高确定性），解聚路线把资源池化到机架/机群（弹性、高利用率、需网络化内存语义）。对服务器产品线的判断：**短期内整柜路线主导训练场景（确定性优先），解聚路线在推理/内存密集场景（如 KV cache 池化）率先落地**。

**PCIe Gen6 交换/retimer 是机柜内互联的"咽喉"。** Switchtec 160-lane Gen6 + XpressConnect retimer（支持 CXL 3.1）显示互联组件商在 PCIe Gen6 时代的竞争焦点：Broadcom（Avago-PLX 时代霸主）、Astera Labs（Scorpio 320-lane）、Marvell、Microchip 四方角力。物理原因很硬：**Gen6 速率（64 GT/s）下信号完整性距离缩短，而机柜尺寸在增长**——retimer 数量成为超节点 BOM 的隐性成本项（每链路一颗甚至多颗），这与 800G 光模块的"距离-成本"矛盾同构。服务器厂商需要把 retimer/switch 的布局与功耗预算纳入机柜级电源/散热规划，而非当作单板器件。

**"设备"语义标准化是超节点可编程性的前提。** WG Device Management + DRA 的演进（v1.36 "Next Era"）意味着：机柜内的 GPU/加速器/网卡/存储将逐步获得统一的可发现、可分配、可健康上报语义。超节点若要在万卡集群里被"当作一台计算机"调度，其内部设备必须暴露标准接口——这是硬件厂商与 K8s 生态的接口契约点。

### 分析

**生产集群运维的"数据稀缺"被 504 GPU 报告打破——四点都可直接反哺设计。** ① **多信号故障检测**：751 指标里没有"银弹"指标，说明 RAS 设计必须走"指标融合 + 根因关联"而非单一阈值告警；② **checkpoint I/O 是显性瓶颈**：加载占 21.5% 峰值读带宽、保存占 16.0% 峰值写带宽——这意味着**每轮 checkpoint 都会制造分钟级 I/O 风暴**，存储系统设计（并行文件系统/突发吸收）与 checkpoint 调度（错峰、增量）同等重要；③ **故障节点高度集中**（top3 占 >50%）：坏节点"扎堆"而非均匀分布，运维策略应优先"隔离+替换"而非"普遍修复"，也支持故障预测模型聚焦少数嫌疑节点；④ **自动重试 2.7 倍于手动**：从故障检测到自动重试的闭环自动化收益可量化（33.3% vs 12.5%），且 11 分钟中位重试间隔给出"故障恢复 SLA"的设计基线。这四点与知识库 RAS/故障诊断主线（FTA、容错）直接对接，建议沉淀为集群设计 checklist。

### 分析

**BMC 的"性能-安全-生态"三角正在重塑。** AST2700 的三项升级各有指向：A35 四核 + DDR5/PCIe Gen4 应对**管理面负载增长**（遥测密度、AI 集群带外监控、固件更新体量）；LTPI 集成 CPLD 功能降低**平台 BOM 与复杂度**（少一颗器件 = 少一个供应链风险点）；Caliptra silicon RoT 回应**供应链安全监管**（美国 CISA 等对固件信任根的强制化趋势）。三者共同说明：**BMC 从"风扇控制器+Web 服务器"（STH 评论的原话）升级为平台安全与可观测性的枢纽**——这正是 AI 集群 RAS 与安全审计都依赖带外通道的原因。

**Axiado 进入 MGX 是"第二供应商"的结构性信号。** 过去十年 BMC 几乎等于 ASPEED（AST2500/2600），但 Axiado 以"安全优先"定位切入 NVIDIA MGX 生态，说明：① 超大规模客户对 BMC 安全（尤其 RoT/信任链）的诉求已强到愿意引入第二供应商；② NVIDIA 对 MGX 生态的"管理面开放"策略（允许第三方 BMC）会传导到整机厂商的选型。对服务器产品团队的启示：**BMC 选型应把"安全认证 + 多源替代"写入评估矩阵**，且 OpenBMC 路线（可审计、可定制）在 AI 集群场景的占比会继续提升——默认凭据治理、固件签名链、带外审计日志是交付清单的硬项。

### 分析

### 发现列表

- **CNCF Blog/DRA vs HAMi（08-07）**: GPU 设备抽象路线之争公开化——设备插件（计数）vs DRA（结构化语义），v1.36 后 DRA 生态与 HAMi 类项目的协作边界成为算力平台选型焦点（详见云原生专题）。https://www.cncf.io/blog/2026/08/07/does-kubernetes-dra-replace-hami/

### 分析

**算力平台的 2026 主题：语义、粒度、电价。** ① **语义**：DRA 把"设备"从计数的数字变成结构化资源（容量/健康/可协商），这是 GPU 分片、多租户、异构混部的语法基础；② **粒度**：Pod-Level Resources + In-Place Vertical Scaling 让"资源粒度"从 pod 出生时固定变为运行时可伸缩，配合 OpenCost 的 token 级计费，"算力计量"从卡时下沉到 token；③ **电价**：GridPilot/Power-Flexible 把电网信号接入调度输入，"算力调度"的优化目标从"利用率最大化"扩展为"利用率 × 电价 × 碳强度的联合最优"。三者叠加意味着：**下一代算力平台的调度器必须同时理解硬件语义（DRA）、工作负载语义（workload-aware）、市场语义（电价/碳价）**——这是从"集群调度器"走向"算力经济调度器"的演进方向。

**GPU 分片的平台化窗口。** HAMi 类项目解决"一卡多用"靠的是设备插件层的 hack；DRA + Pod-Level Resources 成熟后，分片语义可以上移到平台层（可观测、可协商、可恢复）。对服务器厂商的含义：**整卡/半卡/多实例 GPU 的固件与驱动支持（MIG/CXL 内存池化）应与 DRA 语义对齐**，否则硬件能力无法在平台层被"看见"。

### 分析

**AIOps 从"告警降噪"进化到"自主修复闭环"。** ES Guardian Agent 的 4 代架构演进（评估→优化→部署→…→升级 11 阶段）展示了一个完整的 AI SRE 形态：**预测（多源 kernel 级遥测融合）→ 决策（对照故障记忆库）→ 执行（工具调用）→ 学习（新故障入库）**。其 300 次自主循环 + 18 小时跨系统宕机恢复的实证，与 504 GPU 报告的"自动重试 2.7x 收益"互相印证：**运维自动化的价值不再需要论证，而是需要规模化**。两个关键设计点值得沉淀：① 故障记忆库（persistent incident memory）作为 agent 的"经验载体"，本质是运维知识库的运行时形态——与知识库的故障案例库建设同构；② 多源 kernel 级遥测（dmesg + NVMe SMART + NIC bond + 热传感器）说明**硬件健康信号（SMART/传感器）是 AIOps 的燃料**，服务器硬件必须开放这些遥测到带内/带外统一通道。

**可观测性的对象从"服务"扩展到"Agent 会话"与"token 成本"。** 传统 APM 看延迟/错误/流量，Agent 系统还要看**轨迹、决策、成本**（同一问题问三遍 = token 浪费）。OpenCost 把成本观测下沉到 token 粒度，PSI GA 把资源压力观测标准化——**运维平台正在变成"成本 × 压力 × 故障"的三维观测台**。对 AI 集群运维的启示：AIOps 数据面应统一纳管 GPU 遥测（利用率/温度/ECC）、网络遥测（RDMA 丢包/拥塞）、存储遥测（带宽/延迟），支撑故障预测模型——这正是 504 GPU 报告"751 指标多信号融合"的运维侧落地。

### 发现列表

- **ServeTheHome/SPEC CPU 2026 发布（FMS 前后）**: SPEC 发布 CPU 2026 基准套件"下一个十年的 CPU 基准"（评论/标题级信号），LLVM 22 编译对比等配套研究出现——**CPU 评测进入 2026 代际**，AI 服务器 CPU 选型的基准参考更新。https://www.servethehome.com/pcie-gen6-and-gen5-will-both-matter-for-ai-storage/（同站新闻列表可见标题）

### 分析

**评测体系的两个"标准化"：载荷标准化与难度标准化。** Chakra 把分布式训练的**载荷**标准化（轨迹级），CAST 把数据集**难度**可计算化（残差 ρu），合起来指向同一个目标：**AI 系统的性能与能力评测从"黑盒跑分"走向"可分解、可复现、可归因"**。对基础设施团队的直接用途：集群采购/验收时，用 Chakra ET 回放生成的标准载荷测"真实训练行为"（而非单点 benchmark），用 PSI/多信号指标测"压力下的表现"——这与 504 GPU 报告的多信号方法论一致。

**AI 安全与审美的"评测对象"正在升级。** Rules or Character 用 scaling laws 建模安全设计（规则 vs 性格塑造的预算分配），MuseCritic 用可读批评替代标量分数——两者的共同点是：**评测信号从"结果正确性"扩展到"过程可解释性"**。安全评测要知道"为什么失败"（角色脆弱性），审美评测要知道"哪里不好"（五维度批评）。这提示 AI 数据与评测专题的下一个热点：**可解释评测信号 + 规模化评测成本模型**，与 RULE.md 中"数据来源三层依据"的文档质量标准在方法论上同构。
