## MoE→硬件影响

- **ViBE: Co-Optimizing Workload Skew and Hardware Variability for MoE Serving**（arXiv:2606.00735, 2026-06）: 首次将 GPU 硬件变异性（制造偏差/功耗墙/热状态导致的同型号 GPU 执行时间差异）纳入 MoE 专家放置决策。ViBE 按"每 GPU 性能建模 + 专家激活画像"把高负载专家分到快设备、低负载专家分到慢设备，SLO 达成率 +14%、P90 TTFT 最高降 45%，且规模越大收益越明显。https://arxiv.org/abs/2606.00735
- **ROMER: Expert Replacement and Router Calibration for Robust MoE LLMs on Analog Compute-in-Memory**（arXiv:2605.11800, 2026-05）: 首个系统研究 MoE LLM 在模拟存算一体（CIM）噪声下的行为——硬件噪声会破坏专家负载均衡、使路由决策持续次优。ROMER 用"低频专家替换为高频专家 + 分位数归一化路由校准"，在真实芯片噪声下将 DeepSeek-MoE/Qwen-MoE/OLMoE 困惑度分别降低 58.6%/58.8%/59.8%。https://arxiv.org/abs/2605.11800
- **AxMoE: Approximate Multipliers × MoE 首次系统性交互研究**（arXiv:2605.04754, 2026-05, ISVLSI 2026）: 8 种 8-bit 近似乘法器 × 3 种 MoE 变体（Hard/Soft/Cluster）× 4 网络架构。结论：不重训时 Dense 最鲁棒；近似感知重训后 ResNet-20 可完全恢复，VGG 在激进近似下不可逆劣化，ViT-Small 上 Hard MoE 在等归一化推理成本下反超 Dense。https://arxiv.org/abs/2605.04754
- **Why Do Prefetchers Fail? Let Agents Answer**（arXiv:2608.13027, 2026-08-13）: 性能异常驱动的 Agent 自动化硬件设计流——1.91B DeepSeek V4 Pro tokens 驱动构造 Mixture of Prefetchers (MoP)，SPEC CPU2006/2017 几何平均 IPC +61.1%，超越人类设计 Alecto/Berti/Pythia 达 14.5%/21.6%/23.6%；RTL 6nm 综合仅 110KB on-chip 存储 + 0.0347mm²。首次实证 Agent 驱动的硬件设计可产出 RTL 可用的 SOTA 级部件。https://arxiv.org/abs/2608.13027
- **Qwen3.8-2.4T-A95B: 2.4 万亿参数混合 MoE 进入 vLLM Day-0**（vLLM Blog, 2026-08-12）: 2.4T 总参/95B 激活的混合 MoE，FP8/BF16 checkpoint + NVFP4/MXFP4 量化权重，NVIDIA 与 AMD 双平台协同内核，开箱即用。混合 MoE（hybrid attention + 高稀疏专家）成为前端模型标配。https://blog.vllm.ai/
- **vLLM AFD Plugin: Attention-FFN 分解的 MoE 弹性服务**（vLLM Blog, 2026-07-23）: 将 MoE 的 Attention 与 FFN 阶段分离调度，GPU 与昇腾 NPU 双后端、connector 执行、图模式与 unbatching 支持——MoE 服务从"整层固定"走向"阶段级弹性分解"。https://blog.vllm.ai/

**分析：MoE 的硬件影响正从"容量/带宽"单一维度向"多物理层"扩散。** 早期 MoE 硬件讨论聚焦于专家激活稀疏性带来的内存带宽瓶颈（CPU offload、EP 通信），而 2026 年 arXiv 的新工作揭示了三个此前被忽视的物理层交互：(1) 同型号 GPU 的制造/功耗/热变异性（ViBE）——同步执行下"最慢 GPU 决定层延迟"，token 路由均衡≠执行时间均衡，硬件异构成为 MoE 服务的常态而非例外；(2) 模拟存算一体（CIM）的模拟噪声（ROMER）——权重扰动直接破坏专家负载均衡，说明 MoE 对"非理想硬件"比稠密模型更敏感，鲁棒路由需要后训练校准；(3) 近似计算（AxMoE）——低功耗乘法器与专家路由的组合在不同架构上恢复能力差异极大，硬软协同设计必须按架构定制。

**对比表：2026 年 MoE 硬件层研究的干预层级**

| 论文 | 干预层级 | 核心机制 | 量化收益 | 硬件前提 |
|:--|:--|:--|:--|:--|
| ViBE | 系统调度 | 硬件感知专家放置 | SLO +14%, P90 TTFT −45% | 同构 GPU 集群（存在性能差异） |
| ROMER | 模型校准 | 专家替换+路由归一化 | 困惑度 −58.6%~59.8% | 模拟 CIM 芯片（含噪声） |
| AxMoE | 电路/架构 | 近似乘法器协同设计 | 依架构（ViT Hard MoE 反超） | 边缘低功耗场景 |
| MoP | 硬件设计流程 | Agent 自动化设计 | IPC +61.1% vs 无预取 | RTL 综合（6nm, 110KB） |

**因果链推演：为什么硬件变异性问题会随规模放大。** ViBE 论文明确指出"硬件变异性影响随规模增加而放大"——原因有二：其一，大规模 MoE 服务普遍采用 EP（专家并行），token 路由跨更多设备，任何单卡执行时间偏移都会成为整层 straggler；其二，规模化部署往往伴随不同批次/不同代的加速卡混用（H100/H200/B300 或 MI300X 混排），性能异构从"噪声"变为"结构差异"。这解释了业界对"弹性专家并行"（vLLM Elastic EP, 05-14）和"硬件感知调度"的双重兴趣：前者解决负载动态，后者解决设备差异，二者互补。对服务器研发的含义是：**MoE 时代"同构集群"假设正在瓦解，调度器与框架必须把硬件性能画像作为一等公民**。

- **Does Kubernetes DRA Replace HAMi?**（CNCF, 2026-08-07）: 项目维护者正面回答 GPU 共享的 API 演进问题——DRA（Dynamic Resource Allocation）v1.34 GA 后成为设备管理标准接口，HAMi（CNCF 孵化项目）在 DRA 之上提供 vGPU 切分、显存隔离与拓扑感知；结论是"不是替代而是分层"：DRA 是控制面协议，HAMi 是实现面能力。https://www.cncf.io/blog/2026/08/07/does-kubernetes-dra-replace-hami/

- **Kubernetes v1.37 Sneak Peek + v1.36 功能盘点**（Kubernetes Blog, 2026-07-31）: v1.36 已落地 PSI 指标 GA（内存/CPU 压力驱动的调度依据）、Pod-Level Resource Managers (Alpha)、分层内存保护（Tiered Memory Protection with Memory QoS）、Workload-Aware Scheduling、DRA 多驱动演进；v1.37 预告更多弃用与收敛。AI 负载的内存分层与压力感知调度成为 K8s 主线。https://kubernetes.io/blog/
- **Gateway API v1.6: TCPRoute/UDPRoute 转标准**（Kubernetes Blog, 2026-08-03）: 服务网络 API 的第四层（L4）能力转 Stable，配合此前 v1.3 的 Inference Extension（AI 推理扩展），Gateway API 正成为"AI 推理入口流量治理"的标准面。https://kubernetes.io/blog/
- **etcd v3.7.0: RangeStream 特性发布**（Kubernetes Blog/SIG Etcd, 2026-07-08）: 长期诉求的 RangeStream 落地，Watch 事件流式读取大幅改善大规模集群控制面读路径；etcd 作为 K8s 大脑的扩展性仍是万卡集群控制面的关键约束。https://kubernetes.io/blog/
- **LLMOps 与平台工程：AI 流水线该谁拥有？**（CNCF/Syntasso, 2026-08-13）: Daniel Bryant 讨论 LLM 进入生产后训练/评测/发布/监控的职责归属——平台工程团队正在把模型视为"负载"而非"项目"，AI 流水线（LLMOps）需要 GitOps 式声明式管理。https://www.cncf.io/blog/2026/08/13/llmops-and-platform-engineering-who-should-own-the-ai-pipeline/
- **Announcing the AI Gateway Working Group**（Kubernetes, 2025）: Kubernetes 官方成立 AI Gateway 工作组，把 LLM 网关（路由/限流/缓存/可观测）作为 K8s 网络面的标准扩展点——AI 流量的南北向治理正式标准化。https://kubernetes.io/blog/

**分析：Kubernetes 正在完成"AI 负载三件套"的标准化拼图。** 对照 2024-2025 年（DRA alpha→beta→GA、JobSet、Kueue），2026 年 K8s 的 AI 化进入"能力收敛"阶段：计算侧 DRA GA + 设备工作组（WG Device Management）统一设备接入；内存侧 v1.36 的 Tiered Memory Protection + Pod-Level Resources 直接把"HBM/DRAM/NVMe 分层"做成调度原语；网络侧 Gateway API Inference Extension + AI Gateway WG 把推理流量的路由/缓存/限流标准化。三个方向合起来看，K8s 不再只是"调度 GPU"，而是试图成为 AI 基础设施的控制面事实标准——这与 CNCF 生态（HAMi/Volcano/Kueue/KServe）形成"控制面标准 + 实现面生态"的双层结构。

**HAMi vs DRA 的辩证关系值得展开。** 粗看 HAMi 是"设备插件时代的产物"，DRA GA 后似乎会被取代；但 CNCF 这篇文章给出了更准确的图景：DRA 解决"设备是什么、怎么声明、怎么分配"（协议层），HAMi 解决"GPU 怎么切、显存怎么隔离、拓扑怎么感知"（实现层）。类比 CSI 与存储厂商驱动的关系：协议标准化反而让实现者有更清晰的扩展点。对 GPU 服务器厂商的含义：**DRA 驱动的设备健康上报（v1.34 Pods Report DRA Resource Health）意味着 GPU 故障感知将进入 K8s 原生调度闭环**，BMC/带外管理与 K8s 控制面的集成点更明确。

## 分布式OS

- **Agora: 互联网级联预训练 8.6B 模型**（arXiv:2607.13332, 2026-07）: 首次演示"无许可"去中心化预训练：330 个贡献节点（多为消费级 GPU、互联网链路、可随时加入退出）40 天训完 Pluralis-8B（8.6B 参数/500B tokens），~170K tokens/s、4.2 tokens/TFLOP（=集中式 H100 基线效率的 63%），收敛差距很小。带宽高效流水并行分片 + 多方容错集合通信，"Protocol Learning"（协议学习）范式——分布式 OS 的极端形态。https://arxiv.org/abs/2607.13332

- **vLLM Router: Rust 状态感知负载均衡器**（vLLM Blog, 2025-12-13）: 面向大规模服务的 prefill/decode 感知路由：KV-cache 亲和性、P/D 分解编排、K8s 发现、熔断重试、Prometheus 指标——推理集群的"流量 OS"雏形。https://blog.vllm.ai/
- **SGLang/其他运行时未抓取**（预算内未覆盖，留待下轮）。

**分析："分布式 OS"概念正在从论文走向 vLLM 生态的工程现实。** 如果把"OS"定义为"对资源（计算/内存/网络）的抽象、调度与隔离"，那么 2026 年的 LLM 推理栈已经具备 OS 雏形：vLLM Router（进程/实例调度）+ Semantic Router（请求/模型路由）+ Mooncake（分布式内存）+ DCP（跨卡 KV 分片）——四层分别对应传统 OS 的进程调度、路由决策、虚拟内存与 TLB。区别在于：传统 OS 的资源是 CPU 周期与物理页，AI OS 的资源是 GPU 卡、KV cache 块与 token 吞吐。

**Agora 的反直觉价值。** 63% 的集中式效率看似"损失 37%"，但在"无许可、异构、可抢占"约束下达成，其系统意义在于验证了三个机制：(1) 带宽高效流水并行（PP 分片）在互联网级链路上可收敛——通信不是硬约束；(2) 多方容错集合通信让"随时掉线"成为可容忍事件；(3) 没有单一实体持有完整权重（每节点仅一个 stage）——所有权模型本身被改写。对数据中心团队，Agora 的短期价值不是替代集群，而是其容错/异步优化技术可反哺弹性训练（对照 ETC 的 checkpoint-free 迁移，见集群训练专题）。

## 集群训练优化

- **Mixture-of-Parallelisms (MoP): MoE 训练栈**（arXiv:2607.01844, 2026-07）: 按层/阶段组合现有与新型并行技术，12×8×H200（96 卡）支撑万亿参数、1M context 的无损预训练/微调；较强调优 FSDP2 基线 per-GPU 吞吐高 4.7x~8.2x（规模越大差距越大），基线在 64~128K 后 OOM。https://arxiv.org/abs/2607.01844

- **TERRA: 96×H200 的高分辨率地球建模训练**（arXiv:2608.15211, 2026-08-15）: 采样感知窗口/序列/张量并行（SAWSTP）+ 记忆编排（MO），11.4B 模型 39.76 PFLOPS，强扩展 65.0%/弱扩展 94.1%；MO 较纯 checkpoint 峰值显存 −32.2%~51.8%（步开销 ≤20%）。https://arxiv.org/abs/2608.15211
- **SNI-GNN: BlueField-3 SmartNIC 的图神经网络训练**（arXiv:2608.06441, 2026-08, ICDE 2026）: 网内嵌入预测把远程嵌入通信降 21~45%，端到端 1.3~3.6x 加速——DPU 卸载从"网络转发"延伸到"训练数据面"。https://arxiv.org/abs/2608.06441
- **HetCCL: 混合厂商异构集群的集合通信**（arXiv:2605.31000, 2026-05）: NCCL/RCCL 之外补"跨厂商 GPU 直连"：消除 host-device 拷贝开销、控制面卸载 CPU——多厂商加速卡混训的通信层基础设施。https://arxiv.org/abs/2605.31000

## AI数据与评测

- **SUBJSIM: 19,300 上下文的主观性标注基准**（arXiv:2608.19689, 2026-08-20）: 人类行为本身是分布而非单点——提出"主观性系数"（熵度量）区分客观任务（编码）与主观任务（社会模拟），SALT 软标签训练按主观性自适应聚合；19,300 contexts × 193 标注者 × 100 主观问题。LLM 评测从"单标签准确率"走向"分布匹配度"。https://arxiv.org/abs/2608.19689
- **C-Score: 半监督学习的鲁棒性诊断**（arXiv:2608.20667, 2026-08-20, ICSSE 2026）: 干净准确率可能"看似稳定实则恶化"——在 SVHN 污染下 CCI 上升 280% 而准确率仅差 3%；提出预测/表征/优化三空间的内部诊断信号，证明"评测内部动力学"比表面指标更可靠。https://arxiv.org/abs/2608.20667
- **GEAR: 表格基础模型蒸馏到轻量预测器**（arXiv:2608.18849, 2026-08-19）: 两阶段蒸馏（合成协变量软目标 + 真实标签锚定），中位推理时间降 57~2866x、峰值显存降 1.9~3.3x，AUC 反而高于监督基线——"大模型蒸馏到可部署小模型"的量化证据。https://arxiv.org/abs/2608.18849
- **PEMSB-3V: 三变量流量预测基准 + RiskTraf**（arXiv:2608.20656, 2026-08-20, CIKM 2026 Oral）: 公开基准保留原始 flow/speed/occupancy 三测量——"数据完整性"作为基准设计的核心价值。https://arxiv.org/abs/2608.20656
- **ATMOS 类评测方法论未覆盖**（预算内未抓取，留待下轮）。
- **Kubeflow SDK 1M 下载**（CNCF, 2026-08-03）: 数据/ML 工作流 SDK 化的采纳里程碑（见框架专题）。https://www.cncf.io/blog/2026/08/03/kubeflow-sdk-evolution-one-million-downloads-and-counting/

**分析：2026 年 AI 评测的方法论主线是"挑战单点准确率崇拜"。** SUBJSIM（人类行为是分布）与 C-Score（内部动力学比准确率更早劣化）从两个角度戳破同一个假设——"准确率能代表模型质量"。SUBJSIM 针对评测数据（单观察 vs 分布），C-Score 针对训练动力学（外部指标 vs 内部信号）；两者的共同推论是：**评测体系需要从"输出正确性"扩展到"行为分布匹配 + 内部状态健康"**。这对 AI 数据工程的含义：数据集构建（标注分布、污染控制）与评测协议（分布指标、诊断信号）必须同步升级，否则模型迭代会基于失真的反馈信号。

**数据工程的分层策略。** GEAR 给出"大模型→可部署模型"的蒸馏数据路径（软目标 + 锚定），PEMSB-3V 强调基准数据完整性（保留原生三测量），Kubeflow SDK 给出工作流数据管道化的采纳信号——三者分别对应数据生命周期的"蒸馏、标注/采集、编排"环节。综合判断：**AI 数据与评测正在成为与模型/系统并列的第三基础设施**，其工业化程度（基准质量、标注分布建模、蒸馏管线）直接决定模型迭代的飞轮效率。

- **昇腾 NPU 训练万亿 MoE 的可行性之争**：正方(SLAI T-Rex 团队,https://arxiv.org/abs/2607.20145)——34.22% MFU、2.93x 相对基线提升，证明昇腾 SuperPOD 可支撑万亿级 MoE 全参后训练，国产芯片训练栈"可用"；反方(社区对 MFU 基线的质疑，https://arxiv.org/abs/2607.01844)——CUDA 生态（MoP/MatrixFSDP 等）同时期把 FSDP2 基线再推 4.7-8.2x，昇腾 34.22% 与 CUDA 栈最优值的差距仍存在，且优化依赖手工 kernel 移植；辨析:本库判断——34.22% MFU 在"可用性"层面已达标（与 DeepSeek 官方 35-40% 同量级），差距主要在工具链自动化与生态广度，国产训练栈的下一战场是"好用"而非"可用"。
