## 1️⃣ 🟡 Atlassian 设计系统 "Structured Content" — 为 AI 重构知识为机器可读 schema（分类页补录，首次归档）

> ⚠️ **补录说明**: 文章发布于 **2026-06-02**，此前未归档（log.md 无锚点、08-01/08-02 未展开），本期从分类页发现并深挖。量化数据为新增锚点。

| 维度 | 内容 |
|:-----|:------|
| **来源** | [Teaching AI to speak our design language](https://www.atlassian.com/blog/ai-at-work/teaching-ai-to-speak-our-design-language)（2026-06-02, Atlassian AI at Work） |
| **问题** | 设计语言信息散布在文档站/Confluence/Figma/Looms/数百个代码包中——**大部分文档为人阅读设计，机器不可读** → AI 生成 UI 结果不可预测、成本超标：用过时模式、漏可访问性要求、发明不存在的组件 |
| **方案** | 将 Design System 内容重构为 **structured content**——组件/图标/tokens/lint 规则/基础指南的**一致、轻量、机器可读 schema**（TypeScript 文件与代码同源）→ 从单一 schema 源生成 ADS MCP server / design system skill / DESIGN.md 等所有格式 |

### 📊 量化结果（vs 无 MCP、agent 自行扫描 monorepo + 非结构化文档）

| 指标 | 数值 |
|:-----|:----:|
| 特定查询准确率提升（最高） | **+52%** |
| ADS 任务平均提速 | **+34%** |
| AI 工具调用减少 | **−26%** |
| Token 用量减少 | **−16%** |
| 生成代码准确率提升 | +4.9% |
| 错误减少 | −11% |

### 信号意义（三层）

- **① 上下文工程成为新工程实践**: "单一事实源"问题从**人读文档**转向**机器读 schema**——知识以结构化形式直达 agent，而非让人去发现/阅读/解释文档。与 07-13 "Knowledge Architect 角色"、07-17 Teamwork Graph 上下文层定位互为印证
- **② 文档自愈 (self-healing)**: 团队更新组件时 **AI skills 自动更新结构化内容 + 运行 evals 和代码健康检查**——"漂移的文档比没有文档更糟（产生自信的错误/幻觉）"。呼应 08-02 "AI 写作指南"的内容治理维度，从文体层延伸到**知识保鲜机制**
- **③ 与用户知识库实践的直接映射**: schema 同源生成多格式（MCP/skill/DESIGN.md）= 用户"SSOT + 多格式派生"原则的工程化实现；"结构化内容减少冗余源、暴露文档缺口（缺可访问性指南/过期代码示例）"与用户"文档迁移后检查 index/log 链接完整性"同源
