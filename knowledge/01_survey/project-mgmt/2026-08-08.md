## 1️⃣ 🔴 Jira as the System of Record for OpenAI Symphony（新发布, 08-06）

- **来源**: [Introducing Jira as the System of Record for OpenAI Symphony](https://www.atlassian.com/blog/ai-at-work/jira-system-of-record-openai-symphony)（Atlassian AI at Work, 2026-08-06, Alex Radu Principal Developer）
- **结构**: **OpenAI Symphony 负责 Codex 的 agent 编排循环（orchestration loop），Jira 提供 System of Record（工作记录）**——"sessions 和 sandboxes 是临时的，但 Jira 保持上下文完整：intent/status/progress comments/code reviews/follow-up tasks 都连在你已经在用的工作流里"
- **🔴 核心转变**: "Start with the work item, not the session"——agent 工作在隔离环境运行，但 Jira 把它锚定到团队工作流；配 Teamwork Graph 上下文后 agent 工作持续挂在工作项上
- **哲学陈述**: "**让工作对 agent 可读（legible），但不让它对人类不那么可问责（accountable）**"——每个 agent 动作保持可见、可治理、绑定到结果；工程师可看到 queued/running/needs review/discovered follow-up，无需盯每个 session 直播
- **工作流五步**: ① Jira 定义工作（带 agent 所需上下文）② workflow states 控制执行（active/blocked/ready for review/complete 状态机）③ Symphony 协调循环（watch Jira 项目→找合格工作→协调 agent 执行）④ Codex 隔离 worktrees 并行跑（不混改动）⑤ 审查留在 Jira（plans/updates/blockers/follow-ups 连到工作项）
- **🔴 开源落地**: Symphony 为公共仓库（[github.com/openai/symphony](https://github.com/openai/symphony)）——用 `JIRA_WORKFLOW_PROMPT` 让 Codex 生成定制 Workflow.md、配置 Jira workspace、启动 Symphony（elixir/ 目录）；建议从小任务（清晰验收标准+低依赖风险）起步逐步扩大
- **信号意义**: 08-05 "Jira Automation = 开放控制面"（触发 Copilot/Cursor/Claude）的**再升级**——**编排执行（Symphony）与工作锚点（Jira）解耦**，Jira 成为"System of Work"而非"System of Sessions"；"Autonomy stays observable" = 你记忆里"自主性可观察"原则（08-03 harness 分析）的行业落地模板；与 08-02 Rovo 单一推理循环、08-05 orchestration 主线一脉相承 📌

## 2️⃣ 🔴 Jira Summer 2026 Release: 15 个新能力（新发布, 08-05）

- **来源**: [What's new in Jira: Summer 2026 release](https://www.atlassian.com/blog/development/jira-summer-release)（Atlassian Development, 2026-08-05, Dave Meyer）— 8 月底前 Jira Cloud GA，预览 6/15
- **🔴 Delivery Agent（AI 代理执行日常协调工作）**: 自动化过去人工做的协调任务——health checks/standup digests/stakeholder updates；Jira Summary view 的 automation templates 数秒配置——"agent 承担重复协调工作，人专注重要事项"（与 08-06 Agentic Pipelines 文档维护同族）
- **🔴 Rovo 自然语言生成整个 space**: 描述团队工作方式（或附 Confluence pages/Looms/decks/images 上下文）→ Rovo 生成完整 space（workflows/work types/views/建议首批工作项）——**从"配置工具"到"描述即生成"**
- **🔴 核心视图重建（性能量化）**: work items 加载 **+45% 快**、lists/search **+48% 快**、boards/backlogs **+22% 快**；List 与 All Work 合并为单一 List 视图（JQL 或自然语言搜索、父子层级、行内编辑、自定义视图）；软件 board 重建（swimlanes/子任务上卡/行内编辑/无 work item 上限）
- **🔴 Capacity view（容量视图）**: 团队工作分配可视化——谁超载/谁有空闲，backlog 与数字并列、无需切工具即可再平衡——"谁 overloaded? deadline 如何?" 这类问题不再需要离开 Jira
- **🔴 Formula fields（公式字段）**: 自然语言描述 → Rovo 写公式（剩余预算/距截止天数/加权优先级分数），结果可搜索/排序/随工作实时更新——**描述式计算字段**（AI 把"数学"内建进工作项）
- **信号意义**: 15 能力分布 = **AI 代理（Delivery Agent/Rovo space 生成）+ 视图性能（+45%/+48%）+ 数据驱动管理（Capacity/Formula）**——Jira 正从"追踪工具"升级为"AI-native 工作系统"，性能重建为 agent 高频操作打底；Capacity view 呼应 Q4 股东信"编排工作"叙事（容量=编排的输入）

- **信号意义**: **"挑战从 doing the work 转向 orchestrating it"**——CEO 亲口确认编排主线（呼应 08-05 orchestration、08-06 Symphony system of record、本期 Summer Release）；"模型可租（hire intelligence by the token）、上下文不能租" = 你 08-04 Leading with Context（上下文>模型）的**财务级背书**；Rovo 采用者 ARR 2x = AI 采用→商业回报的直接证据链；六上下文 = Teamwork Graph 即企业级"上下文图谱"的完整定义 📌
