## 1️⃣ 🟡 Linear Agent 新增文档编辑能力 — Agent-assisted text editing + Text attribution

| 维度 | 内容 |
|:-----|:------|
| **来源** | [Linear Changelog — Text attribution and agent-assisted editing](https://linear.app/changelog) — Jul 23, 2026 |
| **工具** | Linear Agent × Documents × Loops × Version History |
| **方法论** | Agent 能力从代码区域（Coding Sessions）扩展到**文档区域**，补全了 Agent 知识产出的完整闭环 |

### 1.1 关键更新

| 能力 | 功能说明 |
|:-----|:---------|
| **Agent-assisted text editing** | Linear Agent 现可直接编辑文档（Documents）和项目描述（Project descriptions），不再仅限于代码操作 |
| **Loops 联动** | 可用 Loops（07-20 发布的循环工作流）保持文档和项目描述始终更新——定时或事件驱动 Agent 自动刷新文档内容 |
| **Text attribution** | 作者名指示器显示文本是由**同事编写**还是由 **Loop 添加**，解决「谁写了什么」的溯源问题 |
| **修改高亮** | 通过 Linear Agent 做的编辑以独立高亮显示，便于人工审查 Diff |
| **Version history** | 支持恢复到任意历史检查点 |

### 1.2 方法论 — Agent 能力从代码到文档的补全

```
之前: Coding Sessions -> 代码区域 (写代码/修Bug)
      Code Intelligence -> 代码理解 (读代码)
      (文档区域空缺)

Jul 23: + Agent-assisted text editing -> 文档区域
        + Loops -> 保持文档持续更新
        + Text attribution -> 人与Agent协作溯源
        + Version history -> 可回退的安全网
```

**补全了什么**：
- Agent 的「读」能力已覆盖：代码（Code Intelligence） + 文档（之前就有了）
- Agent 的「写」能力此前仅覆盖：代码（Coding Sessions），**文档只能读不能写**
- Jul 23 补上了文档写的这个缺口

### 1.3 与 07-20 Loops 的联动

Loops（07-20 发布）定义了「团队级循环 Agent 工作流」，但当时 Loop 能做的事受限于 Agent 的能力边界。文档编辑能力的加入，使得以下 Loop 用例变得可行：

- **发布计划自动同步**: Loop 每日扫描活跃 Projects，发现变更 → 自动更新相关文档并记录原因
- **项目状态文档自动刷新**: 每周 Loop 汇总 Issue/PR 状态 → 写入项目描述
- **规范的持续维护**: Loop 检查文档与代码库不一致 → 自动发起更新

### 1.4 赛道意义

| 维度 | 意义 |
|:-----|:------|
| **能力闭环** | Linear Agent 现在能「读代码 + 读文档 + 写代码 + 写文档」— 全栈 Agent |
| **协作透明** | Text attribution 解决了 Agent 时代最关键的问题之一：**谁对什么内容负责** |
| **风险可控** | Version history 提供回退安全网，降低 Agent 写入文档的心理门槛 |
| **文档基建** | 配合 Team Documents (06-04) 和 Agent Assisted Project Updates (06-17)，Linear 的「文档即代码」基础设施已经具备 |
