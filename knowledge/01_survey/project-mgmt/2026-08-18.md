## Agent-first 规模化实证（客户故事）

- **Linear/Ramp：内部 coding agent "Inspect" 编写 60%+ 的 merged PR**（04-27）: 纽约金融科技公司（2019 年成立，1,600 人，从 5 人时即用 Linear），全产品工作流跑在 Linear 上；3 名工程师（Zach Bruggeman 等）用**两周**自建后台 coding agent Inspect——不选市面 agent 的理由是"tight integration with our development lifecycle and our tooling"（内部工具可精确知道"我们唯一 API key 的 schema"）；后端任务可跑测试/review telemetry/查 feature flags，前端可可视化验证并返回截图与实时预览，每 session 沙箱运行。**60%+ merged PR 由 Inspect 编写，是敏感监管行业（金融）负责任规模化 AI 采纳的组织级实证**。URL: https://linear.app/customers/ramp 📎 raw: tmp/raw/2026-08-18/linear-ramp-inspect-agent.md
- **Linear/Ramp：集成速度与采用路径的量化细节**（04-27）: 集成 Linear API for agents 时 Zach 用 coding agent 读 Linear docs，"**30 分钟完成 90%**"；采用路径呈三阶段——web 界面 → Chrome 扩展 → **Slack 集成效果最强**（可见性带动采用，非工程团队 Design/PM/Product Ops/Data 看到 agent 实况后更愿自己试）；"multiplayer" 会话共享（链接分享、Slack 线程接力）让非技术团队把想法推进到"大半完成"，工程师只 review 收尾；配套集中式 AI 治理——central team 定义 agent 可访问系统与权限边界（shared rails），职能团队在此安全轨道上自建自动化。URL: https://linear.app/customers/ramp 📎 raw: tmp/raw/2026-08-18/linear-ramp-inspect-agent.md
- **Linear/Ramp：新瓶颈从写代码移到 review 代码**（04-27）: 反馈流闭环变为"Slack 收到反馈 → @Inspect, fix this → PR 打开 → 批准即上线"，小问题不再滞留 backlog；Zach 明言**软件开发的下一个约束是代码审查**（"shifted the bottleneck from writing code to reviewing it"），Ramp 正在找新工具解决 review 瓶颈，并密切关注 Linear 如何塑造审查流程——与 08-16 Coinbase"工程师审 agent 夜间 PR"形成同一趋势双样本。URL: https://linear.app/customers/ramp 📎 raw: tmp/raw/2026-08-18/linear-ramp-inspect-agent.md
- **Linear/Boom Supersonic：硬件/航空业借用软件项目管理方法**（07-15）: 超音速客机公司（2014 年成立，2023-06 转 Linear）同时自研 Overture 客机与 Symphony 发动机（航空业罕见——"airplane and engine designed together and refined against each other"）；团队刻意不用 1990s 航空传统（长前置规划+慢速专业交接），改借软件习惯：**短周期迭代、尽早构建、实物优先**（"a part you can hold teaches you more than a part you can only model"）、软件工程师与硬件团队并肩、全员被期望自建提效工具；Linear 作为全程序唯一规划层，跨团队可见"自己那块如何拼进整架飞机"——**对服务器/硬件研发组织是"软件式项目节奏落地硬件"的直接参照系**。URL: https://linear.app/customers/boom 📎 raw: tmp/raw/2026-08-18/linear-boom-supersonic.md
- **Linear/Cursor：Linear 作为决策锚点 + agent 预写首版**（02-04）: AI 编辑器公司（旧金山 2023 年成立，2023-05 转 Linear）"ideas don't wait" 文化——Slack 提 idea 次日即 "Oh yeah, I built that"；工程负责人 Andrew Milich 的决策规则：**"The way we decide whether something actually gets fixed is if it's an issue in Linear. If it's not there, it gets lost."**（ticket 即决策清单，不进 Linear 的反馈自动失焦）；两周一发布，工程师从 idea 到 polish 全程拥有；慢的环节曾是跨工具搬运上下文，自建 Linear 内 agent 后"打开 issue 时 agent 已找到相关文件并写好第一版，PR 已开"——**agent 前置打底成为 issue 工作流新默认**。URL: https://linear.app/customers/cursor 📎 raw: tmp/raw/2026-08-18/linear-cursor.md

## Agent 时代 code review（方法论）

- **Linear/Reviewing code in the agent era（06-10, Maciek Pekala）**: 工程师自述 agentic coding 对 review 的真实压力——"without drowning in pull requests"；用 Linear Diffs 把审查标准拉高的个人实践：agent 产出 PR 激增后，review 不再只是"读 diff"，而是与产品上下文（issue/spec/意图）并置审阅。URL: https://linear.app/blog/reviewing-code-in-the-agent-era
- **Linear/Code review should be fast（05-28, Tuomas Artman）**: 联合创始人立论"Agents are forcing a change in how we review code"——Diffs 把 code review 直接搬进 Linear，使审查与产品上下文同处一室；与 Ramp 的 review 瓶颈观察同频：**2026 年 agent-first 组织的第一约束已从"写代码"转移到"审代码"**，审查工具链（Diffs/批量审阅/上下文并置）成为项目管理软件的新竞争点。URL: https://linear.app/blog/code-review-should-be-fast
- **Linear/Continuous planning in Linear（2025-10-30, 背景锚点）**: 连续规划（continuous planning）方法论文档——小步调整计划而非季度级重规划，是 agent 化组织"计划即代码"的基础形态（本期客户故事均建立在该规划模式上）。URL: https://linear.app/blog/continuous-planning-in-linear
