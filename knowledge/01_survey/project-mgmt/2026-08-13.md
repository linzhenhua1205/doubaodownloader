## 1️⃣ 🔴 Code Context: 代码库上下文进入 Teamwork Graph, Rovo/编码 agent 全接入（08-12, 核心发现）

- **来源**: [Introducing the AI context engine for your entire codebase](https://www.atlassian.com/blog/development/code-context)（Inside Atlassian / Development, **2026-08-12**, 全库未归档, 首次收录）
- **本质**: Atlassian Code Context 将**大规模多仓库代码库理解**引入 Teamwork Graph——"Without the right context, every day is day one for a coding agent"; 代码只讲一半故事, agent 还需围绕公司级信号（架构决策/产品策略/解释 tradeoff 的对话）组织思考
- **能力清单**:
  - **索引**: 管理员 opt-in 开启 code indexing; 词法（lexical）+ 语义（semantic）双检索——精确匹配 + 自然语言提问 + 跨仓库取相关源码
  - **接入面**: Teamwork Graph CLI 供 **Cursor / Claude Code / Codex** 使用（agent 行动前高效检索上下文）; 同时是 **Rovo Chat skill**（问 Rovo 你的代码库）
  - **跨仓+跨系统**: 超出本地工作区——可查连接仓库 + Jira work items / Confluence 页面 / Loom 视频 / **50+ 连接器**（Slack/Google Drive 等）
  - **权限感知**: 在 Teamwork Graph 内"secure, permission-aware"推理, 与 08-12 期 Confluence agents 同架构
- **🔴 量化（内部 benchmark 复述, 与 08-12 期 Confluence 文同源）**: 被 Teamwork Graph 增强的 agent **准确率 +44%, token 消耗 -48%**（对比无增强 agent）——上下文层经济性再次成为核心卖点
- **客户背书**: SpotOn CTO Mark Walz——"When an agent starts in the wrong place, everything slows down and costs more"; Code Context 把这一切前置到 agent 面前
- **对比演示要点**: 两个 agent 都理解"可能的技术问题", 但用 Code Context 的 agent 把假设变为**验证过的系统诊断**——在本地不可用的相关仓库定位问题, 依据先前决策判断改在彼仓而非本仓
- **信号意义**: 这是 **08-11 Long Horizon"flattened tools" + 08-12"Teamwork Graph 上下文层"的第三块拼图**——上下文从"工作/人员/知识"扩展到"**代码**", 四维全齐; 对 agent 的"知识盲区"（本地工作区之外）给出平台级答案; **多仓语义检索 + IDE 三端接入 = 编码 agent 的"全局记忆"商业化落地** 📌

## 2️⃣ 🔴 AI Superuser 研究: 一个深度用户就是杠杆, 0→1 即 +18pp 顶分概率（08-11, Teamwork Lab 实证）

- **来源**: [You don't need a team of AI experts. You just need one.](https://www.atlassian.com/blog/ai-at-work/you-dont-need-a-team-of-ai-experts-you-just-need-one)（Inside Atlassian / AI at Work, **2026-08-11**, 全库未归档）
- **方法**: Atlassian Teamwork Lab 将 **ShipIt 黑客松**（24 小时/自组织/统一评审标准）项目评分与内部 AI 使用数据关联——**2,574 参与者 / 1,271 团队, 870 支提交 demo 并获评分的团队**; 定义 superuser = 本职能内周 AI 交互 top 四分位（相对基准, 非绝对用量）
- **🔴 核心发现（0→1 效应）**: 团队从 **0 个 superuser → 1 个**, 获得顶分（高于中位）概率 **+18 个百分点**; 这是最大跃迁——**2+ superuser 团队与 1 个得分基本持平**（收益几乎全部来自第一个）
  - 对比 0 superuser 团队, ≥1 superuser 团队: **创新性评分高 +19pp / 客户影响力 +15pp / 接近完成度 +14pp**
- **🔴 二元分离（交付 vs 质量）**: **团队规模决定是否交付**——每增 1 名成员, 提交 demo 概率 **+79%**（但规模与质量无显著相关）; **superuser 构成决定质量**——与顶分强相关, 但与"是否交付"无关——"Team size determines whether you ship. AI fluency determines whether it's any good."
- **分布警示**: 49% ShipIt 参与者达到 superuser 线, 但**近 1/4 的评分团队一个 superuser 都没有**——"0 superuser 团队比你想的多"; 结合 State of Teams 2026: **85% 知识工作者用 AI, 仅 29% 嵌入日常工作流, 55% 高管称 AI 正拉大团队间绩效差距**
- **落地建议**: ① **识别你的 superuser**（按职能相对定义, 不设全公司统一线）② 别假设 AI 技能均匀分布——"让每支团队至少有 1 个深度使用者", 而非追求全员平均水平
- **信号意义**: 与 08-12 期"高吞吐工程师 2-4 高认知任务上限"同属**人因学边界研究**——AI 采纳不是"越多越好"而是"**临界点效应**"（0→1 收益最大）; 为组织 AI 转型给出可量化指导: **资源应向"每队至少一个深度用户"倾斜**, 而非摊薄全员; 与知识库"AI superuser 识别"概念互证 📌

## 3️⃣ 🟡 Atlassian 营销 3 大 AI Bet: 从"工具堆叠"到"连接系统"（08-11）

- **来源**: [3 AI bets powering Atlassian's integrated marketing impact](https://www.atlassian.com/blog/how-we-build/ai-bets-powering-atlassian-integrated-marketing-impact)（Inside Atlassian / How We Build, **2026-08-11**, 全库未归档）
- **背景量化（AI 采纳鸿沟）**: Atlassian 研究——**94% 营销人员用 AI, 但仅 3% 营销高管有信心展示组织级 ROI**——"The gap comes down to strategy, not technology"; 团队转变: 停止堆 AI 工具, 聚焦"如何用"（three focused, connected investments）
- **Bet #1 付费预算动态优化**: ML 预算工具近实时检测各渠道边际收益递减, 建议即时调仓——目标 **成本转化效率提升 ≥10%**; 从"季度复盘后知后觉"转向"信号变化即调整"（放弃 post-mortem marketing）
- **Bet #2 多触点旅程个性化**: ML 模型跨 landing pages/email 轨道/in-product 触点协调信息, 每次交互学习上一次; **Teamwork Graph 提供"机构记忆"**（受众/信息/跨组织工作上下文）→ 更明智决策
- **Bet #3 创意规模化对抗 ad fatigue**: agentic 创意工具学习表现好的素材并**规模化生成本地化/角色化变体**——省去多轮创意迭代, 压缩数周上线周期
- **核心论点（AI 复利）**: 三 bet 非孤立试点而是**连接系统**——预算信号→投资去向, 旅程数据→客户响应, 创意表现→信息共鸣, 反馈回流使每个 campaign 更智能——"AI builds momentum when you connect it intentionally. Standalone tests stay isolated, but a connected system learns and grows."
- **信号意义**: 营销侧复刻了研发侧的"**上下文连接 > 工具数量**"规律（与 08-12 期 ticket 即 spec、本期 Code Context 同构）; 3% vs 94% 的 ROI 信任鸿沟 = 组织级 AI 价值证明的普遍困境, 与知识库"AI 洞察质量受限于工作连接度"互证 📌
