## 📌 今日要点

AI 项目管理工具正从「跟踪工作」转向「代理工作」：Linear 的 Coding sessions 延伸到部署运行+浏览器测试，Jira 提供全 agent 状态可见性并可用自动化规则直接编排 GitHub Copilot/Cursor/Claude，PM 工具正在成为 AI 编码代理的调度与验收层。**「好 ticket 是 AI 编码的输入资产」与「spec 驱动迁移」两个案例给出量化证据（5x 产出、1 周完成 2 季度工作），对研发管理选型有直接参考价值。**

## 🟢 Linear（官方 changelog）

- **Coding sessions 升级：环境/浏览器测试/透明定价**（2026-08-20, https://linear.app/changelog）: Linear Agent 可自动配置代码环境（Python/Ruby/Go 等开箱支持，可 pin 运行时版本/设置脚本/环境变量），应用运行后进入浏览器测试并采集前后截图；定价改为透明两组件：模型按供应商公开费率无加价 + Sandbox 运行时 $0.25/20 分钟块，管理员可设工作区级/用户级日/周/月花费上限（到限即暂停 AI credits）。「写代码→部署→测试验证→交付」闭环，是 agent 完成度的一次跃迁。
- **Team initiatives + Enterprise MCP 授权**（2026-08-13, https://linear.app/changelog）: initiative（战略级规划）新增团队主导模式，明确负责人与公司方向贡献；私有团队 initiative 仅成员可见，服务保密规划/审计/受限项目；Linear MCP 支持 Okta 托管授权（企业员工经 Anthropic agent 连接时复用 Okta 身份与既有权限，管理员集中管理，无需逐个授权）——企业级 agent 访问控制的落地样板。
- **GitHub Copilot for Linear**（2026-07-30, https://linear.app/changelog）: 用户可直接从 Linear 把 issue 分配给 Copilot 云 agent，Copilot 基于 issue 上下文在自身开发环境打开 draft PR 并回写 issue 进度，可经 Linear 评论持续 steer——「PM 工具成为编码代理调度层」的又一验证，与 Linear Agent（底层 Claude Code/Codex）双轨并行。
- **Loops：agent 周期性工作**（2026-07-20, https://linear.app/changelog）: 用自然语言描述任务，按 schedule 或事件触发运行；官方示例：审查 incoming issues→研究根因→分派编码 agent、从会议记录/事故报告创建跟进工作、保持 launch plan 与项目 spec 更新；运行记录团队级可见可审计，Business/Enterprise 计划可用，赠送 $20/seat 促销 credits（08-20 到期）。agent 从「响应式」走向「主动值守」。
- **Coding sessions 首发（Claude Code/Codex 引擎）**（2026-06-11, https://linear.app/changelog）: Linear Agent 用 Claude Code 和 Codex 写代码，云端运行免本地环境；**量化数据：Linear 内部用该流程自动解决约 30% 的 incoming bug 报告（多数一次通过）**——agent 首轮修复率是选型关键指标。
- **Agent assisted project updates**（2026-06-18, https://linear.app/changelog）: 「Write with Agent」自动汇总上次更新以来的 issue/文档/Slack 变化生成项目更新草稿，人工精修后发布——周报/项目更新的撰写成本被 agent 吸收；另有 Vercel Eve 开源框架（incident 调查/SLA 监控/客户反馈分析类 agent）可直接对接 Linear 被委派 issue。

## 🔵 Atlassian / Jira（官方 blog）

- **Every agent. Every state. Full visibility in Jira**（https://www.atlassian.com/blog）: 软件团队可在 Jira 内查看所有编码 agent 的状态（卡住/进行中/完成）——「agent 可见性」成为 PM 工具新标配，呼应研发管理对 AI 工作流的可观测需求。
- **Jira Automation 编排 AI 编码 agent**（https://www.atlassian.com/blog）: Jira Automation 规则可把 GitHub Copilot、Cursor、Claude 作为步骤触发，设置条件后自动交接工作给 agent——「从 prompts 到 orchestration」，PM 工具=agent 工作流编排中枢。
- **Spec-driven AI Migration 量化案例**（https://www.atlassian.com/blog）: 小团队把 100+ GraphQL fetchers 迁移，通过把 Jira tickets 转为 AI agents 可执行的行为规范，**「近 2 个季度的工作量 1 周完成」**——规范化的 ticket/spec 是 agent 化的前提资产。
- **Why better tickets help agents write better code**（https://www.atlassian.com/blog）: 小团队用 AI agents 构建生产级薪酬应用：**每位工程师 5x 代码量 + 5x Jira tickets 量，且 ticket 质量显著更高**——好 ticket 既是人的协作资产也是 agent 的输入资产，「ticket 质量」指标优先级上升。
- **The future of Jira isn't just tracking work. It's delegating it.**（https://www.atlassian.com/blog）: 把 AI agent 能力映射到软件团队职能的实验——Jira 定位从「跟踪」转向「委派」，与 Linear 走向一致。
- **Rovo Chat Long Horizon 推理引擎**（https://www.atlassian.com/blog）: 单推理循环替代多代理路由（one prompt, multiple steps），第一代 Rovo Chat 已上线——多代理路由 vs 长程单循环的技术路线分歧值得跟踪。
- **Teamwork Graph 上下文连接器**（https://www.atlassian.com/blog）: 新增 Salesforce（客户上下文）、Google Drive/SharePoint（文档知识）、GitHub（代码上下文）连接器，为 teams 与 agents 提供统一上下文——agent 上下文工程从「工具内部」走向「跨系统图谱」。
- **Trello 7 个新 AI 功能**（https://www.atlassian.com/blog）: 面向 Standard/Premium/Enterprise 所有付费用户全量推出——轻量 PM 工具 AI 化的普适推进。
- **AI 治理：Don't Build AI Governance From Scratch**（https://www.atlassian.com/blog）: 引 Gartner 预测（2028 年 Fortune 500 平均将拥有大量 agent，原文数字被截断），主张 agent 化转型的集中式治理「直接开启而非从零搭建」——企业级 agent 治理产品化信号。
