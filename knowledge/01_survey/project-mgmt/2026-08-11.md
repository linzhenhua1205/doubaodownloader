- **平台能力全景（仍值得记录为背景资产）**: **Workers**（托管运行时, 隔离沙箱跑 syncs/tools/workflows, public beta, 8 月前免费）· **Syncs**（Zendesk/Salesforce/Postgres 等外部数据源持续 upsert 进 Notion Database, declarative schema + persistent cursor）· **Agent tools**（自定义工具生成资产/查实时数据/调任意 API, 确定性+token 高效, 补 MCP 短板）· **Webhooks**（外部触发工作流, worker.webhook 监听 PR merged/incident 等）· **External Agents**（Claude/Cursor/Codex/Decagon 或自建 agent 作为一等工作区参与者, External Agents API + waitlist）
- **治理三件套（与知识库记忆互证）**: **progressive trust**（先人工审查→逐步自主）· **可见性**（所有 agent 动作同工作区可见, Mention/Assign/Orchestrate 三交互模式）· **沙箱隔离**（Workers 在 Notion 托管基础设施运行）

- **信号意义**: Notion 以"**任何数据源+任何工具+任何 agent 全进 Notion**"对标企业协作层——与 Atlassian Teamwork Graph、Jira 开放控制面形成**三方竞争格局**（Notion=内容/知识底座, Atlassian=工作/编排底座, Linear=开发工作流底座）；"progressive trust"与你 08-03 harness 分析"自主性可观察"同构, 治理内建成为平台卖点而非事后补丁 📌

## 2️⃣ 🔴 Long Horizon 工程深潜: 全库首次归档（06-17 发布, 与知识库"五机制"方法论同源同构）

- **来源**: [Long Horizon: How Atlassian Built a Reasoning Engine for Complex AI Tasks](https://www.atlassian.com/blog/how-we-build/rovo-long-horizon-reasoning-engine)（Atlassian How We Build, **2026-06-17**, 工程团队）——08-02 期已归档产品转向（multi-agent routing → 单一推理循环）, 本篇为**架构深潜, 全库 grep 零匹配, 首次归档**
- **🔴 架构五机制（与你知识库记忆"五机制=flattened tools/渐进披露/context compaction 95% 水位/child instances/分层 prompt+前缀缓存"完全互证）**:
  - **Flattened tools（工具扁平化）**: 各产品能力折叠为统一命名空间动作（`jira__search_issues`/`google_calendar__list_events`）, 编排 LLM 直接调用, 看到原始参数/原始响应/原始错误——**消除 subagent 有损转译中介**（你 08-02 期"否定路由式多代理"的工程落地）；失败恢复成为推理循环一部分而非跨阶段信息丢失
  - **Progressive disclosure（渐进披露）**: 每个产品命名空间折叠为两个 meta-tools（`{product}__get_tool_schema` 按需取 schema + `{product}__invoke_tool` 按名执行）+ 每命名空间配 **SKILL.md**（产品业务逻辑/工具选择/多步配方/gotchas, 替代原 subagent prompt 内隐知识）；最常用工具（search/todo/file/entity linking/memory）保持顶层常驻——**按需付费, 不预付全部 schema**
  - **Context Compaction（95% 水位）**: 专用 Compaction Service 在每次模型调用前运行, 接近 token 上限时裁剪/摘要旧工具输出, 近期结果保持全分辨率; 被裁剪输出**不丢弃, 按需读回**（offload）——与你记忆"context compaction（95%水位）"一致
  - **Child instances（子实例分解）**: 宽任务（如"调查 checkout 错误尖峰×支付 bug×设计文档×PR×客户反馈"）分解为 5 条独立研究线, 每条 spawn 一个**完整 Long Horizon 推理循环子实例**（干净上下文+最相关 skill）, 并发运行, **最慢线而非总和决定响应时间**; 父编排只收成品合成——与旧架构 subagent 角色根本不同（旧=路由路径上产品专家, 新=按需 spawn 的完整推理循环）
  - **分层 prompt + 前缀缓存**: prompt 按稳定性分层（static system → stable session context → conversation history → turn-dependent）, 最长稳定前缀字节级不变; OpenAI/Gemini 隐式前缀缓存自动复用, **Anthropic 用显式 cache_control 标记**——多轮迭代只重算最新 token, 成本随迭代数复合节省
- **🔴 量化结果（离线评测+在线 A/B）**: 离线答案质量 **+8.5%**（硬多工具查询集）· Confluence 任务完成 **+23% relative**（find page/retrieve/create/edit）· 在线 Chat Success Rate **+0.83%**（higher-reasoning 配置）· **37% 感知延迟降低**（实时推理轨迹可见）· 端到端 2+ 工具调用查询准确率 **77% vs 71%**（截图截断前数据, 待复核）· 迭代上限 **150 次/查询**, 多数 3-8 次, adaptive reasoning effort 按复杂度自适应
- **产品侧增量（07-28 产品公告, 与 08-02 期交叉印证不重复归档）**: 新架构下 **Claude Opus 4.x class 模型**, 可换最新推理模型; 支持 agentic tool use（Slack 消息→Jira ticket）/长时后台任务/跨产品深度推理; 推理轨迹 UI 可见（降感知延迟）
- **信号意义**: **"五机制"是主流 reasoning engine 的公共设计语言**——你知识库记忆（08-02 提炼自同一产品公告）获得工程级背书; "一个模型迁移替代 N 个子代理迁移" = 架构简化的维护成本收益; 对国产 agent 平台（Rovo 竞品）的**直接参考价值**: flattened tools + SKILL.md 替代 subagent prompt = 你"技能三维查重+SKILL 标准化"的行业同构 📌
