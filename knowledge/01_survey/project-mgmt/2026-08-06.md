## 1️⃣ 🔴 Teamwork Lab 新研究: "The tech we love to hate is the tech we'd hate to lose"（新发布, 08-04）

- **来源**: [The tech we love to hate is the tech we'd hate to lose](https://www.atlassian.com/blog/ai-at-work/the-tech-we-love-to-hate-is-the-tech-wed-hate-to-lose)（Atlassian AI at Work, 2026-08-04, Halina Mader / Teamwork Lab 研究员 Conor Donegan）
- **核心论点**: 知识工作者对社会层面 AI 有真实担忧、对自身工作层面 AI 却高度依赖——**这不是矛盾立场，而是同一批人的两面**。Molly Sands（Teamwork Lab 负责人）: "他们已在工位层面做出决定：AI 赢得了位置"
- **Pulse 调查量化（2026-06-26~07-07, 1,001 名美国知识工作者, 双盲）**: **74%** 认为 AI 正面影响工作 vs **64%** 同时对社会影响有担忧 · **90%** 总体采用率（重度用户 +7 个百分点）· **74%** 对 AI 在工作中的角色持积极情绪
- **工作 vs 个人 AI**: 若必须二选一，愿意放弃个人 AI 的是放弃工作 AI 的 **2 倍**——此偏好跨代际/职级/职能稳定成立
- **矛盾指标**: 仅 **19%** 认为没有 AI 难以维持绩效（**57%** 认为没有 AI 也能做得一样好）——但 **50%** 会抵制雇主削减 AI 工具，近 **10%** 会因此另寻工作
- **深层使用 → 深层认同**: "团队标准"用户（AI 嵌入共享协作工作流）比偶尔用户 **>10×** 更可能认为回归困难；AI 持续产出高质量结果的用户 **3×** 更可能反抗削减
- **🔴 Play/Pause 对照实验（2026-06-09/10, ~123 名 Atlassian 招聘专家, 全程 Loom 记录）**: Pause 日 **82%** 有使用 AI 冲动、**23%** 不假思索去用 · **47%** 觉得任务更难、**46%** 觉得非 AI 技能生疏；Play 日优先工作感觉 **44% 更容易**、压力 **22% 更低**；实验后 **92%** 参与者对"何时不用 AI"更有信心
- **方法论价值**: Pause 日的"渴望"信号既可解读为工具价值、也可解读为依赖——研究者给出区分框架："判断力是可以训练的"，实验本质是**团队级 AI 判断力校准**（提供 Play/Pause Day Play 工具包）
- **信号意义**: 与 07-21 认知寄生/能力萎缩、07-22 能力层级四支柱、08-05 产出经济学（毛利 vs 净利）同主题——**"AI 是否侵蚀能力"的核心不是用量而是判断力**；92% 实验后信心提升 = 用户知识库"AI 精度控制/批评检查"方法论的行业级验证

## 2️⃣ 🔴 Agentic Pipelines 蜂群式维护文档: 让代码变更自动驱动文档更新（新发布, 08-04）

- **来源**: [How We Used Agentic Pipelines to Swarm Documentation](https://www.atlassian.com/blog/development/agentic-pipelines-to-swarm-documentation)（Atlassian Development, 2026-08-04, Arthy Vijayaraghavan 高级工程经理）
- **问题**: Rovo Dev CLI 每次变更都触发"找文档→更新 MD→部署→查生成页→回 PR 补漏"的重复链条——"功能只在代码落地时算完成，文档讲同一故事才算真正发布"
- **方案**: 为 release notes / quickstart / API 文档 / 配置参考 / changelog 各建一个**窄任务 agent**（prompt 存仓库），Bitbucket Pipelines 用 **path-based changeset 条件**只在该路径变更时触发对应 agent，agent 读仓库上下文提出文档更新 PR 供人工审查
- **🔴 元级自动化（bootstrap agent）**: 自动化本身又产生重复工作（每块新文档区要写 prompt/agent 定义/pipeline 配置）→ 再建 bootstrap agent：开发者只描述新文档区，agent 自动生成提案文档+任务 prompt+agent 定义+pipeline 配置，全部以 PR 提交供审查——**"自动化能跟上仓库演进的速度"**
- **量化**: 团队每周省约 **1.5 开发者日**；文档变更与触发它的代码同 PR 到达，审查者可同时看"产品做了什么"与"文档怎么说"
- **三条学习**: ① 任务保持窄（"更新 release notes"优于"维护文档"）② 触发要精确（路径条件避免无关构建耗时）③ **审查是默认动作**（agent 产出有变异性，有用工件=可审查 PR）
- **产品状态**: Agentic Pipelines 在 Bitbucket Cloud **beta**，支持 Rovo Dev / Claude Code / Codex 三种 provider——provider 可换，控制点不变（聚焦 prompt/精确触发/作用域权限/可审查结果）
- **信号意义**: 这是 08-05 Jira Automation orchestration（触发 Copilot/Cursor/Claude）的 **Bitbucket 镜像**——Atlassian 把"事件驱动 agent 编排"同时落到 issue 侧（Jira Automation）与 CI/CD 侧（Bitbucket Pipelines）；与你知识库"约束脚本化=流量成本变存量资产"（08-05 产出经济学）完全同构

## 3️⃣ 🟡 补录: Inside AI Builders Week — 从个人效率到团队级工作流再造（07-22 发布, 此前未归档）

- **来源**: [Inside AI Builders Week: How teams work in the AI era](https://www.atlassian.com/blog/how-we-build/ai-builders-week-how-teams-work)（Atlassian How We Build, 2026-07-22, Tamar Yehoshua 首席产品与 AI 官）— ⚠️ 补录：07-22 发布，查 log.md 无锚点（当期归档了 DX 研究/Jira 6 能力集群，漏此篇）
- **机制**: 每季度 R&D 团队停摆一周专攻 AI 实验（AI Builders Week）；本期从"个人工作流提速"转向"团队端到端重塑工作流"，按业务域分组+高管做战略教练
- **量化**: **1,500** 注册者 · **92%** 对日常用 AI 更自信 · **120+** 新工作流数天内建成 · **95%** 的 PM/设计师准备把新工作流带回团队落地
- **代表性成果**: ① Jira 项目变更监控 agent + Rovo 重估计划、标记与关键目标偏离（计划-执行对齐）② 客户反馈→结构化工作项 agent（自动 PRD+优先级建议+投票数→交 coding agent 出 PR）③ Rovo CLI 反馈 skill（聚合 GitHub/社区/HN 反馈→Jira Product Discovery 写回+社区回信草稿）④ Admin Hub 截图→组件生成器（对照设计系统查可复用模式→生产级组件含代码/规格/编辑器）
- **季度复利观察**: "每个季度 AI Builders Week 的产出复杂度和影响力指数级增长，技能彼此叠加"——与 07-22 AI 变更适配四维模型（数据/流程/系统/组织）中的**组织层杠杆**呼应：变革需要被"设计"出来，而非只是培训
