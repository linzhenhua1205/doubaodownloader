## 1️⃣ 🔴 Rovo Chat 架构转向: multi-agent routing → Long Horizon 单一推理循环（重要架构信号）

| 维度 | 内容 |
|:-----|:------|
| **来源** | [Atlassian AI at Work](https://www.atlassian.com/blog/ai-at-work) — "Meet the new Rovo Chat: One prompt, multiple steps, zero hand-holding" |
| **核心变化** | 新一代 **Long Horizon reasoning engine 取代 multi-agent routing**，以**单一推理循环**替代"每工具一 agent"的路由架构 |

- **旧架构**: 第一代 Rovo Chat 为 multi-agent 路由——Jira/Confluence/Slack 各一个专属 agent，用户 query 被路由到对应 agent
- **新架构**: 单一推理循环 (Long Horizon reasoning engine)，一个 prompt 多步骤自主完成
- **信号意义**: 这是对 **multi-agent 编排范式的内部否定**——路由开销/上下文切换成本 > 收益，回归"单 agent + 强推理"。与 06-29 捕获的 "Agent Drift + Multi-Agent System"（Atlassian 自己主推多 Agent 编排）形成**张力/演进方向之争**，值得持续跟踪哪条路线胜出
- **PM 含义**: 若单一推理循环成为主流，Jira 作为"agent 状态锚点"的编排层价值可能被稀释——需观察 Teamwork Graph 定位是否随之调整

## 2️⃣ 🔴 Teamwork Lab 新研究: AI 使用诚实披露反效果（10× 懒惰偏见）

| 维度 | 内容 |
|:-----|:------|
| **来源** | Atlassian Teamwork Lab (AI at Work) — "New research shows honesty about AI use at work is backfiring" |
| **核心发现** | 披露自己使用 AI 的工人，被同事/管理者判定为**比做完全相同工作的同行懒惰 10 倍 (10× lazier)**——除非公司已建立庆祝 AI 使用的文化 |

- **量化锚点**: 10× 判断偏差（同工不同判）
- **PM 含义**: AI 使用的**社会信号成本**（stigma）成为组织级障碍——比"技能不足"更隐蔽。管理者需要主动建设"AI 使用是加分项"的文化信号，否则工具采用率天花板极低
- 与 07-26 "22% 信任 AI"、07-19 "DX 研究" 同属 **AI 信任鸿沟**证据链，本期增加"披露惩罚"维度

## 3️⃣ 🟡 Teamwork Graph GitHub 连接器 — 代码上下文并入 Rovo

| 维度 | 内容 |
|:-----|:------|
| **来源** | Atlassian AI at Work — "Bring GitHub context into Rovo with the Teamwork Graph connector for GitHub" |
| **要点** | GitHub 上下文（代码变更/评审者/计划关联）接入 Rovo，连接 Jira-GitHub-Confluence-对话 |

- 呼应"bottleneck keeps shifting"（07-31）：**AI 写代码变快后，新瓶颈是理解代码周围的工作**——what changed / why / who reviewed / 与计划如何关联
- Teamwork Graph 作为跨工具上下文层的定位持续强化（07-17 首次捕获 Teamwork Graph）
