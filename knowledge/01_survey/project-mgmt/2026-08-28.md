## 今日主线: AI 原生项目管理的两个范式——Linear「Agent 即执行层」 vs Atlassian「意图层 + Agent 编排」

### Linear（2026-08-26 抓取）

- **Linear ARR 突破 $100M / 全员参与回报**（Karri Saarinen, 2026-08-26）: Linear 跨过 $100M ARR 里程碑，向团队提供新的参与回报机会（tender offer）；项目管理工具在 AI 原生叙事下增长显著。https://linear.app/blog/sharing-growth-with-the-people-building-linear

- **How we built Linear Agent**（Matthijs Wolting, 2026-08-10）: 构建可处理复杂任务又不失可预测性的 AI Agent 的产品/工程决策——核心是让 Agent 在既有 issue/工作流约束内行动，而非自由发挥。https://linear.app/blog/how-we-built-linear-agent

- **Coding Sessions 升级: Agent 交付前自测**（Changelog, 2026-08-19）: Linear Agent 现在可在返回工作前自行 setup/run/test 代码，减少人工交接、交付物完成度更高——"agent 完成度"成为新的 PM 关键指标。https://linear.app/blog/coding-sessions-for-linear-agent

- **Introducing Loops: 描述式自动化**（Nan Yu, 2026-07-20）: 用自然语言描述重复性工作，Linear Agent 按计划或事件触发执行（类似 cron × agent）；重复性流程从"工具配置"变为"一句话描述"。https://linear.app/blog/introducing-loops

- **Teaching an agent to auto-fix bugs**（Igor Sechyn, 2026-06-12）: 部分 bug 在工程师介入前已被 Linear Agent 在 triage 阶段自动修复并提交——AI 从"写代码"延伸到"修 bug"闭环。https://linear.app/blog/linear-agent-bug-fix

- **Code review 提速: Diffs 内嵌评审**（Tuomas Artman, 2026-05-28）: Agent 编码迫使评审变革，Diffs 把代码评审放进 Linear，与产品上下文同处一处；配文 "Reviewing code in the agent era"（2026-06-10）讨论 agent 时代如何守住评审质量门槛。https://linear.app/blog/code-review-should-be-fast

- **Delta sync 读路径重构**（Peter Travers, 2026-08-18）: 用 turbopuffer 让 20TB+ sync 动作的追赶延迟可预测——AI 高频读写场景下同步引擎是工具规模化的底层约束。https://linear.app/blog/rebuilding-delta-sync-read-path

- **StyleX 迁移复盘**（Kenneth Skovhus, 2026-08-26）: 长期迁移成为"工具化 + 自动化 + 为人与 agent 划定清晰边界"的工程练习。https://linear.app/blog/styling-linear-for-the-future-stylex

- **Linear 内部如何使用 Linear Agent**（Rhea Purohit, 2026-04-10）: CX/Product/Engineering 三团队最有效的 agent 工作流盘点，及对"与 agent 协作"的洞察。https://linear.app/blog/how-we-use-linear-agent-at-linear

### Atlassian（2026-08-28 抓取）

- **Introducing Jira Planner**（2026-08）: 定位"团队决策建什么 ↔ agent 如何执行"之间的缺失层；核心论点——**AI 辅助开发的瓶颈不是代码生成而是意图（intent）**：省略范围/架构约束/边界情况，agent 会自己脑补并解决错误问题。https://www.atlassian.com/blog/announcements/introducing-jira-planner

- **Jira 的未来不是追踪工作，而是委托工作**（2026-08）: 作者将 AI agent 能力映射到软件团队职能，演示 Jira 从"记录事实的系统"向"委托 agent 的系统"迁移。https://www.atlassian.com/blog/ai-at-work/the-future-of-jira-isnt-just-tracking-work-its-delegating-it

- **Q4 FY26 股东信**（2026-08-21 前后）: 财年收官，三大战略引擎齐发——企业级、AI 与 system of work，实现持续盈利增长（AI 已成 Atlassian 产品叙事主轴）。https://www.atlassian.com/blog/company-news/shareholder-letter-q4fy26

- **Jira 能力规划/项目预算**（2026-08）: Portfolio for Jira 面向开发经理的 capacity planning——"容量/预算/状态/任务"从散落各处收敛到与工作相连的单一系统，并准备交 AI 执行。https://www.atlassian.com/blog/development/capacity-planning-for-development-managers-portfolio-for-jira

- **Rovo MCP Server GA**（2026-08）: Atlassian Rovo MCP 正式可用，开放远程 MCP server 能力，为外部 agent 生态接入 Jira/Confluence 上下文铺路。https://www.atlassian.com/blog/announcements/atlassian-rovo-mcp-ga

## 观察

- **范式分野清晰**: Linear（纯 AI 原生）把 Agent 当作执行层直接落地代码/修 bug/跑流程；Atlassian（存量巨头）补"意图层"（Jira Planner）+ 编排（Jira Automation 触发 Copilot/Cursor/Claude）两路并进。二者共同信号：**2026 年项目管理工具的竞争焦点已从"追踪工作"转向"定义意图 + 委托 Agent"**。
