## 二、arXiv 新论文精选

### 2.1 Windowed-MTP — 百万Token MTP Draft KV 税消除

> **来源**: arXiv:2607.21535 · cs.LG · Jul 23, 2026

**问题**: 原生 MTP/NEXTN draft head 在长上下文下需要对完整 KV cache 跑 full attention，Draft step 的计算成本随上下文线性增长——百万 token 时 draft 本身成为瓶颈，可能使投机解码净收益为负。

**方案**: 对 draft attention 施加 StreamingLLM 式滑动窗口 + attention sink（仅 draft，target 的 full attention 不变），训练无关、lossless、即插即用。

**性能数据**:
- Draft 的 KV working set：百万 token 下 **~99% KV entries 被丢弃**
- 在 Qwen GDN-MoE 35B/122B / Mamba2-hybrid NoPE 120B 三种架构上验证（SGLang, single GPU @ 1M context）
- **每 decode step 成本降低 +28% 到 +44%**（随上下文增长扩大）
- 回收的未读 draft KV：占总量 **7.7–11%**（通过 compact ring buffer 零开销回收）

**意义**: 解决了原生 MTP 在长上下文场景下的"draft 越深越慢"悖论，使原生 MTP 在百万 token 级别变为实用方案。

### 2.2 InstantInfer — vLLM Cold Start 7.2× 加速

> **来源**: arXiv:2607.18957 · cs.DC · Jul 21, 2026

**问题**: LLM 推理服务的 cold start 因顺序初始化和大量细粒度 I/O 请求而极慢。

**方案**: Communicating Finite Automata (CFA) 抽象——系统化分析跨组件优化机会，将 vLLM 的进程树创建/张量加载/模型切换重构为安全并发执行。

**性能数据**:
- **最高 7.2× cold-start speedup**
- 跨 GPU/工作负载/规模均验证鲁棒性

**意义**: 将 cold start 从"痛苦的顺序初始化"变成可并行的系统问题。对 serverless inference 和 PD 分离中的 prefill node 快速扩缩容有价值。

### 2.3 C²KV — 可组合压缩 KV Cache 复用（SIGKDD 2026）

> **来源**: arXiv:2607.17715 · cs.CL · Jul 20, 2026 · Accepted by ACM SIGKDD 2026

**问题**: 非前缀 KV 复用（position-independent）能显著减少 prefill 计算，但存储和传输 KV cache 的成本成为长上下文新瓶颈。直接组合压缩 + 非前缀复用的 naive 方案会导致严重精度退化。

**方案**: C²KV 框架——学习可组合、可压缩的 KV 流形，通过轻量 sidecar Extractor 生成位置无关的模块化 KV 表示。

**关键设计**:
- 可学习压缩 token + 结构化 attention flow
- 压缩-组合联合训练策略：对齐提取时的表征与下游复用行为
- 基座模型冻结，无需修改

**性能数据**:
- **最高 17× 推理加速**（长上下文场景）
- 显著降低 KV cache 存储与传输成本
- 多长上下文 benchmark + 多模型族验证

### 2.4 HyMCache — CXL-Hybrid Memory KV Cache 框架

> **来源**: arXiv:2607.18141 · cs.DC · Jul 20, 2026

**问题**: 长上下文/多轮/agentic 场景下 KV cache 复用使瓶颈从计算转移到存储层。GPU HBM 和 host DRAM 太贵，无法支撑 TB 级共享上下文。

**方案**: HyMCache —— 基于 CXL-Hybrid Memory（CXL-HM，小容量 device DRAM + 大容量 SSD 后端）的 KV cache 框架。利用多轮 KV cache 访问的读密集、可预测、仅追加特性，重新设计 CXL-HM 内部的 DRAM 管理。

**性能数据**:
| 对比对象 | 配置 | 性能 |
|:---------|:-----|:-----|
| vs local LMCache | 相同 DRAM 预算，single-node | **3.0×** |
| vs local LMCache | PD-disaggregated serving | **1.45×** |
| vs 1TB distributed-DRAM Mooncake | 16× 更少 DRAM | **~30% lower perf** |

**意义**: 在 1/16 的 DRAM 成本下达到 Mooncake 约 70% 性能，对大规模 KV cache 共享的 TCO 有重大影响。实际 CXL-HM 原型验证，非模拟。

### 2.5 FlashRT — Agent Harness 自动推理部署（~70× 加速）

> **来源**: arXiv:2607.18171 · cs.LG · Jul 20, 2026

**问题**: 实时多模态应用（语音 agent、交互式视频生成）需要跨 GPU placement、streaming、intra-model parallelism 等应用特定决策，现有 serving system 和 auto-parallelism 编译器都做不好。

**方案**: FlashRT —— Agent harness，引导 coding agent 将简单的 reference implementation 自动转化为优化后的多 GPU 部署。采用 chain-of-program 范式：参考实现 → IR（捕获数据依赖 + persistent-state scope）→ 验证 → 静态分析 → 迭代 benchmark 优化。

**性能数据**:
| 场景 | 硬件 | 性能 |
|:-----|:-----|:------|
| 视频 world model + 多模态 LLM | NVIDIA B200 | **~70× latency 降低**, **2.8× throughput 提升** |
| 同样应用 | AMD MI355X | **匹配峰值 latency 降低**, **3.6× throughput** |
| Qwen3-Omni text-to-audio | AMD MI355X | **-65% latency** vs expert vLLM-Omni 实现 |

**意义**: 证明 agent 驱动的推理优化在"平台专家优化不成熟"的场景下反而更有效（AMD 例）。挑战 vLLM-Omni 团队精心手调的方案。

### 2.6 moefs — 可构建性感知 MoE 优化器

> **来源**: arXiv:2607.18631 · cs.DC · Jul 20, 2026

**问题**: MoE 系统优化器在可排名的计划空间 vs 实际可构建的计划空间之间存在裂缝——"理论最优"的方案工具链根本发不出来。

**方案**: moefs —— 可构建性（realizability）感知的全空间 MoE 优化器，三层搜索（parallelism/schedule/kernels），从单一计划同时生成 Megatron 训练栈和 SGLang 推理栈。

**性能数据**:
| 场景 | 硬件 | 结果 |
|:-----|:-----|:------|
| 训练 | 2× RTX4090 | **+0.9%** vs 最强手调 baseline（通过 0.98× 接受线 **+2.9%**） |
| Serving | 8× H800 | **1.0304** throughput ratio vs 手调配置 |
| 训练（失败案例） | 8× H800 | 诚实地报告 FAIL（**0.9338** of best hand-tuned） |

**意义**: 诚实报告失败比美化更重要——"所有预测在冻结的 adjudication file 中预注册，每个结果如实报告"。这是可复现性/方法论严谨性的标杆。

### 2.7 Error Certificates for KV-Cache Eviction — 随机化驱逐理论突破

> **来源**: arXiv:2607.21475 · cs.LG · Jul 23, 2026

**问题**: 确定性 KV cache 驱逐（保留 top-k 重要性 token）是不可辨识的——已驱逐的值可以被修改而保留系统完全不变，真实的 attention 输出错误可以任意大。

**方案**: 随机化驱逐恢复可辨识性。Poisson 采样尾部 + Hájek correction（survey sampling 方差估计）→ **0.97 empirical coverage**，零精度代价。

**关键发现（预注册 7 claims，失去 3 个）**:
1. ✅ Question-aware eviction at 25–50% budget 几乎免费
2. ❌ Output log-probability 预测失败优于 certificate
3. ❌ Certificate-gated budget escalation 无收益
4. ✅ **Certificate 可区分 cache 引发 vs 模型固有失败**（AUC **0.73–0.75** vs confidence 的 **0.47–0.54**）

**意义**: 首次为 KV cache 驱逐提供可证明的误差界。对生产环境中"我的 KV 驱逐到底损失了多少精度"给出可操作的答案。

## 三、综合观察

### 架构趋势

1. **vLLM 版本节奏加速**: v0.25.0 (Jul 11) → v0.26.0 (Jul 25)，**两周一个大版本**，DSV4 已进入精细调优阶段

3. **KV Cache 论文高密度爆发**: 本期 arXiv 7 篇新论文覆盖压缩（C²KV/Coded-Gauge）、多轮复用（HyMCache/LMCache-CXL）、驱逐理论（Error Certificates）、长上下文 draft（Windowed-MTP）、系统冷启动（InstantInfer）——密度创近期新高
4. **CXL 作为 KV cache 存储介质进入原型验证阶段**: HyMCache 是首个在真实 CXL-HM 原型上验证的结果，可能是大规模共享 KV cache 的 TCO 突破口
5. **Agent 驱动推理优化**: FlashRT 证明 agent + chain-of-program 可以超越 vLLM-Omni 的手调专家实现（AMD 场景 -65% latency）

### 关注/跟进

- vLLM v0.26.0 的 DSV4 routing kernel + fused_topk_bias 具体实现（#48660, #47463）——是否可提取为通用优化

- Error Certificates 的随机化驱逐——如果 KeyDiff 已经用随机化策略，这块可以直接对接
