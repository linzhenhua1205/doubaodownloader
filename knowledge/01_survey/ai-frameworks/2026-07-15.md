### 1.2 FlashAccel: HBF for LLM Inference（arXiv Jul 11, cs.AR）

> arXiv:2607.10186

**核心贡献**：用 High-Bandwidth Flash (HBF) 替代/补充 HBM，解决 LLM 推理中模型权重和 KV cache 快速增长导致的 HBM 容量瓶颈。

**性能数据**：
| 指标 | FlashAccel (6× HBF stacks) | HBM-only GPU | 提升 |
|:-----|:---------------------------|:-------------|:----:|
| Throughput per GPU | — | 基线 | **2.54×** |
| Energy efficiency | — | 基线 | **1.93×** |
| Latency constraint | 100ms | 100ms | 满足 |

**技术要点**：
- HBF（高带宽 Flash）提供比 HBM 更高容量 + 可比带宽
- 架构上 HBF 集成到 HBM-based GPU，通过专用数据布局缓解延迟
- HBF-aware 存储管理层 + 编程模型协调异构内存资源

### 1.3 重复惩罚 Bug（arXiv Jul 9, vLLM/HuggingFace 生态）

> arXiv:2607.09791

**严重性**：影响整个 LLM 推理生态（HuggingFace、vLLM、llama.cpp 等 12+ engine）

**问题**：
- sign-branched repetition_penalty（正 logit 除 θ，负 logit 乘 θ）依赖 logit 零点位置
- softmax 对 logit 加常数不变 → logit 零点是任意的 → penalty 行为不确定

**性能数据**：
| 场景 | 退化幅度 |
|:-----|:---------|
| Greedy token 改变（θ=1.3） | **58-96%** 的 token 被改变 |
| 结构化 JSON 输出退化（θ=1.3） | 有效从 **97% → 23%** |
| HuggingFace 已提供修复 | LogitNormalization（默认关闭且应用在 penalty 之后） |

**建议**：检查推理栈是否使用了 sign-branched penalty；可考虑切换到 log-probability 归一化版本。

## 二、训练框架

### 2.1 PyTorch 2.13 正式发布（Jul 8）

> Source: pytorch.org/blog/pytorch-2-13-release/ · 3,328 commits from 526 contributors

#### 🔧 CuTeDSL "Native DSL" 后端 for Inductor

- Triton 之外第二条**高性能代码生成路径**（当前仅 GEMM + RMSNorm）
- Keras-风格 Quack-derived kernel overrides → 更高 quality 矩阵乘代码
- 编译从 thread pool 迁移到 subprocess pool → 消除 GIL 瓶颈，**编译并行度提升**
- 发布状态：API Unstable

#### 🔧 nn.LinearCrossEntropyLoss（fused 投影 + 损失）

- 将 final linear projection + cross-entropy 融合为单 module
- **逐 chunk 处理 vocabulary 维度，不物化完整 logits 矩阵**
- 峰值显存：**最高 -4×**（大词汇量 LM 训练）
- 支持 label smoothing、weight tying、z-loss regularization
- 与 torch.compile 兼容，**drop-in 替换** nn.Linear + nn.CrossEntropyLoss

#### 🔧 FlexAttention MPS（Apple Silicon）

- FlexAttention API 在 Metal/MPS 上可用
- 手写 Metal kernel for sparse prefill + decode paths（含 GQA + captured buffers）
- **稀疏 mask 性能**（1×8×32768×64, 0.8% density, sliding window 256）：

| 配置 | FlexAttention MPS | SDPA | Speedup |
|:----|:-----------------|:-----|:-------:|
| 32768/256-window | ~35 ms | ~431 ms | **~12.3×** |
| 8192/64-window | (测量值) | (测量值) | **~4.15×** |

- **Deterministic backward path**（CUDA）：用 pre-computed write ordering 替代原子操作
  - 开销：S=32768 时仅 **+0.2%** → 生产可用

#### 🔧 torchcomms — 新分布式通信后端

- 进化自 c10d ProcessGroup（NCCL 时代设计）+ FSDP2 通信重叠
- 改进：**fault tolerance**（graceful timeout + partial-group recovery）
- 更好 **scalability**：大规模集群可调试性
- 结构化 logging + collective tracing
- API 兼容，可作为 c10d 的**现代替代**

#### 🔧 FSDP2 分离 Reduce-Scatter Group

- `FSDP2.set_separate_reduce_scatter_group(enable=True)`
- all-gather 和 reduce-scatter 使用**独立 NCCL communicator** → 通信可重叠 → **提高训练吞吐**

#### 🔧 其他亮点

| 特性 | 说明 |
|:-----|:------|
| `torch.load("foo.safetensors")` | 原生加载 safetensors，无需额外依赖 |
| Python 3.15 wheel | 含 free-threaded 3.15t 实验性构建 |
| ROCm AOTriton 0.12b | 非对称 head dim、gfx950 FA3 partial、Origami GEMM 选型 |
| Armv9-A torch.compile | Neoverse V2 (Graviton4) 识别 + SVE 指令 |
| XPU 设备遥测 | 内存用量/功耗/时钟/温度 API |
| CUPTI Monitor Profiler | 异步 GPU 性能采集，零扰动 |
| CUDAGraph.get_graph_data() | 程序化暴露 capture 内部图拓扑 |
| Deprecations | Named tensors 移除；Bazel build 移除；collective 重命名 |

### 2.2 Towards Free Normalization（Meta Research, Jul 10）

> Source: pytorch.org/blog/towards-free-normalization/

**动机**：Normalization（LayerNorm/RMSNorm）在 Meta Ads GEM 模型中占 **~20%** 训练延迟，在 LLM 中占 **~10%**，且高度 memory-bound（无法用 TensorCore）。

#### 🔧 Lazy Pre-Norm（Pre-RMSNorm + GEMM 融合）

- **关键洞察**：RMSNorm 中 `(A * rstd) @ B = (A @ B) * rstd`（行级乘法等价）
- 将 pre-norm 的 elementwise 乘法延迟到 GEMM 完成后 → 变成 epilogue fusion
- 平方和累积与 TensorCore matmul **并行执行**
- 隐藏 **90%** normalization 延迟（小 N 场景 17-32% 延迟节省，N=64/128）

#### 🔧 Multi-CTA Norm Fusion（Post-Norm + GEMM 融合）

- 使用 CTA clusters + Distributed Shared Memory (DSMEM) 分区计算 N 维度
- 在 Blackwell 上 N 上限 = 4096（max cluster=8, 每 CTA 512）
- N ≤ 2048 时效果显著（N 到 4096 后 norm <5% 总延迟）

#### 🔧 FlashNormAttention（核心贡献）

- 将 PFFN block 中的 2×LayerNorm + 2×Residual + GDPA 融合为**单 kernel**
- 3 项优化应对内存压力：SMEM/TMEM 复用 + TensorCore Accumulate + 寄存器 subtiling
- **应用调优**：
  - KV 短序列时交换 Q/KV 角色（gridding on KV, looping over Q）
  - 5-warp specialization（load·mma·activation·layernorm·epilogue）
  - TMA_REDUCE_ADD 处理 outer residual（backward）
- **性能**：

| 场景 | Forward | Backward |
|:-----|:--------|:---------|
| **FlashNormAttention** | **up to 35% kernel speedup** | **up to 28% kernel speedup** |
