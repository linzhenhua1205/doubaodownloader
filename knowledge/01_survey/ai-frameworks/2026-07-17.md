## 二、arXiv 新论文精选

### 🥇 Cascade Attention — TRT-LLM 新注意力原语（cs.AR, TRT-LLM rc21）

**位置**：TRT-LLM v1.3.0rc21 release notes, PR #14396

**核心创新**：多级 cascade attention 实现，将标准多头注意力分解为 cascading 计算层级，利用低层级的稀疏结果来加速高层级的注意力计算。

**性能数据**：
- **最高 4.6× 快于标准 MMHA**（multi-head masked attention）
- 适用于需要可变精度的注意力计算场景（如长上下文、分层推理）

**意义**：这是 TRT-LLM 在注意力机制层面的重要进化，与 FlashAttention 系列正交。预期后续版本将深度集成到更多模型和硬件配置中。

### 🥇 AAFLOW+：零拷贝分布式 KV Cache 编排（cs.DC, Jul 12）

> arXiv:2607.10987 · 21 pages, 10 figures, 12 tables

**核心创新**：将 KV Cache 作为一等分布式系统对象，为多 Agent 工作流提供 stateful operator 抽象。提供 KV materialization/transfer/fork/composition/eviction 操作符，runtime 支持零拷贝传输感知执行。

**关键数据**：

| 指标 | 提升幅度 |
|:-----|:--------:|
| TTFT 降低 | **最高 50.2×** |
| 多 Agent 计算成本（16-agent） | **降低 7.63×** |
| KV 内存压缩 | **1.72–6.10×** |
| 吞吐量提升 | **>7.74×** |

**意义**：基于 analytical cost model（硬件微基准标定参数），证实 KV 传输在中高带宽网络上优于重算。多 Agent 系统中以 KV-state 共享替代文本传递，大幅提升效率。

### 🥇 HMA-Serve：跨厂商内存异构解耦推理（cs.AR, Jun 29）

> arXiv:2606.29986 · cs.AR/cs.DC

**核心创新**：在 GDDR 加速器（预填充）和 HBM GPU（解码）之间做跨厂商解耦。解决两个假设断裂：KV 格式不兼容 + 软件栈不共享。

**三大关键技术**：
1. **分阶段量化**：预填充用厂商原生低精度，解码保持 BF16
2. **计算-传输流水线**：每层 KV Cache 传输与后层预填充重叠 → 降低 TTFT
3. **延迟反量化**：传输原始量化字节，在解码 GPU 上 lazily 重构 → 减少网络带宽和 HBM 使用

**性能数据**（Qwen3 4B-32B，三个生产 trace）：

| 指标 | 对比基础 |
|:-----|:--------:|
| goodput | **最高 3.2×** vs state-of-the-art 内存同构方法 |
| goodput-per-dollar | **最高 4.8×** |
| 生成质量损失 | **不可测量**（零损失） |

**意义**：从根本上改变了解耦推理的经济学——用便宜的 GDDR 做预填充，贵的 HBM 做解码。跨厂商设计打开了更多硬件组合可能性。

### 🥇 FlashAccel：高带宽闪存加速 LLM 推理（cs.AR, Jul 11）

> arXiv:2607.10186 · cs.AR

**核心问题**：模型权重和 KV Cache 增长远超 HBM 容量，但 HBM 成本极高。High-Bandwidth Flash (HBF) 提供更大容量 + 相近带宽，但延迟高、利用率低。

**解决方案**：FlashAccel 共设计（architecture + system）将 HBF 集成到 HBM GPU 中：

1. **架构支持**：缓解 HBF 访问延迟
2. **专用数据布局**：针对模型权重和 KV Cache 优化带宽利用率
3. **HBF 感知存储管理层**：协调异构内存资源

**性能数据**（6 HBF stacks）：

| 指标 | 对比 HBM-only GPU |
|:-----|:----------------:|
| Per-GPU throughput | **2.54×**（100ms 延迟约束下） |
| 能效（throughput/W） | **1.93×** |

**意义**：HBF 作为 HBM 的容量扩展方案，在 LLM 推理场景中展现出巨大潜力。6 层 HBF 即可实现 2.5× throughput 提升。

### 🥇 Cache-Resident 执行模型：CPU LLM 推理 11.51×（cs.AR, Jun 23）

> arXiv:2606.25353 · cs.AR

**核心创新**：利用 3D-stacked 缓存技术带来的 GB 级末级缓存，让模型权重驻留在片上级 cache，利用 cache 带宽和低延迟。

**三大设计**：
1. 权重-注意力解耦架构：权重驻留 cache，KV 容量独立扩展
2. 子操作级同步松弛：从 operator 边界同步降级为 true sub-operator 依赖同步
3. 局部性感知放置 + 专用静态运行时

**性能数据**：

| 模型 | 对比基准 | TPOT 加速 |
|:-----|:---------|:---------:|
| Llama-3.2-3B | llama.cpp | **2.04×–11.51×** |
| Llama-2-7B | llama.cpp | 同区间 |
| 广义模型（分析模型） | 已验证分析模型 | **最高 13.9×** |

**意义**：商用 CPU 搭载 GB 级末级缓存即可高效推理 LLM，前提是执行模式围绕 cache 驻留设计。这为数据中心 CPU 节点提供了新的推理加速路径。

### 🥇 TokenWeave：融合 AllReduce-RMSNorm 拓扑优化（MLSys'26）

> arXiv:2505.11329 · Accepted at MLSys 2026 · Microsoft

**核心问题**：Tensor parallelism 在 token 数较小时，通信开销可达 20%+（甚至 NVLink 上）。现有重叠技术在小 token 场景无效。

**解决方案**：
1. 发现 RMSNorm 是被忽视的关键操作
2. 实现**融合 AllReduce-RMSNorm kernel**
3. 利用 **NVSHARP/Multimem** 特性只用 2–8 个 SM（8×H100 DGX）

**性能数据**：

| 场景 | 加速比 |
|:-----|:------:|
| Latency speedup（baseline÷ours） | **最高 1.28×** |
| Throughput（ours÷baseline） | **最高 1.19×** |
| 部分配置 | **优于无通信的理想情况** |

**意义**：TokenWeave 的 fused AllReduce-RMSNorm 是首个在 1024 token 以下有效实现 TP 通信重叠的方案。核心洞察：NVSHARP/Multimem 低 SM 占用通信可以让计算和通信自然重叠。

### 🥇 KV Cache 结构性角色偏差诊断（cs.CL, Jul 14）

> arXiv:2607.13205 · 6 pages, 2 figures, 5 tables

**核心发现**：KV cache eviction 方法（如 H2O）以 attention mass 为排序依据时，**结构性非内容 token（分隔符、空白）** 的能量远高于内容 token。

**关键数据**：

| 现象 | 数据 |
|:-----|:-----|
| KEY 角色 tokens 保留率 vs VALUE | **1.8×** |
| 5% 预算下 exact-match 准确率 | **88% → 0%**（vs full cache） |
| 角色条件分配（role-conditional allocation） | 闭包 **63–98%** 的 H2O 差距（sub-20% budget） |

**诊断结果**：Attention mass 是**非平稳滤波器**——schema-dense 输入（如嵌套 JSON）中 delimiter/whitespace 作为 attention sink 被过度保留。

**解决方案**：15 MB 线性角色探针在推理时标记 token 角色，进行 role-conditional allocation。无需重训。

## 三、系统设计趋势分析

### 推理框架架构演化

| 框架 | 版本 | 核心架构方向 |
|:-----|:-----|:------------|
| **TensorRT-LLM** | v1.3.0rc21 | **TensorRT 后端正式退役**，PyTorch backend 成为唯一后端；DSV4 原生支持；Agentic 自动模型支持 |
| **SGLang** | v0.5.15 | Spec V2 全量默认；DSA 推理深度优化；AMD ROCm 全面覆盖 |
| **vLLM** | v0.25.1 | bugfix 版；PagedAttention 移除后架构稳定期 |

### 跨方向交叉趋势

1. **KV Cache 空间化**：从本地 GPU-only 向分布式一等对象演进（AAFLOW+/PEEK/SAC）
2. **解耦推理跨厂商**：HMA-Serve 打开 GDDR+HBM 混合架构，性价比 4.8×
3. **核融合深化**：AllReduce+RMSNorm（TokenWeave）→ 1.19× throughput，通信与计算深度融合
4. **HBF/HBM 异构**：FlashAccel 证明 HBF 可有效扩展 GPU 推理容量 2.54×
5. **CPU 推理再认识**：Cache-Resident 模型显示 CPU LLC 推理可超 10×，不再是"CPU 不能跑 LLM"
6. **Attention 原语创新**：Cascade Attention 4.6×，是 FlashAttention 系列外的独立创新路径
