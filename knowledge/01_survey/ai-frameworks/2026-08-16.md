## 本期发现 (4条)

### 框架与系统

- **Trie Automata：有限集约束解码的 trie 自动机**（[arXiv:2608.12574](https://arxiv.org/abs/2608.12574)，08-12）: LLM 结构化输出常需从有限字符串集合中选择，通用 grammar 编译在合法值达数千时遭遇 "cardinality wall" 性能墙；trie 自动机利用有限集结构（共享前缀/有界深度/已知基数）配合 Aho-Corasick 多模式匹配预计算每节点 token mask——单步 valid-token 计算比 XGrammar 快 7×（0.65us vs 5.8us）、K≥300 时编译快 2-6.5×；预计算 mask 开启无状态 serving 路径、绕过 guided decoding 流水线，批处理下 vLLM 端到端吞吐 219 req/s vs XGrammar 7.5 req/s（batch 256，29×）；7 个 tokenizer 家族（32K-262K 词表）下 K=10,000 编译仍 <100ms、每步成本与集合规模无关、100% 输出合法性。URL: https://arxiv.org/abs/2608.12574 ⭐

- **TokTier：状态化 CPU+GPU tokenization 服务**（[arXiv:2607.29678](https://arxiv.org/abs/2607.29678)，08-06 v3）: LLM serving 缓存 prompt KV 状态，但前端几乎每次调用都重新 tokenize 全请求——coding agent 会话反复提交长 transcript+小 append，153,951 次调用中位 append 仅 ~1.4K 字符，只有 1.0-3.6% 调用启动/重建会话却携带百万字符级上下文；fleet prompt-cache 命中率 94.1%，接近 0.99 时 tokenization 占 TTFT 比例从 10% 升至 64%；TokTier 会话续接只重 tokenize append 周围小窗口（逐请求检查稳定 pre-tokenization 边界），无复用前缀时用 GPU 跑精确 GPT 家族 regex pre-tokenization+BPE；17 个生产 tokenizer 家族、1.5×10^10 split checks、12.4TB 真实语料、93,000+ agent 步重放零分歧；增量修复 0.5-1.1ms（100K-3M 字符）较 HF 快 437×，GPU tokenize 1M 字符 0.87ms；vLLM 集成下 median TTFT -16-34%、P99 TTFT -23%；50ms P99 目标下四核修复池+1 GPU 支撑 1,821 req/s（16 核无状态前端仅饱和 40 req/s）。URL: https://arxiv.org/abs/2607.29678 ⭐

### 模型支持与生态

- **SnapLGR：TensorRT-LLM 支撑的 Snapchat 生成式检索生产系统**（[arXiv:2607.28895](https://arxiv.org/abs/2607.28895)，07-30）: Snapchat 短视频推荐上线生成式检索系统——语义标识符（SID，多模态 embedding + PPR 协同对比学习）经 CPT+SFT 接地；serving 侧用 TensorRT-LLM CUDA-backed beam search + 去中心化 worker-loop 架构；直播 A/B 相对 TIGER 基线：View Time +0.37%、Time Spent +0.09%、Deep Sessions +0.18%、Deep Sessions 唯一用户 +0.11%。URL: https://arxiv.org/abs/2607.28895

- **PyTorch 2.13.0 发布与 vLLM 生态采纳联动**（[PyTorch Release](https://github.com/pytorch/pytorch/releases/tag/v2.13.0)，07-08 / 采纳 08-10）: PyTorch 2.13.0 于 07-08 正式发布（此前 06-18 v2.12.1 bugfix），08-10 被 vLLM v0.27.0 采纳并连带 torchvision 0.28.0 + Triton 3.7.1（破坏性环境变更，XPU/CPU 后端同步跟进 2.13）——服务引擎与底层框架的版本联动成为生态同步锚点，框架升级节奏约 2 月/大版本、被上层引擎采纳滞后约 1 个月。URL: https://github.com/pytorch/pytorch/releases/tag/v2.13.0

## 核心趋势

1. **推理框架的"正确性层"升级为吞吐杠杆**：Trie Automata（结构化输出 29×）与 TokTier（tokenization 零分歧）同窗口出现——约束解码与 tokenize 从"合规功能"变为"可优化吞吐点"，正确性由预计算 mask / 影子验证器保证（与 08-15 期 AI 生产链正确性验收主线互证）
2. **serving 优化重心从 GPU kernel 上移到前端/预处理**：TokTier 将 tokenizer 解耦为状态化服务（TTFT -16-34%），叠加 08-13 期 vLLM Rust 前端 gRPC 控制面与 preprocessing offload——前端热路径成为新一轮差异化战场，长会话/agent 负载最先受益
3. **TensorRT-LLM 获得罕见的端到端生产案例披露**：SnapLGR 以 TRT-LLM beam search 支撑推荐系统生成式检索上线（A/B 全指标正向），是专有框架在延迟敏感生产场景工程适配价值的实证——开源框架（vLLM/SGLang）主导论文曝光，但闭源栈在推荐/检索类生产负载仍有生态位
