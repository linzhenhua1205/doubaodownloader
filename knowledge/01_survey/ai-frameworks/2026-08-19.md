### KV Cache 系统论文（本期最密集主题，08-16~08-17 集中提交 7 篇）

- **Pallas: Proactive KV Cache Migration Framework for LLM Inference in AI-RAN**（[arXiv:2608.16477](https://arxiv.org/abs/2608.16477)，08-17）: AI-RAN 场景下蜂窝切换会将活跃请求与其 KV cache 分离（用户 attach 到目标 gNB 而 cache 留在源站）。Pallas 在切换前就**主动**把推理状态迁移到预测目标：token 序列拆分为稳定历史前缀 + 演化后缀，目标通过本地 prefill 重建前缀、源站流式传输后缀的 KV 块，切换时两段组装为最新 KV cache。vLLM 原型在 100~500 Mbps 链路、3 个 LLM 上，平均服务中断时间（SIT）较目标侧恢复方案降低 **2.28~89.68x**、平均 token 间延迟（ITL）较源侧转发降低 **16.0~50.0%**。在线调度器基于移动性预测与运行时遥测选择预取窗口。对框架层意义：**KV cache 从"节点内资源"升级为"跨节点可迁移状态"，vLLM 首次成为 AI-RAN 边缘推理的载体**。
- **Beyond Binary Priorities: Multi-Tier SLA Scheduling for LLM Serving**（[arXiv:2608.16336](https://arxiv.org/abs/2608.16336)，08-17）: Llumnix 的优先级模型仅支持两档（high/normal），无法表达生产环境的丰富 SLA 类别。本文在 Vidur 模拟器中实现任意层数优先级：per-tier 指数衰减 headroom、tier 感知派发顺序、完整 Llumnix 迁移流水线。对照 INFaaS/vLLM/Orca/Sarathi-Serve，**4 个优先级层成本效益最优**：prefill 平均加速最高 8.3x、端到端 P99 最高 3.1x、cost-per-latency 改善 46~68%，且 10 层时无尾延迟崩塌，开销集中在 prefill 阶段。
- **KV-Pipe: On the Relation Between KV Sharing and Pipeline Parallel Efficiency**（[arXiv:2608.15943](https://arxiv.org/abs/2608.15943)，08-16）: 跨层 KV sharing 此前只作为推理侧 KV cache 降本手段，本文把它变成**流水线平衡旋钮**：从尾层开始以 tail-first 顺序将选定注意力层转为跨层 KV sharing，迭代重定位当前瓶颈，驱动 FLOPs 不平衡率（FIR）趋近 1。离线执行、仅需流水线分区与逐层 FLOPs 估计，零在线调参。多个 PP 配置下训练 MFU 最高 **+9.2%**、迭代时间最高 **-9.8%**（PP 度数越高收益越大），且同机制在推理侧减少 KV 增长与冗余 KV 投影，长上下文解码吞吐更高——**KV 布局成为训练/推理双端联合优化的系统-架构自由度**。
- **Aborted but Not Forgotten: KV-Cache Retention Breaks Rollback Consistency in Language Agents**（[arXiv:2608.15939](https://arxiv.org/abs/2608.15939)，08-16）: 状态化语言 agent 假设"拒绝的分支从 transcript 清除即可回滚"，但 serving session 保留 KV 状态时，**模型仍可 attend 应用层认为已丢弃的内容**——形式化为 rollback consistency 缺失：完整 abort 必须恢复模型 attend 的状态而不只是 transcript。引入 same-token/different-cache 审计（决策 token 相同、仅缓存前缀新旧不同），7 个开源模型族（3.8B~36B）中**保留 KV 在 63 个审计单元里翻转 25 个受保护效果**，而全部 63 个案例的请求中都不存在攻击者 token；重建缓存关闭所有缺口。在 Hugging Face Transformers 默认缓存复用路径和 LangGraph time-travel 下均可复现，事务局部缓存恢复即可修复（无需全局 flush）。**这是推理框架 KV cache 语义与 agent 应用语义之间的安全边界失守实证**。
- **KV-Rescue: Recovering Reasoning LLM KV Eviction Loss via Stepwise Interleaving**（[arXiv:2608.15797](https://arxiv.org/abs/2608.15797)，08-16) : KV eviction 在激进预算下不仅掉精度，还会引发"失控退化"（runaway degeneration）——模型生成不连贯/重复 token 直到长度上限。作者把损失刻画为**信息缺口**（缺上下文）而非**能力缺口**（模型能力不足）：被 evict 的 7B 与全上下文 1.5B 错误互补，oracle 二选一可恢复 79% 精度差距。KV-Rescue 用轻量全上下文 helper 与主模型交错推理步骤共享轨迹，熵 + 可压缩性在线检测提前终止退化候选。Qwen2.5-Math 7B/72B 五个数学基准、eviction budget B=64 时恢复平均 **87%** 丢失精度，防退化使主模型 token 生成平均 **-43%**。
- **GraniKV: Asymmetric Granularity KV-Cache Paging for Multi-Agent Systems with Long Shared Prefix**（[arXiv:2608.15584](https://arxiv.org/abs/2608.15584)，08-16，首尔大学）: 生产分页引擎对 KV cache 用统一分页粒度，但多 agent 负载的两段需求相反：长共享前缀要连续（HOT 池）、逐请求后缀要细粒度（COLD 池）。GraniKV 双池 + 逐步 dispatcher 按计算/内存/通信 bound 选后端，是首个对生产分页引擎 KV cache 应用非对称粒度的系统。L_p=16K 共享 token 时输出 token 吞吐 Llama-3.1-8B/TP=1 **2.16x**、Qwen-2.5-14B/TP=2 **1.98x**、Qwen-2.5-32B/TP=4 **1.57x**；异构多 agent 负载（不同长度 prompt）下存储层独立贡献 **1.95x**（此时 batch-global cascade 退化到持平）。
- **DeltaLog: Deferred Materialization of Recurrent States for Linear Attention Decoding**（[arXiv:2608.15533](https://arxiv.org/abs/2608.15533)，08-16）: 线性注意力模型解码时每生成一个 token 就物化并写回完整 recurrent state，大状态多头的内存流量成为主要开销。DeltaLog 把状态表示为稠密基态 + 有界紧凑更新日志：多数解码步只追加紧凑因子，周期性 merge 折叠回基态——模型看到的仍是 eager 解码的稠密状态。GDN/KDA/RWKV6 上 recurrent-state 更新 kernel 最高 **1.86x**、写流量最高 **-7.83x**、端到端服务 **1.05~1.20x**。
- **vToken: Token-Level Virtualization for Reclaimable KV Caches**（[arXiv:2608.13263](https://arxiv.org/abs/2608.13263)，08-13，清华/复旦）: PagedAttention 用固定块管理，而新 KV eviction 算法在比块更细的 token 粒度工作，导致块内碎片化、已分配 KV 内存大量不可回收。vToken 是轻量 token 级虚拟化层：token-table 间接引用维持稳定逻辑视图 + 异步重打包实现物理回收，保持 PagedAttention kernel 与 CUDA Graph 兼容。vLLM 实现 + H2O/Random/Scissorhands 评测：单请求保留 KV 块 **-27.2~72.3%**、SLA 约束吞吐最高 **1.37x**、受限 active-KV 预算下最大并发 **2x**，且策略集成足迹从 500+ 行降到 **<50 行**。

### 调度 / 解码 / MoE 系统论文

- **MAPLE: MoE Adaptive Plug-and-play Layer-wise Expert allocation**（[arXiv:2608.15299](https://arxiv.org/abs/2608.15299)，08-15）: 所有 MoE Transformer 各层路由专家数固定，忽略层间冗余异质性。MAPLE 用闭式敏感性引导分配 + 敏感性约束遗传搜索，把路由专家预算异质化重分配，不改权重不重训。**DeepSeek-MoE-16B 仅用 75% 专家就超过 100% 均匀基线**（ARC-E 65.09→71.40、ARC-C 48.49→51.50、BoolQ 80.03→82.38）；SGLang 实现单 GPU 端到端延迟 **-32.2%**、吞吐 **+47.4%**——"更少专家但放对位置"优于"更多专家平均分配"。
- **LOCAL: Enabling Learning On-device Contiguously for Agent LLMs**（[arXiv:2608.15241](https://arxiv.org/abs/2608.15241)，08-15）: 首个单 GPU 连续端上学习运行时：适配器更新会使旧版本缓存 KV 失效，且缓存保留影响训练可用内存——三个子系统（协作调度器/版本感知 KV 管理器/多 agent 模型运行时）共享状态保证一致性。24GB GPU + 7B 模型：前台队列等待 p95 降低 **3.1x**（对比 FIFO）、TTFT p95 **1.55x**（对比不可抢占训练）、发布后首命中 prefill p99 **-25.6%**、跨 agent TTFT p99 **-21.9%**，且紧 KV 预算下后台学习持续推进。
- **P-PAS: Prefill-Pressure Adaptive Scheduling for Long-Context LLM Serving**（[arXiv:2608.15171](https://arxiv.org/abs/2608.15171)，08-15) : vLLM 的 MBT（最大批 token 数）调度预算存在压力依赖效应：低调度压力下大预算降低延迟，高压力下小预算更优，**任何静态 MBT 都无法跨负载最优**。P-PAS 轻量策略按并发 prefill/decode 状态动态调预算，跨模型/负载/GPU 维持低端到端延迟。kernel 级 profiling 显示大 prefill chunk 在低压力下执行效率更高、高压力下小 chunk 减少对活跃解码的干扰。代码开源: https://github.com/TimoSaemann/ppas-vllm
- **Anatomy of a Quantized Agent: VRAM Stability and Forecasting in Code-Synthesis Agentic Workloads**（[arXiv:2608.15117](https://arxiv.org/abs/2608.15117)，08-15）: LangGraph 驱动的 CUDA kernel 合成 agent（AgentK）+ Q4_K_M 量化 + H100 + 4 个 LLM 骨干、1,920 条轨迹的峰值 VRAM 测量。闭式解析模型（加载权重 VRAM + 固定激活开销两个经验常数）在 4 个骨干中 3 个匹配或超越最佳学习基线（test MAPE 2.2~4.4% vs 3.4~6.5%）；所有骨干峰值内存 CV 仅 0.3~9.4%——**高量化、权重主导场景下复杂预测模型无统计意义，简单回归即可**。编译成功率严格按骨干能力分叉（Phi-4-mini 5.7% → Qwen2.5-Coder-14B 62.0%）。
- **TEMPO: Makespan-Aware Expert-Parallel Load Balancing Across Memory- and Compute-Bound Regimes**（[arXiv:2608.13057](https://arxiv.org/abs/2608.13057)，08-13，v2 08-14）: EP MoE 每层在最快 GPU 同步，现有 dispatcher 按 token 数（EPLB/LPLB/UltraEP）或激活专家数（METRO）均衡，但实测两者都不对：**token 数 < ~156~168 时 HBM 权重流主导（成本挂激活副本）、之上 grouped GEMM 把 token 舍入到 128-tile M 块（拆分专家反而加 pad 计算）**。max-affine profile t=max(a+bG, c+βN) 双 regime 建模，per-batch 派发形式化为固定费用 makespan 问题（双 GPU 全复制时 NP-hard）。SGLang 集成（进程外 + 派发与计数收集融合单 kernel），8-GPU Testbed A 微基准处处在最优固定基线 1% 内、混合 regime 最多 **+15.5%**；Qwen3-235B 端到端吞吐 +4~6%、p99 延迟 -15.6%；DeepSeek-V3（通信主导，win region 外）仅机制成本——**相位图而非普适胜利才是其主张**。
- **Trie Automata for Constrained Decoding over Large Finite Sets**（[arXiv:2608.12574](https://arxiv.org/abs/2608.12574)，08-12）: 有限集合选择（数千合法字符串）是结构化输出常见约束，通用语法编译在集合变大时撞上"基数墙"。trie 自动机利用有限集结构（共享前缀/有界深度/已知基数）+ Aho-Corasick 多模式匹配预计算逐节点 token mask：每步合法 token 计算 0.65us vs XGrammar 5.8us（**7x**），K≥300 时编译快 2~6.5x；预计算 mask 使无状态 serving 路径绕过 guided decoding 流水线，**vLLM 端到端吞吐 219 req/s vs 7.5 req/s（29x）**（batch 256），7 个 tokenizer 族（32K~262K 词表）K=10,000 时编译 <100ms、单步成本与集合大小无关，100% 输出合法性。

### 压缩 / 存储介质论文

- **KV Cache Compression Through the Lens of Transform Coding**（[arXiv:2608.14191](https://arxiv.org/abs/2608.14191)，08-14）: 现有 KV 量化最小化 cache 本身的重建误差，忽略误差经注意力传播。本文证明白噪声量化模型下**期望 attention-aware 失真可分解为跨 token/通道因式分解的键值可加贡献**，并用变换编码 + 逆注水（reverse water-filling）分配比特。Attention-Aware Transform Coding（AATC）在 Llama-3.1-8B-Instruct 与 Qwen-2.5-7B-Instruct 上（LongBench/RULER/GSM8K/MMLU-Pro/MATH-500）实现 **~5.8x 压缩近无损**，各基线在部分设置均劣化——信号处理经典工具进入 KV 压缩的第一性原理级改造。
- **Beyond Capacity: Scalable MoE LLM Inference via High-Bandwidth Flash**（[arXiv:2608.14333](https://arxiv.org/abs/2608.14333)，08-14，KAIST）: **（已由 tech 组收录）** HBF 双通道专家投递，1.94x 吞吐 / 1.90x 端到端加速。交叉引用，不展开。
- **Potential Applications of HBF in LLM Serving Systems**（[arXiv:2608.13127](https://arxiv.org/abs/2608.13127)，08-13，v2 08-14，三星/KAIST 系）: 与 2608.14333 互为姊妹视角——不追求绕过 HBM 的直接路径，而是把 HBF 作为容量向扩展加入 GPU 存储层级：保持 HBM 驻留执行路径，用 HBF 扩大只读模型状态驻留集。MoE 服务可容纳更多专家副本、多模型服务减少模型加载并支持热副本复制。模拟显示收益依赖"HBM 执行路径不被打断"前提——**HBF 的两条路线（直接路径 vs HBM 中继）之争本质是存储层级设计的取舍**。

## 📊 深度分析（本组视角，3+ 段）

### 分析一：KV cache 治理范式转移——从"压缩省内存"到"生命周期管理"，四条技术路线殊途同归

本期 7 篇 KV cache 系统论文（08-16~08-17 集中提交）表面各异，实质回答了同一个第一性问题：**KV cache 到底是什么性质的资源？** 过去五年答案一直是"可压缩的静态内存占用"（量化/驱逐/稀疏），本期论文集体转向"**有生命周期的动态资产**"。vToken 把它虚拟化成"逻辑 token 活性与物理块放置解耦"——驱逐算法在 token 粒度做决策、物理层在块粒度管理，中间的错配由间接层吸收，收益是 27~72% 的块回收与 2x 并发；GraniKV 则承认"共享前缀要连续、请求后缀要细粒度"是**结构性矛盾**，用非对称双池解决——这是对"统一分页粒度"假设的正面否定；Pallas 把 KV 变成**可跨节点迁移的状态**（AI-RAN 切换场景），预告了"KV 是服务连续性资产"的部署面扩张；KV-Rescue 则从损失结构上证明 eviction 的伤害是"信息缺口"而非"能力缺口"——即 KV 丢失的信息**可被廉价补回**（1.5B helper 恢复 87%）。四条路线共同指向：**KV cache 的价值密度在上升，治理粒度在下沉（块→token→层→跨节点），"省内存"正在让位于"按语义价值管理内存"**。对超节点/万卡集群的工程含义：KV 管理将从"引擎内部实现细节"升级为"跨节点调度协议"（类似 RPC 之于微服务），KV 迁移/分层/回收将成为集群级资源管理的一等公民——Pallas 的预取式迁移与 08-13 期 Mooncake/KV connector 生态是同一趋势的两端。

### 分析二：发布节奏与模型生态耦合——Kimi K3 全栈落地的"两周窗口"，及 TRT-LLM 的历史性转身

将三框架 release 时间线对齐模型发布，可见清晰的耦合模式：**Kimi K3 发布后两周内，vLLM v0.27.0（08-10）与 TRT-LLM v1.3.0rc24（08-12）同时完成全栈落地**——vLLM 侧是模型文件/内核/Python+Rust 前端/AttnRes/DeepGEMM/compressed-tensors/DSpark AR fusion 全套，TRT-LLM 侧是 KDA kernels/优化 MoE/parser/投机解码/disagg serving。这种"双引擎同步跟进旗舰模型"的节奏已成为国产头部模型（DeepSeek-V4、Kimi K3、Qwen3.5）的标配——**模型发布→框架适配的窗口已从数月压缩到两周量级**，对下游用户意味着：旗舰模型的可服务性几乎与发布同步，但这也把框架升级压力推给基础设施团队（每两周一个 v0.27 级大版本，需持续跟进）。TRT-LLM 侧更重要的是**历史性转身**：rc21 声明弃用 AutoDeploy、rc20 明示"最后一个支持 TensorRT backend 的版本"、到 rc24 全面清除 legacy 代码——TensorRT-LLM 已从"图优化编译引擎"彻底变为"PyTorch 运行时 + 内核库"，与 vLLM 的架构趋同（runner + kernel backend + CUDA graph）。两个开源框架（vLLM/SGLang）+ 一个商业闭源引擎（TRT-LLM）**在"PyTorch 运行时 + 高性能内核集合"的架构范式上完成收敛**，差异化竞争转移到内核深度（FA4/稀疏 MLA/DeepGEMM）与生态集成（Rust frontend/模型库/量化格式）。

### 分析三：推理框架成为"语义正确性"的新边界——KV 状态泄漏、混合 dtype 污染与 kernel 分歧的同一根因

本期三件看似无关的事件指向同一结构性事实：**当 KV cache 成为跨请求/跨函数/跨内核的持久状态时，框架层成为 agent 与应用语义正确性的新攻击面与失守点**。① 2608.15939 证明"逻辑回滚 ≠ 状态回滚"——serving session 保留的 KV 让模型 attend 已"删除"的内容，25/63 审计单元被翻转，LangGraph time-travel 和 HF Transformers 默认缓存路径都中招；这是**框架缓存语义与 agent 事务语义的契约缺口**，且攻击者 token 可完全不出现在请求中（纯粹的缓存污染）。② vLLM v0.25.1 的 mixed-dtype 修复说明同一类问题也在数值层出现——BF16 残差流 + FP32 RMSNorm 权重在融合图里被错误匹配，产出 `!!!!!` 垃圾；③ 昨日收录的 Integer Alibi（2608.13756）证明同接口互换 kernel 输出不可 bit 对齐。三者共性：**框架的"状态复用/内核复用"优化假设了可替换性，但正确性验证仍停留在端到端黑盒**——2608.15939 给出的"same-token/different-cache 审计"、Integer Alibi 给出的"预注册逐层预测 + 探针恢复"、vLLM 的 dtype 匹配保护，都是把正确性验证从"结果对不对"推向"状态/路径的哪一环引入偏差"的分层方法。对 agent 平台与推理平台的架构含义：**KV cache 生命周期（何时刷新/何时隔离/何时重建）必须成为应用可见的 API 契约**，否则上层 agent 的"回滚/重试/沙箱"语义都是不可靠的——这与 08-17 期"AI 生产链正确性由预计算保证"主线完全同构。

### 分析四：调度语义从"静态配置"到"负载感知动态策略"——MBT/优先级/EP 三条线的收敛

本期调度论文在三个层面把"静态配置"推翻：P-PAS 证明 vLLM 的 MBT 存在压力依赖效应，**任何固定值都非最优**（低压力大预算、高压力小预算），策略应随 prefill/decode 并发状态在线调整；Multi-Tier SLA 证明两档优先级不够表达生产 SLA 谱系，**4 层是最优成本效益点**（8.3x prefill / 3.1x P99 / 46~68% cost-latency）；TEMPO 更根本——EP 均衡的"均衡对象"本身是错的：token 计数在 <156~168 token 时被 HBM 权重流主导、之上被 128-tile M 块舍入主导，必须用 max-affine 双 regime 模型，且**胜负有相位图**（Qwen3-235B 赢 4~6%、DeepSeek-V3 仅机制成本）。三者的方法论共性：**用"执行成本的真实结构"替代"代理指标"**——调度器不再优化 token 数/优先级档位这类可观测但失真的代理量，而是建模"压力→最优预算""成本→regime""tier→SLA 谱系"的映射关系。这与 08-12 期 AIConfigurator（NVIDIA，30 秒配置搜索）的方向一致：**推理系统的"配置"正在从人工经验走向自动化的成本模型驱动决策**。对框架选型的含义：评估调度器时"在 benchmark 上赢"不如"预测何时会赢"——TEMPO 的相位图主张（先预测后部署）应成为调度类方案评估的默认标准。
