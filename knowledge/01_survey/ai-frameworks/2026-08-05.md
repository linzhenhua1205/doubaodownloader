## 一、推理服务与 KV Cache 管理（3篇）

- **RestoreKV — 激进查询无关 KV 驱逐下的全缓存行为恢复**（[arXiv:2608.01247](https://arxiv.org/abs/2608.01247)，08-02）
  - 洞察：驱逐损失的信息是上下文特定的，但**生成其紧凑补全的机制可跨上下文共享**——prefill 后少数 restore token 以单次 LoRA 适配 pass 关注全量 KV cache，生成上下文条件的 restore cache；基础重要性打分器与驱逐规则不变，后续查询/解码期适配器禁用
  - 量化：仅优化 **0.4% 参数**、免任务调优；Qwen3-4B 上 5 种基础驱逐方法 **59/60 配对设置提升**；5% budget 下 KVzip 从 **38.2 → 73.2**（RULER-4K）；KVzip+ 在 KVPress Benchmark **16× 压缩达 86.4**，32K 上下文一次性 cache 构建开销 <0.5%
  - 意义：与选择式驱逐（保留哪些 KV）互补，开辟"学习式恢复"（补全丢失信息）新轴——驱逐研究的第三范式

- **Sparse Attention Selectivity — 长上下文稀疏注意力的反事实审计**（[arXiv:2608.01676](https://arxiv.org/abs/2608.01676)，08-03）
  - 洞察：稀疏注意力（BSFA 路由重放/受控 block-top-k/KV 驱逐三独立验证）会**改变特定内容对输出的影响力**，且聚合精度无法检测——压缩率 c=0.25→0.75 全扫中 3/4 模型-任务对向更强稀疏放大移动，2 个出现符号反转
  - 量化：BSFA route replay 4 架构 16 cells 中 **13 处输出决策改变**（零身份重放标签翻转）；信号集中 G≈P≫B，隔离 probe block 使影响力从 4.48 logits 坍缩至零
  - 意义：首个"丢弃块如何改变内容影响力"的因果审计框架，可部署于任何暴露 block 身份的模型——为稀疏 KV 选择提供正确性度量新工具

- **PRECOG — SSM 边缘模型的 O(1) 状态注入（对比 Transformer KV 不可行性）**（[arXiv:2608.02560](https://arxiv.org/abs/2608.02560)，08-03）
  - 洞察：RAG prefill 成本 ∝ 检索上下文长度；SSM 固定大小、位置无关的循环隐藏状态是"已读内容的完整摘要"→ **离线预编码文档为 SSM 隐藏状态，查询时直接注入最佳匹配状态**，绕过上下文重新摄入（Transformer KV cache 位置纠缠+线性增长，架构上不可能）
  - 量化：TENNs-LLM（1.2B gated-SSM，192KB 隐藏状态）上 PRECOG 匹配 in-context RAG 答案质量，prefill 延迟 **~27s → <6ms（~4500×）**，跨过"不可用→可交互"阈值；SMC 分层持久记忆 O(1) 会话初始化
  - 意义：SSM 隐藏状态作为"可注入记忆"是 Transformer KV 之外的新复用范式——对边缘 LLM 推理架构有方向性启示

## 二、投机解码与混合架构（2篇）

- **Bole — 混合注意力模型的树投机解码（集成 SGLang）**（[arXiv:2608.01651](https://arxiv.org/abs/2608.01651)，08-03）⭐
  - 洞察：现有树投机系统围绕全注意力模型的 KV cache 设计，在混合模型（全注意力+循环线性注意力）上逐分支遍历循环层、为每个提案节点物化完整状态 → 验证延迟与临时内存随树/批大小恶化；Bole 将**线性注意力递归变换为树结构闭式解**，损失无损编码投机状态更新为 token 级因子，仅重构采样后选中的状态
  - 量化：线性注意力树验证加速 **3.4–7.7×**；临时状态内存降 **82–99×**（释放 GPU 容量给 KV cache）；离线 decode 吞吐最高 **4.72×**（自回归）、**2.03×**（最强树投机基线）；在线 agent 负载 TTFT/TPOT 最高降 **67.6%/49.9%**；4 模型×2 GPU 平台验证
  - 意义：混合架构（Hybrid-Attention）成为投机解码新战场，SGLang 再次作为生产集成载体；state 而非 KV 是混合模型的内存瓶颈

- **DART — Mamba-2 上的解码注意力（SSD 状态即压缩 KV）**（[arXiv:2608.02032](https://arxiv.org/abs/2608.02032)，08-03）
  - 洞察：从 Mamba-2 SSD 视角——SSM 状态可解读为压缩的关联 KV cache；观察 Mamba-2 从状态解码 token 条件值但不解码 token 条件键 → **保留 chunked scan 的 chunk 状态作为记忆，解码 token 条件 K/V 做状态记忆注意力（SMA）**，与原生输出门控残差结合；复用 Mamba-2 chunked scan + FlashAttention 风格 SMA，可实际训练
  - 量化：相比匹配注意力基线，长度相关推理 cache **省 75%**（chunk S=256、state N=128）；相比 Mamba-2，关联回忆与检索显著提升，通用 LM 质量保持
  - 意义：共享记忆表征同时支持循环压缩与注意力检索——混合架构的"状态即 KV"统一视角，推理内存与回忆能力兼得

## 三、训练-推理协同与 Agent 工作负载（2篇）

- **Tevatron 3.0 — Megatron-Core 后端的 MoE Reranker 训练（学术预算）**（[arXiv:2608.00916](https://arxiv.org/abs/2608.00916)，08-02）
  - 洞察：Tevatron 3.0 将 Megatron-Core 训练后端集成进 Tevatron，保留数据管线/评估/HF 兼容 checkpoint；专家并行使 **30B Qwen3-30B-A3B MoE reranker 训练可行**（PyTorch FSDP1 不可行）；对比 MoE vs dense、LoRA vs 全参、蒸馏 vs 对比训练
  - 量化：单节点推荐配置下比 FSDP **快 22%**；MoE reranker 匹配 dense 8B 质量但激活参数少一半、推理吞吐显著更高（HF 与 vLLM serving 均报告）
  - 意义：MoE reranker 训练基础设施下沉到学术预算，vLLM serving 再次作为标准化吞吐基准

- **Agentic Coding in the Wild — GitHub Copilot 生产规模 Agent 负载特征**（[arXiv:2608.00101](https://arxiv.org/abs/2608.00101)，07-30）⭐
  - 洞察：首个生产级 agentic coding 负载特征（3.2M 用户/13M 会话/761M LLM 调用/95T tokens）——用户回合稀疏，每回合展开为"LLM 调用几乎总是伴随工具执行"的自主 agent 循环；**KV cache 命中率 turn 内平均 90%，跨 turn 边界跌至 55%**，模型切换/上下文压缩后急剧失效
  - 量化：轻量 idle-time 预测器捕获 **86–90%** 总空闲时间，支持主动资源编排；token 消耗/时间跨度/工具调用长尾且高度可变
  - 意义：agentic 负载挑战现有 serving 假设——turn 内高 KV 复用 vs 跨 turn 失效的结构化不匹配，为 agent-native 基础设施提供经验基础（与 07-28 归档 Self-Speculating Agent 形成负载-优化闭环）

## 四、综合观察

1. **08 月首发论文窗口开启**：08-01~08-03 出现 7 篇新提交（上周末空窗后恢复），覆盖 KV 恢复/稀疏审计/SSM 注入/混合架构投机/Agent 负载——主题延续 7 月主线（KV 管理与混合架构）但新增"学习式恢复"与"SSM 状态注入"两个新方向。
2. **KV 驱逐研究进入第三范式**：选择式（保留哪些）→ 压缩式（低秩）→ **恢复式（RestoreKV 补全丢失信息）**；稀疏审计（Selectivity）同时提供因果正确性度量，驱逐研究的评价体系从"精度"扩展到"内容影响力保真"。
3. **混合架构（Hybrid-Attention）成为投机解码新战场**：Bole 证明状态（非 KV）是混合模型内存瓶颈，闭式解树投机 + SGLang 集成是当前最优解；DART 从 SSD 视角统一"状态即 KV"，为混合模型推理内存优化提供理论基。
4. **SSM 边缘推理的"可注入记忆"范式**：PRECOG 以 4500× prefill 加速证明 SSM 隐藏状态可作离线预编码记忆，架构上否定 Transformer KV 的等价能力——对边缘 LLM 与 RAG serving 架构有方向性启示。
5. **Agent 工作负载正式进入 serving 特征研究**：Copilot 生产数据给出 KV 命中率"turn 内 90% vs 跨 turn 55%"的结构化不匹配，为 agent-native 基础设施（前缀缓存策略/空闲预测/资源编排）提供量化依据。
