### 1.1 HiKV — 算法-硬件协同设计的层级重要性 KV Cache (TCAS-I)

> **来源**: arXiv:2607.22389 · cs.AR · Jul 24, 2026 · To appear in IEEE TCAS-I

**问题**: 长上下文 LLM 解码时 KV cache 持续增长，已知重要性感知方案仅在 token 级做驱逐，忽略了 token 内部 channel 级的冗余。

**方案**: 二级层级重要性压缩——Stage I 在固定预算下驱逐不重要 token；Stage II 对每个保留 token 只加载重要 channel 分量。硬件侧：可重构重要性排序器，一个电路统一两阶段排序数据路径。

**性能数据**:
- **最高 7.95× 推理加速** + **90% 能量节省** over 完整 KV cache baseline（注意力计算）
- 精度损失 < **1%**
- 在等精度约束下，额外减少 **1.82–4.87× 外部存储访问** vs SOTA 重要性方案
- 专用硬件增加仅 **8%** 系统面积

**意义**: 是首个 token+channel 双粒度 KV cache 压缩 + 专用加速器联合设计的工作。与纯算法方案不同，它在专用硬件上证明了几乎所有注意力计算可被消除而精度几乎无损。

### 1.2 AgentKVShift — Agentic Memory 系统的 KV 残差校正

> **来源**: arXiv:2607.21604 · cs.AI · Submitted May 15, 2026

**问题**: Agentic memory 系统中每次检索都会触发结构化 memory unit 的完整 re-encoding，预填充延迟占主导。现有训练无关 KV 复用方法是针对 RAG 原始段落设计的，在结构化 agentic memory 上退化严重。

**方案**: Probe-guided KV residual correction。关键发现：per-memory KV 复用残差可分解为共享的 memory 级偏移 + 小 token 级波动。从一个 probe 集合估计该偏移后，用单权重校正修正所有复用 token——既校正不重算的 token，也将重算预算变为有效信号。

**性能数据**:
| 指标 | 数值 |
|:-----|:-----|
| 刷新比例 | 仅需 **10–30% cache** 达到近全重算性能 |
| 对比基线（同比例重算） | 基线需要 **45-55%** 才达到相同效果 |
| Prefill speedup (A100) | **2–3.5×** over 无复用 baseline |
| 与 KV quantization 正交组合 | 2-4bit 设置下 F1 是先前复用方法的 **2×+** |
| 跨模型验证 | 4 个开源 LLM, 3B–32B |

**意义**: 首次解决 agentic memory 结构化 KV 复用问题。残差分解（memory-level offset + token-level fluctuation）是原创洞见，且与量化正交叠加。

### 1.3 DAF — 解耦注意力融合加速 RAG KV 复用 (EuroSys 2026)

> **来源**: arXiv:2607.21599 · cs.PF · Submitted May 3, 2026 · Accepted by EuroSys 2026 (poster)

**问题**: RAG 长上下文场景下 TTFT 高。复用预计算文档 KV cache 存在分布不匹配问题——离线 cache 缺少文档间注意力模式。

**方案**: Decoupled Attention Fusion (DAF) — 三步解耦：重要 token self-attention（恢复文档间注意力）→ question-document self-attention（标准推理）→ state fusion（拼接输出）。三层均为 dense 模式，原生兼容 FlashAttention kernel。

**性能数据**:
- **2× speedup** over CacheBlend
- **5.6× speedup** over 完整重算（使用 vLLM）
- 长上下文 benchmark 精度无损

**意义**: 无需复杂 attention mask，dense 模式兼容 FlashAttention，工程化友好。

### 1.4 TileSight — 第一性原理 Tile 中心 GPU 性能模型

> **来源**: arXiv:2607.22432 · cs.DC · Jul 24, 2026

**问题**: Triton/TileLang/CUDA Tile 使 tile 成为头等编程原语，但性能分析工具仍依赖粗粒度 roofline bounds 或黑箱 ML 预测器。

**方案**: TileSight — 将 tile 从编程原语提升为分析原语。三层统一 tile 抽象：
- **intra-tile**: compute-memory pipeline overlap
- **inter-tile**: 依赖调度 + tile reuse distance 推断多级缓存命中率
- **cross-device**: 远程张量访问通过 alpha-beta stage 模型路由

**性能数据**:
| 场景 | 硬件 | 误差 |
|:-----|:-----|:-----|
| Single-GPU kernel latency | A100/H200/B200/B6000 | **12.35% pooled MAPE**（优于 SOTA） |
| L2 cache hit rate | 各 GPU | **~±1 p.p.** |
| Fused distributed kernels (≤32 GPUs) | — | **16.18% wMAPE** |
| **E2E vLLM serving** (≤32 GPUs) | — | **13.52% wMAPE** |

**意义**: 首个将 tile 作为跨层统一抽象的分析工具，精度超越 SOTA baseline 且跨架构迁移性更好。将开源。

### 1.5 ZCube — 少路径反而更好的推理网络拓扑

> **来源**: arXiv:2607.21893 · cs.NI · Jul 23, 2026

**问题**: 数据中心网络遵循多路径信条，但 LLM 结构化流量（AllReduce + KV cache 传输）下，多路径静态 ECMP hashing 有不可控的负载不均衡。

**方案**: ZCube — 移除 Spine 层，消除路径多样性，削减 ⅓ 交换硬件，但 LLM 训练和推理性能反而更好。作者建立与 Braess 悖论的结构性联系。

**性能数据**（GLM-5.1 coding inference 生产集群测量）:
| 指标 | 改善 |
|:-----|:-----|
| 网络成本 | **-33%** |
| GPU 吞吐量 | **+15%** |
| P99 TTFT | **-40.6%** |

**理论保证**:
- ZCube 对 Braess 悖论免疫
- 正交双分区对任意流量矩阵提供可证明的负载均衡
- 代价：微秒级 hash 恢复换毫秒级控制面恢复

**意义**: 挑战"多路径 = 好"的设计教条。对推理集群的胖树/Spine-Leaf 设计有根本性启示。

### 1.6 HijackKV — KV Cache 劫持攻击 (USENIX Security 2026)

> **来源**: arXiv:2607.19957 · cs.CR · Jul 22, 2026 · Accepted by USENIX Security 2026

**问题**: 位置无关 KV 复用（任意位置匹配相同文本块即复用）引入安全威胁——匹配 token chunk 的 KV cache 编码了原始计算时的上下文，攻击者可通过精心构造的前缀污染 benign KV cache。

**方案**: HIJACKKV — 首个系统性攻击框架。

**关键设计**:
- 优化 attacker-controlled prefix，使后续 benign text 的 KV 编码 attacker 目标
- 文本内容不变，仅 KV 内部编码被污染
- 攻击成功后在受害者查询中沉默劫持模型行为——无需输入中包含攻击文本

**性能数据**:
| 场景 | 成功率 |
|:-----|:--------|
| Single attempt | **94%** |
| 低命中率 (10%) + 频繁重算 (50%) | 仍然有效 |
| 多轮交互 | 持续有效 |
| 跨模型 black-box 转移 | 有效 |

**意义**: KV cache 复用的安全风险首次被系统揭示。与 PD 分离/prefix caching 等核心优化直接相关——推广这些优化时必须考虑攻击面。

### 1.7 HeadCast — 注意力头分类加速自回归视频生成

> **来源**: arXiv:2607.20125 · cs.CV · Jul 22, 2026

**问题**: AR 视频扩散模型中，连续增长的 KV cache 使注意力成为主导推理成本，高分辨率下每帧贡献大量 token。暴力驱逐导致帧间闪烁。

**方案**: HeadCast — 训练无关。warm-up 后在最噪步骤一次性将每头分类为 4 种原型（Sink/Dummy/Spatial/Global），将 monolithic KV cache 重组为 head 专属通路。保留 Global heads 确保长时间一致性。

**性能数据**:
| 分辨率 | 加速比 | VBench 质量 |
|:-------|:-------|:------------|
| 720P | **1.62×** | 与 full attention 持平 |
| 1080P | **1.95×** | 基本无闪烁 |

**意义**: Head 粒度分治（4 种 archetype）的细粒度方案比粗粒度驱逐更适用于 AR 视频生成。Global 头保留是关键——解释了为何暴力驱逐在视频场景失效。

### 1.8 Pulsar Attention — 内容感知上下文摘要的分布式注意力 (3.3× FLOP 降)

> **来源**: arXiv:2607.20457 · cs.CL · Submitted May 14, 2026

**问题**: 分布式长序列推理（Star Attention）依赖静态、内容不可知的第一个 block 副本，精度受限。

**方案**: 用两个轻量级内容感知组件替换静态 anchor：(1) 稳定 softmax 的 attention-sink prefix (2) 基于 Max-IDF 启发式的紧凑跨 block 摘要。

**性能数据**:
| 指标 | 数值 |
|:-----|:-----|
| Phase 1 per-GPU FLOPs | **3.3× reduction** over Star Attention |
| KV cache footprint | 与 Star Attention 相同 |
| RULER + BABILong (Llama-3.1-8B, ≤128K) | **优于 Star Attention + dense attention** |
| 绝对增益 vs dense baseline | **最高 +4.7%** |

**意义**: 内容感知比静态 anchor 更强——在减少 3.3× 计算的同时反而提升精度，证明了分布式长序列推理中"见什么文档再决定摘要"的价值。

## 二、综合观察

### 本期趋势信号

1. **KV Cache 安全首次被正视**: HijackKV (USENIX Security 2026) 系统性揭示位置无关 KV 复用的攻击面——94% 单次成功。这对 PD 分离/prefix caching 等核心优化有直接影响，预计会催生新的安全设计约束。
2. **Agentic Memory 成为 KV 复用新场景**: AgentKVShift 区别于传统 RAG，结构化 memory unit 的 KV 残差可分解为级偏移 + token 波动，这是新的复用范式。
3. **硬件-算法协同设计重新活跃**: HiKV (TCAS-I) 证明 token+channel 双级压缩配合可重构排序器可达 7.95× 加速 + 90% 省能。这对未来推理加速器设计有参考。
4. **网络拓扑设计教条被挑战**: ZCube 的生产级测量（-33% 网络成本，-40.6% P99 TTFT）挑战了"多路径=好"的共识。推理工作负载的结构化流量特征使"少路径"更好。
5. **Perf 模型精度达到实用水平**: TileSight 在 ≤32 GPU 的 E2E vLLM serving 上达到 13.52% wMAPE，且跨 A100/H200/B200/B6000 迁移良好。这类工具可减少手动调优、辅助自动 tile 配置。

### 关注/跟进

- HijackKV 攻击面的缓解方案——现有部署是否需要做安全审查？
- ZCube 在生产集群的实际可行性——是否存在其他约束（如故障隔离）？
- HiKV 的两阶段压缩思路是否可在纯软件层（无专用加速器）复现等价收益？
- AgentKVShift 与 vLLM/LMCache 等的集成可能
