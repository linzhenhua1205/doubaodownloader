## 1. KV 压缩：VarRate 训练无关变速率低秩编码

> **来源**: arXiv 2607.15498 · 2026-07-16 | **模型**: Llama-3.1-8B, Qwen2.5-7B | **基准**: LongBench (16 任务)

### 问题

两类主流训练无关 KV 压缩方法各有结构性缺陷：

| 方法族 | 问题 |
|:-------|:-----|
| **Token 选择** (SnapKV/Ada-KV) | 观测窗口打分→evict → 不可逆。当压缩 cache 被不同 query 复用（query-agnostic）时，重要性信号退化，精度**崩 11–15 点** |
| **均匀低秩编码** | 每个 token 分配相同秩 → 预算浪费 |

### 方法：分配 ≠ 淘汰

**核心理念**: 秩应该被分配（allocate），而不是淘汰（evict）。每个 token 保留非零秩，按 query salience 动态分配变速率低秩预算。

- 无需训练：codec 在推理时确定分配合
- 无 token 被丢弃 → query-agnostic 场景仅退化 3.5–5.5 点（vs query-aware 的 11–15 点）

### 性能数据

| 配置 | 精度损失 (vs 全量 KV) | 条件 |
|:-----|:---------------------:|:------|
| 20% 预算, LongBench 平均 | **< 0.8 点** | Llama-3.1-8B & Qwen2.5-7B |
| vs KVzip (同预算) | 精度等价 (3/4 设置) | **1/8** 的 prefill 开销 |
| 均匀秩消融 | VarRate 显著优于 | 两种模型均验证 |

### 影响判断 🔥

VarRate 的可贵之处在于**同时解决了两个看似矛盾的需求**：
1. query-aware 场景：精度与全量 KV 几乎无差别（<0.8 点）
2. query-agnostic 场景（prefix cache 复用）：不像 eviction 方法崩 11–15 点，仅退化 3.5–5.5 点

这意味着 VarRate 可能是**第一个适合同时做在线推理+前缀缓存复用的训练无关方案**。

## 2. 推理架构：LLA 循环潜注意力—交叉循环 KV 编码

> **来源**: arXiv 2607.15456 · 2026-07-20 | **模型**: Ouro-1.4B, Ouro-2.6B-Thinking, Huginn-3.5B | **硬件**: H200

### 问题

Loop/weight-tied Transformers 复用同一组 block 多次，但解码时每个 recurrence step 的 K/V 需独立存储。

### 发现：循环 KV 高度结构化

对一个固定 token、layer、head，K/V 向量在循环之间形成**短低秩轨迹**，而 head 和 layer 轴要平坦得多。这意味着压缩的首要轴是**循环轴**（recurrence），而非 head 轴或 layer 轴。

### 方法：LLA

Post-training cache codec：存储紧凑 K/V latent，仅在 attention 读取时重构循环特定 K/V 向量。

| 模式 | 压缩轴 | 适用场景 |
|:-----|:-------|:---------|
| **LLA (default)** | 循环轴·每 head 独立 latent | 一般 |
| **LLA-2D** | 循环+head 折叠为一个 latent | 极压缩模式 |

### 性能数据

| 指标 | 值 | 条件 |
|:----|:--:|:------|
| **压缩比** | **21.3×** | Ouro-1.4B, 4K context |
| 单 H200 batch 容量 | 32 → **768** sequences | 同比 |
| MATH-500 (4× 压缩) | 0.43 → **0.66** | on-policy 精炼后 |
| No-answer 率 | 显著降低 | — |

与 MLA（head 轴压缩）、跨层共享、KV 量化、最终循环复用相比，per-head LLA 在同等预算下全面领先。

### 影响判断

LLA 的核心洞察——**循环轴压缩优于 head 轴压缩**——对 weight-tied 和循环架构（如 Universal Transformer、recurrent memory 方案）有直接参考价值。

## 3. 编译器/硬件：DSTAR 扩散 Transformer 加速 (MICRO'26)

> **来源**: arXiv 2607.15846 · MICRO 2026 接收 | **硬件**: ASIC (vs A100 GPU)

### 方法

| 层 | 技术 |
|:---|:------|
| **算法** | 细粒度混合精度量化（差异激活不同 bit） + 稀疏 attention 复用 |
| **硬件** | 专用加速器架构 |

### 性能数据

| 指标 | vs A100 GPU | vs SOTA 加速器 |
|:----|:-----------:|:--------------:|
| **延迟加速** | **7.33×** | **2.54×** |
| **能效** | **41.89×** | **3.68×** |
| 精度精度 | 无损失 | 7 个典型 DiT 模型验证 |

### 影响判断

扩散 Transformer 的专用加速器终于突破 7× 加速门槛。与通用 GPU 相比 41.89× 能效意味着对于大规模 DiT 推理集群（视频生成等场景），定制 ASIC 方案的经济账越来越清晰。

## 4. Prompt 缓存：CAPC 缓存感知提示压缩

> **来源**: arXiv 2607.15516 · 2026-07-20 | **API 验证**: Anthropic Sonnet 4.6 | **生产验证**: 企业工具助手 / RAG / tau-bench

### 问题

- Prompt caching 对重用前缀打折
- Query-aware 压缩每次产生不同压缩前缀 → **使 cache 前缀无效**
- Sonnet 4.6 的双层 cache（hot/cold）在 ~3,500 tokens 阈值处有尖锐拐点，命中率 ρ ≈ 0.83（非文献假设的 1.0）

### 方法 CAPC

1. **Query-agnostic 压缩**（保证前缀稳定）
2. **显式 `cache_control`** + 层级保持比率边界（不过度压缩→不推出 hot 层）

### 性能数据

| 对比策略 | 成本节省 | 质量影响 |
|:---------|:--------:|:--------:|
| **CAPC** → vs cache-only | **−49%** | ±0.05 |
| vs query-aware 压缩 | **−64%** | 同 |
| vs vanilla (无缓存/压缩) | **−90%** | 同 |

**生产验证:**
- 企业 94K schema 前缀助手: **51.7% 成本减少** (r=3)
- 知识图谱 RAG (FastAPI codebase): **9.3×** vs cache-all
- tau-bench retail (50 tasks): 最便宜策略, reward 等于 vanilla (36/50, p=1.00) — query-aware 压缩反而 **+40.1%** 比 vanilla

### 影响判断

CAPC 是**首个在生产 API 上验证「缓存+压缩协同最优」的实证研究**。关键教训：query-aware 压缩在缓存场景下可能**负收益**（+40.1%）——而 query-agnostic + 层级感知修正策略始终最优。

## 7. 推理优化：KARA 滑动窗口 KV + KvLLM (vLLM 集成)

> **来源**: arXiv 2607.01237 · 2026-07 | **引擎**: vLLM + PagedAttention

### 方法

KARA 针对 reasoning LLM 长 CoT 解码时 KV cache 膨胀问题，采用：

1. **滑动窗口**：仅在近期生成上下文上操作
2. **双向注意力**：窗口内评分+选择信息性 KV 对
3. **Token2Chunk 模块**：选中 KV 对扩展为 chunk（保持灵活语义块）

**KvLLM** 将 KARA 适配到 vLLM 的 PagedAttention 架构。

### 性能

LongContext 基准一致性能提升 + KV cache 内存减少 + 输出吞吐提升。

## 8. 趋势判断

1. **KV 压缩从「淘汰」走向「变速率分配」** 🔥
   - VarRate 证明**不淘汰任何 token 的变速率编码**在 query-agnostic 场景比 eviction 好 11+ 点
   - 与 SeKV（昨天跟踪的 GPU-CPU 层次方案）和 Fractal KV（存档即索引）方向一致：**存所有 token，但智能分配资源**

2. **循环轴成为 KV 压缩新维度**
   - LLA 证明循环轴压缩优于 head 轴压缩（21.3× vs MLA cross-head）
   - 对 weight-tied Transformer、recurrent memory、multi-turn agent 场景有直接价值

3. **缓存+压缩的协同优化需要重新思考**
   - CAPC 的生产实证显示 query-aware 压缩在缓存场景可**负收益**（+40.1%）
   - 最优解是 query-agnostic + 层级保持 ≤ 过度压缩
   - **对任何部署了 prompt caching 的系统都有修正意义**

4. **DeepSpeed AutoEP 降低 MoE 训练门槛**
   - 自动专家并行配置 + Muon optimizer ZeRO-3 支持
   - MoE 训练的工具链闭环越来越完整
