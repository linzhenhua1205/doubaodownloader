## 本期发现 (8条)

### 框架与系统

- **SALT：子空间对齐的极致低秩 LoRA 服务**（[arXiv:2608.03579](https://arxiv.org/abs/2608.03579)，08-04）: 多租户 LoRA 服务面临"高秩适配器精度好但 PCIe 换入换出开销大"与"超低秩(r≤2)省内存但掉精度"的系统两难；SALT 三阶段（域质心联合训练+对齐正则化→用户私有数据上冻结质心微调 r≤2 任务残差→推理时质心常驻 GPU、按需动态换入残差）；r≤2 残差即可恢复高秩精度，较 SOTA 压缩基线绝对精度 +18.5%，单适配器内存 -16x；集成 vLLM 后 PCIe 带宽压力下吞吐 +51%、VRAM 约束下 +28%（Llama-3.2-3B）。URL: https://arxiv.org/abs/2608.03579 ⭐

- **LiveMem：长运行 LLM 推理的状态连续性**（[arXiv:2608.02515](https://arxiv.org/abs/2608.02515)，08-03）: 长运行助手/Agent 的交互流终将超出上下文，现有保留/摘要/检索只保"选中的历史"而非全生命周期持久状态；形式化为"上下文翻转下的状态连续性"——固定容量记忆状态的计算前向推进，其生命周期独立于活动上下文；LiveMem 给预训练全注意力 LLM 增补内在记忆状态（主注意力路径保持有界 KV 窗口），配记忆导向后训练+状态感知服务；LongMemEval 上证据已移出当前上下文仍能作答，证据-距离分析表明有用信息在活动窗口外持续存在。

- **TELLER：LLM 推理跨层根因分析**（[arXiv:2608.01975](https://arxiv.org/abs/2608.01975)，08-03，ASE 2026）: 单请求横跨推理引擎/Python-C++ 后端/host CUDA API/GPU kernel/分布式通信，现有 profiler 只给裸时间线、日志诊断缺跨层语义；TELLER 非侵入式采集 NVTX/CUPTI 追踪+服务日志，重建逐请求调用链树并做日志-执行步对齐；Trace Pair Encoding(TPE) tokenizer 把依赖感知因果上下文切片压成带 parent/depth/duration 的结构 token 序列——适度词表下逐步 trace 长度 -80% 且横纵两视图诊断质量最佳；提供数值候选定位+多模态根因模型（异常步预测/算子定位/自然语言解释）。

- **Celty：双稀疏 LLM 推理的 SpMspV 内核与 SIMT 微架构协同设计**（[arXiv:2608.01536](https://arxiv.org/abs/2608.01536)，08-02，ICCAD 2026）: 双稀疏（非结构化权重剪枝×运行时激活稀疏）对单用户解码最优，但构成现有 GPU kernel 处理不佳的 Sparse Matrix-Sparse Vector(spMspV) 工作负载；Celty 提出 RLC-CSC 压缩格式（向量化加载+双稀疏跳过无效访存）+ 流水线 RLC 解码器 Sparse SIMT Core（免软件索引重建、寄存器文件免冲突累加）；kernel 较 cuBLAS 最高 2.8x、较 Flash-LLM 2.4x，加 SIMT Core 后 70% 双稀疏下达 5.3x。

### 推理优化与硬件

- **GyRot：旋转与细粒度组量化的协同设计**（[arXiv:2607.27694](https://arxiv.org/abs/2607.27694)，07-30）: 旋转（全局）与组量化（局部）单独都有效但组合常掉精度/增硬件开销，根因在全局旋转与局部组缩放失配；GyRot 以 CoRFiG（粗旋转细分组）+ HAP（谐波对齐置换）实现算法-硬件协同，并重构非对称量化+零点取整实现全整数反量化；INT4 tensor PE 架构落地。与 08-07 期 OptR（输出感知旋转）共同印证"旋转×量化"成为低比特推理主流范式。

- **LightRot：轻量旋转方案与低比特推理专用硬件**（[arXiv:2607.27704](https://arxiv.org/abs/2607.27704)，07-30，JETCAS 2025/2026）: 集成 Grouped Local Rotation(GLR)+Outlier Direction Aligning(ODA)+层级快速 Hadamard 变换(FHT) 旋转单元，直击低比特量化中旋转运算的能耗开销；28nm CMOS 实现 4-bit 推理峰值能效 27.4 TOPS/W 超越前 SOTA；面向 LLaMA2-13B/LLaMA3-8B 而非 GPT-2 级任务，MT-Bench 验证对话场景鲁棒性——低比特硬件评测从"语言建模玩具"转向"真实对话负载"。

- **Prox：训练无关的 FFN 激活稀疏化**（[arXiv:2607.27591](https://arxiv.org/abs/2607.27591)，07-30）: FFN 主导 LLM 推理的访存与计算，是激活稀疏化的首要目标；现有训练无关方法在高稀疏度下因通道选择策略缺陷显著掉质量；关键观察是 SwiGLU 中间状态是高效通道选择信号，但获取它需昂贵稠密计算；Prox 两阶段训练无关框架——稀疏执行只需中间状态诱导的通道掩码而非完整中间值，用近似中间通道显著性替代稠密计算，兼顾高稀疏度质量与开销。

- **From Tokens to Watt-hours：现代 GPU 推理能耗解析估计**（[arXiv:2607.26571](https://arxiv.org/abs/2607.26571)，07-29）: 推理能耗直接测量需硬件遥测/功率仪器/基础设施监控，限制对比研究与早期系统设计；提出解析结构+经验校准的 GPU 级能耗估计方法论（NVIDIA H100 级），以 token 量为输入估计推理能耗，面向可持续性报告与选型——补上 serving 栈 TCO/能耗评估缺口。

## 趋势观察

- **"旋转×量化"成为低比特推理主流范式**：GyRot（旋转×组量化协同）与 LightRot（旋转+专用硬件）同日出现，叠加 08-07 期 OptR（输出感知旋转）——旋转用于抑制离群值、量化负责压缩，算法-硬件协同设计密集回归。
- **推理可观测性/能耗成为一等公民**：TELLER（跨层 RCA）将 LLM 推理重新定义为"持续运维服务"，与 08-07 期 Agentic AIOps 观察一致；Watt-hours 解析能耗模型补上 TCO/可持续性缺口。
- **个性化/长运行服务的"预填充税"问题在模型层回应**：LiveMem 以模型内记忆状态实现状态连续性（系统层方案 InferScale 已于 08-01 期归档），两路线对照：系统注入 vs 模型内在。
- **双稀疏/低秩 serving 工程化加速**：SALT 证明 r≤2 残差 + 质心常驻是 LoRA 多租户的可扩展解；Celty 把双稀疏从算法概念推进到 kernel+微架构联合实现。
