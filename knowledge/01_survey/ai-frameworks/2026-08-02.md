## ① arXiv — 8条新增（07-26 ~ 07-30）

### 1. ReToken: 视觉检索的单一检索 token（07-30）⭐
- **来源/标题**: [ReToken: One Token to Improve Vision-Language Models for Visual Retrieval](https://arxiv.org/abs/2607.28627)（07-30）
- **要点**: 训练单一 learnable embedding 作为显式检索目标，从预填充 visual KV cache 中选出与查询相关的稀疏视觉 token 子集。仅需小规模 image-QA 数据集训练。
- **量化数据**: Visual Haystacks 上 Qwen3VL-8B 提升 **13.4点**、InternVL3.5 提升 **12.4点**（>20% 相对）；LVBench 零样本迁移长视频 **8.0点**；训练+长视频推理单 H100 即可。代码: github.com/avaxiao/ReToken
- **意义**: KV cache 选择从「文本注意力」扩展到「视觉检索目标」，为 VLM 长视觉上下文提供轻量 KV 稀疏化路径。

### 2. Stage-Replay Divergence: KV cache 作为因果充分载体（07-30）⭐
- **来源/标题**: [Stage-Replay Divergence Follows the KV Cache](https://arxiv.org/abs/2607.28495)（07-30）
- **要点**: 在 Qwen2.5 推理系统上审计「阶段重放」假设——用 200 项匹配实验对比保留 live cache 与一次性 prefill 相同 token 序列。BF16 下两构造在 166 个后缀和 20 个正确性标签上分歧，但准确率仅差 1 点（95% CI [-3.5, +5.5]）；FP32 下无解码分歧（95% Wilson 上界 1.88%）。
- **量化数据**: 双向移植全部 48 层 K/V → 24/24（主 checkpoint）与 43/43（盲复制）分歧延续跟随 cache donor。
- **意义**: 边界 K/V cache 是分歧轨迹的因果充分载体，数值精度调制其行为表达——对 KV 缓存移植/复用的正确性分析提供严格方法论。

### 3. S-CEReBrO: 恒定 KV cache 的流式注意力（07-30）
- **来源/标题**: [S-CEReBrO: Breaking the Memory Barrier in Continuous EEG Monitoring](https://arxiv.org/abs/2607.27913)（07-30，MICCAI 2026）
- **要点**: Windowed Alternating Attention 将注意力分解为固定大小时空窗口，仅活动窗口需驻留注意力图 → **恒定 KV cache 内存**。
- **量化数据**: 可比 full self-attention 长 **100×** 信号、比 low-rank 线性注意力长 **3×**；内存仅为线性注意力 **55%**、吞吐 **2.1×**；>25,000 小时/12,000 受试者预训练，7/11 下游任务 SOTA，参数少 60%。
- **意义**: 为连续信号（医疗/传感器）流式 Transformer 提供与信号时长解耦的内存方案。

### 4. VGD: 幻觉接地签名 + KV cache 回滚解码（07-30）
- **来源/标题**: [Hallucinations Leave a Grounding Signature: Verifier-Guided Decoding](https://arxiv.org/abs/2607.27823)（07-30）
- **要点**: 发现幻觉 object mention 编码在 Intrinsic Grounding Signature (IGS) 分布式有符号注意力模式中；轻量 verifier 检测高风险 mention 后**回滚 KV cache**、抑制 object 及同义词并重新生成。仅干预高风险 mention，保留接地 object 覆盖。
- **量化数据**: AMBER-G @rec90 CHAIR 削减 **43.6%**、接地覆盖保留 **99.6%**；CHAIR-MSCOCO CHAIR_i/CHAIR_s 降 **37.0%/30.4%** 且不缩短 caption。
- **意义**: 解码期选择性 KV 回滚成为幻觉校正的有效手段。

### 5. Photonic-CXL Memory Appliance: 光子CXL KV存储（07-29）⭐
- **来源/标题**: [A Photonic-CXL Memory Appliance for Scalable KV Cache Management](https://arxiv.org/abs/2607.27187)（07-29，Marvell）
- **要点**: Marvell Photonic Fabric Memory Appliance——光子-CXL 混合架构，用**无源光纤 shuffle** 替代电开关，16 主机 switch-free 全交叉拓扑提供 **32 TB 共享内存**。
- **量化数据**: 仿真显示比电 CXL 池延迟降低 **50%+**；消除 cache eviction 悬崖，多轮对话 TTFT 改进 **6.6×**。
- **意义**: 呼应 07-29 已归档的「内存语义统一池」趋势——光子互连解决电 CXL 的 switch 延迟/线缆距离/功耗缩放瓶颈，是 TB 级 KV 池的硬件路径。

### 6. DIRECT: KV Cache 模板填充的序列标注（07-29）
- **来源/标题**: [DIRECT: Direct Decoding for Efficient and Aligned Sequence Labeling](https://arxiv.org/abs/2607.26891)（07-29）
- **要点**: DPO 强化任务对齐 + 受控解码（固定输出格式+候选集约束）+ **模板填充**（仅生成 label token，前缀通过 KV Cache 复用）减少冗余计算。
- **量化数据**: 8 个数据集上性能与效率双提升。
- **意义**: KV 前缀复用从推理服务下沉到任务专用解码器设计。

### 7. Route-Block Membership: MoE AWQ 算术路径机制研究（07-28）
- **来源/标题**: [Route-Block Membership Selects Packed-AWQ Arithmetic](https://arxiv.org/abs/2607.26316)（07-28）
- **要点**: 在 Qwen3-Coder AWQ layer-6 fixture（vLLM/Marlin, RTX 3090）上证明路由块成员选择精确的 packed 量化算术轨迹；交换路由可迁移完整相反轨迹。
- **量化数据**: 70 个有效冷进程 + 7 个必需扰动拒绝；forcing 200-block grid 使 W13 逐位相等。
- **意义**: 明确声明为**单 fixture 因果机制结果**（非 prevalence/portability claim）——MoE 量化推理的确定性分析标杆。

### 8. A Frozen 12B: 验证记忆系统 + 零 token 推理（07-26）
- **来源/标题**: [A Frozen 12B Beats Frontier Models on Verified Work](https://arxiv.org/abs/2607.23806)（07-26，Corbenic AI）
- **要点**: 冻结模型 + 已通过独立验证的持久解记忆；已验证问题家族的新实例以**零生成 token、bit-exact、确定性**作答。
- **量化数据**: 180/180（9 家族×4 架构×4 厂商）；记忆选择 1.4μs，完整复用 6-23ms @ 36mWh；**6,000,000 token** 可移动窗口（单 46GB GPU 平坦内存；对照: vLLM 停在 30,399 tokens、SGLang 在 32,000 截断）；近似相似性检索在 4,500 项存储上选错 **94.3%**（精确寻址零错误）。
- **意义**: 行业经验报告——验证记忆 + 精确寻址挑战「每次查询重新生成」范式，间接暴露 vLLM/SGLang 上下文窗口工程上限。

## 🔮 关键趋势判断

1. **KV cache 升格为系统中心抽象**: 从「压缩/驱逐」（前几期）扩展到因果载体（Stage-Replay）、光子存储层级（Photonic-CXL）、视觉 token 选择（ReToken）——KV 状态管理覆盖算法、系统、硬件三层。
2. **解码期干预成主流手段**: VGD（KV 回滚纠幻觉）、DIRECT（KV 模板复用）、SmartGen/InferScale（KV 注入）——「生成过程中选择性操作 KV」正在取代「一次性构建 KV」。
3. **上下文窗口工程上限被公开量化**: Corbenic 报告揭示 vLLM 30,399 / SGLang 32,000 token 的实用上限，与 LOCKS 的 100K+/1M 诉求形成对照——长上下文 serving 仍有显著工程空间。
4. **DeepSeek-V4 成为推理引擎优化锚点**: vLLM 一个版本内 4 项 DSv4 专项优化（routing kernel/fused_topk_bias/repeat移除/DSpark），印证开源权重模型主导 serving 优化资源配置。
5. **光子互连进入内存池赛道**: Marvell PF Memory Appliance 与 07-29 归档的 NVL72/超节点内存池趋势合流，光交换是 TB 级 CXL 池的可行解。
