## 2. 安全/KV：Alignment Collapse — KV Cache 量化无声摧毁安全对齐

> **来源**: arXiv 2606.09864 · 2026-05-31 | **模型**: 11 个 instruction-tuned (3.8B-72B) | **基准**: 5 benchmarks, 1,894 prompts

### 核心发现 🌟

KV cache 量化在几乎不破坏 perplexity 的情况下，**可以无声摧毁模型的安全对齐**：

| 现象 | 数据 | 含义 |
|:-----|:----:|:------|
| **Mistral-7B 拒绝率下降 15.2%** | 在仅 1.03× perplexity 退化时 | 标准指标完全无法预警 |
| **不存在通用安全 bit-width** | 各模型有尖锐的相变点 | 不能照搬其他模型的量化配置 |
| **安全特征位于低维激活子空间** | 脆弱性比全表示空间高 **10²-10³×** | 安全是细丝，不是大树 |

### 根因：几何解释

安全特征（refusal direction）占据低维激活子空间，对量化噪声的敏感度比 perplexity 平均作用的整个表示空间高出 **2-3 个数量级**。

### 方法：PCR 诊断 + 恢复协议

| 阶段 | 方法 |
|:-----|:------|
| **诊断** | Per-Channel Reduction (PCR) → 3 种失效模式分类 |
| **失效模式 A** | outlier-crushes-safety: 安全在非 outlier 通道中被 outlier 驱动的 scale factor 连带破坏 → **换 per-channel 精度** |
| **失效模式 B** | outlier-as-safety: 安全重叠 outlier 通道 → 更细粒度也无法挽救 |
| **失效模式 C** | multi-layer dilution: 安全分布多层 → 每层单独修复不够 |
| **恢复** | 训练无关协议，约 **35 GPU-minutes**，**恢复 97.2% 对齐** |

在 KIVI quantizer 上验证，恢复率高达 97.2%。在生产 vLLM FP8 KV cache 部署中得到确认。

### 影响判断 🔥

**这是一个必须扩散的认知**：KV cache 量化优化以 perplexity 为指标会完全漏掉安全风险。Mistral-7B 在 1.03× perplexity 时拒绝率掉 15.2%——任何工程团队在部署量化策略前必须先跑 PCR 诊断。35 GPU-minutes 的诊断成本几乎可以忽略。

## 3. 推理/机密计算：Serialized Bridge — Blackwell GPU-CC 下 13-27% 吞吐损失归因

> **来源**: arXiv 2606.23969 · 2026-06-22 | **硬件**: RTX Pro 6000, B300 HGX | **引擎**: vLLM

### 核心发现

GPU Confidential Computing (GPU-CC) 已做到 GPU 本地计算几乎无损：**B300 BF16 matmul = 0.998× 非机密性能**。但 **LLM serving 在 Intel TDX + GPU-CC 下仍损失 13-27% 吞吐**，KV cache restore 延迟加倍 (+131%)。

### 根因：机密 VM-GPU 桥成为串行瓶颈

| 问题 | 表现 | 影响 |
|:-----|:------|:------|
| 安全复制无法获得 CUDA-stream 并发 | 流内串行化 | 大块传输无收益 |
| 异步传输在 runtime 边界阻塞 | 期望是非阻塞的 | 小传输付固定 toll |
| vLLM dense decode 中 **44× 更慢的小 alloc-and-copy** | 每次小块操作被放大 | 总吞吐损失主体 |

### 恢复方案

| 方案 | 恢复比例 | 条件 |
|:-----|:--------:|:------|
| 调度 flag | **57%** | 通用 |
| Worker-thread drain | **最高 92%** | 高并发场景 |

### NVLink 在 CVM 中可用

量化了 B300 机密多 GPU NVSwitch 租户：CVM 内 **510 GB/s NVLink P2P**。剩余 fabric-attestation 缺口待解决。

### 影响判断 🟢

对机密计算部署有直接参考价值——关键瓶颈不在 GPU 本地计算（0.998×），而在 **host/device 移动的串行化**。这解释了为什么 B300 BF16 矩阵乘几乎无损但 serving 端到端掉 13-27%。57% 可恢复已可指导工程选型。

## 4. KV 压缩：KVServe (SIGCOMM'26) — 自适应 KV 通信压缩 32.8× TTFT

> **来源**: arXiv 2605.13734 · 2026-05-13 | **SIGCOMM 2026 接收** | **实现**: vLLM

### 问题

解耦推理中，KV 成为跨网络和存储边界的显式载荷，压缩是性能关键。但现有方案使用**静态**压缩配置，而生产服务上下文（负载组合/带宽/SLO 预算）随时间变化 → 固定选择次优甚至增加延迟。

### 方法：服务感知自适应压缩

| 组件 | 功能 |
|:-----|:------|
| **模块化策略空间** | 统一 KV 压缩到一个框架，含新组件和跨方法重组 |
| **贝叶斯分析引擎** | 高效搜索策略空间，提取 3D Pareto 候选集 → 降低 **50× 离线搜索开销** |
| **在线控制器** | 分析延迟模型 + 轻量 bandit → 选择最优 profile，修正 offline-to-online 偏差 |

### 性能数据

| 指标 | 改进 | 场景 |
|:-----|:----:|:------|
| **JCT** | **最高 9.13×** | PD-separated serving |
| **TTFT** | **最高 32.8×** | KV-disaggregated serving |
| 离线搜索开销 | **-50×** | 相比全空间搜索 |

### 影响判断 🔥

SIGCOMM'26 的工作。解耦推理中 KV 传输刚成为显式瓶颈，KVServe 的**自适应压缩**思路是必备工程组件——静态配置在动态负载下不可能最优。模块化策略空间+贝叶斯搜索+在线 bandit 的三层设计是务实的分层方案。

## 5. 稀疏注意力：UNIQUE — 通用 Top-K 稀疏注意力 11.4× 加速

> **来源**: arXiv 2605.27740 · 2026-05-26 | **模型**: 文本 + 语音 LLM | **基准**: LongBench Pro

### 方法

| 组件 | 实现 |
|:-----|:------|
| **KV page 粒度** | 不按 token 按 page 打分 |
| **重要性分数** | page 内 key 均值作为代表向量 + 标准差作为偏移项 |
| **训练-推理一致性** | soft-mask sparsity-aware training (sigmoid 软掩码) |
| 无需 auxiliary loss 或架构变更 | 低侵入 |

### 性能数据

| 指标 | 改进 | 条件 |
|:-----|:----:|:------|
| **Attention kernel 加速** | **最高 11.4×** vs FlashInfer 稠密 |
| **端到端解码加速** | **最低 5.3×** vs vLLM 稠密基线 |
| 长上下文基准精度 | **保持** | LongBench Pro + 语音识别 |

### 影响判断 🟢

稀疏注意力的实用化方案——KV page 粒度 + 均值-标准差评分简单有效。5.3× 以上端到端加速足够引起部署兴趣。语音 LLM 上的验证扩大了适用范围。

## 6. 训练推理：SiDP — 离线推理的存效数据并行 1.8× KV 容量

> **来源**: arXiv 2605.28095 · 2026-05-27 | **GPU**: H20, H200, B200 | **模型**: Qwen3-32B, Qwen2.5-72B, Llama-3.1-70B

### 问题

离线推理（throughput-oriented）中需要大 batch 以充分利用 GPU。但 DP 复制权重占显存，MP 需细粒度同步侵蚀调度灵活性。

### 方法：权重作为共享资源

| 模式 | 机制 | 适用场景 |
|:-----|:------|:---------|
| **WaS (Weight-as-a-Service)** | 远程权重流式经 NVLink 到小 cache | 大 batch 推理 |
| **CaS (Compute-as-a-Service)** | 将激活发送给权重所有者计算 | 小 batch/尾部 |

DP 组内将权重组织为分布式池——每层由一个 GPU 拥有，其他 GPU 按需访问。

### 性能数据

| 指标 | 改进 vs vLLM | 条件 |
|:-----|:------------:|:------|
| **可用 KV 容量** | **最高 +1.8×** | 相同配置 |
| **端到端吞吐** | **最高 +1.5×** | 离线负载 |

### 影响判断 🟢

SiDP 巧妙地将 DP 的显存瓶颈转化为共享资源管理问题。1.8× KV 容量对 offline 推理影响直接——更大 batch → 更好 GPU 利用率。WaS/CaS 双模式覆盖了大/小 batch 场景，是实用的设计。
