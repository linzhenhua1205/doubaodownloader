## 1. 训练框架之 PyTorch 2.13.0 正式发布 (Jul 8, 2026)

> 发布链接：https://github.com/pytorch/pytorch/releases/tag/v2.13.0

**这是 PyTorch 自 2.12.0（May 13）后最重要的一次发布**，包含多项编译器/分布式/硬件的里程碑变更。

### 1.1 亮点与新特性

| 特性 | 说明 | 性能数据 |
|:----|:-----|:---------|
| 🔥 **FlexAttention on MPS (Apple Silicon)** | FlexAttention 首次在 MPS 后端落地 | **~12× speedup** over SDPA on sparse patterns |
| 🔥 **CuTeDSL "Native DSL" Inductor 后端** | Inductor 第二个高性能代码生成路径（Triton 之外），[Prototype] | **更快编译速度** |
| 🔥 **nn.LinearCrossEntropyLoss** | 将 final prediction + loss 合并计算 | 大词汇表 LM 训练 **peak GPU 内存减少 4×** |
| 🔥 **torchcomms (新通信后端)** | PyTorch Distributed 的全新通信后端 | 提升容错/可扩展性/可调试性 |
| **FSDP2 overlap 通信** | 通过专用进程组 overlap reduce-scatter/all-gather | 增加分布式训练吞吐 |
| **Python 3.15 wheel 支持** | Linux 平台，含 free-threaded 3.15t 构建 | — |
| **ROCm AOTriton 0.12b** | 原生 HIP CMake 集成 | — |
| **Armv9-A torch.compile** | ARM 平台编译目标 | — |
| **Intel XPU** | 新设备 telemetry API | — |

### 1.2 向后不兼容变更

| 变更 | 影响 |
|:----|:-----|
| **C++20 最低要求** | PyTorch 2.13 编译和使用需要 C++20 编译器 |
| **NCCL ≥ 2.23 要求** | 从源码构建必须 >= NCCL 2.23 |
| **Bazel 构建移除** | 迁移到 CMake/pip 构建流 |
| **Named Tensors 完全删除** | Tensor.names / .rename() / .align_to() 等全部移除 |
| **Volta (SM 7.0) 从 CUDA 12.8+ 移除** | V100 用户需用 CUDA 12.6 构建 |
| **Python 3.13t free-threaded 停止构建** | 迁移到 3.14t |
| **StorageImpl COW → 可插拔 MaterializerHook** | 替代 is_cow/maybe_materialize_cow |
| **shared_ptr<Node> → intrusive_ptr<Node>** | Tensor.grad_fn() 返回类型变更 |

### 1.3 弃用事项

| 弃用 | 替代方案 |
|:----|:---------|
| 自定义算子返回 alias 输入的输出 | 返回 clone 而非 alias |
| CUDA 12.8 构建（已被 13.0 取代） | CUDA 13.0 或 CUDA 12.6 |
| CMake < 3.10 兼容 | CMake ≥ 3.10 要求 |
| Profiler metadata_json | 改 event_metadata |
| torch.compile(fullgraph=True) 无警告绕过 | v2.14 将直接报错 |

### 1.4 与 AI 框架相关的重要改善

- **FlexAttention now has deterministic backward path on CUDA**
- **新 CuTeDSL Native DSL 后端** — 为 Inductor 开辟了 Triton 之外的第二条高性能路径
- **Batched linalg.eigh on CUDA** — 因 cuSolver 后端更新，**最多 100× 加速**
- **torch.accelerator.Graph API** — 统一 CUDA/XPU/out-of-tree 后端的 graph capture/replay
- **torch.cond 可在 CUDA Graph 内捕获和重放**

## 7. 趋势研判

1. **PyTorch 2.13 确立编译器/分布式/硬件三线升级** — CuTeDSL Native DSL 作为 Triton 平行的第二条代码生成路径，torchcomms 解决大规模通信瓶颈，FlexAttention MPS 打开 Apple Silicon 市场
2. **TRT-LLM 去 TensorRT 化进入最后阶段** — rc20 后下版本彻底移除 TensorRT 后端，全面转向 PyTorch 原生
3. **CXL 成为 KV cache disaggregation 新标准** — SAC 9.7× TTFT 和 ITME 35.7% 吞吐表明 CXL 在稀疏注意力模型上远优于 RDMA
4. **KV Cache 压缩走向联合优化** — RDKV（rate-distortion 联合 eviction+quantization）和 LKV（可微分学习）超越了孤立的单目标方法
5. **工业级推理引擎对比** — Alibaba RTP-LLM 在多项指标上超越 vLLM/SGLang（35-37% TTFT 降低），但仍是专门优化
