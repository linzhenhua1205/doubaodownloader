## 核心发现

- **GitHub Copilot 进入 Slack：agent 从"个人工具"变成"团队共享工作面"**（08-21 Release, public preview）: GitHub Slack 集成把 Copilot CLI + Copilot app 的 agentic 能力带进对话流——@GitHub 提及即启动 agent session（回答代码问题、triage bug、更新/建 issue、cloud sandbox 中调查+实现+验证、开 PR 附会话链接），开会/通勤时异步继续。两个关键新概念：① **Slack Code**——面向 agent 的新型 channel，GitHub 为 launch partner；Copilot 可创建专属 code channel，团队在频道内跟进计划、检查 diff、预览 HTML 产物、迭代，任何人可从原线程加入/加上下文/重定向/停止会话；② **Multiplayer 共享会话**——agent session 对团队共享而非个人私用，"在请求发起处协作"，开发者可互相学习 prompt 技巧。**治理三件套**：issue/PR 归属于 Copilot app identity（可审计）；actions 受现有 GitHub 权限控制约束（有写权限才能触发修改）；repo admin 可要求对 Copilot 身份 PR **额外一次审批**（"要求 2 approval 的仓库，启用后 Copilot PR 需 3 个"）。可用性：Copilot Business/Enterprise 组织 public preview，用量计入现有 entitlements，受 cloud agent budgets 管理。URL: https://github.blog/changelog/2026-08-21-the-new-github-copilot-experience-in-slack
- **GitHub Copilot in Teams：会议决策直接转成 agent 待办，跨表面续作**（08-21 Release, public preview）: 在频道/线程/私信 @GitHub 启动 cloud agent session，所有人可见可引导；**standup/会议中产生 action item 可直接交给 Copilot 边讨论边调查**，"会议结束前就开始解决"。工作流闭环：Teams 启动 → 安全 cloud sandbox 异步执行 → 从终端/Copilot app/IDE 继续处理 agent 产物。**治理与计费**：① cloud agent sessions 消耗 AI credits，org 级受 usage-based billing budgets 治理；② cloud sandbox 单独计费，可用 product-level/SKU-level budget 控制；③ 前置条件=admin 启用 cloud agent policy + cloud sandbox（策略共享配置），public channels 需配默认仓库；④ 与 Slack 同款**额外审批**机制（Copilot 集成身份创建的 PR 需追加 approval，human in the loop）。URL: https://github.blog/changelog/2026-08-21-shared-agentic-work-with-github-copilot-in-microsoft-teams
- **GitHub/blocked users 管理增强**（08-21 Improvement）: 协作治理常规改进（blocked users 管理工具更好用），价值低，与 08-13 个人仓库评论封禁同属账号治理增量。URL: https://github.blog/changelog/2026-08-21-better-tools-for-managing-blocked-users

## 趋势判断（研发管理视角）

1. **"agent 进 IM"是 8 月 agent 工作流治理信号链的第四环**：08-04 stacked PR（可审查性）→ 08-14 agent apps（SDLC 闭环）→ 08-17 canvases（可视/可操控）→ 08-19 My work pane（工作台）→ 08-21 Slack/Teams（**团队协作面**）——agent 从"个人生产力工具"演进为"团队协作一等公民"，且 Slack/Teams 同日双发布说明**多 IM 全面铺开而非单点试点**。研发管理的重心随之从"如何让 agent 干活"转向"如何让团队一起监管 agent 干活"。
2. **"human in the loop"从口号变成可配置策略项**：本轮发布中治理机制首次显式制度化——**额外审批**（Copilot PR 需追加 approval，由 repo admin 配置）、**预算分层**（AI credits 走 usage-based billing budgets / cloud sandbox 走 product/SKU-level budget）、**身份归属**（Copilot app identity 可审计）。三件套与服务器/AI 基础设施的变更管理（审批流/配额/审计）同构，可迁移为内部 AI 研发平台的治理模板。
3. **研发成本核算出现新科目**：agent 会话消耗 AI credits 且与 sandbox 计费分离、按预算管控——**"AI 研发用量"成为可预算化的成本科目**，预示研发管理将新增"agent 算力预算"维度（与 08-20 日报 Code Quality 按 active committers 计费的"成本归因"趋势同向）。
