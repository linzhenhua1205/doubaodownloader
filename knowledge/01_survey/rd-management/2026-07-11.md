## 一、GitHub Engineering: Copilot Code Review 工具重构启示录 ⭐重点

> **来源**: [Better tools made Copilot code review worse — 这里是我们怎么真正改进的](https://github.blog/engineering/better-tools-made-copilot-code-review-worse-heres-how-we-actually-improved-it/) | 作者: Napalys Klicius | 2026-07-10

### 背景与问题

Copilot code review 从自有代码探索工具迁移到 Copilot CLI 共享工具集（grep/glob/view）时，**预期是"更好工具 → 更好表现"，实际却是成本上升、捕获问题减少**。

- 原有工具：`list_dir` / `search_file` / `search_dir` / `read_code`（为 AI code review 定制，自动带周围上下文）
- 目标工具：`grep` / `glob` / `view`（Copilot CLI 共享的类 Unix 工具集）

### 根因：工具指令错配任务

问题不是工具本身，而是**指令隐含的工作流不匹配**：

| 维度 | 通用 coding assistant 指令 | Code review 需要 |
|:-----|:--------------------------|:-----------------|
| 起点 | 猜测路径、探索仓库 | 从 diff 出发 |
| 搜索策略 | 宽搜 → 读 → 再宽搜（browsing loop） | 窄化搜索 → 精确读取 |
| 工具调用 | 交替搜索与读取 | 先批量 grep/glob，再批量 view |
| 失败恢复 | 猜邻近路径继续读 | 简化搜索重试或换 glob |
| 上下文 | 主动累积大块代码 | 最小证据范围 |

> **核心发现**: 工具结果对 agent 不是"一次性打印"，而是留在上下文中的额外 token。工具指令就是产品的 API 文档——不清会导致 agent 花错注意力。

### 解决方案

**重写工具指令为 reviewer 工作流**：

1. 从 diff 出发，形成具体的 review 问题
2. 路径不确定时用 glob，找符号/调用点用 grep
3. 在读取文件前批量完成低成本发现
4. 仅在确切知道文件和行范围时用 view
5. 一次批量读取，而非搜一个读一个

### 量化结果

- **~20% 更低平均 review 成本**（对比对照组）
- 同样的 review 质量指标
- 工具调用次数基本不变，但**更多调用花在相关证据上**

### 关键教训

- ⚡ **Shared tools scale when instructions and benchmarks match the job** — 同一套工具用于 CLI（通用 coding）和 code review（diff-anchored 审查），指令必须按产品场景定制
- ⚡ **工具指令 ≈ API 文档** — 小措辞改变影响成本、质量和调查路径形状
- ⚡ **Traces > final scores** — Benchmark 的可视化 trace 让 agent 行为可调试，能问"它先窄化还是先宽读了？"

## 二、GitHub Agentic Workflows: 跨库文档自动化的安全实践

> **来源**: [Automating cross-repo documentation with GitHub Agentic Workflows](https://github.blog/engineering/automating-cross-repo-documentation-with-github-agentic-workflows/) | Microsoft Aspire 团队 (10人) | 2026-07-08

### 安全约束下的跨库自动化

**问题**：产品代码在 `microsoft/aspire`，文档在 `microsoft/aspire.dev` — 跨库自动化面临安全审查瓶颈（宽 scope token 不被批准）。

**方案**：GitHub Agentic Workflows — "GitHub Actions，但用模型当工作项处理器，且满足安全审查的防护栏"

### 架构设计要点

**Safe-outputs 合约**（核心安全设计）：
- Agent 有**读权限** + prompt
- Agent 不能直接写 GitHub，而是**发射意图**（JSON blob 描述想创建的 PR/Issue/Comment）
- 另一个**极其窄 scope 的 job**（safe-outputs handler）把意图物化为真实操作
- "Agent's reasoning is fuzzy. The action surface is not."

**安全配置示例**：
```yaml
github-app:
  app-id: ${{ secrets.ASPIRE_BOT_APP_ID }}
  owner: "microsoft"
  repositories: ["aspire.dev", "aspire"]
safe-outputs:
  create-pull-request:
    title-prefix: "[docs] "
    draft: true           # 永远 draft，人工确认
    allowed-base-branches: [main, release/*]
    target-repo: "microsoft/aspire.dev"
    protected-files: blocked  # AGENTS.md/manifests/安全配置 不可触及
```

### 量化成果（30天窗口 2026-05-03 ~ 06-02）

| 指标 | 数值 |
|:-----|:-----|
| 产品 PR merged | 396 (338 main / 50 release/13.3 / 8 release/13.2) |
| 工作流执行次数 | 396 |
| 文档 PR 创建数 | **82**（以 user-facing 为准，内部更改自动略过） |
| 文档 PR merge 率 | **100%** |
| 中位数文档交付时间 | **44.8 小时**（从产品 PR merge 到文档 PR merged） |
| 24h / 7天内 merged | 38% / **96%** |
| 同时运行的工作流 | 5 个（docs check / changelog / release support / integration data / repo pulse） |

### 经验总结

**✅ 有效**：
- Milestone → release-branch 映射（利用已有流程，零额外操作）
- Draft-only + SME 作为 reviewer（feature 工程师确认文档准确性）
- 每个 workflow 独立 GitHub App token（明确 repo + permission scope）
- `protected-files: blocked`（agent 不能碰 AGENTS.md、包清单、安全配置）

**❌ 初期踩坑**：
- Agent 判断"是否需文档"门槛太松 → 13% 误创建 → 加 negative examples（CI/内部 helper/纯测试）后收敛
- 跨库 PR 创建需要镜像 checkout 模式
- 大 diff 超 prompt 预算 → 用 pre-agent bash 提取结构化元数据

## 三、Cursor v3.11 (2026-07-10): Side Chats 与 Conversation Search

> **来源**: [Cursor Changelog](https://www.cursor.com/changelog) | 2026-07-10

### Side Chats（侧边对话）
- `/side`、`/btw` 或面板 "+" 按钮开启**并行 agent 对话**
- 不中断主 agent，用于问问题、探索想法、检查决策
- 每个 side chat 是 **durable、full agent conversation**，可后续跟进、回访、`@`引用回主线程
- 默认专注 **reading/searching/answering**（不写代码）

### Conversation Search（对话搜索）
- Cmd+K 在 Agents Window 中搜索 agent 转录
- 本地搜索索引，**支持数千条对话快速搜索**
- Cmd+F 当前对话内搜索（match counter + 跳转）

### 新 Cloud Agent Hooks
新增 hooks：`beforeSubmitPrompt`, `afterAgentResponse`, `afterAgentThought`, `stop`, `subagentStart` 等
- 观察 agent 输出和推理过程
- 控制子 agent 行为
- 构建 **self-correcting loops**

### 项目/仓库选择器重构
- 按 This Computer / Cloud / Remote Machines scope 搜索
- 多仓库选择用 Toggle 代替独立的 Workspace Builder
- Branch picker 默认分支 + 最近使用分支
