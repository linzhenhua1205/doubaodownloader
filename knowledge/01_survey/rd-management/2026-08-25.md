## 核心发现

- **alt text 质量门禁：把"可证明"与"可怀疑"分层，默认值分开设计**（08-24 GitHub Blog, Engineering/UX, Taarik Ashenafi & Keenan Zhou）: WebAIM Million 2026 基线数据——顶部百万主页 **16.2% 图片缺 alt text**，有 alt 的图片中又有 **10.8% 无描述性**（alt="image"、原始文件名、或从相邻图片复制）。GitHub 为此给 Accessibility Scanner 写 alt text 插件，第一性分界线=**"每条规则都是对字符串的断言，而不是对图片的判断"**：五条确定性规则默认开启（缺失/纯空白、文件名 hero.png/IMG_2847.jpg、占位符 TODO/tbd、泛词 image/logo/chart、相邻图片同 alt 重复），全部无需模型/网络调用；唯一需要模型的"质量"规则默认关闭。设计取舍明确：**"质量规则若有误报，团队会关掉它"（a quality-oriented rule with false positives is a rule teams switch off）→ 宁可漏报不误报**（vague-alt 规则仅精确匹配才触发，"image of the login screen with the SSO button highlighted" 不触发）。可迁移到任何质量门禁：能证明的检查=便宜/可预测/默认开，只能怀疑的=opt-in/读作建议而非裁决。URL: https://github.blog/engineering/user-experience/your-alt-text-passes-automated-checks-that-doesnt-mean-its-any-good/

- **重复检测是布局问题而非 DOM 问题："用户看到什么"优先于"标记里有什么"**（08-24 同文细节）: 相邻图片同 alt 重复（一行五个星形图标各说 "3/5 stars"）初版按 document order 走 DOM，误报——header 与 footer 的 "GitHub" logo 在标记里相邻、屏幕上却相距甚远，没人把它们当一组。修复=改用**渲染后的 bounding box 空间判断**：gap = max(水平间距, 垂直间距)，largerDim = max(两框宽高)，`gap > GAP_MULTIPLIER × largerDim` 才延伸重复组；multiplier 明确标注为"凭真实页面调出来的判断值，不是从规范推出来的"；无 measurable box 时**fail open**（漏报不可见、错报不可容忍）。另两个可复用细节：用 Playwright role-based locator 而非 querySelectorAll('img')——不在浏览器无障碍树里的元素（含 alt="" 装饰性图片）直接排除，**空 alt 是作者声明装饰，不该惩罚**。治理含义：质量检查的"正确性基准"应从 DOM 转向用户实际体验，这决定了规则该用什么信号实现。URL: https://github.blog/engineering/user-experience/your-alt-text-passes-automated-checks-that-doesnt-mean-its-any-good/

- **模型入环治理三件套：决策程序化 + 显式反 nitpick + 先推理后裁决；隐私/成本同步设计**（08-24 同文）: 初版模型规则失败模式是"模型有意见"——"could this be better?" 让 LLM 对所有图片都说 yes，每个图都成 finding、信号消失。三个修复：①**决策程序**——prompt 走 4 步有序判断、首个命中即停并输出 verdict（decorative/redundant with caption/functional/informative）；②**显式反 nitpick 规则**——信任作者框架、"Image of…"冗余前缀与"Photograph of…"语义前缀分开、周边 prose 已分析图片时短 alt 视为正确；③**结构化输出强制字段顺序**——先生成 reasoning 再选标签，模型必须"先论证后定罪"。配套治理：规则 opt-in（需 GitHub Models token）、**URL 剥离 query/fragment**（CDN 签名 token 防泄漏）、src/srcset 替换为 (omitted)、上下文全视为未信任输入（页面文字可被构造来诱导模型）；**成本=每图每扫描一次模型调用，image-heavy 站点成本主导→放 schedule 而非每次 commit**。离线评分 harness（WebAIM/W3C images tutorial/POET 教学材料构建）与 CI **共享同一 prompt**——"what you tune offline is what runs in CI"。局限声明诚实：只读 alt 属性而非 computed accessible name（aria-label 修复不拦截）、只查 HTML img（SVG/role="img"/CSS background/canvas 未覆盖）、"Passing isn't conformance——自动化是底线，用辅助技术的人测试才是目标"。URL: https://github.blog/engineering/user-experience/your-alt-text-passes-automated-checks-that-doesnt-mean-its-any-good/

## 趋势判断（研发管理视角）

- **"误报税"是质量门禁设计的第一性约束，AI 时代更甚**：本文核心命题"质量规则有误报→团队关掉它"揭示了检查器的存活条件=误报率必须低到"值得留着"，否则一切收益归零。这与 08-23 AutoGPT"CI 是墙"（门禁要可解释、防绕过）、08-20 Code Quality（按活跃 committer 计费的度量成本）构成**"检查器治理"完整主线：规则可证明性（prove/suspect 分层）→ 规则可用性（误报税）→ 规则成本（计费/schedule）→ 规则权威性（墙/审批）**。设计任何 AI 辅助质量门禁（代码审查/安全扫描/文档检查）时，这四维都要在默认值里定好。
- **"prove/suspect 分层 + 默认值分离"成为 AI 治理的标准模板**：可证明的检查默认开且便宜、可怀疑的 opt-in 且读作建议——本文明确给出该原则；叠加 08-14 agent apps"人工审批保留在 rollout 决策点"、08-17 canvases"显式人工审批点"、08-21 Slack/Teams"额外审批"，模式收敛为：**AI 越有把握的环节越自动化默认开，AI 只是怀疑的环节必须 opt-in + 人工裁决**。研发平台设计权限边界时可直接套用。
- **模型入环的工程化治理三件套可复用**：决策程序化（有序步骤首个命中即停，防"总是有意见"）+ 结构化输出先 reasoning 后 verdict（强制论证再定罪）+ 离线评分与 CI 同 prompt（离线调的即线上跑的）。叠加隐私三件套（opt-in/redact/未信任输入声明）与成本调度（schedule 而非 commit）——这是"让模型当 reviewer 不当 critic"的完整工程模板，对 AI 代码审查/AI 安全检查场景直接可迁移。
