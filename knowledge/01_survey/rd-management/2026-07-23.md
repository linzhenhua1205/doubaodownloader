## ① Cursor Router：Auto Mode 智能模型路由 (Jul 22)

**来源**: [Cursor Changelog](https://changelog.cursor.com/) · Jul 22, 2026

### 核心设计

Cursor 的 Auto mode 底层引擎替换为 **Cursor Router**——一个智能模型路由器。它会分析每个请求的特征，分配合适的模型：

1. **每请求分类**：按任务类型和复杂度即时分类
2. **路由决策**：前缘模型处理需要它们的高难度任务，性价比模型处理其余
3. **隐藏/显示**：被路由的具体模型默认隐藏，也可选择显示

### 三种优化模式

| 模式 | 定位 | 计费方式 | 适用场景 |
|:----|:-----|:---------|:---------|
| **Intelligence** | 前缘质量 | 按路由模型费率 | 匹配最贵最强模型，日常用不起的也覆盖到 |
| **Balance** | 强质量 | 按路由模型费率 | 匹配大多数人日常使用的"前缘"模型 |
| **Cost** | 好质量 | 按路由模型费率 | 在可用最高智能和 token 开销间取最优 |

三种模式沿 **cost-intelligence pareto frontier** 排列。

### 企业管控

| 管控维度 | 粒度 |
|:---------|:-----|
| 启用范围 | 团队级别 / 用户组级别 |
| 模式限制 | 限制成员可用哪些优化模式 |
| 默认模式 | 设置团队的默认路由器模式 |
| 模型黑白名单 | 允许或禁止底层模型 |
| 强制执行 | Soft（建议）或 Hard（强制）标准化为 Auto |

**部署范围**：Desktop、Web、iOS、CLI、SDK 全线覆盖。Teams 计划默认开启，Enterprise 需 admin 从 dashboard 启用。

### 关键数据

| 指标 | 数值 |
|:----|:----:|
| 发布状态 | GA (Jul 22) |
| 可用范围 | Desktop/Web/iOS/CLI/SDK 全线 |
| 默认行为 | Teams 默认开启 |
| 路由可见性 | 默认隐藏，可选显示 |
| 路由要求 | **Grok 4.5** 作为性价比路由选项之一 |

### 研发管理意义

**Cursor Router 标志着 AI coding agent 从 "手动选模型" 迈入 "智能路由" 时代。** 传统模式要求用户根据任务复杂度手动选择模型（便宜可能不够用，贵又浪费 token），Router 将这个决策自动化了。

对企业而言，三个信号值得关注：
1. **成本优化能力**：Cost 模式在 token 开销与可用智能之间取 pareto 最优——这是企业规模化推广 AI coding 的必要组件
2. **治理深度**：per-team/per-group 的控制粒度 + 模型黑白名单 + 强制执行策略 = 已具备企业级安全管控
3. **intelligence 民主化**：Intelligence 模式让团队可以用到"日常用不起"的前缘模型，按实际被路由的模型计费而非固定高价

## ② Copilot 影响力仪表盘 GA (Jul 22)

**来源**: [GitHub Changelog](https://github.blog/changelog/2026-07-22-new-copilot-usage-metrics-impact-dashboard/) · Jul 22, 2026

### 核心设计

Enterprise admin 和 org owner 的新仪表盘，从"谁在用"升级为 **"用得多深、影响多大"**。基于 Copilot usage metrics API 中的 AI adoption phase 分类，将每阶段数据可视化为可操作的洞察。

### 采用阶段定义（基于滚动28天窗口）

| 阶段 | 名称 | 描述 |
|:----:|:-----|:-----|
| Phase 1 | **Code-first** | 使用代码补全等基础能力 |
| Phase 2 | **Agent-first** | 使用 agent 模式编码 |
| Phase 3 | **Multi-agent / Copilot app** | 多 agent 协作或使用 Copilot App |
| Passive | **已授权未活跃** | 有 license 但未深度参与 |

### 仪表盘核心指标

每个 cohort 卡片展示：

| 指标 | 含义 |
|:----|:-----|
| 人均 PR merge 数/月 | 该 cohort 的交付产出 |
| PR merge 速度（中位数） | 从创建到合并的时间 |
| 该阶段用户数 | 绝对数量 |
| 该阶段用户占比 | 相对分布 |
| 人均代码行/天 | 编码活跃度 |

**Adoption Multiplier**: Passive cohort 与活跃 Copilot 用户均值的吞吐量和速度对比（直观展示 "用了 AI 强多少"）。

**Trends**: 6 个月 cohort 增长和 PR 吞吐趋势图。

**Recommended next steps**: 针对每个 cohort 的可执行建议，推动用户向更深阶段迁移。

### 关键数据

| 指标 | 数值 |
|:----|:----:|
| 发布状态 | GA (Jul 22) |
| 可用对象 | Enterprise admin · Org owner（有 Copilot usage metrics 权限） |
| 分类窗口 | 滚动 28 天 |
| API 分类一致 | 与 Copilot usage metrics API `ai_adoption_phase` 字段一致 |

### 研发管理意义

这是 **GitHub AI 可观测性产品线的第五块拼图**（继用量指标 API、仓库级指标、AI credit pools、用量可视化之后）。影响力仪表盘解决的是企业 AI 推广中最头疼的问题：**"我投了 AI，到底起了多大作用？"**

核心价值：
1. **变被动为主动**：不是等 repo 报数，而是看 3 个阶段+passive 的分布，知道瓶颈在哪
2. **迁移路径清晰**：不止告诉你哪个阶段多少人，还给出推动到下一阶段的建议
3. **量化 ROI 叙事**：adoption multiplier 从 PR 吞吐量和速度两个维度，直接回答 "用了 AI 比没用快多少"
