## 一、GitHub Agentic Workflows Token 效率优化实证 ⭐重点

> **来源**: [Improving token efficiency in GitHub Agentic Workflows](https://github.blog/engineering/improving-token-efficiency-in-github-agentic-workflows/) | 作者: Landon Cox (MSR) & Mara Kiefer | 2026-05-07 (Updated May 13)

### 背景：AGW 的隐性成本问题

GitHub Agentic Workflows 作为自动化的 CI agent 工作流，成本在不被察觉的情况下累积（CI 是自动触发的，不像交互式 session 能即时感知成本）。

### 关键创新：Workflows 优化 Workflows

**两层自优化体系**：

| 组件 | 职责 |
|:-----|:-----|
| **Daily Token Usage Auditor** | 读取 token-usage.jsonl 产物 → 按 workflow 聚合 → 报告超支/异常（如正常4turn的任务跑了18turn） |
| **Daily Token Optimizer** | 当 Auditor 标记问题 → 分析源码+日志 → 创建 GitHub Issue 描述具体低效项并给出优化方案 |

> 注意：Auditor 和 Optimizer 本身也是 agentic workflow，它们的 token 也出现在每日报告中，形成**自我强化循环**。

### Token 数据采集架构

通过 API proxy（认证凭据的网关）统一捕获，格式不重要：
- 每条 API 调用记录：input tokens / output tokens / cache-read tokens / cache-write tokens / model / provider / timestamps
- 输出为 `token-usage.jsonl` 产物

### 三大优化发现

**① 未使用的 MCP 工具是最大浪费**

GitHub MCP 有 **40 个工具，10-15 KB schema/turn**。如果 agent 只用 2 个，剩下 38 个在每个请求中都是纯 overhead。

- Smoke-test workflows：移除未用工具后 **per-call context 减少 8-12 KB**
- Glossary Maintainer：`search_repositories` 在一次运行中被调了 **342 次**（占总 tool calls 的 58%），**完全不必要**（只扫描本地文件变更）

**② 用 GitHub CLI 替换 MCP 工具调用的数据获取操作**

MCP 工具调用 = 一次 **LLM round-trip**（tool-use JSON schema + 参数块 + 响应全部要 token）。而 `gh pr diff` 是一次**确定性 HTTP 请求**，无 LLM 参与。

两种替代策略：
- **Pre-agentic data downloads**：agent 启动前用 bash/gh 命令把 agent 必然需要的数据（diff、变更文件列表）写到文件 → agent 直接读文件
- **In-agent CLI proxy substitution**：agent 运行时按需通过轻量透明 HTTP proxy 调用 gh（安全：不暴露认证 token 给 agent）

**③ 单行配置错误导致 64-turn 回退循环**

Daily Syntax Error Quality workflow 中，test 文件被复制到 `/tmp/` 后再调用 `gh aw compile`，但 sandbox 的 bash allowlist **只允许相对路径 glob 模式**。每个编译尝试都被拒绝 → agent 用 64 个 turn 手动读源码重建编译器输出。

> **最便宜的 LLM 调用 = 你根本没发的那次**

### Effective Tokens (ET) 度量方法

为标准化跨模型成本比较，提出 ET 公式：

```
ET = m × (1.0 × I + 0.1 × C + 4.0 × O)
```

| 参数 | 含义 |
|:-----|:-----|
| m | 模型成本乘数（Haiku=0.25×, Sonnet=1.0×, Opus=5.0×） |
| I | 新处理 input tokens |
| C | cache-read tokens（权重 0.1× 因为缓存价低） |
| O | output tokens（**权重 4.0×**，最贵） |

**为什么 output 权重最高** — 这是所有主流 provider 中最昂贵的 token 类型。

### 量化结果

| 工作流 | 改善幅度 | 运行频率 | 观察期运行数 |
|:-------|:--------:|:--------:|:-----------:|
| Auto-Triage Issues | **-62%** | 平均 6.8次/天（峰值15次） | 109 runs |
| Daily Compiler Quality | **-19%** | 最多1次/天 | 12 runs |
| Community Attribution | **-37%** | 非高频 | 8 runs |
| Security Guard | **-43%** | 高频（每次 PR push） | 多 runs |
| Smoke Claude | **-59%** | 高频 | 多 runs |

**聚合节省量**：Auto-Triage Issues 在观察期内节约约 **7.8M Effective Tokens**（按优化前速率推算）。

### 关键教训

1. **大量 agent turns 是确定性数据收集** — Auto-Triage Issues 的 -62% 主要靠把数据读取移出 LLM 推理循环（每次 issue 创建都去取元数据、扫 label 是确定性操作）
2. **未使用的工具比想象的更贵** — Tool manifests 在每个 turn 都作为 context 加载
3. **单行配置错 = 64-turn runaway loop** — 工具权限配置的边界条件必须精确
4. **监控从 Day 1 开始** — 团队现在新建 workflow 时就加入 token 监控

### 下一步方向

- **Monolithic agent → subagent teams**：大 agent 拆成小团队，用更小/更便宜模型
- **从 workflow 级 → 系统级优化**：分析 workflow 内 episode 链（gathering context / reading artifacts / retrying / synthesizing），理解哪个 episode 最贵
- **Portfolio 级优化**：同一事件触发多个 workflow → 重复数据读取 → 应共享中间产物

## 四、Claude Code v2.1.207 (2026-07-11) 新修复详情

> **来源**: [Claude Code Changelog](https://docs.anthropic.com/en/docs/claude-code/changelog) — 2.1.207

### 新增
- **Auto mode 在 Bedrock/Vertex AI/Foundry 默认开启**（之前需 `CLAUDE_CODE_ENABLE_AUTO_MODE` opt-in）
- 可通过 `disableAutoMode` 在 setting 中关闭

### 重要修复
- Terminal **freeze 和 keystroke lag**：流式输出超长列表/表格/段落/代码块时不再卡顿
- **Remote managed settings** 非交互式运行（`claude -p`, SDK）不再不经过同意就永久记录
- **Prompt-injection 误报**修复：良性系统生成的对话更新不再触发假警报
- **Auto-updater** 不再覆盖 `~/.local/bin/claude` 的自定义启动脚本/symlink（`/doctor` 可报告外部管理的 launcher）
- **compound commands with cd** 仅重定向到 `/dev/null` 时不再要求权限
- **Agent teams mailbox crash loop** 修复：损坏的 mailbox 消息不再每秒反复报错
- **Background agent 名称问题**：接受 plan 后自动命名的 session 正确显示名称
- **Remote Control 网络恢复**修复：连接中断/凭证刷新后 task status 不丢失

### Bedrock 特别修复
- **AWS SSO credentials** 频繁刷新问题（每个 API 请求都请求 IAM Identity Center 新凭证）
- 默认模型改为 **Claude Opus 4.8**

### 安全修复
- **Plugin hooks/monitors/MCP headersHelper**：`${user_config.*}` 在 shell-form 命令中被拒绝（shell-injection 修复）
- **Plugin options** 不再从项目级 `.claude/settings.json` 读取（仅用户级、`--settings`、managed settings）

## 六、交叉趋势：Agentic 工作流 Token 成本管理成为新领域

### 关键观测

| 来源 | 发现 | 意义 |
|:-----|:-----|:-----|
| GitHub Agentic Workflows (MSR) | 12个生产workflows平均 -45% ET | Agentic CI 成本可系统化优化 |
| Copilot Code Review | 指令优化 -20% 成本 | 不仅仅是CI，交互式agent也有优化空间 |
| Effective Tokens 度量 | `ET = m×(I + 0.1C + 4O)` | 跨模型的统一成本度量标准 |
| MCP 工具浪费 | 10-15KB/turn schema，38/40工具闲置 | **Tool surface area = agent context overhead** |

### 新模式：Self-Optimizing Agent Fleet

GitHub 内部的 Auditor + Optimizer 模式**可复制**：
1. **API proxy 统一采集**（所有 agent framework 接入同一 proxy）
2. **Token 数据聚合 + 异常检测**（Auditor）
3. **Issue 驱动的优化建议**（Optimizer）
4. **改进后验证闭环**（ET 变化跟踪）
