## ① Linear coding sessions 支持签名提交且可强制：agent 产出从"可审查"走向"可审计" 🔥

- **来源/标题**: Linear Changelog《Signed commits for coding sessions》（Jul 30, 2026）— https://linear.app/changelog
- **要点**: Linear coding sessions（Linear Agent 用 Claude Code/Codex 写代码的会话）现支持**签名提交**——用户在设置中绑定 SSH/GPG key 后 agent 产生的提交自动签名；**Workspace 管理员可强制要求用户先上传签名 key 才能使用 coding sessions**
- **信号解读**:
  - 承接 08-06"可审查性=AI 交付新质量维度"、08-08 usage metrics 统一度量：**审查管"改得对不对"，签名管"是谁/什么机制改的"**——可追溯性成为 agent 交付物的强制属性，而非可选配置
  - "admin 可强制"是关键治理设计：不是建议而是**准入条件**（不上传 key 就不能用 coding sessions），与 08-08 MCP allowlists"policies fail closed"（配置无法验证即拦截）同构——**治理控件默认关闭、显式放行**
  - 对研发管理含义：agent 产出代码的**签名基线**将进入企业合规清单（类似提交者身份审计），"哪些提交来自 agent"从事后分析变为事前强制

## ② GitHub Copilot for Linear：编排层跨平台化的又一实证 🔥

- **来源/标题**: Linear Changelog《GitHub Copilot for Linear》（Jul 30, 2026）— https://linear.app/changelog
- **要点**: GitHub Copilot 用户可在 Linear 内**直接把 issue 分配给 Copilot 的 cloud agent**——Copilot 基于 issue 上下文在自有开发环境工作、开 draft PR、随进展更新 issue；用户可在 Linear 里**配置模型/agent 设置、base 与 working 分支**，并通过 Linear 评论引导进行中的工作
- **信号解读**:
  - 与 08-01 记录的 GitHub 侧"Copilot cloud agent for Linear GA"（Jul 23）形成闭环：**GitHub 发布能力 + Linear 落地集成**——编排不再要求开发者"去 agent 所在平台"，而是"agent 来到工作所在平台"
  - 与 08-06 Jira/OppenAI Symphony（编排与工作锚点解耦）、Cursor Slack 跨频道同向：**编排层跨平台化成为共识**——Issue 系统（Linear/Jira）是工作锚点，agent 执行在云端，模型/分支配置在 Issue 侧完成
  - 治理含义：模型选择、分支策略这些**执行参数上移到 Issue 侧配置**——编排权从开发者个体转移到团队/项目层面可见、可审

## ③ Guided Reviews 正式 GA：大 PR 审查的结构化与可解释化

- **来源/标题**: Linear Changelog《Guided Reviews are now generally available》（Jul 30, 2026）— https://linear.app/changelog
- **要点**: Linear Guided Reviews（引导式审查）**正式 GA**：把 diff 拆成聚焦区块，每块附带"改了什么、为什么"的解释；GA 版本**为更大 PR 生成**（更大上下文窗口、更低延迟），Business/Enterprise 计划免费
- **信号解读**:
  - 承接 08-06 stacked PR（拆解巨型 AI 变更）与 08-08 code review effort levels（审查深度分级）：**"AI 生成的代码量越大，审查入口越需要结构化"**——引导式审查把"审查大型 PR"从体力活变成"按区块理解+抽查"
  - 与 Copilot effort levels 同向：**审查工具正在变成 AI 时代的显式基础设施**——GitHub 管"多深"（Lite/Balanced），Linear 管"怎么组织"（区块+解释）
  - 经济学含义：审查成本随 PR 规模超线性增长，**结构化审查是控制 AI 时代 review 瓶颈的手段**（承接 08-06 Gartner 预测：agent 驱动 SDLC 提效的瓶颈在审查环节）

## ④ Coding sessions 移动化：移动端继续成为 agent 管理面

- **来源/标题**: Linear Changelog《Coding sessions on mobile》（Jul 30, 2026）— https://linear.app/changelog
- **要点**: Linear 移动端支持查看 coding session：**审查代码变更、在具体行上评论、与 Linear Agent 迭代**；My Issues → Assigned 下新增委托 issue 的 coding session 状态区，可查看进度并快速回到活跃工作
- **信号解读**:
  - 与 08-02 Cursor on iPad（完整 PR 审查移动化）、Cursor Start（iOS 远程控制 agent）同向：**移动端成为 agent 工作的"监督与引导面"**——执行在云端，人在移动端审查/引导/接手
  - "逐行评论引导 agent"与 GitHub Copilot app 的 /side 旁路问题（08-08）、/btw 侧聊同主题：**异步引导正在成为 agent 协作的标准交互**——不是打断式对话，而是锚定在产物上的评论式指令
  - 对研发管理含义：移动端审查闭环让"agent 产出验收"不再依赖工位——**管理面与执行面物理分离**成为新常态
