## ① Cursor Router — 模型路由成为 AI 研发平台竞争焦点

| 维度 | 内容 |
|:-----|:-----|
| **来源** | Cursor Changelog, Jul 22, 2026 |
| **标题** | Cursor Router |
| **链接** | https://cursor.com/changelog |
| **标签** | `模型路由` `成本优化` `Auto模式` `治理` |

**核心论点**: Cursor 的 Auto 模式由 **Cursor Router**（智能模型路由器）驱动——分析每个请求并分发给合适的模型：frontier 模型处理高难度任务，价格高效模型处理其余。

### 三种优化模式（成本-智能帕累托前沿）

| 模式 | 定位 | 计费 |
|:-----|:-----|:-----|
| **Intelligence** | Frontier 质量，匹配最贵最强模型 | 按路由模型费率 |
| **Balance** | 强质量，匹配日常主力模型 | 按路由模型费率 |
| **Cost** | 好质量 + 最大化 token 支出效率 | 按路由模型费率 |

### 管理控制（团队/组级）

- 按团队/组启用 Router，限制成员可用优化模式，设置默认模式
- **模型 allow/block 列表**（允许/禁止底层模型）
- 软/硬强制选项（标准化 Auto 模式）
- 路由模型可显示或隐藏（默认隐藏）
- **Grok 4.5 是成本效率路由的必备选项**

### 信号解读

> 这是 **AI 研发平台从"模型捆绑"走向"模型路由"的标志性事件**。与 GitHub Copilot 的多模型市场（5 厂商 6+ 系列）、Claude 的单一强模型路线形成三足鼎立。对企业的意义：**模型路由 = 成本控制的自动化**——把"选模型"从工程师的个人决策变成平台的策略决策。管理控制（allow/block + 模式限制）表明"模型治理"正成为企业级功能标配。

## ② Claude Code 委托失控防护 — Agent 安全的新红线

| 维度 | 内容 |
|:-----|:-----|
| **来源** | Claude Code CHANGELOG (2.1.212) |
| **标题** | Runaway loop protection |
| **链接** | https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md |
| **标签** | `Agent安全` `委托治理` `失控防护` `成本控制` |

**核心论点**: Claude Code 引入**会话级资源上限**，防止 Agent 委托失控（runaway delegation loops）——这是 Agent 规模化后的关键安全/成本红线。

### 上限机制（2.1.212）

| 机制 | 默认值 | 目的 |
|:-----|:------:|:-----|
| **WebSearch 调用上限** | 200/会话 | 阻止失控搜索循环（`CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`） |
| **子代理 spawn 上限** | 200/会话 | 阻止失控委托循环（`CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`），`/clear` 重置预算 |
| **MCP 工具自动转后台** | >2min | 长耗时 MCP 调用不阻塞会话（`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`） |

### 配套演进

- **2.1.219**: 子代理嵌套深度默认 3（原 1），可关闭（`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`）——放开但设限
- **2.1.216**: 并发子代理上限 20（`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`）
- **2.1.217**: `--max-budget-usd` 可停止后台子代理（达上限后拒绝新 spawn + 终止运行中 agent）——**成本硬顶**
- **2.1.214**: EndConversation 工具——Claude 可主动终止滥用会话

### 信号解读

> **"委托失控"是 Agent 时代的新安全类别**。当 Agent 能自主 spawn 子代理、无限搜索、无限循环时，失控不仅浪费 token 还会造成破坏。Claude Code 给出的答案是**资源预算化**：调用次数上限、并发上限、嵌套深度上限、成本硬顶。这与 GitHub 的 AI credit pools/session limits（8/1 追踪）构成同一治理逻辑：**Agent 能力越强，预算约束越刚性**。

## ④ Claude Opus 5 — 1M context 的模型经济学

| 维度 | 内容 |
|:-----|:-----|
| **来源** | Claude Code CHANGELOG (2.1.219) |
| **标题** | Claude Opus 5 default |
| **链接** | https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md |
| **标签** | `模型` `定价` `1M context` `fast mode` |

**核心论点**: Claude Opus 5 成为 Claude Code 默认 Opus 模型，**1M context + fast mode 定价 $10/$50 per Mtok**（输入/输出）。

### 关键变化（2.1.219）

- **1M context 窗口**：单次可处理大型代码库
- **fast mode**: $10/$50 per Mtok（输入/输出）——Opus 级质量的快速/低成本档
- Opus 4.7 退出 fast mode；`/fast` 现适用于 Opus 5 和 4.8
- **Dynamic workflows 默认 medium**（目标 <15 agents）
- **sandbox.network.strictAllowlist**：拒绝非白名单主机的沙箱命令（安全加固）

### 信号解读

> **1M context 是"把整个代码库放进上下文"的竞争节点**：Cursor 有 Composer、GitHub 有多模型、Claude 用 1M context 承载大型仓库理解。fast mode 定价（$10/Mtok 输入）表明**推理成本的竞争正在进入"价格分层"阶段**——质量、速度、成本三者可权衡。对企业的意义：1M context 可能改变"检索-生成"架构的假设（更大上下文 vs RAG 的权衡）。

## ⑤ Cursor 3.11 — Side Chats + 对话搜索 + Agent hooks

| 维度 | 内容 |
|:-----|:-----|
| **来源** | Cursor Changelog, Jul 10, 2026 |
| **标题** | Side Chats and Conversation Search |
| **链接** | https://cursor.com/changelog |
| **标签** | `对话管理` `Agent可观测性` `hooks` `检索` |

**核心论点**: 3.11 聚焦 **Agent 工作流的可观测性与上下文管理**。

### 关键能力

| 能力 | 说明 |
|:-----|:-----|
| **Side Chats** | `/side` 开旁路对话（提问/探索/查证），不打断主 Agent 对话；持久化、可回溯、可 @ 引用 |
| **对话搜索** | Cmd+K 搜索 Agent 转录（本地索引，数千会话级）；Cmd+F 会话内搜索 |
| **新 Agent hooks** | beforeSubmitPrompt / afterAgentResponse / afterAgentThought / stop / subagentStart——**观察和控制 Agent 对话本身**（提示、响应、思考、子代理、压缩、turn 完成） |
| **项目/仓库选择器重构** | 按 This Computer/Cloud/Remote 分域搜索 |

### 信号解读

> **"Agent 对话"正在成为一等公民资产**：Side Chats 支持并行探索（不污染主上下文），对话搜索让历史 Agent 工作可复用，**hooks 让组织可以构建"自校正循环"**（观察 Agent 思考→干预→改进）。这是 Agent 可观测性（observability）从"工具调用日志"向"对话级洞察"的升级——与 7/31 追踪的 GitHub usage metrics "review cycles" 指标形成呼应：**AI 研发管理需要 Agent 对话级的数据**。

## 跨信号综合分析

### 三平台治理能力对比（2026-07/08）

| 维度 | GitHub Copilot | Cursor | Claude Code |
|:-----|:-----|:-----|:-----|
| **模型策略** | 多模型市场 + 团队级模型策略 | Router 路由 + allow/block | 单一强模型（Opus 5 默认） |
| **成本控制** | AI credit pools / session limits | 优化模式（Cost/Balance/Intelligence） | --max-budget-usd 硬顶 |
| **失控防护** | — | — | subagent/WebSearch 上限 + 并发上限 |
| **度量** | 采用阶段仪表盘 / usage API | — | — |
| **审查移动化** | GitHub Mobile | iPad/iPhone 完整审查 | Remote Control |
| **对话可观测性** | Copilot app session streaming | 对话搜索 + Agent hooks | transcript 完整性修复 |

### 三条贯穿线索

1. **模型路由 = 成本控制的自动化**：Cursor Router（成本/智能帕累托前沿）与 Copilot 多模型市场殊途同归——**"选模型"从个人决策变成平台策略**，allow/block 列表 + 模式限制是标配治理工具。

2. **Agent 失控防护成为安全红线**：Claude Code 的资源预算化（调用/并发/深度/成本四重上限）是当前最系统的方案。**Agent 能力越强，预算约束越刚性**——这是从"Demo 速成"走向"生产级"的必经治理。

3. **审查与对话全面移动化/可观测化**：Cursor iPad 完整审查 + Side Chats 对话资产化，指向 **Agent 时代研发管理的基本单元正在从"代码"转向"对话与 PR"**。
