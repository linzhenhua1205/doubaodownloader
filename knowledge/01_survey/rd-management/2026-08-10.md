## ① GitHub 通知系统去复杂度：Custom thread subscriptions 废弃（08-10 当日唯一新条目）

- **来源/标题**: GitHub Changelog《Custom thread subscriptions are being deprecated》（Aug 10, 2026）— https://github.blog/changelog/2026-08-10-custom-thread-subscriptions-are-being-deprecated
- **要点**: GitHub 通知系统**移除自定义线程订阅设置**：线程级通知设置中的 Customize 选项将被完全删除，仅保留 Subscribed / Not subscribed 两项；现有自定义订阅全部转为 Subscribed（用户可自行退订过吵的线程）。官方给出的理由是"简化通知行为、降低订阅复杂度"
- **信号解读**:
  - 这是 08-07 Code Quality 撤回"自动加 Copilot reviewer"（默认行为回退）之后，**平台功能面开始"修剪"的又一信号**——不是加功能，而是删选项。AI 平台在功能膨胀后进入**去复杂度阶段**：选项越多，用户/agent 的认知负担与维护成本越高
  - 对研发管理含义：**"删功能"本身是治理动作**——通知系统的选项收敛让团队的通知基线更可预期（agent 驱动的通知/评论流也需要更简化的订阅语义），承接 08-05 记录的"复杂系统腐化防治"（契约/探测/重构）
  - 注意迁移成本：依赖 Customize 做精细通知过滤的工作流需要改为"退订+重新订阅"的粗粒度模式，平台在简化与用户既有习惯之间做了一次激进取舍

## ② Copilot CLI 会话生命周期工业化：Sessions sidebar + /worktree + /rewind

- **来源/标题**: GitHub Changelog《GitHub Copilot weekly releases — August 3》CLI 部分（Aug 7, 2026）— https://github.blog/changelog/2026-08-07-github-copilot-weekly-releases-august-3
- **要点**: Copilot CLI 新增三件套：**Sessions sidebar**（点 `<` 打开会话侧栏，快捷键 n 新建 / x 关闭 / 左右箭头切换，多并发会话集中管理）；**/worktree 实验命令**（创建隔离 worktree 并开启独立对话，可在不干扰当前工作的情况下探索变更）；**/rewind 无需 Git**（恢复 Copilot 改过的会话与文件，同时保留之后的编辑）
- **信号解读**:
  - **会话从"单次对话"升级为"可管理的工作单元"**：新建（n）/ 关闭（x）/ 切换（箭头）都有了快捷键——agent 会话开始具备"进程管理"语义，多任务并行成为 CLI 一等公民（承接 08-07 斜杠命令方法论、08-08 /side 并行探索）
  - **/worktree 是"隔离执行"的工程化**：agent 的破坏性探索被默认装进隔离工作区——这正好回应研发管理的核心诉求：**让 agent 大胆试错，但把爆炸半径限制在 worktree 内**（与 08-06 记录的"爆炸半径大默认慢"决策准则同构）
  - **/rewind 无 Git 回滚**：恢复 agent 改动而不依赖 Git 提交历史——把"撤销 agent 操作"做成独立于 VCS 的原语，降低 agent 试错的心理/操作成本；"保留后续编辑"意味着回滚是**选择性撤销**而非整段回退

## ③ live tool-call durations：可观测性下沉到工具调用层

- **来源/标题**: GitHub Changelog《GitHub Copilot weekly releases — August 3》CLI 部分（Aug 7, 2026）— https://github.blog/changelog/2026-08-07-github-copilot-weekly-releases-august-3
- **要点**: Copilot CLI 时间线现在**实时显示每个工具调用的耗时（live tool-call durations）**——用户可直接看到哪条命令慢、哪个工具是瓶颈，用于定位慢命令
- **信号解读**:
  - 承接 08-08"度量是治理的地基"：usage metrics 管"谁用了多少 agent/credit"（组织层），**live tool-call durations 管"agent 内部每个动作花多久"（个体层）**——可观测性从"用量统计"下沉到"过程追踪"
  - 对研发管理含义：**agent 的"慢"首次可归因到具体工具调用**——当 agent 任务超时，不再是黑盒"跑得慢"，而是可指出"第 N 个工具调用耗时 X 秒"。这与 08-05 记录的可观测性认知塑造（采集→传输→呈现三要素）同构，agent 执行过程首次具备"可解释的耗时剖面"
  - 经济学含义：工具调用耗时可见 → **成本（时间）归因细化到动作级**，为"哪些工具调用最贵/最该优化"提供数据支撑（呼应 08-03 Cursor Router 的按请求分类计费）

## ④ VS Code 1.132：反馈锚定产物 + 并行上下文 + 可编辑 diff

- **来源/标题**: GitHub Changelog《GitHub Copilot weekly releases — August 3》VS Code 1.132 部分（Aug 7, 2026）— https://github.blog/changelog/2026-08-07-github-copilot-weekly-releases-august-3
- **要点**: VS Code 1.132 更新四连：**集成浏览器元素级反馈**（选中网页元素、逐元素附加注释、一次提交多条精确视觉反馈给 agent）；**多语言听写**（默认使用多语言端侧模型，音频不出设备，可跟随配置语言/系统 locale/自动检测）；**/btw 侧聊**（不打断 agent 当前回合的旁路提问，**共享主会话的上下文与 prompt cache**）；**Markdown 混合编辑器**（实验性：Markdown diff 可在可编辑文档中打开，gutter 标记增删改，text/hybrid 视图可切换）
- **信号解读**:
  - **元素级反馈 = 反馈锚定在产物上的极致化**：从"文字描述问题"→"在具体元素上点选+注释"——与 08-09 记录的 Linear mobile 逐行评论、08-08 /side 旁路问题同主题：**异步引导成为 agent 协作标准交互**，且锚定粒度从"行"细化到"视觉元素"
  - **/btw 共享 prompt cache 是成本治理的隐性设计**：侧聊复用主会话上下文与缓存——并行提问不重复计费，**把"上下文复用"直接转化为 token 成本节约**（呼应知识库 08-05 记录的"Prefix Caching 使 system prompt 稳定性转化为推理成本"）
  - **Markdown 混合编辑器**：diff 不再只是"只读对比"，而是**可编辑的活文档**——审查动作与编辑动作合一，回应 08-06 stacked PR 主题（AI 巨型变更的可审查性）：审查入口从"看 diff"走向"在 diff 上直接改"
  - 多语言听写端侧化：音频不出设备——隐私与合规设计（语音输入进入企业安全基线时，端侧处理是默认选项）
