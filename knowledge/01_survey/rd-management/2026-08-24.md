## 核心发现

- **SDLC 四问 agent 化：agent apps 把工具带进 PR 上下文，人工审批保留在 rollout 决策点**（08-14 GitHub Blog，Copilot PM Sam Zhang）: 用免费试用 onboarding 的"邀请队友步骤可选项"改版走查 agent apps 工作流——①**Before build**（scope）：@amplitude[agent] 验证"完成邀请步骤是否与后续留存相关"（按 segment 拆分），数据支持"单人注册延迟该步骤、团队保留"的 rescope，写代码前先纠偏；②**As you build**（secure）：@endor-labs-github-agenthq[agent] 在 PR 评论中检查被改动依赖的已知漏洞与包风险，把依赖审查从"CI 失败后补救"提前为"改动还在眼前时的主动检查"；③**Rollout**：@launchdarkly-agent[agent] 建 feature flag（key/type/default/target/rollout 内部>5%>25%>100%）并提交代码，**若目标环境需审批则创建 approval request 而非直接生效——"A human still decides whether the rollout moves forward"**；④**Ship**：@pagerduty-agent[agent] 映射 repo→服务、查 active incidents + 近 90 天 incident 历史 + 比对 PR 改动文件与历史故障区，给出部署风险建议。治理含义：agent 覆盖 SDLC 全部四问，但**关键决策点（flag 生效/部署放行）显式保留人工审批**——与 08-21 Slack/Teams"额外审批"、08-23 AutoGPT"CI 是墙"同一条"human in the loop 制度化"主线。其他 inaugural agent apps：Packfiles（读 backlog 建迁移策略）、Miro（可视化协作接代码流）、Bright Security（端到端动态安全测试）、SonarQube（质量门禁+修复）、Octopus Deploy（部署失败诊断）。安装入口=GitHub Marketplace，@mention 或 repo Agents tab 调用。URL: https://github.blog/ai-and-ml/github-copilot/how-to-bring-your-software-delivery-workflow-into-github-with-agent-apps/
- **canvases：agent 工作流"状态显式化 + 审批点"架构模板，造价 2-3K credits 是可核算投资**（08-17 GitHub Blog，Developer Advocate Ayan Gupta）: 问题定义=协调税（coordination tax）——chat 只适合表达意图、不适合持久执行，agent 开始干活后指令/日志/转折/校验全部埋在滚动历史里，"agents can produce changes faster than any human can review them"，且多数工具不是为 multi-agent 编排设计的（丢了什么跑了、改了啥、验证了什么、哪些还需人工判断）。解法=canvases 持久共享表面，工作**可见（visible）/可导（steerable）/可审批（approvable）**。两个实战：Java Modernization Studio（assessment→planning→migration→validation gates→readiness to ship 各阶段显式可检视，团队不再反复问"什么阶段/什么决策/什么被阻塞/什么要审批"）、Site Studio（内容工作流：section 状态、草稿即时持久化、review loops、状态转换）。**可复用蓝图四要素**：①定义 workflow states；②表面化关键决策；③进度与草稿立即持久化；④保留显式人工审批点。成本量化：Site Studio ≈2,000 AI credits、modernization canvas ≈3,000 AI credits——作者明确定位为"invest in better workflow architecture"而非"spend more tokens for nicer UX"，重复工作流长期摊薄。模板发布在 awesome-copilot，/create-canvas 命令起步。URL: https://github.blog/ai-and-ml/github-copilot/how-canvases-make-agentic-workflows-visible-steerable-and-cost-efficient/
- **My work pane：多 agent 会话的集中任务台——"agent 编排的跟踪面"产品化**（08-19 GitHub Blog，Senior Dev Advocate Christopher Harrison）: Copilot app 第三篇入门系列，解决"同时跑多个 agent 会话、多个 PR/issue 在空中"的跟踪问题。My work 面板三内置视图：All（**自动按你在 app 内接触过的仓库过滤**，非全部有权限仓库）、Active（open PR/issues）、Review requests（他人请求你 review 的 PR）、Done（已关闭）；支持自定义视图与过滤器（Is: Issue + Assignee: Me 等，angle-bracket 语法或 UI 双通道）、列表/表格双布局（表格可自定义列/移动/缩放）。关键编排能力：**从 issue/PR 直接起 agent 会话**——单条起会话（以 issue 为上下文）、**多选批量起多个独立会话**、或**把指向同一 feature 的多个 bug report bundle 进单个会话**；可切换 repo（issue 仓库与代码仓库分离场景）。治理含义：agent 任务从"散落在会话里"收敛到**可查询、可过滤、可批量编排的工作台**——研发管理的"任务跟踪"层在 agent 时代被产品化接管，人工只需在 pane 层看状态与分配。URL: https://github.blog/ai-and-ml/github-copilot/github-copilot-app-for-beginners-managing-your-work/

## 趋势判断（研发管理视角）

1. **8 月 agent 工作流治理信号链闭环成型，本日补全中间三环细节**：08-04 stacked PR（可审查性）→ **08-14 agent apps（SDLC 四问全覆盖）** → **08-17 canvases（状态显式化+审批点）** → **08-19 My work pane（任务跟踪工作台）** → 08-21 Slack/Teams（团队协作面）→ 08-23 AutoGPT 5 gate + coder-to-orchestrator（方法论）。看全链条的收敛结论：**研发管理在 agent 时代的四个核心动作 = 设计状态机（canvas workflow states）+ 设计审批点（approval request/额外审批/gate）+ 设计规则墙（CI/CODEOWNERS/branch protection）+ 设计跟踪面（My work pane）**——"管人"让位于"设计墙与检查点"，且每个动作都已出现可配置的产品化载体。
2. **"人工审批点"从口头承诺变成架构要素，且出现在工具链最敏感处**：LaunchDarkly agent 在需审批环境自动降级为 approval request（flag 生效前人工裁决）、PagerDuty agent 只给"建议"不给"放行"、Slack/Teams Copilot PR 需额外 approval、canvas 蓝图第四条=保留显式人工审批点。规律：**越接近生产变更（flag rollout/部署/合并），人工裁决越被显式保留；越靠前的生成环节（scope/实现/依赖检查），agent 自主度越高**——这是内部 AI 研发平台设计权限边界时可复用的分层模板。
3. **"agent 工作流架构"成为可核算的新成本科目**：canvas 造价 2,000~3,000 AI credits 被作者显式讨论为投资而非开销；叠加 08-20 Code Quality 按 active committers 计费、08-21 AI credits/cloud sandbox 预算分层、08-22"agent 算力预算"判断——**研发预算表将新增两行：agent 运行算力（credits）+ 工作流架构设计成本（canvas 搭建与维护）**，后者本质是"协调税的资本化"，重复工作流越多越值得投入。
