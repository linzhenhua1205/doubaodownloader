## 开发者角色与组织转型

- **GitHub/From coder to orchestrator**（08-11）: 开发者角色从"写代码"转向"设计代码如何被提议、验证、评审、发布的系统"；范式=确定性边界（CI 检查/CODEOWNERS/branch protections/required reviews 产生可重复信号）+ agent 处理模糊上下文任务；实施路径：issue label 或定时 workflow 触发 → Actions 调用 agent → 输出进 PR 由确定性检查接管；建议从小处起步（issue triage、docs-and-tests sync）。URL: https://github.blog/developer-skills/career-growth/from-coder-to-orchestrator-how-agents-shift-the-role-of-a-developer/
- **GitHub/The cost of saying yes has changed**（07-17）: "写代码的成本降了，拥有它的成本没降"——AI 时代需新框架判断哪些变更真正便宜（改动→维护的长期成本转移），变更决策从"能否实现"转向"是否值得长期拥有"。URL: https://github.blog/engineering/the-cost-of-saying-yes-has-changed/
- **GitHub/Scaling 50+ services at GitHub（Universe 26 议程）**（08-13）: GitHub Lifecycle 团队用 agentic pipeline 替代跨 50+ 服务的手工修复——agents 自动分类 issue、研究代码库、写实现计划、开 draft PR；预告披露真实数字、"automation pays off most"位置与"工程师为何仍刻意手写部分代码"。URL: https://github.blog/news-insights/company-news/your-guide-to-github-universe-2026-is-here-the-schedule-just-launched/

## 开源维护与 AI 贡献治理

- **GitHub/AutoGPT：AI-first contributors 的治理门禁体系**（08-12）: AutoGPT（180K+ stars、~150 open PRs 大部分由 agent 提交）实战——文档发现性问题："agents 不会主动读你的文档，只读工作目录级别的文件"，故从 CLAUDE.md 转向集中式 AGENTS.md 并置于代码旁；可复制的 gates：①PR 不匹配模板自动关闭（工具建好后甚至不需运行，声明即改变 agent 行为）②test plan 措辞触发 skill 真实跑起应用测试 ③Codecov 80% 覆盖率阈值作为 required check（CI 即墙，agent 自查补测试）④CLA 签名需浏览器+OAuth，天然充当"人类检测器"（一周未签即关 PR）⑤review thread 需链接修复 commit 的完整 SHA（防"acknowledged 不算修复"）；被关闭的 gate：CI 失败 agent 自动评论（噪音大于价值）。URL: https://github.blog/open-source/maintainers/your-contributors-are-ai-first-now-is-your-project/
- **GitHub/AutoGPT 四条实操教训**（08-12）: ①坏 AGENTS.md 比没有更糟（到处乱放会污染上下文）②全团队 CLI 以个人用户身份触发 GraphQL rate limit，应建 GitHub App 认证 ③重审查工具成本真实（PR 测试 rig 克隆分支+8 个 agent 分工+跑全栈+截图，昂贵到只对很小/很大 PR 启用）④定期审计 authorized apps（试用后遗留授权）。URL: https://github.blog/open-source/maintainers/your-contributors-are-ai-first-now-is-your-project/
- **GitHub/不接收也是一种边界**（08-12）: 合并他人 LLM 输出是不对称的（你永久承担维护），关 PR 自行重建是合法选择；参照 SQLite"只收 bug report 不收外部代码"；关闭后重建时加 co-author（AutoGPT 800+ contributors）。URL: https://github.blog/open-source/maintainers/your-contributors-are-ai-first-now-is-your-project/
- **GitHub/Stacked PR：让 AI 生成的巨型 PR 可审查**（08-04）: 教 coding agents 把一次巨型 AI 生成变更拆成有序 stack（stacked pull requests）——AI 代码从"不可评审的巨块"变为可增量审查、按序合入的序列，解决 AI 提 PR 规模失控的可审查性问题。URL: https://github.blog/engineering/turn-one-giant-ai-generated-pull-request-to-a-reviewable-stack/
