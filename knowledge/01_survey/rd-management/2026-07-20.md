## ① 🆕🏆 GitHub Code Quality GA（Jul 20）— 代码质量产品独立发布

**来源**: [GitHub Changelog — Code Quality GA](https://github.blog/changelog/2026-07-20-github-code-quality-is-now-generally-available/) | **类型**: 产品 GA

### 产品定位

GitHub Code Quality 从 public preview 正式 GA，定位为**独立付费产品（非 Advanced Security 捆绑包）**。核心价值：AI 加速代码产出 → Code Quality 帮团队交付信任的代码。

### 技术架构

- **CodeQL 确定性分析** + **AI 辅助检测**：覆盖可维护性（maintainability）和可靠性（reliability）问题
- **Copilot Autofix**：对检测到的问题 AI 建议修复方案，人工审查后合并
- **质量门（Quality Gates）**：通过 GitHub rulesets 强制执行，含覆盖率阈值，支持 evaluate mode 逐步推行

### 内部实证

> GitHub 自身工程团队：**67.3% 的 Code Quality 发现项在 PR 合并前解决**

### GA 新增能力

| 能力 | 技术详情 |
|:-----|:---------|
| **组织级启用** | 一个设置即可覆盖整个组织下的所有仓库 |
| **代码覆盖率** | 从现有 Cobertura XML 测试报告中提取，直接在 PR 上渲染 |
| **质量门 rulesets** | 覆盖率阈值 + evaluate mode（逐步推行） |
| **API** | 管理仓库启用状态 + 拉取 findings |

### 定价模型

- **$10/活跃提交者/月**：90 天内向启用 Code Quality 的仓库推送过 commit 即计为活跃（组织内去重，bot 不计费）
- **AI 用量**：AI-assisted detection + Copilot Autofix 按量计费（无需 Copilot 订阅）
- **计算成本**：CodeQL 分析在 GitHub Actions 上运行，支持自托管 runner

### 研发管理意义

> Code Quality GA 标志着 GitHub 从 "AI 辅助编码" 正式迈入 "AI 辅助质量保证" 阶段——**代码生成加速后的首要瓶颈不再是写代码，而是确保合入的代码可维护、可靠**。这与上周 Copilot Code Review 防火墙/可配置化的方向完全一致，形成 "编码 → 审查 → 质量" 的完整 AI 治理链路。

## ② 🔧 GitHub Blog：「说 Yes 的成本已经变了」（Jul 17）

**来源**: [GitHub Blog — Dalia Abuadas](https://github.blog/engineering/the-cost-of-saying-yes-has-changed/) | **作者**: Dalia Abuadas（Copilot Agent Control Plane 团队） | **7 分钟阅读**

### 核心洞察

> "一个小的功能请求，最贵的部分曾经是写代码。现在通常是在开会决定要不要写代码。"

### 框架：AI 时代「说 Yes」的决策模型

| 阶段 | 传统模式 | AI 时代新模式 |
|:-----|:---------|:-------------|
| **决策方式** | "这需要花多久？"（猜成本） | "先让 agent 试试"（看 patch） |
| **首次产出** | 手写代码，成本高 | Agent 30 分钟出 patch |
| **核心问题** | "这个需求够不够重要？" | "这个 patch 值不值得维护？" |
| **成本核算** | 写代码很贵 | 写得便宜但拥有（own）很贵 |

### 关键原则

**First patch = price check, not product**

Agent 的首轮输出不是最终交付物，而是 **probe（探测物）**。把抽象的 scope 争论变成可审查的真实 artifact：

- 它真的只碰了你预期的文件，还是跨了 5 个包？
- 测试是自然产生的，还是这个改动拒绝被测试？
- 它保留了既有的抽象层吗？
- 6 个月后你愿意维护这个行为吗？

### 最核心的区分：便宜写 ≠ 便宜维护

| 通常便宜 ✅ | 永远不便宜 ❌ |
|:-----------|:-------------|
| 添加一个后端已存在的前端展示字段 | 改变授权/认证行为 |
| 重构一个有良好测试的 helper | 改变数据保留语义 |
| 轻量级展示性改动 | 任何触碰产品契约、隐私、计费、合规的改动 |

### 研发管理含义

> 最佳工程师不再是一律说 Yes 或一律说 No 的人，而是能 **快速定价不确定性** 的人。新技能：判断一个请求是穿实现服装的产品决策、review 比写更难、还是小到 "试试看" 就是最快负责任的答案。

> — Dalia Abuadas, Copilot Agent Control Plane 工程师

## ③ 🏢 Atlassian Teamwork Graph 连通 GitHub（Jul 2026）

**来源**: [Atlassian Blog — Bring GitHub context into Rovo with the Teamwork Graph connector](https://www.atlassian.com/blog/ai-at-work) | **产品**: Rovo

### 核心能力

Teamwork Graph 新增 GitHub connector，将以下上下文注入 Rovo：

| 数据源 | 互通方向 |
|:-------|:---------|
| **Jira issue** ↔ **GitHub PR** | PR 状态在 Jira 中可见，issue 关联 PR |
| **Confluence 文档** ↔ **GitHub 代码** | 文档引用代码片段 |
| **GitHub PR review 状态** ↔ **Rovo Agent** | Agent 理解 PR 的 review 进度和 pending 项 |

### 解决的核心痛点

> "AI 让写代码更快了。新的瓶颈是理解代码周围的工作——什么变了、为什么变、谁审查了、怎么和计划关联。"

这个上下文分散在 Jira、GitHub、Confluence 和沿途的对话中。Teamwork Graph 的目标是**统一上下文**，使 Agent 不再只看到代码 diff，而是看到完整的**变更背景**。

### 与 Atlassian 其他能力的联动

- Rovo MCP：5M+ 日调用、100 万+月活用户
- Rovo Dev：Axel Springer 试点 2.5h/人/周节省
- Agents in Jira：可作为一等公民 assign/mention/automation

## ④ 💬 Cursor in Slack 重大改进（Jul 17）

**来源**: [Cursor Changelog — Slack Improvements](https://changelog.cursor.com/slack-improvements) | **版本**: 3.11 | **GA**

### 三核心改进

| 改进 | 技术详情 |
|:-----|:---------|
| **Plan-before-execution** | 开始任务前先回复计划 → 可提前纠正方向；执行时更新状态，每步可见 |
| **多仓库环境（Multi-repo environment）** | 从 Slack 直接启动命名多仓库环境。前端/后端/共享代码分属不同 repo 时自动定位；中途如需切换仓库，弹出 `Switch repository` 按钮 |
| **跨频道/线程工作流** | 任务期间可从其他 Slack channel 和 thread 拉取上下文，更新结果可发回原始 thread 或相关 channel |

### UI 改进

- 内联按钮替换为紧凑 footer 链接
- 表格、PR、artifact 渲染更干净

### 同版搜索能力

- 侧边对话持久化（`/side`/`/btw`）：阅读/搜索专注，不中断主 agent
- Conversation Search：本地索引数千条对话，Cmd+K 搜索 agent transcript

## ⑤ 🗂️ GitHub Copilot 仓库级用量指标 GA + Code Review 配置化（Jul 17）

**来源**: [GitHub Changelog](https://github.blog/changelog/) Jul 17 | **类型**: GA + Improvement

### 仓库级 Copilot 用量指标

| 端点 | 返回数据 |
|:-----|:---------|
| `GET /repos/{owner}/{repo}/copilot/usage` | 每日每仓库 PR：Copilot coding agent 创建数、合入数 |
| `GET /repos/{owner}/{repo}/copilot/code-review` | 每日每仓库：Copilot code review 建议数（按 comment type 拆分） |

**治理意义**：从企业级聚合下沉到**仓库级颗粒度**，使团队负责人可精确追踪 agent 在具体仓库的产出和 review 覆盖。

### Copilot Code Review 可配置化

| 功能 | 详情 |
|:-----|:------|
| **自定义指令从 HEAD 分支读取** | 无需合入即可测试 review 规则 |
| **REVIEW.md / GEMINI.md / CLAUDE.md** | 支持模型特定 review 指令 |
| **防火墙默认对所有仓库启用** | 自托管 runner 暂不支持 |
| **Runner 配置与云 agent 解耦** | 可分别选配 on-prem vs cloud review |

### 同日其他更新

- **GitHub Mobile**: Copilot cloud agent 修复 PR 评论
- **Copilot app 加入用量指标 API**: 可编程查 agent 用量
