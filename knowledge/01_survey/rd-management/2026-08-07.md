## ① Copilot app 斜杠命令：把研发流程方法论产品化 🔥

- **来源/标题**: GitHub Blog《A guide to slash commands in the GitHub Copilot app》（Aug 6, 2026）— https://github.blog/ai-and-ml/a-guide-to-slash-commands-in-the-github-copilot-app/
- **要点**: Copilot app 引入斜杠命令族，把**规划/挑战/独立审查/并行编排**等研发管理动作变成一条命令，从"聊天驱动"升级为"流程驱动"
- **命令矩阵**:
  - `/plan`（计划优先）：写代码前拆解任务、识别文件/组件/依赖、列实现路径——切 Plan mode，用于新功能、大重构、bug 分诊
  - `/spar`（挑战假设）：Copilot 扮演"唱反调的队友"压力测试方案——验证架构选型、对比实现选项、审迁移计划、挑战性能优化
  - `/rubber-duck`（独立第二意见）：**用不同模型独立审查你的工作**，暴露盲区、质疑假设、catch 主模型漏掉的问题——适合复杂重构/架构决策/迁移计划
  - `/autopilot`（目标驱动实现）：给目标让 Copilot 自主走完实现+测试步骤
  - `/create-canvas`（对话→交互界面）：聊天内容转可视化/仪表盘/自定义工作流
  - `/orchestrate`（跨仓并行编排）：把跨多仓库的大任务拆成并行子任务协调推进——"认证流跨前端/后端/共享库"示例
- **信号解读**:
  - 这是**研发管理 PDCA 直接产品化**：Plan（/plan）→ Challenge（/spar）→ Review（/rubber-duck）→ Execute（/autopilot）→ Coordinate（/orchestrate）——方法论不再是文档，而是 agent 交互原语
  - `/rubber-duck` 用**独立模型做第二意见**尤其值得注意：质量保障从"同模型自查"升级为"异构模型互审"，与 08-06 记录的多 Agent 交叉验证趋势同构
  - 与昨日 Stacked PR（拆可审查粒度）呼应：**审查友好性持续成为 Copilot 核心竞争力**

## ② 组织级 PR 数量限制：治理 agent 的"产出洪泛" 🔥

- **来源/标题**: GitHub Changelog《Set pull request limits at the organization level》（Aug 6, 2026）— https://github.blog/changelog/
- **要点**: 组织级可设置 **PR 数量限制**——防止 agent/自动化在短时间内批量创建 PR 淹没队列（agent 化开发后 PR 洪泛是真实治理痛点）
- **信号解读**:
  - 承接昨日 stacked PR 主题（先把巨型 PR 拆小），本期进一步**从"拆小"走向"限流"**——两层控件合起来形成"agent 产出治理"完整闭环：粒度治理（怎么拆）+ 流量治理（拆多少）
  - 这是平台**首次面向 agent 产出规模的显式治理控件**，与 08-05 记录的"enterprise team specialization for managed settings"（组织→团队→设备→入口四级治理矩阵）同向：治理粒度继续下钻到"产出速率"维度

## ④ Code Quality reviewer 调整 + 工具退役潮：治理微调与生命周期常态化

- **来源/标题**: GitHub Changelog《GitHub Code Quality no longer adds Copilot as a reviewer》（Aug 7, 2026）— https://github.blog/changelog/
- **要点**: Code Quality（GA 于 7/20）**不再自动把 Copilot 添加为 PR reviewer**——默认行为撤回，改为用户显式选择
- **来源/标题**: GitHub Changelog《Retiring the Copilot Billing Preview app》（Aug 4, 2026）— https://github.blog/changelog/
- **要点**: Copilot Billing Preview app 退役（费用预览功能整合进主计费界面，7/07 已预告 8/03 退役）
- **来源/标题**: GitHub Changelog《Upcoming deprecation of GitHub Spark on github.com》（Aug 4, 2026）— https://github.blog/changelog/
- **要点**: GitHub Spark（AI 应用生成工具）宣布弃用预告——与 7/31 "August 2026 model deprecations" 并列，**弃用预告机制已成平台标准动作**
- **信号解读**:
  - Code Quality 撤回"自动加 reviewer"说明：**默认行为一旦产生噪音（reviewer 通知轰炸）就会引发回退**——AI 平台在"默认安全/默认自动化"之间反复校准，宁可显式也不强推
  - Billing Preview 退役 + Spark 弃用 = **工具整合与生命周期管理常态化**：AI 平台产品迭代速度快，弃用预告机制（提前 1 个月）让企业可规划迁移，避免被突然断供

## ⑥ 供应链安全补强 + Dependabot 噪音治理

- **来源/标题**: GitHub Blog《How we took malware advisories beyond npm》（Aug 6, 2026）— https://github.blog/security/how-we-took-malware-advisories-beyond-npm/
- **要点**: GitHub 把 **OpenSSF malicious-packages 数据**接入 Advisory Database——恶意包公告不再止步于 npm，覆盖更多生态；文章强调"用偏执的方式构建管道"（paranoid pipeline）
- **来源/标题**: GitHub Changelog《Customize Dependabot pull request branch names》（Aug 4, 2026）— https://github.blog/changelog/
- **要点**: Dependabot PR 分支命名可定制——依赖自动更新的"噪音面"可配置
- **信号解读**:
  - 供应链安全数据接入跨生态（npm→OpenSSF 聚合）与 7/28 的 npm publish-time malware scanning 同向：**恶意包防线从单一生态扩展到跨生态聚合**
