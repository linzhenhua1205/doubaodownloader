## 一、GitHub AI 安全体系三日完成"三支柱"构建 ⭐重点

> **来源**: [GitHub Changelog — AI security detections on PRs (Jul 14)](https://github.blog/changelog/2026-07-14-code-scanning-shows-ai-security-detections-on-pull-requests/)

### 1.1 AI Security Detections on PRs 🆕

**核心**: GitHub 的 AI 检测引擎现在直接在 PR 上运行，覆盖 CodeQL 不支持的语言和框架。

| 维度 | 详情 |
|:-----|:------|
| 覆盖范围 | 超越 CodeQL 内置分析的语言和框架，减少代码库盲区 |
| PR 集成 | 发现直接出现在 PR 上，标注 `AI` 标签与 CodeQL 结果区分 |
| 运行方式 | PR 创建或更新时自动触发，结果流式返回，不等所有分析源完成 |
| 是否阻塞合并 | **不影响**（informational） |
| 激活条件 | Enterprise 策略允许 → 组织启用 → 仓库已开启 CodeQL default setup |
| 计费 | 消耗 AI Credits |
| 许可要求 | GitHub Code Security (Advanced Security) + Copilot license |

**技术细节**: AI 检测引擎依赖 CodeQL 基础设施运行（不是 CodeQL 本身做 AI 分析），目前 CodeQL default setup 是前提条件。

### 1.2 GitHub AI 安全"三支柱"格局（7月10-14日）

过去 3 个工作日，GitHub 连续发布了 3 个 AI 安全能力，形成了完整的覆盖层面：

| 层次 | 能力 | 日期 | 覆盖阶段 |
|:-----|:-----|:-----|:---------|
| **Layer 1: 前置扫描** | Copilot App `/security-review` | Jul 14 | 本地编码时按需扫描 |
| **Layer 2: PR 自动检测** | AI Security Detections on PRs | Jul 14 | PR 提交时自动运行 |
| **Layer 3: 自动修复** | Agentic Autofix for Code Scanning | Jul 10 | 告警后自动修复+验证闭环 |

**三层覆盖了"编码→提交→告警修复"全链路**，且全部消耗 AI Credits 统一计费。这是 agent 安全工程的重要里程碑——安全不再依赖独立工具链，而是嵌入 agent 工作流的三道防线。

## 二、Claude Code v2.1.210：安全硬化 + 可用性打磨

> **来源**: [Claude Code Changelog (Jul 14)](https://docs.anthropic.com/en/docs/claude-code/changelog)

### 2.1 安全硬化（4项关键修复）🛡️

| 问题 | 修复 | 严重性 |
|:-----|:-----|:-------|
| **间接 prompt injection** | Agent tool 硬化，防范 subagent 读取的内容包含注入 | 🔴 高危 |
| **Worktree 子 agent 隔离** | "worktree" subagents 能对主仓库执行 git 修改命令 → 修复到只能操作自己的独立 worktree | 🔴 高危 |
| **Hook 超时误报为"用户拒绝"** | hook 回调超时 → 模型收到"用户拒绝了该操作" → unattended sessions 停等 | 🟡 中危 |
| **Ultracode 触发误判** | ultracode 关键词在非人类输入（webhook payloads / relayed PR comments）上触发 | 🟡 中危 |
| **Write(path) 权限规则警告** | 启动时警告 — 应使用 Edit(path) 或 Read(path) 替代 | 🟢 低危 |

**技术细节**: Hook 超时被误报为用户拒绝是最隐蔽的问题——在 unattended / background 模式下，agent 以为用户拒绝了某个操作，主动停等。对于需要全天运行的 agent 来说这等于无声死机。

### 2.2 可用性改进

| 改进 | 详情 |
|:-----|:------|
| **实时耗时计数器** | 长耗时 tool call 的折叠行上显示实时计时，不再显示"卡住了" |
| **Auto mode 分类器升级** | 外部 session 默认使用 Sonnet 5 作为权限分类器，在 session 首次请求时验证并锁定 |
| **Memory 写入保护** | MEMORY.md 索引超读上限 → 显式报错而非静默截断 |
| **Dataviz skill 改进** | 感知 OKLab 色差 + 重新校准色盲阈值 |
| **Screen reader 增强** | 切换 permission mode 时语音播报 |
| **Agent view 标识** | ← 退出的 session 保持视觉标记，鼠标/箭头移动也不丢失 |

### 2.3 关键 Bug 修复

- Paste markers 泄漏到外部编辑器（粘贴后出现 stray È/É 字符）
- `claude attach` 有时报 "job not found" → 改为等待 daemon 就绪
- Plugin MCP 在 session 中间重新同步时被错误关闭
- Grep content mode 翻页到结尾后报 "No matches found"
- 技能/命令中 `$1`/`$2` 占位符被静默剥离 → 保留原样
- Background workers crash-loop（client 重置连接时）

## 三、本期交叉趋势

### 3.1 AI 安全扫描"三支柱"格局确立

GitHub 三天内补全了 AI 安全三层覆盖：**本地扫描**（Copilot App `/security-review`）→ **PR 自动检测**（AI Security Detections）→ **自动修复**（Agentic Autofix + CodeQL 验证闭环）。三层共用 AI Credits 计费体系。

与此对照，Claude Code v2.1.210 同一天修复了 **4 项安全相关漏洞**（prompt injection / worktree 隔离 / hook 误报 / ultracode 误触发）。两条路线的安全焦点差异明显：
- **GitHub**: 外部安全扫描（覆盖 CodeQL 不覆盖的语言）
- **Claude Code**: 内部安全隔离（prompt injection / agent 隔离 / 权限规则优化）

### 3.2 Agent 安全治理从"工具"进入"平台"阶段

过去两周（7月1-14日）的治理类发布：
- GitHub: MDM + OTel + Code Quality + Per-user budgets + AI credit pools + Managed settings — 全部 GA
- Claude Code: `CLAUDE_CODE_PROCESS_WRAPPER` (corporate launcher) + managed settings 防篡改 + hook 修复
- JetBrains/VS: MCP 信任验证（指纹比对）+ 本地沙箱 + BYOK

**趋势判断**: 企业不再只是"管控 agent 是否能用"，而是进入"agent 安全治理平台化"阶段——身份认证（BYOK/OAuth）、运行时隔离（沙箱/worktree/指纹）、审计追踪（OTel/hook/usage tracking）、预算归因（per-user AI credits）。

- **Cursor**: 自 Jul 10 v3.11 后无新 changelog 或 blog 发布，v3.11 的 side chats + conversation search + cloud agent hooks 仍是最近特性
