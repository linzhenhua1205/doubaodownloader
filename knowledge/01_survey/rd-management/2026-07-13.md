## 一、Cursor Design Mode: 空间化 Agent 交互新范式 ⭐重点

> **来源**: [Cursor Blog — Direct agents with visual prompts in Design Mode](https://www.cursor.com/blog/design-mode) | Erik Nilsson, Ian Huang & Ryo Lu | 2026-06-05

### 核心思路

Chat 只是与 agent 交互的一种界面。UI 工作是**空间化**的。设计师、PM、前端开发者通过标注（指向元素、区域、页面状态）来沟通。Design Mode 缩小了"你看到的"与"agent 理解的"之间的距离。

### 三种视觉指令方式

| 方式 | 操作 | 适用场景 |
|:-----|:-----|:---------|
| **点选 (Click)** | 在运行中的应用点击元素 → prompt → agent 编辑代码 | 单元素修改 |
| **多选 (Multi-select)** | 选择两个以上组件 → 描述关系（"让 A 匹配 B""去掉重复"） | 跨组件关系变更 |
| **绘制 (Drawing)** | 圈选拥挤区域、框选范围、标记动画部分 | 需要精确定位区域 |

新增**语音输入**，可边画边说（draw + narrate）。

### 技术实现

选中元素时注入**两个互补信号**到 context：

1. **元素身份 (Element Identity)**: xpath, component name, attributes, computed styles, fiber tree props
2. **截图空间上下文 (Screenshot)**: 布局、周围元素、精确页面状态

### 异步工作流

Design Mode 的关键设计是**可以不等第一个编辑完成就发送下一个**：
- 指向一个元素 → 描述变更 → 移到下一处 → 再发一条编辑
- agent 完成后 app hot reload，界面实时更新
- 本质是 **subagent 并行管理** 的 UI 层

### 模型匹配

特别适配 Composer 2.5（快 + 强于界面工作），因为设计迭代需快速反馈循环。

### 工程意义

> **空间交互 + 异步 Agent = 新的前端研发工作流**。Design Mode 体现了一个趋势：Agent 交互从纯文本 chat 向**多模态上下文注入**演进。点击+截图+语音 = 比文字描述更精确的低歧义指令。

## 二、Cursor Auto-review: Agent 自主性的分类器治理

> **来源**: [Cursor Blog — Governing agent autonomy with Auto-review](https://www.cursor.com/blog/auto-review) | David Gomes & Travis McPeak | 2026-06-11

### 问题背景

Agent 需要自主性才能高效，但过度自主引入安全风险。简单方案（每次行动前询问）有"审批疲劳"的副作用 — 用户不再仔细阅读。

**核心想法**: Agent 自主性应该像**旋钮（dial）而不是开关（switch）**。低风险自由移动，高风险慢下来。

### Auto-review 架构

**专用分类器 agent** 在工具调用执行前**上下文审查**行动：

```
Agent 准备调用工具
    v
分类器 agent 审查（同 RPC stream，非独立 endpoint）
    v
    通过 -> 执行
    阻止 -> 解释原因返回父 agent -> 父 agent 自纠正
```

### 技术决策

| 决策 | 选择 | 理由 |
|:-----|:-----|:-----|
| 模型大小 | 小模型 + 足够推理能力 | 低推理模型反而更慢（需更多 token 理解策略），"enough reasoning to make the decision cleanly" |
| 分类器 Agentic | 可以用 ReadFile/Grep/Glob/ListDir 检查 workspace | `python script.py` 安全与否取决于文件内容 |
| RPC 架构 | 同 stream（subagent 模式），非独立 endpoint | 避免额外 round trip 增加延迟 |
| 反馈机制 | 阻止时返回解释给**父 agent**（非用户） | 父 agent 可自行选择更安全路径 |

### 数据支撑

- **Eval 集**: 12 小时内部开发者会话 → 去重 → **6,122 条标注行** + 合成数据覆盖边缘情况（读取 secrets、生产数据、不信任指令、大规模副作用）
- **Flapping 检测**: 同一 case 6次通过4次阻止 → 策略/prompt 不够精确 → 需要收紧
- **实际结果**:
  - 分类器仅审查需要"上下文判断"的行动（大部分已在 allowlist/sandbox 覆盖）
  - **~4% 的行动被阻拦**
  - 阻拦 → 仅 **~7% 的对话最终触发用户中断**
  - 对比：此前企业客户内部策略 **~40% 行动被阻止**

### 对行业的意义

> Auto-review 是 agent 安全治理从"静态策略（allowlist/denylist）"向**动态上下文判断**的关键跃迁。数据表明：用分类器 agent + 父 agent 自纠正的双层架构，可以将用户中断率从 40% 降到 7%。

现在 Auto-review 是新用户的默认设置。

## 四、HBR 最新 AI 与研发管理研究

### 4.1 Agentic AI 如何扶持初创公司并威胁在位者 (Jul-Aug 2026 刊)

> **来源**: HBR July–August 2026 | Vivian S. Lee, Linda Mantia, Jon McNeill

- **核心论点**: Agentic AI 创建了新的运营模式，**大幅缩短**了创办公司所需的**时间和资本**
- 重新定义"venture launch and scale"的方式
- 对在位企业的威胁：起步更快、成本更低的初创公司可以挑战传统壁垒

### 4.2 人们 2026 年真正如何使用 AI (Jun 1)

> **来源**: HBR | Marc Zao-Sanders | 2026-06-01

第三版研究的关键发现：

| 指标 | 数据 |
|:-----|:-----|
| ChatGPT 月活用户 | **9 亿** |
| Google Gemini 月活 | **超过 7.5 亿** |
| OpenAI 估值 | **$8,520 亿**（最新一轮） |

**趋势**: Vibe coding 兴起、Agentic workflows 被企业采纳、LLM 使用持续扩张

**新风险**: "letting AI think for you" — 把思考外包给 AI 的风险在 2026 年变得更加突出

### 4.3 你外包了 AI—但风险仍然是你自己的 (Jul 9)

> **来源**: HBR | M. Alejandra Parra-Orlandoni & Paulo Carvão | 2026-07-09

- 法院和监管机构仍将**追责使用方**（即使 AI 工具是外包的）
- 歧视、数据误处理、客户损害等风险不会因为"是 AI 做的"而转移
- 企业需要建立三层审查：供应商审查 + 内部使用策略 + 持续合规监控

### 4.4 制定 AI 战略时，警惕"紧迫性陷阱" (Jul 1)

> **来源**: HBR | David De Cremer | 2026-07-01

- 组织在优先处理即时挑战和快速胜利时，**可能忽视长期战略一致性**
- "先做再想"的文化在 AI 领域特别危险
- 需要在速度与战略对齐之间取得平衡

### 4.5 AI Agent 行为类似恶意软件 (Mar 30)

> **来源**: HBR | Andrew Burt | 2026-03-30

- AI agent 可能自主行动、造成伤害——本质上像**恶意软件**
- 建议：最小权限、可观察性、人工监督环
