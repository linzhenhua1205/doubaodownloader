## ① 安全扫描"配置即代码"规模化 — code scanning 默认设置集中治理 🔥

- **来源/标题**: GitHub Changelog《Customize code scanning default setup at scale》（Aug 04, 2026）— https://github.blog/changelog/2026-08-04-customize-code-scanning-default-setup-at-scale/
- **要点**: 新增 repository property `github-codeql-config-file`，可将自定义 CodeQL 配置文件应用到 default setup——**无需在每个仓库维护 Actions workflow 文件**，即获得 advanced setup 的细粒度控制 + default setup 的低维护性
- **能力细节**: 配置可与内置默认值合并（增删查询/排除路径/威胁模型）；组织级可设默认值并决定仓库能否覆盖；**中心仓库一份配置，全组织自动拾取**，也可先在单仓库试点再推广
- **跨仓库引用新语法**: 只需仓库名即可引用其他仓库的配置文件（缺省回退到同组织 main 分支默认路径）；私有配置仓库通过 **Git Source private registry** 授权，不再需要 workflow 里管理 token
- **发布范围**: github.com GA + 随 GitHub Enterprise Server 3.23 发布
- **信号解读**:
  - 这是"**配置即代码（config-as-code）**"从 CI/CD 扩展到安全扫描治理的标志性事件——安全策略像代码一样**版本化、集中化、可审计**
  - 组织级强制（禁止覆盖）+ 团队定制（允许覆盖）的二段式授权，与 08-04 记录的"托管设置团队专项化"（Aug 03）同构——**平台治理的共同模式：集中默认 + 分级授权**
  - 对研发管理含义：安全左移从"工具接入"进入"**策略编排**"阶段，安全团队可像管理代码库一样管理安全基线

## ② GitLab→GitHub 迁移 GA — 平台迁移自助化 🔥

- **来源/标题**: GitHub Changelog《Migrate from GitLab to GitHub with GitHub Enterprise Importer》（Aug 03, 2026）— https://github.blog/changelog/2026-08-03-migrate-from-gitlab-to-github-with-github-enterprise-importer/
- **要点**: GitLab.com 与 GitLab Self-Managed → GitHub Enterprise Cloud 的迁移经 GEI **全面 GA**，可完全自助
- **能力细节**: `gh gl2gh` CLI 扩展支持**单仓库迁移或脚本化批量迁移**；迁移归档可存 GitHub-owned blob storage 或自备 **AWS S3 / Azure Blob**；支持 Enterprise Cloud（github.com 与 ghe.com），不支持 Enterprise Server
- **信号解读**:
  - 平台迁移从"专家服务"走向"**自助 CLI 工具**"——研发平台切换成本显著下降，"平台锁定"松动
  - 批量脚本化 = 迁移可纳入**研发流程自动化管线**，对大型组织的平台整合（多 GitLab 实例合并）是直接杠杆
  - 与 07-31 归档的"Copilot 作为研发流程 OS"线索叠加：**平台竞争从功能比拼转向迁移成本博弈**——GEI 免费 GA 是 GitHub 降低对手用户切换门槛的战略动作

## ③ 协作治理微调 + AI 低代码退潮 — Spark 弃用与权限细化

- **来源/标题**: GitHub Changelog《Upcoming deprecation of GitHub Spark on github.com》（Aug 04, Retired）、《Triage role can bypass issue creation restrictions》（Aug 03）— https://github.blog/changelog/
- **要点 A — GitHub Spark 弃用**: GitHub 宣布 **Spark（AI 驱动应用构建/低代码平台）将弃用**——2024 年推出的"用自然语言生成应用"实验性产品生命周期结束
- **要点 B — Triage 角色权限细化**: **Triage 角色可绕过 Issue 创建限制**（bypass issue creation restrictions）——协作治理按角色微调权限边界，减少流程摩擦
- **信号解读**:
  - Spark 弃用 = **AI 低代码/无代码平台退潮信号**：自然语言生成应用的"零代码"叙事让位于 Agent 直接改真实代码库（Cursor/GitHub Copilot 路线）——研发管理启示：**评估低代码工具时警惕平台生命周期风险**
  - Triage 权限细化延续 08-04"控制粒度下钻"线索：**治理微调颗粒度到角色×操作×限制条件**，流程摩擦成为优化对象
  - 两者共同指向：平台在"**收编过宽的能力承诺**（低代码）"与"**放宽过紧的流程约束**（triage bypass）"间双向调优

## ④ Cursor iPad + Inbox — 移动端成为 Agent 管理面 🔥

- **来源/标题**: Cursor Changelog《Cursor, now on iPad》（Jul 29, 2026）— https://cursor.com/changelog
- **要点**: Cursor for iPad 全付费计划可用；**iPhone/iPad 新增 Inbox** 与**覆盖全 PR 的 review 体验**（评论/检查/批准/改审查人/提示 agent 解决评论）
- **能力细节**: iPad 分屏可边看 review 边跑多个 agent（sidebar chats 固定）；截图标记用 Apple Pencil 直接画批注；**Bitbucket 与 Azure DevOps SCM 支持**；多 PR 会话可逐一打开每个 PR；应用内直接切换所属团队
- **信号解读**:
  - **"agent 输出→合并 PR"全路径移动化**——研发管理者/审查者的工作台从桌面扩展到移动端，PR review 不再是"回到电脑才能做"的阻塞点
  - Inbox = **Agent 活动作为一等公民的消息流**：像邮件/IM 一样组织 agent 进度与待办，对应 08-03 记录的"agent 会话状态管理"主题的消费者侧形态
  - SCM 支持扩展到 Bitbucket/Azure DevOps = **Cursor 脱离 GitHub 依赖**，多平台研发团队的统一 AI 工具层成形

## ⑤ Cursor 生态补充 — Slack 计划先行 + 印度本地化定价

- **来源/标题**: Cursor Changelog《Improvements to Cursor in Slack》（Jul 17, 2026）、《Cursor Start》（Jul 28, 2026）— https://cursor.com/changelog
- **要点 A — Slack 集成增强**: Cursor 在 Slack 中**先分享计划再开始执行**（plan before it starts），人可早期干预重定向；支持**命名多仓库环境**（前端/后端/共享代码跨仓库访问）；可跨频道/线程读取上下文并回帖
- **要点 B — Cursor Start 印度定价**: 新增 **₹649/月（约 ¥55）** 本地定价计划，UPI 支付，含 Grok 4.5 / Composer 模型、常驻云 agent、iOS 远程控制——让每日 agentic 开发对新市场可负担
- **信号解读**:
  - "先计划后执行" = **Agent 透明性设计**：与 07-31 归档的"Harness 8 步工作流中 plan 步骤"呼应——**计划先行正在成为 agent 协作的标准交互协议**
  - 多仓库环境 = Agent 从"单仓库助手"走向"**跨仓库系统工程师**"，对应 08-03 多仓库 context 主题的平台化落地
  - 印度本地定价 = **Agent 工具进入新兴市场下沉阶段**（对标 GitHub Copilot 全球分层定价），研发工具采购的本地化/可负担性成为竞争维度

### 主题聚类

- **配置即代码向安全与迁移扩展**（①②）: code scanning 配置集中化 + 迁移工具 CLI 化——研发管理基础设施的"**可编程性**"从 CI/CD 扩展到安全策略与平台切换
