## ① Harness 极简工作流 — "驾驭工程"的实践手册

| 维度 | 内容 |
|:-----|:-----|
| **来源** | GitHub Blog, Jul 27, 2026 |
| **标题** | The harness is all you need (mostly) |
| **作者** | Burke Holland (GitHub Copilot 团队) |
| **链接** | https://github.blog/ai-and-ml/the-harness-is-all-you-need-mostly/ |
| **标签** | `Harness Engineering` `Copilot` `工作流` `研发效能` |

**核心论点**: 在 AI 工具爆炸的时代，**最大的生产力提升来自对 harness（驾驭层）的深刻理解，而非追逐新工具/新提示词**。提出了一套可复制的 8 步工作流：

### 8 步工作流

| 步骤 | 操作 | 关键原则 |
|:----:|:-----|:-----|
| 1 | **选一个工具，坚持用** | CLI/App/VS Code 共享同一 harness，学会一个到处能用 |
| 2 | **开启 YOLO 模式** | Agent 需要自主权才能体现生产力；在 Codespaces/Dev Container 中运行保安全 |
| 3 | **先做原型** | "给我 20 个 date picker 原型"——用低成本的视觉原型发现隐藏需求 |
| 4 | **系统化计划** | 用 `/plan` + `/grill-me` skill 让模型暴力追问边界条件 |
| 5 | **Autopilot 实现** | 内置循环确保模型完成计划的每一项；自动编排 Explore/General Purpose 子 Agent |
| 6 | **人工审查+迭代** | "不要满足于 AI 产出的'够好'——对质量要 ruthless" |
| 7 | **Rubber Duck 审查** | 用不同模型家族的模型交叉审查（如 GPT 产出 → Sonnet 审查） |
| 8 | **收工** | 新功能开新 session，避免上下文污染 |

### 关键洞察

- **"大部分今天看起来神奇的 AI 咒语，明天就会变成反模式"**——追求简单可重复的结果
- Rubber Duck 审查可结合 Autopilot 形成循环：`/autopilot rubber duck → 审查调整 → 重复直到双方模型都认为只剩边际收益`
- 推荐使用中等模型（GPT 5.6 Terra / Claude Sonnet）+ 中等推理，**不切换模型以利用 prompt 缓存节省 token**

## ② "说 Yes 的成本变了" — AI 时代的范围决策经济学

| 维度 | 内容 |
|:-----|:-----|
| **来源** | GitHub Blog, Jul 17, 2026 |
| **标题** | The cost of saying yes has changed |
| **作者** | Dalia Abuadas (Copilot Agent Control Plane 团队) |
| **链接** | https://github.blog/2026/07/17/the-cost-of-saying-yes-has-changed/ |
| **标签** | `工程管理` `范围决策` `代码审查` `AI经济学` |

**核心论点**: "写代码的成本下降了，但**拥有代码的成本没有下降**。" 这颠覆了传统的范围决策直觉。

### 新旧决策模型对比

| 维度 | 旧模型（AI 前） | 新模型（AI 后） |
|:-----|:-----|:-----|
| **最贵环节** | 写代码 | 讨论是否写代码的会议 |
| **决策方式** | 实现前讨论 → 范围辩论 | 先让 Agent 生成 patch → 用证据讨论 |
| **"小需求"判断** | 2 天辩论 → "可能 1-2 天" | 30 分钟生成 diff → 看实际影响 |
| **核心问题** | "这算不算 scope creep？" | "真正的成本在哪里？" |

### 关键框架

1. **第一版 patch 是价格探测器，不是交付物**——用它回答：触及哪些文件？是否跨越 5 个包？测试是否显而易见？6 个月后你愿意拥有这段代码吗？
2. **"便宜写"≠"便宜拥有"**——千行 diff 技术上通过但没人想拥有 = 延期成本，不是便宜
3. **便宜变更 vs 贵变更的分类标准**：
   - 显示已有后端字段 → 通常便宜
   - 改授权行为 → 不便宜，无论 diff 多干净
   - 重构有测试的 helper → 通常便宜
   - 改数据保留语义 → 不便宜
4. **范围约束从"实现前"移到"审查时"**——用约束条件（最小 patch、现有 feature flag、不改公开契约、加测试、列出风险文件）让 Agent 先试

### 信号解读

> 这是 AI 时代**工程管理方法论**的重要文献。核心洞察：**"给不确定性定价"是 AI 时代工程师的核心新技能**——不是 say yes 或反射性 say no，而是快速判断审查成本是否高于实现成本。

## ③ 更好的工具反而让 Copilot CR 变差 — Agent 工具指令设计的工程教训

| 维度 | 内容 |
|:-----|:-----|
| **来源** | GitHub Blog, Jul 10, 2026 |
| **标题** | Better tools made Copilot code review worse. Here's how we actually improved it. |
| **作者** | Napalys Klicius (GitHub Copilot 代码审查团队) |
| **链接** | https://github.blog/engineering/2026-07-10-better-tools-made-copilot-code-review-worse/ |
| **标签** | `Agent设计` `代码审查` `工具指令` `Benchmark` |

**核心论点**: 将 Copilot CR 的代码探索工具从专用实现迁移到共享的 Unix 风格工具（grep/glob/view）后，**审查成本反而上升、发现问题减少**。问题不在工具本身，而在**工具指令（tool instructions）塑造了 Agent 的工作流行为**。

### 实验过程

| 阶段 | 行为 | 问题 |
|:-----|:-----|:-----|
| **迁移前** | 专用工具（list_dir/search_file/search_dir/read_code）| 返回额外上下文，token 成本高，但适合早期模型 |
| **迁移后（初版）** | 共享 CLI 工具（grep/glob/view）| Agent 像"浏览仓库"而非"审查 PR"——广撒网、猜测路径、累积无关上下文 |
| **迁移后（优化）** | 同工具 + 重写工具指令 | 从 diff 出发→grep 缩小→glob 定位→view 精确读取→决策 |

### 关键发现

- **工具指令是 Agent 的"API 文档"**——模糊的 API 文档让开发者困惑，模糊的工具指令让 LLM 低效
- 从"通用编码助手"到"代码审查者"的指令重写，将 Agent 节奏从 **"浏览→读取→再搜索"** 变为 **"提问→缩小→读取→决策"**
- **结果：平均审查成本降低约 20%**，审查质量不变
- **反例：同一套指令在 CLI 中不生效**——因为 CLI 是交互式编码助手，审查是 anchored to diff 的窄任务。**共享工具可行，但指令必须匹配产品形态**

### 信号解读

> 这是 **Agent 工程实践** 的教科书级案例。核心教训：**工具质量 ≠ Agent 质量**。Agent 的行为由工具指令（tool descriptions + system prompt）塑造，而非工具本身。给 Agent 更好的工具但错误的指令 = 给新手一把手术刀但不教他怎么用。

## ④ Stacked Sessions + Stacked PRs — AI 辅助大型重构的新范式

| 维度 | 内容 |
|:-----|:-----|
| **来源** | GitHub Blog, Jul 30, 2026 |
| **标题** | Stacked sessions and pull requests in the GitHub Copilot app |
| **作者** | Cassidy Williams (GitHub 开发者关系高级总监) |
| **链接** | https://github.blog/ai-and-ml/github-copilot/stacked-sessions-and-pull-requests-in-the-github-copilot-app/ |
| **标签** | `Copilot App` `Stacked PRs` `重构` `研发流程` |

**核心论点**: 用 AI 做大项目时，最大的诱惑是做一个 10,000 行的巨型 PR——这其实是**新形式的拖延**。Stacked Sessions + Stacked PRs 提供了正确的分解方式。

### Stacked PR 机制

```
Session 1: 前端现代化（样式迁移）
  +-> PR #1: 基础样式 -> merge to dev
      +-> Session 2: 移除 react-bootstrap（堆叠在 #1 之上）
          +-> PR #2: 依赖替换 -> merge to dev
```

- **Stacked Session**: 每个 session 继承前一个 session 的上下文和代码变更，自动形成依赖链
- **Stacked PR**: 每个 PR 的 target branch 是链中下一个 PR 的分支，最终汇聚到 main
- Agent 自动处理：创建 PR → 建立堆叠关系 → 继承上下文 → 生成新 plan → 执行

### 实战案例

作者用 Copilot App 将一个 **2014 年的 React 15 + Less + Bootstrap 老项目** 现代化：

| 尝试 | 方法 | 结果 |
|:----:|:-----|:-----|
| 1 | One-shot 全量重构 | ❌ 失败——作者自己忘了之前有部分迁移的 dev 分支 |
| 2 | 切换到 dev 分支，重新生成 plan | ✅ 样式迁移完成 |
| 3 | 发现 react-bootstrap 兼容问题 | → 新 session 堆叠，单独 PR |
| 4 | 最终交付 | 2 个清晰可审查的 PR，而非 1 个巨型 PR |

### 信号解读

> Stacked PRs 是解决 **AI 辅助开发中"范围蔓延"问题** 的关键基础设施。它让开发者可以自然地"先交付一批，再在基础上继续"，而不必在"一个巨型 PR"和"人工拆分上下文"之间二选一。这是 **研发流程优化的产品化方案**。

## ⑤ Copilot vs 裸 API — Harness 的量化价值与 BYOK 策略

| 维度 | 内容 |
|:-----|:-----|
| **来源** | GitHub Blog, Jul 22, 2026 |
| **标题** | Copilot vs. raw API access: What are you actually paying for? |
| **作者** | Andrea Griffiths (GitHub 开发者关系) |
| **链接** | https://github.blog/ai-and-ml/github-copilot/copilot-vs-raw-api-access-what-are-you-actually-paying-for/ |
| **标签** | `Copilot` `成本模型` `Harness` `BYOK` `SWE-bench` |

**核心论点**: "Copilot 现在按 API 费率计费——那为什么还要付 Copilot 的钱？" 答案是：**Harness 层有可量化的价值**。

### Harness 量化评估

在 SWE-bench Verified、SWE-bench Pro、SkillsBench、TerminalBench、Win-Hill 等基准测试中，**保持模型/任务/上下文窗口/推理力度/工具选择/MCP 服务器不变**，Copilot CLI vs 裸模型厂商 harness：

- **任务完成率持平**（task-resolution parity）
- **大多数配置下 token 消耗更少**
- TerminalBench 2.0 每个 agent-model 配置至少跑 5 次以测量成本和完成方差

### 决策框架

| 场景 | 推荐方案 | 原因 |
|:-----|:-----|:-----|
| 构建产品功能/内部 Agent 平台/评估流水线 | **裸 API** | 你需要控制 prompt、检索、路由、重试、日志、安全模型、计费 |
| 从 Issue 到已审查 PR 的日常开发 | **Copilot** | Editor + Repo + Terminal + PR + 组织策略已连接 |
| 有现成云厂商合同/承诺消费 | **BYOK** | 保持商业关系，Copilot 提供工具层，厂商承担 token 账单 |

### BYOK 现状（公开预览）

- 支持：Anthropic、AWS Bedrock、Google AI Studio、Microsoft Foundry、OpenAI、OpenAI-compatible、xAI
- Copilot CLI 额外支持本地模型（Ollama）
- 企业管理员可控制哪些模型启用

### 信号解读

> Copilot 从"固定月费"转向"按用量计费"是 AI 研发工具的**定价模式范式转变**。这使企业可以精确衡量 AI 辅助开发的 ROI，同时 BYOK 策略降低了供应商锁定风险。**"Harness 独立于模型"** 正在成为 AI coding 平台的竞争焦点。
