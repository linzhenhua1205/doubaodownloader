## 一、Claude Code v2.1.211：企业安全硬化 + 内存/性能大修 ⭐重点

> **来源**: [Claude Code Changelog — v2.1.211 (Jul 15)](https://docs.anthropic.com/en/docs/claude-code/changelog)

**继 Jul 14 v2.1.210 修复 4 项高危安全漏洞后，v2.1.211 在整个安全-可用性-性能三角上全面加固**，共 62 项变更（20+ 安全/修复 + 10+ 性能 + 30+ 可用性）。

### 1.1 新增企业级安全能力

| 特性 | 详情 |
|:-----|:------|
| **`CLAUDE_CODE_PROCESS_WRAPPER`** 🆕 | 所有 Claude Code 自 spawn 的子进程（agent view + background service）通过指定包装器可执行文件启动。**企业可在 wrapper 中嵌入审计/日志/安全策略** |
| **Permission preview 字符中和** 🆕 | relay 到 chat channels 的 permission preview 在展示前对 **bidirectional-override、zero-width、look-alike 引号** 做字符中和，防止 tool 输入在视觉上篡改审批消息 |
| **Hook ask 优先级修复** 🆕 | Auto mode 不再覆盖 `PreToolUse` hook 的 `ask` 决策——hook 的 ask 现在保持最低级别，要求用户确认 |

**安全价值**:
- `PROCESS_WRAPPER` 对企业意义重大——类似容器 runtime 的 seccomp profile，可在 agent 运行时层注入审计和策略控制
- Permission preview 字符中和是针对 **视觉欺骗攻击**（approval phishing）的主动防御

### 1.2 关键 Bug 修复（15+ 项）

| 严重性 | 问题 | 修复 |
|:------|:-----|:-----|
| 🔴 | 并行 Claude Code session 在休眠唤醒后**全部同时登出**（共享凭证存储导致） | 修复凭证存储竞态条件 |
| 🟡 | Plugin MCP servers 在 web session **闲置恢复后不重连**，MCP 调用一直失败直到下一条消息 | 修复重连逻辑 |
| 🟡 | 子 agent 带显式 model override spawn 后，**resume 或 follow-up 时回退到父 session 的模型** | 修复模型覆盖传递 |
| 🟡 | Claude on Vertex/Bedrock 启动时**尝试默认 Opus 模型**，即使已显式配置了其他模型 | 修复默认模型策略 |
| 🟡 | 嵌套 `.claude/rules/*.md` 在 settings 排除了 project sources 时**仍被加载** | 修复规则加载隔离 |
| 🟡 | Background jobs on **LLM gateway auth** (`ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL`) 在 daemon 重启后报 "Not logged in" | 修复 gateway auth 持久化 |
| 🟡 | 被杀死的 background agents **自动重生**；revived agents **重跑旧 session 的 stale prompt** | 修复 agent 生命周期管理 |

### 1.3 性能 & 架构改进

| 改进 | 数值/效果 |
|:-----|:----------|
| **Terminal 渲染性能** | 改进布局和渲染性能（具体未量化，但属持续优化） |
| **Background agent 结果报告** | Claude 现在报告仍在运行的 agent 状态并等待真实完成，**不再虚构结果** |

## 二、GitHub PR 仪表板 GA + Agentic PR 可见性正式化

> **来源**: [GitHub Changelog — New PR dashboard GA (Jul 9)](https://github.blog/changelog/2026-07-09-new-pull-requests-dashboard-is-now-generally-available/)

### 2.1 PR Dashboard GA 核心特性

| 特性 | 详情 |
|:-----|:------|
| **Inbox** | 统一发现需要关注的 PR（review requests / CI 失败 / 新评论 / ready to merge），支持重新排序和隐藏 section |
| **Saved views** | 创建/编辑/组织自定义视图，替代 browser bookmarks |
| **智能搜索** | 内置 `Authored by me` / `Assigned to me` / `Involves me` / `Review requested` 过滤 |
| **高级搜索** | 支持 `AND`/`OR` 及嵌套搜索，如 `(org:github AND author:@me) OR (org:dizzbot assignee:mona)` |

### 2.2 ⭐ Agentic PR — `author:@me` 现在包含 agent 创建的 PR

> **这是本次更新最重要的研发管理信号**

`author` 过滤条件**新增了对 agent-created PRs 的支持**：
- `author:@me` → 返回你**本人创建** + **你指示 Copilot 代创**的所有 PR
- 同一搜索语法，agent 和人类 PR 在同一视图管理

**管理意义**: 这是 GitHub 首次将 agent 产出的 PR 与人类产出放在**同一可见性平面**上。不再需要手动标记 \"这是 agent 开的 PR\"，团队可以通过 Inbox + Saved views 统一追踪。

### 2.3 补充：GitHub 企业治理三件套（Jul 8）

> **来源**: [MDM Copilot Settings GA (Jul 8)](https://github.blog/changelog/2026-07-08-deploy-managed-copilot-settings-via-mdm-in-vs-code-and-cli/) + [OTel Export GA (Jul 8)](https://github.blog/changelog/2026-07-08-enterprise-managed-opentelemetry-export-for-vs-code-and-cli/) + [VS Code June Update (Jul 8)](https://github.blog/changelog/2026-07-08-github-copilot-in-visual-studio-code-june-2026-releases/)

GitHub 同日发布的 3 项治理能力构成了**企业 Copilot 管控三件套**：

#### ① MDM 推送 Copilot 设置（GA）

| 维度 | 详情 |
|:-----|:------|
| 推送渠道 | Microsoft Intune / Jamf / Group Policy / Chef / Puppet / Ansible |
| 三层优先级 | Native MDM > Server-managed > File-based |
| 覆盖设置 | `permissions.disableBypassPermissionsMode` / `model` / `enabledPlugins` / `extraKnownMarketplaces` / `telemetry.*` |
| 平台 | VS Code + Copilot CLI，**不受开发者登录方式影响** |
| 文件路径 | macOS: `/Library/Application Support/GitHubCopilot/managed-settings.json`<br>Windows: `%ProgramFiles%\GitHubCopilot\managed-settings.json`<br>Linux: `/etc/github-copilot/managed-settings.json` |

#### ② 企业托管 OpenTelemetry 导出（GA）

| 维度 | 详情 |
|:-----|:------|
| 管控范围 | Copilot Chat extension (VS Code) + agent host process (Copilot CLI) |
| 配置项 | OTLP endpoint + 传输协议（`otlp-http` / `otlp-grpc`）+ service name / resource attributes + exporter headers |
| **Prompt 内容开关** | 控制是否捕获 prompt / response / tool content，以及开发者能否修改此设置 |
| **安全设计** | 托管 exporter headers（如 auth token）**只应用于 Copilot Chat 的 OTLP exporter，不通过环境变量传递**→ token 不会泄漏到 agent host 再 spawn 的子进程中 |
| 优先级 | **Managed value 始终胜出**，覆盖环境变量和用户设置 |

#### ③ VS Code June 更新（agent 开发平台化）

与 MDM + OTel 同日发布，VS Code 自身在 agent 平台化上同步推进：

| 特性 | 状态 |
|:-----|:-----|
| **Agentic browser tools** | **GA** — agent 可在 VS Code 内导航页面、截图、验证 web app |
| **Parallel sessions** | 并排运行多个独立 agent 任务，各有独立视图 |
| **Multi-chat per session** | 一个 session 内多个 chat，分离实现/审查/测试/docs |
| **Cost visibility** | session 总成本 + subagent 分解 + 超额使用追踪 |
| **Marketplace model providers** | 从 VS Code 内发现/安装/调整模型（context size / reasoning effort） |
| **Autopilot improved** | agent 更智能判断任务何时真正完成，减少手动干预 |
| **1M context** | 兼容 Anthropic + OpenAI 的大上下文模型 |
| **Session sync & chronicle** | 跨机器/workspace 同步和搜索编码历史 |
| **Gutter feedback** | 直接在编辑器 gutter 对 agent 修改留言 |
| **MCP OAuth credentials** | OAuth client ID 配置，secret 存储在 VS Code secret storage |
| **Extension auto-update delay** | 新版本自动安装前 **2 小时延迟**，给团队安全缓冲期 |
| **Ollama official extension** | 从内置 Ollama provider 迁移到官方扩展 |

## 三、Atlassian: Jira Agent 全状态可见性 GA 🆕

> **来源**: [Inside Atlassian Blog — "Every agent. Every state. Full visibility in Jira" (Jul 2026)](https://atlassian.com/blog)

### 核心特性

| 维度 | 详情 |
|:-----|:------|
| **统一视图** | 跨所有 spaces 和 repos 的 agent 状态单页面视图 |
| **分组展示** | 按需要关注的内容排序（stuck / shipping / completed） |
| **状态维度** | 每个 agent 的完整状态：正在运行 / 需要输入 / 已完成 / 需要关注 |
| **规模验证** | "Engineering orgs are rapidly scaling from working manually to validating agent output at scale" |

### 管理意义

这是 Atlassian **Agent 可见性三阶段**的第二阶段：

1. **Phase 1** (已完成): Claude Agent for Jira + Cursor in Jira — agent 可从 Jira 触发
2. **Phase 2** (本次): Agent 状态全可见 — 所有 agent 在单一视图统一管理
3. **Phase 3** (推测): Agent 治理策略 — 权限/配额/审计

**与 GitHub PR Dashboard 的对比**: 两者解决了不同层面的 agent 可见性问题：
- GitHub: **代码产出**可见性 — agent-created PRs 纳入统一 PR inbox
- Atlassian: **工作流**可见性 — agent 执行状态在 Jira 中和人类任务同一视图

## 四、本期交叉趋势分析

### 4.1 Agent 安全管理形成"内-外"双路线

| 维度 | GitHub 路线 | Claude Code 路线 | Atlassian 路线 |
|:-----|:------------|:-----------------|:---------------|
| 安全重点 | 代码层安全发现 | Agent 运行时安全隔离 | 工作流可见性+治理 |
| 最近动作 | AI Security Detections + MDM + OTel | 7 项安全修复 + PROCESS_WRAPPER | Agent 状态视图 + 上下文传递 |
| 核心命题 | "agent 写的代码是否安全" | "agent 自身是否安全可控" | "agent 工作是否可观察可治理" |

**三者合起来才是 agent 安全的全景**: 代码安全 + agent 运行时安全 + 工作流可见性。

### 4.2 企业 Copilot 治理从"可选"到"强制管控"

**两周之内的变化**:
- Jul 1: Enterprise managed-settings.json **GA**（服务器侧推送）
- Jul 8: MDM 推送 Copilot 设置 **GA**（设备侧推送）
- Jul 8: 企业托管 OTel **GA**（审计追踪强制）
- Jul 8: Per-user budgets **GA**（AI credits 归因）
- Jul 10: 部门级 Code Quality 目标（组织级管控）

**趋势**: Copilot 的治理模型已从"用户自选→IT 推荐"演进到"IT 强制管控→审计追踪→归因计费"阶段。MDM + OTel + Budget 三件套让 IT 部门首次能对 agent 使用实现：**谁在用、用多少、花在哪、是否安全**。

### 4.3 本周无新内容的源

- **Cursor**: 自 Jul 10 v3.11 后无更新（v3.11 的 side chats + conversation search + cloud agent hooks 是最近特性）
- **HBR**: 本周无 AI+研发管理相关文章
