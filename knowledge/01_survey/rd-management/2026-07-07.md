## 一、Claude Code v2.1.202 — Dynamic Workflow Sizing + /review 回退

> **来源**: [Claude Code Changelog](https://docs.anthropic.com/en/docs/claude-code/changelog) · Jul 6, 2026

### 新功能
- **Dynamic workflow size** (`/config`): 控制动态工作流的 Agent 数规模（small/medium/large）——只提供建议尺度，非硬性上限
- **OpenTelemetry 增强**: `workflow.run_id` 和 `workflow.name` 属性加入 workflow 派生子 Agent 的遥测数据，可完整重建工作流运行的活动图

### 重要行为变更
- **`/review <pr>` 回退到快速单通审查**：之前（v2.1.186）改为与 `/code-review medium` 相同引擎，现在恢复为单次快速通过
- **`/code-review <level> <pr#>`**：用于多 Agent 的分级审查（取代了 `/review` 的深度审查功能）

### 批量修复（14 项）
- 修复了包含大量 git worktree 的仓库中按名称恢复会话或打开恢复选择器耗时数分钟/占用大量内存的问题
- 修复了 Remote Control (mobile/web) 发送的命令在交互式会话中失败的问题
- 修复了图片/文件通过 Remote Control 发送但无标题时被静默丢弃的问题
- 修复了语音输入在麦克风或录音器失败时的无限重试循环——连续捕获失败现在会暂停语音输入
- 修复了工作流脚本中的 Unicode 引号转义导致解析错误的问题
- 修复了 SSH 下 sign-in URL 因换行无法点击（现在以单个超链接形式发送）
- 修复了重复加载已加载的技能（现在不再重复追加副本到 context）
- 修复了因代理或网络断开导致安装器/更新器下载立即失败的问题（瞬断现可自动重试）

> 📌 **关键信号**：`/review` 回退到简单模式 + `/code-review` 承担深度审查 → **Claude Code 正采用分级审查架构**：简单审查单 Agent 快速完成，复杂审查走多 Agent 协作

## 二、GitHub Copilot Billing Preview App — 8 月 3 日退役

> **来源**: [GitHub Changelog](https://github.blog/changelog/2026-07-07-copilot-billing-preview-app-will-be-retired-on-august-3) · Jul 7, 2026

### 背景
- **Billing Preview App** 是为帮助用户理解 **Usage-based Billing 过渡期账单** 而构建的临时工具
- 随着原生计费 UI 的成熟（覆盖用户级预算、成本中心、用量池分配），Preview App 已不再必要

### 替代方案（原生 UI）
- **AI Usage 页面** → 分组/筛选/导出 AI Credits 数据
- **预算设置** → 控制用户/组织级支出上限
- **用户级预算** → 控制并跟踪个体级别用量
- **API & 用量报表** → 随时拉取原始数据

> 📌 标志着 **GitHub Copilot 计费模式转型的第一阶段工作已经完成**——从过渡工具到原生能力的内化

## 三、Atlassian × Dropbox — AI 转型实践：从"采纳率"到"Super User"

> **来源**: [Atlassian Blog](https://www.atlassian.com/blog/how-we-build/atlassian-dropbox-ai-transformation) · Jun 29, 2026

### 核心论点
- **AI 是人的转型，不是技术转型**。Atlassian 的 Chief People and AI Enablement Officer 认为：技术转得动，但行为转不动 = 失败
- **上下文是护城河**，不是 AI 模型。与知识管理成熟度正相关
- **异步 + 文档丰富文化**在 AI 时代具有天然优势（Dropbox 同样体认）

### "Super User" 度量框架（Atlassian 内部实践）
- **从采纳率 → Super User 度量**：99% 员工每日使用 Rovo，但这不能说明效果
- **Super User 定义**：至少 **40 次/周** 在角色特定工作流中使用 **高级 AI 功能**（含第一方和第三方工具）
- **当前覆盖**：组织内约 **30%** 达到 Super User 水平
- **按工种区分**：工程部门的 Super User 与 HR 的 Super User 标准不同

### 三条实操建议
1. **从任务层级理解工作**：先问"这个任务用 AI 做会怎样？"，再提升到技能和角色层面
2. **重新设计工作方式**：AI 工作协议（AI Working Agreements）、AI 回顾（AI Retros）
3. **建立实验文化**：ShipIt 黑客松 + AI Innovation Days；鼓励非技术团队参与

> 📌 **交叉验证** → 与 Atlassian "Fragmentation Tax 可降低 46%"（2026-07-06 跟踪）形成互补——不但要减税，还要培养 Super User 来驱动正向循环

## 四、Atlassian Claude Agent for Jira — 将编码 Agent 嵌入 Issue 驱动工作流

> **来源**: [Atlassian Blog](https://www.atlassian.com/blog/company-news/claude-agent-for-jira) · Jun 18, 2026

### 产品模式
- **Jira Issue 中直接指派**：在评论中 @ 提及 Claude Agent for Jira，或将 Assignee 选为 Claude
- **Sandboxed 执行**：在 Anthropic 隔离基础设施中克隆仓库、分析代码、实现变更、push 分支
- **Draft PR + 实时回写**：Agent 打开 Draft PR，同时在 Jira work item 上回传实时状态

### 与已有方案的关系
| 方案 | 模式 | 上下文来源 |
|:-----|:-----|:-----------|
| **Cursor in Jira** (之前跟踪) | Cursor Agent 从 Jira issue 接单 | Teamwork Graph |
| **Rovo Dev in Jira** (Atlassian 自研) | Rovo Dev 从 Jira 分配编码/审查任务 | Teamwork Graph + 知识库 |
| **Claude Agent for Jira** (新) | Claude Managed Agents 基础设施 | Jira issue 上下文 + 仓库 |

### 价值定位
- Given **400 组织研究中 AI 采纳率 90% → 生产力提升仅 10-15%** 的瓶颈，核心障碍是**上下文断裂**
- Claude Agent for Jira 让 Agent 自动读取 Jira issue 的全部上下文（验收标准、目标仓库、设计标准）→ **消除计划到代码的上下文切换成本**

> 📌 **趋势判断**：三大 Agent 方案全部嵌入 Jira → **Issue Tracking 正成为 Agent 调度中心和上下文枢纽**。核心差异化在上下文基础设施（Teamwork Graph vs 原生 issue 解析 vs 知识库集成）

## 五、HBR: 绩效管理需要 AI 时代新指标（Jul 6）

> **来源**: [HBR](https://hbr.org/2026/07/performance-management-needs-new-metrics-in-the-ai-era) · Randy Bean, Erik Strauss, Randeep Singh · Jul 6, 2026

### 核心问题
- 公司在 AI 时代用传统指标（生产力、目标完成、效率）衡量员工表现
- **速度 vs 判断力**——当 AI 产出加速，如何在效率与问责之间找到平衡？
- 依赖 AI 的员工可能得分更高，但使用 AI 的方式是否"负责"才是关键

### 需要回答的问题
1. **"好表现"的定义变了**——当产出由"人 + AI"共同产生，如何评估个体的贡献？
2. **组织需要新框架**：不能只看速度和 token 消耗，而要关注 **判断力、上下文运用、AI 协作质量** 等新维度

> 📌 **与 Atlassian "Fragmentation Tax" 和 HBR "AI Is Squeezing Middle Managers" 形成完整闭环**：个体产出加速 → 管理者承压 → 需要全新的绩效框架来评价人 + AI 的联合产出

## 六、HBR: 与 AI 共存的关键是心态，不是技能（Jun 12）

> **来源**: [HBR](https://hbr.org/2026/06/to-thrive-alongside-ai-focus-on-mindset-not-skillset) · Marco Argenti (Goldman Sachs CIO) · Jun 12, 2026

### Goldman Sachs CIO 的核心问题
> **"我的工作中有哪 10% 是 AI 永远做不到的，值得我保持竞争优势？"**

### 论点
- 在快速变化中，最危险的不是缺乏 AI 技能，而是缺乏正确的**心态**
- 技能可以学，但**思考方式（元认知）** 决定了一个人能多快重新定位自己的价值
- 每个知识工作者都应该不断追问：**"什么是我唯一能做的？"**

3. **Issue Tracking = Agent 调度中心**：Cursor、Rovo Dev、Claude Agent 三套方案全部嵌入 Jira → 上下文枢纽化竞争，核心壁垒在知识管理基础设施
