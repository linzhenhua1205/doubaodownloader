## ① Copilot on web 会话控制 + token 花费指示器：成本透明化下沉到个人交互层 🔥

- **来源/标题**: GitHub Changelog《Copilot on web expands conversation controls》（Aug 10, 2026）— https://github.blog/changelog/2026-08-10-copilot-on-web-expands-conversation-controls/
- **要点**: Copilot Chat on github.com 改进三件事：**最近会话更易访问**；**会话可最小化**（等待 Copilot 响应时可继续浏览 GitHub，随后返回进行中的会话）；**token 花费指示器**——点击 token spend 图标可查看 **per-session 与 per-message quota**，用量与预算可见性提升。全部 Copilot 计划可用
- **信号解读**:
  - 成本透明化出现**第三层下沉**：08-08 组织层（impact dashboard ROI 板块）→ 08-08 桌面 app 层（Auto 显示 AI credit/cache 详情）→ **本次个人 web 交互层（per-session/per-message quota）**——成本感知从"管理员视角"一路下沉到"每个开发者的每次对话"，**用量意识内建到交互动作本身**
  - "最小化会话 + 浏览其他页面 + 返回继续"与 08-08 的 /side 并行探索、08-10 的 /btw 侧聊同向：**会话不再是一次性阻塞交互**，而是可挂起/可并行/可恢复的工作单元（延续 08-10 "agent 会话生命周期工业化"线索）
  - 对研发管理含义：per-message quota 可见后，开发者对"哪类问题最烧 token"会有第一手感知——**成本教育的责任从管理员转移到使用者自身**（组织无需再逐条解释，用量即反馈）

## ② GitHub Copilot SDK for Java：Copilot 从"产品"走向"可编程平台" 🔥

- **来源/标题**: GitHub Blog《Using the GitHub Copilot SDK for Java》（Edward Burns, Aug 10, 2026）— https://github.blog/engineering/using-the-github-copilot-sdk-for-java/
- **要点**: 企业 Java 开发者可通过 **GitHub Copilot SDK for Java** 从惯用 Java 代码驱动 Copilot——支持**注解（annotations）与虚拟线程（virtual threads）**等惯用 Java 特性，把 Copilot 能力嵌入企业自建工具链
- **信号解读**:
  - 这是 SDK 生态扩展的又一实证：Copilot 从"IDE 插件/桌面 app"走向**可编程平台**——与 08-06 JetBrains 走 LSP 开放语言智能、Cursor 插件市场、MCP 生态（08-03 双事实标准）完全同向：**能力边界由协议与 SDK 划定，而非产品边界**
  - 选择 Java + 虚拟线程 + 注解是精准瞄准**企业存量市场**：Java 仍是企业后端最大语言池，虚拟线程（JDK 21 特性）表明 SDK 面向现代 Java 栈——**AI 能力嵌入"企业工程师的母语"是渗透研发管理的捷径**
  - 对研发管理含义：SDK 化意味着**研发团队可以自己构建"Copilot 驱动的内部工具"**（如自动化代码审查、规范检查、文档生成流水线）——AI 能力从"人人可用的产品"变成"组织可编程的基础设施"，治理责任（谁写的工具、权限如何）随之转移到组织内部
