## ① 🔴 bmcweb 安全修正 — HTTPBasicAuth 部分写入漏洞 + 回调竞态崩溃

### 1.1 bmcweb: HTTPBasicAuth PATCH 部分写入漏洞修复 ⚠️

| 项目 | 详情 |
|:-----|:------|
| **提交** | `df3d7b2e` — Akshay Gaitonde — **Reject invalid HTTPBasicAuth PATCH values** |
| **日期** | 2026-07-30 (UTC) — 昨日本日合并 |
| **严重性** | **中等（逻辑漏洞）** — 客户端看到 400 但属性已写入 |
| **问题** | 为一个不支持的 `HTTPBasicAuth` 值设置 `PropertyValueNotInList` 错误后没有 return，`handleAccountServicePatch` 继续执行应用请求体中的其他属性 |
| **示例** | `PATCH {"HTTPBasicAuth": "Unadvertised", "Oem": {"OpenBMC": {"AuthMethods": {"BasicAuth": true}}}}` → 返回 400 但 **BasicAuth 已被启用** |
| **同时修复** | 纠正了错误消息中的属性名称 (`HttpBasicAuth` → `HTTPBasicAuth`)，此前名称不匹配导致客户端无法将错误映射回请求 |
| **意义** | 这是一类**状态不一致 + 错误吞没**的组合漏洞：看似拒绝（400），实则已经发生状态变更 |

### 1.2 bmcweb: IBM 修复 EventService 回调竞态导致的崩溃

| 项目 | 详情 |
|:-----|:------|
| **提交** | `a74ef929d7` — Myung Bae (IBM) — **Add defensive callback invocation** |
| **原因** | EventService 的 `recvMessage()` 中 callback 函数指针在竞态条件下变为 null：`sendNext()` 将 `conn->callback = nullptr`，但在异步操作尚未完成时 callback 已被调用，触发 `std::bad_function_call` → bmcwebd ABRT |
| **journal** | `recvMessage() failed: asio.ssl error` → `recvMessage() failed: stale parser` → `terminate called after throwing an instance of 'std::bad_function_call'` |
| **修复** | 在调用 `callback(...)` 前增加 `if (callback)` 防御性检查 |
| **意义** | 这暴露了 bmcweb 异步 http_client 设计中潜在的**竞态窗口**。红帽子事件订阅场景下可能出现，生产环境风险不可忽视 |

## ③ 🔧 IPMI 演进: phosphor-host-ipmid 两个核心修复

### 3.1 System Info Parameter 编码按参数独立存储（AMI）

| 项目 | 详情 |
|:-----|:------|
| **提交** | `f42adfa89c` — Nagavarapu Sai Pavan (AMI) — fix system info parameter encoding per-parameter storage |
| **问题** | IPMI v2.0 Set System Info Parameters (NetFn 0x06, Cmd 0x58) 的 encoding byte 被**全局共享**，导致多个参数互相覆盖 |
| **修复** | 引入 `SysInfoParamStore` 按参数独立存储 encoding；新增 `updateEncoding()/lookupEncoding()` 方法；移除全局 `GlobalEncoding` 结构 |
| **严格校验** | 无效 encoding (>0x02) 返回 0xCC completion code |
| **验证** | 13 项测试用例全覆盖：合法/短/长 payload、无效 encoding、多参数编码隔离 |

### 3.2 VLAN 清理差异化（AMI）

| 项目 | 详情 |
|:-----|:------|
| **提交** | `1ea4f4e685` — Rashid MP (AMI) — Add deconfigureVLAN helper for VLAN cleanup |
| **问题** | 原有 `deconfigureChannel` 会删除 channel 上的所有对象（包括 parent interface），VLAN 禁用时不应影响 parent |
| **修复** | 新增 `deconfigureVLAN` 方法，仅删除 VLAN 关联的 D-Bus 对象 |
