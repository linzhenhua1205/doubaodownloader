## ① ⭐ bmcweb: 支持 Processor EnvironmentMetrics PATCH (GPU 功耗上限配置)

> **来源**: OpenBMC GitHub — bmcweb
> **提交者**: Ender Hsieh (`andhsieh@nvidia.com`, **NVIDIA**)
> **合并日期**: 2026-07-21
> **SHA**: a47c650
> **涉及 Schema**: `Processor.EnvironmentMetrics` (Redfish)

**变更核心**: 新增 Redfish PATCH 端点用于设置 GPU/Processor 功耗上限（Power Cap），通过 `/redfish/v1/Systems/system/Processors/<id>/EnvironmentMetrics` 实现。

### 实现路径

```
Redfish PATCH -> Processor EnvironmentMetrics
  v
复用已有的 getPowerCapObject + setPowerLimitWatts helper
（与 Chassis EnvironmentMetrics PATCH 共享同一验证逻辑）
  v
D-Bus: Control.Power.Cap.PowerCap (SetPoint)
        Control.Power.Cap.PowerCapEnable (ControlMode)
  v
dbus-sensors 执行实际限功率
  v
错误映射：InvalidArgument -> 400 PropertyValueIncorrect
         冲突/范围外 -> 409 PropertyValueExternalConflict
```

### Redfish ↔ D-Bus 映射

| Redfish 属性 | D-Bus 接口 | 说明 |
|:-------------|:-----------|:------|
| `PowerLimitWatts.SetPoint` | `Control.Power.Cap.PowerCap` | 功耗上限目标值 (W) |
| `PowerLimitWatts.ControlMode` | `Control.Power.Cap.PowerCapEnable` | 控制模式：`Disabled` / `Automatic` |

### NVIDIA 测试验证

在 `nvl32-obmc` 平台（NVIDIA NVL32 参考设计）上测试通过：

```bash
# ✅ 成功：设置 GPU 功耗上限 550W
$ curl -X PATCH -d '{"PowerLimitWatts":{"SetPoint":550,"ControlMode":"Automatic"}}'
  → HTTP 204 (Control.Power.Cap.PowerCap 回读 550)

# ❌ 拒绝：无效 ControlMode "Manual"
$ curl -X PATCH -d '{"PowerLimitWatts":{"ControlMode":"Manual"}}'
  → PropertyValueNotInList

# ❌ 拒绝：超出范围 SetPoint 999
$ curl -X PATCH -d '{"PowerLimitWatts":{"SetPoint":999}}'
  → PropertyValueIncorrect (400)
```

**Redfish Validator 结果**: PASS: 9472, WARN: 369, FAIL: 0

### 深度解读

1. **🚀 NVIDIA 主导**: 这是 bmcweb 中 **NVIDIA 直接提交**的代码，而非通过 ODM/OEM 间接贡献。Ender Hsieh 是 NVIDIA BMC 团队工程师。说明 NVIDIA 正在自建 Blackwell 系列（NVL32/NVL72/GB200）的 OpenBMC + Redfish 管理面，不再完全依赖供应商

2. **GPU 功耗管理的标准化**: 此前 GPU 功耗上限配置通常通过 NVML/nvidia-smi 在带内完成（OS 层面），或通过厂商私有 IPMI OEM 命令走带外。此合入意味着 GPU 功耗上限配置可以在 **Redfish 标准管理面**统一完成，对集群管理平台（DCIM/CSP 自研）意义重大——无需再为 GPU 功耗管理维护单独的 NVML 通道

3. **复用 Chassis 路径已有逻辑**: `getPowerCapObject` + `setPowerLimitWatts` 此前已用于 Chassis EnvironmentMetrics PATCH (Jul 6, zhanghao/jeaaustx)。Processor 版本复用同一 helper，说明 bmcweb 的功耗管理架构正走向**跨资源类型统一**——Chassis（机箱级）和 Processor（处理器级）共享同一功耗控制后端

4. **NVL32 参考设计成熟度信号**: 测试中提到三个需要 cherry-pick 的补丁 (mctpd config、upstream u-boot dts、nvidia-gpu sensor patch)，说明 NVIDIA NVL32 平台的 OpenBMC BSP 正在从开发走向集成验证阶段
