## ② openpower-vpd-parser: 多线程 VPD 采集架构重构 (Jul 17) ⭐

> 来源: OpenBMC GitHub — openpower-vpd-parser
> 提交者: IBM (Alpana Kumari, Anupama B R, Faisal Awada, Jinu Joy Thomas, Rekha Aparna, Souvik Roy, Sunny Srivastava)
> 版本: d4731a766d..989d966823 (13 commits)

### 核心变更

| 变更 | 作者 | 说明 |
|:-----|:-----|:------|
| **FRU 存在性检测** | Alpana Kumari | 通过 baseAction 或 sysfs 判断 FRU 是否在位，避免对空槽位做 VPD 采集 |
| **ThreadManager 并发采集** | Anupama B R | 使用 ThreadManager 管理所有 FRU VPD 采集线程；删除旧 semaphore/thread tracking |
| **VPD 采集超时机制** | Anupama B R | 为 VPD 采集循环添加超时保护，避免某 FRU 卡死整机采集 |
| **后采集回调** | Anupama B R | IbmHandler 实现 post-collection actions |
| **采集耗时日志** | Anupama B R | 记录所有 FRU VPD 采集的总耗时 |
| **等待 psu-monitor 就绪** | Faisal Awada | wait-vpd-parsers 添加对 phosphor-psu-monitor 的依赖 |
| **PR 审核流程文档** | Jinu Joy Thomas | 为 openpower-vpd-parser 添加 README，规范 PR review/merge 流程 |
| **vpd-tool: record 可选化** | Rekha Aparna | record 选项不再强制，同时定义错误码 |
| **ConfigManager 单例重构** | Souvik Roy | 重构为 singleton 模式；修复 pollingRequired 验证 |
| **VPD Manager 多线程架构设计文档** | Sunny Srivastava | 新增架构设计文档 (.md) |
| **前置 phosphor-psu-monitor** | Faisal Awada | 确保 VPD 采集在电源监控就绪后启动 |

### 架构意义

这是 **openpower-vpd-parser 自引入以来最大的一次架构升级**，核心变化：
1. **串行 → 并行**: 之前逐个 FRU 串行采集 VPD，现在通过 ThreadManager 多线程并发
2. **空槽位跳过**: 未安装 FRU 的槽位不再浪费采集时间
3. **超时兜底**: 某 FRU 卡死不会拖垮整体采集（生产环境关键）
4. **设计文档化**: VPD Manager 多线程架构设计文档首次纳入仓库

> **影响评估**: IBM Power 平台 BMC 启动时 VPD 采集耗时将显著缩短，多 FRU 场景尤其受益

## ③ obmc-ikvm: NPCM845 UDC 支持 (Jul 17) ⭐

> 来源: OpenBMC GitHub — obmc-ikvm
> 提交者: Hariharan Rangasamy
> 版本: 281d190897..ec3fad81ca

**变更**: NPCM845 BMC 芯片的 USB Device Controller (UDC) 支持 — 添加 `ci_hdrc.0` 设备树节点。

**NPCM845** 是 Nuvoton 最新一代 BMC 芯片（NPCM8xx 系列），基于 ARM Cortex-A35 四核 @ 1.2GHz，定位对标 ASPEED AST2600。主要特性：
- 4× ARM Cortex-A35 cores
- 2× RGMII / 2× RMII（与 AST2600 持平）
- PCIe Gen3 x4
- 内置 USB 2.0/3.0 控制器
- 增强的安全引擎（TrustZone + OTP + 安全启动）

> **趋势**: NPCM845 的 UDC 驱动合入意味着 Nuvoton 生态在 OpenBMC 中持续完善，**NPCM845 正成为 AST2600 之外 BMC 芯片的第二选择**，尤其在 Quanta/Facebook/Intel 平台有部署。

## ④ bmcweb: GenerateSecretKeyRequired 语义修复 (Jul 17)

> 来源: OpenBMC GitHub — bmcweb (srcrev bump via openbmc repo)
> 提交者: Jishnu CM (IBM) → 合并者: Asmitha Karunanithi (IBM)

**变更**: 修正 `GenerateSecretKeyRequired` 的 HTTP 响应码。

**问题**: 之前将 GenerateSecretKeyRequired 返回 HTTP 403 Forbidden，这会**错误地暗示 session 创建失败**。实际上 session 已成功创建（201 Created），只是受限——只能执行 GenerateSecretKey 操作。

**修复**: 根据 Redfish DSP0266 §13.5.5：
- 当启用 MFA 时，用户登录返回 **201 Created** + `@Message.ExtendedInfo` 中包含 `GenerateSecretKeyRequired`
- 只有对受限资源的操作才返回 **403 Forbidden**
- 允许的操作: GET ServiceRoot、POST GenerateSecretKey、DELETE 自身 session、POST VerifyTimeBasedOneTimePassword

**测试**:
- 启用 MFA → 用户登录 → 201 Created + GenerateSecretKeyRequired 消息
- 受限资源 → 403 Forbidden + 正确错误码

> **Redfish 合规影响**: 这是对 Redfish MFA 流程的**关键语义修复**。之前 403 响应会让 BMC 管理客户端认为登录失败（无法创建 session），而实际上 session 已创建但受限。修复后客户端可正确识别 MFA 场景并引导用户完成二次认证。

## ⑤ meta-facebook rainiera6: Host Reset 支持 (Jul 16)

> 来源: OpenBMC GitHub — meta-facebook
> 提交者: RQ Lai (Quanta) → Amithash Prasad (Meta)
> 版本: 2026-06-25 提交, 2026-07-16 合并

**变更**: 为 Facebook Rainier A6 平台添加 host-powerreset 支持。

**流程**: SoC → CPLD → BMC → GPIO pull-down → 系统复位

当主机发送 reset 命令时：
1. SoC 通知 CPLD
2. CPLD 将事件传递给 BMC
3. BMC 拉低 GPIO 触发系统复位

> **意义**: Rainier 系列完整了 host-initiated reset 链。这意味着从 BIOS shell 发起的复位请求可以被 BMC 可靠识别并执行硬件级复位。

## ⑥ meta-ibm: 全线关闭 IPMI 网络接口 (Jul 16) ⭐

> 来源: OpenBMC GitHub — meta-ibm
> 提交者: Crystal Huang
> 版本: 2026-07-08 提交, 2026-07-16 合并

**变更**: IBM 全系列平台（via `phosphor distro feature`）启用 `no-ipmi-rmcp` 特性，关闭 IPMI 网络接口。

**验证**: 编译后确认 IPMI systemd units 在镜像中不存在。

> **趋势判断**: IBM 成为**首个在 OpenBMC 中全面关闭传统 IPMI 网络接口的主流服务器厂商**。这不仅是安全加固——关闭 IPMI 的 UDP 623 端口攻击面，更是 BMC 管理协议栈从 IPMI → Redfish 的**最终过渡信号**。IBM pst 全系列平台（此前已全线启用 debug-trigger）将完全依赖 Redfish 管理。
