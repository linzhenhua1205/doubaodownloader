### 1️⃣ AMI: bmcweb — DBus EventLog 不可用时返回空 Redfish 集合而非 500 🆕🟡

| 属性 | 值 |
|:-----|:---|
| **来源** | 🔧 `openbmc/bmcweb` commit [`0868ab5a`](https://github.com/openbmc/bmcweb/commit/0868ab5aa1b32e6922bb7fdc987e247af6e991eb) |
| **日期** | 2026-07-09（author）/ 2026-07-10（merged） |
| **作者** | Joel Pullokaran Jesin (AMI) |
| **Commiter** | Ed Tanous (NVIDIA) |
| **版本** | master branch (2.19-dev) |
| **重要性** | 🟡 **中** |

**概要**：
当 DBus 后端的 EventLog Entry 集合不可用时（如 `EBADR` 或 `host_unreachable`），bmcweb 原先返回 internal error（500）。此 patch 将预期缺失情况处理为返回空 Redfish EventLog 集合：

- 对 `GetManagedObjects` 返回的 `EBADR` 和 `host_unreachable` 视为可选后端不可用
- 设置 `Members` 为空数组，`Members@odata.count` 为 0
- 意外 DBus 错误仍正常上报为 internal error

**意义**：
- ✅ 提升 Redfish API 的鲁棒性：上电/运行时状态切换过程中不会因 EventLog 后端短暂不可用而返回 500
- ✅ AMI 作为传统 BMC 厂商持续向 OpenBMC/bmcweb 栈贡献质量修复
- ✅ RSV（Redfish Service Validator）合规性增强

### 2️⃣ Quanta/Meta: San Miguel 平台 — PLDM 动态 NIC 传感器发现 🆕🟡

| 属性 | 值 |
|:-----|:---|
| **来源** | 🔧 `openbmc/openbmc` commit [`fc5c2984`](https://github.com/openbmc/openbmc/commit/fc5c29842ed99fa1d0a0e43a05fa0dac853e279c) |
| **日期** | 2026-07-07（author）/ 2026-07-09（merged） |
| **作者** | Potin Lai (Quanta) |
| **Commiter** | Patrick Williams |
| **平台** | `meta-facebook: sanmiguel` |
| **重要性** | 🟡 **中** |

**概要**：
为 Facebook San Miguel 平台引入 PLDM Platform PDR（Platform Descriptor Records）驱动动态 NIC 传感器发现机制：

- **新增 `build_sensor_list` 函数**：通过 `pldmtool` 获取 NIC 的 Platform PDR，动态解析传感器 ID
  - PWR: 50-59
  - Temp: 300-399
  - OSFP Temp: 500-699
- **重构主循环**：将原先的静态传感器列表替换为动态构建
- **Host 状态切换时重置**：host state 转为 OFF 时清空传感器列表，下次上电重新发现

**技术路线**：
```
pldmtool -> Platform PDR(s) -> 解析 sensor ID -> 构建动态传感器列表 -> 轮询采集
```

**意义**：
- 🔄 从**静态硬编码**传感器列表转向**PLDM 协议动态发现**，大幅提升平台适配灵活性
- 🔄 San Miguel 作为 Meta 的 OCP 平台，此贡献可复用至其他采用 PLDM 管理的平台
- 🔄 Quanta 在 OpenBMC 社区中持续增加贡献深度，从板级集成进入管理协议层面

### 3️⃣ 9elements: smbios-mdr PCIeDevice D-Bus 暴露 🆕🔵

| 属性 | 值 |
|:-----|:---|
| **来源** | 🔧 `openbmc/openbmc` commit [`0ae5af8a`](https://github.com/openbmc/openbmc/commit/0ae5af8a4323836e17f72417d3a6e33d5952f2f3) |
| **日期** | 2026-07-09（author + committer） |
| **作者** | Tan Siewert (9elements) |
| **版本** | smbios-mdr PACKAGECONFIG |
| **重要性** | 🔵 **低（工具链）** |

**概要**：
为 `smbios-mdr` 新增 `pcie-device-dbus` PACKAGECONFIG 选项。启用后可**将 SMBIOS Type 9（System Slots）记录中的 PCIe 设备信息暴露为 D-Bus 对象**，供上层 Redfish 或其他管理组件消费。

**意义**：
- 🔧 打通从 SMBIOS → D-Bus → Redfish 的 PCIe 设备资产信息链路
- 🔧 对使用 SMBIOS Type 9 记录 PCIe 拓扑的平台尤其有用
- 🔧 9elements 持续深耕 OpenBMC 固件/BIOS 互通领域

### 4️⃣ AMI: bmcweb NetworkProtocol — SSH 错误信息属性路径修正 🆕🔵

| 属性 | 值 |
|:-----|:---|
| **来源** | 🔧 `openbmc/bmcweb` commit [`9641d8bc`](https://github.com/openbmc/bmcweb/commit/9641d8bc61120410b09d245f296de6c1c3c41b5b) |
| **日期** | 2026-07-08（author）/ 2026-07-10（merged） |
| **作者** | Shivraj Toravi (AMI) |
| **重要性** | 🔵 **低（Bug fix）** |

**概要**：
修复 `handleProtocolEnabled()` 函数中使用硬编码字符串 `"IPMI/ProtocolEnabled"` 作为 Redfish property name 的 bug。DBus 错误中 SSH 的失败被错误地报告为 IPMI 路径。新增 `redfishProperty` 参数使每个调用点传递正确的属性路径：
- IPMI → `"IPMI/ProtocolEnabled"`
- SSH → `"SSH/ProtocolEnabled"`

已在 gb200nvl-bmc 上验证 SSH 开关功能正常，且 Redfish Service Validator 通过。
