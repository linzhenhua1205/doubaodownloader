## ① ⭐⭐ bmcweb: PCIe Gen6 generation 映射

> **来源**: OpenBMC GitHub — bmcweb
> **提交者**: **Ender Hsieh** (`andhsieh@nvidia.com`, NVIDIA)
> **合并日期**: 2026-07-23
> **SHA**: `db385290bb6e`

### 变更核心

在 `redfishPcieGenerationFromDbus` 映射表中新增 `Gen6` 枚举值，使得 PCIe Gen6 设备可通过 Redfish 上报 `PCIeType` 为 `Gen6`，而非此前映射失败时的未知类型。

### 技术细节

```cpp
// redfishPcieGenerationFromDbus — 新增 Gen6 映射
// phosphor-dbus-interfaces 已新增 PCIeSlot generations 的 Gen6 值
// 补丁后，Gen6 设备将返回正确的 PCIeType
```

**背景**: PCIe Gen6 是 PCI-SIG 于 2022 年发布的标准，单通道速率达 64 GT/s（x16 双向 ~256 GB/s）。此前 OpenBMC Redfish 仅支持到 Gen5，Gen6 设备会因找不到映射而回退为 `Unknown` 或报错。

### 深层解读

1. **NVIDIA 需要 PCIe Gen6** — Blackwell/B300 及后续 GPU 将使用 PCIe Gen6 进行 CPU-GPU 互联。此提交与 NVIDIA 工程师 Ender Hsieh 连续多日在 bmcweb 的活跃一致（此前完成了 Processor EnvironmentMetrics PATCH）
2. **映射超前于硬件落地** — PCIe Gen6 Retimer/Redriver 芯片（Astera Labs / Parade / Montage）尚处于样品或早期量产阶段，但 BMC 软件栈已开始准备。说明 NVIDIA **NVL 平台的 Redfish 管理面正在提前完成铺路**
3. **上游依赖** — 依赖 `phosphor-dbus-interfaces` 中新增的 PCIeSlot Gen6 枚举值（同日 srcrev bump 中包含了此依赖）

## ② ⭐⭐ bmcweb: GPU Processor FirmwareVersion + ServiceLabel

> **来源**: OpenBMC GitHub — bmcweb
> **提交者**: **JY Voon**
> **合并日期**: 2026-07-23
> **SHA**: `2baff8d6daaa` (主变更) + `d1c098fa12fb` (单元测试)

### 变更核心

为 GPU Processor 的 Redfish 资源添加两个重要属性：

| Redfish 属性 | D-Bus 来源 | 说明 |
|:-------------|:-----------|:------|
| **`FirmwareVersion`** | `xyz.openbmc_project.Software.Version` | GPU 固件版本号 |
| **`Location.PartLocation.ServiceLabel`** | 资产/定位信息 | GPU 物理位置服务标签 |

### 配套提交

| SHA | 内容 |
|:----|:------|
| `2baff8d6` | 主变更：GPU Processor 增加 FirmwareVersion + ServiceLabel |
| `d1c098fa` | 单元测试：覆盖 D-Bus 异常、ambiguous subtree、missing owning service 三个分支 |
| `1a972a35` | 容错处理：容忍 deprecated Software Purpose 缺失 — 配合 Purpose 属性废弃迁移 |

### 测试验证

在 `nvl32-obmc` 平台验证通过：

- **D-Bus 异常** → 返回 Internal Server Error (500)
- **ambiguous subtree** → 返回 Internal Server Error (500)
- **missing owning service** → 返回 Internal Server Error (500)
- **正常流程** → 返回正确 FirmwareVersion + ServiceLabel

### 深层解读

1. **GPU 管理 Redfish 标准化重要一步** — 此前 Processor 资源主要覆盖 CPU（x86/ARM），GPU Processor 的 FirmwareVersion 常通过 NVML 或其他私有路径获取。通过 bmcweb 将其纳入 Redfish 标准，意味着**集群管理平台可通过统一 Redfish 查询 GPU 固件版本**
2. **ServiceLabel 的价值** — 在超节点/万卡集群中，物理定位（哪个机箱、哪个槽位）对运维至关重要。此前 GPU 位置信息通过厂商 OEM 扩展获取，现在向标准 Redfish `Location` 属性靠拢
3. **JY Voon 的同日 3 提交** — 主功能 + 单元测试 + 容错处理，说明提交规范良好（功能、测试、容错三件套齐全）

## ③ ⭐⭐ meta-facebook: Rainier A6 MCTP over I3C

> **来源**: OpenBMC GitHub — openbmc (`meta-facebook`)
> **提交者**: Facebook/Meta OpenBMC 团队
> **合并日期**: 2026-07-23
> **SHA**: `f177ced7`

### 变更核心

为 **Rainier A6** 平台启用 **MCTP over I3C** 管理总线传输层。

**技术栈**:
```
+---------------------------------+
|  MCTP Userspace Daemons         | <- pldmd, mctpd
|  (endpoint discovery, control)  |
+---------------------------------+
|  MCTP I3C Transport Binding     | <- Linux Kernel mctp-i3c
|  (kernel MCTP stack)            |
+---------------------------------+
|  I3C Bus (MIPI I3C Basic v1.0) | <- 物理层, 替代 I2C
+---------------------------------+
```

**摘要**:
- Linux 内核 MCTP 栈已提供 I3C 传输层绑定 (`mctp-i3c`)
- Rainier A6 是首个集成此支持的 FB 平台
- 启动时自动配置总线、分配本地 EID、暴露接口给用户态守护进程
- 支持 MCTP 控制消息、端点发现和协议交互

### 深层解读

1. **I3C 正在取代 I2C/SMBus 成为新一代管理总线** — I3C (Improved Inter-Integrated Circuit) 由 MIPI 联盟定义，速率可达 12.5 MHz (vs I2C 的 400 kHz-1 MHz)，功耗更低，支持带内中断。这是 BMC 硬件层面**十年来最重要的总线升级**
2. **MCTP over I3C 是 DMTF 标准方向** — DMTF 已定义 MCTP over I3C 绑定，MCTP 作为 PLDM/SPDM 等管理协议的传输层。I3C + MCTP = 服务器管理新标准
3. **Rainier A6 = FB 第 6 代 OpenBMC 平台** — 从 Rainier Pass 1→A6，再结合同日 `Meta Rainier A7` 的 dbus-interfaces 新增，说明 Meta 的 BMC 平台代际迭代活跃，A6 和 A7 并行开发
4. **与传统 I2C 的兼容性** — I3C 总线上可混合挂载 I3C 设备和传统 I2C 设备（向下兼容），因此可以平滑过渡，无需一次全量替换
