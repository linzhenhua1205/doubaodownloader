### 主线一：Facebook — rsyslog imfile 状态文件清理（今日新合入，长期运行稳健性）

- **meta-facebook: rsyslog: delete imfile state on file move**（2026-08-06 合入 openbmc 主仓库）: rsyslog imfile 模块按 **inode** 记录 state 文件，console log 每次轮转都会残留一个 stale state 文件，且无人回收——长期运行的 BMC 上无界积累，最终可能耗尽所在文件系统。修复：设置 `deleteStateOnFileMove`，让 imfile 在日志被轮转移除时同步删除对应 state 文件，state 目录**按构造约束为每监控输入仅 1 个文件**。来源: https://github.com/openbmc/openbmc/commit/bb1a525b38
- **旧 workaround 的静默失效缺陷被点名**: 现有 logrotate 配置靠 hourly logrotate-trigger.log 轮转 + postrotate 脚本把 state 目录修剪到 20 个文件，但该 workaround **绑定硬编码路径**，一旦 $WorkDirectory 变化即静默失去保护——这正是"机制性修复优于脚本修补"的又一实证（与 08-05 电源时序重试循环同思路：根治而非绕过）

### 主线二：bmcweb — Redfish 响应边界值整治三连（延续 08-05/08-06 主题）
