## 1️⃣ 🔴 bmcweb: Mozilla modern TLS profile 支持

- **来源**: OpenBMC `bmcweb` `917fbad478`
- **作者**: Ed Tanous (NVIDIA) | **合并日期**: 2026-07-02
- **PR**: https://github.com/openbmc/bmcweb/commit/917fbad478cf5db4a79944d59a4927207adf49d1

**关键特性**:
- 新增 `tls-profile` meson 构建选项，可选 `intermediate`（默认）或 `modern`
- `modern` 配置基于 Mozilla TLS 推荐 -> 仅启用 TLS 1.3，禁用 TLS 1.2 及更早版本
- 使用 testssl.sh 验证加密套件生效

**意义**: 生产环境 BMC 可配置为仅 TLS 1.3，消除 TLS 1.2 及其降级攻击面。对高安全合规场景（金融/政府/云服务商）是重要的安全加固选项。

## 2️⃣ 🟡 bmcweb: 错误消息响应规范化 — 列为正式 error

- **来源**: OpenBMC `bmcweb` `8b0993927e`
- **作者**: Myung Bae (IBM) | **合并日期**: 2026-06-25
- **PR**: https://github.com/openbmc/bmcweb/commit/8b0993927ede52f4a32228d955a8405805acedac

**关键特性**:
- `PropertyValueFormatError`、`ResourceAlreadyExists`、`PropertyDuplicate`、`PropertyValueNotInList`、`PropertyValueTypeError`、`PropertyValueError`、`PropertyNotWritable`、`PropertyValueModified`、`PropertyMissing`、`CreateFailedMissingReqProperties` 共 10 种消息类型从纯 `@Message.ExtendedInfo` 提示升级为标准 `error` 响应结构
- 示例：PATCH 无效密码后，之前只返回 Warning 级别扩展信息，现在返回包含 `"error": { "code": ..., "message": ... }` 的标准 Redfish 错误体

**意义**: 显著提升 API 客户端的错误处理能力——客户端可以通过 `error` 顶层字段判断操作失败，无需再解析 `MessageSeverity` 字段。

## 3️⃣ 🟡 phosphor-bmc-code-mgmt: Altera MAX10 CPLD 固件远程更新

- **来源**: OpenBMC `phosphor-bmc-code-mgmt` `fd6e299a11`
- **作者**: Alex Wang (FII/Foxconn) | **合并日期**: 2026-07-02
- **PR**: https://github.com/openbmc/phosphor-bmc-code-mgmt/commit/fd6e299a116851e0b47d7dfc0889942b3419b7bc

**关键特性**:
- 新增 `Max10CPLD` 类，通过 I2C Avalon-MM 桥接器实现寄存器级操作
- 支持 CFM (Configuration Flash Memory) 擦除与编程
- 注册 MAX10 全系列 (10M04/08/16/25) 至 `CPLDFactory`
- 依赖 Entity-Manager 的 `MuxOutputs` 属性自动切换更新模式
- 在 Clemente（GB200NVL 平台）上验证通过，含完整 AC cycle 持久性验证
- 与现有 Lattice XO5 CPLD 采用相同供应商模式架构

**意义**: 为常见的 Altera MAX10 系列 CPLD 提供 OTA 固件更新能力，通过 Redfish multipart 更新流程管理——这是 GB200NVL 等 GPU 服务器平台 BMC 管理 CPLD 的关键能力补全。

## 4️⃣ 🟡 phosphor-dbus-interfaces: Control.OperatingClockSpeed 接口

- **来源**: OpenBMC `phosphor-dbus-interfaces` `f475857403`
- **作者**: Deepak Kodihalli / Ender Hsieh (NVIDIA) | **合并日期**: 2026-05-29
- **PR**: https://github.com/openbmc/phosphor-dbus-interfaces/commit/f4758574032fdf214fa99c801727b20196941a82

**关键特性**:
- 新增 `Control.OperatingClockSpeed` 通用 D-Bus 接口，支持运行时时钟速度限制直接控制
- 四个属性:
  - `RequestedSpeedLimitMinHz` / `RequestedSpeedLimitMaxHz`：请求的最小/最大频率限制（可写）
  - `PresentSpeedLimitMinHz` / `PresentSpeedLimitMaxHz`：当前生效的最小/最大频率限制（只读）
- 区分请求值与实际值的原因：部分设备需要复位或驱动加载后才生效
- 映射至 Redfish Processor/Memory/Control 三个 schema 的 `OperatingSpeedRangeMHz` / `SpeedLimitMHz`
- 通过 `PresentSpeedLimitMinHz == PresentSpeedLimitMaxHz` 判断时钟是否锁定

**意义**: 为 Redfish 控制处理器/内存频率提供 D-Bus 层原子接口。对 GPU 服务器的功耗/散热动态管控（如 GB200 的 GPU/CPU 频率协同调节）提供基础设施支持。
