## ② bmcweb: 多厂商 Redfish 合规修复密集合入 (Jul 9-16)

> 来源: GitHub openbmc/bmcweb commits
> 维护者: Ed Tanous (NVIDIA)

### 关键 Bug Fix 与合规修复

| 日期 | 提交者 | 厂商 | 内容 | 影响 |
|:----|:------|:----|:-----|:-----|
| Jul 9 | **Rick Yazwinski** | **Meta** | 将 maxValues 从 500 bump 至 ~2000 以支持 ~200 个 bmcweb session | ⚠️ 严重: ~50 个 session 后重启丢失所有持久化 session（每个 session ~11 JSON values 触发文件 500 cap） |
| Jul 9 | Chandramohan Harkude | NVIDIA | 修复 handleProtocolEnabled 中硬编码 "IPMI/ProtocolEnabled" 导致 SSH 错误被错误报告的问题 | 错误归因修复 |
| Jul 10 | **Yuvakumar Selvamani** | **AMI** | EventService PATCH: ✅ HTTP 200→204 No Content (DSP0266 §7.5.2); ❌ queryParameterOutOfRange→propertyValueOutOfRange | Redfish 协议合规 |
| Jul 10 | Joel Pullokaran | AMI | DBus EventLog: 后端不可用时返回空集合而非 internal error | 健壮性 |
| Jul 10 | Shivraj Toravi | AMI | 修复 NTPProtocolEnabled 属性路径拼写错误 → 正确报错 |
| Jul 10 | Rashid MP | AMI | 修复 VLAN RelatedInterfaces URL 缺少父接口名 | REST API 正确性 |
| Jul 13 | Crystal Huang | — | NetworkProtocol: 无 RMCP 时 IPMI/ProtocolEnabled 返回 PropertyNotWritable | Redfish 合规 |
| Jul 13 | Joel Pullokaran | AMI | HTML Content-Type 用 http_helpers::getContentType() 统一解析 | 代码质量 |
| Jul 15 | Ed Tanous | NVIDIA | 修复 asio resolver bypass 回归（代码无法编译） | 编译修复 |
| Jul 16 | Patrick Williams | — | 修复 meson zstd dependency: `-Dhttp-zstd=disabled` 若未禁用仍被启用 | 构建系统 |

> **重点**: Meta Rick Yazwinski 的 session 上限修复最值得关注——这是一个典型的"写到文件后再解析"的双端 cap 不匹配 bug。bmcweb 的 session 持久化用单一 JSON 文件，读端 parseStringAsJson() 硬 cap 500 values，而每个 session ~11 个 value → ~50 session 后文件被判定为 malformed → 重启后全部丢失。当前临时方案 bump cap 到 ~2000，长期方案是"每个 session 独立一个 JSON 文件"。
