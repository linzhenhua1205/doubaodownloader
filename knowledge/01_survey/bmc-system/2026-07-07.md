## ✅ 动态汇总

### 1️⃣ bmcweb: Chassis EnvironmentMetrics 新增 PowerLimitWatts 支持

| 属性 | 值 |
|:-----|:---|
| **来源** | 🔧 `openbmc/bmcweb` commit `ff90bece` |
| **日期** | 2026-07-06 |
| **作者** | Albert Zhang |
| **版本** | master branch (2.19-dev) |
| **重要性** | 🔴 **高** |

**概要**：
实现 `EnvironmentMetrics` schema 中 `PowerLimitWatts` 属性的 GET/PATCH 支持。该字段自 Redfish 2021.2 发布起纳入规范，用于替代已废弃的 `Power` schema 进行机箱功率限制管理。

**关键特性**：
- GET 响应返回 `PowerLimitWatts` 对象，包含 `AllowableMax`、`AllowableMin`、`ControlMode`、`SetPoint`（Control v1_7_0 的 `ControlSingleExcerpt` 类型）
- PATCH 支持动态修改功率限制值
- 关联 Redfish schema：`EnvironmentMetrics.v1_5_0.json`、`Chassis.v1_28_0.json`、`Control.v1_7_0.json`
- 测试验证：p10bmc 硬件模拟器 + Redfish Service Validator 通过
- 错误处理：无效 chassisId 返回标准 `ResourceNotFound` 错误消息

**意义**：
补全了 OpenBMC 在 Redfish 功率管理领域的最后一块拼图——通过 EnvironmentMetrics 而非 Power schema 实现功率限制，符合 DMTF 推荐的最佳实践路径。对于数据中心级功率管控（TDP 限制、机柜功率封顶）有直接实用价值。

## 📊 趋势观察

- **Redfish 功率管理迁移加速**：PowerLimitWatts 进入 bmcweb 主分支，标志着 OpenBMC 全面从废弃的 `Power` schema 转向 `EnvironmentMetrics` + `Control` 的现代化路径。这一迁移已持续多个版本，值得跟踪各平台是否适配完成。
- **OpenBMC 2.19 仍无时间表**：距离 2.18.0 发布已超 13 个月，社区开发重心完全在 master 分支。若团队在 2.18 上建产品，需关注 master 中已合入的以下关键功能未 backport：
  - TLS 1.3-only modern profile
  - 密码过期管理 API
  - 运行时频率限制接口
  - 功率限制（PowerLimitWatts）
