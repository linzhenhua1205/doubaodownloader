## ⚡ 内核

### 1️⃣ 🆕 **sched_ext: 子调度器层级 + proxy-execution 支持 — 可扩展调度器里程碑** 🚀

- **来源**: LWN.net (Jul 16, corbet) — [$] Sched-ext: enqueue() for sub-schedulers and proxy-execution support
- **版本**: 即将合入 linux-next
- **核心**: sched_ext（可扩展调度器类）允许通过 BPF 程序安装自定义 CPU 调度器，本次有两项重大进展接近完成：

#### 两大能力突破

| 能力 | 说明 |
|:-----|:------|
| **子调度器层级** | 支持建立 sub-scheduler 层级结构，enqueue() 机制允许调度器在子级之间传递任务，实现更灵活的调度策略组合 |
| **proxy-execution 兼容性解决** | 长期存在的 sched_ext 与 proxy-execution 不兼容问题终于解决，意味着 sched_ext 可以在更广泛的内核场景下安全使用 |

- **对服务器团队**: 🟡 **值得关注** — sched_ext 允许数据中心部署自定义 CPU 调度策略（如 AI 推理 vs 批处理 vs 延迟敏感任务差异化调度），子调度器层级使策略组合成为可能
- **当前 AI 集群场景**: 不同任务类型（训练/推理/数据预处理）对 CPU 调度需求差异大，子调度器层级可灵活组合策略

### 2️⃣ 🆕 **Lockless MPSC FIFO queues for io_uring → kernel 7.2** ⚡

- **来源**: LWN.net (Jul 15, corbet) — [$] Lockless MPSC FIFO queues for io_uring
- **版本**: **Linux 7.2** 将包含
- **变更**: io_uring 从标准内核链表切换为 **lockless MPSC (multi-producer, single-consumer) queue**
- **效果**: "notable performance gains" — 无锁队列在高并发场景下显著性能提升
- **设计特点**: 无锁算法通常复杂，但这里的实现"相对易理解"
- **背景**: io_uring 需跟踪大量并发在途操作，MPSC 是适合该工作负载的高效数据结构
- **对服务器团队**: 🟡 **中** — 对高 IOPS 场景（存储/NVMe/网络）有直接性能影响

## 🛡️ BPF 安全与可观测性

### 5️⃣ 🆕 **Tetragon: 直接从 BPF 发送网络包 — 消除用户态代理依赖** 🐝

- **来源**: LWN.net (Jul 14, daroc) — [$] Sending packets directly from BPF
- **场景**: LSFMM+BPF Summit 2026 — Song Liu, Mahé Tardy, Liam Wiseheart
- **问题**: Tetragon (BPF 安全监控工具) 依赖用户态进程转发数据到中央监控服务，该进程本身是一个攻击面
- **方案**: 直接从 BPF 程序**发送网络包到远端**，**消除用户态 agent**
- **意义**: 攻击者杀死 Tetragon 用户态 agent 后仍能保持安全监控链路
- **对服务器团队**: 🟡 **中** — 消除用户态 agent 是 BPF 安全工具的长期趋势，对服务器安全架构有影响

### 6️⃣ 🆕 **Cisco: 用 BPF 屏蔽运行中内核的漏洞 — 比内核热补丁更快速** 🛡️

- **来源**: LWN.net (Jul 13, daroc) — [$] Shielding running kernels against exploits with BPF
- **场景**: LSFMM+BPF Summit 2026 — John Fastabend (Cisco)
- **问题**: Cisco 有大量运行自定义内核的设备，安全补丁部署困难
- **方案**: 用 BPF 在运行时**屏蔽漏洞利用路径**，无需等待内核热补丁
- **效果**: 大幅缩短从漏洞披露到防护的时间窗口
- **限制**: 需要内核提供更多 hook 点才能完全有效
- **对服务器团队**: 🟡 **中** — BPF 作为安全响应加速器，对服务器运维有潜在价值

## 🤖 AI 基础设施

### 7️⃣ 🆕 **Red Hat Physical AI — 从 Automation 到 Autonomy 的范式跃迁** 🏭

- **来源**: Red Hat Blog (Jul 15, Arizmendi) — Physical AI: Physical operations are broken
- **核心概念**: Physical AI = 感知(Perceive)→推理(Reason)→行动(Act) 自治闭环，不同于传统预编程机器人
- **三大转变**:
  - **运营自动化**: AMR 自主导航 / AI 分拣 / 视觉引导机械臂 — 部署成本自2021年降35%，回本周期18-24月
  - **安防监控**: 巡逻机器人 + LiDAR/热成像 + 自动无人机响应
  - **预测维护**: AI 检测设备故障模式，提前数周预警
- **市场**: Physical AI 市场 2025年 $5.23B → 2033年 $49.73B (**CAGR 32.53%**)
- **关键技术栈**: ROS 2 / MoveIt / Nav2 / Open-RMF 等开源机器人中间件已在 Red Hat 企业级平台上运行
- **对服务器团队**: 🟢 **趋势参考** — Physical AI 对边缘算力 (x86/ARM + GPU/NPU/FPGA) 和分布式设备管理提出新需求

### 8️⃣ 🆕 **Red Hat: 好 AI Agent 为什么在生产中失败 — 缺失的基础设施层** 🤖

- **来源**: Red Hat Blog (Jul 13, Naszcyniec) — Why good AI agents fail in production
- **核心论点**: AI Agent POC 成功率高，但**超过半数 AI 项目无法走出试点阶段**
- **五大失败原因**:
  - 模型在真实硬件上表现与仿真不同
  - 边缘设备大规模管理难度被低估
  - 安全和合规要求被推迟到生产阶段成为阻塞
  - 单终端运行多模型 (检测/导航/控制/异常) — 异构模型管理复杂
  - 生产环境条件漂移导致模型性能退化
- **对服务器团队**: 🟡 **中** — AI Agent 基础设施层将成为 AI 集群规划的重要维度
