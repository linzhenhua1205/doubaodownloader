#### 7.1.4 关键修复领域

**🔴 安全/稳定性级别（服务器直接影响）**

| 子系统 | 关键修复 | 说明 |
|:-------|:---------|:-----|
| **🔴 fuse-uring** | **10+ 修复** | io_uring 路径的 NULL解引用、UAF、数据竞态、cancel死锁、32位计数溢出等（详见下方专项分析） |
| **🔴 RDMA/siw** | **Read Response越界写** | iWARP对端可触发越界内存读取—需要IOMMU配合防御 |
| **🔴 RDMA/rtrs** | **RDMA-Write长度未绑定** | chunk边界检查缺失，对端可控长度导致越界 |
| **🔴 SMB client** | **重叠数据区拒绝** | SMB2响应中的重叠数据区域处理 |
| **🔴 XFS** | **12+ 修复** | 多项scrub/repair路径修复（rt refcount/rt rmap/inode repair/配额迭代等） |
| **🟡 VFS** | **start_removing_noperm() 回退** | 导致FUSE_NOTIFY_INVAL_ENTRY负dentry失效的回归修复 |
| **🟡 timekeeping** | **clocksource锁顺序修复** | 启动时raw spinlock下取sleeping mutex的死锁风险 |
| **🟡 Bluetooth 6lowpan** | **chan->conn UAF修复** | L2CAP conn引用计数变更后的未清理路径 |

> 💡 **7.1.4 的 RDMA 修复最为关键**：siw (iWARP) 和 rtrs 两处 RDMA 内存越界/信息泄露修复直接关系到 RDMA 集群安全

### 2️⃣ 🔬 **专项分析：fuse-uring 批量安全修复 — 10+ 补丁齐发** 🔐

- **来源**: Linux 7.1.4 changelog (kernel.org)
- **背景**: FUSE 文件系统在 6.14 内核引入了 io_uring 支持（`fuse-uring`），这是近年来 FUSE 最大的架构变更。本次 7.1.4 一次性修复了 **10+ 个 fuse-uring 相关问题**
- **修复分类**:

| 严重性 | 修复数 | 典型问题 |
|:------:|:------:|:---------|
| 🔴 **UAF/空指针** | 5 | cancel路径未终结fuse_req导致阻塞/取消后entry残留导致解引用、异步停止队列UAF |
| 🔴 **数据竞态** | 2 | ring->ready弱排序架构可观测到不一致的fiq->ops、commit fetch未加锁读queue->stopped |
| 🟡 **逻辑错误** | 3 | EFAULT返回值被正数residual覆盖、background队列深度只生效到1、32位prune计数溢出 |
| 🟡 **W^X/一致性** | 2 | re-lock遗漏、内存屏障缺失 |

- **修复方式特征**: 多个补丁由 **Chris Mason**（Btrfs维护者）和 **Joanne Koong**（fuse-uring原作者）主导，且 `Assisted-by: kres (claude-opus-4-7)` 出现多次
- **对服务器团队**: 🟡 **建议关注**
  - 生产环境使用 FUSE 文件系统（如 s3fs-fuse、gcsfuse、GlusterFS 的 FUSE 桥接）且启用了 io_uring 的场景
  - 这些问题从 6.14 引入 fuse-uring 以来累积至今，本次是首次集中修复
  - 建议将 7.1.4 纳入内核升级清单

### 3️⃣ 🔬 **XFS + LOLLM：LLM 辅助内核代码审计崭露头角** 🤖🔎

- **来源**: Linux 7.1.4 changelog (Darrick J. Wong 系列补丁)
- **发现**: Darrick J. Wong（XFS 联合维护者）的 12+ 个 XFS 修复补丁中，绝大多数标注了 **`Assisted-by: LOLLM # finding obvious bugs`**
- **LOLLM 是什么**: LWN 之前报道过，这是一个专门用于找代码bug的LLM工具/项目
- **LOLLM 发现的问题类型**:
  - 错误传递了 btree cursor 类型（rtrefcount vs 非rt）
  - 写完 rtgroup superblock 但未实际写入磁盘
  - rtrmap 交叉检查时的 off-by-one
  - 条件判断逻辑取反（`enable interruptible sorts` 写成了 `disable`）
  - dqiterate 32位 ID 回绕
  - 时间戳 nsec 的 off-by-one（tv_nsec == 1e9）
  - parent handle 缺少generation检查
- **对服务器团队**: 🟡 **趋势信号**
  - LLM 辅助内核代码审计开始产生实际产出 — 发现的都是"明显的bug"但人类审查容易错过
  - 与 `Assisted-by: Codex:gpt-5.5-cyber-preview`（fuse 32位计数溢出修复）、`Assisted-by: Antigravity:gemini-3.5-flash`（Input驱动）等并列，显示多种LLM已进入内核开发流程
  - 对服务器长期可靠性：LLM审计可能在后续版本捕获更多条件边界漏洞
