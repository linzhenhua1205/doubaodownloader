### 2️⃣ [新] BPF 屏蔽运行中内核的漏洞利用 — Cisco 实战方案 🛡️🐝

- **来源**: LWN.net (Jul 13, daroc) — 2026 LSFMM+BPF Summit 报道
- **演讲者**: John Fastabend (Cisco)
- **背景**: Cisco 面临在多台运行自定义内核的设备上部署安全补丁的巨大挑战
- **核心方案**: **用 BPF 防止漏洞利用** — 在漏洞对应的 kernel hook 点注入 BPF 程序，垫片层拦截攻击路径
- **关键结论**:
  - ✅ 能**大幅缩短**对内核漏洞的响应时间（从等补丁→改配置→重启，到 BPF 热加载）
  - ❌ **不会完全有效** — 除非内核添加更多 hooks 点供 BPF 挂载
  - ⚡ 目前已有可用的 hooks 覆盖了大部分常见漏洞利用路径，但存在盲区
- **对服务器团队**:
  - 🟡 **重要信号** — BPF 正在从"可观测工具"进化为"安全防护层"
  - 对 AI 集群: 万卡集群内核安全热修复一直是大难题，BPF 提供了一条不重启的路径
  - 企业级场景: 期待更多 kernel hook 点加入主线，以覆盖全面

### 5️⃣ [新] AI Agent 生产失败根因 — 缺少基础设施层 🤖❌

- **来源**: Red Hat Blog (Jul 13, Naszcyniec)
- **核心论点**: AI Agent 在生产环境失败，主要原因不是模型能力不足，而是**缺少基础设施层**
- **三个真实失败案例**:
  1. Agent 调用 SaaS API → API 限流/认证过期 → 任务中途死掉
  2. Agent 访问企业知识库 → 权限配置不一致 → 访问被拒绝或返回错误上下文
  3. Agent 做批量推理 → 资源争抢/非预期高延迟 → 超时放弃
- **Red Hat 定位**: 用 Red Hat AI Inference + OpenShift 提供 Agent 基础设施层
- **对服务器团队**: 🟢 低 — 了解 Agent 基础设施需求趋势，作为 AI 集群能力规划的输入
