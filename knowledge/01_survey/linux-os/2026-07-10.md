## ⚡ K8s 核心组件

### 1️⃣ etcd v3.7.0 GA — RangeStream 正式发布 🗄️🆕

- **来源**: Kubernetes Blog (Jul 8, SIG etcd Leads)
- **核心**: etcd v3.7.0 正式版发布，这是 etcd 的重要里程碑版本
- **关键特性**:
  - 🎯 **RangeStream**: 长期被请求的功能，支持对键范围进行流式监听，大幅提升大规模集群的 watch 效率
  - 包含大量重构和清理工作（从 v3.6 以来的累积改进）
- **对服务器团队的意义**:
  - etcd 是 K8s 控制面核心，RangeStream 直接影响大规模集群的 API Server watch 性能
  - 对于万卡集群控制面，etcd watch 优化可减少控制面压力
- **注意**: etcd v3.6.x 仍在维护周期内，升级前需评估兼容性

### 2️⃣ OpenShift Service Mesh 3.4 — Istio 1.30 + Kiali 2.27 🌐🆕

- **来源**: Red Hat Blog (Jul 9), Jamie Longmuir
- **基于**: Istio 1.30 / Envoy / Kiali 2.27，跳过两个 Istio 小版本升级
- **核心新特性**:

| 特性 | 状态 | 说明 |
|:----|:----:|:-----|
| Ambient mode 多集群 | 🧪 TP | multi-primary multinetwork 接近生产就绪，waypoint 跨网遥测修复 |
| Sidecar ↔ Ambient 共存/迁移 | ✅ GA | 官方支持双向迁移指南，可逐步渐进 |
| **原生 nftables 支持** | ✅ New | 为 RHEL 10+ 准备，sidecar + ambient 双模式，RHEL 10 将弃用 iptables |
| Kubernetes User Namespaces | ✅ New | 支持 hostUsers: false + Istio CNI 注入 |
| Kiali 多集群概览页 | ✅ GA | 全新架构，大幅降低内存和渲染时间 |
| TrafficExtension API | 🧪 TP | 统一 WasmPlugin + Lua 扩展，比 EnvoyFilter 更安全 |
| Zero Trust 身份管理器 | 🧪 TP | SPIRE 多因素认证 + 跨信任域联邦 |
| AI 辅助排障 (Lightspeed) | 🧪 TP | MCP 协议集成，token 用量分析，提示注入防护 |
| CRL 证书撤销支持 (ztunnel) | ✅ New | Ambient mode 证书撤销验证 |
| Core Istio 网络策略 | ✅ New | 最小权限 ingress 加固，后续版本默认开启 |
| Gateway API 1.5 | ✅ 支持 | TLSRoute termination + 混合模式，东西向 TLS 透传 |
| Kiali 命名空间多租户 | ✅ New | 按 get 权限限制命名空间可见性 |

- **EOL**: OpenShift Service Mesh 2.6 已于 **2026-06-30** 停止维护
- **对服务器团队的意义**:
  - **nftables 支持**是重要信号：RHEL 10 将全面转向 nftables，当前集群需评估 iptables 依赖
  - Ambient mode 多集群接近 GA，适合跨机房数据中心服务网格场景
  - AI 辅助排障（Lightspeed + MCP）为大规模集群运维提供新范式

## 🔥 安全

### 3️⃣ OpenMandriva 仓库遭破坏 — 供应链安全警钟 ⚠️🆕

- **来源**: LWN.net (Jul 8, jake)
- **事件**: OpenMandriva 发行版报告其仓库遭内部破坏
  - 一名被踢出社区的贡献者利用遗留的管理员凭据
  - **删除了部分 GitHub 仓库内容**
  - **在 cooker 仓库中发布空包**，导致所有 gnome 和 cosmic 包被覆盖（标记为过时）
  - 可能损坏使用 gnome/cosmic 用户的系统
- **事后处理**:
  - 已恢复删除的仓库和损坏的包
  - 完成全系统审计，除上述外**未发现其他违规**
- **对服务器团队的意义**:
  - 这是**内部人员威胁（insider threat）**的典型案例：即使某人已离开社区/组织，遗留的管理员凭据可能被滥用
  - 暴露了几个核心问题：
    1. 凭据回收流程不完善
    2. 仓库保护机制（如 branch protection、admin 审计）不足
    3. 空包覆盖已有包的机制缺乏防护
  - **可对比参考**: 此前 Go 仓库 socks5 投毒（社会工程学）、xz-utils 后门（长期潜伏）等供应链事件，本次是内部破坏（非后门植入）

## ⚡ 内核 & LWN 本周精选

### 5️⃣ Secure Boot 证书到期跟进 — 影响服务器启动链 🔑

- **来源**: LWN.net (Jul 1, bexelbie/Microsoft)
- **核心**: 微软用于 Linux 安全启动验证的证书之一已到期
  - 能正常启动的系统**不会因此停止工作**（硬件固件缓存的签名仍然有效）
  - 但**问题场景**：新安装/新签名二进制时，依赖已过期证书的验证可能失败
  - 依赖已签名二进制的时间窗口比看起来短
- **对数据中心团队的意义**:
  - 大规模服务器部署/重装时需确保 Secure Boot 证书链更新
  - 特别是裸机部署、PXE 安装场景需要检查固件证书更新状态

### 🔟 内核加速 — RCU + kmalloc_nolock() 无锁分配 ⚡🆕

- **来源**: LWN.net (Jul 7, daroc, LSFMM+BPF 2026 会议)
- **背景**: Puranjay Mohan 分享 RCU 加速工作 + Harry Yoo/Alexei Starovoitov 介绍 `kmalloc_nolock()`
- **核心**:
  - **`kmalloc_nolock()`**: 从任何内核上下文进行无锁分配的新函数，与 RCU 子系统协同工作
  - RCU 加速：减少 read-copy-update 的临界区开销
- **意义**: 这对 BPF 程序、网络包处理、高频率内存分配场景有直接性能提升
- **注意**: 两个 session 在同一会场上半段/下半段，内容互补

### 1️⃣1️⃣ 内核加密框架现代化 — LSS 2026 🛡️🆕

- **来源**: LWN.net (Jul 8, jzb, Linux Security Summit 2026)
- **主讲**: Eric Biggers（内核加密子系统维护者）
- **核心**:
  - 传统 crypto API 存在**脆弱性**：复杂的异步回调、容易出错的内存管理、不利于静态分析
  - **Library API**（新方案）：开发者可直接调用加密函数（如 `aes_encrypt()`），无需经过传统 crypto API 的异步框架
  - 简化了开发者和内核维护者的工作
  - 这是内核加密子系统的**长期现代化方向**
- **对服务器团队**: 了解即可，用户态不直接涉及

### 1️⃣2️⃣ OpenSSH 10.4 — 后量子签名实验支持 🔑🆕

- **来源**: LWN.net (Jul 6, jzb)
- **版本**: OpenSSH 10.4
- **关键特性**:
  - **后量子复合签名方案**（实验性）：ML-DSA 44 + Ed25519 组合签名（IETF draft）
  - **安全加固**：开启 sandbox 编译的 sshd 在未启用 SECCOMP 或 NO_NEW_PRIVS 的 Linux 系统上将直接**拒绝启动**（之前仅打日志）
  - 多个安全修复和 bug fix
- **对服务器团队**: 后量子签名是长期演进方向，当前阶段了解即可。**SECCOMP 强制检测**影响老系统部署

### 1️⃣3️⃣ Rust 1.97.0 — 新符号改名方案 🦀🆕

- **来源**: LWN.net (Jul 9, corbet)
- **版本**: Rust 1.97.0
- **关键变化**:
  - 默认使用新的 symbol-mangling 方案（影响二进制兼容性）
  - Cargo 支持 deny warnings
  - 成功构建后不再隐藏链接器输出（方便调试）
- **对服务器团队**: 如果内核模块/用户态组件使用 Rust，注意 symbol-mangling 变更导致的 ABI 兼容性

### 1️⃣4️⃣ Trusted Publishing — 不能当作安全信号 ⚠️🆕

- **来源**: LWN.net (Jul 7, jzb, Woodruff 博客)
- **核心观点**: William Woodruff（"yossarian"）指出 Trusted Publishing 只是**认证机制**，不是**安全/质量信号**
  - Trusted Publishing 只说明上传经过了认证（所有 PyPI 上传都经过认证）
  - 它**不是**绿色勾号，不能用于判断包是否安全或"好"
  - PyPI 有意识地避免将其渲染为安全标记以防止误用
- **对服务器团队**: 在内部制品仓库/镜像管理中使用类似机制时，注意不要将其等价于安全检查
