## ⚡ LWN 本周重点

### 1️⃣ AI 爬虫问题持续恶化 — 开放 web 可持续性危机 🤖🌐

- **来源**: LWN.net (Jul 10, corbet)
- **背景**: LWN 早在 2025 年初就报道了"Fighting the AI scraper bot scourge"问题。一年半后，情况不但没有缓解，反而持续恶化
- **核心**: 
  - 大量无名实体的爬虫流量冲击网站达到新高
  - 开放 web 正变得**越来越难以维持（the open web is becoming increasingly difficult to maintain）**
  - 这些流量来自哪里？我们能做什么？
- **对服务器/运维团队**:
  - 底层技术: bot 识别/流量过滤/CDN 防护是基础设施层必备能力
  - 长远看: AI 训练数据获取模式的演变可能改变 web 架构（更严格的 API 策略、付费墙、认证访问）
  - 内部: 企业内部知识源的爬虫防护策略需评估
- **LWN 本身**: 作为靠订阅维持的网站，LWN 是少数能抵御爬虫冲击的独立技术媒体。**订阅 LWN 是维护开源技术信息源可持续性的直接方式**

### 2️⃣ QBE 1.3 — 小型编译器后端里程碑 🦅

- **来源**: LWN.net (Jul 10, arshal)
- **QBE**: Quentin Carbonneaux 开发的轻量编译器后端，是 LLVM/GCC 的替代品，设计核心是"小到单个开发者能完全理解"
- **v1.3 新特性**:
  - **元编程（metaprogramming）**: 编译时代码生成能力
  - 性能优化
  - 跨平台支持增强
- **路线**: QBE 是 Hare 语言和 cproc C11 编译器的后端，正在逐步成熟
- **对服务器团队**: 低优先级，了解即可。QBE 代表了编译器领域"少即是多"的设计哲学，对嵌入式/定制编译场景有长期参考价值

### 3️⃣ Kitty 终端模拟器 — 鼠标支持升级 🐱

- **来源**: LWN.net (Jul 9, leephillips)
- **新特性**: 
  - 重大发布添加了新的鼠标支持级别
  - 可作为基于文本应用的平台使用
  - 支持图像、高级字体处理
- **对服务器团队**: 🔵 低 — 日常运维终端选择，个人偏好为主

## 🏢 Red Hat 动态

### 5️⃣ Red Hat AI: 可插拔 Agent Mesh 架构 🤖🆕

- **来源**: Red Hat Blog (Jul 10, Domkowski/Awofolu/Browning)
- **核心**: Red Hat AI 团队发布 Agent Mesh 架构 — 用于软件现代化的可插拔 Agent 网格
- **关键设计原则**:

| 层级 | 可插拔性 | 说明 |
|:-----|:--------:|:-----|
| **模型** | ✅ 无侵入替换 | 通过 vLLM + Red Hat AI Inference 服务，Gemma 4 接入零改动 |
| **Agent** | ✅ 接口化替换 | Claude Code/Codex ↔ OpenCode/自定义 Agent，YAML 配置切换 |
| **静态工具** | ✅ 组件化 | OpenRewrite / 迁移工具包，可增删不改编排层 |
| **编排框架** | ⚠️ 有限耦合 | CrewAI 0.x→1.x 升级需重构 mesh 代码但上层保持稳定 |

- **实战案例**: 
  - **Gemma 4 替换**: 零改动接入，vLLM 原生 tool call 解析器 + chat template
  - **CrewAI 升版**: 0.x → 1.x 需代码层调整，但 harness 模式（5 大能力: 代码考古/特征测试/计划/变更生成/审查）保持稳定
  - **chat template 修复**: Red Hat 团队发现 Gemma 4 template 处理 OpenCode system message 的 bug，提 PR 修复后 24h 合入上游
- **对服务器团队**: 
  - 🟢 低信号，但可参考其**模型/Agent/工具分层解耦**思路
  - vLLM + 可插拔 AI 推理架构是长期方向
