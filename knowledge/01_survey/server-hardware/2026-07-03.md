## 1️⃣ 🔥 AMD Instinct MI450X IF128 — 128-GPU 机架级系统正面迎战 Nvidia VR200

**来源**: [Tom's Hardware - AMD preps rack-scale Instinct MI450X IF128 with 128 GPUs](https://www.tomshardware.com/tech-industry/artificial-intelligence/amd-preps-rack-scale-instinct-mi450x-if128-with-128-gpus-to-challenge-nvidias-vr200-nvl144-in-2026) (Anton Shilov, May 16 2025, via SemiAnalysis)
**来源**: SemiAnalysis 付费报告

### 🔬 系统架构

AMD 的首个机架级 AI 系统，直接对标 Nvidia VR200 NVL144（72 GPU）：

| 维度 | MI450X IF64 | MI450X IF128 | Nvidia VR200 NVL144 |
|:-----|:-----------|:------------|:-------------------|
| **GPU数** | 64 | **128** | 72 |
| **机架** | 单rack | 跨2个rack（Infinity Fabric over Ethernet） | 单rack |
| **服务器单元** | — | **16× 1U 服务器** | — |
| **每服务器** | — | 1× EPYC Venice CPU + **4× MI450X GPU** | — |
| **互连方案** | 简化设计 | 被动铜缆（非Nvidia有源光缆） | 有源光缆AOC |

### 📊 性能与带宽数据

| 指标 | 数值 |
|:-----|:-----|
| **GPU内单向带宽** | **>1.8 TB/s** / GPU（同scaling域内） |
| **Scale-out网络** | **3× 800GbE Pensando** / GPU = 2.4 Tb/s 总出站带宽 |
| **次级方案** | 2× 800GbE/GPU（但PCIe 5.0带宽不足以跑满） |
| **互连策略** | 被动铜缆 — 降低成本与功耗，但有SI/线长限制 |
| **发布窗口** | **2026** |

### ⚠️ 风险分析

- 系统复杂度极高，制造/部署可能面临延迟与技术问题
- IF64（单rack简化版）作为保底方案，预计更可控
- 铜缆 vs Nvidia有源光缆 — 信号完整性是核心约束
- 若执行成功，可显著提升AMD在AI推理市场的竞争力

## 3️⃣ 🧠 AMD Zen 6LP — 低功耗核心在 Linux 内核中确认

**来源**: [Tom's Hardware - AMD confirms low-power CPU cores in Linux kernel patch](https://www.tomshardware.com/pc-components/cpus/amd-confirms-low-power-cpu-cores-in-linux-kernel-patch-zen-6-chips-could-follow-in-intels-footsteps-with-new-core-type-for-background-tasks) (Anton Shilov, June 30, 2026)

### 🔬 三阶核心架构

AMD 通过 CPUID Function 0x80000026 (Extended CPU Topology) 的 EBX bits [31:28] 区分三类核心：

| 核心类型 | 代号 | 用途 |
|:---------|:-----|:-----|
| **0** | **Performance** | 高性能核心 |
| **1** | **Efficiency (C-core)** | 高效能核心（现有Zen 5c类） |
| **2** | **Low-Power (LP)** | 新增: 后台/idle轻负载 |

### 📊 技术要点

| 要点 | 细节 |
|:-----|:-----|
| **提交者** | AMD 工程师 Vishal Badole |
| **设计目标** | "降低后台与空闲任务的能耗" | 
| **架构策略** | 同微架构不同优化（非Intel式完全不同的微架构） |
| **与Zen 5c区别** | Zen 5c是面积优化（dense），LP是**功耗优化** |
| **适用平台** | 很可能Zen 6 APU优先（Olympic Ridge），桌面Zen 6待定 |
| **对标** | Intel Nova Lake的LPE cores（SoC tile内的低功耗岛） |

> 标志着 AMD 从 **big.LITTLE** 向 **big.MEDIUM.tiny** 的三阶混合架构演进。

## 4️⃣ ⚛️ AMD Versal HBM 停产 → 全面转向 LPDDR5X 封装

**来源**: [ServeTheHome - AMD Pivots From HBM to LPDDR5X For New Versal Premium Gen 2 Memory on Package Chips](https://www.servethehome.com/amd-pivots-from-hbm-to-lpddr5x-for-new-versal-premium-gen-2-memory-on-package-chips/) (Ryan Smith, June 30, 2026)

### 🔬 时间线

| 事件 | 日期 |
|:-----|:-----|
| Versal HBM 停产宣布 | **2025年9月** |
| Versal HBM **最后下单日** | **2026年6月30日**（今天！） |
| Versal Premium Gen 2 LPDDR5X 发布 | **2026年6月30日** |

### 📊 为什么 HBM 做不下去了？

| 因素 | 详情 |
|:-----|:------|
| **HBM2e 供应枯竭** | 三大HBM厂商全力转产HBM3，HBM2e产线关闭 |
| **AI Boom 挤占产能** | AMD Instinct/Nvidia H100/B200 吃掉所有HBM产能 |
| **FPGA生命周期长** | Xilinx传统芯片供货到2045年，HBM跟不上这个节奏 |
| **替代方案** | **LPDDR5X** — 供应稳定、生命周期长、经济可行 |

> **标志性意义**: AI boom 正在从加速器端向整个半导体供应链传导，连相对低容量的FPGA HBM都被挤掉了。

## 5️⃣ 🏗️ Qualcomm Dragonfly C1000 + HBC — 千兆互联与近存计算

**来源**: [ServeTheHome - Qualcomm Investor Day 2026 Data Center Announcements](https://www.servethehome.com/qualcomm-investor-day-2026-data-center-announcements/) (Patrick Kennedy, June 24, 2026)

| 指标 | 数据 |
|:-----|:-----|
| **核心数** | **250+** chiplets |
| **PCIe** | **PCIe Gen7** |
| **内存** | LPDDR5X + 可选 **HBC (High Bandwidth Compute)** 近存加速 |

### 🔬 HBC (High Bandwidth Compute) 近存计算架构

| 维度 | 细节 |
|:-----|:------|
| **核心思路** | **LPDDR堆叠在compute tile之上**，不再走CoWoS+HBM |
| **带宽优势** | 省掉interposer上的功耗与延迟，类似近存计算 |
| **容量** | ~**768 GB** LPDDR（远超HBM容量） |
| **首发** | **AI250 加速器** — **2027年** |
| **Gen2** | AI300+ 集成 ESUN/UALink fabrics |
| **关键客户** | **Meta**（Mark Zuckerberg上镜确认多代合作） |
| **其他客户** | 2个hyperscaler在FY27各驱动 >$10亿收入 |

### 📊 Qualcomm 数据中心财务框架

| 指标 | 2024 | FY29目标（18月前） | FY29更新目标 |
|:-----|:-----|:-----------------|:------------|
| 数据中心收入 | 0（仅connectivity） | $22B | **$40B** |
| TAM份额目标 | — | — | **>5% / $1T+ TAM** |

> **判断**: 这不同于Centriq 2400时代的失败。Qualcomm有了Meta等坚定客户+Modular软件栈+HBC差异化技术，但**2028年才出CPU**意味着当前主要还是靠connectivity和ASIC服务。
