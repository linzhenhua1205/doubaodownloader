## 二、NVIDIA BlueField-4 DPU：从"可选插卡"到"AI Factory 可信前端"（08-25）

- **来源/标题**: [NVIDIA BlueField-4 DPU at Hot Chips 2026](https://www.servethehome.com/nvidia-bluefield-4-processor-at-hot-chips-2026/)（ServeTheHome, 2026-08-25, Patrick Kennedy）📎 raw: tmp/raw/2026-08-27/nvidia-bluefield-4-processor-at-hot-chips-2026.md
- **定位**: BlueField-4 = 第四代 DPU，NVIDIA 叙事中是"连接 CPU、GPU、网络"的组件，支撑 agentic AI 的 observe → reason → act 闭环；属于 **Vera Rubin 全栈 AI Factory 的 7 颗芯片之一**（Vera CPU、Rubin GPU、BlueField-4、Spectrum-6、Groq LPU）
- **角色升级**: DPU 被定义为平台的**"可信实体"（trusted entity）**——"server in front of the server"，隔离 host 与数据中心 fabric，**拥有租户数据路径（tenant data path）**；每个 Vera Rubin 系统 co-design 内置 BlueField，而非可选插卡
- **架构分层新增 "scale-in"**: NVIDIA 把网络分为 scale-up（NVLink，多 GPU 如单系统）/ scale-out（ConnectX + Spectrum-X，数据中心如单计算单元）/ **scale-in（新增，host 与数据中心之间的流量，跨多租户多应用）**；BlueField-4 Spectrum-X scale-in network 面向混合 agentic 负载
- **核心规格**: **Grace CPU + 64 Arm Neoverse V2 核 @ 1.7GHz**、LPDDR5 **275 GB/s**、**ConnectX-9 800G Ethernet（200G PAM4 SerDes）**、inline encryption、**PCIe Gen6 x16** host 接口——STH 点评 1.7GHz 低于 GB300 系统上的 Grace，疑似为低功耗包络刻意降频；预计远快于 Xsight E1（V2 vs N2 核心）
- **带宽跃迁**: 云 DPU 时代 200 Gb/s 级 → AI DPU **7 Tb/s 聚合带宽**；Vera Rubin 每计算托盘需 **7 Tb/s = 4× 1.6 Tb/s GPU scale-out + 800 Gb/s scale-in 到 DPU**
- **非 DPU 方案的代价（NVIDIA 论证）**: ① 安全缺口——传统方案只隔离 scale-in 流量，scale-out 无法端到端安全隔离；② **功耗 4x**——每 NIC 需独立 CPU、内存子系统、管理连接；BlueField-4 前置后 4x 功耗优势
- **Astra（7 Tb/s 平台级安全/管理）**: DPU 拥有数据路径、零信任强制 + 线速遥测不碰 host；用 Astra links（Vera Rubin 中类似 PCIe）承载管理，避免每个 ConnectX-9 链路都挂 BlueField-4
- **存储性能**: **NVMe-oF on BlueField-4 Grace = 1.6 Tb/s @ 8 核、20M IOPS @ 16 核**，GPU 数据访问路径 2x 快；**DOCA MEMOS storage-scale = 3.2 Tb/s、10x IOPS、5x 效率**，KV context 从 GPU HBM → 系统内存 → 本地/网络存储分层
- **scale-in 存储访问加速**: Spectrum-X 对比 off-the-shelf Ethernet——**5GB 文件 1.5x、10GB 1.4x、50GB 1.3x**
- **安全/可编程**: DOCA Flow / DOCA Vault / DOCA Argus 把文件、对象、处理器、网络上下文映射到策略；in-silicon 策略强制；小包线速转发（控制面小包场景）
- **命名体系**: "BlueField-4" 覆盖 **BlueField-4G（Grace + 单 ConnectX-9）** 到 **BlueField-4V（单/双 Vera + 多 ConnectX-9）**——STH 建议改名为 4G/4V 区分

**BlueField-4 分析**：这场演讲的信号不在于规格表，而在于**NVIDIA 对 DPU 产品形态的重新定义**——上一代 BlueField-3 还是"插入现有服务器的 PCIe 卡"，BlueField-4 是"AI Factory 的默认组件，与 CPU/GPU/NIC 深度 co-design"。这背后是超大规模客户（Meta 等）大规模用 DPU 的产业现实：**当 DPU 从可选变必选，网络安全的控制点就从"每个租户的软件栈"上移到"平台硬件层"**，租户数据路径被 NVIDIA 硬件拥有。对服务器硬件厂商的含义：**机架设计时 DPU 不再是"要不要加"而是"如何集成"**——供电、散热、管理网络（Astra links）、NVMe-oF 存储路径都要为 BF4 预留。值得注意的是 1.7GHz 的低频选择——NVIDIA 明显在功耗与性能间取平衡（每个托盘 7 Tb/s 带宽 + 4x 功耗叙事下，DPU 自身功耗必须收敛），这与 Broadcom Thor 的 40-42W 芯片功耗形成对照：**AI 时代的网络芯片也开始卷能效（per-Gbps 功耗）**。

## 三、Broadcom Thor Ultra Ethernet NIC：800G 开放路线的完整工程细节（08-25）

- **来源/标题**: [Broadcom Thor Ultra Ethernet NIC at Hot Chips 2026](https://www.servethehome.com/broadcom-thor-ultra-ethernet-nic-at-hot-chips-2026/)（ServeTheHome, 2026-08-25, Patrick Kennedy）📎 raw: tmp/raw/2026-08-27/broadcom-thor-ultra-ethernet-nic-at-hot-chips-2026.md
- **定位**: Thor Ultra = 800GbE NIC，面向 AI/HPC fabric；Ethernet 覆盖三域——**scale-up（rack 内）/ scale-out（跨 rack）/ scale-across（跨数据中心）**，各层共享需求：高带宽、增强 RDMA、低延迟、QoS + 虚拟化/安全/时间/遥测/诊断
- **接口规格**: **PCIe Gen6 x16 host + 8-port 100G MAC + 256 SR-IOV VF + 8× 100G Serdes**；offload RoCEv2、stateless packet processing、inline encryption；增强 RoCE **>64K QP**；TruFlow 引擎 + BroadSAFE 安全
- **芯片物理**: **5nm、24 亿晶体管、27×27mm 封装、40-42W max**；die 内含 TX/RX buffer、嵌入式 CPU 子系统、P4-like 可编程引擎（承载大部分 eRoCE 工作）
- **板卡形态**: OCP NIC 3.0 + PCIe 形态；**1× OSFP112（800G/2×400G/4×200G/8×100G 复用）或 2× QSFP112**；线缆覆盖 DAC/LPO/AEC/光；板卡 50-55W（不含光模块）
- **代际跃升（对比前代 Thor）**: **packet spraying + out-of-order placement**、可靠性超越 Go-Back-N、更简单可编程拥塞控制、**端口翻倍 + multiplane 连接**
- **eRoCE 实现**: multipath 跨最多 **8 plane** 喷洒；out-of-order placement 处理 RDMA 响应（send/atomics 保持有序）；选择性 ACK/NACK + 重传；**per-packet 路径选择**，header 携带 placement 信息；SACK bitmap 按 QP 跟踪；接收端重排后再按序交付
- **拥塞控制**: **Receiver Credit-Based Congestion Control（RC-CC）为 eRoCE 基线**——接收方向活跃发送方授信、speculative credits 线速启动、感知 ECN/trimming/CSIG 遥测、P4-like match-action 引擎支持定制算法
- **对等内存（GPU 直连）**: **dma-buf 本地 peer-to-peer DMA**（NIC↔GPU 内存）+ eRoCE 远程传输；RoCE 用户库用户态、驱动内核态
- **软件栈**: 内核 **bng_re（RoCE）+ bng_en（NIC）双驱动**，libbng_re 用户库，标准 libibverbs/rdma-core；**peer memory + direct collectives 经 verbs provider / xCCL plugins 连 NCCL、RCCL、MPI**——upstream dma-buf 模型，应用零修改
- **实测数据（Gen5 GPU 平台，2 节点 × 8 GPU，16 ranks × 16 400G 链路）**:
  - all_reduce **383.93 GB/s**、reduce_scatter **380.23 GB/s**（400 GB/s 上限下）——总线带宽 >96% 线速
  - alltoall 84.62 GB/s（工作负载特性决定，明显低于前两者）
  - TCP（Gen6 CPU + 512GB DDR5-8000）: 单向往 **791 Gbps @ 16 流（98.9% 线速）**；双向 ~1.51 Tbps；8 流近线性
  - RDMA 写: 单向 **781 Gbps 饱和**、双向 **1558 Gbps（97.6% 1.6Tb/s 聚合）**；32KB 消息达 88% 线速、128KB 进入峰值 3% 内
- **时间/安全/可管理**: PTPv2 纳秒时间戳 + Precision Time Measurement（PPS in/out、time-of-day plane、外部 TCXO）；FUSE root of trust + ROM boot + 认证固件 + SPDM 证明 + PSP 加解密；健康监控/温度/眼图/诊断/DMTF-OCP 标准管理
- **竞争定位（STH 点评）**: 与 NVIDIA ConnectX-8、AMD Vulcano 同场竞技；数据路径为增强 RoCE / MRC++ 构建，QoS + 虚拟化支持 XPU/CPU as a service

**Thor Ultra 分析**：Broadcom 这场演讲的价值在于**把"开放 Ethernet 路线能否支撑 AI 规模网络"从口号变成了可验证的工程事实**——96% 线速的集体通信、97.6% 的 RDMA 写聚合效率、98.9% 的 TCP 线速，配上 40-42W 的芯片功耗，说明 800G 开放路线在性能上已经不输私有 fabric 太多。三个技术细节值得注意：**① packet spraying + 乱序放置**——这是对标 NVLink/InfiniBand 类私有 fabric 的关键能力，把多路径利用率从"流级"提升到"包级"，是 800G 时代突破单路径瓶颈的必经之路；**② Receiver Credit-Based CC**——把拥塞控制从"发送方猜测"变成"接收方授信"，配合 speculative credits 解决线速启动问题，这是 Ultra Ethernet 联盟（UEC）路线图的核心组件；**③ P4-like 可编程引擎**——保持协议可演进性，让客户可以定制拥塞算法而不等厂商固件。对万卡集群运维的启示：**Thor Ultra 的 dma-buf peer memory + xCCL plugins 意味着 NCCL 可以不经过 CPU 内存直达 GPU**，这会把 GPU 直连网络的延迟再压一档——与昨日 NVIDIA "130 TFLOPS in-network compute" 的叙事正面竞争，只是路径相反（开放 vs 封闭）。

## 四、800G NIC 三方对决：Thor Ultra vs ConnectX-8 vs Vulcano（横向对比）

| 维度 | Broadcom Thor Ultra | NVIDIA ConnectX-8 SuperNIC | AMD Vulcano 800 |
|:--|:--|:--|:--|
| 速率 | **800G**（1×OSFP112 或 2×QSFP112） | **800G**（PCIe Gen6，双 400G 形态） | **800G**（单端口） |
| host 接口 | PCIe Gen6 x16 | PCIe Gen6 | PCIe Gen6 x16 + UAL128 |
| 芯片 | 5nm，24 亿晶体管，40-42W | 未披露（ConnectX-7 同代 7nm 起） | 未披露 |
| 可编程性 | **P4-like match-action 引擎** | 固件 + FlexIO | **P4 可编程**（192 MPUs + P4DMA） |
| RDMA 路线 | **eRoCE（喷洒+乱序+RC-CC）** | RoCEv2 + NVIDIA 私有扩展 | **MRC**（800G 端口可拆 1x/2x/4x/8x） |
| GPU 直连 | dma-buf peer memory + xCCL | GPUDirect RDMA（NVIDIA 生态原生） | peer memory + 共享内存模型 |
| 生态绑定 | **开放（UEC/UALink 阵营）** | NVIDIA 全栈（DOCA/Spectrum-X） | AMD 开放（ROCm + 多供应商） |
| 实测 | all_reduce 383.93 GB/s（400GB/s 上限） | 未在本期披露 | 昨日收录：all-reduce 单 QP 优势 |
| 拥塞控制 | Receiver Credit-Based（可编程） | 私有（配合 Spectrum-X） | MRC/UEC 框架 + DCQCN 兼容 |
| 关键信号 | 开放路线性能已达标 | 私有路线确定性（10x 低延迟叙事） | 拆分粒度最灵活（8×100G） |

**分析**：三强格局的本质是**两条技术路线的碰撞**。Broadcom 与 AMD 站在开放侧——都强调 P4 可编程、标准 Ethernet、多供应商互操作（UALink/UEC 联盟），差异在于 Thor 更偏"高性能通用 NIC"（eRoCE + 多平面 + 接收方授信），Vulcano 更偏"协议可拆分的弹性"（MRC 把 800G 拆成任意粒度、P4DMA 高频遥测）。NVIDIA 站在封闭侧——ConnectX-8 与 Spectrum-X 交换机、DOCA 软件栈、NVLink scale-up 构成闭环，用"确定性"（10x 低延迟、in-network compute）而非"开放性"取胜。**对超大规模客户的现实选择不是二选一而是分桶**：训练集群的 scale-out 若选开放 Ethernet 生态（省钱、多供应商），Thor/Vulcano 是主力；若追求极致确定性与全栈调优（NVIDIA 叙事），ConnectX-8 + Spectrum-X 仍是默认。但 Thor 96% 线速的实测说明**开放的代价（性能差）正在快速收敛**——这正是 2026-2027 年 scale-out fabric 选型最大的变量，也是服务器硬件追踪后续要盯的焦点：**Thor Ultra 在真实万卡集群（非 2 节点）上的集体通信效率、与 ConnectX-8 的混合部署互操作**。

## 五、FMS 2026 存储密度：Supermicro 160-bay 4U = 19-20PB/台（08-14）

- **来源/标题**: [160-bay NVMe SSD 4U Server Shown at FMS 2026 Supermicro ASG-4116S-NU160R](https://www.servethehome.com/160-bay-nvme-ssd-4u-server-shown-at-fms-2026-supermicro-asg-4116s-nu160r/)（ServeTheHome, 2026-08-14, Eric Smith）📎 raw: tmp/raw/2026-08-27/160-bay-nvme-ssd-4u-server-shown-at-fms-2026-supermicro-asg-4116s-nu160r.md
- **产品**: Supermicro ASG-4116S-NU160R——**160× U.2 NVMe 盘位、单路 AMD EPYC 9005（最高 360W）、4U**
- **容量**: 配 122-128TB 级盘（Solidigm D5-P5336 122.88TB 等）→ **约 19-20PB/单系统**；评论区 Ksec 指出 245TB 盘（Solidigm 2026 下半年）→ **~40PB/4U**
- **拓扑核心**: 160 盘 × 4 lanes = **640 PCIe lanes**（不含 NIC）——用**中心列 PCIe switches** 组网（类似 top-loading SAS 服务器架构，但以 PCIe switch 替代 SAS expander）
- **可服务性设计**: **上抽屉放 SSD、下抽屉放 CPU/内存/网络**，滑出式托盘维护（无需整机出柜）；前 I/O: 4× E1.S 槽 + IPMI + 双 USB + **2× 10Gbase-T（Broadcom BCM57416）** + **3× PCIe Gen5 x16 槽**（供 400GbE NIC / DPU）
- **密度对比**: 24-bay 2U × 7 台（168 bays）才能接近同等容量 → **省 ~6 颗 CPU + 72 根 DIMM**
- **功耗效率**: 冗余 **2.6kW PSU** 驱动整系统；**130-137W/PB all-in at outlet**——低于 500 块 HDD 同等容量的盘功耗
- **成本估算**: 122TB 级盘配置下 **$8-10M/台**
- **权衡**: PCIe switch 架构下每盘达不到最大顺序吞吐，但 lane 限制让盘可低功耗运行
- **联动信号（页面内）**: Sandisk 用 E3.S 原型盘演示**单台此类服务器移除 $300K DRAM、省 10kW+**（AI factory 场景）；FMS 2026 同步展出 Microchip **Switchtec 160-lane PCIe Gen6 switch**（更高 lane 密度的下一代）

**160-bay 存储服务器分析**：这则报道的产业含义远超"一台很挤的机器"。**640-lane PCIe switch 拓扑**意味着 PCIe 交换芯片正在取代 SAS expander 成为超大容量存储的中枢——这是 PCIe Gen5/Gen6 switch 生态成熟的直接证据（Microchip Switchtec 160-lane Gen6 同期展出，Astera Labs Scorpio 320-lane 也在推进）。**130-137W/PB 的功耗指标**则把存储密度竞争从"容量"拉到了"能效"维度——对比 HDD 时代每 PB 数千瓦，全闪存 4U 系统的每 PB 功耗已经反超。对服务器硬件设计者的启示有三：**① 供电设计**——2.6kW 冗余 PSU 在 4U 内驱动 160 盘 + 360W CPU，单机柜功率密度压力进一步上移；**② 散热**——160 盘 + PCIe switch + 360W CPU 在 4U 内，气流组织与风扇策略需要重新设计（存储服务器从"低功耗大容量"变成"高密度高功耗"）；**③ 网络瓶颈**——19-20PB 容量只有 2×10Gbase-T 板载 + 3×PCIe Gen5 x16 槽可插 400GbE NIC，**容量与带宽的剪刀差**（20PB 数据用 400GbE 传完需要数天）将成为这类系统的结构性矛盾——这也是 Sandisk "移除 DRAM" 叙事的背景：**存储密度越高，内存/网络瓶颈越显性，越需要近存计算或分层存储**。

## 六、AMD EPYC 8005 "Sorano"：SP6 插槽的性能画像重塑（06-29 报道，本期补全）

- **来源/标题**: [AMD EPYC 8005 Sorano Completely Changes AMD SP6](https://www.servethehome.com/amd-epyc-8005-sorano-completely-changes-amd-sp6/)（ServeTheHome, 2026-06-29, Patrick Kennedy）📎 raw: tmp/raw/2026-08-27/amd-epyc-8005-sorano-completely-changes-amd-sp6.md
- **定位**: EPYC 8005 "Sorano" 沿用 EPYC 8004 "Siena" 的 **SP6 socket**，但彻底改变插槽内性能画像；STH 称其为**自 EPYC 7002 Rome 以来最大的服务器产品线/插槽动荡**
- **兼容性**: 8004 → 8005 **drop-in 替代**（平台支持 + BIOS 更新即可）；SP6 封装尺寸 ≈ Threadripper / EPYC 7000 系
- **核心规格**: 最高 **84 核 / 168 线程 + 384MB L3**；**DDR5-6400**；**CXL 2.0**
- **核心架构变化（关键）**: 8004 用 **Zen 4c**（低缓存密度核）→ 8005 用 **Zen 5 全缓存核**——L3 大幅增大，与 EPYC 4005 / EPYC 9005 Turin（除 Dense）**同架构**，"架构差距关闭"
- **TDP/功耗**: 默认 TDP 上限升至 **225W（+25W / +12.5%）**；系统级 100% 利用率实际 +30-34W（<10%）——更多核 + 新架构 + 更快内存换来 <10% 功耗增量
- **价格**: SKU 8~84 核，**$529 ~ $5799**；**84 核 SKU 仅比 64 核略贵**——AMD 聚焦 $/core 指标
- **平台意义（评论区 Zibi 补充）**: Siena 原为 telco 设计（无 turbo、低延迟）；Sorano 更通用，为下一代 **Verano** 定调；填补 **16-32 核小型企业服务器**市场空白（Genoa/Turin 12 通道内存太贵）
- **实测**: STH AgentSTH V7 基准 + 多工具；单核性能大幅提升（Zen 4c → Zen 5 时钟差）；L1 0.88ns、deep-memory 7.2ns（评论区指出该值实为 L3 性能，真实深内存延迟 75-90ns——STH 已修正正文但图表残留旧值）；文章为 AMD 赞助（AMD 提供 CPU）

**Sorano 分析**：这则 6 月的新闻放在今天补全，是因为它与 Hot Chips 2026 的 CPU 叙事形成完整拼图。**SP6 从"边缘/telco 专用"变成"通用小型服务器平台"**，本质是 AMD 用同一插槽覆盖更广市场段的战略——Zen 5 全缓存核心下沉到中端，让 16-32 核的小型企业服务器（此前 Genoa/Turin 因 12 通道内存成本过高而缺席）获得与旗舰同架构的性能。三个推论：**① 服务器 CPU 的"性能分层"正在消失**——4005/8005/9005 同用 Zen 5 全缓存核心，差异只剩核数/通道/插槽，客户按规模而非架构选型；**② 对 Intel 的压力**——Diamond Rapids 256 核 + 模块化架构是 Intel 对 AMD 高核数的回应，但 SP6 的中端渗透（84 核 $5799）正在挤压 Xeon 的腰部市场；**③ 与 NVIDIA Vera 的错位竞争**——Vera 走"高 IPC + GPU 亲和"（88 核），AMD 走"同架构全价位覆盖"（8~84 核），Intel 走"高核数模块化"（256 核）——**2027 年服务器 CPU 的三条路线已经清晰**，追踪重点是各路线在 agentic AI 负载（长上下文 + 高交互）下的实际 tokens/MW。

## 九、趋势研判（供后续追踪）

1. **网络侧成为 Hot Chips 2026 的隐藏主线**：计算侧（GPU/CPU）已被充分报道，但 08-25 的 DPU/NIC 专场才是真正的新增量——**7 Tb/s 平台级 DPU（BF4）与 800G 开放 NIC（Thor）同日登台**，加上昨日 AMD Vulcano，三强格局确定。后续追踪：**Spectrum-X Multiplane 架构细节（下期优先）、Thor Ultra 在真实大规模集群的集体通信数据、UALink/UEC 标准进展**。
2. **开放 vs 封闭的 scale-out 之争进入实测阶段**：Thor 96% 线速、97.6% RDMA 聚合效率是开放路线的首个公开实测；NVIDIA 用 10x 低延迟 + in-network compute 回应。**2027 年万卡集群 fabric 选型将取决于这两条路线的规模化实测，而非纸面规格**。
3. **存储密度竞赛开启**：160-bay 4U（20PB→40PB）把存储服务器推入"单机 = 小型数据中心"时代；PCIe switch 640-lane 拓扑 + 130-137W/PB 能效是新标尺。后续追踪：**E3.S/E1.S 形态迁移（160-bay 用 U.2 被评论诟病）、PCIe Gen6 switch 量产（Microchip 160-lane / Astera 320-lane）、Sandisk 去 DRAM 方案落地**。
4. **CPU 三路线收敛于 agentic AI 负载**：AMD（同架构全价位，SP6 渗透中端）、Intel（256 核模块化 + 18A-P）、NVIDIA（88 核高 IPC + GPU 亲和）——**三家都在为"长上下文 + 高交互"重新设计 CPU**，tokens/MW 而非核数将成为选型第一指标。
5. **800V HVDC / 45°C 液冷 / 无电缆托盘的工程化落地**（昨日已收录）与 Delta 150kW 液冷-空气（本期标题级）互证——**机架级供电散热从"选项"变"标配"**，服务器硬件追踪将持续跟进 ODM/伙伴的落地节奏。
