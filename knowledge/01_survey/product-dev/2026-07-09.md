## 1️⃣ AI Agent 决策框架：何时用，何时不用

- **来源**: Product School — Carlos Gonzalez de Villaumbrosia, 2026-03-03
- **链接**: https://productschool.com/blog/artificial-intelligence/when-should-product-teams-use-ai-agents

### 核心框架：AI Agent 决策评分矩阵（0-24 分）

| 维度 | 0分 = 不需要 Agent | 1分 = 可能 | 2分 = 强适配 | 说明 |
|:-----|:-------------------|:-----------|:-------------|:-----|
| 规则自动化可行性 | 规则即可处理 | 部分边界情况 | 规则经常断裂 | Agent 在逻辑不稳定时最有用 |
| 多步骤工作流复杂度 | 单步 | 少量步骤 | 跨工具多步骤 | Agent 在协调成本高时最有用 |
| 工具交互需求 | 无工具 | 单系统 | 多系统 | Agent 强在编排工具 |
| 成功可衡量性 | 难以定义"正确" | 部分信号 | 清晰指标 | 必须能检测失败 |
| 错误动作成本 | 高+不可逆 | 中等 | 低或可逆 | 越高越要限制自主权 |
| 人类过度信任风险 | 非常可能 | 可能 | 不太可能 | 过度信任产生静默失败 |
| 输出的可逆性 | 难以撤销 | 部分可回滚 | 容易回滚 | Agent 适合可修复场景 |
| 执行频率 | 偶尔 | 频繁 | 持续循环 | 重复性放大 ROI |
| 输入变异性 | 高度可预测 | 混合 | 混乱/非结构化 | Agent 胜出在混乱输入 |
| 协调开销 | 极少 | 中等 | 沉重 | Agent 压缩协调成本 |
| 判断需求 | 无 | 一些 | 很多 | Agent 在推理需求高时有用 |
| 延迟容忍度 | 必须即时 | 中等 | 灵活 | Agent 往往以速度换推理 |

**总分解读**:
- 0-8: 不要用 Agent，用脚本/规则/模板
- 9-16: 考虑 Agent 推荐模式（人类决定）
- 17-20: 适合有审批的 Agent
- 21-24: 强 Agent 候选，加护栏

### 预警信号

- Gartner 预测 2027 年前 40%+ Agentic AI 项目将被取消
- MIT NANDA 报告：**95% 组织从 GenAI 项目获取零回报**
- OWASP #1 风险：提示注入（过度代理 + 过度信任）
- "Human-in-the-loop" 可能成为时间陷阱——Wharton 研究：AI 接近正确时，人类更难保持警觉（"契约悖论"）

### 安全部署的三阶段

1. **只读优先**: 搜索、总结、起草、建议
2. **写操作需审批**: 创建工单、更新文档
3. **敏感操作明确审批**: 不可逆动作

> **关键结论**: Agent 是昂贵的自主权。在产品团队中，安全模式是 Agent 做 50-70% 的工作，人类拥有最终判断权和责任。

## 2️⃣ AI Builder：重塑产品交付的新角色

- **来源**: Product School, 2026
- **链接**: https://productschool.com/blog/skills/what-is-an-ai-builder

### 角色定义

**AI Builder** = 使用 AI 进行原型设计、分析、评估和交付的产品专业人员。将产品思维转化为可工作的制品，比传统构建周期快得多。

### 与传统 PM 的核心差异

| 维度 | 传统 PM | AI Builder |
|:-----|:--------|:-----------|
| 核心技能 | 文档撰写/需求管理 | 提示工程/AI 工具编排 |
| 验证周期 | 周级 → 月级 | 小时级 → 天级 |
| 产物形式 | PRD/Figma/Excel | 可工作原型/代码片段/Agent |
| 决策依据 | 用户研究/数据分析 | AI 辅助的实时数据+模拟 |
| 角色价值 | "文档管理者" | "产品加速器" |

### 关键能力要求
- 提示精度：从"写什么"变为"精确描述意图"
- 多工具协调：AI编码/设计/分析工具的组合使用
- 判断力：识别 AI 输出质量，知道何时纠偏
- 安全治理：理解数据风险、权限设计和伦理边界

## 3️⃣ AI 实验方法论：PM 如何更快测试和学习

- **来源**: Product School — Carlos Gonzalez de Villaumbrosia, 2026-03-18
- **链接**: https://productschool.com/blog/artificial-intelligence/ai-experimentation-how-ai-pms-test-and-learn-faster

### 五种实验类型与选择

| 实验类型 | 回答的问题 | 适用阶段 | 复杂度 |
|:---------|:-----------|:---------|:-------|
| **A/B 测试** | 这个特性的实际影响是多少？ | 验证优化 | 低 |
| **多变量测试** | 哪个组合效果最好？ | 调优阶段 | 高 |
| **假门测试 (Fake Door)** | 用户想要这个功能吗？ | 需求验证 | 极低 |
| **AI 原型测试** | 用户理解和信任它吗？ | 可用性验证 | 中 |
| **金丝雀发布** | 在生产环境中安全吗？ | 安全上线 | 中 |
| **自适应实验 (MAB)** | 哪个变体持续最优？ | 持续优化 | 高 |

### AI 实验的特殊挑战

1. **非确定性输出**
   - 冻结模型版本（同一实验期间不更新模型）
   - 种子随机性确保组间可比

2. **模型漂移**
   - 持续监控关键指标
   - 上线后定期重测

3. **偏差与公平性**
   - 按用户分组切分指标
   - 对抗式测试/边缘用例测试
   - 高风险场景保持人在环

4. **信任与安全**
   - Cisco CPO Jeetu Patel: "安全与效率不是对立关系，而是效率的前提条件"
   - 人类评估者捕捉算法忽略的问题（语调/合规/可解释性）

### 指标体系三层

| 层级 | 示例指标 |
|:-----|:---------|
| 模型性能 | 准确率/精确率/召回率/F1/响应时间 |
| 用户体验 | 功能使用率/满意度/留存/任务完成率 |
| 业务影响 | 转化率/收入提升/成本节约/错误率下降 |

## 4️⃣ AI 运营模型分层：80% 卡住意味着什么

- **来源**: Product School

### 产品团队 AI 运营成熟度

| 层级 | 特征 | 占比 |
|:-----|:-----|:----:|
| **L1: 点状工具** | 个人用 AI 写文档/总结/写代码 | ~80% |
| **L2: 流程嵌入** | AI 嵌入特定工作流，有监控和治理 | ~15% |
| **L3: 运营模型重建** | 围绕 AI 重建组织运营系统 | ~1% |
| **L4: 产品即运营 (AI Native)** | 产品 DNA 与 AI 运营完全融合 | <0.5% |

### "运营模型即产品"（Product School 创始人视角）

- CEO Carlos Gonzalez 宣布推出 **Product Partners**，将产品思维扩展到企业级
- 关键信念：**产品 DNA 是 AI 转型的核心要素**
- 单 PM 提升不够，需要重建组织系统
