## MoE→训练/集群调度

- **RoutePack（08-12）**: MoE RL 训练中序列组合（attention 负载）与 token 路由（专家负载）两类负载均衡耦合问题；层次化规划器先按聚合路由需求逐层放置专家，再做注意力+专家感知的 token 上限数据打包，用并行退火搜索可行布局；Ling-3.0-Tiny/Flash 上专家重路由 +3.80%/+10.50%、路由感知打包再 +4.86%/+3.98%，合计吞吐 +8.85%/+14.89%（URL: https://arxiv.org/abs/2608.12146）
- **TAOT / 拓扑感知最优传输（08-04）**: 动态专家副本放置建模为带通信代价矩阵的熵正则最优传输，Sinkhorn-Knopp 迭代求解产生 rank 级流提示，整数副本匹配+token 分配生成可执行调度；系统层用 guest 权重传输与 home 专家计算重叠隐藏通信开销；端到端 MoE 训练加速 **1.43x**、加权专家通信成本最高降 **74%**（URL: https://arxiv.org/abs/2608.03676）
- **Kimi K3 技术报告（08-07）**: 2.8T 总参/104B 激活 MoE，16-of-896 路由专家，1M 上下文窗口；基础设施亮点="perfectly balanced expert-parallel training with efficient memory management"、百万 token agentic RL 持久 rollout——2.8T 规模下专家并行均衡已作为硬件/系统能力验收项（URL: https://arxiv.org/abs/2607.24653）
- **HyperParallel-MoE / Ascend NPU（06-01）**: 昇腾 AIC/AIV 异构调度——tile 级静态调度任务流跨两种计算单元、AIV 驱动单向通信消除 host 侧集合同步、事件驱动静态调度单 kernel 启动并发驱动；DeepSeek 风格 MoE 在 Ascend A3 集群 Dispatch-to-Combine MoE-FFN 延迟降 **1.58x**，源码已开源（URL: https://arxiv.org/abs/2605.23764）
- **Tevatron 3.0（08-02）**: Megatron-Core 后端集成使学术预算可训练 30B Qwen3-30B-A3B MoE reranker（FSDP1 不可行）；MoE vs dense 受控对比：MoE 以不到一半激活参数匹配 dense 8B 质量且推理吞吐显著更高——为 MoE 硬件需求（EP 训练基础设施）提供低门槛验证路径（URL: https://arxiv.org/abs/2608.00916）

## MoE→推理系统与调度

- **Gimbal / 协调调度（06-13）**: 前端 DP-engine 细粒度调度（KV 用量/剩余 prefill/队列压力/专家压力在线信号）+后端 MINLP 启发式专家放置（联合负载/源感知通信/迁移稳定性）；平均 TTFT 降 **42.9%**、TPOT 降 **33.3%**（vs vLLM），高负载吞吐 +3.0%（URL: https://arxiv.org/abs/2606.15177）
- **ASAP / CloudMatrix384 异步 prefill（06-21）**: DP(attention)/EP(MoE) 混合并行中全局同步屏障是 TTFT 与吞吐的主要杀手；ASAP 解耦 attention/MoE 阶段为全异步流水线、定制异步通信原语+四类请求调度/执行优化拆屏障；CloudMatrix384 超节点上 SLO 达标 prefill 吞吐较同步方案 **+90%**（URL: https://arxiv.org/abs/2606.22541）
- **Director / INFOCOM'26（06-13）**: 在线主动专家放置——级联预测器或低比特量化副本预测请求专家激活模式、计算密集阶段执行近零停机迁移、松弛优化器容量约束下多项式时间 (1+ε) 近似；Mistral/DeepSeek/Qwen 上端到端延迟降 **11-55%**（URL: https://arxiv.org/abs/2607.08782）
- **NanoCP / 请求级动态上下文并行（05-20）**: DP-EP 混合解码中 attention 延迟随 KV 大小、MoE 通信随 batch 大小增长的双重失衡；DCP 按 KV 足迹分配每请求 context-parallel 度（长请求跨实例、短请求本地），配合 AOT 图引擎+路由通信后端；SLO 达标请求率 **1.88-3.27x**、P99 尾延迟降 **1.79-2.12x**（URL: https://arxiv.org/abs/2605.21100）
- **EasyBalance / ICML'26（08-08）**: 跨层负载均衡——"其他层专家可视为当前层天然冗余"，贪心调度每 MoE step 执行跨层工作负载子集、其余延迟至未来均衡窗口；不改专家-设备映射、近零额外开销；分布式 MoE 推理 GPU 空闲减少 **>40%**（URL: https://arxiv.org/abs/2608.07964）

## MoE→芯片与硬件经济学

- **The Economics of AI Decoding Chips（07-10）**: 以 F/B（roofline ridge point）与 F/S（每 GB 内存捆绑的计算量）两个固定常量形式化"GPU 计算过载、容量不足"；Skymizer HTX-301 28nm PCIe 加速卡（DDR5、无 HBM/CoWoS/先进制程）占据再平衡设计点：8 卡板 $19K 容纳 DeepSeek-R1 671B、4U 4 板 $28K 服务 2 用户 20.3 tok/s；8 台 4U 服务 16 用户 $224K、$12/M token vs 八卡 GPU 节点 $350K 的 $21/M——MoE 推理成本结构重构（URL: https://arxiv.org/abs/2607.13068）
- **CPU-GPU Hybrid 本地 MoE / OSDI'26（06-09）**: 消费级 CPU-GPU 达到云级 SLO——SLP 流式 prefill 1,200 tok/s（32K 提示 30s 内）、DSLP+SmallEP 双 RTX 5090 达 1,800 tok/s、AVX-512 优化 FP8 GEMV 原生 CPU FP8 推理（CPU 延迟低 4-5x）、prefill-decode 节点内分离零拷贝共享权重；INT4 DeepSeek-V3 28 tok/s、FP8 完整精度 21.5 tok/s（URL: https://arxiv.org/abs/2606.10493）

## MoE→安全与运维

- **Load Hijack（08-11）**: 恶意模型提供者仅改 checkpoint 的 router 权重即可构造"触发器控制的设备调度器"——三阶段优化使 92.3-95.6% 触发 token 集中到单 GPU 上专家，制造 straggler；真实 EP 服务中触发流量 TTFT **1.43x**、吞吐 **0.86x**，普通输入路由近干净参考；为 MoE 服务引入 checkpoint 路由审计+运行时负载基线需求（URL: https://arxiv.org/abs/2608.10614）

## MoE→边缘/多模态硬件

- **Beyond Independent Optimization（07-23, 综述）**: 多模态边缘智能中压缩/MoE 路由/量化三轴强耦合——token 压缩改变 MoE 路由分布、路由行为影响专家利用与量化敏感度、量化 router logits 干扰专家指派、硬件约束把计算节约转化为内存/通信瓶颈；提出 Temporal Routing Consistency 诊断并呼吁硬件感知协同设计——边缘 MoE 硬件评估需全链路而非单轴（URL: https://arxiv.org/abs/2607.20981）

## NVIDIA 官方

- **AI Model Co-Design: Hardware-Friendly LLM Design（07-10）**: NVIDIA 官方硬件-模型协同设计框架——三维度（Accuracy/Throughput/Interactivity）；核心量化结论：①专家并行（EP）=attention 数据并行+FFN 专家分布式，规避 TP 的 AllReduce 瓶颈；②Amdahl 定律视角——attention 占运行时 77% 时优化 FFN 仅边际收益；③GEMM-M 随并发增长、随稀疏收缩，#experts=256（DeepSeek-R1），per-GPU 并发被 KV cache 足迹封顶，**跨更多 GPU 拓宽 EP 是稀疏 MoE 利用率的主要杠杆**（URL: https://developer.nvidia.com/blog/ai-model-co-design-hardware-friendly-llm-design/）
