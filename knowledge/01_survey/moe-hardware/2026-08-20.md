## 一、核心发现（arXiv 新提交，08-15~08-18）

- **来源/标题**: [FreeToken: Efficient Edge-Native MoE Serving with Bandwidth-Adaptive Execution](https://arxiv.org/abs/2608.16157)（08-18, Song Han/Zaharia/Stoica 组, flashml.ai）
  - 边缘原生 MoE serving：把个人机当作统一弹性推理平台，按机器实际带宽/内存比连续重映射计算与模型状态（模型布局/专家驻留/CPU-GPU 执行/agent 状态复用/运行内存全栈协同设计）
  - 支持 >20 个 MoE 模型、真实 coding/tool-use agent；硬件跨度 8GB 笔记本 GPU → 单工作站 GPU：35B→笔记本、284B→游戏台式机、753B GLM-5.2→单工作站 GPU
  - **硬件含义**: 边缘 GPU 无 HBM 容量时，MoE 稀疏性价值取决于"带宽自适应执行"而非静态 offload——与 WiSP 的 working-set 视角（06-20 已收录）同向，但把执行粒度从专家页扩展到全栈

- **来源/标题**: [KV-Pipe: On the Relation Between KV Sharing and Pipeline Parallel Efficiency in LLMs](https://arxiv.org/abs/2608.15943)（08-18）
  - 把跨层 KV 共享从"推理期省 KV 内存"重定位为**流水线并行平衡控制旋钮**：tail-first 转换注意力层为跨层 KV 共享、迭代重定位瓶颈使 FLOPs Imbalance Ratio(FIR)→1；离线执行、零在线调参
  - 训练 MFU **+9.2%**、迭代时间 **−9.8%**（PP 度数越高增益越大，stage imbalance 放大）；推理侧同机制降低 KV 增长与冗余 KV 投影，长上下文解码吞吐提升
  - **硬件含义**: KV 布局成为系统-架构自由度（architecture degree of freedom）——训练/推理共用同一内存布局优化，呼应 MoE 时代"权重/激活/KV 三类流量分治"的存储层次设计趋势

- **来源/标题**: [Collective Communication for Distributed LLM Systems: Planning, Runtime Adaptation, and Computation Coordination](https://arxiv.org/abs/2608.15118)（08-15, 北航+清华）
  - 集合通信教程式综述（tutorial taxonomy）：三层框架 = 通信规划（拓扑感知 schedule 生成）→ 执行与适配（映射到 GPU 运行时与真实集群硬件）→ 计算-通信协调（转成端到端收益）
  - AlltoAll(A2A) 与 AllReduce/ReduceScatter/AllGather 并列为核心原语——MoE 专家并行是 A2A 最大用户
  - **硬件含义**: 异构 GPU 互连 + 多 NIC 网络下，MoE 的 A2A 优化正从"带宽够不够"转向"规划层能否感知拓扑+运行时能否动态适配"；与 UBEP（SIGCOMM'26, 已收录）同主题的体系化梳理

- **来源/标题**: [When Does Distributed AI Inference Need More Wide-Area Bandwidth? A Co-Design Evaluation of Optical, Packet, and Software Levers](https://arxiv.org/abs/2608.14967)（08-15）
  - 引入 compute-intensity-ratio(CIR, bytes/FLOP) 衡量：WAN 带宽/GPU 算力比每代下降，与片内存储差距 4-5 个数量级、每年拉大 12-19%
  - 跨站点移动推理状态 vs 重算的 crossover：70B MHA 模型 74-111 Gbps/流；GQA 1/8 KV heads 降至 9-14 Gbps；GPU 稀缺×KV 复用使有效 GPU 成本放大 5-20× 时传输胜出（列表价下重算更便宜）
  - **硬件含义**: 对 MoE 尤甚——专家权重/激活/KV 三类状态跨站点移动的成本模型，直接支撑"KV 缓存跨数据中心迁移"与弹性光网络的经济论证；网络杠杆（光容量分钟级 vs 包交换毫秒级）分工清晰

- **来源/标题**: [P-PAS: Prefill-Pressure Adaptive Scheduling for Long-Context LLM Serving](https://arxiv.org/abs/2608.15171)（08-15, vLLM 实现开源）
  - 证明 vLLM 的 max-batched-tokens(MBT) 调度预算存在**负载压力依赖的最优性翻转**：低压下大 token 预算更优（大 prefill chunk 提升执行效率），高压下小预算避免干扰 decode；无单一静态 MBT 全负载最优
  - P-PAS 按并发 prefill/decode 状态动态调整预算；kernel 级剖析显示 chunk 大小效益**随模型-硬件配置变化**
  - **硬件含义**: 长上下文 RAG/agent 负载下，prefill/decode 争抢 GPU 资源的调度解与硬件配置强耦合——服务层需要"硬件感知的调度预算"

- **来源/标题**: [Agentic Kernel Optimization: Generating State-of-the-Art GPU Kernels Without Hand-Written CUDA](https://arxiv.org/abs/2608.14560)（提交 05-25, MLSys 2026 FlashInfer 竞赛, B200）
  - 代码 agent（Houmao 多代理框架）生成 GPU 内核：Fused MoE 较 PyTorch 参考 **92.68×**、DSA TopK Indexer 1101×、DSA Sparse Attention 181×；~1.9B agent tokens
  - MLSys 2026 FlashInfer AI Kernel 生成竞赛官方评测：Fused MoE 内核较 FlashInfer baseline **1.71×**（超过 agent-assisted track 第一名 1.68×）
  - **硬件含义**: MoE 专用内核（TopK/专家融合）的生成式优化达到 SOTA——"内核工程自动化"是 MoE 硬件效率的软件侧新杠杆

- **来源/标题**: [FlashQuant: Sparse-Dense Fusion for Memory-Efficient Outlier-Aware LLM Inference](https://arxiv.org/abs/2608.15531)（08-16）
  - W4A16 离群值感知解码：把低比特 dense GEMM + 高精度稀疏 SpMM **融合为单 GPU 内核**（Tile-COO 编码 + 流水化调度，片上复用激活/输出块）
  - 较 cuBLAS BF16 **2.74-4.18×**、较最强未融合离群值 baseline **1.53×**；针对内存受限 decode
  - **硬件含义**: 量化 MoE 推理的"稀疏-稠密双路径分核执行"有片上复用浪费——融合内核是内存带宽受限场景的下一个优化点

- **来源/标题**: [AdaSprite: Resource-efficient Online Co-Adaptation for V2I Systems Under Large-scale Data Drifts](https://arxiv.org/abs/2608.16188)（08-17, MobiSys 2026）
  - V-MoE 边缘协同自适应：弹性伸缩+多级复用优化专家生命周期，缓解 DRAM 碎片限制专家并行、内存-I/O 瓶颈限制计算复用
  - 弱边缘上支持 **17 个并发 V2I 任务（baseline 6 个）**、SLO 达成 **1.6×**、吞吐 **2.1×**
  - **硬件含义**: 边缘 MoE 的瓶颈从"算力"转向"DRAM 碎片 + 内存 I/O"——内存子系统成为稀疏模型边缘化的第一约束
