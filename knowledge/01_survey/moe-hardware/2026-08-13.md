### arXiv（4 条新，去重后）

- **UBEP: Re-architecting Expert Parallelism Communication Library for Production Superpods**（2026-07-08，SIGCOMM 2026）：针对生产超节点（NVIDIA NVL72/576、华为 CloudMatrix384）重设计 MoE All-to-All 原语；识别三大瓶颈：BSP 粗粒度串行化、同步开销随带宽不扩展、距离无关调度导致不规则 token 流量负载不均；实验 All-to-All 延迟降 **52.4%**、MoE 推理 TPOT 降 **11.1%**。URL: https://arxiv.org/abs/2607.06202

- **NCCL EP: Towards a Unified Expert Parallel Communication API for NCCL**（2026-03-13 v3，NVIDIA 官方）：在 NCCL Device API 之上原生构建 EP 通信库，提供统一 `ncclEpDispatch`/`ncclEpCombine` 原语（C/Python 双接口）；LL 模式面向 decode（1-128 token，RDMA+NVLink mesh 直连 all-to-all + 双缓冲重叠 dispatch/combine），HT 模式面向训练/prefill（4096+ token，NVLink 域内聚合后再跨节点 RDMA）；全 GPU 发起通信（Device API），H100 集群多节点评估 + vLLM 集成——NVIDIA 平台 EP 通信官方化路径，与 DeepEP/Hybrid-EP/UBEP 形成对照系。URL: https://arxiv.org/abs/2603.13606

- **Decoupled Mixture-of-Experts for Parametric Knowledge Injection**（2026-06-12）：DMoE 将专家与路由均与基座模型解耦，外部知识语料转为可独立更新的专家模块，不确定性感知路由仅当基座知识不足时激活；专家仅挂载于最后层 FFN，**保留 KV-cache 复用**，实现参数级知识增强（对比 RAG 的 prompt 级与后训练的全参数级）。URL: https://arxiv.org/abs/2606.14243

- **NanoCP: Request-Level Dynamic Context Parallelism for Data-Expert Parallel Decoding**（2026-05-20）：MoE 混合数据-专家并行下，attention 延迟随 KV 规模增长而 MoE 通信延迟随 batch 增长，静态绑定无法双平衡；DCP 按请求 KV 足迹动态分配 context 并行度（长请求跨实例、短请求本地），实现集群 KV 缓存"液态化"；SLO 约束下请求率提升 **1.88x-3.27x**，P99 尾延迟降 **1.79x-2.12x**。URL: https://arxiv.org/abs/2605.21100
