## 边缘/消费级 MoE 推理：内存带宽墙成为第一瓶颈

- **Cacheable by Design: MoE 路由器局部性训练的预注册负结果**（arXiv:2608.18261, 2026-08-18）: 在单张 8GB 消费级 GPU 上服务 Qwen3-235B（Q4_K_M 量化后 134GB），decode 实测仅 0.44 tok/s（warm），与"每 token 流式加载活跃专家权重"的 bytes/token÷带宽模型吻合——瓶颈是内存带宽而非算力；batch=32 时磁盘分页抖动反而使吞吐崩塌。配套工具 llama-moe-trace 实测 Qwen3-30B：相邻 token 专家复用 2.0×随机基线，95% 流量集中在 52.5% 专家，13.4% 专家规模的 LRU 缓存可服务 66% 请求。训练侧（137M MoE + 局部性/领域路由损失）：缓存缺失最高降 60%、静态钉扎命中率 99%，但所有配置均未通过预注册的 ≤1% 困惑度门控——**缓存友好性与生成质量强耦合，多领域规模下局部性训练"税"真实存在**（340M 规模验证不随规模缩小）；免训练缓存感知重路由 + 训练局部性叠加可降 ~80% 缺失且困惑度 ≤3.4%。URL: https://arxiv.org/abs/2608.18261
- **APEX: 自适应专家预取框架**（arXiv:2608.11688, 2026-08-12, 已录用 ESWEEK/CODES 2026）: 边缘 MoE 推理中专家参数常驻片外内存、加载在关键路径上；APEX 用轻量预取路由器 + 置信度模型，在 attention 块之前预测候选专家并重叠加载，重叠准确率 >99%（优于固定 top-k 预取）；保持正确性模式将每 token 延迟降低最高 26%、能量-延迟积（EDP）改善最高 41%。URL: https://arxiv.org/abs/2608.11688
- **EdgeXpert: 边缘 MoE+投机解码协同加速器**（arXiv:2608.05303, 2026-08-05, 已录用 MICRO 2026）: 指出投机解码（多 token/阶段）与 MoE（稀疏激活）组合存在不兼容；prefill 用 prompt 级专家复用（轻量编码器选重要 token 构共享专家集），decode 用深度感知专家合并（只加载显著通道+计算校准）；Samsung 28nm @800MHz 综合，相对 prior works 延迟降 56.3%、能耗降 44.1%。URL: https://arxiv.org/abs/2608.05303
- **RotaryQuant: 120B MoE 装进消费硬件**（arXiv:2608.08081, 2026-08-08, 已收录 08-19）: 混合精度（dense 4bit/expert 2bit/shared 8bit）+ LRU 专家换出 + IsoQuant KV 压缩（Walsh-Hadamard+SO(4) 旋转各向同性化后 3bit 量化，每 head 仅 256 参数 vs 稠密旋转 16,384）；Metal 四核融合管线直接在压缩态做 attention。16GB 跑 Gemma4-26B/Qwen3-30B、32GB 跑 Nemotron-H 120B，9-19 tok/s，ΔPPL ≤ +0.0012。URL: https://arxiv.org/abs/2608.08081（交叉引用 08-19 条目）

## 存储层次重构：HBF / ReRAM 近存成为 MoE 权重供给新路径

- **Beyond Capacity: 高带宽闪存（HBF）双路径专家交付**（arXiv:2608.14333, 2026-08-14, 已收录 08-18/19）: 利用 HBF 直连 GPU 与经 HBM 基片的转发路径并行传输专家权重（专家级路由分配，双路并发），早期专家判定重叠 HBF 读延迟，权重与 KV 缓存流量分治；事件驱动连续批处理仿真下代表性工作负载吞吐 1.94×、端到端加速 1.90×（对比全走 HBM 基片方案）。URL: https://arxiv.org/abs/2608.14333（交叉引用 08-18 条目）
- **MoE 专家执行在分离式服务 + ReRAM 近存架构**（arXiv:2608.13962, 2026-08-14）: Attention-FFN 分离（AFD）下 FFN 池需在稀疏路由并集下提供权重读带宽密度、在偏斜下恢复占用率。ReRAM 近存设计将专家权重常驻高带宽局部读之后：实际 MFU 分解为理想 MFU×占用率，核心局部多播池化（side-4）将占用率 0.328→0.519，等峰值算力下每 token FFN 池延迟较 H20 低 9.5×、权重搬运能耗低 20×；H20-attention + ReRAM-FFN 混合系统 vs 同构 H20 池，decode TPOT 分别降低 1.25-4.0× / 2.4-10.3× / 2.5-10.4×（Qwen3.5-35B-A3B / Qwen3.5-397B-A17B / GLM-5.2）。URL: https://arxiv.org/abs/2608.13962
- **HBF Sucks: 全栈表征揭示 HBF 不适合 KV 暂存**（arXiv:2608.11668, 2026-08-12, 已收录 08-18）: 把 SSD 型 Mooncake KV 卸载栈直接换 HBF 反而变慢——端到端延迟升 2-5.5×、SLO goodput 降 1.1-2.7×（H100/B200，Qwen-Bailian 生产轨迹）；成本-收益模型解释：快速远端层仅在读 I/O 为瓶颈、读多于写、带宽可持续时获益，而瞬态 KV 三者全违反；HBF 读延迟自身不重要（缩放 3.75× 延迟仅变 <1%），写重负载+热限制+磨损才是问题。URL: https://arxiv.org/abs/2608.11668（交叉引用 08-18 条目）

## 系统级协同设计：最优稀疏度是"集群属性"而非"算法属性"

- **MOSAIC: Compute-Optimal ≠ Cluster-Optimal**（arXiv:2608.10605, 2026-08-11）: 将 MoE 架构与系统协同设计形式化为优化问题：预测性缩放律（含稀疏度维度，活跃参数 104M-2.7B、总参数至 79B）+ 校准性能模型（MFU/通信/内存/最优并行布局）联合求解；关键发现——**在纯模型 FLOPs 预算下不存在内部最优稀疏度（损失随稀疏单调下降、算力最优在数据支撑上界），最优稀疏度只在集群系统约束（MFU/通信/内存）下才涌现**，论证前沿模型训练应转向架构-系统统一协同设计。URL: https://arxiv.org/abs/2608.10605
- **AFD-Ledger: Attention-FFN 分离部署配置决策框架**（arXiv:2608.04502, 2026-08-05）: 回答"同模型/负载/TPOT SLO/硬件预算下，AFD 是否优于最优共置部署"：离线解析供给系统 + 评估有界硬件搜索，穷举可行域上部署评估减少 68.8%-83.5% 且仍恢复全局最优；三个 LongCat 2.0 物理部署上预测 AFD:共置吞吐误差仅 6.6%-9.6%。结论：同构 AFD 仅在少数场景提升固定预算吞吐、异构 AFD 需要部署级硬件互补性而非启发式选设备、角色专用硬件改善需跨越能力-价格边界才有意义。URL: https://arxiv.org/abs/2608.04502
- **HYMELL: 混合解析-ML 的 LLM 推理延迟/能耗三层建模**（arXiv:2608.06723, 2026-08-07）: 解析建模原始算子 + ML 预测高层组件 + 端到端系统开销模型（覆盖 prefill/decode、dense 与 MoE FFN、MHA/GQA）；NVIDIA H100 上 LLaMA3-8B 两阶段误差 <5%，可直接从架构参数做无硬件的设计空间探索。URL: https://arxiv.org/abs/2608.06723
- **多分区 NUMA GPU 的 LLM kernel 访存特征刻画**（arXiv:2607.28824, 2026-07-30）: 对权重投影/MoE/attention 变体的 kernel 做 workgroup 级访存追踪：三类工作组间共享模式（global/partial/private）对应不同优化策略（per-workgroup 钉扎 → 子组感知协同调度）；呼吁位置感知 kernel 编程与更智能的工作/数据局部性架构支持。URL: https://arxiv.org/abs/2607.28824

## 调度与负载均衡（EP 侧增量）

- **TEMPO: Makespan 感知的专家并行负载均衡**（arXiv:2608.13057, 2026-08-13, 已由 distributed-os 收录）: HBM 权重流主导（<156-168 token）与 GEMM tile 舍入（≥）双机制导致专家耗时非线性；8-GPU 微基准下保持 ≤1% 差距、混合机制场景最高赢 15.5%；Qwen3-235B 端到端 +4-6% 吞吐、p99 降 ~15.6%。URL: https://arxiv.org/abs/2608.13057（交叉引用 distributed-os）
- **FreeBalance: 预路由在线负载均衡**（arXiv:2608.14205, 2026-08-14, 已收录 08-18/19）: 利用残差网络跨层相似性预测路由分布，把专家迁移与路由前计算阶段重叠（无损失）；max-to-mean rank 负载比降 32.8%、端到端 prefill 延迟降 13.1%，隐藏平均 5.1 专家/层迁移（约占关键路径 8.5%）。URL: https://arxiv.org/abs/2608.14205（交叉引用 08-18 条目）
- **DA-MoE: 分布感知 fused-MoE 内核分发**（arXiv:2607.23099, 2026-07-28, 已由 distributed-os 收录）: 路由偏斜与 token 数决定最优 fused-MoE kernel；Effective Experts 指标 + Dirichlet 逆向建模生成可控路由分布做系统化硬件研究；HumanEval-X 轨迹上 DeepSeek-V3 geomean 延迟 1.16×、Kimi K2 1.29×，峰值 1.40×/1.56×。URL: https://arxiv.org/abs/2607.23099（交叉引用 distributed-os）

## 趋势小结

- **内存带宽墙取代算力墙成为 MoE 推理第一约束**：消费级（8GB GPU 跑 235B 仅 0.44 tok/s）、边缘（专家片外加载关键路径）、数据中心（HBM 容量/成本压力）三线同证；对策分两路——**软件侧**（预取/缓存/路由局部性，但 08-21 预注册负结果提示"训练局部性"有质量税）与**硬件侧**（HBF 双路径、ReRAM 近存、更高带宽互连）。
- **存储层次正在为 MoE 重构**：HBF/ReRAM 等近存介质从"KV 缓存加速器"角色转向"专家权重仓库"；但 HBF Sucks 论文警示——"设备好≠掉入部署好"，分层缓存策略必须按读写比/复用率设计。
- **最优稀疏度是集群属性**：MOSAIC 证明纯算法视角无内部最优稀疏度，系统约束（MFU/通信/内存/并行布局）才定义最优——MoE 架构与硬件进入联合设计期，与 NVIDIA 官方"MoE 改变训练限制因素"表态互证。
