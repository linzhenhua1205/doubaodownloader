## 互连与训练通信

- **UBEP：面向生产超级节点的 EP 通信库重构**（arXiv:2607.06202, SIGCOMM 2026, 2026-07-08, https://arxiv.org/abs/2607.06202）: 指认 NVL72/576、CloudMatrix384 等超级节点上 MoE all-to-all 的三瓶颈——BSP 粗粒度串行化、同步开销、距离无关调度的负载不均；统一总线 EP 原语重设计后 All-to-All 延迟降 52.4%、MoE 推理 TPOT 降 11.1%——MoE 稀疏通信在超节点形态下「带宽不是瓶颈、通信编排才是」
- **TAOT：拓扑感知最优传输的专家副本放置**（arXiv:2608.03676, 2026-08-04, https://arxiv.org/abs/2608.03676）: 动态复制热专家到空闲 rank 只优化负载均衡、忽视跨节点权重迁移成本；用带通信成本矩阵的熵正则最优传输(Sinkhorn-Knopp)+整型副本匹配，权重迁移与计算重叠，端到端 MoE 训练 1.43x 加速、加权专家通信成本最高降 74%——多节点拓扑感知是 MoE 训练副本放置的下一层优化
- **RoutePack：MoE RL 训练的注意力+专家联合打包**（arXiv:2608.12146, 2026-08-12, https://arxiv.org/abs/2608.12146）: MoE RL 中序列打包决定 dense attention 负载、token 路由决定稀疏专家负载，两者互相转嫁瓶颈；层级专家重路由+注意力/专家感知打包分层规划，Ling-3.0 系列吞吐 +8.85%~14.89%——训练侧「打包+放置」耦合优化新范式
- **（08-28 已收录）** 晶圆级光互连热调谐(2608.24637, 铁电调谐 2.7-3.8x) / FreeBalance 预测性迁移重叠(2608.14205, 负载比 -32.8%)——本期无增量

## 推理系统与调度

- **Moebius：EP/TP 运行时无缝切换**（arXiv:2606.26607, 2026-06-25, https://arxiv.org/abs/2606.26607）: EP 高并发优、TP 低并发优，生产负载持续跨界；视 EP/TP 为同一模型的两种布局（字节相同权重+KV cache），仅移动 owner 切片，8×H200 上 Qwen3-235B-A22B 每次切换 215-434ms、双布局内存开销仅 2.4%，RL rollout 提速 1.16-1.25x——服务端并行度自适应是 MoE 推理调度新主线
- **ELDR：PD 分离架构的专家局部性解码路由**（arXiv:2607.00466, 2026-07-02, https://arxiv.org/abs/2607.00466）: 等负载 decode worker 因每步加载 batch 激活专家的权重而异延迟；由 prefill 专家激活构建专家签名+K-means 划分+局部性路由，vLLM 40 GPU 部署下 TPOT 降 5.9-13.9%（输出不变）——MoE 使「负载均衡」升级为「专家局部性均衡」
- **EasyBalance：跨层联合执行的负载均衡**（arXiv:2608.07964, ICML 2026, 2026-08-08, https://arxiv.org/abs/2608.07964）: 不复制不迁移，把其他层专家视为当前层天然冗余、跨层工作负载联合调度，GPU 空闲时间多数场景降 40%+（代码: github.com/yize-wu/EasyInfra）——零开销的第三种均衡路径
- **TriRoute：注意力/专家/KV 位宽三轴联合学习路由**（arXiv:2607.06601, 2026-07-07, https://arxiv.org/abs/2607.06601）: 单控制器逐 token 联合决策 attention 模式、FFN 专家集、KV cache 位宽（Gumbel-Softmax+负载均衡 top-k），Pareto 支配独立 MoD+MoE+KV 量化组合；句子开头/罕见子词/命名实体获全 attention+高精度缓存——「条件计算三轴耦合」成为推理硬件负载的新结构特征

## 内存与存储架构

- **Beyond Capacity：HBF 高带宽闪存双路专家供给**（arXiv:2608.14333, 2026-08-14, https://arxiv.org/abs/2608.14333）: 专家权重逼近 HBM 容量/成本极限；HBF 组织同时启用 direct GPU-HBF 与 relay(HBF-HBM-GPU) 两路并发传输（整专家分配一路、不复制、无共享瓶颈），早定专家+不可变权重与可变 KV 分离管理，事件驱动仿真吞吐 1.94x、端到端 1.90x（vs 仅 HBM 中继）——HBF 直连 GPU 是 MoE 容量墙的存储级破局方向
- **PagedWeight：运行时动态专家量化的 KV 权衡**（arXiv:2607.16184, 2026-07-17, https://arxiv.org/abs/2607.16184）: KV 密集服务下模型权重与 KV cache 争 GPU 内存；运行时动态量化专家权重、平衡精度与 KV 容量，FP16 等效精度下内存节省 72.0%、吞吐 1.94x（同内存预算质量较量化基线 +39.3%，代价 ≤4.1% 吞吐）——权重-KV 联合内存管理是 MoE 服务的关键杠杆
- **WiSP：极低资源硬件的专家工作集分页**（arXiv:2606.21868, 2026-06-20, https://arxiv.org/abs/2606.21868）: 层级 CPU offload 每前向流式过 PCIe 损失稀疏红利；路由感知分页仅驻留复用专家，同内存预算 decode 吞吐 1.95x；关键实证——单流 decode 预取帮助甚微，瓶颈是 PCIe 带宽而非预测精度，问题从「预取」转向「专家/KV 的 VRAM 分配」——带宽受限硬件上 MoE 成本跟随总参数量

## 边缘与消费级硬件

- **MoE 在消费/边缘硬件上的实证检验**（arXiv:2606.21428, 2026-06-19, https://arxiv.org/abs/2606.21428）: OLMoE-1B-7B(1.3B 激活/6.9B 总参) vs 三个 dense 基线实测（M2 Pro/Jetson Orin Nano 8GB, llama.cpp）：笔记本约落后同激活 Llama-3.2-1B 10%，边缘设备落后 31% 且每 token 能耗 2.1x、峰值内存触 8GB 上限；路由本身 <9% MoE-block 计算——带宽受限硬件上稀疏激活红利不兑现，成本追踪总参数而非激活参数
- **RotaryQuant：消费级硬件跑 120B MoE 的三轴压缩**（arXiv:2608.08081, NeurIPS 2026 投稿, 2026-08-08, https://arxiv.org/abs/2608.08081）: 4-bit dense/2-bit 路由专家/8-bit 共享专家混合精度+LRU 专家磁盘换页+IsoQuant（Walsh-Hadamard+SO(4) 旋转各向同性化后 3-bit KV 量化，每 head 仅 256 参数 vs dense 旋转法 16384）+Metal 四核融合 kernel 直接算 3-bit 打包态；16GB 预算跑 Gemma 4-26B/Qwen3-30B-A3B、32GB 跑 Nemotron-H 120B，9-19 tok/s、ΔPPL≤+0.0012、32K 上下文检索 100%——消费级 MoE 落地的「架构角色化位宽+KV 各向同性化」路线
- **AdaSprite：边缘 V-MoE 在线协同适配**（arXiv:2608.16188, MobiSys 2026, 2026-08-17, https://arxiv.org/abs/2608.16188）: 车路协同(V2I) 边缘服务器多 V-MoE 共适配面临 DRAM 碎片化限制专家并行+内存 I/O 瓶颈；弹性扩缩+多级复用+双缓冲调度，弱边缘上 17 个并发任务（基线 6 个）、SLO 达成率 1.6x、吞吐 2.1x——边缘侧专家并行的资源碎片化问题首现

## 前沿模型与硬件经济学

- **Kimi K3：2.8T MoE 开源**（arXiv:2607.24653, 2026-08-07, https://arxiv.org/abs/2607.24653）: 104B 激活/896 路由专家中激活 16 个（Stable LatentMoE），百万 token 上下文，较 K2 缩放效率约 2.5x；基础设施侧强调「完美平衡的专家并行训练+高效内存管理」、百万 token agentic RL 持久 rollout——前沿 MoE 训练对 EP 均衡性与内存工程的要求再次升级
- **解码专用芯片经济学**（arXiv:2607.13068, 2026-07-10, https://arxiv.org/abs/2607.13068）: 主流 GPU 计算重/容量轻，decode 期 FP 单元利用率个位数百分比；F/B(roofline 脊点)与 F/S(每 GB 内存捆绑算力)两个常量形式化不匹配；Skymizer HTX-301（28nm PCIe 卡+DDR5、无 HBM/CoWoS/先进逻辑）8 卡单卡组 DeepSeek-R1 671B 约 $19K（20.3 tok/s 确定性），4U 四卡组两用户约 $28K；成本每百万 token $12 vs 8×GPU 节点 $21，扩展靠加卡——「MoE 解码是内存受限」催生无稀缺输入的专用解码硬件，与 Groq LPU 路线互为验证
- **MoE 架构演进综述：五维控制面框架**（arXiv:2608.08650, 2026-08-09, https://arxiv.org/abs/2608.08650）: 沿专家粒度/拓扑/路由自由度/均衡范围/执行结构五维组织 8 个架构里程碑，四控制面（Topology/Routing/Balance/EP）连接算法选择（top-k/共享专家/细粒度）与系统关切（token dispatch、设备放置、all-to-all、通信计算重叠）；主线=从「激活更多稀疏参数」转向「解耦语义路由、计算预算与物理执行」——为 MoE→硬件映射提供统一分析框架
- **Load Hijack：MoE 服务供应链攻击面**（arXiv:2608.10614, 2026-08-11, https://arxiv.org/abs/2608.10614）: 恶意模型提供方仅改 checkpoint 路由权重、保留私有触发器，触发时把 token 集中在单 GPU 专家上制造 straggler；92.3-95.6% 触发分配命中目标专家，TTFT 恶化 1.43x、吞吐 0.86x——EP 调度成为可武器化的攻击面，路由与运行时负载需纳入 checkpoint 审计
- **Tevatron 3.0：学术预算下的 EP 训练**（arXiv:2608.00916, 2026-08-02, https://arxiv.org/abs/2608.00916）: Megatron-Core 后端接入 Tevatron，单节点较 FSDP 快 22%，EP 使 30B(Qwen3-30B-A3B) MoE reranker 训练可行（FSDP1 不可行）；MoE reranker 匹配 dense 8B 质量、激活参数减半、推理吞吐显著更高——EP 训练栈正从工业界下沉到学术单节点

## 本日小结（MoE→硬件映射）

- **通信编排超越带宽成为超节点瓶颈**：SIGCOMM'26 UBEP 证明 NVL72/CloudMatrix384 上 MoE 稀疏通信的主要损失来自 BSP 串行化/同步/调度而非带宽（All-to-All -52.4%）；TAOT 补上「副本放置的拓扑感知」维度（训练 1.43x）——MoE 硬件优化从「堆带宽」转向「改编排」
- **解码专用硬件的经济学拐点出现**：HTX-301（$12/M tokens vs GPU 节点 $21/M、无 HBM/CoWoS 供应链约束）+ Groq 3 LPX 平台化，印证「MoE decode 内存受限→专用低算力高容量芯片」判断；本库观点：2027 前 GPU 仍是主流，但专用解码卡在 671B 级 MoE 推理的成本/供应链优势已具杀伤力
- **内存层级再分化**：HBF 直连 GPU 双路供给（1.94x）为「HBM 容量墙」提供存储级答案；消费级路径（RotaryQuant 120B/32GB、WiSP 1.95x）证明「总参数量决定带宽成本」下压缩+分页仍是唯一出路；边缘实证（2606.21428）反向确认稀疏激活在带宽受限硬件不兑现
- **运行时自适应成为服务端主线**：Moebius EP/TP 切换（215-434ms）+ELDR 专家局部性路由（TPOT -13.9%）+EasyBalance 跨层均衡（idle -40%）——MoE 服务的「并行度/放置/均衡」三轴全部走向运行时可变
