### 14.1 🔴 EcoSpec: Cost-Aware Speculative Decoding for MoE（arXiv 2607.12696, 2026-07-14）

**来源**: https://arxiv.org/abs/2607.12696

**核心方法**: 首次在MoE场景中引入**cost-aware speculative decoding**。关键发现：置信驱动(confidence-driven)的draft tree选择会导致**expert scattering**——高概率draft token可能路由到互不重叠的expert集合，显著增加verification阶段的weight memory traffic，抵消SD的加速收益。EcoSpec在draft选择中纳入predicted marginal expert activation cost，通过轻量expert predictor + dynamic expert buffer，偏好能保持高acceptance率同时复用当前verification集已有expert的draft路径。

**性能数据**:
| 指标 | 数值 |
|:-----|:-----|
| 模型测试 | DeepSeek-V3.1 (671B)·Qwen3-235B-A22B·GPT-OSS-120B |
| 端到端加速 | **↑1.62×** decoding speedup |
| 对比对象 | 无cost-aware的标准SD |

**硬件影响**: ⭐⭐⭐⭐⭐
- **首次将expert activation cost显式建模为SD的优化目标**——这是从"最大化acceptance率"到"最小化expert-memory traffic"的范式转变
- **对GPU调度的启示**：draft tree生成器需要感知GPU的expert weight layout，而非仅依赖模型logits
- **与MoE-Spec (2602.16052)的互补**：EcoSpec在draft选择端优化，MoE-Spec在verification端优化，两者可叠加

### 14.2 🔴 NVIDIA AI Model Co-Design: Hardware-Friendly LLM Design（NVIDIA Tech Blog, 2026-07-10）

**来源**: https://developer.nvidia.com/blog/ai-model-co-design-hardware-friendly-llm-design/

**核心方法**: NVIDIA官方发布的**7条硬件友好LLM设计指南**，全栈覆盖从模型维度选择到并行策略。由NVIDIA首席架构师Ritika Borkar等7位作者联合撰写。核心洞察：模型设计选择（H/hidden dim, H'/intermediate dim, 深度vs宽度, 精度格式）对硬件利用率的影响可与batch size相提并论。

**7条设计准则**:
1. **近方形权重矩阵**：避免projection/reduction维度过小，FP4 GEMM在K>3072后才能达到80%峰值
2. **维度对齐GPU tile**：最小128的倍数，优选256（clusterMMA）或512（CGA），避免tile quantization
3. **宽度优先于深度**：固定参数预算下，更宽模型提供更高arithmetic intensity
4. **低精度执行设计**：NVFP4在DeepSeek-R1上精度损失<1pt，应设计可量化层
5. **大规模Expert Parallelism**：MoE场景下EP是吞吐关键，Wide-EP + TensorRT-LLM处理all-to-all和负载不均衡
6. **规则重复层模式**：适配Chunked Pipeline Parallelism的平衡分片
7. **解耦Attention和FFN并行**：Helix Parallelism在Blackwell NVL72上实现KV cache sequence分片 + TP×EP

**性能数据**:
| 准则 | 数据 | 平台 |
|:----|:----|:----|
| 准则1·GEMM K阈值 | K>3072达80%峰值·K≈6144饱和 | GB300 NVFP4 |
| 准则2·tile对齐 | 128倍数安全→256/512捕捉clusterMMA/CGA收益 | GB300 |
| 准则4·NVFP4精度 | DeepSeek-R1精度匹配FP8，差距<1pt | Blackwell |
| 准则5·EP扩展 | Wide-EP跨Blackwell多节点NVLink | NVL72+ |
| 准则6·CPP | 256K prefill下FTL降低不牺牲吞吐 | DeepSeek-R1 |

**硬件影响**: ⭐⭐⭐⭐⭐
- **这是NVIDIA首次系统性地发布面向MoE的硬件-模型协同设计准则**，标志着"模型设计者必须懂硬件"成为NVIDIA的官方立场
- **准则2(GPU tile对齐)和准则1(近方形维度)对有深度量化含义**：当前DeepSeek-V4的CSA/HCA等非标准层可能产生非对齐维度，BlinkDL/MLA的low-rank projection也可能引入小K
- **准则5(EP扩展)直接定义Blackwell NVL72/NVL576的Moe部署最佳实践**：EP宽度是吞吐最大化第一杠杆
- **贯穿7条准则的统一信息**：MoE模型不仅是算法问题，更是**硬件布局问题**

### 14.3 🟢 TriRoute: Unified Learned Routing for Joint Adaptive Attention, Experts, and KV-Cache Allocation（arXiv 2607.06601, 2026-07-06）

**来源**: https://arxiv.org/abs/2607.06601

**核心方法**: **首个联合三轴（attention分辨率·expert选择·KV cache位宽）协同路由框架**。核心论点：MoE的expert选择、MoD的attention跳过、KV-cache量化是**强耦合**的——一个需要full attention的rare token可能也需要高精度KV cache，无论它路由到哪个expert。TriRoute用一个轻量控制器为每层每token输出联合策略：(i) attention模式(skip/local/full)、(ii) FFN expert集（含null expert恢复MoD）、(iii) KV cache位宽。通过Lagrangian budget约束将平均计算和内存成本变为可控旋钮。

**关键技术要素**:
- 识别跨轴路由坍塌级联(cross-axis routing-collapse cascade)并引入per-axis normalization + coupling-aware balancing loss解决
- 端到端用Gumbel-Softmax + ST估计 + load-balanced top-k gating训练

**性能数据**:
| 指标 | 数值 |
|:-----|:-----|
| 模型规模 | 160M–1.3B dense + MoE decoder-only |
| Pareto支配 | 在匹配FLOPs+内存下支配独立MoD+MoE+KV quantization组合 |
| 尾部鲁棒性 | rare实体·代码·数学场景更好保留（纯perplexity优化会侵蚀） |
| 可解释结构 | full attention+高精度cache分配给句子首位置·rare subword·named entity |

**硬件影响**: ⭐⭐⭐⭐⭐
- **最重要贡献：证明三轴决策高度耦合，独立优化各轴是次优的**——这对GPU硬件调度器设计有根本性影响：未来GPU可能需要支持**per-token per-layer的异构KV cache精度 + expert激活 + attention sparsity**
- **对Blackwell NVFP4+KV cache tier设计的启示**：TriRoute的结果支持在硬件层做异构KV cache级（如高精度cache + 低精度cache的双池），而非统一压缩
- cross-axis routing-collapse cascade是硬件设计者必须理解的现象：当expert collapse发生时，attention和KV cache也会跟着collapse

### 14.4 🟢 MoE-nD: Per-Layer Mixture-of-Experts Routing for Multi-Axis KV Cache Compression（arXiv 2604.17695, ICML 2026区域主席亮点, 2026-04-19）

**来源**: https://arxiv.org/abs/2604.17695

**核心方法**: 将MoE路由的思想引入KV cache压缩决策——不同层对eviction和quantization的响应极不均匀，采用统一方案导致精度损失。MoE-nD为每层路由到其专属的(eviction-ratio, K-bits, V-bits)三元组，构成一个**layer-wise MoE over compression strategies**。离线用greedy solver选择最小化预测质量损失的路由；推理时通过single attention patch实现per-layer异构eviction+quantization。

**性能数据**:
| 指标 | 数值 |
|:-----|:-----|
| 压缩比 | **14×** (1.9GB→136MB) | 
| 质量保持 | 匹配未压缩基线@14×，其他方法在同等更小内存下<8/100 |
| AIME推理 | +6至+27 pts vs最强per-layer quantization基线 |
| 空结果 | MATH-500/TREC短输入时所有层keep=1.0，无优化空间 |

**硬件影响**: ⭐⭐⭐⭐
- **"用MoE来优化MoE的KV cache"的递归思路**——MoE的per-token动态决策能力被创新性地复用到了内存管理层面
- **对GPU cache tier设计的启示**：不同层需要不同精度的KV cache，意味着未来GPU可能需要支持**layer-aware的HBM分配策略**而非统一的cache压缩
- 空结果同样有价值：短输入场景下per-layer routing无优化空间，说明layer-wise压缩的优势在**长上下文场景**才体现

### 14.5 🟢 Irminsul: MLA-Native Position-Independent Caching for Agentic LLM Serving（arXiv 2605.05696, 2026-05-07）

**来源**: https://arxiv.org/abs/2605.05696

**核心方法**: 针对**Multi-Head Latent Attention (MLA) + MoE**模型的agentic serving场景，实现内容寻址(position-independent)KV cache共享。关键洞察：agentic工作负载中同一token序列在每轮对话后shift位置，使传统prefix cache完全失效（运营商报告cache命中率骤降→TTFT 10-16s）。MLA将KV行分解为position-free的cKV + 64-dim kr（可闭式校正），因此内容寻址caching是MLA的自然适配而非绕开GQA的变通方案。

**关键技术要素**:
- 扩展SGLang的radix cache，用content-hash keying + CDC-chunked segments + δ-rotation rule for kr
- 验证三个原生MLA-MoE部署：DeepSeek-V2-Lite, Kimi Moonlight-16B-A3B, JoyAI-Flash

**性能数据**:
| 指标 | 数值 |
|:-----|:-----|
| 提示词恢复 | **~83%** 的prompt tokens在agentic流量上被恢复（超过exact-prefix） |
| Prefill能耗节省 | **↓63%** per cache hit |
| 兼容性 | 三个MLA-MoE模型输出一致验证通过 |

**硬件影响**: ⭐⭐⭐⭐
- **MLA正在成为下一代MoE模型的事实标准KV架构**（DeepSeek-V2/V3/R1/V4, Kimi-K2/Moonlight, GLM-5, Mistral Large 3），Irminsul证明MLA的cKV/kr分解在存储/缓存维度有额外红利
- **对GPU KV cache tier设计的启示**：内容寻址cache需要硬件层支持content-hash查找（类似CAM），而非仅依赖linear prefix match——这对未来GPU的cache controller架构有影响
- **63% prefills能耗节省**——在agentic推理场景中，KV cache的设计优先级应从"容量最大化"转向**"寻址灵活性最大化"**

### 14.6 🟢 Variable-Width Transformers: Nonuniform Width Allocation Across Depth（arXiv 2606.18246, 2026-06-16）

**来源**: https://arxiv.org/abs/2606.18246

**核心方法**: 挑战"所有层统一宽度"的约定俗成，提出> <former（哑铃形）——加宽早期和晚期层、收窄中间层，通过parameter-free residual resizing实现。在dense和**MoE**模型上均验证。关键洞察：不同层对容量的需求不同，统一分配导致中间层参数/计算浪费。

**性能数据**:
| 指标 | 数值 |
|:-----|:-----|
| 模型验证 | 200M–2B dense + **3B MoE** |
| FLOPs减少 | **↓22%**（fitted loss-matched scaling curve下） |
| KV cache减少 | **↓15%** I/O cost |
| 质量 | 持续优于参数匹配的uniform基线（perplexity） |
| 表征差异 | bottleneck结构产生性质不同的residual stream表征 |

**硬件影响**: ⭐⭐⭐
- **验证了中间层宽度可以被压缩而不损失质量**——这对MoE模型的GPU部署直接有利：中间层更窄→更少的expert参数→更低的HBM占用和all-to-all通信量
- **KV cache 15%减少**——注意力层宽度在中间层被压缩，直接降低KV cache token行维度
- 与NVIDIA HW-Friendly准则的关系：准则1/2要求近方形和128对齐，与Variable-Width存在张力——收窄的中间层可能不满足tile对齐要求，需在部署时做padding补偿

### 17.3 🟢 Infineon TLVR四相功率模块 >2 A/mm² — AI供电密度新标杆（eeNews Power 03/31）

**来源**: [eeNews Power](https://www.eenewspower.com), Mar 31, 2026 — "Infineon targets AI power density with TLVR quad-phase module"

| 信号 | 内容 |
|:-----|:------|
| 事件 | Infineon发布**业界首款基于TLVR（Trans-inductor Voltage Regulator）的四相功率模块**，功率密度>**2 A/mm²** |
| 架构 | TLVR → 比传统的多相buck转换器在**瞬态响应和电流密度**上更优，适合**高di/dt的AI加速器负载** |
| 密度 | **>2 A/mm²**是当时业界最高水平的功率密度指标 |

**解读**: TLVR是VR（Voltage Regulator）拓扑的重要演进方向。传统多相buck的瞬态响应受限于电感耦合，TLVR通过耦合电感实现了更快的电流斜率。Infineon将其推向AI芯片供电是其**TLVR商用的重要里程碑**——这意味着下一代AI加速器的VR模块体积不变（甚至更小）但可承载更高电流。

### 17.4 🟡 Lotus Microsystems垂直供电平台 — AI供电架构新思路（eeNews Power 06/24）

**来源**: [eeNews Power](https://www.eenewspower.com), Jun 24, 2026 — "Vertical power delivery platform aims to ease AI infrastructure constraints"

| 信号 | 内容 |
|:-----|:------|
| 事件 | Lotus Microsystems推出**垂直供电平台**，直接将功率转换移至**芯片正下方/垂直堆叠** |
| 创新 | 传统水平供电（板级走VRM→主板→Socket）→**垂直供电**（缩短电流路径，降低IR drop） |

**解读**: 垂直供电（Vertical Power Delivery / VPD）是AI高功耗芯片供电架构的前沿方向。传统板级VRM的路径损耗在>1000W场景下变得不可接受。Lotus的产品如果成熟，可能根本改变**AI服务器主板布局**——供电模块从"放在CPU/GPU旁边"变成"放在CPU/GPU下面"。
