- **NVIDIA 官方博客《ModelExpress: Distributing Model Artifacts at the Speed of Light》**（2026-07-24）: 模型权重生命周期加速平台——**NIXL 直接 GPU-to-GPU P2P RDMA 传输权重**，减少对对象存储与 host memory 的依赖；四策略=多线程流式 + 原子分布式缓存 + GPUDirect Storage + 运行时路径选择；面向 MoE/大模型数百 GB~TB checkpoint 与 expert 权重加载场景，优化冷启动、消除冗余数据移动；支持接收方驱动 RL refit 工作流，集成 vLLM/SGLang/Dynamo/llm-d；VMM arena registration 显著降低生产 LLM 部署的启动/注册开销。**对 MoE→硬件意义：EP 权重加载从「对象存储拉取」走向「GPU P2P RDMA 直传」，权重分发成为可优化的一等基础设施环节**。URL: https://developer.nvidia.com/blog/modelexpress-distributing-model-artifacts-at-the-speed-of-light/

- **NVIDIA 官方博客《Enhancing Goodput in Large-Scale LLM Training with Nonuniform Tensor Parallelism》**（2026-07-06）: NTP 让大规模训练任务**动态调整 TP 度应对瞬时 GPU 不可用**（故障/抢占），维持 goodput 并最小化计算停滞与吞吐损失；scale-up 域内集成**动态功率提升**（active GPU 临时升频补偿资源减少），避免 DP replica 间全局同步减速；overlapped tensor resharding 开销 **<1%**；在 Blackwell/Blackwell Ultra **72 GPU NVLink 域**验证。**对 MoE 训练：瞬态故障韧性 + 域内功率弹性，契合 MoE 长时程训练对 MTBF 敏感的特性**。URL: https://developer.nvidia.com/blog/enhancing-goodput-in-large-scale-llm-training-with-nonuniform-tensor-parallelism/

- **NVIDIA 官方博客《Co-Designing AI Model Attention for Fast, Interactive Long-Context Inference》**（2026-07-31）: dense attention 性能三决定因子=group size（每 KV head 的 query head 数）× head dim × seq len；**decode（memory-bound）效率随 group size 提升，prefill（compute-bound）由 seq len 主导**；硬件对齐规则=decode 用高 G、**head dim 取 128/256 匹配 GPU tile 与内存对齐**、**TP 度不得超过 KV head 数（TP≤KH）避免 KV 复制**；最小化有效 KV 状态=缓存压缩/稀疏/滑动窗口/混合架构（Nemotron 3）。**对 MoE→硬件：GQA/KV 头设计约束参与并行度选择，attention 层与 MoE 层的并行策略需联合设计而非独立优化**。URL: https://developer.nvidia.com/blog/co-designing-ai-model-attention-for-fast-interactive-long-context-inference/

- **arXiv 2605.20982《Diagnosing Overhead in Dispatch Operations: Cross-architecture Observatory》**（2026-05-20）: AlltoAll dispatch 被确认为 MoE EP 主导瓶颈；互联社区已有四类缓解=预测性样本放置/自适应专家重排/层次化集合通信/EP 感知拓扑；**论文检验四类方案共同的隐藏假设：①路由不均衡可由系统层纠正 ②mock-token 基准的有效性——假设不成立时缓解措施即失效**；以跨架构观测平台量化 dispatch 开销构成。**方法论信号：现有 MoE 通信优化的基准方法（mock-token）本身可能失真，硬件评估需真实负载轨迹**。URL: https://arxiv.org/abs/2605.20982

- **arXiv 2607.28633《Topology-Aware Data Movement for Disaggregated GPU Inference》**（2026-04-19）: PD 分离推理下 KV cache 需跨池传输——70B 模型 **2.6 GB/请求**、生产规模聚合 **>100 GB/s**；DistServe/Splitwise/Mooncake 均用 uniform RDMA、**忽视池内/池间带宽拓扑差异**；提出拓扑感知数据移动减少跨拓扑流量并规划放置。**对超节点：PD 分离网络需拓扑感知而非统一 RDMA，KV 搬家带宽是 MoE 时代存储×网络协同的关键量化点**。URL: https://arxiv.org/abs/2607.28633

- **arXiv 2603.02731《Practical FP4 Training for Large-Scale MoE Models on Hopper GPUs》**（2026-03-03）: MoE 训练被激活内存 + EP 通信双重瓶颈约束；Hopper 无原生 MXFP4/NVFP4 硬件支持使 FP4 训练不切实际；**给出无原生 4-bit 计算下实现 MXFP4 效率的训练配方**，在上一代硬件上延续 FP4 收益。**硬件含义：FP4 生态从「硬件原生」走向「软件模拟补位」，低比特训练提前于硬件换代落地**。URL: https://arxiv.org/abs/2603.02731

- **arXiv 2602.04870《Multi-Head LatentMoE and Head Parallel: Communication-Efficient and Deterministic MoE Parallelism》**（2026-02-04）: EP 三大局限=通信开销随激活专家数 k **线性增长**/负载不均衡损害延迟与内存/并行确定性差；MLHA + Head Parallel 新并行范式降低通信复杂度并恢复确定性。**对硬件：专家并行通信从 O(k) 下探，确定性并行利于故障诊断与可复现训练**。URL: https://arxiv.org/abs/2602.04870

- **arXiv 2608.00916《Tevatron Meets Megatron: Expert-Parallel LLM Reranker Training on an Academic Budget》**（2026-08-02）: 亿级 cross-encoder + MoE 骨干 + 强教师蒸馏的现代 reranking 配方已超出学术组基础设施能力；现有 Tevatron（HF Trainer + DeepSpeed/FSDP1）缺大规模 MoE 训练后端支持；提出基于 Megatron 的 EP 训练管线，在学术预算内实现大规模 MoE reranker 训练。**信号：EP 训练基础设施下沉到学术场景，MoE 训练工具链成本曲线持续下探**。URL: https://arxiv.org/abs/2608.00916
