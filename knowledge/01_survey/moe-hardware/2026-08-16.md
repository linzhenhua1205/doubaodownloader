## MoE→超节点/集群通信

- **UBEP / SIGCOMM 2026（07-07, 华为+南大等）**: 面向生产超节点（NVIDIA NVL72/576、华为 CloudMatrix384）的 MoE 通信库，直指三大瓶颈——BSP 粗粒度串行化、同步开销不随带宽扩展、距离无关调度致负载不均；全规模实验 All-to-All 延迟最高降 **52.4%**、MoE 推理 TPOT 降 **11.1%**（URL: https://arxiv.org/abs/2607.06202）

- **Scaling Multi-Node MoE Inference / Meta（04-25）**: 采集 Llama 4 Maverick、DeepSeek V3-671B、Qwen3-230B-A22B 超 10 万条真实专家激活轨迹，发现专家负载不均、领域相关激活漂移、prefill-decode 激活强相关三大特征；据此做工作负载感知微批分组+专家放置，inter-node all2all 通信数据降 **20x**（URL: https://arxiv.org/abs/2604.23150）

- **NCCL EP / NVIDIA（03-13）**: 完全基于 NCCL Device API 构建的 MoE 通信库，统一 ncclEpDispatch/ncclEpCombine 原语；LL 模式（1-128 token 批）走 direct all-to-all RDMA+NVLink mesh 双缓冲，HT 模式（4096+ token 批）走 NVLink 域内聚合+节点间 RDMA 分层——GPU-initiated 通信成为 NVIDIA 官方 MoE 并行路径（URL: https://arxiv.org/abs/2603.13606）

- **Fine-grained Computation-Communication Overlap / ICPP'26（07-21）**: tile 级信号+调度把 MoE 第二次 all-to-all 与专家计算重叠（生产者-消费者协同：持久计算 kernel + 专用 SM 分区通信 kernel）；4×A100 上对比四个 SOTA MoE 系统，端到端最高 **2.64x**、MoE 层 **2.74x** 加速（URL: https://arxiv.org/abs/2607.19539）

- **DisagMoE（05-10）**: 解耦 AF-Pipe 并行——attention 与 FFN 分置独立 GPU 组、单向多对多通信 + 计算通信 roofline 模型平衡带宽分配；Megatron-LM 实现，16 节点 8×H800 集群训练效率最高 **1.8x**（URL: https://arxiv.org/abs/2605.11005）

- **Federation of Experts FoE（05-07）**: 重构 MoE block 为按 KV head 分簇、簇内专家并行，单节点完全消除 all-to-all、多节点收敛至节点内互联；LongBench 上端到端 forward 延迟降 **5.2x**、TTFT **3.62x**、TBT **1.95x**（URL: https://arxiv.org/abs/2605.06206）

- **Piper / ORNL（05-06）**: 面向 HPC 平台的 MoE 训练资源建模（内存/计算/通信三要素，微基准+硬件剖析验证），流水并行+优化调度使 MFU 较 X-MoE 等 SOTA 高 **2-3.5x**，自研 all-to-all 算法带宽达厂商实现 **1.2-9x**（URL: https://arxiv.org/abs/2605.05049）

- **LAER-MoE / ASPLOS'26（02-12）**: FSEP 全分片专家并行范式——专家参数按设备数全切分、训练中按专家粒度 All-to-All 重组，负载均衡规划器动态重排专家与路由；A100 集群较 SOTA 训练系统最高 **1.69x** 加速（URL: https://arxiv.org/abs/2602.11686）

## MoE→GPU/芯片架构

- **NVIDIA 官方博客/Serve Qwen3.8-Max on GB300 NVL72（08-12）**: 阿里开源最大 MoE 模型 Qwen3.8-2.4T-A95B（2.4T 总参数/95B 激活，可配置推理模式），NVIDIA 官方给出 GB300 NVL72 部署方案——2.4T 参数 MoE 的显存占用与专家并行布局成为超节点算力验证样板（URL: https://developer.nvidia.com/blog/serve-qwen3-8-2-4t-a95b-a-2-4t-parameter-model-with-configurable-reasoning-on-nvidia-gb300-nvl72/）

- **NVIDIA 官方博客/GB300 NVL72 MoE 预训练世界纪录（07-21）**: 官方确认 frontier 预训练已收敛于 MoE，"计算每 token 的极限"成为新瓶颈；GB300 NVL72 上实现 MoE 预训练世界纪录，验证超节点对稀疏大模型训练的主导地位（URL: https://developer.nvidia.com/blog/setting-a-world-record-for-moe-pre-training-on-nvidia-gb300-nvl72/）

- **Mozart / NeurIPS'25 Spotlight（03-07）**: 3.5D 晶圆级 chiplet 架构上的 MoE 算法-硬件协同设计——专家分配策略实现 on-package all-to-all、细粒度调度提升通信计算重叠，架构侧 2.5D NoP-Tree 拓扑+分层内存异质模块共置；三个流行 MoE 模型验证显著效率提升（URL: https://arxiv.org/abs/2603.07002）

- **Birkhoff Decompositions and Photonic Interconnects（05-26）**: 重构 MoE 光子互连电路调度：BvN 分解因 MoE 通信矩阵非双随机引入调度气泡、匹配数过多致小批量计算碎片化；贪心最大权重分解在保持大批量同时逼近无拥塞 all-to-all 理想性能——MoE 稀疏通信为可重构光电路交换提供天然场景（URL: https://arxiv.org/abs/2605.26845）

## MoE→推理系统与显存

- **Moebius（06-25）**: EP/TP 运行时无缝切换（EP 高并发优、TP 低并发优，生产负载持续跨越边界）；关键洞察"EP 与 TP 是同一模型的两种布局"——仅移动归属变化的切片，8×H200 服务 Qwen3-235B-A22B 全工作点追平最优静态并行，RL rollout 场景 **1.16-1.25x**，单次切换 **215-434ms**、双布局共存仅 **2.4%** 内存开销（URL: https://arxiv.org/abs/2606.26607）

- **ELDR（07-01）**: PD 分离架构下 expert-locality 感知 decode 路由——从 prefill 专家激活构建专家签名、K-means 划分 worker、签名缓存与 KV cache 同粒度索引；vLLM 实现、40 GPU 部署，三个 MoE 模型上中位 TPOT 较四种负载均衡基线降 **5.9-13.9%**（URL: https://arxiv.org/abs/2607.00466）

- **WiSP（06-20）**: 极低资源硬件上 MoE 服务=工作集管理问题：路由专家权重与 KV cache 竞争显存；MV-WSA 按每字节边际延迟收益分配显存，decode 吞吐达静态 offload **1.95x**、在线控制器再添 **1.20x**；实证 prefetch 专家帮助甚微——瓶颈是 PCIe 带宽而非预测精度（URL: https://arxiv.org/abs/2606.21868）

- **PagedWeight（07-17）**: MoE serving 中动态质量感知权重量化——运行时权衡专家权重精度与 KV cache 大小；FP16 等价精度下 GPU 内存节省 **72.0%**、吞吐 **1.94x**，同内存预算下质量较量化基线高 **39.3%**（最多损失 4.1% 吞吐）（URL: https://arxiv.org/abs/2607.16184）

- **TriRoute（07-07）**: 统一学习控制器联合决策 attention 模式/FFN 专家集合/KV cache 位宽（MoD+MoE+KV 量化三轴联合）；160M-1.3B 模型上帕累托支配独立组合方案，稀有实体/代码/算术尾部鲁棒性更好——控制器把全 attention+高精度缓存分配给句首/稀有子词/命名实体（URL: https://arxiv.org/abs/2607.06601）

- **MawForge（06-17）**: 受限统一内存机器（Mac 类）本地 MoE 推理：模型存磁盘、公共张量常驻、路由专家按需物化进有界执行缓存；结论是"有界执行机制+测量基板有效、但非缓存最大化策略"——专家复用 vs 驻留足迹 vs KV cache 三方权衡（URL: https://arxiv.org/abs/2607.09686）

- **Detecting a Route Flip（07-14, 预注册）**: 4-bit KV cache 量化读数经 BF16 gate 可致 MoE 路由翻转：OLMoE-1B-7B 上约 1/3 量化损伤为路由介导（RMF≈0.31）；可部署路由裕度能检出翻转（AUC 0.772）但无法区分有害/有益——量化-路由交互的因果拆解（URL: https://arxiv.org/abs/2608.11212）

- **RotaryQuant（08-08, NeurIPS'26 投稿）**: 三轴压缩把 120B MoE 压进消费硬件：4-bit 稠密层+2-bit 路由专家+8-bit 共享专家混合精度、LRU 专家磁盘 offload、IsoQuant（Walsh-Hadamard+SO(4) 旋转等向化后 3-bit 量化 KV cache，每 head 仅 256 参数 vs 稠密旋转法 16,384）；16GB 跑 Gemma 4-26B-A4B/Qwen3-30B-A3B、32GB 跑 Nemotron-H 120B，交互 **9-19 tok/s**、ΔPPL≤+0.0012、32K 上下文检索 100%（URL: https://arxiv.org/abs/2608.08081）

## MoE→消费级/边缘硬件

- **Does MoE Actually Help on Consumer/Edge Hardware?（06-19, 实证研究）**: OLMoE-1B-7B（1.3B 激活/6.9B 总参）对比三个 dense 基线：M2 Pro 笔记本落后同激活 Llama-3.2-1B 约 **10%**，Jetson Orin Nano 8GB 落后 **31%** 且每 token 能耗 **2.1x**、峰值内存触 8GB 天花板；路由仅占 MoE block 计算 <9%——差距来自总参显存足迹+专家调度+KV 压力；**带宽受限边缘设备上推理成本跟随总参数而非激活参数**（URL: https://arxiv.org/abs/2606.21428）

- **GQE Grouped Query Experts（06-18）**: GQA 自注意力上加 MoE 层——每 token 每 GQA 组选 k 个 query-head 专家，KV head 保持稠密，保留 GQA 的 KV cache 收益同时激活 query-head 计算减半；250M 尺度 30B token 预算下下游精度持平全激活基线（URL: https://arxiv.org/abs/2606.20945）

## MoE→网络架构

- **Switching Efficiency Framework（04-16）**: 提出交换效率 η（单位交换容量承载的计算有效吞吐），分解为数据/路由效率/端口利用率三因子；论证 3D-Torus 对称分布式交换与 Rail-Optimized 集中分层交换对不同稀疏/失衡训练流量的适配，**MoE 的 All-to-All 流量严重劣化端口利用率与路由效率**——为 AIDC 网络设计提供度量工具（URL: https://arxiv.org/abs/2604.14690）

- **The Evolution of MoE Architectures 综述（08-09）**: 五维耦合框架（专家粒度/拓扑/路由自由度/负载均衡范围/执行结构）+8 个架构里程碑依赖图+四控制平面（拓扑/路由/均衡/专家并行）；主线趋势：从"激活更多稀疏参数"转向"语义路由、计算预算、物理执行解耦"——为 MoE 硬件需求（token 分发、设备放置、all-to-all、通信计算重叠）提供系统化图谱（URL: https://arxiv.org/abs/2608.08650）
