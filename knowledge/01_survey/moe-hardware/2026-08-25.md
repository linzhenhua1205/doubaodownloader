## MoE 通信与专家并行（arXiv）

- **MoE 架构演进综述：路由/拓扑/负载均衡/专家并行五维框架**（arXiv:2608.08650, 2026-08-09）: 综述按五维组织现代 MoE——专家粒度/专家拓扑/路由自由度/负载均衡范围/执行结构；八架构里程碑按依赖图而非代际排列；四控制面（专家拓扑/路由/均衡/专家并行）将算法选择与系统关切（token 分发、设备放置、all-to-all、通信计算重叠）打通；主旨趋势=从"激活更多稀疏参数"转向"解耦语义路由、计算预算与物理执行"。http://arxiv.org/abs/2608.08650
- **Tile 级信令调度实现 MoE 通信-计算细粒度重叠**（arXiv:2607.19539, ICPP'26）: 生产者-消费者协同设计——常驻计算核（producer）覆盖本秩全部专家消除重复 kernel 启动，专用 SM 分区上的常驻通信核（consumer）按 tile 就绪粒度发段传输；避免侵入算子/通信原语；4×A100 上 3 个 MoE 模型对 4 个 SOTA 系统最高 2.64x 端到端、2.74x MoE 层加速。http://arxiv.org/abs/2607.19539
- **UBEP：面向生产级超节点重构专家并行通信库**（arXiv:2607.06202, ACM SIGCOMM'26）: 瞄准 NVL72/576 与华为 CloudMatrix384；指出裸互联带宽外的三大瓶颈——BSP 粗粒度串行化、同步开销不随带宽扩展、距离无关调度的 token 流量负载失衡；Unified-Bus EP 将 All-to-All 延迟降 52.4%、MoE 推理 TPOT 降 11.1%。http://arxiv.org/abs/2607.06202
- **NCCL EP：NVIDIA 官方统一专家并行通信 API**（arXiv:2603.13606, NVIDIA）: 完全基于 NCCL Device API 的 MoE 通信库，提供 ncclEpDispatch/ncclEpCombine（C+Python）；LL 模式（1-128 token，RDMA+NVLink mesh 直连 all-to-all 双缓冲重叠）面向 decode，HT 模式（4096+ token，NVLink 域内聚合后跨节点 RDMA）面向训练/prefill；H100 集群评估 + vLLM 集成；标志 EP 通信从 DeepEP/Hybrid-EP 等专用库走向 NCCL 官方路径。http://arxiv.org/abs/2603.13606
- **Expert Activation Patterns：多节点 MoE 推理规模化的激活模式刻画**（arXiv:2604.23150）: 对 Llama 4 Maverick/DeepSeek V3-671B/Qwen3-230B-A22B 采集 10 万+真实专家激活轨迹；发现跨模型共性——专家负载失衡可变、专家激活领域相关（代码/数学/对话迁移）、prefill 与 decode 激活强相关；workload-aware 微批分组+专家放置最大化 token 本地性，all2all 通信数据降 20x。http://arxiv.org/abs/2604.23150
- **FarSkip-Collective：架构改造解锁 MoE 通信计算重叠**（arXiv:2511.11505, MLSys'26）: 修改模型架构（跳过连接）使计算可重叠通信，16B-109B 全量转换精度保持（Llama 4 Scout 109B 自蒸馏后评测差距 <1%）；SGLang 服务 DeepSeek-V3 架构 TTFT 提速 32.6%、prefill 阶段通信计算重叠 97.3%；训练侧 all-to-all 重叠 88.9%。http://arxiv.org/abs/2511.11505
- **DisagMoE：AF-Pipe 分离式 MoE 训练**（arXiv:2605.11005）: 将注意力与 FFN 层分置不同 GPU 组，多级流水线+单向多对多通信+roofline 模型平衡 GPU/网络带宽分配；Megatron-LM 实现，16 节点 8×H800 最高 1.8x 训练加速。http://arxiv.org/abs/2605.11005
- **Piper：资源建模驱动的 MoE 训练策略**（arXiv:2605.05049）: 数学建模量化内存/计算/通信需求，识别四大瓶颈（EP all-to-all 延迟、重叠不足、瘦 GEMM 利用率低、缺平台感知混合并行）；比 X-MoE 等 MFU 高 2-3.5x，新 all-to-all 算法带宽超厂商实现 1.2-9x。http://arxiv.org/abs/2605.05049
- **Moebius：TP/EP 运行时无缝切换**（arXiv:2606.26607）: 关键洞察=EP 与 TP 是同一模型两种布局（字节相同权重与 KV cache），切换仅移动归属变更的分片；8×H200 服务 Qwen3-235B-A22B 匹配两种静态并行最优，RL rollout 提速 1.16-1.25x，单次切换 215-434ms，双布局驻留仅 2.4% 内存开销。http://arxiv.org/abs/2606.26607
- **Switching Efficiency 框架：从网络效率拆解 MoE all-to-all 劣化**（arXiv:2604.14690）: 提出 η=计算有效吞吐/交换容量，分解为 Data/Routing Efficiency/Port Utilization 三因子；证明 3D-Torus 对称分布式交换与 Rail-Optimized 集中分层交换对稀疏/失衡 LLM 流量适配差异，MoE all-to-all 严重劣化端口利用率与路由效率。http://arxiv.org/abs/2604.14690
- **光子互连调度：MoE all-to-all 与 Birkhoff 分解冲突**（arXiv:2605.26845）: MoE 通信矩阵罕见双随机，BvN 分解产生调度气泡；贪心最大权重分解限制匹配数保持大批次，逼近无拥塞 all-to-all 性能——为可重构光子交换在 MoE 场景应用提供调度约束分析。http://arxiv.org/abs/2605.26845
- **Mozart：3.5D 晶圆级 chiplet 上的 MoE 训练协同设计**（arXiv:2603.07006, NeurIPS'25 Spotlight）: 算法侧专家分配策略+流式 token/专家细粒度调度，架构侧 2.5D NoP-Tree 拓扑+分层内存，包内 all-to-all；面向晶圆级集成（wafer-scale）的 MoE 硬件架构探索。http://arxiv.org/abs/2603.07006
- **LAER-MoE：负载自适应专家重排**（arXiv:2602.11686, ASPLOS'26）: FSEP 并行范式全分片专家参数+all-to-all 按专家粒度恢复，训练中灵活重排专家位置；负载均衡规划器联合优化重排与路由；A100 集群最高 1.69x 加速。http://arxiv.org/abs/2602.11686
- **PROBE：MoE 推理实时预测预取协同均衡**（arXiv:2602.00509）: 连续前瞻流水线（gate 初始化预测下一层专家激活）+硬件感知均衡规划（动态专家复制+token 分配）+相位锁定协同调度（分裂相位传输隐藏带宽）；极端负载波动下 prefill 延迟降 1.32x、decode 吞吐提升 1.26x。http://arxiv.org/abs/2602.00509
- **MixServe：TP-EP 混合并行的自动 MoE 服务系统**（arXiv:2601.08800, ICDCS'26）: 融合 AR-A2A 通信算法重叠节点内 AR 与节点间 A2A；DeepSeek-R1/Qwen3 上 TTFT 加速 1.08-3.80x、ITL 1.03-1.66x、吞吐提升 5.2%-50.3%。http://arxiv.org/abs/2601.08800

## MoE 推理与 KV cache（arXiv）

- **Beyond Capacity：HBF 双路径直连 GPU 的 MoE 推理**（arXiv:2608.14333, 2026-08-14）: 高带宽闪存（HBF）组织同时利用直连 GPU-HBF 与 HBF-HBM 中继双独立专家投递路径并发传输，整专家分配单路径；早期专家判定将 HBF 读延迟藏入前序计算，专家权重与 KV cache 分治降干扰；模拟代表负载吞吐 1.94x、端到端 1.90x vs 仅 HBM 中继路径。http://arxiv.org/abs/2608.14333
- **HBF 在 LLM Serving 中的潜力**（arXiv:2608.13127, 2026-08-14）: HBF 作为容量向扩展融入 GPU 内存层级（不损害计算 die 带宽预期）；MoE 场景=支撑更多专家副本（hot-model 复制）、多模型服务减少加载；收益依赖保留 HBM 驻留执行路径+HBF 扩展权重驻留集。http://arxiv.org/abs/2608.13127
- **KARAT：面向检索式稀疏注意力的通用 PNM 设计**（arXiv:2608.03555）: KV cache 移出 GPU 内存，PNM 节点持 KV+索引键并执行读取侧全部操作；GPU 执行投影/MoE 层；推导 PIM/PNM 四大设计需求；LPDDR 大容量+通用算力适配检索索引器；三模型+真实 agent 轨迹吞吐/TDP 提升 2.09-6.13x（GPU-only 基线）。http://arxiv.org/abs/2608.03555
- **RotaryQuant：消费级硬件拟合 120B MoE**（arXiv:2608.08081, NeurIPS'26 投稿）: 三轴压缩——混合精度量化（dense 4-bit/路由专家 2-bit/共享专家 8-bit）+LRU 专家磁盘卸载+IsoQuant KV 压缩（Walsh-Hadamard 变换+SO(4) 块对角旋转各向同性化后 3-bit 标量量化，O(d log d)）；融合四核 Metal 流水线直接算 3-bit 张量；16GB 跑 Gemma 4-26B/Qwen3-30B，32GB 跑 Nemotron-H 120B，9-19 tok/s，ΔPPL ≤ +0.0012。http://arxiv.org/abs/2608.08081
- **CrossPool：冷 MoE 多模型服务的权重/KV 分离**（arXiv:2606.24506）: 权重（稳定、模型决定）与 KV cache（瞬态、需求决定）分池——权重池跨冷模型合并 FFN 权重，KV 池动态服务活跃请求且注意力本地化；层级流水调度隐藏隐藏态传输；P99 TBT 降 10.4x。http://arxiv.org/abs/2606.24506
- **ELDR：PD 分离下专家本地感知解码路由**（arXiv:2607.00466）: decode 步骤需加载每批激活专家的全部权重，等负载≠等延迟；从 prefill 专家激活构建专家签名，离线 K-means 分区签名空间，在线 locality-band 路由；签名缓存与 KV cache 同粒度共索引支持前缀缓存；vLLM 实现 40 GPU 部署，中位 TPOT 降 5.9-13.9%。http://arxiv.org/abs/2607.00466
- **TriRoute：注意力/专家/KV 位宽三轴联合学习路由**（arXiv:2607.06601）: 三决策强耦合（值得全注意力的 token 可能也需高精度缓存）；单一轻量控制器逐 token 逐层输出注意力模式（skip/local/full）+稀疏专家集（含 null 专家=MoD）+KV 位宽；Gumbel-Softmax+负载均衡 top-k gating 联合训练，Lagrangian 预算约束把平均成本变成可控旋钮；160M-1.3B 模型上 Pareto 支配独立 MoD+MoE+KV 量化组合。http://arxiv.org/abs/2607.06601
- **Windowed-MTP：百万 token 上下文去除 draft-KV 税**（arXiv:2607.21535）: 前沿模型内建 MTP/NEXTN draft 头在长上下文下全注意力读 KV 成本随长度线性增长（draft 越深越可能净负）；对 draft 注意力仅用 StreamingLLM 滑窗+attention sink，target 全注意力验证不变（无损 by construction）；1M 上下文丢弃 ~99% KV 条目，Qwen GDN-MoE 35B/122B 等每 decode 步成本降 28-44%。http://arxiv.org/abs/2607.21535
- **PagedWeight：KV 密集场景动态质量感知权重量化**（arXiv:2607.16184）: MoE 服务中权重内存与增长 KV cache 的张力；运行时动态量化专家权重平衡精度/内存/吞吐；FP16 等效精度下 72.0% GPU 内存节省、1.94x 吞吐，同内存预算质量优于量化基线 39.3%。http://arxiv.org/abs/2607.16184
- **KV Cache 管理综述：30+ 系统四轴分类**（arXiv:2607.02574）: KV cache 已是 LLM serving 一阶内存对象；四轴=局部性/生命周期/所有权/底层介质，五架构原型（local-paged/disaggregated-pipeline/shared-store/memory-pool/hybrid-tier）；识别 7 项缺失的 KV 专属测量，关联 MoE serving 等开放问题。http://arxiv.org/abs/2607.02574
- **量化下 MoE 路由翻转的因果损伤检测**（arXiv:2608.11212）: 4-bit KV 量化读数+BF16 gate 保护使 token 跨越决策边界翻转专家激活；RMF≈0.31（OLMoE-1B-7B pilot）；路由器 margin 能检测翻转发生（AUC 0.772）但无法判断翻转有害/有益（chance）——存在经验收益检测屏障，为 MoE+量化部署提供安全边界洞察。http://arxiv.org/abs/2608.11212
- **Decode-Branch Transformers：prefill/decode 计算解耦**（arXiv:2608.12385）: 主路径单独处理 prompt 写 KV cache，decode 分支仅从末位激活追加续写计算；MoE 下主/分支专家 fan-out 成为调节 prefill/decode 成本与质量的独立旋钮。http://arxiv.org/abs/2608.12385
- **多模态边缘智能中压缩/MoE 路由/量化交互综述**（arXiv:2607.20981）: 论证视觉 token 压缩改变 MoE 路由决策、量化 router logits 影响专家分配、KV 策略决定多模态证据保留，各优化不可独立处理；提出 Temporal Routing Consistency 诊断。http://arxiv.org/abs/2607.20981

## 趋势洞察（本组增量）

- **MoE 硬件影响主线=通信而非计算**：本轮 15+ 篇 arXiv 一致指向 all-to-all 专家通信是 MoE 规模化（训练+推理）第一瓶颈，优化收敛于三大方向——(1) 通信计算重叠（tile 级信令/FarSkip 架构改造/disaggregation）、(2) 通信库重构（NCCL EP 官方化/UBEP 超节点化）、(3) 拓扑与调度联合（激活模式驱动的专家放置/PD 分离路由/TP-EP 运行时切换）。对硬件启示：超节点内互联带宽（NVLink/UB）与节点间网络（RDMA/光交换）共同决定 MoE 效率，单一带宽堆叠不够，需调度感知的交换拓扑。
- **内存层级重组是第二主线**：HBF 双路径、PNM/KARAT、KV 池化（CrossPool）显示 MoE 推理正把"专家权重驻留"与"KV cache 驻留"拆成独立内存策略——权重看容量（HBF/LPDDR 卸载），KV 看动态需求（池化/压缩），未来加速器内存层级（HBM→HBF→LPDDR→盘）将按对象类型分化设计。
- **验证信号与 MEMORY 研究跟踪一致**：NCCL EP（NVIDIA 官方）与 DeepEP 生态、UBEP（CloudMatrix384 协同）呼应"MoE 硬件主线"跟踪中的调度与通信优化；Qwen3.8-2.4T 落地 GB300 NVL72 印证 2T+ 稀疏模型成为 2026H2 主流规模，机柜级推理形态固化。
