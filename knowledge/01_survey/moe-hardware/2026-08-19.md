## 结论概要

- **MoE 已收敛为前沿模型预训练主流架构，且"通信取代算力"成为扩展瓶颈**——NVIDIA 官方以 GB300 NVL72 在 DeepSeek-V3 671B 上的世界纪录实证：MoE 使 per-token 算力下降，expert 分布在不同 GPU 上，all-to-all 通信进入前向/反向关键路径，系统吞吐与通信设计强耦合
- **硬件-软件协同设计收益显著**：同一 GB300 硬件 6 个月软件优化 +1.5×；TorchTitan 累计 ~6×、JAX 累计 ~10×（256 GPU 规模），说明 MoE 时代"堆硬件不如软件栈协同"
- **本周 arXiv 密集产出 MoE 负载均衡/推理优化论文**（FreeBalance/EasyBalance/Beyond Capacity/RotaryQuant），与已跟踪主线（RoutePack/TAOT/Load Hijack/Kimi K3）形成呼应，方向一致：**负载均衡 + 内存/存储层次创新 + 边缘硬件适配**

## 一、NVIDIA 官方（最高可靠 · 机架级实证）

- **来源/标题**: [Setting a World Record for MoE Pre-Training on NVIDIA GB300 NVL72](https://developer.nvidia.com/blog/setting-a-world-record-for-moe-pre-training-on-nvidia-gb300-nvl72/)（2026-08-06）
  - GB300 NVL72 在 DeepSeek-V3 671B 预训练达成 **1,648 TFLOPS/GPU** 世界纪录，对比 GB200 NVL72 早期软件的 606 TFLOPS/GPU，**单代交付吞吐 ~3×**
  - 硬件底座：第五代 NVLink **1.8 TB/s per-GPU** 带宽 + **130 TB/s 无阻塞 all-to-all**（机架内）；机架外经 ConnectX-8 SuperNIC + Quantum-X800 InfiniBand / Spectrum-X Ethernet 保持确定性扩展
  - 软件驱动增长：同一 GB300 平台 6 个月性能 +1.5×（纯软件）；Megatron Core 累计优化 ~6×；JAX 优化累计 ~10×（256 GPU，最新 1,025 TFLOPS/GPU）
  - 扩展效率：256→1,024 GPU，Megatron Core 保持 98.5% per-GPU 性能，TorchTitan/JAX 各 97%——scale-out 织物几乎无损转成系统级 token/s
  - **架构论断（第一性原理）**: MoE 下"每 token 计算量随总参数量下降"，但专家分布跨 GPU，每层 all-to-all（forward+backward）落在关键路径——**通信效率决定 MoE 大规模扩展上限**，比芯片算力更关键

- **来源/标题**: [Serve Qwen3.8-2.4T-A95B, a 2.4T-Parameter Model, with Configurable Reasoning on NVIDIA GB300 NVL72](https://developer.nvidia.com/blog/serve-qwen3-8-2-4t-a95b-a-2-4t-parameter-model-with-configurable-reasoning-on-nvidia-gb300-nvl72/)（2026-08-14）
  - 2.4T 总参 / 95B 激活 MoE（A95B）在 GB300 NVL72 上可配置推理服务——2.4T 级 MoE 落地机架级推理，说明 MoE 推理对 scale-up 域（NVLink 域内承载 EP 通信）的需求与训练同构
  - 佐证 NVIDIA 生态向"超大 MoE 服务化"迁移：推理侧同样依赖 NVL72 机架的 130 TB/s 域内带宽

- **来源/标题**: [Boosting MoE Training Throughput with Advanced Fusion Kernels](https://developer.nvidia.com/blog/boosting-moe-training-throughput-with-advanced-fusion-kernels/)（2026-06-25，补充）
  - MoE 训练吞吐提升依赖融合 kernel 消除 kernel 启动/中间内存搬运开销——软件优化是 MoE 硬件利用率的第二杠杆（与 08-19 主线呼应）

## 二、arXiv 新论文（最近 1 个月 · 高可靠预印本）

- **来源/标题**: [FreeBalance: Pre-Routing Online MoE Load Balancing via Residual Workload Prediction](https://arxiv.org/abs/2608.14205)（2026-08-14）
  - 提出 pre-routing 在线负载均衡：用残差负载预测在路由前预判专家负载，规避经典 auxiliary-loss 路由的负载抖动——MoE 负载均衡从"事后纠偏"走向"事前预测"

- **来源/标题**: [EasyBalance: Cross-Layer Load Balancing in Distributed MoE Inference](https://arxiv.org/abs/2608.07964)（2026-08-08）
  - 面向分布式 MoE 推理的**跨层**负载均衡——识别层间负载不均衡（不同层专家热度不同）并统一调度，直接作用于推理吞吐/延迟，硬件侧对应 GPU 利用率与 all-to-all 带宽占用

- **来源/标题**: [Beyond Capacity: Scalable MoE LLM Inference via High-Bandwidth Flash with Direct GPU and HBM Paths](https://arxiv.org/abs/2608.14333)（2026-08-14）
  - **硬件最相关**：高带宽 Flash（直连 GPU 与 HBM 路径）支撑 MoE 推理扩展——把专家权重/激活下沉到直连闪存层次，绕过 DRAM 容量墙；指向"GPU-HBM-Flash 三级内存层次"成为 MoE 推理硬件新方向

- **来源/标题**: [RotaryQuant: Fitting 120B MoE Models on Consumer Hardware via Fused Compressed-Space Attention](https://arxiv.org/abs/2608.08081)（2026-08-08）
  - 消费级硬件（个人 GPU）跑 **120B MoE**：融合压缩空间注意力 + 量化，MoE 从数据中心下沉到边缘/桌面——对端侧硬件（显存/带宽/算力）提出新的适配需求

- **来源/标题**: [The Evolution of Mixture-of-Experts Architectures in Large Language Models: Routing, Topology, Load...](https://arxiv.org/abs/2608.08650)（2026-08-09）
  - MoE 架构演进综述（路由/拓扑/负载），适合作为 MoE→硬件影响图谱的文献锚点

- **来源/标题**（已跟踪主线呼应，一行带过）: RoutePack（[2608.12146](https://arxiv.org/abs/2608.12146) 08-12 专家放置+数据打包）、TAOT（[2608.03676](https://arxiv.org/abs/2608.03676) 08-04 拓扑感知最优传输放置 +8.85%/14.89%）、Load Hijack（[2608.10614](https://arxiv.org/abs/2608.10614) 08-11 负载劫持攻击 TTFT 1.43×）、Kimi K3（[2607.24653](https://arxiv.org/abs/2607.24653) 2.8T/104B 激活 16-of-896 EP）——与 FreeBalance/EasyBalance 同属"负载均衡×并行"主线（已由 08-17/18 调研收录）

- **来源/标题**（KV cache 侧补充）: [Aborted but Not Forgotten: KV-Cache Retention Breaks Rollback Consistency](https://arxiv.org/abs/2608.15939)（08-16, KV 缓存保留与 agent 回滚一致性）、[Compression, MoE Routing, and Quantization Interactions](https://arxiv.org/abs/2607.20981)（07-23, 压缩×路由×量化相互作用）——MoE 推理的内存层次优化侧写
