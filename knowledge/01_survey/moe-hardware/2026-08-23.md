## 专家并行通信（All-to-All 体系）

- **UBEP：为生产级超节点重构专家并行通信库**（arXiv 2607.06202, ACM SIGCOMM 2026, 2026-07-08）：针对 NVIDIA NVL72/576 与华为 CloudMatrix384 指出三大瓶颈——BSP 粗粒度串行化、同步开销不随带宽扩展、距离无关调度导致负载不均；实验 All-to-All 延迟最高降 52.4%、MoE 推理 TPOT 最高降 11.1%（https://arxiv.org/abs/2607.06202）
- **细粒度计算-通信重叠：tile 级信令与调度**（arXiv 2607.19539, ICPP 2026, 2026-07-21）：4×A100 平台、三个 MoE 模型对比四个 SOTA 系统，端到端最高 2.64x、MoE 层 2.74x 加速；方案=每 rank 持久计算 kernel（producer）+ 专用 SM 分区持久通信 kernel（consumer），免侵入算子/通信原语（https://arxiv.org/abs/2607.19539）
- **CommBench：LLM 生成 GPU 通信代码基准**（arXiv 2608.04450, 2026-08-05）：100+ 专家任务覆盖 P2P/集合通信/专家并行通信/计算通信融合；最强模型 GPT-5.5 仅 30.7% 任务正确且高性能实现——专家并行通信仍是"人写代码"领域，LLM 自动化尚未攻克（https://arxiv.org/abs/2608.04450）

## 内存体系（HBM 容量 vs MoE 权重）

- **Beyond Capacity：高带宽闪存（HBF）直连 GPU 双路径专家交付**（arXiv 2608.14333, 2026-08-14）：MoE 权重增长超过 HBM 容量/成本效益 → HBF 双路由（direct GPU-HBF + relay via HBM base die）并发传输专家权重，权重/KV 分流管理；典型负载吞吐 1.94x、端到端 1.90x 加速——MoE 成为 HBF 存储新架构的首要驱动（https://arxiv.org/abs/2608.14333）（产业面：三星 zHBM/HBF 堆叠已由 hardware 组收录）
- **解码芯片经济学：为 LLM 推理重配计算/容量/带宽**（arXiv 2607.13068, 2026-07-10）：MoE 仅超大规模可部署（96-320 GPU 专家并行集群）；Skymizer HTX-301（28nm PCIe 卡、无 HBM 纯 DDR5）8 卡 $19K 跑 DeepSeek-R1 671B，成本 $12 vs GPU 节点 $21 per M token——稀疏激活+权重驻留瓶颈催生"去 HBM"推理芯片路线（https://arxiv.org/abs/2607.13068）
- **RotaryQuant：消费级硬件跑 120B MoE**（arXiv 2608.08081, 2026-08-08）：三轴压缩——按架构角色分配位宽（dense 4-bit / routed 2-bit / shared expert 8-bit）+ LRU 专家磁盘换出 + IsoQuant KV 压缩（Walsh-Hadamard+SO(4) 旋转，256 参数/头 vs 稠密旋转 16,384）；16GB 跑 26-30B、32GB 跑 Nemotron-H 120B，9-19 tok/s、ΔPPL≤+0.0012（https://arxiv.org/abs/2608.08081）
- **PagedWeight：KV 密集场景动态权重量化**（arXiv 2607.16184, 2026-07-17）：MoE 权重 vs KV cache 显存竞争，运行时动态量化专家权重以平衡精度/内存/吞吐；FP16 等效精度下显存节省最高 72.0%、吞吐 1.94x（https://arxiv.org/abs/2607.16184）
- **WiSP：极低资源 MoE serving 的工作集视角**（arXiv 2606.21868, 2026-06-20）：将路由专家权重与 KV cache 视为两股竞争 VRAM 的存储流；路由感知专家分页最高 1.95x decode 吞吐（同显存预算），在线控制器再 +1.20x；关键结论=单流 decode 瓶颈是 PCIe 带宽而非路由预测精度（https://arxiv.org/abs/2606.21868）

## 并行策略与调度

- **Moebius：运行时无缝切换 TP/EP**（arXiv 2606.26607, 2026-06-25）：TP 低并发快、EP 高并发赢，生产负载频繁跨界；8×H200 上 Qwen3-235B-A22B，单次切换 215-434ms、双布局驻留仅 2.4% 显存开销，RL rollout 各步 1.16-1.25x——MoE serving 的并行度需随负载动态化（https://arxiv.org/abs/2606.26607）
- **ELDR：PD 分离场景专家局部性感知解码路由**（arXiv 2607.00466, 2026-07-02）：decode worker 等负载不等延迟（每步需加载本批激活专家的全部权重）；vLLM 实现、40 GPU 规模，中位 TPOT 降 5.9-13.9%，输出不变（https://arxiv.org/abs/2607.00466）
- **TriRoute：注意力/专家/KV 位宽联合路由**（arXiv 2607.06601, 2026-07-07）：MoE 选专家+MoD 跳层+KV 量化三轴耦合，单控制器逐 token 联合决策；160M-1.3B 解码器模型上 Pareto 支配独立组合方案，识别出跨轴路由坍缩级联（https://arxiv.org/abs/2607.06601）

## 综述与趋势

- **MoE 架构演化综述：路由/拓扑/负载均衡/专家并行**（arXiv 2608.08650, 2026-08-09）：八个架构里程碑按依赖图组织（6 主线+2 正交分支），四大控制平面（Expert Topology/Routing/Balance/Expert Parallelism）连接算法选择与系统关切（token 分发、设备放置、all-to-all 通信、通信计算重叠）；主线趋势=从"激活更多稀疏参数"转向"解耦语义路由、计算预算与物理执行"（https://arxiv.org/abs/2608.08650）
