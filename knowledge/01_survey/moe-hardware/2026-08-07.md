## §15 MoE→硬件影响 — 本期新增10条（2026-08-07）

- **🔴 NVIDIA GB300 NVL72 创 MoE 预训练世界纪录（NVIDIA Tech Blog 2026-07-21, 正文深挖）**: DeepSeek-V3 671B（671B 参数仅激活 ~37B/token）在 256 GPU 上达 **1,648 TFLOPs/GPU**，较 GB200 NVL72 早期软件 606 TFLOPs/GPU 提升 **~3×/单代**。核心架构：第五代 NVLink 每 GPU 1.8 TB/s + 机架内 **130 TB/s 无阻塞 all-to-all**（内存语义、lossless、switch 内归约）。扩展效率：256→1,024 GPU 时 Megatron Core 保持 98.5% per-GPU 性能、TorchTitan/JAX 各 97%。软件增益：同硬件 6 个月 Megatron 1.5×、TorchTitan ~6×、JAX ~10×（达 1,025 TFLOPS/GPU）。**硬件影响 ⭐⭐⭐⭐⭐**：MoE 时代训练瓶颈从算力转向通信——每层每步的 all-to-all 都在关键路径上，scale-up 域内必须全带宽低延迟、scale-out 梯度须隐藏于计算窗口；「delivered FLOPs 而非 peak FLOPs」成为超节点设计判据。来源: https://developer.nvidia.com/blog/setting-a-world-record-for-moe-pre-training-on-nvidia-gb300-nvl72/

- **🔴 Fine-grained Compute-Comm Overlap via Tile-level Signaling（ICPP 2026, arXiv 2607.19539, 2026-07-21）**: MoE 每层两次 all-to-all（dispatch + return），常规实现把 return all-to-all 排在专家计算后→暴露通信延迟于关键路径。本文 producer-consumer 协同：持久化 per-rank 计算内核（producer）覆盖全部本地专家 + 专用 SM 分区上持久化通信内核（consumer）按 tile 就绪粒度发 segment 传输。4×A100、3 个 MoE 模型 vs 4 个 SOTA 系统：端到端 **2.64×**、MoE 层 **2.74×** 加速，且不改算子/通信原语。**硬件影响 ⭐⭐⭐⭐**：通信-计算重叠从「粗粒度并行」走向「SM 级资源分区」——对 GPU 的启示是 SM 可显式分区执行通信，超节点场景可把该模式映射到 NVLink/UALink 的细粒度段传输。来源: https://arxiv.org/abs/2607.19539

- **🟡 PagedWeight: MoE 权重动态量化 vs KV-cache 显存竞争（arXiv 2607.16184, 2026-07-17）**: KV-cache 密集服务场景下 MoE 权重（常驻显存）与 KV cache（随并发增长）直接竞争 GPU 内存。PagedWeight 运行时按质量感知动态量化专家权重、平衡权重精度与 KV 容量：**FP16 等效精度下节省 72.0% GPU 显存、吞吐提升 1.94×**，同显存预算下质量较量化基线提升最多 39.3%（吞吐损失 ≤4.1%）。**硬件影响 ⭐⭐⭐⭐**：量化从「静态压缩」转为「运行时显存分配策略」——权重精度成为与 KV 容量同等的动态资源，对 GPU 显存架构（L2/HBM 分层）与 MoE 服务调度均有新约束。来源: https://arxiv.org/abs/2607.16184

- **🟡 DisagMoE: 解聚 AF-Pipe 重叠 MoE 训练（arXiv 2605.11005, 2026-05-10）**: 专家并行（EP）all-to-all 通信瓶颈被跨节点带宽放大；既有重叠方案受 attention/FFN 层计算-通信比失衡拖累（残留 network-bound stall）。DisagMoE 把 attention 与 FFN 分离到不相交 GPU 组、引入单向多对多通信的多级流水 + 计算-通信 roofline 模型平衡两组带宽分配。Megatron-LM 实现，16 节点 8×H800：训练效率最高 **1.8×**。**硬件影响 ⭐⭐⭐**：模型放置（attention 组 vs FFN 组）成为训练系统级决策——集群拓扑需支持「异构 GPU 分组」而非均匀网格。来源: https://arxiv.org/abs/2605.11005

- **🟡 Scaling Multi-Node MoE Inference Using Expert Activation Patterns（arXiv 2604.23150, 2026-04-25）**: 剖析 Llama 4 Maverick / DeepSeek-V3 671B / Qwen3-230B-A22B，收集 **10 万+ 条真实专家激活轨迹**，揭示三大持久特性：①专家负载不均衡可变；②专家激活具领域特异性（code/math/chat 任务族间 popularity 漂移）；③prefill 与 decode 的专家激活强相关。据此提出 workload-aware micro-batch 分组 + 专家放置最大化 token 局部性：all2all 通信数据量最多降 **20×**，降低 decode 延迟、提升加速器利用率。**硬件影响 ⭐⭐⭐⭐**：专家激活有可预测结构 → 「专家放置 = 拓扑感知」成为超节点/多节点推理的设计输入，scale-up 域应尽量装下高共现专家组。来源: https://arxiv.org/abs/2604.23150

- **🟡 MawForge: 有界显存专家物化（arXiv 2607.09686, 2026-06-17）**: 统一内存受限机器（如 Mac）本地 MoE 推理把全模型存磁盘、常驻公共张量、按需物化路由专家到有界执行缓存。结论：作为**有界执行机制与测量基座有效，但非缓存最大化策略**——性能取决于专家复用×常驻足迹×KV 缓存×量化×路由局部性×内存压力的平衡。**硬件影响 ⭐⭐⭐**：与 WiSP（07-13 归档）同一问题空间（专家权重 vs KV 争显存），侧证「带宽受限设备上稀疏激活买不回总参数量内存成本」的共识。来源: https://arxiv.org/abs/2607.09686

- **🟢 Birkhoff 分解与光互联：别忘了计算（arXiv 2605.26845, 2026-06-23）**: MoE 高度倾斜的通信模式天然适配可重构光交换（circuit-switched），但既有方案孤立优化通信。本文指出 dispatch-compute-combine 结构从根本上挑战 Birkhoff-von Neumann（BvN）调度：MoE 通信矩阵极少双随机 → BvN 引入调度气泡；且分解过多 matchings 把执行切成小批量 → 固定执行开销导致计算效率崩塌。提出贪心 max-weight 分解：限界 matchings 数量同时保持大批量，逼近无拥塞 all-to-all。**硬件影响 ⭐⭐⭐**：光互联的调度器不能只看通信矩阵，必须联合计算批量大小——为 OCS/光交换在 MoE 集群的落地提供调度约束。来源: https://arxiv.org/abs/2605.26845

- **🟢 Models Take Notes at Prefill: KV Cache 可编辑可组合（arXiv 2606.17107, 2026-06-14）**: 跨 4 个模型家族因果验证：prefill 时模型已把「字段条件化结论」写入下游 notes，字段自身 KV 对决策贡献 <1% → KV cache 可当「记忆化结论笔记本」编辑（erratum 追加，8B 模型 ~1% 计算恢复决策）与组合（RoPE 重定位 + 拼接，logit 余弦 0.90-0.999，TTFT 从 O(L²) 降 O(L)）。在线 vLLM 基准：前缀缓存命中 98.5%，p90 TTFT 降 53-398×。**硬件影响 ⭐⭐⭐**：KV 编辑/组合使前缀缓存命中率逼近理论上限——MoE + 前缀缓存的显存压力进一步向「KV 语义复用」方向释放。来源: https://arxiv.org/abs/2606.17107

- **🟢 Grouped Query Experts: GQA 上的 MoE（arXiv 2606.20945, 2026-06-18）**: 在 grouped-query attention（GQA）每组上叠加 MoE 层，router 每 token 选 k 个 query-head 专家，KV head 保持稠密不变 → 保留 GQA 的 KV cache 收益、只削减活跃 query-head 计算。250M 规模 30B token 预算：激活一半 query head 即匹配全激活 GQA 基线下游精度。**硬件影响 ⭐⭐**：注意力侧稀疏化（区别于 FFN 侧 MoE）将把注意力算力需求再打折——对硬件意味着 attention 专用加速单元的利用率假设需重估。来源: https://arxiv.org/abs/2606.20945

- **🟢 Beyond Independent Optimization: 压缩×MoE路由×量化的交互（arXiv 2607.20981, 2026-07-23）**: 多模态边缘智能综述：视觉 token 压缩改变下游特征分布与 MoE 路由决策，路由行为影响专家利用与量化敏感性，量化 router logits 影响专家分配，KV-cache 策略决定多模态证据留存，硬件约束常把计算节省转化为内存/通信瓶颈——**五项优化不可独立进行**。提出 Temporal Routing Consistency 作为视频 MoE 诊断指标。**硬件影响 ⭐⭐⭐**：边缘/端侧 MoE 部署的硬件感知协同设计（routing-aware compression、cross-modal cache 管理）成为开放方向。来源: https://arxiv.org/abs/2607.20981

## 📌 本期小结（2026-08-07）

- **主线一·训练侧**：NVIDIA 官方以 GB300 NVL72 世界纪录（1,648 TFLOPs/GPU）确立「MoE 时代 = 通信决定扩展效率」叙事，scale-up all-to-all（130 TB/s 机架级）与 scale-out 梯度隐藏是超节点硬指标；软件 6 个月 1.5-10× 增益说明「同硬件性能仍在快速爬坡」，对比时须标注软件版本。
- **主线二·服务侧**：MoE 权重与 KV cache 的显存竞争成为新热点（PagedWeight/WiSP/MawForge 三篇同向），动态量化为新杠杆；专家激活的可预测结构（领域特异+prefill/decode 相关）支持「专家放置=拓扑感知」。
