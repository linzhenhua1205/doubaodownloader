## 2️⃣ GitHub Copilot Code Review — Instruction 工程实战：~20% 成本优化 🔧

- **来源**: [GitHub Blog Engineering](https://github.blog/engineering/better-tools-made-copilot-code-review-worse-heres-how-we-actually-improved-it/) · Jul 10, 2026
- **工具**: **GitHub Copilot Code Review**
- **核心发现**: 给 Copilot Code Review 换用更好的共享代码探索工具（grep/glob/view，来自 Copilot CLI 框架）后，**成本反而上升、效果下降**——原因是工具指令（instructions）是为通用编码场景设计的，不适合代码审查的窄聚焦需求。

**解决路径**:

```
"浏览->猜测->读取->扩大搜索"   ->   "基于 diff -> grep 缩小 -> glob 定位 -> view 精确读取"
  通用编码助手的宽探索模式        审查场景的窄聚焦证据链模式
```

**关键改动**：
- 工具指令从通用姿势重写为 **review-shaped**：从 diff 出发，先 grep 缩小范围，再用 glob 定位候选文件，最后用 view 读取精确范围
- 失败恢复策略从"猜测临近路径"改为"简化搜索重试"或"转用 glob"
- **批量独立搜索**（先 grep 批量查，再 view 批量读），避免交替搜索-读取的上下文膨胀

**量化结果**: 上线后 **平均审查成本降低约 20%**，质量无退化信号。

**价值说明**:
这是一篇**极其难得的 Agent Instruction Engineering 实战案例**。它揭示了一个反直觉事实：更好的工具 + 错误的指令 = 更差的结果。对任何构建 AI Agent 的团队，这篇文章提供了三个可复制的方法论：
1. **Tool Instruction 必须与产品任务对齐**——Copilot Code Review 从 coding assistant 的宽探索模式改为 reviewer 的窄聚焦模式
2. **Benchmarks 需要展示工具调用轨迹**——不只看最终分数，要看 agent 的搜索路径、工具调用序列、上下文膨胀量
3. **共享工具层 ≠ 共享指令**——同一个 grep/glob/view，不同产品需不同指令

## 3️⃣ GitHub Agentic Workflows — 跨仓库文档自动化实战 📄

- **来源**: [GitHub Blog](https://github.blog/engineering/automating-cross-repo-documentation-with-github-agentic-workflows/) · Jul 8, 2026
- **工具**: **GitHub Agentic Workflows**（GitHub Next 团队项目）
- **场景**: Microsoft Aspire 团队（10 人）实现**产品代码仓库 → 文档仓库**的全自动文档创建流程

**核心架构**：

```
产品PR merged
    v
pr-docs-check workflow (在 microsoft/aspire 仓库)
    +-- 前置 bash：解析 milestone -> 目标分支
    +-- Agent 阶段：读 diff + 关联 issues -> 判断是否需要文档
        +-- 如果是 -> 在 microsoft/aspire.dev checkout 中起草文档内容
            v 发出 safe-output（JSON 意图）
   safe-outputs handler（狭义、可验证管道）
    +-- 标题前缀：[docs]
    +-- 标签：docs-from-code
    +-- Draft: true（永不自动合并）
    +-- 目标仓库：microsoft/aspire.dev
    +-- Reviewer: 源 PR 的 SME（批准功能的工程师审文档）
```

**关键安全设计**：
- Agent 只有读权限，写操作通过 safe-outputs 管道
- GitHub App Token 限定到恰好两个仓库，无其他 org 资源可访问
- `protected-files: blocked` → Agent 不能碰 AGENTS.md / 安全配置
- Draft PR 永不自动合并

**量化结果**（30 天窗口）：
- 396 个产品 PR merged → **82 个文档 PR 自动创建**（100% merged，0 关闭，0 待处理）
- 中位合并时间：**44.8 小时**（24h 内 38%，7 天 96%）
- **安全零事故**

**价值说明**:
这是一个**跨仓库 Agent 自动化的安全设计典范**。核心模式 `Agent reads → safe-outputs writes` 为解决「AI Agent写权限」这一核心安全矛盾提供了工程模板。同模式还扩展到了 changelog 自动维护、支持策略更新、集成数据刷新等 5 个工作流。对于任何有安全合规约束的团队，这个案例都可以直接参考复制。
