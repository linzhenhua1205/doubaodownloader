## 1️⃣ Cursor Router — 智能模型路由正式上线 🔀

- **来源**: [Cursor Changelog](https://changelog.cursor.com) — Jul 22, 2026
- **工具**: Cursor
- **新功能**: Auto mode 底层替换为 **Cursor Router**，智能模型路由器。分析每次请求的复杂度，自动路由到最合适的模型
- **详情**:
  - **三种优化模式**:
    - `Intelligence`: 前沿模型质量，匹配最贵的模型
    - `Balance`: 强质量，匹配大多数人日常使用的模型
    - `Cost`: 好质量，最高性价比
  - Balance / Intelligence 按路由模型的速率计费
  - **管理员控制**: 可按团队/组启用、限制模式、设置默认、Allow/Block 底层模型
  - 全平台覆盖：Desktop、Web、iOS、CLI、SDK
  - Teams 计划默认开启；Enterprise 管理员可从 Dashboard 启用
  - Grok 4.5 作为价格高效的必选路由选项
- **价值**: Cursor 从"手动选模型"时代进入"自动路由"时代。Intelligence 模式意味着用户日常就能享受到此前因成本只在前沿模型才有的质量，而 Cost 模式大幅降低 token 消耗。对企业来说，Admin 侧可按团队粒度控制路由策略，这是 Copilot 级的企业管控能力
- **影响**: 这对 Copilot 构成直接竞争——Copilot 通过 BYOK 让企业自带模型，Cursor 通过 Router 让企业自动选择最优性价比模型，两条路线分叉

## 2️⃣ GitHub Copilot Canvases — 从对话到交互工作空间 🖼️

- **来源**: [GitHub Blog — "How to build interactive experiences with canvases"](https://github.blog/ai-and-ml/github-copilot/how-to-build-interactive-experiences-with-canvases/) — Jul 21, 2026
- **工具**: GitHub Copilot
- **新功能**: Canvases — 在 Copilot app 中创建共享交互式工作空间，用 `/create-canvas` 命令创建可交互的 UI
- **详情**:
  - Agent 可实时更新 Canvas，用户可点击/编辑/拖拽直接操作
  - 内置能力示例：
    - **Issue Triage Helper**: 卡片式滑动筛选 Issue（右滑 Ship / 左滑 Reject）
    - **Interactive Codebase Diagram**: 动态架构图，拖拽过滤探索
    - **Sessions Worktree View**: 可视化所有活跃 session 和 git worktree，一键清理
    - **Agent Prompt Coach**: 分析历史 prompt，提示改进建议
    - **Knowledge Finder**: 跨 Slack/Teams/Email/Docs 搜索"谁知道这个文件"
  - Canvas 可随工作流持续演化和迭代
- **价值**: 让 AI 从"聊天工具"变成"可视化工作空间"，解决对话式 AI 难以处理复杂关系型任务的痛点。Issue 排期、代码可视化、Prompt 优化都可以在交互界面上完成。这是 Copilot 从代码辅助走向全工作流辅助的关键一步

## 4️⃣ Copilot vs. Raw API — 成本模型深度解析 💰

- **来源**: [GitHub Blog — "Copilot vs. raw API access"](https://github.blog/ai-and-ml/github-copilot/copilot-vs-raw-api-access-what-are-you-actually-paying-for/) — Jul 22, 2026
- **工具**: GitHub Copilot
- **新功能**: GitHub 发布深度成本对比分析，解释 Copilot 和裸 API 调用的实际成本差异
- **核心论点**:
  - Copilot 已按 API 的列表速率计费（AI Credits），但 Copilot 提供的是**模型周围的工作流**（Editor + Repo + Terminal + PR + Policy）
  - GitHub 的评测显示：在 SWE-bench / TerminalBench 等基准中，Copilot CLI 的 **harness 层** 在同样模型下用更少 token 达到任务完成率持平或更高
  - BYOK 在 Public Preview 中：企业可用自有 API 密钥（Anthropic/AWS Bedrock/Google AI Studio/OpenAI/xAI/Ollama），让自家 provider 承担 token 账单，GitHub 仍提供工作流工具
  - 关键结论：**写代码的成本降了，理解、审查、拥有的成本没降**
- **价值**: 这篇文章是 GitHub 对"为什么不直接用 API"这个常见问题的正式回应，对企业 Copilot 采购和工程团队工具选型有直接参考价值。BYOK 模式尤其适合已有大额 provider 合同的企业
