## 1️⃣ Copilot App 独立访问策略上线 🛡️

- **来源**: [GitHub Changelog](https://github.blog/changelog/) — Jul 27, 2026 (Release)
- **工具**: GitHub Copilot App
- **新功能**: Copilot App 现在拥有**独立的访问策略**，不再与 Copilot CLI 策略绑定
- **详情**:
  - 此前 Copilot App 的访问权限依赖于 CLI 策略是否启用。企业无法单独控制 App 与 CLI 的访问
  - 现在两者各有独立策略，提供三个选项：**Enabled everywhere**（全员可用）、**Disabled everywhere**（关闭）、**Let organizations decide**（交组织管理员决定）
  - 默认值为 Enabled everywhere，无需管理员额外操作即可让开发者使用
  - Copilot App 同样加入 CLI 和 VS Code 的行列，成为 enterprise managed settings 的受支持客户端
  - App 内 Agent 会话在隔离工作空间中运行，变更通过 PR 落地，保留审查/检查/审计历史
- **价值**: 对使用 Copilot App 的企业来说，这是合规性的关键补丁——不再「一刀切」地通过 CLI 策略控制所有客户端。IT 管理员可以按团队/场景分别放开或收紧不同客户端。结合 App 已支持的 enterprise managed settings（插件管控、审批提示等），企业 Copilot 治理从「粗粒度」迈入「细粒度、按客户端差异化管控」阶段

## 2️⃣ Enterprise Managed Settings 扩展到 Copilot App 和 Cloud Agent 🔒

- **来源**: [GitHub Changelog](https://github.blog/changelog/) — Jul 27, 2026 (Release)
- **工具**: GitHub Copilot App / Copilot Cloud Agent
- **新功能**: enterprise managed settings（企业托管配置）覆盖范围扩展到 **Copilot App** 和 **Copilot Cloud Agent**
- **详情**:
  - 通过 `managed-settings.json` 统一管控的客户端从 CLI + VS Code 扩展到 App 和 Cloud Agent
  - 可管控项包括：可用插件 / 可安装的插件市场 / 是否可跳过审批提示（运行命令、访问文件、获取 URL 前）/ 新对话默认使用自动模型选择
  - Cloud Agent 仅读取适用的设置（如插件和市场管控），Bypass-prompt 控制不适用于 Cloud Agent（仅在交互式客户端生效）
  - 已有 `managed-settings.json` 的组织无需额外配置——Copilot App 自动在下一次登录或重启时生效，Cloud Agent 在下一个任务分配时生效
  - 首次设置：创建 `.github-private` 仓库 → 添加 `copilot/managed-settings.json` → 提交即生效（约 1 小时内或客户端重启后）
- **价值**: 这标志着 GitHub Copilot **企业治理从「碎片化管控」走向「一处定义、处处执行」**。此前不同客户端（App / CLI / VS Code / Cloud Agent）可能走不同的管控路径，安全短板效应（最弱管控面决定整体安全水位）一直存在。本次更新关闭了这个缺口。对于有严格合规要求的企业（金融/医疗/政府），这是 Copilot 从「开发者工具」走向「企业级平台」的关键一步
