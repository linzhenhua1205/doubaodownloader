## 趋势判断（工具赛道）

1. **Cursor 与 Copilot 路线分野加速："纵向吞基础设施" vs "横向聚合模型"**：Cursor 本周连发 Origin 代码托管 + 订阅机制 + 独立 VM subagents + Builds 环境工程，全部指向把 agent 变成"自主运行的系统"——向上吞噬代码托管/CI/CD 集成位；GitHub Copilot 则走模型聚合（一周 3 外部模型）+ 企业治理（MCP allowlist/ROI 度量）。第一性角度看，Cursor 押注 **agent 运行时的完整性**（环境/事件/编排），Copilot 押注 **模型供给与管控**——2026H2 两种 agent 平台哲学的竞争将决定 IDE 工具链的权力结构。
2. **事件驱动（event-driven）成为 agent 产品化的分水岭**：Cursor 订阅机制（PR/Slack/定时）让 agent 首次"主动醒来"而非"被动响应"，与 GitHub 注释触发自动化（08-03）、Copilot automations 同向——"agent 自主运行"的信任门槛（何时醒来、醒后做什么、如何停止）将是下一轮产品竞争焦点。
3. **环境工程 = agent 性能新杠杆**：Cursor Builds（boot 10x / first-token 3x 提速）把"启动环境成本"显性化为可优化指标，环境快照/缓存/回滚将成为 agent 基础设施标准件——与 Cursor 09-19 的"agent 系统化"叙事（subagents 独立 VM）互为表里。
