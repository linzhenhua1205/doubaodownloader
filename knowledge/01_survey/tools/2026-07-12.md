## 1️⃣ VS Code June 2026 大版本合集 (v1.123–v1.127) 📦

- **来源**: [GitHub Changelog (Jul 8, 2026)](https://github.blog/changelog/2026-07-08-github-copilot-in-visual-studio-code-june-2026-releases/)
- **工具**: VS Code / GitHub Copilot
- **标签**: `vscode` `copilot` `browser-tools` `parallel-sessions` `cost-visibility` `autopilot` `session-sync`

**概览**: VS Code 在 6 月到 7 月初连续发布了 v1.123 → v1.127 总计 5 个版本，围绕 Agent 工作流做了大量体验和基础设施升级。

---

### 🔹 Browser Tools GA — Agent 可在 VS Code 内浏览验证 Web 应用

| 能力 | 说明 |
|:-----|:------|
| **Agentic browser tools** | Agent 可直接在 VS Code 内导航页面、检查内容、截图、验证 Web 应用（默认开启） |
| **浏览体验升级** | 收藏夹、历史记录、网页搜索、摄像头/位置/麦克风权限管理 |
| **页面上下文传递给 Agent** | 支持截图 / 区域截图添加到对话 |
| **远程 workspace 浏览** | 远程 workspace 中 HTTP(S) 流量可通过远程连接代理（公测中） |

> **价值**: 此前 Agent 做 Web 验证需要外部浏览器，现在 VS Code 内置的 browser tools GA 意味着 Agent 可以端到端完成「写代码 → 跑应用 → 验证 UI」闭环，无需手动切出 IDE。

### 🔹 Parallel Sessions + Multi-Chat 并行工作流

| 特性 | 说明 |
|:-----|:------|
| **Run sessions side by side** | 多个独立 Agent 任务并排运行，同时保持可见和活跃 |
| **单 session 多 chat** | 一个大任务拆成多个聚焦的工作流（实现/审查/测试/文档各占一个 chat），整体管理 |
| **Agent session 整理** | Agents Window 支持分组、拖拽排序 |

> **价值**: 之前一个 Agent session 只能跟一个主题，想「并行跑两个不同任务」或「一个大任务拆多步」成本很高。现在支持真正的多 session 并行 + 多 chat 拆分，更接近真实开发者的多任务工作习惯。

### 🔹 Cost Visibility — Agent 成本透明化

| 能力 | 说明 |
|:-----|:------|
| **总 session 成本** | 查看完整 chat 而非单次请求的 credit 用量 |
| **子 Agent 成本** | 查看委派给 subagent 的部分的单独 credit 用量 |
| **额外用量** | 从 GitHub Copilot status dashboard 查阅 |

> **价值**: 对于 Copilot Business/Enterprise 的预算管理场景，之前只能看到总用量不知道哪里花了钱。现在可以精确到「哪个 Agent 任务 / 哪个子 Agent 花了多少」，为预算优化提供数据基础。

### 🔹 Model Marketplace — 一站式模型发现

从 VS Code 内的 Language Models editor 直接发现和安装模型提供商的扩展：
- 从统一位置发现提供商
- 安装 Marketplace 中的模型扩展
- 统一的上下文大小和推理 effort 调整面板

### 🔹 Autopilot 改进

| 改进 | 说明 |
|:-----|:------|
| **任务完成判断** | Agent 更智能地判断请求的工作是否真的完成 |
| **独立推进** | Agent 可以更少人工干预地继续推进步骤 |

### 🔹 其他重要更新

| 功能 | 说明 |
|:-----|:------|
| **Session sync & chronicle** | 将 Chat session 同步到 GitHub 账户，跨机器/跨工作区搜索编码历史 |
| **1M context windows** | 配合 Anthropic/OpenAI 支持大模型使用更大上下文窗口 |
| **Model hover cards** | 鼠标悬停模型名可查看描述并跳转到配置 |
| **Official Ollama 扩展** | 从内置 Ollama 提供商迁移到官方 VS Code 扩展，更快获取模型和能力更新 |

## 2️⃣ Ask Copilot for a Repository Overview — 陌生仓库秒级上手 📖🚀

- **来源**: [GitHub Changelog (Jul 9, 2026)](https://github.blog/changelog/2026-07-09-ask-copilot-for-a-repository-overview/)
- **工具**: GitHub Copilot
- **标签**: `github` `copilot` `repo-overview` `readme` `onboarding`

**核心内容**: 在 github.com 访问一个从未贡献过的仓库时，Copilot **主动提供**高层面概述——生成仓库**用途**、**使用的技术栈**、**贡献指南**的摘要。如果仓库没有 README，Copilot 可以自动生成一份。

| 能力 | 说明 |
|:-----|:------|
| **触发方式** | 访问陌生仓库首页 → Copilot 提示 "Give me a high-level overview" |
| **输出内容** | 仓库目的、技术栈、贡献指南摘要 |
| **无 README 兜底** | 自动生成 README 帮助快速了解仓库 |
| **手动访问** | 随时可通过 github.com 导航栏的 Copilot 图标或 Copilot Chat 的 "generate a repository overview" 触发 |
| **可用计划** | 所有 Copilot 计划 |

> **价值**: 对于一天要接触多个新仓库的开发者来说，每次手动翻 README（如果有的话）、看 package.json、扫 issue 标签来理解仓库是高频低效操作。这个功能把「快速了解一个仓库」的认知成本降到一次点击。特别是第一次为开源项目做贡献时，能立即知道「这个项目是干什么的、用什么技术、怎么贡献」。
>
> 注意：此功能和 Copilot 之前已有的 `@workspace` 了解 workspace 的知识不同——它专注于 **github.com 上的陌生仓库**，不需要 clone 到本地就可获取概述。

## 3️⃣ Codex 作为 Agent Provider + JetBrains IDE 增强 🧩🔧

- **来源**: [GitHub Changelog (Jul 7, 2026)](https://github.blog/changelog/2026-07-07-improvement-codex-as-agent-provider-and-agentic-enhancements-in-jetbrains-ides/)
- **工具**: GitHub Copilot / JetBrains
- **标签**: `github` `copilot` `codex` `jetbrains` `agentic`

| 改进 | 说明 |
|:-----|:------|
| **Codex as agent provider** | Codex 现在可以作为 Copilot 的 Agent provider 使用，让 Codex 的代码生成能力在 Agent 工作流中发挥作用 |
| **JetBrains IDE 增强** | Agentic 能力进入 JetBrains IDE 生态，包含 agentic 编程增强 |

> **价值**: 此前 JetBrains IDE 的 Copilot 体验以补全和 Chat 为主，Agent 能力（自主探索、修改代码）主要在 VS Code 和独立 App 上。这次更新标志着 Copilot 的 Agent 能力正式向 JetBrains 生态扩展，覆盖 IDEA、PyCharm、WebStorm 等用户。

### 🔹 GitHub Mobile Copilot 功能增强

| 能力 | 说明 |
|:-----|:------|
| **Fix merge conflicts with Copilot cloud agent** | 手机端直接在 PR 上让 Copilot Cloud Agent 解决合并冲突 |
