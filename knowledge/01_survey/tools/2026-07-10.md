## 1️⃣ Cursor v3.7→v3.10 全景：从 Cloud Subagents 到 iOS App 的 Agent 生态扩张 🚀📱

- **来源**: [Cursor Changelog](https://www.cursor.com/changelog)
- **工具**: Cursor
- **标签**: `cursor` `ai-ide` `cloud-agent` `mobile` `automation` `mcp` `team`

**概览**: 6 月 17 日至 6 月 30 日，Cursor 连续发布了 v3.7→v3.10 四个版本，完成了从本地 IDE 到 **Cloud + Mobile + Team 三位一体 Agent 平台**的进化。此前记录仅在 7/01 简单提及 iOS App，本文做全景盘点。

### v3.7 (Jun 17) — Cloud Environment Setup + Cloud Subagents ☁️

| 新功能 | 核心能力 | 价值 |
|:-------|:---------|:-----|
| **Cloud Environment Setup** | Cursor 帮你在 <10 分钟内完成云端开发环境搭建，环境捕获为可复用快照 `.cursor/environment.json` | 新成员/新项目秒级启动环境，团队共享快照，云端 Agent 可热启动 |
| **`/in-cloud` Cloud Subagent** | 在独立 VM + 独立分支上启动子 Agent，不影响本地环境 | 并行执行长任务（修 CI、排查 Issue、探索代码），本地继续工作 |
| **`/babysit` PR 保姆** | Cloud Subagent 在云端迭代准备 PR 合并，不占用本地 session | PR 审核流程自动化，Agent 自循环直到合并条件满足 |
| **Local↔Cloud Handoff** | Agent session 在本地与云端之间可靠迁移 | 本地→云端→本地完整闭环，测试验证不断链 |

> **意义**: v3.7 奠定了 Cursor 的 Cloud Agent 基础设施。过去 Agent 跑在本地，占用资源且无法持续运行；现在 Agent 可在云端独立 VM 中长期运行（"long time horizons until outputs are verified"），开发者只需关注结果验收。

### v3.8 (Jun 18) — Cursor Automations 重大升级 ⚡

| 新功能 | 核心能力 | 价值 |
|:-------|:---------|:-----|
| **`/automate` 技能** | 直接在 Agent session 中用自然语言描述要自动化的任务，Cursor 自动配置 triggers + instructions + tools | 创建自动化从「写配置」变成「说需求」，零门槛 |
| **GitHub 5 种新触发器** | Issue comment / PR review comment / PR review submitted / Review thread updated / Workflow run completed | 覆盖 PR 全生命周期：提交→评论→审核→合并→CI 完成 |
| **Slack Emoji 触发器** | Slack 中 emoji 反应即可触发的自动化 | 从聊天工具直通开发工作流，无需切换上下文 |
| **Computer Use 工具** | Cloud Agent 可用自己的虚拟机操作桌面（截图、演示、生成产物） | Agent 可以自动产生可视化 demo/artifact，不只是写代码 |
| **自动开 PR** | Automations 默认可自动创建 PR | 流水线完全自动化 |

> **意义**: Cursor Automations 从「定时触发器」进化到**事件驱动的全自动工作流**。GitHub 事件 + Slack Emoji 覆盖了开发者和运维人员最常用的两个交互入口。Computer Use 则让 Agent 从「只能写代码」进化为「可以像人一样操作电脑做演示」。

                |
    +-----------+-----------+
    v           v           v

| 维度 | v3.6 | v3.10 |
|:-----|:-----|:------|

## 2️⃣ GitHub Agentic Workflows 自动化跨仓库文档生成 📄🤖

- **来源**: [GitHub Blog Engineering (Jul 08, 2026)](https://github.blog/engineering/automating-cross-repo-documentation-with-github-agentic-workflows/)
- **工具**: GitHub Agentic Workflows / Copilot Agent
- **标签**: `github` `agentic-workflows` `documentation` `automation` `cross-repo`

**核心内容**: GitHub Aspire 团队分享了如何用 **GitHub Agentic Workflows** 实现跨仓库文档自动生成：产品变更合并后，Agent 自动分析 diff、生成文档草稿、提交 SME 审核的 PR，解决了「发布与文档同步」这个经典问题。

### 🔹 问题背景

| 问题 | 描述 |
|:-----|:------|
| **文档滞后** | 功能上线后文档通常滞后数天到数周 |
| **跨仓库同步难** | 代码在 `aspire` 仓库，文档在 `docs` 仓库，手动同步耗时 |
| **SME 瓶颈** | 技术审核人需要在繁忙的开发节奏中手动写文档 |
| **上下文丢失** | 开发者写完代码时最清楚变更含义，但写文档的动力最低 |

### 🔹 方案：Agentic Workflows 自动文档流水线

```
代码 PR 合并到 main
       |
       v
触发 Agentic Workflow
       |
       v
Agent 读取合并后的 diff + 相关 issue/PR 描述
       |
       v
Agent 分析变更影响范围（API 变更？配置变更？行为变更？）
       |
       v
Agent 搜索 docs 仓库中需要更新的页面
       |
       v
Agent 生成文档草案 PR（带 diff 引用 + 变更说明）
       |
       v
自动分配 SME Reviewer -> 审核 -> 合并
```

### 🔹 关键技术点

| 维度 | 实现方式 |
|:-----|:---------|
| **触发方式** | Agentic Workflow 监听特定路径/标签的 PR merge 事件 |
| **文档定位** | Agent 通过语义搜索在 docs 仓库中找到需要更新的页面 |
| **生成质量** | Agent 引用代码 diff 中的具体行号作为证据，减少幻觉 |
| **审核流程** | 自动分配职责匹配的 SME，PR 描述包含变更上下文 |
| **跨仓库** | Workflow 配置了跨仓库权限——代码仓触发，文档仓提 PR |

### 🔹 价值分析

| 维度 | 说明 |
|:-----|:------|
| **解决「文档滞后」** | 代码合并 → 文档 PR 自动创建，间隔从「天/周」缩至「分钟」|
| **降低 SME 负担** | Agent 写初稿，SME 只做审核而非从零撰写，工作量从「写」变成「改」|
| **上下文保鲜** | 代码合并时上下文最新，Agent 自动捕获，不会因时间推移遗忘细节 |
| **复用性** | 流水线模式可扩展到 API 文档、Release Notes、迁移指南等 |

> **价值**: 这是 GitHub Agentic Workflows（6 月 11 日 Public Preview）目前最有说服力的落地案例之一。它巧妙地将 Agent 定位为「初稿者」而非「决策者」——Agent 写、SME 审，既保证效率又守住质量。对于有跨仓库文档需求的大中型团队，可直接复现此模式。
