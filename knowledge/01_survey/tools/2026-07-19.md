## 1️⃣ Repository-level GitHub Copilot Usage Metrics GA — 仓库级 Copilot 使用指标全面上线 📊

| 来源 | GitHub Changelog |
|:-----|:-----------------|
| 日期 | 2026-07-17 |
| 标签 | `copilot` · `account management` · `enterprise management tools` |
| 链接 | [Repository-level GitHub Copilot usage metrics generally available](https://github.blog/changelog/) |

### 新功能

Copilot 使用指标从 **组织/团队级下钻到仓库级**（GA，此前为 beta/limited），可通过 API 按仓库粒度查询：
- Copilot 采纳率（acceptance rate）按仓库统计
- AI 代码生成行数、活跃用户数按仓库区分
- 配合 Jul 2 的 metrics 准确度提升 + Jul 7 的 review cycles/time-to-adoption 阶段数据，形成完整的使用分析栈

### 价值说明

**对服务器/AI 基础设施团队的直接影响**：
- 此前 Copilot 费用按人头算，但往往整个 org buy-in，无法区分哪些仓库/repo 真正产生价值
- 仓库级指标让 **ROI 核算精细化**：可以对比 infra 仓库（告警/配置生成）vs 产品仓库 vs 测试仓库的 Copilot 采纳差异
- 配合 Jul 7 的 **per-user budgets + AI credit pools**（均 GA），管理层可做：repo A 超预算 → 排查 → 是否降低 seat 级别
- 核心启示：**AI 编程工具的计量核算进入成熟期**，从"要不要买"进入"怎么优化使用分布"阶段

## 2️⃣ Advanced Search for Projects GA — GitHub Projects 终于有高级搜索了 🔍

| 来源 | GitHub Changelog |
|:-----|:-----------------|
| 日期 | 2026-07-16 |
| 标签 | `projects & issues` |
| 链接 | [Advanced search for Projects is generally available](https://github.blog/changelog/) |

### 新功能

GitHub Projects（项目管理看板）正式支持高级搜索，包括：
- **嵌套查询**（nested queries）— 多条件组合筛选
- **布尔运算符**（boolean operators）— AND/OR/NOT
- **按自定义字段**过滤、排序

此功能是 May 2025 针对 Issues 搜索的重建工作（nested queries + boolean operators）在 Projects 维度的落地。

### 价值说明

- Projects 之前缺少高级搜索一直是个核心短板 — 卡片一多几乎不可用
- 对于管理 **多项目、多团队的架构/研发 Leader**：可以快速定位"所有 blocked 状态的、优先级 P0 的、负责人为空的卡片"，替代人工翻阅
- 与 Jul 16 的 **PR 归档能力**（Repository admins can archive PRs）形成配套 — 高级搜索找到完事的 PR → 批量归档，形成生命周期管理闭环

## 3️⃣ Dependabot Version Updates 引入 Default Package Cooldown — 减少更新噪声 🧹

| 来源 | GitHub Changelog |
|:-----|:-----------------|
| 日期 | 2026-07-14 |
| 标签 | `supply chain security` |
| 链接 | [Dependabot version updates introduce default package cooldown](https://github.blog/changelog/) |

### 新功能

Dependabot 引入默认的 **package cooldown（冷却期）** 机制：
- 同一个 package 的版本更新在一定时间间隔内不再重复创建 PR
- 避免"某个库一天发三次 patch → Dependabot 开三个 PR → CI 跑三轮"的低效循环
- 冷却期长度由 Dependabot 根据更新频率/类型自动判断

### 价值说明

- Dependabot **噪声问题** 长期被抱怨：一个不重要的依赖一天多个 PR，分散团队注意力
- 冷却期是 GitHub 对**更新疲劳**（alert fatigue）的针对性回应
- 与 Jul 15 的 Secret Scanning 改进（public monitoring 增强）配合，说明 GitHub 在 Supply Chain Security 侧正从"全量提醒"转向"智能聚合"模式
- 对服务器团队：依赖多（BMC SDK/firmware toolchain/协议库），冷却期可减少 CI 资源浪费
