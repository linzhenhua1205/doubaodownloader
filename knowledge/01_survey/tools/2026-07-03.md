## 1️⃣ Copilot CLI 免除 PAT——CI/CD 中的零配置 Agent 编排 🚫🔑

- **来源**: [GitHub Changelog (Jul 02, 2026)](https://github.blog/changelog/)
- **工具**: GitHub Copilot CLI
- **标签**: `github` `copilot` `cli` `actions` `ci-cd` `pat`

**核心内容**: Copilot CLI 在 GitHub Actions 中运行时，**不再需要配置 Personal Access Token（PAT）**，自动通过 OIDC 身份验证完成授权。

### 🔹 能力

- Copilot CLI 在 Actions workflow 中运行时，**自动继承 runner 的 GitHub App 身份**，无需手动管理 PAT
- 之前需要额外步骤：`gh auth login` + `GITHUB_TOKEN` + Copilot Token 三步配置 → 现在直接调用

### 🔹 价值分析

| 维度 | 说明 |
|:-----|:------|
| **DX 质变** | 此前要在 CI 中用 Copilot CLI 做 Agent 编排，需手动配置 PAT（容易泄露、过期、Scope 不匹配）。现在零配置，`copilot` 命令直接在 Actions 中可用 |
| **安全提升** | PAT 是长期凭证，泄露风险高。OIDC 是临时令牌，自动续签、自动过期 |
| **Agentic Workflows 拼图** | 6 月 11 日 GitHub 发布了 Agentic Workflows Public Preview，但当时需要 PAT。现在 Token 问题解决，Agentic Workflows + Copilot CLI 的组合在 CI 中可以真正零配置跑通 |
| **门槛归零** | 任何一个 CI pipeline 现在都可以加一行 `copilot` 命令做代码审查、自动修复、PR 分析，不再需要额外的认证配置 |

> **意义**: 这是 Copilot CLI 从「桌面工具」走向「CI 原生工具」的关键一步。OIDC 自动授权意味着 Copilot CLI 可以成为 Actions pipeline 中的一等公民，像 `actions/checkout` 一样开箱即用。

## 2️⃣ Copilot Agent Session Streaming — Public Preview 📡

- **来源**: [GitHub Changelog (Jul 02, 2026)](https://github.blog/changelog/)
- **工具**: GitHub Copilot Agent
- **标签**: `github` `copilot` `agent` `streaming` `preview` `real-time`

**核心内容**: Copilot Agent 的**会话流式输出**功能进入 Public Preview，Agent 的思考过程、代码生成、调试循环可实时流式展示。

### 🔹 能力

- Agent 不再是一次性「生成→展示」的批处理模式，而是**边思考边输出**（类似 Cursor Agent 的实时流式效果）
- 开发者可以**实时看到 Agent 的每一步操作**——分析代码、搜索文件、生成代码、运行命令、查看输出
- 对长时间运行的 Agent 任务，可以**中途干预**，提前纠正方向

### 🔹 战略定位

| 对比 | 传统模式 | Streaming 模式 |
|:-----|:---------|:---------------|
| 用户感受 | 提交 Prompt → 等待 → 看到结果（黑盒） | 提交 Prompt → 观察 Agent 每一步（透明） |
| 调试效率 | 等全部完成再看成品，偏差难以干预 | **边看边纠偏**，减少无效 Agent 循环 |
| 信任建立 | 不信任 Agent 做的事，总是要审查 | Agent 过程透明，更容易建立信任 |
| 教育价值 | 低（看不到过程） | 高（能看到 Agent 如何推理和决策） |

### 🔹 与 Copilot Chat Agent Session 联动

注意 6 月 10 日的更新：「Copilot Chat now sees your agent sessions」——当时的 Agent Session 信息是**事后查看**。现在 Session Streaming 是**实时查看**。

| 日期 | 更新 | 阶段 |
|:----:|:-----|:----:|
| Jun 10 | Copilot Chat 可见 Agent Session 历史 | 事后查看 |
| **Jul 02** | **Agent Session Streaming Public Preview** | **实时查看 + 干预** |

> **意义**: Streaming 模式是 Agent 从「工具」进化到「协作者」的必经之路。Cursor Agent 的核心体验之一就是实时流式输出带来的**透明感和可控感**。Copilot 现在补齐了这个体验短板。对于 Agent 开发者来说，这意味着可以边观察边调整 Prompt，大幅减少无效 Agent 调用。

## 3️⃣ AI Credit Pools + Enterprise Auto Model Selection — Enterprise 治理双响炮 💰🎯

- **来源**: [GitHub Changelog (Jul 02 & Jul 01, 2026)](https://github.blog/changelog/)
- **工具**: GitHub Copilot Enterprise
- **标签**: `github` `copilot` `enterprise` `cost-center` `credit-pool` `auto-model`

**核心内容**: 两个 Enterprise 治理能力更新：(1) Cost Center 新增 **AI Credit Pools** 将 Credits 按池子分配；(2) 管理员可**默认启用 Auto Model Selection**。

### 🔹 AI Credit Pools — 从「个人预算」到「团队池子」

| 治理层级 | 能力 | 上线时间 |
|:---------|:-----|:--------:|
| Cost Center 创建（上限 500 个） | 组织级成本中心划分 | Jun 10 |
| Budget & Usage APIs GA | 预算和用量 API | Jun 04 |
| Cost Centers + Enterprise Teams | 与组织架构对齐 | Jun 25 |
| Per-user AI Credit Budgets | 用户级 AI Credits 预算上限 | Jun 30 |
| **AI Credit Pools** | **将 AI Credits 分配到池子，团队共享** | **Jul 02** |

**Credit Pools 的核心价值**：
- 将 Credits 按团队/项目维度**打包分配**，团队内成员共享池子
- 避免「有人用不完、有人不够用」的分配不均
- 结合 Per-user Budget 实现「池子总额度 + 个人上限」的双层管控

### 🔹 Enterprise Auto Model Selection 默认值

- 管理员现在可在 Enterprise 层面设置**默认启用 Auto Model Selection**
- Auto Model Selection（6 月 4 日上线）根据任务复杂度自动选择最优模型（简单任务用快速便宜模型，复杂任务用强大模型）
- 过去每个用户需要手动开启，现在**管理员可以一键推到整个组织**
- 配合 Jul 01 的「Copilot CLI auto model selection routes based on task」，覆盖了 IDE + CLI 双场景

### 🔹 Enterprise 治理能力全景（截至 7 月 2 日）

| 领域 | 能力 | 状态 |
|:-----|:-----|:----:|
| **成本管控** | Cost Centers（500 个）+ Per-user Budget + AI Credit Pools | ✅ 完整 |
| **模型管理** | Auto Model Selection 默认值 + BYOK + Evaluation Models | ✅ 完整 |
| **用量可视** | Budget APIs + AI Usage Report + Per-user Metrics API | ✅ 完整 |
| **安全管理** | Enterprise managed-settings.json GA | ✅ Jul 01 |
| **合规** | Open Source License Compliance Preview | ✅ Jun 30 |

> **意义**: GitHub Copilot Enterprise 的管理能力在 6 月~7 月初快速成熟。从「谁都能用」到「谁能用多少、用什么模型、花多少预算」，治理工具链基本完整。Credit Pools 解决的是**大规模推广的最后一块石头**——企业 CFO 不担心成本失控了。
