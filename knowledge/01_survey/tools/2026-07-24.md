## 3️⃣ Dependabot 引入默认 3 天冷却期 — 供应链安全护盾 🛡️

- **来源**: [GitHub Blog](https://github.blog/security/supply-chain-security/the-case-for-a-cooldown-why-dependabot-now-waits-before-issuing-version-updates/) — Jul 23, 2026
- **工具**: Dependabot
- **新功能**: Dependabot version updates 默认等待 3 天才打开 PR
- **详情**:
  - 此前 (Jul 14) 已在 Changelog 中作为 Improvement 上线，Jul 23 以博客文章形式详细解释设计思路
  - 动机：供应链攻击常通过发布恶意新版本来实施，几小时内即被拉取（案例：npm chalk/debug 被投毒，2 小时内传播到 2B 周下载量的应用）
  - 过去一年 GitHub Advisory Database 发布了 **6,500+ 个 npm 恶意包**（约 18 个/天）
  - 三天的冷却期让社区/扫描器有时间发现恶意版本，在它进入你的 PR 前被撤下
  - **仅作用在 version updates（非安全更新）**，安全更新仍然即时响应
  - 可通过 `dependabot.yml` 的 `cooldown` 参数自定义
  - 案例研究：axios、Solana web3.js、ua-parser-js 等被投毒版本均在数小时内被发现并移除，3 天冷却期足以过滤绝大多数此类攻击
- **价值**: 对研发团队来说——Dependabot 默认开箱即用的供应链安全加固，不需要任何配置变更。对持续集成流程来说——依赖更新延迟 3 天，降低了"自动更新引入恶意代码"的风险，也减少了因紧急版本回退导致的 CI 中断
