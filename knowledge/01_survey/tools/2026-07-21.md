## 1️⃣ GitHub Code Quality 正式 GA 🎯

**来源**: [GitHub Changelog — Jul 20, 2026](https://github.blog/changelog/)
**工具**: GitHub Code Quality
**类型**: 代码分析工具 / 平台更新

### 新功能
GitHub Code Quality 正式从 public preview 转 GA。这是 GitHub 在代码分析领域的第二个支柱产品（与 Code Scanning/Secret Scanning 并列）：
- **定位**：专注于代码质量/风格/一致性，而非安全性
- 与 Code Scanning（安全）形成互补：Quality → 可读性/可维护性，Security → 漏洞/风险
- **License estimate** 已于 Jul 13 进入 public preview，可预估 License 用量

### 价值说明
- ⚡ **代码质量左移**: 在 PR 阶段即检测代码风格、模式一致性和可维护性问题，减少 code review 中"这写得不太好"的主观讨论
- 🔗 **平台闭环**: 质量分析结果不脱离 GitHub 工作流，直接在 PR Checks 和对话框体现
- 💰 **License 预估**: 在购买前即可预估用量和成本，降低采购风险

> **与你的关联**: 你团队使用 GitHub 作为代码托管平台，Code Quality GA 意味着可以在不引入 SonarQube/Codacy 等第三方工具的前提下完成代码质量门禁，减少工具链维护成本。

## 2️⃣ Copilot 账单 & 治理升级 — AI Credit Pools + 每周期用量可见 💰

**来源**: [GitHub Changelog — Jul 20, 2026](https://github.blog/changelog/)
**工具**: GitHub Copilot
**类型**: AI 编程工具 / 成本治理

### 新功能
两条关联更新（同日发布）：
1. **AI credit pools for cost centers in the billing UI** — 成本中心级 AI credit 池，支持在组织内按业务线/部门分配和跟踪 AI 使用配额
2. **Copilot users can now see AI credits used per billing cycle** — 每个 Copilot 用户可查看自己在本账单周期内的 AI credit 消耗量

### 价值说明
- 🏢 **组织级治理**: AI 编程工具从"全员按头付费"走向"按业务单元分配和核算"，中大型组织可精细化管控 AI 工具成本
- 👤 **用户透明**: 开发者能看到自己的 credit 消耗，减少"不知道用了多少"带来的消费焦虑
- 🔗 **叠加 repo 级用量指标（Jul 17 GA）**: 形成了从"全局 → 仓库级 → 用户级 → 成本中心"的完整计量体系

> **与你的关联**: 如果团队正在推广或管控 AI 编程工具的 ROI，这套计量体系可以让你回答"哪个 repo/部门/人在消耗最多的 AI credit？"而不靠猜测。

## 3️⃣ Repository Admins 可以归档 Pull Requests 📦

**来源**: [GitHub Changelog — Jul 16, 2026](https://github.blog/changelog/)
**工具**: GitHub
**类型**: 协作工具 / PR 生命周期管理

### 新功能
仓库管理员现可归档 Pull Request。归档后的 PR 状态变为只读，不再出现在默认的 Open/Closed 列表中（需在 Filter 中选择 "Archived" 查看）。

### 价值说明
- ♻️ **PR 生命周期完整化**: Open → Merged/Closed → Archived，形成完整的生命周期管理链
- 🧹 **减少 PR 列表噪音**: 大量 stale PR、experimental PR、abandoned PR 可以从工作视图中隐藏，但不会丢失（历史记录可查）
- 🚀 **对比 Close/Discard**: Close 意味着"已合并或明确不合并"，Archive 更适合"暂时不处理但不想删除"的场景

> **与你的关联**: 对团队做大规模技术重构或 baseline 升级时，往往会产生大量 intermediate PR。Archive 机制可以让主 PR 列表保持干净，而不必因为"删不掉"而忍受信息过载。
