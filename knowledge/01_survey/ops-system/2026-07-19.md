## 3️⃣ 🔴 SRE 4-Body Problem — AIOps 的认知基础设施

**来源**: [CNCF Blog Jul 6 | The 4-body problem of SRE](https://www.cncf.io/blog/2026/07/06/the-4-body-problem-of-sre-why-autonomous-operations-depend-on-context/) · StackGen Field CTO Sanjeev Sharma
**状态**: 关键框架性文章

### 四个耦合的运维真理体系

```
                +---------------------+
                |    🖊️ Code          |
                |  (Git/PR/发布)       |
                +---------+-----------+
                           |
          +----------------+----------------+
          |                |                |
+---------v------+  +-----v-------+  +-----v---------+
|  🏗️ Infra State |  | 📊 Runtime  |  | 🧠 Operational |
| (Terraform/K8s) |  | (OTel/Pro) |  | Knowledge     |
+----------------+  +-------------+  +-------+-------+
                                               |
                                     +---------v---------+
                                     | 🤖 AI Agent 决策  |
                                     | (统一知识图谱)     |
                                     +-------------------+
```

### 关键洞见
- **单一体"已解决"**（Git/Terraform/OTel/Confluence），但**四体交汇处从未有系统**能处理
- **"People putty"问题**：部落知识藏在 3 个工程师脑中 → 每 2 年流失 → 被 runbooks 和 AI 填补但不可靠
- **信任 = 可审计决策轨迹**：Agent 必须记录输入快照 + 生效策略 + 模型版本 + 假设 + 行动 + 结果
- **施政路径**: 先建知识图谱 → 再插 Agents，顺序不可逆

### 对 AI 集群运维的意义
- Code: GPU 驱动/NCCL 版本/模型权重
- Infra: GPU 拓扑/NVLink/网络拓扑/供电
- Runtime: NCCL 通信延迟/E2E 训练吞吐
- Knowledge: 故障恢复 runbook/已知不兼容组合

## 4️⃣ 🟡 Platform Engineering 2.0 的运维视角

**来源**: [CNCF Blog Jul 6 | Evolving platform engineering for AI-native workloads](https://www.cncf.io/blog/2026/07/06/evolving-platform-engineering-for-ai-native-workloads/) · VMware/Broadcom

### 与运维直接相关的三个支柱

**Embedded FinOps**
- 预部署成本门禁：GPU 成本在调度时可见 → 避免推理 GPU 浪费
- 实时成本归因：每个 Pod/Namespace 的实际 GPU 开销
- **容器运维的 FinOps 信号**: GPU 利用率需进入成本核算基线

**Security Shifts Down**
- Shadow AI 治理：检测未经授权的模型部署/推理 API
- 模型投毒/提示注入防护：CI/CD 流水线+运行时双层检测
- **运维需增设**: AI 安全基线扫描（模型 registry 审计、推理日志监控）

**AI Agent 作为平台消费者**
- Agent 需自己的访问凭据/作用域/配额 → 与用户同一治理层级
- Agent 产生的运维事件需关联到 Agent Identity，而非随机 ServiceAccount
- **CISO 关切**: 可审计的 Agent 决策轨迹（与 SRE 4-Body Problem 呼应）

## 5️⃣ 🟡 SUSE seunshare 3.10 → 3.11 修复详情

**来源**: [LWN Jul 15 | SUSE Security Team Blog](https://lwn.net/Articles/987293/)
**状态**: 已在 07-18 提及，本报告补充技术细节

### 漏洞分解
| 类型 | 影响 | 触发条件 | 修复 |
|:-----|:-----|:---------|:-----|
| 本地 DoS | 系统拒绝服务 | setuid-root 任意参数 | v3.11 |
| SELinux 提权 | unconfined → root 级 | 目标策略默认用户域未约束 seunshare_t | v3.11 |

> **警示**: "SELinux enforced mode 下依然可实现 root 级提权" — 默认 target 策略对交互用户不做域隔离
