### 1. BPF LSM 防篡改：Christian Brauner 指出当前架构局限性

> 📄 LWN.net, Jul 17 · daroc | 2026 Linux Storage, Filesystem, Memory-Management, and BPF Summit

**背景**：自 2020 年起 BPF 程序可作为 LSM（Linux Security Module）运行。systemd 等项目正在利用此能力增强安全。

**Christian Brauner 提出的核心问题**：

| 问题 | 说明 | 影响 |
|:-----|:------|:------|
| **BPF 程序删除风险** | BPF LSM 程序可以被 `bpf()` syscall 删除 | 攻击者可禁用安全保护 |
| **私有数据篡改** | BPF map（私有数据）无防篡改保护 | 策略可被绕过 |
| **系统级依赖** | systemd 依赖 BPF LSM 实现运行时安全策略 | 如果 BPF 程序可被移除，整个安全模型崩溃 |

**待推进方向**：
- 需要内核机制防止已加载的 BPF LSM 程序被移除（类似 pinned 但更强）
- BPF map 需要写保护 + 只允许特定程序访问
- 讨论后续在 Linux Plumbers Conference 继续

**运维关联**：
- AI 集群使用 systemd + BPF LSM 作为安全基石的方案 → 需关注此问题的内核补丁进度
- 当前工作区：可临时用 `bpf()` pinning + 监控告警检测 BPF 程序异常删除

### 2. 大量旧版 Shim 仍未撤销 — Secure Boot 防线存在系统性风险

> 📄 LWN.net, Jul 15 · corbet | CMU CERT 协调中心公告

**漏洞描述**：
- 许多可被利用的旧版 **shim** 引导加载程序版本从未被加入吊销列表
- 攻击者（有管理员权限或可修改启动流程）可利用这些 shim 绕过 Secure Boot
- 在操作系统加载前执行任意代码 → 可能获得持久化低级别控制权

**影响范围**：

| 维度 | 详情 |
|:-----|:------|
| 受影响组件 | shim（UEFI Secure Boot 的 Linux 引导加载程序） |
| 攻击前提 | 已获得管理员权限或可物理/远程修改启动流程 |
| 后果 | 绕过 Secure Boot → 加载未签名内核模块 → 持久化后门 |
| 修复状态 | 公告列出可用的受损 shim 列表，需要在 BIOS/UEFI 层面吊销 |

**运维建议**：
- 检查数据中心服务器 shim 版本是否在受影响列表中
- 配合硬件厂商更新 UEFI Secure Boot 吊销数据库（DBX）
- 对 AI 集群（通常有严格启动安全策略）应列为 P1 优先级

### 3. seunshare 本地 DoS + SELinux 权限提升 — 3.10 版本漏洞

> 📄 LWN.net, Jul 15 · jzb | SUSE Security Team Blog

**seunshare** 漏洞详情（版本 3.10，修复于 3.11）：

| 漏洞 | 类型 | 影响 |
|:-----|:-----|:------|
| **DoS 向量 1** | 本地拒绝服务 | 利用 seunshare setuid-root 特性使系统崩溃 |
| **DoS 向量 2 + SELinux 提权** | 权限提升 | 在 SELinux targeted 策略下，交互式用户运行在 unconfined 域 → 提权至 root 级别 |

**关键问题**：SELinux targeted 策略默认对交互式用户使用 unconfined 域，seunshare 执行时无域转换 → seunshare_t 未生效 → setuid-root 漏洞直接导致 root 权限提升

**修复**：升级至 seunshare 3.11+
