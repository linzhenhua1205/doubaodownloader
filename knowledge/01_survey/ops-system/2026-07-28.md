## 🔴 高价值条目

### 1. 集群联邦实现零停机 — 多区域运维最佳实践
- **来源**: [Federating clusters for zero-downtime Kubernetes](https://www.cncf.io/blog/2026/07/27/federating-clusters-for-zero-downtime-kubernetes/) — Linkerd 贡献者 Dominik Táskai
- **运维痛点**: 多区域 K8s 集群的「影子副本」问题——一个集群挂掉后，另一区域的副本无法自动接管流量
- **解决方案**: Linkerd Service Mirroring + 跨集群联邦
  - 跨集群服务发现：每个集群的服务自动同步到联邦中
  - 区域故障自动摘除：故障集群的服务从 DNS/负载均衡中自动移除
  - 灰度发布跨集群：新版本先部署到一个集群验证后再全量上线
- **运维影响**:
  - 需要配置联邦控制面之间的 TLS 认证（mTLS）
  - 跨集群网络延迟对联邦同步的时效性有约束（推荐同 Region 多 AZ 或低延迟跨 Region）
  - 联邦的故障域隔离需要与 CI/CD 管道协同设计

### 2. Confidential Containers Incubating — 安全运维新维度
- **来源**: [CNCF Blog](https://www.cncf.io/blog/2026/07/22/confidential-containers-becomes-a-cncf-incubating-project/) (Jul 22)
- **运维影响**:
  - **TEE 运维复杂度**: 需要管理 TEE 硬件验证（Intel TDX/AMD SEV）、密钥代理服务（KBS）、证明策略（attestation policy）
  - **多租户运维**: 在共享 GPU 节点上为不同租户提供数据隔离，需协调 GPU MIG/MPS + CoCo TEE 双重隔离
  - **监控盲区**: TEE 内进程/内存不可观测，传统监控工具无法深入，需要**远程证明（Remote Attestation）** 作为信任锚
- **AI 运维关联**: 多租户 AI 训练集群中，CoCo + GPU 机密计算组合将成为安全定级标配

### 3. LLM serving goodput 指标 — 从吞吐导向到效果导向
- **来源**: [Why goodput matters more than throughput for LLM serving](https://www.cncf.io/blog/2026/07/20/why-goodput-matters-more-than-throughput-for-llm-serving/) (Jul 20) — Akamas
- **运维指标演进**:
  - 传统指标：Throughput（rps）、P50/P95/P99 延迟
  - 新指标：**Goodput** = 满足 SLO 的有效吞吐量
  - Goodput ratio = Goodput / Throughput → 衡量基础设施「浪费了多少容量」
- **SLO 设计建议**:
  - 首 token 延迟（TTFT）≤ 500ms
  - token 间延迟（ITL）≤ 50ms/token
  - 回答完整性约束（不提前截断）
- **成本优化影响**: 从「压榨最高吞吐」转向「在 SLO 边界内最大化 goodput」→ 同等硬件容量可服务更多用户

## 🟡 中等价值条目

### 4. Kyverno 策略引擎负载测试方法论
- **来源**: [I made a policy engine think it was in production](https://www.cncf.io/blog/2026/07/22/i-made-a-policy-engine-think-it-was-in-production/)
- **方法论**: 混沌工程 + 并发注入模拟生产策略负载
- **关键发现**: 策略数量增加与准入控制延迟非线性关系——某些策略组合（mutating + validating 叠加）产生指数级延迟增长
- **运维启示**: 策略引擎的准入控制延迟需要纳入集群升级 SOP 的预检步骤

### 5. Agent 时代的平台工程运维
- **来源**: [Platform engineering for the agentic enterprise](https://www.cncf.io/blog/2026/07/21/platform-engineering-for-the-agentic-enterprise-managing-applications-resources-and-ai-agents/) (Jul 21)
- **运维新职责**:
  - GPU/TPU 配额管理 → 扩展为 Agent 级资源预留
  - Agent 行为可观测性 → 追踪 Agent 的推理调用链（不仅是 API 调用）
  - Agent 成本归属 → 按 Agent 实例核算推理/存储/网络费用
- **平台工具栈**: K8s + Backstage + Crossplane + OpenCost

### 6. 多集群数据库运维
- **来源**: [Multi-Cluster databases on Kubernetes](https://www.cncf.io/blog/2026/07/22/multi-cluster-databases-on-kubernetes-architecture-and-deployment/)
- **三种故障恢复策略**:
  - 完整区域故障 → 主动故障转移（需 DNS/TLS 更新滞后处理）
  - 控制面损坏 → Operator 自治恢复
  - 网络隔离 → Split-brain 防护（仲裁节点）
