## 1️⃣ 🟡 Kyverno 生产模拟测试方法论 — K8s 策略运维的 CI 实践

**来源**: [CNCF Blog Jul 22 | I made a policy engine think it was in production](https://www.cncf.io/blog/2026/07/22/i-made-a-policy-engine-think-it-was-in-production/) · Sargam Puram (Kyverno Maintainer)
**状态**: Kyverno 策略测试框架的运维实践指南

### 运维场景的核心矛盾

K8s 运维团队在安全策略落地时面临「三难困境」：

```
  1. 策略必须覆盖生产复杂场景
  2. 策略不能直接在生产中试验
  3. 脱敏的测试环境总与生产有差异
  +-> 三者不可兼得 -> 策略测试不足 -> 生产事故
```

### Kyverno 测试框架如何打破三难

| 策略测试层级 | 工具/模式 | 适用场景 | 覆盖度 |
|:------------|:----------|:---------|:------:|
| **单元测试** | `kyverno test` CLI + `kyverno-test.yaml` | 策略逻辑验证 | 低（单一资源） |
| **静默集群** | 复刻生产 YAML（去敏感数据）到测试集群 | 策略交互验证 | 中（批量资源） |
| **Audit 模式** | `validationFailureAction: Audit` + `background: true` | **生产中验证但不阻断** | 高（真实流量） |
| **dry-run 预览** | `generate` 策略的变更预览 | 资源生成的预检 | 中（生成场景） |

### CI 集成建议

```
PR 提交策略变更
  +-> kyverno test（单元测试） <- 必须通过
  +-> 静默集群测试（批量资源） <- 自动触发
  +-> 生产 Audit 模式部署 <- 自动部署，人工审核结果
  +-> 人工确认后 -> 切换为 Enforce 模式
```

### 对我方运维的价值
- 超节点集群的**安全准入策略（SBOM/镜像签名/资源配额）** 可搬用此测试流程
- **运维 Agent 自动生成策略测试用例**：Agent 提出策略变更 → 自动在静默集群跑测试 → 生成 Audit 报告 → 人工决策

## 2️⃣ 🟡 Multi-Cluster 数据库运维模式 — 跨集群故障域隔离

**来源**: [CNCF Blog Jul 22 | Multi-Cluster databases on Kubernetes: Architecture and deployment](https://www.cncf.io/blog/2026/07/22/multi-cluster-databases-on-kubernetes-architecture-and-deployment/) · Edith Puclla & Ivan Groenewold (Percona)
**状态**: 跨集群数据库运维方法，衔接 CNCF TAG Infra 7月8日白皮书

### 集群故障场景与运维响应

| 故障场景 | 传统响应 | Multi-Cluster DB 运维模式 |
|:---------|:---------|:--------------------------|
| **单个控制面损坏** | 集群不可用 → 等恢复 | 自动故障转移到备集群的 DB 实例 |
| **网络割接/分区** | DB 成员失联 → 脑裂风险 | 仲裁机制 + 自动降级为独立副本 |
| **区域级故障** | 依赖云厂商恢复 | 跨区域 Active-Passive 自动切换 |
| **版本升级故障** | 回滚困难 | 蓝绿集群升级 + 流量切换 |

### 运维最佳实践（来自 Percona MongoDB Operator）

| 实践 | 说明 |
|:-----|:------|
| **健康检查分层** | K8s liveness/readiness → DB replicaset status → 跨集群 ping |
| **仲裁节点（Arbiter）** | 跨集群奇数仲裁确保无脑裂（建议 3 集群 write concern: majority） |
| **监控跨集群** | Prometheus + Kube-Prometheus-Stack 聚合多集群指标 |
| **自动切换策略** | PreStop Hook 做数据同步 + readiness probe 做流量摘除 |
| **备份独立集群** | 备份从备集群拉取，不影响主集群性能 |

### 对我方运维的价值
- 超节点的**集群间资产管理/监控数据同步**可参考：主集群采集 → 跨集群复制 → 备集群只读查询
- 仲裁节点机制可复用于超节点**多 Region 控制面高可用设计**
