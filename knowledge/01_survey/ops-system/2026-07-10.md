- **对 MLOps 运维的直接影响**: 从\"GPU 利用率监控\"扩展到\"LLM 调用链路可观测\"

## 3️⃣ 🟡 Prometheus：Native Storage for Composite Types + PromQL info()

**来源**: Prometheus Blog (2026-02-14 ~ 04-22)

### A. Native Storage for Composite Types (2026-02-14)
- **背景**: Prometheus 存储层长期基于 float64 单一值类型
- **核心改动**: 为**复合类型**（histogram/summary/info）提供原生存储支持
- **解决的问题**:
  - 之前 histogram 存储需要拆成多条时序，查询聚合代价高
  - Native histogram 可以原生存储分位数结构
- **与 OTel 的关系**: 作为 OTel metric 的默认存储后端，需要原生支持 OTel 的数据模型

### B. info() PromQL 函数 (2025-12)
- 简化元数据标签关联：`info(my_metric)` 替代复杂的 PromQL join 查询
- 解决了\"标签变更导致查询失败\"的 churn 问题（尤其在使用 OTLP 摄入时）

### C. 其他 Prometheus 动态

## 5️⃣ 🟡 PSI Metrics for K8s GA：容器级压力信号可观测

**来源**: K8s Blog (v1.36)
**链接**: https://kubernetes.io/blog/

**关键信息**:

- **PSI (Pressure Stall Information)** 从 Linux 内核 4.20 引入，K8s v1.36 将其暴露为 **GA 级指标**
- **含义**:
  - CPU 压力: 等待 CPU 的时间比例
  - 内存压力: 等待回收内存的时间比例
  - IO 压力: 等待 IO 完成的时间比例
  - 分 **some**（至少一个任务被阻塞）和 **full**（所有任务被阻塞）
- 之前在 v1.34 Beta，v1.36 升至 GA

**影响判断**: PSI GA 意味着**运维团队可以在 K8s 层面统一采集容器级压力信号**，而不是需要单独部署内核监控工具。这是构建真正的\"资源压力预警\"体系的关键基础设施。
