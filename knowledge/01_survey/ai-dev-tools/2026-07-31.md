## 二、深度项目分析

### 2.1 🏆 ECC ⭐236k — Agent Harness生态的"操作系统"

> 仓库: [affaan-m/ECC](https://github.com/affaan-m/ECC) | 今日+810 | MIT

ECC 是当前GitHub上规模最大的Agent工具生态系统，定位为 **"Agent Harness Performance Optimization System"**。

| 维度 | 数据 |
|:-----|:-----|
| **Agent** | 67个专用Agent（planner/architect/code-reviewer/security-reviewer等） |
| **Skills** | 281个可复用Workflow |
| **Commands** | 94个维护中的Slash Command |
| **平台覆盖** | Claude Code + Codex + Cursor + OpenCode + Gemini + Zed + Antigravity + Qwen + Hermes + OpenClaw + Kimi + CodeBuddy + JoyCode + Copilot |
| **核心承诺** | "plan → test → implement → review → verify → remember → improve" |
| **特色** | AgentShield安全扫描、Memory Vault跨harness记忆、Plan Canvas可视化审批 |

**架构亮点**：
- **混合安装策略**：Claude Code/Codex/Cursor等各平台皆有专属适配器，install.sh自动检测并配置
- **Hook Runtime**：SessionStart/Stop阶段的自动化hook链，Script-based代替脆弱的inline
- **Memory Vault**：统一的Markdown格式跨harness记忆系统，支持project/user scope
- **ECCi**：Rust实现的control-plane原型（ecc2/目录），含daemon/dashboard/sessions

**战略意义**：ECC代表"Agent Harness操作系统"概念——不再是单一Agent，而是**跨平台Agent治理层**。67个Agent + 281 Skill = 可组合的Agent能力网格，是工具生态从"单点"到"平台"的关键信号。

### 2.2 🏆 code-review-graph ⭐27.8k — 代码审查的"GPS导航"

> 仓库: [tirth8205/code-review-graph](https://github.com/tirth8205/code-review-graph) | 本周+2,451 | MIT

本地优先的代码知识图谱，通过Tree-sitter解析AST构建函数/类/调用/继承关系图，让AI工具**只读必要的文件**而非整个代码库。

| 维度 | 数据 |
|:-----|:-----|
| **Token Reduction** | 中位数 **82×**（范围 38×–528×） |
| **Impact F1** | 0.71（召回率1.0为图推导上界） |
| **语言覆盖** | 30+语言，含Jupyter Notebook |
| **MCP Tools** | 30个MCP工具 + 5个工作流模板 |
| **构建速度** | 500文件~10秒，增量<2秒 |
| **支持平台** | Codex/Claude Code/Cursor/Windsurf/Zed/Continue/OpenCode/GitHub Copilot等14+ |
| **CI** | 原生GitHub Action，风险评分PR评论 |

**关键特性**：
- **Blast-radius分析**：变更影响的可达函数/类/测试集
- **增量更新**：文件保存触发重新解析，2900文件库<2秒
- **语义搜索**：可选向量嵌入（sentence-transformers/Gemini/OpenAI-compatible）
- **Hub/Bridge检测**：betweenness centrality找架构瓶颈
- **图形可视化**：D3.js力导向图，社区着色+度缩放节点

**差异化优势** vs LSP/传统静态分析：
- 跨语言统一图（不是每个语言开个daemon）
- 结构边≠相似度块（不是RAG chunk）
- 多跳推理（调用者→调用者→...的传递闭包）

## 四、趋势判断（7/31增量）

### 趋势5: Agent Harness"操作系统化" — ECC现象的启示

ECC 236k⭐不是单个工具的成功，而是代表 **Agent工具链从"工具集合"到"操作系统层"的跃迁**：
- **平台抽象层**：在Claude Code/Codex/Cursor/Gemini之上提供统一的能力接口
- **可组合能力网格**：67 Agent × 281 Skill 形成组合爆炸
- **记忆持久化**：Memory Vault跨harness统一记忆
- **安全治理**：AgentShield扫描Harness自身作为攻击面

**信号强度**: 🟢🟢🟢 极强。与之前分析的"编码Agent资源效率"趋势正交——资源效率解决"怎么跑得更省"，Harness OS解决"怎么跑得更系统"。

### 趋势6: 代码审查从AI辅助到"AI原生" — 知识图谱驱动

code-review-graph 提出的路线与alibaba/open-code-review形成互补：
- open-code-review：**规则+LLM的混合审查引擎**（确定性问题→规则，复杂推理→LLM）
- code-review-graph：**代码结构图驱动的精准上下文**（审查前先建图，只聚焦受影响的文件）

两者结合意味着代码审查正在走向 **"先建图，再审查"的新范式**。

### 趋势7: Agent编程语言化 — BAML与Agent DSL崛起

BoundaryML/baml 提出"Agent的编程语言"概念——声明式Agent编程：
- 用BAML DSL定义Agent行为、工具调用、数据转换
- 编译型（不是运行时解释），类型安全
- 与ECC/pi等Harness互补而非竞争

**信号强度**: 🟡 中等。Agent DSL是否能成为主流取决于标准化进程——当前碎片化严重。

### 趋势8: Git工作流为Agent重构 — worktrunk的启示

max-sixty/worktrunk ⭐6.1k 专门为**并行AI Agent工作流**设计Git worktree管理：
- 传统git worktree：手动管理，适合人
- Agent化worktree：自动创建/合并/销毁，适合AI Agent并行

这反映了一个更深层的变化：**开发者工具正在为"Agent作为第一用户"重新设计**。不是"给人类开发者的工具加AI功能"，而是"给AI Agent设计的原生工具"。

### 趋势9: 微软与NVIDIA全面入局Agent工具基础设施

两家巨头的官方项目：
- **NVIDIA OpenShell** (Rust) — Agent安全运行时，定位为"safe, private runtime for autonomous AI agents"
- **microsoft/agent-governance-toolkit** — Agent治理（策略/身份/沙箱/可靠性）
- **microsoft/azure-devops-mcp** — DevOps → Agent接入

**三件套信号**: NVIDIA做下层（运行时沙箱），微软做上层（治理+DevOps接入），各占生态位。Agent工具基础设施已进入大厂争夺阶段。
