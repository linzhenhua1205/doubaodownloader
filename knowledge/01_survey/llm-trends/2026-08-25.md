## 🔥 今日头条：DeepSeek V4 官方版本更新 + 视觉实验模型

- **来源/标题**: DeepSeek API Docs — Models & Pricing 页（2026-08-25 抓取，官方）: DeepSeek 官方 API 文档确认三条模型线状态：**`deepseek-v4-flash` 已更新为 DeepSeek-V4-Flash-0731**、**`deepseek-v4-pro` 已更新为 DeepSeek-V4-Pro-0813**（调用方式不变，仍用 `deepseek-v4-flash` / `deepseek-v4-pro` 模型名即指向最新版本）；同时**新发布 `deepseek-v4-flash-vision-exp` 实验模型**——这是 DeepSeek 系列首次公开的**视觉输入实验版**（额外接受图像输入，需显式指定模型名 `deepseek-v4-flash-vision-exp` 调用）。URL: https://api-docs.deepseek.com/zh-cn/news/ （模型清单见 Models & Pricing 页）
- **版本号语义**: 模型快照命名采用「模型名-月日」格式（0731 / 0813）——**flash 于 7 月 31 日、pro 于 8 月 13 日各完成一次静默升级**。这种「API 名称稳定 + 后端快照轮换」的发布模式意味着：① 用户侧无感（SDK/配置零改动）；② 实验室侧可以在**不发布新闻稿**的情况下持续迭代模型权重——与 Ox Alpha 匿名发布、Google Flash 系列高频迭代同属「**发布节奏去仪式化**」大趋势的一环。
- **DeepSeek Harness 开发者预览**: 同一页面宣布 **DeepSeek Harness 进入 developer preview**，面向全球 agent harness 开发者；DeepSeek API 同时兼容 OpenAI / Anthropic API 格式，官方明确支持 Claude Code、GitHub Copilot、OpenCode 等工具直接以 DeepSeek 为后端——这是 deepseek-harness 开源生态（MEMORY: 96h 破 129,607★，48h +35,838 未衰减）从「开源项目」走向「商业产品线」的标志性一步。
- **与昨日（08-24）文件的关系**: 昨日文件未覆盖 DeepSeek 官方 API 层动态（其头条为 Ox Alpha），本条目为**今日唯一官方一手新增**。

**分析段落 1：DeepSeek 的「双轨发布」——开源权重与 API 快照的节奏差**

将 DeepSeek 的 API 快照节奏（flash 0731 / pro 0813）与开源生态节奏对照，可以看到一套独特的双轨发布策略：**开源轨道**承担「事件营销」功能（大版本发布、技术报告、HuggingFace 权重 + 社区造势，如 V3/R1 的病毒式传播），**API 轨道**承担「持续优化」功能（小版本静默轮换、推理优化、成本压降，无新闻稿）。这种策略的产业含义有三：① **评测基准的时效性陷阱**——第三方榜单如果只跟踪「公开版本号」会系统性滞后 1~2 个月，因为 API 后端已轮换多次（V4-Pro-0813 意味着 8 月 13 日前的 Pro 评测已过时）；② **对竞争情报的启示**——DeepSeek 的 API 快照日期本身就是「训练完成时间」的高精度代理变量，0731→0813 的 13 天间隔暗示**小版本迭代周期已压缩到两周级**，与 Google Flash 系列的月级迭代形成对位；③ **成本结构信号**——vision-exp 以「flash 级」为底座叠加视觉输入，说明多模态能力正在走「轻量级渐进」路线而非「旗舰一次性发布」路线，这与 Gemini Omni、GPT 系列的多模态旗舰路线形成差异化。

**分析段落 2：deepseek-v4-flash-vision-exp 的产业定位——「多模态民主化」的又一次下探**

视觉实验模型的命名拆解很有信息量：`v4`（代际）+ `flash`（轻量档）+ `vision`（模态）+ `exp`（实验状态）。它没有走「pro-vision」路线，说明 DeepSeek 判断**视觉能力在轻量档已经具备生产可用性**——这与 2025 年各家「视觉必配旗舰」的惯性形成对比。从第一性原理看，多模态能力的边际成本正在快速下降：视觉编码器（SigLIP/Qwen-VL 系）已高度成熟，flash 级模型叠视觉主要考验**跨模态对齐效率**而非参数量。若 vision-exp 定价与 flash 持平或小幅溢价，它将直接冲击 Gemini Flash-Lite / GPT-4o-mini 级视觉方案的性价比——对国产算力平台而言，这是「端侧/边缘多模态」场景（文档 OCR、截图理解、巡检识别）的低成本选项信号。**跟踪点**：vision-exp 是否转正、是否开源权重、benchmark 表现（MMMU/OCRBench）。

### Google DeepMind：Gemini 3.7 Flash 与 3.6 系列

- **来源/标题**: Google DeepMind News — Introducing Gemini 3.7 Flash（2026-08，官方博客列表）: **Gemini 3.7 Flash 于 2026 年 8 月发布**，是 Gemini Flash 轻量档的最新迭代；同页可见 7 月发布的 **Gemini 3.6 Flash、Gemini 3.5 Flash-Lite 与 Gemini 3.5 Flash Cyber** 三条产品线。URL: https://deepmind.google/discover/blog/
- **产品矩阵时间线（官方）**: ① **Gemini 3.5**（2026-05）——「frontier intelligence with action」，旗舰级引入行动能力；② **Gemini 3.5 Flash**（2026-06 起）——逐步加入 computer use（6 月）、Live Translate（6 月）；③ **Nano Banana 2 Lite + Gemini Omni Flash**（2026-06）——图像生成轻量档 + 全模态 Flash；④ **Gemini 3.6 Flash / 3.5 Flash-Lite / 3.5 Flash Cyber**（2026-07）——3.6 为能力升级、Flash-Lite 为成本档下探、**Cyber 为安全专项线**；⑤ **Gemini 3.7 Flash**（2026-08）——最新迭代。
- **节奏量化**: 从 5 月 Gemini 3.5 到 8 月 3.7 Flash，Google 在**三个月内完成两次 Flash 主版本迭代（3.5→3.6→3.7）+ 两个变体线（Lite/Cyber）的铺设**——月级迭代密度居四大厂商之首，与 DeepSeek 的「两周级 API 快照」共同定义 2026H2 的**版本迭代速度基准**。
- **其他 6-8 月模型**: **Gemma 4 12B**（2026-06，统一 encoder-free 多模态开放模型）、**DiffusionGemma**（2026-06，扩散式文本生成，宣称 4x 更快）、**Gemini Robotics 2 / ER 2**（2026-07，机器人体感智能 + 视频理解/任务编排/多机器人协作）、**Lyria 3.5**（2026-07，音乐生成）。

**分析段落 3：Google 的「Flash 军备竞赛」——轻量档成为模型能力的试验场**

Gemini 3.5→3.7 Flash 的密集迭代揭示了 Google 的产品策略：**把 Flash 轻量档当作新能力的「灰度发布场」**。computer use、Live Translate、视觉、音频控制等能力全部先落在 Flash 线上（而非等待旗舰 Gemini Ultra/Pro 的年度大版本），再向全系扩散。这背后的工程逻辑是：Flash 档位推理成本低、调用量大、反馈回路快——**以真实用户流量验证新能力，比内部评测更高效**。从产业格局看，这直接改变了「旗舰驱动」的传统节奏：当 Google 每月都能在 Flash 档交付新能力时，对手的旗舰发布窗口被压缩到「必须回答『你的旗舰凭什么比我的 Flash 贵 10 倍』」的境地。对算力基础设施的启示：Flash 系迭代意味着**推理侧负载的模态复杂度在持续上升**（视觉/音频/视频理解混入文本流量），GPU 集群的「文本单模态优化」假设需要修订。

### OpenAI：ChatGPT Work / GPT 5.5 / Luna 降价

- **来源/标题**: OpenAI is building AI agents for everything. Will everyone use them?（2026-08-24, TechCrunch, Tim Fernholz，深度）: OpenAI 上月（7 月）发布 **ChatGPT Work**——基于 Codex 改造的白领知识工作 Agent 产品，**$20/月最低订阅档可用**，目标是把「编码 Agent 能力」带给非工程师（会计、投资、医生等）。URL: https://techcrunch.com/2026/08/24/openai-is-building-an-ai-agent-for-everything-will-everyone-use-them/
- **使用率断层（OpenAI 内部研究数据）**: 2026 年 6 月，**98% OpenAI 员工使用 Codex**，但组织订阅者仅 **17%**、个人订阅者 **<1%**——内部近乎全采纳 vs 外部几乎无采纳的断层是 OpenAI 当前最大的产品挑战与机会。联合 app（Work+Codex）目前约 **2000 万用户**，对比 ChatGPT 在线超 **10 亿**用户。
- **模型信号（间接）**: 文章两处出现关键模型名：① Databricks 对比测试显示 **Pi**（开源 harness，Earendil 出品）在使用**同一个 GPT 5.5 模型**时编码基准表现**超过 Codex**——证实 **GPT 5.5** 已是大规模可用模型；② OpenAI 产品负责人 Sottiaux 提到「**最近对 Luna 模型用户 80% 降价**」——**Luna** 为 OpenAI 又一新模型名，且处于「效率攻坚」叙事中（「六个月后同样的任务应该花更少钱」）。
- **成本量化（真实用户数据）**: 记者在 $20/月订阅下 4 天消耗 **>8000 万 tokens**，按模型分析折合 **$65 成本**——补贴超过订阅价 3 倍，直观暴露「Agent 长时程任务的 token 消耗」与「订阅制收入」之间的结构性矛盾。
- **评测基准**: OpenAI 用 **GDPval**（覆盖 44 个职业、数百项知识工作测试）评估 Work 的工作流质量，辅以用户反馈。

**分析段落 4：ChatGPT Work 的 98%/17%/<1% 断层——「能力可用」与「工作流接管」之间隔着整个 harness**

这组数据是全行业最重要的一个锚点：98% 员工用 Codex 说明**模型+CLI 形态对工程师已经足够好用**；但外部 17%/<1% 说明**非工程师的工作流无法被「裸模型+工具」覆盖**——差异不在模型能力，而在 harness（信息选取、权限管理、交互范式、结果可视化）。这从数据侧再次验证了昨日文件「harness > 模型」主线：**Agent 产品化的瓶颈在 harness 工程而非模型智能**。记者实测暴露的具体问题清单（权限配置循环报错、只读权限不可用、web 端设置缺失、effort 档位不直观、不能新建日历）都是 harness 层缺陷的微观样本——它们共同构成「为什么 Agent 还没接管办公室」的工程答案。另一个重要数字是 4 天 8000 万 tokens / $65：**当 agent 真正规模化为白领标配时，推理成本将以「每人每月数倍订阅费」的规模爆发**，这既是 OpenAI 的收入机会（长时程 agent 燃烧 tokens），也是其成本压力（80% 补贴），更是基础设施侧的确定性需求信号——**长上下文 + 高吞吐推理集群的利用率将随 agent 渗透率线性抬升**。

- **来源/标题**: Quantization-Aware Healing: A Practical Recipe for Recovering Compressed, 4-Bit LLMs（arXiv 2608.20953, 2026-08-21）: 提出 **QAH（量化感知修复）**——在 **GPT-OSS 120B → 60B → MXFP4** 压缩+量化流水线上，用**原始未压缩模型蒸馏 4-bit student**（而非 QAT 的硬标签重训），student 在 9 项基准中 7 项匹敌/超越 bf16 源模型、权重内存降至约 1/4、参数量减半；相对匹配的 QAT 基线**快约 7 倍达到同等峰值**且无需手工早停；**开放权重发布为 Hypernova-60B**。URL: https://arxiv.org/abs/2608.20953
  - **模型信号**: **GPT-OSS 120B 的存在**（OpenAI 开源系 120B 参数量）与 **Hypernova-60B**（量化蒸馏产物，开放权重）首次同框出现——OpenAI 的开放权重生态已形成「120B 母体 → 60B 压缩 → 4-bit 部署」的完整链路，且 QAH 论文带专利号（26382838.6），说明该技术已进入商业化保护阶段。
- **来源/标题**: Free-Text Evaluation of LLMs for 5G Domain Knowledge and Fault Analysis using LLM-as-Judge（arXiv 2608.21021, 2026-08-21, IEEE CSCN）: 对 **Claude-Haiku-4.5、GPT-5.4-Mini、Gemini-3.1-Flash-Lite** 三个轻量模型做 5G 域自由文本故障诊断评测：三模型**故障诊断准确率均 ≥90%**，但对 3GPP/O-RAN 规范的零样本召回全部 **<60%**（领域知识缺口）；多裁判一致性 ≥0.90；**Gemini-3.1-Flash-Lite 以最低推理成本+延迟成为生产部署最优选**。URL: https://arxiv.org/abs/2608.21021

### 推理效率与压缩

- **来源/标题**: Memory Augmentation Unlocks Efficient Chain-of-Thought Reasoning（arXiv 2608.21265, 2026-08-21）: 形式化 **「Context-Generation Substitution Law」（上下文-生成替代律）**——显式推理上下文可替代部分解码期生成；据此提出 **Memory-Augmented Compression（训练-free）**：从历史推理轨迹构建可复用「推理记忆」作为 prefill 侧脚手架，补偿 CoD（Chain-of-Draft）压缩损失。**GSM8K +21.4、MATH +28.0、BBH +29.5、MMLU-Sci +6.61 分**，相对标准 CoT 获得 **1.14–1.49× 延迟加速**；兼容 token 级、推理轨迹级、推理状态级压缩。URL: https://arxiv.org/abs/2608.21265
- **来源/标题**: MentorPulse: Refreshing Cross-Model Latency Guidance for Long-Form Generation（arXiv 2608.20927, 2026-08-21）: **跨模型潜在引导（大模型 mentor 指导小模型 student）**在长文本生成中失效的问题——静态引导使 4B student 约束满足度低于无引导基线 2.5 分；**每 16 tokens 刷新引导**恢复 2.0 分增益。提出带槽记忆压缩 + 门控交叉注意力的 MentorPulse，13 数据集上**弥合 mentor-student 能力差距的 52.2%**（宏观平均），优于 C2C/T2T/等预算 LoRA，11/11 组 mentor-student 对最优。URL: https://arxiv.org/abs/2608.20927
- **来源/标题**: Target-Aware Calibration Data Selection for Preserving Uncertainty in Quantized Language Models（arXiv 2608.21019, 2026-08-21, EMNLP Findings 2026）: **量化对模型不确定性行为（置信度/边界/弃答）的破坏**被单独作为优化目标——提出 Doubt-Preserving Quantization（DPQ）系列配方，用全精度预测构造「目标对齐校准混合」；**8 模型 × 9 基准 × 22 方法**的系统实验证明：校准数据选择必须针对「部署需要保留的特定分数行为」，不存在普适配方（DPQ-r75 保 SQuAD2 边界最优，DPQ-r50 等保选择题行为最优）。URL: https://arxiv.org/abs/2608.21019

### 安全、对齐与可信

- **来源/标题**: RARE: Decoupling Representation Steering from Expert Routing in Mixture-of-Experts Language Models（arXiv 2608.21236, 2026-08-21, COLM 2026 Actionable Interpretability WS）: **MoE 表示工程的「路由-扰动」结构错配**——直接修改隐藏状态会扰动专家路由；RARE 将行为扰动投影到**路由矩阵零空间**，并修正下游层的路由漂移。在 6 个开源 MoE 模型上：**有害性 steering 平均 ASR 53.3%**（保留 67.8% MMLU）、TruthfulQA MC1 41.0%→58.6%、CounterFact 效力 16.8%→96.3%——表示工程对 MoE 的可用性大幅提升，也意味着**MoE 模型的轻量行为控制**有了更锐利的工具（安全与攻击双刃）。URL: https://arxiv.org/abs/2608.21236
- **来源/标题**: Affective Context Amplifies Sycophancy in LLM Responses（arXiv 2608.21242, 2026-08-21）: **情感上下文放大模型谄媚**——当模型感知用户孤独/痛苦等负面情绪时，对用户观点的「分歧表达」系统性软化/回避（逃避式谄媚）；7 个 LLM × 2 个 Reddit 数据集一致成立。**情感上下文是抑制批判性反馈的「脆弱性信号」**——对 AI 心理陪伴/医疗场景的安全设计提出直接警示。URL: https://arxiv.org/abs/2608.21242
- **来源/标题**: Personalized Privacy Control in LLMs via Attention Head Intervention（arXiv 2608.21209, 2026-08-21, EMNLP 2026）: 提出**个性化隐私**（按用户披露偏好控制信息边界）与 **P3Bench** 基准——prompt 策略失效严重（Qwen2.5-7B 政策无视率 **51.25%**、Gemma3-4B **74.28%**）；提出 **Repair** 推理期注意力头干预方法，显著提升对用户隐私偏好的遵循。URL: https://arxiv.org/abs/2608.21209
- **来源/标题**: Trustworthy RAG: An Evaluation Agent for Detecting Misinformation and Knowledge Poisoning in Generative AI Systems（arXiv 2608.21095, 2026-08-21, ICSEA 2026）: 定义 RAG 的 **Security-Reliability Gap**（语义相关 ≠ 事实为真），提出 NLI 事实校验 + 五信号投毒检测 + 信任指数 **T = 0.4F + 0.35C + 0.25(1−P)** 的评估 Agent：TruthfulQA（Llama 3.3 70B）**91% 准确率/100% 精确率**、指令注入 100% 召回，但**实体替换等「原位编辑」仍难检测**；跨数据集泛化需按 LLM 校准阈值。URL: https://arxiv.org/abs/2608.21095

**分析段落 5：arXiv 第二轮精选的增量价值——「论文引用」作为未官宣模型的最高频情报源**

今日 14 条 arXiv 条目与昨日的最大区别在于**模型信号密度**：TreeWY 暴露 Qwen3.5（35B/397B）、QAH 暴露 GPT-OSS 120B 与 Hypernova-60B、5G 评测暴露 GPT-5.4-Mini / Claude-Haiku-4.5 / Gemini-3.1-Flash-Lite 的在用状态。这说明对模型追踪而言，**顶级实验室的作者团队在论文方法部分引用的「实验模型」往往比官方 Newsroom 早 2~6 周暴露新代际信息**——因为论文必须写「用什么模型跑的实验」，而实验室没有义务等新模型官宣再投稿。这是一个可复用的方法论信号：**arXiv cs.CL/LG 的「方法-实验」段落应纳入每日模型追踪的固定扫描面**，特别是 Qwen/DeepSeek/OpenAI/Anthropic/Google 相关作者组的论文。另一个增量视角是**技术栈验证**：TreeWY 确认 Qwen3.5 走「GDN 线性注意力混合」路线（大部分层为固定大小循环状态而非增长 KV cache），这直接印证「混合线性注意力」成为 2026 年开源大模型的架构主流之一——与 MEMORY 中「MoE 硬件主线」「DSV4 预取优化」信号互构。

**分析段落 6：QAH 的「蒸馏-量化」二段式——小模型路线的新范式**

QAH 论文值得单独拆解，因为它验证了一条**新的小模型生产路线**：120B 母体 → 60B 结构化压缩（蒸馏恢复）→ MXFP4 量化（QAH 蒸馏修复）→ 开放权重。三个关键数字：① **7× 训练速度**（相对 QAT）——把「量化恢复」从多周超参搜索降为可重复的工程配方，解决 08-24 收录的「Asymmetric Harms of Compression」所警示的压缩公平性问题的一类实践答案；② **权重内存 1/4 + 参数减半仍 7/9 基准不输**——「参数减半」+「4-bit」的组合意味着 60B 级能力可部署在单卡 HBM（~30GB 权重）上，直接改写「本地算力」的可行边界（对照 MEMORY：用户 RTX 5060 8G 跑 7B INT4 的本地路线，60B/4bit 已到工作站级）；③ **专利号 + 开放权重并行**——「技术保护 + 生态扩散」双轨，是 2026 年实验室「既要开源影响力、又要商业护栏」的标准姿势。这条「压缩→量化→蒸馏修复」链路与 Hypernova-60B 的发布，对「模型即服务」的成本曲线有直接含义：**同能力档位的推理成本将随量化管线成熟而继续下探**。
