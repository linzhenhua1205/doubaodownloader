## 🔥 头条一：Anthropic 发布 Claude Cowork 移动端/Web端 + 云端持续运行

**来源**: [The Verge](https://www.theverge.com/ai-artificial-intelligence) (Jul 8, 2026) · Anthropic Newsroom

Claude Cowork 正式从桌面扩展至**移动端和 Web 端**，并支持**云端后台持续运行**。

### 核心功能
- **移动端/Web端**: 手机浏览器或 Web App 即可使用 Claude Cowork
- **云端持续运行**: Cowork 切换到云端执行，**即使合上笔记本电脑**，任务也能继续推进
- 与桌面版 Claude Cowork 相同的 Agent 能力：计划、工具使用、代码编写、文件操作

### 意义
这是 Anthropic **"无处不在的 Agent"** 战略的关键一步。Cowork 之前是桌面端重度用户的专属工具，现在向移动场景开放，覆盖"发出指令后让 Agent 在后台持续运行"的使用模式。

## 🔥 头条二：NVIDIA 发布 Audex — 统一音频智能，文本智能不退化

**来源**: arXiv:2607.05196 · [Nemotron-Labs-Audex-30B-A3B (Audex)](https://arxiv.org/abs/2607.05196) · NVIDIA Research (Jul 6, 2026)

### 模型概览
| 项目 | 数据 |
|:-----|:-----|
| **模型名** | Nemotron-Labs-Audex-30B-A3B（简称 Audex） |
| **基座** | Nemotron-Cascade-2-30B-A3B（纯文本 MoE LLM，30B 总参/3B 激活） |
| **架构** | 统一单 Transformer 解码器：音频输入→编码→投影到文本 embedding 空间 |
| **训练数据** | 音频 157.4B tokens + 文本 320.5B tokens |
| **训练方法** | 多阶段 SFT → 文本仅 Cascade RL → 多领域在策略蒸馏 |
| **开源** | ✅ 权重已发布到 HuggingFace |

### 统一设计哲学
- 音频输入直接编码到文本 embedding 空间
- 文本 token 和**量化音频输出 token** 在生成时统一处理
- 单 Transformer 解码器兼容标准 LLM 训练/推理基础设施

### 能力覆盖
| 领域 | 能力 |
|:-----|:-----|
| 🎧 **音频理解** | SOTA |
| 🗣️ **语音识别/翻译** | SOTA |
| 🔊 **语音生成 (TTS)** | SOTA |
| 🎵 **音频生成** | SOTA |
| 🗨️ **语音到语音生成** | SOTA |
| 📝 **文本推理/知识/Agent** | **保持基座能力，无退化或仅极小退化** |

### 核心创新点
- **"文本智能不退化"** 是统一音频-文本模型长期的核心难题（之前的多模态模型通常在融合时降低文本能力），Audex 通过多阶段训练+多领域蒸馏首次实现
- MoE 架构（30B 总参/3B 激活）兼顾了推理效率

## 🔥 头条三：EdgeBench — 首次揭示 Agent 真实环境学习的 Scaling Law

**来源**: arXiv:2607.05155 · [EdgeBench](https://arxiv.org/abs/2607.05155) (Jul 6, 2026)

### 核心发现
> Agent 在**真实世界环境中学习**的性能遵循 **log-sigmoid scaling law**，拟合精度 **R² = 0.998**。
> 跨模型代际，Agent 学习速度约 **每 3 个月翻倍**。

### 数据规模
| 维度 | 数据 |
|:-----|:-----|
| **Agent-环境交互时长** | ~ **38,000 小时** |
| **真实世界任务数** | **134 个**（含 51 个公开任务+完整评估框架） |
| **单个任务最小持续** | **12+ 小时**连续运行 |
| **覆盖领域** | 科学发现、软件工程、组合优化、专业知识工作、形式数学、交互游戏 |
| **反馈类型** | 丰富多级反馈 |

### 任务示例
- 科学发现（自主实验设计）
- 软件工程（完整的 PR 修复流程）
- 组合优化（求解大规模问题）
- 专业知识工作（长链分析推理）
- 形式数学（定理证明）
- 交互游戏（需要策略学习的环境）

### 意义
这是业界**首个**大规模量化 Agent 在真实环境中的学习效率的研究。相比于预训练阶段的数据/算力 Scaling Law，这是**部署后学习**的 Scaling Law——对 Agent 产品设计、推理预算分配有直接指导价值。

## 📄 arXiv 精选论文（Jul 5-6 提交）

### 1️⃣ Wrong Before Right — 对齐模型中"先错后对"的因果机制
**arXiv:2607.04640** · Jul 6

- **关键发现**：对齐模型在**中间层（25-90% 深度）** 内部偏好会短暂地**错误提交**，再由**晚期层校正**回来（wrong-dip）
- **跨 17 个模型验证**：3 个家族（Qwen2.5, Llama-3, Mistral）× 0.5B-32B 规模
- **对齐放大了 wrong-dip**：Qwen2.5 系列中，3B 开始出现，32B 达峰值（paired t=9.7）
- **实际影响**：高 wrong-dip 条目在**低秩压缩、Block Drop、结构化剪枝**下出错概率高 **3-7×**
- **解决方案**：LoRA 中间层 wrong-margin 惩罚 → 减少 causal dip **67-70%**，同时保持精度；而纯输出 SFT **反而加重 wrong-dip 达 2.8×**

### 2️⃣ SIS — 选择性重要性采样：离策略→在策略 token 转换
**arXiv:2607.04728** · Jul 6

- **问题**：RL 后训练中"rollout then update"不可避免地产生离策略数据，Token 级重要性采样在长序列上方差爆炸
- **方法**：受**拒绝采样**启发，将离策略模型视为提议分布，Token 级拒绝检验——**接受即视为在策略**，拒绝则保留 IS 校正
- **理论保证**：减少 Token 级与序列级梯度估计差异
- **效果**：Dense 和 MoE LLM 上，数学+Agent 基准**一致提升**，离策略数据下鲁棒性更强

### 3️⃣ dOPSD — 扩散语言模型的在策略自蒸馏
**arXiv:2607.04428** · Jul 5

- 将 OPSD 框架移植到**扩散语言模型（dLLM）**
- 教师特权直接来自学生自身的**去噪轨迹**（而非外部标签）
- Dream 和 LLaDA 上：**域内数学推理 + 域外代码生成**均提升，超 SFT 和 RL 基线

### 4️⃣ LP-SFT — 局部保持的有监督微调
**arXiv:2607.04733** · Jul 6

- 问题：SFT 导致模型**过度拟合特定格式**，丧失生成多样性
- 方法：基于多模态熵结构，在 SFT 过程中保留局部行为模式
- **效果**：保持对齐水平的同时保留生成多样性

### 5️⃣ ToolFailBench — Agent 工具使用失败诊断基准
**arXiv:2607.04686** · ICML 2026 Workshop

- 系统分类 Agent 工具调用失败模式（工具调用、参数解析、结果解读等）
- 为 Agent 开发者提供失败诊断框架

## 📈 关键趋势

1. **Agent 云端化** — Claude Cowork 云端运行标志 Agent 从"交互式"走向"委托式"，用户只需下发指令
2. **统一多模态 LLM 的文本智能保持** — Audex 证明 MoE+多阶段训练可解决文本退化问题，MoE 架构（30B/3B）兼顾效率
3. **部署后学习受关注** — EdgeBench 的 Scaling Law 标志着研究方向从"预训练规模"扩展到"部署后学习效率"
4. **对齐机制的深层理解** — "Wrong Before Right"揭示输出级对齐掩盖的内部脆性，压缩/剪枝等部署优化需关注中间层
5. **RL 对齐方法精细化** — SIS（选择性在策略化）、dOPSD（扩散模型自蒸馏）、DemoPSD（周日已报）等指向更精确的梯度/蒸馏控制
