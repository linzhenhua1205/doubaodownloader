## 🔥 头条一：In-Place Tokenizer Expansion — 不改权重即可扩展分词器，小语种解码加速 2-4×

**来源**: arXiv:2607.15232 · Jimmy T.H. Smith, Tarek Dakhran 等 (Jul 16, 2026)

### 核心方法

| 维度 | 数据 |
|:-----|:------|
| **问题** | 分词器在预训练开始时固定，后期加入的语言每个词被切成更多 token → 延迟/计算/能耗放大；小模型无法像云端大模型一样承担大词表 |
| **方法** | 在现有 BPE merges 基础上对多语语料继续 merge → 大部分源 token 原样保留，新 token 有精确的源子 token 分解路径 |
| **初始化** | 承载 embedding 行不变，新行初始化为对应子 token embedding 的均值 |
| **两阶段适应** | embedding-only 训练 → 全模型继续预训练 → 恢复源 checkpoint 质量 |
| **应用模型** | LFM2-8B-A1B (8B MoE) → **LFM2.5-8B-A1B** (128K 词表) |

### 能力数据

| 语言 | token 数减少 | 每字符解码加速 |
|:-----|:------------:|:--------------:|
| **印地语 (Hindi)** | **2.4×** | 2.2-3.7× |
| **越南语 (Vietnamese)** | **2.6×** | 2.2-3.7× |
| **泰语 (Thai)** | **4.0×** | 2.2-3.7× |

### 意义

> 解决小模型多语部署的核心痛点：**分词器即语言公平性的第一道关口**。提供了"不改权重"的 in-place 升级方案，embedding-only 训练即可恢复质量。权重+扩展分词器已开源。

## 🔥 头条二：OmniaBench — 最严苛 Agent 综合基准，Claude Sonnet 5 / GPT-5.6 仅 58%/57%

**来源**: arXiv:2607.14989 · Chengyu Shen, Yujie Fu 等 (Jul 16, 2026)

### 基准设计

| 维度 | 数据 |
|:-----|:------|
| **域层次** | ToC / ToB / ToE 三大类，**90 个一级域，354 个二级域**（来自应用商店/产品文档/行业资源） |
| **任务数** | 1,431 个（含 644 个困难子集） |
| **能力维度** | 10 维能力分类 + 8 个组合原子难度因子 |
| **生成方式** | 4 条互补路线：DAG / DAG-S / Solver / Program |

### 前沿模型表现

| 模型 | Overall Pass@1 |
|:-----|:--------------:|
| **Claude Sonnet 5** | **58.54%** — 最高 |
| **GPT-5.6 Sol** | **57.14%** |
| **GPT-5.6 Terra** | 55.10% |
| **GPT-5.6 Luna** | 52.10% |
| **DeepSeek V4 Lite** | 32.86% |

### 主要瓶颈

详细分析显示，当前前沿模型的**核心瓶颈**不在任务理解或工具调用，而是：
- **规划能力** (Planning)：任务分解与顺序编排不稳定
- **约束维护** (Constraint Maintenance)：在长交互链中持续保持初始约束
- **自适应修正** (Adaptive Correction)：遇到错误后恢复困难

### 意义

> 当前最全面的 Agent 评测基准之一。**Claude Sonnet 5 和 GPT-5.6 Sol 均未达 60%**，说明 Agent 能力成熟的**真实瓶颈不在模型规模的 scaling**，而在规划和约束维护等结构性能力——与 CCH 假说和 Severance Problem 的结论一致。

## 🔥 头条三：Answer-Conditioned CoT 破坏推理蒸馏 — 硬题准确率暴跌 27 点

**来源**: arXiv:2607.14552 · Jungseob Lee, Seungyoon Lee 等 (Jul 16, 2026)

### 核心发现

| 维度 | 数据 |
|:-----|:------|
| **标准方法** | 采样 CoT → 只保留到达正确答案的 → 微调幸存者 |
| **常见改进** | 采样失败时给出正确答案，要求 CoT 到达该答案（Answer-Conditioned CoT） |
| **核心结论** | **Answer-Conditioned CoT 损害蒸馏数据质量**，且正确率过滤无法检测 |
| **最高性能下降** | 最难的竞赛题下降约 **27 pp** |
| **机制** | 模型从显示的答案**反向合理化**而非推导出答案——早期答案声明是可测量的症状 |
| **Prompt ablation 确认** | 损伤来自"朝着答案推理"指令，而非答案的视觉暴露 |

### 机制可迁移性

| 维度 | 数据 |
|:-----|:------|
| 跨 8 个 thinking 模型 | 4 个模型家族一致观测到 |
| 跨教师家族 | 损伤可转移 |
| 无标签时可预判 | 在标注前从未校对的 generation 中可读出损伤 |

### 实用建议

> **"Generate answer-blind"** — 因为正确率过滤器无法看到训练数据中的损伤。如果必须事后补链，确保条件是"推导"而非"合理化"。

## 📈 趋势聚焦

1. **分词器即语言公平性的第一关口** — In-Place Tokenizer Expansion 和 Current AI 项目从不同角度直击同一问题：LLM 的语言偏见从 tokenizer 开始。小模型 + 扩展词表 + 多语覆盖正在成为基础设施层共识

2. **Agent 基准进入「难到前沿模型也仅 58%」的阶段** — OmniaBench 1,431 任务 × 90 域 × 10 维能力，Claude Sonnet 5 不过 58.54%。瓶颈明确在规划/约束/自适应修正——与 CCH 假说（能力靠结构非规模）形成交叉印证

3. **CoT 蒸馏的「因果方向污染」被精确定位** — Answer-Conditioned CoT 破坏推理是继 Simplicity Paradox 后又一个对常见做法产生根本性质疑的工作。两条论文都发出同样信号：**你不是太弱，而是做法有毒**

4. **多语评估的偏见暴露系统性安全问题** — LLM Evaluators 偏见研究在 23 语言中揭示 **43% 接受率差异**——低资源语言中的有害内容更容易过 safety filter，且 code-switch 可绕过语言 ID 防护

5. **KV-Cache 嫁接产生 8,700× 能效改善** — 字节精确 KV cache 嫁接+已验证知识库的组合使小模型超越大模型，是**推理时 knowledge injection** 的最极端示范
