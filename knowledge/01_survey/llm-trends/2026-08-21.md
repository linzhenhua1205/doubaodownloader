### 训练与自我改进

- **SPADE: Self-Play in Adaptive Synthetic Executable Environments——环境生成器与推理 Agent 的自我对弈，目标分布随 learner 扩展而自适应**（arXiv:2608.19197, 08-19 提交, Bo Liu/Simon Yu/Yiding Jiang/Ao Qu/Andrew Zhao/Zichen Liu/Junsu Kim/Zijian Zhou/Seongmin Kim/Tongzheng Ren/Mickel Liu/Hanfei Yu/Zhaorun Chen/Weiyan Shi/Paul Pu Liang/Luke Zettlemoyer/Yejin Choi/Natasha Jaques 等，Meta FAIR/UW 系大牛阵容）: 论文开宗明义——**持续自我改进需要一个不断扩大的自生成、多样、自适应的目标池**。现有训练环境池（手工精选、静态合成、冻结验证器）在 learner 扩展时把目标分布锁死，这是自我改进的天花板。SPADE 让单个 LLM 扮演两个角色：① **Environment Designer**：把完整的长时程训练环境写成**可执行代码**（OpenAI Gym 风格 reset()/step() 接口），每个环境都是有状态、多轮的——状态转移、奖励函数、验证代码全在内，一个接口横跨推理问题与多步 agentic 工具使用；② **Reasoning Agent**：在该环境中学习行动。Reasoning Agent 的 regret 用「有特权 vs 无特权奖励的 gap」估计——**把「环境是否在教会 agent 新东西」变成可度量的信号**。信号含义：这是「自适应课程」从调度器（curriculum on fixed tasks）升级为**生成器（curriculum on generated environments）**的里程碑式框架，与 08-19 的 CoE（经验链持续改进）、Palmyra x6 保守后训练共同构成「模型自我演进」主线的第三条技术路线：**自我博弈生成环境**。https://arxiv.org/abs/2608.19197

- **What is Missing from AI Post-Training AI: An Empirical Analysis——AI 自己训练 AI 的实证解剖：策略在开局即锁定，剩下全是局部调整**（arXiv:2608.19072, 08-19 提交）: LLM agent 已经能端到端后训练另一个 LLM——写代码、启动训练、评估 checkpoint、改进下游性能，AI-for-AI 的前景看似打开。但本文论证这个图景**混淆了两种根本不同的能力**：① **执行级能力**（execution-level）：在选定的训练策略内迭代调参；② **策略级能力**（strategy-level）：随实验证据积累修订高层判断（换数据配比、换损失、换训练方法）。分析大量公开后训练轨迹后发现一个普适现象：**agent 的训练策略在开始时就被锁定，剩余全部预算花在所选策略内的局部调整**——策略级修订几乎不发生。作者进一步用递进干预（缺失经验/缺失指导/推理不足三种解释）做实验：(1) 经验增强能改善执行级表现，但（截断处可见实验设计为三路对照）。这是「AI 对齐自己」叙事的降温剂：**当前 AI-for-AI 只能做「既定策略的执行放大」，做不了「研究策略的自主发现」**——后者仍依赖人类研究者的判断力，与用户「判断力不可外包」的原则直接互证。https://arxiv.org/abs/2608.19072

- **Write, Execute, Refine: From Skill Followers to Skill Optimizers via RL from Execution Feedback——agent 自己写 skill 比不用还差 8-11 分，执行反馈驱动的技能优化器成为解药**（arXiv:2608.17587, 08-18 提交）: 一个反直觉的实证：**专家手写的自然语言 skill 能改善 tool-using agent，但 agent 自己写的 skill 比「不用任何 skill」还差 8-11 分**。核心洞见：**遵循程序性指导 ≠ 从执行证据改进它**——这是两种能力。推理时循环（inference-time loops）能修复 skill 本身，但不会改进「写下一条 skill 的模型」。WER 提出多阶段框架：在**冻结执行器之外**训练一个 Skill Optimizer——optimizer 提议 skill → 冻结 agent 重复执行 → 程序化 verifier 打分；分数提供相对信用并筛选混合结果记录；**匹配的成功/失败轨迹对构成下一阶段的细化状态**，让 optimizer 从「哪个 skill 步骤害了结果」中学到因果。信号含义：**技能（skill）作为「模型外知识」的优化闭环正在成型**——与 WER 同日出现，与 SPADE 的「环境即代码」、EvalCEGAR 的「指标即代码」共同指向 2026-08 的一个大趋势：**把训练/推理的辅助知识全部代码化、可执行化、可优化化**。https://arxiv.org/abs/2608.17587

### 推理与扩展

- **Test-Time Scaling in the Wild: Why Exploitation, Not Exploration, Is the Bottleneck——开放式任务首次 compute-normalized 对比五个 TTS 家族：探索端稳定有效，利用端全线失效**（arXiv:2608.18931, 08-19 提交）: TTS（测试时扩展）通过额外推理算力改进输出——生成多候选、搜索部分序列、迭代细化草稿。在数学和代码上收益巨大，但**这些技术几乎只在「验证容易」的任务上被测试**。本文是**首次**在五个开放式生成基准（医学/法律/金融/闲聊/创意写作）上、以计算归一化方式对比五个 TTS 家族的实证研究，统一框架把每种方法的 token 预算分解为**探索（exploration）与利用（exploitation）**两个维度。结论干净利落：**「探索」端有效——池中最佳候选的质量随算力投入稳定提升，五个基准无一例外；「利用」端是瓶颈——从候选池中选出/合成最终答案的环节随算力增加而失效**。第一性解释：开放式任务缺少可验证的 ground truth，「利用」环节的挑选/融合没有可靠的评分信号，只能靠模型自评——而模型自评（LLM-as-judge）本身不可靠（呼应 08-19 的 Judge-Retrieve-Abstain）。**TTS 的收益上限不由「生成更多」决定，而由「验证更准」决定**——这是 2026H2 推理经济学的核心命题。https://arxiv.org/abs/2608.18931

- **MoNe: Modular Neural Memory for Efficient Long Context Inference——挂接任意冻结 Transformer 的模块化神经记忆：128K 上下文计算与峰值内存双降 ~80%**（arXiv:2608.17616, 08-18 提交）: MoNe 是轻量模块化神经记忆，**无需重训练**即可挂接任意冻结的预训练 Transformer 实现长上下文推理。机制：测试时学习 fast-weight 神经记忆网络（层局部梯度更新），把上下文按固定大小分段读取；推理时记忆**仅从查询 token 生成 K/V，不再重读任何上下文 token**。两阶段设计把推理成本与上下文长度解耦：**O(N) 预处理 + O(1) 查询成本，峰值 GPU 内存不随 N 增长**。量化数据：128K tokens 下相比 ICL（in-context learning）**计算和峰值 GPU 内存均降约 80%，仅 6.4% 参数开销**；且泛化到远超 backbone 原生窗口的上下文，在 RULER 的 needle-in-a-haystack 与词提取基准上表现强（这些场景 ICL 直接失效）。信号含义：**长上下文的成本结构正在被「记忆外置 + 测试时学习」重构**——这与 KV cache 压缩（WhiteMatter，ai-frameworks 已收录）、HBF/ReRAM 近存（moe-hardware 组）是三条并行路径：架构层改 KV 产生方式、系统层改 KV 存储介质、**本文改 KV 的查询方式（把上下文变成可学习记忆而非缓存）**。https://arxiv.org/abs/2608.17616

### 蒸馏与能力整合

- **Open-MOPD: Diagnosing and Fixing Capability Imbalance in Multi-Teacher On-Policy Distillation——标准多教师蒸馏只捕获 35.6% 的能力集成空间，简洁任务严重退化**（arXiv:2608.19098, 08-19 提交）: 多教师 on-policy 蒸馏（M-OPD）通过 token 级密集奖励监督，把领域专精的 RL 专家整合为单一通才学生——是「专家合并」的蒸馏路线。但优化动力学长期缺乏受控研究，也没有可复现的公开配方。本文在 SmolLM3-3B-Base 上建立受控基准（用 oracle routing 把「能力整合」与「路由歧义」隔离），发现一个**显著的能力整合缺口：标准 M-OPD 只捕获相对 domain-routed oracle ensemble 可用 headroom 的 35.6%**，其中指令跟随等「简洁任务」遭受严重退化与过早停滞。失败根源指向 token 级监督的信号冲突——不同教师对不同任务的密集 token 级偏好相互干扰，学生在细粒度上「顾此失彼」。https://arxiv.org/abs/2608.19098

- **Beyond Teacher Likelihood: Group-Calibrated On-Policy Distillation for Long-Context Reasoning——长上下文暴露 teacher-verifier 分歧，分组校准弥合蒸馏与验证的鸿沟**（arXiv:2608.19181, 08-19 提交）: on-policy 蒸馏（OPD）用更强教师的 token 级密集指导训练学生。但在**长上下文任务**中，token 级教师支持会偏向「局部看似合理」的响应——遗漏分散在长输入中的证据、违反全局任务约束；而 task-specific verifier 在响应级评估、返回反映部分成功的分级奖励。本文在两类代表性长上下文证据聚合任务上诊断出：**输入越长，轨迹级 OPD 分数与 verifier 奖励越不对齐（teacher-verifier disagreement 随上下文长度扩大）**。GC-OPD 的解法：在分组内分别归一化 verifier 奖励与轨迹级 OPD 分数，把两种信号放到可比尺度再融合——**token 级信号（局部流畅）与响应级信号（全局正确）的分歧，是长上下文蒸馏失败的机制根源**。https://arxiv.org/abs/2608.19181

### 评测与安全

- **Grading the Graders: Verification Autonomy Levels (L0-L5) for LLM Reasoning——验证文献的「level」一词至少指五种不同东西，VAL 元标准给出单一轴分类**（arXiv:2608.19009, 08-18 提交）: LLM 越来越常配验证器（步骤检查器、self-consistency 过滤器、工具事实检查器、形式证明助手），但**验证文献中「level」至少被用于五种不同含义**：验证粒度、概念抽象、风险 tier、系统栈层、ground truth 的认识论来源。VAL 提出沿单一轴分类的元标准——**验证规范从哪来、判定保证什么**：L0（LLM 自声明，无确定性锚点）→ L1/L2（客观 ground truth，仅保证正确性）→ L3/L4（可判定系统，单属性或域级完备），**L5 在无限制情形下不可能**。核心概念是完备性边界（completeness boundary）：任何验证方案能保证什么、不能保证什么，必须在设计时显式声明。信号含义：这是「评测基础设施形式化」浪潮的最新一块——与 08-19 的 TokEval（tokenizer 评测）、Judge-Retrieve-Abstain（可证明风险保证）共同把「验证」从实践技巧变成**有公理的学科**。https://arxiv.org/abs/2608.19009

- **Metrics That Write Themselves: Evolving an Evaluator from Its Own Blind Spots（EvalCEGAR）——「说好难，指错易」：用程序验证的 CEGAR 循环进化评测器**（arXiv:2608.18744, 08-18 提交）: 起点问题：agent 在可靠的自动指标下改进快、没有指标就停滞；而最需要指标的领域（报告生成）恰恰没人知道怎么打分。**指标能自己写吗？**本文的答案架构很妙：既然「说什么让答案好」难、「指出某个答案哪里错」容易，那就把指标进化成**一池小型 Python 算子**——每个算子标记一个命名缺陷或弃权，然后投票。直接让模型写算子失败：**183 个候选只实现 96 种不同行为，且全部来自巨大算子空间的同一狭窄区域**（模型生成多样性幻觉）。EvalCEGAR 借程序验证的 **counterexample-guided abstraction refinement**：把算子池视为对「好答案集合」的抽象，搜索碰撞——**两个得分相同的答案，一个正确一个错误**；这对碰撞（而非 prompt）就是「创作请求」，驱动新算子补齐盲区，循环细化。https://arxiv.org/abs/2608.18744

- **SMTrap: Cost-Effective DoS Attacks Against Large Reasoning Models via SMT Conflict Guidance——推理深度被武器化：CPU 级成本放大目标模型算力消耗的 DoS 新范式**（arXiv:2608.18921, 08-19 提交）: 现有 LRM-DoS（大型推理模型拒绝服务攻击）方法高度依赖模型反馈——重复查询目标模型或训练专用攻击模型来合成攻击查询，**昂贵且削弱攻击杠杆**。SMTrap 提出 **search amplification（搜索放大）**：一种无模型反馈范式，用 SMT（Satisfiability Modulo Theories）求解器的 **conflict count 作为低成本外部信号**，指导合成推理密集的 CSP（约束满足问题）实例。关键观察：**LRM 解 CSP 时依赖 trial-and-backtracking 搜索，SMT conflict count 越高的实例 → LRM 回溯搜索越多 → 输出轨迹越长**——攻击者可以用 CPU-only 的轻量工具，低成本制造「推理黑洞」查询，放大目标模型的算力消耗。信号含义：推理模型（reasoning model）把「思考时间」变成商品化算力成本，**攻击面随之从「输出内容安全」扩展到「输出长度经济学」**——这为 DoS 防护（响应长度上限、推理预算门控）提出了新的第一性需求，与 RLVR/推理成本控制形成攻防两面。https://arxiv.org/abs/2608.18921

## 📌 今日信号

**信号 1 — AI-for-AI 的「策略级缺口」：三篇同日论文互相印证，自主研究的最后一道壁垒仍是判断力**。2608.19072（后训练实证）发现 agent 的训练策略在开局即锁定、预算全花在执行级微调；2608.17587（WER）发现 agent 自写 skill 比不用还差 8-11 分；2608.19098（Open-MOPD）发现多教师蒸馏只捕获 35.6% 能力空间。三篇独立工作从「后训练」「技能生成」「专家整合」三个角度指向同一结论：**当前 LLM 能做好「既定范式内的执行放大」，做不好「范式选择与策略修订」**。第一性拆解：执行级能力的反馈信号是**局部、密集、可归因**的（token 级 reward、单次执行成功与否）；策略级能力需要的反馈信号是**全局、稀疏、跨实验**的（换一个训练方法是否整体更好），后者恰恰是当前 RL 信号结构最弱的部分——**不是模型不够聪明，而是「策略选择」缺乏可用的监督信号**。对用户「判断力/第一性原理不可外包」原则的技术注脚：**在策略级反馈信号被工程化之前，AI 自动化只能停在工作流执行层，研究决策层仍需人脑**。这也解释了为何 2608.19072 的递进干预实验中「经验增强」有效而「策略修订」停滞——经验丰富执行、判断需要信号结构。

**信号 2 — TTS 经济学的拐点：开放式任务的「利用瓶颈」把验证基础设施推上 C 位**。2608.18931 的结论值得反复咀嚼：五个开放式基准上，探索端（生成更多候选）随算力稳定提升，利用端（从池中挑选/融合）全线失效。这意味着：**在可验证任务上（数学/代码），TTS 的边际收益由「生成量」决定；在开放式任务上，TTS 的边际收益由「验证质量」决定**——继续砸推理算力而不解决验证，收益会撞墙。这与本批的 VAL（验证自治级别元标准）、EvalCEGAR（指标自进化）、08-19 的 Judge-Retrieve-Abstain（不确定性门控裁判）构成完整的因果链：**TTS 撞墙 → 验证成为瓶颈 → 验证本身被形式化/自动化/自进化**。「验证基础设施」正在从评测论文的学术话题，变成决定推理成本-质量曲线的**工程变量**——对推理服务商的含义：谁先把「可靠验证器」做成可插拔组件（模型路由器里的 judge 服务），谁就能在开放式场景拿到 TTS 的增量红利。与 08-20 信号 2（评测颗粒度下沉）共振：评测基础设施细化 + 验证器服务化，是 2026H2 最值得跟踪的工程趋势之一。

**信号 3 — 蒸馏范式分裂：token 级（局部流畅）与响应级（全局正确）的信号冲突成为模型压缩的新瓶颈**。Open-MOPD（35.6% headroom 缺口）与 GC-OPD（teacher-verifier 分歧随上下文扩大）从两个侧面暴露同一机制：**token 级密集监督在长上下文/多任务场景会系统性偏向局部最优，与全局正确性冲突**。第一性分析：token 级信号的信用分配天然「近视」——它奖励每一个局部合理的 token，却看不见「这段证据没被引用」「这个全局约束被违反」这类跨 token 的结构性错误；响应级 verifier 能看见，但信号稀疏、难以训练。GC-OPD 的分组归一化是「调和两级信号」的工程折中，而 Open-MOPD 证明纯 token 级路线有硬上限。**蒸馏正在从「单一信号源」走向「多信号源校准」**——这与 MoE 专家整合（Open-MOPD 同源）、小模型追赶大模型（蒸馏是主要手段）直接相关：模型压缩的下一步竞争不在算法细节，而在**信号融合架构**。

**信号 4 — 推理深度成为双向武器：SMTrap 把「思考时间」变成攻击放大器**。SMTrap 的威胁模型值得基础设施侧认真对待：推理模型（LRM）的核心卖点是「想得久」，而 SMTrap 用 CPU-only 工具合成高 conflict CSP 实例，**把目标模型的推理预算消耗放大到极致**——攻击者花 1 分 CPU 成本，目标模型烧 N 分 GPU 算力。第一性看，这是「推理经济」的暗面：**当模型把算力花在试错搜索上，攻击者只需操纵「搜索的艰难程度」**。SMT conflict count 与 LRM 回溯深度的正相关，本质上是**问题难度与推理深度的可预测映射**——攻击者免费获得了「推理深度控制器」。防护侧的含义：① 响应长度上限/推理预算门控不再是可选项（尤其 API 计费场景）；② 异常长轨迹检测（per-query 推理时间/输出长度基线）应成为推理服务的标准监控项；③ 与 08-20 的 Load Hijack（TTFT 放大）并列，**推理侧 DoS 正在形成「输入构造 → 算力放大」的通用攻击工具箱**。对超节点/推理集群设计者：多租户推理服务的算力隔离策略需要把「恶意长推理」纳入配额模型。

**信号 5 — 内容污染 + 质量事故双杀：35% 网页 AI 作者 + Grok 乱码，「AI 互联网」的自我指涉风险进入可量化阶段**。Pew 数据（35% AI 作者网页、.com 是 .edu/.gov 的 10 倍）与 Cloudflare 的「机器人流量超人类」里程碑拼出完整图景：**人类写的内容在被 AI 写的内容稀释，而浏览这些内容的流量本身也在被机器人稀释**——「bots reading web pages written by other bots」。这个自我指涉结构有两个深层后果：① **数据飞轮污染**：下一轮模型训练语料中 AI 生成内容的占比持续上升，模型在「自己写的文本」上继续训练——合成数据的比例失控风险（模型坍缩的宏观版本）从论文假设变成统计事实；② **信任稀释**：Grok 乱码事故（PDF 生成触发幻觉性乱码 + 幻觉引用）是「模型输出可信度」在消费端的又一次公开打折，与昨日 Pew 52% 担忧率互相喂养。对基础设施侧的第一性含义：**「数据真实性」正在变成算力基础设施的上游约束**——内容来源标注、合成数据过滤、训练语料配比治理，将与算力/互联/存储并列成为 AI 基础设施的第五个维度。谁先建立「可信数据供应链」（publisher 签名、来源校验、合成数据登记），谁就在下一轮模型质量竞争中占据语料侧优势。
