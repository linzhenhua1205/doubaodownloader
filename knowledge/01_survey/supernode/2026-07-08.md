## 🔴 1️⃣ NVIDIA Kyber 机架（NVL144）被曝延迟至 2028 年——PCB 中板问题 + 中间方案被客户否决

- **来源**: [Tom's Hardware](https://www.tomshardware.com/tech-industry/artificial-intelligence) (Luke James, 2026-07-06) / SemiAnalysis
- **分类**: 🏭 超节点方案 / 厂商路线图
- **原文标题**: 「Nvidia's Kyber rack for Rubin Ultra reportedly delayed to 2028, stopgap solution also axed due to customer pushback — Analyst firm SemiAnalysis says PCB midplane problems led to the delay [Updated]」
- **关联上游**: DIGITIMES (2026-07-07): "Rumored Kyber delay seen to have limited impact on Nvidia's long-term rack upgrade; Nvidia denies rumor"

### 核心事实

| 维度 | 详情 |
|:-----|:------|
| **产品** | NVIDIA **Kyber NVL144** 机架系统（Rubin Ultra 的参考机架方案） |
| **原定时间** | 此前 GTC 2026（2026年3月）公开演示 Rubin Ultra tray，目标 **2027 年** 出货 |
| **新时间** | 据 SemiAnalysis 报道 **推迟至 2028 年**——延迟超 **12 个月** |
| **延迟原因** | **PCB midplane 问题**（PCB 中板/背板设计制造困难） |
| **中间方案（取消）** | 曾考虑过渡性方案但被**客户否决**（因客户不愿为短期方案投入验证） |
| **NVIDIA 回应** | DIGITIMES 7/7 报道 NVIDIA 否认该传闻或认为影响有限 |
| **报道日期** | Tom's Hardware: 2026-07-06 · DIGITIMES: 2026-07-07 |

### PCB Midplane 问题的技术根源

Kyber NVL144 机架的设计挑战根源在于 SemiAnalysis 此前报道的 **Rubin Ultra 从 4-die 降至 2-die**（参见 [6/30 报道](2026-06-30.md)）之后的架构连锁反应：

```text
原方案 (取消):          新方案 (延迟):
+--------------+       +--------------+
| Rubin Ultra  |       | Rubin Ultra  |
| 4 compute die|  ->    | 2 compute die|
| 16 HBM4E     |       | 8 HBM4E      |
+--------------+       +------+-------+
                              |
                    +---------v---------+
                    | Kyber NVL144       |
                    | PCB midplane 问题  |
                    | -> 信号完整性/电源  |
                    |   完整性验证失败    |
                    +-------------------+
```

| 技术挑战 | 说明 |
|:---------|:------|
| **PCB 层数激增** | NVIDIA Kyber 机架级背板需要在单一 PCB 上承载 **144+ GPU 的 scale-up 网络**（NVLink），信号完整性约束迫使 PCB 层数和复杂度远超 NVL72 |
| **电源完整性** | 600kW 级机架的供电分配在 PCB midplane 上面临巨大 IR drop 和热管理挑战 |
| **SI 收敛困难** | 144 GPU 之间的 NVLink 拓扑需要大量高速 SerDes 走线，层叠串扰和损耗导致 eyemask 闭合 |
| **可制造性** | 超大尺寸 + 超高层的 PCB 良率在经济规模下无法达标 |

### 延迟的超节点影响

| 影响维度 | 分析 |
|:---------|:------|
| **NVIDIA 路线图缺口** | Kyber NVL144 延迟至 2028 → 2027 年 NVIDIA 机架级方案仅剩 **GB300 NVL72**（非 Rubin 代际）→ Rubin 架构的规模优势（600kW/rack 级别）延迟兑现 |
| **AMD MI500 窗口机会** | AMD Advancing AI 2026（7/22-23）即将发布 MI500 系列 → Kyber 延迟给 AMD 一个 **12-18 个月的机架级竞争窗口** |
| **客户锁定风险** | 中间方案被客户否决说明大客户（微软/Meta/谷歌）不愿为短期过渡方案投入 → 可能推动客户加速**自研互联/机架方案**（如 Meta 的 MTIA 集群、谷歌 TPU v6 pod） |
| **液冷部署节奏调整** | 600kW 液冷机架延迟 → 2027 年超节点液冷部署仍以 GB300 NVL72（~140kW）为主力，800V DC busbar 量产时间线同步推迟 |
| **OEM/ODM 影响** | 纬颖/Wistron/Foxconn 等 Kyber 供应链的营收预期需下调；原定 2027 年放量的 Kyber 液冷机架产能被推迟 |

### DIGITIMES 视角

DIGITIMES 2026-07-07 的分析标题为 **"Rumored Kyber delay seen to have limited impact on Nvidia's long-term rack upgrade; Nvidia denies rumor"**，这一叙事角度的潜在含义：

| 解读方向 | 含义 |
|:---------|:------|
| **NVIDIA 官方否认** | 公司否认延迟传闻，或认为市场过度反应 |
| **"有限影响"** | 即使 Kyber 延迟，NVIDIA 的 **GB300 NVL72 产品线仍在正常出货**，客户需求可被现有 Blackwell 方案满足 |
| **长期升级路径** | Kyber 虽然延迟，但 Rubin 架构（双芯片方案 + HBM4E 1TB/socket）的技术方向不变，2028 年 Kyber 仍将是 600kW 级机架的标杆 |
| **DIGITIMES 供应链信号** | 台湾供应链消息源暗示 Kyber 并未完全取消，但时间线调整已在进行 |

### 历史对标

此前 NVIDIA 同样遭遇过 **Blackwell (B200/B100)** 的延迟问题（2024年8月报道），但最终在 2024Q4-2025H1 解决了产量爬坡。此次 Kyber 延迟的恢复时间取决于：

1. **PCB midplane 的 SI/PI 收敛周期**（通常 6-9 个月，多轮 tape-out）
2. **中间方案的替代性**（如 NVL72×2 双机架方案是否足够？）
3. **客户耐心**（如果大客户加速自研，Kyber 的价值主张会被削弱）

## 🟢 2️⃣ 英国数据中心获"国家重要性"地位——可绕过地方规划法规，审批缩短一年

- **来源**: Tom's Hardware (Jowi Morales, 2026-07-07)
- **分类**: 🔧 超节点选址 / 法规 / 国际对比
- **原文标题**: 「UK gives data centers option to apply for 'national importance' status that overrides local regulations, cuts timeline by a year」

### 核心事实

| 维度 | 详情 |
|:-----|:------|
| **政策** | 英国政府允许数据中心申请 **"国家重要性"（national importance）** 地位 |
| **效果** | 获得该地位后：**可绕过地方规划法规**，审批时间**缩短一年** |
| **背景** | Tom's Hardware 直接对比：**"Local opposition has caused massive delays for data centers in the U.S."** |
| **对标** | 这与美国全美 **69 个辖区实施数据中心禁令、社区阻力持续升级** 的趋势形成鲜明对比 |
| **报道日期** | 2026-07-07 |

### 政策对比：英美数据中心审批模式

| 维度 | 🇬🇧 英国 | 🇺🇸 美国 |
|:-----|:---------|:---------|
| **顶层定位** | 数据中心 = **国家战略基础设施**，可获"国家重要性"地位 | 数据中心 = **商业开发项目**，受地方 zoning 法规约束 |
| **审批层级** | 中央（国务大臣）可直接审批，绕过地方议会 | 完全由地方（县/市议会）决定，联邦基本不介入 |
| **社区话语权** | 被"国家重要性"裁定覆盖 | 社区可通过听证会/诉讼/公投阻止项目（弗吉尼亚支持率 69%→35%） |
| **典型周期** | ~12-18 个月（加速后） | 18-36 个月，部分项目被无限期延迟 |
| **案例结果** | 待观测 | 69 辖区禁令 / Digital Gateway 死亡 / Wisconsin 集体诉讼 |

### 对超节点部署的影响

| 影响维度 | 分析 |
|:---------|:------|
| **选址格局变化** | 英国政策可能被其他面临 AI 基础设施短缺的国家效仿（如法国/德国/新加坡），形成"数据中心基建优先"的政策阵营 |
| **加速海外布局** | 美国选址困难持续 → 更多超节点部署转向政策友好的国家/地区（英国、印尼 Batam、中东） |
| **中国模式** | DIGITIMES 同日分析标题 **"AI's bottleneck has shifted from chips to infrastructure — China plans it centrally, US fights it out locally"** ——中国的中央统一规划 vs. 美国的地方各自为战，英国选择接近中国模式（中央定调 > 地方审批） |
| **对 NVIDIA 资本伙伴计划的影响** | Firmus Batam（印尼 360MW）和 Sharon AI（主权 AI）的选址策略被双重强化：**避开美国地方阻力 + 选择政策友好区域** |
