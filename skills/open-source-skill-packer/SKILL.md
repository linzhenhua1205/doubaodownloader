# Open Source Skill Packer

将整个GitHub压缩成你自己的超级技能库。

## 核心方法论

**"你的需求，永远不是世界上第一个提出的，也绝对不是最后一个。"**

互联网三十年，开源世界大神辈出，绝大多数需求都已有现成解决方案。Skill化让这些经过时间检验的项目，成为Agent可调用的能力。

## 完整流程

### 阶段1：需求分析

明确用户的核心需求，用自然语言描述：
- 需要解决什么问题？
- 使用场景是什么？
- 期望的输入输出是什么？

### 阶段2：开源项目搜索

使用AI搜索GitHub上的开源项目：
- 搜索关键词：功能描述 + "github open source"
- 筛选标准：
  - Star数 > 100（社区认可）
  - 发布时间 > 3个月（稳定成熟）
  - 文档完善（README清晰）
  - 近期有更新（活跃维护）

### 阶段3：项目评估

评估项目是否适合Skill化：
- **稳定性**：经历足够多用户测试
- **易用性**：是否有CLI接口、API、或可脚本化
- **安全性**：是否有已知漏洞、权限要求
- **可移植性**：依赖是否复杂、环境要求

### 阶段4：Skill封装

按标准Skill结构封装：

```
skill-name/
├── SKILL.md          # 技能定义与使用说明
├── _meta.json        # 元数据（可选）
├── scripts/          # 可执行脚本
├── templates/        # 模板文件
├── references/       # 参考文档
└── assets/           # 静态资源
```

**封装要点：**
- 将命令行工具封装为自然语言接口
- 提供清晰的输入输出定义
- 处理异常情况和错误提示
- 添加环境配置说明

### 阶段5：首次运行验证

首次运行时：
- 安装必要依赖
- 配置环境变量
- 测试基本功能
- 记录遇到的问题和解决方案

### 阶段6：迭代优化

将首次运行的经验更新到Skill：
- 添加缺失的依赖说明
- 优化配置流程
- 修复发现的问题
- 固化成功路径

## 安全原则

- 只封装知名、可信的开源项目
- 审查脚本的网络请求和文件访问
- 不硬编码敏感信息（走环境变量）
- 首次运行使用review模式

## 产出

- 完整的Skill目录结构
- SKILL.md使用说明文档
- 可执行脚本（如有需要）
- 依赖和环境配置说明
- 测试用例和验证方法

## 使用建议

1. 构建Skills时使用强推理模型（如GPT 5.2 Codex）
2. 首次运行时使用详细模式，记录问题
3. 运行成功后将经验固化到Skill中
4. 定期检查开源项目更新，同步升级Skill
