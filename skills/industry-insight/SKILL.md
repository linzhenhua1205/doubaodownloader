# 行业洞察技能 (Industry Insight)

> 以「五看三定」方法论为核心，将一个技术/行业领域从技术原理到商业化落地全链路拆解清楚，并以**专题化方式**在 `knowledge/07_industry-research/` 下建立持续跟踪体系。

---

## 核心方法论：五看三定

### 五看 (Five Looks)

```
                       五看体系
                          │
      ┌──────────┬───────┼───────┬──────────┐
      │          │       │       │          │
  看宏观      看市场    看竞争   看自身     看机会
  (行业)     (客户)    (对手)   (能力)     (收拢)
```

| 看 | 分析维度 | 核心问题 |
|:---|:---------|:---------|
| **① 看宏观/行业** | PESTEL 分析、技术成熟度、政策法规、产业链结构 | 这个行业当前处于什么阶段？政策和宏观环境如何？ |
| **② 看市场/客户** | TAM-SAM-SOM、客户画像、需求分析、痛点洞察 | 市场有多大？客户最痛的是什么？愿意为什么付费？ |
| **③ 看竞争** | 竞争格局、替代品威胁、竞品对比、护城河分析 | 谁在做了？做得怎么样？我们的差异化在哪？ |
| **④ 看自身** | 核心能力、资源禀赋、技术壁垒、团队优势 | 凭什么我们能做？有什么独特优势？ |
| **⑤ 看机会** | SWOT 汇总、机会窗口、优先级排序、切入策略 | 综合以上，最值得做的 3-5 个机会是什么？ |

### 三定 (Three Decisions)

```
           ┌──────────────┐
           │ ① 定战略     │ ← 赛道选择、定位、愿景
           ├──────────────┤
           │ ② 定目标     │ ← 阶段性目标、可量化指标
           ├──────────────┤
           │ ③ 定策略     │ ← 落地路径、执行计划、监控体系
           └──────────────┘
```

| 定 | 内容 | 输出 |
|:---|:-----|:-----|
| **① 定战略** | 赛道选择、价值主张、战略定位 | 1 句话战略定位 |
| **② 定目标** | 阶段性里程碑、商业化指标 (GMV/用户数/市占率/ROI) | 目标指标体系 (含基线值) |
| **③ 定策略** | 落地路径、时间线、资源需求、风险应对、监控方案 | 执行路线图 + 监控仪表盘 |

## Phase 1：技术深潜（原理 × 演进路径）

从第一性原理出发，深度解析技术原理和演进路径。

### 1a — 技术原理深度解析

按**技术栈分层**拆解，每层回答：

```
┌────────────────────────────────────┐
│  Layer N: 应用层                   │
│  ├─ 原理: 核心机制是什么？          │
│  ├─ 关键指标: 带宽/延迟/功耗/成本   │
│  └─ 物理极限: 为什么有天花板？       │
├────────────────────────────────────┤
│  ...                               │
├────────────────────────────────────┤
│  Layer 0: 物理层                    │
│  ├─ 原理: ...                      │
│  └─ 物理极限: ...                  │
└────────────────────────────────────┘
```

**关键原则**：
- **回到物理极限**：这项技术的根本限制是什么？（光速/功耗/信噪比/材料特性）
- **定量分析**：每个原理必须有量化指标（数值 + 单位 + 对比基线 + 条件）
- **对比参照**：与相邻技术方案做同维度对比

### 1b — 技术演进路径分析

从历史到未来的演进轨迹：

| 阶段 | 代际 | 关键指标 | 标志性产品/标准 | 驱动因素 |
|:-----|:-----|:---------|:---------------|:---------|
| 萌芽期 | Gen 0 | — | — | — |
| 成长期 | Gen 1 | — | — | — |
| 成熟期 | Gen 2 | — | — | — |
| 收敛期 | Gen 3+ | — | — | — |

**分析要点**：
- 每代之间的**关键转折点**是什么？（技术突破/成本拐点/标准统一）
- 当前处于什么阶段？**S 曲线**上的位置？
- 下一代的**工程挑战**和**可能突破方向**

### 1c — 技术成熟度评估

| 维度 | 评估 | 依据 |
|:-----|:-----|:------|
| TRL (技术就绪度) | 1-9 | 论文/原型/商业产品/大规模部署 |
| 生态成熟度 | 萌芽/成长/成熟/饱和 | 供应商数量/标准完整度/人才供给 |
| 成本下降曲线 | 当前$/GB → 目标$ | 历史成本下降率 (learning curve) |

## ⚠️ 零产出自愈与源发现机制

### 问题

每日行业调研中，以下故障模式导致 `web_fetch` 无法获取有效信息：

| 故障模式 | 典型场景 | 根因 |
|:---------|:---------|:------|
| **搜索引擎污染** | Bing 英文搜电源架构→中文AI工具站/百科 | SEO 垃圾内容淹没技术源 |
| **反爬/验证码** | Baidu 验证码拦截、OCP HTTP 403 | 源站反爬策略 |
| **付费墙** | DIGITIMES / IEEE Spectrum 内容需订阅 | 商业内容保护 |
| **源内容陈旧** | IEEE 仅返回2023年旧文 | 非持续更新的专题源 |
| **关键词过窄** | 特定产品名+品牌名无结果 | 关键词过于精确 |

### 自愈工作流（执行跟踪时强制触发）

当 `web_fetch` 对一个专题的全部给定源返回空/无效结果时，使用行业调研统一跟踪器触发自愈：

```bash
# Step 1: 检查源可靠性状态
python3 scripts/industry-research-tracker.py registry --status

# Step 2: 触发源发现
python3 scripts/industry-research-tracker.py discover --topic <专题名>

# Step 3: 查看推荐搜索计划（含发现的新源）
python3 scripts/industry-research-tracker.py plan --topic <专题名>
```

### 源可靠性数据库

自动记录在 `tmp/source-registry.json`。每次 `web_fetch` 成功后应当记录：

```python
# 成功时记录
# record_source_result('<topic>', '<source_name>', True)
# 失败时记录
# record_source_result('<topic>', '<source_name>', False)
```

**自动降级规则**: 连续 3 次失败 → 该源自动降一级（A→C, B→D），降级后自动发现替代源。

### 跨专题源共享（自动）

如果一个源的某个专题成功率高，系统会自动推荐给其他专题。例如电源架构源全部失效→自动发现云原生 AI 专题中成功率 100% 的 cncf-blog/k8s-blog/techcrunch。

### 零产出占位文件规范

每次搜索即使零产出也必须创建占位文件：

```markdown
## 📋 搜索摘要（无新增内容）
- **执行时间**: YYYY-MM-DD HH:MM
- **搜索源**: [源1: 状态] [源2: 状态] [源3: 状态]
- **搜索词**: xxx
- **结论**: 未发现值得归档的有效信息
- **上次有产出日**: YYYY-MM-DD
```

### 中断恢复（session 断裂恢复）

如果定时任务运行中 session 断裂导致任务状态不明，执行：

```bash
# 查看 tmp/ 下的中间文件确定执行状态
ls -la tmp/industry-tracker-*-<日期>.json
# 汇总
python3 scripts/industry-research-tracker.py summary --date <日期>
```

- `industry-research-tracker.py` — **行业调研统一跟踪器** (usage: 见上方"零产出自愈与源发现机制")

  - 输出文件名: `tmp/source-registry.json` (持久化数据库) + `tmp/industry-tracker-<topic>-<date>.json` (单次中间文件)

- `research_task_runner.py` — **调研定时任务统一执行器**（39 个定时调研任务的标准入口，规则全部内建）
  - 子命令: `guide` / `plan` / `register` / `scaffold` / `verify` / `placeholder` / `update-log` / `check-gap` / `list`
  - 定位: 把 tasks.json 任务描述中的规则（源发现/源可靠性/文档质量/内容丰度/生成格式/输出校验/token管理/占位/index-log）下沉到脚本，任务描述只保留 `guide --task <id|任务名>` 引用
  - 内建规则: 每源仅1次抓取·失败跳过·读前30行·输出≤15KB·每条含来源URL·每专题最低发现数·零产出占位·日志自动归档到 knowledge/log.old.md（01_survey 不再维护分布式 index/log，2026-08-19 起）·**专题独立输出硬规则**
  - 任务配置: **独立于脚本**，存放于 `configs/research_topics.json`（39 任务：3 大组 + 36 单主题，含搜索源/输出路径/丰度阈值；改配置无需改脚本，支持按任务名匹配 ID 防 ID 漂移）
  - **观点维度（v1.6）**: 三大组任务新增观点收集 section（服务器行业技术观点/服务器供应链观点/AI最新技术业界观点/服务器商业观点）；plan 输出观点采集规范（来源分级：行业专家>顶级媒体>顶级会议；**正反两面辨析**；时效优先近3日）；scaffold 观点 section 用辨析格式模板；verify 增加观点双向校验（含正反标记）
- `configs/research_topics.json` — **调研主题配置**（SSOT）：任务ID → 搜索源/输出路径/丰度阈值；覆盖服务器/交换机产销研、算力平台、运维平台、AI全栈；**每个专题输出到各自独立目录**（组任务→industry-research/<group>/），禁止共享文件
