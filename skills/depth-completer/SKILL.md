# 深度完善器（Depth Completer）

> **核心诊断标准**：**"框架堆名词不深入原理=不合格"**（来自 AGENT.md 自检清单）。
>
> 一个文档是否真正"有深度"，不在于它覆盖了多少个模块、引用了多少个名词，
> 而在于对**每一个关键断言**是否做了：原理溯源 → 量化支撑 → 边界条件分析 → 对比基线。

## 概述

```
输入：浅层文档（名词堆叠、缺原理分析、断言无推导）
 ↓
深度诊断 → 找出"最浅的 N 个点"
 ↓
知识挖掘 → 从知识库 + 在线资源补充原理深度
 ↓
输出：深度补齐后的文档 + 深度完善报告
```

## 深度诊断框架：六维深度评分 × 五层管道映射

六维深度评分与五层管道框架的映射关系：

| 维度 | 含义 | 主检层 | 对应失效类 | 权重 |
|:-----|:-----|:------:|:-----------|:----:|
| **D1-原理溯源** | 追溯到物理/数学/信息论"为什么" | L3+L4 | G1幻觉+H1逻辑谬误 | 25% |
| **D2-量化支撑** | 数值+单位+对比基线+条件 | L1+L4 | F2假精确+H4数值失效 | 25% |
| **D3-对比基线** | 明确"和什么比" | L2+L4 | E1方向锁定+H6虚假二分 | 15% |
| **D4-边界条件** | 适用范围和限制 | L5 | I2过度自信 | 15% |
| **D5-推导链条** | A→B完整推理链可追溯 | L4 | H3步骤遗漏 | 10% |
| **D6-来源质量** | 论文/标准>白皮书>博客 | L1 | F1来源不可靠+G5来源编造 | 10% |

### 深度评分公式（扩展为层感知评分）

```
总体深度分 = Σ(维度分 × 权重)
其中维度分 = 0（无） / 1（有痕迹） / 2（部分满足） / 3（完整满足）
深度评级：≥2.5 优秀 / 2.0-2.4 达标 / 1.5-1.9 需补齐 / <1.5 不合格

层深度分 = 该层相关维度的加权平均
层平衡度 = 1 - (各层深度分的标准差 / 最大层深度分)
          层平衡度 ≥ 0.7 = 平衡 / 0.4-0.7 = 有失衡 / <0.4 = 严重失衡
```

### 层平衡检测（对抗方向锁定 E1 + 过早收敛 H2）

方向锁定的深度症状：**在某一层过度深挖而牺牲了其他层的必要深度**。

| 失衡类型 | 表现 | 示例 |
|:---------|:-----|:------|
| **L1过深** | 来源追溯精确到每条数据，但缺乏原理理解 | 每条数据标出处但不知为什么重要 |
| **L3过深** | 概念原理剖析极深但缺乏量化支撑 | 深入解释CXL协议但没说带宽延迟 |
| **L4过深** | 逻辑链条完整但边界条件缺位 | 推导链无懈可击但没说明适用范围 |
| **L2过浅** | 格式完美结构清晰但内容毫无深度 | TOC/格式都合规但全是名词堆叠 |

**检测方法**：
```
① 对文档每层独立评分（L1-L5各给1-5分）
② 计算各层分数标准差
③ 某层≥4且另一相关层≤2 → 标记深度失衡
④ 整体在某方向极深且其他方向极浅 → 标记方向锁定
⑤ 给出层平衡修正建议（优先补齐最低分层的深度）
```

## 使用方法

## 使用方法

### 快速诊断

```bash
# 对单个文件的六维深度评分
python3 <base_dir>/scripts/tools/depth_score.py <文件路径>

# 详细诊断报告
python3 <base_dir>/scripts/tools/depth_score.py <文件路径> --verbose

# 批量扫描目录
python3 <base_dir>/scripts/tools/depth_score.py <目录> --summary
```

### 完整补齐流程

#### 步骤 1：深度诊断

运行脚本获取六维评分，定位最弱的2-3个维度（得分最低的就是最需要补齐的地方）。

#### 步骤 2：按维度补齐策略

根据诊断结果，选择对应的补齐策略：

| 诊断结果 | 补齐策略 | 核心动作 |
|:---------|:---------|:---------|
| **D1 原理溯源不足** | 🔄 **原理深潜** | ① 识别核心名词 → ② 搜索论文/标准中的原理定义 → ③ 用第一性原理解释"为什么"（物理/数学/信息论层面） → ④ 附对比基线 |
| **D2 量化支撑不足** | 📊 **数据挖掘** | ① 找出所有"定性断言" → ② 搜索量化数据（优先论文/白皮书） → ③ 补充数值+单位 → ④ 标注来源和测试条件 |
| **D3 对比基线不足** | ⚖️ **对比补齐** | ① 列出所有"最优/最强/最佳"类断言 → ② 确定隐含的对比对象 → ③ 补充至少2个平行方案 → ④ 说明为什么选定方案更好 |
| **D4 边界条件不足** | 🧩 **边界扫描** | ① 找所有"适用于/适合/支持"类断言 → ② 追问"什么场景不适用" → ③ 补充量化阈值 → ④ 添加局限性声明 |
| **D5 推导链不足** | 🔗 **链式补齐** | ① 找出"跳跃断言" → ② 补全中间环节 → ③ 标注每一步的支撑来源 → ④ 检查是否有隐藏假设 |
| **D6 来源质量不足** | 📚 **来源升级** | ① 按来源优先级扫描当前引用 → ② 对低质量来源找替代（博客→白皮书→标准→论文） → ③ 补充DOI/URL/发布日期 → ④ 标注取材时效性 |

#### 步骤 3：来源优先级挖掘

深度补齐的核心在于获取高质量信息。按以下优先级搜索：

```
P0: 论文原文 / 国际标准文档（IEEE / IETF / JEDEC / PCI-SIG / CXL Consortium）
P1: 芯片厂商官方白皮书 / Datasheet（Intel / NVIDIA / AMD / Broadcom / Marvell）
P2: 一线工程报告 / 开源项目文档 / 内核代码注释
P3: 行业分析 / 技术博客 / 问答
P4: 通用知识（可外链化，不需要深挖）
```

从知识库中已经沉淀的内容优先使用：

```bash
# 从知识库搜索相关深度内容
python3 <base_dir>/scripts/tools/depth_score.py <文件> --mine-kb knowledge/

# 搜索特定领域深度内容
python3 <base_dir>/scripts/tools/depth_score.py <文件> --search-topic "信号完整性" --kb-only
```

#### 步骤 4：输出补齐后的文档

补齐原则：
1. **不是"增加篇幅"**，而是**替换浅层内容为深层内容**（总篇幅不一定增加）
2. **保持结构**：不破坏原有框架，只在薄弱点深钻
3. **保留作者判断**：AI 补充的是"支撑材料"，最终判断权归用户
4. **标记新增内容**：用 `>[!INFO]` 标注 AI 补充的来源深度内容

## 高频浅层模式与应对

| 浅层模式 | 典型句式 | 深度要求 | 补齐方法 |
|:---------|:---------|:---------|:---------|
| **名词堆叠** | "支持全链路优化、智能调度、弹性伸缩" | 每个术语解释具体实现机制 | 选一个最关键的深挖，其余外链 |
| **模糊定性** | "性能有显著提升" | 量化提升幅度+测试条件 | 搜索同类对比的实测数据 |
| **忽略代价** | "X 是最优方案" | 列出 X 的前置条件和约束 | 补齐替代方案和放弃理由 |
| **凭空断言** | "业界普遍认为" | 具体到谁认为、在哪说过 | 搜原始出处，无出处则降级为"某一家观点" |
| **类比当定理** | "就像人脑的神经网络" | 类比后必须解释机制差异 | 加"但区别在于"段落 |
| **假完整性** | "分为A/B/C/D四个方面" | 问"为什么是这四个？MECE吗？" | 检查分类是否为先验分类 |
| **空洞趋势** | "未来将是X的趋势" | 趋势的驱动力、时间线、量化预期 | 搜第三方预测+给出条件判断 |

## 深度补齐检查清单（交付前自检）

- [ ] 每个关键名词都做了原理溯源？（不是概念解释，而是"为什么这样实现"）
- [ ] 每个"提升/优化/改进/加速"类断言有数值量化？
- [ ] 每个数值有单位+对比基线+测试条件？
- [ ] 每个"最优/最佳/首选"有对比对象和选择理由？
- [ ] 每个适用范围有声明的边界条件？
- [ ] 引用来源能追溯到论文/标准/白皮书层级？
- [ ] 分类是推导出来的还是预设的？MECE吗？
- [ ] 补充内容不改变原有判断方向，只是深化支撑？
