# 会话意图分析 🧠

定期分析 `conversation-log/db-sessions/` 中的会话数据，提取用户问题，识别话题边界和任务切换，生成用户意图分析报告，用于驱动技能和脚本的优化。

**核心增强**: 利用大模型进行语义级意图识别和深度解析，超越关键词匹配的局限。

---

## 核心功能

| 功能 | 说明 |
|:-----|:-----|
| **提取用户问题** | 从会话日志中提取用户消息，去除调度器定时任务 |
| **话题边界识别** | 检测对话中的话题切换，识别任务切换场景 |
| **意图分类（增强）** | 结合关键词匹配 + 大模型语义理解，实现精准意图识别 |
| **LLM深度解析** | 利用大模型对统计数据进行语义分析、模式挖掘、趋势解读 |
| **生成分析报告** | 结合 MEMORY.md + RULE.md + LLM洞察，生成全面意图分析报告 |

---

## 工作流程（增强版）

```
1. 导出会话 → 提取用户问题（去除定时任务）
           ↓
2. 矫正对话主线 → 识别话题边界和任务切换
           ↓
3. 基础意图分析 → 关键词匹配生成初步统计报告
           ↓
4. LLM深度解析 → 对统计数据进行语义分析和洞察挖掘
           ↓
5. 输出结果 → 更新 user-questions/ 和 user_indent.md（含LLM解析）
```

## 使用方法

> 🚀 **2026-08-13 已工具化**：自动化脚本已实现（`scripts/intent_analysis/`），一键执行覆盖「导出会话 → 提炼 CSV → 报告骨架」，Agent 只需补 LLM 深度解析。

### 一键执行（推荐）

```bash
cd ~/cow
bash scripts/intent_analysis/run_all.sh --since 2026-08-07   # 导出+CSV+报告骨架
bash scripts/intent_analysis/run_all.sh --no-export          # 跳过会话导出
bash scripts/intent_analysis/run_all.sh --report-only         # 仅用已有CSV生成报告骨架
```

### 脚本清单

| 脚本 | 功能 |
|:-----|:-----|
| `conversation-log/export_db_sessions.py` | 从 `memory/long-term/index.db` 导出会话到 `conversation-log/db-sessions/`（含近期） |
| `scripts/intent_analysis/export_user_questions_csv.py` | 提炼用户问题 → CSV（**v2 全量 9 列**：时间/问题/通道/会话ID/会话标题/会话创建时间/seq/消息ID/是否定时任务），过滤调度任务与 tool_result |
| `scripts/intent_analysis/gen_intent_report.py` | 基于 CSV 生成报告骨架（统计+意图分类+话题热点+明细） |
| `scripts/intent_analysis/run_all.sh` | 一键串联以上三步 |

### 手动流程（脚本输出骨架后由 Agent 完成）

1. **导出会话** → `conversation-log/db-sessions/`（脚本自动；⚠️ 通道判定走 session_id 前缀映射，**勿用 channel_type 字段**——83% 为空）
2. **提炼用户问题** → CSV（脚本自动；过滤 `scheduler_` 前缀会话与 `[SCHEDULED]` 开头消息）
3. **统计与骨架** → 报告骨架（脚本自动生成统计/意图分类/话题热点/明细）
4. **LLM 深度解析** → Agent 基于 CSV + 骨架统计 + MEMORY.md/RULE.md 补全「五、LLM 深度解析」章节（参考下方「LLM深度解析模块」）
5. **归档** → 报告存至 `knowledge/weekly-reports/07_kb_stat/06_conversation/conversation-intent-analysis-<日期>.md`；CSV 同目录 `user-questions-<日期>.csv`；用 kb-log-append.py 追加摘要到全局 `knowledge/log.md`（2026-08-19 起 07_kb_stat 不再维护独立 index/log）

## 输出文件

| 文件 | 说明 |
|:-----|:-----|
| `knowledge/weekly-reports/07_kb_stat/06_conversation/conversation-intent-analysis-<日期>.md` | **意图分析报告（主输出）** |
| `knowledge/weekly-reports/07_kb_stat/06_conversation/user-questions-<日期>.csv` | 用户问题明细 CSV（**v2 全量 9 列**，utf-8-sig 兼容 Excel，问题全文不截断） |
| `conversation-log/db-sessions/*.md` | 导出的会话原文 |
| `conversation-log/user-questions/*.md` | 按会话分类的用户问题文件（历史机制，可选） |
| `conversation-log/user_indent.md` | 用户意图分析主报告（历史路径，新报告以 06_conversation 为准） |

> ⚠️ **数据源与过滤要点（2026-08-13 实测，v2 口径）**：
> - 会话库: `memory/long-term/index.db`（sessions/messages 表，`created_at` 为 **Unix 时间戳**）
> - ⚠️ 通道判定**不要用 `sessions.channel_type`**（83.3% 为空，仅 42 个真实用户会话有值）；权威口径 = session_id 前缀映射（`scheduler_oc_`=feishu定时 / `scheduler_session_`=web定时 / `ou_`/`oc_`=feishu / `session_`=web）
> - ⚠️ 必须过滤 tool_result 伪装：role='user' 的消息中 2 万余条实为工具结果（content JSON 首元素 type=tool_result），真实用户提问仅 ~1,900 条（type=text）
> - ⚠️ 行数统计一律用 `COUNT(*)`：messages ID 有断号 3,694（历史删除），**禁用 `MAX(id)`**
> - 调度任务过滤: session_id 前缀 `scheduler_` + 消息内容前缀 `[SCHEDULED]` 双保险（web 渠道调度任务的 session_id 无 scheduler_ 前缀）

## 话题切换检测

脚本通过以下信号识别话题切换：

- **显式切换信号**: 另外、还有、切换、回到、开始、接下来、补充
- **意图一致性**: 当前问题与上一个问题的意图类型完全不同
- **时间间隔**: 超过30分钟的长时间间隔

## 🤖 LLM深度解析模块

### 核心价值

关键词匹配存在明显局限：
- 无法理解上下文语义
- 英文技术术语识别率低
- 无法发现隐性意图模式

LLM深度解析补充以下能力：

| 能力 | 说明 |
|:-----|:-----|
| **语义理解** | 理解对话的深层意图，而非表面关键词 |
| **上下文关联** | 结合对话主线，识别连续性意图演化 |
| **模式发现** | 发现统计数据背后的隐性规律和趋势 |
| **洞察生成** | 对统计数据进行人-readable的解读和建议 |

### LLM调用时机

在脚本生成基础统计报告后，由 Agent（即你）进行 LLM 深度解析：

```
[步骤1-3] 脚本执行 → 生成 user_indent.md（基础统计）
           ↓
[步骤4] Agent解析 → 对统计数据进行语义分析
           ↓
[步骤5] Agent补充 → 将LLM洞察追加到报告末尾
```

### LLM解析框架

**解析输入**：读取 `user_indent.md` 的统计数据，包括：
- 意图分类占比
- 决策模式频次
- 技术维度关注
- 对话主线示例

**解析维度**：

| 维度 | 解析要点 | 输出格式 |
|:-----|:---------|:---------|
| **意图分布解读** | 为何某意图占比高？背后的用户需求模式 | 2-3句分析 |
| **决策模式洞察** | 发现用户工作习惯、决策偏好 | 1-2条模式描述 |
| **技术关注演化** | 技术维度关注的优先级变化趋势 | 1-2条趋势判断 |
| **对话主线提炼** | 从对话示例中提炼核心工作流 | 1个典型场景描述 |
| **优化建议增强** | 基于LLM洞察，补充具体可执行的优化建议 | P0-P2建议表 |

**解析输出模板**：

```markdown
## 十、LLM深度解析

### 意图分布解读

<对意图分类占比的语义分析>

### 决策模式洞察

<对决策模式的深层解读>

### 技术关注演化

<技术维度关注的分析和趋势判断>

### 对话主线提炼

<典型工作场景描述>

### 优化建议增强

| 优先级 | 建议 | 具体执行路径 | LLM洞察依据 |
|:-:|:-----|:-------------|:------------|
| P0 | ... | ... | ... |
```

### 执行示例

**Agent执行流程**：

1. **读取基础报告**
   ```
   我会读取 conversation-log/user_indent.md，获取统计数据
   ```

2. **LLM语义解析**
   ```
   基于统计数据，进行以下解析：
   - 意图占比背后的用户需求模式
   - 决策模式反映的工作习惯
   - 技术维度关注的优先级变化
   ```

3. **追加LLM洞察**
   ```
   将解析结果追加到 user_indent.md 的末尾（第九章后面）
   生成新的"十、LLM深度解析"章节
   ```

## 🔄 下游协作：Evolver 自进化引擎

本技能的分析结果可为 `evolver` 提供进化数据源：

| 意图分析产出 | Evolver 利用方式 | 示例 |
|:-------------|:-----------------|:------|
| **用户问题模式** | 识别频率最高的技能调用，判断哪些技能需要优化 | 若 `doc-reviewer` 调用频率骤降 → 可能触发条件不准确 |
| **话题边界切换** | 检测用户在任务间的切换点，优化 `light-orchestrator` 的编排策略 | 频繁在"调研→写作"间切换 → 可缩短 light-literature-search 的预期耗时 |
| **失败模式** | 分析用户纠错/重复请求的模式，驱动 skill-evolver 生成修复 | 用户多次纠正同一技能行为 → 触发 GEP 进化 |
| **技能覆盖缺口** | 识别用户需要但无对应 Skill 的场景 | 发现新需求 → 建议创建新 Skill |

**触发方式**: `session-intent-analysis` 分析完成后，调用 `evolver` 的 `/evolve --from-intent-analysis` 模式
**数据传递**: `intent_analysis/output/` → `evolver` 的 GEP 进化基因组

---

| 维度 | 标准 | 检查点 |
|:-----|:-----|:-------|
| **语义准确性** | 意图解读符合用户真实需求 | 意图占比解读有理有据 |
| **洞察深度** | 超越表面统计，发现隐性模式 | 至少发现1条隐性规律 |
| **建议可执行** | 优化建议具体、可落地 | 每条建议有执行路径 |
| **格式规范** | 符合报告结构要求 | 新章节编号正确，表格完整 |
