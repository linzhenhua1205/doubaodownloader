## 1. 系统概述

> **实现 AR**: `AR-SYS-001`（身份文件体系）→ `AR-SYS-002`（记忆系统持久化）→ `AR-SYS-005`（渠道适配层）→ `AR-SYS-008`（三论原则引擎）

### 1.1 定位

Cow 是一个 **AI 驱动的自演进知识库系统**，面向产品研发（特别是服务器领域与 AI 基础设施），覆盖技术、工具、概念理解、企业管理、产品产研销等多维度知识。

### 1.2 核心设计目标

| 目标 | 描述 | 当前状态 | 优先级 |
|:-----|:------|:--------:|:------:|
| **知识体系化** | 从数据到知识的端到端自动化闭环 | ✅ 基础闭环 | P0 |
| **AI 创造性应用** | 充分发挥 AI 在知识组织/提炼/分析中的创造力 | ✅ 核心能力 | P0 |
| **幻觉约束** | 多源交叉验证 + 来源追溯 + 批判性使用 | ✅ 已落地 | P0 |
| **可信输出** | 每条断言可追溯、每个数据可验证 | ✅ 质量内建 | P0 |
| **自演进能力** | 系统自动识别短板、优化策略、迭代进化 | 🚧 规划中 | P1 |
| **RAG 集成** | 知识库向量化检索 | 🚧 待激活 | P1 |

### 1.3 三论指导原则

| 方法论 | 在系统中的应用 | 实例 |
|:-------|:---------------|:------|
| **MECE 原则** | 知识分类相互独立、完全穷尽；模块划分不重叠不遗漏 | 知识库 7 大模块 + 22 个跟踪子模块 |
| **第一性原理** | 回归物理极限/经济规律/信息论，不盲从共识 | 带宽/延迟/算力等从物理约束推导 |
| **约束辩证法** | SSOT 约束适度，规范与灵活动态平衡 | 25% 松弛规则、bak 回收站机制。详见 `sr-001-knowledge-system-requirements.md §1.2` C5 定义 |

### 1.4 技术栈

| 层 | 技术 | 说明 |
|:---|:-----|:------|
| Agent 运行时 | DeepSeek / Claude / AI 框架 | AI 对话与工具调用 |
| 知识存储 | Markdown + Git | 纯文本知识库，版本控制 |
| 调度系统 | Scheduler（38 个任务） | 定时任务调度 |
| 脚本语言 | Python 3.10+ | 主要自动化语言 |
| 批处理 | Shell / PowerShell | 环境脚本 |
| 版本控制 | Git | 知识库变更追踪 |
| Web 浏览 | Flask（`flask_dir_browser.py`） | 本地目录浏览与 Markdown 渲染 |
| 数据转换 | markitdown / python-pptx / PaddleOCR | 多模态文件 → Markdown |

## 11. 系统设计方法

> **实现 AR**: `AR-SYS-008`（三论原则引擎）— MECE/第一性原理/辩证法在系统设计中的实践

### 11.1 MECE 分层设计法

系统设计遵循 **MECE（相互独立、完全穷尽）** 原则：

| 设计层次 | MECE 应用 | 验证方法 |
|:---------|:----------|:---------|
| 四阶段分割 | 收集/加工/优化/使用 — 阶段间无重叠 | 每阶段前检查：输入单一、输出明确 |
| 知识分类 | 7 大模块互斥，无跨目录归属 | 文件分类准确率审计 |
| Skills 分类 | 11 个分类互斥，每个 Skill 有唯一定位 | 触发条件冲突检测 |
| 脚本功能 | 按 `check_/fix_/generate_/import_/export_` 前缀划分 | 功能重叠检查 |

### 11.2 第一性原理验证法

对于系统中的关键断言和数据，回归物理极限/经济规律/信息论验证：

| 验证对象 | 第一性原理 | 应用场景 |
|:---------|:-----------|:---------|
| 带宽/延迟/算力 | 物理极限（光速/信号/热力学） | 芯片/互联性能对比 |
| 知识库存储 | 信息论（冗余/压缩/检索效率） | 索引结构设计 |
| 自动化程度 | 经济规律（token 成本 vs 人工成本） | 自动化边界决策 |

### 11.3 约束辩证法

SSOT（单一可信源）的约束应当适度，在规范与灵活之间动态平衡：

| 约束 | 适度原则 | 过度约束风险 |
|:-----|:---------|:-------------|
| 目录结构 | MECE 分层 + 25% 松弛 | 过度分类导致维护负担 |
| 文档格式 | TOC + 交叉链接 + Changelog | 过多模板细节抑制产出 |
| 质量要求 | 量化四要素 + 来源可追溯 | 完美主义导致不产出 |

### 11.4 操作工具与方法

| 操作 | 工具 | 方法 |
|:-----|:------|:------|
| 架构设计 | ADR（架构决策记录） | 记录每次关键决策的理由和替代方案 |
| 质量保障 | 三层审查体系 | 结构层 → 逻辑层 → 来源层 |
| 目录治理 | 独立审计 | 每季度执行目录 MECE 审计 |
| 技能开发 | 创建→审查→迭代闭环 | 先产出，再审查，再优化 |
| 记忆管理 | 频率优先定位 | 按信息更新频率匹配存储位置 |

## 13. 技术决策记录（ADR）

### ADR-001: 知识库使用 Markdown + Git

- **决策**: 知识库采用纯 Markdown 文件 + Git 版本控制
- **理由**: 纯文本可读性强、工具链成熟、diff 友好、无需数据库
- **替代方案**: Notion、Obsidian、Wiki — 但外部依赖、迁移成本高
- **结论**: ✅ 采用

### ADR-002: 对话持久化使用 SQLite

- **决策**: 完整对话记录使用 SQLite 存储
- **理由**: 结构化查询、事务支持、嵌入式无外部依赖
- **位置**: `memory/long-term/index.db`
- **结论**: ✅ 采用

### ADR-003: Python 为主脚本语言

- **决策**: 自动化脚本使用 Python 3.10+
- **理由**: 生态丰富、跨平台、AI 工具支持好
- **例外**: Windows 环境用 PowerShell 处理批处理
- **结论**: ✅ 采用

### ADR-004: 三层审查体系

- **决策**: 文档审查分结构层、逻辑层、来源层三层
- **理由**: 不同问题类型需要不同严重度处理
- **实现**: `doc-reviewer` 技能 + `review_doc.py` 脚本
- **结论**: ✅ 采用

### ADR-005: 文件删除使用回收站模式

- **决策**: 不直接删除文件，使用 `mv` 移动到 `tmp/bak/`（原 `knowledge/bak/`，2026-07-24迁址）
- **理由**: 历史教训 — 多次永久删除事故
- **实现**: 所有删除操作先移动到 bak/，附带日期标记
- **结论**: ✅ 采用

### ADR-006: 四阶段数据流模型

- **决策**: 数据按「收集→加工→优化→使用」四阶段组织
- **理由**: 清晰划分输入/输出边界，便于质量控制和管线化管理
- **目录映射**: `import/` → `discover/` → `knowledge/` → 使用
- **结论**: ✅ 采用

### ADR-007: Skills + Scripts 双引擎

- **决策**: 使用 Skills（AI 驱动、质量高、灵活）和 Scripts（批量、可重复、速度快）双引擎
- **理由**: 两类任务特性不同，分离更高效
- **协同模式**: Skill 编排 + Script 执行
- **结论**: ✅ 采用

### ADR-008: 定时任务使用 Scheduler 而非 Cron

- **决策**: 使用内置 Scheduler 而非系统 Cron
- **理由**: 与 Agent 共享上下文、可动态增删、日志集成
- **例外**: 需要独立于 Agent 运行的核心任务用 Cron
- **结论**: ✅ 采用

### ADR-009: import/ 素材批判性使用

- **决策**: import/ 素材不作为文档唯一来源，关键数据需独立源交叉验证
- **理由**: 素材来源广泛（L4/L5 级别），可信度不一致
- **实现**: RULE.md 中硬编码规则 + 文档头部标记
- **结论**: ✅ 采用
