## 规格流转路径

spec/ 文档从需求到落地共 **5 层流转**，配套 1 套一致性检测闭环：

```text
sr-xxx (系统需求规格)
  │  ⚠️ 历史参考，记录原始需求输入
  │  最新需求点 → 直接同步到 ar-001，不再追加 sr
  │
  ▼
std-xxx (工程标准规范)
  │  系统级约束：开发规范/内容格式/操作指南/流水线约束
  │
  ▼
ar-001 (架构需求映射表)
  │  SR→AR 双向追溯 + 实施优先级
  │  ✅ 活跃需求锚点，所有新需求在此落地
  │
  ▼
design-xxx (架构设计方案)
  │  7 份设计文档，逐层决策拆解，每份对应具体 AR
  │
  ▼
落实层
  ├── scripts/README.md    — 154 个脚本的使用手册与分类索引
  └── skills/README.md     — 技能系统的入口导航
```

**一致性检测闭环**（逆向上溯验证）：检测链与流转方向相反，逐层校验：

```text
                   ┌─────────────────────────────────────┐
                   │ spec-consistency-checker (Skill)     │
                   │                                     │
  L6 跨层引用 ────▶│ scripts/check/check-*-trace.py     │◀── L1 AR
  L5 边界验证 ────▶│   · L1: SR→AR 映射完整性            │◀── L2 AR→Design
  L4 约束来源 ────▶│   · L2: AR→Design 回溯              │◀── L3 Design→Impl
  L3 Design→Impl ─▶│   · L3: Design→Impl 实现验证         │
  L2 AR→Design ───▶│   · L4: Constraint Source 来源验证   │
  L1 AR 映射 ─────▶│   · L5: Pipeline Boundary 边界验证   │
                   │   · L6: Cross-Layer Refs 跨层引用     │
                   │                                     │
                   │ scripts/tools/gen-spec-consistency-  │
                   │   report.py (编排器, 全量/指定层级)   │
                   │                                     │
                   │ 📄 报告输出: knowledge/weekly-reports/│
                   │    07_kb_stat/YYY-MM-DD-spec-       │
                   │    consistency-report.md             │
                   └─────────────────────────────────────┘
```

### 流转原则

| 原则 | 说明 |
|:-----|:------|
| **SR 即历史** | sr-xxx 保留原始需求记录，**不再新增 SR 条目**（2026-08-19 例外：用户指令新增 sr-011 CowAgent 改进点**需求收集**文档，属需求分析/盘点性质，非单一需求点）。新需求点直接写入 ar-001 |
| **AR 即锚点** | ar-001 是活跃需求文档，所有 design/std/skills/scripts 均应对齐 AR |
| **检测即校验** | 6 层检测链 + 编排器确保上下游一致性，不一致即 bug，需修复 sr/ar/design 而非跳过检测 |
| **报告有路径** | 每次检测输出结构化报告，归档至 `knowledge/weekly-reports/07_kb_stat/`，可追溯历史趋势 |

## 前缀命名体系

| 前缀 | 全称 | 用途 | 数量 | 说明 |
|:----:|:-----|:-----|:----:|:------|
| `design-` | Architecture Design | 架构设计方案 | 10 | 系统/模块/优化层的设计输出 |
| `meth-` | Methodology | 方法论设计文档 | 13 | 可复用的分析/设计/审查方法论 |
| `sr-` | System Requirement | 系统需求规格 | 8+1 | 需求定义、约束注册、问题分析（含 1 归档桩 sr-004） |
| `std-` | Engineering Standard | 工程标准规范 | 5 | 可执行的操作规范、格式标准（含 std-005 目录注册表） |
| `ar-` | Architecture Mapping | 架构需求映射 | 1 | SR→AR 双向追溯 |
| `audit-` | Compliance Audit | 合规审计 | 2 | 约束合规 + 完整/封闭性实证审计报告 |
| `_archive/` | Archived Reports | 一次性报告 | 5 | 优化方案/审计/历史版本（非持续性规范） |

## 阅读顺序

**第 1 遍（新读者 — 建立全貌）**:

```
sr-001 -> design-001 -> sr-004 -> sr-003 -> std-001
```

**第 2 遍（深入理解 — 掌握细节）**:

```
std-002 -> std-003 -> design-003 -> design-004 -> design-007
```

**第 3 遍（优化视角 — 发现问题与改进）**:

```
design-002 -> design-005 -> design-006 -> sr-005 -> sr-006 -> sr-002
```

**可选（方法论视角）**:

```
meth-001 (architecture methodology)
ar-001 (SR->AR mapping table)
audit-001 (constraint compliance audit report)
audit-002 (skills/scripts completeness closure audit)
```
